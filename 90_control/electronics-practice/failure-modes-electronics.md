## 目录结构

```
project-name/
├── 01_specs/              ← 需求/规格文档
├── 02_schematics/         ← 原理图（PDF，文件名标注版本号）
├── 03_pcb/                ← PCB 设计文件（Gerber/立创EDA源文件）
├── 04_bom/                ← BOM 清单（CSV/XLSX，文件名标注版本号）
│   └── ordering/          ← 采购用 BOM（区分贴片/插件/定制件）
├── 05_firmware/           ← 固件源码
│   ├── production/        ← 量产版本（已验证通过的）
│   ├── archive/           ← 历史版本（标注各版本差异）
│   └── diagnostics/       ← 诊断版固件（强制/旁路/单步测试用）
├── 06_photos/             ← 实物照片（正常板 vs 故障板对照）
├── 07_logs/               ← 调试日志（按日期命名）
└── README.md              ← 项目概要：一句话说清项目、关键版本对照表、当前状态
```

## E-FM-001：SN74LVC2G07 开漏输出导致 RCLK 上升沿变缓

| 属性 | 内容 |
|:----|:------|
| **场景** | 3.3V MCU → SN74LVC2G07（开漏）→ 上拉电阻 → 5V 外设（SN74LV595 等） |
| **表现** | 595 锁存不可靠，通道错位，LED 状态异常 |
| **根因** | 开漏输出只能拉低不能拉高，拉高靠上拉电阻对负载电容充电。若上拉电阻太大（10kΩ+），RCLK 上升沿变成斜坡，595 在上升沿未达到 Vih 时锁存错误数据 |
| **排查** | ① 诊断版固件强制拉高 QD 绕过 595 确认硬件正常 ② 示波器量 RCLK 上升沿时间 → 若 >100ns 即异常 |
| **修复** | ① 减小上拉电阻（10kΩ→1kΩ）② RCLK 拉高后加软件延时等待上升沿稳定（如 Ir_Delay(200)）③ 改用推挽输出电平转换器（TXS0108 等） |
| **关联项目** | 广冷电子 HX-SMJ 红外光栅板 |

## E-FM-002：BOM 多版本资料不同步

| 属性 | 内容 |
|:----|:------|
| **场景** | 多人交接的硬件项目，原理图/BOM/PCB/Gerber/固件分散在多台电脑 |
| **表现** | 新接手的人花 80% 时间理清哪个版本是对的，且容易用错版本 |
| **预防** | ① 每个文件文件名必须含版本号+日期（如 `BOM_HX-SMJ-03-A_V2.1_2025-12-03.csv`）② 每次改版同步更新所有关联文件 ③ 项目根目录 README.md 维护版本对照表 |

## E-FM-003：批量焊板和手焊板不一致

| 属性 | 内容 |
|:----|:------|
| **场景** | 原型阶段工程师手焊调通→量产机贴后表现不同 |
| **表现** | 原型可用的参数在量产板上无效 |
| **根因** | 手焊板可能有隐性改动（飞线、跳线、不同批次元件），未记录在正式 BOM 中 |
| **预防** | ① 量产前用正式 BOM 重新打样验证 ② 对比手焊板和量产板的外观差异（飞线/替换元件/割线）③ 调试参数标注"适用版本" |

## E-FM-004：诊断版固件缺失导致定位困难

| 属性 | 内容 |
|:----|:------|
| **场景** | 复杂信号链路（如 MCU→电平转换→595→MOSFET→LED→接收管→MUX→运放→MCU）出现故障 |
| **表现** | 不知道哪一级出了问题，只能盲调参数 |
| **对策** | 建一个 diagnostic/ 目录，里面放"短路"某级链路的诊断固件。例如：强制拉高 QD 信号绕过 595，直接点灯确认发射管和接收管硬件正常 |
| **关联项目** | 广冷电子 HX-SMJ 红外光栅板 |
