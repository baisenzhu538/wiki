# 电子工程基线规则

> 路径：`90_control/electronics-practice/project-standards.md`
> 
> 所有电子工程项目必须遵守的三条规则。

---

## 规则一：文件三分类

项目中的每一份文件必须归入以下三类之一：

| 类别 | 色标 | 定义 | 管理方式 |
|:----|:----:|:------|:---------|
| **基准线** | 🔴 | 描述"产品是什么"的不可替代文件 | 只增不改，新版本=新文件，不覆盖旧文件 |
| **佐证** | 🟡 | 有存档价值但不是产品本身的文件 | 按项目归档，可批量压缩 |
| **过程** | ⚪ | 用完即弃的中间产物 | 项目结束时删除 |

### 典型归属

| 文件 | 类别 | 说明 |
|:----|:----:|:------|
| 原理图（PDF/源文件） | 🔴 | 唯一的设计意图记录 |
| PCB 设计文件（JSON/Gerber） | 🔴 | 不可替代 |
| BOM（CSV/XLSX，标注版本号） | 🔴 | 不可替代 |
| 坐标文件（PickAndPlace CSV） | 🔴 | 不可替代 |
| 固件源码 + 最终烧录 hex | 🔴 | 不可替代 |
| 项目 README（版本对照表） | 🔴 | 不可替代 |
| 调试日志、实物照片 | 🟡 | 有存档价值 |
| 示波器截图、采购清单 | 🟡 | 备份即可 |
| 芯片数据手册 PDF | 🟡 | 可归档 |
| 编译中间产物（.o/.crf/.d） | ⚪ | 随时可删 |
| 重复备份、微信传图副本 | ⚪ | 随时可删 |
| 未解压的 .rar（内容已在外） | ⚪ | 可删 |
| KEIL 临时文件 | ⚪ | 可删 |

---

## 规则二：基准线文件的版本管理

1. **每份基准线文件必须标注版本号和日期**——文件名含 `Vx.x_YYYY-MM-DD`，否则视为草稿不投产
2. **原理图+PCB+BOM+坐标 四者锁定为同一个设计基线**——动了其中任何一个，其他三者必须重新确认匹配
3. **固件可以独立迭代**——不改硬件时可以单独改固件版本
4. **每一个基线变更必须记录原因**——在 README 版本对照表中注明

### 版本锁表示例

| 基线 | 原理图 | PCB | BOM | 坐标 | 固件 | 说明 |
|:----|:------|:---:|:---:|:----|:----|:-----|
| B1.0 | V1.0 | V1.0 | V1.0 | V1.0 | V1.0 | 初始设计 |
| B2.0 | V2.0 | V2.0 | V2.0 | V2.0 | V2.0 | PCB 改版 |
| B2.1 | V2.0 | V2.0 | V2.0 | V2.0 | **V2.1** 🔧 | 仅固件修复，硬件不变 |

## 规则三：项目收网清理

项目结束时（批量投产或结项），必须执行以下收网步骤：

1. **删除所有 ⚪ 类文件**（OBJ 目录、重复副本、未使用的压缩包）
2. **🟡 类佐证文件压缩归档**（照片、日志、截图等可打包）
3. **🔴 类基准线文件锁入 `_archive/`**，确保版本对照表完整
4. **确认"收网后存储 < 收网前存储的 50%"**——如果删掉的不到一半，说明有该删没删的

---

## 四、快速清查清单

| 文件类型 | 处理方式 |
|:--------|:---------|
| .o / .crf / .d / .htm / .dep | 直接删除 |
| .rar / .zip（已解压的内容已使用） | 确认后可删除 |
| 微信传图 `微信图片_*` 的重复副本 | 每张只留一个 |
| `广冷001` 与 `广冷002` 的完全重复 | 删 002 |
| JLinkLog.txt / .bak / .iex | 直接删除 |
