# 诊断版固件套路

> 路径：`90_control/electronics-practice/diagnostic-firmware-skills.md`
> 
> 当一片板子完全没反应时，不要先查原理图。先做一个诊断版固件，把复杂链路"短路"掉。

## 核心思路

```
正常模式：MCU → 逻辑链（很长）→ 输出
诊断模式：MCU → 强制输出 → 直接看硬件是否正常
```

如果诊断模式能工作 → 问题在逻辑链的时序/配置上
如果诊断模式也不能工作 → 问题在硬件（电源/焊接/元件损坏）

## 常用诊断手法

| 手法 | 做法 | 适用场景 |
|:----|:-----|:--------|
| 强制拉高 | GPIO 直接输出 1，不经过任何外设控制逻辑 | 确认驱动管/MOSFET/继电器本身正常 |
| 旁路芯片 | 用 GPIO 直接模拟芯片输出，不经过 SPI/I2C 等总线 | 确认后级电路正常 |
| 单步扫描 | 每步加长延时（1s 级），肉眼观察灯变化 | 定位哪一步开始出错 |
| 分半测试 | 屏蔽后半通道，只测前半 | 缩小范围 |

## 模板

```c
// 诊断版示例：强制拉高 QD 信号，绕过 595
void Diagnostic_ForceTx(void)
{
    // 不经过 Ir_Select_Send，直接拉高所有发射管控制脚
    IR_595_QD1 = 1;
    IR_595_QD3 = 1;
    IR_595_SRCLK = 1;
    IR_595_RCLK = 1;
    // 如果 LED 亮了 → 发射管和 595 供电正常
    // 如果 LED 不亮 → 硬件问题
}
```
