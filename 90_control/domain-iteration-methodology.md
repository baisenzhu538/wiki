# KDO 域迭代五阶段法

> 工厂标准流程 v1.0 · 黄药师 · 2026-06-21
> 将任何领域的原始素材系统性地转化为可复用资产（卡片 / Skill / Workflow / 模板）。

## 核心原则

**调研先行。** 每个阶段的第一步是查最佳实践，不是凭记忆动手。

**先骨架后血肉。** 不要追求 100% 覆盖——先用最少卡片让 Agent 能搜到、能理解，然后在真实使用中按需补缺。

**专家即素材。** 课程口述稿 = 专家的认知任务记录（PARI 模式），直接可提取前因/动作/结果/解释。

## 五阶段总览

```
阶段1: 诊断          阶段2: 骨架          阶段3: 工具化        阶段4: 验证          阶段5: 资产化
┌──────────┐       ┌──────────┐       ┌──────────┐       ┌──────────┐       ┌──────────┐
│ 素材验收   │  →   │ 框架卡    │  →   │ Skill化   │  →   │ Agent实测  │  →   │ Workflow │
│ 盲区识别   │      │ 概念卡    │      │ 工具卡    │      │ 补缺修正   │      │ 模板     │
│ 价值判断   │      │ 索引入口   │      │ 提示词    │      │ 交叉验证   │      │ 域索引   │
└──────────┘       └──────────┘       └──────────┘       └──────────┘       └──────────┘
  王语嫣              老顽童              老顽童+黄药师        Agent+用户           全厂
```

## 阶段 1：诊断

**执行者**：王语嫣
**输入**：`00_inbox/<新域>/` 下的原始素材
**输出**：诊断记录 + 生产任务清单

### 步骤

1. **盘点素材**：统计文件类型、数量、口述稿/笔记/图片/PDF
2. **标记置信度**（L1/L2/L3）：≥2 独立来源 → 🔵 高；单一来源 → 🟡 存疑；来源不明 → 🔴 不建议
3. **识别盲区**：图片缺 OCR？素材不完整？课程 Q&A 尾巴有未被笔记覆盖的暗知识？
4. **对照已有卡片**：`kdo cards --domain <域>` 查库存，避免重复建设
5. **写诊断记录**：输出到 `60_feedback/diagnosis/diag_<日期>_<域>素材验收.md`
6. **生成任务清单**：按五阶段排 Wave，每张卡给 ID / 类型 / 素材来源 / 验收标准

### 验收标准
- 诊断记录包含素材盘点总表 + 置信度标记 + 与已有卡片对照 + 盲区清单
- 任务清单按 Wave 分批，Wave 1 优先框架卡

> 参考：`60_feedback/diagnosis/diag_20260620_调研专题素材验收.md`

## 阶段 2：骨架

**执行者**：老顽童
**输入**：诊断记录 + 任务清单
**输出**：核心框架卡 + 概念卡 + 域索引入口卡（15-30 张）

### 步骤

1. **先读诊断记录**：理解王语嫣的置信度标记和盲区提示
2. **从口述稿提取框架**：每份口述稿的"核心方法论"→ 1 张 framework 卡
3. **提取核心概念**：域内关键术语、原则 → concept 卡
4. **建立索引入口**：用 `scaffold-domain-index.py --domain <域> --topic <名称>` 生成骨架，手工填写描述
5. **每张卡跑 `kdo lint`**：格式合格再提交

### 关键规则（来自欧阳锋审查标准）
- 每张卡必须有 Critique（≥2 外部攻击者） + Boundary + Action Triggers
- 框架卡必须配案例链接；案例卡必须链回方法卡
- 域内第一张索引入口卡必须在骨架阶段就建——后续卡片才有地方挂载

### 验收标准
- 域索引入口卡已写入 `30_wiki/domains/`
- 域内核心方法论已覆盖为 framework 卡
- `kdo lint` 通过

## 阶段 3：工具化

**执行者**：老顽童（工具卡/提示词） + 黄药师（Skill 格式）
**输入**：骨架阶段的框架卡 + 原始素材
**输出**：Tool 卡 + Claude Code Skill + AI 提示词

### 三类产出

#### A. Tool 卡（wiki 内，老顽童）
- 路径：`30_wiki/tools/`
- 结构：操作步骤 + 失败模式 + 适用边界 + 场景索引
- 每张 tool 卡链 ≥1 张 framework 卡

#### B. Claude Code Skill（黄药师/老顽童）
- 路径：`40_outputs/capabilities/skills/<skill-name>/SKILL.md`
- 格式（参考 `business-research/SKILL.md`）：
  ```yaml
  ---
  name: <skill-name>
  allowed-tools: [WebSearch, WebFetch, ...]
  description: 一句话 + 触发词
  ---
  # <Skill 标题>
  ## Constraints
  <hard_limits>：严禁捏造信源 / 核心结论需交叉验证 / ...
  <constraints>：时效性 / 置信度标注 / 禁用套话 / ...
  ## 核心理念
  ## 执行步骤（Step 1 → Step N）
  ## 输出规范
  ```

#### C. AI 提示词（老顽童）
- 路径：`00_inbox/<域>/<域>提示词.txt`（草稿），稳定后入库
- 结构：Role + 核心逻辑 + 字典/框架 + Output Constraints
- 参考：`需求分析提示词.txt`

### 工具化决策
- 该流程可自动化执行？→ **Skill**（Agent 可调用）
- 该流程需人工判断？→ **Tool 卡** + 检查清单
- 该流程是固定模板？→ **提示词**（AI 按模板填充）
- 该技能需要特定工具组合？→ **Workflow**（阶段 5）

### 验收标准
- Skill 卡可通过 `/skill-name` 直接调用
- Tool 卡包含失败模式和适用边界
- 提示词包含全量字典和输出约束

## 阶段 4：验证

**执行者**：Agent（老顽童/王语嫣驱动的 Hermes 会话） + 用户
**输入**：阶段 2-3 产出的全套卡片
**输出**：验证报告 + 补缺卡片

### 步骤

1. **设测试场景**：用户给出真实任务（如"用 USP 模型分析 XX 产品"）
2. **Agent 执行**：Agent 查域索引入口 → 定位框架卡 → 调用 Skill → 产出报告
3. **记录失败**：Agent 找不到哪张卡？Skill 哪一步卡住了？缺什么工具？
4. **补缺**：根据失败记录追加缺失卡片
5. **重复**：DDC 模式（Demand-Driven Context）——20-30 个问题周期达到充分覆盖

### 验收标准
- Agent 能独立完成域内典型任务（从检索到产出报告）
- 检索命中域索引入口卡 → 框架卡 → 工具卡的正确链路

---

## 阶段 5：资产化

**执行者**：全厂（老顽童 + 黄药师 + 段王爷）
**输入**：验证通过的域卡片体系
**输出**：Workflow + 模板 + 域索引更新 + 发布

### 产出

| 资产类型 | 是什么 | 路径 |
|:--|:--|:--|
| **Workflow** | 多张工具卡串联的端到端流程（如 OSCAR 五步法执行手册） | `30_wiki/systems/` |
| **模板** | 可复用的分析报告模板 | `40_outputs/content/templates/` |
| **域索引** | 更新索引入口卡，补充新增卡片 | `30_wiki/domains/` |
| **发布** | 段王爷 `kdo ship` → 渠道分发 | `50_delivery/` |

### 验收标准
- Workflow 可由 Agent 按步骤执行
- 域索引入口卡已更新
- （可选）文章/视频等对外交付物
