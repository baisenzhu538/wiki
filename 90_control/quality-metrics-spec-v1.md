## 总则

- 只读统计，不改任何流程（阶段 0 纪律）
- 按周聚合（周一~周日），每周一出上周报
- 数据源以 git 历史与日志文件为准（queue_transition 流转留痕 / gate-blocked.log / force-exceptions.log / 任务单终审记录节），机器可读优先于人工登记
- 分母口径与分子口径同名同范围，禁止混用（动作级≠单级）

## 四类指标口径

1. **FAIL 率（动作级）** = 终审 review_fail 动作数 ÷ 终审动作总数（review_pass + review_fail）
   - 数据源：queue_transition review 流转留痕 + 任务单「## 终审记录」节
   - 同一单返工重审，每次终审动作各计一次（反映审查负载）
2. **打回率（单级）** = 统计周期内至少被打回一次的任务单数 ÷ 周期内提审过的任务单数（complete→pending_review 去重计单）
   - 与 FAIL 率的差异：FAIL 率看动作、打回率看单——一单三轮 FAIL 在 FAIL 率里计 3、在打回率里计 1
3. **门禁拦截率** = gate-blocked.log 拦截条数 ÷ queue_transition 流转动作总数，**按拦截类型分类**（F-034 五字段 / F-035 意见书 / complete 交付物入仓（#522）/ pre-submit / 其他）
   - 注意：门禁拦截 ≠ 终审 FAIL，两类事件不得合并（原任务书数据源混了这两者，以本口径为准）
4. **误判率（基线期用代理指标）** = force 放行率 = force 例外次数 ÷ 拦截次数（force-exceptions.log ÷ gate-blocked.log）
   - 真误判需人工标注「拦截是否正确」样本，基线期先跑代理指标并附注；基线报告 v1 里给真误判的标注方案（进入阶段 1 再启用）
