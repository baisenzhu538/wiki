# KDO Ingestion Pipeline：素材 → 卡片流水线

> 生效日期：2026-06-14  
> 设计：王语嫣（入口质量门）+ 黄药师（管线设计）+ 欧阳锋（审批）

## 管线总览

```
00_inbox/ 素材
    │
    ├── P2 级（笔记/碎片）────────→ 老顽童直接处理
    │
    └── P0/P1 级（课程/录音/报告）→ 王语嫣入口质量门
                                        │
                                        ├── 🟢 high → 老顽童写卡
                                        ├── 🟡 medium → 老顽童写卡（标注 `confidence < 0.7`，status: draft）
                                        ├── 🔴 low → 仅入 `10_raw/sources/`，不入 wiki
                                        └── ⚫ discard → 归档，不入库
                                              │
                                              ↓
                                    老顽童写卡 + CI/CD 自动门禁
                                              │
                                              ↓
                                    欧阳锋抽检
```

## 一、素材分级（谁做什么）

| 级别 | 素材类型 | 例子 | 走门禁？ | 处理人 |
|:--|:--|:--|:--:|:--|
| **P0** | 新域开荒、付费课程、客户录音、诊断访谈 | 一堂新课、七件事录音、药柜访谈 | ✅ 必须 | 王语嫣→老顽童 |
| **P1** | 已有域补充、公开文章、行业报告 | 药监局新规、36氪深度报道 | 可选 | 王语嫣或老顽童直接 |
| **P2** | 个人笔记、灵感碎片、随手标注 | Truman 课堂笔记片段 | ❌ | 老顽童直接 |

## 二、王语嫣角色：入口质量门

### 输入
- `00_inbox/` 下 P0/P1 级别的新素材

### 职责
1. **六层交叉比对**（L1-L6），给每条核心陈述标注 confidence
2. **标记高价值段落**：源材料中哪些是方法论现场演示、哪些是首次公开、哪些有实战数据
3. **标记 ⚡CONTRADICTION**：同素材内部矛盾 or 素材 vs 已有知识库矛盾
4. **提取案例素材**：源材料中的具体案例，标注"建议出 case 卡"
5. **输出置信度分层表**：🟢 high / 🟡 medium / 🔴 low / ⚫ discard

### 输出格式
```markdown
## 高价值段落索引
| 位置 | 内容摘要 | 建议出卡类型 | 优先级 |
| 第448-668行 | 直播SOP三年迭代 | case | P0 |
| 第1194行 | AI skills封装过程 | method | P0 |

## 置信度分层
| 陈述 | confidence | 判定 |
| "服务十四万家企业" | 0.65 🟡 | 需独立验证 |
```

### 不做什么
- 不写最终卡片（那是老顽童的活）
- 不修改 `30_wiki/` 下任何文件
- 不自己做内容决策（标出来让老顽童判断）

## 三、老顽童角色：卡片量产

### 输入
- 王语嫣质量门输出（高价值段落索引 + 置信度分层）
- P2 级素材直接消化

### 职责
1. 根据王语嫣的标注，精准定位源材料中的金矿
2. 三步编译法写卡：Condense → Question → Synthesize
3. 框架卡必须含案例（至少 1-2 个真实案例）
4. 案例卡必须从源材料提取，不能用通用例子
5. 每张卡挂 `confidence` 字段（继承王语嫣的评估）

### 不受别人标记影响时
- 如果消化源材料时发现王语嫣漏标的内容 → 加标签后继续写
- 如果认为王语嫣的 confidence 高估/低估 → 标注并写自己的判断

## 四、自动门禁（黄药师维护）

| 规则 | 触发条件 | 动作 |
|:--|:--|:--|
| 缺 confidence | 新卡无此字段 | BLOCK / WARN（存量） |
| confidence < 0.5 | 低信卡混入 wiki | BLOCK，仅入 raw |
| 单信源 | source_refs 仅 1 条 | WARN |
| 无出链 | Synthesis 无 wikilink | WARN |
| diagnostic_signals 空 | framework/tool/case 卡 | WARN |

每日凌晨 02:07 自动跑，报告在 `60_feedback/auto/health-check-*.md`。

## 五、欧阳锋角色：抽检

- 不审查每张卡（量太大）
- 每月抽检 3-5 张，交叉验证 claims 和源材料
- 发现模式性问题 → 写纠正记录 → 调门禁参数

## 六、常见问题

**Q: 王语嫣忙不过来怎么办？**  
P0 必走，P1 老顽童自行判断。小素材直接消化不排队。

**Q: 老顽童不同意王语嫣的 confidence 评分？**  
写卡时标注自己的 confidence，在 Synthesis 里注明"王语嫣评估 X，我评估 Y，差异原因：..."。

**Q: 案例层的卡谁来写？**  
老顽童。王语嫣标"建议出 case 卡"，不写 case 卡。

**Q: 一张卡跨了多个 domain 怎么归？**  
主 domain 写在最前面。跨域属性用 `bridges_to` 标记。

## 七、OCR 卡分层处理（2026-06-15 新增）

### 问题

OCR 输出直接作为卡片入了 `30_wiki/concepts/`，与精修知识卡混放。368 张 OCR 卡污染了检索和门禁统计。

### 分层方案

```
图片 → OCR → 30_wiki/raw/ocr/ (原始转录层, trust=low)
                    ↓
              人工精修 (老顽童/洪七公)
                    ↓
              kdo scaffold --new → 30_wiki/ (精修知识层)
```

### 规则

1. **OCR 输出默认入 `30_wiki/raw/ocr/`**，不是 `30_wiki/concepts/`
2. **`trust_level: low`** 标记，搜索默认跳过（`kdo query --trust medium` 自动过滤）
3. **门禁不扫描 `raw/`** 目录
4. **精修升级路径**：老顽童从 OCR 卡提取知识点 → `kdo scaffold --new` 创建正式卡 → 原 OCR 卡保留在 raw/ 作为溯源记录

### 存量处理

368 张存量 OCR 卡已迁移到 `30_wiki/raw/ocr/`，门禁已排除。
