# tags 词表设计（#426 挂起中——等更多对标素材）

## 一、半肥猫对标结论（示例拆解）

`标签示例.yaml` 的体系精髓：

| 设计 | 半肥猫做法 | 我们现状（08-23 实测 2200 张抽样） |
|:--|:--|:--|
| tags 只放内容词 | 4 个：主题（膳食指南）+对象（食物份量）+性质（量化）+用途（膳食设计），全部 2-4 字 | 124 张混入课程来源名（「决策高度实操课口述」「需求评估避坑合集」×14）与长短语（「scene:破坏性创新判断」） |
| 判断类信息字段化 | `quality_score: 9` / `review_required` / `status` 独立字段 | 已有同位字段：`quality_labels`（#31 五标签）/ `status` / `confidence` ——**字段基建已齐，只是 tags 没分流** |
| 复用方向独立 | `reuse_direction` 单列（非 tags） | `discoverable_by` 承载——同构 |
| 来源三件套字段 | `source` / `source_type` / `author` | `source_refs` 承载——同构 |

**一句话**：我们的 frontmatter 字段体系与半肥猫同构度很高，缺的只是 tags 的纪律——**把判断/质量类信息和来源名从 tags 里赶出去，tags 只留内容词**。

## 二、四条设计原则（词表宪法）

1. **tags 只放内容词**：每卡 ≤5 个，每个 2-6 字中文，取自分域受控词表（词表外词需域 digest 评审后入表）
2. **判断类信息不进 tags**：质量→`quality_labels`、状态→`status`、置信→`confidence`、审查→`reviewed_by`（字段已齐，零新建）
3. **来源名/课程名禁入 tags**：`source_refs` 是唯一归宿（「决策高度实操课口述」这类词从 tags 清除）
4. **四层语义结构**（半肥猫同款）：主题域词（对齐 domain）+ 对象词 + 性质词 + 用途词——不必四层全填，但词必须可归类

## 三、分域受控词表结构

- 每域一张受控词表（20-40 词），落 `90_control/tags-vocab/<domain>.yaml`，含：词 / 语义层 / 同义词归并映射（旧词→受控词）
- 判断类 tags 迁移映射表：如 `科学决策`→保留（域词）；`五步法之需求分析`→`需求分析`（去课程名前缀）；`需求评估避坑合集`→`需求评估`+`避坑`（拆词）；`scene:破坏性创新判断`→`破坏性创新`+`判断`（去前缀拆词）
- 词表由王语嫣按域起草、老顽童试点反馈、欧阳锋批次验收、老朱终稿

## 四、试点批方案（首批）

- **试点域=决策域**（判断类浓度最高：科学决策×47+需求分析×42+决策评估画布×11≈100 张池）
- 首批 50 张：老顽童按词表治理→欧阳锋验收（抽 tags 四原则合规+迁移映射正确）→通过后放量其余域

## v0.2 重大修正预告（2026-08-23 老朱转述半肥猫原话，v0.1 原则 1 待推翻重估）

> 半肥猫原话两条（老朱 2026-08-23 转述）：
> 1. **「标签打得越细，agent 找起来越快越准。」**
> 2. **「一个 Obsidian 知识库 8000~10000 张卡，只要标签打得细，是可以的。如果打得不细，就没有用了。」**

**方向修正**：v0.1 原则 1「每卡 ≤5 个、2-6 字」与「打得越细越好」**方向相反**——细粒度（多维/层级/多标签）才是对标理念；「打得不细=没有用」把标签细度定为知识库可用性的生死线（8000-10000 张卡的规模下检索全靠它）。

**待重估问题**（等更多素材后回答）：
- 「细」的形态：维度标签？层级标签（膳食指南>份量>生熟换算）？每卡多少个为「细」？
- 细粒度与「判断类走字段、来源名禁入」两原则的关系（后者应该仍成立——细≠什么都塞）
- 词表结构：受控词表在「细」理念下是「每域词更多」还是「层级更深」
