# 知识冲突处理 SOP

> 生效：2026-06-19  
> 背景：一堂课程持续迭代，新素材可能与已有卡片矛盾。这不是系统故障——是知识进化的正常过程。

## 冲突类型与处理

| 冲突类型 | 示例 | 处理 |
|:--|:--|:--|
| **深化型** | 旧课"转化率是最重要的"，新课"转化率重要但复购率才是长期护城河" | 旧卡不删，加 `## 补充` 节，标注新课来源和修正内容。新卡独立建，链回旧卡 |
| **修正型** | 旧课"单元模型用三个工具就够了"，新课"五步法第六步被拆成独立单元" | 旧卡 `status: needs-review`，新卡 `status: enriched`。欧阳锋裁决：替换还是共存 |
| **边界型** | 旧课"Y 模型适用所有决策"，新课"价值观决策不适用广义 ROI" | 两张卡都保留。旧卡加 `Constraints` 表标注边界，新卡（dk）作为边界说明 |
| **矛盾型** | 不同讲师对同一概念给出不同定义 | 两张卡都保留为 draft，标注 `contradiction: 卡A说X, 卡B说Y`。不掩盖冲突——这是未来的研究素材 |

## 处理流程

```
新素材入场 → 王语嫣六层交叉比对
    │
    ├── 无冲突 → 正常走 pipeline
    │
    └── ⚡CONTRADICTION 检测到冲突
            │
            ├── 在旧卡 frontmatter 标注:
            │     status: needs-review
            │     contradiction: "新素材(源文件名)在第X行提出..."
            │
            ├── 新卡正常产出，标注:
            │     status: draft
            │     confidence: 0.6（降低——未经验证的修正）
            │
            └── 写一条纠正记录到 60_feedback/corrections/
                  格式: corr_YYYYMMDD_<主题>-contradiction.md
                  内容: 冲突双方的核心主张 + 王语嫣的独立判断 + 建议处理方式
```

## 谁裁决

- **深化型**：老顽童可以直接加补充节，不需要裁决
- **修正型**：欧阳锋裁决（保留旧版/替换/共存）
- **边界型**：黄药师判断（是否属于同一框架的边界扩展）
- **矛盾型**：用户（老朱）裁决——涉及方法论根基的冲突只有你能判断

## 禁止事项

- ❌ 发现冲突就删旧卡——旧卡是知识演化史，有版本价值
- ❌ 不标注冲突来源就让两张矛盾卡共存——Agent 检索到两张会困惑
- ❌ 因为"讲师更有名"就默认新课对——用六层交叉比对独立验证
