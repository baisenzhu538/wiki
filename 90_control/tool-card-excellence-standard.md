# Tool Card 卓越标准（T4 标杆拆解）

> 基于 [[yt-tool-strategy-workshop]]（欧阳锋审查 A+，全库迄今最佳 tool 卡）的结构逆向工程。本文件是 tool 卡的质量上限参照系——不是每张 tool 卡都必须达到 T4 的所有维度，但写卡前读一遍，知道"好"的天花板在哪。

## T4 为什么是 A+

不是因为战略会这个主题——是因为结构完整度+攻击者深度+工程化防御三重同时达标。

---

## 一、操作流程：五层深度

普通 tool 卡只有"步骤列表"。T4 在每一步上叠加了 5 层信息：

| 层 | 内容 | T4 示例 |
|----|------|---------|
| **步骤名** | 这一步叫什么 | "段 3：诊断深度" |
| **时间** | 这一步占多少时间/什么时候做 | "30% 时间"、"战略会前 2 周" |
| **负责人** | 谁做 | "运营/数据团队"、"会议主持人" |
| **关键约束** | 这一步的红线是什么 | "没有完成诊断，不允许进入方向选择" |
| **产出** | 这一步做完交付什么 | "差异热力图"、"战略决策纪要" |

**标准**：至少 3 层。T4 全部 5 层覆盖。

### 反例

T1 的 Step 1 只有"问题+答案形式+通不过标准"——3 层，合格但未达 T4。

---

## 二、退出标准：工具不是无限的

T4 不仅告诉你"什么时候用"，还告诉你"什么时候该怀疑这个工具本身失效了"：

```
当以下情况发生时，本工具需要被修订或替换：
- 连续两次战略会产出被 3 个月内推翻 → 诊断质量不足
- 战略会后团队执行率 <50% → 活动检查失效
- 参会者反馈"战略会只是老板想法的包装" → 独立作业没真正执行
```

**标准**：≥3 条退出标准，每条包含"信号→诊断→动作"。

---

## 三、常见陷阱：与操作步骤一一对应

T4 的 7 个陷阱对应 7 个操作步骤可能的失败模式，不是泛泛的"管理常见错误"：

| 陷阱 | 对应的步骤 |
|------|-----------|
| 汇报大会 | Step 0 信息包被误解为 PPT |
| 一言堂 | Step 0 独立作业没匿名 |
| 跳过诊断 | Step 1 段 3 被压缩 |
| 伪共识 | Step 1 段 5 没记录异议 |

**标准**：陷阱 ≠ 通用管理鸡汤。每个陷阱指向上游某一步骤的具体失效。

---

## 四、攻击者配对：三要素齐全

T4 的 Christensen 攻击段落包含三个要素，缺一不可：

### 要素 1：学者身份+核心著作

```
Clayton Christensen（哈佛商学院教授，《创新者的窘境》作者）
```

不是"某管理学家认为"——有名有姓有 institution 有代表作。

### 要素 2：与本卡核心假设的精确冲突点

```
"好公司的战略会天然排斥颠覆性创新"
→ 冲突点：T4 假设"战略会能做出更好的方向选择"，Christensen 说"战略会的机制让好公司选择性地忽视颠覆"
```

不是"Christensen 也关心创新"——是精确命名了冲突。

### 要素 3：让使用者睡不着觉的问题（具体场景 × 直击要害）

```
"你们的战略会花了多少时间讨论'如果我们被一个从低端市场切入的颠覆者攻击，该怎么办'？答案是零——因为低端市场不在你们的数据包里。"
```

不是"所以你要注意创新"——是给出了一个使用者无法回避的具体拷问。

**标准**：每个攻击者段落必须具备三要素。缺任一要素→降级。

---

## 五、不要用场景：失效机制 + 替代方案

T4 的三个不要用场景，每个都包含：

1. **具体场景**（不是泛化的"不适合大公司"）
2. **失效机制**（为什么失效——引用学者理论解释因果关系）
3. **替代方案**（给出了可执行的替代做法，不只是"别用"）

```
场景：公司处于生存模式，现金流只够 3-6 个月
失效机制：Rumelt——战略需要"有选择余地"才能生效
替代方案："生存三问"——三个问题一个下午出答案
```

**标准**：≥2 个不要用场景，每个 ≥3 个要素（场景+机制+替代）。缺替代方案→降级。

---

## 六、Action Triggers：触发→动作→指标，三位一体

T4 的 4 个 AT，每个都满足：

- **触发是可观测的**（不是"当你觉得需要时"）
- **第一个动作是具体的**（不是"应该考虑使用本工具"）
- **成功指标是可验证的**（不是"团队更好了"）

```
触发：上季度战略执行很差，团队说"方向没问题，是执行的问题"
动作：做 Porter 式活动系统诊断——画图，逐条问"这个活动为战略改变了什么"
指标：至少识别 3 个"战略选 A 但活动仍为 B 服务"的错位
```

**标准**：≥3 AT，每个三位一体。缺指标→降级。

---

## 七、工程化防御：不止于"要小心"

T4 最高价值的设计：把"组织常见病"翻译成可操作的工程机制。

| 组织病 | 传统对策（弱） | T4 工程化防御（强） |
|--------|-------------|-----------------|
| 一言堂 | "鼓励大家发言" | 独立作业匿名提交 → 会前不能互相看 → 差异地图先亮出来 |
| 开完就算了 | "要跟进" | 会后三检查——24h 纪要 / 48h 传达 / 72h 活动检查 |
| 伪共识 | "确认大家都同意" | 记录异议 + 写进纪要 + 下季度复盘第一条过 |
| 没有撤销条件 | "保持灵活" | 段 5 必须产出 3 个撤销条件 + 定义"看什么数据判断" |

**标准**：至少 1 处"组织病→工程化防御"的翻译。越多越好。

---

## 八、跨域引用：密度 + 多样性

T4 的 9 个 related 覆盖 3 个域：

| 域 | 引用数 | 示例 |
|----|--------|------|
| yitang/management | 4 | strategy-meeting, goal-management, company-culture, meeting-designer |
| yitang/decision | 2 | y-model, full-process |
| master | 2 | decision-hygiene, knowledge-compound |

**标准**：≥3 个域，master 域 ≥1。纯 yitang 域的卡不算跨域。

## 九、自检清单

写完一张 tool 卡后，逐条过：

- [ ] 操作步骤：≥3 层深度（步骤名+时间/负责人+关键约束+产出）？
- [ ] 退出标准：≥3 条，每条有信号→诊断→动作？
- [ ] 常见陷阱：每个陷阱指向具体步骤的失效模式？
- [ ] 攻击者：≥2 位，每位三要素（身份+冲突点+睡不着问题）？
- [ ] 不要用场景：≥2 个，每个三要素（场景+机制+替代）？
- [ ] Action Triggers：≥3 个，每个三位一体（触发+动作+指标）？
- [ ] 工程化防御：≥1 处组织病→机制的翻译？
- [ ] 跨域引用：≥3 域，master ≥1？
- [ ] 攻击者是否与本知识库已有出场记录去重？（查 `kdo query "<attacker_name>"`）
- [ ] 不要用场景的替代方案是否引用了其他工具卡？（能引用 = 工具箱内部自洽）

## 十、最佳实践示例（T4 逐维拆解）

以下每段都是从 T4 原件截取，标注了对应标准维度。写卡时参照——不是抄主题，是匹配深度。

### 10.1 操作步骤五层深度

T4 Step 0 "会前四件套"的"独立作业"：

```
| **独立作业** | 会前 1 周 | 每个参会者 |
  独立回答 3 个问题（不超过 1 页纸）：
  ① 当前最大瓶颈是什么？
  ② 我们拥有什么独特的不对称优势？
  ③ 如果立刻砍掉 50% 业务，保留哪一半？
| 每人 1 页独立答案 |
```

> 五层全在：步骤名+时间+负责人+具体内容+产出。没有"应该做好准备"这类空话——直接给了 3 个具体问题。

### 10.2 关键约束 = 红线，不是提醒

```
- 如果有人不做独立作业，不允许参加战略会
  ——没有独立思考的参会者是噪音源
```

> 不是"建议提前准备"——是"不做就不能参会"。红线的标志：违反后有名确后果。

### 10.3 退出标准

```
- 参会者反馈"战略会只是老板想法的包装"
  → 独立作业和差异暴露环节没有真正执行
```

> 信号→根因，一步到位。不是"用户不满意时重新设计"——精确指向上游哪一步失效。

### 10.4 常见陷阱对应操作步骤

```
| **跳过诊断** | 直接进入"选 A 还是选 B" |
  段 3 必须分配 ≥30% 时间——主持人有权拒绝提前进入方向选择 |
```

> 陷阱名=操作步骤的失效模式。防御方案=给主持人一个具体权力（拒绝权）。

### 10.5 攻击者三要素（范例：Christensen）

**要素 1 — 身份**：
```
Clayton Christensen（哈佛商学院教授，《创新者的窘境》作者）
```

**要素 2 — 精确冲突点**：
```
好公司的战略会天然排斥颠覆性创新：你的战略会讨论的是"如何在现有业务上
做得更好"——但颠覆性创新从不来自"服务好现有客户"
```

**要素 3 — 睡不着的问题**：
```
"你们的战略会花了多少时间讨论'如果我们被一个从低端市场切入的颠覆者攻击，
该怎么办'？答案是零——因为低端市场不在你们的数据包里，不在你们的客户调研里。
但它可能正在某个车库发生。"
```

> 三要素全中：有名有姓 + 精确冲突 + 具体拷问。拷问指向了工具使用者的一个可验证行为（"你花了多少时间讨论 X"），不是泛泛的"所以你要注意"。

### 10.6 不要用场景的三要素（范例：生存模式）

```
场景：公司处于"生存模式"——现金流只够 3-6 个月
失效机制：Rumelt 指出——战略需要"有选择余地"才能生效。
  当公司只有一条路可走时，战略讨论是伪命题
替代方案："生存三问"——
  ① 接下来 30 天哪 3 个客户最可能付钱？
  ② 哪些成本可以立即砍掉？
  ③ 如果有机会把 runway 延长 2 个月——愿意付出什么代价？
  三个问题一个下午出答案，然后所有人去执行。
```

> 场景边界分明（3-6 个月），失效有学者背书（Rumelt），替代方案可执行（3 个具体问题+时间承诺）。

### 10.7 Action Triggers 三位一体（范例：异议档案）

```
触发：战略会讨论激烈，一号位拍板"就这么定了"，
  但散会后有人小声说"我觉得不对但我懒得说了"
动作：做"异议档案"——让每个有异议的人公开说
  "我的异议是什么、在什么条件下这个决策可能会错"。
  写进战略决策纪要，下季度复盘时第一条就过
指标：下一季度复盘时，至少有 1 条"异议被事后证明是对的"
  被公开承认——不是为了打脸，是为了证明"提异议是安全的"
```

> 触发可观测（散会后的小声抱怨）、动作精确（公开说的格式都给了）、指标反直觉（"至少 1 条异议被证明是对的"←不是零异议，而是异议有价值）。

### 10.8 工程化防御（范例：反一言堂）

| 组织病 | T4 机制 |
|--------|---------|
| 老板先发言，其他人附议 | 独立作业**匿名**提交，会前不能互相看答案 |
| 表面上都同意 | 差异地图先亮出来——"三个人对最大瓶颈的判断完全不同" |
| 散会后不执行 | 会后三检查——24h 纪要 / 48h 传达 / 72h 活动检查 |

> 每行是一个组织病→一个不可绕过机制的翻译。不是"要鼓励发言"——是没有发言前你先交了作业。
