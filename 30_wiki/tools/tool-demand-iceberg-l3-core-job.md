# L3圈定核心任务

> 如果L1/L2是"谁在什么情况下有什么问题"，L3就是"他们真正要完成什么"。关键：方案中立——不能用特定产品/技术的语言描述任务。

## JTBD核心任务公式

```
核心任务 = 动词 + 对象 + 语境
```

| 方案绑定（差） | 方案中立（好） |
|:---|:---|
| "用App点外卖" | "在不想做饭的晚上，快速获得一顿热饭" |
| "在淘宝上买衣服" | "为下周的面试准备一套得体的穿搭" |
| "用Zoom开会" | "和异地团队高效同步项目进度" |

## 为什么方案中立如此重要

一旦你在L3说了"用App点外卖"，你就已经把"App"这个方案锁死了。你不再会去想：也许用户真正需要的是"附近的食堂延长营业时间"或"预制菜配送"。

## Agent执行指令

```python
# 引自 AI场景推演教练 Step 2
prompt = """基于已确认的用户和场景，草拟3个不同视角的"核心任务陈述"。

要求：
- 格式：动词 + 对象 + 语境
- 方案中立——不能出现任何产品/技术名词
- 如果我选"用App点外卖"这类方案绑定的描述，提醒我重新用方案中立的语言

示例（差→好）：
  差："用外卖App点餐"
  好："在不想做饭的晚上，快速获得一顿热饭"
"""
```

## 失败模式

| 失败 | 症状 | 修复 |
|:---|:---|:---|
| 方案绑定 | 核心任务里出现了产品/技术名词 | 去掉所有方案词汇，只留动词+名词+情境 |
| 太宽泛 | "高效工作"——什么任务？ | 加动词+对象，直到可被观察和测量 |

## 适用边界

- **适用**：L2完成后，需要定义"用户究竟要什么"
- **不适用**：需求已经非常明确（如"修复已知Bug"）
