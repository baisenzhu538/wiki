# 一堂用户分层四步法（SABC 分级）

## 一句话

用户分层四步法是先明确阶段销售目标，再提出并验证分层假设，最后按 S/A/B/C 四级分配资源与跟进策略，让销售团队把有限兵力集中在最值得打的客户上的操作工具。

## Purpose

解决「销售资源有限，却不知道该把精力押在哪些客户上」的问题。通过把客户按当前阶段目标分为 S/A/B/C 四级，帮助团队停止平均用力，把最好的资源集中给最有可能带来业绩的客户，同时用低成本方式覆盖长尾客户。

## When to Use

- 线索量大但转化率低，销售团队陷入「谁都在跟、谁都跟不深」的平均用力状态。
- 销售精力和资源分散，管理层无法回答「本周最该押哪几个客户」。
- 高价值客户被大量低优先级线索淹没，S 级客户反而得不到足够关注。
- 新产品、新市场启动，需要快速识别第一批应该集中攻坚的客户画像。
- 销售业绩波动大，希望通过聚焦优质客户来稳定产出和现金流预测。

## 四步法

| 步骤 | 核心动作 | 关键问题 | 典型产出 |
|:---|:---|:---|:---|
| **1. 确定销售目标** | 明确本阶段最重要的 1–3 个指标：流水、收入、毛利、用户数、标杆客户等 | 公司这个阶段到底要什么？ | 1–3 个清晰、可衡量的阶段目标 |
| **2. 提出分层假设** | 从产品特性、行业常识、历史数据、同行案例、专家访谈等维度，提出「哪些客户可能是重点」的假设 | 哪些客户可能是重点？ | 3–5 个可验证的分层假设 |
| **3. 验证分层假设** | 有历史数据时做定量分析；数据不足时做定性测试 | 真正最重要的那批客户是谁？ | 经数据或访谈校准的分层标准 |
| **4. 全面执行分层** | 按客户等级分配资源、制定策略、匹配卖点和话术 | 如何集中优势兵力打主要客户？ | SABC 客户清单 + 资源分配表 + 跟进策略 |

### Step 1：确定销售目标

分层没有标准答案，它和目标高度相关。同一批客户，在「追利润」和「打标杆」两个阶段可能被分到不同等级。目标必须具体、可衡量，并且被销售团队理解，否则分层容易变成「拍脑袋」。

### Step 2：提出分层假设

假设不是凭空想象，而是基于可获取的信息快速提出可证伪的猜想。常见假设维度包括：客户规模、行业、采购周期、决策链复杂度、地域、客单价、复购潜力、推荐价值等。

### Step 3：验证分层假设

验证是四步法中最容易被跳过的一步。没有验证的分层只是新的「经验主义」。验证方法详见下一节。

### Step 4：全面执行分层

分层必须落地到三个动作：谁来跟、投入多少资源、用什么策略。只分级不分配，分层就是一张废纸。

## Protocol

1. **对齐目标**：与销售负责人确认本阶段 1–3 个核心目标（流水 / 收入 / 毛利 / 标杆客户），并明确分层将服务于哪个目标。
2. **列出假设**：从产品特性、行业常识、历史数据、同行案例、专家访谈中，提出 3–5 个「哪些客户更重要」的假设。
3. **选择验证方式**：
   - 有历史数据 → 做成交画像分析、漏斗分层转化率分析。
   - 数据不足 → 做成交 / 未成交客户访谈，或小范围试点。
4. **定义 SABC 标准**：根据验证结果，为 S/A/B/C 四级写下可识别的类型、特征和配套策略。
5. **分配资源与策略**：明确每个等级的责任人、跟进节奏、投入上限和配套话术 / 卖点。
6. **落地执行**：将分级清单导入 CRM 或跟进系统，确保一线销售可见、可执行。
7. **复盘迭代**：每月或每季度复核一次分层标准，根据目标变化和客户反馈调整等级边界。

## SABC 分级表

SABC 不是对客户做道德判断，而是对「当前阶段、有限资源下，客户值得投入多少精力」的管理约定。各等级边界必须根据业务目标动态调整。

| 级别 | 定义 | 资源分配原则 | 跟进策略 | 典型动作 |
|:---|:---|:---|:---|:---|
| **S 级** | 战略级客户：行业头部、高预算、高成交概率、强复购或推荐价值 | 销售总监 / Top sales 亲自跟进，投入最多时间与定制化资源 | 一对一深度经营，长期关系维护 | 周度拜访、专属方案、高管对接、季度复盘 |
| **A 级** | 重点客户：画像匹配、成交概率高、成长性好 | 资深销售专人负责，稳定投入 | 定期回访，纳入私域池，提供增值服务 | 双周跟进、案例营销、方案迭代 |
| **B 级** | 培育型客户：有需求但犹豫、比价明显、需多次触达 | 标准化服务，控制人力投入 | 自动化 / SOP 培育，活动激活，适时升级 | 月度群发、活动邀约、内容培育 |
| **C 级** | 长尾 / 低价值客户：成交率低、预算小、维护成本高 | 低成本触达或暂时放弃 | 自动化营销、自助服务、长期放养 | SOP 邮件 / 微信、FAQ、社群运营 |

**资源分配经验参考**：多数情况下，S 和 A 级客户应占据销售团队绝大部分有效精力，B/C 级通过自动化或低人力方式覆盖。例如涂料公司案例中，销售团队把约 80% 的精力集中在 Top 220 客户上，其余进入自动培育池。

## 分层假设来源清单

| 来源 | 用途 | 获取方式 |
|:---|:---|:---|
| **产品特性** | 判断哪些客户最能从产品差异化中获益 | 产品功能清单、客户成功访谈、交付复盘 |
| **行业常识** | 利用已知行业规律快速缩小假设范围 | 行业报告、从业者经验、供应链上下游反馈 |
| **历史数据** | 用成交记录反推高价值客户画像 | CRM 数据、订单数据、客户生命周期价值分析 |
| **同行案例** | 借鉴已被验证的客户选择逻辑 | 竞品分析、行业标杆拆解、同行访谈 |
| **专家访谈** | 弥补数据不足，获取隐性判断 | 销售冠军访谈、行业专家、头部客户深访 |

## 验证方法

### 定量分析（优先）

- **历史成交画像分析**：对已成交客户按规模、行业、来源、成交周期等维度分组，看哪一组转化率、客单价、复购率最高。
- **漏斗分层转化率**：把线索按假设标准分组，比较各组从线索 → 商机 → 成交的转化率。
- **相关性 / RFM 分析**：在数据量足够时，用 RFM（最近购买、购买频率、金额）或 LTV 模型辅助分层。

> 经验参考：定量分析至少需要几十条历史样本才具有参考意义；样本量过少时，结论只能作为假设，不能作为决策依据。

### 定性测试（数据不足时）

- **成交客户深访**：访谈 10–20 个已成交客户，了解他们为什么买、决策链如何、痛点排序。
- **流失 / 未成交客户深访**：访谈 10–20 个未成交或流失客户，验证「我们以为的重点客户」是否真的是高价值客户。
- **销售冠军经验萃取**：让业绩最好的销售列出他们心中最重要的 3–5 个客户特征，与数据假设交叉验证。
- **小范围试点**：先对一个细分群体集中投入 2–4 周，看转化效果是否显著优于平均水平。

## 案例嵌入

### 案例 1：快钱支付的商旅客户 SABC 分层

**背景**：团队最初只有 2–3 人，业绩完成率约 40%–50%，客户拓展没有章法，目标平均分配。

**分层过程**：
1. 明确阶段目标：追流水，快速放量。
2. 提出假设：航空公司、经济型连锁酒店等商旅场景客户，交易频次高、流水规模大。
3. 验证假设：分析历史成交客户，发现上述行业客户转化率显著高于其他行业。
4. 执行分层：将客户分为 S/A/B/C，集中资源打航空公司和连锁酒店，弱化长尾小商户。

**结果**：团队逐步扩张到约 40–50 人，业绩完成率稳定在约 85%–90%。

> 数字说明：以上数据来自课程经验分享，属于特定项目经验，不作为普适业绩保证。

### 案例 2：涂料公司从 10 万线索到 20 条 S 级

**背景**：涂料公司拥有约 10 万条注册线索，但销售分不清谁是真客户，精力被大量低质量线索稀释。

**分层过程**：
1. 明确目标：短期要利润，同时储备标杆客户。
2. 提出假设：按公司规模、项目类型、采购周期、地域等维度划分 S/A/B/C。
3. 验证假设：分析历史成交客户画像，并抽样访谈约 20 个已成交客户和约 20 个未成交客户。
4. 执行分层：从约 10 万线索中筛出约 20 条 S 级、约 200 条 A 级，其余进入自动化培育池。

**结果**：销售团队把约 80% 精力放在 Top 220 客户上，S 级客户转化率显著提升；B/C 级线索通过自动邮件、社群等方式低成本培育，不被浪费。

> 经验提示：这家公司同时配套了「零级 → 壹级 → 贰级 → 叁级 → S 级」的五级线索漏斗，每一级都有明确责任主体和转化率红线，分层不是一次性动作，而是持续过滤过程。

## Checklist

- [ ] 本阶段销售目标已明确到 1–3 个可衡量指标（流水 / 收入 / 毛利 / 标杆客户等）。
- [ ] 至少提出 3 个可验证的分层假设，并写明验证标准。
- [ ] 已检查历史数据质量：样本量、字段完整性、时间跨度是否足够。
- [ ] 对数据不足的假设，已设计定性验证方案（客户访谈 / 试点 / 专家验证）。
- [ ] S/A/B/C 四级定义已写入团队共享文档，并与当前目标挂钩。
- [ ] 每个等级已配套明确的资源分配、跟进策略和责任人。
- [ ] B/C 级客户已设计低成本培育或放弃机制，避免销售精力被稀释。
- [ ] 分层标准已设定复盘周期（建议每月 / 每季度复核一次）。
- [ ] 销售团队已培训分层逻辑，避免「挑客户」「只打 S 级」等执行变形。
- [ ] 涉及客户隐私的分层数据已做合规处理，避免歧视性使用。

## Anti-patterns

### Anti-pattern 1：平均分配线索

**症状**：每个销售拿到同样数量和质量的线索，S 级客户和 C 级客户混在一起。
**后果**：高价值客户得不到深度跟进，低价值客户消耗大量时间。
**修复**：按 SABC 等级分配线索，并对 S/A 级设置专门的资深销售或销售总监跟进。

### Anti-pattern 2：分层不做验证

**症状**：管理层凭直觉或行业经验直接定分层标准，不与历史数据或客户访谈交叉验证。
**后果**：分层标准与真实高价值客户脱节，资源押错方向。
**修复**：每个分层标准必须至少经过「历史数据 + 小规模试点」或「定量 + 定性」其中一种验证。

### Anti-pattern 3：脱离目标分层

**症状**：分层标准多年不变，或在不同目标下使用同一套标准。
**后果**：短期要利润时却押注低毛利客户，或打标杆时忽视长尾放量机会。
**修复**：每次重大目标调整时，重新审视 S/A/B/C 的定义和权重。

### Anti-pattern 4：只分层不分配策略

**症状**：只产出一份客户分级名单，但没有跟进策略、话术、资源配套。
**后果**：分级变成行政动作，一线销售不知道该怎么打。
**修复**：分层输出必须包含「谁跟、投入多少、用什么策略、匹配什么卖点」四要素。

### Anti-pattern 5：B/C 级直接丢弃

**症状**：只关注 S/A 级，把 B/C 级线索完全放弃。
**后果**：浪费已有线索资产，也可能错失未来会升级的客户。
**修复**：B/C 级进入低成本自动培育池，定期评估升级可能性。

## When NOT to Use

- **产品价值尚未验证**：如果产品本身没有被市场验证，分层只能帮你更快地把错误客户筛出来，而不是解决根本问题。应先用精益方法验证价值假设。
- **历史样本极少且无法做定性验证**：如果只有不到几十条线索，且无法访谈客户，分层标准基本靠猜，此时不如先密集跟进所有线索，积累数据后再分层。
- **销售团队只有 1–2 人且没有自动化工具**：人手极少时，分层的边际收益有限，反而增加管理成本。OPC 场景建议先用轻量智能体判断优先级。
- **一次性或短期项目**：分层适用于持续销售场景；单次 campaign 或短期突击更适合用项目制管理。
- **没有后续跟进和培育能力**：如果 B/C 级客户没有自动培育机制，分层后会被直接丢弃，造成线索浪费。

## OPC 智能体适配

对一人公司（OPC）而言，「用户分层四步法」可以压缩为一个可直接调用的智能体判断：**这个客户值不值得我亲自跟？**

### 输入

- 客户基础画像（行业、规模、角色、来源）。
- 客户与创始人的对话记录（微信 / 邮件 / 通话转写 / CRM 备注）。
- 可选：当前阶段目标（追利润 / 打标杆 / 跑通案例）。

### 输出

- **S/A/B/C 建议等级** + 简要理由。
- **建议投入精力**：例如「值得本周安排一次 30 分钟电话」「可放入月度培育清单」。
- **下一步动作**：该做什么、不该做什么。

### System Prompt 核心逻辑（精简版）

```text
你是一名销售分层顾问。请根据用户提供的客户画像和对话记录，按以下规则判断：
1. 先问：当前阶段最重要的销售目标是什么？（利润/标杆/放量）
2. 从产品匹配度、预算/规模、成交概率、决策链复杂度四个维度打分。
3. 给出 S/A/B/C 等级，并说明理由。
4. 建议创始人投入多少精力，以及下一步具体动作。
5. 如果信息不足，列出还需要确认的 2–3 个问题。
```

### 边界提示

- AI 只提供分层建议，最终是否亲自跟进由创始人判断。
- 涉及客户隐私的对话数据需本地或合规处理，不宜直接上传至不可控的第三方模型。
- 分层不替代关键信任建立，S 级客户的重要沟通仍应由人主导。

## Critique

### 外部质疑 1：统计学派认为 SABC 过度简化

**质疑**：客户价值往往是连续分布，四级切分会损失信息，边界人为且粗糙。
**回应**：SABC 本质是管理简化工具，不是统计模型。对需要精细预测的场景，可以在 S/A/B/C 内部再引入打分卡或 RFM 模型作为补充。

### 外部质疑 2：关系型销售认为大客户无法被分层

**质疑**：大客户决策受隐性关系、组织政治、个人信任影响，分层标准无法捕捉这些变量。
**回应**：分层解决的是「值得跟谁」而不是「怎么赢得信任」。对复杂大客户，分层后仍需配合关系经营、决策链分析和长期跟进。

### 外部质疑 3：组织行为学担心分级引发士气问题

**质疑**：公开的客户分级可能让销售产生「挑客户」「抢资源」的道德风险，也可能让被分到 C 级的客户受到歧视。
**回应**：分级标准应基于商业属性而非个人属性，且需与过程管理、激励机制配套，避免「只看结果、只看等级」。对客户的服务边界和隐私保护应写入团队规范。

### 外部质疑 4：**Michael Porter** 战略定位派认为分层只是运营效率工具

**质疑**：Porter 会认为 SABC 分层只解决了「把资源投给谁」的运营效率问题，却没有回答「为什么选择这群客户能强化企业战略定位和护城河」。如果竞争对手用同样的分层逻辑，优势会被快速抵消。
**回应**：用户分层是必要但不充分的工具。它应与价值主张、竞争策略、客户选择逻辑结合，确保分层结果服务于企业的长期差异化定位，而不是单纯的内部效率优化。

### 内部局限 1：高度依赖数据质量

分层效果取决于历史数据的完整性、准确性和样本量。初创公司或新产品早期往往数据不足，此时分层更多是假设驱动的方向判断，需要配合快速试点迭代。

### 内部局限 2：只解决「选谁」，不解决「怎么打动」

用户分层告诉你该优先打哪些客户，但没有告诉你如何提炼卖点、设计销售动作。它必须与 `[[tool-yitang-value-proposition-4step]]` 和 `[[tool-yitang-sales-process-decomposition]]` 配合使用，否则容易出现「找到了重点客户，但还是拿不下」的情况。

## 边界与风险提示

- **数据隐私**：客户分层可能涉及个人信息、交易记录、沟通内容。使用这些数据时需遵守所在司法辖区的数据保护法规，避免未经授权收集或滥用。
- **公平性**：分层应基于与交易相关的商业属性（如规模、需求匹配度、采购周期），避免基于性别、年龄、地域、民族等受保护特征进行歧视性排序。
- **数字性质**：本卡中引用的完成率、转化率、客户数量等数字来自课程经验分享，属于特定项目经验，不应被当作普适业绩保证。
- **法律声明**：本卡仅提供销售管理公共知识扫盲，涉及合同、提成、客户权益等法律判断时，需由专业机构复核。

## Synthesis

- `[[framework-demand-validation-pipeline]]`：四步法中的「提出假设 → 验证假设 → 执行」与该框架的假设验证流程同构，只是聚焦在销售客户选择场景。
- `[[concept-一堂-hypothesis-driven-business-methodology]]`：用户分层本质上是一套假设驱动的业务决策：先猜谁重要，再用数据验证，最后规模化执行。
- `[[tool-iceberg-triangle-modeling]]`：冰山模型帮助识别客户分层中容易被忽视的隐性变量（如决策链、组织政治、使用场景），避免只看表面标签。
- `[[master-decision-hygiene]]`：SABC 分级的底层逻辑是资源稀缺下的优先级决策，需要配合决策卫生避免认知偏差（如锚定效应、可得性偏差）。
- `[[yt-five-step-method-complete]]` / `[[yitang-methodology-system]]` / `[[framework-一堂五步法-泛产品设计]]`：本工具是一堂五步法在「销售管理 → 提炼卖点」环节的专项实例化，强调从通用方法论到销售场景的操作落地。
- 未来可与 `[[framework-yitang-scientific-sales-five-step]]` 形成总分关系，作为科学销售五步法 Step 1 的核心工具卡。
