# 技能：Problem与Question区分法

- 待补充链接

## 原始表述

Problem与Question区分法是纪浩在AI协作方法论分享中提出的具体方法，用于Problem与Question区分法。

## 操作步骤

1. 判断当前面对的是Question还是Problem：Question只需信息答案即可结束，Problem需要现实状态改变
2. 确认遇到的是Problem后，追问四层验证：解决前的状态vs解决后的状态（Before-After）
3. 验证真实锚点：是否有具体场景、具体问题现场，而非想象需求
4. 确认受益人：解决后是否有人实打实获得好处或便利
5. 验证可解性：是否有因果链、能力支撑，相信问题可被解决
6. 四层验证不通过则不下场动手，避免在错误问题上投入

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 用AI烧了很多token但产出无用时，需要区分problem/question |
| ✅ 适合 | 准备让AI动手解决某个问题前，做前置验证 |
| ✅ 适合 | 需求似乎无限放大、边界模糊时，需要收敛 |
| ✅ 适合 | 不确定是否是伪需求时，做快速筛选 |
| ❌ 不适合 | 纯粹的信息检索和知识学习 → question不需要验证 |
| ❌ 不适合 | 明确已知答案的标准化问题 → 直接执行 |
| ❌ 不适合 | 探索性、发散性的创意brainstorm → 过早验证扼杀创意 |
| ❌ 不适合 | 紧急救火场景 → 先解决后验证 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **token浪费** | 用AI烧了很多token但产出无用，没有区分problem/question | 每次向AI提问前3秒判断：这个问题解决后我的行为会改变吗？会=problem，不会=question |
| **需求膨胀** | 需求似乎无限放大、边界模糊 | 四层验证不通过则不下场动手。Before-After不清晰、锚点不具体、受益人不明确、可解性不足=暂停 |
| **伪需求陷阱** | 在错误问题上投入大量资源，最后发现是伪需求 | 四层验证是前置门禁，不是事后复盘。必须在动手前完成验证 |
| **伪装problem** | 把question包装成problem，逃避行动检验 | 用before/after检验：能不能写出具体的before/after？写不出就是question |
| **验证宽松** | 四层验证通过但执行失败，验证标准太松 | 四层验证必须严格：before/after可观察、锚点具体到时间地点、受益人可命名、可解性有因果链 |
| **验证跳过** | 觉得验证麻烦，直接动手 | 设定验证时间上限（5分钟）。快速验证比事后补救成本低100倍 |
| **混淆层次** | problem和question的区分标准不清晰 | 核心标准：解决后行为是否改变。不改变=question，改变=problem |
| **验证后不作为** | 验证通过了但不行动，停留在认知层面 | 验证通过=绿灯，必须立即进入执行或四要素详细验证。验证不行动=没验证 |

## 为什么有效

AI时代AI能执行工具改变现实世界，区分Problem与Question避免将token浪费在无需行动的信息收集上；四层验证防止伪需求，降低在错误方向上的沉没成本。
