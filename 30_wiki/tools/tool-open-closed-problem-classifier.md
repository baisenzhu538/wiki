# 开放/封闭问题分类器：判断任务该交给 AI 控制台还是 Agent 平台

> **Burn line**: 不是所有问题都适合自动化。先把任务分成「开放问题」和「封闭问题」，再决定是让 AI 当副驾保护你的心流，还是让 Agent 平台工业化地跑。

---

## 一句话

一个 7 问决策工具，帮你判断一项任务属于**开放问题**（需要人的探索、判断、品味）还是**封闭问题**（目标、标准、边界清晰，可自动化），并推荐对应的协作形态：AI 控制台、Agent 平台或混合。

---

## 1. 核心概念

| 维度 | 开放问题 | 封闭问题 |
|:---|:---|:---|
| **定义** | 没有标准答案，需要探索、创造、判断的问题 | 有明确对错/完成标准，可验证、可重复的问题 |
| **典型特征** | 目标模糊、路径未知、需要灵感 | 目标清晰、路径确定、可检查 |
| **人的角色** | 主导者：定义问题、判断方向、守护品味 | 边缘节点：仅在异常/权限/物理障碍时介入 |
| **AI 的角色** | 超级副驾：脑暴、扩展思路、保护心流 | 调度中心：自动执行、工业化闭环 |
| **协作形态** | **AI 控制台** | **Agent 平台** |
| **失败信号** | 强行自动化、用 AI 逃避理解 | 把开放问题硬塞给 Agent、人在 loop 中沉睡 |

> 来源：拆书稿「闲庭落木：开放问题由人驱动，封闭问题由 AI 驱动」[待验证观点]；口述稿 L2138-L2168 对两类问题的展开说明。

---

## 2. 七问判别法

对任意任务依次回答以下 7 个问题。回答「是」越多，越偏向封闭问题；回答「否」越多，越偏向开放问题。

| # | 问题 | 开放问题倾向 | 封闭问题倾向 |
|---:|---|---|---|
| 1 | 任务的**成功标准**是否已经明确且可验证？ | 否 | 是 |
| 2 | 任务的**输入、输出、边界**是否可以被清晰描述？ | 否 | 是 |
| 3 | 任务是否存在**已知且稳定的最佳实践/SOP**？ | 否 | 是 |
| 4 | 任务失败时，是否能**快速、低成本地回滚或修正**？ | 否 | 是 |
| 5 | 任务执行过程中，是否需要频繁做出**价值判断/审美选择**？ | 是 | 否 |
| 6 | 任务是否需要**探索未知路径或产生从未有过的想法**？ | 是 | 否 |
| 7 | 任务的**代价是否主要是执行成本**（而非判断失误成本）？ | 否 | 是 |

**计分规则**：
- 问题 1-4、7 答「是」得 1 分；问题 5-6 答「否」得 1 分。
- **5-7 分**：封闭问题 → 优先 Agent 平台
- **2-4 分**：混合问题 → 拆解后分别处理
- **0-1 分**：开放问题 → 优先 AI 控制台

> 注：本分类器为启发式工具，非数学模型。临界分数可根据团队风险偏好调整。

---

## 3. 决策树

```
开始
│
├─ 成功标准是否明确？
│   ├─ 否 → 开放问题 → AI 控制台（人主导，AI 脑暴）
│   └─ 是 → 继续
│
├─ 是否存在稳定 SOP 或最佳实践？
│   ├─ 否 → 混合问题 → 拆解为子任务后再分类
│   └─ 是 → 继续
│
├─ 执行中是否需要大量审美/价值判断？
│   ├─ 是 → 开放问题（子集）→ AI 控制台
│   └─ 否 → 继续
│
├─ 失败是否可快速回滚？
│   ├─ 否 → 高风险封闭问题 → Agent 平台 + 强人在环
│   └─ 是 → 继续
│
└─ 是封闭问题 → Agent 平台（AI 主导，人处理异常）
```

## 4. 推荐协作形态

| 分类结果 | 推荐形态 | 关键动作 | 人不做什么 |
|:---|:---|:---|:---|
| **开放问题** | AI 控制台 | 用 AI 扩展思路、快速原型、A/B 对比、保护探索者心流 | 不急于自动化、不跳过理解 |
| **封闭问题** | Agent 平台 | 设计 loop、自动触发、监控异常、持续优化 | 不睡觉守夜、不在每个步骤 micro-manage |
| **混合问题** | 拆解后分别处理 | 把任务拆成开放子任务 + 封闭子任务，分别进入不同形态 | 不试图用一个形态解决所有子问题 |

---

## 5. 操作步骤

### Step 0：写下任务的一句话描述
如果一句话说不清楚，说明任务还没被定义清楚，先回到 AI 控制台做问题澄清。

### Step 1：跑七问
逐题回答，记录分数。不要凭直觉，要对每个问题给出具体证据。

### Step 2：看决策树
结合分数和决策树，给出初步分类。

### Step 3：检查例外
问自己：
- 这个任务是否涉及高风险决策？（即使封闭，也需要强人在环）
- 这个任务是否会影响他人？（需要额外审批/确认节点）
- 这个任务的「完成标准」是否会被团队不同成员理解不同？（如果是，先对齐标准）

### Step 4：选择形态并执行
根据分类结果选择 AI 控制台或 Agent 平台，并在执行 1-2 个周期后复盘分类是否正确。

## 6. 失败模式

| 失败模式 | 症状 | 根因 | 修复动作 |
|:---|:---|:---|:---|
| **把开放问题硬塞给 Agent 平台** | AI 跑出来的结果「完成了但不对」；团队抱怨 AI 不懂业务 | 开放问题的成功标准本身需要迭代，无法被预设 | 切回 AI 控制台，先用人+AI 共同定义「对」的标准 |
| **把封闭问题留在 AI 控制台** | 人反复做同样的判断，AI 只是聊天搭子 | 低估了任务的自动化潜力 | 提取判断标准，封装成 Agent 平台的规则/检查点 |
| **混淆「可验证」和「已验证」** | 以为任务有标准，实际标准未经过真实场景检验 | 把假设当事实 | 先跑小规模真实案例，验证标准后再自动化 |
| **忽视混合问题的拆解** | 一个任务里开放和封闭部分互相牵制，效率低下 | 没有按子任务分类 | 用工作流拆解，把封闭子任务自动化，开放子任务保留人在环 |
| **人在环中沉睡** | Agent 平台长期运行，人不再审核输出 | 自动化带来虚假安全感 | 设定强制审核节点和随机抽检机制 |

---

## 7. When NOT to Use

- 任务本身还没有被清晰定义时（先不要用分类器，先用 AI 控制台澄清问题）。
- 团队对「成功标准」没有共识时（分类结果会被争议）。
- 任务涉及伦理、法律、安全等高敏感域时（分类器只给形态建议，不给风险授权）。

## 9. Mini Case

**场景**：一个内容团队想用 AI 生产短视频脚本。

- **开放问题**：「这个月的选题方向是什么？」——需要市场洞察、用户情绪判断、品牌调性把握 → AI 控制台。
- **封闭问题**：「把已确定的选题扩展成 10 个标题，按点击率排序」——有明确输入输出 → Agent 平台。
- **混合问题**：「根据爆款脚本结构，批量生成初稿」——结构是封闭的，但初稿质量需要审美把关 → 先 Agent 平台生成，再 AI 控制台审稿。
