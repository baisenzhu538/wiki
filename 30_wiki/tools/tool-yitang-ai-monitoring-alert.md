# AI监控/预警

> 设置自动化监控，让AI帮你盯住竞对的一举一动——不用每天手动搜索。

**监控对象**：竞对官网更新、招聘JD变化、融资新闻、社交媒体动态、产品页面改动、App更新日志。

**工具**：Google Alert + AI爬虫 + 飞书/企微机器人推送。竞对一有动作，你第一时间知道。

**价值**：从"定期调研"升级为"持续监控"。竞对的新动向不再是"偶然发现"，而是"自动推送"。

**坑**：信息过载——设置过滤规则，只推送高信号变化。

## Purpose

本工具用于建立对竞争对手、行业关键玩家及市场信号的自动化、持续性监控体系。通过AI爬虫、关键词订阅与即时推送，把"想起来才搜"的被动调研，转变为"有变化即触达"的主动情报流。适用于竞争节奏快、信息源分散、需要第一时间响应对手动作的业务场景。

## Protocol

1. **定义监控范围**：列出核心竞争对手、关键人物、产品关键词、行业事件标签，并区分"必须即时知道"与"每日摘要即可"两级信号。
2. **搭建信息源矩阵**：将官网、招聘网站、新闻站点、社交媒体、应用商店、财报披露等来源映射到对应的抓取或订阅工具（如 Google Alert、RSS、AI 爬虫、官方 API）。
3. **设置过滤与降噪规则**：用关键词组合、变化阈值、情感得分、去重逻辑剔除低信噪比信息，避免推送淹没。
4. **接入推送渠道**：把高优先级告警接入飞书/企微/钉钉机器人，低优先级汇总为日报或周报。
5. **建立复核闭环**：每周抽取 5-10 条推送做人工复核，评估误报/漏报率，持续优化监控词与阈值。

## When NOT to Use

| 场景 | 原因 | 替代方案 |
|---|---|---|
| 竞争对手信息极少或处于 stealth 阶段 | 可监控信号不足，自动化回报极低 | 采用人脉情报或定向访谈 |
| 对单一事件的短期追踪 | 搭建成本高于收益 | 使用一次性人工搜索 + 新闻订阅 |
| 需要深度因果解释 | 监控只能捕捉"发生了什么"，不能解释"为什么" | 结合 [[tool-yitang-research-deep-attribution]] 或专家访谈 |
| 涉及非公开敏感信息 | 自动化抓取可能触碰法律与合规边界 | 改用合规渠道与法务评估 |

## 质疑

- **具体假设**：本工具假设"公开信息的变化足以反映竞争态势"，但若对手刻意释放噪音或隐藏真实意图，监控结果可能变成反向误导。
- **边界**：自动化监控擅长捕捉"显性变化"（价格、JD、融资、产品更新），却难以识别"隐性变化"（组织张力、战略转向、未公开实验）。
- **反例**：某 SaaS 厂商通过监控发现对手降价 30%，随即跟进；三个月后对手悄然撤回折扣并推出高端版本——跟随者因过度反应而损伤品牌与利润。
- **前提**：有效运行的前提是监控词、阈值、过滤规则持续被人校准；一旦缺少人 loop，系统会快速退化为准垃圾信息流。

外部反对者 **Michael Porter** 可能会批评：竞争情报的价值不在于信息数量，而在于对产业结构与战略定位的深刻理解。自动化监控若只追逐新闻流，容易让团队陷入"活动幻觉"，把"知道得更多"误当成"理解得更深"。
