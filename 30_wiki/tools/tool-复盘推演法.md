# 技能：复盘推演法

## 原始表述
> L3.复盘推演 √复盘过去：复盘过去的成败得失 √推演未来：推演下一步具体工作 √角色扮演：带入角色解决高难问题

## 操作步骤
1. 复盘过去：系统回顾成败得失
2. 推演未来：基于复盘推演下一步具体工作
3. 角色扮演：代入特定角色解决高难度问题

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 项目/阶段结束后，需要系统回顾成败得失 |
| ✅ 适合 | 面临重大决策前，需要推演降低风险 |
| ✅ 适合 | 需要突破能力瓶颈时，角色扮演突破视角局限 |
| ✅ 适合 | 团队学习，需要萃取可复制的因果链 |
| ❌ 不适合 | 日常微任务 → 复盘成本超过收益 |
| ❌ 不适合 | 情绪未平复时 → 归因会带有情绪偏差 |
| ❌ 不适合 | 没有行动验证条件 → 推演变成纸上谈兵 |
| ❌ 不适合 | 团队缺乏心理安全感 → 复盘变成追责大会 |

## 常见失败模式

| 失败模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **复而不盘** | 只列出"做了什么"，没有追问"为什么这次能成/会败" | 强制写出 3 条"因为 X，所以 Y"的因果链，并标注哪些因素可控 |
| **归因情绪化** | 把失败归结为"我不行""同事不靠谱"，无法指导下次行动 | 把结论改写成系统/行为/信息三类因素，例如"需求变更未同步" |
| **只复不推** | 分析了很多，但下一步仍停留在"以后注意" | 复盘结尾必须产出"谁在什么时间前做什么"的行动清单 |
| **推演缺约束** | 推演未来时只画理想路径，没考虑资源、时间和风险 | 每个推演结论都要配一个"如果 X 不发生，Plan B 是什么" |
| **角色扮演走形式** | 代入角色后仍在用自己的视角说话 | 先列出"这个角色和我的 3 个关键差异"，再开始推演 |
| **验证闭环断裂** | 上次复盘定的行动，这次没有检查是否执行、是否有效 | 把"检查上次行动效果"列为本次复盘的第一议程 |
| **成功经验浪费** | 只复盘失败，对成功一句"运气好"带过 | 对成功案例同样追问"哪些因素可复制"，并沉淀到工具/清单 |
| **复盘变批斗** | 讨论聚焦在"谁的错"，成员开始防御 | 约定规则：只讨论流程、数据和决策，不评价个人动机 |

## 判断标准

**什么算一次好的复盘推演**：

| 标准 | 好的复盘 | 坏的复盘 |
|:---|:---|:---|
| 有因果链 | 找到了"因为 X 所以 Y"的可复制因果逻辑，而不是"不够努力" | 停留于描述"做了什么"——复而不盘 |
| 正反都复盘 | 成功案例也拆解因果链：什么因素导致了成功？可复制吗？ | 只复盘失败——成功的因果链同样需要萃取 |
| 推演具体 | 复盘最后产出了"下周具体做什么"的行动清单 | 知道哪里错了但下一步计划模糊到"以后要注意" |
| 有验证闭环 | 推演的行动被实践了，并且下次复盘时检查了效果 | 复盘完了没有动作——复盘的价值在行动不在记录 |

**自检问题**：
1. 这次复盘我找到了几个"可复用的因果逻辑"？如果不到 1 个，说明复盘太浅。
2. 推演的行动中，最具体的那个是什么？如果写不出来"下周一做 X"，就是不够具体。
3. 上次复盘后的行动，这次检查了吗？——没有检查的复盘等于没做。
