# 场景设计语言转译：把场景需求变成可执行设计约束

> 没有业务理解的调研只是高级刷信息流。把「它要用在哪」翻译成「这里要清晰、那里要克制」，设计判断才有落脚点。

## 不要用的场景


- 场景设计语言转译：把场景需求变成可执行设在监管合规要求严格的场景中不要自行判断——需要法务或合规团队参与审核。
- 团队缺乏场景设计语言转译：把场景需求变成可执行设相关领域基础认知时不要用——工具会放大认知偏差而非纠正它。先建立基础共识。
- 刚接触场景设计语言转译：把场景需求变成可执行设的新手不要直接用——先通过3-5个真实案例建立体感，否则执行只是走流程。

## 质疑


- **具体假设**：场景设计语言转译：把场景需求变成可执行设工具假设结构化方法论能产生正确结论，但结论质量取决于输入数据和执行者判断力。
- **边界**：在场景设计语言转译：把场景需求变成可执行设相关的数据稀缺或快速变化场景中，已有经验框架可能完全失效。
- **反例**：团队在场景设计语言转译：把场景需求变成可执行设任务中完整执行了所有步骤，但核心假设从一开始就是错的。
- **前提**：使用者已具备场景设计语言转译：把场景需求变成可执行设领域的基础认知，且数据来源具有代表性。

**Eric Ries**（精益创业创始人）会质疑：方法论的有效性取决于执行者的判断力和场景适配——没有判断力的执行只是走流程。

## 操作步骤


1. 场景设计语言转译：把场景需求变成可执行设问题定义——写下要解决什么、为谁解决
2. 信息收集——找3个以上数据源
3. 结构化拆解——按框架逐项分析
4. 假设验证——对每个关键假设设计验证方案
5. 输出与迭代——形成文档并定期更新

## 目的


系统化解决场景设计语言转译：把场景需求变成可执行设中的常见陷阱——通过前置检查和后置验证，将错误率降到最低。

## 一、Purpose：目的

帮助设计者和业务方把交付物的使用场景，转译成可执行、可讨论、可验收的设计语言：

- **清晰**：信息必须被快速识别（如远距离、小尺寸）。
- **克制**：避免过度设计导致识别成本增加（如复杂渐变、过多色彩）。
- **强化辨识度**：在同类噪音中一眼被记住（如独特负形、高对比色块）。

## 二、When to Use：适用场景

- 商标、Logo、品牌图形需要适配线上线下多场景。
- 海报、详情页、包装需要在不同尺寸和媒介中保持一致性。
- 团队对「好设计」争论不休，需要把主观判断转译为客观约束。
- 与 AI 协作生成视觉交付物时，需要给 AI 明确的设计约束而不是抽象形容词。

## 三、Input：输入

1. **场景清单**：交付物会出现的所有场景（线上店铺、头图、包装、社媒头像、平台备案等）。
2. **SABC 分级**：按业务重要性把场景分成 S/A/B/C 四级。
3. **呈现形式与约束**：每个场景的尺寸、观看距离、停留时长、背景环境、色彩模式。

## 四、Steps：五步转译流程

### Step 1：MECE 场景分类

和 AI 死磕分类原则，确保场景不重不漏。常用维度：

- 线上 / 线下
- 远距 / 近距
- 静态 / 动态
- 单色 / 彩色
- 大尺度 / 小尺度

### Step 2：标注呈现形式与约束

每个场景填写：

| 字段 | 说明 |
|:---|:---|
| 场景 | 具体使用位置 |
| 呈现形式 | 图标、头图、包装、水印、社媒头像等 |
| 尺寸范围 | 最小显示尺寸到最大显示尺寸 |
| 观看距离 | 远距离扫视 / 近距离阅读 |
| 背景环境 | 白底、黑底、复杂图片、动态视频 |
| 色彩模式 | RGB、CMYK、黑白、专色 |

### Step 3：SABC 分级

| 级别 | 含义 | 设计投入权重 |
|:---|:---|:---|
| S | 高频 + 高转化 + 品牌第一印象 | 最高 |
| A | 重要但非决定性场景 | 高 |
| B | 中等频率或辅助场景 | 中 |
| C | 低频或仅合规露出的场景 | 低 |

### Step 4：转译设计语言

把场景约束转译为设计动作：

| 场景约束 | 设计语言 |
|:---|:---|
| 远距离、小尺寸 | 需要高对比、简洁图形、避免细线 |
| 复杂背景 | 需要留白或反白版本 |
| 多色彩模式 | 优先黑白稿，再扩展彩色 |
| 多语言渠道 | 图形优先，文字系统后置 |
| 快速识别 | 强化视觉记忆点，控制元素数量 |

### Step 5：输出设计约束表

汇总为一张表，作为后续设计、评审、AI 提示词的依据。

## 五、Output Template：输出模板

| 场景 | 呈现形式 | 关键约束 | 设计语言 | 优先级 |
|:---|:---|:---|:---|:---:|
| 亚马逊店铺头像 | 圆形/方形小图标 | 最小 80×80px；常与其他品牌并列 | 高对比、图形简洁、无细线 | S |
| 产品包装主视觉 | 中大尺寸印刷 | 可能 CMYK；需与竞品并置 | 强记忆点、色块克制、留白充足 | S |
| 社媒头像 | 圆形裁切 | 小尺寸；动态信息流中一闪而过 | 中心聚焦、边缘少细节 | A |
| 详情页水印 | 小尺寸、半透明 | 不能干扰商品信息 | 低存在感、单色 | B |
| 平台备案材料 | 矢量文件 | 黑白优先；无渐变 | 清晰可识别、格式规范 | C |

## 六、Example：Live81 喵善养商标场景矩阵

以 meow sayang 宠物用品出海商标为例：

| 场景 | 呈现形式 | 关键约束 | 设计语言 | 优先级 |
|:---|:---|:---|:---|:---:|
| 亚马逊/东南亚平台店铺头像 | 小图标 | 多国用户、快速识别、与其他品牌并列 | 图形优先、MS 负形清晰、高对比 | S |
| 产品包装（袋/盒） | 中大印刷 | 货架陈列、可能彩色也可能单色 | 包裹感猫咪图形、色块克制、留白 | S |
| 独立站/详情页头图 | 横版 Banner | 可放大、需与文字系统配合 | 可扩展、不抢商品风头 | A |
| 社媒头像（TikTok/IG） | 圆形裁切 | 小尺寸、动态环境 | 中心聚焦、边缘干净 | A |
| 邮件签名/水印 | 小尺寸 | 低存在感 | 单色、简化版 | B |
| 平台备案/商标注册材料 | 矢量文件 | 黑白、无装饰 | 规范、清晰、可注册 | C |

> 这个表格最大的价值，是把「场景信息」翻译成「设计判断」：哪些地方要清晰，哪些地方要克制，哪些地方要强化辨识度。

## 七、Anti-patterns：典型反模式

| 反模式 | 症状 | 修复 |
|:---|:---|:---|
| 分类重叠遗漏 | 同一个场景被分到两类，或漏掉重要场景 | 用 MECE 原则重新检查线上/线下、远/近、静/动等维度 |
| 只列场景不分级 | 所有场景投入相同精力 | 按业务影响做 SABC 分级 |
| 设计语言停留在形容词 | 「要高级」「要可爱」 | 转译为线条、比例、留白、对比度等可度量描述 |
| 忽略小场景 | 只看 S 级场景 | C 级场景（如备案）可能决定合规，不能遗漏 |
| 一次性输出不再更新 | 场景变化后约束表失效 | 每次业务迭代时同步更新 |

## 八、Checklist：≥8 项自检

- [ ] 场景分类是否 MECE（不重不漏）？
- [ ] 每个场景是否标注了呈现形式和尺寸约束？
- [ ] 是否按 SABC 对场景做了业务优先级分级？
- [ ] 每个场景是否都转译成了可执行设计语言？
- [ ] 设计语言是否避免停留在「高级」「好看」等形容词？
- [ ] 是否同时考虑了线上和线下、彩色和黑白、大尺度和小尺度？
- [ ] C 级场景（如合规、备案）是否被遗漏？
- [ ] 约束表是否被用于后续 AI 提示词和评审？
- [ ] 业务场景变化时，约束表是否同步更新？

## 九、Critique：质疑与局限

### 外部反对者

1. **资深设计师**：「真正的设计直觉不需要这么机械地列表，过度结构化会扼杀创意。」
   - 回应：本工具面向的是非专业设计者或与 AI 协作的场景，结构化是防止拍脑袋；专业设计师可以把它当作与业务方对齐的语言。
2. **业务方**：「我只要一张图，为什么要花时间列这么多场景？」
   - 回应：前期 10% 的时间对齐场景，能避免后期 50% 的返工；场景遗漏导致某个渠道无法使用，成本更高。
3. **AI 工具派**：「未来 AI 可以自动识别所有使用场景并生成适配版本。」
   - 回应：AI 可以辅助枚举和整理，但业务优先级（SABC）和「哪些场景必须放弃」仍需人决策。

### 内部局限

1. **依赖业务输入**：如果业务方自己都不清楚产品会出现在哪些场景，约束表会流于形式。
2. **无法穷尽所有场景**：出海业务常出现未预期的渠道，约束表需要动态更新。
3. **设计约束可能被误当设计答案**：约束表说「要简洁」，但简洁的具体形态仍需人判断。
