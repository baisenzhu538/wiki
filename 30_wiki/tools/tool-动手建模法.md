# 技能：动手建模法

## 原始表述
> L3.动手建模 √整理框架：梳理流程方法 √提炼本质：挖掘底层原理

## 操作步骤
1. 整理框架：把学到的内容梳理为流程方法
2. 提炼本质：挖掘底层原理和核心要素

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 学习后需要内化时，把知识转化为自己的产出 |
| ✅ 适合 | 需要传授他人或标准化时，建立可复用的框架 |
| ✅ 适合 | 复杂问题需要结构化分析时，降低认知负荷 |
| ✅ 适合 | 团队知识沉淀，需要统一认知语言 |
| ❌ 不适合 | 仅为了解常识，无需深入应用 → 建模成本超过收益 |
| ❌ 不适合 | 问题过于简单，一句话能说清 → 过度建模 |
| ❌ 不适合 | 没有使用场景，建完即弃 → 浪费建模投入 |
| ❌ 不适合 | 信息不足，无法提炼本质 → 强行建模产出空架子 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **建空架子** | 搭了MECE框架但里面没内容，只有分类没有洞察 | 框架分类下面必须有具体的行为标准、判断依据，不能只有框架没有洞察 |
| **建完不迭代** | 第一版模型用了一年没更新 | 模型是假设，需要持续验证和修正。超过1个月没用可能已过时 |
| **建完不用** | 模型写得很漂亮但日常工作中从不参考 | 建模的目的是用不是看，过去一个月至少用这个模型解决过一个真实问题 |
| **过度建模** | 把一个简单概念建了三层模型，复杂度超过实用价值 | 好的模型别人照着步骤能执行并得到相近结果，太抽象或太复杂都是坏模型 |
| **维度不客观** | 模型里的分类，不同人/不同时间分类结果不一致 | 分类维度应该可操作、可复现、可量化，不同人/不同时间结果一致 |
| **本质提炼失败** | 模型停留在现象层面，没有触及底层原理 | 建模必须回答"为什么"，找到可迁移的底层逻辑，不只是描述"是什么" |
| **框架僵化** | 模型一旦建立就拒绝修正，即使现实已变化 | 模型是假设不是真理，定期用真实案例检验，发现例外立即修正 |
| **协作断层** | 模型只有作者自己理解，团队成员无法使用 | 建模后必须让至少一个团队成员独立使用并反馈，确保可传递性 |

## 判断标准

**什么算一个好模型**：

| 标准 | 好的模型 | 坏的模型 |
|:---|:---|:---|
| 有内容 | 框架分类下面有具体的行为标准、判断依据 | "分了三类但每类都是空的"——只有框架没有洞察 |
| 可操作 | 别人照着模型的步骤能执行并得到相近结果 | 太抽象或太复杂——看懂它的人做不了，能做的人不需要它 |
| 有迭代记录 | 模型有版本号，标注了每次更新修正了什么 | 第一版用了一年没改过——模型是假设，需要持续验证 |
| 有使用证明 | 过去一个月至少用这个模型解决过一个真实问题 | 写得漂亮的模型静静躺在文件夹里，从来没用过 |

**自检问题**：
1. 这个模型最近用过了吗？如果超过 1 个月没用，它可能已经过时了。
2. 模型里的分类，是否不同人/不同时间分类结果一致？——如果不一致，说明维度不够客观。
3. 用一个真实案例跑一遍这个模型，它能覆盖所有关键因素吗？——如果总有例外，说明模型还需要修正。
