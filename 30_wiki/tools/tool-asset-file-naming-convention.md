# 素材文件七要素命名法

## 目的

解决设计文件与素材文件混杂时「找不到、不敢用、用错版本、版权不清」的问题。把素材从「原料」维度标准化命名，让任何人只看文件名就能判断：**这是什么、从哪来、能不能用、技术规格如何**。

## 操作步骤

### Step 1：判断文件类型

先区分这是「素材」还是「设计成品」：

| 类别 | 判断标准 | 处理去向 |
|:---|:---|:---|
| **素材** | 未经设计排版的原始图片/视频/音频/参考图/AI 生成图 | 走本命名法 |
| **设计成品** | 已完成设计、用于投放或交付的文件 | 走「月白设计文件八要素命名法」 |
| **中间稿** | 设计过程中产生的临时文件 | 放入项目工作区，不进入素材库 |

### Step 2：按七要素命名

命名模板：

```
类型_项目_场景_来源_版权状态_技术参数_日期_序号.扩展名
```

| 要素 | 必填 | 可选值 | 说明 |
|:---|:---:|:---|:---|
| **类型** | ✅ | `IMG` 图片 / `VID` 视频 / `AUD` 音频 / `REF` 参考 / `ICO` 图标 / `3D` 模型 | 素材大类 |
| **项目** | ✅ | 品牌名或项目名，如 `润之美` / `巨米` / `鑫港湾` / `通用` | 归属 |
| **场景** | ✅ | 如 `产品图` / `门店` / `人物` / `活动` / `竞品` / `灵感` / `海报背景` | 使用场景 |
| **来源** | ✅ | `拍摄` / `采购` / `AI生成` / `截图` / `用户投稿` / `网络` | 怎么来的 |
| **版权状态** | ✅ | `自有` / `已授权` / `待确认` / `仅限内部` / `CC0` | 能否商用 |
| **技术参数** | 建议 | `800x800` / `4K` / `15S` / `RAW` / `PNG透明` | 分辨率/时长/特殊格式 |
| **日期+序号** | ✅ | `20260630_001` | 时间 + 唯一序号 |

### Step 3：放入对应文件夹

```
_assets/
├── 01_raw/                    # 原始素材（未处理）
│   ├── IMG_拍摄/
│   ├── VID_拍摄/
│   └── AUD_录音/
├── 02_reference/              # 参考与灵感
│   ├── 竞品/
│   ├── 行业案例/
│   └── 设计灵感/
├── 03_ai_generated/           # AI 生成素材
│   ├── 已筛选/
│   └── 待筛选/
├── 04_licensed/               # 已授权素材
│   ├── 图片/
│   ├── 视频/
│   └── 字体/
├── 05_production/             # 已用于生产的素材
│   ├── 润之美/
│   ├── 巨米/
│   └── 鑫港湾/
├── 06_archive/                # 过期/低价值素材
└── _naming_convention.md      # 本规范文档
```

### Step 4：定期审计

每月执行一次：

1. 检查 `_assets/` 根目录是否有「漏网」未命名文件
2. 把 `03_ai_generated/待筛选/` 中未采用的素材移入 `06_archive/`
3. 把 `版权状态=待确认` 的素材标记为「已授权」或「删除」
4. 删除重复文件

## 不要用的场景

- **设计成品不要用本方法**：已完成的设计文件应使用「月白设计文件八要素命名法」，包含渠道、用途、版本、输出端、接收端等要素。
- **临时工作稿不要进素材库**：PSD 源文件、未定稿的修改稿应放在项目工作区，避免污染素材库。
- **个人截图/临时沟通图**：如果只是某次对话中使用一次，不需要进入 `_assets/`，用完后删除。
- **版权完全不可追溯的网络素材**：无法确认来源和授权状态的素材，直接删除，不要进入素材库。

## 质疑

### Q1：文件名这么长，会不会太麻烦？

**A**：麻烦只发生一次，找文件时的焦虑会发生无数次。实际执行中，类型、项目、场景、来源、版权状态这 5 个要素是核心，技术参数和日期可以部分由脚本自动填充。比起「找不到图」「不敢用图」的隐性成本，命名成本很低。

### Q2：AI 能不能自动帮我命名？

**A**：能识别图片内容（VLM 可以判断「这是产品图还是人物照」「室内还是室外」），但**项目、来源、版权状态无法从图片本身推断**。最务实的做法是：
- AI 自动识别：类型、场景、技术参数
- 人工输入：项目、来源、版权状态
- 脚本自动填充：日期、序号

### Q3：为什么不用 `v1/v2/最终版`？

**A**：素材没有「最终版」，只有「第 N 张」。用 `001/002/003` 序号替代，避免「最终版_真最终版_最终版2_不改了」的灾难。

### Q4：和月白的八要素命名法是什么关系？

**A**：八要素命名法面向**设计成品**（下游交付物），七要素命名法面向**素材**（上游原料）。两者是同一套命名哲学在不同资产阶段的落地：
- 素材七要素回答：这是什么、从哪来、能不能用
- 设计八要素回答：给谁看、什么渠道、什么版本、什么时间交付

### 深层质疑

- **具体假设**：七要素命名法假设"文件名可以承载足够的决策信息"，但文件名长度有限——当要素过多时，文件名变得冗长且难以人眼快速扫描，反而降低了"看文件名就能判断"的效率。
- **边界**：当素材库规模超过 10,000+ 文件时，文件名命名法的检索效率远低于全文本搜索引擎——此时应转向"标签 + 全文索引"而非"文件名编码"。
- **反例**：Figma/Notion 等现代工具已不依赖文件名管理资产，而是用"项目内嵌 + 全局搜索 + 标签筛选"——七要素命名法是"文件系统时代"的产物，在云端协作工具中可能过度设计。

**David Allen**（GTD 时间管理方法论创始人）会质疑：命名规范的执行成本被严重低估。他的核心观察是：任何需要"人记住规则并手动执行"的系统，最终都会因为执行疲劳而崩塌。七要素命名法需要人在每次保存文件时记住 7 个维度并正确填写——这在实践中几乎不可能持续。更务实的方案是：让脚本自动提取尽可能多的要素（日期、技术参数、类型），人工只填最少必要信息。

## 失败模式

| 失败信号 | 原因 | 修复动作 |
|:---|:---|:---|
| 文件名全是 `IMG_1234.jpg` | 相机默认命名未改 | 导入时立即批量重命名 |
| `最终版.psd` 和 `最终版2.psd` 共存 | 用版本文字代替序号 | 统一改为 `001/002` 序号 |
| 同一张图出现在 5 个文件夹 | 没有统一素材库入口 | 建立 `_assets/` 单一真相源 |
| 用了网络图被投诉 | 版权状态未标注 | 所有素材必须标注版权状态 |
| AI 生成图被误认为原创 | 来源未写 `AI生成` | AI 生成素材强制标注来源 |

> **一句话总结**：素材命名不是艺术创作，是信息编码。让文件名成为「不用打开文件就能判断能不能用」的决策入口。
