# 鱼骨图根因分析工具

> 用于结构化拆解业绩差距或问题的根因，从现象逐层深入到可行动的底层要素。

---

## 一、鱼骨图基本结构

```
                    ┌── 因素 A
                    ├── 因素 B
      问题/差距 ←───┼── 因素 C
                    ├── 因素 D
                    └── 因素 E
```

## 五、使用步骤

1. **明确问题**：用可量化指标描述差距（如“Q2 销售额缺口 500 万”）。
2. **确定一级分类**：按MECE原则选择分类维度（如人、货、场；或收入、支出）。
3. **逐层拆解**：每个分类下追问“为什么”，直到找到可行动的根因。
4. **验证根因**：用数据确认根因与问题的因果关系。
5. **制定对策**：针对关键根因制定改进行动。

## 六、Agent 执行指令

```python
def fishbone_analysis(problem: str, categories: list[str]):
    """用鱼骨图拆解问题根因"""
    prompts = {
        "明确问题": f"将问题「{problem}」量化为具体差距。",
        "一级分类": f"按{categories}构建鱼骨图主骨。",
        "逐层拆解": "每个分类下至少拆解三级，直到找到可行动的根因。",
        "验证": "用数据或事实验证每个候选根因与问题的因果关系。",
        "对策": "针对Top 3根因制定具体改进行动、负责人、Deadline。"
    }
    return {step: ask(prompt) for step, prompt in prompts.items()}
```

## 七、失败模式

| 失败 | 症状 | 修复 |
|--|--|--|
| 问题描述模糊 | “销售不好” | 必须量化为具体指标和缺口 |
| 分类不MECE | 各主骨之间有重叠 | 重新设计一级分类 |
| 只拆到表面 | 三级就停止 | 继续追问“为什么”直到可行动 |
| 根因未经证实 | 把假设当根因 | 用数据验证因果 |
| 对策与根因脱节 | 根因是A，对策是B | 每个根因必须对应至少一条对策 |

## 质疑

> 待补充：这个工具的内在局限是什么？外部反对者会怎么批评？

**Kaoru Ishikawa** 可能会质疑：这个工具依赖的 **因果归因、分类完备性、根因深度、验证假设** 是否已经被充分验证？

- 鱼骨图容易把症状当根因，停留在表面分类而没有深入机制。
- 团队可能为了填满骨架而硬凑原因，忽视真正关键变量。

- 使用前应明确本工具的 **具体假设**、适用 **边界**、潜在 **反例** 和隐含 **前提**，避免把模板输出直接当成战略结论。
