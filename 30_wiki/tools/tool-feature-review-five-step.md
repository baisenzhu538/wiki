# Feature复盘五步法：用/缺/叠加/改进/沉淀

> 一句话：一个可教给任何人的 AI 实践复盘模板——每次用 AI 做完一件事，按"用→缺→叠加→改进→沉淀"五步走一遍，把"感觉不太对"变成可测试的 Feature 缺口，把散经验变成可复用资产（10 案例实证：黄华春 L237-L351 / jeffgirl L1825-L2421 / 张丽娜 L2423-L2791 / 王鹏飞 L2795-L2905）。

---

## 操作步骤（五步，按序执行）

### 第 1 步：用——本次实践实际用了哪些 Feature

**做法**：先列后标。先把本次实践做过的事全部列出来（含无意识的——凭感觉做的也算），再对照周期表给每件事命名 Feature。

| 动作 | 说明 | 实证 |
|:---|:---|:---|
| 列出全部做法 | 不筛选、不评判，先写满 | 黄华春三篇文章"无意识"用了 4 个 Feature（L23） |
| 对照命名 | 设定角色/参考案例/格式设定/负面限制…… | jeffgirl"用了但没意识到"的 4 项（L2177-L2203） |
| 标注意识状态 | 刻意用 or 无意识用 | 王鹏飞"用对了但不知道那是牌"（L2901） |

**输出**：Feature 使用清单（含意识状态标注）。

### 第 2 步：缺——对照周期表，缺了哪些 Feature

**做法**：对照 Feature 周期表逐层过（L0-L5），记录"如果当时有 X 会怎样"。**高频缺项收敛表**（10 案例统计，诊断报告 §四 洞察 2）：

| 高频缺项 | 缺失人数 | 代表案例 | 症状 |
|:---|:---|:---|:---|
| 最终意图 | 8/10 | 王鹏飞"四不像平均值"（L2863）；田力"没说要立项要钱"（L1111-L1135）；张丽娜"第一封意图没说透"（L2577-L2591） | 多目标混一句，AI 给平均解 |
| 验收清单/评测标准 | 7/10 | 王鹏飞"读到最后自己也没标准"（L2865）；张丽娜"靠感觉无评分表"（L2607-L2619） | 返工失控，逐字读稿 |
| Few-shot/参考案例 | 6/10 | 张丽娜"没给好坏邮件对比"（L2593-L2605）；黄华春第二篇加案例阅读量翻倍（L243） | 描述不如例子直接 |
| 事实约束/DataPack | 5/10 | 王鹏飞 18 桥口误扩散（L2861） | 错误输入被放大 |

**输出**：缺失 Feature 清单（每条标"实测缺失"或"推测缺失"）。

### 第 3 步：叠加——哪些 Feature 组合生效？机制是什么

**做法**：识别本次实践中的组合，判断机制属于哪种：

| 机制 | 特征 | 实证 |
|:---|:---|:---|
| 并列维度覆盖 | 各 Feature 解决正交维度（身份/风格/结构） | 黄华春 1+1+1>3（L239-L257）；张丽娜身份+场景+限制（L2671-L2675） |
| 链式管道 | 上输出=下输入，流程逐步深化 | jeffgirl V4 Feature 链（L2025-L2029） |
| 关键维度补全 | 补一个关键 Feature 即质变 | 王鹏飞身份+上下文 40→65 分（L2871） |

**注意**：叠加不单调——单一指标可能下降（黄华春第三篇阅读量 4200 < 6500 但转化率 33% 更高，L245），要看组合指标。

**输出**：生效组合清单 + 机制判定。

### 第 4 步：改进——下一版补哪些 Feature，每条对应可测试假设

**做法**：从第 2 步缺失清单选 2-5 个补，**每个改进必须对应一个可测试假设**（每版一个假设——张丽娜 L2651-L2665）：

| 假设示例（张丽娜） | 测试方式 |
|:---|:---|
| 标题不讲采购改讲经营问题 → 打开率更高 | A/B 对比打开率 |
| 正文从新会员场景切入 → 回复率更高 | A/B 对比回复率 |
| 只问一个问题不介绍全服务 → 回复门槛更低 | 单变量对比 |

**输出**：改进清单（每条 = Feature + 假设 + 测试指标）。

### 第 5 步：沉淀——验收清单 + 个人 Feature 库 + 效果追踪表

**做法**（三件套）：
1. **验收清单先于下一次生成**：把"好"的标准写成可照抄的评分表，让 AI 先自评再交付（张丽娜 1-5 分自评表 L2613-L2619；王鹏飞"老师能否照常上课/家长能否 30 秒看懂" L2865）
2. **进个人 Feature 库/DataPack**：本次验证有效的 Feature 命名归层入库（与 `[[dk-feature-pieces-not-recognized-as-cards]]` 的散牌识别衔接），事实性数据进只读 DataPack
3. **效果追踪表**：记录"本次用了哪些 Feature + 效果如何 + 下次改进什么"（黄华春 L295-L301 样式），每周回顾更新组合模板

**输出**：验收清单模板 + Feature 库更新 + 效果追踪表（三件套落盘）。

## 输入 / 输出 / 触发条件

| 项 | 内容 |
|:---|:---|
| 输入 | 一次 AI 实践的完整记录（做了什么/效果如何/过程文件） |
| 输出 | 五步复盘文档（用清单/缺清单/叠加判定/改进假设/沉淀三件套） |
| 触发条件 | ①任何 AI 实践结束（10 分钟快速版）②效果不达预期的实践（完整版）③周/月定期复盘（组合模板迭代） |
| 耗时 | 快速版 10 分钟；完整版 30-60 分钟 |

## 适用边界（When NOT to Use）

| 场景 | 适用？ | 说明 |
|:---|:---|:---|
| 高频重复 AI 实操 | ✅ 核心场景 | 复盘 ROI 最高 |
| 一次性低风险任务 | ⚠️ 不必要 | 直接跑默认即可，不值得复盘 |
| 纯创意探索无输出标准 | ⚠️ 部分适用 | "缺"步缺参照系，复盘会空转 |
| 复杂状态机类工作流 | ⚠️ 注意成本 | 黄谦"抽卡耗时/状态机复杂度高，小团队易冗余"（L2947）——复盘本身也要控制成本 |

> ⚠️ 边界警示（反例）：复盘五步法不是"越细越好"——黄谦导演指出抽卡测试"耗时久，复杂度高，小团队场景下易冗余"（L2947）。快速版 10 分钟是为了防"复盘本身变成负担"。另外王鹏飞提醒：**"不要收藏Feature，要消化Feature"**（L2905）——第 5 步沉淀的终点是"下次真用上并记下分数变化"，不是"库很漂亮"。

## 失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| 收藏癖不消化 | 库建得很漂亮，从不调用（王鹏飞 L2905） | 沉淀强制带使用记录：每条 Feature 标"用过几次/分数变化"，季度清理 0 使用 |
| 复盘写成流水账 | 只记"做了什么"不答"缺了什么" | 第 2 步强制对照周期表逐层过；缺项必须标假设 |
| 叠加只看单一指标 | 4200<6500 就判"格式设定没用" | 看组合指标（转化率/信任度/复购），记录指标选择 |
| 改进无假设 | "下次试试别的"——无法验证 | 第 4 步强制：每条改进 = Feature + 假设 + 测试指标 |
| 复盘本身过重 | 复盘点超过产出价值 | 控制节奏：快速版 10 分钟；高频任务才做完整版 |
| 五步与案例结构脱节 | 模板套不上实际 | 第 1 步先"列满再做"，无意识实践先列后标 |

## Critique

**内部局限**：五步法从 10 份"优秀作业"提炼——样本是筛选后的成功案例（幸存者偏差），"用/缺/叠加"四段式结构是作业的自我呈现，可能系统性美化过程（真实实践更乱）。证据均为学员二手自述（trust_level: observed）。

**外部攻击者 1（Kahneman 式——复盘过度理性化）**：五步法假设实践可以事后整齐拆成 Feature——但真实决策是模糊、试错、嵌套的；事后复盘（hindsight）必然重构过程，把"运气"写成"Feature 配置"。复盘的产出是叙事，不是因果证据——除非配合第 4 步的前瞻性假设验证（每版一个假设 + A/B 测试）。

**外部攻击者 2（Taleb 式——方法论万能化）**：不是所有 AI 实践都能被 Feature 复盘提升——创意差异化工件（农夫三拳认知反差型，L923）、依赖实时现场信息的任务、超小团队复杂状态机（黄谦）都不适用。五步法如果被当成"每次必做"的仪式，会变成新的流程负担（与黄谦"复杂度高易冗余"同构）。

**业界反方**：rubric 体系研究（诊断报告 §一 组2）支持"验收清单先于生成"（rubric 先行），但强调"先 reason 后 score、定期人机对齐校验"——机械的自评表会漂移，需要人定期校准评分标准，五步法第 5 步应包含"验收清单季度校准"。

## Action Triggers

| 触发场景 | 第一个动作 |
|:---|:---|
| 刚用 AI 完成一件事 | 10 分钟快速复盘：列用/缺，各 5 分钟 |
| 效果不达预期 | 完整五步：重点走第 2 步（缺）和第 4 步（假设） |
| "感觉 AI 输出怪怪的" | 把感觉翻译成 Feature 缺口（"不够深入"→缺 CoT；"没对比"→缺多轮对话） |
| 要开始一个重要 AI 项目 | 先写验收清单（第 5 步模板前置）——标准先于生成 |
| 每周末 | 更新效果追踪表，迭代个人 Feature 组合模板 |
