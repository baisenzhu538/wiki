# 技能：延迟直觉法

> **来源**：基于 master-decision-hygiene 框架提炼（Kahneman《噪声》）
> **核心**：不要在做完分析后立即拍板——让判断"多飞一会儿"。直觉太快、太自信、太容易被最近的信息污染。

---

## 原始表述
> "你的第一反应不是你的最佳反应，只是你最快的反应。"
> —— 基于Kahneman研究提炼

---

## 操作步骤

### Step 1：完成分析（不拍板）

走完所有分析步骤（偏差自检、外部视角、独立评估等）后，**强制不拍板**。

在分析结论上标注：
```
分析完成时间：_____年_____月_____日 _____:_____
建议拍板时间：_____年_____月_____日 _____:_____（至少24小时后）

当前判断：________________________
暂不拍板的原因：等待延迟直觉验证
```

### Step 2：设置强制等待期

根据决策重要度设置等待时间：

| 决策重要度 | 等待时间 | 设置方式 |
|:----------|:--------|:--------|
| 日常决策 | 不需要 | 不适用 |
| 中等重要 | 24小时 | 日历提醒 |
| 高重要度 | 3-7天 | 日历提醒+他人监督 |
| 战略级 | 1-2周 | 团队评审会 |

**关键规则**：等待期间不要主动想这个决策。让大脑"孵化"。

### Step 3：重新审视（强制对比）

等待期结束后，强制回答：

```
重新审视表：

24小时前的判断：________________________
现在的判断：________________________

是否有变化？是 / 否

如果变化了：
- src_unknown
- src_unknown

如果没有变化：
- src_unknown
- src_unknown

最终拍板：________________________
拍板时间：________________________
```

### Step 4：记录延迟效果（可选）

长期追踪延迟直觉的准确率：

```
延迟直觉记录：

决策#1：延迟后改变了判断 → 结果：正确/错误
决策#2：延迟后未改变判断 → 结果：正确/错误
...

统计：延迟后改变判断的准确率 = _____%
       延迟后未改变判断的准确率 = _____%
```

## 为什么有效

直觉（System 1）太快、太自信、太容易被最近的信息污染。延迟让System 2有机会检查System 1的结论。

**金句**：你的第一反应不是你的最佳反应，只是你最快的反应。

## 常见失败模式

| 失败现象 | 原因 | 解决方案 |
|---------|------|---------|
| 等待期间偷偷决定了 | 忍不住提前拍板 | 告诉他人你的拍板时间，让他监督 |
| 等待后没有重新审视 | 忘记执行 | 设置强制提醒，写入日程 |
| 重新审视只是形式 | 心理上已经决定了 | 强制回答"如果今天是第一次看到这个问题，还会做同样选择吗？" |
| 等待时间太长 | 等待1周，机会消失 | 根据重要度调整等待时间，不是越长越好 |
| 团队等不及 | 组织有上线压力 | 用"最小可行延迟"——至少等1晚 |
