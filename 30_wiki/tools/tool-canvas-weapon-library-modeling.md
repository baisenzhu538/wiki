# 画布/武器库建模法：把工具箱变成可快速调用的系统

> **Burn line**: 武器库不是工具的堆砌，而是“遇到什么情况，拿哪把刀”的快速匹配系统。

## 用一句话讲清楚

画布是把复杂主题的关键维度强制铺到一张纸上，以完成无遗漏的系统扫描；武器库是按场景把多种工具分类索引，让人在遇到问题時能在 30 秒内找到合适工具；两者共同把“工具箱”升级为“情景匹配系统”。

## Protocol

### 画布使用步骤

#### 步骤 1：定义画布主题

你要完整扫描什么？商业模式、产品规划、用户增长、个人发展？

#### 步骤 2：确定关键维度

把主题拆成 6–10 个关键维度。例如商业模式画布：

#### 步骤 3：每个区块独立填写

不要跳过难填的区块。画布的完整价值来自每个区块都有内容。

#### 步骤 4：检查区块间一致性

客户细分和价值主张是否匹配？收入来源和成本结构是否合理？

#### 步骤 5：基于画布做决策

画布不是目的，目的是发现缺口、机会或矛盾。

## When NOT to Use

| 场景 | 为什么失效 | 替代方案 |
|---|---|---|
| **主题边界不清** | 画布会变成无边界的填空。 | 先用清单或 SABC 明确范围 |
| **工具太少，不够成库** | 武器库会变成强行分类。 | 先积累工具，再建库 |
| **只是为了好看** | 画布和武器库变成装饰。 | 回到使用场景，明确要解决什么问题 |
| **不更新维护** | 武器库会过期失效。 | 建立定期 review 机制 |

---

## 边界

| 边界 | 说明 |
|------|------|
| **画布区块数** | 通常 6–10 个，过多难以一次填满 |
| **武器库工具数** | 没有上限，但每个工具必须有明确适用场景 |
| **匹配粒度** | 不能太粗（所有场景都推荐同一个工具），也不能太细（50 个场景 50 个工具） |
| **维护成本** | 武器库需要定期 review，否则失效 |
| **输出转化** | 画布/武器库本身不产生行动，必须链接到决策、SOP 或检查清单 |
| **适用问题类型** | 结构化、可拆解的问题；高度模糊或瞬息万变的问题需先澄清 |

## 失败模式

| 失败模式 | 典型症状 | 根因 | 修复动作 |
|---|---|---|---|
| **画布形式化** | 填完没人看，区块内容相互矛盾 | 把画布当目的，未导出决策 | 填写前明确“要用画布回答什么问题”，填写后做一致性检查和行动转化 |
| **武器库堆砌** | 工具越来越多，常用只有两三个 | 只加不汰，缺少匹配规则 | 定期 review，淘汰失效工具，合并重复工具，补充场景说明 |
| **匹配过粗** | 所有场景都推荐同一个工具 | 分类维度太笼统 | 增加子场景或二级过滤条件，细化匹配规则 |
| **匹配过细** | 50 个场景 50 个工具，选择更困难 | 分类维度太细碎 | 合并相似场景，提炼高频通用场景 |
| **维护滞后** | 工具已更新但武器库还是旧版 | 缺少固定迭代触发器 | 每次新增/淘汰工具或遇到新场景后 24 小时内更新 |
| **边界不清** | 画布被跨主题误用，武器库工具跨场景错配 | 头部未写明触发条件和适用范围 | 在画布/武器库头部明确主题、适用场景、不适用场景 |
| **行动断链** | 画布很漂亮，武器库很全，但问题依旧 | 未把产出链接到具体决策或执行 | 为每个画布/武器库设计“下一步动作”和成功指标 |

### 外部攻击：Russell Ackoff — "坏系统比坏元素更危险"

**Russell Ackoff**（系统思考）会警告：把一堆工具放进武器库并不等于系统。如果没有清晰的“场景 → 工具 → 结果”逻辑，武器库只是一个分类目录，不能产生新的能力。
