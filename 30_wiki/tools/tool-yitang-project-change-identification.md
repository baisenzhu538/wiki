# 常见项目变化五维识别清单

> **一句话**：项目变化有规律——按五个维度分类，提前知道"什么会变"，比"变了再处理"强十倍。

---

## 一、五维变化分类表

| 分类 | 常见变化情形 |
|:---|:---|
| **方案** | 老板新想法 / 政策变了 / 甲方需求变了 / 前期没细化 / 有了更棒的选项 / 情况不符合预期 |
| **进度** | 计划要提前 / 大量任务超时 |
| **人力** | 有人请假了 / 成员被调走 / 被卡在其他项目上 / 能力远不如预期 |
| **质量** | 大家能力不够降低标准 / 改标准才能达到目标 |
| **预算** | 预算少了 / 预算花多了 |

---

## 二、操作步骤

```
Step 1: 启动时预判 → 逐维过一遍，标出本项目"最可能发生"的2-3类变化
Step 2: 制定预案 → 对标注的高风险类型，提前想好应对方向
Step 3: 执行中监控 → 一旦出现预判类型的变化，直接启用预案
Step 4: 新类型出现 → 追加到清单，完善自己的变化库
```

---

## 三、Constraints

- 五维不代表五个独立问题——方案变了往往连带进度、人力、预算一起变
- "老板新想法"和"甲方需求变了"是最高频的两类，优先准备应对
- 这份清单是"识别"，不是"处理"——识别后用"变化处理判断清单"决定怎么处理

---

## 四、失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| 只盯着进度 | 人力出问题、质量问题都没发现 | 五维每周过一遍 |
| 把"常见"当"正常" | "老板改主意很正常"就不再管理 | 常见也要走判断流程 |
| 预案只做不说 | 自己知道预案，团队不知道 | 高风险类型的预案同步给团队 |
| 预案过于乐观 | "老板应该不会改" | 默认老板会改——准备好如何应对 |

---

## 五、Action Triggers

- 项目启动会：用五维分类做一次变化风险预判
- 周会固定议程：本周出现了哪些类型的变化？
- 项目复盘：统计实际发生的变化类型，更新预判准确性
