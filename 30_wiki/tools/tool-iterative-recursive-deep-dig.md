# 迭代递归深挖法：用“喷—撞—改”循环把模型推到撞无可撞

## 用一句话讲清楚

建模不是一次成型，而是“先建 1.0，再用高标准内部挑错（喷），用外部标杆和反例撞击（撞），反复修正直到当前能力上限（改）”的递归循环。

> **Burn line**: 建模不是一次成型，而是“喷到无可喷，撞到无可撞，改到改不动”。

---

## 核心要点

1. **高质量模型是“撞”出来的，不是“想”出来的。** 1.0 版先画框子，再用推翻为目标的方式去找硬伤。
2. **“喷”是内部挑错，必须具体。** 针对不完整、有遗漏、没顺序、不完备、不清晰、乱糟糟等具体缺陷，而不是笼统说“不够好”。
3. **“撞”是外部验证，需要反例和标杆。** 找专家评审、竞品对照、真实案例测试，以推翻模型为目标进行讨论。
4. **“改”要记录改动和原因。** 每轮补遗漏、调结构、清定义、限边界，避免反复横跳。
5. **停止条件是能力上限，不是时间上限。** 当“喷无可喷、撞无可撞、改无可改”时，才进入封装。
6. **AI 是理想的挑错对象。** AI 不会离职，可以连续迭代 5–15 轮，直到改到你的能力上限。

---

## Visual Analysis

该方法呈现为一个螺旋上升的循环：
- 中心：1.0 模型原型
- 内环：喷（内部挑错）
- 中环：撞（外部验证）
- 外环：改（迭代修正）
- 终点：撞无可撞、喷无可喷、改无可改

## Purpose

用系统化的挑错和验证循环，把模型从“看起来对”推到“经过多轮攻击仍然站得住”，提升模型的 robustness 和可信度。

---

## Protocol

### Step 1：建 1.0

不要追求完美，先产出第一个完整版本。可以是：
- 一个清单
- 一个流程图
- 一个模型框架
- 一个 Skill 指南

### Step 2：喷（内部挑错）

用高标准系统性质疑 1.0：

| 检查项 | 问题示例 |
|--------|---------|
| **完整性** | 是否覆盖全链路？ |
| **MECE** | 是否有遗漏或重叠？ |
| **逻辑性** | 前后是否自洽？ |
| **顺序性** | 是否有明确优先级？ |
| **清晰性** | 是否容易理解和执行？ |
| **可验证性** | 是否能被事实检验？ |

### Step 3：撞（外部验证）

用外部力量撞击模型：
- 找反例
- 找专家评审
- 找标杆对照
- 找真实案例测试

### Step 4：改（迭代修正）

根据喷和撞的结果修改模型：
- 补遗漏
- 调结构
- 清定义
- 限边界

### Step 5：判断停止条件

问自己：
- 我还能挑出具体毛病吗？
- 外部还有可见反例吗？
- 还能吸收标杆优点吗？

如果答案都是“不能”，则进入封装。否则回到 Step 2。

## 失败模式

| 失败模式 | 典型症状 | 根因 | 修复/预防 |
|---|---|---|---|
| **迭代变成完美主义** | 迟迟不交付，无限挑错 | 混淆“能力上限”与“绝对真理” | 明确停止条件为“我当前找不到新问题”，并设定时间盒 |
| **挑错者水平不够** | 挑不出真问题，只改措辞 | 缺少领域知识或逻辑洁癖 | 引入外部专家或标杆对照 |
| **没有外部撞击** | 只靠自己喷，陷入自我验证 | 缺少反例和外部视角 | 强制每轮至少找 1 个反例或 1 位专家评审 |
| **外部标杆不存在** | 无法撞击验证 | 领域太新或信息封闭 | 先用内部一致性检查，再积累案例包 |
| **改动不记录** | 反复横跳，同一问题改多遍 | 缺少每轮改动和原因的记录 | 建立迭代日志，记录问题、修改、验证结果 |
| **把AI迭代当质量保证** | 让AI自己改100轮，结果收敛到平均审美 | 缺少人的判断和审美把关 | 人在循环中扮演挑错者和审美守门员 |
| **简单任务过度深挖** | 迭代成本超过收益 | 工具错配 | 简单任务一次成型，复杂任务再用深挖法 |

---

## 边界

| 边界 | 说明 |
|------|------|
| **迭代轮次** | 通常 5–15 轮，不是越多越好，到你的能力上限即可 |
| **停止条件** | 以“喷无可喷、撞无可撞”为准，不是以时间为准 |
| **参与者** | 需要有人扮演“挑错者”角色 |
| **记录机制** | 每轮改动和原因要记录，避免反复横跳 |
| **适用对象** | 复杂模型、高频复用指南、方法论级资产 |
| **不适用对象** | 一次性任务、时间极紧、缺乏判断标准或外部标杆的场景 |

## 行动 Checklist

- [ ] 已产出第一个完整的 1.0 版本（不追求完美）
- [ ] 已按完整性、MECE、逻辑性、顺序性、清晰性、可验证性逐项挑错
- [ ] 已找到至少 1 个反例或 1 位专家进行外部撞击
- [ ] 已对照 1–2 个外部标杆，吸收其优点
- [ ] 每轮改动都记录了“问题—修改—验证结果”
- [ ] 已补遗漏、调结构、清定义、限边界
- [ ] 当前能力范围内找不到新的具体缺陷或可见反例
- [ ] 已明确标注模型的边界条件和假设
- [ ] 已决定进入封装，还是再回到下一轮迭代

## [Critique]

### 内部局限性

- 迭代过程可能陷入“完美主义”，迟迟不交付
- 如果挑错者水平不够，会挑不出真问题
- 外部标杆不一定存在

### 外部攻击：Karl Popper — "证伪有边界，不要无限逼近"

**Karl Popper** 会警告：任何模型都无法被完全证实，只能被暂时证伪。“喷无可喷、撞无可撞”只是人类当前能力的上限，不是绝对真理。要清楚区分“当前最佳模型”和“终极真理”。

### 反事实测试

- 如果没有外部撞击，只靠自己喷，会怎样？容易陷入自我验证。
- 如果时间有限，只能做一轮喷和撞，优先做哪个？优先撞，因为外部视角更难自欺。
