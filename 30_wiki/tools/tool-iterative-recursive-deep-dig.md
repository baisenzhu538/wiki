# 迭代递归深挖法：用“喷—撞—改”循环把模型推到撞无可撞

> **Burn line**: 建模不是一次成型，而是“喷到无可喷，撞到无可撞，改到改不动”。

这是 Truman 在一堂高阶建模课上展示的底层工作法。无论是自己做模型、和团队讨论模型，还是和 AI 协作生成模型，核心循环都是同一套：**先建个 1.0，然后用高标准不断挑错（喷），再用外部标杆和反例撞击（撞），反复修改直到上限（改）**。

---

## Visual Analysis

该方法呈现为一个螺旋上升的循环：
- 中心：1.0 模型原型
- 内环：喷（内部挑错）
- 中环：撞（外部验证）
- 外环：改（迭代修正）
- 终点：撞无可撞、喷无可喷、改无可改

---

## Claims

- **C1 [conf=0.9]**: 高质量模型不是一次生成的，而是经过“建 1.0 → 喷 → 撞 → 改”多轮迭代得到的。——依据：`src_20260614_8269ccdb#2586`。
- **C2 [conf=0.85]**: “喷”的对象是具体缺陷：不完整、有遗漏、没顺序、不完备、不清晰、乱糟糟。——依据：`src_20260614_8269ccdb#2586`。
- **C3 [conf=0.85]**: “撞”是用外部标杆、友商、反例来验证自己的模型。——依据：`src_20260614_8269ccdb#2586`。
- **C4 [conf=0.8]**: 迭代停止条件不是时间到了，而是“喷无可喷、撞无可撞、改无可改”。——依据：`src_20260614_8269ccdb#2238、2586`。

---

## Purpose

用系统化的挑错和验证循环，把模型从“看起来对”推到“经过多轮攻击仍然站得住”，提升模型的 robustness 和可信度。

---

## Protocol

### Step 1：建 1.0

不要追求完美，先产出第一个完整版本。可以是：
- 一个清单
- 一个流程图
- 一个模型框架
- 一个 Skill 指南

### Step 2：喷（内部挑错）

用高标准系统性质疑 1.0：

| 检查项 | 问题示例 |
|--------|---------|
| **完整性** | 是否覆盖全链路？ |
| **MECE** | 是否有遗漏或重叠？ |
| **逻辑性** | 前后是否自洽？ |
| **顺序性** | 是否有明确优先级？ |
| **清晰性** | 是否容易理解和执行？ |
| **可验证性** | 是否能被事实检验？ |

### Step 3：撞（外部验证）

用外部力量撞击模型：
- 找反例
- 找专家评审
- 找标杆对照
- 找真实案例测试

### Step 4：改（迭代修正）

根据喷和撞的结果修改模型：
- 补遗漏
- 调结构
- 清定义
- 限边界

### Step 5：判断停止条件

问自己：
- 我还能挑出具体毛病吗？
- 外部还有可见反例吗？
- 还能吸收标杆优点吗？

如果答案都是“不能”，则进入封装。否则回到 Step 2。

---

## When NOT to Use

| 场景 | 为什么失效 | 替代方案 |
|---|---|---|
| **简单任务** | 迭代成本超过收益 | 一次成型即可 |
| **时间极紧** | 无法完成多轮迭代 | 先做轻量版，后续补深挖 |
| **没有判断标准** | 不知道喷什么 | 先学习领域知识 |
| **没有外部标杆** | 无法撞击验证 | 先做内部一致性检查 |

---

## Constraints & Boundaries

| 边界 | 说明 |
|------|------|
| **迭代轮次** | 通常 5–15 轮，不是越多越好 |
| **停止条件** | 以“喷无可喷、撞无可撞”为准，不是以时间为准 |
| **参与者** | 需要有人扮演“挑错者”角色 |
| **记录机制** | 每轮改动和原因要记录，避免反复横跳 |

## [Critique]

### 内部局限性

- 迭代过程可能陷入“完美主义”，迟迟不交付
- 如果挑错者水平不够，会挑不出真问题
- 外部标杆不一定存在

### 外部攻击：Karl Popper — "证伪有边界，不要无限逼近"

**Karl Popper** 会警告：任何模型都无法被完全证实，只能被暂时证伪。"喷无可喷、撞无可撞"只是人类当前能力的上限，不是绝对真理。要清楚区分“当前最佳模型”和“终极真理”。

### 反事实测试

- 如果没有外部撞击，只靠自己喷，会怎样？容易陷入自我验证。
- 如果时间有限，只能做一轮喷和撞，优先做哪个？优先撞，因为外部视角更难自欺。
