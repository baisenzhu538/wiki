# 线上签约统计

> 如果竞对的用户ID/订单号是自增的，通过观察ID变化推算用户量和订单量。

**做法**：注册一个账号→看自己的用户ID→隔一段时间再注册一个→看ID差值→推算日均新增用户。同理，下单后看订单号→隔几天再下一单→推算日均订单量。

**价值**：这是逆向数据分析中最简单但最有效的一招。不需要爬虫、不需要技术能力——只需要注册两个账号。

**坑**：不是所有系统都用自增ID（有些用随机ID/UUID）；ID差值可能包含取消订单和测试数据。

*卡片类型：tool | 审核状态：待审*

## 目的

解决"竞对用户量/订单量全靠猜"的问题——如果竞对系统使用自增 ID，通过注册两个账号观察 ID 差值即可推算日均新增量。适用于 SaaS、电商、社区等线上产品的竞对规模估算，是逆向数据分析中最简单有效的手段。

## 操作步骤

1. **确认 ID 是否自增**：注册一个账号，记录用户 ID（如 #1024567）。检查 ID 是否为纯数字递增格式——如果是 UUID/随机字符串则此方法无效。部分平台在订单确认页/个人资料页显示编号型 ID。
2. **间隔测量**：隔一段已知时间（如 7 天/14 天）再注册一个账号，记录新 ID。ID 差值 ÷ 间隔天数 = 日均新增用户。同理可对订单号操作：下单后看订单号，隔几天再下单，推算日均订单量。
3. **修正与估算**：ID 差值可能包含测试数据、取消订单、批量导入等噪音，实际新增通常为差值的 70-90%。多次测量取中位数，并与行业公开数据交叉验证合理性。

## 不要用的场景

- **非自增 ID 系统**：使用 UUID、雪花算法、时间戳+随机数等非连续 ID 的系统，此方法完全无效。
- **多租户/多品类系统**：如果竞对不同业务线共用 ID 池或分库分表，差值含义不明确。
- **ID 包含大量历史数据迁移**：系统迁移导入的旧用户会占据大量 ID 段，推算的"新增"严重高估。
- **需要精确数据的场景**：此方法只能做量级估算（±20-30%），不能替代精确数据。

## 质疑

### 内在局限

自增 ID 推算是"聪明但脆弱"的方法——它依赖于系统设计的透明性，而越来越多的现代系统已经迁移到非自增 ID。即使 ID 是自增的，差值中混杂的测试账号、内部账号、批量注册等噪音也无法完全过滤。

### 外部反对者

**Avi Ruben**（系统安全研究）：
> 「通过 ID 差值推算竞对数据本质上是在做'信息侧信道攻击'。竞对一旦意识到这个信息泄露，只需在 ID 生成策略中加入随机偏移就能让你的推算完全失效。这个方法的有效期取决于竞对的技术意识。」

**Carl Bergstrom**（信息扭曲研究）：
> 「ID 差值数据最大的陷阱是'精确的错觉'——你拿到了一个具体数字（比如日均新增 3,247 人），这个数字看起来精确，但实际上包含了大量未知噪音。人们倾向于把'看起来可计算的数据'当作'可靠的数据'，这是认知偏差。」

进一步审视该方法的四类关键术语：
- **具体假设**：竞对系统使用自增 ID，且 ID 差值能反映真实新增用户/订单量。
- **边界**：适用于使用编号型自增 ID 的线上产品；不适用于 UUID、多租户/多品类、历史数据迁移或需要精确数据的场景。
- **反例**：现代系统多用非自增 ID，且差值中含测试/内部/批量注册噪音，造成"精确的错觉"。
- **前提**：前提是多次测量取中位数，并将结果与行业公开数据交叉验证，仅作量级估算（±20-30%）。
