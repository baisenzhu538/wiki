# 技能：清单小抄工具箱法

## 原始表述
> L1.清单小抄 √清单：完整的清单/目录 便于执行 √合集：工具箱/模板库

## 操作步骤
1. 将经验转化为完整清单/目录
2. 建立工具箱/模板库合集
3. 确保格式便于立即执行

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 重复性工作场景，需要标准化防遗漏 |
| ✅ 适合 | 团队协作标准化，减少决策疲劳 |
| ✅ 适合 | 关键环节检查，防止人为疏忽 |
| ✅ 适合 | 有先例可循的工作，可提炼为清单 |
| ❌ 不适合 | 完全创造性、无先例的工作 → 清单限制创新空间 |
| ❌ 不适合 | 需要灵感突破的工作 → 清单是约束不是推动 |
| ❌ 不适合 | 团队规模小、个人习惯已稳定 → 建清单成本>收益 |
| ❌ 不适合 | 清单维护无人负责 → 建完即过时 |

## 判断标准

**什么算一条好的清单条目**：

| 标准 | 好的条目示例 | 坏的条目示例 |
|:---|:---|:---|
| 可操作 | “检查客户留言中是否提及价格异议” | “关注客户需求”（太抽象，不知道怎么做） |
| 可判断 | “确认合同签章页有双方签名+日期” | “确认合同没问题”（什么叫“没问题”？） |
| 完整独立 | “测试登录流程”（单独执行） | “测试”（测什么？前后上下文是什么？） |
| 可检查 | “回复时间 < 2 小时”（有数字） | “及时回复”（多快算及时？） |
| 无歧义 | “确认支付方式为银行转账” | “确认付款”（什么方式？现金？转账？） |

**自检问题**：
1. 这条清单执行完成后，我能明确说“通过/不通过”吗？
2. 如果换一个没经验的人来执行，他能看懂并执行吗？
3. 这条需要多少时间完成？超过 2 分钟就应该拆分
4. 这条的结果是否可以被第三方验证？（而不是只有自己知道做没做）

## 常见失败模式

| 失败模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **清单太全** | 清单超过 15 条，执行前需要先花 10 分钟通读，关键提醒被淹没 | 控制在 5-9 条，只保留"一旦漏掉就会出错"的关键项，其余移到附录或单独 SOP |
| **用完不更新** | 同一清单使用半年后，其中 3 条已不适用，但仍在每次执行时勾选 | 每次使用后用 2 分钟标注"失效/需改/新增"，每月集中 Review 一次 |
| **只建不用** | 工具箱里积累了 50 个清单小抄，实际执行时仍凭记忆或临时搜索 | 在关键执行入口嵌入清单链接/二维码，前 3 次强制对照清单执行，形成调用习惯 |
| **清单与 SOP 混淆** | 清单条目写成"必须用左手扭到 3.5N·m"式的详细动作，失去快速检查意义 | 清单只写"检查胎压是否正常"，具体动作和数值放到 SOP 或操作手册中 |
| **过度依赖** | 核心能力未内化，离开清单就无法独立完成工作 | 清单只用于防遗漏和标准化，复杂判断项要配套训练，直到能脱离清单执行 |
| **假努力幻觉** | 花两周搭建精美分类体系和工具箱界面，却未在实际任务中用过一次 | 建完第一个清单后 24 小时内必须投入使用，先用起来再优化排版和分类 |
| **更新成本无人承担** | 团队清单建完后没有 owner，三个月后无人敢改、无人知道是否还准确 | 每个清单指定唯一维护人，并在清单顶部标注"最后更新日期+维护人" |
| **条目歧义不可检查** | 条目如"及时回复客户"，不同人理解不同，无法判定通过/不通过 | 改写为可判断、可验证的描述，例如"工作时间内客户留言 2 小时内回复" |

## Critique

### 外部攻击

**攻击者1：创意工作者 —— “清单是创造力的敌人”**

> 真正的创造力来自于打破规则而不是遵循清单。如果你的工作每次都按照同一个清单执行，你永远不会有突破。创意工作需要空间和自由度，清单是一种约束——对于需要灵感的工作，它可能是杀手。

**攻击者2：敏捷实践者 —— “清单是‘假努力’的幻觉”**

> 很多人花大量时间搭建精美的清单系统，以为自己在"做系统“，实际上只是在"避免做难事“。清单建得越复杂，执行越低。真正的效率来自于"做“而不是"建“。
