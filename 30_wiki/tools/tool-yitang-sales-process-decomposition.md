# 一堂销售过程拆解三步法（用户决策路径地图）

## 操作步骤


1. 确认一堂销售过程拆解三步法（用户决策路径地图的适用前提是否满足
2. 梳理当前状况与目标的差距
3. 选择对应的一堂销售过程拆解三步法（用户决策路径地图分析维度
4. 逐维度填写并标注数据来源
5. 汇总形成行动建议

## 一句话

销售过程拆解三步法是从用户视角出发，把成交黑盒拆成「路径 → 阶段 → 动作」的可管理地图，让销售能力从依赖个人经验变成可复制、可预测的组织能力。

## Purpose

解决「销售周期长、客户推进不透明、丢单原因不清楚、老销售经验无法复制」的问题。通过识别用户从接触到履约的关键决策点，把销售过程变成可监控、可优化、可培训的流程资产。

## When to Use

- 销售周期长（数周至数月），客户推进状态靠销售口头汇报，管理层看不清真实进度。
- 老销售个人能力强但不愿分享，新人成长慢，团队整体产出受制于少数几个人。
- 丢单原因不清楚，客户常卡在某一环节迟迟不推进，却不知道卡点在哪。
- 想规模化复制销售能力，但缺少统一的语言、阶段和动作标准。
- 销售动作五花八门，有的销售做了很多无效动作，有的销售漏掉关键动作。
- 周会和日报变成流水账，无法基于过程数据做诊断和干预。

## 三步法

| 步骤 | 核心任务 | 关键问题 | 典型产出 |
|:---|:---|:---|:---|
| **第一步：拆路径** | 确定用户与产品，按用户决策视角梳理完整路径 | 这类用户从接触到履约会经历哪些决策点？ | 用户决策路径图（含接触/购买/付款/履约节点） |
| **第二步：划阶段** | 聚焦用户高成本决策点，定义里程碑并梳理顺序 | 哪些决策点成本高、风险大，需要重点监控？ | 销售阶段划分 + 里程碑定义 |
| **第三步：配动作** | 为每个阶段设计精准销售动作，定义标准并配套工具 | 每个里程碑需要销售做什么、做到什么标准？ | 销售动作清单 + 工具包 + 数据监控点 |

### Step 1：拆路径——从用户视角梳理决策路径

拆路径不是列销售动作，而是回答「用户要做出哪些决策才能从接触到成交」。

**操作要点：**

1. **先确定用户和产品**：同一款产品，面对新用户和老用户、低价产品和高价产品，决策路径不同；销售方式不同（直销/分销/电销/面销），路径也不同。
2. **具象用户场景**：尽可能想象用户的真实情境。例如家长是否忙到只能让爷爷奶奶带孩子试课、To B 客户是否涉及多个决策部门。
3. **识别四类决策**：把路径上的每个关键节点归入接触决策、购买决策、付款决策、履约决策四类。
4. **关注高成本决策**：用户需要花时间、花钱、调动他人、对未来产生长远影响的决策点，是路径拆解的重点。

### Step 2：划阶段——聚焦高成本决策点定义里程碑

阶段划分的核心是把用户决策成本高、风险大的节点设为重点监控的里程碑。

**里程碑识别方法：**

| 方法 | 适用场景 | 操作方式 |
|:---|:---|:---|
| **定性分析** | 早期数据不足 | 逻辑分析 + 情景想象：用户在这个阶段需要付出什么代价？不推进会有什么风险？ |
| **定量分析** | 已有一定销售数据 | 看节点转化率和推进周期：转化率异常低、推进周期异常长的环节，通常是高成本决策点 |

**节点转化率**：从一个阶段成功进入下一个阶段的客户比例。例如试听课到正价课的转化率。
**推进周期（销售流速）**：客户从一个阶段推进到下一个阶段所花的时间。某阶段明显偏长，说明该阶段需要进一步拆分或加监控动作。

### Step 3：配动作——设计精准、标准化、可配套工具的销售动作

每个里程碑下，销售需要完成的具体动作要满足四个原则：

1. **做足加法**：先穷尽列出所有可能动作，避免漏项。来源包括：拆解优秀销售、同行调研、直接询问客户、逻辑分析用户场景。
2. **匹配精准动作**：用对比和 A/B 测试判断哪些动作真正推动客户进入下一阶段，去掉无效动作。
3. **定义动作标准**：统一动作名称、完成标准和量化指标，避免不同销售记录口径混乱。
4. **配套销售工具**：为关键动作匹配话术、模板、资料、视频、清单等工具，降低执行难度。

## 四类用户决策

销售过程的本质是帮助用户完成一系列决策。用户的决策大致可分为四类：

| 决策类型 | 核心问题 | 典型场景 | 销售动作方向 |
|:---|:---|:---|:---|
| **接触决策** | 用户是否愿意与销售建立联系？ | 接电话、加微信、回消息、到店、参加试听 | 降低首次接触成本，设计可信的开场与邀约 |
| **购买决策** | 用户是否决定购买产品/服务？ | 让真正的决策人参与、解决信任顾虑、对比竞品 | 找到关键决策人，匹配卖点，处理抗拒点 |
| **付款决策** | 用户是否完成付款动作？ | 内部审批、财务请款、合同签署、打款 | 提前了解付款流程，推动审批，消除付款阻力 |
| **履约决策** | 用户是否真正使用已购买产品/服务？ | 上课、上线、使用系统、消课、复购 | 确保用户完成首次使用，降低退款和流失风险 |

**注意**：对 SaaS、订阅制、培训、健身等依赖持续履约产生收益的业务，履约决策往往就是销售的「真正关单点」。例如支付产品需等客户上线走量后才算完成销售，私教课需等学员来销课后才容易续费。

## 里程碑定义

里程碑是销售阶段之间的关键节点，代表用户完成了一个重要的、可观察的决策动作。

**好里程碑的标准：**

- **用户视角**：描述的是用户完成了什么决策，而不是销售做了什么动作。
- **可判断**：有明确的结果标准，能回答「完成了 / 没完成」。
- **可统计**：能被记录、被量化、被复盘。
- **高成本关联**：与用户的时间、金钱、精力、组织成本高度相关。

**常见错误**：把「建立深厚感情」「开场白」「介绍公司」等销售动作或模糊目标当作里程碑。这些无法量化，也不能作为管理抓手。

**示例对比：**

| 不好的里程碑 | 问题 | 改进后的里程碑 |
|:---|:---|:---|
| 建立深厚感情 | 无法量化判断 | 客户同意引荐关键决策人 |
| 开场白 | 这是销售动作，不是用户决策 | 客户愿意继续沟通超过 30 秒 |
| 介绍公司 | 动作本身不等于阶段目标 | 客户认可公司资质与背书 |
| 持续跟进 | 没有节点感 | 客户确认预算范围 |

## 动作设计原则

### 原则 1：做足加法，再精准减法

不要一开始就追求简洁。先穷尽列出所有可能推动用户的动作，来源包括：

- 拆解优秀销售的成单过程。
- 向同行或竞品销售调研。
- 直接询问客户：「您现在最大的顾虑是什么？」「还需要什么信息才能决定？」
- 回到用户决策场景做逻辑推演。

### 原则 2：匹配精准动作

每个动作都要回答三个问题：

1. 这个动作对应用户的哪个决策点？
2. 它增加用户动力还是减少购买阻力？
3. 不做这个动作，成单会受到什么影响？

判断方法：对比不同销售的做法差异，或用 A/B 测试验证哪些动作真正提升节点转化率。

### 原则 3：定义动作标准

没有统一标准，过程管理就会混乱。例如：

- 有效通话：通话时长 ≥ 30 秒且聊到关键信息。
- 有效拜访：见到关键决策人并确认下一步动作。
- 意向客户：明确表达购买意愿并进入内部审批。

标准应松紧适度：关键节点必须统一，非关键细节给销售留发挥空间。

### 原则 4：配套销售工具

关键动作应配备可直接调用的工具：

| 动作 | 配套工具示例 |
|:---|:---|
| 首次接触 | 开场白话术、30 秒价值说明 |
| 需求确认 | 客户信息清单、需求访谈提纲 |
| 方案呈现 | 产品一页纸、案例集、竞品对比表 |
| 内部审批 | 标准报价单、审批材料包、ROI 测算模板 |
| 付款跟进 | 收款信息模板、合同模板、催款话术 |
| 履约启动 | 上线 checklist、首次使用引导、客户成功对接流程 |

## 案例嵌入

### 案例 1：剧本杀 SaaS 的过程拆解

**背景**：一家剧本杀 SaaS 公司刚起步，只有一个专职销售加一群兼职销售，原本靠扫街、打电话、凭感觉推进，年目标约 200 万。

**拆解过程**：

1. **拆路径**：目标用户是即将开店和翻新老店的剧本杀店主，决策路径包括了解产品、体验系统、决定购买、付款、安装上线。
2. **划阶段**：把路径拆为添加微信 → 联系决策人 → 客户探店体验 → 施工安装 → 上线。其中「客户探店」被识别为核心里程碑，因为店主只有亲眼看到系统效果才愿意下单。
3. **配动作**：
   - 每个销售每天加约 16 个微信、联系约 45 家客户。
   - 关键节点必须见面，推动客户探店。
   - 配套话术、产品演示视频、施工案例。

**结果**：团队建立了基本打法，数据开始沉淀，为后续全职销售团队奠定基础。

> 数字说明：以上数据来自课程经验分享，属于特定项目经验，不作为普适业绩保证。

### 案例 2：美容院的美团咨询转化

**背景**：一家美容院连锁，总部在美团投放获客，但在线咨询响应不及时，新客到店转化率低，总部与门店利益不一致。

**拆解过程**：

1. **拆路径**：用户从美团咨询 → 门店回复 → 预约到店 → 到店体验 → 转化购买 → 后续复购。
2. **划阶段**：梳理出从美团咨询到转化的 20 多个关键节点，发现「在线咨询响应速度」是一个高成本决策点——用户等待时间越长，流失率越高。
3. **配动作**：
   - 优化在线咨询响应机制，缩短首次响应时间。
   - 统一到店接待话术和体验流程。
   - 用两家样板店验证，再推广到所有门店。

**结果**：在线咨询响应提升后，新客到店转化率从约 15–20% 提升至约 25%；总部与门店利益逐步统一。

> 数字说明：以上数据来自课程经验分享，属于特定项目经验，不作为普适业绩保证。

### 案例 3：线下培训课的私域招生

**背景**：一家面向创业者的线下培训课程，通过私域微信群招生，同一款产品因首次触达对象不同（老板 vs. 销售总监），决策路径完全不同。

**拆解过程**：

1. **拆路径**：拆出两条路径：
   - 路径 A：销售总监自己想上课 → 内部申请 → 老板审批 → 财务请款 → 上课。
   - 路径 B：老板先接触 → 转给销售总监评估 → 销售总监反馈 → 内部申请 → 财务请款 → 上课。
2. **划阶段**：关键里程碑包括「找到意向客户」「确认购买决策人」「内部审批通过」「财务请款」「打款到账」。
3. **配动作**：
   - 对路径 B，关键动作是确认销售总监才是真正的课程评估者，而非仅让老板拍板。
   - 在请款环节主动提供收款信息，避免客户因流程拖延而遗忘。
   - 高价课程必须电话沟通，解决信任问题。

**启示**：同一产品、同一用户群体，首次触达角色不同，路径和里程碑可能完全不同，不能一套流程覆盖所有客户。

## Checklist

- [ ] 已明确本次拆解针对的「用户类型 + 产品 + 销售方式」组合。
- [ ] 已从用户视角（而非销售视角）梳理出主要决策路径。
- [ ] 路径上的关键节点已归入接触 / 购买 / 付款 / 履约四类决策。
- [ ] 已通过定性分析或定量数据识别出 3–5 个高成本决策点作为里程碑。
- [ ] 里程碑定义满足「用户视角、可判断、可统计、高成本关联」四项标准。
- [ ] 每个里程碑已匹配 1–3 个关键销售动作，并明确动作目标。
- [ ] 关键动作已完成「加法穷尽 → 精准匹配 → 标准定义 → 工具配套」四步。
- [ ] 已建立节点转化率和推进周期的数据监控点。
- [ ] 销售团队已理解阶段和动作标准，避免「干就完了」的粗放执行。
- [ ] 已设定复盘周期，计划根据数据持续迭代路径、阶段和动作。

## Anti-patterns

### Anti-pattern 1：从销售视角拆过程

**症状**：阶段写成「打电话 → 介绍产品 → 邀约 → 逼单」，全是销售动作，看不到用户决策。
**后果**：销售很忙但不知道卡在哪，管理没有抓手。
**修复**：每个阶段都先问：「用户在这个阶段要完成什么决策？」

### Anti-pattern 2：阶段不可量化

**症状**：里程碑写成「建立信任」「加深关系」，无法判断完成与否。
**后果**：过程管理变成玄学，好销售和差销售无法用同一标准衡量。
**修复**：把里程碑换成可观察的用户行为，例如「客户同意引荐决策人」「客户确认预算范围」。

### Anti-pattern 3：只拆不配套动作

**症状**：阶段图做得很漂亮，但一线销售不知道每个阶段该做什么。
**后果**：拆解停留在纸面，无法落地。
**修复**：每个阶段必须匹配动作清单、完成标准和配套工具。

### Anti-pattern 4：过度复杂

**症状**：为了拆解而拆解，阶段多达十几个，每个动作都要监控，销售疲于应付。
**后果**：管理成本剧增，销售抵触，效率反而下降。
**修复**：初期先抓 3–5 个关键里程碑，根据数据逐步细化；非关键环节合并或放权。

### Anti-pattern 5：忽略履约决策

**症状**：销售以「签约」或「付款」作为关单点，不关注客户是否真正使用产品。
**后果**：退款率高、复购率低、客户成功部门被动救火。
**修复**：根据业务模型把关单点定义到合适的履约动作，例如「系统上线走量」「学员完成首次课程」。

### Anti-pattern 6：一套流程覆盖所有客户

**症状**：不同用户角色、不同触达方式共用同一条路径。
**后果**：关键决策人被忽略，路径与实际客户行为脱节。
**修复**：按用户角色、产品、渠道拆出多条路径，分别定义里程碑。

## When NOT to Use

- **产品价值尚未验证**：如果产品本身还没有被市场接受，拆解过程只能帮你更快发现「没人买」，不能替代价值验证。
- **销售周期极短的冲动消费**：例如直播带货、便利店零售，用户决策路径极短，过度拆解反而增加成本。
- **完全依赖个人关系的顶级顾问式销售**：如家族办公室、艺术品经纪，关键变量是信任和关系，难以标准化。
- **数据极少且无法做定性验证**：如果既没有历史数据，也无法访谈客户，里程碑容易变成猜测。
- **团队缺乏执行和复盘能力**：拆解只是开始，如果没有周会、数据监控和迭代机制，拆解会迅速失效。

## OPC 智能体适配

对一人公司（OPC）而言，「销售过程拆解」可以压缩为一个智能体判断：**这个客户现在卡在哪个决策点？下一步该做什么？**

### 输入

- 客户画像与分层标签（S/A/B/C）。
- 客户与创始人的对话记录（微信 / 邮件 / 通话转写 / CRM 备注）。
- 当前已知的销售阶段（可选）。

### 输出

- **阶段判断**：接触 / 购买 / 付款 / 履约，当前处于哪个阶段。
- **关键决策点识别**：用户当前最大的阻力或成本是什么。
- **下一步建议**：该做什么、不该做什么。
- **风险提示**：是否需要创始人亲自介入。

### System Prompt 核心逻辑（精简版）

```text
你是一名销售过程顾问。请根据用户提供的客户对话记录和画像，按以下规则分析：
1. 判断客户当前处于哪个决策阶段：接触 / 购买 / 付款 / 履约。
2. 识别当前阶段用户的核心阻力（时间、金钱、信任、决策链、使用成本等）。
3. 给出 1–2 个下一步关键动作，并说明动作目标。
4. 列出 2–3 个此刻不该做的事，避免过度推进或让客户反感。
5. 如果信息不足，列出还需要确认的 2–3 个问题。
```

### 边界提示

- AI 只提供阶段判断和动作建议，关键信任建立和复杂谈判仍应由创始人主导。
- 涉及客户隐私的对话数据需本地或合规处理。
- OPC 场景下，过程拆解应比团队版更轻量，优先抓住 2–3 个关键决策点即可。

## Critique


**Amy Edmondson**（哈佛商学院教授）会质疑：工具只是能力放大器——如果使用者的判断力不足，工具只会放大错误而非放大正确。
### 外部质疑 1：关系型销售认为过程拆解会扼杀销售灵性

**质疑**：顶尖销售靠的是直觉、临场反应和人际洞察力，把过程拆成标准化动作会让销售变成机器人，失去灵活性。
**回应**：过程拆解针对的是「关键节点的核心动作」，而非所有细节。它提供的是下限保障，让普通销售达到 60–80 分稳定产出，同时为优秀销售保留发挥空间。顶级销售的灵性应被萃取为可复用的动作，而不是被依赖为唯一解法。

### 外部质疑 2：精益创业派认为过早拆解是浪费

**质疑**：在产品价值尚未验证、客户画像模糊时，花大量时间拆路径、定阶段是过早优化，应该用更轻量的方式快速试错。
**回应**：这一质疑在边界上成立。过程拆解适用于「已有基本价值验证、需要规模化复制」的阶段；在 0→1 探索期，应先用最小化流程验证卖点和客户选择，再逐步细化为可拆解的销售过程。

### 外部质疑 3：CRM/SaaS 厂商会把工具当答案

**质疑**：很多 CRM 厂商宣扬「上了系统就能管好销售过程」，导致企业误以为数字化工具可以替代方法论和流程设计。
**回应**：工具是放大器，不是起点。过程拆解必须先回答「用户决策路径是什么、关键里程碑是什么、动作标准是什么」，再考虑用什么工具承载。没有流程先行的 CRM 往往沦为数据录入负担。

### 外部质疑 4：行为经济学质疑「理性决策人」假设

**质疑**：真实用户的决策受情绪、认知偏差、组织政治影响，四类决策模型过度简化了复杂的人类行为。
**回应**：四类决策是启发式框架，不是完备模型。它的价值在于帮助销售团队快速定位卡点，而非精确解释所有行为。对复杂大客户，仍需配合决策链分析、组织政治判断和关系经营。

### 内部局限 1：依赖管理者的分析能力和一线输入质量

拆路径、划阶段、配动作都需要对业务有深入理解，且需要一线销售的真实反馈。如果管理者脱离一线，或销售不愿意暴露真实卡点，拆解容易变成「纸上流程」，与实际执行脱节。

### 内部局限 2：定量分析需要足够的数据样本

节点转化率和推进周期的判断需要一定样本量。初创公司或新产品早期样本不足时，定量分析可能失真，此时更依赖定性分析和快速迭代。过早迷信数据，可能把噪声当信号。

## 边界与风险提示

- **数据隐私**：销售过程拆解可能涉及客户通话、聊天记录、内部审批信息。使用这些数据时需遵守所在司法辖区的数据保护法规，避免未经授权收集或滥用。
- **客户关系**：过程拆解的目的是帮助用户决策、降低决策成本，而非操纵或施压。任何销售动作都应以真实价值和客户利益为前提。
- **法律声明**：本卡仅提供销售管理公共知识扫盲，涉及合同、付款、提成、客户权益等法律判断时，需由专业机构复核。
- **数字性质**：本卡中引用的转化率、客户数量、业绩完成率等数字来自课程经验分享，属于特定项目经验，不应被当作普适业绩保证。

## Synthesis

- `[[framework-一堂五步法-泛产品设计]]`：销售过程拆解是泛产品设计思维在销售场景的应用——把用户决策路径显性化、阶段化、动作化。
- `[[yt-business-formula-parameter-iceberg]]` / `[[tool-iceberg-triangle-modeling]]`：冰山模型帮助识别用户决策中隐藏的隐性变量（如决策链、组织阻力、使用场景），避免只看表面行为。
- `[[framework-yitang-channel-exploration-4step]]`：渠道探索解决「客户从哪来」，销售过程拆解解决「客户怎么从接触到成交」，两者共同构成完整的销售漏斗。
- `[[tool-yitang-customer-segmentation-4step]]`：用户分层决定「哪些客户值得重点打」，销售过程拆解决定「怎么一步步把他们打下来」。
- `[[tool-yitang-sales-performance-management]]`：过程拆解提供「追什么」，业绩管理提供「怎么追、追得怎样」。
- `[[framework-yitang-scientific-sales-five-step]]`：本工具是科学销售五步法中 Step 2「拆解过程」的核心落地工具，与 Step 1 的卖点提炼、Step 3 的业绩管理形成连贯的销售管理体系。
