# AI调研纠偏与验证技能：从“丝滑回答”到“证据决策”的六步闭环

## 原始表述

半肥猫在AI俱乐部分享中说："我觉得AI给的回答越丝滑，问题越大。完全不等于可靠。然后我就会想怎么让这些内容不要做错，比如什么样的Skill值得做，什么样的Skill不值得做，有没有一些检测标准。"

本技能将半肥猫在调研纠偏中的实践沉淀为一套可复用的结构化流程。

## 操作步骤

**步骤1：定义调研目标**

明确需要解答的核心问题和判断标准。产出：调研问题单。

常见失误：目标模糊，AI回答范围过宽。

**步骤2：提供干净上下文**

把原始资料整理成Markdown，清理噪音，标注重点。产出：结构化上下文。

常见失误：直接拷贝粘贴原始文档，信息量过大或过小。

**步骤3：设定判断标准**

告知AI如何评价一个回答是否达标。产出：评价棱角。

常见失误：没有标准，随意接受AI的任何输出。

**步骤4：首轮输出与走偏检测**

获取AI首轮回答，主动识别推理vs证据。产出：走偏诊断书。

常见失误：被"丝滑回答"迷惑，不做质问。

**步骤5：连续纠偏**

根据走偏类型选择纠偏模板，逐轮逼近证据。产出：纠偏对话记录。

常见失误：纠偏指令抹糊，没有具体要求。

**步骤6：贴合真实场景**

把调研结论放回真实业务验证。产出：业务验证报告。

常见失误：调研结论放在文档里不用，没有实际验证。

**纠偏模板库**（在步骤5中使用）：

| 走偏类型 | 检测信号 | 纠偏指令模板 |
|:---|:---|:---|
| 纯推理无证据 | AI用"应该"“通常"等模糊词 | "请用具体数据支撑这个结论。如果没有数据，请明确说'这是推理，缺乏证据'。" |
| 过时数据 | AI引用几年前的数据 | "现在是[insert date]，请用最新数据。如果训练数据截止日期早于[date]，请明确告知。" |
| 地域偏差 | AI默认使用海外/大企业数据 | "请聚焦中国地区微小企业/个体户的实际情况，大企业数据不具有代表性。" |
| 信源不明 | AI未标注数据来源 | "每个数据和结论都必须标注信源和出处。禁止使用自媒体营销软文、无法核实的媒体报道、未经训练的AIGC生成内容。" |
| 极端化表述 | AI使用"所有"“都会"等绝对词 | "请用条件性表述替代绝对表述。如果不能确定，请说'在某些条件下'。" |

## 适用场景

**适合使用**：
- 你正在用AI进行业务调研、市场分析、用户画像研究
- 你的调研结论需要被真实业务验证
- 你有足够的时间进行多轮纠偏

**不适合使用**：
- 你只是想快速获得一个“参考”而不是要做出决策
- 你的任务是纯惄念性/创意性任务，不需要证据
- 你没有真实业务可以验证AI的结论

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 用AI进行业务调研、市场分析、用户画像研究 |
| ✅ 适合 | 调研结论需要被真实业务验证 |
| ✅ 适合 | 有≥5-10轮对话时间进行多轮纠偏 |
| ✅ 适合 | 用户能区分"推理"和"证据" |
| ❌ 不适合 | 只想快速获得"参考"而非做决策 → 用简单提示词即可 |
| ❌ 不适合 | 纯概念性/创意性任务不需要证据 → 纠偏无意义 |
| ❌ 不适合 | 没有真实业务可以验证结论 → 纠偏变成空转 |
| ❌ 不适合 | 用户无法区分推理和证据 → 先培养基础判断力 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **丝滑陷阱** | 被AI流畅回答迷惑，不做质问 | 建立"检测AI编故事的信号系统"，遇到丝滑回答自动触发纠偏 |
| **纠偏过度** | 15轮纠偏后AI开始复读，无新信息 | 检查调研目标是否过于宽泛，纠偏需要焦点 |
| **验证缺失** | 调研结论放在文档里不用，无实际验证 | 步骤6强制贴合真实场景，没有业务验证=空转 |
| **隐私泄露** | 业务数据（用户信息）喂给AI后泄露 | 纠偏前做隐私保护检查，敏感数据脱敏或本地处理 |
| **效率质疑** | 花2-3小时纠偏，初级研究员半天做完 | 纠偏适合复杂决策，简单调研用人工更高效 |
| **模型依赖** | 认为纠偏能弥补模型能力不足 | 模型完全无推理能力时纠偏无效，需换模型或RAG |
| **假设场景纠偏** | 用虚构场景练习，纠偏变成"纠偏假设" | 必须有真实业务问题，虚构场景无法沉淀 |

## Claims

1. **AI首轮回答越丝滑，风险越大**
   - “丝滑”意味着逻辑自洽、表达流畅、听起来对——但这恰恰是推理而非证据的特征
   - 真正可靠的答案往往“结巴”——有限制条件、有不确定性、需要更多信息

2. **纠偏的本质不是"让AI说对"，而是"让自己知道什么时候AI在编故事"**
   - 不是追求AI给出完美答案，而是建立一套"检测AI编故事的信号系统"
   - 纠偏模板库的价值在于将"感觉有问题"转化为"可操作的质问步骤"

3. **真实业务验证是纠偏的唯一终点**
   - 没有业务验证的纠偏，结果可能是“纠偏得更精致的错误”
   - 真实业务提供了"纠偏是否有效”的黄金标准

## External Attacks

**外部攻击者**：

> **“效率至上”派**：你花两三个小时纠偏AI的调研结果，我雇一个初级研究员半天就做完了，成本比你低、质量比你高。你这套"纠偏流程"不是技能，是用新技术复现旧工作流的傻瓜式自动化。如果AI需要被这样“审问”，那它的价值在哪里？

> **“AI原教旨”派**：你这套"质问AI→要求证据→标注信源"的流程，本质上是对AI的不信任。如果一个工具需要被这样对待，说明这个工具本身就不值得用。真正的解决方案是换更好的模型（比如带搜索增强的RAG系统），而不是把人当成AI的保母。

> **“数据隐私”派**：你要求AI引用真实数据、标注信源，但你的业务数据（4000+付费用户信息）已经在调研过程中喂给了AI。你的"验证"是以牺牲用户隐私为代价的。如果这份调研报告泄露，谁为这些数据负责？你的纠偏流程里有隐私保护检查吗？

## Case Studies

**成功案例**：

- [[case-ban-fei-mao-from-assignment-to-tool]] —— 半肥猫运用本技能，将一堂AIGC调研课程作业转化为可复用的调研工具。关键转折：AI首轮回答的“三类用户画像”是纯推理，经过四轮纠偏后，发现"已有流量但被卡住的IP/博主"付费意愿最强，一个纠偏带来了完全不同的商业结论。

**失败案例**：

- **纠偏失败**：某用户在用AI做市场调研时，发现AI给出的竞品分析"听起来很有道理"，但没有质问证据。后来用这份分析做决策，发现AI列出的三个竞品中有两个已经倒闭，一个根本不存在。损失了两周调研时间和一次产品会议的信任度。

- **纠偏过度**：某团队在调研时进行了15轮纠偏，最终AI开始"复读"前面的回答而没有新信息。纠偏未能收敛，团队放弃了这个项目。问题在于：调研目标本身过于宽泛，纠偏没有焦点。

**边界案例**：

- **“假设场景纠偏”**：某学习者用虚构的"小红书博主"场景练习调研，AI给出了精美的用户画像。但因为没有真实业务验证，纠偏变成了"纠偏一个假设"，最终什么都没有沉淀下来。

## Synthesis

### 关联知识节点
- **质量警示：**[[dk-ban-fei-mao-silky-answers-are-dangerous]] — 暗知告诉你"为什么要纠偏"（AI首轮回答是推理而非证据），技能告诉你"怎么纠偏"。两者缺一不可：知道要纠偏但不会方法，等于知道有毒但不会解毒
- **前置条件：**[[dk-ban-fei-mao-real-business-is-the-engine]] — 如果没有真实业务作为燃料，这项技能的纠偏环节会变成空转。真实业务提供了"纠偏是否有效”的验证标准
- **实践案例：**[[case-ban-fei-mao-from-assignment-to-tool]] — 案例展示了技能的具体应用，技能提供了案例的可复制方法
- **下游输出：**[[tool-半肥猫-course-to-skill-workflow]] — 调研纠偏技能用于"获取高质量信息输入"，课程转Skill技能用于"将信息输入转化为可复用工具"。两者是同一条产业链的上下游

### 知识体系定位
- 本技能位于 **AI协作信息层**，是"输入质量控制"的核心工具
- 与一堂方法论的"调研验证"环节对应

### 跨学科锚点
- **认知心理学（确认偏误）：**人们天生倾向于接受符合自己期望的信息——纠偏是一种反本能的认知行为
- **法学（证据法）：**"质证“和"证据分级——与法律领域的证据标准有异曲同工之妙
- **信息论（噪声与信号）：**AI回答中的“丝滑”部分是高信号但低信息量的噪声——纠偏是提高信噪比的过程

**退出条件**：你发现自己只是在"练习使用AI"，而不是在解决真实问题。
