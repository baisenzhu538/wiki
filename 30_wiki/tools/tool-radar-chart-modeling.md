# 雷达图建模法：多维度评估与筛选

> **Burn line**: 当你需要从多个选项中做选择，但不想靠拍脑袋时，先用雷达图把维度拆清楚。

## 用一句话讲清楚

雷达图建模法是把一个复杂决策对象拆成 4–6 个可独立打分的维度，画成多边形后通过面积和形状快速比较强项、弱项与整体均衡性的结构化筛选工具。

## 核心要点

1. **多维拆解**：把"我感觉不错"拆成可讨论、可验证的维度。
2. **维度独立**：4–6 个核心维度，彼此之间尽量不重复、不高度相关。
3. **评分标准**：每个维度使用 1–10 分或 1–5 分，并给出具体可观察的行为定义。
4. **可视化比较**：不同候选对象的多边形形状直接暴露强项、弱项和短板。
5. **决策规则**：提前约定入选、淘汰或排序规则，避免看图后仍然拍脑袋。

## Visual Analysis

雷达图由一个中心向外辐射出 4–6 条轴，每条轴代表一个评估维度。评估对象在每个轴上有一个得分，连成多边形。通过比较不同对象的多边形面积和形状，可以快速看出强项、弱项和整体均衡性。

## Purpose

把主观拍板变成结构化评估，让团队对"什么是好"有共同语言，并暴露单一维度上的明显短板。

## Protocol

### 步骤 1：明确评估目标

你要选什么？评选讲师、筛选选题、评估方案、判断候选人？目标决定维度。

### 步骤 2：头脑风暴所有可能维度

先不筛选，把所有可能相关的维度列出来。例如评估讲师：专业度、表达力、案例质量、学员口碑、价值观匹配。

## When NOT to Use

| 场景 | 为什么失效 | 替代方案 |
|---|---|---|
| **只有 1–2 个维度重要** | 雷达图是多维工具，维度太少不如直接列表比较。 | 清单或 SABC 分级 |
| **维度无法量化/观察** | 雷达图依赖可判断的维度，否则打分变成主观 impression。 | 先访谈/收集事实，再做雷达图 |
| **需要严格因果关系** | 雷达图不表达因果，只表达多维度状态。 | 逻辑链、公式、冰山图 |
| **团队对维度没有共识** | 维度本身有争议时，雷达图会放大分歧。 | 先用专家共识会议敲定维度 |

## 边界

| 边界 | 说明 |
|------|------|
| **维度数量** | 4–6 个最佳，超过 8 个可读性急剧下降 |
| **评分尺度** | 统一使用 1–10 分或 1–5 分，不要混用 |
| **维度独立性** | 尽量避免维度之间高度相关（如"专业度"和"经验年限"可能重复） |
| **权重** | 默认等权，重要场景可显式加权 |
| **参与人数** | 适合小组讨论，大型决策需配合结构化打分流程 |
| **数据来源** | 评分需基于事实/数据，避免纯印象 |

## 失败模式

| 失败模式 | 症状 | 原因 | 修复 |
|---|---|---|---|
| **维度过多** | 雷达图拥挤，难以比较 | 想求全，超过人脑处理极限 | 强制压缩到 4–6 个 |
| **维度不独立** | 多个维度同时高/低，重复计分 | 维度定义重叠 | 合并或删除重复维度 |
| **评分标准模糊** | 同一人两次打分差异大 | 缺乏可观察标准 | 每个分数写一句行为定义 |
| **权重不明确** | 看图后仍拍脑袋 | 默认等权与真实优先级不符 | 显式标注权重或决策规则 |
| **伪装客观** | 用分数掩盖价值观冲突 | 维度/权重隐含立场 | 先对齐维度背后的价值观 |
| **维度缺失** | 入选后发现关键短板 | 没有从事故/反例中补维度 | 用反例测试维度完备性 |
| **可视化误导** | 只看面积不看形状 | 面积受维度数量影响 | 同时比较形状和单项得分 |

## 质疑

- **具体假设**：该工具假设现有方法论框架能指导实践，但框架的有效性依赖于'环境稳定性'——当环境发生颠覆性变化时，旧框架不仅无效，还可能误导。
- **边界**：在全新领域或快速变化的环境中，已有数据和经验可能完全失效——工具的有效性高度依赖场景的稳定性。
- **前提**：该工具的前提是使用者能正确理解和执行工具的规则，但执行者的认知偏差和经验限制会影响工具的实际效果。

**Clayton Christensen**（哈佛商学院教授）会质疑：工具的价值不在于"有没有"，而在于"用得好不好"。任何工具都是"能力放大器"——如果使用者的判断力不足，工具只会放大错误。真正的风险不是"缺少工具"，而是"有了工具后产生的虚假安全感"——让你以为自己已经覆盖了所有可能性，实际上只是走完了流程。
