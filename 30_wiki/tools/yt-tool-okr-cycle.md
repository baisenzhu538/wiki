# OKR 制定与复盘罗盘

> 来源：从 [[yt-management-goal-management]] 概念卡萃取的工具内核。一套季度 OKR 全周期操作工具——从目标对齐到关键结果量化到周度脉搏到季度复盘，防止 OKR 沦为 KPI 换皮。

## Summary

OKR 制定与复盘罗盘是一套季度级目标管理工具。核心主张：OKR 不是"季度初写一次、季度末看一次"的形式文档，而是一个有呼吸的周期系统。本工具卡交付：诊断模板 → O/KR 设定框架 → 对齐会议流程 → 周度脉搏 → 季度复盘——每个阶段都有进入标准、操作步骤和退出标准。

---

## 进入标准（When to Use）

| 场景 | 信号 |
|------|------|
| 新季度/新半年开始，需要制定团队目标 | 日历提醒"下周是 QX 第一周" |
| 当前 OKR 执行中，感觉"偏航了"或"无人关心" | 周会上没人提 OKR，或进展汇报变成"形式主义" |
| 季度末，需要做复盘 | 季度最后两周 |
| 团队扩张或组织变更后，目标需要重新对齐 | 新部门成立、合并或 pivot |

**不满足进入标准**：团队 <5 人且每人都知道自己该干什么（只用简化版：每人 1 个 O + 2 个 KR）、业务方向极度不确定（每周都在 pivot）、高度创造性工作且产出质量优于量化（见不要用的场景 2）。

---

## 操作步骤（Step-by-Step）

### Step 0：季度诊断（制定 OKR 前 1 周）

**目的**：确认"方向基本清晰"——如果方向不清晰，OKR 是建在流沙上的。

填写诊断模板（每个问题不超过 3 行）：

```
【业务诊断】
Q1：上个季度最大的业务变化是什么？_____
Q2：业务公式中哪个变量变化最大？_____
Q3：我们是在"探索期"还是"扩张期"？_____

【组织诊断】
Q4：团队最大的能力矛盾是什么？（想做什么 vs 能做什么）_____
Q5：上个季度 OKR 的关键教训是什么？_____

【决策点】
如果 Q3 答案是"探索期"→ 跳过完整 OKR，用"假设驱动"替代（见不要用的场景 1）
如果 Q5 答案含"方向错误"→ 先开战略会（[[yt-tool-strategy-workshop]]），再回来制定 OKR
```

### Step 1：设定 Objective（季度第一周 Day 1-2）

**原则**：公司级 3-5 个 O，团队级每个部门 1-3 个 O。10 个 O = 0 个 O。

**好 O 的检查清单**：
- [ ] 是否能用一句话说清？（不超过 20 字）
- [ ] 是否"激励人心"而非"告诉任务"？（"成为行业第一" vs "发布 5 个功能"）
- [ ] 是否指向"突破"而非"维护"？（OKR 不是仪表盘）
- [ ] 是否可以被下属团队理解并转化为他们的 O？

**下属团队对齐测试**：
把 O 念给团队听，让他们用自己的话重复。如果重复版本与原版本有轨迹不同——O 还没有被理解。

### Step 2：设定 Key Results（季度第一周 Day 3-4）

**每个 O 配 3-5 个 KR。KR 必须满足 SMART**：

| 检查项 | 标准 | 反例 |
|--------|------|------|
| S 具体 | 指向什么结果 | "提升用户满意度"→ "NPS 从 35 提升到 45" |
| M 可量化 | 有数字或是/否 | "努力做好"→ "错误率从 5% 降到 2%" |
| A 有挑战 | 跳一跳够得着（70% 完成即优秀） | "日活增长 1%"→ "日活增长 20%" |
| R 相关 | 与 O 直接相关 | O="打破口碑"、KR="修复 bug 50 个"→ 不直接相关 |
| T 有时限 | 季度末截止 | 无 DDL 的 KR 不是 KR，是愿望 |

**红线检查**：KR 是"结果"而非"任务"。对每个 KR 问："如果这个结果达成了，但是没有做任何任务——还能成立吗？"如果答案是否定的，这是结果；如果答案是肯定的（必须做了某些任务才能达成），这是任务。

### Step 3：目标对齐会议（季度第一周 Day 5）

**流程**：
1. 老板先分享公司级 OKR（30 min）
2. 每个部门负责人提出部门级 OKR 草案（每人 10 min）
3. 交叉质询："你们的 KR 如何支撑其他部门的 O？"——关注"竖向对齐"而非"竖向叠加"
4. 双向承诺：每个部门级 OKR 必须有"向上支撑"（支撑老板 O）和"向下支撑"（被下属团队理解并转化）
5. 锁定并发布：全公司 OKR 公开可见

**对齐质量门槛**：
- 每个部门级 O 必须能追溯到至少 1 个公司级 O
- 每个部门级 KR 必须能追溯到至少 1 个部门级 O
- 如果某个部门的 OKR 与其他所有部门都没有交叉——要么这个部门被隔离了，要么这个 OKR 是多余的

### Step 4：周度脉搏（季度中每周/每双周）

**周度脉搏会议（15 分钟）**：

```
周度脉搏仪式
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
时间：每周一上午 9:00-9:15（固定时间盒，不延长）

仪式流程：
1. 每个部门负责人用 1 分钟报告：
   - 本周最重要的 1 个进展
   - 本周最大的 1 个阻碍
   - 下周最关键的 1 个动作
2. 老板用 2 分钟回应：
   - 哪个 KR 需要资源倾斜？
   - 哪个 KR 已经失去意义应该放弃？
   - 哪个新出现的机会/风险需要加进来？
3. 行动项（1 分钟）：什么改变从今天开始执行

禁止：
- 不讲过程（不要说"我们做了什么"）
- 不解决方案（脉搏会只是发现信号，解决方案单独开）
- 不超时（15 分钟到点结束）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### Step 5：季度复盘（季度最后两周）

**复盘四问**：

1. **达成度**：每个 KR 的实际完成率？（不是打分，是记录）
2. **价值度**：达成的 KR 真的创造了价值吗？（Deming 式拆谜）
3. **学习度**：没达成的 KR 教了什么？为什么会偏差？
4. **下一季度调整**：哪些 KR 应该放弃？哪些新出现的机会应该加进来？

**复盘产出**：
- 季度 OKR 完成报告（含达成率 + 价值审计）
- 下季度 OKR 初稿（基于复盘调整）

## 退出标准（Done When）

| 检查项 | 标准 |
|--------|------|
| 诊断 | 季度诊断模板已填写，确认不是"探索期" |
| 目标 | 公司级 O ≤3-5 个，每个 O 都通过"下属团队对齐测试" |
| 关键结果 | 每个 O 有 3-5 个 KR，每个 KR 通过 SMART 检查 + 红线检查 |
| 对齐 | 目标对齐会已开完，全员 OKR 公开可见，每个部门级 OKR 能追溯到公司级 O |
| 脉搏 | 季度中至少进行了 6 次周度脉搏 |
| 复盘 | 季度末完成"复盘四问"，产出完成报告 + 下季度初稿 |

**最小可行版本**：第一次使用只做 Step 1（只写 1 个 O + 2 个 KR）+ Step 3（对齐会议简化版）。跑通一个季度后再加载完整流程。

## 常见陷阱（Pitfalls）

| 陷阱 | 信号 | 对策 |
|------|------|------|
| **KR 写成任务清单** | "完成 XX 功能上线"、"发布 10 篇文章" | 红线检查："没做任何任务但达成了结果，还能成立吗？" |
| **OKR 与绩效奖金直接挂钩** | "KR 完成率决定年终奖" | 第一个季度明确宣布"不挂钩"——完成了问"学到了什么"，没完成也问"学到了什么" |
| **老板的 OKR = 团队的 OKR 简单拆解** | 老板的 KR 直接变成部门的 O | 要求 30-50% 的 O 来自团队自下而上的提案 |
| **设定后不追踪**——"写完就放进抽屉" | 季度中没人提过 OKR | 固定周度脉搏会议，15 分钟，不取消 |
| **O 太多 = 没有突破点** | 一个团队有 8 个 O | 公司级 ≤3-5 个 O，部门级 ≤3 个 O，10 个 O = 0 个 O |
| **季度复盘变成"打分考核"** | 复盘会上给 KR 打分、排名次 | 复盘四问中没有"打分"——只有"达成率"、"价值审计"、"学习"、"调整" |

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:------|
| ✅ 团队方向基本清晰、处于执行/扩张期 | OKR的前提是"知道要往哪走"。探索期应改用假设驱动 |
| ✅ 团队≥5人、有跨部门协作需求 | 少于5人的团队直接对齐即可，OKR的形式成本大于收益 |
| ❌ 业务高度不确定（每周都在pivot） | 方向不确定时OKR是建在流沙上的——锁定错误方向比没有方向更糟 |
| ❌ 创造性工作占主导、产出质量优于数量 | 量化型OKR会挤出内在动机，导致"做得多但质量差" |

## 外部攻击

### Henry Mintzberg：战略是涌现的——你的 OKR 周期假设方向是一个月前就能设定的

**Henry Mintzberg**（McGill University，*The Rise and Fall of Strategic Planning* 作者）的核心论点：真正有效的战略不是计划出来的，而是在实践中**涌现**（emerge）的。Mintzberg 跟踪了 10 家公司的战略制定过程，发现最有效的战略决策往往发生在日常运营中，而非战略会上。

对 OKR 罗盘的攻击：你的工具假设"方向在季度初就是清晰的"，然后用一个季度的时间去执行。但 Mintzberg 的研究表明：在快速变化的环境中，正确的方向可能在季度第二个月才涌现出来——而你在第一个月就锁定了 OKR。这不是说 OKR 没用——而是说：当 OKR 遇到"方向需要调整"的时候，你的周期系统是否允许中途调整？如果 OKR 是"季度初定好就不能改"的钢板，它不是工具，是笼子。

> **Mintzberg 的拷问**："你的 OKR 罗盘在季度第一周 Day 5 锁定了全公司 OKR，然后周度脉搏追踪到季度末。但 Mintzberg 会问：如果季度第二个月你发现了一个比原来 O 更重要的方向——你的系统允许你在季度中增加或替换 O 吗？如果不允许，你的 OKR 是计划，不是战略。如果允许，你是怎么处理'方向变化了但已经投入了 2 个月精力的 KR 怎么办'这个问题的？"

### Lisa Ordonez：目标设定的副作用——你的 OKR 可能正在系统性地损害团队

**Lisa Ordonez**（亚利桑那大学奥尔布鲁克学院，*目标设定的作用与副作用* 系列研究作者）的研究系统地记录了"目标设定"在组织中的隐性代价。核心发现：

- **目标的紧张效应**：当人们被告知"你必须达成目标" 时，他们会系统性地避开危险任务、减少探索行为、停止帮助同事（同事的成功不计入自己的 OKR）。
- **多目标的冲突**：当 OKR 同时追求多个目标（比如"提高收入" + "提升用户满意度" + "控制成本"）时，员工会在目标之间进行权衡——而不是做出最正确的决策。
- **目标的矛盾激励**：最让人不安的发现是：当目标与内在动机冲突时，目标往往胜出——但是胜出后的行为变得短视、机械、危险原恨。

对 OKR 罗盘的攻击：你的工具卡设计了精美的流程来追踪 OKR。但 Ordonez 会问：你追踪了"达成率"，但你追踪了"目标带来的行为变化"吗？如果一个团队的 OKR 完成率从 60% 提升到 80%，但同时这个团队的面试完成率下降了（因为面试不计入 OKR）、同事间的信任度下降了（因为没有人有时间帮助别人）、创新尝试次数下降了（因为创新风险大且不计入 OKR）——你的 OKR 系统是在推动进步，还是在系统性地损害进步？

> **Ordonez 的拷问**："你设计了一个精美的 OKR 追踪系统。但 Ordonez 会问：在你的周度脉搏会上，有没有一个问题是'本周有没有因为 OKR 的引导而忽略了其他重要但不计入目标的事情'？如果没有这个问题，你的脉搏会不是在保护组织健康，它是在系统性地让团队变得短视。"

## 不要用的场景

| 场景 | 为什么失效 | 替代方案 |
|------|-----------|---------|
| **团队在探索 PMF，方向不确定度极高**（如每周都在 pivot 的 0→1 阶段） | OKR 假设"方向基本清晰、需要量化执行"。在探索期，连"正确方向"都不知道，KR 是建在流沙上的。Deming 说：在没有稳定过程的系统中引入目标管理，你不会得到更好的结果——你会得到更聪明的借口。 | 用"假设驱动"替代 OKR：每周列 3-5 条关于产品的关键假设（"用户会因为 X 付费"），每条配一个"验证方法"和"本周要做的验证动作"。目标是"学得快"而非"做到某个数字"。验证速度是唯一需要追踪的指标。 |
| **面对高度创造性工作，产出质量优于量化**（如研发、设计、内容创作） | Muller 指出：创造性工作最有效的激励是内在动机（自主性 + 精通性 + 目的感），外在指标会挤出内在动机。如果设计师的 OKR 是"产出 20 个方案"，他会产出 20 个平庸方案并在 2 个月内离职。 | 去量化，用"作品集回顾"替代 KR：每月底做一次"这个月我最好的作品是什么"的团队分享。不看数量看质量，不评估"完成率"而是互相给反馈。如果团队做不出任何自己骄傲的东西，不是目标不够明确，是工作环境出了问题。 |

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|---------|-----------|---------|
| **第一次在团队推行 OKR，担心"搞成变相 KPI"** | 第一个周期（Q1）OKR 不与任何奖惩挂钩——明确向全员宣布"这个季度的 OKR 只是用来练习的。季末如果某个 KR 完成了，我们会问'学到了什么'；如果没完成，我们会问'学到了什么'——而不问'谁的责任'" | Q1 结束后团队对"OKR 和绩效脱钩"的信任度 >70%（匿名投票），且至少 2 个 KR 在季度中被主动上调（说明团队不怕设高目标） |
| **发现团队在玩"OKR 游戏"——设低目标、挑软柿子、只做能量化的事** | Muller 提醒你已进入"指标专政"模式。暂停本季度 OKR 的完成率考核，改成"意外发现"回顾会——"这个季度发生了什么 OKR 没有预见到的事？这些事对我们真正目标的影响是什么？" | 回顾会上至少提到 3 个"OKR 没覆盖但实际重要"的事项；下一季度至少有 1 个 KR 是从"意外发现"转化来的而非从业务公式推导出来的 |
| **季度末 OKR 完成率 70%+ ，但你对业务真实进展的感觉比 70% 差很多** | Deming 在此告诉你：KR 完成率 ≠ 业务进展。做一次"KR 拆谎"——逐个 KR 问"这个数字的提升真的创造了用户/客户价值，还是只是数字变好看了？"剔除以操作手段达成的 KR | 至少有 1 个 KR 被标记为"完成但无真实价值"——这一条出现在复盘中的频率直接反映了你的团队在"指标游戏"中的投入程度 |
