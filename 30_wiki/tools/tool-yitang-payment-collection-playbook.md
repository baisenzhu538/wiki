# 回款 / 催款 / 履约阶段 playbook

> 数字与比例说明：本卡中所有金额、时长、顺序判断与关单标准均来自课程经验分享，属于特定业务场景的经验值，不作为普适标准或业绩保证。

## 一句话

把「签约≠关单」显性化：用四类用户决策（接触/购买/付款/履约）重新映射回款节奏，在合规边界内灵活重构付款顺序，并用标准催款动作把现金流风险前置管理。

## 目的

解决 B2B 长周期销售中「合同签了款没收、客户说付款但财务忘了、上线走量才算真正成交」的灰度问题。让销售在付款/履约阶段有阶段判断、有关单标准、有合规边界，降低现金流波动和误判成单的概率。

## When to Use

- 客户决策链长，签约与付款/履约不同步（如 To B SaaS、培训、咨询、分销）。
- 销售把「签约」当关单，但后续回款/上线周期长、流失率高。
- 需要优化付款顺序以缩短收款周期（如小老板客户、定金锁定场景）。
- 周会/日报中出现「客户答应了但款没到账」的滞后信号。
- 销售团队对「什么时候算真正成交」没有统一标准。

## When NOT to Use

- **产品价值尚未验证**：过早固化付款/履约流程只会加速验证「没人买」。
- **冲动消费或即时付款场景**：如直播带货、便利店零售，用户决策路径太短，无需独立回款阶段。
- **公司合规要求必须先签合同/先开票后付款**：此时重构顺序的建议需直接禁用，按公司法务/财务流程执行。
- **完全依赖个人信誉的顶级顾问式销售**：信任关系凌驾流程，标准化催款动作可能破坏关系。
- **团队没有周会/数据监控**：回款 playbook 需要过程数据支撑，否则动作无法闭环。

## 操作步骤

### Step 1：判断客户当前处于哪类决策点

用 [[tool-yitang-sales-process-decomposition]] 的四类决策重新定位：

| 决策类型 | 核心判断问题 | 常见信号 |
|:---|:---|:---|
| **接触决策** | 用户愿不愿意继续沟通？ | 接电话、加微信、回消息、参会 |
| **购买决策** | 用户是否决定要买？ | 明确意向、进入内部评估、要方案 |
| **付款决策** | 用户是否完成付款动作？ | 合同审批、请款、开票、打款 |
| **履约决策** | 用户是否真正开始使用？ | 上线、安装、消课、走量、复购 |

> 课程经验：很多销售把「购买决策」当成终点，忽略了付款和履约是独立的决策点，导致回款周期长、关单标准混乱 [课程经验值]。

### Step 2：识别付款/履约卡点和关键人物

针对付款决策和履约决策，列出卡点：

| 卡点类型 | 典型表现 | 关键人物 |
|:---|:---|:---|
| 内部审批慢 | 客户说已报请款，但财务/法务卡住 | 采购、财务、法务、老板 |
| 合同流程长 | 盖章、邮寄、条款反复 | 法务、决策人、行政 |
| 付款动作遗忘 | 客户答应付款但迟迟未打 | 对接人、财务 |
| 履约启动难 | 系统未安装、学员未上课 | 客户成功、使用部门 |
| 上线走量慢 | 支付产品未产生真实交易 | 技术、运营、商户 |

### Step 3：重构付款/履约顺序（合规边界内）

根据客户类型和决策路径，判断哪些环节可以前置或后置：

| 场景 | 可尝试的顺序 | 合规边界 |
|:---|:---|:---|
| 中小老板客户、客单价低、信任高 | 先付款 → 后补合同/后开票 | **需财务/法务复核**：确认公司合规允许后补合同/后开发票，且保留付款凭证。 |
| 需要锁定客户但合同未就绪 | 先收定金 → 再补合同/再付尾款 | **需财务/法务复核**：明确定金、尾款、违约责任与退款条款，避免口头约定。 |
| 标准企业客户、合规严格 | 先签合同 → 再付款/再履约 | **需财务/法务复核**：按公司法务/财务流程执行，不可为提速绕过审批。 |
| 履约即收益（如支付走量） | 签约/付款后，以上线走量为关单 | **需财务/法务复核**：确认收入确认与关单标准符合会计准则。 |

> 课程经验：线下培训场景中，中小老板客户常现场付款、后续补合同；剧本杀系统销售中，先收定金锁定客户比纠结合同更重要 [课程经验值]。

### Step 4：匹配催款话术与标准动作

根据付款阶段和逾期风险，选择动作：

| 阶段 | 销售动作 | 话术模板 |
|:---|:---|:---|
| 意向确认后 | 立刻发送标准收款信息（账号、金额、备注） | 「张总，方案已确认，我把收款信息发您，方便您安排请款。」 |
| 承诺付款后 1–2 天 | 温和确认：是否已提交请款？还需要什么材料？ | 「王经理，昨天您说这周安排付款，想确认一下财务那边还需要我补充材料吗？」 |
| 承诺付款后 3–7 天 | 提醒+了解卡点：是人忘了还是流程卡了 | 「李总，款项还没到账，我担心是不是我们流程上有什么没配合到位，还是内部审批卡住了？」 |
| 逾期 > 7 天 | 升级：请对接人同步决策人或财务催办 | 「赵总，这笔款财务已经多次提醒，能否麻烦您帮我问一下进展，或者我让财务直接对接贵司财务？」 |

> 课程经验：销售常犯的错误是「客户答应付款后就干等」；应在付款节点主动跟进财务是否已请款、是否遗忘 [课程经验值]。

### Step 5：定义关单标准并回写过程数据

根据业务模型确定「真正关单点」：

| 业务类型 | 建议关单标准 |
|:---|:---|
| 一次性交付产品/服务 | 款项到账且合同签署完成 |
| SaaS / 支付 / 需要上线走量 | 上线并产生真实交易/走量后 |
| 培训 / 健身私教 | 学员完成首次课程/销课后 |
| 订阅制 | 首期付款且完成首次激活 |

动作：将关单标准写入 CRM/跟进表，并在周会中用 Gap 分析复核。

## 示例/模板

### 模板 A：付款顺序重构决策表

| 客户类型 | 决策路径特征 | 建议顺序 | 必须复核 |
|:---|:---|:---|:---|
| 中小老板、个人决策者 | 自己就能决定付款 | 先付款 → 后补合同 | **需财务/法务复核** |
| 大型企业、多层审批 | 需法务/财务/老板审批 | 先签合同 → 后付款 | **需财务/法务复核** |
| 竞争激烈、需锁定 | 客户多家比价 | 先收定金 → 再签正式合同 | **需财务/法务复核** |
| 履约即收入 | 上线走量才产生收益 | 签约/付款 → 以上线走量为关单 | **需财务/法务复核** |

### 模板 B：催款跟进清单

- [ ] 客户已明确购买意向并确认金额/付款方式
- [ ] 收款信息已以标准格式发送
- [ ] 客户内部请款流程/审批人已确认
- [ ] 承诺付款日期已记录
- [ ] 承诺日期前 1 天已做温和提醒
- [ ] 逾期 3 天内已了解卡点（人/流程）
- [ ] 逾期 7 天内已升级到决策人/财务对接
- [ ] 款项到账后更新 CRM 并触发履约/上线动作
- [ ] 上线/走量/首次使用后才算真正关单（视业务模型）

### 模板 C：关单标准确认表

| 业务模型 | 何时算「成单」 | 何时算「关单」 |
|:---|:---|:---|
| 线下培训 | 客户付款 | 客户到场并完成首次课程 |
| SaaS 订阅 | 客户签约 | 上线并产生首次真实使用 |
| 支付产品 | 客户签约/付款 | 上线后走量一周 |
| 私教健身 | 客户购课 | 完成首次销课 |

> 课程经验：支付产品案例中以「上线走量一周」作为关单，而非签约或付款 [课程经验值]。

## Critique

### 外部质疑 1：公司法务/合规官会认为「先付款后补合同」触碰合规红线

**身份**：企业法务总监 / 内控合规负责人

**冲突点**：本卡主张在中小客户场景下可重构付款顺序，但合规体系要求「先签约、后付款、后开票」，重构可能引发合同风险、税务风险和审计问题。

**睡不着的问题**：「如果销售为了成单绕过合同审批，客户事后以未签合同为由要求退款或索赔，财务如何确认收入？审计问到这笔无合同收入时，你用什么证明交易成立？」

**回应**：本卡把「需财务/法务复核」作为强制前置条件，且只建议在「客户类型允许、公司合规授权、保留付款凭证」的前提下使用；对标准企业客户仍要求先签合同。

### 外部质疑 2：财务总监会质疑「关单标准」与收入确认冲突

**身份**：上市公司财务总监 / 会计准则专家

**冲突点**：销售以「上线走量」或「首次使用」作为关单，但财务收入确认可能以签约/付款/交付为准，两者口径不一致会导致业绩预测与财报脱节。

**睡不着的问题**：「如果销售部门把『上线走量』当成成交，财务部门按签约确认收入，月底对账时两边的数字差出几十万，你让 CFO 信谁？」

**回应**：本卡明确区分「销售关单点」（过程管理抓手）与「财务收入确认点」（会计准则），两者需对齐但不必相同；涉及收入确认、退款、开票标准时必须由财务/法务复核。

### 外部质疑 3：行为经济学/谈判学者会认为催款话术损害关系

**身份**：谈判学教授（如哈佛谈判项目）

**冲突点**：标准化催款动作把客户关系推向交易化，反复提醒付款会激活客户的损失厌恶与防御心理，降低长期合作意愿。

**睡不着的问题**：「当你的催款话术让客户感觉『你只关心钱』时，你损失的复购和转介绍价值，是否大于这笔回款带来的现金流？」

**回应**：话术设计以「服务客户完成付款流程」为出发点，而非施压；对高价值长期客户应降低催款频率，增加履约支持动作。

### 外部质疑 4：顶级关系型销售会认为流程化回款破坏信任

**身份**：大客直销老兵 / 家族办公室顾问

**冲突点**：在关系驱动型销售中，过度标准化的催款/履约动作会让客户觉得销售「公事公办」，削弱人情资本。

**睡不着的问题**：「如果你的关键客户因为你按 playbook 催款而认为你不再『够意思』，下次大单他还会第一个想到你吗？」

**回应**：本卡提供的是底线动作和可选策略，不是机械执行；对高信任客户应把催款动作包装成「协助完成内部流程」，并允许销售根据关系深浅调整节奏。

### 内部局限 1：前置依赖客户分层和过程拆解

如果 [[tool-yitang-customer-segmentation-4step]] 和 [[tool-yitang-sales-process-decomposition]] 没做到位，销售无法准确判断客户类型和决策阶段，导致付款顺序重构建议错配（如把大企业当小老板处理）。

### 内部局限 2：行业差异和合规差异大

课程案例集中在 To B SaaS、培训、支付、剧本杀等场景；对医药、金融、政府等强监管行业，「先付款后补合同」等重构策略可能直接违法，必须按行业合规要求裁剪。

### 内部局限 3：催款效果依赖关键人物信息

如果销售不知道客户内部真正的审批人、财务对接人、决策人是谁，催款动作会卡在对接人层级，效率低下。

## Synthesis

- `[[tool-yitang-sales-process-decomposition]]`：本 playbook 是销售过程拆解中「付款/履约决策」的专项落地工具，承接其四类决策框架。
- `[[framework-yitang-scientific-sales-five-step]]`：对应 Step B「拆解过程」和 Step C「推进业绩」，把关单标准从签约推进到履约。
- `[[dk-yitang-sales-common-pitfalls]]`：本卡直接对抗「过程黑盒陷阱」和「目标拍脑袋陷阱」，防止销售以签约代替回款。
- `[[tool-yitang-sales-performance-management]]`：回款/履约数据是 Gap 分析和周会复盘的重要输入。
- `[[opc-ai-sales-agent-architecture]]`：可作为「回款/履约风险预警 Agent」的调用卡，由 Agent 判断阶段、输出催款建议、附加合规提示。
- `[[framework-yitang-sales-incentive-6d]]`：提成/奖金设计应与关单标准对齐，避免激励销售只追签约不追回款。
