# 员工公开名录分析

> 通过钉钉/飞书/企业微信的公开组织架构、打卡信息、通讯录取反推公司组织。

**做法**：
- 从脉脉、领英、看准网收集竞对公司员工的公开信息，拼出部门结构和汇报关系
- 通过钉钉/飞书/企业微信的公开组织架构功能查看部门设置和人员分布
- 交叉比对招聘信息（岗位名称/所属部门）反推组织架构的扩张方向

**价值**：拼出竞对的完整组织架构图——哪些部门在扩张、哪些在收缩、汇报关系是怎样的。

**坑**：组织架构可能已经过时（员工离职后脉脉信息不更新）。多源交叉验证。

*卡片类型：tool | 审核状态：待审*

## 目的

解决"竞对组织架构黑箱"问题——你不知道对手有多少人、分了哪些部门、谁向谁汇报、哪些团队在扩招。适用于竞品分析、投资尽调、人才竞争策略制定。通过公开渠道拼出对手的组织架构图，判断其战略重心转移和资源分配变化。

## 操作步骤

1. **信息采集**：从脉脉/领英/看准网收集目标公司员工的公开信息（部门、职级、入职时间），同时在钉钉/飞书/企业微信的公开页面查看组织架构
2. **结构拼图**：将收集到的员工信息按部门归类，画出组织架构树；重点标注新设部门（扩张信号）和缩减部门（收缩信号）
3. **交叉验证**：用招聘网站的岗位 JD 交叉验证——如果持续招"直播电商负责人"，说明该部门在扩张；如果某部门半年没有招聘，可能在收缩

## 不要用的场景

- **初创公司（<30人）**：组织架构简单到不需要逆向分析，直接问就能知道
- **高度保密的军工/政务领域**：员工信息不公开，此方法完全失效
- **需要精确到个人汇报关系**：公开信息只能拼出大概框架，无法精确到每条汇报线
- **快闪型项目团队**：组织架构变动极快，拼出来的图三天就过时

## 质疑

- **具体假设**：该工具假设结构化方法论本身能产生正确结论，但方法论只是框架——结论质量取决于输入数据的质量和执行者的判断力。
- **边界**：在数据稀缺或快速变化的新兴领域，已有经验框架可能完全失效——工具的有效性高度依赖场景的稳定性。
- **反例**：一个团队完整执行了所有步骤，产出了漂亮的文档，但核心假设从一开始就是错的——流程的完整性掩盖了判断的缺陷。
- **前提**：使用者已具备该领域的基础认知，能正确理解和执行工具规则，且数据来源具有代表性。

**核心局限**：公开信息永远是滞后快照——你拼出的是"过去的组织架构"，不是"现在的"。

**Henry Mintzberg**：「组织架构不是一张图表能概括的。真正决定组织行为的是非正式网络——谁和谁关系好、谁实际说了算——这些信息从公开渠道永远拿不到。」

**Adam Grant**：「过度关注组织架构会让你忽略人才个体的能动性。一个关键人物的离职比整个部门的重组影响更大，而组织架构图看不出谁是关键人物。」

**关键术语**：组织架构逆向工程（org chart reverse engineering）、非正式网络（informal network）、滞后快照（lagging snapshot）
