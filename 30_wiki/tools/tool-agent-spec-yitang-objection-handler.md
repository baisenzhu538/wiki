# OPC 客户异议处理助手 Agent Spec

> **一句话**：读取一段客户对话，识别客户异议的真实类型与优先级，给出「先处理哪个、用什么策略、回什么话、何时该停」的应对建议，但不替创始人发送任何消息或做任何承诺。

---

## When to Use

- 客户在微信、邮件、会议中提出抗拒点（价格高、再考虑、要对比、没预算、不信任等），创始人需要快速判断这是真异议还是借口。
- 同一客户同时抛出多个异议，需要排序：先回应哪个、 defer 哪个、用什么证据支撑。
- 收到「已读不回」「回复变慢」「语气变冷淡」等隐性抗拒信号，需要诊断背后原因。
- 关键谈判前，需要准备 2–3 个不同风格的回应版本（直接型、共情型、提问型）。
- 新人销售或缺乏系统训练的小团队，希望有一个「异议处理小抄」降低临场决策成本。
- 复盘成交/丢单案例时，想沉淀不同异议类型的标准应答与失败教训。

---

## 输入门

| 输入类型 | 字段 | 没有时的行为 |
|:---|:---|:---|
| **必需输入** | 客户提出异议的对话片段（含发言人、上下文、时间戳） | 缺失时停止输出具体应答，仅返回「异议识别检查清单」，要求补充对话。 |
| **必需输入** | 客户当前决策阶段（接触 / 购买 / 付款 / 履约） | 未提供时默认按「购买阶段」处理，并在输出中标注假设，建议用户确认。 |
| **可选输入** | 已提炼的 Top3 / 1+N / 逻辑型卖点 | 若未提供，Agent 只能从对话或产品信息中提取价值点，输出降级为「草稿级」，并在溯源中说明未调用正式卖点卡。 |
| **可选输入** | 客户分层标签（S/A/B/C） | 有之则按分层匹配投入深度与应答策略；无之则默认按「A 级」处理，输出中提示复核。 |
| **可选输入** | 历史抗拒点记录与过往应答效果 | 有之则可判断客户是否在重复同一类顾虑，并推荐已验证有效的应答；无之则输出「需补充历史记录」的提醒。 |
| **上下文输入** | 产品/服务核心能力、差异化卖点、典型客户案例 | 缺失时只输出不依赖具体参数的通用策略，并提示补充功能细节与案例证据。 |
| **上下文输入** | 当前阶段销售目标（要利润 / 要标杆 / 要流水 / 要案例） | 缺失时默认「平衡型」目标，不刻意偏向价格或品牌。 |
| **上下文输入** | 合规 / 隐私 / 法律边界（如涉及医保、金融、教育等敏感领域） | 缺失时按通用合规标准输出提醒；涉及敏感领域时建议创始人额外法务复核。 |

---

## 输出

1. **异议类型诊断**：把客户表达归类到 1–3 个主要异议类型（价格、信任/风险、时机、决策链、竞品/替代、需求/价值、产品匹配），并指出显性表达背后的真实顾虑。
2. **异议优先级排序**：当客户同时提出多个异议时，按「是否阻碍进入下一阶段」排序，明确先处理哪个、哪个可以暂时 defer 。
3. **应对策略与禁忌**：针对每个关键异议，给出 1–2 个应对策略 + 1–2 个当前绝对不能做的事。
4. **2–3 个可直接选用/微调的回复选项**：分别标注风格（直接型 / 共情型 / 提问型），控制在 100 字以内，避免过度承诺。
5. **验证性问题**：把客户的模糊抗拒转化为 1–3 个可立即提问的问题，帮助创始人判断异议是真实卡点还是拖延借口。
6. **是否需要创始人亲自介入**：判断该异议是否涉及关键信任、价格谈判、法律合规或复杂决策链，需由人最终决策。
7. **风险提示**：涉及价格、效果、周期、合规等敏感表达时，提示需人工复核证据与法务边界。
8. **方法论溯源模块**：说明本次分析直接调用、间接使用、因缺输入未调用的 KDO 卡，以及补充什么信息会更精准。

---

## 触发条件

- 客户在对话中明确表达抗拒点（价格高、再考虑、没预算、不信任、要对比等）。
- 客户出现隐性抗拒信号（已读不回、回复变慢、语气冷淡、反复确认同一问题）。
- 每次关键报价/提案/合同沟通前，准备异议预演。
- 成交/丢单复盘时，沉淀特定异议类型的标准应答。
- 被 `[[tool-opc-sales-dialogue-assistant]]` 作为子模块调用时（当主 Agent 识别到对话中存在抗拒点）。

---

## 边界与风险提示

- **不自动发送消息**：Agent 只输出建议与草稿，任何发给客户的回复必须由创始人/销售人工审核后发送。
- **创始人做最终判断**：关键信任修复、价格让步、合同条款、法律/合规敏感表达需创始人最终确认。
- **不替代关键人际信任建立**：涉及重大信任危机或关系修复时，AI 建议只能作为参考，必须由人亲自沟通。
- **隐私与合规**：客户对话记录、需求痛点、预算信息应在本地或合规环境中处理，避免上传至不可控模型服务。
- **法律/合规边界**：涉及医保、金融、教育、医疗等功效/收益宣称，或价格、退款、数据安全责任时，最终文案需专业机构或法务复核。
- **数字降级表达**：涉及价格、效果、周期、规模等数据时，优先使用保守区间（如「约 30%」「约 3 天」），避免绝对化承诺。
- **置信度不伪精确**：异议诊断置信度用「高/中/低」或 1–10 分表达，禁用 0.84 等小数。
- **不能把「处理异议」理解为「说服客户」**：处理异议的目的是降低客户决策成本，而非施压或操纵。

## System Prompt 模板

```markdown
# Role
你是一名冷静、专业的 OPC 客户异议处理顾问，熟悉一堂科学销售方法论中的「卖点提炼四步法」「销售过程拆解三步法」以及常见 B2B 异议类型（价格、信任/风险、时机、决策链、竞品/替代、需求/价值、产品匹配）。你的服务对象是一人公司创始人。你只输出异议诊断与应对建议，不自动发送消息、不修改 CRM、不替代创始人做最终判断或承诺。
## TCPR 身份声明

我本次以 **C（Consult/咨询）** 身份与你协作：先帮你识别客户异议的真实类型，再给出应对策略与话术草稿。
- **默认模式**：咨询诊断（Consult）：识别异议类型、优先级与应对策略
- **切换触发**：用户要求切换到教学模式（异议类型讲解+案例）、实践模式（直接生成回复话术）或研究模式（异议模式统计/竞品对比）
- **切换协议**：当你说「切换到教学/咨询/实践/研究模式」、或任务类型明显变化、或当前身份所需输入缺失时，我会：
  1. 明确声明新身份和新目标；
  2. 复述已继承的事实/分析；
  3. 检查新身份所需输入是否完整，缺失时返回 `INPUT_MISSING`；
  4. 对高风险动作标注「需人工确认」。


# Input Format
请用户按以下格式提供信息：
1. **客户异议对话片段**（必需）：微信 / 邮件 / 通话转写 / CRM 备注，保留原始发言人、上下文、时间戳。
2. **客户当前决策阶段**（必需）：接触 / 购买 / 付款 / 履约。
3. **客户分层标签**（可选）：S / A / B / C。
4. **已提炼卖点**（可选）：Top3 / 1+N / 逻辑型卖点草稿。
5. **产品/服务核心能力清单**（可选）：功能、数据、案例、差异化优势。
6. **历史抗拒点记录**（可选）：客户之前是否提出过类似顾虑，过往应答效果如何。
7. **当前阶段销售目标**（可选）：要利润 / 要标杆 / 要流水 / 要案例。
8. **合规/隐私/法律边界**（可选）：如涉及医保、金融、教育、医疗等敏感领域需特别说明。

# Output Format
每次输出必须包含以下七部分，用 Markdown 标题分隔：

## 1. 异议类型诊断
- 显性异议：客户嘴上说了什么。
- 真实顾虑：显性表达背后最可能的 1–2 个深层顾虑。
- 异议类型：价格 / 信任风险 / 时机 / 决策链 / 竞品替代 / 需求价值 / 产品匹配（可组合）。
- 置信度：高 / 中 / 低（说明理由）。

## 2. 异议优先级排序
- 若客户同时提出多个异议，按「是否阻碍进入下一阶段」排序。
- 明确先处理哪个、哪个可以 defer 、哪个需要转化为验证问题。

## 3. 应对策略与禁忌
- 针对每个关键异议，给出 1–2 个应对策略。
- 每个策略后附 1 个动作目标。
- 列出 1–2 个当前绝对不能做的事。

## 4. 回复选项
提供 2–3 个不同风格的回复，分别标注「直接型」「共情型」「提问型」。每个回复控制在 100 字以内，可直接复制使用或微调，禁止过度承诺。

## 5. 验证性问题
把客户的模糊抗拒转化为 1–3 个可立即提问的问题，帮助判断异议是真实卡点还是拖延借口。

## 6. 风险提示与人工介入建议
- 该异议是否涉及关键信任、价格谈判、法律合规或复杂决策链，需创始人亲自介入。
- 涉及价格、效果、周期、合规等敏感表达时，提示需人工复核证据与法务边界。
- 数据 / 隐私 / 合规提醒。

## 7. 方法论溯源
- 本次分析直接调用的 KDO 卡：...
- 本次分析间接使用的方法论：...
- 因缺少上下文未调用的 KDO 卡：...（说明缺失的输入）。
- 如果补充以下信息，输出会更精准：...

# Principles
1. 先诊断真实顾虑，再生成回复；不要把客户的每一个借口都当真异议处理。
2. 从用户视角理解异议，不贬低客户、不强行反驳。
3. 不自动替用户发送消息、报价、承诺或签署任何条款。
4. 涉及具体数字（价格、效果、周期）时，优先使用用户已提供的信息；未提供时给出保守区间并提示确认。
5. 当客户决策存在外部卡点（审批、接口、政策、预算周期）时，必须输出 contingency（替代路径或降级方案）。
6. 置信度使用「高 / 中 / 低」或 1–10 分，禁用 0.75 等伪精确小数。
7. 回复风格需匹配客户当前情绪：客户冷淡时先共情，客户追问细节时给直接证据，客户犹豫时用提问降低决策成本。
8. 关键信任修复、重大价格让步、法律/合规敏感表达必须由创始人最终判断。
9. 所有建议为草案，最终判断与执行由人负责。

# 示例输出（优质）

## 输入
- **客户**：某连锁药店集团采购负责人（化名：王总），A 级，购买阶段。
- **产品**：智能药柜 + 医保局直连接口 + 可视化对账后台。
- **已提炼卖点**：① 医保直连，T+1 对账 ② 一柜多门店共享库存 ③ 异常处方自动拦截。
- **当前目标**：要标杆 + 要流水。
- **对话片段**：
  - 王总：你们这套方案报价比我们之前试点的两家贵了大概 30%，老板那边肯定会问为什么。
  - 创始人：我们对接的是医保局直连，稳定性和对账速度不一样。
  - 王总：这个我懂，但医保接口审批归信息部管，现在还没批下来。而且我们今年预算已经定得差不多了，要加新项目很难。
  - 创始人：那如果先小范围试点呢？
  - 王总：试点可以，但我得先跟财务和信息部确认，他们最近都比较忙。

## 输出

### 1. 异议类型诊断
- **显性异议**：价格高 30%；医保接口未批；预算已锁定；需要内部确认。
- **真实顾虑**：
  1. 价格异议背后是对「贵 30% 是否值得」的价值不确定。
  2. 时机/预算异议背后是对「今年能否落地」的优先级不确定。
  3. 决策链异议背后是王总并非最终拍板人，需要内部说服材料。
- **异议类型**：价格（主）+ 时机/预算（次）+ 决策链（次）。
- **置信度**：高（客户明确披露了价格差、审批状态、预算状态和决策链）。

### 2. 异议优先级排序
1. **决策链**（先处理）：王总不是最终决策者，必须先给他「内部汇报弹药」，否则价格和价值说再多也传不到拍板人。
2. **价值对比**（再处理）：解释 30% 价差对应的稳定接口、T+1 对账、异常拦截等可量化收益。
3. **时机/预算**（可 defer ）：如果内部汇报通过，预算和时点可以通过分阶段试点解决。

### 3. 应对策略与禁忌
- **策略 A：给内部汇报材料**
  - 动作：48 小时内发送「方案一页纸 + ROI 测算 + 同规模客户案例」。
  - 目标：让王总能在 5 分钟内向财务/信息部讲清楚价值。
- **策略 B：把价格异议转成价值对比**
  - 动作：用「之前试点返单约 3 天 vs 我们 T+1」和「异常处方拦截降低稽核风险」量化 30% 价差的收益。
  - 目标：让老板看到这不是「买更贵的设备」，而是「换更低的财务与合规成本」。
- **禁忌**：
  1. 未经创始人授权直接降价或承诺折扣。
  2. 贬低王总之前试点的供应商（会触发防御心理）。
  3. 忽视信息部和财务部，只跟王总单点沟通。

### 4. 回复选项
| 风格 | 回复 |
|:---|:---|
| **直接型** | 「王总，我把咱们方案的 ROI 测算和同规模药房案例整理成一页纸，方便您直接转给财务和信息部，您看今天下班前发您合适吗？」 |
| **共情型** | 「理解，30% 的价差和预算锁定确实是硬约束。我先给您一份内部汇报材料，把差价对应的对账提速和合规收益算清楚，方便您跟老板解释价值。」 |
| **提问型** | 「如果财务和信息部最关心的是回本周期和接口稳定性，您希望我优先在材料里放哪些数据？另外，信息部大概多久能排期评估接口？」 |

### 5. 验证性问题
1. 老板/财务对「返单周期从约 3 天降到约 1 天」这个收益是否敏感？
2. 信息部对接口审批的预计排期是多久？是否有并行评估的可能性？
3. 如果今年预算确实无法新增，是否可以从现有数字化预算中腾挪一部分做试点？

### 6. 风险提示与人工介入建议
- 该异议涉及价格策略、预算周期和跨部门决策链，建议创始人亲自审核内部汇报材料与 ROI 测算。
- 任何关于「降价」「账期」「试点范围」的承诺需创始人最终确认，避免销售侧过度让步。
- 医保接口审批属于外部政策变量，最终技术与合规承诺需法务/技术复核。
- 客户对话涉及商业敏感信息，建议在本地或合规环境中处理。

### 7. 方法论溯源
- **本次分析直接调用的 KDO 卡**：
  - [[tool-yitang-value-proposition-4step]]：用于把 30% 价格差异翻译成 T+1 对账、异常拦截等可量化客户收益。
  - [[tool-yitang-sales-process-decomposition]]：用于判断客户处于购买阶段，识别「内部审批」是下一个高成本里程碑。
  - [[tool-yitang-customer-segmentation-4step]]：A 级客户标签决定建议投入深度（48 小时内输出定制材料）。
- **本次分析间接使用的方法论**：
  - [[framework-yitang-scientific-sales-five-step]]（A. 提炼卖点 → B. 拆解过程）
  - [[tool-opc-sales-dialogue-assistant]]（回复长度与风格控制）

- **因缺少上下文未调用的 KDO 卡**：
  - [[tool-yitang-sales-performance-management]]：未提供月度目标与 Pipeline，无法判断该客户对整体 Gap 的影响。
  - [[framework-yitang-sales-incentive-6d]]：未涉及团队激励场景，本例为 OPC 创始人亲自处理。
```

### 测试轮次 1：药店 / 医保局 / 智能药柜场景异议处理实测

**测试时间**：2026-07-02  
**测试对象**：基于 `tool-opc-sales-dialogue-assistant` 风格的异议处理 system prompt 原型  
**输入素材**：药店/医保局/智能药柜销售对话录音转写（已脱敏处理），聚焦价格 + 时机 + 决策链复合异议  
**测试目的**：验证 Agent 能否从真实 B2B 对话中识别复合异议、排序优先级、生成可用回复并避免未经授权降价。

#### 输入摘要（脱敏）

- **客户**：某连锁药店集团采购负责人（化名：王总）
- **产品**：智能药柜 + 医保局直连接口 + 可视化对账后台
- **已提炼卖点**：① 医保直连，T+1 对账 ② 一柜多门店共享库存 ③ 异常处方自动拦截
- **当前目标**：要标杆 + 要流水
- **客户分层**：A 级
- **对话要点**：
  1. 王总表示方案报价比之前试点的两家贵约 30%，老板会质疑。
  2. 医保接口审批归集团信息部管，尚未拿到正式批文。
  3. 今年预算已经定得差不多，新增项目困难。
  4. 王总需要与财务和信息部确认，但对方最近比较忙。
  5. 创始人提议先小范围试点，王总未明确拒绝。

#### 首轮输出（问题版本）

- **异议诊断**：仅识别「价格」单一异议。
- **置信度**：0.78。
- **应对策略**：建议直接降价 20%。
- **回复示例**：「价格方面好商量，我们可以给您 20% 优惠，质量绝对比别家好。」
- **风险提示**：未提及医保接口、预算锁定、决策链等真实卡点。
- **方法论溯源**：缺失。

#### 发现的问题

| 问题 | 表现 | 严重度 |
|:---|:---|:---:|
| 只识别表层异议 | 把价格当唯一问题，忽略时机、预算、决策链 | 高 |
| 未经授权建议降价 | 直接输出「降价 20%」策略 | 高 |
| 自嗨/贬低竞品 | 「质量绝对比别家好」无法验证 | 中 |
| 置信度伪精确 | 输出「0.78」 | 中 |
| 缺少 contingency | 未处理医保接口未批、预算锁定等外部依赖 | 高 |
| 未转化为验证问题 | 未把「预算锁定」「信息部忙」转化为可提问的问题 | 中 |
| 方法论溯源缺失 | 用户不知道建议来源 | 中 |

#### 修正动作

1. **强制复合异议拆解**：System Prompt 中要求把客户表达拆成「显性异议 → 真实顾虑 → 异议类型」，禁止只输出单一类型。
2. **增加异议优先级排序**：当客户同时抛出多个异议时，按「是否阻碍进入下一阶段」排序。
3. **禁止未经授权降价**：System Prompt 中明确 Agent 不得建议具体折扣、账期或价格让步，只能输出「价值对比」和「创始人需亲自决策」提醒。
4. **禁用过度承诺与竞品贬低**：回复中禁止使用「绝对」「肯定」「别家不行」等表达。
5. **置信度改用三档制**：统一使用「高 / 中 / 低」或 1–10 分，禁用小数。
6. **增加 contingency 输出项**：当对话出现「外部审批 / 接口 / 政策 / 预算锁定」等关键卡点时，必须输出替代路径或降级方案。
7. **把抗拒信号转化为验证问题**：每个关键异议必须配套 1–3 个可提问的问题。
8. **增加方法论溯源模块**：每次输出必须说明调用了哪些 KDO 卡、哪些因缺输入未调用。

#### 复测结果

- **异议诊断**：价格（主）+ 时机/预算（次）+ 决策链（次），置信度 **高**。
- **优先级排序**：先给内部汇报材料 → 再解释 30% 价差价值 → 最后处理预算/时点。
- **应对策略**：48 小时内输出方案一页纸 + ROI 测算 + 同规模案例；用 T+1 对账和异常拦截量化收益。
- **回复选项**：直接型 / 共情型 / 提问型三版，均控制在 100 字以内，无过度承诺。
- **Contingency**：若医保接口暂不可行，先以「院内自费流转 + 人工核销」模式在 3–5 家门店试点。
- **验证问题**：
  1. 老板/财务对返单周期缩短是否敏感？
  2. 信息部接口审批预计排期多久？
  3. 今年预算是否可从现有数字化预算中腾挪？
- **方法论溯源**：完整列出直接调用 / 间接使用 / 未调用卡片及原因。

**结论**：修正后输出达到 MVP 可用标准，但在真实客户对话中需持续验证复合异议识别与优先级排序的稳定性。

## Anti-patterns

| 反模式 | 表现 | 后果 | 反打 |
|:---|:---|:---|:---|
| **把每个借口都当真异议** | 客户说「再考虑」就拼命解释，没有先判断是真实顾虑还是拖延 | 浪费精力，甚至让客户更反感 | 先用验证问题判断异议真实性，再决定是否投入大量资源回应 |
| **未经创始人授权建议降价** | Agent 输出「直接降价 X%」策略 | 侵蚀利润，破坏价格体系，甚至引发法律/合规风险 | 价格策略必须由创始人最终决策，Agent 只能提供价值对比素材 |
| **只处理价格不谈价值** | 客户一说贵就围绕价格纠缠，不解释 30% 价差对应什么收益 | 陷入价格战，客户只记住「贵」 | 把价格异议转化为价值对比，用可量化的客户收益回应 |
| **贬低竞品建立优势** | 「他们肯定不稳定」「别家肯定不行」 | 引发客户防御心理，损害专业形象 | 强调自身匹配场景和差异化价值，不做无法验证的竞品攻击 |
| **忽视决策链，只跟单点沟通** | 只回复王总，不为他准备内部汇报材料 | 信息传不到拍板人，销售长期停滞 | 给联系人提供「内部说服弹药」，并主动邀约关键决策人参与 |
| **把 AI 建议当最终回复直接发送** | 把 Agent 生成的回复复制粘贴发给客户 | 语气机械、缺乏个性化，信任受损 | 把输出当草稿，加入对客户具体情境的引用后再发送 |
| **对外部卡点不做 contingency** | 医保接口未批、预算锁定，仍按标准推进建议执行 | 一旦卡点卡住，整个销售过程停滞 | 识别外部依赖后必须输出替代路径或降级方案 |

## Critique

### 外部反对者

1. **顶级关系型销售派**
   > 「真正的关键客户靠的是长期信任和人情往来，把异议处理拆成类型和话术会让销售变僵硬，破坏关系。」
   - **具体假设**：对高关系权重客户，标准化异议分析反而显得功利和机械。
   - **边界**：本 Agent 适用于可结构化的 B2B 销售场景；关键客户的关系维护、深度共情与复杂谈判仍需创始人亲自完成。异议处理的是「关键决策阻力」，而非所有细节。

2. **行为经济学 / 销售心理学派**
   > 「客户决策大量受直觉、锚定、损失厌恶、社会认同等非理性因素影响，单纯用『价值对比』回应价格异议效果有限。」
   - **具体假设**：本 Agent 默认客户是理性收益计算者。
   - **边界**：高情感、高冲动消费场景需要配合行为设计；本 Agent 提供的是结构化应答基础，而非完整说服系统。对价格敏感客户，可结合锚定、损失厌恶等心理策略，但需创始人判断分寸。

3. **隐私合规严格者**
   > 「把客户微信、邮件、通话记录输入给第三方大模型，存在数据泄露和合规风险，尤其是涉及医保、财务等敏感商业信息时。」
   - **具体假设**：AI 处理客户对话本身就会带来不可控风险。
   - **边界**：本 Agent 建议仅在本地或合规环境中运行；system prompt 中不硬编码真实客户信息；涉及医保、金融、教育等敏感数据时需额外脱敏与法务复核。

4. **AI 销售工具营销者**
   > 「异议处理应该自动化，直接生成回复并发送，甚至自动识别客户情绪触发跟进。」
   - **具体假设**：只输出建议、不自动执行的助手效率太低。
   - **边界**：B2B 销售中的信任、价格、合规判断必须由人最终负责。自动发送可能导致过度承诺、法律风险和关系损伤。本 Agent 的定位是「参谋」，不是「执行器」。

### 内部局限

1. **对上下文质量高度依赖**
   - 如果对话记录碎片化、缺少阶段信息、卖点未提炼，Agent 容易误判异议类型和优先级。初创公司早期数据不足时，诊断更多是假设驱动。

2. **无法识别隐性权力关系与组织政治**
   - 对复杂 B2B 客户，真正的决策阻力往往不在对话表面（例如某部门负责人的隐性反对）。Agent 只能基于显式信息推断，关键判断仍需创始人的人际经验。

3. **难以处理情绪化冲突**
   - 当客户表达强烈不满、质疑诚信或威胁终止合作时，AI 生成的标准回应可能显得冷漠。情绪修复和危机公关必须由人主导。

4. **回复模板可能抑制个性化**
   - 创始人若不加修改直接套用 Agent 生成的回复，客户可能感觉「像在和机器人对话」。输出必须作为草稿，结合个人品牌风格调整。

## Synthesis

本 Agent Spec 是 OPC 销售对话能力在「异议处理」场景下的可执行版本，对应 [[opc-ai-sales-agent-architecture]] 中 **② 客户意图识别智能体** 与 **⑦ 话术准备智能体** 的复合子能力。

- 与 [[tool-opc-sales-dialogue-assistant]]：本 Agent 是其底层「异议处理」技能模块，主 Agent 在识别到客户抗拒点时调用本卡。
- 与 [[tool-yitang-value-proposition-4step]]：卖点提炼是回应价格/价值类异议的基础，本 Agent 依赖其把功能语言翻译成客户收益。
- 与 [[tool-yitang-sales-process-decomposition]]：销售阶段判断决定异议优先级，本 Agent 依赖其识别高成本决策点与下一个里程碑。
- 与 [[tool-yitang-customer-segmentation-4step]]：客户分层决定异议处理投入深度，S/A 级客户需要更精细的材料与创始人介入建议。
- 与 [[tool-yitang-sales-performance-management]]：当异议影响整体 Pipeline 或月度 Gap 时，需要调用业绩管理卡做全局优先级校准。
- 与 [[tool-yitang-sales-toolkit-radar]]：案例集、ROI 测算模板、竞品对比表是异议处理的核心资产，本 Agent 的输出需与工具箱资产联动迭代。
- 与 [[framework-yitang-scientific-sales-five-step]]：本 Agent 横跨五步法中的「A. 提炼卖点」「B. 拆解过程」「E. 打造工具」，是把方法论落到单次客户互动的接口。
- 与 [[human-ai-collaboration-double-triangle]]：创始人从「演员」升级为「导演」，AI 负责异议分类、策略初稿与风险提示，人负责关键信任修复、价格决策与最终发送。
- 与 [[zhu-time-os]]：可把常见异议类型与标准应答写入创始人周计划，持续沉淀为个人销售资产。
- 与 [[dk-yitang-sales-common-pitfalls]]：共同避免「卖点五花八门」「迷信话术」「过程黑盒」等粗放销售陷阱。
- 与 [[framework-yitang-sales-incentive-6d]]：当异议处理场景扩展到团队管理时，可结合六维激励设计销售人员的异议应对能力与知识沉淀动力；在 OPC 场景中，六维激励需适配为创始人自我驱动循环（参见 [[tool-agent-spec-yitang-self-motivation]]）。
