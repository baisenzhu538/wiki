# 需求分层画布：从"所有人"到"第一批100个"的结构化工具

> 一堂五步法：用户分层不是分类，而是识别需求差异，找到最值得先服务的群体。

## 核心框架

画布结构：

```
┌─────────────────────────────────────────────────────────┐
│                    需求分层画布                          │
├─────────────────────────────────────────────────────────┤
│  维度1：需求强度                                         │
│  ┌─────────────┬─────────────┬─────────────┐         │
│  │   高痛      │    中痛      │    低痛      │         │
│  │  (必须解决)  │  (最好解决)  │  (无所谓)    │         │
│  └─────────────┴─────────────┴─────────────┘         │
├─────────────────────────────────────────────────────────┤
│  维度2：获取难度                                         │
│  ┌─────────────┬─────────────┬─────────────┐         │
│  │   易获取     │   中难度     │   难获取     │         │
│  │  (渠道成熟)  │  (需探索)    │  (需教育)    │         │
│  └─────────────┴─────────────┴─────────────┘         │
├─────────────────────────────────────────────────────────┤
│  维度3：付费意愿                                         │

│  优先级矩阵                                              │
```

## 关键洞察

### 1. 分层维度的选择

不是按人口统计（年龄/性别/地域），而是按需求属性：

| 维度 | 说明 | 为什么重要 |
|:---|:---|:---|
| **需求强度** | 高痛 vs 低痛 | 决定用户付费意愿 |
| **场景频率** | 高频 vs 低频 | 决定使用习惯和留存 |
| **替代方案成本** | 高成本 vs 低成本 | 决定切换意愿 |
| **获取难度** | 易获取 vs 难获取 | 决定获客成本 |
| **付费意愿** | 高付费 vs 低付费 | 决定商业模式 |

### 2. 第一批100个的识别

画布输出：找到"高痛+易获取+高付费"的用户层。

示例：

| 用户层 | 需求强度 | 获取难度 | 付费意愿 | 优先级 |
|:---|:---:|:---:|:---:|:---:|
| 大型企业HR | 高（合规压力） | 中（需销售） | 高（预算足） | 第一批 |
| 中型企业HR | 中（效率提升） | 易（线上获客） | 中（看ROI） | 第二批 |
| 小型企业HR | 低（能用就行） | 易（线上获客） | 低（预算紧） | 第三批 |
| 个人用户 | 低（非必需） | 易（自然流量） | 极低（只愿免费） | 放弃 |

### 3. 分层后的产品决策

不同层需要不同产品策略：

| 用户层 | 产品策略 | 定价策略 | 获客策略 |
|:---|:---|:---|:---|
| 第一批 | 核心功能极致体验 | 高价高服务 | 直销/BD |
| 第二批 | 标准化产品 | 中等价位 | 线上+内容营销 |
| 第三批 | 自助式产品 | 低价/免费增值 | 自然流量+口碑 |

### 4. 分层的动态调整

分层不是一次性的，需要定期调整：

- 第一批服务好后，口碑扩散到第二批
- 市场变化，某层的需求强度可能变化
- 竞品进入，某层的获取难度可能变化

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **人口统计分层** | 按年龄/性别分层，忽视需求差异 | 按需求属性分层 |
| **分层太粗** | 只分2-3层，无法指导决策 | 至少分5层，找到最痛的1-2层 |
| **分层未验证** | 假设某层有高痛，未访谈 | 每层至少访谈3-5个用户 |
| **忽视层间差异** | 不同层需求差异大，但产品统一 | 为不同层设计差异化功能 |
| **过早扩展** | 第一层未服务好，就想服务所有人 | 先服务好第一批100个 |
| **分层维度单一** | 只按一个维度分层 | 至少两个维度交叉 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新产品冷启动 | 成熟产品全量运营 |
| 需求验证阶段 | 技术架构设计 |
| 产品定位模糊时 | 已有明确PMF后的规模化 |
| 资源有限时的优先级排序 | 品牌传播策略 |

## 行动触发器

- 当你想说"所有人都是我的用户"时 → 用画布填出第一批100个
- 当转化率低时 → 检查是否匹配了非核心用户层
- 当团队争论功能优先级时 → 先对齐"服务哪一层用户"
- 当考虑扩展新用户群时 → 先验证当前层是否已深度服务
