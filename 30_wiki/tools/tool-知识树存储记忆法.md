# 技能：知识树存储记忆法

## 原始表述
> L1.存储记忆 √记录：筛选/保存/记忆 真实案例 整理：梳理内容/结构

## 操作步骤
1. 筛选信息，决定哪些值得保存
2. 记录保存到知识管理系统
3. 梳理内容结构和逻辑关系
4. 建立可检索的记忆存储

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 大量信息输入时，需要结构化筛选和保存 |
| ✅ 适合 | 需要长期积累知识资产，建立可复用的认知结构 |
| ✅ 适合 | 团队知识沉淀，需要统一存储和检索标准 |
| ✅ 适合 | 跨项目/跨领域学习，需要整合不同来源的知识 |
| ❌ 不适合 | 临时性、一次性信息 → 存储成本超过收益 |
| ❌ 不适合 | 信息过载但无筛选能力 → 囤积而非存储 |
| ❌ 不适合 | 没有检索习惯 → 存了等于没存 |
| ❌ 不适合 | 知识更新极快的领域 → 存储的知识快速过时 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **树种太细** | 每个碎片知识都是一片叶子，知识树变成知识灌木 | 树的价值在主干和枝干，不在叶子。必须提炼3-5个核心概念作为主干，碎片信息挂在枝干下 |
| **只存不取** | 花了大量时间构建完美的知识树，但从不检索 | 存储是为了检索，不是为了好看。过去一周检索过0次的知识树是信息囤积 |
| **知识树不更新** | 新知识和旧知识矛盾时，选择忽略新知识 | 知识树需要修剪和嫁接，定期删除不再相关的内容，有明确的'淘汰'记录 |
| **树根太浅** | 枝干很茂盛但底层原理没吃透 | 树的高度取决于根的深度。不看笔记就说不清楚核心，说明那不是你的知识树 |
| **结构混乱** | 所有东西都在一个文件夹里，靠搜索关键字找 | 任意一个枝干，10秒内能找到它的根（属于哪个主干）。结构混乱的知识树无法有效提取 |
| **工具 obsession** | 频繁切换知识管理工具，内容迁移成本过高 | 选定一个工具后至少使用6个月，工具是手段不是目的。内容比工具重要 |
| **收藏即学习** | 把收藏文章当成学习，从未回顾和加工 | 收藏后必须在一周内进行筛选、标注、提炼，否则只是信息囤积 |
| **完美结构陷阱** | 追求完美的分类体系，但内容本身浅薄 | 先确保内容有深度、有判断，再考虑结构。结构是放大器不是替代品 |

## 判断标准

**什么算一棵好的知识树**：

| 标准 | 好的知识树 | 坏的知识树 |
|:---|:---|:---|
| 主干清晰 | 知道这个领域的 3-5 个核心概念（主干）是什么 | 一堆叶子（碎片信息）分散在多处，找不到核心结构 |
| 枝干可检索 | 任意一个枝干，10 秒内能找到它的根（属于哪个主干） | 所有东西都在一个文件夹里，靠搜索关键字找 |
| 有修剪记录 | 定期删除不再相关的内容，有明确的"淘汰"记录 | 只增不减，越存越乱，信息噪声淹没了信号 |
| 知识可提取 | 不看笔记也能用自然语言讲出某个枝干的核心 | 不看笔记就说不清楚——说明那不是你的知识树 |

**自检问题**：
1. 这个笔记我三个月后还会看吗？如果不会，它不应该存在知识树上。
2. 如果我的知识树今天被删了，我能快速重建多少？——答案就是真正属于我的知识量。
3. 最近一次修剪/更新知识树是什么时候？超过一个月没更新，说明树在枯萎。
