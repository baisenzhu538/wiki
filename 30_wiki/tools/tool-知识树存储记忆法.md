# 技能：知识树存储记忆法

## 原始表述
> L1.存储记忆 √记录：筛选/保存/记忆 真实案例 整理：梳理内容/结构

## 操作步骤
1. 筛选信息，决定哪些值得保存
2. 记录保存到知识管理系统
3. 梳理内容结构和逻辑关系
4. 建立可检索的记忆存储

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 大量信息输入时，需要结构化筛选和保存 |
| ✅ 适合 | 需要长期积累知识资产，建立可复用的认知结构 |
| ✅ 适合 | 团队知识沉淀，需要统一存储和检索标准 |
| ✅ 适合 | 跨项目/跨领域学习，需要整合不同来源的知识 |
| ❌ 不适合 | 临时性、一次性信息 → 存储成本超过收益 |
| ❌ 不适合 | 信息过载但无筛选能力 → 囤积而非存储 |
| ❌ 不适合 | 没有检索习惯 → 存了等于没存 |
| ❌ 不适合 | 知识更新极快的领域 → 存储的知识快速过时 |

## 判断标准

**什么算一棵好的知识树**：

| 标准 | 好的知识树 | 坏的知识树 |
|:---|:---|:---|
| 主干清晰 | 知道这个领域的 3-5 个核心概念（主干）是什么 | 一堆叶子（碎片信息）分散在多处，找不到核心结构 |
| 枝干可检索 | 任意一个枝干，10 秒内能找到它的根（属于哪个主干） | 所有东西都在一个文件夹里，靠搜索关键字找 |
| 有修剪记录 | 定期删除不再相关的内容，有明确的"淘汰"记录 | 只增不减，越存越乱，信息噪声淹没了信号 |
| 知识可提取 | 不看笔记也能用自然语言讲出某个枝干的核心 | 不看笔记就说不清楚——说明那不是你的知识树 |

**自检问题**：
1. 这个笔记我三个月后还会看吗？如果不会，它不应该存在知识树上。
2. 如果我的知识树今天被删了，我能快速重建多少？——答案就是真正属于我的知识量。
3. 最近一次修剪/更新知识树是什么时候？超过一个月没更新，说明树在枯萎。

## 常见失败模式

| 失败模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **叶子过载** | 笔记越积越多，每个概念都成独立节点，层级超过 5 层仍找不到主干 | 强制每棵树先有 3-5 个主干概念，碎片信息必须挂靠在枝干下，不单独建根节点 |
| **零提取使用** | 过去两周没有一次主动打开知识树查找信息，构建时间远超使用时间 | 给每条枝干设置使用场景，例如“写方案时查案例”“复盘时查 checklist”，每周至少触发一次检索 |
| **根系浮浅** | 能复述枝干标题，但讲不清背后的原理、前提和适用条件 | 每个主干节点必须配一个“为什么成立”的根部笔记，能不看原文向他人解释 |
| **只增不减** | 知识树体积持续膨胀，过期、矛盾或重复的内容从未删除 | 每月做一次修剪：标记过时节点、合并重复项、记录删除理由 |
| **分类强迫症** | 花大量时间调整标签和目录，笔记本身空洞无判断 | 先写内容再调结构，单个节点至少包含“是什么+我怎么看+用在哪”三要素 |
| **搬运式存储** | 原文、截图、链接直接丢进知识库，没有自己的语言转述 | 存储前强制用自己的话重述核心观点，并标注来源与自己的使用场景 |

**Peter Drucker**（管理学大师）会质疑：工具的价值不在于"有没有"，而在于"用得好不好"。任何工具都是"能力放大器"——如果使用者的判断力不足，工具只会放大错误。真正的风险不是"缺少工具"，而是"有了工具后产生的虚假安全感"——让你以为自己已经覆盖了所有可能性，实际上只是走完了流程。
