# 关键假设池：三层形态 + 字段模板 + 四条运营纪律

> **一句话**：假设池是把「随机的灵光一闪」变成「确定性的组织机制」的容器（进阶篇-口述 L3194-L3208）——三层形态逐级升级（个人备忘→团队备忘→正式假设池），最小可用字段只要五列（提出人/内容/优先级/验证人/结果），配四条运营纪律：测试群只扔不聊、颗粒度比需求池小一个量级、证伪记录永久留存、用云端多维表格协作。全部数字为课程案例口径/课程经验值。

---

## 何时用

- 团队开始稳定地产出假设（每周 ≥3-5 条），靠脑子记开始丢、开始乱时——这是从第一层升级到第二层的信号
- 假设多到「最应该验证什么」吵不出来时——需要字段化的优先级列来排序（管理篇-口述 L1502-L1518）
- 业务进入长周期迭代（两三个月到三年五年），四象限定位在 C 域（宏观效率）时——C 域周期最长、假设最多，是假设池的刚需场景（管理篇-口述 L1700-L1798，详见 `[[yt-business-formula-hypothesis-management-playbook]]`）
- 降龙十八掌第 16 招「建立假设池」的执行落地（进阶篇-口述 L3202；全招清单见 `[[yt-tool-business-formula-18-moves]]`）

## 需要什么

- 一个「假设默认为假、允许验证失败」的团队共识（没有它，假设池是座没人敢用的仓库——先回落地策略集 1.1 格）
- 至少一个假设负责人（Admin 角色），负责记录、备忘、驱动（管理篇-口述 L1060-L1066）
- 一个云端协作表格（飞书多维表格或同类），别用本地文档（管理篇-口述 L1612-L1634）

---

## 一、三层形态（逐级升级，别跳级）

课程原话：假设池「一般有三种常见的类型」（进阶篇-口述 L3208-L3216）：

| 层 | 形态 | 载体 | 门槛 | 对应策略集格 |
|:--|:--|:--|:--|:--|
| 1 | **个人备忘**（想法笔记） | 个人笔记本/Cubox/手机备忘录 | 随手记，「最起码可以沉淀」 | 入门 1.4 |
| 2 | **团队备忘**（集体分享） | 假设群/公司知识库/公共文档 | 可以交流、相互激发 | 入门 1.4 |
| 3 | **团队正式假设池**（系统维护） | 云端多维表格，团队增删改查 | 字段化+状态机+优先级 | 进阶 2.4 |

跳级警告：没有第 1-2 层的记录习惯，直接上第 3 层正式表格，大概率建成一座没人维护的摆设（进阶篇-口述 L3266「假设池零散地在那写着，大家不会往里放」——所以第 17 招配套会议要求固定会议往池子里喂假设）。

楚门的个人实践（课程案例口径）：早晨半小时逼自己记 20 条新假设，其中七八成不会验证，验证的里约 30% 有一两个有效「就很厉害」（管理篇-口述 L1242-L1250）——第 1 层追求数量，不追求质量。

## 二、字段模板（三档，从简到繁）

**最小可用版（5 列）**——管理篇原话（L1492-L1500、L1610）：

| 字段 | 取值 |
|:--|:--|
| 提出人 | 谁提的（「谁提出谁功劳」的激励依据） |
| 假设内容 | 提了啥假设（针对哪个参数/哪个目标） |
| 成本 | 高中低（定性即可，「绝大部分假设池不需要严格定量」L1508） |
| 收益 | 高中低（同上；能定量给预期范围更好） |
| 认领验证人 | 谁把这假设认领走、负责验证 |
| 验证结果 | 有效 / 无效 / 未知 / 一般 |

**学员实践版（小东老师字段）**——管理篇 L830-L836：谁提出 → 假设展开 → 谁去验证 → 验证动作 → 验证情况 → **哪些是可复用的资源和 SOP**（比最小版多了「沉淀复用」一列，这是把假设验证变成组织资产的关键增量）。

**一堂实战版（飞书多维表格）**——管理篇 L1620-L1626 展示的真实表结构：

- **状态列**：待验证 / 放一放 / 进行中 / 已完成 / 酝酿中未开始——「有的时候重心在这个表上，有的时候重心在那个表上」，没精力的模块允许停在那儿
- **优先级列**：P0 / P1
- **归属列**：服务于哪个目标、哪个环节、哪个模块
- **责任列**：谁提出来的、提出时间、谁跟进、对哪个指标负责
- **进度列**：大概的进展

工具建议：飞书表格或多维表格，理由是「支持权限管理，可以多人协作」（管理篇-口述 L1612-L1616）；本地文档「会非常难」协作（L1634）。课程配套的空白模板见课件图 002232（"XX 公司增长假设清单"）。

## 三、四条运营纪律

### 纪律 1：测试群只扔假设，不讨论不点赞不闲聊

Vicky（短视频培训）案例的机制（管理篇-口述 L800-L814）：为了避免假设消息被日常消息淹没，专门拉一个测试群——「这个群甚至不讨论，不点赞不闲聊，就是往里扔」。两个作用：① 关键假设不丢；② 全公司都知道大家在积极思考，营造提假设的氛围。看到同行/竞品有什么就扔进来。楚门评：「这是公司最简单的测试管理的机制」。

### 纪律 2：假设池 ≠ 需求池，颗粒度小一个量级

核心辨析（管理篇-口述 L1580-L1608）：

| | 需求池 / 线索池 / 项目池 | 假设池（广义） |
|:--|:--|:--|
| 容量 | 五个十个就满了 | 可以几十个甚至上百个 |
| 颗粒度 | 项目级（一个需求天然包含多个假设） | 机会点级：改一个价格、加一个运营节点、优化一版文案、调整一个人群、增加一个动力、优化一个阻力，都算一条假设 |
| 可测性 | 太粗，测不动 | 细，「可以更好的测试和验证」 |

操作建议：早期不必拘泥它是线索、项目还是转化率，「你就认为它是服务于目标的一个增长机会，列成假设就好了」（L1596-L1598）；公司小、阶段早，颗粒度拆细一点；成熟大公司可继续叫需求，但要知道一个需求里藏着好几个假设（L1602-L1606）。

### 纪律 3：证伪的假设也要留，永久留

两处一等源互证：

- **管理篇 L854-L860**：有了假设池，团队心态反转——「数据差就是证伪，只是验证一个假设，而且后面还有那么多假设排着队，说明我们还有很大的空间」，团队反而越挫越勇。假设堆着做不完是资产不是负债。
- **进阶篇 L3236-L3264**：验证无效的「当然要留，日志一定要留下来」——「信息经验是属于个人的，知识是属于业务的、属于公司的」，后面的人得知道前面的人证明了啥。甚至项目管理级的纪律：沟通记录（谁提了什么问题、当时怎么回复的）也要留，B 看到就不会重复问。补充一条反直觉点：**很多时候验证失败是「时间没到」**，不是假设错了（L3260），删掉就永远失去了复盘机会。

### 纪律 4：正式池必须云端协作

本地 Excel/文档无法多人增删改查，会退化成某个人的私人文件（管理篇 L1634）。进阶篇 L3222-L3234 给了两个实证：一堂增长团队内部假设池=飞书多维表格，专人把各处奇奇怪怪的想法扔进去、定期评估优先级排序；学员潘武海（口述转写，课程案例）上完课后也搭了完备假设池——业务环节/渠道/假设类型/提出人/时间/优先级/验证结果，「通过一个又一个假设支撑了公司完成比较好的增长」。

## 四、常见坑（Failure Modes）

| # | 症状 | 根因 | 修复 |
|:--|:--|:--|:--|
| 1 | 直接建第 3 层正式表格，三个月后落灰 | 跳级：没有第 1-2 层的记录习惯打底 | 退回测试群（第 2 层）跑一个季度，习惯养成再上正式池 |
| 2 | 假设池变成意见箱，全是"我觉得应该…"的大词 | 没挂参数：假设没说清服务哪个公式参数 | 每条假设强制写「针对参数」列；挂不上的退回灵感阶段 |
| 3 | 追求每条假设都严格定量评估，池子建不动 | 评估过度：「绝大部分假设池不需要严格定量」（L1508） | 成本/收益定性打高中低即可排序，只对高成本假设补定量 |
| 4 | 失败假设删了，同样的想法每年来一遍 | 违反纪律 3 | 恢复证伪记录，新人入职先翻假设池的「无效」列 |
| 5 | 池子里 200 条假设没人认领验证 | 只有记录没有驱动：缺 Admin 角色和配套会议 | 指定唯一假设负责人；固定复盘会每周从池子里捞假设（第 17 招配套会议） |
| 6 | 把假设池当 KPI 考核工具，按提假设数量发奖金 | 数量激励会灌水，毁掉「默认失败」共识 | 激励挂在「有效验证的认知增量」上，不挂条数（激励设计见 `[[concept-一堂-假设飞轮]]`） |

## When NOT to Use

| 场景 | 为什么失效 | 替代 |
|:--|:--|:--|
| 0→1 阶段、商业模式未验证 | 此时是 A 象限成败问题，一两个假设定生死，不需要池子 | 关键假设画布，证伪通过后再建池 |
| 单次短周期决策（几小时到几周） | B 象限 ROI 决策的领地，建池=杀鸡用牛刀 | 直接走 ROI 决策 |
| 团队没有「假设默认为假」的共识 | 池子会变成讨好老板的想法收集箱 | 先建共识（策略集 1.1 格），一号位先往群里扔三个月 |
| 想靠假设池替代攻坚会的深度解题 | 池子管「广度排队」，攻坚会管「深度攻坚」，是两件事 | 卡点上用 `[[yt-tool-business-formula-gongjianhui]]` |

## Critique

**1.「不就是 idea backlog / 需求管理换皮？」**（**Marty Cagan** 式产品管理质疑）：形式像，内核不同——backlog 管「要做什么」，假设池管「我们对业务的什么认知还没验证」；backlog 的完成态是上线，假设池的完成态是认知（有效/无效都是产出）。证伪留存（纪律 3）是 backlog 文化里恰恰最容易丢的东西。

**2.「几十上百条假设，管理成本会不会超过收益？」**：回应：字段最小版只有五列、评估定性高中低即可（L1508-L1512），单条维护成本极低；真正的成本在「没有池子」——同样的假设每年重提一遍、同样的坑每年重踩一遍。

**3.「小团队三五个人，值得搞这套吗？」**：值得，但只搞前两层。个人备忘+测试群几乎零成本，Vicky 的小团队就是靠这两层跑出业务的（管理篇 L870-L874，收入/活跃/口碑均跑出，课程案例口径）。

## 八、Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:--|:--|:--|
| 团队刚学完假设思维，从 0 开始 | 拉测试群+立群规（只扔不聊），一号位先扔 20 条 | 两周内出现第一个非一号位扔进来的假设 |
| 假设开始丢、开始乱 | 建云端正式假设池，先只上最小五列 | 一个月内 ≥20 条假设，每条说清服务哪个参数 |
| 池子里不知道先验证哪个 | 成本/收益定性打高中低，叠加确定性粗排序 | 排出 Top 5 验证清单，每条有认领人 |
| 发现新人重复提已证伪的想法 | 带他翻假设池「无效/证伪」列 | 新人能复述三条「我们试过、证伪了」的假设 |

## Purpose

团队聊假设全靠脑子记、三个月后谁也找不着、证伪过的想法每年重提一遍——本卡把「随机的灵光一闪」变成「确定性的组织机制」：三层形态（个人备忘→团队备忘→正式假设池）给出不跳级的升级路径，五列最小字段模板让池子建得动，四条运营纪律（测试群只扔不聊/颗粒度比需求池小一个量级/证伪永久留存/必须云端协作）守住机制命门。它是十八掌第 16 招「建立假设池」的执行手册，也是假设飞轮的蓄水池。

## Protocol

1. **起步不跳级**：先第 1 层个人备忘（随手记，只要求「想追溯时找得着」），再第 2 层测试群（只扔假设，不讨论不点赞不闲聊），习惯养成一个季度后再上第 3 层云端正式池——直接建正式表格大概率建成没人维护的摆设
2. **建池先上最小五列**：提出人/假设内容/成本（高中低）/收益（高中低）/认领验证人/验证结果——绝大部分假设池不需要严格定量
3. **每条假设强制挂参数**：写清服务哪个公式参数，挂不上的退回灵感阶段；颗粒度按「改一个价格/加一个节点/优化一版文案」拆，一个需求拆成 3-5 条假设
4. **守四条纪律**：测试群只扔不聊；颗粒度比需求池小一个量级；证伪假设只改状态不删除、永久留存（很多时候是「时间没到」不是假设错了）；正式池必须云端协作，不用本地文档
5. **配驱动机制**：指定唯一假设负责人（Admin 角色）负责记录、备忘、驱动；固定复盘会每周从池子里捞假设、按成本/收益/确定性粗排序验证；结果（含证伪）回写验证结果列
