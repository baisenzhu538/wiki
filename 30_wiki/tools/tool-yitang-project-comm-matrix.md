# 项目沟通方式四象限选择矩阵

> **一句话**：沟通方式不对，信息就丢了。按同步/异步×线上/线下两个维度，找到最合适的那个。

---

## 一、四象限速查

```
                    异步←──────────→同步
         ┌──────────────────────────────────┐
   线上  │ 顶层文档  电子看板  │ 1v1消息  1v1电话  │
         │ 项目群    邮件      │ 群聊消息          │
         ├─────────────────────┼──────────────────┤
   线下  │ 墙面看板            │ 封闭研发  1v1当面  │
         │                     │ 攻坚小组  坐你旁边 │
         │                     │ 团队例会          │
         └──────────────────────────────────┘
```

---

## 二、选择指南

| 场景 | 推荐象限 | 推荐方式 | 理由 |
|:---|:---|:---|:---|
| 通知型信息（不需要回复） | 线上+异步 | 邮件/项目群/文档 | 可回溯，不打断 |
| 简单确认/快速问答 | 线上+同步 | 1v1消息 | 即时但不打断深度工作 |
| 重要决策/复杂讨论 | 线下+同步 | 团队例会/攻坚小组 | 需要看表情、即时反馈 |
| 需要深度协作 | 线下+同步 | 封闭研发/坐旁边 | 最高带宽，最快迭代 |
| 信息沉淀/知识共享 | 线上+异步 | 顶层文档/电子看板 | 长期可查，新人可看 |

---

## 三、Constraints

- 线上+同步（IM消息）最容易滥用——重要讨论不要留在聊天记录里
- 线下+同步成本最高——只用于真正需要"面对面"的事
- 异步沟通的前提是信息写清楚——否则变成"异步+反复追问"

---

## 四、失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| 一切在群里说 | 重要决策埋在99+消息里 | 决策后补一句"结论见文档链接" |
| 一切开会说 | 每天3个会，没时间干活 | 先问：这件事能用异步方式解决吗？ |
| 线上同步当异步用 | 发消息等半天才回，当成已通知 | 紧急事项用电话/当面 |
| 只有同步没有异步 | 项目文档为零，老人离职=知识清零 | 强制每个里程碑输出一份异步文档 |

---

## 五、Action Triggers

- 准备发起一次沟通时：先定位象限再选方式
- 发现沟通效率低时：检查是否选错了象限
- 项目启动时：和团队约定"什么事用什么方式沟通"
