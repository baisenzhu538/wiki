# 一堂产品内核画布应用技能

## 不要用的场景


- 在问题边界尚不清晰时不要使用——一堂产品内核画布应用技能需要明确的目标和约束才能有效。先做探索性分析再回来。
- 需要秒级决策的紧急场景中不要用——一堂产品内核画布应用技能的完整流程耗时较长，紧急场景需要更轻量的判断。
- 一堂产品内核画布应用技能在跨领域迁移时不要直接套用——不同领域的边界条件和关键变量不同，需要先验证适配性。

## 质疑


- **具体假设**：一堂产品内核画布应用技能工具假设结构化方法论能产生正确结论，但结论质量取决于输入数据和执行者判断力。
- **边界**：在一堂产品内核画布应用技能相关的数据稀缺或快速变化场景中，已有经验框架可能完全失效。
- **反例**：团队在一堂产品内核画布应用技能任务中完整执行了所有步骤，但核心假设从一开始就是错的。
- **前提**：使用者已具备一堂产品内核画布应用技能领域的基础认知，且数据来源具有代表性。

**Peter Drucker**（管理学大师）会质疑：工具的价值不在于方法论本身，而在于执行者的判断力。

## 目的


解决一堂产品内核画布应用技能场景中信息散乱、决策靠直觉的问题——通过结构化拆解将隐性经验转化为可复用的显性知识。

## 原始表述

> "产品内核是用户愿意选择你的最小解决方案。"
>
> "真正的产品内核不是你认为什么功能最重要，而是用户选择你的那个逻辑。"
>
> "必须勇敢做产品价值取舍，这是一号位的基本义务。"

本技能帮助产品经理或创业者用结构化方法识别"用户愿意选择你的最小解决方案"，避免困境：产品功能越做越多但用户不买账；团队以为的卖点不是用户关心的买点；商业模式难以跑通。

## 外部攻击者

### 攻击者1：战略咨询师 —— "3-5条内核太简化，复杂业务无法压缩"

> "你诹于航空发动机、医院信息系统或企业级SaaS这类高复杂度产品，3-5条内核就像用一张A4纸概括一本书。用户决策是多维度、多角色、长周期的，这种压缩会让团队忽视关键利益相关者的差异化需求。"

### 攻击者2：数据分析师 —— "单一转化率指标会导致短视"

> "转化率是一个短期、可操控的指标，它会鼓励团队做出一切提升短期转化但损害长期价值的决策。例如过度优化首页注册转化，可能会降低用户质量和续费率。内核画布需要配备长期价值指标。"

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 产品定义阶段：已有明确需求，需确定"用户为什么选择我们" |
| ✅ 适合 | 商业模式设计阶段：需将用户价值转化为可量化转化率指标 |
| ✅ 适合 | 产品迭代阶段：需对现有功能做取舍，聚焦真正决定性要素 |
| ❌ 不适合 | 非标准化、高定制化产品 → 每个客户内核要素差异过大，需分层分类 |
| ❌ 不适合 | 创意/艺术类项目 → 用户决策受情感驱动，难以压缩为3-5条要素 |
| ❌ 不适合 | 企业级B2B采购 → 决策链涉及多利益相关者，需分角色讨论 |
| ❌ 不适合 | 高复杂度产品（航空发动机/医院信息系统） → 3-5条内核过于简化 |

## 常见失败模式

| 失败模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **Green-bloat** | 不舍得删除要素，绿色列表超过 5 条，团队仍在追求“面面俱到” | 强制绿色≤5 条；每条必须通过三问：去掉它用户会放弃选择吗？ |
| **Yellow-neglect** | 只盯绿色要素，黄色优化项长期不迭代，体验被竞品反超 | 黄色虽不决定购买，但影响复购/口碑；每季度做一次黄色项 Review |
| **Red-resurrection** | 明面上排除的要素，在产品规划、PRD、OKR 里又偷偷加回来 | 建立红色要素清单，每次迭代前由一号位检查是否有“红色复活” |
| **用户逻辑错位** | 绿色要素是团队一厢情愿，未对应真实用户决策行为 | 用户访谈必须指向具体选择场景：你上次为什么选/不选我们？ |
| **指标游戏** | 为短期转化率牺牲长期价值，例如诱导注册、夸大承诺 | 内核画布必须配长期指标：续费率、复购率、NPS/口碑，不单看转化 |
| **画布对象混淆** | 把多个产品/多个用户角色混在一张画布上，导致结论打架 | 严格按步骤 1 拆分：一个独立交付物、一个核心用户角色、一张画布 |
| **画完即弃** | 画布一次定型，市场变化后仍沿用旧内核，逐渐失效 | 每季度回顾画布；出现新竞品、新渠道、用户结构变化时立即触发重画 |
