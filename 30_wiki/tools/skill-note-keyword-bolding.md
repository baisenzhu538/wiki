# 关键词加粗三重结构：视觉重心即认知重心的标记法则

## Purpose

本技能卡提供清单体笔记中**关键词视觉标记**的三级递进方法。核心洞察：读者（包括未来的自己和AI）在阅读时不是逐字扫描，而是**先扫视觉重心、再决定要不要细读**。加粗不是装饰，而是**认知导航**——它告诉读者"这里是重点，其他可以略读"。Truman十年实践的核心发现：不加粗的清单体是"信息仓库"，加粗后的清单体是"决策工具"。

## When to Use

| 场景 | 判断标准 |
|:---|:---|
| 任何需要快速定位重点的笔记 | 读者可能在30秒内需要找到关键信息 |
| 给团队/他人阅读的协作文档 | 降低沟通成本，减少"这句话重点是什么"的追问 |
| 给AI处理的结构化输入 | AI对加粗关键词的权重识别更敏感，输出更聚焦 |
| 会议纪要和决策记录 | 事后回顾时能在10秒内定位核心结论 |
| 培训材料和操作手册 | 学习者需要在压力下（现场）快速找到下一步动作 |
| 超过10行的列表 | 无视觉标记的长列表会让读者迷失在信息海洋中 |

## When NOT to Use

| 场景 | 为什么失效 | 后果 |
|:---|:---|:---|
| 个人速记（不分享） | 只有自己看，视觉标记无意义 | 增加记录时间，无额外收益 |
| 脑暴阶段原始记录 | 想法尚未结构化，过早标记会固化不成熟判断 | 把草稿当成定稿，扼杀后续迭代 |
| 全部加粗 = 全不加粗 | 失去"对比"这一核心机制 | 视觉重心消失，读者重新陷入逐字阅读 |
| 文学性/情感性内容 | 加粗会破坏语感节奏 | 内容变得机械、生硬 |
| 已经用颜色/图标做了强区分 | 多重标记系统造成视觉噪音 | 读者困惑"到底哪个才是真正的重点" |
| 移动端极窄屏幕阅读 | 加粗在窄屏上的区分度大幅下降 | 标记效果不明显，反而增加视觉负担 |

## Protocol

### 步骤1：区分"主体词、关键词、关键动作"

在加粗之前，先对一句话做**语义解剖**：

| 类型 | 定义 | 示例 |
|:---|:---|:---|
| **主体词** | 这句话在讲"谁/什么" | 用户流失率、产品定位、团队文化 |
| **关键词** | 决定这句话含义的核心概念 | 同比、环比、A/B测试、MVP |
| **关键动作** | 需要执行的具体行为 | 验证、迭代、复盘、对齐、下沉 |

**Truman原话**："主体词、关键词和关键动作都得保留，语气词、插入语、解读细节、修饰语如果非必要的话全拿掉都用不着。"

**常见失败模式**：
- 把修饰语也加粗（"**非常**重要的**一个**关键点"）→ 稀释了真正的重点
- 把连接词加粗（"**因此**、**但是**、**所以**"）→ 这些词的功能是逻辑衔接，不是信息承载
- 每个词都加粗 → 全加粗 = 全不加粗，失去导航功能

### 步骤2：第一重——加粗（基础层，必做）

**操作**：对主体词、关键词、关键动作加粗。

**效果**：读者扫一眼就能知道"这段话在讲什么、核心概念是什么、需要做什么"。

**示例**：

```
❌ 不加粗：
我们在上季度发现用户流失率有明显上升，经过分析主要原因是产品定位不够清晰，导致目标用户群体不够聚焦。建议在下个迭代中重新验证产品定位，通过用户访谈和对齐团队认知来解决这个问题。

✅ 加粗后：
我们在上季度发现**用户流失率**有明显上升，经过分析主要原因是**产品定位**不够清晰，导致**目标用户群体**不够聚焦。建议在下个迭代中**重新验证产品定位**，通过**用户访谈**和**对齐团队认知**来解决这个问题。
```

**3秒测试**：给同事看加粗后的版本3秒，问他"刚才那段话的核心问题是什么、建议做什么"。如果能答对，加粗成功。

### 步骤3：第二重——加颜色（进阶层，选做）

**操作**：对"需要特别注意"或"待决策"的内容加颜色（红/橙）。

**适用场景**：
- 风险项（红色）
- 待确认项（橙色）
- 机会点（绿色）
- 最佳实践（蓝色）

**原则**：
- 同一篇笔记中，颜色不超过3种
- 颜色必须有统一语义（团队内约定）
- 不要为"好看"而加颜色，要为"决策"而加颜色

**常见失败模式**：
- 彩虹式标记（红黄蓝绿紫全上）→ 视觉噪音，比不加还糟
- 颜色语义不一致 → 读者需要重新学习每篇笔记的颜色规则
- 在黑白打印场景下失效 → 未考虑多媒介分发

### 步骤4：第三重——加底色/模块（高阶层，极少用）

**操作**：对"独立成块的背景信息"或"完整的子模块"加底色框。

**适用场景**：
- 背景上下文（灰色底色）
- 数据引用（浅蓝色底色）
- 决策结论（浅黄色底色）
- 行动清单（浅绿色底色）

**原则**：
- 底色比加粗更强，使用频率应更低
- 一个屏幕内不超过2个底色块
- 底色块必须有明确标题

**Truman原话**："基本上绝大部分靠这些（加粗、加颜色、加底色），很多平台不支持颜色。"

### 步骤5：建立团队统一规范

**最小可行规范（MVP）**：

| 标记 | 语义 | 使用频率 |
|:---|:---|:---|
| **加粗** | 关键词/核心概念 | 每句话0-2处 |
| 🔴 红色 | 风险/问题/警告 | 每篇笔记1-3处 |
| 🟠 橙色 | 待确认/待决策 | 每篇笔记1-3处 |
| 🟢 绿色 | 机会/最佳实践 | 每篇笔记1-3处 |
| ⬜ 灰色底色 | 背景上下文 | 每篇笔记0-1处 |

**常见失败模式**：
- 个人随意标记，团队无统一规范 → 协作时每个人有自己的"方言"
- 规范太复杂（10种颜色+8种底色+5种图标）→ 规范本身成为认知负担
- 只定规范不检查 → 规范沦为纸面文件，实际执行走样

### 步骤6：用AI辅助检查标记质量

**Prompt模板**：
```
请检查以下清单体笔记的关键词加粗是否合理：
1. 是否有"该加粗没加粗"的情况？
2. 是否有"不该加粗却加粗"的情况？
3. 加粗后，3秒内能否定位核心信息？
4. 建议如何优化？

[粘贴笔记内容]
```

**注意**：AI对"什么该加粗"的判断不如人类准确（因为涉及上下文和意图），但AI对"全加粗=全不加粗"这类结构性问题非常敏感。

## Example

### ❌ 反例：标记失败的笔记

```
**我们**在**上季度**发现**用户流失率**有**明显**上升，**经过分析**主要**原因**是**产品定位**不够**清晰**，导致**目标用户群体**不够**聚焦**。**建议**在**下个迭代**中**重新验证产品定位**，**通过用户访谈**和**对齐团队认知**来**解决**这个**问题**。
```

**问题诊断**：
- 14处加粗，信息密度过高
- "我们、经过分析、建议、通过、来、解决"都不是关键词
- 读者需要逐字阅读才能理解，失去"扫读"优势

### ✅ 正例：标记成功的笔记

```
上季度**用户流失率**↑15%，核心原因：**产品定位模糊**导致**目标用户分散**。

下阶段行动：
1. **重新验证产品定位**（负责人：张三，DDL：6.15）
2. **用户访谈**10人（聚焦流失用户，负责人：李四，DDL：6.10）
3. **对齐团队认知**（全员会，负责人：王五，DDL：6.20）

🔴 风险：若6.15前未完成定位验证，Q3预算可能冻结。
```

**关键改进**：
- 加粗从14处降到7处，聚焦核心信息
- 关键动作带负责人和DDL，可执行
- 🔴 红色标记风险项，决策层3秒定位

### 案例：Truman自己的标记演进

Truman在2012年（毕业第一年）的笔记几乎不加粗，"一大坨文字"。到2014年，他开始强制自己"视觉重点一定要加粗"。到2016年，他形成了稳定的三重结构习惯：

- **日常笔记**：只用加粗（第一层）
- **团队共享文档**：加粗+颜色（第二层）
- **重要决策记录**：加粗+颜色+底色模块（第三层）

他的经验是：**"标记的频率和笔记的重要性成正比。越重要的笔记，标记越重。但不要为了标记而标记。"**

## Synthesis

本技能的本质是**用视觉层级替代认知层级**。人类视觉系统处理图像的速度比文字快6万倍（Sperling, 1960），加粗关键词就是给读者的视觉系统装了一个"快速筛选器"。[[yt-note-checklist-concept]] 提到的"视觉逻辑就是内容逻辑"——加粗不是装饰，而是逻辑的可视化。

[[skill-note-layer-constraint]] 与本技能互补：分层解决"结构在哪"，加粗解决"重点在哪"。两者结合，才能实现Truman所说的"AI看它特别顺手，一下加载"的效果。分层让AI知道"这些信息是并列还是包含关系"，加粗让AI知道"这些信息里哪些权重更高"。

[[dk-note-surplus-brainpower]] 提供了本技能的底层动力解释：只有当分层和加粗都内化为肌肉记忆，你才有剩余脑力去做更高级的操作。否则，你的脑力会不断被"这段话的重点是什么"消耗掉。

---

**Feedback Path**：使用本技能后，记录"读者3秒定位核心信息的通过率"。如果连续3次低于80%，回到步骤2检查加粗密度是否过高，或步骤5检查颜色语义是否一致。
