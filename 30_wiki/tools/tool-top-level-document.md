# 顶层文档制度：每个项目有且只有一个入口

> 本卡属于「AI×知识管理」体系（楚门探索营第二次飞跃·团队集体，L648-706 + 批注 213157）：任何一个独立项目/业务/复杂课题，顶层有且只有一个文档（四字开头"顶层文档"）——解决什么问题、背景目标、参与方、关键文档、思考讨论，从顶层文档能索引出所有东西。金句："知识不在于某一个人的脑子里，也不靠大家的口头交接；重要的事儿都有入口，关键的材料都有位置"（L688-690）。

## 1. 工具定义

顶层文档 = 项目最上层的入口文档（L658-684）：
- **有且只有一个**（L664）：一个项目一个顶层文档
- **四字开头**（L676）：文档名从"顶层文档"四个字开始（搜索习惯）
- **内容**：解决的问题/背景目标/参与方/关键文档/当时思考与讨论（L684）
- **索引能力**：从顶层文档能索引出项目所有东西（L684）

## 2. 为什么需要

- 团队协作摩擦：来回问"你的项目在哪儿/文档在哪儿"效率极低——摩擦力太大大家就不用知识库了（L666-674）
- 倒逼协同：搜到关键词就有文档；没有就骂负责人（L694）
- 新人加速：扫描两篇文档基本入门（L698）；离职补一两篇文档可走，不对团队造成大损失（L702-704）
- 每年 100+ 个（批注 213157）；第二团队阶段 1000+ 文档 50 员工共用（015236）

## 3. 使用步骤

1. **立项即开**：新项目/业务/课题启动时，先开顶层文档（开一篇文档的动作）
2. **四字命名**：文档名"顶层文档-XXX"（保证搜索命中）
3. **写必知必会**：解决什么问题放最前（最大的必知必会放在前，L686）
4. **挂关键索引**：背景目标/参与方/关键文档/思考讨论全部索引进去
5. **持续更新**：项目进展中所有关键材料都从顶层文档可达

## 4. When NOT to Use

1. **一次性小任务**——当天做完的临时任务不需要顶层文档。
2. **个人速记**——个人知识库用个人文档即可（顶层文档是团队制度）。
3. **AI 单任务**——AI 的"顶层文档"是指给 AI 用的上下文文档（同一机制，见 framework-dual-center 的 Obsidian 侧）。

## 5. 失败模式

| 失败模式 | 真实信号 | 修复动作 |
|:--|:--|:--|
| 多入口 | 项目文档散落各处 | 合并到唯一顶层文档 |
| 无必知必会 | 新人看文档看不懂 | 解决什么问题放最前 |
| 不更新 | 顶层文档过期 | 项目动→顶层文档跟着动（索引更新） |
| 有文档没人搜 | 团队仍口头问 | 立规矩：先搜顶层文档再问人 |

## 6. Action Triggers

- 新项目立项 → 先开顶层文档（"立项即开"）
- 团队"文档在哪儿"来回问 → 检查顶层文档是否缺失/不唯一
- 新人入职 → 给两篇顶层文档（两天入门）
