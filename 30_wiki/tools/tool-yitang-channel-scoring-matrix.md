# 渠道预判评分矩阵：科学排序候选渠道

## Burn line

在 20–100 个候选渠道里，用一张表把「谁更值得先做」从拍脑袋变成算分数；让团队对「先做哪 3–5 个渠道」有结构化的共识，而不是谁嗓门大听谁的。

## 一句话

渠道预判评分矩阵是在渠道探索四步法的「预判」阶段，把候选渠道按**渠道特性、产品匹配度、执行确定性**三个模块量化打分，从而排出优先测试短名单的工具 `[conf=0.85, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-笔记.txt §47]`。

## 1. 为什么需要评分矩阵

渠道探索最常见的死法不是「找不到渠道」，而是：

- 渠道太多，每个都看起来有机会，资源被摊薄；
- 老板凭个人资源或最近热点做决策，团队跟着摇摆；
- 大渠道诱人但hold不住，小渠道能跑但天花板低；
- 测了一圈才发现，产品标准化程度或客单价根本不适合该渠道。

评分矩阵的核心价值是**把隐性的判断显性化**：把「大小、成本、快慢、持续性、标准化、客单价、决策复杂度、资金/技能/资源要求」这些维度变成可对比的分数，让减法有依据 `[conf=0.82, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §284-296, §4248-4316]`。

## 2. 评分矩阵的三模块结构

```text
┌─────────────────────────────────────────────────────────────┐
│                    渠道预判评分矩阵                          │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────────┐  │
│  │ 模块 A       │  │ 模块 B       │  │ 模块 C               │  │
│  │ 渠道特性     │  │ 产品匹配度   │  │ 执行确定性           │  │
│  │ 5 维度       │  │ 3 维度       │  │ 3 维度               │  │
│  │ 大小/集中度  │  │ 标准化程度   │  │ 资金要求             │  │
│  │ 成本/快慢    │  │ 客单价/毛利  │  │ 技能要求             │  │
│  │ 持续性       │  │ 决策复杂度   │  │ 关键资源             │  │
│  └──────┬──────┘  └──────┬──────┘  └──────────┬──────────┘  │
│         └─────────────────┼────────────────────┘             │
│                           ▼                                  │
│              加权总分 → Top 3-5 → 低成本测试                  │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 模块 A：渠道特性（五维度）

渠道特性描述的是「渠道本身长什么样」，与你的产品无关 `[conf=0.92, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-渠道特性-五个维度_paddle_ocr.txt]`：

| 维度 | 高分（5）含义 | 低分（1）含义 | 典型场景 |
|:---|:---|:---|:---|
| **大小** | 年获客/收入天花板高，可支撑长期增长 | 只能带来零散订单，无法规模化 | 平台流量 vs 小众社群 |
| **集中度** | 目标人群高度集中，触达效率高 | 人群分散，触达成本高 | 司机聚集在加油站 vs 散居社区 |
| **成本** | 获客成本低或 ROI 高 | 获客成本高，消耗现金流快 | 内容/SEO vs 信息流买量 |
| **快慢** | 起盘快，1–4 周可见效 | 起盘慢，需数月甚至半年才能验证 | 朋友圈/地推 vs 品牌 SEO |
| **持续性** | 稳定可持续 12 个月以上 | 红利期短，政策/流量波动大 | 老客户推荐 vs 短期热点平台 |

### 2.2 模块 B：产品匹配度（三维度）

产品匹配度回答「这个渠道能不能卖得动你的产品」 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §3939-4074]`：

| 维度 | 高分（5）含义 | 低分（1）含义 | 判断提示 |
|:---|:---|:---|:---|
| **标准化程度** | 规格、定价、交付清晰，用户决策依赖信息少 | 高度非标，需要大量解释、定制或信任建立 | 烟灰缸/渔网（高） vs 鱼子酱洗发水（低） |
| **客单价/毛利** | 渠道销售成本能被毛利覆盖，且有利润余量 | 渠道销售成本吃光毛利甚至亏损 | 万元面销产品 vs 9.9 元包邮品 |
| **决策复杂度** | 用户购买路径短，单人即可决策 | 决策链长、多人参与、需反复说服 | 个人消费品 vs 企业采购系统 |

> **经验锚点**：低客单价、标准化程度高的产品适合电商/短视频/图文等自动化渠道；高客单价、非标、决策复杂的产品更适合直播、社群、面销或顾问式销售 `[数字来自 Truman 口述/估算，待独立核实，source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §4120-4162]`。

### 2.3 模块 C：执行确定性（三维度）

执行确定性回答「这个渠道你到底有没有能力搞定」 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §4246-4292]`：

| 维度 | 高分（5）含义 | 低分（1）含义 | 自检问题 |
|:---|:---|:---|:---|
| **资金要求** | 现有资金/现金流足以支撑 3 轮以上试错 | 需要一次性大额投入，失败即伤筋动骨 | 测这个渠道需要多少试错预算？ |
| **技能要求** | 团队已具备该渠道所需核心能力 | 关键技能完全空白，需从零搭建 | 地推/短视频/PR/BD 你会不会？ |
| **关键资源** | 已有渠道关系、人脉、牌照或合作资源 | 冷启动，没有任何可借力的资源 | 有没有现成的合作入口或背书？ |

## 3. 操作步骤

### Step 0：明确当前阶段权重

不同阶段的权重应该不同 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §4294-4316]`：

| 阶段 | 推荐权重 | 原因 |
|:---|:---|:---|
| **起盘期/ survival** | 确定性 40% + 产品匹配 35% + 渠道特性 25% | 先活下来，优先选快、稳、能 hold 住的 |
| **快速增长期/ scale** | 渠道特性 45% + 产品匹配 30% + 确定性 25% | 已有容错空间，可追求天花板和持续性 |
| **多元化/ portfolio** | 三模块均分 33% | 布局渠道组合，平衡现金流与实验 |

### Step 1：列出候选渠道

- 扫描阶段应产出 **20–50 个候选渠道** `[conf=0.85, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-笔记.txt §46]`；
- 每个渠道一行，先在表上打分，不急着讨论。

### Step 2：逐项打分（1–5 分）

- 每个维度 1–5 分，5 分为最佳；
- 如果某个维度信息不足，标注 `?`，并用最低合理分或暂不纳入总分；
- 多人独立打分，再取平均或中位数，避免个人偏见。

### Step 3：加权求和

```
渠道总分 = Σ(维度得分 × 维度权重)
```

### Step 4：生成短名单

- 按总分排序，取 **Top 3–5** 进入测试；
- 对 Top 5 做敏感性分析：如果把「确定性」权重提高 10%，排序是否剧烈变化？如果会，说明该维度争议大，需要补充情报。

### Step 5：进入低成本测试

- 评分矩阵只做预判，不做终审；
- Top 3–5 渠道必须进入「小预算 / 小范围 / 快反馈」测试，拿真实数据修正分数。

## 5. 典型场景

### 5.1 早期 To C 消费品

- 候选渠道：小红书种草、抖音直播、拼多多、私域社群、线下便利店。
- 关键维度：产品标准化程度 + 客单价/毛利 + 快慢。
- 常见结论：低客单价标品先试拼多多/短视频；高客单价非标品先试小红书+私域。

### 5.2 To B SaaS

- 候选渠道：行业展会、内容 SEO、老客户推荐、代理商、信息流、电话销售。
- 关键维度：决策复杂度 + 关键资源 + 持续性。
- 常见结论：早期优先老客户推荐 + 内容/SEO；有 BD 资源后再拓代理商。

### 5.3 本地生活服务

- 候选渠道：美团/大众点评、抖音团购、社群、地推、异业合作。
- 关键维度：集中度 + 资金要求 + 快慢。
- 常见结论：半径 3 公里内的人群集中渠道优先，避免一开始就铺全国流量。

### 5.4 一堂自身案例映射

一堂在 2021 年后测试了知乎、公众号、抖音、小红书、私域、KOL 推广等渠道，「几乎以每周为单位提假设、做实验、复盘认知」 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-笔记.txt §42]`。评分矩阵的价值在于把这类高频实验的优先级从「老板感觉」变成「可复盘的分数」。

## 6. When NOT to Use

- **产品价值尚未验证**：如果产品本身没人买单，再好的渠道评分也是缘木求鱼。先回去做用户/产品验证。
- **候选渠道少于 10 个**：样本太少，评分排序意义有限。先用渠道扫描小抄把清单打开。
- **只有一个可用渠道**：没有比较对象，评分的价值在于取舍，无取舍则无意义。
- **关键数据完全缺失**：如果某个候选渠道的 70% 维度都是 `?`，评分会变成集体幻想。
- **团队会无视分数**：如果评分只是走流程、最终还是资源/政治说了算，不要做形式主义评分。
- **把评分当终审**：评分矩阵只解决「先测谁」，不解决「能不能跑通」。终审权属于测试数据。

## 7. 常见失败模式

### 失败模式 1：维度定义不一致

**症状**：同一张表，A 同事的「成本 3 分」和 B 同事的「成本 3 分」完全不是一回事。

**修复**：打分前先对齐每个维度的 1/3/5 分定义，最好举出本行业的具体例子。

### 失败模式 2：权重与阶段错配

**症状**：起盘期把「大小」权重设得过高，结果选了一个需要 100 万试错预算的大渠道，现金流撑不住。

**修复**：起盘期优先「确定性」，快速增长期优先「渠道特性」大小/持续性。

### 失败模式 3：平均分掩盖致命短板

**症状**：某个渠道总分高，但「关键资源」只有 1 分（完全没资源），因为其他维度拉高而被选中。

**修复**：设置「一票否决」维度。例如资金要求 ≤2 分直接不进短名单；或在总分旁标注「致命短板」。

### 失败模式 4：产品匹配度被忽视

**症状**：只看渠道大小和快慢，忽视产品标准化程度和客单价，结果落地页卖不动或销售成本覆盖不了毛利。

**修复**：产品匹配度权重不应低于 25%，且必须结合具体产品验证。

### 失败模式 5：打分后不再测试

**症状**：花了两天做评分矩阵，然后选最高分渠道 all in，不做小样本测试。

**修复**：评分矩阵是「预判」，必须搭配 1–4 周、小预算、可量化的测试闭环。

### 失败模式 6：把历史高分渠道无限复制

**症状**：某渠道过去评过分高，现在环境变化（平台政策、竞争加剧）仍然按原分数执行。

**修复**：每季度或在重大环境变化后重新评分，避免路径依赖。

## 8. 与相关框架的关系

- **渠道探索四步法**：评分矩阵位于「预判」步骤，是扫描之后、测试之前的减法工具。
- **渠道单元经济模型**：评分矩阵帮你决定「先测谁」，单元经济模型帮你判断「测完后值不值得放大」。
- **精益创业 ABCD 模型**：评分中的高确定性、低成本渠道可作为「渠道 MVP」优先假设。
- **增长飞轮**：当某个渠道被验证后，要思考它能否嵌入飞轮，成为自我强化的环节。

## 9. 速查卡

```text
3 模块 × 11 维度

- 致命短板被平均 → 必须一票否决
```
