# SABC分级/段位图建模法：给事物排优先级与成长路径

## 用一句话讲清楚

用 **SABC 分级**在资源有限时强制区分“必须做 / 应该做 / 可以做 / 不必做”，用 **段位图**把抽象能力拆成可观察的成长阶梯，让优先级和成长路径从模糊判断变成可执行的结构。

> **Burn line**: SABC 不是分类，而是分级；段位图不是位置，而是路径。

## 核心要点

| 维度 | SABC 分级 | 段位图 |
|---|---|---|
| **解决什么问题** | 当下任务/议题太多，必须做取舍 | 能力/认知/业务水平抽象，看不到下一步 |
| **核心动作** | 按优先级/质量把选项分为 S/A/B/C 四档 | 把水平拆成 4–6 个可观察的等级 |
| **关键规则** | S 不超过 3 个；必须有 C 级；每档标准清晰 | 每一级必须有行为/产出标准，不能是形容词 |
| **输出形态** | 四档列表或金字塔 | 阶梯、水平轴或能力地图 |
| **常见用途** | 会议议题管理、周计划、项目排期 | 能力评估、培训设计、个人成长规划 |

## Visual Analysis

SABC 通常表现为一个四档列表或金字塔，每档有明确标准。段位图通常表现为一个阶梯或水平轴，每一级有清晰的行为/能力描述，能看出从低到高的演化路径。

## 案例：AI 工具小组的周计划分级

**背景**：一个 3 人 AI 工具小组在周一例会上列出 12 项待办，包括模型接入、提示词优化、用户反馈整理、内部培训、文档更新、竞品监控等。所有人觉得每件事都重要，结果上周只完成了 4 项，且关键交付延期。

**SABC 应用过程**：

1. **穷尽列出**：把 12 项全部写在白板上，不做预先排序。
2. **强制定义标准**：
   - src_unknown
   - src_unknown
   - src_unknown
   - src_unknown
3. **强制分级**：S 限 3 个，必须有 C。

| 档位 | 入选事项 | 处理动作 |
|---|---|---|
| **S** | 完成核心模型接入并跑通端到端测试 | 负责人亲自盯，每天站会同步 |
| **S** | 修复用户反馈中导致 30% 请求失败的 Bug | 优先排入周二前修复 |
| **S** | 交付给试点客户的试用报告 | 周三前必须发出 |
| **A** | 提示词模板优化、竞品监控周报 | 拆分给两名组员 |
| **B** | 内部培训材料更新、文档补全 | 延后到下周 |
| **C** | 新模型尝鲜、界面配色微调、非核心指标看板 | 本周全部砍掉 |

**结果**：S 级全部按期完成，A 级完成 75%，团队从"救火"变成"按级推进"。这个做法可以结合 [[case-yitang-weekly-modeling-engine]] 中的周建模引擎，以及 [[modeling-three-values]] 中对"价值、成本、风险"的拆解来细化标准。执行时建议再配一份 [[tool-checklist-cheatsheet-modeling]] 防止分级变成形式。

## diagnostic_signals

出现以下信号时，优先考虑使用 SABC 分级或段位图：

| 信号 | 说明 | 优先使用 |
|---|---|---|
| 手头事项超过 10 项，感觉都做不完 | 资源有限但优先级模糊 | SABC 分级 |
| 会议议题过多，讨论发散 | 需要强制取舍和聚焦 | SABC 分级 |
| 团队能力参差不齐，培训无从下手 | 能力水平难以描述和比较 | 段位图 |
| 自我成长方向模糊，不知道下一步练什么 | 长期目标抽象，缺少中间阶梯 | 段位图 |
| 评估项目/培训效果时只有主观感受 | 缺少可观察的进步标准 | 段位图 |
| 战略方向清晰但落地动作混乱 | 战略与执行之间缺少分层 | SABC + 段位图 组合使用 |

## 失败模式

| 失败模式 | 典型症状 | 原因 | 修复/预防 |
|---|---|---|---|
| **S 级泛滥** | 所有事都是 S，分级后没有变化 | 不敢取舍，或标准过宽 | 强制 S 级上限为 3，超出则重新讨论标准 |
| **没有 C 级** | 列表里只有 S/A/B | 团队害怕承认“这件事不做” | 把“必须有 C 级”写进规则，允许 C 级存在 |
| **标准不可观察** | 段位描述只有“精通”“熟练”等形容词 | 缺少行为/产出定义 | 每一级替换为“能做什么 + 典型产出” |
| **分级后仍不执行** | SABC 停留在文档，资源分配照旧 | 缺少与计划/执行的绑定 | 把 SABC 结果写入周计划、OKR 或项目排期 |
| **段位图变成贴标签** | 低段位成员感到被评价而不是被支持 | 缺少成长视角和进阶路径 | 强调段位可进化，配套具体提升动作 |
| **忽略系统约束** | 排序合理但整体产出没提升 | 瓶颈未被识别，局部优化 | 先用 TOC/约束分析找到真正瓶颈，再用 SABC |
| **段位标准僵化** | 业务已变化，段位定义仍沿用旧标准 | 缺少动态更新机制 | 每季度/半年 review 一次段位标准 |

## 边界

| 边界 | 说明 |
|------|------|
| **S 级数量** | 建议 1–3 个，超过 5 个等于没有分级 |
| **段位层级数** | 通常 4–6 级，过多失去指导意义 |
| **标准可观察** | 每级/每档必须有可验证的标准 |
| **动态更新** | 段位标准应随业务变化迭代 |
| **不替代决策** | SABC 提供优先级结构，不替代对约束、风险、价值的深度判断 |
| **不用于人身评价** | 段位图是成长工具，不是绩效标签 |
