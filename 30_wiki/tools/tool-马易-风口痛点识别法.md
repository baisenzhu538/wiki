# 技能：风口痛点识别法

## 原始表述

风口痛点识别法是马易在AI落地场景识别中提出的实操方法。

## 操作步骤

1. 识别当前热门风口
2. 深入分析风口中的具体痛点
3. 验证痛点是否真实存在
4. 基于痛点设计解决方案

## 目的

解决AI创业中"追风口却找不到真痛点"的问题——团队看到某个赛道火热就一头扎进去，但只追到了泡沫而非真实需求。风口痛点识别法通过先识别风口、再深入分析风口中的具体痛点、最后验证痛点的真实性，确保切入点是"风口中的真问题"而非"风口中的热闹"。适用于AI SaaS创业团队在选方向阶段，需要从大量风口噪音中筛选出可落地的痛点。

## 质疑

风口痛点识别法的隐含前提是"风口中存在可以被识别的真实痛点，且识别痛点的速度足以跟上风口窗口期"，但这个假设在快速变化的市场中可能不成立。**Clayton Christensen** 在破坏性创新研究中指出，追逐现有风口本质上是延续性创新思维——真正的机会往往不在可见风口内，而在尚未被定义为风口的边缘区域。一个具体反例：团队在RPA风口中识别出"数据录入自动化"的痛点并投入，但这个痛点已被十余家竞品解决，痛点虽真实但已无差异化空间。另一个边界是：验证痛点真实性的方法本身可能存在前提偏差——用户访谈中确认的"痛点"与用户实际愿意付费解决的"痛点"之间存在巨大鸿沟，**Nir Eyal** 在习惯养成研究中指出，"觉得烦"和"愿意花钱"是两个完全不同层级的痛点。
