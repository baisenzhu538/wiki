# 一堂阻力挖掘方式：把阻力当关键假设来定位

> **一句话**：阻力是影响最终转化率的前置关键假设；一旦把阻力理解为关键假设，一堂讲的所有假设验证方法就都能用了——调研、专家访谈、低成本测试、客观数据。（`阻力篇-口述:732-736`）

---

## Purpose

解决"转化率低但不知道用户卡在哪"的问题。把阻力从模糊的"用户犹豫"还原成可定位、可验证的关键假设，提供系统化的挖掘方法。

适用场景：
- 新产品上线前内部推演
- 某个转化环节数据明显异常
- 客服/销售反馈"用户总在问同样的问题"

---

## Protocol

### 核心认知：阻力 = 关键假设

> "阻力是一种关键假设，就是阻力是一种影响最终转化率的前置关键假设。所有在一堂讲的假设的实验方法都有效了。"（`阻力篇-口述:732-736`）

这意味着：挖掘阻力不是猜用户心思，而是提出假设 → 收集证据 → 验证/证伪。

### 九种挖掘方法

| 方法 | 具体做法 | 适用情境 |
|---|---|---|
| **内部推演** | 场景推演、角色模拟，静下来带入用户视角列"用户到底担心什么" | 产品上线前、没有真实用户数据时 |
| **数据分析** | 看销售数据哪些环节差；买数据行为样本；内部复盘；找销冠问"这单当时解决了什么点才转化的" | 已有转化漏斗数据 |
| **客服/投诉分析** | 提问最多、投诉最多、咨询最多的问题就是阻力 | 客服/售后有话术日志 |
| **用户访谈** | 最浅层是访谈；限制建立后直接开诚布公问"你在犹豫什么" | 能接触到真实用户 |
| **反馈收集** | 市场反馈、不满建议、投诉 | 有公开/私域反馈渠道 |
| **客户测试** | AB 测试、可用性测试，把用户拉过来看他怎么用 | 产品/页面可快速改动 |
| **市场调研** | 提问区、竞品分析 | 线上销售、电商场景 |
| **评论区 vs 提问区** | 评论区看的是**动力**；阻力主要扎堆在**提问区** | 电商、知识付费、课程详情页 |
| **专家访谈** | 找行业专家/销冠/老用户访谈，提取隐性阻力 | 复杂产品、B2B、高客单价 |

### 关键洞察：评论区看动力，提问区看阻力

> "评论区看的往往是动力，阻力主要扎堆在提问区。买之前的那些纠结的东西，其实才是阻力。"（`阻力篇-口述:786-800`）

- **评论区**：买后用户的评价、晒单、好评，反映的是"已经转化的用户为什么买"。
- **提问区**：买前用户的纠结、顾虑、比较，反映的是"没转化的人在担心什么"。

### 操作步骤

1. **列出转化链路**：把用户从看到产品到成交的每一步列出来。
2. **每步提一个阻力假设**："用户在这里可能担心什么？"
3. **选 1-2 种挖掘方法收集证据**：根据资源选数据分析、访谈、提问区等。
4. **按影响程度排序**：哪些阻力出现的频率最高？对转化率影响最大？
5. **把 Top 阻力交给消除工具**：用 `[[tool-一堂-阻力消除12策小抄]]` 或 `[[tool-一堂-阻力三句话心法]]` 处理。

---

## Anti-patterns

| 反模式 | 症状 | 修复 |
|---|---|---|
| **只看评论区找阻力** | 评论区是动力，不是阻力 | 重点看提问区、客服咨询、用户访谈 |
| **不问用户** | 团队内部脑补用户担心什么 | 直接问用户"你在犹豫什么" |
| **不做内部推演** | 等产品上线后才发现阻力 | 上线前做场景推演和角色模拟 |
| **把每个阻力都当成真的** | 列了 20 条阻力，分不清主次 | 用数据/访谈验证，按频率和影响排序 |

## 案例区：阻力挖掘口述案例精选

### 案例 1：一堂的"骗子"阻力

> 直接问用户后，很多用户说"我觉得你们是骗子"，尤其抖音来的用户。之前没意识到这是阻力。（`阻力篇-口述:776-779`）

### 案例 2：电商提问区才是阻力金矿

> 用户买前会问"买了之后还会额外交钱吗？""护眼功能跟 iPad 一样吗？""摔了有质保吗？"这些才是阻力。（`阻力篇-口述:792-797`）
