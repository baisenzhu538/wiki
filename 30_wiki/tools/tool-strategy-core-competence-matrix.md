# 核心能力评估矩阵：影响力 × 急迫性

> 用于对识别出的核心能力进行优先级排序，决定资源投入顺序。

---

## 一、矩阵结构

```
              影响力
         低          高
    ┌─────────┬─────────┐
高  │    B    │    A    │
急  │ 列入计划 │ 立即行动 │
迫  │ 适当配置 │ 资源倾斜 │
性  ├─────────┼─────────┤
低  │    D    │    C    │
    │ 关注伺机 │ 中长期  │
    └─────────┴─────────┘
```

| 象限 | 策略 | 说明 |
|--|--|--|
| **A：影响力高 × 急迫性高** | 立即行动，资源倾斜 | 对业务成功至关重要且缺口明显 |
| **B：影响力低 × 急迫性高** | 列入计划，适当配置资源 | 需要解决但不必all in |
| **C：影响力高 × 急迫性低** | 中长期改善计划 | 战略性能力，需持续建设 |
| **D：影响力低 × 急迫性低** | 关注，伺机而动 | 不主动投入，观察变化 |

---

## 二、使用步骤

1. **列出核心能力清单**：基于 KSF 或业务设计六要素识别出的关键能力。
2. **影响力打分（1-5）**：该能力对业务成功/竞争优势的影响程度。
3. **急迫性打分（1-5）**：当前缺口是否已影响战略落地或竞争表现。
4. **填入矩阵**：按象限分类。
5. **制定行动计划**：A 象限立即投入，C 象限做长期能力建设规划。

## 三、评估模板

```markdown
| 编号 | 核心能力 | 影响力 (1-5) | 急迫性 (1-5) | 象限 | 行动策略 | 负责人 | 时间 |
|--|--|--|--|--|--|--|--|
| 1 | 数据中台能力 | 5 | 4 | A | 立即行动，资源倾斜 | | |
| 2 | 会员运营体系 | 4 | 3 | C | 中长期改善计划 | | |
| 3 | 海外渠道拓展 | 2 | 4 | B | 列入计划，适当配置资源 | | |
| 4 | 政府关系 | 2 | 2 | D | 关注，伺机而动 | | |
```

---

## 四、与核心能力三标准结合

Prahalad & Hamel 提出核心能力三标准：
1. **客户价值**：对客户感知价值有重大贡献
2. **延展性**：能应用到多个市场或产品
3. **难模仿性**：竞争对手难以复制

**评估流程：**
1. 先用三标准筛选“真核心能力”。
2. 再用影响力×急迫性矩阵决定建设优先级。

## 五、Agent 执行指令

```python
def core_competence_matrix(capabilities: list[str]):
    """评估核心能力优先级"""
    prompts = {
        "筛选": f"对候选能力{capabilities}，用客户价值、延展性、难模仿性三标准筛选真核心能力。",
        "打分": "为每个核心能力的影响力、急迫性打分（1-5）。",
        "分类": "填入影响力×急迫性矩阵，确定A/B/C/D象限。",
        "计划": "为每个象限制定差异化的资源配置和行动计划。"
    }
    return {step: ask(prompt) for step, prompt in prompts.items()}
```

## 六、失败模式

| 失败 | 症状 | 修复 |
|--|--|--|
| 把普通能力当核心能力 | 能力很多但都不独特 | 先用三标准筛选 |
| 打分无标准 | 不同人打分差异大 | 定义每个分数的具体描述 |
| 只做A不做C | 只看急迫不看战略影响 | A 和 C 都要有计划 |
| 不更新 | 一次评估用一年 | 每半年根据战略变化复评 |

## 质疑

> 待补充：这个工具的内在局限是什么？外部反对者会怎么批评？

**Michael Porter** 可能会质疑：这个工具依赖的 **核心能力识别、资源稀缺性、能力延展性、路径依赖** 是否已经被充分验证？

- 核心能力可能成为核心刚性，当环境变化时反而阻碍转型。
- 自评核心能力容易高估，需要用外部市场和客户结果验证。

- 使用前应明确本工具的 **具体假设**、适用 **边界**、潜在 **反例** 和隐含 **前提**，避免把模板输出直接当成战略结论。
