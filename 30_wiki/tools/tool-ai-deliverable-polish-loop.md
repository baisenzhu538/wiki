# AI 交付物打磨循环：从模糊需求到 60 分可用版本

> 把任何「需求模糊、资源有限、时间紧」的 AI 交付任务，从一次随机的生成尝试，变成一套有框架、有判断、有迭代的打磨工作流。

## 不要用的场景

- 在问题边界尚不清晰时，不要急于使用此工具——先做探索性分析。
- 在数据严重不足时，工具的输出质量会急剧下降——宁可暂停也不要强行推进。
- 在团队缺乏该领域基础认知时，工具会放大错误而非纠正错误。
- 在需要快速决策的紧急场景中，完整的工具流程可能过于耗时。

## 质疑

- **具体假设**：该工具假设结构化方法论能产生正确结论，但结论质量取决于输入数据和执行者判断力。
- **边界**：在数据稀缺或快速变化的新兴领域，已有经验框架可能完全失效。
- **反例**：团队完整执行了所有步骤，但核心假设从一开始就是错的。
- **前提**：使用者已具备该领域的基础认知，且数据来源具有代表性。

**Peter Drucker**（管理学大师）会质疑：工具的价值不在于方法论本身，而在于执行者的判断力——没有判断力的执行只是走流程，不等于做好事。真正的风险是有了工具后产生的虚假安全感。

## 操作步骤

1. 明确当前问题的边界和目标
2. 选择合适的工具/方法进行拆解
3. 按步骤执行，记录关键决策点
4. 验证结果，根据反馈调整

## 目的

解决「AI 交付物打磨循环：从模糊需求到 60 分可用版本」场景下的核心问题——帮助使用者系统化地完成任务，减少盲目试错。

## 一、When to Use：适用场景

| 信号 | 说明 |
|:---|:---|
| 任务来自一句模糊指令 | 「做一个 Logo」「写一份方案」「出一张海报」 |
| 资源见底 | 没有专业人手、没有充裕时间、没有外包预算 |
| 需要快速产出 60 分可用版本 | 先解决有无，再逐步迭代 |
| 交付物涉及审美或创意判断 | 需要人把关，但 AI 可以扩样和加速 |
| 团队对「好坏」没有共识 | 需要建立可讨论的判断标准 |

**不适用场景**：任务完全标准化、已有成熟 SOP、对错误零容忍（如财务对账、法律合同终稿）、没有审美判断能力的人单独使用。

## 二、What You Need：前置条件

1. **一页纸顶层文档**：用 [[tool-纪浩-项目启动五问法]] 明确目标、交付物、工作流、知识依赖；用 [[tool-一堂-product-kernel-canvas]] 锁定最小价值组合。
2. **调研渠道**：AI 用于公共知识扫盲，专业结论必须外移给人工或机构。
3. **≥2 个不同能力的 AI 模型**：一个偏意图理解/找方向，一个偏画面/执行。
4. **审美参照系**：[[yt-panproduct-aesthetic-pool]]（最佳实践池子）+ [[yt-panproduct-aesthetic-modeling]]（评价模型），避免拍脑袋判断。
5. **明确的 60 分标准**：先定义「可用」的最低条件，再追求更好。

## 三、Steps：十二步循环

### Step 1：需求对齐（把默认变成白纸黑字）

写出：交付物是什么？做到什么程度？自己做还是外部做？已知关键约束有哪些？

### Step 2：策略匹配（选方法论框架）

判断任务属于哪类框架。设计/内容类交付物优先用 [[framework-一堂五步法-泛产品设计]] 的「磨设计」内环。

### Step 3：内核边界 + 关键路径倒拆

- 用一页纸文档沉淀业务目标、用户、约束、取舍逻辑。
- 从目标倒拆必经判断节点：为了拿到结果，中间必须经过哪些决策？

### Step 4：常识调研（AI 扫盲 + 专业复核）

- 用 AI 快速扫盲公共知识：规范、风险、常见坑。
- 把信息按场景归档：设计时、申请时、使用时，不要一次性全部塞进 prompt。
- 涉及法律、医疗、安全等结论，必须交由专业机构复核。

### Step 5：场景调研（SABC 分级 + 设计语言翻译）

用 [[tool-scene-design-language-translation]] 把场景清单转译为可执行设计约束。

### Step 6：用户调研（找因果模型，错了回退）

- 和 AI 一起列出可参考的拆解框架。
- 如果 AI 产出「每个字都对但连在一起不对」，勇敢回退框架，重新建模。

### Step 7：最佳实践调研（200 / 20 / SABC）

- 看约 200 个案例，记录约 20 个，按 SABC 分级。
- 产出：黑盒直觉 + 白盒标准 + 最佳实践池子。

### Step 8：找 1.0 参考对象

目标不是抄袭，而是找到一个可讨论、可修改、可否定的基础。没有 1.0，就没有迭代。

### Step 9：跨模型抽卡（意图模型 + 执行模型）

| 环节 | 推荐模型类型 | 作用 |
|:---|:---|:---|
| 找方向 / 意图理解 | 推理型模型（Claude / GPT / 其他） | 理解抽象需求，扩创意方向 |
| 画面 / 视觉执行 | Midjourney / 即梦 / 豆包等 | 执行明确画面描述 |
| 文档整理 | 通用大模型 | 整理表格、约束、场景 |
| 法律 / 注册 | 人 / 专业机构 | 最终判断，不可由 AI 替代 |

> 3 版无质变就换模型。模型选择本身是一个决策，不是选一次就用到死。

### Step 10：人抓半成品，精细打磨

- 从一堆 AI 产出中抓住「最值得继续打磨的半成品」。
- 抽象愿望（更高级、更均衡）必须转译为具体操作（线条加粗、留白增加、负形闭合）。
- 必要时人工手绘或软件精修。

### Step 11：场景预览 + 最佳实践池对比

把交付物放进真实场景和最佳实践池，问自己：它解决了什么场景问题？在池子里是更好还是更差？

### Step 12：输出 60 分版本，标注后续迭代点

明确标注：当前版本满足什么、不满足什么、下一步迭代条件是什么。不要让团队误以为这就是终稿。

## 四、AI Model Selection Guide：模型选择速查

本指南只保留 Live81 实战经验；更系统的模型选择策略参考 [[tool-月白-AI模型选择策略]] 和 [[tool-多模型对比抽卡]]。

| 任务 | 推荐模型能力 | 判断标准 |
|:---|:---|:---|
| 意图理解、找方向、框架讨论 | 推理型 / 对话型模型 | 能否把抽象需求拆解成可执行维度 |
| 视觉创意生成、抽卡 | 图像生成模型 | 同一 prompt 下 3 版是否有质变 |
| 文档整理、表格输出 | 通用大模型 | 输出格式是否稳定、可编辑 |
| 法律 / 合规 / 注册判断 | 人 / 专业机构 | 是否承担法律责任 |

**核心原则**：
- 没有最好的模型，只有最适合当前环节的模型。
- 一个模型在同一任务上 3 次无质变，立即换模型或同时抽多个模型。
- 不要把「模型选错」变成「人硬磨」。

## 五、Checklist：≥10 项自检

- [ ] 需求是否已经写成白纸黑字，而不是一句模糊指令？
- [ ] 是否选定了工作框架（如泛产品设计）并明确使用边界？
- [ ] 是否有一页纸顶层文档沉淀业务目标和约束？
- [ ] 是否已完成常识调研，并把信息按场景归档？
- [ ] 是否用 SABC 对场景分级，并转译成设计语言？
- [ ] 是否建立了用户侧的因果模型，而不是业务公式的照搬？
- [ ] 是否已有最佳实践池子和白盒评价标准？
- [ ] 是否找到 1.0 参考对象，进入可迭代状态？
- [ ] 是否根据任务环节选择了合适的 AI 模型？
- [ ] 同一模型 3 版无质变时，是否及时换模型或跨模型抽卡？
- [ ] 抽象要求是否已转译为可执行操作？
- [ ] 是否已做场景预览和最佳实践池对比？
- [ ] 交付物是否标注了 60 分标准和后续迭代点？
- [ ] 法律 / 合规 / 注册类结论是否已外移给专业机构？

## 六、Anti-patterns：典型反模式

| 反模式 | 症状 | 修复 |
|:---|:---|:---|
| 抽象许愿 | 说「更好看、更高级」 | 转译为线条、比例、留白、色彩等可执行描述 |
| 单模型硬磨 | 同一模型反复调不出质变 | 3 版无质变即换模型或跨模型抽卡 |
| 跳过调研 | 直接打开 AI 生成 | 先完成常识、场景、用户、最佳实践四层输入 |
| 追求完美 | 想在有限时间内做到 90 分 | 先输出 60 分可用版本，标注迭代点 |
| 把 AI 输出当终稿 | 直接提交未经人工精修和法律复核的产出 | 人抓半成品 + 专业机构复核 |

## 七、Critique：质疑与局限

### 外部反对者

1. **效率至上派**：「12 步太复杂，直接生成 10 版挑一版更快。」
   - 回应：如果任务是一次性的、后果可控，直接生成没问题；本工具面向的是需要沉淀判断标准、可复用的交付场景。
2. **专业方法论派**：「泛产品设计不是万能药，硬套框架会增加摩擦。」
   - 回应：框架不是枷锁，而是查缺补漏的武器库；应根据任务大小裁剪步骤，不是每一步都同等重量。
3. **AI 乐观派**：「未来 agent 可以自动完成这 12 步，人只需提需求。」
   - 回应：即使 agent 自动执行，目标设定、审美判断、责任承担仍需人；工具帮人建立判断，不是等人被取代。

### 内部局限

1. **依赖人的判断能力**：工具无法替代审美和业务体系；如果使用者本身没有判断力，只会产出更精致的垃圾。
2. **模型能力快速变化**：具体模型推荐半年后可能失效，需要持续更新。
3. **小任务可能过度工程**：对于一张临时海报或一次性文案，完整走 12 步不经济，应裁剪使用。
