# 课程→Skill八步工作流：从结构化内容到可复用AI技能的完整转化

## 原始表述

半肥猫在AI俱乐部分享中说："我最近在做的一件事情就是试图把一堂的课程偐成一个Skill。我拿到了一个老师的授权，把他的课程偐成一个Skill。在偐的过程中，会发现特别多问题……然后我就会想怎么让这些内容不要偐错，比如什么样的Skill值得偐，什么样的Skill不值得偐，有没有一些检测标准。"

本技能将半肥猫的课程转Skill实践沉淀为一套可复用的八步工作流。

## 操作步骤

**步骤1：判断值不值得偐**

评估课程是否适合偐成Skill：触发范围、用户场景明确度。产出：通过/放弃决策。

通关标准：课程有明确的方法论和使用场景。

**步骤2：整理课程主线**

把课程结构化输出为Markdown，清理噪音。产出：结构化课程笔记。

通关标准：能用一个文档说清楚课程的核心逻辑。

**步骤3：抽取案例/问答/行业应用**

识别课程中的具体案例、常见问答、行业场景。产出：素材清单。

通关标准：每个理论点都有配套的实例和反例。

**步骤4：方法变诊断协议**

把课程方法转化为"适用场景+评分规则+风险分级"。产出：诊断协议。

通关标准：能回答"什么情况下用、什么情况下不用、用了有什么风险"。

**步骤5：证据校准+课程主张审查**

区分课程中哪些是事实、哪些是老师观点、哪些需要用户补充验证。产出：证据质量报告。

通关标准：每个主张都有标注（事实/观点/待验证）。

**步骤6：搭技能目录框架**

按功能模块组织Skill指令结构。产出：Skill框架PRD。

通关标准：指令结构清晰，用户知道输入什么、期望得到什么。

**步骤7：测试**

执行5个正向场景+5个反向场景+1个高风险场景。产出：测试得分表。

通关标准：所有场景总分≥20分，高风险场景拒绝能力=3分。

**步骤8：维护**

设计版本号+反馈模板+回归测试流程。产出：维护手册。

通关标准：有明确的版本号、反馈入口、回归测试周期。

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 有结构化方法论的课程（非零散观点） |
| ✅ 适合 | 有明确用户场景和使用边界 |
| ✅ 适合 | 能区分"课程主张"和"可验证事实" |
| ✅ 适合 | 愿意投入时间做多轮测试（≥11个场景） |
| ❌ 不适合 | 课程内容缺乏结构（只有零散观点） → 无法转化为协议 |
| ❌ 不适合 | 没有明确使用场景和边界 → Skill会变成"大而全的废墟" |
| ❌ 不适合 | 默认课程内容全对，不做证据审查 → 丝滑错误会被放大 |
| ❌ 不适合 | 需要快速上线（<3周） → 八步流程需要完整测试，时间不足 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **内容搬运** | 把课程当成知识库而非决策协议 | 课程转Skill的本质是方法论固化为协议，不是内容搬运 |
| **测试不足** | 只测3个正向场景，上线后出事故 | 必须完成5正向+5反向+1高风险测试，高风险拒绝能力=3分 |
| **证据校准缺失** | 课程观点被当成事实固化到Skill | 每个主张标注事实/观点/待验证，防止系统性误解 |
| **版权风险** | 未经授权转Skill被发律师函 | 步骤1前必须确认授权，无授权=红线 |
| **维护缺失** | 课程内容更新后Skill失效 | 设计版本号+反馈模板+回归测试周期，维护成本计入总投入 |
| **过度设计** | 18维度评分标准太复杂无法执行 | 评分标准简化到3-5级，确保评审员能一致执行 |
| **快速上线陷阱** | MVP三天上线但无测试，质量不达标 | 快速上线≠跳过测试，至少完成高风险场景验证 |
| **裸模型替代** | 用户直接把课程丢给模型，无需Skill | Skill必须比裸模型好10倍（36分 vs 8分），否则不值得存在 |

## External Attacks

**外部攻击者**：

> **“版权法务”派**：你把老师的课程偐成Skill，经过授权了吗？即使有授权，课程内容本身受版权保护。你把它偐成可复用的Skill，本质上是在用技术手段稀释课程价值——以后谁还买课？如果你是老师，你会同意学生把你的课偐成Skill卖给别人吗？

> **“快速上线”派**：你搞八步工作流、12维度评分、还要偐11个测试场景，这一套下来三个月过去了。市场窗口早就关了。真正偐产品的人MVP三天上线、一周迭代，你这是在用“完美主义”避免交付。你的评分标准越复杂，越说明你对自己的产品没信心。

> **“AI原教旨”派**：你把一门课程偐成Skill，但大模型本身就能读这门课。用户直接把课程讲义丢给模型就行了，为什么要用你的Skill？你的Skill本质上是在模型和课程之间加了一个不必要的中间层——增加了复杂度，没有增加价值。如果Skill不能比裸模型好10倍，它就不值得存在。

## Action Framework

**启用条件**：你有一门结构化的课程/方法论，有明确的使用场景，且获得了授权。

**退出条件**：你发现课程只是观点集合没有方法论，或者你无法获得授权，或者你没有足够的测试资源。
