# 客户选择：六步循环迭代法

> 业务设计六要素第 1 要素。核心问题：**我们到底为谁创造价值？谁是我们最重要的客户？**

## 六步循环

```
构建场景 → 分析行为 → 情绪因素 → 触发器 → 数据反馈 → 循环迭代
   ↑                                                          │
   └──────────────────────────────────────────────────────────┘
```

| 步 | 做什么 | 关键问题 |
|:--|:--|:--|
| 1 | **构建场景** | 用户在什么情境下遇到问题？时间/地点/社交状态？ |
| 2 | **分析行为** | 用户现在怎么解决？土办法？竞品？不解决？ |
| 3 | **情绪因素** | 做这件事时的情绪是什么？焦虑？期待？无聊？ |
| 4 | **触发器** | 什么让用户觉得"今天必须解决"？ |
| 5 | **数据反馈** | 用什么数据验证以上假设？（不是"我觉得"） |
| 6 | **循环迭代** | 回到步骤 1——客户选择不是一次性的 |

## 客户选择三问（PPT _97 工作坊标准）

1. **我们到底为谁创造价值？**——不是"所有人"，不是"中小企业"，是具体的一类人
2. **谁是我们最重要的客户？**——80% 价值来自 20% 客户，那 20% 是谁？
3. **我们不服务谁？**——"不做什么"比"做什么"更难——但只有说清了才能聚焦

## Agent 执行指令

```python
def customer_selection_workshop(business_context: str):
    """六步循环客户选择推演"""
    prompts = {
        "场景": f"基于「{business_context}」，描述3个最典型的使用场景（时间/地点/社交状态）",
        "行为": "在以上场景中，用户现在怎么解决？（列出3种现有方案+每种方案的最大不满）",
        "情绪": "在以上场景中，用户的情绪是什么？焦虑/期待/无聊/愤怒？第一人称描述",
        "触发器": "什么信号会让用户觉得'今天必须解决这个问题'？列出3个具体触发器",
        "数据": "用什么数据可以验证以上假设？列出3个可测量的指标",
        "循环": "基于前面5步的发现，修正你对'谁是最重要的客户'的判断"
    }
    return {step: ask(prompt) for step, prompt in prompts.items()}
```

## 失败模式

| 失败 | 症状 | 修复 |
|:--|:--|:--|
| 客户太宽 | "目标用户是中小企业" | 加限定条件——行业/规模/地域/痛点，直到可以画出一个具体的人 |
| 跳过"不服务谁" | 只说了要服务谁 | 明确列出不服务的客户类型——帮你聚焦资源 |
| 数据和假设脱节 | 假设是假设，数据是另一个东西 | 每个假设必须配一个可测量的验证指标 |

## 质疑

> 待补充：这个工具的内在局限是什么？外部反对者会怎么批评？

**Michael Porter** 可能会质疑：这个工具依赖的 **客户需求层次、情境适用性、样本偏差、过度细分** 是否已经被充分验证？

- 基于当前客户做选择，可能忽视未满足的新客户群体。
- 过度细分会导致市场碎片化，无法形成规模效应。

- 使用前应明确本工具的 **具体假设**、适用 **边界**、潜在 **反例** 和隐含 **前提**，避免把模板输出直接当成战略结论。
