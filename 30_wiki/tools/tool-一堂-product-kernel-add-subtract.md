# 技能：产品内核加减法

## Summary

产品内核加减法是Truman提出的结构化定位工具，用于从"一大坨"功能中剥离出"用户愿意选择你的最小解决方案"。核心逻辑：**先做加法尽可能多列举价值要素，再做减法按"用户选择逻辑"砎到3-5条内核**。这个过程强迫团队从"内部视角"转向"用户视角"，避免功能堆砌和资源浪费。

## 操作步骤

1. **明确目标用户和核心转化率** — 在画布第一格填入细分人群描述，第二格填入1-3个关键转化率指标（如进店率、续费率、复购率）
2. **做加法：炸弹式脑暴** — 用绿色标记"决定性要素"（去掉后用户不会选你），黄色标记"优化性要素"（有则更好，没则仍选），红色标记"默认不做"（成本高信息低）。尽可能多列，不做过滤
3. **做减法：用户视角砎刀** — 对每个绿色要素问："如果去掉这个，用户还会选我们吗？转化率会大降吗？"如果答案是"仍会选"，降级为黄色或砎掉
4. **强迫取舍到3-5条** — 如果剩余超7条，必须继续砎。Truman强调："必须勇敢做产品价值取舍，这是一号位的基本义务"
5. **验证最小内核** — 用假产品、落地页或最小MVP测试，验证"这3-5条真的能让用户付费/留存吗？"

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 新产品冷启动前确定最小价值单元 |
| ✅ 适合 | 现有产品转化率低迷，怀疑内核不清晰 |
| ✅ 适合 | 团队对"产品定位"有分歧，需要对齐 |
| ✅ 适合 | 增加功能前评估是否真的属于内核 |
| ❌ 不适合 | 用户需求尚未验证 → 需先跑需求验证，再做内核分析 |
| ❌ 不适合 | 纯技术驱动产品 → 内核加减法假设产品有明确的用户价值 |
| ❌ 不适合 | 一次性项目或定制项目 → 内核方法适用于可复制的产品或服务 |
| ❌ 不适合 | 团队无法跳出内部视角 → 产品经理视角会污染"用户视角"判断 |

#| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **舍不得减** | 内核装7-10条，团队焦点分散 | 强迫按"去掉后用户还会选吗"重新排序，内核必须减到3-5条 |
| **内部视角替代用户视角** | 把"我觉得这个功能很酷"当成内核 | 每条要素必须能说出"用户选择我们的具体原因"，用用户原话支撑 |
| **过早做减法** | 加法阶段就否决想法，错过潜在突破点 | 加法阶段不评判只做收集，减法阶段才做判断 |
| **优化性当决定性** | 将"有则更好"的要素留在内核，挤占决定性资源 | 重复问"没有它用户还会选吗"，不会选的才是决定性 |
| **成本敏感缺失** | 内核中穿插高成本低信息要素，拖累利润率 | 默认不做高成本低信息项，除非有强劣数据支持 |
| **加权偏差污染** | 团队投入更多时间的功能被自动认为更重要 | 引入外部评审或用户数据，打破内部权力格局 |
| **替代答案失效** | 用户用"喜欢/不喜欢"简单回答，非真实场景想象 | 结合行为数据（转化率/留存率）验证，不只依赖用户自述 |
| **尾部风险忽视** | 精简内核导致系统缺乏缓冲能力 | 保留1-2条"保险性"要素应对黑天鹅，非日常内核但关键时刻救命 |
| **创新产品保守化** | 用户对全新品类无法准确表达选择逻辑 | 创新型产品需辅以MVP测试，不依赖内核加减法 alone |

## 为什么有效

内核加减法强迫团队从"功能列表"转向"用户决策逻辑"，通过结构化的加减流程消除主观偏差。其有效性基于三个机制：用户视角强制对齐、取舍的可操作性、验证的可循环性。
