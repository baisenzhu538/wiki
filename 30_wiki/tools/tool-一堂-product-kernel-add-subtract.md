# 技能：产品内核加减法

## 不要用的场景


- 团队缺乏产品内核加减法相关领域基础认知时不要用——工具会放大认知偏差而非纠正它。先建立基础共识。
- 产品内核加减法在跨领域迁移时不要直接套用——不同领域的边界条件和关键变量不同，需要先验证适配性。
- 产品内核加减法在监管合规要求严格的场景中不要自行判断——需要法务或合规团队参与审核。

## 目的


将产品内核加减法从'个人经验驱动'升级为'方法论驱动'——让新人能快速上手，让老人能持续迭代。

## Summary

产品内核加减法是Truman提出的结构化定位工具，用于从"一大坨"功能中剥离出"用户愿意选择你的最小解决方案"。核心逻辑：**先做加法尽可能多列举价值要素，再做减法按"用户选择逻辑"砎到3-5条内核**。这个过程强迫团队从"内部视角"转向"用户视角"，避免功能堆砌和资源浪费。

## 操作步骤

1. **明确目标用户和核心转化率** — 在画布第一格填入细分人群描述，第二格填入1-3个关键转化率指标（如进店率、续费率、复购率）
2. **做加法：炸弹式脑暴** — 用绿色标记"决定性要素"（去掉后用户不会选你），黄色标记"优化性要素"（有则更好，没则仍选），红色标记"默认不做"（成本高信息低）。尽可能多列，不做过滤
3. **做减法：用户视角砎刀** — 对每个绿色要素问："如果去掉这个，用户还会选我们吗？转化率会大降吗？"如果答案是"仍会选"，降级为黄色或砎掉
4. **强迫取舍到3-5条** — 如果剩余超7条，必须继续砎。Truman强调："必须勇敢做产品价值取舍，这是一号位的基本义务"
5. **验证最小内核** — 用假产品、落地页或最小MVP测试，验证"这3-5条真的能让用户付费/留存吗？"

### 民主集中做减法流程（团队协作版）

当团队能力较强、氛围开放时，Truman 强烈建议用**民主集中**的方式做减法，效率远高于一人拍脑袋或纯民主一人一票。流程如下：

| 步骤 | 动作 | 关键要点 |
|:-----|:-----|:-----|
| **第一步：加法** | 所有参与方一起做加法，现场调研、头脑风暴，尽可能多列价值要素 | 不评判、不筛选，目标是穷举；可以从经验、同行、用户调研、时间/空间拆解四个维度展开 |
| **第二步：分类** | 告一段落后，对所有加法结果进行分类整理 | 按主题或价值维度归并，消除重复，让清单可读 |
| **第三步：投票** | 所有人带入用户视角，每人投 2 票，选出你认为最重要的要素 | 必须站在用户立场，而非内部视角；投票前可短暂讨论，但最终一人 2 票独立完成 |
| **第四步：一号位合并** | 按投票结果排序，结合一号位的经验和直觉，合并相似项，最终选出 **3-5 条**内核 | 一号位有最终裁量权（因为承担后果），但必须尊重投票结果；合并时避免"和稀泥"，敢于删除低票项 |
| **输出** | 团队共识的 3-5 条产品内核 | 因为全员参与了全过程，这 3-5 条天然具有团队共识基础，执行阻力小 |

> **Truman 原话**："民主集中其实是一个非常好的方式，我们自己大量内部在用……第一步就是大家一起尝试做加法，现场调研。第二步是排序，大家一起投票……投完之后，按照大家的投票和我的经验，最后合并一下，选出 3 到 5 条。"（来源：`一堂-产品内核实操课-Truman-口述.txt` L2378-L2416）

### 两种减法路径对比

| 维度 | 一号位独断 | 民主集中 |
|:-----|:-----|:-----|
| 适用场景 | 一号位经验极强、团队尚不成熟、时间极紧 | 团队能力强、氛围开放、需要全员共识 |
| 优势 | 速度快、责任清晰 | 参与度高、天然共识、信息更全面 |
| 风险 | 个人盲区被放大、团队无参与感 | 耗时稍长、可能陷入"谁也不得罪"的和稀泥 |
| 一号位角色 | 全权拍板 | 最终裁量者，但尊重投票 |

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 新产品冷启动前确定最小价值单元 |
| ✅ 适合 | 现有产品转化率低迷，怀疑内核不清晰 |
| ✅ 适合 | 团队对"产品定位"有分歧，需要对齐 |
| ✅ 适合 | 增加功能前评估是否真的属于内核 |
| ❌ 不适合 | 用户需求尚未验证 → 需先跑需求验证，再做内核分析 |
| ❌ 不适合 | 纯技术驱动产品 → 内核加减法假设产品有明确的用户价值 |
| ❌ 不适合 | 一次性项目或定制项目 → 内核方法适用于可复制的产品或服务 |
| ❌ 不适合 | 团队无法跳出内部视角 → 产品经理视角会污染"用户视角"判断 |

#| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **舍不得减** | 内核装7-10条，团队焦点分散 | 强迫按"去掉后用户还会选吗"重新排序，内核必须减到3-5条 |
| **内部视角替代用户视角** | 把"我觉得这个功能很酷"当成内核 | 每条要素必须能说出"用户选择我们的具体原因"，用用户原话支撑 |
| **过早做减法** | 加法阶段就否决想法，错过潜在突破点 | 加法阶段不评判只做收集，减法阶段才做判断 |
| **优化性当决定性** | 将"有则更好"的要素留在内核，挤占决定性资源 | 重复问"没有它用户还会选吗"，不会选的才是决定性 |
| **成本敏感缺失** | 内核中穿插高成本低信息要素，拖累利润率 | 默认不做高成本低信息项，除非有强劣数据支持 |
| **加权偏差污染** | 团队投入更多时间的功能被自动认为更重要 | 引入外部评审或用户数据，打破内部权力格局 |
| **替代答案失效** | 用户用"喜欢/不喜欢"简单回答，非真实场景想象 | 结合行为数据（转化率/留存率）验证，不只依赖用户自述 |
| **尾部风险忽视** | 精简内核导致系统缺乏缓冲能力 | 保留1-2条"保险性"要素应对黑天鹅，非日常内核但关键时刻救命 |
| **创新产品保守化** | 用户对全新品类无法准确表达选择逻辑 | 创新型产品需辅以MVP测试，不依赖内核加减法 alone |

## 为什么有效

内核加减法强迫团队从"功能列表"转向"用户决策逻辑"，通过结构化的加减流程消除主观偏差。其有效性基于三个机制：用户视角强制对齐、取舍的可操作性、验证的可循环性。

### 外部攻击

#### Daniel Kahneman 的"置换检验"与决策偏差

**Daniel Kahneman**（*思考，快与漫*作者，诺贝尔经济学奖得主）从行为经济学角度攻击内核加减法：

- src_unknown
- src_unknown

> **Kahneman 的讯刺**："你的'内核加减法'听起来很科学，但它假设了一个从未被验证的前提：团队能够在判断'重要性'时保持客观。我研究了几十年人类偏差，告诉你这个假设不成立。你的内核最终反映的不是用户价值，而是团队内部的权力格局。"

#### Nassim Taleb 的"反脆弱性"与极端风险

**Nassim Taleb**（*反脆弱*作者，风险分析学家）从非对称风险角度攻击：

- src_unknown
- src_unknown

> **Taleb 的讯刺**："你在剥离'非必要'要素时，也在剥离'缓冲能力'。你的'最小解决方案'在平稳期看起来很美，但当黑天鹅来临时，你会发现自己的产品没有任何'冒险边际'。你以为在做减法，其实在制造脆弱性。"
