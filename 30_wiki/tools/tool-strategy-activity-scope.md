# 活动范围设计工具：What × How × Where 三问

> 业务设计六要素第 4 要素。核心问题：**我们在价值链上做哪些事、不做哪些事？经营边界和角色是什么？**

---

## 一、活动范围三问

| 问题 | 含义 | 输出物 |
|--|--|--|
| **What：公司致力于哪些业务活动？** | 在价值链各环节（研发、设计、生产、品牌、营销、渠道、服务）中，哪些自己做？ | 自营活动清单 |
| **How：如何联结公司的各业务活动？** | 各环节之间如何协同？通过流程、系统、数据还是关系？ | 活动协同图 |
| **Where：如何选择最合适业务活动的地点？** | 地理/组织布局：哪些放在公司内部、哪些外包、哪些本地化、哪些全球化？ | 布局决策表 |

## 三、零售商对比案例（PPT _121）

PPT `_121` 用三个零售商展示了不同战略定位下的活动范围选择：

| 维度 | 零售商 A：成本导向 | 零售商 B：时尚导向 | 零售商 C：品质导向 |
|--|--|--|--|
| **客户选择** | 注重“成本”的购买者 | 注重“时尚”的购买者 | 注重“品质”的购买者 |
| **价值主张** | “低成本”策略 | “高质量、追逐时尚”的代言 | “高品质、时尚和健康”的选择 |
| **What** | 公司内部：零售（沃尔玛连锁卖场）<br>公司外部：设计、生产（中国低成本中心） | 公司内部：品牌、设计（意大利人才窗口）<br>公司外部：零售、生产（Sunglass Hut / LensCrafters） | 公司内部：品牌、设计<br>公司外部：生产（韩国许可、中国制造） |
| **关键洞察** | 把“零售”做重，把“设计生产”做轻 | 把“品牌设计”做重，把“零售生产”外包 | 聚焦品牌与设计，生产全球布局 |

**核心启示：** 同样的价值链环节，不同定位的企业会选择完全不同的“做与不做”。

## 五、Agent 执行指令

```python
def design_activity_scope(value_proposition: str, industry_value_chain: list[str]):
    """设计业务活动范围"""
    prompts = {
        "三问": f"""基于价值主张「{value_proposition}」，回答活动范围三问：
1. What：在{industry_value_chain}中，我们自营/外包/不做哪些？
2. How：各环节如何协同？
3. Where：活动放在哪里（内部/外部/本地/全球）？""",
        "决策矩阵": "对每条价值链活动，评估战略重要性、内部能力、外部可获得性，给出决策。",
        "对比案例": "找一个同行业标杆，对比其活动范围选择，找出我们的差异点。",
        "风险检查": "识别‘不做’或‘外包’活动可能带来的依赖风险和失控风险。"
    }
    return {step: ask(prompt) for step, prompt in prompts.items()}
```

## 六、失败模式

| 失败 | 症状 | 修复 |
|--|--|--|
| 什么都想做 | 自营环节过多，资源分散 | 用“战略重要性×内部能力”矩阵强制做减法 |
| 关键活动外包 | 把核心能力交给第三方 | 对高战略重要性活动，即使外包也要保留控制力 |
| 活动之间割裂 | 各部门各自为政 | 画出活动协同图，明确数据/流程/决策接口 |
| 地点选择惯性 | 因为“一直这样做”所以继续 | 定期复盘 Where，考虑成本、人才、政策、供应链变化 |

## 质疑

> 待补充：这个工具的内在局限是什么？外部反对者会怎么批评？

**Peter Drucker** 可能会质疑：这个工具依赖的 **活动边界、核心能力、交易成本、垂直整合假设** 是否已经被充分验证？

- 活动范围决策一旦固化，调整成本很高，需要预判技术和市场变化。
- 过度外包关键活动会削弱长期控制力和创新能力。

- 使用前应明确本工具的 **具体假设**、适用 **边界**、潜在 **反例** 和隐含 **前提**，避免把模板输出直接当成战略结论。
