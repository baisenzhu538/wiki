# Y模型应用工作流

> **When to Use**：面对复杂问题、需要持续迭代、不知道从哪入手时，用 Y模型把模糊难题转写为「可验证的因果模型 + 行动计划」。

## 五步法操作清单

### ① 明确核心问题

1. 用一句话写下「我要解决什么」，并标注「这是症状还是根因」。
2. 用 5Whys 或「预期 - 现实之差」追问至少 3 层，找到真正的「因」。
3. 定义 1-3 个可量化目标指标，区分最终目标与过程指标。
4. 把问题复述给不同角色（执行者、用户、旁观者），确认理解一致。
5. 用蓝卡「泛泛而谈」自检：问题描述是否含糊到可以放之四海皆准。

### ② 拆解变量 / 业务公式

1. 列出所有可能影响结果的因素，先用 MECE 做分类。
2. 把目标表达为业务公式：结果 = 变量 A × 变量 B × 变量 C …
3. 识别关键变量：改变哪个变量对结果影响最大。
4. 区分可控变量、不可控变量与外部约束。
5. 对关键变量给出初步的定性分级（高 / 中 / 低）或区间估计。

### ③ 理论端

1. 检索已有课程、书籍、同行模型，列出可借用的理论清单。
2. 对每个理论做「科学类比」：它像什么、不像什么、边界在哪。
3. 用反例攻击：历史上有没有这个理论失效的案例？为什么？
4. 把多个理论组合成针对当前问题的最小因果模型。
5. 把模型显性化：画成图、写成公式、做成一页纸画布。

### ④ 事实端

1. 定性收集：用户访谈、案例对标、专家访谈、现场观察。
2. 定量收集：现有数据、行业基准、历史实验结果、竞品公开数据。
3. 把判断转写为「我假设…」，并为每个假设设计证伪条件。
4. 按「常识 → 情报 → 实验 → 全量投入」的成本阶梯选择验证方式。
5. 执行最小验证闭环：小样本、低成本、快速拿到反 / 正反馈。

### ⑤ 知行迭代

1. 把验证结果与假设对比，记录「证实 / 证伪 / 不确定」。
2. 做归因：结果是模型错了、执行错了，还是外部变量变了？
3. 更新因果模型和关键假设清单，标记置信度变化。
4. 把可复用的经验沉淀为 SOP、检查清单或新卡片。
5. 启动下一轮：提出新假设 → 验证 → 复盘，形成持续迭代节奏。

## 输入

| 输入项 | 说明 | 示例 |
|:---|:---|:---|
| 问题描述 | 当前遇到的模糊难题 | 「产品转化率持续下降」 |
| 已知信息 | 已掌握的数据、理论、案例 | 过去 3 个月漏斗数据、竞品页面 |
| 目标 | 期望达成的可量化结果 | 30 天内转化率从 2% 提升到 3% |
| 约束条件 | 时间、预算、人力、合规等限制 | 预算 5 万、不可改核心功能 |

## 输出

| 输出项 | 说明 | 示例 |
|:---|:---|:---|
| 因果模型图 | 问题 → 关键变量 → 结果的因果链 | 转化 = 流量 × 点击 × 注册 × 付费 |
| 关键假设清单 | 可证伪的前置假设及证伪条件 | 「假设标题优化可提升 20% 点击；若 AB 测试低于 5% 则证伪」 |
| 验证计划 | 按成本阶梯排列的验证动作 | 先用户访谈 5 人，再跑 2 组 AB 测试 |
| 行动计划 | 责任人、时间节点、成功指标 | 周一出方案，周三上线测试，周五复盘 |

## 配套工具：红卡与蓝卡

- **红卡（+1）**：科学实践的正确姿势。例如：明确问题、科学笃定、知行合一、实事求是、解放思想、科学类比、提炼建模、追求事实、定性定量、假设驱动。
- **蓝卡（-1）**：常见避坑清单。例如：泛泛而谈、盲目迷信、知行分裂、主观臆测、思考太浅、不信规律、错误类比、不会建模、忽略事实、以偏概全、运气驱动。

使用方式：当发现自己或团队触发一张蓝卡时，立即减 1 并切换到对应红卡进行修正；当看到红卡行为时，加 1 并鼓励扩散。

## 示例：用 Y模型分析「如何提高某产品转化率」

1. **明确核心问题**：转化率下降是症状，根因可能是「落地页没有让用户产生信任」或「流量质量变差」。目标：30 天内转化率从 2% 提升到 3%。
2. **拆解变量**：转化 = 访问 UV × 点击通过率 × 注册率 × 付费率。先聚焦「注册 → 付费」环节，因为历史数据波动最大。
3. **理论端**：借用一堂「动力 - 阻力 - 触点」模型，假设用户付费动力不足、价格阻力过高、临门触点缺失。
4. **事实端**：
   - 定性：访谈 5 个弃购用户，发现主要阻力是「担心不适合自己」。
   - 定量：漏斗显示 60% 用户停在支付页。
   - 验证：设计「7 天无理由退款 + 1 元试听」实验，小流量跑 1 周。
5. **知行迭代**：实验组转化率提升 35%，但退款率上升。更新模型：降低阻力的同时需控制退款成本；下一步测试「限制试听章节」方案。

## Checklist

1. 问题描述是否已经区分了症状与根因？
2. 是否至少列出一个业务公式或因果链？
3. 关键变量是否已识别并给出置信度？
4. 理论端是否标注了每个模型的适用边界？
5. 事实端是否有定性 + 定量双重输入？
6. 每个关键假设是否有明确的证伪条件？
7. 验证方式是否优先选择了低成本路径（常识 / 情报 / 小实验）？
8. 行动计划是否有责任人、截止时间和成功指标？
9. 复盘时是否记录了「模型错了」还是「执行错了」？
10. 可复用经验是否已沉淀为 SOP 或卡片？
11. 关键节点是否调用了对应蓝卡自检？
12. 团队是否对因果模型达成了显性共识，而非默认一致？

## Anti-patterns

1. **把 Y模型当万能模板**：连午餐吃什么、推文标题都要走完整五步法。
   - **修复**：设定决策阈值，影响 < 3 人、可撤回成本 < 1000 元的决策直接凭直觉。
2. **跳过验证直接全量**：模型看起来对就直接 all-in。
   - **修复**：强制至少一轮小样本验证，关键假设未经验证不得进入全量投入。
3. **只收集支持证据**：访谈只找认同方案的人，数据只看有利维度。
   - **修复**：为每个关键假设设计证伪实验，主动搜索反面案例。
4. **定量迷信**：把估算值当精确事实，未标置信度与来源。
   - **修复**：每个数字标注高 / 中 / 低置信度 + 数据来源，并对 TOP3 参数做敏感性分析。
5. **知行分裂**：开会分析得头头是道，会后没人执行或执行后不复盘。
   - **修复**：每个会议必须产出一个「48 小时内可验证的最小动作」。
6. **框架挡箭牌**：「我们已经用 Y模型分析过了」成为拒绝质疑的借口。
   - **修复**：明确规则——任何人可以挑战关键参数，每次分析必须回答「如果 TOP3 参数错 50%，结论会不会变」。

## OPC 智能体适配

可把本工具封装为 `tool-agent-spec-yitang-Y-model-coach` 的对话工作流：

| 触发条件 | Agent 动作 | 输出 |
|:---|:---|:---|
| 用户输入模糊问题 | 问题拆解 Agent 追问目标、约束、已知信息 | 结构化问题陈述 |
| 问题结构化完成 | 因果建模 Agent 引导用户拆变量、画公式 | 因果模型图 + 关键变量清单 |
| 变量清单确认 | 理论推荐 Agent 推荐相关模型与边界 | 理论卡片 + 反例提醒 |
| 理论确认后 | 验证设计 Agent 生成低成本验证计划 | 假设清单 + 验证计划 |
| 验证结果回流 | 迭代复盘 Agent 引导归因与模型更新 | 更新后的模型 + 下一步动作 |

关键约束：Agent 必须在每一步显式要求用户输出「事实依据」或「证伪条件」，不能替用户生成不可验证的结论。

## Critique

### 外部反对者

1. **Gary Klein（自然决策理论）**：专家在真实高压场景中常依赖模式识别而非清单。强制五步法可能降低专家的直觉效率。
2. **Daniel Kahneman（噪声）**：清单能减少偏差，但不能消除估计噪声。如果团队对关键参数估计差异大，工具会放大形式化决策的幻觉。
3. **Paul Feyerabend（反对方法）**：把复杂创新过程压缩为固定步骤，可能丢失真实决策中的偶然性、说服与试错。

### 内部局限

1. **学习曲线陡峭**：新手常在「明确问题」和「拆解变量」阶段卡住，需要多次练习才能形成体感。
2. **容易被仪式化**：团队可能把填画布当作任务完成，而不是真正的认知升级。
3. **对数据基础设施有要求**：事实端高度依赖可获取的数据，数据缺失时工具威力大减。

## Synthesis

Y模型应用工作流是把 [[yt-decision-y-model]] 从「元框架」落到具体问题的操作手册。它与 [[yt-decision-canvas]]、[[yt-decision-ai-partner]] 形成「框架 - 画布 - AI 伙伴」的工具链，也与 [[dk-yitang-Y-model-pitfalls]] 的红蓝卡体系互补。在 OPC 智能体中，它可以被拆分为多 Agent 协作的诊断 - 建模 - 验证 - 复盘工作流，但前提是保留人类对关键假设和证伪条件的最终判断权。
