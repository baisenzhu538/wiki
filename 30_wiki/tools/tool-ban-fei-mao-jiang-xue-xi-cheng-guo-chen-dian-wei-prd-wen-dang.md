# 技能：将学习成果沉淀为 PRD 文档

## 用一句话讲清楚

每次学习或 AI 对话到达阶段性成果时，用 PRD 的结构把“我知道了”写成“别人能直接用的产品说明书”，让知识从消耗品变成可复用资产。

## 失败模式

| 失败模式 | 征兆 | 应对 |
|---|---|---|
| 沉淀变成“记录流水账” | 文档只有过程，没有可执行结构 | 用 PRD 五要素（问题、用户、场景、功能、边界）强制产品化 |
| 只沉淀“做了什么”，没沉淀“为什么这么做” | 后人看了文档仍无法做决策 | 每条核心判断都补充决策逻辑和适用条件 |
| 沉淀后不复盘、不更新 | 文档过时被束之高阁 | 设定维护周期（建议每季度 review），并指定维护人 |
| PRD 范围模糊导致滥用 | 什么场景都答，高风险场景给出错误建议 | 在 PRD 中明确拒绝条件和边界条件 |
| 把 PRD 当能力本身 | 能调用文档但关掉 AI 后无法独立分析 | 保留 20% 无 AI 练习，每周手写一次核心判断 |

## 质疑

- **具体假设**：该工具假设"PRD 结构是知识沉淀的最佳容器"，但 PRD 本质上是产品开发流程的产物——它面向"可执行的功能规格"，而许多学习成果（如直觉判断、隐性经验、审美感觉）无法被 PRD 的五要素（问题、用户、场景、功能、边界）干净承载。
- **边界**：在技术密集型领域（如机器学习模型调优经验），PRD 的结构化反而可能丢失"只能意会不能言传"的关键细节。
- **前提**：该工具的前提是"学习者愿意花额外时间做结构化沉淀"，但现实中大多数人在学习后直接进入下一个任务——沉淀的执行疲劳是最大瓶颈。

**Michael Schrage**（MIT 斯隆管理学院研究员，《The Innovator's Hypothesis》作者）会质疑：PRD 是"瀑布时代"的产物，它假设"先想清楚再执行"。但在快速迭代的实践中，最有价值的知识往往是在"做"的过程中涌现的，而非在"写 PRD"时预设的。把学习成果强制塞入 PRD 结构，可能把"动态理解"冻结成"静态文档"——而后者在三个月后就已经过时了。
