# 项目复盘七维度差距分析清单

> **一句话**：复盘不是"感觉好不好"，而是"计划vs实际差在哪"。七个维度逐项对比，让差距无处可藏。

---

## 一、七维度差距分析表

| # | 分析维度 | 计划（原来定的） | 实际（最后发生的） | 差距原因 |
|:---:|:---|:---|:---|:---|
| 1 | **时间点** |  | 是否延期？过程是否延期？ |  |
| 2 | **人力使用** | 计划__人 | 实际__人 |  |
| 3 | **分工安排** | 原来定了谁做？ | 后来实际谁做的？ |  |
| 4 | **投入程度** | 预期投入度？ | 实际大家投入度？ |  |
| 5 | **分支完成** | 各模块目标？ | 各模块实际完成情况？ |  |
| 6 | **预算投入** | 原来定了__钱？ | 最后花了__钱？ |  |
| 7 | **项目管理** | 预期过程有序？ | 实际有无摩擦/混乱？ |  |

---

## 二、操作步骤

```
Step 1: 填计划列 → 复盘前先找出原始计划数据（文档/邮件）
Step 2: 填实际列 → 根据项目数据填写实际发生的情况
Step 3: 标差距 → 计划vs实际有差异的维度标注"有差距"
Step 4: 找原因 → 对每个有差距的维度追问"为什么？"
Step 5: 定改进 → 基于原因制定具体改进措施
```

---

## 三、Constraints

- 必须先填"计划"再填"实际"——顺序反了会受"后见之明"影响
- 维度4（投入程度）最难量化——可以用1-5分打分代替
- 不是每个维度都有差距——没有差距也是发现（说明这个维度管得好）

---

## 四、失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| 找不到原始计划 | 计划列全空，只能凭记忆填 | 下次启动时把计划文档存档，标记"复盘用" |
| 只填差距不找原因 | "超期了"但不知道为什么 | 每个差距至少追问一层Why |
| 忽略维度4和7 | 只看硬指标，不看投入度和过程 | 这两个维度往往是最根本的原因 |
| 差距分析后无行动 | 找出差距但下次还犯 | 每个Top3差距对应一条改进措施+责任人 |

---

## 五、Action Triggers

- 每个项目复盘的第一个环节：填七维度差距表
- 项目中途出现重大偏差：做一次快速差距分析（只填1/5/6三个维度）
- 季度复盘：汇总多个项目的差距模式，找出系统性问题
