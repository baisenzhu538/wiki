# 清单体分层硬约束：2-3层每层≤7点，Truman十年经验的量化标准

## 用一句话讲清楚

清单体笔记的分层硬约束是**2-3层、每层≤7点（理想≤5点）**，用结构约束降低认知摩擦，让读者和AI能在3秒内加载完整逻辑。

## Purpose

本技能卡提供清单体笔记分层的**量化硬约束**——不是"建议"而是"必须遵守的底线"。Truman十年笔记实践的核心发现：**2-3层结构、每层不超过7点（最好不超过5点）** 是人类认知负荷与信息密度的最优平衡点。违反这个约束，笔记会从"清晰工具"变成"认知迷宫"。

## 边界

| 边界类型 | 具体约束 | 说明 |
|:---|:---|:---|
| **结构边界** | 层级数 ≤ 3 | 1层用于简单列表，2层用于大多数工作笔记，3层用于复杂方案/培训材料 |
| **数量边界** | 每层点数 ≤ 7（理想 ≤ 5） | 5点为轻松处理，6-7点为可接受上限，≥8点必须拆分 |
| **语义边界** | 每层子点 ≥ 2 | 只有1个子点的层级属于过度分层，应合并或取消 |
| **时间边界** | 3秒可加载 | 陌生读者在3秒扫视后应能说出大主题和主要结构 |
| **工具边界** | 任何支持列表的编辑器 | 飞书文档、Notion、Obsidian、Word、Markdown编辑器均可 |
| **灰区边界** | 技术文档/法律文本可例外 | API规范、协议、法律条文可能需要4-5层嵌套，此时本约束让位于信息完整性 |

## When to Use

| 场景 | 判断标准 |
|:---|:---|
| 任何需要分层的清单体笔记 | 内容包含多个层级关系（大点→小点→细节） |
| 给团队/他人阅读的笔记 | 读者的认知资源有限，需要快速定位 |
| 给AI处理的笔记 | AI对过深层级的解析准确率显著下降 |
| 会议纪要和决策记录 | 信息需要在24小时内被快速回顾 |
| 培训材料或操作手册 | 学习者需要在压力下（现场）快速理解 |

## When NOT to Use

| 场景 | 为什么失效 | 后果 |
|:---|:---|:---|
| 纯线性流程（无分支） | 不需要分层，强行分层增加冗余 | 读者困惑"为什么这点下面只有一个子点" |
| 文学性/叙事性内容 | 分层会破坏叙事节奏和情感流动 | 内容失去灵魂，变成干巴巴的操作手册 |
| 脑暴阶段原始记录 | 脑暴需要发散，约束会扼杀创意 | 过早结构化导致遗漏关键想法 |
| 个人速记（不分享） | 只有自己看，认知负荷约束可放宽 | 过度约束降低记录速度 |
| 技术文档（API/协议） | 技术规范可能需要4-5层嵌套 | 强行压缩到3层会导致信息丢失 |

## Protocol

### 步骤1：判断是否需要分层

问自己：**"这些内容是否存在'包含'关系？"**
- src_unknown
- src_unknown

**常见失败模式**：为了"看起来专业"而强行给单层内容加层级，结果每层只有1-2个子点，反而增加阅读负担。

### 步骤2：确定层级数（硬约束：≤3层）

| 层级数 | 适用场景 | 判断标准 |
|:---|:---|:---|
| 1层 | 简单列表、行动项 | 所有条目平行，无包含关系 |
| 2层 | 大多数工作笔记 | 大分类→具体条目 |
| 3层 | 复杂方案、培训材料 | 大分类→中分类→具体条目 |
| **≥4层** | **禁用** | 人类工作记忆无法同时处理4层嵌套 |

**Truman原话**："除非特别复杂，不建议超过三层，2到3层比较舒服的结构。"

**工具/环境要求**：任何支持有序/无序列表的编辑器（飞书文档、Notion、Obsidian、Word）。

### 步骤3：控制每层点数（硬约束：≤7点，理想≤5点）

**Miller法则**：人类工作记忆的容量大约是7±2个信息单元。超过这个范围，大脑会开始"丢包"。

| 点数 | 认知状态 | 建议 |
|:---|:---|:---|
| ≤5 | 轻松处理，有余力思考 | **理想状态** |
| 6-7 | 刚好满载，需要专注 | 可接受的上限 |
| 8-10 | 轻微超载，开始遗漏 | 需要拆分或合并 |
| ≥11 | 严重超载，几乎无法有效处理 | **必须拆分** |

**操作方法**：
1. 列出所有子点后，数一下数量
2. 如果超过7个，强制合并同类项（找共同特征归为一组）
3. 如果合并后仍超过7个，说明这一层需要**拆成两个并列的大分类**

### 步骤4：验证"3秒法则"

完成分层后，做一个**3秒测试**：
1. 把笔记给一个从未看过的人
2. 给他3秒钟扫视
3. 问他："你能说出这篇笔记有几个大主题吗？"

如果答不上来，说明层级或点数超标了。

## 失败模式

| 失败模式 | 典型症状 | 修复动作 |
|:---|:---|:---|
| **层级超载** | 出现4层及以上嵌套，如1.1.1.1 | 拆分为2-3层并列分类，删除无意义中间层级 |
| **点数超载** | 某一层子点≥8个，读者记不住后半段 | 先合并同类项，仍超过7则拆分为两个并列大分类 |
| **过度分层** | 某一层只有1-2个子点，层级意义稀薄 | 取消该层级，改为单层列表或与相邻层级合并 |
| **虚假完整** | 用"等等""其他""未完待续"逃避整理 | 强制归类，补全所有条目，确保清单闭合 |
| **结构不清** | 读者3秒内说不出大主题 | 重新分配层级和点数，做3秒测试 |
| **层级冗余** | 同一主题在多个层级重复出现 | 确定唯一归属层级，删除重复或改为引用 |
| **为分层而分层** | 单层内容强行加层级，显得"专业" | 回归内容本身，无包含关系时直接用单层列表 |
| **忽视AI可读性** | AI无法正确解析嵌套结构 | 压缩到3层以内，统一列表符号（如全部用无序列表或有序列表） |

| 审计项 | 通过标准 | 不通过时的动作 | 跨域映射 |
|:---|:---|:---|:---|

## Synthesis

本技能的本质是**用结构约束来降低认知摩擦**。[[yt-note-checklist-concept]] 提到清单体的四特征之一是"分层"，但分层不是目的而是手段——目的是让读者（包括未来的自己）能在最短的时间内加载完整逻辑。分层约束的量化标准（2-3层、≤7点）来自认知科学中的工作记忆容量研究（Miller, 1956），不是Truman的主观偏好。

[[tool-note-keyword-bolding]] 与本技能互补：分层解决"结构清晰度"，关键词加粗解决"内容辨识度"。两者结合，才能实现Truman所说的"AI看它特别顺手，一下加载"的效果。

[[dk-note-surplus-brainpower]] 提供了本技能的底层动力解释：只有当基本功（分层能力）内化为肌肉记忆，你才有剩余脑力去做更高阶的操作（如跨层关联、现场建模）。分层约束看似是"限制"，实则是"解放"——它释放了你的认知资源。

## 质疑

- **具体假设**：该工具假设"2-3 层每层≤7 点是最佳的笔记结构"，但"7±2"规则来自短期记忆研究，它描述的是"人在短时间内能记住的信息块数量"，不是"笔记的最佳组织结构"。笔记的组织应该服务于"理解和检索"，而非"记忆"。
- **边界**：在复杂领域（如法律条文、医学诊断），信息天然有 5+ 层级——强行压缩到 2-3 层会丢失必要的层级关系。
- **前提**：该工具的前提是"结构化约束能提升笔记质量"，但约束也可能抑制思考——当你为了"每层≤7 点"而合并或拆分条目时，你在"适配规则"而非"适配内容"。

**George Miller**（普林斯顿大学心理学教授，"7±2"规则的提出者）会质疑：他的研究被广泛误读了。"7±2"描述的是短期记忆的容量限制，但它不是"组织信息的最佳实践"。实际上，后续研究表明，专家的短期记忆容量可以远超 7——因为他们能把多个信息"组块化"（chunking）为一个单元。真正的限制不在于"点数"，而在于"组块质量"。一个好的笔记系统应该关注"每个条目的自洽性和关联性"，而非"每层的点数"。
