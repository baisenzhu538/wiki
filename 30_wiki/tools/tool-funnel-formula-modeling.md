# 漏斗图/公式建模法：量化流程与关键变量

> **Burn line**: 漏斗图告诉你哪一步漏得最多，公式告诉你最终结果是哪些变量的乘积。

---

## 用一句话讲清楚

把业务流程拆成阶段看流失（漏斗图），把结果拆成可干预的关键变量（公式），从而定位 ROI 最高的干预点。

---

## 核心要点

1. **漏斗图定位损耗点**：把过程拆成 4–7 个阶段，用阶段间转化率找到最大跌落点，而不是只看总转化率。
2. **公式识别杠杆变量**：把目标指标写成 3–5 个关键变量的乘积/函数，找到对结果影响最大且可干预的变量。
3. **数据是前提**：没有数据的漏斗图和公式只是数字游戏，必须配套埋点与验证计划。
4. **动态更新**：流程和公式都应随业务变化定期复盘，避免一次建模长期套用。
5. **可干预性优先**：只保留团队能动的变量，排除无法影响的宏观因素。

---

## Visual Analysis

漏斗图通常以上宽下窄的倒梯形呈现，每一层代表一个阶段，层与层之间标注转化率或流失率。公式通常以等式呈现，左侧是目标指标，右侧是几个相乘或相加的关键变量。

- **C3 [conf=0.85]**: 漏斗图最重要的不是总转化率，而是阶段间最大跌落点。——推断：基于漏斗图通用用法和 Truman 对“主要矛盾”的强调。
- **C4 [conf=0.8]**: 公式中的变量通常是乘积关系，因为业务结果往往由多个因素共同放大或限制。——推断：基于 GMV = 流量 × 转化率 × 客单价等常见公式。
- **C5 [conf=0.75]**: 漏斗图和公式都需要数据支撑，没有数据时只能做定性示意。——推断：基于量化工具特性。

---

## Purpose

把模糊的“效果不好”变成“哪一步流失最多”或“哪个变量对结果影响最大”，从而找到最高 ROI 的干预点。

---

## Protocol

### 漏斗图使用步骤

#### 步骤 1：定义完整流程

列出用户/业务经历的完整阶段。例如：
- 曝光 → 点击 → 留资 → 试听 → 付费 → 复购

#### 步骤 2：收集各阶段数据

每个阶段的人数、转化率、流失原因。没有数据时先做假设，但要有验证计划。

#### 步骤 3：计算阶段间转化率

重点关注：
- 哪一步转化率最低？
- 哪一步绝对流失人数最多？

#### 步骤 4：定位最大损耗点

把资源优先投入到最大损耗点，而不是平均用力。

#### 步骤 5：干预后重新测量

漏斗图必须动态更新，才能验证干预是否有效。

### 公式使用步骤

#### 步骤 1：明确目标指标

你要拆解什么？GMV、利润、用户增长、内容爆款率？

#### 步骤 2：列出关键变量

用“如果我把 X 翻倍，Y 会不会翻倍？”来测试变量是否真的关键。

#### 步骤 3：确定变量关系

- 乘积关系：GMV = 流量 × 转化率 × 客单价
- 加法关系：总成本 = 固定成本 + 变动成本
- 混合关系：利润 = 收入 - 成本

#### 步骤 4：识别杠杆变量

找那个对结果影响最大、且可干预的变量。

#### 步骤 5：设定改进目标

不要泛泛说“提升转化”，而是说“把试听转化率从 10% 提升到 15%”。

## When NOT to Use

| 场景 | 为什么失效 | 替代方案 |
|---|---|---|
| **阶段无法清晰拆分** | 漏斗图会强行线性化非线性过程。 | 用逻辑链或流程图先梳理 |
| **没有数据或数据质量差** | 量化工具变成数字游戏。 | 先收集数据或做定性分析 |
| **变量之间高度相关** | 公式会高估独立影响。 | 用回归分析或更复杂的统计模型 |
| **追求公式酷炫而忽略可干预性** | 公式好看但无法指导行动。 | 只保留可干预的关键变量 |

---

## 边界

| 边界 | 说明 |
|------|------|
| **漏斗阶段数** | 通常 4–7 个，过多会稀释重点 |
| **转化率定义** | 每个阶段必须有统一口径 |
| **公式变量数** | 最好 3–5 个，过多失去指导意义 |
| **数据更新频率** | 漏斗图和公式都应定期更新 |

---

## 失败模式

| 失败模式 | 典型症状 | 根因 | 修复动作 |
|---|---|---|---|
| **阶段划分过细或过粗** | 找不到重点 / 每个阶段都跌 | 阶段粒度与业务动作不匹配 | 按“可独立干预的动作”重新划分阶段 |
| **转化率口径不统一** | 各部门数据打架 | 分子分母定义不一致 | 明确每个阶段的进入/离开标准并文档化 |
| **把相关当因果** | 调了变量 A，结果没变 | 忽略混杂变量或滞后效应 | 加埋点、做对照实验、引入统计检验 |
| **变量不可干预** | 公式漂亮但没人知道动哪 | 选了宏观/外部变量 | 只保留团队能在 1–2 个季度内影响的变量 |
| **一次建模长期不更新** | 公式越来越不准 | 业务形态变化后未复盘 | 每月/每季度检查变量是否仍成立 |
| **沉迷漏斗忽略质量** | 转化率提升但客诉上升 | 只盯数量指标 | 每个阶段补充质量指标（如 NPS、差评率） |

## [Critique]

### 内部局限性

- 漏斗图容易让人只关注转化率，忽略每个阶段的质量
- 公式容易把复杂因果关系简化成算术关系
- 数据不足时，量化模型会制造虚假精确感

### 外部攻击：Daniel Kahneman — "数字会制造虚假的精确感"

**Daniel Kahneman** 会警告：公式看似客观，但变量的选择、权重的设定都隐含价值判断。一个糟糕的公式会固化偏见，且因其“数学外衣”更难被质疑。

### 反事实测试

- 如果漏斗图去掉某一层，结论会变吗？如果会，说明这一层是真实关键阶段。
- 如果公式中某个变量设为 0，结果是否合理？如果不合理，说明变量关系定义错误。

## 行动 Checklist

### 开始建模前

- [ ] 已明确要分析的业务目标（如 GMV、付费转化、用户增长）
- [ ] 已确认有可靠数据或已制定数据收集计划
- [ ] 已列出完整流程阶段或候选关键变量
- [ ] 已检查变量/阶段是否可被团队干预

### 漏斗图检查

- [ ] 阶段数控制在 4–7 个
- [ ] 每个阶段有明确的进入和离开口径
- [ ] 标注了阶段间转化率和绝对流失数
- [ ] 识别出最大跌落点并给出假设

### 公式检查

- [ ] 目标指标在等式左侧，只保留 3–5 个关键变量
- [ ] 变量关系（乘/加/混合）有业务依据
- [ ] 每个变量都有对应的数据来源或埋点
- [ ] 已识别至少一个杠杆变量并设定量化改进目标

### 落地与复盘

- [ ] 干预方案与最大损耗点/杠杆变量直接挂钩
- [ ] 设定了对照组或前后对比的验证方式
- [ ] 约定了复盘周期（建议 2–4 周）
- [ ] 复盘后根据数据更新漏斗图或公式

## diagnostic_signals

以下信号出现，说明本工具适用或需要被调用：

| 信号 | 说明 |
|------|------|
| 团队说“转化不好”但说不出哪一步 | 需要漏斗图把过程可视化 |
| 目标指标波动大但找不到抓手 | 需要公式拆出可干预变量 |
| 多个部门对“问题在哪”争论不休 | 用漏斗/公式把讨论锚定到数据 |
| 资源有限需要决定优先投哪里 | 用最大跌落点或杠杆变量做 ROI 排序 |
| 已有数据但只被用来报数 | 把数据变成阶段转化率或公式变量 |
| 公式写成后长期没有更新 | 触发复盘，检查变量是否仍成立 |
| 一次优化只盯一个指标但副作用明显 | 用漏斗图补充质量维度的检查 |
