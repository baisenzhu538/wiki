# 单商圈模型：按物理空间算最小单元的经济账

> **一句话定义**：单商圈模型是「以商圈（校区、商业区、美食街、工业园等）为最小可独立核算的物理空间单元，计算其客流、转化、客单价与片区运营成本，判断该片区能否独立跑通并可复制」的单元模型工具 [conf=0.70, source=一堂原创]。

## Purpose

单商圈模型解决的核心问题是：**当业务以物理空间为复制单元扩张时，如何算清「一个片区」本身是否赚钱，而不是被公司总账或单店账所误导**。具体触发场景包括 [conf=0.80, source=原图/VLM描述]：

1. **打算复制商圈的**：你已经在一个商圈跑通，想判断另一个商圈是否值得复制。
2. **以几公里为单位复制生意的**：业务天然以地理半径划分服务范围（如 3 公里配送圈、一个街道/园区）。
3. **按物理区域设置仓储、运营中心的**：需要按片区配置仓库、BD 团队、配送运力，成本与收入都随空间变化。

使用本工具可以回答：这个商圈的客流质量、转化效率、履约成本是否足以支撑独立盈利？跨商圈协同成本会不会让局部盈利变全局亏损？

## Protocol/Procedure

### Step 1：界定商圈边界

明确商圈的物理范围和服务范围：
- 以门店/前置仓/服务点为圆心，服务半径是多少公里？
- 商圈内包含哪些小区、写字楼、园区、学校？
- 商圈之间是否有重叠？客流/客户是否会被多个商圈共享？

### Step 2：识别单商圈收入结构

原图把单商圈模型的核心算式概括为 [conf=0.80, source=原图/VLM描述]：

```
单商圈利润 = 片区总客流 × 转化率 × 客单价 − 片区运营成本 [conf=0.70, source=一堂原创]
```

拆解为可量化参数：

| 参数 | 说明 | 常见坑 |
|:---|:---|:---|
| 片区总客流 | 商圈内真正能被触达的目标人群，不是总人口 | 用「路过人数」替代「有效触达人数」会高估转化 |
| 转化率 | 有效客流中实际下单/签约的比例 | 用试点期最佳数据替代常态数据 |
| 客单价 | 单客/单次的平均收入 | 忽略退款、折扣、账期后的真实收入 |

### Step 3：拆分单商圈成本

**显性成本**：房租/点位费、地推/BD 人力、配送/履约成本、仓储租金、本地营销费用。
**隐性成本**：跨商圈调度成本、总部管理分摊、坏账/退费率、区域竞争导致的获客溢价 [conf=0.70, source=一堂原创]。

### Step 4：做敏感性扫描与可复制性验证

- 对客流、转化率、客单价、关键成本项做乐观/基准/悲观三点估算。
- 对比不同城市/区域的同类型商圈，验证模型参数是否稳定。
- 识别规模扩大后的潜在拐点：配送密度饱和、竞争加剧、房租上涨。

### 核心机制一览

原图把单商圈模型概括为四行 [conf=0.80, source=原图/VLM描述]：

| 维度 | 内容 |
|:---|:---|
| 一句话解释 | 按每个商圈为物理空间，来计算单元模型 |
| 常见变种 | 单校区模型、单商业区模型、单美食街模型、单工业园模型 |
| 典型类型 | To B 团餐、房产中介、物流配送 |
| 触发条件 | 1）打算复制商圈的；2）以几公里为单位复制生意的；3）按物理区域设置仓储、运营中心的 |

基于一堂单元模型通用公式，单商圈模型的核心算式可展开为：

```
单商圈利润 = 片区总客流 × 转化率 × 客单价 − 片区运营成本 [conf=0.70, source=一堂原创]
```

其中「片区运营成本」至少包括：
- **显性成本**：房租/点位费、地推/BD 人力、配送/履约成本、仓储租金、本地营销费用
- **隐性成本**：跨商圈调度成本、总部管理分摊、坏账/退费率、区域竞争导致的获客溢价 [conf=0.70, source=一堂原创]

## When NOT to Use

以下场景使用单商圈模型会失效或产生误导：

| 不适用场景 | 原因 | 替代方案 |
|:---|:---|:---|
| **纯线上业务**（SaaS、内容订阅、在线广告） | 空间成本不显著，用户不受物理商圈约束 | 使用单用户/单订单/单客户模型 |
| **商圈之间高度重叠** | 两个商圈共享配送站、客户、运力，强行拆分会导致重复计算或成本遗漏 | 先划分清晰的服务半径，或改用「单门店/单履约中心」模型 |
| **强关系型、项目制业务**（政府项目、大型 B2G、定制咨询） | 每单差异极大，无法用一个统一商圈模型覆盖 | 使用单项目/单客户模型，按项目单独核算 |
| **模式未验证、无真实片区数据** | 参数波动大，算出来的模型只是假设的伪装 | 先用最小样本做假设验证，再进入单元模型精算 |
| **总账健康但局部亏损已被接受** | 如果战略目的是铺密度、占市场，单商圈模型可能被选择性忽视 | 明确告知模型结论，由一号位做战略取舍，而不是把模型当决策本身 |

### 适用边界（正面清单）

| 适用边界 | 说明 |
|:---|:---|
| 业务以物理空间为复制单元 | 团餐、中介、物流、线下零售、即时零售等 |
| 商圈内部客流、成本、竞争可相对独立核算 | 有清晰的地理边界和服务半径 |
| 业务模式相对标准化 | 单商圈可横向比较，参数有参考意义 |
| 已有 3–6 个月的真实片区数据 | 支撑客流、转化、成本的可靠估算 |

## 失败模式（≥3 条）

1. **把「单门店」误当「单商圈」**：一家门店可能服务多个商圈，或一个商圈有多家门店。用门店算账会掩盖商圈层面的真实客流密度和竞争格局 [conf=0.70, source=一堂原创]。
2. **客流用「路过人数」而非「有效触达人数」**：商圈总客流很大，但真正能被你的产品/服务触达并转化的比例可能极低。高估转化率会让模型从盈利瞬间变亏损 [conf=0.70, source=一堂原创]。
3. **忽视跨商圈协同成本**：单算每个商圈都盈利，但商圈之间的调度、补货、人员支援会吃掉利润。模型缺少「网络级成本」会系统性高估 [conf=0.70, source=一堂原创]。
4. **理想化复制假设**：北京 CBD 的商圈模型直接套用到三线城市，忽视消费能力、竞争强度、履约密度差异，导致规模化后单商圈利润快速衰减 [conf=0.70, source=一堂原创]。

## 与已有框架的关系

- **与 [[yt-unit-model-overview]]**：单商圈模型是「十大单元模型」中「按空间」方向的关键模型之一，与单门店、单城市模型共同构成空间维度的单元经济视图 [conf=0.70, source=一堂原创]。
- **与 [[yt-unit-model-selection]]**：当业务同时涉及单订单、单客户、单商圈等多个单元时，用「复制哪个算哪个」原则判断单商圈是否为核心单元 [conf=0.70, source=一堂原创]。
- **与 [[yt-unit-model-dynamic]]**：商圈模型在规模化过程中会受规模变量（配送密度）、业务变量（客户结构）、环境变量（竞争）影响，动态单元模型用于预判拐点 [conf=0.70, source=一堂原创]。
- **与 [[yt-tob-unit-model]]**：To B 团餐、物流配送等 To B 业务是单商圈模型的典型场景，To B 单元模型强调「业务单元总毛利覆盖所有成本」，单商圈模型是其空间落地 [conf=0.70, source=一堂原创]。

## 可迁移场景

| 场景 | 单商圈模型如何迁移 |
|:---|:---|
| **To B 团餐** | 以一个写字楼/园区为商圈，计算该片区企业客户数、转化率、客单价、地推与配送成本 |
| **房产中介** | 以一个片区/街道为商圈，计算房源量、客源量、成交转化率、门店与经纪人成本 |
| **社区团购** | 以一个小区/驿站覆盖范围为商圈，计算团长密度、订单密度、履约成本 |
| **即时零售** | 以前置仓覆盖的几公里为商圈，计算订单密度、拣货配送成本、库存周转 |
| **线下教育/健身** | 以校区/门店周边 3–5 公里为商圈，计算获客半径、到店转化率、场地人力成本 |

## 行动 Checklist

- [ ] 已明确商圈的物理边界（几公里、哪些小区/写字楼/园区）
- [ ] 已估算商圈内有效客流/潜在客户数，而非简单使用总人口
- [ ] 已拆分单商圈收入：客流 × 转化率 × 客单价
- [ ] 已拆分单商圈成本：房租/点位、本地人力、履约/配送、本地营销、总部摊销
- [ ] 已对关键参数做乐观/基准/悲观三点估算
- [ ] 已检查商圈之间是否存在重叠或共享成本，避免重复计算或遗漏
- [ ] 已对比不同城市/区域的同类型商圈，验证模型可复制性
- [ ] 已设定单商圈模型的监控指标（如日订单密度、单均履约成本、商圈 ROI）
- [ ] 已识别规模扩大后的潜在拐点（配送密度饱和、竞争加剧、房租上涨）

## Critique

### **Alfred Marshall** — 局部均衡无法保证整体最优

Alfred Marshall 在经济学中提出「局部均衡」方法，即把经济系统切分成若干局部市场分别分析。单商圈模型本质上是局部均衡思维在商业管理中的应用：它假设商圈可以被独立切开、独立算账。但 Marshall 自己警告过，局部均衡只有在「其他条件不变」时才成立 [conf=0.75, source=学术观点]。

真实商业中，商圈之间通过品牌溢出、跨区配送、客户流动相互影响。你把 A 商圈的运营成本压到最低，可能导致 B 商圈服务质量下降；你在 A 商圈降价抢客，可能引发 B 商圈价格战。单商圈模型算的是「局部最优」，但局部最优之和未必是全局最优。

### **Michael Porter** — 商圈优势是结构性的，不是算出来的

Michael Porter 在《Competitive Strategy》中提出五力模型，强调行业利润取决于竞争结构、进入壁垒、替代品威胁等结构性因素。单商圈模型倾向于把商圈当成一个可以内部优化的「单元」，但忽略了商圈本身在产业结构中的位置 [conf=0.75, source=学术观点]。

例如，一个位于核心 CBD 的商圈可能客流大、客单价高，但进入壁垒高、竞争者众、房租吞噬利润；一个位于郊区的商圈看似客流小，但竞争弱、履约成本低、客户忠诚度高。单商圈模型如果只看「客流 × 转化率 × 客单价 − 成本」，会低估结构性位置对长期利润的影响。Porter 会提醒：有些商圈天然就是「利润陷阱」，算得再细也改变不了结构。
