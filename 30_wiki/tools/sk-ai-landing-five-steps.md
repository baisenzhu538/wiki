# 技能：AI落地五步执行清单

> **Burn line**: AI落地不是技术炫技，而是从熟悉的小场景出发，五步验收、逐步放大的执行路径。

## 用一句话讲清楚

把企业AI落地拆成**找场景→做判断→做验证→搞开发→慢上线**五步，每步都有明确产出和验收标准，防止跳过验证就全面铺开。

## 核心要点

1. **找场景：找老的干小的**。优先选熟悉的、小颗粒度的业务场景；AI只能干你会的事，不会的事AI也干不了。
2. **做判断：四有可纠偏**。场景需满足有容错、有方法、有数据、有判断，且人类负责人力纠偏。
3. **做验证：用方法套AI环境**。不是问AI能不能做，而是把你现有的方法放到AI环境里跑一遍；缺信息化/数字化时要先补前序步骤。
4. **搞开发：基于验证结果固化工具**。产出可复用的prompt、工作流或工具，团队里至少2人能独立使用。
5. **慢上线：先平行再独行**。AI和人工同时跑至少2-3个月，对比效果、标注错误、逐步替换，而非一次性全量切换。
6. **每步必须验收后才能进入下一步**。这是“一步都不能少”的核心含义。

## Purpose

帮助企业或团队把AI落地从“想试试”变成可执行、可验收、可回退的项目路径。

## Protocol

### 步骤1：找场景（找老的干小的）

| 项目 | 内容 |
|---|---|
| **做什么** | 拆工作流，用[[sk-ai-old-small-checklist]]筛选出1-2个试点场景 |
| **输出物** | 场景清单 + 选择理由 |
| **验收标准** | 能写出该场景的现有SOP |
| **常见坑** | 贪多，一次想落地5个场景 |

### 步骤2：做判断（四有可纠偏）

| 项目 | 内容 |
|---|---|
| **做什么** | 评估“我能不能做”和“值不值得做” |
| **输出物** | 可行性判断表（技术难度/资源投入/预期收益/人类纠偏点） |
| **验收标准** | 有明确的Go/No-Go决策 |
| **常见坑** | 只看ROI最高，不看自己能不能驾驭 |

### 步骤3：做验证（方法套AI环境）

| 项目 | 内容 |
|---|---|
| **做什么** | 用现有方法套入AI环境，小规模跑一个完整周期 |
| **输出物** | 验证报告（AI输出 vs 人工输出对比） |
| **验收标准** | 至少跑完一个完整周期，有数据 |
| **常见坑** | 只验证“能不能跑通”，不验证“效果好不好”；跳过信息化/数字化直接做智能化 |

### 步骤4：搞开发（固化可复用工具）

| 项目 | 内容 |
|---|---|
| **做什么** | 基于验证结果，开发正式的AI工作流或工具 |
| **输出物** | 可复用的prompt/工作流/工具 |
| **验收标准** | 团队里至少有2个人能独立使用 |
| **常见坑** | 开发到一半发现验证阶段的假设是错的 |

### 步骤5：慢上线（先平行再独行）

| 项目 | 内容 |
|---|---|
| **做什么** | 逐步扩大使用范围，不是一次性全量替换 |
| **输出物** | 上线计划（分批替换节奏 + 回退方案） |
| **验收标准** | 有回退方案，出问题能切回人工 |
| **常见坑** | 急于求成，直接全量替换 |

## 边界

| 边界 | 说明 |
|------|------|
| **适用对象** | 已有明确业务场景、想系统推进AI落地的团队；不适用于纯技术探索或AI原生创业 |
| **场景前提** | 必须基于“你会做的事”；完全陌生的领域需先补齐业务认知 |
| **数据前提** | 需要已有方法、数据或规则；从零开始建数据的场景需前置信息化/数字化 |
| **时间预期** | 验证+平行运行通常需要2-3个月，不能期望几周见效 |
| **人类角色** | AI目前最高只能做到98-99%的准确率，最后1%需人类兜底纠偏 |
| **开发深度** | 业务人员掌握流程方法即可，不必深入模型训练/向量差分等技术细节 |

## 失败模式

| 失败模式 | 真实症状 | 可执行修复 |
|---|---|---|
| **跳步推进** | 还没验证就直接开发或全量上线 | 严格按步骤执行，每步必须验收后进入下一步 |
| **场景贪多** | 一次选5个以上场景，资源分散 | 用[[sk-ai-old-small-checklist]]限制首批试点≤2个 |
| **只看ROI不看驾驭力** | 选了一个听起来很酷但团队不懂的场景 | 回到“找老的干小的”，优先熟悉的小场景 |
| **验证只做POC** | 只跑通一次就认为AI可以落地 | 至少跑完一个完整业务周期，对比AI vs人工效果 |
| **跳过平行运行** | 开发完直接全量替换人工 | 按[[sk-ai-parallel-validation]]执行至少2-3个月平行运行 |
| **缺少回退方案** | AI出错后无法切回人工 | 上线前写好回退条件、流程和预留人力 |
| **忽视前置数字化** | 线下/物理场景直接上AI，数据采集成本高 | 先信息化、再数字化、最后智能化 |
