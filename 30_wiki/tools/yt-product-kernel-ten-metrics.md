# 产品内核十大典型指标：从假设到验证的数据体系

> 一堂五步法：产品内核必须有指标验证，不是"感觉好"，而是"数据好"。

## 核心框架

十大典型指标分为三类：

| 类别 | 指标 | 说明 | 验证什么 |
|:---|:---|:---|:---|
| **用户指标** | 1. 目标用户精准度 | 用户画像与实际用户的匹配度 | 用户定义是否准确 |
| | 2. 用户获取成本(CAC) | 获取一个目标用户的成本 | 获客效率 |
| | 3. 用户激活率 | 完成核心功能的用户比例 | 内核吸引力 |
| **转化指标** | 4. 关键转化率 | 从了解到选择的比例 | 内核竞争力 |
| | 5. 付费转化率 | 从试用到付费的比例 | 价值认可度 |
| | 6. 复购/续费率 | 再次付费的比例 | 持续价值 |
| **产品指标** | 7. 核心功能使用率 | 内核功能的使用比例 | 功能设计是否命中 |
| | 8. 功能使用深度 | 用户使用的功能数量 | 是否过度设计 |
| | 9. 用户满意度(NPS) | 用户推荐意愿 | 综合体验 |
| | 10. 用户流失率 | 停止使用产品的比例 | 内核是否持续满足需求 |

## 关键洞察

### 1. 指标与内核的对应关系

每个指标必须对应内核假设：

| 内核假设 | 验证指标 | 指标下降说明 |
|:---|:---|:---|
| 用户定义准确 | 目标用户精准度 | 用户画像与实际不符 |
| 内核有吸引力 | 关键转化率 | 内核竞争力不足 |
| 价值被认可 | 付费转化率 | 价值感知不足或定价问题 |
| 价值持续 | 复购/续费率 | 内核价值不持续 |
| 功能设计命中 | 核心功能使用率 | 功能未命中用户痛点 |

### 2. 关键指标 vs 虚荣指标

| 虚荣指标 | 关键指标 | 为什么 |
|:---|:---|:---|
| 总用户数 | 目标用户精准度 | 用户多但不精准，无价值 |
| 总下载量 | 激活率 | 下载了但不用，无价值 |
| 总营收 | 付费转化率 | 营收高但转化率低，不可持续 |
| 功能数量 | 核心功能使用率 | 功能多但不用，是负担 |
| 媒体曝光 | 关键转化率 | 曝光多但转化少，效率低 |

### 3. 指标的基准和目标

每个指标需要：

- **基准值**：当前值是多少？
- **目标值**：改进后的目标值是多少？
- **行业标杆**：同行优秀值是多少？
- **差距分析**：差距原因是什么？

### 4. 指标的聚焦原则

不是看所有指标，而是聚焦关键指标：

- **阶段1（验证期）**：聚焦关键转化率、激活率
- **阶段2（增长期）**：聚焦CAC、付费转化率
- **阶段3（成熟期）**：聚焦复购率、NPS、流失率

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **指标缺失** | 产品上线，但没有指标监测 | 定义3-5个关键指标，建立监测机制 |
| **虚荣指标** | 关注总用户数、下载量 | 替换为关键指标 |
| **指标与内核脱节** | 指标变化无法说明内核问题 | 重新设计指标，确保对应内核假设 |
| **指标过多** | 看20个指标，无法聚焦 | 聚焦3-5个关键指标 |
| **无基准无目标** | 有指标，但不知道好坏 | 设定基准值和目标值 |
| **指标不行动** | 指标差，但不采取措施 | 建立指标-行动闭环 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 产品内核验证 | 技术性能评估 |
| 产品迭代决策 | 品牌传播效果 |
| 投资尽调 | 运营活动评估 |
| 团队绩效评估 | 财务预测 |

## 行动触发器

- 当定义内核时 → 同时定义验证指标
- 当产品上线时 → 建立指标监测机制
- 当指标异常时 → 分析原因，采取行动
- 当迭代产品时 → 基于指标数据决策
