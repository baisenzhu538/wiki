> 将复杂的决策/分析框架浓缩为一张 A4 速查图，分析时置于案头快速查阅——把"需要记忆"的认知负担转移为"需要看到"的外部辅助。

## 操作步骤

1. **选定要浓缩的 1-3 个核心框架**：不要试图把学过的所有框架都做成速查卡。选"过去 3 个月里你至少有 2 次'啊我应该用那个框架但是记不清步骤了'的时刻"的框架。如果没有这样的框架，先不要做——说明你还不需要。

2. **提炼核心要素**：把每个框架的原始材料（课程笔记/概念卡/书）拿出来，用荧光笔只标记：(a) 步骤名称 (b) 每个步骤的核心问题 (c) 关键检查点/常见错误。标记后，把所有没被荧光笔覆盖的文字删掉。

3. **设计视觉层级**：一张 A4 纸分成 3-4 个区域（每个框架一个区域，或一个框架的 3-4 个阶段各一个区域）。用：(a) 大字号标题区分框架/阶段 (b) 不同颜色标注不同类型信息（步骤=黑色、警告=红色、检查点=蓝色）(c) 箭头或数字标注流程顺序 (d) 框线分组相关内容。

4. **打印并物理放置**：打印出来（彩打最好，黑白也可——用灰度区分层级）。放在：(a) 办公桌右侧（右手取放）(b) 笔记本第一页 (c) 如果在家办公，贴在显示器旁边。关键：必须是物理纸张——不是屏幕上的一个窗口。

5. **使用 2 周后迭代**：用了一两周后，你会自然发现哪些信息是"写上去但从来不看"的，哪些是"每次都要临时补充"的。迭代一次——砍掉冗余，补充缺失。迭代后的版本才是真正好用的。

## 常见失败模式

| 失败模式 | 症状 | 预防 |
|:
------|:-----|:-----|
| **浓缩不够——变成"讲义打印版"** | A4 纸上密密麻麻全是字，看完需要 5 分钟——和看原始笔记没区别 | 规则：速查卡上每个框架的核心步骤不超过 5 行文字。多出来的说明没浓缩到位 |
| **做完就放抽屉里** | 做了精美的速查卡，但放在文件夹里再也没拿出来过 | 强制：做好后必须放在"眼角能扫到的物理位置"。如果 3 天内一次都没用到，要么框架选错了，要么位置没放对 |
| **选了太多框架** | A4 纸上塞了 6 个框架，每个只有指甲盖大小 | 一张 A4 最多 3 个框架。超过了就做两张——但最多两张，超过两张说明你还没想清楚哪个框架最重要 |
| **只做不看——迷恋制作过程** | 花 2 小时设计了一张精美的速查卡，然后满足于"我做完了"的成就感，实际使用时根本不看 | 自问："上周我有任何一次决策/分析时，实际看了这张卡吗？"如果答案是 no，速查卡只是装饰 |

## Example

**五步法速查卡**：

```
┌─────────────────────────────────────────────────────────────┐
│  一堂五步法 ── 速查卡                                        │
├──────────┬────────────────────┬─────────────────────────────┤
│ 1. 需求   │ 用户是谁？          │ ⚠ 别跳过用户访谈             │
│          │ 痛点有多痛？        │ ⚠ 区分"想要"和"需要"         │
├──────────┼────────────────────┼─────────────────────────────┤
│ 2. 方案   │ 最小可交付是什么？   │ ⚠ 别追求完美 v1              │
│          │ 竞品差在哪？        │ ⚠ 先人工跑通再写代码           │
├──────────┼────────────────────┼─────────────────────────────┤
│ 3. 商业模式│ LTV > 3× CAC?     │ ⚠ 别用"行业平均值"算自己的     │
│          │ 谁来付钱？          │ ⚠ 别假设"用户最后会付费"       │
├──────────┼────────────────────┼─────────────────────────────┤
│ 4. 增长   │ 前100个用户从哪来？  │ ⚠ 别指望"做好了自然有人来"    │
│          │ 渠道可复制吗？      │ ⚠ 别把 PR 当增长策略           │
├──────────┼────────────────────┼─────────────────────────────┤
│ 5. 壁垒   │ 6个月后别人能抄吗？  │ ⚠ 别把"先发优势"当壁垒        │
│          │ 为什么是你？        │ ⚠ 别把"品牌"放 v1             │
└──────────┴────────────────────┴─────────────────────────────┘
```

（实际使用时 A4 全尺寸打印，字体和框线足够大以在桌前清晰阅读）

## 为什么有效

认知心理学中的"认知卸载"（cognitive offloading）理论：人类的工作记忆容量极其有限（约 4±1 个 chunks）。当做复杂分析时，工作记忆同时在被"分析对象本身"和"用什么方法分析"两个任务占据。将"方法"外化为视觉辅助后，工作记忆全部释放给"分析对象"——分析质量自然提升。

物理纸张相对于数字工具有独特的优势：无加载时间、无通知干扰、无"切到另一个窗口"的上下文切换成本。眼角扫到 = 已读取。这是数字工具无法替代的体验。

### 外部攻击

**Alfie Kohn**（《奖励的惩罚》作者，教育批判家）会质疑："速查卡本质上是一种'浅学习'工具——它鼓励人们跳过理解，直接套用步骤。你不需要理解五步法为什么是这五步、每步之间的逻辑关系，你只需要跟着卡上的问题走。"长期依赖速查卡的人可能永远无法形成真正的框架思维——他们只是在执行 checklist，而不是在思考。

**Marshall McLuhan**（"媒介即讯息"）的视角：把复杂的思维框架压缩为一张 A4 纸，改变的不仅是"使用方便性"，还有"知识本身的形态"。框架从"需要花时间理解的系统"变成了"可以快速消费的步骤清单"。知识的"速食化"——方便的代价是营养的流失。

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:---------|:----------|:---------|
| 第 N 次发现自己在分析中忘了某个步骤 | 拿出纸笔，把这个框架的步骤写在卡片上（先不设计，纯文字） | 下次分析时能自然想起看卡 |
| 学完一个新框架 | 问自己：这个框架未来 3 个月会用到 ≥3 次吗？如果会→做速查卡 | 3 个月内实际用了 ≥2 次 |
