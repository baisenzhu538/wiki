# 借搭建工具：用现成系统跑业务流

> 在启动自研或重投入之前，先用微信、表单、在线文档、无代码平台、AI 等现成工具把业务流串起来，验证用户是否愿意按预期路径完成核心动作。

## Purpose

这个工具解决的核心问题是：**在正式启动研发或重投入之前，如何以最低成本验证"用户是否愿意按预期路径完成核心动作"**。它把获客、交付、服务链路用现成工具串起来，让团队在写代码、买设备、招研发之前，就能获得真实的用户行为反馈 [conf=0.80, source=一堂精益创业讲义 / FALSE 模型 L 阶段定义]。

## 一句话定义

借搭建工具验证的是**"业务流是否跑通"**：在没写一行自研代码、没买重资产之前，用现成的 IM、表单、文档、原型、无代码、AI 工具把获客-交付-服务链路先跑起来，确认用户会按设计的路径行动，再决定是否进入正式研发 [conf=0.80, source=一堂精益创业讲义 / FALSE 模型 L 阶段定义]。

## 成本/周期/样本量

以下为经验参考，实际取决于业务复杂度和团队熟练度 [conf=0.60, source=经验判断 / 一堂课程通用说法]。

| 产品形态 | 典型工具组合 | 周期 | 成本量级 | 建议样本量 |
|:---|:---|:---:|:---:|:---:|
| 知识/内容类产品 | 微信群 + 在线文档 + 表单 | 1-3 天 | 0-500 元 | 10-50 人 [conf=0.60, source=经验判断] |
| 服务/O2O 类产品 | IM 群 + 多维表格 + 问卷 | 3-7 天 | 0-2000 元 | 10-30 单 [conf=0.60, source=经验判断] |
| 消费品/电商 | 海报/落地页 + 表单 + 收款工具 | 3-7 天 | 500-3000 元 | 50-200 人点击 / 5-20 单 [conf=0.60, source=经验判断] |
| SaaS/B2B 工具 | 原型 + 表单 + 演示文档 | 1-2 周 | 1000-5000 元 | 5-15 家企业访谈/试用 [conf=0.60, source=经验判断] |
| 复杂平台型业务 | 智能体 + 无代码 + 人工撮合 | 2-4 周 | 3000-10000 元 | 20-50 对撮合/交易 [conf=0.60, source=经验判断] |

## When NOT to Use

- 当核心待验证假设是**技术可行性**（如算法延迟、并发稳定性、硬件可靠性、特定接口兼容性）而非用户行为时，不要套用借搭建工具。现成工具只能模拟前端交互，无法暴露真实系统的技术瓶颈。
- 当目标用户**无法通过现成工具自然触达**（例如企业采购决策者拒绝进入微信群、填写公开表单，或行业要求使用官方/合规渠道）时，工具本身会引入严重样本偏差，验证结论失真。
- 当业务流必须依赖**深度系统集成**（如实时库存同步、ERP/CRM 双向接口、支付分账、供应链状态回传）才能判断用户是否愿意行动时，人工拼接的工具链会过度简化关键节点，导致“跑通”是假阳性。
- 当所在行业对**数据留存、资质展示、用户隐私**有强制要求（金融、医疗、教培、政务等），继续用个人微信、公共表单跑验证可能直接触碰合规红线，应先完成合规调研或采用受控沙盒。
- 当把多个工具串起来的**运营、脚本、会员、人工撮合成本**已经接近甚至超过一个最小自研版本，并且拖慢了迭代速度，就不应再“借搭建”，而应转向精简版自研或购买成熟系统。

## 失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| **工具组合越搭越重，变成"低成本的高成本"** | 为了串起工具，买了多个 SaaS 会员、雇了专门运营、写了大量自动化脚本，投入反而接近自研 [conf=0.70, source=经验判断] | 回到"要验证什么假设"，只保留能回答该假设的最小工具链 |
| **把工具当产品，长期不升级** | 用微信群接单一年了还在手动统计， scalable 问题被拖延 [conf=0.70, source=经验判断] | 设定明确的"升级触发条件"，验证通过后就进入系统自研或购买成熟系统 |
| **忽视数据埋点和反馈闭环** | 用户点了海报、进了群，但没有记录转化路径，跑完一轮不知道哪个环节出问题 [conf=0.75, source=经验判断] | 在表单、链接、文档中预留可追踪的入口，至少记录"曝光→点击→留资→转化"四步 |
| **用现成工具做违法违规的"假"** | 在金融、医疗、教培等领域用假资质、假承诺获客 [conf=0.80, source=任务指令 L3 政策/合规边界] | 明确区分"业务流验证"与"对外承诺"，必要时先用合规调研替代实验 |

## 质疑

**Henry Mintzberg** 可能会质疑：这个工具依赖的 **工具适配性、学习成本、流程刚性、人效假设** 是否已经被充分验证？

- 工具本身不能替代判断，过度依赖工具会让团队丧失问题定义能力。
- 新工具的学习成本和流程改造成本往往被低估。

- 使用前应明确本工具的 **具体假设**、适用 **边界**、潜在 **反例** 和隐含 **前提**，避免把模板输出直接当成战略结论。
