# 项目复盘五大价值挖掘清单

> **一句话**：复盘不是为了"走流程"，而是为了"挖金矿"。五个维度逐一挖掘，确保每次复盘都有产出。

---

## 一、五大价值维度

| 价值类型 | 挖掘目的 | 产出物 |
|:---|:---|:---|
| **成败共识** | 更好深入沟通、更好协作、更好汇报 | 团队对齐文档——这事到底算成还是败？ |
| **项目亮点** | 做成了什么、关键成功要素、如何连续成功 | 最佳实践清单——下次可以复用 |
| **问题教训** | 做错了什么、主要失败原因、避免再错 | 踩坑清单——下次不会重复 |
| **过程资产** | 收获思考框架、执行框架、萃取知识 | 方法论/SOP/模板——可迁移到其他项目 |
| **执行计划** | 下一步决定、重点任务、关键事项 | 行动清单——复盘后的具体TODO |

---

## 二、操作步骤

```
Step 1: 成败共识 → 先对齐"这事算成还是败"，不同人的判断可能完全不同
Step 2: 项目亮点 → 每人写3个亮点，合并后投票选出Top3
Step 3: 问题教训 → 每人写3个问题，按影响程度排序
Step 4: 过程资产 → 问"如果再来一次，有什么可以直接复用的？"
Step 5: 执行计划 → 基于以上产出，制定具体的下一步行动
```

---

## 三、Constraints

- 五个维度必须按顺序——先共识成败，再挖亮点教训，最后才到资产和计划
- "成败共识"最容易被跳过——但这是后续所有讨论的基础
- 过程资产不是"会议纪要"——是可复用的框架/模板/清单

---

## 四、失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| 跳过成败共识 | 有人觉得成功有人觉得失败，各说各话 | 第一个环节必须对齐"成败定义" |
| 只有问题没有亮点 | 复盘变成批斗会 | 强制先挖亮点再挖问题 |
| 过程资产=会议纪要 | 写了一堆流水账 | 问"如果给下一个做类似项目的人看，最有用的3条是什么？" |
| 执行计划空洞 | "下次注意""继续努力" | 每条计划必须有负责人+Deadline |

---

## 五、Action Triggers

- 每个项目结束时：按五维度完整走一遍
- 项目中途出现重大失误/成功：做一次迷你复盘（只走亮点+教训）
- 季度/年度总结：汇总多个项目的过程资产，形成团队知识库
