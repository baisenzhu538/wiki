# 技能：低成本输出验证法

- src_unknown

## 原始表述

低成本输出验证法是纪浩在AI协作方法论分享中提出的具体方法，用于低成本输出验证法。

## 操作步骤

1. 选择低成本的输出出口（自媒体文章/图文/短视频）
2. 先通过小范围输出验证思路和案例
3. 收集反馈后迭代
4. 再考虑高成本的线下分享或拆推会

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 高成本演练机会有限，需要降低迭代成本 |
| ✅ 适合 | 担心讲不好受打击，需要低心理门槛的输出方式 |
| ✅ 适合 | 需要快速验证假设，当天可得反馈 |
| ✅ 适合 | 新内容/新观点需要小范围测试市场反应 |
| ❌ 不适合 | 已有成熟舞台和容错空间 → 可以直接高成本输出 |
| ❌ 不适合 | 输出内容涉及敏感或保密信息 → 自媒体公开风险 |
| ❌ 不适合 | 需要深度互动和即时反馈的场景 → 低成本输出互动性弱 |
| ❌ 不适合 | 内容需要权威背书 → 自媒体缺乏权威性 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **迭代成本高** | 高成本演练机会有限，每次必须讲完大课才能进步一次 | 选择低成本输出出口（自媒体/图文/短视频），先小范围验证。降低单次失败成本 |
| **输出恐惧** | 担心讲不好受打击，不敢输出 | 低成本输出降低心理门槛。自媒体文章失败成本远低于线下分享，先写再讲 |
| **验证缓慢** | 需要快速验证假设，但验证周期太长 | 小范围输出当天可得反馈。收集反馈后迭代，再考虑高成本输出 |
| **跳跃验证** | 跳过低成本验证，直接高成本输出，结果失败损失大 | 必须先低成本验证。自媒体文章→图文→短视频→线下分享，逐步升级 |
| **验证不迭代** | 低成本输出后不做迭代，原地重复 | 收集反馈后必须迭代。低成本验证的价值在迭代，不在一次性输出 |
| **反馈噪音** | 自媒体反馈过于碎片化，难以提炼有效信息 | 设定明确的反馈收集目标（如"验证核心观点是否清晰"），定向收集而非全盘接收 |
| **低成本陷阱** | 长期停留在低成本输出，不敢升级 | 设定升级标准（如"连续3篇正向反馈>80%"），达标后必须尝试更高成本输出 |
| **内容稀释** | 为了低成本频繁输出，内容质量下降 | 低成本不等于低质量。每篇输出都应有明确的学习目标，不是为发而发 |

## 为什么有效

降低单次失败的成本，通过小步快跑形成PDCA，避免每次必须讲完大课才能进步一次。低成本输出是假设验证的快速通道。
