# 定量建模：用数字说话的分析框架

> **一句话**：定量建模不是"做数学题"，而是"用数字把模糊的判断变得清晰可验证"。没有数字支撑的调研结论，都是观点。

---

## 核心工具：定量建模四步法

```
定义问题 → 收集数据 → 建立模型 → 验证输出
```

---

## 第一步：定义问题

### 问题类型

| 类型 | 说明 | 示例 |
|:---|:---|:---|
| **估算问题** | 估算某个数值 | "市场规模多大？" |
| **比较问题** | 比较两个选项 | "A和B哪个更好？" |
| **预测问题** | 预测未来趋势 | "明年增长多少？" |
| **优化问题** | 找到最优解 | "最优定价是多少？" |
| **验证问题** | 验证某个假设 | "用户是否愿意付费？" |

### 问题定义模板

```markdown
## 定量建模问题

### 问题描述
[具体要回答的问题]

### 问题类型
[估算/比较/预测/优化/验证]

### 关键变量
1. [变量1]
2. [变量2]

### 输出要求
[需要什么形式的输出]
```

## 第二步：收集数据

### 数据收集方法

| 方法 | 说明 | 适用场景 |
|:---|:---|:---|
| **行业报告** | 引用行业数据 | 市场规模、趋势 |
| **公司财报** | 分析财务数据 | 收入、成本、利润 |
| **用户调研** | 收集用户数据 | 需求、偏好、意愿 |
| **行为数据** | 分析用户行为 | 使用频率、转化率 |
| **实验数据** | A/B测试 | 功能效果、定价 |
| **专家估计** | 专家判断 | 难以量化的因素 |

### 数据质量检查

| 检查项 | 问题 | 标准 |
|:---|:---|:---|
| **来源** | 数据从哪来的？ | 可追溯 |
| **时效** | 什么时候的数据？ | 在有效期内 |
| **样本** | 样本够大吗？ | 统计显著 |
| **方法** | 怎么收集的？ | 方法科学 |
| **偏差** | 有选择性偏差吗？ | 随机抽样 |

## 第三步：建立模型

### 常用模型类型

| 模型 | 说明 | 示例 |
|:---|:---|:---|
| **市场规模模型** | TAM/SAM/SOM | TAM=总人口×渗透率×客单价 |
| **财务模型** | 收入-成本-利润 | 利润=收入-固定成本-变动成本 |
| **用户模型** | 获客-留存-变现 | LTV=CAC×(留存率/流失率) |
| **竞争模型** | 市场份额 | 份额=我的收入/市场总收入 |
| **敏感性模型** | 关键变量影响 | 如果价格变化10%，利润变化多少？ |

## 第四步：验证输出

### 验证方法

| 方法 | 说明 | 示例 |
|:---|:---|:---|
| **历史验证** | 用历史数据验证 | "模型预测去年增长30%，实际是28%" |
| **交叉验证** | 用不同方法验证 | "用两种方法估算市场规模，结果接近" |

## Constraints & Boundaries

### 适用边界

1. **需要量化**：问题需要数字回答
2. **数据可得**：有数据支撑
3. **决策重要**：决策需要量化依据
4. **说服他人**：用数字增强说服力
5. **验证假设**：用数据验证假设

### 不适用场景

1. **纯主观问题**：如审美、偏好
2. **数据不可得**：无法获取数据
3. **快速决策**：没有时间建模
4. **复杂系统**：模型过于复杂
5. **高度不确定**：变量无法估计

## Common Failure Modes

| 失败模式 | 症状 | 修复方法 | 预警信号 |
|:---|:---|:---|:---|
| 数据质量差 | 用不准确的数据 | 数据质量检查 | "这个数据大概..." |
| 模型过度复杂 | 模型太复杂 | 简单优先 | "模型有100个变量" |
| 忽视验证 | 模型不验证 | 强制验证 | "模型应该对" |
| 输入错误 | 变量数值错误 | 交叉验证 | "这个数字好像不对" |
| 忽视不确定性 | 把预测当事实 | 标注置信度 | "预计明年增长30%" |
| 模型僵化 | 不更新模型 | 定期更新 | "模型建了就没动" |
| 行动缺失 | 建模后不行动 | 制定行动计划 | "模型做完了，然后呢？" |

## 目的

解决"模糊判断，无法用数字验证"的问题。当你需要回答估算型问题（市场规模多大）、比较型问题（A 和 B 哪个更好）、预测型问题（明年增长多少）、优化型问题（最优定价是多少）或验证型问题（用户是否愿意付费），但只靠"感觉"和"观点"无法说服他人时，定量建模用数字把模糊的判断变得清晰可验证。适用于：市场规模估算、财务模型搭建、用户 LTV 计算、竞品份额分析、敏感性分析。

## 操作步骤

1. **定义问题**：明确问题类型（估算/比较/预测/优化/验证），用模板输出问题描述、关键变量（如市场规模=人口×渗透率×客单价中的"人口""渗透率""客单价"）和输出要求（需要一个数字？一个区间？一个概率分布？）
2. **收集数据和建立模型**：根据问题类型选择数据收集方法（行业报告、公司财报、用户调研、行为数据、实验数据、专家估计），检查数据质量（来源可追溯、时效在有效期内、样本够大、方法科学、无选择性偏差），然后选择常用模型（市场规模模型 TAM/SAM/SOM、财务模型、用户模型 LTV/CAC、竞争模型、敏感性模型）
3. **验证输出**：用 5 种方法验证模型——历史验证（用历史数据验证预测准确度）、交叉验证（用不同方法估算同一问题，结果是否接近）、专家验证（请行业专家评估模型合理性）、敏感性分析（测试关键变量变化对结果的影响）、边界测试（测试极端情况下的结果是否合理）

## 不要用的场景

- 纯主观问题（如审美、个人偏好），无法用数字量化，强行建模只会制造"伪精确"
- 数据不可得（无法获取关键变量数值），模型再漂亮也没用，先解决数据获取问题
- 快速决策（没有时间建模），用快速估算或专家判断，标注"粗略估计，需验证"
- 复杂系统（模型过于复杂），如宏观经济、生态系统，变量太多且相互影响，模型可信度低
- 高度不确定（变量无法估计），如颠覆性技术、黑天鹅事件，定量模型不如定性判断

## 质疑

- **具体假设**：该工具假设结构化方法论本身能产生正确结论，但方法论只是框架——结论质量取决于输入数据的质量和执行者的判断力。
- **边界**：在数据稀缺或快速变化的新兴领域，已有经验框架可能完全失效——工具的有效性高度依赖场景的稳定性。
- **反例**：一个团队完整执行了所有步骤，产出了漂亮的文档，但核心假设从一开始就是错的——流程的完整性掩盖了判断的缺陷。
- **前提**：使用者已具备该领域的基础认知，能正确理解和执行工具规则，且数据来源具有代表性。

**Ben Wei**：定量建模最大的陷阱是"伪精确"——你建了一个复杂的财务模型，输出了"明年利润 3287 万"这样的精确数字，但实际上你的关键变量（如用户增长率、客单价、留存率）都是粗略估计，误差可能超过 50%。精确的输出格式给人"科学"的错觉，但底座是沙子。更诚实的做法是输出区间（如 2000-5000 万）和置信度，而不是单点估计。

**Clara Wang**：这个方法有个隐藏假设："数字=客观"。但数字也是人制造的——市场规模数据来自行业报告，而报告的数据来源可能是"估算"或"样本推断"；财报数据可能被美化；用户调研数据可能有选择性偏差。你用"数字"建模，但这些数字的制造过程你根本没验证。定量模型的垃圾进垃圾出（GIGO）问题比定性分析更严重，因为"数字外壳"让人放松了警惕。

**Dylan Wu**：定量建模最适合"已知问题、已知变量、已知关系"的场景，但商业调研中大量问题是"未知问题、未知变量、未知关系"。你不知道哪个变量是关键变量，不知道变量之间是什么关系（线性？指数？阈值？），这时候建模型就是在"用精确的语言描述模糊的认知"。更有价值的可能是先做定量建模——用定性方法探索变量之间的关系，然后再考虑建模。
