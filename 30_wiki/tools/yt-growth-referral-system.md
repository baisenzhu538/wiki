# 推荐系统：老带新的设计框架

> 一堂五步法：推荐系统是低成本获客的核心。设计好双边激励，让老用户成为获客渠道。

## 核心框架

推荐系统的核心公式：

```
推荐效果 = 推荐率 × 推荐转化率 × 推荐用户LTV

推荐成本 = 推荐者奖励 + 被推荐者奖励 + 系统运营成本

推荐ROI = 推荐带来的收入 / 推荐成本
```

## 关键洞察

### 1. 推荐系统的4个要素

| 要素 | 说明 | 设计要点 |
|:---|:---|:---|
| **推荐者激励** | 老用户为什么推荐 | 利己、利他、社交货币 |
| **被推荐者激励** | 新用户为什么接受推荐 | 专属优惠、额外价值 |
| **推荐渠道** | 在哪里推荐 | 用户常用的社交平台 |
| **推荐转化** | 被推荐者如何转化 | 降低 friction |

### 2. 双边激励设计

| 激励类型 | 推荐者 | 被推荐者 | 示例 |
|:---|:---|:---|:---|
| **现金奖励** | 现金/优惠券 | 现金/优惠券 | 滴滴红包 |
| **积分奖励** | 积分 | 积分 | 会员积分 |
| **功能解锁** | 解锁高级功能 | 解锁高级功能 | 云存储空间 |
| **社交货币** | 展示身份 | 专属体验 | 邀请码 |
| **公益激励** | 捐赠 | 捐赠 | 公益项目 |

### 3. 推荐系统的类型

| 类型 | 说明 | 适用 | 示例 |
|:---|:---|:---|:---|
| **一对一推荐** | 推荐一个好友 | 社交产品 | 微信邀请 |
| **裂变推荐** | 推荐多个好友 | 激励驱动 | 拼多多 |
| **团队推荐** | 推荐团队/企业 | B2B | Slack |
| **内容推荐** | 分享内容 | 内容产品 | 小红书 |
| **功能推荐** | 使用功能时推荐 | 工具产品 | Dropbox |

### 4. 推荐系统的评估

| 指标 | 说明 | 健康标准 |
|:---|:---|:---|
| **推荐率** | 多少用户推荐 | > 20% |
| **推荐转化率** | 被推荐者多少注册 | > 30% |
| **推荐用户质量** | 推荐用户LTV | > 平均LTV |
| **推荐成本** | 单用户推荐成本 | < CAC |
| **推荐ROI** | 推荐投资回报 | > 3 |

### 5. 推荐系统的防作弊

| 作弊类型 | 说明 | 防范 |
|:---|:---|:---|
| **虚假推荐** | 自己推荐自己 | 身份验证 |
| **批量注册** | 批量注册虚假账号 | 设备指纹、行为分析 |
| **羊毛党** | 专门薅推荐奖励 | 奖励门槛、限制条件 |
| **刷量** | 刷推荐量 | 数据监控、异常检测 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **激励不足** | 用户不愿推荐 | 提升激励 |
| **激励失衡** | 推荐者或被推荐者不满 | 平衡双边激励 |
| **推荐 friction 高** | 推荐流程复杂 | 简化流程 |
| **忽视推荐质量** | 推荐用户质量差 | 筛选推荐者 |
| **作弊泛滥** | 推荐系统被薅羊毛 | 防作弊机制 |
| **推荐成本过高** | 推荐成本超过CAC | 优化激励 |

## 质疑

- **具体假设**：该工具假设工具本身能解决问题，但工具只是'能力放大器'——如果使用者的判断力不足，工具只会放大错误而非放大正确。
- **边界**：在全新领域或快速变化的环境中，已有数据和经验可能完全失效——工具的有效性高度依赖场景的稳定性。
- **前提**：该工具的前提是使用者能正确理解和执行工具的规则，但执行者的认知偏差和经验限制会影响工具的实际效果。

**Amy Edmondson**（哈佛商学院教授）会质疑：工具的价值不在于"有没有"，而在于"用得好不好"。任何工具都是"能力放大器"——如果使用者的判断力不足，工具只会放大错误。真正的风险不是"缺少工具"，而是"有了工具后产生的虚假安全感"——让你以为自己已经覆盖了所有可能性，实际上只是走完了流程。
