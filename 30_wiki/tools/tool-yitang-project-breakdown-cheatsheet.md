# 项目拆计划一页纸小抄

> **一句话**：拆计划的全部操作检查清单——拿到项目后，从敏感度判断到最终排期，每一步该做什么、用什么工具、有什么要点，一页纸全搞定。可打印、可投屏、可发飞书。

---

## 一、四步总览

| 环节 | 工作 | 工具/模型 | 要点 |
|:---|:---|:---|:---|
| **0. 分析计划重心** | 判断项目敏感类型 | 六维敏感度模型（雷达图） | 敏感点在哪，计划的重点就在哪 |
| **1. 拆解事情** | ① 里程碑 → ② 工作模块 → ③ 优先级 | 两必要两最好 / WBS三原则 / 253思考法 | 核心目标：把方案变成可执行的完整工作清单 |
| **2. 拆分角色** | 为每个工作指定责任人 | RASCI责任矩阵 | 每个模块有且只有一个R |
| **3. 拆分排期** | 梳理依赖关系 + 排时间 | 进度网络图 + 排期三原则 | 识别关键路径，并行压缩工期 |

---

## 二、0️⃣ 分析计划重心：六维敏感度速判

> **原则**：你的项目的敏感点在哪，你的计划的重点就在哪。

| 维度 | 含义 | 高分时重点做什么 |
|:---|:---|:---|
| 预算敏感 | 钱不能超 | 细化预算拆解 + 预留20%缓冲 |
| 时间敏感 | 错过时间点就没了 | 关键路径优化 + 多任务并行 |
| 人力敏感 | 人不能随便加 | 明确分工 + 提前拉齐关键角色 |
| 协作敏感 | 跨部门合作易出问题 | 制定沟通计划 + 可视化进度 |
| 风险敏感 | 第一次做易失败 | 制定风险清单 + 应急预案 |
| 老板敏感 | 老板特别关心 | 清晰里程碑 + 关键节点主动汇报 |

**快速操作**：拿到项目后30秒内，对六个维度直觉打分（1-5），标出最高的2个。

---

## 三、1️⃣ 拆解事情

### 3.1 里程碑检查清单

> 用"完成/提交/评审通过/确认/组建完毕/敲定"造句，每个节点必须有交付成果。

| # | 检查项 | 级别 | 通过标准 |
|:---:|:---|:---:|:---|
| 1 | 是必经之路吗？ | **必要** | 不做这个节点，项目目标完不成 |
| 2 | 有交付成果吗？ | **必要** | 有一个可评审可检查的具体产出（不是"讨论了"） |
| 3 | 可检查验证吗？ | 最好 | 完成与否可以被客观判断 |
| 4 | 前后依赖吗？ | 最好 | 做完前一个才能做后一个 |

**常见错误**：把"动作"当"里程碑"——
- ❌ 拜访供应商 → ✅ 敲定供应商
- ❌ 讨论主题 → ✅ 敲定主题和目标
- ❌ 设计初稿 → ✅ 视觉设计方案评审通过

### 3.2 工作分解（WBS）三原则速查

| 原则 | 判断问题 | 不满足怎么办 |
|:---|:---|:---|
| **独立负责** | 能找到一个人独立承担这个任务吗？ | 能 → 拆到这一层就够 / 不能 → 继续往下拆 |
| **计划可控** | 负责人靠谱吗？任务风险大吗？ | 老手+低风险 → 粗拆 / 新人+高风险 → 细拆 |
| **不重不漏** | 做完这些工作能达成目标吗？有没有重复的？ | 用"先拆后查"交叉验证 |

**先拆后查法**：

```
① 先拆：按时间线（先→后）或按模块（前端/后端/运营）初步拆解
② 后查：
   - 故事线检查：从头到尾讲一遍项目故事，有没有遗漏环节？
   - 角色检查：列出所有参与角色，每个人该做的工作都覆盖了吗？
```

### 3.3 优先级：253思考法

| 层级 | 占比 | 含义 | 处理 |
|:---:|:---:|:---|:---|
| **2** | 20% | 核心必做——决定成败 | 死守，无论如何不能放手 |
| **5** | 50% | 支撑工作——要做的 | 正常推进 |
| **3** | 30% | 弹性调整——可以砍 | 压力大时优先删减/简化 |

**评估维度**：价值 × 成本 × 难度 × 是否在关键路径上 × 老板关心度

## 四、2️⃣ 拆分角色：RASCI速查

| 角色 | 全称 | 一句话 | 数量建议 |
|:---:|:---|:---|:---:|
| **R** | 负责人 | 牵头推进，对结果负责——做砸了锅是你一个人的 | 每个模块**有且只有1个** |
| **A** | 批准者 | 审核决策——关键方案必须经过A签字确认 | 每个模块1个 |
| **S** | 支持者 | 具体执行干活——项目"真正做事的人" | 可按需多个 |
| **C** | 咨询者 | 有信息有判断——帮你补盲区 | 需要时拉入 |
| **I** | 知情者 | 需要同步信息——避免"做完了才说不行" | 尽量覆盖利益相关方 |

**三个常见坑**：
1. 不做分工——项目经理自己冲上去做所有事
2. 缺负责人——多人负责=无人负责
3. 关键成员缺失——做到一半才发现需要法务/运营/老板审批

**RASCI极简模板**（Excel/飞书表格）：

| 工作模块 | R | A | S | C | I |
|:---|:---|:---|:---|:---|:---|
| 内容撰写 | Leo | Truman | 各课老师 | 阿蕊 | 运营团队 |
| 视觉设计 | 张亮亮 | Truman | — | — | 内容团队 |
| ... | | | | | |

## 五、3️⃣ 拆分排期

### 5.1 排期工具选择

| 工具 | 适用级别 | 包含信息 | 何时用 |
|:---|:---:|:---|:---|
| **简单排期** | A/B | 里程碑 + 时间节点 | 项目简单，不需要分工明细 |
| **完整排期表** | B/C | 任务 + 负责人 + 开始/结束时间 + 依赖关系 | 需要清晰的责任追溯 |
| **甘特图** | C/D | 可视化依赖关系 + 时间分布 + 进度条 | 复杂项目，需要看整体时间线 |

### 5.2 排期三原则检查

| # | 原则 | 检查方法 |
|:---:|:---|:---|
| 1 | **能执行** | 每个任务的时间估算合理吗？有没有"每秒审核80条"这种不可能的事？ |
| 2 | **有顺序** | 每个任务的"前置依赖"都标清楚了吗？不能随便挑着做 |
| 3 | **时间最短** | 能并行的都并行了吗？关键路径上的任务还能压缩吗？ |

### 5.3 依赖关系与关键路径速判

```
依赖关系：A→B（串行，B等A） vs A∥B（并行，同时做）

关键路径 = 最长的那条任务链 = 决定总工期
→ 想缩短工期？只优化关键路径上的任务
```

**快速画依赖关系图**：
1. 把所有任务列出来
2. 每个任务问：它前面必须完成什么？
3. 画箭头连接
4. 找出从起点到终点最长的那条线 → 这就是关键路径

## 六、最小可行版（时间紧时用）

如果只有5分钟做计划：

```
1. 敏感度（20秒）：六维中哪2个最高？
2. 里程碑（2分钟）：写3-5个以"完成/敲定/评审通过"结尾的节点
3. RASCI（1分钟）：每个模块只填R和A
4. 排期（1分钟）：只标关键路径上的3个任务时间
5. 缓冲区（40秒）：关键路径上每个任务×1.2
```

---

## 七、完整操作流程

```
Step 0: 分析计划重心
   └→ 六维敏感度打分 → 确定计划的重点管理方向

Step 1: 拆解事情
   ├→ 1.1 拆里程碑：用"两必要两最好"检查
   ├→ 1.2 拆工作模块：用WBS三原则 + 先拆后查
   └→ 1.3 拆优先级：用253思考法标注

Step 2: 拆分角色
   └→ 填RASCI表 → 每个模块有且只有一个R

Step 3: 拆分排期
   ├→ 3.1 选排期工具（简单/完整/甘特图）
   ├→ 3.2 梳理依赖关系（串行/并行）
   ├→ 3.3 画关键路径（最长的那条线）
   └→ 3.4 压缩工期（并行为主，关键路径加缓冲）
```

## 八、失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| 跳过敏感度 | 所有项目用同一套方法，重点管偏了 | 启动前30秒打分 |
| 里程碑写成动作 | "讨论""拜访""测试"——看不出交付了什么 | 用"完成/敲定/确认/评审通过"改写成结果 |
| WBS过度拆分 | 一个西红柿炒蛋拆了12层 | 回到"独立负责"原则——有人能接下就不用再拆 |
| 跳过优先级 | 所有任务都是P0 | 强制标出20%和30% |
| RASCI缺A | 做完没人审，出问题没法补救 | 关键模块必须填A |
| 排期无依赖 | 以为能并行实际互相等 | 画依赖关系图 |
| 排期无缓冲 | 一出意外就全线崩溃 | 关键路径任务×1.2 |
