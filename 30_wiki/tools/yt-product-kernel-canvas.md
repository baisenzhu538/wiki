# 产品内核画布：从问题到解决方案的结构化工具

> 一堂五步法：产品内核画布是把"用户问题→解决方案→验证指标"结构化的工具，帮助团队对齐认知、指导迭代。

## 核心框架

画布结构：

```
┌─────────────────────────────────────────────────────────┐
│                    产品内核画布                          │
├─────────────────────────────────────────────────────────┤
│  用户定义                                                │
│  ┌─────────────────────────────────────────────────┐   │
│  │  目标用户是谁？（第一批100个）                     │   │
│  │  用户的核心问题是什么？（3-5句话）                  │   │
│  │  用户现在怎么解决的？（替代方案）                   │   │
│  └─────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────┤
│  解决方案                                                │
│  ┌─────────────────────────────────────────────────┐   │
│  │  我们的最小解决方案是什么？（一句话）                │   │
│  │  核心功能是什么？（20%关键功能）                     │   │
│  │  比替代方案好在哪里？（10倍法则）                    │   │
│  └─────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────┤
│  验证指标                                                │
│  ┌─────────────────────────────────────────────────┐   │
│  │  关键转化率是什么？（了解→选择）                    │   │
│  │  当前转化率是多少？（基准数据）                      │   │
│  │  目标转化率是多少？（改进目标）                      │   │
│  └─────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────┤
│  一句话价值描述                                           │
│  ┌─────────────────────────────────────────────────┐   │
│  │  对于[目标用户]，我们的产品通过[核心功能]，          │   │
│  │  解决[核心问题]，比[替代方案]好[10倍优势]。          │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

## 关键洞察

### 1. 画布填写的原则

- **用户视角**：每个格子必须从用户视角填写，不是团队视角
- **具体可验证**：每个答案必须具体，能用数据验证
- **团队共识**：画布必须团队一起填，确保共识

### 2. 用户定义的关键

不是"所有人"，而是"第一批100个"：

| 问题 | 正确填写 | 错误填写 |
|:---|:---|:---|
| 目标用户 | "25-35岁上班族，有健身习惯但时间碎片化" | "所有想健身的人" |
| 核心问题 | "去健身房时间成本高，在家运动缺乏专业指导" | "用户想健身" |
| 替代方案 | "健身房、户外跑步、其他家用器械" | "用户现在不健身" |

### 3. 解决方案的最小化

- **一句话描述**：能用一句话说清楚
- **20%功能**：找到决定用户选择的关键功能
- **10倍优势**：比替代方案好10倍（成本、效果、体验）

### 4. 验证指标的设定

- **关键转化率**：从"了解产品"到"选择产品"的转化率
- **基准数据**：当前转化率是多少？
- **目标数据**：改进后的目标转化率是多少？

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **画布填写太泛** | 每个格子都很大，无法指导行动 | 强制具体化，每个答案不超过3句话 |
| **团队视角偏差** | 从团队视角填写，不是用户视角 | 用用户原话填写，不加加工 |
| **验证指标缺失** | 画布填完了，但没有验证指标 | 必须填写关键转化率和目标 |
| **画布填完不用** | 填完就放一边，不指导迭代 | 每次迭代前回顾画布，基于画布决策 |
| **一句话描述太长** | 价值描述超过50字 | 强制20字以内，能向客户口述 |
| **忽视替代方案** | 画布中替代方案填写模糊 | 列出至少3种具体替代方案 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新产品定义 | 成熟产品优化（已有数据） |
| 团队对齐 | 个人独立决策 |
| 产品迭代规划 | 技术架构设计 |
| 向客户介绍产品 | 品牌传播 |

## 行动触发器

- 当定义新产品时 → 先填画布，再设计功能
- 当团队对齐时 → 一起填画布，对比差异
- 当迭代产品时 → 回顾画布，基于验证指标决策
- 当向客户介绍时 → 用画布的一句话价值描述
