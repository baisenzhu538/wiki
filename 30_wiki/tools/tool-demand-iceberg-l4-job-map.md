# L4任务地图

> 任务地图≠用户旅程。用户旅程关注"用户和产品的触点"，任务地图关注"用户要完成任务的完整过程——包括用土办法的阶段"。目标是找到那个让用户产生"崩溃感"的切入机会。

## 8步推演表

| # | 步骤 | 用户做什么 | 现有替代方案/土办法 | 摩擦点/情绪 |
|:---:|:---|:---|:---|:---|
| 1 | **定义** | 明确自己要完成什么 | | |
| 2 | **定位** | 找到需要的信息/工具/人 | | |
| 3 | **准备** | 收集所需资源和条件 | | |
| 4 | **执行** | 实际动手完成核心动作 | | |
| 5 | **监控** | 检查执行过程是否在轨道上 | | |
| 6 | **调整** | 偏离时修正 | | |
| 7 | **结束** | 确认任务完成 | | |
| 8 | **总结** | 反思经验、记录备忘 | | |

## 三个分析深度

| 深度 | 内容 |
|:---|:---|
| **基础** | 推理场景过程——极简一条线 |
| **更宽** | 完整8步任务地图——前中后全景 |
| **更深** | 每步：动作+痛点+机会点（三句话） |

## Agent执行指令

```python
# 引自 AI场景推演教练 Step 3
prompt = """基于核心任务「{CORE_JOB}」，用表格推演8个关键步骤：

| # | 步骤 | 用户具体做什么 | 现有土办法 | 摩擦点/情绪 |
每步填写后，明确指出1-3个"关键崩溃环节"——用户在哪一步最痛苦、最想放弃？
"""
```

## 失败模式

| 失败 | 症状 | 修复 |
|:---|:---|:---|
| 写成用户旅程 | 每步都是"用户打开App→点击X" | 去掉产品触点，只关注用户要完成什么 |
| 土办法列不出来 | 不知道用户现在怎么解决 | 这是信号——你还没做用户调研 |

## 适用边界

- **适用**：L3确认后的自然下一步；需要找到具体切入点的场景
- **不适用**：核心任务非常简单的场景

## 策略清单（8条）

| # | 策略 | 核心 | 来源 |
|:--|:---|:---|:---|
| 1 | 基础深度 | 推理场景过程——极简一条线串起8步 | OCR |
| 2 | 更宽深度 | 完整8步×4列（做什么/土办法/摩擦点/机会信号） | OCR |
| 3 | 更深深度 | 每步三句话：动作+痛点+机会点 | OCR |
| 4 | ODI机会评分 | 重要性×满意度四象限——定量验证哪步最值得切入 | Ulwick ODI |
| 5 | 崩溃感识别 | 不是"用户觉得不方便"——是"用户在这一步想砸手机" | — |
| 6 | 土办法深挖 | 用户的土办法里藏着最好的产品设计线索——不只列出来，要分析"为什么用这个" | Christensen |
| 7 | CES度量 | 客户费力指数：在哪一步最费劲？ | — |
| 8 | 步数弹性 | 简单任务5步，复杂任务12步——不要机械套用8步模板 | — |（如"点个外卖"的深度有限）

## 全网调研补强（2026 最佳实践）🆕

| # | 策略 | 来源 | 操作 |
|:--|:--|:--|:--|
| 1 | **ODI 机会评分** | Ulwick ODI 方法论 | 每个步骤打分：重要性(1-5) × (1-满意度(1-5)的差值)。高分 = 高重要性低满意度 = 切入机会 |
| 2 | **CES 度量** | thrv 2025 | 每步计算 Customer Effort Score——高努力步骤 = 用户最想放弃的地方 |
| 3 | **崩溃感识别** | JTBD 社区 | 不是"用户觉得不方便"，是"用户在这一步想骂人/想放弃/想找替代方案"——找到情绪峰值 |
| 4 | **土办法深挖** | Christensen | 用户的土办法往往比你的产品更有创造力——分析土办法的"为什么"比分析产品功能更有价值 |
| 5 | **步数弹性** | thrv 2025 | 简单任务 5-8 步，复杂任务可到 20+ 步——不要强制套 8 步模板 |
| 6 | **跨案例比对** | 2026 新兴 | 同一核心任务找 3-5 个不同用户的执行方式——对比差异发现"最佳实践"和"最痛点" |
