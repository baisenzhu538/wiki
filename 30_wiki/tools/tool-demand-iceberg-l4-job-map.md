# L4任务地图

> 任务地图≠用户旅程。用户旅程关注"用户和产品的触点"，任务地图关注"用户要完成任务的完整过程——包括用土办法的阶段"。目标是找到那个让用户产生"崩溃感"的切入机会。

## 8步推演表

| # | 步骤 | 用户做什么 | 现有替代方案/土办法 | 摩擦点/情绪 |
|:---:|:---|:---|:---|:---|
| 1 | **定义** | 明确自己要完成什么 | | |
| 2 | **定位** | 找到需要的信息/工具/人 | | |
| 3 | **准备** | 收集所需资源和条件 | | |
| 4 | **执行** | 实际动手完成核心动作 | | |
| 5 | **监控** | 检查执行过程是否在轨道上 | | |
| 6 | **调整** | 偏离时修正 | | |
| 7 | **结束** | 确认任务完成 | | |
| 8 | **总结** | 反思经验、记录备忘 | | |

## 三个分析深度

| 深度 | 内容 |
|:---|:---|
| **基础** | 推理场景过程——极简一条线 |
| **更宽** | 完整8步任务地图——前中后全景 |
| **更深** | 每步：动作+痛点+机会点（三句话） |


## 失败模式

| 失败 | 症状 | 修复 |
|:---|:---|:---|
| 写成用户旅程 | 每步都是"用户打开App→点击X" | 去掉产品触点，只关注用户要完成什么 |
| 土办法列不出来 | 不知道用户现在怎么解决 | 这是信号——你还没做用户调研 |

## 全网调研补强（2026 最佳实践）🆕

| # | 策略 | 来源 | 操作 |
|:--|:--|:--|:--|
| 1 | **ODI 机会评分** | Ulwick ODI 方法论 | 每个步骤打分：重要性(1-5) × (1-满意度(1-5)的差值)。高分 = 高重要性低满意度 = 切入机会 |
| 2 | **CES 度量** | thrv 2025 | 每步计算 Customer Effort Score——高努力步骤 = 用户最想放弃的地方 |
| 3 | **崩溃感识别** | JTBD 社区 | 不是"用户觉得不方便"，是"用户在这一步想骂人/想放弃/想找替代方案"——找到情绪峰值 |
| 4 | **土办法深挖** | Christensen | 用户的土办法往往比你的产品更有创造力——分析土办法的"为什么"比分析产品功能更有价值 |
| 5 | **步数弹性** | thrv 2025 | 简单任务 5-8 步，复杂任务可到 20+ 步——不要强制套 8 步模板 |
| 6 | **跨案例比对** | 2026 新兴 | 同一核心任务找 3-5 个不同用户的执行方式——对比差异发现"最佳实践"和"最痛点" |

## 质疑

- **具体假设**：该工具假设"8 步推演能完整覆盖用户完成任务的全流程"，但"8 步"是一个任意数字——有些任务（如冲动消费）只有 2 步，有些（如企业级 SaaS 采购）可能有 20 步。强制 8 步可能导致"为了凑数而拆分"或"为了精简而合并"。
- **边界**：在非线性的任务流程中（如创意工作、探索性研究），用户不会按"步骤 1→步骤 2→..."的线性路径执行——他们会在步骤之间跳跃、回退、并行。8 步地图无法表达这种非线性结构。
- **前提**：该工具的前提是"摩擦点出现在步骤中"，但有些摩擦点不在任何步骤中——它们是"步骤之间的过渡"（如从"搜索"到"比价"的切换成本），这些过渡摩擦在 8 步地图中会被遗漏。

**Herbert Simon**（诺贝尔经济学奖得主，有限理性理论创始人）会质疑：8 步地图假设用户是"按步骤执行的理性决策者"，但他的有限理性理论表明，用户在真实环境中的行为是"满意即可"（satisficing）而非"最优选择"——他们不会走完所有 8 步，而是在第 3 步就因为"够了"而停下来。摩擦点不是"步骤中的障碍"，而是"用户决定停止继续"的时刻——这种"停止决策"无法在 8 步地图中被定位。
