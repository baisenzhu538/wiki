# 技能：结构化AI工作空间搭建

## 用一句话讲清楚

在让 AI 动手之前，先把工作空间拆成 **系统自述、领域知识、Agent 服务、任务管理、日志** 五类知识分开放置，让 AI 在清晰的结构中执行，而不是在混乱的目录里“重新投胎”。

> **Burn line**: AI 只会模仿，不会设计结构；人先把五类知识分开，结构才能自己长出来。

---

## 核心要点

1. **先搭空间，再写提示词。** 任务一多，目录就会乱；目录一乱，AI 的理解、流程、输出都会退化。
2. **五类知识必须分开。** 系统自述（L1）、领域知识（L2）、Agent 服务（L3）、任务管理（L4）、日志（L5）增长速度和管理方式不同，混在一起一定乱。
3. **AI 不会创造结构。** 它只能从预训练里找相似结构匹配；结构设计是人的责任。
4. **最小化启动，不要追求完美。** 新手起步只要做到“五类分开”，先定义 Agent 的工作手册、工具箱、经验库即可。
5. **交付物要独立。** 不要把任务产出堆到系统文档或领域知识里，否则结构很快再次崩溃。
6. **一次对话围绕一个任务。** 任务上下文独立管理，避免多任务串扰。
7. **渐进式披露。** 复杂任务按 **导诊台 → 工作手册 → 经验库 → 领域知识** 逐层深入，避免一次性塞给 AI 全部信息。

---

## Protocol/Procedure

### Step 1：初始化五层目录

在项目根目录下建立五个独立区域：

| 层级 | 目录示例 | 放什么 |
|------|---------|--------|
| **L1 系统自述** | `01-system/` | 项目架构、组件、技术栈、目录说明 |
| **L2 领域知识** | `02-domain/` | 业务术语、业务逻辑、运营规则、行业常识 |
| **L3 Agent 服务** | `03-agent/` | 导诊台、工作手册/SOP、工具集、经验与模式库 |
| **L4 任务管理** | `04-tasks/` | 任务定义、状态、输入材料、预期输出、验收标准、上下文 |
| **L5 日志** | `05-logs/` | 执行记录、排查信息、错误复盘 |

### Step 2：先写最简三件套

1. **系统自述（1 页）**：这个项目是什么、核心模块有哪些、技术栈是什么。
2. **工作手册（1 份）**：你最常让 AI 做的一类任务的标准步骤和输出格式。
3. **任务跟踪表（1 张）**：任务名称 / 状态 / 输入 / 输出 / 验收标准 / 问题记录。

### Step 3：新任务进场流程

1. 在 `04-tasks/` 下新建任务卡片，填写名称、状态、输入、预期输出、验收标准。
2. 从 `01-system/` 和 `02-domain/` 拷贝相关背景到当前对话上下文。
3. 如果是常见任务，让 AI 按 `03-agent/` 里的工作手册执行。
4. 任务结束后更新状态，记录遇到的问题，有价值的经验沉淀到 `03-agent/经验库/`。

### Step 4：定期维护

- 系统自述和领域知识增长慢，人工定期更新即可。
- Agent 服务前期增长快，任务稳定后趋于稳定。
- 任务管理和日志增长最快，需要独立管理、定期归档/清理。

## 边界

| 边界 | 说明 |
|------|------|
| **适用场景** | AI 任务多、需要反复协作、团队需要统一上下文的复杂项目 |
| **不适用场景** | 单一一次性简单任务 → 直接给完整上下文即可 |
| **不适用场景** | 快速原型验证、时间极紧 → 分层管理 overhead 过高 |
| **不适用场景** | 团队对 AI 协作结构无共识 → 先对齐认知再分层 |
| **最小启动** | 只需 3 个文件：系统自述、工作手册、任务跟踪表 |
| **结构原则** | 五类知识逻辑分层，不必严格物理隔离；聊和问可以并行，查和测可以重叠 |
| **人的职责** | 定义结构、维护 L1/L2、把控审美；AI 负责在结构内执行 |

## 失败模式

| 失败模式 | 典型症状 | 根因 | 修复/预防 |
|---|---|---|---|
| **重新投胎陷阱** | 目录乱了直接放弃重建，新目录很快又乱 | 只换目录名，没改变结构设计方法 | 先按 L1-L5 分类，再迁移内容 |
| **五类知识混放** | 项目文档、任务上下文、约束文档在一个文件夹 | 缺少分层意识 | 强制每类知识有独立存放位置 |
| **让 AI 自己设计结构** | AI 分析得头头是道，但越修越乱 | AI 只会模仿，不会创造结构 | 人先定义框架，AI 在框架内执行 |
| **一次性塞满上下文** | AI 输出质量下降、遗漏关键点 | 违反渐进式披露原则 | 按导诊台→工作手册→经验库→领域知识逐层加载 |
| **交付物混入系统文档** | 任务产出散落在系统自述或领域知识中 | 交付物未独立管理 | 所有任务产出放在 `04-tasks/` 下 |
| **没有工作手册** | 同类任务每次都要重新解释流程 | SOP 未沉淀 | 把重复任务写成工作手册，放在 `03-agent/` |
| **L4 管理失控** | 任务状态不清、上下文丢失 | 缺少状态管理和版本控制 | 任务跟踪表必填：状态、输入、输出、验收标准、问题 |
| **日志不清理** | 日志堆积，排查时找不到关键信息 | L5 增长最快却未归档 | 自动化收集 + 定期清理，保留关键日志归档 |

## 行动 Checklist

### 开始搭建前
- [ ] 已明确让 AI 做什么事情、会产出什么交付物
- [ ] 已判断任务是否复杂到需要分层管理（≥3 个重复任务或 ≥1 个多步骤任务建议分层）
- [ ] 已选择至少一个文档工具（Obsidian / Notion / 飞书文档等）

### 初始化工作空间
- [ ] 已建立 L1-L5 五个独立目录/区域
- [ ] 已写 1 页系统自述（项目是什么、模块、技术栈、目录说明）
- [ ] 已写 1 份工作手册（最常见任务的 SOP + 输出格式）
- [ ] 已建 1 张任务跟踪表（名称 / 状态 / 输入 / 输出 / 验收标准 / 问题）

### 任务执行流程
- [ ] 新任务来了先在 `04-tasks/` 建立任务卡片
- [ ] 已将相关背景从 `01-system/` 和 `02-domain/` 加载到当前对话
- [ ] 常见任务已按 `03-agent/` 工作手册执行
- [ ] 任务结束后更新了状态、记录了问题
- [ ] 有价值的经验已沉淀到 `03-agent/经验库/`

### 维护与迭代
- [ ] 每周/每迭代检查一次目录是否仍然五类分明
- [ ] 定期归档或清理 `05-logs/`
- [ ] 任务稳定后将重复流程沉淀为新的工作手册
- [ ] 团队关键人对齐了工作空间结构

## Claims

- **C1 [conf=0.9]**: 让 AI 执行任务前，应先搭建结构化工作空间，否则任务增多后易出现理解偏差、流程变异、原地打转。——依据：`src_20260606_42e11f09#468-518`。
- **C2 [conf=0.85]**: 工作空间至少应包含五类知识：系统自述、领域知识、Agent 服务、任务管理、日志。——依据：`src_20260606_42e11f09#526-538`。
- **C3 [conf=0.85]**: AI 不会创造结构，只会从预训练中匹配相似结构；因此结构设计必须由人主导。——依据：`src_20260606_42e11f09#512-518`。
- **C4 [conf=0.8]**: 五类知识增长速度不同，应分层管理：系统自述和领域知识增长慢，任务管理迅速变更，日志增长最快。——依据：`src_20260606_42e11f09#746-756`。
- **C5 [conf=0.8]**: 复杂任务应按“导诊台 → 工作手册 → 经验库 → 领域知识”渐进式披露，避免一次性给 AI 全部信息。——依据：`src_20260606_42e11f09#794-804`。
