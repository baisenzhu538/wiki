# KDO Agent 生产 SOP 清单：从业务任务到可运行 Agent 的五步法

> 一句话：老顽童接到任务单后，按此清单逐项勾稽——五步、每步 3+ 检查项，跳一步就是埋一颗雷。本卡来自半肥猫 18 个数字员工的实战验证。

> 注：本卡是 Agent 生产操作 SOP。Agent 设计规范见 `agent-native-card-design`，运行时加载见 `system-yitang-Y-model-os`。与建模四步法互补——建模四步法是方法论建模工具，本卡是 Agent 生产工序清单。

---

## Step 1：找业务任务

| # | 检查项 | 合格标准 | 跳过会怎样 |
|:---:|:---|:---|:---|
| 1.1 | 这个 Agent 要解决的业务任务是什么？ | 一句话能说清楚，不是"提升效率"这种空话 | 做出来的 Agent 没人用——因为不知道用它干什么 |
| 1.2 | 这个任务现在是谁在做？耗时多少？ | 有具体的人和耗时数字 | 没法衡量 Agent 是否省了时间 |
| 1.3 | 这个任务属于哪个已有域/子域？ | 挂到已有域下，不建新域 | 孤岛 Agent 找不到入口 |

---

## Step 2：定输入输出协议

| # | 检查项 | 合格标准 | 跳过会怎样 |
|:---:|:---|:---|:---|
| 2.1 | Agent 的输入是什么？格式？ | 有明确的输入字段和类型 | Agent 不知道用户要给它什么 |
| 2.2 | Agent 的输出是什么？格式？ | 有明确的输出字段和类型 | 用户不知道 Agent 能产出什么 |
| 2.3 | 输入→输出的处理逻辑能说清楚吗？ | 用 3-5 步能描述完整链路 | 内部逻辑黑箱，出错无法 debug |

---

## Step 3：封装 Skill（Prompt + 正反例 + 流程 + 验收标准）

| # | 检查项 | 合格标准 | 跳过会怎样 |
|:---:|:---|:---|:---|
| 3.1 | System Prompt 包含了角色、任务、边界、输出格式吗？ | 四个要素齐全 | Agent 行为不稳定 |
| 3.2 | 有 ≥ 3 个正面示例（好的输入→好的输出）吗？ | 每个示例含输入+输出+为什么好 | Agent 不知道"好的标准" |
| 3.3 | 有 ≥ 2 个反面示例（典型错误→应如何纠正）吗？ | 每个反例含错误输入+错误输出+正确做法 | Agent 不知道"什么不能做" |
| 3.4 | 有承诺核对表吗？ | 四列：对外承诺/对应交付/用户动作/验收标准 | 用户不知道 Agent 能承诺什么、不能承诺什么。见 `dk-agent-promise-verification` |

---

## Step 4：接入环境（MCP/TCPR）

| # | 检查项 | 合格标准 | 跳过会怎样 |
|:---:|:---|:---|:---|
| 4.1 | Agent 需要什么工具？每个工具调用安全吗？ | 列出工具清单，标注是否需要人工确认 | 危险操作可能被自动执行 |
| 4.2 | Agent 的 TCPR 角色标注了吗？ | T/C/P/R 至少选一个，在 System Prompt 中声明 | Agent 不知道自己该扮演什么角色 |
| 4.3 | 有没有测试过工具调用通路？ | 至少 1 次端到端调用测试成功 | 生产环境第一个用户就报错 |

---

## Step 5：加控制机制

| # | 检查项 | 合格标准 | 跳过会怎样 |
|:---:|:---|:---|:---|
| 5.1 | 有没有人工审核节点？ | 标注哪些输出需要人工确认才能执行 | AI 自主执行了不该做的事 |
| 5.2 | 有没有日志记录？ | 每次调用记录输入/输出/耗时/异常 | 出问题了无法追溯 |
| 5.3 | 有没有测试回归用例？ | ≥ 2 个测试用例，覆盖正常+异常路径 | 改了 prompt 后不知道是否退化 |

---

## 使用方式

```
接到任务单 →
1. 打开本卡
2. 从 Step 1 到 Step 5 逐项勾稽
3. 不通过的检查项 → 修复 → 再勾稽
4. 全部通过 → 提交欧阳锋终审
5. 终审通过 → 投产
```

---

## 失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| 跳 Step 2 直奔 Step 3 | 写了一个很长的 System Prompt 但输入输出没定义清楚 | 先定协议再写 Prompt |
| Step 3.4 承诺核对表缺失 | Agent 上线后用户发现它做不到某些事 | 上线前先列"不能承诺什么" |
| Step 5 控制机制跳过 | 初版直接上线没有审核 | 至少加一个人工审核节点 |
