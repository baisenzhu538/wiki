# 业务单元业务设计模板

> 为公司各业态/业务单元快速梳理业务设计的轻量模板，从客户场景到价值主张、产品服务、盈利模式，再到底层核心能力和业务策略。

---

## 一、模板结构

```
        ┌─────────────────────────────┐
        │  XXX业务单元 业务设计        │
        └─────────────────────────────┘
                    │
    ┌───────────────┼───────────────┐
    ▼               ▼               ▼
┌────────┐    ┌──────────┐    ┌──────────┐
│目标客户 │ →  │ 价值主张* │ →  │ 产品和服务│
│/使用场景│    │          │    │          │
└────────┘    └──────────┘    └──────────┘
                                    │
                              ┌──────────┐
                              │ 盈利模式  │
                              └──────────┘
                                    │
                    ┌───────────────┴───────────────┐
                    ▼                               ▼
              ┌──────────┐                  ┌──────────┐
              │ 核心能力  │                  │ 业务策略  │
              └──────────┘                  └──────────┘
```

> *价值主张用红色星号标注，表示业务设计的中心锚点。

---

## 二、填写清单

| 模块 | 必填内容 |
|--|--|
| **目标客户/使用场景** | 核心客群、核心场景、次要客群、次要场景 |
| **价值主张** | 客户为什么选择我们而不是对手？差异化竞争优势是什么？ |
| **产品和服务** | 具体提供什么产品/服务？解决什么痛点？ |
| **盈利模式** | 收入来源、成本结构、关键盈利点 |
| **核心能力** | 支撑以上业务设计必须具备的能力 |
| **业务策略** | 关键举措、资源配置、阶段里程碑 |

---

## 三、与业务设计六要素的映射

| 本模板模块 | 对应六要素 |
|--|--|
| 目标客户/使用场景 | 客户选择 |
| 价值主张 | 价值主张 |
| 盈利模式 | 价值获取 |
| 产品和服务 + 核心能力 + 业务策略 | 活动范围 + 战略控制 |
| 业务策略中的风险应对 | 风险管理 |

---

## 四、使用步骤

1. **定义业务单元边界**：是产品线、区域、渠道还是子公司？
2. **填写上四层**：客户 → 价值主张 → 产品服务 → 盈利模式。
3. **校验一致性**：价值主张是否能被目标客户感知？盈利模式是否能被产品和服务支撑？
4. **填写下两层**：核心能力是否能支撑价值主张？业务策略是否能补齐能力缺口？
5. **跨业务单元对比**：检查不同业务单元之间是否存在资源冲突或协同机会。

---

## 五、失败模式

| 失败 | 症状 | 修复 |
|--|--|--|
| 价值主张空洞 | "高品质""好服务"，无法被验证 | 用具体场景和客户行为定义价值主张 |
| 客户与价值主张错配 | 价值主张不是目标客户最关心的 | 先做客户选择，再推导价值主张 |
| 盈利模式单一 | 只写"卖产品赚钱" | 列出收入来源、定价机制、成本结构 |
| 核心能力泛泛 | "我们有团队" | 列出具体能力、资源、数据或专利 |

## 六、Agent 执行指令

```python
def business_unit_design(business_unit: str):
    """为业务单元生成业务设计概要"""
    prompts = {
        "目标客户": f"定义{business_unit}的核心客群、核心场景、次要客群、次要场景。",
        "价值主张": "提炼差异化价值主张：客户为什么选我们？",
        "产品服务": "列出支撑价值主张的核心产品和服务。",
        "盈利模式": "说明收入来源、定价逻辑和成本结构。",
        "核心能力": "列出必须具备的核心能力和资源。",
        "业务策略": "给出关键举措、资源配置和阶段里程碑。"
    }
    return {step: ask(prompt) for step, prompt in prompts.items()}
```

## 质疑

> 待补充：这个工具的内在局限是什么？外部反对者会怎么批评？

**Alexander Osterwalder** 可能会质疑：这个工具依赖的 **商业模式假设、客户验证、价值主张一致性、盈利逻辑** 是否已经被充分验证？

- 模板若未经过真实客户验证，容易把假设当成事实。
- 七要素之间的内部一致性比单点设计更重要，但模板难以暴露冲突。

- 使用前应明确本工具的 **具体假设**、适用 **边界**、潜在 **反例** 和隐含 **前提**，避免把模板输出直接当成战略结论。
