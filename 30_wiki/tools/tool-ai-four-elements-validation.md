# 技能：真需求四要素验证法

> **来源**：纪浩（AI俱乐部-AI协作方法论-口述）
> **核心**：一个真正的problem需要同时满足四个条件——前后对比、真实锚点、受益对象、可解性。缺一不可。

---

## 原始表述
> "一个真正的problem需要同时满足：前后对比、真实锚点、受益对象、可解性。"
> —— 纪浩

> **暗知识**："四要素中'可解性'是最容易被过度估计的。很多人认为自己的问题'可解'，但实际上缺少'因果链'或'能力支撑'。"

---

## 操作步骤

### 四要素检查清单（强制逐条回答）

| # | 要素 | 检查问题 | 回答格式 |
|:--:|:----|:---------|:---------|
| 1 | **Before/After** | 解决前是什么状态？解决后希望是什么状态？ | "解决前：_____；解决后：_____" |
| 2 | **真实锚点** | 在真实世界中有没有具体场景？ | "场景：_____，时间：_____" |
| 3 | **受益对象** | 谁受益？ | "受益人：_____，受益方式：_____" |
| 4 | **可解性** | 相信可解吗？有因果链和能力支撑吗？ | "因果链：_____；能力支撑：_____" |

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 准备用AI解决一个需求时，验证需求是否真实 |
| ✅ 适合 | 产品需求评审时，判断PRD里的需求是否是真需求 |
| ✅ 适合 | 创业/做项目前，验证idea是否值得投入 |
| ✅ 适合 | 给AI派任务前，确保任务边界清晰、目标可衡量 |
| ❌ 不适合 | 纯粹探索性学习 → 不需要验证，探索本身就是目的 |
| ❌ 不适合 | 已知有效的标准化任务 → 如"帮我整理会议纪要" |
| ❌ 不适合 | 创意发散阶段 → 过早验证会扼杀创意，先发散再验证 |
| ❌ 不适合 | 紧急救火场景 → 先灭火，事后复盘时再验证 |

#| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **可解性高估** | 缺少因果链或能力支撑 | 强制写出从X到Y的具体步骤。不能写'应该可以'，必须有具体因果链 |
| **锚点虚化** | 用'类似情况'替代'具体情况' | 要求某月某日、某地点、某事件。真实锚点必须具体 |
| **受益虚化** | 受益对象写'公司'或'团队'，不具体 | 要求'谁在什么时间获得什么具体好处'。受益对象必须明确 |
| **资源盲区** | 四要素全通过了但项目失败，忽略了时间成本和资源约束 | 追加资源约束检查。四要素通过不代表资源足够 |
| **验证瘫痪** | 过度验证导致paralysis，验证完不敢做了 | 设定验证时间上限（15分钟）。四要素是快速筛选工具 |
| **循环盲区** | 有方法但没有数据，直接让AI上手 | 四要素是循环而非简单清单。没数据时先做人工积累，再让AI接手 |
| **确认偏误** | 倾向于相信自己的想法是对的，验证流于形式 | 让第三方或AI反向挑战每个要素，寻找证伪证据 |
| **要素遗漏** | 只验证部分要素，跳过最难的 | 强制逐条回答，缺一不可。跳过任何一个要素都是伪需求 |

## 为什么有效

人的大脑有"确认偏误"——倾向于相信自己的想法是对的。四要素验证法强制你从四个独立维度审视同一个需求，打破"我觉得这是个好需求"的直觉陷阱。

**暗知识**：四要素是一个**循环**而非简单检查清单。如果"有方法"但"没有数据"，需要先用人工积累数据——这意味着AI落地往往需要"先做一段时间的人工工作"。
