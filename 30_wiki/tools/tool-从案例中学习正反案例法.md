# 技能：从案例中学习（正反案例法）

## 原始表述
> L1.从案例中学 √失败案例：学习踩坑教训 √最佳实践：培养顶级见识 真实案例 具体事实 搞砸案例 曼佳实践落地案例

## 操作步骤
1. 收集失败案例，分析踩坑教训
2. 收集最佳实践案例，培养顶级见识
3. 关注真实案例和具体事实
4. 整理搞砸案例和成功落地案例

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 学习新领域时快速建立认知，避免从零开始 |
| ✅ 适合 | 需要避免重复犯错，从他人失败中学习 |
| ✅ 适合 | 需要理解实际操作细节，抽象规则不够时 |
| ✅ 适合 | 团队培训，用真实案例降低认知门槛 |
| ❌ 不适合 | 纯理论抽象概念学习 → 案例可能引入无关噪声 |
| ❌ 不适合 | 案例来源不可信 → 学习错误经验 |
| ❌ 不适合 | 场景差异过大 → 直接照搬导致失败 |
| ❌ 不适合 | 没有拆解能力 → 只记住故事没学到原则 |

## 常见失败模式

| 失败模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **只收正面案例，回避失败案例** | 收藏夹里全是"字节/阿里怎么做成了"，找不到"同样打法怎么死的" | 每个主题强制配对 1 正 1 反；找不到反面案例时，先假设"这个方法什么情况下会失效"，再去搜索 |
| **把案例当鸡汤，不拆因果链** | 看完只记得"他们很拼/运气好"，说不出"因为 X，所以 Y" | 用"如果…那么…"格式重述案例；必须写出 3 条可迁移的因果原则 |
| **忽视背景标签，直接照搬** | 把大厂成熟期做法套用到自己 0-1 阶段 | 每个案例必须标注公司阶段/行业/团队规模/时间窗口；迁移前回答"我的场景和这个案例有哪 3 点不同" |
| **贪多不拆解，案例成集邮** | 一周收藏 20 个案例，一个都没写成行动清单 | 每周最多新增 5 个案例，但必须拆解 1 个；拆解标准：能讲给别人听并让对方说出"我懂了什么时候该用/不该用" |
| **用案例当论据，只看想看的** | 先有结论，再挑支持自己的案例 | 先看反面案例并记录"哪些证据会让我放弃原观点"；再找正面案例验证 |
| **学了不对照自身场景** | 案例是别人的故事，看完后行为和之前一样 | 每次拆解完必须回答"我本周要做的 1 个具体行动是什么"以及"如果我在那个场景会踩哪个坑" |
| **迷信"最佳实践"，忽视可执行成本** | 把案例里的豪华配置当成最低标准 | 把最佳实践降级为"最低可行版本"，列出资源/时间/能力 3 个约束条件下的阉割版方案 |
| **案例来源单一或过时** | 反复引用同一本书/同一公众号的案例，或 5 年前的打法 | 每个结论至少来自 2 个独立来源；标注案例时间戳，超过 3 年需重新验证市场环境 |

## 判断标准

**什么算一次有效的案例学习**：

| 标准 | 好的案例学习 | 坏的案例学习 |
|:---|:---|:---|
| 正反成对 | 同时研究一个成功和一个失败案例，对比出关键差异 | 只看成功案例——只知道"怎么做"，不知道"什么不能做" |
| 有拆解 | 从案例中提取了可迁移的因果原则："因为 X，所以在 Y 场景下应该避免 Z" | 只记住了故事本身——"阿里当年也遇到过这个问题"但说不清楚解决逻辑 |
| 有上下文标注 | 标注了案例发生的公司规模、阶段、行业、团队特征 | "阿里最佳实践"直接照搬——不看资源、阶段、团队差异 |
| 有自我对照 | 思考了"如果我在类似场景，我能做什么？有什么不同的？" | 案例是"别人的故事"——看完没有联系到自己的实际情况 |

**自检问题**：
1. 这个案例我能讲成"如果 X 发生，则 Y 结果"的因果逻辑吗？如果不确定，说明没有拆解透。
2. 如果让我在相似的场景做决策，这个案例能帮我做出更好的选择吗？
3. 最近一周，有没有因为某案例而改变了某个行为？——案例学习的价值在行动，不在收藏。

## 质疑

- **具体假设**：该工具假设结构化方法论能提升效果，但方法论的有效性取决于执行者的判断力和场景适配——没有判断力的执行只是'走流程'，不等于'做好事'。
- **边界**：在全新领域或快速变化的环境中，已有数据和经验可能完全失效——工具的有效性高度依赖场景的稳定性。
- **前提**：该工具的前提是使用者能正确理解和执行工具的规则，但执行者的认知偏差和经验限制会影响工具的实际效果。

**Peter Drucker**（管理学大师）会质疑：工具的价值不在于"有没有"，而在于"用得好不好"。任何工具都是"能力放大器"——如果使用者的判断力不足，工具只会放大错误。真正的风险不是"缺少工具"，而是"有了工具后产生的虚假安全感"——让你以为自己已经覆盖了所有可能性，实际上只是走完了流程。
