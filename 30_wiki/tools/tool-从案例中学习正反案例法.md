# 技能：从案例中学习（正反案例法）

## 原始表述
> L1.从案例中学 √失败案例：学习踩坑教训 √最佳实践：培养顶级见识 真实案例 具体事实 搞砸案例 曼佳实践落地案例

## 操作步骤
1. 收集失败案例，分析踩坑教训
2. 收集最佳实践案例，培养顶级见识
3. 关注真实案例和具体事实
4. 整理搞砸案例和成功落地案例

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 学习新领域时快速建立认知，避免从零开始 |
| ✅ 适合 | 需要避免重复犯错，从他人失败中学习 |
| ✅ 适合 | 需要理解实际操作细节，抽象规则不够时 |
| ✅ 适合 | 团队培训，用真实案例降低认知门槛 |
| ❌ 不适合 | 纯理论抽象概念学习 → 案例可能引入无关噪声 |
| ❌ 不适合 | 案例来源不可信 → 学习错误经验 |
| ❌ 不适合 | 场景差异过大 → 直接照搬导致失败 |
| ❌ 不适合 | 没有拆解能力 → 只记住故事没学到原则 |

#| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **案例偏食** | 只收集正面案例，不看失败案例 | 失败案例比成功案例更稀缺，只看成功案例导致对风险边界缺乏感知 |
| **场景错配** | 把阿里最佳实践直接搬到自己的创业公司 | 必须标注案例发生的公司规模、阶段、行业、团队特征，不能直接照搬 |
| **案例收集癖** | 搜集了100个案例但从不拆解 | 案例的价值在拆解后的可迁移原则，不在数量。每周至少拆解1个案例 |
| **确认偏误** | 拿案例当论据而非学习材料，看完只强化原有偏见 | 先看反面案例挑战自己的假设，再找正面案例验证，避免只拿案例佐证已有观点 |
| **自我对照缺失** | 案例是别人的故事，看完没有联系到自己的实际情况 | 每次看完案例必须思考'如果我在类似场景，我能做什么？有什么不同？' |
| **幸存者偏差** | 只研究成功案例，忽略了同样做法但失败的沉默案例 | 主动寻找"做了同样的事但失败了"的案例，平衡幸存者偏差 |
| **案例过时** | 引用5年前的案例指导当前决策，市场环境已变化 | 标注案例时间戳，超过3年的案例需重新验证适用性 |
| **拆解深度不足** | 只记住"阿里当年也遇到过这个问题"但说不清楚解决逻辑 | 必须提取可迁移的因果原则："因为X，所以在Y场景下应该避免Z" |

## 判断标准

**什么算一次有效的案例学习**：

| 标准 | 好的案例学习 | 坏的案例学习 |
|:---|:---|:---|
| 正反成对 | 同时研究一个成功和一个失败案例，对比出关键差异 | 只看成功案例——只知道"怎么做"，不知道"什么不能做" |
| 有拆解 | 从案例中提取了可迁移的因果原则："因为 X，所以在 Y 场景下应该避免 Z" | 只记住了故事本身——"阿里当年也遇到过这个问题"但说不清楚解决逻辑 |
| 有上下文标注 | 标注了案例发生的公司规模、阶段、行业、团队特征 | "阿里最佳实践"直接照搬——不看资源、阶段、团队差异 |
| 有自我对照 | 思考了"如果我在类似场景，我能做什么？有什么不同的？" | 案例是"别人的故事"——看完没有联系到自己的实际情况 |

**自检问题**：
1. 这个案例我能讲成"如果 X 发生，则 Y 结果"的因果逻辑吗？如果不确定，说明没有拆解透。
2. 如果让我在相似的场景做决策，这个案例能帮我做出更好的选择吗？
3. 最近一周，有没有因为某案例而改变了某个行为？——案例学习的价值在行动，不在收藏。
