# 冰山图/三角图建模法：从表象深挖结构与本质

## 用一句话讲清楚

冰山图和三角图是两种从表象下探结构、用极简图形表达复杂系统因果与支撑关系的深度建模工具：冰山图逐层下挖“事件→行为→模式→结构→信念/本质”，三角图则把系统稳定支撑显化为“三个相互依存、缺一不可的核心要素”。

> **Burn line**: 冰山图让人看见水面下的部分，三角图让人看见三要素之间的支撑关系。

## 核心要点

1. **冰山图的核心是“深”**：水面上的事件只是症状，真正决定症状反复出现的是水下的行为、模式、结构、信念/本质；越往下越难改变，但也越能带来杠杆解。
2. **三角图的核心是“稳”**：三个角必须真实相互支撑，去掉任意一个，整个系统就应出现明显崩塌；三角图不是三个好听词的拼盘。
3. **关系必须可验证**：每一层/每一角都要有事实、案例或数据支撑，不能为了图形好看而硬凑。
4. **深挖后必须回到行动**：深度建模的终点不是“看透了”，而是找到可干预的杠杆点，并转化为可验证的下一步。
5. **对判断力要求高**：两种工具都位于深度模型层，适合“反复出现、原因不明、需要洞察”的问题，不适合简单执行问题。

冰山图和三角图是深度模型中用于“洞察”的工具。冰山图强调**层层深挖**：水面上的问题是表象，水面下是行为、模式、结构、信念。三角图强调**三要素的相互支撑**：三个角共同构成一个稳定结构，缺一不可。一堂用冰山图做深度复盘，用三角图表达战略、竞争力等三要素模型。

---

## Visual Analysis

冰山图通常以上下分层结构呈现，水面以上小，水面以下大，暗示可见部分只是整体的一小部分。三角图以等边/不等边三角形呈现，三个角代表三个核心要素，边和内部可进一步细分层次关系。

## Claims

- **C1 [conf=0.9]**: 冰山图适用于“从现象深挖根本原因”的场景，如复盘、问题诊断、文化分析。——依据：`src_20260614_73352fa5` 武器库“洞察：三角图、冰山图、圈层图”。
- **C2 [conf=0.85]**: 三角图适用于表达“三个核心要素相互支撑”的模型，如竞争力三角、增长三角、决策三角。——依据：`src_20260614_8269ccdb#1254-1256`。
- **C3 [conf=0.85]**: 冰山图的常见结构：事件→行为→模式→结构→信念/本质，越往下越难改变但也越有价值。——推断：基于冰山图通用模型和 Truman 对深度复盘的描述。
- **C4 [conf=0.8]**: 三角图的关键是三个要素之间要有真实关系，而不是硬凑三个词。——推断：基于 Truman 对“定义不清、丢三落四”的批评。
- **C5 [conf=0.75]**: 冰山图和三角图都属于深度模型，需要较高判断力，不适合解决简单执行问题。——依据：`src_20260614_73352fa5` 深度模型分类。

## Purpose

把对问题的理解从表层事件推进到深层结构和本质，找到真正有效的干预点。

---

## Protocol

### 冰山图使用步骤

#### 步骤 1：明确表象事件

写下你看到的问题或现象。例如：
- 直播状态不稳定
- 销售额连续下滑
- 团队沟通效率低

#### 步骤 2：逐层下挖

按冰山结构追问：
- **行为层**：当事人做了什么？
- **模式层**：这种行为是偶发还是反复出现？
- **结构层**：什么机制/流程/激励在维持这个模式？
- **信念/本质层**：当事人或组织相信什么？这个领域的核心变量是什么？

#### 步骤 3：找到杠杆点

真正有效的干预通常在越深的层次。但不要一次性跳到最底层，要验证每一层是否站得住脚。

### 三角图使用步骤

#### 步骤 1：找出三个核心要素

问自己：
- 这个系统的稳定由哪三个东西支撑？
- 去掉哪一个，整个系统会垮？
- 这三个东西之间是什么关系？

#### 步骤 2：定义每个角

每个要素必须：
- 可定义
- 与其他两个有真实关系
- 共同构成一个完整系统

#### 步骤 3：表达关系

三角图不只是三个词。要说明：
- 谁支撑谁？
- 谁限制谁？
- 增强一个角会如何影响其他角？

## Diagnostic Signals

| 信号 | 含义 | 建议动作 |
|---|---|---|
| 同一问题反复出现，治标无效 | 表层事件背后存在更深层的结构或信念 | 使用冰山图，从事件逐层下挖到结构与信念层 |
| 团队争论停留在“谁对谁错” | 缺乏对系统机制的共同理解 | 用冰山图把讨论从事件层拉到模式/结构层 |
| 需要向他人解释“这个系统靠哪三块支撑” | 三要素关系需要显性化 | 使用三角图，定义三要素及其相互关系 |
| 战略/产品方案被质疑“少了关键一环” | 可能存在未被识别的支撑要素 | 画三角图并做“去掉一个角”测试 |
| 深层结论无法被事实反驳 | 模型可能玄学化 | 要求每层/每角给出反例或证据 |
| 模型画完后没人知道下一步做什么 | 深挖与行动脱节 | 为每个杠杆点匹配可验证的下一步行动 |

## When NOT to Use

| 场景 | 为什么失效 | 替代方案 |
|---|---|---|
| **问题已经很明确，只需执行** | 深度模型会过度复杂化。 | SOP、清单 |
| **缺乏足够事实支撑** | 深挖容易变成臆测。 | 先收集案例和数据 |
| **团队没有共识基础** | 深层信念讨论容易引发冲突。 | 先用象限图/雷达图建立表层共识 |
| **硬凑三要素/五层** | 为了图形好看而堆砌概念。 | 回到事实，真的有几个要素就画几个 |

---

## 边界 / Constraints & Boundaries

| 边界 | 说明 |
|------|------|
| **冰山层数** | 通常 4–5 层，过多会变成玄学 |
| **三角要素数** | 严格 3 个，超过 3 个用雷达图或其他结构 |
| **事实基础** | 每层都需要事实或案例支撑，不能凭空想象 |
| **可行动性** | 深挖后必须能回到“所以下一步做什么” |

---

## 失败模式

| 失败模式 | 典型症状 | 后果 | 预防/修复 |
|---|---|---|---|
| 硬凑层级或要素 | 为了图形好看，事件/行为/模式/结构之间缺乏真实因果 | 模型变成概念堆砌，无法指导行动 | 每层/每角必须有事实和可验证的关系 |
| 过度心理学化 | 业务问题轻易归因于“信念”“文化” | 忽视结构与激励机制，干预点不可操作 | 先穷尽结构、流程、激励，再进入信念层 |
| 缺乏事实支撑 | 深层论断来自臆测或个体感受 | 团队不信服，复盘变成互相指责 | 每层至少配1-2个案例或数据点 |
| 只挖不行动 | 讨论很深入，但没有下一步 | 深度建模沦为智力游戏 | 每个杠杆点必须对应一个可验证的行动 |
| 三角要素不互斥 | 三个角概念重叠或边界模糊 | 结构不稳定，分析冗余 | 用MECE检验三要素 |
| 一次性跳到最底层 | 跳过行为/模式，直接断言“本质” | 结论站不住脚，难以被挑战 | 逐层验证，每层都有证据才能继续下挖 |

## 行动 Checklist

- [ ] 判断问题类型：是“反复出现/原因不明”还是“明确后只需执行”？
- [ ] 收集至少3个相关案例或数据点，避免空挖
- [ ] 选择工具：冰山图（下挖因果）或三角图（表达三要素支撑）
- [ ] 写下每一层/每一角的定义，并标注可观察的证据
- [ ] 检查是否硬凑层级或要素（反例测试）
- [ ] 找到最深或最脆弱的杠杆点
- [ ] 将杠杆点转化为可验证的下一步行动
- [ ] 与关键利益相关者对齐模型假设与行动计划

## [Critique]

### 内部局限性

- 冰山图容易陷入过度心理学化，把业务问题归因于“信念”
- 三角图容易硬凑三要素，变成三个好听词的堆砌
- 深度模型对使用者的判断力要求高，新手容易 misuse

### 外部攻击：Chris Argyris — "冰山下的东西看不见，所以容易被滥用"

**Chris Argyris**（组织学习理论）会警告：冰山图很诱人，因为可以把问题推到“看不见的深层原因”。但深层原因很难验证，容易变成解释一切的万能框架。每个深层的论断都必须有可被挑战的证据。

### 反事实测试

- 如果冰山图少挖一层，结论会不同吗？如果会，说明某一层是关键的。
- 如果三角图去掉一个角，模型还成立吗？如果不成立，说明这个角是真的核心要素。
