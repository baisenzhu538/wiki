# 一行一点精简法则：砍掉语气词、括号、修饰语，只留主语+关键词+关键动作

## 用一句话讲清楚

**把清单体笔记的每一行压缩成“谁/什么 + 核心概念 + 动作”的最小可执行信息单元，砍掉一切不承载信息熵的成分。**

## 核心要点

1. **一行一点是认知压缩，不是排版习惯**：只有在脑中完成“什么是重要的”判断，才能写出一行一点。
2. **保留三类信息承载者**：主体词（谁/什么）、关键词（核心概念）、关键动作（要做什么）。
3. **砍掉六类噪音**：语气词、插入语、修饰语、连接词、重复信息、常识性表述。
4. **补充信息降级处理**：数据来源、负责人、截止日期、优先级、相关文档用括号/`@`/符号/链接标注，不打断主阅读流。
5. **每行能单独被理解**：脱离上下文后，3秒内能说出核心信息。
6. **与分层、加粗形成组合**：[[tool-note-layer-constraint]] 解决信息在哪一层，[[tool-note-keyword-bolding]] 解决视觉重心，一行一点解决每一行的粒度。

## Purpose

本技能卡提供**清单体笔记的语义压缩标准**——把一行话从“口语化叙述”压缩成“信息单元”的核心方法。Truman十年实践发现：**清单体笔记的每一行必须是一个独立的“可执行信息单元”**——包含主体词、关键词和关键动作，砍掉一切不承载信息熵的成分。核心洞察：“一行一点”不是排版习惯，而是认知压缩算法。

## When to Use

| 场景 | 判断标准 |
|:---|:---|
| 会议/课程/访谈实时记录 | 信息输入速度快，每句话必须在2秒内记完 |
| 团队协作文档 | 降低阅读者的认知摩擦，减少“这句话什么意思”的追问 |
| 给AI处理的结构化输入 | AI对冗余信息的理解准确率显著下降 |
| 行动清单和待办事项 | 每行必须能直接转化为可执行动作 |
| 复盘/决策记录 | 事后回顾时需要在10秒内理解当时的判断 |
| 任何超过500字的清单体笔记 | 没有精简的笔记会退化成“小作文”，失去清单体优势 |

## When NOT to Use

| 场景 | 为什么失效 | 后果 |
|:---|:---|:---|
| 头脑风暴原始记录 | 需要发散，过早精简会扼杀创意 | 把未成形的想法当成定论 |
| 文学性/情感性内容 | 冗余是文学节奏的一部分 | 内容变得干瘪、失去感染力 |
| 法律/合规文档 | 法律文本的每一个词都可能有关键含义 | 精简导致法律风险 |
| 给上级/客户的正式汇报 | 过于精简可能显得敷衍 | 被认为“不认真”或“不够详细” |
| 个人私密日记 | 只有自己看，无需考虑他人认知负荷 | 过度精简让日记失去情感价值 |
| 首次接触新领域时的学习笔记 | 自己也不懂，强行精简会导致理解偏差 | 把不懂的当懂了，埋下隐患 |

### 步骤2：执行“一行一点”转换

**转换公式**：
```
原始句子：【主体词】+【修饰语】+【关键词】+【语气词】+【关键动作】+【插入语】
```

**判断标准**：
- 待补充链接
- 待补充链接
- 待补充链接

**示例对比**：

| 原始（口语化） | 精简后（一行一点） | 砍掉的内容 |
|:---|:---|:---|
| 我们上个季度的用户流失率好像上升了15%左右 | Q3用户流失率↑15% | “我们”“上个季度”“好像”“左右” |
| 我觉得可能是因为我们的产品定位不太够清晰 | 根因：产品定位模糊 | “我觉得”“可能”“不太够” |
| 所以建议大家在下个迭代中重新验证一下产品定位 | 行动：Q4验证产品定位 | “所以”“建议”“大家”“重新”“一下” |
| 具体来说可以通过用户访谈和对齐团队认知来解决 | 方法：用户访谈+团队对齐 | “具体来说”“可以”“来解决” |

**3秒测试**：给同事看精简后的版本3秒，问“刚才那几条的核心信息是什么”。如果能答对，精简成功。

### 步骤3：处理“必须保留的补充信息”

有些补充信息不能砍，但需要**降级处理**：

| 信息类型 | 处理方式 | 示例 |
|:---|:---|:---|
| 数据来源 | 用括号标注，但不占主行 | Q3用户流失率↑15%（CRM数据） |
| 负责人 | 用@标注 | 行动：验证产品定位 @张三 |
| 截止日期 | 用日期标注 | 行动：验证产品定位 @张三 6.15 |
| 优先级 | 用符号标注 | 🔴 行动：验证产品定位（P0） |
| 相关文档 | 用链接标注 | 行动：验证产品定位 [产品定位v2] |

**原则**：补充信息不能**打断**主行的阅读流，必须能被“扫读”时忽略。

### 步骤4：建立“口语→清单体”的快速转换通道

**实战场景**：你在开会，讲者说了一大段话，你需要在5秒内转成一行一点。

**快速转换三步法**：
1. **抓主语**：这句话在讲“谁/什么”？
2. **抓变化**：发生了“什么变化/什么问题”？
3. **抓动作**：需要“做什么”？

**示例**：
> 讲者说：“啊，那个，我这边想补充一下啊，就是关于上个季度的那个用户反馈，我们这边整理了一下，发现其实啊，大部分用户觉得我们的界面有点复杂，就是操作流程太长了，所以建议啊，我们下个版本是不是可以考虑简化一下？”

**5秒内转换**：
```
用户反馈：界面复杂、流程过长
→ 行动：下版本简化界面流程
```

**砍掉**：“啊”“那个”“我这边想补充一下”“就是关于”“我们这边整理了一下”“发现其实”“大部分”“有点”“是不是可以考虑”

### 步骤5：用AI辅助检查冗余度

**Prompt模板**：
```
请将以下清单体笔记的每一行精简为“主体词+关键词+关键动作”格式。
要求：
1. 砍掉语气词、插入语、修饰语
2. 每行不超过20字
3. 保留主体词、关键词、关键动作
4. 补充信息用括号标注
5. 如果某行无法精简，说明为什么

[粘贴笔记内容]
```

## 失败模式

| 失败模式 | 典型表现 | 后果 | 修复方式 |
|:---|:---|:---|:---|
| 保留主观判断 | “我觉得这个方案可能比较好”仍保留“我觉得”“可能” | 把观点当事实，降低决策可信度 | 加标签：`[个人观点] 方案A更优`，或砍掉主观词 |
| 保留修饰语 | “我们做了一个非常重要的决定”仍保留“非常重要” | 信息熵为零，增加阅读负担 | 直接写“决定：XXX” |
| 补充信息混入主行 | 一行50字，括号、从句、负责人全堆在主句中 | 无法扫读，关键动作被淹没 | 用括号/`@`/符号降级到主行之后 |
| 过度降级丢信息 | 把负责人、DDL、数据来源全删掉 | 行动项无法执行，复盘找不到依据 | 按步骤3的表格保留最小必要补充信息 |
| 逐字记录会议 | 讲者说什么记什么，跟不上节奏 | 遗漏关键信息，笔记变成流水账 | 用“抓主语→抓变化→抓动作”三步法 |
| 只记结论丢前提 | “简化界面”但没有“用户反馈”依据 | 行动失去上下文，难以复盘 | 保留根因/依据行，再用箭头引出行动 |
| 拆成无关联碎片 | 每行孤立，看不出因果或层级 | 清单体退化为散装词组 | 用缩进、箭头、标签表示层级关系 |
| 在新领域强行精简 | 自己还没懂就压缩 | 把不懂的当懂了，形成错误认知 | 先写完整学习笔记，理解后再精简 |

## Synthesis

本技能的本质是**用硬性约束倒逼认知筛选**。当你被迫把一句话压缩到15字以内时，你必须在0.5秒内做出判断——“这句话的核心是什么”。这个判断过程就是[[dk-note-surplus-brainpower]]中说的“高阶认知操作”：它不是记录，而是**实时加工**。

[[tool-note-layer-constraint]] 与本技能互补：分层解决“信息在哪一层”，一行一点解决“每一行承载多少信息”。两者结合，才能实现Truman说的“AI看它特别顺手，一下加载”的效果。分层让AI知道结构，一行一点让AI知道粒度。

[[tool-note-keyword-bolding]] 与本技能形成“压缩+标记”的双层体系：一行一点负责把信息压缩到最小可执行单元，加粗负责在压缩后的单元中标出视觉重心。没有一行一点，加粗会淹没在冗余中；没有加粗，一行一点会变得过于密集。

[[dk-note-maximum-common-divisor]] 解释了为什么一行一点对AI特别友好：AI处理token有成本，冗余信息不仅浪费token，还会引入噪声。一行一点的笔记对AI来说相当于“预处理过的数据”——结构清晰、信息密度高、无噪声。

## 质疑

- **具体假设**：该工具假设"一行一点 = 最精简的表达"，但"精简"和"清晰"不是同一件事。砍掉修饰语和括号可能丢失关键的限定条件——"在特定条件下成立"的"特定条件"可能就是那个被砍掉的括号。
- **边界**：在需要精确性的场景（法律合同、医疗记录、技术规格），"一行一点"的精简法则可能导致歧义——省略一个限定词就能改变法律含义。
- **反例**：把"如果用户在30天内未登录，则自动降级为免费版（不含历史数据导出功能）"精简为"30天未登录→降级免费版"——丢失了"不含历史数据导出"这个关键后果。

**William Strunk**（康奈尔大学英语教授，《The Elements of Style》作者）会质疑："省略不必要的词"是好的写作原则，但判断"不必要"需要理解上下文——一行一点的规则假设"精简是绝对好的"，但实际上"必要的冗余"才是好写作的核心。Strunk 会说：真正的好写作不是"字数最少"，而是"每个字都在工作"——有时候一个修饰语恰好是让句子"工作"的关键。机械地砍掉所有修饰语，得到的不是"精简"，而是"贫乏"。
