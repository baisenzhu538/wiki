# 关键词加粗三重结构：视觉重心即认知重心的标记法则

## 用一句话讲清楚

**通过加粗、颜色、底色三级视觉标记，把读者的注意力引导到关键词上，让清单体笔记从"信息仓库"变成"决策工具"。**

## 核心要点

1. **加粗是认知导航，不是装饰**：读者先扫视觉重心，再决定是否细读；加粗告诉读者"这里是重点，其他可以略读"。
2. **三级递进，按需使用**：第一层加粗（必做）、第二层颜色（选做）、第三层底色/模块（极少用）。
3. **只标记三类信息承载者**：主体词（谁/什么）、关键词（核心概念）、关键动作（要做什么）。
4. **控制密度才能生效**：每句话0-2处加粗，全加粗等于全不加粗；颜色不超过3种，底色块一屏不超过2个。
5. **团队必须有统一规范**：标记语义一致，否则协作时每个人有自己的"方言"。
6. **与一行一点、分层约束形成组合**：[[tool-note-one-line-one-point]] 解决每行粒度，[[tool-note-layer-constraint]] 解决结构层级，加粗解决视觉重心。

## Purpose

本技能卡提供清单体笔记中**关键词视觉标记**的三级递进方法。核心洞察：读者（包括未来的自己和AI）在阅读时不是逐字扫描，而是**先扫视觉重心、再决定要不要细读**。加粗不是装饰，而是**认知导航**——它告诉读者"这里是重点，其他可以略读"。Truman十年实践的核心发现：不加粗的清单体是"信息仓库"，加粗后的清单体是"决策工具"。

## When to Use

| 场景 | 判断标准 |
|:---|:---|
| 任何需要快速定位重点的笔记 | 读者可能在30秒内需要找到关键信息 |
| 给团队/他人阅读的协作文档 | 降低沟通成本，减少"这句话重点是什么"的追问 |
| 给AI处理的结构化输入 | AI对加粗关键词的权重识别更敏感，输出更聚焦 |
| 会议纪要和决策记录 | 事后回顾时能在10秒内定位核心结论 |
| 培训材料和操作手册 | 学习者需要在压力下（现场）快速找到下一步动作 |
| 超过10行的列表 | 无视觉标记的长列表会让读者迷失在信息海洋中 |

## When NOT to Use

| 场景 | 为什么失效 | 后果 |
|:---|:---|:---|
| 个人速记（不分享） | 只有自己看，视觉标记无意义 | 增加记录时间，无额外收益 |
| 脑暴阶段原始记录 | 想法尚未结构化，过早标记会固化不成熟判断 | 把草稿当成定稿，扼杀后续迭代 |
| 全部加粗 = 全不加粗 | 失去"对比"这一核心机制 | 视觉重心消失，读者重新陷入逐字阅读 |
| 文学性/情感性内容 | 加粗会破坏语感节奏 | 内容变得机械、生硬 |
| 已经用颜色/图标做了强区分 | 多重标记系统造成视觉噪音 | 读者困惑"到底哪个才是真正的重点" |
| 移动端极窄屏幕阅读 | 加粗在窄屏上的区分度大幅下降 | 标记效果不明显，反而增加视觉负担 |

## Protocol

### 步骤1：区分"主体词、关键词、关键动作"

在加粗之前，先对一句话做**语义解剖**：

| 类型 | 定义 | 示例 |
|:---|:---|:---|
| **主体词** | 这句话在讲"谁/什么" | 用户流失率、产品定位、团队文化 |
| **关键词** | 决定这句话含义的核心概念 | 同比、环比、A/B测试、MVP |
| **关键动作** | 需要执行的具体行为 | 验证、迭代、复盘、对齐、下沉 |

**Truman原话**："主体词、关键词和关键动作都得保留，语气词、插入语、解读细节、修饰语如果非必要的话全拿掉都用不着。"

### 步骤2：第一重——加粗（基础层，必做）

**操作**：对主体词、关键词、关键动作加粗。

**效果**：读者扫一眼就能知道"这段话在讲什么、核心概念是什么、需要做什么"。

**示例**：

```
❌ 不加粗：
我们在上季度发现用户流失率有明显上升，经过分析主要原因是产品定位不够清晰，导致目标用户群体不够聚焦。建议在下个迭代中重新验证产品定位，通过用户访谈和对齐团队认知来解决这个问题。

✅ 加粗后：
我们在上季度发现**用户流失率**有明显上升，经过分析主要原因是**产品定位**不够清晰，导致**目标用户群体**不够聚焦。建议在下个迭代中**重新验证产品定位**，通过**用户访谈**和**对齐团队认知**来解决这个问题。
```

**3秒测试**：给同事看加粗后的版本3秒，问他"刚才那段话的核心问题是什么、建议做什么"。如果能答对，加粗成功。

## 失败模式

| 失败模式 | 典型表现 | 后果 | 修复方式 |
|:---|:---|:---|:---|
| 全加粗=全不加粗 | 一句话中80%以上词汇加粗 | 视觉重心消失，读者重新逐字阅读 | 只保留主体词、关键词、关键动作 |
| 标记修饰语/连接词 | "**非常**重要的**一个**关键点""**因此**、**但是**" | 稀释真正重点，混淆逻辑衔接与信息承载 | 删掉修饰语，连接词用层级结构表示 |
| 颜色彩虹化 | 红黄蓝绿紫全上，语义混乱 | 视觉噪音比不加还糟 | 同一篇笔记颜色≤3种，团队约定语义 |
| 底色块滥用 | 一屏内3个以上底色块 | 屏幕碎片化，读者无法聚焦 | 一屏≤2个底色块，且必须有标题 |
| 个人方言化 | 协作文档中每人标记习惯不同 | 沟通成本不降反升 | 建立并执行团队最小标记规范 |
| 忽略媒介差异 | 用颜色标记的内容被黑白打印 | 关键信息丢失 | 打印版用加粗+图标替代颜色 |
| 过早标记草稿 | 脑暴阶段就加粗定型 | 把不成熟判断固化 | 草稿阶段只分层，定稿后再加粗 |
| 该加粗没加粗 | 关键结论淹没在长段文字中 | 读者3秒内找不到重点 | 对每句话做语义解剖，标记信息承载者 |

## Synthesis

本技能的本质是**用视觉层级替代认知层级**。人类视觉系统处理图像的速度比文字快6万倍（Sperling, 1960），加粗关键词就是给读者的视觉系统装了一个"快速筛选器"。[[tool-note-one-line-one-point]] 中提到的"主体词、关键词、关键动作"——加粗正是这三类信息承载者的视觉化。

[[tool-note-layer-constraint]] 与本技能互补：分层解决"结构在哪"，加粗解决"重点在哪"。两者结合，才能实现Truman所说的"AI看它特别顺手，一下加载"的效果。分层让AI知道"这些信息是并列还是包含关系"，加粗让AI知道"这些信息里哪些权重更高"。

[[dk-note-surplus-brainpower]] 提供了本技能的底层动力解释：只有当分层和加粗都内化为肌肉记忆，你才有剩余脑力去做更高级的操作。否则，你的脑力会不断被"这段话的重点是什么"消耗掉。
