# 技能：真需求四要素验证法

## 原始表述

纪浩在AI协作方法论中提出：Question（疑问）满足好奇心，Problem（问题）需要行动改变现实。判断一个问题是不是值得解决的"真需求"，需要检验四个要素：Before-After状态变化、真实锚点、受益人、可解性。四个要素不够，不要下场动手。

## 操作步骤

1. **描述 Before 状态**——用一句话说清楚"解决之前是什么样子"。如果说不出来，说明你可能连问题现场都没看清
2. **描述 After 状态**——用一句话说清楚"解决之后变成什么样子"。Before和After之间必须有可观察的差异
3. **检验真实锚点**——这个问题是否在你的真实工作/生活中存在？还是只是"如果有一个XX就好了"的想象？真实锚点的检验标准：能说出具体的时间、地点、人物、事件
4. **确认受益人**——解决这个问题后，有没有具体的人觉得"实打实获益"？受益人不能是"所有人"或"未来的用户"，必须是你能命名的具体人
5. **验证可解性**——从 Before 到 After 之间是否有清晰的因果链？你是否有能力（或能获取的资源）支撑这个因果链？如果因果链是"运气"或"希望"，不算可解
6. **作出判断**——四个要素都通过 → 可以动手。任何一个不通过 → 暂停，先补充信息或放弃

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 打算让AI执行新任务前，不确定是否值得做 |
| ✅ 适合 | 团队讨论新需求时，需要快速检验真实性 |
| ✅ 适合 | 自己有好点子，不确定是真需求还是假需求 |
| ✅ 适合 | 需要向别人证明方案价值时，需要结构化论证 |
| ❌ 不适合 | 一次性、单轮的快速尝试 → 验证成本超过收益 |
| ❌ 不适合 | 已被多实例验证的标准流程 → 重复验证 |
| ❌ 不适合 | 紧急故障排查 → 先解决后验证，四要素延误时机 |
| ❌ 不适合 | 高不确定性探索项目 → 连问题是什么都不知道 |

#| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **Before模糊** | Before状态描述模糊，说不出来解决前是什么样子 | 必须用一句话说清楚解决前是什么样子，说不出来说明连问题现场都没看清 |
| **After不可验证** | After是'更好'而非'可观察'的变化 | After必须有可量化或可视化的判断标准，模糊的'更好'无法验证效果 |
| **受益人虚化** | 受益人是'未来用户'或'所有人' | 受益人必须是能命名的具体人，不能是'所有人'或'未来的用户' |
| **可解性虚假** | 可解性验证被'希望'替代 | 因果链中每一环都需要具体的能力或资源支撑，'运气'或'希望'不算可解 |
| **验证逃避** | 新手觉得自己没资格做验证，不做判断盲目开干 | 新手的验证工具是假设、调研、访谈、问AI、做实验。不做验证就动手是赌博 |
| **探索扼杀** | 在高不确定性领域用四要素，把创造性探索死在门外 | 探索性项目用快速原型+实地观察，四要素用于验证阶段而非探索阶段 |
| **计划暴政** | 检验阶段写下的Before-After，执行阶段被重写 | 四要素提供虚假安全感，真正问题只有在做的过程中暴露。保持验证的开放性 |
| **过度收敛** | 四要素是收敛工具，把思维过早钉死在框架上 | 创意发散阶段用IDEO脑暴规则，方向明确后再用四要素验证 |

## 为什么有效

四要素验证法的核心机制是**强制拆解假设**。大多数人的"好点子"死在第一步（没有真实锚点）或第四步（受益人是想象出来的）。通过强制回答四个具体问题，把"感觉对"转化成"可验证的判断"。

### 外部攻击

#### Nassim Taleb 的"反脆弱性"批评

**Nassim Taleb**（《反脆》《黑天鹅》作者，风险分析学家）会质问：**四要素验证假设了一个可预测的世界**——Before 和 After 之间有清晰的因果链。但在高不确定性环境下，你可能连自己在解决什么问题都不知道，更不用说因果链。Taleb 会说：**真正创造性的突破往往来自于"先做，然后在做的过程中发现问题"——而四要素验证正在把这种不可预测的探索死在门外。**

> **Taleb 的敛命敲响**："如果你在使用四要素验证时发现自己总是在第三步或第四步被卡住，不是你的锚点不够真实——是你正在面对一个不可预测的问题域，而这种问题域正是创造性突破的温床。四要素验证对于驻立业务是好工具，对于探索未知可能是毒药。"

#### Lucy Suchman 的"情境行动"批评

**Lucy Suchman**（《Plans and Situated Actions》作者，人类学家，在机器人与AI交互领域的开创性学者）会追问：**四要素验证假设了计划与执行之间完美的传递**——你在检验阶段制定的Before-After，在执行阶段一定会被打破。Suchman 的核心论点是：人的行动永远是"情境性的"（situated），即使是同一个人在同一个场景下，下一次的行动也不会完全重复上一次。四要素验证在尝试用"静态的计划"控制"动态的情境"，这是计划对行动的暴政。

> **Suchman 的敛命敲响**："你在检验阶段写下的 Before 和 After，到了执行阶段都会被重写。你的四要素验证不是在验证需求，是在制造一个虚假的安全感——让你以为自己已经想清楚了，但真正的问题只有在做的过程中才会暴露。"

## Action Triggers

| 触发条件 | 行动 | 预期结果 |
|---|---|---|
| 当你有一个"好点子"并想让AI实现时 | 先用四要素检验，不要直接开始写prompt | 按此行动执行 |
| 当团队成员提出一个新需求时 | 让对方用四要素填写，填不出来就暂缓 | 按此行动执行 |
| 当你在多个项目之间不知道该做哪个时 | 分别用四要素验证，通过率高的优先 | 按此行动执行 |

## Synthesis

### 不要用的场景

| 场景 | 为什么失效 | 替代方案 |
|---|---|---|
| 创意发散/脑暴阶段 | 四要素是收敛工具，会把思维过早钉死在框架上 | IDEO脑暴规则——延迟判断、追求数量、先生成再过滤 |
| 高不确定性的探索性项目 | 连自己在解决什么问题都不知道，更不用说因果链 | 快速原型+实地观察（精益创业/客户开发法） |
| 紧急故障排查 | 先解决，后补充验证，四要素会延误时机 | 先恢复服务，事后做根因分析 |
