# 跨域模式层

> **这是什么**：一堂课程表面独立（决策/需求/增长/销售/AI/设计...），底层共享同一套方法论模式。本目录为这些底层模式建立索引——不新建概念卡，只记录"这个模式在哪些域、哪些卡里出现，以及用法差异"。

## 三个底层模式

| 模式 | 一句话 | 定位 |
|:---|:---|:---|
| [[pattern-layered-matching]] | 先把问题分层，再为每层匹配不同工具 | **骨架**（结构层）——定义"问题长什么样" |
| [[pattern-hypothesis-validation]] | 把信念变成可证伪假设，用最低成本验证 | **引擎**（动力层）——定义"怎么确认判断是对的" |
| [[pattern-tool-vs-model]] | 从使用别人的工具到建立自己的模型 | **进化**（成长层）——定义"怎么从新手到高手" |

## 三者关系

```
分层+匹配（结构）
    ↓ 每一层都需要
假设+验证（动力）
    ↓ 每一轮验证都在推动
工具→建模（进化）
```

**具体例子**：你做用户分层（分层+匹配），对"高价值用户最在意的功能是X"这个假设做最低成本验证（假设+验证），验证了 10 次以后你不再需要用户分层模板，本能地知道怎么分层（工具→建模）。

## 使用方式

1. **读卡时**：看完一张卡后，来对照这三个模式——它用了哪个？有没有跨域变体？
2. **写卡时**：如果你的卡在描述一个方法，明确标注"这个方法是哪个底层模式在本域的应用"
3. **跨域桥接时**：两个域用了同一模式但形态不同→这是最有价值的桥接点

## 维护规则

- 不新建概念卡——只做已有卡片的连接索引
- 新发现一个底层模式→在本目录新建 pattern-*.md
- 某张卡体现了某个模式→在对应 pattern 文件中追加
- 发现跨域差异的新维度→更新对应 pattern 文件的"跨域差异总结"表
