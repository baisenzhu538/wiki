# 项目螺旋思考法：先顶层再细节、先选择再执行、先确认再推进

> **Burn line**：项目总是变来变去、返工不断，根源往往不是执行力差，而是思考层次错乱——用细节思考替代了顶层判断，用执行热情跳过了方案确认。「先顶层再细节、先选择再执行、先确认再推进」不是慢，是让每一步都踩在正确的方向上不回头。

---

## 何时使用

在以下场景，必须启动螺旋思考：

1. **接到一个"老板想法"级的需求时**
   老板说"我觉得咱们可以做X"，你直接开始执行——这就是跳过螺旋思考。应该先追问背景（真的疼吗？）、对齐目标（真性感吗？）、粗判路径（真可行吗？）。

2. **方案被频繁推翻、反复返工时**
   设计师出了三版都被推翻——因为风格没确认就进入了精细排版。回退到上一个确认节点，先锁风格再细化。

3. **跨部门协作推不动时**
   别人不配合，往往不是你人缘差，而是你没讲清楚"这项目解决了他们什么问题"。先收集各方的落差，再出方案。

4. **A/B/C/D 级别跳跃时**
   项目从B升级到C，复杂度变了。回退到螺旋起点，重新判断做不做、怎么做。

5. **任何涉及"做不做"的关键决策节点**
   创业方向选择、大额投入、关键人事决定——这些不是执行层问题，是顶层判断。启动螺旋思考的三问。

## 核心框架：从「想到就做」到「螺旋上升」

### 一张图理解螺旋思考

```
        顶层判断（做不做）
        ┌─────────────────────┐
        │  背景：真的疼吗？     │
        │  目标：真性感吗？     │
        │  路径：真可行吗？     │
        └─────────┬───────────┘
                  │  ← 先想清楚这层，再往下走
                  ▼
        方案设计（怎么做）
        ┌─────────────────────┐
        │  三段论 + 评估三角    │
        │  风险预判 + 评审      │
        └─────────┬───────────┘
                  │  ← 方案没定，别执行
                  ▼
        执行落地（做出来）
        ┌─────────────────────┐
        │  拆计划 → 管过程 → 复盘 │
        └─────────────────────┘
```

Truman 在定方案课上总结的螺旋思考原则（定方案口述稿 L178-L197）：

> 「你们真正在做执行、做项目管理之前，要做方案设计。在方案没有设计完美之前，不要轻易地执行。方案设计之前，先想顶层的可行性判断。当顶层可行性判断没想清楚之前，就不要做太多细节。在初期评估一个项目可行性的时候，尽量忍住，尽量不要进入执行细节。」

### 螺旋思考的「三先三后」

| 原则 | 含义 | 跳过此步的后果 |
|:---|:---|:---|
| **先顶层再细节** | 先回答"做不做"再深入"怎么做" | 花三周设计精美方案，发现根本不值得做 |
| **先选择再执行** | 先锁定方向/方案/风格，再投入执行资源 | 设计师画完精细字体后被要求推倒重来 |
| **先确认再推进** | 每个决策节点找决策人拍板，再进入下一阶段 | 做到一半老板说"这不符合公司VI，回去改" |

## 操作步骤：螺旋思考三问法

在任何重大决策或行动之前，按顺序回答三个问题。**顺序不能乱**——跳过第一个直接回答第二个是典型的思考错误。

### 第一步：背景——真的疼吗？

回答"我到底在解决什么问题"。不要从"我想做什么"开始，要从"我看到了什么事实"开始。

**追问技巧**：
- 这个问题的现状是什么？预期是什么？落差有多大？
- 用8维度落差分析（宏观战略/中观商业/微观用户）找到最有力的论据。详见 `[[framework-yitang-project-plan-design]]`。
- 如果只能用一个数据点说服别人这问题真实存在，你选哪个？

**通过标准**：你能让一个不相关的人听完背景后说"这确实是问题，值得解决"。

**未通过**：不要进入第二步。继续收集事实，或者直接放弃。

### 第二步：目标——真性感吗？

回答"解决了问题之后，我们想达到什么状态"。目标必须让协作方"想要"。

**追问技巧**：
- 这个目标是否让老板想要？让协作部门想要？让自己想要？
- 定性目标是什么（方向）？定量目标是什么（数字）？
- 第一目标和辅助目标分别是什么？

**通过标准**：你能让三个不同角色的干系人听完目标后说"我支持你这么做"。

**未通过**：回退到第一步——可能是问题找对了但目标拆错了，也可能是问题本身就不值得做。

### 第三步：关键路径——真可行吗？

回答"从现状到目标，我们大概怎么过去"。粗粒度即可——不需要甘特图、不需要WBS，只需要回答"有路吗"。

**追问技巧**：
- 从背景到目标的路径上，最关键的三步是什么？
- 最大的假设是什么？（假设不成立，整个方案崩塌的那种）
- 有没有"先粗糙验证核心假设"的最小动作？

**通过标准**：你能画出一条从背景到目标的路径，且路径上最大的假设有办法低成本验证。

**未通过**：不是放弃——而是回到第一步，缩小目标范围，或者回到第二步，降低目标野心。

## 快速检查单

在任何重要行动之前，用以下五条自查：

1. **我当前的思考在哪一层？**
   （顶层判断 / 方案设计 / 执行细节——先确认是在正确的那层）
2. **三问的顺序对吗？**
   （背景→目标→关键路径，不能跳步）
3. **有没有忍住「不进入细节」？**
   （方案没通过"做不做"之前，不讨论配色、字体、排期）
4. **当前阶段的决策人确认过了吗？**
   （该拍板的人拍了板，再进入下一阶段）
5. **如果现在被推翻，最小后悔成本是多少？**
   （越早确认顶层，推倒重来的成本越低）

## 失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| **倒着思考** | 先想好要做什么，再回去编背景和目标 | 强制从问题出发——"先有疼，才有方案" |
| **跳层思考** | 方案还没定，开始讨论用什么字体、什么时候上线 | 画螺旋图贴在工位上——每次讨论前先确认"我们现在在哪一层" |
| **假确认** | "老板应该同意吧""大概方向对就行"——没有真正的拍板 | 确认必须有过明确表态（口头/文档均可），不能靠"应该" |
| **把三段论当一次性的** | 项目启动时写了背景目标路径，后面再也不回头看 | 每个关键里程碑回看三段论——目标变了吗？路径还通吗？ |
| **把螺旋当借口拖延** | "我还在顶层思考"想了三个月没有行动 | 螺旋思考不是替代行动——顶层判断最多占项目总时长20% |
| **单人项目跳过螺旋** | 觉得"就我一个，直接干就行" | A级项目也要问老板三问（背景/目标怎么做）——不要纯当执行者 |

## 适用边界

### 适用场景
- 需要多人协作的项目（B/C/D级）
- 老板提出的模糊需求需要转化为方案
- 项目被频繁推翻、反复返工
- 跨部门争取资源的方案论证
- **非项目场景**：职业选择、重大采购、关键人事决策、创业方向选择——任何涉及"做不做"的重大决策

### 不适用场景
- 已明确SOP的日常运营动作（不是项目，不需要螺旋）
- 单人1天的简单任务（A级最轻量：口头三问即可）
- 快速A/B测试（测试本身就是验证方式，不需要完整的方案论证）
- 紧急救火（安全第一，先灭火再复盘螺旋）

### 非项目场景迁移

螺旋思考的本质是**决策前的结构化思维纪律**，不限项目：

| 场景 | 螺旋三问适配 |
|:---|:---|
| 职业选择（要不要跳槽） | 背景：现在真的疼在哪？目标：新工作必须满足的三个条件？路径：怎么低成本验证新机会？ |
| 重大采购（要不要买这个系统） | 背景：不用这个系统的真实损失？目标：用了之后的核心指标变化？路径：最小试用方案是什么？ |
| 学习投资（要不要报这个课） | 背景：当前能力缺口的具体症状？目标：学完后能做成什么现在做不了的事？路径：有没有试听课可以判断？ |

## 行动触发器

完成螺旋思考三问后，立即执行：

1. **写一页纸方案**
   背景（一段话）+ 目标（定性+定量）+ 关键路径（三条以内）+ 最大假设（一条）。C级以上项目用三段论 + 评估三角。

2. **找决策人确认顶层判断**
   拿着这一页纸找A（拍板人），确认三件事：问题对吗？目标想要吗？路径觉得可行吗？确认后再进入方案细节。

3. **设定螺旋回退触发器**
   当项目出现以下信号时，自动回退到螺旋起点重新判断：目标变化超过20%、范围扩大超过30%、关键假设被证伪。
