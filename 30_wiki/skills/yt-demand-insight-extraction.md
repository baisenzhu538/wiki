# 从用户访谈中提取真实需求：访谈技巧与偏见规避

> 一堂五步法：用户访谈不是"聊天"，而是结构化的需求挖掘过程。

## 核心框架

### 访谈原则

| 原则 | 说明 | 错误示范 | 正确示范 |
|:---|:---|:---|:---|
| **少说多听** | 让用户说，不引导 | "您是否需要更高效的工具？" | "您现在怎么管理这个任务的？" |
| **追问具体** | 从抽象到具体 | "您觉得怎么样？" | "您刚才说的'麻烦'，具体是指什么？" |
| **关注行为** | 问做了什么，不是想做什么 | "您想要什么样的功能？" | "您上次遇到这个问题时，是怎么解决的？" |
| **寻找反例** | 主动寻找不支持假设的证据 | "您也觉得这个功能很有用吧？" | "您觉得这个功能对您没用的情况是什么？" |
| **记录原话** | 记录用户的原话，不加解读 | "用户说想要更好的体验" | 记录原话："我现在每次找文件都要花10分钟" |

### 访谈框架：JTBD访谈五问

1. **最近一次**：您最近一次遇到这个问题是什么时候？
2. **情境描述**：当时的情境是什么？时间、地点、情绪？
3. **替代方案**：您当时怎么解决的？用了什么工具/方法？
4. **切换点**：如果用了新产品，是什么让您决定切换？
5. **结果评估**：完成后，结果和您预期的一致吗？

## 关键洞察

### 1. 访谈偏见的识别

| 偏见类型 | 表现 | 规避方法 |
|:---|:---|:---|
| **引导性偏见** | 问题暗示了期望答案 | 用开放式问题，避免"是否"问题 |
| **社会期望偏差** | 用户说"想要"以符合期望 | 问"现在怎么做"替代"想要什么" |
| **确认偏见** | 只记录支持假设的证据 | 主动寻找反例，记录负面反馈 |
| **幸存者偏差** | 只访谈现有用户，忽视流失用户 | 访谈流失用户，了解为什么不使用 |
| **创始人投射** | 把自己的需求当成用户需求 | 访谈外部用户，寻找反例 |
| **样本偏差** | 只访谈容易找到的用户 | 主动寻找不同用户层 |

### 3. 访谈数量的判断

| 目的 | 最少访谈数 | 标志 |
|:---|:---:|:---|
| 发现主要问题 | 5-8个 | 新问题出现频率降低 |
| 验证假设 | 10-15个 | 假设得到一致验证或否定 |
| 量化需求强度 | 20+个 | 可进行统计分析 |

**判断标准**：当连续3-5个访谈没有新信息时，可以停止。

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **访谈无结构** | 闲聊，没有预设框架 | 使用JTBD访谈五问或拆推评算框架 |
| **引导性问题** | 用户说"想要"，但行为不一致 | 用"现在怎么做"替代"想要什么" |
| **样本不足** | 只访谈3-5个用户 | 至少访谈10个，覆盖不同用户层 |
| **忽视反例** | 只记录支持假设的证据 | 主动寻找反例，记录负面反馈 |
| **访谈后不验证** | 访谈结论直接指导决策 | 用行为数据或原型测试验证 |
| **记录不结构化** | 访谈记录混乱，无法分析 | 使用统一模板，结构化记录 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新产品需求验证 | 成熟产品数据优化 |
| 用户痛点挖掘 | 技术可行性评估 |
| 产品定位验证 | 竞品功能对比 |
| 用户行为理解 | 市场进入策略 |
