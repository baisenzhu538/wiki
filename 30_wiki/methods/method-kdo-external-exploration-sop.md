# KDO 外部探索标准操作流程 v2（OSCAR 注入版）

> **一句话**：v2 用一堂 OSCAR 的 O/S/C 三步补齐了旧版"前轻"的短板——在搜索之前先锁定目标、缩小范围、罗列清单，同时保留 KDO 原有的六层比对+四路 Attacker 后端验证能力。

---

## v1 → v2 变更摘要

| 维度 | v1（旧） | v2（新） |
|:---|:---|:---|
| 步数 | 5步 | 6步（O/S/C/A/R/出诊断） |
| O 目标锁定 | 无 | ✅ 四类型判断 + "了解一下"拒绝门控 |
| S 层面意识 | "选方向"无层面标注 | ✅ 四层面标注 + 剥离清单 |
| C 执行清单 | 无 | ✅ 关键词清单 + 门控条件 |
| A 获取手段 | web_search | ✅ 公开+半公开，13武器调用 |
| R 归因 | 已有 | 保留，加 OSCAR 归因四步法引用 |

---

## 六步流程

### Step 0：锁定目标（O）← 新增

**做什么**：在搜索之前，先明确本次外部探索要回答什么决策问题。

**操作**：
1. 写核心决策问题（一句话）——"这次探索要回答的问题是：____？"
2. 用四种类型分类：

| 目标类型 | 判断标准 | 后续策略 |
|:---|:---|:---|
| 选择题 | "从 A/B/C 中选一个" | 构建选项对比表 |
| 解答题 | "为什么 X 发生了？" | 根因分析路径 |
| 设计题 | "如何做出 Y？" | 方案设计 + 验证 |
| 竞争题 | "如何在竞品中突围？" | 竞争分析框架 |

3. **拒绝门控**：如果答案为"了解一下"或"我看看"→拒绝启动。"不了解清楚会影响什么决策？"答不上来→不启动。

**产出**：核心决策问题 + 目标类型。

---

### Step 1：缩小范围（S）← 增强

**做什么**：确定搜索方向，标注层面，写剥离清单。防止"什么都想看"。

**操作**：
1. 确定搜索方向（≤5个），每个标注层面：

| 层面 | 搜索对象 | 时间预算 |
|:---|:---|:---|
| 宏观 | 行业报告、市场规模、政策趋势 | 1-2天 |
| 中观 | 竞品公司、组织架构、产品线 | 2-3天 |
| 微观 | 单元经济模型、用户价值、成本拆解 | 1-2天 |
| 单点 | 关键假设验证、单一问题深挖 | 1-3天 |

2. 写**剥离清单**：明确"本次不搜索什么"。
   - 用"不知道这个信息会做错决策吗？"筛选——不会的砍掉
   - 每发现一条有趣但无关的信息，记入"停车区"而非当场深追

3. **门控检查**：
   - 搜索方向是否 >5 个？→ 缩小
   - 是否跨了两个以上层面？→ 缩小
   - 是否每个方向都有明确层面标注？→ 没有就补

**产出**：搜索方向列表（≤5个，每方向标层面）+ 剥离清单。

---

### Step 2：罗列清单（C）← 新增

**做什么**：为每个搜索方向设计关键词、来源类型、预期产出和门控条件。防止"拿模板套"。

**每方向清单模板**：
```
方向：[名称]，层面：[宏观/中观/微观/单点]

核心关键词：
  - [关键词1] → 用于 web_search 广撒网
  - [关键词2] → 用于深追搜
  - [关键词3] → 用于 Google Dorking

目标来源类型：
  - [官网 / 财报 / 行业报告 / 新闻报道 / 招聘 / 专利 / ...]

预期产出：
  - [具体可检查的产出，如"前3竞品市场占有率数字"]

门控条件：
  - 信息源 ≥3 个独立来源才进入下一阶段
  - 覆盖率 ≥70%（清单关键词都搜到了有效信息）
  - 发现矛盾 → 加搜一轮
```

3. **反模式检查**：清单和上次探索完全一样？→ 重新设计（防止清单僵化）。

**产出**：每方向的搜索清单 + 门控条件。

---

### Step 3：获取情报（A）← 增强

**做什么**：按清单执行搜索，从公开层开始，条件触发半公开层。

**操作**：
1. **公开层（主）**：`web_search` 按清单关键词并行搜索（3-4路），`web_extract` 提取关键页面
2. **半公开层（条件触发）**：当公开信息不足以满足门控条件时触发——招聘信息、专利检索、招投标记录
3. **广撒网 → 深追搜**：
   - 广撒网：3-4 路并行，每路至少 5 条结果
   - 动态饱和制：≥2 独立来源确认 or 1 来源否定 or 搜索无新发现 → 停止
   - 深追搜：对高价值方向精确搜索（行业报告 PDF、财报原文、专利数据）
4. **13武器调用**（按需）：

| 武器 | 用途 | 命令 |
|:---|:---|:---|
| 1 搜索引擎 | 全网信息搜集 | `web_search "query"` |
| 2 行业报告 | 市场数据 | `web_search "行业名 市场报告 PDF"` |
| 3 财报分析 | 财务数据 | `web_search "公司 investor relations"` |
| 4 媒体验证 | 新闻交叉 | 多源搜索同一事件 |
| 8 另类数据 | 招聘/专利 | 见 `references/research-principles.md` |
| 12 Web Scraping | 结构化抓取 | `web_extract "url"` |

5. **门控检查**（Step 3 末尾强制）：
   - 信息源 ≥3 个独立来源？
   - 覆盖率 ≥70%？
   - 不满足 → 不进入 Step 4

**产出**：情报集合（每条标注来源 + URL + 可信度）。

---

### Step 4：正确归因（R）← 保留并增强

**做什么**：将外部获取的情报与 wiki 内部知识交叉验证，用六层比对+四路 Attacker 确认可信度。

**操作**：
1. **交叉比对（vs 30_wiki）**：用 `search_files` 扫 wiki——外部发现是否与已有卡片一致？矛盾点标为"待确认"
2. **六层比对（L1-L6）**：

| 层 | 检查项 | 关键问题 |
|:---|:---|:---|
| L1 可证伪 | 结论能否被证伪？ | "什么证据能推翻这个结论？" |
| L2 行为一致 | 言行是否一致？ | "说的和做的一样吗？" |
| L3 多源 | 多源能否交叉？ | "至少2个独立来源都这么说？" |
| L4 情绪 | 是否有情绪偏差？ | "这个结论有没有被乐观/悲观情绪影响？" |
| L5 时间 | 时效性如何？ | "这个信息是什么时候的？还适用吗？" |
| L6 利益 | 利益是否相关？ | "说这话的人有没有利益冲突？" |

3. **四路 Attacker 并行**（条件触发）：
   - A 逻辑攻击者：结论的推理链有没有漏洞？
   - B 证据攻击者：证据是否充分、来源是否可靠？
   - C 完整性攻击者：有没有遗漏关键视角？
   - D 时效性攻击者：信息是否过时？

4. **准入清单标注**：每条核心发现标注——
   - 🟢 可信：≥2独立来源验证，无利益冲突
   - 🟡 存疑：单一来源或来源有利益关联
   - 🔴 不可信：证据矛盾或来源不可靠
   - ⚫ 无法验证：无可靠来源

5. **跨域桥接**：新发现是否与已有域相关？→ 填入桥接表（新发现 → 已有卡片 ID）

**产出**：带置信度标注的核心发现列表 + 矛盾点清单。

---

### Step 5：出诊断

**做什么**：整合所有验证通过的信息，输出诊断报告和后续生产任务清单。

**诊断报告模板**：
```
# 外部探索诊断报告

## 核心发现
- [发现1] 置信度：🟢/🟡/🔴/⚫
- [发现2] ...

## 证据链
| 发现 | 来源1 | 来源2 | 一致性 |
|:---|:---|:---|:---|
| ... | URL/文件名 | URL/文件名 | ✅/⚠️/❌ |

## 矛盾点
| 矛盾 | A说 | B说 | 判断 |
|:---|:---|:---|:---|

## 与已有知识的关联
| 新发现 | 已有卡片 | 关系（确认/补充/矛盾） |
|:---|:---|:---|

## 待验证项
- [ ] 需要更多来源验证的项目

## 生产任务建议
- [ ] 建议新建卡片：[卡片类型] + [主题]
- [ ] 建议补充卡片：[已有卡ID] + [补充内容]
```

**产出**：诊断报告 + 生产任务清单。

## Constraints & Boundaries

### 适用边界

| 场景 | 适合？ | 说明 |
|:---|:---:|:---|
| KDO 外部知识探索（需要 web_search + wiki 交叉比对） | ✅ | 直接场景 |
| 新域诊断/王语嫣入口质量门的前置调研 | ✅ | Step 0-3 满足 |
| 简单事实查询（如"竞品A的官网"） | ❌ | 用 web_search 直搜 |
| 纯 wiki 内检索 | ❌ | 用 kdo query |
| 紧急响应 | ❌ | 六步太慢 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| 跳过 Step 0 | 没锁定目标就开始搜，方向反复变 | 强制回退到 Step 0——如果核心决策问题写不满一行，不算完成 |
| 剥离清单不执行 | 搜着搜着就偏了，范围越来越大 | Step 1 剥离清单要具体到"本次不看XX公司的YY业务线"这种粒度；中途发现偏离→立刻回剥离清单 |
| 清单套模板 | 每次探索用同一套关键词 | Step 2 反模式检查——和上次清单完全一样？重新设计 |
| 门控当摆设 | 门控条件设了但不检查 | Step 3 末尾强制检查——不满足条件不回 Step 4 |
| 归因偷懒 | 只看一层来源就下结论 | Step 4 强制至少通过 L1+L3 两层，🟢结论必须≥2独立来源 |
| 诊断报告无模板 | 每次格式不同，难以比较 | 使用 Step 5 标准模板 |

## 与"三方法前置门禁"的关系

本 SOP 是王语嫣 context 中"三方法前置"铁律（全网调研→本地检索→已有卡片对齐）的工程化实现——

- **全网调研**：本 SOP Step 0-3
- **本地检索**：本 SOP Step 4 交叉比对（vs 30_wiki）
- **已有卡片对齐**：本 SOP Step 4 跨域桥接表
