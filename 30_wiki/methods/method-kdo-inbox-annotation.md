# Inbox 素材标注方法——老顽童影子诊断三方法

> **一句话**：王语嫣做正式诊断之前，老顽童同步独立跑标注。用三方法（全网调研 + 六层交叉比对 + 九层深挖）逐层穿透素材，产出标注报告。与王语嫣诊断的差异点 = 最该深挖的内容。目标是交叉比对防遗漏，不是替代王语嫣的诊断。

---

## 一、为什么需要影子诊断

王语嫣 context 定义：老顽童独立扫描+标注，差异=该深挖的内容。

| 没有影子诊断时 | 有影子诊断时 |
|:---|:---|
| 只有王语嫣一个视角看素材 | 两个独立视角交叉比对 |
| 漏了关键内容没人发现 | 差异点自动暴露遗漏 |
| 王语嫣排什么老顽童做什么 | 老顽童提前理解素材，生产时更快更深 |

**核心原则**：
- 标注不是诊断——标注是"我看到了什么"，诊断是"应该怎么处理"
- 先独立标注，再对比王语嫣诊断——不要看王语嫣的诊断后再标注
- 差异不一定是错——可能是不同角度，但每个差异都要被解释

## 二、标注三方法总览

```
                     inbox 新素材
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
    方法一：           方法二：          方法三：
   全网调研          六层交叉比对       九层深挖
   (外部对标)        (可信度判断)       (深度穿透)
          │               │               │
          └───────────────┼───────────────┘
                          ▼
                    标注报告
                (含差异标注建议)
```

三方法的关系：
- **全网调研**：先看外面——这个领域有没有通行框架？素材的说法是否与国际共识一致？
- **六层交叉比对**：再看可信度——素材里的说法可靠吗？有没有矛盾？有没有遗漏？
- **九层深挖**：最后穿透——素材表面之下还有什么？失败模式？隐性成本？暗知识？

---

## 三、方法一：全网调研——素材外部对标

### 做什么

在理解素材之前，先搜一下：这个主题在外面是怎么讲的？素材的说法有没有独立验证？

### 操作

```
Step 0：提取素材中的核心主张（3-5条）
  → 每条写"素材说：____"
  
Step 1：对每条核心主张做 web_search
  → 搜索格式："[核心主张关键词] + 研究/报告/案例"
  
Step 2：动态饱和判断
  → ≥2 个独立来源确认 → ✅ 可信任
  → 无独立来源 → ⚠️ 标记"待外部验证"
  → 有来源但矛盾 → 🔴 标记"需交叉验证"
  
Step 3：发现外部框架
  → 素材的方法论是否对应国际通行框架？
  → 如有→标注"已对标：[框架名]"，说明异同
  → 如无→标注"🆕 无外部对标，可能是原创方法论"
```

### 标注输出示例

```markdown
## 全网调研

### 核心主张外部验证
| 素材主张 | 外部验证结果 | 来源 |
|:---|:---|:---|
| [主张1] | ✅ 已确认 | [来源1], [来源2] |
| [主张2] | ⚠️ 无独立验证 | — |
| [主张3] | 🔴 与外部矛盾 | [来源3]说相反 |

### 外部框架对标
- 素材方法论 [X] ↔ 国际框架 [Y]：[异同说明]
- 素材方法论 [Z] ↔ 无外部对标 → 可能是原创，标注为 🔑 重点关注
```

## 四、方法二：六层交叉比对——素材可信度判断

### 做什么

不轻信素材里的任何说法。从六个维度逐层验证信息的可信度。来自 `framework-yitang-six-layer-cross-validation`。

### 六层检查

| 层 | 检查项 | 关键问题 | 标注动作 |
|:---|:---|:---|:---|
| **L1 来源** | 谁说的？ | 说话人的身份、立场、利益关系是什么？ | 标注来源可信度：🟢高/🟡中/🔴低 |
| **L2 时间** | 什么时候？ | 信息是多久前的？还适用吗？ | 标注时效性：新鲜/可用/过时 |
| **L3 逻辑** | 说得通吗？ | 结论和证据之间有没有跳步？有没有替代解释？ | 标注逻辑漏洞位置 |
| **L4 数据** | 数字可靠吗？ | 数字怎么来的？样本量多少？有没有选择性报告？ | 标注数字可信度 + 缺失数据 |
| **L5 反例** | 有没有反例？ | 有没有相反的证据被忽略了？失败案例在哪里？ | 标注缺失的反面证据 |
| **L6 行动** | 能落地吗？ | 这个信息能指导什么具体行动？还是只能"增加认知"？ | 标注可操作性：可直接行动/需补充/纯认知 |

### 标注输出示例

```markdown
## 六层交叉比对

| 层 | 判定 | 证据 | 风险 |
|:---|:---:|:---|:---|
| L1 来源 | 🟡 | 讲师口述，非独立第三方 | 可能有自利偏差 |
| L2 时间 | 🟢 | 2026年6月分享，新鲜 | — |
| L3 逻辑 | 🟡 | 结论有跳步——从"我们做了X"跳到"X有效"，缺对照 | 因果推断脆弱 |
| L4 数据 | 🔴 | 提到"效率提升"但无数值 | 关键数据缺失 |
| L5 反例 | 🔴 | 全文无失败案例 | 幸存者偏差风险高 |
| L6 行动 | 🟢 | 有可复用的4步流程 | — |

### 交叉比对结论
- 整体可信度：🟡 中等（来源非独立 + 无失败案例）
- 最薄弱层：L5 反例——建议王语嫣诊断时追问失败案例
- 可直接行动的部分：4步流程可复用（L6 ✅）
```

## 五、方法三：九层深挖——素材深度穿透

### 做什么

不只看素材表面说了什么，逐层往下挖：业务公式 → 假设 → 边界 → 失败模式 → 隐性成本 → 组织能力 → 竞争动态 → 二阶效应 → 决策框架。来自 `framework-yitang-nine-layer-deep-dig`。

### 标注时至少过前四层

| 层 | 检查什么 | 标注问题 | 标注输出 |
|:---|:---|:---|:---|
| **L1 业务公式** | 核心商业逻辑 | 素材里的业务模型是什么？收入=什么×什么？ | 提取或标注"缺失" |
| **L2 假设审计** | 隐含假设 | 素材里的结论建立在什么假设上？这些假设可靠吗？ | 列出假设 + 可靠度 |
| **L3 政策/边界** | 外部约束 | 素材讨论的范围边界在哪？哪些情况不适用？ | 标注适用边界 |
| **L4 失败模式** | 怎么死的 | 素材提到过失败案例吗？如果没提，可能怎么失败？ | 标注失败模式（含缺失警告） |
| **L5 隐性成本** | 没算的账 | 素材有没有漏算的成本？（时间/学习/切换/维护） | 标注隐性成本 |
| **L6 组织能力** | 谁能做 | 素材里的方法对组织有什么要求？多少人、什么技能？ | 标注组织依赖 |
| **L7 竞争动态** | 对手反应 | 如果对手也做了同样的事会怎样？先发优势能持续吗？ | 标注竞争脆弱性 |
| **L8 二阶效应** | 副作用 | 这样做下去会产生什么非预期的后果？ | 标注二阶风险 |
| **L9 决策框架** | 做不做 | 看完以上八层，go/no-go 的决策条件是什么？ | 标注决策框架 |

### 标注输出示例

```markdown
## 九层深挖

| 层 | 素材覆盖 | 标注 |
|:---|:---:|:---|
| L1 业务公式 | ✅ | 收入=曝光×点击率×转化率×客单价。链条完整 |
| L2 假设审计 | ⚠️ | 假设"点击率=行业平均"，未验证。🔑 待深挖 |
| L3 边界 | ❌ | 未讨论什么情况下这个方法不适用。🔑 缺口 |
| L4 失败模式 | ❌ | 全文只讲成功路径。🔑 重大缺口——建议王语嫣追问"你试过哪些没成功的？" |
| L5 隐性成本 | ❌ | 未提及学习成本、工具切换成本。标注缺口 |
| L6-L9 | ❌ | 未覆盖 |

### 深挖结论
- 素材深度：停在 L1-L2，缺 L3 以上
- 最大缺口：L4 失败模式——这是暗知识的主要来源
- 建议王语嫣深挖方向：L3 边界 + L4 失败模式 + L5 隐性成本
```

## 六、第四步：已有卡片交叉比对

### 做什么

标注完素材本身后，查 wiki：素材里的每个关键概念，有没有对应的已有卡片？

### 操作

```
对每条关键发现：
  → kdo query "<关键词>" --limit 5
  → search_files 全文搜 wiki
  
标注与已有卡的关系：
  → ✅ 确认：素材和已有卡说法一致，互为印证
  → ➕ 补充：素材提供了已有卡没有的内容（具体是什么？）
  → ⚠️ 矛盾：素材和已有卡说法不一致（哪里不一致？）
  → 🆕 缺口：完全新内容，没有对应卡
```

### 标注输出示例

```markdown
## 已有卡片交叉比对

| 素材关键点 | 已有卡片 | 关系 | 说明 |
|:---|:---|:---:|:---|
| 4步蒸馏法 | method-yihang-human-self-distillation | ✅ 确认 | 素材是已有卡的来源，一致 |
| 工具升级陷阱 | dk-ai-collaboration-degradation-spiral | ✅ 确认 | 素材案例已在卡的模式3中 |
| 正例反例对 | — | 🆕 缺口 | 素材给了3组具体正反例，已有卡没收录这些例子 → 建议补 |
| 多partner工位设计 | method-kdo-agent-design-meta | ➕ 补充 | 素材的5工位比已有卡的描述更具体 |
```

## 八、标注 vs 诊断的区别

| 维度 | 老顽童标注（本卡） | 王语嫣诊断 |
|:---|:---|:---|
| 目标 | 发现、标记、比对 | 定方向、定优先级、定任务 |
| 深度 | 至少过 L1-L4 | 完整七步诊断 |
| 产出 | 标注报告 + 卡片候选建议 | 诊断报告 + 任务单 + 入队 |
| 决策 | 不提"应该做什么" | 决定做不做、谁来做、什么时候做 |
| 边界 | 不替王语嫣做判断 | 最终方向把关 |

---

## Constraints & Boundaries

- **标注不是诊断**：标注只回答"看到了什么"，不回答"应该怎么办"
- **先独立标注再对比**：如果先看了王语嫣的诊断再标注，影子诊断就失效了
- **差异不等于错**：和王语嫣标注不一致的地方，标注为"差异点"而非"王语嫣错了"
- **不标注纯个人笔记/内部行政文档**：只标注有知识提取价值的素材

### 失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| 标注太浅 | 只有 L1 业务公式，没有往下挖 | 强制至少到 L4，L4 空白就标"🔴 重大缺口" |
| 只看 wiki 不搜外网 | 已有卡片交叉比对做得好，但没有外部对标 | 每条核心主张必须先 web_search 再写标注 |
| 标注=复述 | "素材说要做X"——没有自己的判断 | 每条标注必须有"为什么标注这一条"的理由 |
| 和王语嫣完全一致 | 没有独立思考 | 检查：是不是先看了王语嫣的诊断？ |
