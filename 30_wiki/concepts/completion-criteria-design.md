# 完成标准设定

> 在学一个新能力之前，先定义「学会」的 3 条具体标准。没有标准，学习就没有终点。

## Summary

很多人学一个工具学到一半就放弃，或者学了很久还觉得自己「不会」，根本原因是没有提前定义「学会」是什么。

完成标准设定的核心规则：**把「学会」「掌握」这种虚词，换成「能做 X」「能判断 Y」这种可验证的描述。**

标准模板包含三个维度：
1. **能做什么**：我能用它独立完成什么任务
2. **边界判断**：我能说清它不适合什么场景
3. **产品化**：我能判断它在产品里的集成位置或价值

## The Three Dimensions

| 维度 | 问题 | 示例 |
|:---|:---|:---|
| **能做什么** | 学会后，我能独立完成什么任务？ | "能用它独立完成一张海报的文字替换" |
| **边界判断** | 什么场景下不该用它？ | "不适合需要精确排版的高端印刷物料" |
| **产品化** | 在产品里它应该放哪？ | "适合放在运营后台的批量素材生成环节" |

## Core Claims

### claim:01 [conf=0.85] 没有完成标准的学习是开放式的，容易产生焦虑

如果不知道「什么时候算学完」，每次学习都没有完成感，会一直在「我还没学会」的状态里打转。

### claim:02 [conf=0.80] 完成标准必须具体到可勾选

「掌握这个工具」不是完成标准，因为它无法验证。「能用它独立完成 X 任务」才是。

### claim:03 [conf=0.80] 完成标准在学习开始前设定，而不是学完后补

学完后补的标准容易被结果扭曲。提前设定，才能保证学习过程围绕目标进行。

## Usage Template

```markdown
## 学会 [工具名] 的 3 条完成标准

1. **能做什么：** 我能用它独立完成 _____________。
2. **边界判断：** 我能说清它不适合 _____________ 场景。
3. **产品化：** 我能判断它在产品里的集成位置是 _____________。
```

## 目的

完成标准设定解决的核心问题是：**把"学会""掌握"这种虚词，换成"能做 X""能判断 Y"这种可验证的描述**。大多数人学一个工具学到一半就放弃，或者学了很久还觉得自己"不会"，根本原因是没有提前定义"学会"是什么。

适用场景：
- 任何需要明确学习终点的场景
- 用户说"不知道学到什么程度算学会了"
- 作为 AI 差距分析的评估依据
- 开始学新工具之前（提前设定标准）

## 操作步骤

1. **学之前先写 3 条完成标准**：用模板（能做什么 / 边界判断 / 产品化）写下"学会这个工具"的 3 条具体标准。这时候写的标准可能不准确，但没关系——重要的是"先有标准"。
2. **学习过程中对照标准**：每学一个功能/模块，问自己"这对完成标准有贡献吗？"如果不在完成标准里，可能是次要功能，可以跳过或略读。
3. **学完后打勾或修正**：如果能完成这 3 条标准，就"学会了"。如果标准定得太高/太低，修正它（但不要学完后补标准——那样会被结果扭曲）。

## 不要用的场景

- **探索性、无明确目标的学习**：如果学习目标本身就是"看看这个工具能做什么"，强行设定完成标准会限制探索。先探索，等有明确方向后再设定标准。
- **标准太虚**：如果完成标准写成"掌握这个工具""熟练使用"，这不是完成标准，这是模糊的目标。必须强制换成"能做 X""能判断 Y"。
- **标准不现实**：如果第一条标准就是"达到专家水平"，这不符合当前阶段。按当前阶段设定可实现标准（例如"能用它独立完成 X 任务"而非"能用它解决所有问题"）。
- **一次写太多标准**：超过 5 条标准会难以验证，也容易偏离核心。只保留 3 条最核心的。

## 质疑


**Clayton Christensen**（哈佛商学院教授）会质疑：现有方法论框架的有效性依赖于环境稳定性——当环境发生颠覆性变化时，旧框架不仅无效，还可能误导。
### 内部局限

完成标准设定假设"只要提前定义标准，学习就会更高效"。但实际上，很多学习过程本身就会改变"什么是学会"的定义——你学之前觉得"能跑通 demo"就算学会，学完发现"能跑通 demo"只是起点。提前设定的标准可能会限制学习的自然演化。

另外，完成标准设定是"闭门造车"——你自己定义的标准，可能和真实业务场景需要的"学会"不一样。更好的做法是：先找 3 个真实业务场景，再看"学会"需要什么能力。

### **徐玲**（《得到》总编辑）——"完成标准设定忽视了学习的非线性特征"

完成标准设定隐含了一个假设：学习是"线性累积"的——你设定标准，然后朝着标准前进，达到标准就"学会了"。但真实的学习是"非线性"的——你可能突然顿悟，可能长期停滞，可能在某个点上反复跌倒。

更重要的是：完成标准设定是"结果导向"的，但它忽视了"学习过程本身的价值"。有些学习，即使没有达到预设标准，过程中的思考、试错、失败也是有价值的。过度强调"完成标准"可能会让人急于求成，跳过有价值的"迷失"过程。

**当用这张卡的人睡不着觉时**：他们会想——"我达到了自己设定的 3 条标准，但为什么还是觉得'没学会'？是不是我的标准定得太低了？还是'学会'本身就是一个无法标准化的概念？"

**前提与边界**：完成标准设定的**前提**是"学会"可以被明确定义且线性分解。**边界**：适用于技能型学习（如编程、写作），不适用于探索型学习（如创意、战略判断）。**反例**：一个产品经理设定"学会 SQL = 能写 JOIN 查询"，但实际工作中需要的"学会"还包括性能优化、索引设计等——预设标准反而限制了学习范围。
