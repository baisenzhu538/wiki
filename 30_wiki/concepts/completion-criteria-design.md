# 完成标准设定

> 在学一个新能力之前，先定义「学会」的 3 条具体标准。没有标准，学习就没有终点。

## Summary

很多人学一个工具学到一半就放弃，或者学了很久还觉得自己「不会」，根本原因是没有提前定义「学会」是什么。

完成标准设定的核心规则：**把「学会」「掌握」这种虚词，换成「能做 X」「能判断 Y」这种可验证的描述。**

标准模板包含三个维度：
1. **能做什么**：我能用它独立完成什么任务
2. **边界判断**：我能说清它不适合什么场景
3. **产品化**：我能判断它在产品里的集成位置或价值

## The Three Dimensions

| 维度 | 问题 | 示例 |
|:---|:---|:---|
| **能做什么** | 学会后，我能独立完成什么任务？ | "能用它独立完成一张海报的文字替换" |
| **边界判断** | 什么场景下不该用它？ | "不适合需要精确排版的高端印刷物料" |
| **产品化** | 在产品里它应该放哪？ | "适合放在运营后台的批量素材生成环节" |

## Core Claims

### claim:01 [conf=0.85] 没有完成标准的学习是开放式的，容易产生焦虑

如果不知道「什么时候算学完」，每次学习都没有完成感，会一直在「我还没学会」的状态里打转。

### claim:02 [conf=0.80] 完成标准必须具体到可勾选

「掌握这个工具」不是完成标准，因为它无法验证。「能用它独立完成 X 任务」才是。

### claim:03 [conf=0.80] 完成标准在学习开始前设定，而不是学完后补

学完后补的标准容易被结果扭曲。提前设定，才能保证学习过程围绕目标进行。

## Usage Template

```markdown
## 学会 [工具名] 的 3 条完成标准

1. **能做什么：** 我能用它独立完成 _____________。
2. **边界判断：** 我能说清它不适合 _____________ 场景。
3. **产品化：** 我能判断它在产品里的集成位置是 _____________。
```

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:---|
| ✅ 适合 | 任何需要明确学习终点的场景 |
| ✅ 适合 | 用户说"不知道学到什么程度" |
| ✅ 适合 | 作为 AI 差距分析的评估依据 |
| ❌ 不适合 | 探索性、无明确目标的学习 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| **标准太虚** | "掌握""学会" | 强制换成"能做 X" |
| **标准太多** | 一次写 10 条 | 只保留 3 条最核心的 |
| **标准不现实** | 第一条就是"达到专家水平" | 按当前阶段设定可实现标准 |

## Action Triggers

| 触发场景 | 第一个动作 |
|:---|:---|
| 用户开始学新工具 | 先写 3 条完成标准 |
| 用户说"不知道学会了没" | 回头看完成标准，打勾 |
| 用户做 AI 差距分析 | 让 AI 评估完成标准是否合理 |
