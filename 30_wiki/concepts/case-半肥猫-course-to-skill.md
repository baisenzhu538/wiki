# 案例：半肥猫把一堂课程转化为AI Skill——八步工作流与12维度评分标准

## 原始表述

半肥猫在AI俱乐部分享中说："我最近在做的一件事情就是试图把一堂的课程做成一个Skill。我拿到一个老师的授权，把他的课程做成一个Skill。在做的过程中，会发现特别多问题……然后我就会想怎么让这些内容不要做错，比如什么样的Skill值得做，什么样的Skill不值得做，有没有一些检测标准。"

## 问题

半肥猫拿到一堂「转化率黑客」课程的官方授权测试，尝试将其转化为可复用的AI Skill。核心难题在于：

1. **课程转Skill不是搬运内容**——把课程讲义喂给AI不等于Skill。裸模型自己就能读课程，Skill的价值在哪里？
2. **缺乏验收标准**——怎么判断一个Skill做得好还是不好？没有评分维度，就无法迭代优化。
3. **高危场景风险**——如果Skill被用在保险、医疗等高风险领域，出错代价极高，必须有边界守护能力。
4. **证据纪律缺失**——课程内容本身是"老师的主张"，不是"经过验证的事实"，直接转化为Skill会放大误导。

## 方案

半肥猫设计了一套完整的「课程→Skill」转化流程和评分标准：

### 八步工作流

| 步骤 | 动作 | 关键产出 |
|:---|:---|:---|
| 1. 判断值不值得做 | 评估课程是否适合做成Skill（触发范围、用户场景明确度） | 通过/放弃决策 |
| 2. 整理课程主线 | 把课程结构化输出为Markdown，清理噪音 | 结构化课程笔记 |
| 3. 抽取案例/问答/行业应用 | 识别课程中的具体案例、常见问答、行业场景 | 素材清单 |
| 4. 方法变诊断协议 | 把课程方法转化为"适用场景+评分规则+风险分级" | 诊断协议 |
| 5. 证据校准+课程主张审查 | 区分课程中哪些是事实、哪些是老师观点、哪些需要用户补充验证 | 证据质量报告 |
| 6. 搭技能目录框架 | 按功能模块组织Skill指令结构 | Skill框架PRD |
| 7. 测试 | 5个正向场景+5个反向场景+1个高风险场景 | 测试得分表 |
| 8. 维护 | 版本号+反馈收集模板+回归测试流程 | 维护手册 |

### 12维度评分标准（0=无能力/1=弱/2=可接受/3=强）

| 维度 | 含义 | 正常场景裸模型 | Skill | 高风险场景裸模型 | Skill |
|:---|:---|:---|:---|:---|:---|
| 触发范围 | 能否正确识别场景适用边界 | 1 | 3 | 1 | 3 |
| 结论明确 | 给出的建议是否清晰、可操作 | 1 | 3 | 1 | 3 |
| 场景拆解 | 能否细化到具体业务场景 | 1 | 3 | 1 | 3 |
| 技术路径 | 是否给出具体执行步骤 | 1 | 3 | 1 | 3 |
| 风险识别 | 是否提示潜在风险 | 0 | 3 | 0 | 3 |
| 拒绝能力 | **在不适合的场景下是否明确拒绝** | **0** | **3** | **0** | **3** |
| 证据纪律 | 是否标注数据来源、区分事实与观点 | 0 | 2 | 0 | 2 |
| 评分MVP | 是否能在极简输入下给出有效评分 | 1 | 3 | 1 | 3 |
| 可维护性 | 结构是否清晰、易于迭代 | 1 | 3 | 1 | 3 |
| 复用性 | 是否能迁移到同类场景 | 1 | 3 | 1 | 3 |
| 用户反馈 | 是否有明确的反馈收集入口 | 0 | 2 | 0 | 2 |
| 版本追踪 | 是否标注版本号和迭代记录 | 0 | 2 | 0 | 2 |
| **总分** | | **8** | **36** | **9** | **36** |

### 核心发现：最大差异在"拒绝能力"

正常场景下，裸模型8分 vs Skill 36分（差距28分）；高风险场景下，裸模型9分 vs Skill 36分（差距27分）。12维度中，**"拒绝能力"是裸模型的最大短板**——裸模型为了"讨好"用户，在不适合的场景下会说"做吧做吧"；而Skill会明确告知"不要做，换方案"。

### 证据质量原则

半肥猫要求Skill在引用时必须标注信源和出处，禁止使用三类内容：
- 自媒体营销软文
- 无法核实的媒体报道
- 未经训练的AIGC生成内容

优先使用：官方来源、研究机构报告、企业官网数据。

## 可迁移

**这个案例可以复用的条件**：

1. 你有一门体系化的课程/方法论，内容结构化程度较高
2. 你有明确的用户场景和使用边界（知道谁会在什么情况下用）
3. 你有能力区分"课程主张"和"可验证事实"
4. 你愿意投入时间做多轮测试（正向+反向+高风险），而不是写完就上线

**不能近乎复制的场景**：

- 课程内容本身缺乏结构（只有零散观点，没有方法论）
- 没有明确的使用场景和边界（"通用工具"往往是伪需求）
- 你默认课程里的内容都是对的，不做证据审查
- 你需要快速上线，没有时间做测试和迭代

**关键转折点**：

> Skill相比裸模型的最大价值差异，不在内容生成，而在**边界守护与拒绝能力**。
