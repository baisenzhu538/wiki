# 增长黑客：低成本快速实验

> 一堂五步法：增长黑客不是找漏洞，而是系统性的低成本快速实验。核心：假设→实验→数据→迭代。

## 核心框架

增长黑客的PDCA循环：

```
Plan（假设）→ Do（实验）→ Check（数据）→ Act（迭代）
```

| 步骤 | 行动 | 关键 |
|:---|:---|:---|
| **Plan** | 提出可验证的增长假设 | 假设具体、可衡量 |
| **Do** | 设计最小化实验 | 低成本、快速 |
| **Check** | 收集和分析数据 | 统计显著性 |
| **Act** | 迭代或放弃 | 快速决策 |

## 关键洞察

### 1. 增长假设的提出

| 假设类型 | 说明 | 示例 |
|:---|:---|:---|
| **渠道假设** | 某个渠道能有效获客 | "小红书能带来1000个注册用户" |
| **产品假设** | 某个功能能提升留存 | "添加推送能提升次日留存10%" |
| **定价假设** | 某个定价能提升收入 | "年付折扣能提升付费率20%" |
| **体验假设** | 某个优化能提升转化 | "简化注册能提升注册率15%" |

### 2. 实验设计原则

| 原则 | 说明 | 注意 |
|:---|:---|:---|
| **最小化** | 最小成本验证假设 | 不要过度投入 |
| **快速** | 实验周期短 | 1-2周 |
| **可衡量** | 有明确的指标 | 数据驱动 |
| **可对比** | 有对照组 | A/B测试 |
| **可迭代** | 实验结果能指导下一步 | 学习导向 |

### 3. 实验类型

| 类型 | 说明 | 适用 | 示例 |
|:---|:---|:---|:---|
| **A/B测试** | 对比两个版本 | 页面优化 | 按钮颜色 |
| **多变量测试** | 测试多个变量 | 复杂优化 | 页面+文案+价格 |
| **灰度发布** | 小范围发布 | 功能发布 | 新功能5%用户 |
| **用户访谈** | 深入了解用户 | 需求验证 | 5个用户访谈 |
| **数据挖掘** | 从数据中发现机会 | 机会识别 | 用户行为分析 |

### 4. 实验优先级

| 优先级 | 标准 | 排序 |
|:---|:---|:---|
| **影响力** | 实验对增长的潜在影响 | 高→优先 |
| **信心** | 对假设的信心 | 高→优先 |
| **容易度** | 实验的实施难度 | 低→优先 |
| **ICE评分** | 影响力×信心×容易度 | 高→优先 |

### 5. 增长黑客的工具箱

| 工具 | 说明 | 用途 |
|:---|:---|:---|
| **Google Analytics** | 网站分析 | 流量分析 |
| **Mixpanel** | 用户行为分析 | 漏斗分析 |
| **Optimizely** | A/B测试 | 实验平台 |
| **Hotjar** | 用户行为记录 | 热力图、录屏 |
| **Amplitude** | 产品分析 | 留存分析 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **假设不清晰** | 实验没有明确假设 | 明确假设 |
| **实验不最小化** | 实验成本过高 | 最小化实验 |
| **数据不显著** | 样本量不足 | 增加样本量 |
| **忽视对照组** | 没有对照组 | 设计对照组 |
| **实验后不迭代** | 实验结果不应用 | 快速迭代 |
| **随机实验** | 没有系统性 | 建立实验流程 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 增长优化 | 技术架构设计 |
| 产品优化 | 品牌传播策略 |
| 低成本实验 | 大规模投入决策 |
| 数据驱动决策 | 纯直觉决策 |

## 行动触发器

- 当增长停滞时 → 设计增长实验
- 当预算有限时 → 最小化实验
- 当不确定时 → A/B测试验证
- 当优化时 → 数据驱动迭代
