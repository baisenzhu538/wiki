# P-10：口头禁令 vs 书面约束——审查意见必须落笔到任务文件

## 原始表述

> **症状**：欧阳锋在审查老顽童 Batch 2+3 时口头说"后续 Batch 全面封禁 Kahneman 和 Taleb"。用户问"禁令指什么？"——任务文件里根本没有这条。口头意见与书面指令脱节，造成执行者和决策者之间的信息不对称。
>
> **根因**：审查者在对话中产出了约束性意见，但没有同步写入任务文件（唯一真相源）。口头指令在换 session 后丢失，且执行者无法核实。
>
> **对策**：
> - **所有约束性指令必须写入任务文件，口头审查只能是讨论**
> - 审查意见要分"观察"和"指令"两类，指令类必须当场写入 task 文件
> - 任务文件是唯一真相源——如果任务文件里没有，就等于不存在
> - 具体案例：最终改为写入任务文件的软约束"同一域内，每5张卡至少引入1位新攻击者"

## 使用场景

- 你在审查他人工作时产生了约束性意见（如"不准再用 X"、"以后必须 Y"）
- 你作为执行者，听到审查者口头说了某条规则，但任务文件里没有
- 你在换 session 后需要确认之前审查的约束是否仍然有效
- 你设计审查流程时，需要确保口头意见能够被追溯和执行

## 操作方法

1. **审查时分类意见**：每次审查后，将意见分为"观察"（可采纳的建议）和"指令"（必须执行的约束）
2. **指令当场落笔**：对于"指令"类意见，审查者必须在当场编辑任务文件，将约束写入书面形式
3. **执行者核实**：如果任务文件里没有某条约束，执行者可以（应该）质疑它的有效性——"任务文件里没有的就等于不存在"
4. **换 session 时检查**：每次启动新 session 时，先读任务文件，确认所有约束都在书面上
5. **审查者自检**：如果觉得自己说了"重要的话"，问自己"这句话写进任务文件了吗？"

## 适用边界

- 适用于所有涉及审查-执行流程的场景
- 不适用于非约束性的随意讨论（如"这个写得不错"）——这些不需要落笔
- 如果审查是实时进行的（同一 session 内），口头意见可能不会丢失，但仍建议落笔以便追溯
- 用户在对话中的随口指示也应当成"指令"——如果它具有约束性，必须写入任务文件
- 任务文件不是"备忘录"，而是"唯一真相源"——这是认知上的根本转变

## 为什么值钱

- 这是多 Agent 协作项目特有的沟通问题：**每个 session 都是独立的工作者，没有跨 session 的记忆**
- "口头意见与书面指令脱节"是最消耗信任的失败模式：执行者执行了 A，但审查者说的是 B，最后发现谁都没错但就是不对
- 揭示了一个更深层的组织原理：**"写下来"是消除信息不对称的唯一有效方式**——人脑的短期记忆不可靠
- 任何 AI 训练语料中都不会有"KDO 项目的任务文件是唯一真相源，口头指令无效"这条知识
