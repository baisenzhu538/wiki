# 单元模型搭建五步法

> 来源：一堂五步法·单元模型篇 | [[yt-unit-model-concept]] | [[yt-unit-model-ladder]] | [[yt-unit-model-selection]] | [[yt-market-size-estimation]] | [[case-unit-model-gashapon]]

## Summary

单元模型搭建五步法是将抽象的"单元模型"概念落地为**可复制的分析流程**。通过"找单元→列收入→清成本→验数据→做预判"五个步骤，帮助业务一号位从"不算账"（L1）进阶到"动态预判"（L5）。

## Claims

### 步骤一：找到最小可复制单元

**目标**：找到业务最小的可独立运营单元，而不是公司整体。

| 业务类型 | 单元示例 | 关键问题 |
|:---|:---|:---|
| 零售/餐饮 | 单店/单门店 | 这家店是否赚钱？ |
| 自动售货机 | 单台设备 | 这台机器是否赚钱？ |
| 电商 | 单SKU | 这个 SKU 是否赚钱？ |
| SaaS | 单用户 | 获取一个用户能赚多少？ |
| 教育 | 单班级/单课程 | 这门课是否赚钱？ |

**常见错误**：选择的单元过大（如整个城市）或过小（如单次交易），导致无法复制。

### 步骤二：列出所有收入项

**收入分类**：
1. **主营收入**：核心产品/服务的直接收入
2. **次营收入**：配套产品、增值服务收入
3. **间接收入**：广告、数据、交易佣金等

**关键原则**：收入项必须**可量化**、**可验证**。"感觉会有"不等于"会有"。

### 步骤三：清理所有成本项

**成本分类**：

| 成本类型 | 具体项目 | 常见忽略项 |
|:---|:---|:---|
| **变动成本** | 原材料、制造、物流 | 损耗、废品、返货 |
| **固定成本** | 租金、工资、设备折旧 | 空置期成本、设备维护 |
| **营销成本** | 广告、推广、渠道佣金 | 品牌建设、用户教育 |
| **组织成本** | 人员招聘、培训、管理 | 沟通成本、决策效率损失 |
| **财务成本** | 税费、资金占用 | 应收账期、现金流压力 |

### 步骤五：做动态预判

**三种变化**：
1. **规模变化**：扩大后租金、人工、采购成本如何变化
2. **外部变化**：竞争、政策、技术变化对模式的影响
3. **业务变化**：产品升级、渠道变化、用户结构变化

## Critique

### 外部攻击：Clayton Christensen（破坏性创新与第三市场）

Christensen 的破坏性创新理论认为，很多成功企业之所以失败，不是因为单元模型不好，而是因为**它们的单元模型太好**了——它们不愿意放弃高利润的现有业务去抢占低利润的新市场。单元模型分析是静态的，但企业的持续成功需要在**新旧业务单元模型冲突**时做出正确选择。

### 外部攻击：Josh Kaufman（个人 MBA 与商业知识类别）

Kaufman 在《个人 MBA》中提出，商业模式分析有**四个维度**：价值创造、价值交付、价值捕获、价值增值。五步法的单元模型偏重"收入-成本"财务视角，对于"价值交付过程"和"价值体验"的分析不足。一个"财务上正向"的单元模型，如果交付过程体验差，可能导致高流失率。

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:------|
| ✅ 适合条件 | 需要量化商业模式验证的创业团队、从0到1阶段需要算清盈利性的业务、有至少3-6个月运营数据可供参考的场景 |
| ❌ 不适合条件 | 纯概念阶段没有任何数据支撑、非营利组织、主营业务为一次性大额交易而非可复制单元的业务 |
| 阶段边界：0→1验证期最佳 | 在单点模型未跑通前，五步法用于"验证是否值得继续投入"；进入规模化扩张期后，应升级为动态模型并配合 [[yt-unit-model-selection]] 选择主模型 |
| 数据边界：≥3个核心参数有真实数据 | 获客成本、转化率、客单价/毛利率、复购率等核心参数中，至少3项来自真实测试或行业可靠对标，否则模型只是"精确包装的猜测" |

#| 模式 | 症状 | 修复 |
|:-----|:------|:------|
| **搭建了但算不准** | 单元模型结构完美，但关键参数（获客成本、生命周期、转化率）靠拍脑袋填充。模型输出漂亮，但和实际业务对不上 | 在模型旁附加"参数可信度标注"：每个参数标注数据来源（实测/行业对标/猜测），并做敏感性分析——识别对最终结果影响最大的3个参数，优先验证它们 |
| **遗漏关键成本项** | 模型只算了直接成本（原材料、人力），遗漏了间接成本（管理损耗、退货率、创始人时间、融资成本），导致表面盈利实际亏损 | 建立"成本补丁清单"：在模型搭建完成后，用创始人时间、管理损耗、退换货率三个补丁做二次检查 |
| **单元选得过大或过小** | 单元选成"整个城市"无法复制，选成"单次交易"无法独立运营 | 用两个标准检验：①可独立运营（不依赖其他单元也能算出盈亏）②可复制（同一单元能在不同场景重复运行） |
| **把静态模型当动态预测** | 用当前单店/单台数据直接外推100店/100台利润，忽略租金议价能力下降、管理成本指数上升、竞争加剧导致的转化率下滑 | 先做"规模压力测试"：把核心成本项按+10%、+20%、+30%三档上调，核心收入项按-10%、-20%、-30%三档下调，看哪个情景下模型会先崩；找到崩盘点后，把它作为扩张前的必解问题 |

## 单元模型搭建检查清单

在把五步法交付给团队或投资人前，用以下 10 项逐项自检：

| 检查项 | 通过标准 | 常见失败 |
|:---|:---|:---|
| 1. 最小单元已界定 | 能用一句话说清楚"复制哪个算哪个" | 单元过大（整个城市）或过小（单次交易） |
| 2. 收入项可量化 | 每项收入都有计算公式和数据来源 | "感觉会有广告收入"但没有CPM/DAU假设 |
| 3. 成本项≥10条 | 变动+固定+营销+组织+财务五类成本均已列出 | 只列原材料和人力 |
| 4. 隐形成本已补丁 | 创始人时间、管理损耗、退换货率至少检查过 | 表面盈利实际亏损 |
| 5. 参数有可信度标注 | 每个核心参数标注实测/对标/猜测 | 所有参数都是拍脑袋 |
| 6. 三点预测非形式 | 乐观/合理/悲观三种情景参数差异≥30% | 三情景差别只在"希望值" |
| 7. 规模变量已识别 | 列出扩大10倍后至少3个会非线性变化的成本/收入项 | 静态外推 |
| 8. 崩盘点已找到 | 能回答"在什么参数组合下模型不成立" | 只说"我们最悲观也能活" |
| 9. 主模型已选择 | 在多单元业务中明确"哪个单元是决策主模型" | 单订单/单客户/单门店混用 |
| 10. 下一步行动明确 | 模型输出直接对应一个"go/no-go/再验证"决定 | 模型写完没有决策结论 |

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|---------|-----------|---------|
| 要评估新业务机会 | 用五步法搭建单元模型，做三点预测 | 明确最悲观情景下仍然可行 |
| 业务扩张前 | 验证新场景下的单元模型 | 新场景单元利润不低于现有场景 |
| 团队对投资/不投资争论 | 要求每人独立填写单元模型对比 | 5分钟内找到分歧点 |
| **融资路演需要展示商业模式** | 用三个维度（盈利性、持续性、规模经济）展示单元模型 | 投资人能看懂每一块钱的来去 |

## When NOT to Use
| 场景 | 为什么失效 | 替代方案 |
|------|-----------|---------|
| **业务尚无任何运营数据、所有参数都是猜的**（如"我们预计转化率3%"但连一个用户都没接触过） | 五步法的核心是"验数据"（Step 4），但如果没有数据可验，前面的搭建只是把"不知道"包装成"算过了"。精确的公式 + 猜测的参数 = 精确的谎言。更危险的是，搭建过程产生的"我算过了"的安全感，会让你对业务不确定性的警觉下降 | 先不做单元模型搭建。做"参数采集运动"——找到3-5个最小数据点（如：先投放一个广告看真实CAC、先手动接5个客户看真实转化路径）。只有当≥3个核心参数有真实数据后，再搭建模型 |
| **业务模型过于复杂、单元不可独立拆分**（如平台型、生态型企业） | 五步法假设"可以找到一个最小的可独立运营单元"。但平台/生态型业务的价值来自系统内各单元的网络交互，单独拆出一个单元（如单边用户）算其利润率，忽略了双边交叉补贴和网络效应——算出来可能是"每个单元都亏损"但平台整体很值钱 | 改用"系统经济学"分析替代单单元搭建——算相互依赖的≥2个单元组合的综合经济表现。核心问题从"这一个单元赚不赚钱"变成"这一组单元的交互价值-联合成本>0吗" |
| **创业者已经对数字产生了"分析依赖"——反复搭模型但不敢行动** | 五步法是"算清楚再行动"的逻辑，但如果创业者把"算清楚"当成"继续算"而不是"现在行动"，模型搭建就成了拖延决定的工具。每多搭一版模型，安全感增加一分，但时间窗口和竞争对手也在逼近 | 设定单元模型搭建的硬截止——最多搭两版（乐观版+悲观版），两版都完成后必须做出"做一个决定"：要么基于模型决定"这个方向可行，启动最小测试"；要么决定"方向不行，放弃"。不允许"再搭一版看看" |
