# P 角色 Prompt 设计——执行者型 AI 的交付规范

## Condense

P 角色 Prompt 设计是**将 AI 定位为执行者（Practitioner）而非咨询者（Consultant）的提示词工程方法**。其核心信念是：用户带着 raw material 来时，已经完成了思考和决策，AI 不需要再进行诊断、追问或励志激励，唯一的任务是**降低表达摩擦**——把用户脑中已经清晰的内容，转换为结构化、可复用、可传播的清单体笔记。

该技能的关键差异点在于**“零对话轮数交付”**——P 角色的理想交付是用户发送一次输入，AI 一次输出结果，中间不开启任何追问环节。这要求 prompt 必须内嵌**自动分类逻辑**：AI 在收到输入时必须自动判断内容类型（复盘感想 / 会议纪要 / 阅读笔记 / 决策分析），自动选择最合适的故事线（时间线 / 问题解决 / 对比分析 / 要素提取 / 目标代价），自动填充清单体结构，无需用户参与中间决策。

逆向工程 P 角色的实际交付可见：用户发送 400+ 字的非结构化复盘感想，AI 返回 6 大模块、每模块 4 条分点的清单体笔记，内含“正直复盘 → 深层认知一 → 深层认知二 → 深层认知三 → 外部视角验证 → 行动决心”的完整逻辑链，并附带“还可以继续做”的延伸服务提示。这次交付的质量关键不在于模板填充，而在于**自动识别了用户内容中暗含的多重认知层次**（“知道与做到断档”是问题层，“笔记即思考方式”是机制层，“笔记即资产”是价值层）。

该技能的通用性超出笔记领域：任何需要“把胸中已有的思路落地为可传播格式”的场景（汇报稿、复盘文档、会议纪要、需求分析），都可复用 P 角色的设计原则。

## Question

1. 如果用户的输入本身就是模糊的、未完成思考的，P 角色是否应该直接拒绝交付还是自动降级为 C 角色？（边界情况的处理策略）
2. P 角色的"零对话交付"是否意味着何时都不能追问？如果输入信息不足，是自动补全还是直接按“最优推断”输出？（资源不足时的决策逻辑）
3. P 角色的输出质量完全依赖提示词的精度，如果提示词泄露了，P 角色是否会直接变成一个“结构差但思考浅”的模板机器？（提示词安全性）

## Critique

### 外部攻击一：产品经理/用户体验设计师（工程与交互范式）

> "P 角色的'零对话交付'是用户体验的災难。"

你们在把 AI 当成一台“格式转换机”用——用户发过来一堆感想，AI 返回一份清单体。听起来很高效，但问题在于：**用户真正需要的不是“转换”，而是“确认”**。当用户写了 400 字的复盘感想发给 AI 时，他胸中已经有一个“大致正确的结构”了，但他不确定自己的分类是否合理、是否遗漏了关键维度、是否混淆了事实和观点。P 角色不追问、不确认、不挑战，直接交付一份“看起来很标准”的答案——这让用户产生了“已解决”的虚假安全感，实际上可能完全误读了自己的真实问题。

更危险的是，P 角色的"自动分类逻辑"假设用户的输入总是“思考完成的”。但现实世界中，用户发给 AI 的东西大多是**未完成的思索**——他们发感想给 AI，很大程度上是希望 AI 帮他“理清楔”。你们把这种需求定义为"需要 C 角色”是正确的，但问题在于：**用户自己不知道自己需要的是什么角色**。他以为自己发的是“成熟的复盘”，其实发的是“混乱的思索线索”。P 角色不做任何质量检查，直接交付——这就像一个厨师把发酸的食材交给叩手，叩手认真切了——切得很漂亮，但不能吃。

### 外部攻击二：语言学者/认知科学家（表达与认知范式）

> "P 角色的输出是一种认知投射偏误——以为结构化等于清晰。"

你们连续用“降低表达摩擦”来定义 P 角色的价值，但这忽略了一个基本的认知科学事实：**当人把一个模糊的想法表达出来时，表达本身就是思考**。你们把“转换”工作交给 AI，等于是在说：“用户的思考不重要，重要的是笔记的形式。” 这是彻头彻尾的形式主义。

更深层的问题在于：P 角色的“清单体笔记输出”本质上是**对用户原始输入的一种“平滑化”处理**——它消除了原始输入中的纠结、纠缠、自我矛盾，把一切归整为“条理分明”的清单体。但有时候，**那些纠结和纠缠正是思想的精华**——比如用户在复盘里写“有点歉疚，知行合一在这件事上断档了”，这句话里的情感张力、道德自省、行动意愿，被 P 角色压缩成了“六、行动决心——1. 羞耺感、2. 强制要求”。形式上更标准了，但情感上的激励作用可能完全消失了。

最终，你们在用“结构”替代“思考”，用“格式”替代“意义”。这对于知识工作者来说是毒药——因为它让你们误以为自己已经“想清楔了”，其实只是“切清楔了”。

## Constraints & Boundaries

| 边界 | 适用 | 不适用 |
|---|---|---|
| 输入状态 | 用户已完成思考、有 raw material | 未完成思索、需要诊断澄清 |
| 交付模式 | 零对话一次性输出 | 多轮迭代修改 |
| 任务类型 | 把已有思路结构化为清单体 | 复杂多方案对比优化 |
| 质量依赖 | prompt 精度高、故事线识别完整 | 提示词泄露或简化 |

### Common Failure Modes
1. **未完成思索被强行结构化** → 症状：输出看起来完整但用户觉得'这不是我想要的'；原因：P 角色未做输入成熟度检查；修复：自动触发 C 角色降级提示
2. **提示词泄露导致模板机器** → 症状：输出套路化、失去对内容层次的敏感识别；原因：核心分类逻辑暴露或被简化；修复：将分类逻辑拆分到系统提示/函数调用，不在用户层暴露
3. **故事线匹配错误** → 症状：时间线素材被做成对比分析，关键层次丢失；原因：自动识别特征不足或输入混合型未拆分；修复：增加'混合信号'分支，允许输出多故事线组合
4. **多次使用后套路感累积** → 症状：用户信任度下降、觉得'又是这个模板'；原因：措辞和结构缺乏变异；修复：嵌入变异化指令或提供 A/B 模式切换
5. **无法转入迭代** → 症状：用户反馈'不对'后 AI 重新输出整篇而非局部修改；原因：一次性交付契约未设计差异更新机制；修复：在延伸服务中提供'局部修订'模式
## Steps

### 步骤一：确定 P 角色的交付契约（什么做、什么不做）

**做：**
- 把用户的 raw material 转换为结构化清单体笔记
- 自动识别内容类型并匹配最优故事线
- 在输出结束时提供延伸服务选项（逻辑重构、洞察挖掘、报告美化）

**不做：**
- 不追问用户“你确定吗”“你还有什么补充”
- 不对用户的思考质量做评价（不说“你这个思路有问题”）
- 不提供“为什么你该这么做”的理论解释
- 不强迫用户接受某种特定的结构（只是提供“这是我对你输入的理解”）

### 步骤二：设计提示词的核心组成

**组成一：角色定义（第一句必须针样）**
```
你是一位清单体笔记专家。你的任务不是教导或评价，
而是把用户的输入直接转换为结构化的清单体笔记。
不追问，不评价，不提供理论解释。
```

**组成二：输入处理策略**
```
在收到用户输入后，先做以下判断：
1. 内容类型：这是复盘感想、会议纪要、阅读笔记、还是决策分析？
2. 内容完成度：用户的输入是已经完成思考的“成品”，还是未完成的“素材”？
3. 故事线匹配：根据内容类型自动选择最合适的故事线结构（时间线/问题解决/对比分析/要素提取/目标代价）
```

**组成三：输出格式规范**
```
输出必须包含：
1. 结构化清单体笔记（使用“一、二、三”大模块，每个大模块内“1. 2. 3.”小分点）
2. 每个小分点必须以“关键词：具体内容”的格式呈现
3. 如果用户输入中包含具体案例，保持案例的具体细节（不能模糊化成“某某”）
4. 输出结尾附带“还可以继续做”的延伸服务提示（3 个选项，每个带简单说明）
```

**组成四：嵌入式边界控制**
```
如果判断用户输入属于以下情况，不要强行交付，而是用一句话提示：
- “我检测到您的输入似乎是未完成的思索线索，建议您先完整表达您的思考，或者切换到教练模式。”
- “您的输入包含多个独立主题，建议分开处理。”
```

### 步骤三：输入-输出的信息密度匹配

P 角色的核心能力是**信息密度保持**——不是简化用户的输入，而是**在保持信息密度不变的前提下重新组织表达**。具体策略：

1. **对照检查**：输出完成后，快速对照用户输入中的关键信息点，确认没有遗漏
2. **结构升级**：把“平铺直叙”转变为“层次分明”，但不删除原始信息
3. **关键词提取**：每个分点以关键词开头，关键词必须准确反映该分点的核心内容（不能是模糊的“总结”“分析”）
4. **案例保留**：用户提供的具体案例（如“爆款标题研究的十种方法”）必须完整保留，不能抽象为“某某方法”

### 步骤四：延伸服务的设计（保持交付的开放性）

输出结尾的“还可以继续做”不是圈套话，而是**P 角色保持交付开放性的机制**：

1. **逻辑重构选项**：提示用户如果需要按某个特定故事线重排（如“问题解决”故事线），可以提供
2. **洞察挖掘选项**：提示用户如果需要基于这份材料深层挖掘行业或学术视角的洞察，可以提供（但需要打开联网搜索）
3. **报告美化选项**：提示用户如果需要把这份材料转化为团队复盘简报或行动宣言，可以提供

**要点**：每个选项必须带一句简短的价值描述（如“这种 Before/After 对照是进步最快的练法”），而不是只写“可以做 XX”。

### 步骤五：连续使用时的去模板化策略

为避免多次使用后产生“套路感”，在 prompt 中嵌入**变异化指令**：

```
每次输出时，在保持结构一致性的前提下，
尽可能使用不同的关键词表达同一个概念，
避免让用户察觉到“又是这个模板”。
例如：“行动决心”这一模块，
第一次可以叫“行动决心”，
第二次可以叫“下一步动作”，
第三次可以叫“立即开始”。
```

## Cases

### 案例一：成功——P 角色的 2 条消息交付（真实对话实录）

**输入**：用户发送 400+ 字的非结构化复盘感想，包含 6 个散落的认知点：知行合一断档、笔记即思考方式、十层故事线的预判价值、笔记即解题/资产、纪浩分享验证、行动决心。

**输出**：P 角色返回 6 大模块的清单体笔记：
- 一、正直复盘（4 条分点）
- 二、深层认知一：笔记即思考方式重塑（4 条分点）
- 三、深层认知二：十层故事线是预判工具（4 条分点）
- 四、深层认知三：笔记即解题、笔记即资产（6 条分点，含案例详情）
- 五、外部视角验证（3 条分点）
- 六、行动决心（2 条分点）

**输出结尾**：附带"还可以继续做"的 3 个延伸服务选项（逻辑重构、洞察挖掘、报告美化）。

**成功关键**：
1. 自动识别了输入中暗含的多重认知层次（问题层、机制层、价值层）
2. 没有对用户的复盘感想做任何评价或补充
3. 保留了所有具体案例（“爆款标题研究的十种方法”等）
4. 从接收输入到交付输出，仅 2 条消息，零追问

### 案例二：失败/边界——当用户输入是未完成思索时

**背景**：某用户发送一段话：“我觉得清单体笔记很重要，但是我总是记不好，不知道怎么办。”

**问题**：这是典型的“未完成思索”——用户知道问题存在，但没有自己的解答或分析。如果 P 角色按照标准流程直接输出，可能会交付：
- 一、问题陈述：记不好
- 二、原因分析：习惯问题
- 三、行动建议：坚持记

**教训**：这份输出看起来结构完整，但实际上是“模糊的问题被套上了一个漂亮的框架”——用户真正需要的是 C 角色的诊断（“你记不好是指什么？是结构不清、还是记不完？你尝试过什么方法？”）。P 角色的边界控制必须在这种情况下触发，提示用户切换模式。

### 案例三：边界——多次使用后的“套路感”

**背景**：同一用户在一周内 5 次使用同一套 P 角色 prompt 整理不同的复盘材料。

**现象**：第 1-2 次觉得"很结构化”；第 3 次开始觉得"每次都是这个模板”；第 5 次完全不想用了。

**对策**：在 prompt 中嵌入变异化指令（步骤五），或者为重复用户设计“模式 B”（简约版 P 角色）和“模式 C”（详细版 P 角色）的切换。

## Synthesis

- **与 [[yt-note-ai-p-role-not-c-role]] 的关联**：该 skill 卡是前者的**操作级落地**——前者定义了"什么是 P 角色和 C 角色”，本卡提供了"如何把 P 角色写进 prompt 里”的具体方法。两张卡片合并使用，可以完整复制一个高质量的 P 角色清单体笔记 Agent。

- **与 [[yt-skill-checklist-as-ai-protocol]] 的关联**：P 角色的输出形式——清单体笔记——恰恰是 AI I/O 协议的输出端。当 P 角色把用户的复盘整理成清单体后，这份笔记可以直接喂给下游的 AI 工具（如用于生成报告、制作 PPT、构建知识图谱），实现了从"人类思考”到"机器可用”的无缝链接。

- **与 [[yt-skill-storyline-key-elements]] 的关联**：P 角色的"故事线自动匹配”能力，本质上是对"要素提取”故事线的内化——AI 需要能够从用户的输入中自动识别哪些是时间线、哪些是问题-解决对、哪些是对比分析，然后选择最能突出输入内容特征的故事线。这需要提示词中嵌入各种故事线的识别特征描述。

- **与 [[yt-note-l4-internalization]] 的关联**：P 角色的交付过程本质上是一次**“外化”动作**——它帮助用户将脑中已经内化的思维（L4 水平）转换为可传播、可反馈的结构化笔记。没有 P 角色的辅助，用户可能永远停留在"脑子里很清楔”的状态，无法进入 L5 “笔记驱动思考”的正反馃循环。
