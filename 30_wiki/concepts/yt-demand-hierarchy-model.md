# 需求层次模型：真需求、伪需求与衍生需求

> 一堂五步法第一步的核心认知：超过30%甚至50%的项目失败，标签最终贴在了"需求"这一列。

## 核心框架

需求不是单层的。同一个用户表述的背后，可能藏着三层完全不同的需求结构：

| 层次 | 定义 | 特征 | 验证标准 |
|:---|:---|:---|:---|
| **真需求** | 用户愿意为之付费、持续使用、主动推荐的核心问题 | 高频、高痛、高付费意愿 | 用户现在就在花钱/花时间解决 |
| **伪需求** | 用户说需要，但实际不会付费或使用的"兴趣" | 低频、低痛、替代方案充足 | "挺好的但不需要" |
| **衍生需求** | 基于真需求生长出来的次级功能或服务 | 依附于真需求存在，单独无价值 | 去掉真需求后，这个功能还有价值吗？ |

## 关键洞察

### 1. 真需求的三个维度

一堂需求分析框架要求同时回答：

- **拆**：用户真正要解决的核心问题是什么？（不是功能，是问题）
- **推**：用户现在怎么解决的？现有方案的成本和痛点？
- **评**：你的方案比现有方案好多少？（10倍法则）
- **算**：这个需求的用户规模、付费意愿、天花板

### 2. 伪需求的典型来源

- **创始人想象**："我觉得用户需要"——没有用户验证
- **竞品跟随**："竞品做了，我们也得做"——未验证是否适合自己用户
- **技术驱动**："我们能做，所以做了"——技术能力≠用户需求
- **调研偏差**：用户说"想要"但行为上不付费——口头需求≠真实需求

### 3. 衍生需求的膨胀陷阱

最危险的不是没有真需求，而是**在真需求上无限膨胀衍生需求**：

```
真需求：用户需要高效管理客户信息
    ↓
衍生1：加个标签功能
    ↓
衍生2：再加个自动化流程
    ↓
衍生3：再加个数据分析看板
    ↓
衍生4：再加个AI预测...
    ↓
结果：产品臃肿，核心功能被淹没，用户流失
```

## 失败模式（常见陷阱）

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **把兴趣当需求** | 用户说"想要"但转化率极低 | 用"现在怎么解决"替代"你想要什么"提问 |
| **需求定义太宽** | "所有人都是我的用户" | 先聚焦一个细分场景，验证后再扩展 |
| **忽视现有方案** | 假设用户现在不解决这个问题 | 深度访谈：用户现在的替代方案是什么？成本多高？ |
| **创始人自我投射** | "我就是用户，我懂" | 至少访谈10个真实用户，寻找反例 |
| **需求验证过早定量** | 先做市场规模估算，没搞清楚用户是谁 | 先定性（用户是谁、场景是什么），再定量（规模多大） |
| **伪需求堆叠** | 功能越来越多，核心越来越模糊 | 定期做"需求减法测试"：去掉这个功能，用户会流失吗？ |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新产品立项前的需求验证 | 成熟产品的增量优化（已有数据反馈） |
| 创业方向选择 | 技术可行性评估（属于工程问题） |
| 用户访谈和需求调研 | 市场进入策略（属于增长问题） |
| 产品定位模糊时的重新梳理 | 已有明确PMF后的规模化扩张 |

## 行动触发器

- 当你想说"我觉得用户需要..."时 → 先问"用户现在怎么解决的？"
- 当团队争论产品方向时 → 回到"我们的真需求是什么？"
- 当考虑新增功能时 → 做"需求减法测试"
- 当用户说"挺好的"但不付费时 → 识别为伪需求信号
