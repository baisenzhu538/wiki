# YAI C角色咨询法：Counsel 式方案输出节奏

> Source: `00_inbox/元能力-刻意练习/YAI的C角色给我的诊断.md`
> 角色定位：C（Counsel / 咨询者）—— 在 T 角色诊断的基础上，给出具体、系统、可执行的训练方案。

## Summary

YAI 的 C 角色（咨询者角色）不是简单回答"怎么做"，而是在 T 角色完成理解和诊断之后，把用户的情况套进一个经过验证的方法论模型里，生成一套可执行的训练系统。

C 角色的输出有三个层级：
1. **诊断报告** —— 能力校准、四要素状态、最大卡点
2. **训练系统** —— 固定套路、非舒适区、反馈机制、重复安排的闭环
3. **延展工具** —— 24 小时计划、Checklist、1.0 套路清单

核心原则：**先校准能力定义，再分层目标，再系统诊断，最后输出资产。**

## Core Claims

### claim:01 [conf=0.90] C 角色的起点是校准能力定义，而不是直接给计划

用户说"我想练 AI 学习能力"时，C 角色没有直接排计划，而是先把它校准成"AI工具的结构化学习与产品化判断"。因为太虚的能力无法设计训练动作。

### claim:02 [conf=0.85] 目标必须分两层：长期追求 + 当前阶段出口

长期追求回答"要成为谁"，当前阶段出口回答"这一轮先做到什么"。两者缺一不可。没有长期追求，用户遇阻容易放弃；没有阶段出口，目标无法落地。

### claim:03 [conf=0.85] 四要素诊断是 C 角色的核心骨架

固定套路、非舒适区、及时反馈、大量重复。C 角色逐个要素诊断，每个要素给出状态标签、最大盲区、两个策略、一个候选启动动作。

### claim:04 [conf=0.80] C 角色必须调用知识库中的已有方法论

本案例中，C 角色大量调用了一堂知识库里的 Truman「AI上手第一课」循序渐进学习曲线，而不是从零构建方法。这让方案有依据、可溯源。

### claim:05 [conf=0.80] 诊断报告之后必须跟延展工具

诊断本身不产生行为改变。24 小时计划、Checklist、套路清单才是把诊断变成行动的桥梁。

## C 角色 vs T 角色

| 维度 | T 角色（Teacher/TCPR） | C 角色（Counsel） |
|:---|:---|:---|
| 核心目标 | 让用户理解自己、对齐认知、定位卡点 | 在诊断基础上给出系统化训练方案 |
| 输出物 | 自评、最小动作、共鸣感 | 诊断报告、训练系统、工具清单 |
| 主要问题 | "你现在在哪里？" | "我们怎么从那里走到目标？" |
| 节奏 | 慢、对话式、共建 | 结构化、系统式、输出资产 |
| 何时启动 | 用户刚开始表达需求 | 用户已完成自评/诊断，说"开始"或"生成报告" |
| 切换信号 | 用户说"开始""你可以帮我设计方案了" | 用户说"这个我理解""先汇总" |

## C 角色七步流程

### Step 1: 接住自评并正常化

用户完成自评后，C 角色先复述 + 正常化，不评判。

> 示例："你自评在第4档——了解刻意练习，偶尔尝试用，但很难坚持。这个状态其实很典型，不是你的问题，而是很多人卡在同一个地方。"

### Step 2: 确认能力范围

让用户自由说出想练的能力，然后通过追问澄清具体指向。

> 示例问题：
> 1. 你现在最想刻意练习的具体能力是什么？
> 2. 你为什么想练这个能力？
> 3. 大概希望用多长时间练？
> 4. 你希望练到什么水准？

### Step 3: 校准能力定义

把用户模糊的能力诉求，校准成可训练、可检验、有质量维度的能力描述。

> 示例：
> "AI学习能力" → "AI工具的结构化学习与产品化判断"
>
> 校准标准：
> - 足够具体
> - 能独立训练
> - 好坏可检验
> - 可以反复练
> - 有长期复利

### Step 4: 确认目标档位

- **长期目标档位**：无限进步 / 岗位专家 / 快速上手
- **长期追求**：用户未来想成为什么状态
- **当前阶段出口**：1-2 个月内要先完成什么

> 示例：
> - 长期：成为 AI 时代 Solopreneur，5 人团队撬动 30 人产出
> - 当前阶段出口：1-2 个月内建立第一版固定套路，跑通 2-3 个工具的完整循环

### Step 5: 四要素诊断

逐个诊断四个要素，每个要素包含：

| 内容 | 说明 |
|:---|:---|
| 当前状态 | 给出一个状态标签 |
| 用户证据 | 引用用户刚才说的话作为依据 |
| 主要盲区 | 指出最大的问题 |
| 提速判断 | 解释为什么这个要素影响速度 |
| 优先策略 | 给出 2 个最对症的策略 |
| 候选启动动作 | 1 个可执行的最小动作 |

#### 四要素状态标签示例

| 要素 | 用户状态 | 状态标签 |
|:---|:---|:---|
| 固定套路 | 想建文档但做不完整，靠感觉搜索 | 弱套路 |
| 非舒适区 | 不怕难，愿意突破，但缺方法 | 有效挑战但结构不足 |
| 及时反馈 | 不知道学到什么程度算学会 | 无反馈 |
| 大量重复 | 想一周学一个，但一被打断就崩 | 机会充足但重复结构不足 |

### Step 6: 汇总报告

汇总时包含：
1. 十倍速诊断摘要
2. 能力校准与长期追求
3. 四要素诊断详情
4. 第一版训练系统
5. 启动排期（24小时 / 7天 / 1个月 / 长期）
6. 用户特质、风险与下一步

### Step 7: 延展工具

根据用户需求生成：
1. **24 小时计划** —— 精确到时间点和产出物
2. **可打印 Checklist** —— 一页以内，每次学习打勾
3. **1.0 套路清单** —— 完整训练流程、检查点、常见偏差

## 关键技法清单

1. **接住自评**：复述 + 正常化，不评判
2. **追问澄清**：用 4 个问题确认能力范围
3. **校准能力**：把模糊能力变成可训练的具体能力
4. **目标分层**：长期追求 + 当前阶段出口
5. **证据驱动**：每个状态判断都引用用户原话
6. **四要素骨架**：固定套路、非舒适区、及时反馈、大量重复
7. **状态标签化**：用简洁标签让用户看见自己的位置
8. **双策略 + 一动作**：每个要素收敛到可执行
9. **调用知识库**：优先使用已有方法论模型
10. **输出资产**：报告 + 24小时计划 + Checklist + 套路清单

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:---|
| ✅ 适合 | 用户已完成自评，说"开始"或"给我方案" |
| ✅ 适合 | 用户的能力诉求比较模糊，需要校准 |
| ✅ 适合 | 用户需要系统训练方案，而不只是单一建议 |
| ✅ 适合 | 知识库中有相关方法论可以调用 |
| ❌ 不适合 | 用户情绪还很抗拒，需要先 T 角色处理 |
| ❌ 不适合 | 用户只想要一个快速答案，不想被诊断 |
| ❌ 不适合 | 完全没有相关知识库素材支撑 |

#| 模式 | 症状 | 修复 |
|:---|:---|:---|
| **能力校准不准确** | 用户觉得"这不是我想练的" | 让用户用三选一或自己改 |
| **四要素变成说教** | 用户在每个要素都觉得很累 | 每个要素后给用户选择：继续/调整/深入/先记下 |
| **报告太宏大** | 用户看完不知道怎么开始 | 必须跟一个 24 小时最小启动计划 |
| **缺少知识库调用** | 方案听起来像通用建议 | 先查询知识库，找到相关方法论 |
| **跳过 T 角色直接 C** | 用户执行意愿低 | 退回 T 角色做理解和最小动作 |

## Critique

### 内部局限

- C 角色依赖 T 角色已完成诊断。如果 T 角色没做足，C 角色容易给出"正确但不被执行"的方案。
- 四要素诊断如果每个要素都深入，可能会让用户疲惫。需要给用户"继续/调整/深入/先记下"的选择权。
- 报告和延展工具需要占用较多 token/output，需要确认用户确实需要完整输出。

### 外部攻击

#### 效率至上视角 —— "直接给方案不行吗？"

如果用户只要一个工具清单，C 角色这套流程确实慢。但本案例证明：用户要的不是清单，而是"把自己的情况套进一个系统"。直接给清单，用户会得到信息；给系统，用户会得到改变的路径。

#### 反方法论视角 —— "每个人的情况不同，模板化诊断会不会削足适履？"

四要素本身是通用框架，但 C 角色的关键是**基于用户证据做状态判断**，而不是把每个人都套成同一个状态。同一个要素，不同用户可能是"弱套路"或"强套路"，策略完全不同。
