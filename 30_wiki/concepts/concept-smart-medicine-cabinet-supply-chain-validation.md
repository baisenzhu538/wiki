# 智能药柜供应链/技术交叉验证（知识卡草稿）

## 1. 一句话摘要
当前项目已从“硬件外包意向”推进到“200 台药柜报价”阶段，但**销售承诺（Windows/医保/6 月上线）明显超前于研发和供应链准备度**；核心风险集中在医保接入复杂度、6 月排期过紧、小批量供应链不稳定、断电状态丢失四个方面。



## 2. 关键事实（多方确认或有数据）

| 事实 | 证据来源 | 说明 |
|------|----------|------|
| 技术栈：安卓上位机 + STM32 控制板 + 485/232/CAN 总线 | 4528361、6578799、7296034 | 三段录音技术描述一致 |
| 货道内空 14 mm，组合后 28 mm（加隔板约 30 mm） | 6578799 | 原文有直接尺寸讨论 |
| 原设计 9 层，因智能模块占空间改为 7–8 层 | 6578799、1428540 | 两录音互补 |
| 医保场景必须用 Windows + 医保前置服务器 | 4528361、7296034 | 7296034 解释最详细 |
| 无备用电源时断电无法保留出货状态 | 7296034 | 硬件能力边界，明确承认 |
| 3 台以下供应链不愿接单，客户多为几台小单 | 7983893 | 市场现状与起订量矛盾 |
| 核心芯片（3588/3288/STM32）存在断供/涨价风险 | 4528361 | 亲历数据，已考虑 STC 替代 |
| 管理费参考标准 120–200 元/台/年 | 7983893 | 谈判中提出 |

---

## 3. 关键条件（需特定配置才成立）

| 条件 | 依赖 | 风险 |
|------|------|------|
| 一拖二结构容量 336 品规 | 需按图纸复算、实际样机验证 | 理论值，未经验证 |
| 扫码枪 1–3 秒识别 | 依赖厂家型号与药物条码质量 | 4 面扫描可能不满足 6 面合规要求 |
| 医保统筹对接 | 需 Windows 版成熟 + 前置服务器 + 各地医保审批 | 排期与复杂度被低估 |
| 小批量可接单 | 依赖硬件方愿意配合、3 台起订 | 成本摊薄困难 |
| 200 台订单交付 | 依赖图纸、BOM、合同、付款全部闭环 | 目前仅为报价阶段 |

## 4. 关键风险（与商业/技术逻辑冲突）

| 风险 | 冲突点 | 录音依据 |
|------|--------|----------|
| **6 月上线目标过紧** | 4 月 20 日结构（爪子/层高/滑道）仍未定，却要求 5 月 20 日样机、6 月上线 | 6578799 |
| **销售承诺超前于研发** | 7983893 承诺医院 HIS/医保统筹，4528361 称 Windows 版仍在开发 | 4528361 vs 7983893 |
| **断电状态丢失** | 药店 24 小时/处方完整性要求高，但硬件方案无备用电源 | 7296034 |
| **SKU 数字异常** | 1428540 称传统机器“300 万 SKU”，与 800 目标、336 品规数量级冲突 | 1428540 |
| **小批量与产能矛盾** | 客户多为几台，供应链 3 台不接，200 台线索未落地 | 7983893 |
| **团队能力边界** | 朱总团队仅 4–5 人软件，无整机能力；可转入人员偏售后/装配 | 7983893、4528361 |

## 5. 需要进一步验证的问题

1. 1428540 中“300 万 SKU”“5 万台”“70 万家药店”是否为转写/纪要错误？需复核原始录音或官方数据。  
2. 200 台江朝汇/东莞宜家订单是否有书面 PO、付款条件、交付周期？  
3. 医疗器械认证具体证书编号及覆盖机型范围？  
4. 3588/3288/STM32 替代方案（STC 等）是否已完成适配测试？  
5. Windows 版医保对接当前真实进度，是否已有医院试点？  
6. 断电保护/备用电源是否纳入后续 BOM 与成本？
