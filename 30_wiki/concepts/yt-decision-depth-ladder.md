# 深度阶梯工具：L1-L4停车场模型 + 三点预测法

## Summary

任何决策都不该"一刀切"地追求最深分析。深度阶梯工具把ROI评估拆成四级（L1定性→L2部分定量→L3定量公式→L4严格财务），配合"停车场"机制——从浅层开始试，够了就停，不够再往下走。工具同时提供三个数据策略（攒经验值、交叉类比、三点预测法），解决"知道模型但没数据"的实操困境。

**一句话定位**：决策前先问"这车该停在哪一层"，而不是一上来就拆单元模型。

---

## Claims

### 一、四级深度阶梯（What）

| 层级 | 核心动作 | 适合决策类型 | 典型耗时 | 停车信号 |
|------|----------|-------------|---------|----------|
| **L1 优先级定性** | 列收益/成本项，纯文字描述价值与风险 | 简单管理动作、短平快试错（几百~几千元） | 5-15分钟 | 团队一看就懂，无分歧 |
| **L2 部分定量** | 关键收益/成本项转成数字/钱，大差不差估算 | 资源投入类（办公室、涨薪、打车、午餐） | 15-45分钟 | 关键项定量后ROI明显>1或<1 |
| **L3 定量公式** | 把最关键指标拆成转化率漏斗/公式，代入经验值范围 | 获客渠道、运营策略、商业模式验证 | 45-120分钟 | 最好情况都不可接受，或明显可接受 |
| **L4 严格财务ROI** | 完整单元模型：全量成本+收益+退款+履约+复购的财务精算 | 重大投资、融资决策、生死级战略 | 数小时~数天 | 即使最好情况单元模型<1，或明显>安全线（如1.6-2.5） |

> **停车原则**：每层分析完后问自己"这决策能做吗？"——能，停车执行；不能，继续往深走。**不要在浅层吵架**。

#### 三层递进：定性 < 定量 < 定钱

四级深度的本质不是"复杂度递增"，而是**参数的可信度递进**。每一层用颜色编码表示参数的量化成熟度：

| 层级 | 定性（黑） | 定量（绿） | 定钱（红） | 核心特征 |
|------|-----------|-----------|-----------|---------|
| **L1** | A,B,C,D,X,Y,Z 全部为定性描述 | — | — | 只问"有没有"，不问"是多少" |
| **L2** | 部分参数仍为定性 | 关键参数给出数字区间 | 核心成本/收益折算为钱 | "大差不差"的估算，够用就停 |
| **L3** | 极少数边缘参数保留定性 | 转化率漏斗等核心指标定量 | 关键产出折算为财务指标 | 拆公式、代入经验值、证伪判断 |
| **L4** | 无 | 辅助参数定量 | **所有参数全部定钱** | 完整单元模型，财务级精度 |

> **单元模型公式**：`ROI = (A + B + C + D) / (X + Y + Z)` —— 产出端四项，投入端三项。L1时所有字母都是黑色（定性）；L4时所有字母都是红色（定钱）。从L1到L4的过程，就是把字母逐个从黑变绿再变红的过程。

### 二、停车场操作流（How）

```

遇到决策 → L1定性列项 → 能判断？→ 停车

                ↓ 不能

         L2部分定量（关键项变钱）→ 能判断？→ 停车

                ↓ 不能

         L3拆公式漏斗（A×B×C×D）→ 能判断？→ 停车

                ↓ 不能

         L4完整单元模型 → 能判断？→ 停车

                ↓ 还不能

         转化为关键假设 → 设计MVP/MAP实验

```

**关键口诀**："先在黑板上成功，再在现实里成功。"

### 三、L3公式化实操（核心难点）

#### L3定量公式的视觉化表达（源于源图像提取）

L3的核心是“定量”——将关键假设用数字表达，但不强求精确到“定钱”。其公式结构可表达为：

```
投入成本 = A + B + C + D
单位产出 = X
总产出 = Y
```

**变量语义**（源于图像色彩编码）：

**定量与定钱的区别**：

| 层级 | 核心差异 | 示例 |
|:---|:---|:---|
| L3 定量 | 关键项有数字，但可能是区间估算或经验值 | “每个客户获取成本约100-200元”、“转化率约3%-5%” |
| L4 定钱 | 完整财务公式，连边角成本都计算 | “单元交易ROI = 142.6万 / 55万 = 2.59x”、“内部收益率IRR = 18.7%” |

> 视觉标记语义：浅绿色标题栏=L3标识；黑底=权威性声明；红色用于分子区与变量标注；绿色用于分母区与变量标注。色彩编码区分投入产出两组变量，但未在图中标注各字母对应的具体业务场景。

L3是多数复杂决策的"分水岭"。操作步骤：

1. **锁定关键指标**：找到最影响ROI的那一个指标（如获客成本、订单量、收入）

2. **拆转化率漏斗**：把指标展开为乘积公式。例如：

   ```

   有效体验课用户 = 总线索 × 真实率A × 匹配率B × 接通率C × 意向率D × 添加率E

   ```

3. **代入经验值范围**：每个转化率给出一个合理区间（如接通率50%-70%），先用**最高值**算一遍

4. **证伪判断**：如果最好情况都不满足预期→直接关掉；如果最好情况可以→再算中等/悲观

> **案例**：一堂评估"电话外呼10万线索"项目。L2估算"20%×20%=4%转化率"太糙；L3拆成6层漏斗后发现即使每层取最高值，最终转化率仅1.4%，获客成本远高于现有渠道。项目在黑板上被证伪，避免了一个合伙人季度+几十万试错的损失。

### 四、三个数据策略（没数据怎么办）

| 策略 | 适用场景 | 操作步骤 |
|------|---------|----------|
| **① 攒经验值/benchmark** | 长期积累，用于日常决策 | 建立"决策经验值清单"：记录行业常识、竞争对标、历史数据。定期更新（如一堂记录"课程打磨6-18个月"、"转化漏斗通常5-20%"、"教育SaaS年增速50-200%"等） |
| **② 交叉类比** | 新业务缺乏直接数据 | 三步法：①找背后因素（客户密度/付费意愿/竞争程度/品牌基础）；②按影响力排序；③对比多个参照物（头部同行+相邻赛道+自己历史），调整估算，不直接抄数 |
| **③ 三点预测法** | 数字范围很大，不知该用哪个 | 算三遍：①**乐观版**（成本最低、价格最高、转化率最高）→证伪用；②**合理版**→正常预期；③**悲观版**→底线测试。如果乐观版都不成，项目关掉；如果悲观版会死，谨慎推进 |

### 五、深度选择参考表

| 决策特征 | 建议最低深度 | 原因 |
|----------|-------------|------|
| 试错成本<1万，可快速撤回 | L1 | 不值得分析成本 |
| 资源投入（人力/资金/时间） | L2 | 需要钱vs钱的比较 |
| 获客渠道/运营策略/产品方案 | L3 | 转化率漏斗是核心 |
| 融资/重大投资/商业模式验证 | L4 | 必须全量财务精算 |
| 团队有严重分歧 | 比当前深一层 | 吵架是因为讨论太浅 |

### 六、案例：从L2到L3的实际推演

**案例一：是否全员涨薪20%（美容连锁企业）**

| 类别 | 具体项 | 定量估算 | 补充说明 |
|------|--------|----------|---------|
| 关键成本 | 增加人力预算 | 300万/年 | 人力预算上调20% |
| 关键收益 | 保留优质员工 | 30-50万/年 | 培养成熟员工成本3-5万/人，预期多保留10个老员工 |
| | 提升员工士气 | 150万/年 | 基本盘1亿销售额，士气提升3%销售额，净利润50% |
| | 压迫竞争对手 | 100万+/年 | 对手跟进损失5000元/月·店，我们主观评估值100万+ |
| | 提升品牌声誉 | 定性 | 对当地市场品牌知名度、口碑、雇主形象有很好的帮助 |

>评估结果：总收益280-300万/年，总成本300万/年。看似ROI接近1，但"品牌声誉"是定性收益未进入计算，加上后实际ROI>1。这是一个典型的**L2部分定量**案例——关键项转成钱，大差不差估算，已足以支撑决策。

**案例二：一堂租办公室（v3.0版本）**

| 类别 | 具体项 | 定量估算 | 计算过程 |
|------|--------|----------|---------|
| 关键成本 | 装修投入 | 50万（一次性） | — |
| | 房租成本 | 增加50万/年 | — |
| | 水电成本 | 增加5万/年 | — |
| | **总成本** | **55万/年（第一年100万）** | — |
| 关键收益 | 磨课会 | 22万/年 | 每月12场×12月=144场，每场等效1500元研发成本 |
| | 线下活动 | 9.6万/年 | 每月4场×12月=48场，每场节省2000元场地费 |
| | 磨课小屋 | 45万/年 | 3个研发文案类工作效率翻倍，占研发工作50% |
| | 创新实验 | 66万/年（模糊定量） | 3年测出千万利润级业务，场地贡献占20% |
| | 品牌提升 | 定性 | 很难评估新办公室对品牌提升的影响 |
| | **总收益** | **142.6万/年** | — |

>评估结果：第一年净收益42.6万，第二年起净收益87.6万/年。这是一个典型的**L2到L3过渡**案例——大部分项目定量了，但\"创新实验\"和\"品牌提升\"仍是模糊定量或定性。L3的价值在于把\"磨课会\"和\"磨课小屋\"的收益结构拆到了\"次数×单价\"的级别，但\"创新实验\"因为是未知业务，只能做模糊定量。这正是正常的L2停车点——不用等到所有参数都精确才做决策。

## 深度幻觉：挖太深忘了行动

### 幻觉机制

深度阶梯的本质是将\"定性判断\"逐步转化为\"定量计算\"。但L3（定量公式化）带来的精准数字会让决策者产生一个错觉：**\"数据越精确，决策质量越高\"**。实际上，L3的精确性只适用于那些你已知、可测量的变量——而关键决策变量往往是不确定的新变量（不可测），或者你有反向动机去美化/低估的变量（不愿测）。

换而言之：**你能精确计算的部分往往是\"容易算的\"，而不是\"最重要的\"。**

### 什么时候你会掉进深度幻觉

| 触发条件 | 症状 | 诊断 |
|:---------|:------|:------|
| 你花了 80% 时间在算一个 L3 数据，但它只占总决策权重的 10% | 重要但难算的变量被忽略或定性带过 | 先看每个变量对决策结果的影响权重，按权重分配时间 |
| 你为了算一个变量的 L3，拖了 3 天还没拍板 | 决策窗口在关闭，但你在优化一个已足够好的数字 | 算 L3 之前先问：L2 的结论是什么？L3 会让结论翻盘吗？ |
| 你算出结论后，前提假设的可靠性与结论看起来完全不匹配 | 数字精确但逻辑脆弱——前提是拍脑袋的，后面算得再精确也是垃圾 | 每做一个 L3 定量，同步标注\"这个数字的可信度\"——让虚假精确性暴露出来 |

### 修复：什么时候该停在 L2

**深度阶梯的价值不在于\"爬得越高越好\"，而在于\"知道什么时候该停在当前层\"。** 以下情况下停在 L2（不爬 L3）是合理选择：

#| 模式 | 症状 | 修复 |
|:-----|:------|:------|
| **\"算对了但选错了\"** | 非核心变量的 L3 精确度极高，但核心假设（前提条件）没验证 | 先验证前提假设，再算定量——顺序错了，算得越准错得越狠 |
| **\"停车位过深\"** | L2 已经足够做决策了，但硬要算到 L3 才敢拍板 | L2 初步结论 + L3 敏感性分析——L3 只算\"如果关键变量±20%会怎样\"，不做完整 L3 |
| **\"模糊变量的假装定量\"** | 对根本无法量化的变量（如品牌影响力、用户信任）强行赋值一个数字 | 标注\"定性判断\"，把不确定量留给决策者的直觉判断，而不是用数字掩盖不确定性 |
| **\"数据疲劳\"** | 团队反复修改同一模型的多版数据，每次只是微调参数 | 每次模型迭代只改 1 个假设，确认改动是否导致结论变化 |

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:------|
| ✅ 关键数据可得 | 你需要至少对关键变量有可靠的定量数据来源。完全拍脑袋的 L3 比 L2 定性更危险——因为它制造了虚假精确 |
| ✅ 决策权重够大 | ROE 分析值得花 1-2 天做深度计算。小额/高频决策用 L1 定性就够了 |
| ❌ 前提假设未验证 | 如果核心前提（\"用户真的有这个需求吗\"）还没验证，算 L3 是浪费——先验证前提再算定量 |
| ❌ 窗口期即将关闭 | 还剩 3 天做决策，但计算需要 2 天——停 L2，先做决策再看要不要补 L3 |

| 检查项 | 停在 L1 | 停在 L2 | 停在 L3 | 冲 L4 | 如果触发这一列，就停在这里 |
|:-----|:------|:------|:------|:------|:------|
| **关键变量可测量性** | 大部分未知 | 核心变量可估区间 | 关键指标可拆漏斗/公式 | 所有变量都能定钱 | 变量越不可测量，停车层越浅 |
| **决策错误的撤回成本** | <1 万/1 周内可撤回 | <10 万/1 月内可撤回 | 重大但可控 | 不可逆/生死级 | 成本越低，越不要深算 |
| **结论对精度的敏感度** | ±50% 不影响结论 | ±30% 不影响结论 | ±20% 会改变结论 | ±10% 会改变结论 | 精度不敏感时，停在当前层 |
| **团队分歧层级** | 要不要做 | 值不值得 | 怎么算/关键参数是多少 | 精确 IRR/IRR 口径 | 分歧在上一层，说明当前层已够 |
| **剩余时间窗口** | <1 天 | <1 周 | <1 月 | 充裕 | 窗口紧迫时，用 L2+敏感性分析替代完整 L3 |

### 使用步骤

1. **逐行打勾**：5 个问题中，找到"最浅的自然停车层"（即触发条件中最常出现的那一列）。
2. **硬约束优先**：如果"时间窗口"或"撤回成本"指向浅层，优先停在浅层；精度追求不能替代行动窗口。
3. **写下停车理由**：在决策记录中写一句"本决策停在 Lx，因为……"，便于事后复盘时检查"当时是否停车过深/过浅"。
4. **预留 deeper 触发条件**：任何停在 L2/L3 的决策，必须同步写出"如果后续出现什么情况，需要补做 deeper"。

> **示例**：评估"是否给销售团队新增一套 CRM 工具"——关键变量（采用率、人效提升）可估区间，错误后可撤换（撤回成本约 2-3 万/月），结论对±30% 不敏感 → 停在 L2；如果试点后采用率超预期，再补 L3 漏斗。

## 目的

解决"决策深度不对：要么想太少（拍脑袋），要么想太多（分析瘫痪）"的问题。适用于：判断一个决策应该花多少时间/资源、避免"大事拍脑袋、小事纠结死"、团队对齐决策的颗粒度。不是让你"每个决定都想透"，是让你用"决策深度阶梯"匹配"决策重要性"——大事想透，小事快速过。

## 操作步骤

1. **第一步：用L1-L4框架判断决策重要性**——L1（创意/方向）：想1天，最多1周；L2（PMF验证）：想1-2周，最多1个月；L3（规模化）：想1-2个月，需要数据支撑；L4（壁垒/护城河）：想3-6个月，需要外部视角。决策重要性越高，想的深度越深，参与的人越多
2. **第二步：匹配决策工具和方法**——L1用"快速原型+用户访谈"、L2用"五步法+单元模型"、L3用"增长实验+数据复盘"、L4用"壁垒四问+外部专家诊断"。工具深度必须匹配决策深度，不要拿大炮打蚊子，也不要拿水果刀上战场
3. **第三步：设置"决策截止时间"和"验证机制"**——深度想清楚后，必须设一个"截止时间"（如L2决策最多想2周），到点就做。同时设"验证机制"（如L2决策后1个月看PMF指标），根据现实反馈调整。决策是"假设"，不是"真理"

## 不要用的场景

- 危机决策（如系统宕机、公关危机）——先止损，事后复盘
- 纯执行层决策（如选哪个供应商、定哪天发布）——L1深度就够了，不要过度分析
- 创始人直觉极强且历史验证过的领域——有些决策"想多了"反而错，直觉比分析快
- 团队还不理解L1-L4框架就强制使用——会变成"形式主义"，大家填表但不思考

## 质疑

**Mandy Wu**：决策深度阶梯最大的问题是"静态视角"——你假设决策重要性是固定的，但现实是：同一个决策，在 different context 下重要性不同。比如"是否加一个新功能"，对早期项目（L1-L2）可能是"方向判断"（L2深度），对成熟项目（L3-L4）可能只是"优化迭代"（L1深度）。你需要加一个"决策重要性动态评估"步骤：每次决策前问"这个项目现在在哪个阶段？这个决策在这个阶段的权重是多少？"

**Nick Zhang**：这个方法有个"决策疲劳"的风险——你每做一个决策都要先判断"这是L几"，然后匹配工具和方法，然后设截止时间...太累了！创业者每天要做几十个决策，如果每个都走这个流程，会累死。建议只对有"可逆性低、错误成本高"的决策用这个框架，其他决策靠直觉或简单规则快速过。

**Olivia Wang**：决策深度阶梯最严重的盲区是"忽略了组织能力"——你假设团队有能力完成L1-L4的所有分析，但现实是：大部分团队连"单元模型"都算不清楚。如果团队能力跟不上，给你L4的框架也没用。建议你加一个"团队能力诊断"步骤：在做决策深度设计之前，先评估团队有没有能力完成这个深度的分析。如果没有，要么降维（用更简单的工具），要么补能力（培训或招人）。

**前提与边界**：决策深度阶梯的前提假设是"决策重要性可以预先判断"——反例是危机决策中，重要性在事后才显现。适用边界：本框架适用于可分析的商业决策，不适用于需要即时响应的运营决策。具体假设"更深分析 = 更好决策"在信息不完整时失效——此时 L1 直觉可能比 L3 精算更可靠。
