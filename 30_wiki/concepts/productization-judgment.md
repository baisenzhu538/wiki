# 产品化判断四维度

> 学完一个 AI 工具后，用四个维度判断它在产品里的位置。能答出「不能做什么」，才算真正理解。

## Summary

产品化判断是把「会用工具」升级为「会用工具做产品决策」的关键能力。

四个维度：
1. **适用场景**：这个工具最适合解决什么类型的问题？
2. **不适用场景**：这个工具不适合什么？什么情况下不该用它？
3. **集成位置**：如果放进产品里，它应该在哪个层级？
4. **组合可能性**：它能和哪些工具组合产生 1+1>2 的效果？

## The Four Dimensions

| 维度 | 核心问题 | 示例 |
|:---|:---|:---|
| **适用场景** | 最适合解决什么问题？ | "批量生成电商主图、快速迭代营销素材" |
| **不适用场景** | 什么情况下不该用？ | "需要精确品牌一致性的大型 campaign、高精度印刷" |
| **集成位置** | 在产品架构里放哪一层？ | "运营后台的素材生成模块，通过 API 调用" |
| **组合可能性** | 能和哪些工具组合？ | "+ 提示词管理工具做模板库；+ 数据分析工具做 A/B 测试" |

## Core Claims

### claim:01 [conf=0.85] 能说清「不能做什么」比只说「能做什么」更重要

大多数人只会列工具的优点。真正的判断力体现在知道边界在哪里——什么场景下这个工具会失效。

### claim:02 [conf=0.80] 产品化判断是 AI 工具学习的最高产出

一个工具的操作细节很快会过时，但「这个工具适合什么场景、放在产品哪一层」的判断会持续有价值。

### claim:03 [conf=0.80] 产品化判断需要在真实业务场景中验证

只坐在电脑前想的产品化判断是猜测。必须结合实际业务需求、用户场景、技术架构才能准确。

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:---|
| ✅ 适合 | 评估 AI 工具在产品中的可用性 |
| ✅ 适合 | 需要向团队/客户解释工具价值 |
| ✅ 适合 | 作为 AI 工具学习曲线的最终产出 |
| ❌ 不适合 | 纯个人兴趣学习，无产品场景 |
| ❌ 不适合 | 对工具完全不了解时（先跑前 4 阶段） |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| **只写适用场景** | 全是优点 | 强制写不适用场景 |
| **判断太泛** | "适合各种场景" | 举 2-3 个具体例子 |
| **脱离业务** | 判断都是技术层面 | 结合真实业务场景写 |
