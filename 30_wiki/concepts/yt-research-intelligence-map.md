# 情报获取全景地图：13+渠道穷尽手段

> 来源：一堂《调研武器库》课程核心内容 | 解决问题："信息在哪里？还能怎么找？"——将商业调研中95%的常用情报获取渠道系统化整理为"三端七点"框架，从内核到外围逐层拓展。

## Constraints & Boundaries

### 适用边界
| 边界 | 说明 |
|:-----|:------|
| ✅ **适合：商业调研中信息缺口大、需要多源交叉验证的决策** | 如进入新市场、评估竞品、验证商业模式假设，单一来源无法建立足够置信度 |
| ✅ **适合：调研目标明确、信息对决策影响显著的场景** | 信息价值≥调研成本时，多渠道投入才有 ROI；目标越清晰，渠道选择越精准 |
| ✅ **适合：团队具备基本调研执行能力（访谈、搜索、数据解读）** | 地图上的渠道需要不同能力组合，团队至少能执行其中 5-7 个渠道 |
| ✅ **适合：时间窗口≥1-3 天的中短期调研** | 13 个渠道的完整遍历无法压缩到几小时内，但也不必无限拉长 |
| ❌ **不适合：信息已充分公开、单一权威来源即可确认的事实** | 如查询公司注册信息、公开财报核心数据，使用完整地图是过度杀伤 |
| ❌ **不适合：信息价值低、不值得投入多渠道成本的琐碎问题** | 如确认某功能是否存在，用 1-2 个渠道快速验证即可 |

### 常见失败模式
| 模式 | 症状 | 修复 |
|:-----|:------|:-----|
| **搜索引擎依赖症** | 调研 2 小时后，所有信息都来自百度搜索、AI 摘要和公众号二手文章；找不到一手数据，结论人云亦云 | 强制使用"三端三角"：每次调研至少选 1 个产品本身渠道（如亲自体验）、1 个用户端渠道（如访谈/社群）、1 个公开数据渠道（如财报/专利） |
| **为穷尽而穷尽** | 调研笔记超过 50 条，但 70% 与决策问题无关；团队陷入"再找一条"的惯性，迟迟不进入分析 | 先写"信息价值声明"：这个信息会改变哪个决策？值多少钱？超过预算时间后，新增信息必须能推翻已有结论才继续 |
| **来源黑箱** | 汇报时只能说"网上看到""有人说"，无法追溯原始出处；不同成员引用的"数据"其实是同一篇洗稿文章 | 建立"情报来源卡片"：每条关键信息记录来源 URL/访谈对象、采集时间、可信度等级（高/中/低）；同一来源只算一条独立证据 |
| **把收集当终点** | 收集了 13 个渠道的信息，但没有整合到同一框架下；不同渠道的数据互相矛盾，没有标注冲突点 | 使用"冲突标注法"：在分析文档中专门开辟"渠道冲突区"，列出矛盾信息及其来源动机（利益相关方/时效性/统计口径），再判断哪条更可信 |
| **灰色渠道合规盲区** | 使用爬虫、前员工套取、社会工程学等手段获取信息，未评估法律与合规风险 | 先划分"红/黄/绿"渠道：绿色（公开/授权）优先；黄色（需脱敏/匿名）需合规确认；红色（可能违法）禁用，改用官方披露或正规咨询报告 |

## Summary

情报获取全景地图是OSL框架第4步"获取情报"的实操扩展，将商业调研中的情报获取渠道按"三端（用户端、合作方、产品本身）—内部（员工、发布、数据）—外部（专家、数据、报告）"分层组织。每个节点下附着具体的策略和案例，形成从内核到外围的情报穿透路径。核心原则：如果你还没有把这张地图上的渠道穷尽，不要轻易说"找不到信息"。

与[[yt-lean-qualitative-quantitative-research]]配合使用时，可先用定性渠道（用户访谈、专家访谈）建立假设，再用定量渠道（问卷、平台数据、爬虫）验证规模。

## Claims

### 核心定位

情报地图在一堂知识体系中的坐标：[[yt-research-osl-framework]]的子系统，专注于"怎么找"而非"找什么"。与[[yt-research-competitor-toolkit]]、[[yt-research-expert-interview]]等工具卡形成"总图-工具"关系——地图告诉你去哪找，工具卡告诉你怎么找。

### 三端七点框架

| 层级 | 节点 | 信息深度 | 获取难度 | 核心策略 |
|------|------|---------|---------|---------|
| **三端（产品本身）** | 1. 完整体验产品 | 最深（直接接触） | 低（自己用） | 软件逐功能测试、硬件拆解、线下神秘顾客 |
| | 2. 数据分析/逆向工程 | 深（反编译内部） | 中（技术门槛） | APP分析、网站爬虫、芯片拆解、成本反推 |
| | 3. 用户端调研 | 深（直接见用户） | 中（需要资源） | 用户访谈、问卷、社群观察、评论区挖掘 |
| | 4. 合作方/供应链 | 深（上下游关系） | 高（需要关系） | 供应商调研、猎头信息、投资机构访谈 |
| | 5. 合作伙伴/渠道 | 深 | 高 | 代理商访谈、渠道走访 |
| **内部（公司内）** | 6. 员工/前员工 | 中（一手信息） | 中（社会工程学） | 领英职位拆解、前员工访谈、薪酬套取 |
| | 7. 官方发布 | 中（公开但筛选） | 低（公开信息） | PR稿、年报、白皮书、海报、官网、招股书 |
| | 8. 内部数据 | 中 | 高（需要牵线） | 行业数据平台、专业数据库、芯片交易量 |
| **外部（市场环境）** | 9. 行业专家 | 中 | 中（需要约访） | 行业专家访谈、协会、行业大佬 |
| | 10. 数据分析 | 浅（表层趋势） | 低 | 爬虫、平台数据监控、另类数据 |
| | 11. 行业报告 | 浅 | 低 | 综合报告、垂直报告、专题研究 |
| | 12. 社交媒体/舆情 | 浅 | 低 | 微博、知乎、豆瓣、小红书、脉脉 |
| | 13. 专利/知识产权 | 中 | 低 | 专利库、论文、技术百科 |

### 五个必备概念

在使用情报地图前，需先掌握这五个商业调查领域的基础概念：

| 概念 | 定义 | 应用场景 |
|------|------|---------|
| **尽职调查(DD)** | 投资前对标的公司进行全面调查（经营、财务、法律、合规） | 投资决策、重大合作前的风险筛查 |
| **逆向工程** | 拿到成品后倒推设计逻辑、算法、成本结构 | 产品拆解、成本反推、竞品分析 |
| **社会工程学** | 通过人的关系链、信任获取信息 | 套取薪酬、获取内部数据、产品成本 |
| **另类数据** | 通过非传统渠道（地理、手机信号、舆情）获取经营信号 | 美团营收预测、特斯拉产量估算、投资决策 |
| **爬虫** | 通过程序自动抓取网络数据 | 市场监控、竞品数据收集、资讯追踪 |

## 实战模板：SaaS 竞品调研 30 分钟渠道速查清单

以"评估一款垂直 SaaS 竞品的市场真实占有率与用户满意度"为例，演示如何根据决策价值选择渠道，而非机械遍历 13 个渠道。

| 阶段 | 时间 | 目标信息 | 推荐渠道组合 | 退出标准 |
|:-----|:-----|:---------|:-------------|:---------|
| **0. 定义价值** | 0-5 min | 明确这条信息对决策值多少钱 | 自问：如果占有率低于 X%，我会放弃进入吗？ | 写出"信息价值声明" |
| **1. 产品本身** | 5-10 min | 产品功能边界、定价策略 | 完整体验产品（试用账号）+ 官网定价页 + 招股书/招贤书 | 列出功能清单与价格档位 |
| **2. 用户端** | 10-18 min | 真实用户评价、替换成本 | 社群观察（微信群/知识星球）+ 评论区挖掘（知乎/脉脉）+ 用户访谈 1-2 人 | 收集 ≥5 条负面反馈 + 3 条正面反馈 |
| **3. 合作方/供应链** | 18-24 min | 渠道政策、上下游依赖 | 代理商访谈（假装采购）+ 猎头信息（招聘需求反推业务规模） | 确认主要获客渠道与分成比例 |
| **4. 公开数据** | 24-30 min | 市场规模、融资/财务信号 | 行业报告（2-3 份）+ 工商/融资数据库 + 专利/知识产权检索 | 获得 ≥2 个独立来源的同一量级数据 |
| **5. 交叉验证** | 同步 | 发现矛盾点时启动 | 专家快问 1 人（15 min 电话） | 解释清楚最大矛盾点 |

> **使用原则**：如果某渠道在 5 分钟内无法获得有效信息，立即切换下一个，不要死磕。30 分钟后必须产生"占有率区间判断 + 3 个关键假设"。

## Critique

### 内部局限

情报地图的三条边界声明揭示了框架的内在张力：

- **"完整性假象"风险**：地图给人一种"我已经拥有全部渠道"的安全感，但真实情况是市场上还有大量"水下"渠道（行业私密社群、小众航班圈子、机构内部数据库）不在地图上。完整性是假象，是一个动态补充的过程。
- **渠道能力的不均衡**：13个渠道的"能力门槛"差异巨大——"社交媒体观察"只需要手机和时间，"内部数据"可能需要几个月的关系经营。地图隐藏了"能力门槛"这个维度，导致用户对某些渠道的难度估计不足。
- **地图的"过时性"问题**：数据平台、AI工具、社交媒体平台的可用性每年都在变化。今天能用的爬虫工具明天可能被反爬机制封死。地图需要定期更新。
- **源头材料盲区**：地图容易让人把注意力放在"找更多渠道"，而忽略了对原始材料本身的理解。参考[[dk-foresight-source-material-blindness]]：如果只处理二手信息，渠道再多也无法产生真正的洞察。

### 外部攻击

#### Daniel Ellsberg 的"信息不确定性"：批判

**Daniel Ellsberg**（决策理论家，《不确定性下的决策》作者）对"穷尽手段"的核心假设提出根本溢出：

- **信息的"本质不确定性"无法通过更多渠道消除**：Ellsberg证明，当事人面对"未知概率"时，不确定性本身就是信息的属性，而非信息不足的临时状态。"穷尽手段"暗含假设：只要我们找得够多，就能消除不确定性。但Ellsberg认为，对于创新决策、战略选择这类"完全没有先例"的场景，不确定性是本质性的，无法通过更多信息收集消除——你不可能找到不存在的信息。
- **"信息支配"的不均等**：Ellsberg的研究表明，人们对信息的使用不是公平的——你会偏爱"确定的"信息（即使它是错的）而回避"不确定的"信息（即使它更有价值）。情报地图的13个渠道中，哪些是"确定的"（官方数据、公开报告），哪些是"不确定的"（社会工程学、前员工访谈）？Ellsberg质疑：如果你的团队天性偏好确定信息，地图会被用作"回避不确定性"的工具，而非"面对真实"的工具。
- **适用范围：什么时候"穷尽"是有害的**：在"高风险、高不确定性、低可逆性"的决策中，"穷尽手段"可能延迟决策、增加决策成本，最终导致"分析瘫痳"。Ellsberg的替代方案：在不确定性高的场景中，应该采用"柔性决策"——设计可逆、可调整的行动方案，而非在收集信息上无限投入。

#### Yochai Benkler 的"网络公共领域"：批判

**Yochai Benkler**（哈佛法学院教授，《富足的网络》作者）从信息生态和平台经济学角度对情报地图提出结构性质疑：

- **平台封闭导致地图失效**：Benkler证明，当下互联网的核心趋势是"平台封闭"——Facebook、LinkedIn、知乎等平台的可爬取数据比五年前减少了90%。情报地图中的"社交媒体"、"评论区挖掘"、"爬虫"等渠道在平台封闭趋势下加速失效。今天有效的渠道，明天可能被API政策或反爬机制封死。
- **信息的"集中化"风险**：Benkler认为，当信息生产被少数平台垂断时，"多渠道交叉验证"本身就变得可疑——因为所有渠道可能都在消化同一套算法推荐的信息。如果你的"社交媒体"、"行业报告"、"专家观点"都来自同一个信息生态，交叉验证只是同一个假象的不同投影。
- **"另类数据"的新集中化**：Benkler警告，"另类数据"（地理信号、消费记录、移动轨迹）正在被少数数据买卖平台垂断。普通创业者无法获取这些数据，地图中的"另类数据"渠道正在从"大众工具"变成"大型机构特权"。
- **替代方案**：Benkler的理论暗示，在平台封闭时代，"情报地图"需要从"渠道列表"升级为"关系网络"——你的情报能力不取决于你知道多少个渠道，而取决于你在信息生态中的"位置"——你是否处于某个行业的信息交流网络的核心节点。

## Synthesis

### 不要用的场景

| 场景 | 为什么失效 | 替代方案 |
|------|-----------|---------|
| **紧急决策场景（时间窗口<2小时）** | 13个渠道的完整遍历需要大量时间，紧急场景需要的是"最佳猜测"而非"穷尽验证"。 | 采用"专家快问"模式：用1个电话/微信问1-2个行业老兵，15分钟内获取"够用的"信息，而非"完整的"信息。 |
| **信息已经足够明确的场景** | 如果调研目标是"确认一个已知事实"（如"这家公司是否存在"），使用完整地图是过度杀伤。 | 采用"单点打穿"：直接使用最可能的1-2个渠道（如工商信息、官网），验证即止。 |
| **高度规管的行业（金融、医疗、政府）** | 社会工程学、前员工访谈、爬虫等渠道可能触及合规红线。 | 使用官方公开渠道（年报、监管披露、招标信息）+正规咨询公司报告，避开灰色地带。 |

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|---------|-----------|---------|
| **团队成员说"找不到信息"或"没有数据"时** | 打开情报地图，按"三端七点"从内到外逐层检查：产品本身→用户→合作方→内部→外部 | 至少发现2个"之前完全没想到"的渠道；如果每个节点都已尝试过，才能说"真的找不到" |
| **开始一个新行业/新产品调研时** | 先用"行业画布"（[[yt-research-industry-canvas]]）快速定位，再用情报地图选择渠道 | 30分钟内确定"我需要哪3类信息"，而非无差别地搜索 |
