# 单元模型六段进阶：从不会算账到动态预判

> 来源：一堂《单元模型实操系列课》完整进阶体系。单元模型的操盘能力从 L1（不算账）到 L6（动态预判）构成一条完整的商业分析能力进阶路径。每个段位都有明确的判断标准、典型错误和能力盲区。

## Summary

单元模型六段进阶路径（L1→L6）是一条从"商业直觉"到"系统量化"再到"动态预判"的能力进化路线。L1-L2 解决"有没有意识"，L3-L4 解决"能不能算准"，L5-L6 解决"能不能预判"。本框架提供每个段位的判断标准、典型错误清单和升段路径，帮助操盘手定位自身段位、识别盲区、制定进阶计划。

## Claims

### 六段进阶路径

```
L1 不算账 ──→ L2 粗算账 ──→ L3 找单元 ──→ L4 建模型 ──→ L5 算得准 ──→ L6 动态预判
     │            │            │            │            │            │
  没意识      有意识但      找到核心      完整拆解      数据准确      预判未来
  不量化      算不清楚      经济单元      收入成本      静态准确      调整对抗
```

**L1 不算账**：看到商业机会只凭直觉，不计算收入成本。典型表现："我觉得这个生意能成"、"别人都在做所以我也做"。

**L2 粗算账**：有量化意识，但只算大头、漏算隐性成本。典型表现：算收入时乐观估计、算成本时只算直接成本忽略间接成本、不考虑时间成本。

**L3 找单元**：能够找到业务的核心经济单元（单订单/单用户/单门店等），并判断该单元是否成立。典型表现：明确说出"我们赚的钱=单用户LTV-单用户CAC"，但单元模型可能不完整。

**L4 建模型**：能够完整拆解单元的收入项和成本项（拆推评算/练推借查），建立可复用的单元模型框架。典型表现：画出完整的单元模型公式，识别出至少 80% 的收入来源和成本项。

**L5 算得准**：单元模型公式完整，数据准确，但仍是静态的——能算清楚"现在"，不能预判"未来"。典型表现：模型中的每个数字都有来源（基准值、历史数据、行业数据），但不考虑规模变量、环境变量的影响。

**L6 动态预判**：不仅算清楚现在，还能预判单元模型如何随规模、时间、竞争变化，并制定调整策略。典型表现：建立"三点预测"（乐观/基准/悲观），识别拐点，设计规模经济对抗方案。

### 常见错误清单（15 个段位盲区）

| 错误 | 典型表现 | 多发段位 |
|:---|:---|:---|
| **只算收入不算成本** | "这个项目一年能做 1000 万"——但没算需要投多少钱、养多少人 | L1→L2 |
| **找不到核心单元** | 试图同时分析"单订单+单用户+单门店"，结果哪个都算不清楚 | L2→L3 |
| **把规模当单元** | 用"全公司月收入"代替"单订单收入"，混淆总量与单元 | L2→L3 |
| **漏算隐性成本** | 只算物料成本，不算获客成本、运维成本、管理成本、资金成本 | L2→L3 |
| **把毛利当净利** | 用"收入-直接成本"判断盈利，忽略税费、折旧、摊销、资金占用 | L3→L4 |
| **成本项找不全** | 用了"拆推评算"但漏掉了最关键的 1-2 个成本项 | L3→L4 |
| **收入项过于乐观** | 用"最高客单价×最大转化率"计算收入，而非"平均客单价×实际转化率" | L3→L4 |
| **模型无法验证** | 单元模型中的数字都是假设，没有数据来源，无法被验证或证伪 | L4→L5 |
| **基准值拍脑袋** | "行业平均转化率 5%"——但这个数字是从哪来的？有没有依据？ | L4→L5 |
| **忽视时间维度** | 单元模型是静态的，没有考虑"回本周期"、"现金流节奏"、"季节性波动" | L4→L5 |
| **忽视竞争变量** | 假设市场只有自己，没考虑对手降价、新进入者、替代方案 | L5→L6 |
| **忽视规模变量** | 假设"单单元盈利=规模化盈利"，没考虑规模扩大后的边际成本变化 | L5→L6 |
| **忽视环境变量** | 没考虑政策变化、技术变革、消费习惯迁移对单元模型的影响 | L5→L6 |
| **预测过于乐观** | "三点预测"的乐观情景和悲观情景差距太小，实际波动远超预期 | L5→L6 |
| **算完不调** | 单元模型算完了就束之高阁，没有建立"按月/按季更新"的机制 | L5→L6 |

## Constraints & Boundaries

- claim:boundary-01 [conf=0.85] **段位评估是相对的，不是绝对的**：L3 的标准在不同行业差异巨大。互联网 SaaS 的 L3 可能需要理解 LTV/CAC，而餐饮的 L3 只需要理解"单店模型"。跨行业比较段位没有意义。
- claim:boundary-02 [conf=0.80] **段位不等于业绩**：一个 L5 的操盘手可能在夕阳行业，单元模型算得再准也改变不了行业趋势；一个 L3 的操盘手可能在风口行业，即使模型粗糙也能赚钱。
- claim:boundary-03 [conf=0.80] **升段需要刻意练习，不是自然积累**：很多创业者做了 10 年生意仍在 L2——因为他们从未系统训练过单元模型分析。"经验丰富≠段位高"。
- claim:boundary-04 [conf=0.75] **L6 的预测准确率被高估**：即使是最优秀的动态预判，在复杂商业环境中的准确率也有限。L6 的核心价值不是"预测对"，而是"提前建立应对框架"。

## Critique

### 外部攻击

#### Gerd Gigerenzer — 生态理性与启发式决策

> "在不确定的世界里，少即是多。复杂的模型往往比简单的启发式规则表现更差。"

Gigerenzer 在《Adaptive Thinking》和《Gut Feelings》中提出的"生态理性"理论直接挑战了"六段进阶"背后的隐含假设——"越量化越好"。

- **L1-L2 的直觉可能比 L5-L6 的复杂模型更有效**：Gigerenzer 的实验表明，在信息不完全、时间压力大的环境中，"再认启发式"（recognition heuristic）和"选取最佳"（take-the-best）等简单规则，往往优于复杂的回归模型。一个 L1 的创业者凭直觉判断"这个地段开奶茶店能成"，可能比一个 L5 分析师用 20 个变量建立的模型更准确——因为模型无法包含"这条街的烟火气"这种难以量化的信息。
- **段位进阶可能制造"分析瘫痪"**：从 L3 到 L6，分析复杂度指数级上升。Gigerenzer 警告，"当分析成本超过决策收益时，更多的分析就是更差的决策"。一个创业者在 L3 阶段就能做出 80 分决策，强行推到 L6 反而可能因为"过度拟合数据"而做出 60 分决策。
- **"基准值"可能是认知陷阱**：L4-L5 高度依赖"行业基准值"，但 Gigerenzer 指出，基准值往往是赢家的事后归纳，而非可复制的因果规律。用"行业平均转化率"作为自己单元的预测基准，忽略了生态位差异——你的用户、渠道、产品都与行业平均不同。

**失效机制**：当业务环境高度不确定、数据稀缺、时间压力大时，"六段进阶"中的高段位模型反而成为负担。此时 L1-L2 的"快速启发式"可能比 L5-L6 的"精细模型"更有效。

#### Dave Snowden — Cynefin 框架与复杂性域决策

> "在复杂域中，你不应该分析——你应该探测。"

Snowden 的 Cynefin 框架将决策环境分为五类：清晰（Clear）、繁杂（Complicated）、复杂（Complex）、混沌（Chaotic）、混乱（Confused）。"六段进阶"的问题在于：它假设计算环境是"繁杂"的（complicated）——即通过足够的数据和分析可以得出正确答案——但多数商业环境实际上是"复杂"的（complex）。

- **L5-L6 在复杂域中失效**：Snowden 指出，在复杂域中，"因果关系只有在事后才能理解，事前无法预测"。L6 的"动态预判"假设"如果我们知道足够多的变量，就能预测未来"——但复杂系统的关键特征就是"不可预测"。你分析了 50 个变量，但第 51 个变量（一个突发政策、一个竞品动作、一个技术突破）可能完全改变游戏规则。
- **"三点预测"是虚假的控制感**：L6 的"乐观/基准/悲观"三点预测给用户一种"我已经考虑了不确定性"的安慰。但 Snowden 会指出：真正的复杂性不是"在三个已知情景中选择"，而是"存在你根本无法想象的情景"。三点预测的范围往往过于狭窄——真正的黑天鹅永远在预测之外。
- **"段位"概念本身可能是危险的**：Snowden 强调，复杂域中需要的是"安全探测"（safe-to-fail probes）而非"精确分析"。"六段进阶"可能让人误以为"只要我升到 L6，就能掌控商业未来"——这是一种对复杂性的傲慢。

**失效场景**：当业务处于新兴市场、技术快速迭代、政策高度不确定的环境时，"六段进阶"从 L3 开始的所有高段位分析都可能产生"精确的幻觉"。此时应该用"快速实验+快速迭代"替代"精确预判"。

### 内部局限

- **"15 个错误"清单可能不完整**：不同行业的错误类型差异很大，本清单基于一堂学员案例归纳，可能遗漏特定行业的关键错误。
- **段位之间的过渡不连续**：从 L3 到 L4、L4 到 L5 需要的能力跃迁很大，但框架没有提供"过渡期"的具体训练方法。
- **缺少"如何教别人"的段位**：框架只关注个人段位，没有涉及"如何让团队也达到 L3/L4"——而这往往是规模化复制的瓶颈。

### 不要用的场景

| 场景 | 为什么失效 | 替代方案 |
|------|-----------|---------|
| **用段位评价他人能力** | 段位评估应只用于自我诊断，而非对他人贴标签。给合伙人/员工贴"你只有 L2"的标签会破坏信任。 | 用"能力 gap 诊断"替代"段位评定"——聚焦"具体哪个能力需要补"，而非"你属于哪个段位"。 |
| **强迫团队所有人达到同一段位** | 创始人可能需要 L5-L6，但销售负责人可能只需要 L3，设计师可能只需要 L2。统一升段要求会造成资源错配。 | 按角色定义"最低段位要求"：创始人 L5+、业务负责人 L4+、执行层 L2-L3。 |
| **在危机中用"升段"替代"行动"** | 公司现金流断裂时，创始人花两周时间"系统学习 L6 动态预判"是逃避行为。 | 危机模式下直接行动：砍成本、找收入、谈融资。等危机解除后再系统补段位。 |

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|---------|-----------|---------|
| **不确定自己的单元模型段位在哪里** | 对照"六段进阶"标准，诚实自评：你目前能完整列出单元的收入项和成本项吗？你的数字有数据来源吗？你能预判未来三个月的变化吗？ | 在 10 分钟内给自己定位到具体段位（不是区间），并写出"升到下一段位需要补的 1 个具体能力" |
| **团队交上来的单元模型一看就有明显错误** | 不要直接修改，而是用"15 个错误清单"做诊断：这是"漏算隐性成本"（错误 #4）还是"把规模当单元"（错误 #3）？标注具体错误编号。 | 产出 1 份"错误诊断报告"，含错误编号+具体例子+修正建议，而不是直接给正确答案 |
| **觉得自己算得很准，但业务仍然不达预期** | 做"段位盲区检查"：如果你是 L5，问题可能是"忽视竞争变量"（错误 #11）或"忽视规模变量"（错误 #12）。如果你是 L4，问题可能是"模型无法验证"（错误 #8）。 | 找到 1 个具体盲区，产出"假设清单"——列出模型中"我假设为真但可能为假"的 3 个前提 |
| **投资人要求"动态预测"，但你只有静态模型** | 不要硬编数字。先做"变量清单"：列出所有可能影响单元模型的外部变量（政策、竞争、技术、消费习惯），标注每个变量的"可预测性"和"影响程度" | 产出 1 张"变量热力图"：高影响+高可预测性的变量先做三点预测，高影响+低可预测性的变量先做"情景分析"而非"精确预测" |
