# 清单体故事线①：严格时间线——用时间轴重构事件因果链

## Condense

严格时间线是清单体笔记最基础也最强大的故事线之一。它的核心不是"按时间顺序记录"，而是**用时间轴作为因果关系的骨架**。

**核心操作**：将事件按时间顺序排列，每个时间点只记录"发生了什么"和"导致了什么"，删除所有解释、评价和推测。

**关键原则**：
- 最严格：时间顺序不可打乱
- 不追求华丽：不用修辞，只用事实
- 最贴近事实：每个时间点必须有可验证的来源
- 极其简洁清晰：每个时间点一句话，不超过两行

**输出形态**：
```
- T0: 事件发生前状态
- T1: 触发事件A
- T2: 事件A导致结果B
- T3: 结果B触发事件C
...
```

## Question

**为什么"严格"比"完整"更重要？** 因为时间线的价值在于**暴露因果链中的断裂点**。如果你在其中混入了解释和评价，读者就无法判断"这是事实"还是"这是你的解读"。严格的时间线让读者自己发现因果，而因果的自行发现比被告知更有说服力。

**时间线和流水账的区别是什么？** 流水账是"我做了什么"，时间线是"什么导致了什么"。关键差异：时间线的每个节点都必须包含**状态变化**（before/after），而流水账只记录动作。

## Critique

### 攻击者1：叙事学家——"严格时间线扼杀了故事的灵魂"

Mona Baker的叙事理论指出，人类理解世界的方式是**叙事性**的，而非**编年性**的。严格时间线剥离了情感、动机、背景，把丰富的人类经验压缩成干瘪的"事件A导致事件B"。这种格式适合法庭记录，不适合知识传递。真正有价值的不是"发生了什么"，而是"为什么这很重要"。

### 攻击者2：复杂系统科学家——"线性因果是工业时代的幻觉"

在复杂系统中，因果关系不是线性的，而是**网络状的**——多个因素同时作用，反馈循环无处不在。严格时间线强制把网状因果压缩成线性序列，这是一种认知暴力。它让你"感觉"理解了，实际上你只是在用一个过时的框架自欺欺人。气候变化、经济崩溃、社会运动——这些都不能用严格时间线理解。

## Synthesis

严格时间线的真正价值不在于"记录"，而在于**暴露**。当你强制自己只用时间轴来组织信息时，你会突然发现很多"理所当然"的因果关系其实站不住脚。

[[yt-note-checklist-concept]] 中的"分层"特征在时间线中得到极致体现：第一层是时间点本身，第二层是每个时间点的状态变化，第三层是跨时间点的因果推断。但只有第一层和第二层属于"严格时间线"的范畴，第三层必须被标注为"推断"而非"事实"。

[[yt-note-five-levels-training]] 中L2-L3的训练核心就是这个：从"我记了什么"（L2）到"我记的东西之间有什么关系"（L3）。严格时间线是训练"关系识别"的最基础工具。

## Constraints & Boundaries

- **适用**：需要追溯因果关系链的场景（事故复盘、项目回顾、历史分析、决策回溯）
- **不适用**：高度复杂的系统分析（需要网络图而非时间线）、情感密集型叙事（需要故事弧而非时间轴）
- **警惕**：不要在时间线中混入"因为...所以..."的解释性语言。时间线只呈现"A发生后B发生"，不呈现"A导致B"
- **边界**：严格时间线最多处理10-15个关键节点。超过这个数量，因果链会变得不可读，需要拆分成多个子时间线

## Cases

**正例：Truman的产品迭代复盘**

Truman用严格时间线复盘一次产品迭代失败：
```
- 2023.03.15: 用户反馈页面加载慢（N=23）
- 2023.03.16: 团队决定优化图片加载策略
- 2023.03.20: 图片懒加载上线
- 2023.03.21: 用户反馈页面加载更慢（N=41）
- 2023.03.22: 发现懒加载脚本与广告SDK冲突
- 2023.03.23: 回滚懒加载，加载速度恢复
```

这个时间线暴露了一个反直觉的因果："优化"导致了"恶化"。如果混入评价（"团队决策失误"），这个反直觉的发现就会被掩盖。

**反例："解释型"时间线**

某产品经理的时间线：
```
- 2023.03.15: 用户反馈页面加载慢（说明用户体验差）
- 2023.03.16: 团队英明地决定优化图片加载策略
- 2023.03.20: 图片懒加载上线（技术团队效率很高）
```

混入评价后，时间线失去了暴露问题的能力。读者看到的是"团队在努力"，而不是"优化导致了新问题"。

**边界案例：10个节点的时间线**

某次危机公关涉及15个关键事件。尝试用一条时间线呈现时，读者在第8个节点后就失去了追踪能力。解决方案：拆分为"事件链"和"决策链"两条子时间线，每条不超过8个节点。

## Action Protocol

| 阶段 | 操作 | 标准 |
|:---|:---|:---|
| **进入标准** | 需要回答"这件事是怎么发生的"时 | 事件涉及≥3个时间节点，且因果关系不明确 |
| **Step 1** | 列出所有已知的时间节点 | 每个节点必须有可验证的来源（邮件/日志/聊天记录） |
| **Step 2** | 按时间顺序排列，删除重复 | 同一时间点只保留最关键的一个事件 |
| **Step 3** | 为每个节点标注"状态变化" | before/after必须可测量（数字/布尔值） |
| **Step 4** | 检查因果链的完整性 | 相邻节点之间是否有"断裂"（A发生后B为什么没有立即发生？） |
| **Step 5** | 标注"推断" | 所有非直接观察到的原因必须标注为[推断] |
| **退出标准** | 时间线呈现后，读者能独立发现≥1个你之前没注意到的因果问题 | 如果时间线只验证了你已知的结论，说明还有隐藏节点未被发现 |

## Attacker

### Attacker 1：叙事心理学家——"严格时间线让人变成认知吝啬鬼"

Walter Fisher的"叙事范式理论"指出，人类天生是"叙事动物"，我们通过故事来理解世界、做出道德判断、形成身份认同。严格时间线剥夺了叙事的"情感共鸣"维度，把知识传递变成了一种冰冷的"数据投喂"。

长期使用严格时间线的人可能会出现"叙事贫困"——他们能精确描述"发生了什么"，但无法回答"这对我意味着什么"。在组织环境中，这意味着决策者能获得完美的"事实清单"，却无法产生"行动意愿"。**数据不能驱动行动，故事才能。**

**当用这张卡的人睡不着时**：他们会想——"我的时间线完美到无可挑剔，但团队看了之后没有任何情绪波动，没有人说'我们必须改变'。我是不是在追求一种'正确但无用'的完美？"

### Attacker 2：系统动力学专家——"时间线是反馈回路的坟场"

Jay Forrester的系统动力学已经证明，真实世界中的因果是**循环的**而非**线性的**。严格时间线把A→B→C的反馈回路切割成A→B和B→C两条独立链条，彻底消灭了"C反过来影响A"的可能性。

更危险的是：严格时间线创造了一种"过去决定未来"的幻觉。它让你相信"如果当初没有A，就不会有B"，但现实可能是"A和B互为因果，同时被D、E、F共同决定"。这种简化在事后复盘中尤其危险——它让你"找到"了一个单一原因，而实际上问题来自系统结构。

**当用这张卡的人睡不着时**：他们会想——"我的时间线找到了'根本原因'，但这个'根本原因'可能只是我在复杂系统中抓到的第一个浮木。真正的问题可能藏在时间线看不见的网络里，而我因为'已经找到了答案'而停止了探索。"
