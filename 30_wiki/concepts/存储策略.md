## Open Questions

- 飞书文档"单文档实时追加"策略的容量上限在哪里？当单文档超过多少条记录后，检索性能会显著下降？前提假设：飞书文档的 API 对单文档大小有隐含限制。
- 自动打标签（关键词提取）的准确率如何评估？误标率超过多少时需要人工干预？边界：关键词提取在领域术语密集的场景中可能失效。
- 多源数据（飞书文档 + 本地 Markdown + 其他 SaaS）的存储策略如何统一？是否存在"数据孤岛"风险？反例：分散存储导致同一信息在多处不同步。
- 存储策略的"冷热分层"如何设计？哪些信息应该高频访问（热存储），哪些可以归档（冷存储）？具体假设：信息的使用频率随时间递减。
- 如何衡量存储策略的 ROI？存储成本（时间 + 工具费用）与信息检索效率之间的平衡点在哪里？
