# "找老的干小的"场景评估框架

> Source: src_20260606_ef4877d0 (马易-AI落地场景识别-口述)

## Summary

一个可独立使用的场景评估工具，用于判断一个业务场景是否适合AI落地。核心原则：**不是找"最好的"，而是找"最适合的"。

| 场景 | 信号 |
|------|------|
| 想用AI但不知道从哪里开始 | 有多个候选场景，但无法判断优先级 |
| AI项目上线后效果不好 | 怀疑场景选择是否有误 |
| 团队对AI落地方向有争议 | 需要客观评估标准 |

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 有多个候选AI场景需要排序选择 |
| ✅ 适合 | 已有≥1个业务流程做过>10次 |
| ✅ 适合 | 团队对AI方向有分歧需要客观标准 |
| ❌ 不适合 | 全新创新业务（无"老的"可找） → 先用人工走通流程 |
| ❌ 不适合 | 需要全公司协调的大项目 → 分解为多个小项目分别评估 |
| ❌ 不适合 | 竞争对手已用AI做得很好 → 考虑竞争差异化而非仅仅优化 |
| ❌ 不适合 | 无明确评估标准（无法判断输出好坏） → 先定义before/after |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **权重迷信** | 盲目使用0.4/0.3/0.3权重，忽视行业差异 | 首月用默认权重，次月根据实际结果调整权重 |
| **小的标准错配** | 大公司的"小"=小公司的"大"，场景评估失真 | 用"1天验证+1周恢复"作为绝对标准，不看组织规模 |
| **检查清单偏差** | 为了让场景通过而故意低估难度 | 引入外部评审：让不参与项目的人独立打分 |
| **老的标准过松** | 把"做过3次"当成"老的"，失败模式不清晰 | 强制要求写出3个常见失败模式，写不出=不够老 |
| **四要素缺一硬上** | 有方法有数据但无判断标准，AI输出无法验收 | 先定义可量化的before/after，再启动评估 |
| **排序后不复盘** | 选了最高分场景但从不验证选择是否正确 | 3个月后复盘：实际结果是否与预测排序一致？偏差>30%则调整权重 |

### 外部攻击

#### Nassim Taleb —— "反脆弱性的缺失"
Taleb在《反脆性》中指出，真正重要的决策应该基于"反脆性"而非"预测"。马易的框架是在"预测"哪个场景最适合AI，但Taleb会问：**如果AI在这个场景中失败了，你的系统能够承受多少损失？**你在选场景时考虑过"失败后的恢复能力"吗？如果没有，那你只是在选择"看起来最好的"，而不是"最安全的"。

#### Michael Porter —— "竞争优势的误区"
Porter强调竞争优势来自于"做不同的事"。马易让你"找老的干小的"，但Porter会问：**如果所有人都在"找老的干小的"，那么竞争优势在哪里？**你是在用AI做"优化"，还是在用AI创造"差异化"？如果只是优化，你的竞争对手也会做。
