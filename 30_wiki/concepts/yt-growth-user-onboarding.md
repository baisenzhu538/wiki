# 用户 onboarding：第一印象设计

> 一堂五步法：onboarding不是教程，而是让用户快速体验到价值的旅程。第一印象决定留存。

## 核心框架

onboarding的核心目标：

```
让用户在最短时间内体验到核心价值（Time to Value < 3分钟）
```

| 阶段 | 目标 | 关键 |
|:---|:---|:---|
| **欢迎** | 让用户感到被欢迎 | 个性化、温暖 |
| **引导** | 引导到核心功能 | 简洁、明确 |
| **价值** | 让用户体验到价值 | 快速、惊喜 |
| **习惯** | 让用户形成使用习惯 | 持续、奖励 |

## 关键洞察

### 1. onboarding的设计原则

| 原则 | 说明 | 示例 |
|:---|:---|:---|
| **简洁** | 步骤少， friction 低 | 3步内完成 |
| **价值前置** | 先体验价值，再注册 | 试用、演示 |
| **渐进披露** | 不一次性展示所有功能 | 按需展示 |
| **个性化** | 根据用户类型定制 | 角色选择 |
| **可跳过** | 用户可跳过引导 | 不强制 |
| **即时反馈** | 每一步都有反馈 | 进度条、提示 |

### 2. onboarding的类型

| 类型 | 说明 | 适用 | 示例 |
|:---|:---|:---|:---|
| **引导式** | 逐步引导用户 | 功能复杂 | 分步教程 |
| **自助式** | 用户自己探索 | 功能简单 | 空白画布 |
| **演示式** | 先展示价值 | 价值不明显 | 视频演示 |
| **渐进式** | 随使用深入解锁 | 功能多 | 等级解锁 |
| **游戏化** | 用游戏机制引导 | 用户年轻 | 任务、奖励 |

### 3. onboarding的评估

| 指标 | 说明 | 健康标准 |
|:---|:---|:---|
| **onboarding完成率** | 完成onboarding的用户比例 | > 70% |
| **Time to Value** | 注册到体验价值的时间 | < 3分钟 |
| **激活率** | 体验核心价值的用户比例 | > 50% |
| **次日留存** | onboarding后次日回来 | > 40% |
| **onboarding满意度** | 用户对onboarding的满意度 | > 4/5 |

### 4. onboarding的优化

| 优化方向 | 说明 | 方法 |
|:---|:---|:---|
| **缩短路径** | 减少onboarding步骤 | 合并、跳过 |
| **价值前置** | 让用户先看到价值 | 试用、演示 |
| **个性化** | 根据用户类型定制 | 角色、场景 |
| **减少 friction** | 降低注册门槛 | 社交登录 |
| **增加反馈** | 让用户知道进度 | 进度条、提示 |
| **设计习惯** | 让用户形成习惯 | 每日任务、提醒 |

### 5. onboarding的误区

| 误区 | 说明 | 避免 |
|:---|:---|:---|
| **功能展示** | 展示所有功能 | 只展示核心价值 |
| **强制引导** | 用户不能跳过 | 可跳过 |
| **忽视用户类型** | 所有用户统一onboarding | 个性化 |
| **onboarding结束就不管** | 忽视后续体验 | 持续优化 |
| **忽视数据** | 不监控onboarding效果 | 数据驱动 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **onboarding太长** | 用户不耐烦 | 缩短 |
| **核心价值不清晰** | 用户不知道产品有什么用 | 明确价值 |
| ** friction 高** | 注册、使用 friction 高 | 降低 |
| **忽视用户反馈** | onboarding后用户流失 | 用户访谈 |
| **onboarding后不管** | 用户很快流失 | 持续价值 |
| **一刀切** | 所有用户统一 | 个性化 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新用户转化 | 老用户运营 |
| 产品体验 | 技术架构 |
| 激活优化 | 品牌传播 |
| 留存提升 | 一次性决策 |
