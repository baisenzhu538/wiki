# 技能：清单小抄工具箱法

## 原始表述
> L1.清单小抄 √清单：完整的清单/目录 便于执行 √合集：工具箱/模板库

## 操作步骤
1. 将经验转化为完整清单/目录
2. 建立工具箱/模板库合集
3. 确保格式便于立即执行

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 重复性工作场景，需要标准化防遗漏 |
| ✅ 适合 | 团队协作标准化，减少决策疲劳 |
| ✅ 适合 | 关键环节检查，防止人为疏忽 |
| ✅ 适合 | 有先例可循的工作，可提炼为清单 |
| ❌ 不适合 | 完全创造性、无先例的工作 → 清单限制创新空间 |
| ❌ 不适合 | 需要灵感突破的工作 → 清单是约束不是推动 |
| ❌ 不适合 | 团队规模小、个人习惯已稳定 → 建清单成本>收益 |
| ❌ 不适合 | 清单维护无人负责 → 建完即过时 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **清单太全** | 清单太长，执行前要先花20分钟看清单 | 清单的价值在精简不在全，好的清单是'关键提醒'不是'完全指南'，控制在5-9条 |
| **用完不更新** | 第一次做的清单三年没改过 | 清单是活的，每次使用后都应该微调，存储的内容应随着经验积累而进化 |
| **只建不用** | 工具箱里有50个清单小抄，但每次执行还是靠记忆 | 清单的价值在于'执行时的快速调用'，不是'收集时的满足感'，强制使用习惯 |
| **清单SOP混淆** | 清单是提醒不是指令，但条目写得像SOP | 清单是'检查胎压'，SOP是'必须用左手扭到3.5N·m'，清单提醒关键项不规定具体动作 |
| **过度依赖** | 没有清单就不会做，能力退化 | 清单是辅助不是拐杖，核心能力需内化，清单只用于防遗漏和标准化 |
| **假努力幻觉** | 花大量时间搭建精美清单系统，以为在做系统 | 真正的效率来自于'做'而不是'建'，清单建完必须立即投入使用 |
| **更新成本忽视** | 清单需要持续维护，但团队建完就不管 | 设定清单维护责任人，每次执行后Review是否需要更新 |
| **条目歧义** | 清单条目抽象模糊，不同人理解不同 | 条目必须可操作、可判断、完整独立、可检查、无歧义 |

## Critique

1. **清单的价值在于“精简”不在于“全面”**
   - 清单太长 = 执行前先花20分钟看清单 = 反效用
   - 好的清单是"关键提醒“，而不是"完全指南"

2. **清单是活的——每次使用都应该微调**
   - 第一次做的菜谱三年没改过 = 失去了清单的本质价值
   - 清单是知识的"外化存储“，存储的内容应该随着经验积累而进化

3. **建工具和用工具是两件不同的事**
   - 工具箱里有50个清单小抄但每次执行还是靠记忆 = 工具缺乏使用习惯
   - 清单的价值在于“执行时的快速调用”，而不是“收集时的满足感”

## 工具/环境
- 清单工具
- 模板库
- 共享文档系统

## 判断标准

**什么算一条好的清单条目**：

| 标准 | 好的条目示例 | 坏的条目示例 |
|:---|:---|:---|
| 可操作 | “检查客户留言中是否提及价格异议” | “关注客户需求”（太抽象，不知道怎么做） |
| 可判断 | “确认合同签章页有双方签名+日期” | “确认合同没问题”（什么叫“没问题”？） |
| 完整独立 | “测试登录流程”（单独执行） | “测试”（测什么？前后上下文是什么？） |
| 可检查 | “回复时间 < 2 小时”（有数字） | “及时回复”（多快算及时？） |
| 无歧义 | “确认支付方式为银行转账” | “确认付款”（什么方式？现金？转账？） |

**自检问题**：
1. 这条清单执行完成后，我能明确说“通过/不通过”吗？
2. 如果换一个没经验的人来执行，他能看懂并执行吗？
3. 这条需要多少时间完成？超过 2 分钟就应该拆分
4. 这条的结果是否可以被第三方验证？（而不是只有自己知道做没做）

## 常见失败模式
- 清单太全：把"所有可能要做的事"都列上，每次执行前要先花20分钟看清单——清单的价值在精简不在全
- 用完不更新：第一次做的菜谱三年没改过——清单是活的，每次使用后都应该微调
- 只建不用：工具箱里有50个清单小抄，但每次执行还是靠记忆——建工具和用工具是两件不同的事
- 把清单当SOP：清单是提醒不是指令——"检查胎压"和"必须用左手扭到3.5N·m"不是一回事

## Critique

### 外部攻击

**攻击者1：创意工作者 —— “清单是创造力的敌人”**

> 真正的创造力来自于打破规则而不是遵循清单。如果你的工作每次都按照同一个清单执行，你永远不会有突破。创意工作需要空间和自由度，清单是一种约束——对于需要灵感的工作，它可能是杀手。

**攻击者2：敏捷实践者 —— “清单是‘假努力’的幻觉”**

> 很多人花大量时间搭建精美的清单系统，以为自己在"做系统“，实际上只是在"避免做难事“。清单建得越复杂，执行越低。真正的效率来自于"做“而不是"建“。

### 内部局限

- **不适用于非标准化场景：**完全创造性、无先例的工作无法用清单规范
- **更新成本被低估：**清单需要持续维护，很多团队建完就不管了
- **过度依赖风险：**长期使用清单可能导致"没有清单就不会做”的能力退化
