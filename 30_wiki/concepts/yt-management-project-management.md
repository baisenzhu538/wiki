# 科学项目管理：一堂管项目四步闭环

> **一句话**：项目管理是公司最小的管理单元——做好项目才能带团队、管业务。一堂把项目管理化简为四步（定方案→拆计划→管过程→做复盘），按项目复杂度ABCD分级匹配工具，避免"拿大炮打蚊子"或"拿小锤造航母"。

---

## 一、项目管理的重新理解

### 什么是项目

项目 = 一次性的关键任务，有特定资源、在特定时间内完成一个目标。它跟日常运营（每天都要做的重复性工作）不同。

### 为什么项目管理是"最小管理单元"

素材中反复强调（拆计划口述稿 L98/L2198/L4882，管过程笔记 L67，入门篇笔记 L15）：
> "项目管理其实是所有公司的最小管理单元。做好项目才能带团队，才能管业务。"

项目管理在管理域中的位置：

- **目标管理**：项目是目标落地的最小闭环——公司年度目标拆成季度OKR（`yt-tool-okr-cycle`），每个OKR关键结果由一个项目承载
- **科学决策 / Y模型**：项目是假设验证的最小实验单元——每个项目方案都是"我认为这样能做成"的假设，做完才知对错（`yt-decision-y-model`）
- **时间管理**：项目是时间资源分配的最小容器——所有"这周要做什么"最终落到具体的项目里程碑上（`yt-personal-time-management`）
- **单元模型**：项目是业务单元能力复制的最小实例——成功跑通一个项目=验证了一个可复制的单元模型（`yt-entrepreneur-unit-model`）
- **团队知识管理**：项目是团队知识沉淀的最小场景——每个项目复盘产出的SOP/checklist/案例是最小的团队知识资产（`yt-management-team-knowledge`）
- **科学管理基本功**：项目管理是基本功在"事"上的最小演练场——管人、管钱、管进度、管质量，都在一个项目里练（`yt-management-basic-skills`）

### 初创公司项目管理的典型问题

- 顶层思考不够，协作没节奏，不会写文档，没有章法，缺少工具
- 很多公司一直在"裸跑"——一点机制都没有，逮着项目就硬上
- 无法说服下属，讲不明白道理（入门篇口述稿 L33-L40）

## 二、ABCD 项目复杂度分类

不是所有项目都需要全套工具。一堂按复杂度分四级，工具跟着复杂度走：

| 级别 | 名称 | 特征 | 推荐工具量 | 典型项目 |
|:---:|:---|:---|:---:|:---|
| A | 口头/单人 | 一个人基本完成，不需复杂协作 | 轻 | 写个文档、做个简单物料 |
| B | 简单多人 | 2-5人协作，不涉及跨部门 | 轻-中 | 小型活动、内部培训 |
| C | 跨部门中等 | 涉及多部门、需协调资源 | 中-重 | 产品功能上线、年度市场活动 |
| D | 公司级战略 | 大、不能失败 | 重 | 融资、战略转型、年度大课 |

**核心原则**：工具复杂度跟着项目走——A级项目用甘特图是过度管理，D级项目不写文档是赌博。

详见 `[[framework-yitang-project-abcd-classification]]`。

## 三、四步闭环

```
┌──────────────────────────────────────────┐
│         一堂项目管理四步闭环              │
│                                          │
│  定方案 ──→ 拆计划 ──→ 管过程 ──→ 做复盘  │
│    ↑                             │       │
│    └─────────── 经验回流 ────────┘       │
└──────────────────────────────────────────┘
```

| 步骤 | 名称 | 核心问题 | 一堂工具 | 详见 |
|:---:|:---|:---|:---|:---|
| 1 | 定方案 | 背景是什么？目标是什么？怎么达成？ | 三段论+评估三角形+背景分析8维度 | `[[framework-yitang-project-plan-design]]` |
| 2 | 拆计划 | 方案怎么变成可执行的任务？ | 六维敏感度模型+WBS+RASCI | `[[framework-yitang-project-breakdown]]` |
| 3 | 管过程 | 怎么保证不跑偏？ | 进度/质量/变更+向上管+体验管 | `[[framework-yitang-project-execution]]` |
| 4 | 做复盘 | 怎么把经验变成资产？ | 16字原则+深度选择5维+复盘画布 | `[[framework-yitang-project-retrospective]]` |

## 四、五大自我修养

认知课上 Truman 提出优秀PM需要五个维度的自我修养（入门篇口述稿）：

1. **螺旋思考**：先顶层再细节，先选择再执行，先确认再推进。详见 `[[skill-yitang-project-spiral-thinking]]`
2. **结构化表达**：能把模糊意图写成可执行方案
3. **非授权领导力**：没有直接管辖权的协作推动
4. **风险嗅觉**：提前嗅到"这个地方可能出问题"
5. **复盘习惯**：把每个项目变成团队能力提升的机会

## 五、武器库矩阵

一堂将所有项目管理工具按"ABCD × 四步"组织为一个武器库矩阵（V1.8）：

|  | A 口头 | B 简单 | C 跨部门 | D 战略 |
|:---|:---|:---|:---|:---|
| 定方案 | 口述确认 | 一页纸方案 | 三段论+评估三角 | 完整方案文档 |
| 拆计划 | 口头分工 | 简单排期 | WBS+RASCI | 甘特图+里程碑 |
| 管过程 | 站会 | 周报 | 质量节点+变更管理 | 健康度雷达 |
| 做复盘 | 口头总结 | 简单复盘 | 深度复盘四步法 | 复盘画布+全员复盘会 |

## 六、Constraint & Boundaries

### 适用边界

| 场景 | 适用？ | 说明 |
|:---|:---:|:---|
| 初创公司 50-100 人以内 | ✅ | 本框架专为此设计 |
| 有明确交付物和时间约束的一次性任务 | ✅ | 项目定义本身 |
| 大公司（500+）标准化项目管理 | ⚠️ | ABCD可参考，但工具层可能需要PMBOK级别 |
| 日常重复运营工作 | ❌ | 不是项目 |
| 纯个人任务 | ❌ | 不需要协作工具 |

### When NOT to Use

| 场景 | 替代方案 |
|:---|:---|
| 项目为了融资/获取批准而启动——真实目的不是交付 | Flyvbjerg式诚实估算：用参照类预测代替WBS |
| 项目环境高度不确定——启动时无法写出有意义的计划 | 滚动缓冲管理：只拆2周内5个最关键动作 |
| 团队只有1-2人，互相都知道对方在做什么 | ABCD A级口头工具即可，不需要正式方法论 |

## 七、失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| 工具至上 | 用了工具就以为在管理 | 先建立项目管理思维，再选工具 |
| 范围蔓延 | 项目越做越大 | ABCD升级/降级触发器——变化超过20%重新定级 |
| 只在里程碑检查 | 偏航后才发现 | 建立周报/站会节奏 |
| 不复盘 | 做完就结束 | 强制复盘四步法：目标→结果→原因→规律 |
| 过度管理 | 简单项目用了全套工具 | ABCD分级——先分级，再选工具 |
| 裸跑 | 完全不用工具 | A级也有口头确认——裸跑=0管理 |

## 八、Critique

### 外部攻击

#### Bent Flyvbjerg：项目管理方法论的"生存欺骗"问题

Flyvbjerg（牛津大学教授，16,000+项目数据库）发现：90%以上大型项目超预算，平均超支28%（IT项目73%）。根因不是方法论缺陷，是**激励机制缺陷**——项目发起者系统性地低估成本、高估收益，因为诚实的估算意味着项目不会被批准。

> **拷问**：你教创始人用WBS拆解项目、用甘特图排期。但他们回到公司，融资PPT里的"6个月上线"是用WBS诚实算出来的，还是用投资人想听到的数字倒推进甘特图的？你的方法论是在帮助项目成功，还是在帮助不诚实的估算变得更难识破？

**一堂回应**：ABCD分级本身就内置了诚实机制——A/B级项目不需要甘特图，不存在"装饰审批文件"的动机。C/D级项目我们强调"方案评估三角形"中的ROI和风险预判，鼓励在面对重要项目时做诚实评估。但Flyvbjerg的批评在D级战略项目中成立——需要在`framework-yitang-project-plan-design`中增加"参照类预测"作为评估三角的补充工具。

#### Eliyahu Goldratt：WBS忽略了人的行为

Goldratt提出三个行为陷阱：学生综合征（人们等到最后一刻才开始）、帕金森定律（工作膨胀到填满所有可用时间）、多任务并行摧毁效率。

> **拷问**：你让团队做了WBS，每个工作包独立可估算。但第一周检查——所有人都说"进展顺利"，实际完成0个WBS包。你怎么区分"真的80%"和"前80%做了但后20%是最难的部分"？

**一堂回应**：管过程框架（`framework-yitang-project-execution`）中的"守质量节点对照表"正是解决这个问题——不依赖百分比进度报告，而是检查关键质量节点的交付物是否真的完成。螺旋思考（`skill-yitang-project-spiral-thinking`）中的"先确认再推进"也是对抗学生综合征的机制。

## 九、Synthesis

科学项目管理是一堂管理必修课的完整板块，五节系列课构建了从认知到复盘的闭环。其核心创新在于：① 将PMBOK级别的复杂方法论简化为适合初创公司的四步+ABCD分级；② 将项目管理定位为"最小管理单元"，横向连接目标管理、科学决策、时间管理、单元模型等多个管理域；③ 强调"工具跟着复杂度走"，避免过度管理或裸跑两个极端。

本卡为总纲入口。具体方法论见四个基本功的framework卡，完整工作流见`[[workflow-yitang-project-four-step-loop]]`，项目管理助手Agent见`[[agent-spec-project-management-assistant]]`。

## 十、Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:---|:---|:---|
| 准备启动一个新项目 | 用ABCD分级判断复杂度 | 1分钟内完成分级 |
| 项目总是变来变去 | 回退到定方案——方案没写清楚 | 三段论（背景/目标/关键路径）写满一页 |
| 项目进度报告连续3周"完成80%" | Goldratt缓冲诊断：问"从今天专注做，多久能交？" | 发现≥1个虚报进度的任务 |
| 项目做完了 | 跑16字复盘：目标→结果→原因→规律 | 产出≥1条可复用的规律 |
| 投资人问"什么时候上线" | Flyvbjerg诚实回答：查参照类项目的时间范围 | 不做一个自己也不信的数字承诺 |
