> "三个每天的拷问：你在想这个事情做错了会不会死？这个事情是不是致命的假设？我能不能拿更低的成本来验证这个假设？"  
> —— 张磊，一堂《精益测试关键问题》AMA Q26（来源：`src_20260616_b1e25c49`、`src_20260616_59f708ea`）

**假设驱动日常决策三问**是把精益验证的"概率思维"压缩成每天可执行决策习惯的心法：用"失败致命否 / 致命假设是什么 / 能否更低成本验证"三个问题，把抽象的风险意识变成具体的投入级别、测试顺序与验证手段选择。

## 三问框架

| 问题 | 核心作用 | 日常决策输出 |
|------|---------|-------------|
| **失败致命否** | 判断风险等级与投入级别 | A 级致命假设 → 必须用 MVP / 低成本验证；C 级优化项 → 可直接执行或延后 |
| **致命假设是什么** | 剥离并排序最高风险假设 | 优先验证"一旦被证伪就全盘推翻"的前置假设 |
| **能否更低成本验证** | 选择验证手段 | 优先使用专家访谈、竞品调研、假页面等左侧 FALSE 模型手段，而非直接研发或重投放 |

> 张磊原话："我接下来要做的事情，多大概率会失败？如果这个失败会烧掉我多少条命？这个直接决定了今天做这个动作的投入级别。"（`src_20260616_59f708ea`）

### 第二问：分析概率——最致命的假设是哪个？

把当天任务背后的假设显性化，按"全盘推翻风险"排序：

1. 前置假设优先：需求是否成立 > 解决方案是否有效 > 商业模式是否跑通 > 增长能否放大。
2. 同一阶段内，优先验证"一旦被证伪，后续所有投入都白费"的假设。
3. 不要把精力耗在低风险环节。

> "不是按'哪个最容易做'排优先级，而是按'哪个最可能杀死我'来排。"（`src_20260616_b1e25c49`）

## 使用流程

```text
1. 列出今日/本周关键动作
2. 对每个动作问：失败会死多惨？ → 标 A/B/C 级
3. 对 A 级动作问：背后的致命假设是什么？ → 拆出需验证的关键假设
4. 对该假设问：能否用 10% 成本验证？ → 从 FALSE 模型左侧选手段
5. 验证后更新假设清单与下一步动作
```

## Constraints & Boundaries

| 边界 | 说明 |
|------|------|
| **适用对象** | 创业者、业务负责人、项目经理每天面对的多任务决策场景；不适用于纯执行层面的标准化操作 |
| **前提条件** | 已对业务有初步假设拆解；若连假设都拆不出来，需先用五步法/关键假设 ABCD 等工具前置梳理 |
| **与精益验证的关系** | 三问是"把精益思维日常化"的决策习惯，不能替代系统性的里程碑测试或实验设计 |
| **与 AI 的关系** | AI 可降低 FALSE 模型各环节的验证成本，但无法替代人判断"哪个假设最致命" |

## Common Failure Modes

| 模式 | 症状 | 修复 |
|------|------|------|
| **把优化当致命** | 在业务早期纠结 UI 配色、文案细节，迟迟不验证需求 | 用第一问重新标级：这些错了会不会死？不会就放到 C 级 |
| **跳过前置假设** | 需求还没验证就投入产品打磨或增长投放 | 用第二问强制排序：需求假设被证伪，后面全白搭，必须先测 |
| **验证方案过重** | 一上手就做完整开发、大规模问卷、长期陪跑 | 用第三问逼自己从 FALSE 左侧找 10% 成本方案：5 个访谈、1 张假海报、1 次专家访谈 |
| **混淆测量工具与被测量对象** | 用自评分数、问卷满意度等"用户说"的指标证明核心假设成立 | 为每个关键假设匹配行为指标或证伪实验，例如订单、复购、隐藏任务表现 |
| **用"阶段并存"当借口跳步** | 多线程并行，资源分散，没有完成任何一项关键验证 | 明确里程碑的前后依赖关系，前一假设拿到初步肯定后再探索下一阶段 |

## 案例一：一堂早期课程内核验证

一堂 2019 年打磨课程内核时，样本量只有几百到上千，作业率、NPS 等数据甚至不够做精确定量判断。团队用三问压缩日常决策：

1. **失败致命否**：课程内核不好，用户不会买单，全盘推翻 → A 级。
2. **致命假设是什么**："用户是否觉得这门课真的有价值、愿意积极评价、在多个选项中优先选择我们"。
3. **能否更低成本验证**：不做完整课程，用一节课的 Demo，找少量目标用户人工交付，收集横向课程对比、用户定性评价、主观审美信心三个信号。

结果：用极小成本完成了内核打磨的关键判断，再进入后续定价与单元模型验证（`src_20260616_b1e25c49`）。

## 案例二：美业门店 200→4000 元转化链路验证

某美业项目产品漏斗为：200 元体验品 → 3980 元套餐 → 2 万元加盟。团队最初想同时打磨三个产品。

用三问Daily拷问后调整：

1. **失败致命否**：如果 200 元用户不能转化到 3980 元，引流再多也亏损，2 万加盟更没基础 → A 级。
2. **致命假设是什么**：200→3980 的转化率是否成立，而非 200 元产品本身是否完美。
3. **能否更低成本验证**：不铺新媒体获客，先用朋友圈/熟人推荐找 30-50 人做体验，观察升级转化率与不升级的卡点。

结果：资源集中在关键转化链路，避免了在引流品和加盟政策上的过早固化（`src_20260616_b1e25c49`、`src_20260616_59f708ea`）。
