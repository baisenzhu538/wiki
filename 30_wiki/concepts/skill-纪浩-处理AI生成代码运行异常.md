# 技能：处理AI生成代码运行异常

- **纪浩体系**：[[concept-纪浩-ai-collaboration-methodology]] — 纪浩 AI 协作方法论总纲

## 原始表述

处理AI生成代码运行异常是纪浩在AI协作方法论分享中提出的具体方法，用于处理AI生成代码运行异常。

## 操作步骤

1. 确认异常现象和复现路径
2. 检查提示词是否表达清晰（避免promote歧义）
3. 人工加班排查（必要时）

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | AI代码报错或行为异常，需要定位问题根源 |
| ✅ 适合 | 提示词存在歧义导致AI理解偏差，需要修正 |
| ✅ 适合 | 同样问题反复出现，需要系统性排查 |
| ✅ 适合 | AI生成代码在本地能跑但部署后出问题 |
| ❌ 不适合 | 问题已定位且可自动修复 → 直接修复，不需要排查流程 |
| ❌ 不适合 | 纯AI幻觉导致代码完全不可理解 → 重新生成比修复更快 |
| ❌ 不适合 | 紧急生产故障 → 先回滚恢复，事后排查 |
| ❌ 不适合 | 非AI生成代码的问题 → 用标准调试流程 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **排查无头绪** | AI代码报错，不知道从哪里开始排查 | 先确认异常现象和复现路径。没有复现路径的问题无法修复 |
| **重复异常** | 同样的问题反复出现，每次都要重新排查 | 检查提示词是否表达清晰，避免promote歧义。记录异常和修复方案到经验库 |
| **提示词歧义** | 提示词有歧义但自己没意识到，AI理解偏差 | 人工Review提示词，用具体示例替代抽象描述。让AI复述理解确认 |
| **环境差异** | AI生成的代码在本地能跑，部署后出问题 | 排查环境差异（依赖版本、系统配置、权限等）。脚本化环境配置，确保一致性 |
| **经验不沉淀** | 异常修复后不做记录，下次同样问题再排查 | 每次异常修复后记录到日志和经验库。沉淀的异常处理经验是宝贵资产 |
| **过度排查** | 在AI生成的代码上花过多时间排查，不如重新生成 | 设定排查时间上限（如30分钟），超时则重新生成代码 |
| **盲目信任** | 认为AI代码应该没问题，排查方向错误 | 先假设AI代码有问题，再假设提示词有问题。不要先假设环境有问题 |
| **修复不验证** | 修复后不复现验证，问题可能仍存在 | 修复后必须复现验证，确认问题已解决。验证通过后再关闭问题 |

## 为什么有效

提示词歧义或AI理解偏差会导致代码问题，需要人工介入定位。系统化的排查流程避免无头苍蝇式调试，提升修复效率。
