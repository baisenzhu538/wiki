# 一堂产品内核画布应用技能

## 核心目标

帮助产品经理或创业者用结构化方法识别"用户愿意选择你的最小解决方案"，避免困境：

- 产品功能越做越多，但用户不买账。
- 团队以为的卖点，不是用户关心的买点。
- 商业模式难以跑通，因为内核不清晰导致转化率下降。

## 步骤 1：明确分析对象，确保独立交付

**输入：**一个产品或服务（如"一堂AI高考志愿填报服务"）。

**动作：**问自己：这个产品能不能独立交付价值？如果它是一个大产品中的一个模块，需要先定义清晰的边界。

**检查清单：**

- [ ] 分析对象是一个可独立交付的产品/服务。
- [ ] 分析范围不过大（如果太大，拆分成更小单元分析）。
- [ ] 已确认目标用户群体。

## 步骤 2：做加法，列出所有可能的内核要素

**输入：**用户调研、竞品分析、团队脑爆、行业专家访谈等多源信息。

**动作：**从用户视角出发，列出所有可能影响用户选择的要素。不要做判断，先全部倒出来。

**常见要素来源：**

- 用户直接说出的理由（如"我选你们是因为..."）。
- 好评中的高频关键词。
- 坏评中的痛点。
- 竞品的主打卖点。
- 团队自认为的优势。

**检查清单：**

- [ ] 列出了至少10个潜在内核要素。
- [ ] 每个要素都是从"用户选择理由"出发，而不是从"我们有什么功能"出发。
- [ ] 避免使用模糊形容词（如"体验好"要具体化为"响应时间30秒内"）。

## 步骤 3：做减法，用三问分类要素

**输入：**步骤 2 产生的潜在内核要素列表。

**动作：**对每个要素提问：

1. **决定性检查**：如果去掉这个要素，用户会放弃选择吗？
   - 是 → 标绿色（内核要素）。
   - 否 → 进入下一问。
2. **优化性检查**：如果去掉这个要素，用户体验会下降，但仍会选择吗？
   - 是 → 标黄色（优化性要素）。
   - 否 → 标红色（非内核，默认不做）。
3. **完备性检查**：绿色+黄色要素组合起来，能导向较好的转化/留存吗？
   - 否 → 回到步骤 2，补充缺失的要素。

**检查清单：**

- [ ] 每个要素都已标记颜色（绿/黄/红）。
- [ ] 绿色要素不超过5条（最佳3-5条）。
- [ ] 黄色要素有明确的投入优先级。
- [ ] 红色要素已被明确排除（或放入“做而不信”区域）。

## 步骤 4：用核心指标验证内核

**输入：**步骤 3 产生的绿色+黄色要素。

**动作：**为每个内核要素配一个可量化的核心指标，并设定“通过/失败”标准。

**常见核心指标示例：**

| 业态 | 可能的核心指标 |
|:---|:---|
| SaaS | 注册率、激活率、续费率 |
| 电商 | 转化率、客单价、复购率 |
| 教育 | 完课率、推荐率、学习效果评估 |
| 线下门店 | 进店率、办卡率、复购率 |

**检查清单：**

- [ ] 每个绿色要素都对应一个可量化指标。
- [ ] 指标的“通过标准”已明确（如"转化率≥5%"）。
- [ ] 指标能够在短期内获取（避免长周期验证）。

## 步骤 5：输出内核画布，强迫取舍

**输入：**步骤 3-4 的分类结果和指标。

**动作：**将结果填入画布模板，并强迫团队对取舍做出决策。

**产品内核画布模板：**

```
【分析对象】_____________
【目标用户】_____________
【核心指标】_____________

【绿色：决定性要素】（3-5条）
1. _____________ （指标：_____）
2. _____________ （指标：_____）
3. _____________ （指标：_____）

【黄色：优化性要素】
1. _____________ （投入优先级：_____）
2. _____________ （投入优先级：_____）

【红色：默认不做】
1. _____________ （原因：_____）

【做而不信区】
1. _____________ （验证方式：_____）
```

**检查清单：**

- [ ] 画布已填写完整，没有留空。
- [ ] 绿色要素已经过团队讨论并达成共识。
- [ ] 红色要素已明确被排除，避免"明面上排除、背地里做"。

## 步骤 6：快速验证，做而不信

**输入：**已完成的内核画布。

**动作：**选择最低成本的验证方式，快速检验内核假设是否成立。

**低成本验证方式对照表：**

| 验证目标 | 推荐方式 | 成本 |
|:---|:---|:---|
| 需求是否真实 | 用户访谈5-10人 | 低 |
| 价值主张是否被接受 | 着陆页/问卷测试 | 低 |
| 产品是否能解决问题 | MVP或假产品 | 中 |
| 转化率是否可达 | 小规模活动/测试 | 中 |

**检查清单：**

- [ ] 已确定验证的优先级（从风险最高的假设开始）。
- [ ] 验证方式的成本在可接受范围内。
- [ ] 验证结果已记录，并用于修正画布。

## 步骤 7：迭代画布，动态调整

**输入：**验证结果、市场反馈、竞品动态。

**动作：**每隔一段时间（建议每季度）回顾画布，根据新信息调整要素分类。

**迭代触发条件：**

- 用户反馈显示某个黄色要素实际上是决定性的。
- 验证结果推翻了某个绿色要素的假设。
- 市场环境发生重大变化（如新竞品、新政策）。

**检查清单：**

- [ ] 画布有版本号和更新日期。
- [ ] 每次迭代都记录了"变化原因"和"调整内容"。
- [ ] 团队对最新版本画布达成共识。

## 外部攻击者

### 攻击者1：战略咨询师 —— "3-5条内核太简化，复杂业务无法压缩"

> "你诹于航空发动机、医院信息系统或企业级SaaS这类高复杂度产品，3-5条内核就像用一张A4纸概括一本书。用户决策是多维度、多角色、长周期的，这种压缩会让团队忽视关键利益相关者的差异化需求。"

### 攻击者2：数据分析师 —— "单一转化率指标会导致短视"

> "转化率是一个短期、可操控的指标，它会鼓励团队做出一切提升短期转化但损害长期价值的决策。例如过度优化首页注册转化，可能会降低用户质量和续费率。内核画布需要配备长期价值指标。"

## Constraints

- **依赖高质量的用户调研**：如果用户访谈不到位，"绿色要素"很可能是团队的一压情愿，而不是真正的用户决策逻辑。
- **对"红色要素"的执行力要求极高**："默认不做"很容易在执行中被各种理由"破例"。
- **不适用于非标准化、高定制化产品**：每个客户的内核要素可能差异很大，需要分层分类讨论。

## 常见失败模式

- **Green-bloat（绿色膨胀）**：不舍得刊除要素，最终绿色列表超过5条，失去聚焦力。
- **Yellow-neglect（黄色忽视）**：只关注绿色要素，忽视了优化性要素对长期竞争力的贡献。
- **Red-resurrection（红色复活）**：明面上排除的要素，在产品规划中又偷偷加回来。
- **Indicator-gaming（指标游戏）**：为了达到短期指标，损害了内核的长期健康度。
