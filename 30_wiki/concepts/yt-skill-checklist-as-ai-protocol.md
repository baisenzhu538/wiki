# 清单体作为AI的I/O协议——用笔记替代prompt工程

## Condense

传统的AI交互模式是"prompt描述任务 → AI理解 → AI输出"。Truman的方式是**“清单体笔记 → 笔记=prompt+context → AI输出清单体”**。

**核心跳跃**：不是用更好的prompt描述任务，而是用**笔记本身就是prompt**。

**关键操作**：
1. **笔记即prompt**：你写的清单体就是给AI的指令，不需要额外的prompt翻译层
2. **笔记即context**：笔记中的每个分点、每个层级都是context的结构化呈现
3. **输出即笔记**：AI的输出不是大段文字，而是结构化的清单体，可以直接接入下一次输入
4. **没有中间层**：不需要"把笔记翻译成prompt"的步骤，清单体就是AI的原生语言

**关键原则**：
- 写好笔记=写好prompt：笔记质量直接决定AI输出质量
- 笔记是人类认知和AI数据结构之间的适配层：不需要中间的"翻译"步骤
- 两者都能直接使用：人类看得懂，AI解得开，无需二次翻译

## Question

**为什么"清单体是AI的原生语言"？** 因为AI的核心能力是在大量文本中提取模式和结构。大段文字对AI来说是"需要解构的数据"，清单体对AI来说是"已经结构化的数据"。AI在清单体上的"解构能力"远强于在大段文字上的能力。

**这种模式不是在“限制AI”吗？** 不是限制。传统模式是"任务描述→AI理解→AI输出大段文字→人类再次理解"。Truman的模式是"笔记=prompt+context→AI理解→AI输出笔记"。后者少了两个"翻译"步骤，效率更高、误差更小。

## Critique

### 攻击者1：计算机科学家——"清单体是AI的原生语言”是过度简化"

当代LLM的核心能力不是“结构化数据"而是“上下文理解”。在Transformer架构中，清单体和大段文字被处理的方式并没有本质区别——都是被转换成token序列，然后通过自注意力机制计算关系。清单体的“分层”和“分点”对于LLM来说，不过是一些特殊的token模式，并不是"更原生的语言"。

更深层的是：说“清单体是AI的原生语言”等同于假设AI“更擅长处理结构化数据”，但实际上**当代AI对于非结构化的自然语言的理解能力，已经远超其对于结构化表格的填充能力**。AI是“语言动物”，而非“结构化数据动物”。强调结构化可能是用二十年前的“数据库思维”来理解今天的“语言模型”。

### 攻击者2：产品经理——"这种模式报复性地限制了AI的能力边界"

当代AI能力已经远超"按照结构化输入输出"。Claude 3.5、GPT-4o、Gemini 1.5都能处理非常复杂的非结构化任务——多轮对话、创意写作、情感分析、跨领域联想。将AI定位在"清单体输入→清单体输出"的管道里，相当于用一个精英工程师去做数据录入——可以做，但是**浪费**。

结果是：这种模式对于L1-L2级别的任务是高效的，但对于L3+级别的任务（创意思考、策略推演、情感共鸣），**强制让AI输出清单体就是强制让AI少说话——而对于复杂问题，有时候说得多比说得少更有价值**。

## Synthesis

清单体I/O协议的本质不是"让AI输出更好"，而是**"让人的输入更好"——倒逼人提高笔记质量**。

[[truman-ai-partner-design-analysis]] 中的三个约束——P角色、清单体I/O、L1-L2边界——共同构成了一个倒逼机制：如果你给AI的输入是垃圾，AI的输出也是垃圾；要得到好输出，你必须先写出好的清单体。

dk-note-human-creativity-ai-data 的分工在这里得到体现：AI攻“数据”（处理清单体中的结构化信息），人攻“场景”（决定这份清单体在什么场景下用、怎么用、用完之后怎么迭代）。清单体I/O协议确保了AI只做"数据层面"的事，人类做"场景层面"的事。

[[dk-note-maximum-common-divisor]] 中的"最大公约数"的真正含义在这里得到了完整解释：清单体不是"人类和AI都能用的格式"，而是"人类和AI之间不需要翻译就能直接交互的格式"。

## Constraints & Boundaries

| 边界 | 说明 |
|------|------|
| **适合** | L1-L2任务：信息整理、清单化、数据提取、格式转换 |
| **适合** | 需要与AI多轮交互、反复迭代的场景 |
| **不适合** | L3+任务：创意思考、策略推演、情感共鸣 |
| **不适合** | 一次性、非结构化的简单聊天 |

### 失败模式

1. **把复杂创意任务也硬套清单体协议**
   - **原因**：协议滥用
   - **修复**：判断任务层级，L3+任务允许自然语言输出

2. **笔记本身质量差，导致AI输出也差**
   - **原因**：输入 garbage in
   - **修复**：先提升清单体笔记的分层、分点、独立性

3. **完全依赖AI输出，不做人工判断**
   - **原因**： abdication
   - **修复**：人对清单体的场景使用和最终决策负责

4. **把清单体协议当成唯一交互方式**
   - **原因**：过度结构化
   - **修复**：保留自然语言作为探索和高复杂度任务的备用方式

## Cases

**正例：阿蕊老师的工作流**

Truman的工作流：
```
- 人类（L3-L4）：
  - 用清单体笔记完成诊断（问题定义、原因分析、关键要素提取）
  - 输出：一份完整的、有结构的清单体
- AI（P角色，L1-L2）：
  - 输入：这份清单体
  - 处理：执行清单体中的每个执行项
  - 输出：新的清单体（含执行结果和下一步待办）
- 人类（L3-L4）：
  - 输入：AI输出的清单体
  - 处理：任务分解、重点优化、格式提升
  - 输出：下一份清单体
```

这个循环的精妙之处在于：**清单体是唯一的语言**——人类不需要把自己的思考"翻译”成prompt，AI也不需要把自己的输出"翻译”成大段文字。双方都在同一个语言系统里工作。

**反例：“清单体缺口”的陷阱**

某用户尝试用清单体I/O模式让AI帮忙写一篇情感类文章。结果：
- 用户用清单体写了"主题、观点、论点"
- AI输出了一份“结构化的文章纲要”
- 用户发现文章缺少情感和灵气

问题：创意写作需要的不是"结构"，而是"情感和创意"。清单体I/O在这里被错误地应用了——**它是一种工具，不是一种解药**。

**边界案例：“垃圾输入垃圾输出”**

某学员用清单体I/O模式让AI帮忙整理会议记录。但输入的清单体本身就是坏的：没有时间点、没有谁发言、没有行动项。AI输出了一份"看似完整但实际上无用"的清单体。

问题：清单体I/O协议的本质是**"倒逼机制"——人类必须先提高自己的笔记质量**。如果人类的输入是垃圾，这个机制不仅不能提升输出质量，还会让人以为"因为用了AI，所以我不需要写好笔记了"。

## Action Protocol

| 阶段 | 操作 | 标准 |
|:---|:---|:---|
| **进入标准** | 任务属于L1-L2级别（整理、结构化、格式转换、数据提取） | 如果任务需要情感、创意、策略推演，不用清单体I/O协议 |
| **Step 1** | 人类写好清单体输入 | 笔记质量必须达到"如果不是交给AI，交给人也能看懂并执行"的标准 |
| **Step 2** | AI接收清单体并输出结果清单体 | AI的输出必须是清单体，不是大段文字 |
| **Step 3** | 人类检查AI输出 | 每个执行项都必须被验证，不能假设AI做对了 |
| **Step 4** | 人类对AI输出进行优化和迭代 | 优化的标准是"下一次的输入是否比这次更好" |
| **Step 5** | 如果任务需要多轮交互，重复Step 2-4 | 每次循环都必须让笔记质量提升一个等级 |
| **退出标准** | 任务完成，最终输出是人类可以直接使用的产品 | 如果最终输出还需要人类大量二次加工，说明输入质量不足 |

## Attacker

### Attacker 1：计算机科学家——"清单体I/O协议是一种新的‘拆分与中转’特定"

在计算机科学中，任何“标准化协议”的核心价值在于**"消除中间层的有效性"——即这个中间层是必需的还是可以省略的**。清单体I/O协议声称“不需要中间层”，但实际上它只是把中间层从"人类提供prompt”变成了"人类提供清单体”。如果清单体本身的质量低（如反例中的垃圾输入），这个“省略”反而可能导致更大的输出问题。

更深层的问题：这种协议假设了**“清单体”和“prompt”之间存在结构性同构**。但实际上，有些任务的最佳表达形式并不是清单体——比如情感表达、故事描述、或跨模态的创意组合。强行将这些任务“清单体化”，可能是**对复杂性的暴力简化**。

**当用这张卡的人睡不着觉时**：他们会想——"我用清单体作为I/O协议，但是不是有些任务恰恰因为‘不能被清单体化’才更有价值？我是不是在用‘协议标准化’来掩盖‘任务本质复杂’？"

### Attacker 2：认知科学家——"清单体I/O协议可能消耗了人类的高阶认知能力"

Sweller的认知负荷理论指出，人类的工作记忆容量极其有限。清单体的一个核心特征是"分层”——通过层级结构减少同时需要处理的信息块。这对于人类来说是有利的，因为人类的工作记忆有限。

但对于AI来说，它的“工作记忆”（上下文窗口）远强于人类。**强迫AI使用清单体，相当于强迫一个能同时处理128K token的大脑去使用一个只能处琈7±2个信息块的小脑的工作模式**。

这可能导致两个后果：
1. **能力浪费**：AI的深度推理和创意能力被"清单体管道"限制
2. **人类能力退化**：人类过度依赖清单体，逐渐丧失处理非结构化信息的能力

更严重的是：这种设计可能创造了一个**“认知鼓励不匹配”**——人类被鼓励写清单体（消耗人类的低级认知资源），AI被限制用清单体（浪费AI的高级认知资源）。双方都没有在各自最擅长的模式上工作。

**当用这张卡的人睡不着觉时**：他们会想——"我写清单体的能力是不是在退化？当我不能用清单体表达某个复杂想法时，我的第一反应不是‘我该怎么更好地表达’，而是‘我该怎么把它改写成清单体’。这是不是一种‘模式固化’？"
