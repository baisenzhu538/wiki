# Feature 深卡 F040：状态机——用数学定义状态编号，让 AI 不跳步

> **一句话定义**：状态机（State Machine）= 把任务流程拆成若干**编号状态**，用**数学方式**严格定义——什么状态在什么条件下才能转移到哪一个状态，如果没有发生就不允许转移——让 AI **不跳步、严谨按流程走**。
>
> **卡片定位**：ai-basic 域 Feature 周期表 **F040**（L2 提示词层 / D 维度）的首张深卡，也是 Feature 深卡系列的**金标准样板**。溯源精确到行号，引文全部逐字，转写噪音诚实标注，应用场景分**口述验证 / 库内实证 / 推演探索**三级。

## 一、这是什么（严谨定义）

Truman 口述上 L996-1000 的原始定义（逐字，三行连引）：

> "简单来说什么叫状态机啊？"（L996）
>
> "就是严谨地说，它是一个复杂机制，就是什么样的状态它能全部严格地以数学的方式定义出来。"（L998）
>
> "然后什么状态在什么条件下才能转移到哪一个状态，如果没有发生就不允许转移。"（L1000）

拆成三个要素：

| 要素 | 含义 | 反例（无状态机） |
|:--|:--|:--|
| **状态编号** | 流程拆成 1/2/3/4/5 个离散状态，每个状态有名字和编号 | 先聊聊，聊得差不多再推进（无编号，全凭感觉） |
| **转移条件** | 每个状态定义什么时候进入、什么时候退出的硬条件 | 觉得问得差不多了就给方案（无退出条件，容易跳步） |
| **硬约束** | 没满足转移条件就**不允许**推进 | AI 自己判断时机成熟就往下走（无硬约束，必然跳步） |

**关键区分**：状态机 ≠ 工作流。工作流是**我规定了一堆节点让 AI 走**（语文描述），状态机是**我给每个节点编号并定义数学化的转移条件**（数学定义）。Truman 正是先在工作流上失败，才摸到状态机（见第二节）。

## 三、为什么有效（原理拆解）

状态机让 AI 不跳步，靠三个机制：

**① 数学定义消除歧义（L1016）**
语文描述**先充分了解需求再聊方案**，AI 对**充分了解**的理解是模糊的，随时可以自认为已经了解了。数学定义**状态 2（需求确认）的退出条件 = 用户明确说 对，就是这个意思**，AI 没有模糊空间。

**② 硬约束阻断跳步（L1000）**
**如果没有发生就不允许转移**——状态机把**建议**变成**门禁**。AI 在状态 2 没满足退出条件时，无论多想给方案都不允许进入状态 3。

**③ 编号让流程可审计（L1012/L1022）**
每个状态有编号，意味着任何时刻都能回答**现在在哪一步**。L1018**一旦成型，后面都是A自动做的**——编号状态 + 转移条件定义清楚后，流程推进不需要人盯。

**一句话原理**：语文定义给 AI 留了**自我裁量**的空间，状态机把这个空间用数学堵死。

## 四、怎么用（四步操作法）

从口述提炼的可复用操作：

| 步骤 | 动作 | 口述依据 |
|:--|:--|:--|
| **1. 拆状态** | 把流程拆成 1/2/3/4/5 个离散状态，每个状态命名 | L1012 12345什么时候进入，什么时候退出 |
| **2. 定条件** | 给每个状态写 进入条件 + 退出条件，用数学/可判定的语言，不用形容词 | L1000 什么状态在什么条件下才能转移到哪一个状态 |
| **3. 加硬约束** | 写死 退出条件没发生，不允许转移到下一状态；需要回退时定义回退机制 | L1000 如果没有发生就不允许转移；L1008 包括会退机制，如果发现什么就会退 |
| **4. 按编号执行** | 提示词里写 严格按编号走，每个环节按编号执行，用户没点头就停在当前状态 | L1012 严格按照编号走；L1022 按编号执行；L956 用户点头都在做下一步用户没点头就一直在这跟他好好聊 |

**最小可用提示词模板**：

```
你要严格按以下状态编号执行，不允许跳步：
状态1【需求确认】：只提问，不给方案。退出条件=用户明确确认需求。
状态2【方案】：给出方案。退出条件=用户认可方案方向。
状态3【执行】：按方案执行。
规则：当前状态的退出条件未满足时，停在当前状态，不允许进入下一状态。
```

### B. 推演探索（演绎，非口述原文，hypothesis）

状态机的本质是**多步骤 + 有先后依赖 + AI 容易跳步 + 状态可编号 + 转移有明确条件**。按这个特征，以下场景可探索（⚠️ 均为演绎，未经实证，引用时需标注 hypothesis）：

| 探索场景 | 状态编号示例 | 转移条件 | AI 角色 |
|:--|:--|:--|:--|
| **问诊/医疗分诊** | 1初诊接待→2症状采集→3初步判断→4检查检验→5确诊→6开方→7随访 | 状态 2 退出 = 主诉+现病史+既往史+过敏史全部采集 | 引导式问诊助手——**最大价值是阻断 一上来就下诊断**（AI 医疗最大风险） |
| **制造品控工序** | 1来料检验→2工序一→3工序二→4成品检验→5入库 | 每道工序检验通过才放行，不合格触发回退 | 质检流程守门员 |
| **销售/客户对话** | 1线索→2需求确认→3方案→4报价→5成交→6复购 | 用户明确表态（点头）才推进，未点头停在当前状态深聊 | 销售对话教练（直接对口述 L956 用户点头都在做下一步，用户没点头就一直在这跟他好好聊） |
| **审批/合规流程** | 1起草→2部门审→3法务审→4签批→5归档 | 每级审批通过；任一驳回触发回退到起草 | 流程推进器 |
| **客服工单** | 1受理→2分类→3处理→4回访→5关闭 | 状态 5 进入 = 客户确认已解决；未确认回退到状态 3 | 工单状态机 |
| **招聘面试** | 1简历筛→2电面→3技术面→4终面→5offer | 每轮通过才进入下一轮；每轮有明确评估标准 | 面试流程管理 |
| **结对编程/代码评审** | 1需求理解→2设计→3编码→4测试→5评审→6合并 | 测试通过才进评审；评审通过才合并 | 不跳步的结对伙伴（KDO 工厂已在实践） |

**探索场景的选用判断**：不是**这个场景能不能用状态机**，而是**这个场景的 AI 会不会跳步**。会跳步、且步骤有明确完成标准的，就值得用状态机编号。

## 七、适用边界（When NOT to Use）

| 边界 | 依据 |
|:--|:--|
| **创意发散型任务不适用** | `dk-demand-feature-stacking` L167：叠加不适用创意差异化任务（农夫三拳认知反差型失败——反差很难通过系统设置制造，素材 L923） |
| **小团队/短平快任务慎用** | `case-live258-huangqian-promo-film` L184：状态机在中长周期、多交付节点的创作流程里是资产（保障节奏），在短平快任务里变负担（管理开销超收益），**过程类 Feature 的启用应有规模阈值**；黄谦（素材 L2947）复杂状态机在小团队易冗余 |
| **状态边界模糊的任务不适用** | 状态机的前提是状态能 严格地以数学的方式定义出来（L998）——定义不出离散状态的任务（如开放式头脑风暴）用不了 |
| **一次性任务不必建** | 状态机的收益是 一旦成型，后面都是A自动做的（L1018）——只跑一次的任务，定义状态机的成本 > 收益 |

**启用阈值自检**：任务周期短、交付节点少 → 退回轻量流程；中长周期、多交付节点、AI 反复跳步 → 上状态机。（黄谦 素材 L2947 共识）

## 八、常见误区（反模式）

| 误区 | 为什么错 | 正解 |
|:--|:--|:--|
| 把状态机当工作流用 | 工作流是语文描述节点，AI 照样跳步（Truman 试错② L982） | 状态机要数学定义编号 + 硬转移条件 |
| 状态没有退出条件 | 聊得差不多再推进——AI 自己判断 差不多，必然跳步 | 每个状态必须有可判定的退出条件 |
| 用语文定义状态 | 先充分了解需求——充分 是形容词，AI 有裁量空间 | 用数学：退出条件 = 用户明确说 对 |
| 只定义前进不定义回退 | 发现错了没法退，只能硬往前走 | L1008 包括会退机制，如果发现什么就会退 |
| 状态太多太细 | 10+ 个状态，管理开销超收益 | 3-7 个状态为宜；单元模型教学观是 5 个（12345） |

## 九、落地模板（可抄的状态机定义清单）

**适用时机**：设计任何多步骤 AI 流程前。

```
流程名称：________
```

## 十、Critique

### 内部局限
1. **转写噪音多**：口述原文多处转写不可解（L992/L1002/L1012/L1020），关键定义虽完整但上下文有损耗——本卡已逐处标注，引用时需注意。
2. **数学的方法未展开**：Truman 说 你得用数学的方法做（L1016），但没具体讲数学方法是什么形式（形式化状态机？真值表？代码？）。L1024 甚至有一些人会用代码来做 提示了方向，但缺乏可操作的数学定义范式。
3. **生效证据是单向的**：L1018 一旦成型后面都是A自动做的、L1024 遵循度就好很多——均为 Truman 单向陈述，无对照实验数据。立竿见影（L1028）是体感评价。

### 外部攻击

**[软件工程师]**
> 状态机是软件工程 20 年前的老概念（finite state machine），Truman 讲的不过是把 FSM 搬到提示词里。这算什么新 Feature？

**回应**：正因为是老概念，才是好 Feature——它是经过验证的成熟机制迁移到 AI 协作域。Feature 思维本来就不追新（`concept-yihang-ai-feature-thinking`：不被工具带走），状态机的价值不在**新**，在**AI 跳步**这个问题第一次有了可复用的工程化解法。且提示词态的状态机与代码态 FSM 的约束强度不同——提示词态是软约束（AI 可能违反），这正是为什么 Truman 强调**用数学的方法做**以提高遵循度。

**[极简主义者]**
> 为了防跳步就要定义状态编号和转移条件？小任务这么做纯粹是增加认知负担。

**回应**：成立，且已被库内案例验证——黄谦（素材 L2947）复杂状态机在小团队易冗余。本卡第七节明确给出了启用阈值：短平快任务退回轻量流程。状态机是**资产还是负担**取决于任务规模，这正是 Feature 思维**边界**阶段（六阶段之 5）要掌握的判断。
