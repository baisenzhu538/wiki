# 单元模型三工具：斧子尺子梯子

> 来源：一堂五步法·单元模型篇 | [[yt-five-step-method]] | [[yt-growth-cycle-model]] | [[case-toy-cabinet-business-model]]

## Summary

单元模型是一堂五步法中最硬核的第三步——商业模式。核心工具是"斧子、尺子、梯子"三工具，分别对应预判期、测试期、经营期的决策场景。Truman强调："不要过早复制未经验证的商业模式"。

## Claims

### 三工具对比

| 维度 | 🪓 斧子（预判期） | 📐 尺子（测试期） | 🪛 梯子（经营期） |
|:
|:---|:---|:---|
| **核心定义** | 在没花钱之前，用框架和常识砍掉明显不成立的机会 | 花最少的钱，拿到最能说明问题的真实数据 | 规模起来后持续调优模型，让ROI越做越好 |
| **花钱程度** | 不花钱，做选择 | 少花钱，测可行性 | 花大钱，优化和提升 |
| **核心问题** | 这个能做吗？值不值得下场？ | 数据成立吗？值不值得继续测？ | 怎么越做越好？怎么对抗变差？ |
| **典型动作** | 在纸上算最乐观能不能赚钱→不能就砍掉 | 跑一个小样本测试，用真实数据替代拍脑袋 | 调收入结构、降成本结构、推标准化 |
| **决策风险** | 错过机会（砍错） | 样本偏差导致误判 | 优化方向错了，越调越差 |
| **不做会怎样** | 一开始就下错场，花了几百万才发现模型不成立 | 拿拍脑袋的数字做扩张决策，测试结论不可靠 | 模型固化，规模越大问题越大 |
| **核心产出** | 一个"不该做的清单" | 一组有统计意义的关键指标数据 | 一个持续进化的经营模型 |
| **数字精度** | 粗：区间估算即可 | 中：需要真实数据，但不追求极致 | 高：需要真实经营数据做精细调优 |
| **时间跨度** | 几分钟到几周 | 几周到几个月 | 长期、持续、永无止境 |

### 六大段位

| 段位 | 名称 | 核心能力 |
|:---:|:---|:---|
| L1 | 不算账 | 只有初心和用户调研，无定量分析 |
| L2 | 算错账 | 只算公司层面大账，未找核心单元模型 |
| L3 | 粗糙单元模型 | 找到单元模型但不完整，忽略关键成本项 |
| L4 | 完整单元模型 | 模型完整但数据不准，存在错误类比或乐观预期 |
| L5 | 动态预判 | 能预测单元模型随规模、外部、业务变化的趋势 |
| L6 | 顶级认知 | 全面的商业分析能力，能系统评估并指导决策 |

### 三大关键问题

单元模型回答商业模式的三个核心问题：
1. **能不能赚钱？** — 盈利性
2. **能不能持续赚钱？** — 持续性
3. **能不能持续赚大钱？** — 规模经济

## Critique

### 外部攻击：Eric Ries（精益创业）

Eric Ries 的"构建-测量-学习"循环对"斧子"提出挑战：传统预判可能永远无法"在纸上算清"一个完全新的商业模式——建议斧子的判断必须在数周内快速跳到尺子阶段，用最小可行测试验证。

### 外部攻击：Clayton Christensen（创新者的困境）

Christensen 在《创新者的困境》中证明，**正确的商业模式在初期往往看起来不赚钱**。如果斧子阶段就要求"纸上赚钱"，可能会提前砍掉最终成为巨头的机会。Christensen 的经典案例是小型钢厂最初的"低端"产品利润率远低于大型钢厂，但随着技术进步最终食上了整个市场。

## Constraints & Boundaries

| 边界 | 适用 | 不适用 |
|---|---|---|
| 业务阶段 | 已有初步产品/服务，需分阶段决策 | 纯理念阶段无数据 |
| 决策类型 | 预判/测试/经营期的商业模式判断 | 一次性非商业决策 |
| 数据状态 | 斧子可估算，尺子/梯子需真实数据 | 尺子/梯子阶段无数据 |
| 行业环境 | 可找到类比或历史数据 | 完全革命性无类比 |

### Common Failure Modes
1. **阶段工具错配** → 症状：预判期做精细测试、经营期还在纸上推演；原因：未按阶段选工具；修复：明确当前阶段只使用对应工具
2. **尺子阶段样本过小** → 症状：几个用户反馈就下结论；原因：急于求成；修复：设定最小样本量和统计显著性标准
3. **忽视外部变化** → 症状：用旧模型参数做新阶段决策；原因：未更新模型；修复：每个阶段转换前重新校准参数
4. **梯子阶段只看 ROI** → 症状：忽视竞争能否复制；原因：未评估构造性壁垒；修复：同步分析护城河和规模经济对抗
5. **三个工具混用** → 症状：预判期用尺子、测试期用梯子；原因：工具边界不清；修复：建立阶段-工具对照表

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|---------|-----------|---------|
| 有个创业想法想判断是否下场 | 用斧子在纸上算最乐观情况能不能赚钱→不能就砍掉 | 30分钟内生成"不该做的清单" |
| 已做过MVP想判断是否继续 | 用尺子跑小样本测试，用真实数据替代拍脑袋 | 获得有统计意义的关键指标数据 |
| 业务在扩张但ROI下降 | 用梯子分析收入结构和成本结构的变化趋势 | 明确规模化带来的是"变优"还是"变劣" |
