# 课程→Skill八步工作流：从结构化内容到可复用AI技能的完整转化

## 定义

这项技能是指：将一门系统化的课程或方法论，通过结构化抽取、证据校准、边界定义、多场景测试，转化为可在特定业务场景中反复使用的AI Skill的完整流程。核心是**边界清晰**而非**内容全面**。

## 核心命题

1. **课程转Skill不是搬运内容**
   把课程讲义喂给AI不等于Skill。裸模型自己就能读课程，Skill的价值在于**边界守护与拒绝能力**。

2. **方法论需要变诊断协议**
   课程中的方法需要被转化为"适用场景+评分规则+风险分级"，而不是原封不动地喂给AI。

3. **测试是唯一的真理标准**
   “不要相信自己的设计，只相信测试数据”。Skill必须经过5个正向场景+5个反向场景+1个高风险场景的测试。

4. **证据质量是生命线**
   课程内容本身是"老师的主张"，不是"经过验证的事实"。Skill必须对课程内容进行证据校准，区分事实、观点和需要用户验证的部分。

## 核心流程

**八步工作流**：

| 步骤 | 动作 | 关键产出 | 通关标准 |
|:---|:---|:---|:---|
| 1. 判断值不值得做 | 评估课程是否适合做成Skill | 通过/放弃决策 | 课程有明确的方法论和使用场景 |
| 2. 整理课程主线 | 结构化输出为Markdown，清理噪音 | 结构化课程笔记 | 能用一个文档说清楚课程的核心逻辑 |
| 3. 抽取案例/问答/行业应用 | 识别课程中的具体案例、常见问答、行业场景 | 素材清单 | 每个理论点都有配套的实例和反例 |
| 4. 方法变诊断协议 | 转化为"适用场景+评分规则+风险分级" | 诊断协议 | 能回答"什么情况下用、什么情况下不用、用了有什么风险" |
| 5. 证据校准+课程主张审查 | 区分事实、观点、需验证部分 | 证据质量报告 | 每个主张都有标注（事实/观点/待验证） |
| 6. 搭技能目录框架 | 按功能模块组织Skill指令结构 | Skill框架PRD | 指令结构清晰，用户知道输入什么、期望得到什么 |
| 7. 测试 | 5正向+5反向+1高风险 | 测试得分表 | 所有场景总分≥20分，高风险场景拒绝能力=3分 |
| 8. 维护 | 版本号+反馈模板+回归测试流程 | 维护手册 | 有明确的版本号、反馈入口、回归测试周期 |

**测试模板**：

**正向场景测试清单**（至少5个）：
- [ ] 标准业务场景A：Skill能否正确识别并给出建议？
- [ ] 标准业务场景B：Skill的建议是否具体可执行？
- [ ] 边界场景：在正常边缘情况下Skill能否处理？
- [ ] 复杂度逐步提升：从简单到复杂的输入，Skill表现是否稳定？
- [ ] 连续使用场景：多轮对话后Skill是否保持一致性？

**反向场景测试清单**（至少5个）：
- [ ] 明显越界场景：Skill是否明确拒绝？
- [ ] 模糊场景：输入信息不足时Skill如何处理？
- [ ] 极端输入：恶意/无效输入时Skill的反应？
- [ ] 课程未覆盖场景：课程没讲过的情况Skill如何处理？
- [ ] 目标冲突场景：用户目标与课程方法冲突时Skill如何处理？

**高风险场景测试**（至少1个）：
- [ ] 选择一个出错代价极高的场景（如保险给付方案、医疗建议、法律意见）
- [ ] 确认Skill在此场景下的"拒绝能力"=3分（明确拒绝并解释原因）
- [ ] 如果Skill没有拒绝，返回步骤4重新审查诊断协议的风险分级

**证据质量标准**：

| 优先级 | 信源类型 | 示例 |
|:---|:---|:---|
| 高 | 官方来源 | 企业官网、政府统计局、行业协会公开数据 |
| 高 | 研究机构报告 | 知名咨询公司、大学研究机构、行业百皮书 |
| 中 | 经验证的专业媒体 | 有明确作者和编辑审核的行业媒体 |
| 禁止 | 自媒体营销软文 | 无明确作者、无核实机制的营销文章 |
| 禁止 | 无法核实的媒体报道 | 传闻、未经验证的社交媒体爆料 |
| 禁止 | 未经训练的AIGC生成内容 | AI生成的"数据"、"报告"、"研究" |

## Constraints

**本技能的内部局限**：

1. **依赖课程有结构化方法论**——如果课程只有零散观点没有方法论，无论怎么转化都只是"高级搬运"。
2. **需要课程作者授权**——未经授权的课程转Skill涉及版权风险。即使有授权，也需要明确使用范围和修改权限。
3. **测试资源需求高**——至少需要11个测试场景（5正向+5反向+1高风险），每个场景需要设计输入并执行评分。
4. **维护成本不低**——课程内容更新后，Skill需要同步更新。如果没有版本管理和回归测试流程，Skill会快速过时。

## External Attacks

**外部攻击者**：

> **“版权法务”派**：你把老师的课程做成Skill，经过授权了吗？即使有授权，课程内容本身受版权保护。你把它偐成可复用的Skill，本质上是在用技术手段稀释课程价值——以后谁还买课？如果你是老师，你会同意学生把你的课偐成Skill卖给别人吗？

> **“快速上线”派**：你搞八步工作流、12维度评分、还要做11个测试场景，这一套下来三个月过去了。市场窗口早就关了。真正做产品的人MVP三天上线、一周迭代，你这是在用“完美主义”避免交付。你的评分标准越复杂，越说明你对自己的产品没信心。

> **“AI原教旨”派**：你把一门课程偐成Skill，但大模型本身就能读这门课。用户直接把课程讲义丢给模型就行了，为什么要用你的Skill？你的Skill本质上是在模型和课程之间加了一个不必要的中间层——增加了复杂度，没有增加价值。如果Skill不能比裸模型好10倍，它就不值得存在。

## Case Studies

**成功案例**：

- [[case-半肥猫-course-to-skill]] —— 半肥猫将「转化率黑客」课程转化为AI Skill，获得官方授权。关键数据：正常场景Skill 36分 vs 裸模型 8分（差距28分）；最大差异项为"拒绝能力"（Skill 3分 vs 裸模型0分）。

**失败案例**：

- **授权风险爆雷**：某团队未经授权将一门热门课程转化为Skill上线，被课程作者发现后发出律师函。Skill下线，团队损失了两个月的开发成本和品牌信任度。

- **测试不足导致事故**：某Skill在上线前只做了3个正向测试，没有做反向和高风险测试。上线后一周，一个用户在保险场景下使用Skill获得了错误建议，损失了一单业务。团队被责令下线。

- **过度设计导致延迟**：某团队花了两个月设计了18维度的评分标准，每个维度分为5级。评分标准太复杂，实际测试时评审员无法一致地执行，最终被简化为3级。

**边界案例**：

- **“大而全的工具墟墟”**：某团队将一个通用"营销助手"Skill上线，没有明确的使用边界。用户问什么都答，结果在高风险场景（保险给付方案）下给出错误建议，被责令下线。

## Synthesis

这个技能与 [[case-半肥猫-course-to-skill]] 形成实践关系：案例是一次成功的实践，技能是可复制的方法。案例告诉你"可以做成"，技能告诉你"怎么重复做成"。

这个技能与 [[skill-半肥猫-ai-research-validation]] 形成业务链关系：调研纠偏技能用于"获取高质量信息输入"，课程转Skill技能用于"将信息输入转化为可复用工具"。两者是同一条产业链的上下游。

这个技能与 [[dk-半肥猫-silky-answers-are-dangerous]] 形成质量关系：课程内容本身可能包含AI式的"丝滑主张"（听起来有道理但缺乏证据）。如果不做证据校准（步骤5），Skill就会把课程中的推理错误放大并固化。

这个技能与 [[dk-半肥猫-real-business-is-the-engine]] 形成前置条件关系：如果课程不能解决真实业务问题，那么无论技术上做得多好，都是"用锤子找钉子"。

## Action Framework

**启用条件**：你有一门结构化的课程/方法论，有明确的使用场景，且获得了授权。

**退出条件**：你发现课程只是观点集合没有方法论，或者你无法获得授权，或者你没有足够的测试资源。

**下一步**：回去查看 [[case-半肥猫-course-to-skill]] 中的测试数据，选择一门你手边的课程，尝试跑通八步工作流的第一步“判断值不值得做"。
