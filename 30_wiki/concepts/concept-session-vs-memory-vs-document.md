# Session << AI 记忆 << 文档知识库：降 Session 依赖

> 本卡属于「AI×知识管理」体系（楚门探索营进步二，L1360-1530）：长期靠 Session 跟 AI 协作，AI 永远是"刚睁眼的天才"（L1412-1416）。三个层级——Session（短期会话）<< AI 记忆（自动保存但不稳定）<< 文档知识库（全局可见可传递可复用）。核心纪律："降低对 Session 的依赖"（请死死记住，L75）。

## 1. 核心洞察

Session 是 AI 协作的**最不可靠载体**：碎片化+记忆丢失（L1404-1408）。"你们对 Session 的依赖约等于你们对下属脑子里知识的依赖——他一走你就完蛋了"（金句 7）。文档知识库才是 AI 时代的资产：严格可见/可传递/可复用，是"高水平的可视化协作环境"（L1508-1522）——不是笔记工具，是协作环境。

## 2. 三类比

| 层级 | 类比 | 特点 | 可靠性 |
|:--|:--|:--|:--|
| Session | 开会脑记 | 短期、散会就忘、第二周忘光 | 极低 |
| AI 记忆 | 自觉小本本 | 自动存但不稳定；不给你看；离职不留 | 低 |
| 文档知识库 | 文档会议 | 所有人盯着文档干活；结论都在文档里 | 高 |

（口述 L1426-1472 原文类比）

## 3. 为什么文档知识库赢

- **可见**：决策依赖 Session 就全消失——"你哪知道当年错了个啥"（L1514-1516）
- **可传递**：换人/换 AI 都能继承（小本本离职就走）
- **可复用**：反复加载文档效率获得一次大的飞跃（L1526-1528）
- **协作**：一堆 AI 共享一个知识库工作（framework-multi-agent-collab-chain-six）

## 4. 应用方法

1. **别把项目放 Session 里**：临时现场（短期）/个人经验（自己总结）/公共地基（文档）三层分离（图 015500）
2. **对话沉淀成文档**：每次重要对话结束把结论写进文档（"所有对话你再把它沉淀成文档"）
3. **基于文档协作**：与 AI 协作时先加载文档，不重新口述背景
4. **盯文档交付物**：不盯 Agent 窗口（金句 12）

## 5. 适用边界

- Session 不是完全不用——单次会话内的即时交互仍靠 Session（临时现场层）
- AI 记忆有用（自动保存规则）但不可依赖（你不知它存了什么）
- 文档需要维护成本（费 token）——但效率获得大飞跃（L1526-1528）

## 6. 失败模式

| 失败模式 | 真实信号 | 修复动作 |
|:--|:--|:--|
| 纯 Session 工作 | 每次都要重新介绍自己/项目 | 建文档地基，对话前加载 |
| 记忆依赖 | 以为 AI 自动记住了 | 关键结论写文档（记忆不给你看） |
| 文档不沉淀 | 对话结束就扔 | 对话→文档（沉淀到知识库） |
| 传纸条 | 复制粘贴文档来回传 | 共享知识库+读写关系 |
