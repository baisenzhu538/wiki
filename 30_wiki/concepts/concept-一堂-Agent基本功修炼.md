# Agent 基本功修炼：KDO 工厂就是 Agent 军团练基本功的系统

> **一句话**：老朱问"agent 是不是也需要苦练基本功"——**需要**。基本功元命题同样适用 Agent 军团：人不是组织能力的最小单位，基本功才是；对 agent 而言，**针对具体场景的独立可检验原子能力**就是它的基本功。而 KDO 整套工厂（30_wiki 卡 + cap_hub + pre-submit + 终审 + 复盘）正是 Agent 军团练基本功的系统——卡是建模，武器库在手边，考核在门禁，复利在复盘。
>
> **双视角注记**：本卡与 [[concept-一堂-AI时代基本功变与不变]] 构成双视角——那卡讲"人如何在 AI 时代练基本功"（AI 是外骨骼、肌肉靠苦练），本卡讲"agent 自身如何练基本功"。反向回链（#15 卡 related 补本卡）按 #152 约定**挂起**，待 #15 卡 reviewed 后由本任务承接人补。

---

## 何时用

- 设计新 agent / agent-spec 时，先问"它该练哪些基本功"再写 System Prompt
- 某个 agent 反复犯同类错误，需要诊断"是能力没建模还是没练够"时
- 评估 cap_hub 里一个能力该不该上线（三环准入）时
- 给团队讲"KDO 工厂到底在干什么"时——一句话答案：Agent 军团练基本功的系统

## 需要什么

- 一个明确的 agent 角色及其高频场景（没有场景就没有"具体场景的原子能力"）
- 该角色的真实工作记录（会话日志/产出物），基本功从真实动作里拆，不在会议室里空想
- 承认前提：agent 的基本功和人一样——靠记忆守不住，必须建模成卡/机制

---

## 一、定义：agent 基本功 = 针对具体场景的独立可检验原子能力

把 [[concept-一堂-基本功定义]] 原样套到 agent 身上，六关键词一个不改：**针对具体场景、独立、可检验、重复练习、长期复利**的动作单元。军团里已有的真样本：

| Agent | 基本功（原子能力） | 可检验性 |
|:--|:--|:--|
| 王语嫣 | 6 层交叉验证 / 证据分级 / 口述稿行号锚定 | 诊断报告的每个数字能否点回行号 |
| 老顽童 | pre-submit 自检 / wikilink 闭环 / 子任务复验 | 交付物门禁全绿、无死链 |
| 洪七公 | OCR+VLM 交叉校验 | 两路结果一致性可比对 |
| 欧阳锋 | 终审 checklist（结构/口径/边界逐项过） | 终审记录可复查 |

反例（不是基本功）："认真负责""保证质量"——素质词，不可拆不可练，和人卡里的"沟通能力强"同病。

## 二、三环筛选：哪些 agent 能力配叫基本功

用 [[tool-一堂-基本功-三环六维自检]] 的三环给 agent 能力做准入：

| 环 | 对人的问法 | 对 agent 的问法 |
|:--|:--|:--|
| 务实（具体+场景） | 是否落到具体工作场景 | **有无 input/output spec**——说不清输入输出的能力不存在 |
| 可练（独立+检验） | 能否独立成组、一动手分高下 | **有无独立验证脚本**——pre-submit/比对脚本/回归测试，没有验证手段就练不了 |
| 价值（重复+复利） | 是否高频重复、长期复利 | **是否高频复利**——每次会话都调用的能力才值得练，一次性脚本不值得 |

**同构声明**：#151 黄药师线的 B-2 `tool-three-ring-capability-filter`（cap_hub 三环过滤器）本质就是"agent 基本功准入"——cap_hub 里的能力要上线，过的正是这三环。本卡提供概念锚点，工具由 #151 建设，本域只引用不代建。

## 三、拆建推练 × KDO 映射表

| 四字诀 | 人练基本功 | Agent 军团（KDO 实现） |
|:--|:--|:--|
| **拆** | 把工作拆到独立动作 | 任务 → 原子能力：每个 agent 拆自己的原子动作（如老顽童拆出"pre-submit 自检"） |
| **建** | 提炼固定套路/模型/SOP | 建模成 30_wiki 卡 / agent-spec / cap_hub Skill——固定套路必须落成文件，不靠记忆 |
| **推** | 以身作则→先锋→灰度→共识 | 军团共识：按 #143 协议注册分诊，新 agent 按协议被路由调用；口径文件（任务单/规则卡）即启动会 |
| **练** | 刻意练习+大量反馈，重复成复利 | 复盘（daily-context/feedback-patterns）+ pre-submit 自检 + 欧阳锋终审考核——每次会话都是一次重复 |

## 五、两个实证案例

### 案例一（课程侧）：春萍·花总——实习生是 agent 的预演

花总五年五步（详见 [[case-一堂-春萍-花总AI研发]]，数字均课程案例口径）：先拆自己 → 拆三个项目的能力合并同类项建成体系 → 把任务**作业化**（清晰背景+输出边界+标准答案）交给四周培训出来的 200+ 名大学生（L742-770）→ 2022 年发现**作业式任务描述转手就是优质提示词**，AI 直接接手基础编程（L784-806）→ 全员练 AI+基本功，算法评估从一周到 3-4 天再到一天（L720-724、L854-858）。

对 agent 的启示：**实习生是 agent 的预演**——当年为练人做的基本功建模（作业卡、SOP、段位图），正是今天让 AI 能干活的资产。顺序铁律同样成立：**先把基本功拆出来、建成型，再让 agent 在拆好的基本功上干活**；没有作业化的任务，给 AI 就是玄学。

### 案例二（我们侧）：王语嫣角色锚定事故（2026-07-10）

事故：王语嫣在长上下文压缩后丢失"只编排、不写 30_wiki 方法论卡"的角色边界，越界生产 #149 三张 case 卡，被用户纠正（"下次不许再犯"；用户选 A：内容保留+如实标注越界，留待终审）。

用本卡框架解剖（素材：`zhu-feedback-patterns` 模式 #2 与盲区标记）：
- **根因**："角色锚定"这条基本功**未建模、未练**——它只存在于对话记忆里，压缩即丢失。对照三字诀：没「建」（当时没有成文规则卡）、没「练」（没有每次会话的强制重复机制）。
- **补救**：事后补「建」——立规写入 `zhu-feedback-patterns`（会话启动先重读 personal-os 锚定角色；唯一写卡例外是 personal-os 维护）。
- **教训**：**agent 基本功靠记忆守不住，必须建模成卡/机制**。这条教训对所有 agent 通用——凡是"上次说过的"，不落成卡就等于没说。

## When NOT to Use

| 场景 | 为什么失效 | 替代 |
|:--|:--|:--|
| 想用它证明"agent 能取代人练基本功" | 本卡立场相反——AI 是外骨骼、肌肉靠苦练（[[concept-一堂-AI时代基本功变与不变]] 命题） | 人该练的基本功照练；agent 接的是已建模的作业化任务 |
| 一次性、低频的 agent 任务 | 没有重复就没有复利，不值得建模练基本功 | 直接写一次性脚本，不进 cap_hub |
| 没有验证手段的"能力" | 不可练环不过——练了也不知道长进没有 | 先补验证脚本/检查清单，再谈修炼 |
| 拿本卡替 #150 总纲或教练 agent-spec 造内容 | 本卡是概念锚点不是操作手册 | 操作走 [[framework-一堂-苦练基本功-总纲]] 与 `agent-一堂-基本功教练` |

## Failure Modes（症状 → 根因 → 修复）

| # | 症状 | 根因 | 修复 |
|:--|:--|:--|:--|
| 1 | 同类错误跨会话复发，每次都要人重新提醒 | 能力只在对话记忆里，没建模成卡 | 24 小时内把这条能力写成规则卡/检查项（补「建」），挂进启动序列（补「练」） |
| 2 | 新 agent 的 spec 写了一堆"要认真、要严谨" | 把素质词当基本功，不可检验 | 逐条改写成可检验原子能力（如"每个数字必须能点回行号"），写不出检验手段的删掉 |
| 3 | cap_hub 能力上线后无人调用 | 三环准入没做——不务实或不高频 | 下线；回三环重评，先把高频场景的原子能力建透 |
| 4 | 复盘写了十篇，同类问题照样出现 | 只记录不闭环——复盘没接"防再犯规则"的修改动作 | 每篇复盘必须产出一条机制改动（规则/脚本/锚定），没有改动的复盘不算数 |
| 5 | 让 agent 直接干未拆的整任务，产出玄学 | 跳过花总顺序——任务没作业化 | 先拆能力→作业化（背景+边界+验收），再交给 agent |

## Critique（外部攻击与回应）

**1. 拟人化批判**：把"苦练基本功"这种人的成长话语套到 agent 身上，是范畴误用——agent 没有肌肉记忆，只有权重和上下文，"练"字是修辞不是事实。**本域回应**：半成立。agent 的确不在权重层面"练"，但本卡的"练"落在系统层：规则卡的迭代、验证脚本的回归、复盘机制的重复触发——这些是组织为 agent 建的"外置肌肉"。花总案例证明这套外置肌肉的顺序（先作业化、再交给执行者）对人对 AI 同样成立。修辞危险在于让人误以为 agent 会自己进步；本卡 Failure Mode #1 正是对此的防御。

**2. Goodhart 式担忧**：把 pre-submit 通过率当"基本功段位"，agent 会学会写"过门禁但没营养"的卡。**本域回应**：门禁只是考核评估（练16）的一层，欧阳锋终审 checklist + 月度抽检构成第二层监督（练17）；且三环准入里"价值环"要求高频复利，过门禁的空心卡在调用率上自然暴露。

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:--|:--|:--|
| 某 agent 跨会话复发同类错误 | 当天把该能力写成规则卡/检查项并挂进启动序列 | 下一次会话该错误零复发（有验证记录） |
| 设计新 agent | 先列原子能力清单逐条过三环，再写 System Prompt | spec 里每条能力都有 input/output + 检验手段 |
| 能力申请进 cap_hub | 按三环评估：io spec / 验证脚本 / 调用频次 | 上线能力三个月内有真实调用记录 |
| 任务要交给 agent 做 | 先问"这任务作业化了吗"（背景+边界+验收标准答案） | agent 一次产出达标，不靠返工猜意图 |
