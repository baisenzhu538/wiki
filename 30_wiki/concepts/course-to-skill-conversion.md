# 课程→Skill转化：将知识变成AI可执行的能力模块

> Source: [[src_20260606_90b44191]] (半肥猫-AI学习落地-口述)

## Summary

将课程/书籍中的方法论转化为AI Skill的流程。核心原则：**Skill不是提示词的堆叠，而是带有判断边界的可执行模块**。半肥猫的实践表明，使用Skill能让场景拆解得分36分，未使用只能得8分，差值28分。

## 进入标准

| 场景 | 信号 |
|------|------|
| 学完一堂课后想在工作中复用 | 能写出课程的三个核心步骤，但每次用时都要翻笔记 |
| 团队成员对同一业务的分析结果不一致 | 有明确的评估标准，但标准只在某个人脑子里 |
| AI生成的分析报告"每次都不一样" | 缺少固定判断流程，AI在"讨好"而非"执行"标准 |

## 操作步骤

### Step 1: 课程质量筛选
**不是每个课程都值得转化**。检查三个标准：
1. 有无科学方法（可复现的流程，而不是东拼西凑的案例）
2. 有无可验证案例（真实业务中可以对照结果）
3. 有无明确边界（什么时候用、什么时候不用）

**暗知识**：半肥猫未明说但已在实践的判断是——**如果课程的讲师自己都没有用这个方法做过一个真实项目，那这个方法就不值得转化**。

### Step 2: 抽取方法主线
将课程抽象为**可执行的判断流程**，而不是"知识点清单"。例如：
- 错误："课程讲了调研方法"→ Skill只是一堆提示词
- 正确："调研流程 = 问题澄清 → 假设地图 → 证据链补强 → 决策报告"→ Skill包含每个节点的输入、判断和输出格式

### Step 3: 设计诊断协议
Skill的核心价值不是"生成"，而是**场景拆解 + 风险识别 + 拒绝能力**。
- 设计"输入检查清单"：用户提供的信息是否足以做出有效分析？
- 设计"边界警告"：当输入不足时，Skill应该拒绝而非编造答案
- 设计"适用范围"：明确标注这个Skill只适合什么类型的问题

### Step 4: 证据校准
用真实案例测试Skill：
1. 找1-2个已知结论的真实业务问题
2. 用Skill跑一遍，看结果是否与事实一致
3. 如果不一致，调整诊断协议
4. 重复测试直到准确率稳定

### Step 5: 工程化封装
将Skill包装为**可重复调用的模块**：
- 定义输入/输出格式
- 写入PRD文档（见 [[prd-as-ai-instruction]]）
- 存入知识库，配合标签体系管理

## 退出标准

| 信号 | 行动 |
|------|------|
| 连续3次测试结果与事实偏差>20% | 回到Step 3重新设计诊断协议 |
| 课程本身无法验证（讲师没有实践案例） | 放弃转化，只做笔记 |
| Skill使用频率低于每月1次 | 检查场景选择是否错误，或简化为检查清单 |

## Critique

### 内部局限
- Skill转化的质量严重依赖原始课程的质量。如果课程本身是"东拼西凑"，Skill只会让庞杂知识系统化地出错。
- 诊断协议的设计需要设计者具备较高的业务判断力。如果设计者自己都不知道"什么时候该拒绝"，Skill会变成"勇气的编造者"。
- 测试环节需要真实业务案例，但很多人在学习阶段缺少这些案例。

### 外部攻击

#### Kahneman —— "技能自动化陷阱"
Kahneman在研究中发现，人类对"自动化过程"的信任度远超其可靠性。当你把一套方法固化为Skill时，**你实际上是在用"去年的成功经验"解决"今年的未知问题"——这是经验主义陷阱的技术化版本**。半肥猫的Skill得分36分vs8分，但这个对比是在"特定类型的问题"上做的。你有没有检查过，当问题类型发生偏移时，Skill是不是反而在放大错误？

#### Herbert Simon —— "有界合理性的终结"
Simon的有界合理性理论指出，人的决策能力受到信息处理能力和时间的严格限制。Skill的本质是用"预先设计好的流程"减少这些限制，但问题是：**当问题超出Skill设计者的经验范围时，Skill不会告诉你"我不知道"，它会用应付的方式给你一个看似合理的错误答案**。你有没有这种体验：用Skill跑了十次都对，第十一次错得离谱，但你因为前十次的成功而完全没有怀疑？

### 不要用的场景
| 场景 | 为什么失效 | 替代方案 |
|------|--------|---------|
| 课程本身是概念/理论型（无可执行流程） | 无法抽取判断流程 | 做概念卡/思维模型卡 |
| 业务场景变化极快（如活动运营） | Skill过时速度超过更新速度 | 使用灵活的检查清单而非固定Skill |
| 用户缺少业务判断力 | 无法设计有效的诊断协议 | 先学习基础方法论，不要跳过学习直接做Skill |

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|---------|---------|---------|
| 学完一堂课想在工作中复用 | 写出课程的三个核心步骤 + 两个适用边界 | 30分钟内完成 |
| 团队分析结果不一致 | 把分析流程写成检查清单，让两个人分别按清单执行 | 结果一致率从<50%提升到>80% |
| AI分析报告每次结果不同 | 构建"输入检查清单"，强制验证必填字段 | 连续3次输出结构一致 |
