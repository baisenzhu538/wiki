# 用户分层与需求差异：从"所有人"到"第一批100个"

> 一堂五步法：超过50%的需求分析失败，根源是"人群定的太泛了"。

## 核心框架

用户分层不是"分类"，而是**识别需求差异**，找到最值得先服务的群体：

| 分层维度 | 说明 | 适用场景 |
|:---|:---|:---|
| **需求强度** | 高痛 vs 低痛 | 新产品冷启动，先服务高痛用户 |
| **场景频率** | 高频 vs 低频 | 先服务高频场景，建立使用习惯 |
| **付费意愿** | 高付费 vs 低付费 | 先服务高付费意愿，验证商业模式 |
| **替代方案成本** | 高成本替代 vs 低成本替代 | 先服务替代方案成本高的用户 |
| **获取难度** | 易触达 vs 难触达 | 先服务易触达的，降低获客成本 |

## 关键洞察

### 1. 从"所有人"到"第一批100个"

错误路径：
```
"我的产品适合所有销售" → 市场太大 → 无法聚焦 → 资源分散 → 都服务不好
```

正确路径：
```
"我的产品适合年营收500-2000万的SaaS公司销售总监" → 精准定位 → 深度服务 → 口碑扩散 → 逐步扩展
```

### 2. 用户分层的四象限

按"需求强度"和"获取难度"分层：

|  | 高需求强度 | 低需求强度 |
|:---|:---|:---|
| **易获取** | **第一批目标**（高痛+易触达） | 第二批（培养需求） |
| **难获取** | 第三批（高价值但难触达） | 放弃（低痛+难触达） |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **人口统计分层** | 按年龄/性别/地域分层，忽视需求差异 | 按需求强度/场景/付费意愿分层 |
| **分层太粗** | 只分2-3层，无法指导产品决策 | 至少分5层，找到最痛的1-2层 |
| **分层未验证** | 假设某层用户有高痛，未访谈验证 | 每层至少访谈3-5个真实用户 |
| **忽视层间差异** | 不同层的需求差异大，但产品统一服务 | 为不同层设计差异化功能或服务 |
| **过早扩展** | 第一层未服务好，就想服务所有人 | 先服务好第一批100个，再扩展 |
| **分层维度单一** | 只按一个维度分层 | 至少两个维度交叉（如需求强度×获取难度） |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新产品冷启动 | 成熟产品的全量运营 |
| 需求验证阶段 | 已有明确PMF后的规模化 |
| 产品定位模糊时 | 技术架构设计 |
| 资源有限时的优先级排序 | 品牌传播策略 |
