---# 建模的三重价值：确定性、框架性、迁移性

> **Burn line**: 所有模型最终都是为了解决三个问题：让输出更确定、让思考有框架、让经验可迁移。

这是 Truman 对建模能力价值的高度概括。无论流程建模、抽象建模还是本质建模，最终都指向这三重价值。

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 需要稳定产出的重复性工作（确定性） |
| ✅ 适合 | 复杂问题需要结构化思考（框架性） |
| ✅ 适合 | 跨领域经验提炼和复用（迁移性） |
| ✅ 适合 | 团队能力建设和知识沉淀 |
| ❌ 不适合 | 完全创新型工作（无先例可循） → 确定性建模失效，用探索式方法 |
| ❌ 不适合 | 极度简单任务（无需框架） → 框架性建模过度，直接执行即可 |
| ❌ 不适合 | 领域壁垒极高（如核物理→美妆） → 迁移性有限，需重新验证前提 |
| ❌ 不适合 | 追求100%确定性 → 模型只能提高概率，不能消除所有不确定性 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:-----|:-----|
| **确定性幻觉** | 认为有SOP就能100%稳定产出 | 模型提高概率但不消除变异，保留20%弹性空间 |
| **框架僵化** | 用框架套所有问题，忽视特殊情况 | 框架是起点不是终点，遇到反例时更新框架 |
| **迁移过度** | 把A领域模型硬套到B领域，前提不成立 | 迁移前验证：B领域是否满足A模型的前提条件？ |
| **建模不足** | 永远在救火，从不提炼模型 | 设定"项目复盘必提炼模型"规则，强制沉淀 |
| **建模过度** | 花80%时间建模型，20%时间执行 | 简单任务直接执行，复杂任务才建模 |
| **三层混淆** | 把流程建模（确定性）当成本质建模（迁移性） | 明确当前要解决什么问题：稳定产出？复杂章法？跨域复用？ |
| **模型不更新** | 模型建立后从不迭代，逐渐失效 | 每季度Review模型有效性，偏差>30%则重构 |
