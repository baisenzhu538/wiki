# 行知自媒体六层诊断：30 年行业经验输给工具思维，短板全在 L1-L3 基础层

> 一句话：近 30 年地产/创业实战老兵做自媒体全流程 AI 批量生产，目标日更 3 短视频+2 图文，结果只有 50+ 分——文案同质化、脚本流水账、封面混乱、定位漂移。用 Feature 六层一拆：唯一生效的组合只有「主题约束+单任务拆分」，核心缺失全在 L1-L3 基础层（最终意图/专属角色/Few-shot/RAG 素材库），根本不需要龙虾和复杂 Agent——「只要补齐基础 Feature 就能解决 80% 的内容质量问题」（L653-L655）。

---

## 过程（起点→尝试→失败→转折→结果）

### 起点：想用 AI 解放时间去做主业

行知 2021 年至今运营垂直自媒体，赛道覆盖地产干货、创业咨询，日常产出图文笔记、短视频脚本、口播文案、封面配图四类内容（L521）。2025 年下半年尝试全流程 AI 批量生产，目标：摆脱单人撰稿作图的繁重工作量，日更 3 条短视频+2 篇图文，解放时间去做咨询、电商主业（L523）。

### 尝试：纯工具思维的四种典型操作

原始执行方式（L525-L533）：
- 内容文案：直接用通用大模型，网上复制爆款短视频提示词模板
- 封面配图：切换多款文生图工具，直接输入标题生成画面
- 无标准化流程，想到什么指令给什么，脚本、配图分开独立操作
- **数据差就更换 AI 工具**——今天豆包、明天 GPT、作图工具频繁切换

### 失败：50+ 分，批量生产失败

成品几乎无法直接发布，五大硬伤（L537-L547）：

| 硬伤 | 根因方向（后见） |
|:--|:--|
| 文案同质化严重，缺个人从业视角，完播率/私信极低 | 缺专属角色+最终意图 |
| 短视频脚本逻辑流水账，缺钩子/痛点/转化引导 | 缺输出结构约束 |
| 封面风格混乱，无统一 IP 视觉 | 缺品牌规范数据包 |
| 每次换工具重新磨合，效率比手写更低 | 工具思维的直接代价 |
| AI 偏离账号定位（一会房产投资一会泛创业） | 缺长期记忆+定位约束 |

### 转折：六层诊断——短板全在基础层

用 Feature 思维按六层能力分层逐层梳理缺失（L549-L605）：

**当时仅用到的少量浅层 Feature**（L553-L559）：L2 基础主题约束（限定「地产/创业」选题）、L1 简单模型切换（效果差就换）、L3 单次单任务 Workflow（文案封面分开生成）。**唯一生效的组合=主题约束+单任务拆分**——只解决「AI 不乱写」的最基础问题，对质量/转化/IP 统一「提升效果微乎其微」（L561-L565）。

**核心缺失清单**：

| 层 | 缺失 Feature | 行号 |
|:--|:--|:--|
| L1 基础模型层 | 模型参数调优（从未调温度/Top-P，输出随机性极强）；多模态协同（文案封面两个独立工具，图文脱节）；模型分工（单一模型兼顾所有内容类型） | L569-L575 |
| L2 提示词层（**最核心短板**） | 最终意图（从未明确商业目标：同城引流/咨询转化）；专属角色（没有「30 年地产营销+连续创业者」IP 身份）；Few-shot 案例（没导入过往爆款数据包）；分层评测（没有完播/引流/人设三标准）；输出结构约束（没有「3 秒钩子→痛点→干货→行动引导」固定框架） | L577-L587 |
| L3 能力流程层 | RAG 素材库（多年案例/踩坑故事没沉淀，AI 只能输出网络通用理论）；分支循环 Workflow（没有「初稿→痛点优化→转化强化」多轮迭代，一版定稿）；品牌规范数据包（配色/字体/排版每次都不一样） | L589-L595 |
| L4 Agent 工作层 | 状态机分步（AI 经常跳过干货直接写广告）；长期记忆（频繁产出重复选题重复观点） | L597-L601 |
| L5 硅基组织层 | 无多 AI 协同（文案/配图/标题/评论全靠单一模型独立完成） | L603-L605 |

### 结果：自下而上的分层补全方案（60+→80+ 目标）

遵循「底层优先，自下而上叠加」原则（L611）：
- L1 打底：创意脚本调高温度、商业干货调低温度；创意/文案拆专用模型；打通图文多模态联动（L613-L615）
- L2 核心商业 Feature 补齐（自媒体成败关键）：每条内容前置最终引流意图；固定 IP 角色；导入全部爆款案例做 Few-shot；强制四段式脚本结构；完播+转化双维校验（L617-L619）
- L3 叠加：个人行业案例 RAG 库；三阶段迭代 Workflow；统一 IP 视觉规范数据包（L621-L623）
- L4 完善：状态机强制按选题-撰稿-润色-配图-标题执行；长期记忆规避重复（L625-L627）
- L5 协同：创意 AI/文案 AI/视觉 AI/评论 AI 多角色分工（L629-L631）

优化后核心组合：模型参数分层调优+IP 角色+最终意图+爆款案例 RAG 库+四段式脚本约束+三轮迭代 Workflow+全流程状态机（L633）。**⚠️ 注意：这是设计方案，「预期整套特性组合落地后」的效果（L635）未经过实测验证。**

## Critique

**内部局限（自指）**：分层补全方案是**设计文档不是实验报告**——「60+→80+」是目标不是结果，六层缺失诊断虽自洽，但「补齐基础 Feature 解决 80% 问题」（L655）没有任何验证数据。方案同时上七组 Feature（L633），违反了自己案例族里黄华春/田力的「逐个叠加观测」纪律——全量改造后即便有效也无法归因。

**外部攻击者 1（Kahneman 式——规划谬误）**：「日更 3+2 且无需大量人工修改」（L635）是典型规划谬误——方案落地涉及 RAG 建库、Workflow 搭建、多模型协同，每一项的实际成本都被低估；自媒体老手自评的「50 分→80 分」尺度和平台算法现实（完播率由选题/时机/运气共同决定）之间也没有校准。

**外部攻击者 2（Taleb 式——幸存者对照缺失）**：诊断框架来自事后归因——失败项目拆出的「缺失 Feature」清单，天然倾向把失败解释成「缺了我现在知道的东西」。对照缺失：是否有账号用了同款浅层 Feature 却成功（运气/红利期）？是否有账号补齐了全部 Feature 仍失败？没有负样本，「短板全在 L1-L3」的可信度停留在合理推测。

## Synthesis

本卡是 Live258 族中**分层诊断最工整**的样本——六层逐层列缺失、按「底层优先」定补齐顺序，是 [[framework-truman-feature-layered-system]] 最标准的学员应用，且用自身失败独立验证了体系原则「除非必要，勿增上层封装」（L655：「完全不需要龙虾、复杂多 Agent 等高阶工具」）。与族内对照：行知的「唯一生效组合=主题约束+单任务拆分」（L561-L565）是黄华春「无意识用对 4 Feature」的负片——同样是无意识，黄华春蒙对了三维覆盖，行知只蒙对了一个维度，结果 0 成本获客 vs 50+ 分失败，正好标定 [[dk-demand-feature-stacking]]「维度覆盖决定效果」的两端。反思 2（L645-L649）与 [[dk-feature-not-learned-but-used]] 互为镜像：Feature 不仅是「用了不知道」，还有「有经验不会转」——行业老兵的最大盲区是把线下经验工程化为数据包的能力。

## Action Triggers

1. AI 产出不行时先禁换工具——按六层清单从 L1 逐层自查，80% 的短板在 L1-L3 基础层
2. 把行业经验工程化：独家案例/踩坑故事→RAG 素材库；爆款内容→Few-shot 数据包；视觉风格→品牌规范包
3. 内容生产前置两个 Feature：最终意图（这条内容要引流还是转化）+IP 角色（谁在说、对谁说）
4. 补 Feature 按「底层优先、逐个叠加」：每补一组观测效果，拒绝七组全量改造（防归因失败）

## 失败模式

| 失败模式 | 症状 | 修复 |
|:--|:--|:--|
| 数据差就换工具 | 今天豆包明天 GPT，每次重新磨合，效率比手写更低（L533/L545） | 冻结工具栈，先补 Feature；换工具只在 Feature 补齐仍无效后 |
| 经验留在脑子里 | 30 年案例只靠口述写作，AI 输出网络通用理论（L591/L647） | 建 RAG 素材库+Few-shot 爆款包，让 AI 继承差异化 |
| 无最终意图写内容 | 「写一条短视频脚本」→无钩子无转化引导（L579） | 每条内容前置商业目标：引流/咨询/转化三选一 |
| 跳层上复杂工具 | 基础层全缺就上 Agent/多模型协同 | 「除非必要勿增上层封装」——L1-L3 补齐前先不碰 L4+ |
| 全量改造无法归因 | 七组 Feature 一次全上，有效也不知道哪组起效 | 逐个叠加+效果追踪，对照 Feature 效果表归因 |
