# 案例：Truman 用 Y模型 重构时间管理——从被动打断到科学体系

> **一句话定义**：Truman 经历了从 2021 年前「被动打断、低水平重复」到 2022 年起用 Y模型 建立「时间模型 + 事情模型 + 匹配模型」三模型体系的完整转型，提出 30-50 个关键假设并持续迭代。这是 Y模型 引擎层在个人效能领域的经典演示，与 PPT 案例并列。

---

## 一、背景

**人物**：Truman（一堂创始人，口述者本人）

**起点状态（2021 年前）**：
- 时间管理处于「被动、被打断、低水平重复」状态（口述稿第 316-320 行）
- 和大多数人一样，凭感觉、靠意志力、被紧急事务推着走
- 尝试过各种时间管理工具和方法，但效果不稳定——因为没有一个统一的框架来整合它们

**关键转折**：Truman 意识到时间管理和其他商业问题一样，可以用 Y模型 来解决——先建模、再提假设、持续迭代。他开始把时间管理当作一个「可无限优化的系统工程」而非「靠自律就能解决的习惯问题」。

---

## 二、决策与行动

### Y模型 引擎层的完整演示

| Y模型 循环要素 | 时间管理案例中的具体表现 |
|:---|:---|
| **目标** | 把时间投入到真正重要的事情上，减少被动打断，提升长期产出 |
| **V1（朴素认知）** | 时间管理 = 自律 + 工具（日历、待办清单、番茄钟） |
| **理论侧·科学类比** | 借鉴「格子理论」——时间像货架，事项像货物，关键是聪明地分配货物到格子里（口述稿第 418-420 行） |
| **理论侧·提炼建模** | 建立三个独立但互相关联的模型：**时间模型**（什么时候做什么类型的事）、**事情模型**（哪些事真正重要、如何分类）、**匹配模型**（什么时间匹配什么事效率最高） |
| **实践侧·假设驱动** | 提出 30-50 个关键假设并逐一验证，例如："把深度工作放在上午 8-11 点产出最高""公开排期能减少 30% 的被动打断""AB 工作法能用半天切换成本换一整天的深度时间" |
| **实践侧·定性定量** | 记录时间切片、追踪产出效率、对比不同排期方案的 ROI |
| **实事求是** | 承认某些假设是错的——有些时间安排理论上完美但实践中扛不住突发状况 |
| **解放思想** | 跳出「时间管理就是把自己塞得更满」的隐含假设，转向「时间管理的本质是把时间和精力分成格子，把事项一件一件聪明放进去」（口述稿第 418-420 行） |
| **V2（更新认知）** | 时间管理 ≠ 自律，时间管理 = 时间模型 + 事情模型 + 匹配模型，三个模型各自独立迭代 |
| **知行合一** | AB 工作法落地、公开排期制度化、深度工作模型成为日常操作 |
| **飞轮** | 每次提出新假设 → 验证 → 更新模型 → 模型越准 → 越容易发现可以优化的地方 → 提出新假设 |

### 三模型详解

| 模型 | 核心问题 | 关键洞察 | 可迁移性 |
|:---|:---|:---|:---|
| **时间模型** | 什么时间做什么？ | 时间是有限的「格子」，不是无限资源。先定义格子（深度工作时间 / 会议时间 / 碎片时间），再往里放事项 | 任何需要长期时间分配的场景 |
| **事情模型** | 哪些事真正重要？ | 不是所有「紧急」的事都「重要」。建立事情的分类标准和优先级体系 | 适用于个人和团队的任务管理 |
| **匹配模型** | 什么事放在什么时间做？ | 不同类型的事项匹配不同精力状态的时间段。高认知负荷 → 深度时间；低认知负荷 → 碎片时间 | 适用于知识工作者、创意工作者 |

### AB 工作法

Truman 采用的 AB 工作法：将一周分为 A 周和 B 周——A 周专注对外事务（会议、协作、沟通），B 周专注深度工作（创作、思考、建模）。半天的切换成本换来整周的深度时间，整体产出不降反升。

**关键假设**：公开排期后，团队会自然适应这种节奏，减少在 B 周的打断请求 → 被验证为真。

---

## 三、成果与数字

- **假设数量**：过去一两年提出并验证了 30-50 个关键假设（口述稿第 316-594 行）
- **模型迭代**：三个模型各自经历了多轮迭代——从粗糙的分类到精细的匹配规则
- **系统化**：所有碎片化的时间管理工具（日历、待办清单、番茄钟等）被整合到一个统一框架下——「一旦有了基础模型框架，所有碎片工具都能被重新激活并挂到树上」（口述稿第 486-492 行）
- **持续运转**：至今仍在持续优化，因为模型本身允许无限迭代

---

## 四、与双三角/Y模型 的关系

1. **Y模型 引擎层演示**：本案例和 PPT 案例是 Y模型 在「个人效能」和「AI 协作」两个领域的最佳演示。PPT 案例展示了引擎如何从零创造一个新工作流；时间管理案例展示了引擎如何把一个长期混沌的问题变成可无限优化的系统。

2. **双三角要素对应**：
   - **审美**：判断什么时间投入是「值得的」——这是时间管理中最核心的判断力
   - **体系**：三模型 + AB 工作法 + 公开排期构成时间管理的完整体系
   - **创造力**：跳出「时间管理 = 自律」的隐含假设，用建模思维重构
   - **数据**：时间切片记录、产出效率追踪
   - **基本功**：日历、待办清单、深度工作法

3. **人在环**：Truman 不依赖 AI 来替他管理时间，而是用 Y模型 建立了自己的判断框架——人在框架层把关（定义什么重要），执行层可以借助工具。

---

## 五、Critique

### 内部局限

1. **个人案例，迁移需谨慎**：Truman 作为一号位，对时间的控制权高于大多数员工。AB 工作法在他身上有效，在客户经理、客服等角色上可能不可行。
2. **30-50 个假设的验证质量未知**：数量不等于质量。案例提到了假设数量但没有逐个展开验证过程和结果。
3. **模型的维护成本**：三模型体系需要持续维护和迭代，对于不需要长期优化时间管理的角色可能 overkill。

### 外部攻击

**[Cal Newport, Deep Work Author]**
> 「AB 工作法的核心理念——用半天切换成本换整周深度时间——听起来合理，但缺乏对照实验。在没有对照组的情况下，我们不能确定产出提升是因为 AB 工作法，还是因为 Truman 作为一号位本来就有持续提升的趋势。」

**回应**：这个批评成立。Truman 的时间管理改善可能是多因素共同作用（AB 工作法 + 团队成熟 + 个人经验增长）。这不影响三模型框架作为**起点框架**的价值，但不应将其效果归因于单一因素。

## 六、Synthesis

本案例与 [[case-yihang-dual-triangle-truman-feishu-to-slide-ppt-evolution]] 构成 Y模型 引擎层的**双案例锚点**：

| 维度 | PPT 案例 | 时间管理案例 |
|:---|:---|:---|
| 领域 | AI 协作 / 工具创新 | 个人效能 / 自管理 |
| 起点 | 完全不懂 PPT Agent | 长期混沌、被动打断 |
| V1→V2 跨度 | 工具问题 → 系统问题 | 自律问题 → 建模问题 |
| 核心产出 | 飞书 To slide 工作流 | 三模型 + AB 工作法 |
| 飞轮 | 每次项目都让资产库更强 | 每次假设验证都让三模型更准 |

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:---|:---|:---|
| 感觉时间管理失控、被动打断严重 | 用三模型框架诊断：是时间模型的问题（格子没画好）、事情模型的问题（不知道什么重要）、还是匹配模型的问题（事情放错了格子）？ | 能指出最需要优化的那个模型 |
| 想尝试 AB 工作法 | 先和团队沟通，公开排期。用两周试运行 | 试运行期间的打断次数下降 ≥20% |
| 积累了大量时间管理工具但效果不稳定 | 停止追新工具。先画出你的三模型 V1——哪怕很粗糙 | 三模型 V1 在 30 分钟内完成 |
