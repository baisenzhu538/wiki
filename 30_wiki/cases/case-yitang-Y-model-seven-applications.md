# Y模型七人跨域应用案例集

## Background

来源：段王爷整理的《Y模型火种·科学做事思考合集》。七位同学在一堂 Y模型课程后，各自选择一个真实难题，按照「明确核心问题 → 拆解变量 → 理论端 → 事实端 → 知行迭代」的五步框架完成作业，并由段王爷做逐步骤对标点评。七个领域覆盖子女教育、AI 产品、情绪管理、职业晋升、SaaS 运营、内容创作和小说拆解。

## Problem

同一套 Y模型框架，能否迁移到完全不同的七个领域？如果可行，不同领域的应用会暴露出哪些共同短板？

## Decision

用 Y模型五步框架对七个案例做逐步骤对标，既验证框架的可迁移性，也找出共性缺陷。

## Process

### 1. 张海波：孩子成绩提升

| Y模型步骤 | 关键执行 | 亮点 |
|:---|:---|:---|
| 明确问题 | 从「分数低」下沉到「知识吸收卡点」 | 区分根因与表象 |
| 拆解变量 | 预习 → 听课 → 复习 → 作业 → 考试全流程拆解 | 细化到错题类型、失分题型分布 |
| 理论端 | 最近发展区、费曼学习法、刻意练习 | 借理论最全 |
| 事实端 | 成绩比作业低 10-15 分 → 锁定考试心态问题 | 定性定量最具体 |
| 知行迭代 | 试一周睡前提问 → 对比错题数变化 | 最小验证闭环 |

### 2. 一堂创业者：百度数字人 Keevx 优化

| Y模型步骤 | 关键执行 | 亮点 |
|:---|:---|:---|
| 明确问题 | 判断产品处于「用户价值验证阶段」，不是增长阶段 | 阶段判断准确 |
| 拆解变量 | 259 模型 → 商业画布 → 业务公式三层拆解 | 唯一拆到业务公式 |
| 理论端 | 259 模型、商业画布、增长飞轮、用户价值假设 | 借力体系完整 |
| 事实端 | 5 个假设逐条列出，定义一级指标与数据口径 | 事实端扎实 |
| 知行迭代 | 产品太新，停留在逻辑推演 | 验证尚未启动 |

### 3. 任桓毅：用语写梳理情绪

| Y模型步骤 | 关键执行 | 亮点 |
|:---|:---|:---|
| 明确问题 | 从「给别人上课」纠偏为「总结自己用语写梳理情绪的方法」 | 回溯到因最深刻 |
| 拆解变量 | 自由书写 → 借鉴同侪 → 框架应用 → 刻意练习 | 四阶段递进 |
| 理论端 | 课题分离、非暴力沟通、冰山模型三件套 | 借理论最密 |
| 事实端 | 3800 万字、1000 万字情绪梳理数据意识 | 有主观验证，缺系统量化 |
| 知行迭代 | 3 年持续迭代，内化成思考方式 | 长期主义 |

### 4. 陈川：3 年内晋升为产品总监

| Y模型步骤 | 关键执行 | 亮点 |
|:---|:---|:---|
| 明确问题 | 从执行层 → 策略层，对标总监能力要求 | 目标清晰量化 |
| 拆解变量 | 竞品分析 × 文档撰写 × 客户访谈，每维度 3 个量化标准 | 结构化程度最高 |
| 理论端 | 波特五力、STAR 原则、NPS 分层、OSCAR 模型 | 借力体系完整 |
| 事实端 | 全量化指标 + 3 个月 / 2 个月 / 6 个月时间线 | 事实端扎实 |
| 知行迭代 | 加法 → 减法 → 实践 → 每月能力矩阵自检 | 四步法最结构化 |

### 5. 李思远：提升 AI CRM 系统用户活跃度

| Y模型步骤 | 关键执行 | 亮点 |
|:---|:---|:---|
| 明确问题 | 7 日活跃 28%，远低于行业 35-40% | 有基准对标 |
| 拆解变量 | 活跃 = 注册 × 登录率 × 使用率 × 满意度 × 触达频率 | 业务公式最直接 |
| 理论端 | 偏实战派，理论借力较少 | — |
| 事实端 | 每个变量定义具体验证实验 | 实验设计清晰 |
| 知行迭代 | 每周选 1 个变量做 MVP 实验，8 周一循环 | 工业化迭代节奏 |

### 6. 丁立章：财经号涨粉

| Y模型步骤 | 关键执行 | 亮点 |
|:---|:---|:---|
| 明确问题 | 让专业内容穿透用户认知壁垒 | 问题定义精炼 |
| 拆解变量 | 用户端（需求 × 场景）+ 内容端（价值 × 模型）双线 | 双线拆解 |
| 理论端 | 资产负债表 → 家庭记账本；降息 → 菜市场降价；内容三段式 | 科学类比冠军 |
| 事实端 | 写 3 篇测打开率 / 转化率 | 有验证思路，数据锚点不足 |
| 知行迭代 | 看关注转化和回流效果 → 调整选题 | 有闭环意识 |

### 7. 赵干：《长安的荔枝》运荔枝

| Y模型步骤 | 关键执行 | 亮点 |
|:---|:---|:---|
| 明确问题 | 拆解为速度、保鲜、成本三个核心子问题 | 问题拆分清晰 |
| 拆解变量 | 保鲜端（整株移植 + 盐水 + 冰块）+ 运输端（驿站接力） | 双线并行 |
| 事实端 | 小说情节，无真实数据 | 天然数据不足 |
| 知行迭代 | 发现快马损耗大 → 调整为水陆联运 + 保鲜升级 | 迭代路径清晰 |

## Result

- **七人合在一起恰好覆盖 Y模型全部环节**：
  - 一堂创业者 → 怎么拆到最细
  - 张海波 → 怎么用红卡蓝卡
  - 任桓毅 → 怎么回溯到因
  - 丁立章 → 怎么做好科学类比
  - 李思远 → 怎么工业化迭代
  - 陈川 → 怎么结构化执行
  - 赵干 → 怎么看到二阶效应
- **共同短板**：
  1. **数据闭环**：多数人停留在「先假设 → 再验证」框架，但缺少真实数据分析。
  2. **反例验证**：无人做「什么情况下这个方案会失败」的反向推演。
  3. **用户反馈**：除陈川（客户访谈）外，其他人缺少外部验证环节。

## 可迁移场景

1. **学习一门方法论后的迁移训练**：强制把同一框架应用到三个完全不同领域，检验是否真懂。
2. **团队组合使用 Y模型**：让擅长理论类比的人和擅长事实量化的人配对，覆盖 Y模型双路径。
3. **课程作业 / 训练营设计**：用「七人跨域案例集」作为学员模仿模板，降低入门门槛。
4. **个人决策训练**：把子女教育、职业晋升、情绪管理等个人难题用 Y模型五步拆解。
5. **方法论可迁移性验证**：任何新框架推广前，都可以先做跨域案例集测试。

## 教训

1. **Y模型是一套可迁移的科学思维方式**：七个完全不同的领域能用同一框架产生高质量分析，说明其价值不在于具体领域知识，而在于「遇到难题先拆因果」的思维肌肉记忆。
2. **框架只是起点，验证才是终点**：案例分析要补数据闭环和反例验证，否则容易沦为「用 Y模型包装直觉」。
3. **不同领域的强弱项互补**：有人擅长理论类比，有人擅长事实量化，团队组合使用比个人单打独斗更能覆盖 Y模型全链路。

## 失败模式

1. **只套框架不验证**：把五步法当 PPT 模板，写完后没有执行任何验证动作。
2. **只看成功不看失败**：只收集支持案例，不做预复盘和反例推演。
3. **只做定性不做定量**：停留在「用户不喜欢」这类模糊结论，没有数据锚点。
4. **忽视外部反馈**：只在自己脑子里闭环，不引入真实用户或利益相关者验证。

## Critique

### 外部反对者

1. **Daniel Kahneman /《噪声》**：七人案例把 Y模型描述为「可迁移的科学思维方式」，但案例多为单次作业而非受控实验。不同领域的分析质量差异大，「可迁移」可能是一种后见之明叙事，而非被严格验证的结论。结构化框架本身也会放大锚定效应：一旦画出五步图，分析者容易过度相信自己已经科学。
2. **Paul Feyerabend（《反对方法》）**：七位同学用同一框架产出高质量分析，并不意味着框架是原因。可能是学员本身具备较高认知水平、课程训练或段王爷点评的催化作用。把成功归因于 Y模型，可能犯叙述谬误和因果混淆。
3. **组织行为学视角**：七个案例全是个人作业，缺少团队协作、权力冲突和真实利益约束。把个人分析能力迁移到组织决策，中间隔着巨大的执行鸿沟——个人能「拆因果」，不代表组织能「做验证」。
4. **教育评估视角**：作业合集是选择性样本，只有愿意提交并被点评的案例；失败或低质量作业可能被过滤。这种选择偏差会高估 Y模型的实际迁移效果。

### 内部局限

1. **案例深度不均**：有人拆到业务公式，有人仍停留在定性描述；七人合在一起才覆盖 Y模型全链路，说明单个个案往往只能触达局部。
2. **验证环节普遍薄弱**：除陈川外，多数案例缺少真实用户或利益相关者反馈，「知行迭代」更接近自我叙事，而非可证伪的迭代。
3. **点评者效应**：段王爷的逐步骤点评本身可能塑造了案例结构，学员未必能独立复现同样质量的分析。

## Synthesis

本案例集是 [[yt-decision-y-model]] 跨域迁移性的经验证据，也是 [[tool-yitang-Y-model-application]] 的实操参照。它与 [[case-yitang-Y-model-advertising-turnaround]] 形成对照：七人案例展示「框架如何迁移到多领域」，广告投放案例展示「框架如何在单一复杂商业难题中持续迭代」。共同短板（数据闭环、反例验证、用户反馈）正好对应 [[dk-yitang-Y-model-pitfalls]] 中的主观臆测、知行分裂和错误类比陷阱。
