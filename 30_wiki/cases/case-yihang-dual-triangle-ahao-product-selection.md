# 一行双三角案例：阿豪电商选品函数替代模型

> **一句话定义**：童装电商运营背景的阿豪，在公司资源、技术、数据基础均薄弱的情况下，3 个月内带队搭建内部自动选品系统，把 60 分钟人工数据收集压缩到 3 分钟，当月新增收入约 40 万，并验证「能写成函数的判断不要交给大模型」的关键原则。

---

## 一、背景

**业务**：阿豪长期深耕电商运营，尤其是童装电商；团队曾在 4 年内把 GMV 做到破亿，从夫妻档扩展到百人团队。他在公司内负责运营，日常工作覆盖选品、推广、库存等全链路。

**规模与痛点**：
- 公司每年要上新约 1000 个 SKU/SQ 测评，其中只有少量值得加杠杆重点推广。
- 选品依赖少数资深员工的「不可名状的经验」，没有成体系的方法；A 做得好、B 做得差，但说不清楚 A 到底强在哪里。
- 数据采集基本靠人工：运营每天从淘宝、抖音、拼多多、ERP 等各个平台把数据导到本地 Excel，用 vlookup 对齐字段，再用肉眼扫表分析，最后做成报告提交管理层。
- 因为表格太复杂、数据量太大，管理层也很难细看，往往是「按大概的感觉挑大概的数据」，决策质量高度依赖个人状态和当天精力。
- 来源材料中直言：「基本上绝大部分公司都这个水平」（page003）。

这种工作模式的直接后果是：
- 重复、枯燥、费人，运营每天被困在拉数、拼表、看表里；
- 人的注意力有限，1000 个品里只有极少部分被认真评估，大量潜在爆款根本没被看到；
- 选品质量随个人水平波动，无法沉淀为公司资产。

这也意味着，AI 落地的第一步不是急着找工具，而是先正视这种混乱、把它结构化。

**资源约束**：
- 公司不大，技术能力弱，没有专职程序员和开发能力。
- 数据化基础薄弱，数据散在各个平台，没有集中数据中心。
- 阿豪本人没有技术背景，却要在 3 个月内完成一次业务攻坚。
- 来源材料描述他手里的牌时说：「在没有任何技术背景，没有任何所谓的程序员和开发能力的情况下，如何三个月的时间完成整个业务的攻坚和突破？」（page001）。
- 主讲人评价这种状态「比较符合很多人的状态」——没有大平台、没有技术中台、没有充足预算，却要落地 AI（page001）。

**解题范式**：主讲人在引出阿豪之前特别强调了解题范式的重要性：遇到一个问题解一个问题，不要一开始被惯性吓退，双三角给了大家笃定和能力（page001）。阿豪的整个过程——从梳理业务、补齐数据、组建团队到函数替代模型——正是这种「迎难而上、问题驱动」范式的体现。

**目标**：阿豪没有满足于简单的降本增效，而是给自己定了一个「大愿」——全面提升公司运营效率，并探索未来可对外复用的行业通用方案（口述 page002）。这个案例因此具有很强的参照意义之一：它不是说只有资源充足的大公司才能做 AI 落地，而是证明在资源受限、技术薄弱、数据混乱的条件下，只要双三角六要素补齐，就能用三个月跑通一个高价值场景。

## 二、决策与行动

### 人类三角

| 要素 | 具体体现 |
|:---|:---|
| **审美** | 判断 AI 方向是否合理、能否看懂 AI 分析结果、建立最佳实践的评判标杆；在选品场景中判断哪些品值得投杠杆、哪些只是数据噪音；对「果绿色是今年流行色」这类行业经验设定权重（page005）。 |
| **体系** | 先用飞书/文档把业务模块（选品→推广→库存）和数据流程图画清楚；建立项目管理里程碑；把原来靠直觉运转的成熟业务体系改造成可落地的 AI 流程；设计三层打标签体系和稳定的数据处理链路（page004、page005）。 |
| **创造力** | 提出「全 AI 自动化选品/诊断完整方案」；用「外部临时合伙人团队」补足技术缺口；用「内网穿透+本地部署」快速上线；提出并坚持「能写成函数的判断不要交给大模型」的函数替代模型原则（page004、page006、双三角模型图）。 |

### AI 三角

| 要素 | 具体体现 |
|:---|:---|
| **场景** | 用「业务频率高 + 有商业价值 + 实现难度可控」的筛选模型，从全链路中锁定「内部选品」这个具体切口；使用 START 模型评估提效降本价值（page002、双三角模型图）。 |
| **数据** | 电商多平台数据采集；建立数据库+知识库；把隐性经验变成正向/负向/属性标签；针对流量层、转化层、渠道层打标签；加入行业趋势权重；用模拟数据测试（page004、page005、page006、双三角模型图）。 |
| **基本功** | 基础提示词、工作流、RPA、Python 脚本、工程化部署；用 Python 函数完成打标签与分类，而不是直接调用大模型；把 LLM 限制在「最基本的部分」；用敏捷方式拼凑前后端、本地服务器快速上线（page005、page006、双三角模型图）。 |

### 关键动作链

1. **许大愿，但切小口**
   - 目标定为全面提升运营效率，甚至未来行业通用；
   - 先用「高频率 × 商业价值 × 可控难度」的公式筛选，避免做「最容易」或「最宏大」但无法落地的场景；
   - 最终锁定「内部选品」：不是开放选品，而是对已有每年约 1000 个 SKU/SQ 进行内部筛选（page002）。

2. **业务地图先行，不急着动手**
   - 阿豪没有把第一步定义为「写提示词」或「调模型」；
   - 他先把过去没有盘清楚的业务全部盘了一遍，画出选品、推广、库存等业务模块图；
   - 再输出数据流程图、数据模块图和实际场景图，把入口、出口、关键节点全部理清楚（page002、page003）。

3. **学习对标，补齐认知**
   - 在动手之前，阿豪先去全网学习，看一堂知识库、找对标案例、研究各行业基于 AI 的业务流；
   - 这一步让他对「汽车工厂」应该长什么样有了大致图景，也为后续技术选型和团队沟通打下基础（page003）。

4. **先做 AI 的「地基工程」**
   - 在引入 AI 之前，先把旧的「马车工厂」推倒，重新为「汽车工厂」打地基；
   - 来源材料强调：「准备数据准备流程叫 AI 工作吗？叫啊当然叫」「你给新的工厂打地基做防水，这已经在建那个工厂了」（page004）；
   - 这一步看起来没有直接用 AI，却是整个项目能跑通的关键。

5. **把隐性直觉显性化成标签**
   - 从流量层、转化层、渠道层拆出正向标签、负向标签、属性标签；
   - 把「老师傅脑子里」的经验变成可复用的数据结构；
   - 例如给「果绿色是今年流行色」这类行业趋势设定 +20% 的权重（page004、page005）。

6. **用外部临时合伙人团队补技术缺口**
   - 阿豪自知只懂业务不懂 AI，借助大航海生态组建了一支临时合伙人队伍；
   - 队伍里包括后来帮了大忙的 B 同学等技术背景成员；
   - 团队不占用公司编制，通过定章程、定目标、定交付标准来管理（page004、page006）。

7. **数据自动化：让重复劳动先消失**
   - 用 RPA 把多平台数据采集、字段对齐、入库做成自动化链路；
   - 建立数据库和知识库，让后续打标签和算法判断有稳定的数据底座；
   - 原来 60 分钟的人工收集工作被压缩到 3 分钟（page006）。

8. **函数替代模型：能写 Python 就别用大模型**
   - 对确定性判断（ABC 分类、属性标签）全部用 Python 函数实现；
   - 大模型只保留在「没法写成规则」的最小环节；
   - 原因很现实：大模型输出随机不稳定，而且「贼贵」；来源材料的原话是「他都能写脚本了，你为什么要还要用模型呢？」（page005、page006）。

9. **黑盒转白盒，持续纠偏**
   - 1.0 版本「特别差」，模拟数据测试后不断迭代；
   - 通过大量数据处理和规则显化，把系统从「二三十个答案里碰一个还行」变成稳定交付；
   - 来源材料把这一过程概括为「黑盒转白盒，然后纠偏」（page005、page006）。

10. **敏捷工程化，三个月内上线**
    - 用本地服务器+内网穿透等短平快方式拼凑前后端；
    - 在 3 个月内完成自动抓取、整理、入库、分类、打标签、前端展示的全链路系统（page001、page006）。

## 三、结果

- **效率**：原来需要 60 分钟的人工数据收集、整理、对齐工作，被压缩到 **3 分钟**。
- **收入**：系统上线当月为公司带来约 **40 万新增收入**，年化约 **500 万**（page001、page006）。
- **能力沉淀**：搭建了一套内部自动选品系统，实现数据采集、整理、分类、打标签、算法判断、前台展示的端到端自动化。
- **精力转移**：运营团队从「拉数、拼表、看表」中释放出来，可以把注意力放回判断、策略和创意上。
- **方法论验证**：验证了「能写成函数的判断不要交给大模型」的规模化落地原则。
- **资产沉淀**：更重要的是，它把原本依赖个人经验的选品能力，沉淀为公司可复用的数字资产和规则库。
- **后续扩展**：选品模块跑通后，阿豪又把同样思路复制到推广、库存等其他模块（page007）。

## 四、可迁移洞察

### 洞察 1：准备数据和流程本身就是 AI 工作

阿豪在真正「调用 AI」之前，花了大量时间调研、梳理业务、整理数据、画流程图。来源材料里反复强调：「准备数据准备流程叫 AI 工作吗？叫啊当然叫」（page004）。把马车工厂的地基挖深、做防水、选址，这些看起来不是造车的工作，其实就是在造汽车工厂。很多团队失败的原因正是跳过这一步，直接打开 ChatGPT 写提示词，结果提示词调得再漂亮，底层数据一塌糊涂，系统也跑不稳。 glamorous 的提示词工程背后，往往是脏数据和模糊流程。地基不牢，提示词和 Agent 都只是空中楼阁。

### 洞察 2：能写成函数的判断，绝不要交给大模型

这是本案例最核心的暗知识。阿豪在建立三层打标签体系时，对凡是能形成规则、能生成函数的判定，全部用 Python 脚本完成。来源材料的原话是：「打标签就判断标签这件事情能用 python 别用大元模型……模型有两个巨大的问题，第一个随机概率不稳定，第二贼贵」（page005）。代码不费 token，规则稳定、成本低，只有在「没法写成函数」的地方才保留大模型。规模化落地的稳定性与成本，很大程度上取决于这条边界划得有多清楚。确定性判断交给代码，概率性理解才交给模型，这是工程化与 demo 的根本区别。本案例也因此成为五部曲工程化阶段「规则显性化」原则的关键注脚。

### 洞察 3：用外部临时合伙人团队解决技术资源缺口

阿豪的公司没有程序员、没有技术预算，但他没有因此放弃。他借助大航海生态拉起一支临时合伙人团队，不占用公司工资成本，通过定章程、定目标、定交付来驱动。来源材料评价：「充分利用了大航海的优势，就是给自己拉个团队」「这些人挺开心的」（page006）。这是典型的组织创新杠杆：当内部资源不够时，用外部协作网络补足缺失要素，把「缺人」变成「缺机制」。

### 洞察 4：场景选择公式——业务频率高 + 商业价值 + 实现难度可控

阿豪没有一开始就想做全行业通用系统，而是先用一个简单模型筛选场景：业务频率高、有商业价值、实现难度可控。最终锁定「内部选品」（page002）。这个公式可以直接复用到任何 AI 落地项目：避免选最容易做的（没价值），也避免选最值钱的（做不出来）。它本质上是在五部曲「定场景」阶段做的一次「充分加法，专业减法」。阿豪的双三角模型图里还明确把 START 模型作为评估工具，说明场景筛选不是拍脑袋，而是有框架支撑的决策。

### 洞察 5：AI 不是替代人，而是把人的东西放大

来源材料在最后总结：「AI 真的不是替代人，而是把人的那个东西给放大了」（page007）。阿豪的审美、业务经验、判断标准被写进规则和数据标签后，系统才能稳定运行；没有这些人类三角的输入，技术再强也是原地转圈。双三角里「没有数据不行，没有流程不行，没有审美不行」（page007），这句话在本案例中体现得尤为明显。而审美恰恰是这里面最难临时抱佛脚的——来源材料以写歌为例说，「学审美这件事情，真的一时半会学不会」（page007）。

### 洞察 6：从黑盒到白盒是工程化的关键一跃

项目初期，老方法虽然稳定，但决策逻辑藏在少数人脑子里，是典型的黑盒。阿豪通过标签化、规则化、Python 化，把黑盒经验逐步转白盒，再用模拟数据不断纠偏。来源材料把这一过程总结为「黑盒转白盒，然后纠偏」（page005、page006）。只有完成这步，AI 系统才能从「偶尔灵验」变成「稳定交付」，也才具备被团队复制和长期维护的可能。这种白盒化还为后续审计和迭代提供了基础：每一条规则都可以被追问、被修改、被版本控制，而不是依赖某个离职员工的记忆。对组织而言，白盒化才是 AI 资产真正的护城河。

## 可迁移场景

- 电商选品、爆款预测、商品分级与资源倾斜。
- 任何依赖多平台数据采集与规则判断的运营工作。
- 资源受限、无技术团队的中小企业做 AI 落地。
- 把老师傅经验显性化为可复用数据资产。
- 用外部临时合伙人/外包团队补齐技术短板的创新项目。

## 教训

- 准备数据、准备流程本身就是 AI 工作，不要急着写提示词。
- 能写成函数/规则的判断，绝不要交给大模型，稳定性与成本差一个数量级。
- 场景选择公式：业务频率高 + 有商业价值 + 实现难度可控。
- 组织资源缺口可以通过「外部临时合伙人 + 清晰章程」来解决。
- 从黑盒经验到白盒规则，是工程化的关键一跃。

## 失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| 跳过业务地图直接动手 | 系统与实际流程脱节 | 先画业务模块图和数据流程图 |
| 把模糊判断交给 LLM | 输出不稳定、不可解释 | 先尽量规则化、函数化 |
| 没有数据地基 | AI 输出质量波动大 | 先统一数据采集与标签体系 |
| 忽视变革管理 | 老员工抵制、系统闲置 | 设计激励机制，让老师傅参与规则制定 |
| 贪大求全 | 3 个月做不出来 | 先切高频率、高价值、可控难度的小口 |

## 五、Critique

### 内部局限

1. **行业特殊性**：童装电商选品依赖可抓取的平台数据和相对明确的商品属性，换到数据封闭、合规严格或线下服务占主导的行业，同样的自动化路径会受阻。
2. **外部临时团队不可复制**：阿豪能借力大航海生态低成本组建技术团队，普通企业在没有类似协作网络时，需要承担真实的招聘或外包成本，ROI 会被稀释。
3. **规则上限明显**：用 Python 函数打标签适合历史规律可归纳的品类，对全新品类、突发流行趋势、非结构化情感信号（如社交媒体热度）的捕捉能力有限，需要持续补充数据和人工审美校准。
4. **财务核算不完整**：来源材料只披露了当月 40 万新增收入，没有公开临时团队成本、后续运维成本、平台接口变动带来的 RPA 重配成本，长期 ROI 仍需更严谨的财务验证。
5. **责任边界模糊**：当系统推荐了一个亏损 SKU 时，责任应该归算法、归数据、还是归做最终判断的人？如果这个问题没有提前约定，团队信任可能随错误案例累积而下降。
6. **审美仍需人在环**：即便系统能自动打分，最终哪些品值得加杠杆推广，仍然需要人的审美判断。系统无法替代人对品牌调性、用户情绪和长期战略的把握。

### 外部攻击

**运营务实派**：当月 40 万新增收入听着漂亮，但并未公开计入临时团队成本、后续维护成本、平台接口变动带来的 RPA 重配成本。一旦平台反爬升级或字段改版，3 分钟的优势可能迅速消失，实际 ROI 需要更长期的财务核算。而且，把决策从人转移到系统后，谁来对错误选品负责？责任边界模糊会影响团队信任。

**AI 技术派**：过度强调「函数替代模型」可能走向另一个极端——把本可以交给 LLM 的非结构化理解任务也硬写成规则，导致系统僵化、遗漏长尾信号。真正的最佳实践应是「规则兜底 + 模型补位」，而不是一刀切地排斥大模型。

## 七、Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:---|:---|:---|
| 要启动一个 AI 改造项目 | 先画业务地图：模块、数据流、入口/出口，而不是先选工具 | 输出 1 套业务模块图 + 数据流程图 |
| 有确定性判断需要规模化执行 | 问：这个判断能写成函数/规则吗？能就用 Python/RPA，不用大模型 | 规则覆盖 ≥80% 的判定场景，且输出稳定 |
| 内部缺技术资源但想落地 AI | 寻找外部临时合伙人/志愿者团队，定章程、定目标、定交付 | 形成 1 份有里程碑和退出机制的合作章程 |
| 数据收集占据大量人工时间 | 优先用 RPA/脚本把多平台数据采集、字段对齐、入库自动化 | 数据收集耗时缩短 5 倍以上 |
| AI 输出不稳定或出现幻觉 | 把判定拆成「规则层」+「模型层」，让 LLM 只做最小必要部分 | 关键指标波动范围缩小到可接受阈值 |
| 面对多个 AI 场景不知道选哪个 | 用「频率高 + 商业价值 + 实现难度可控」三维度打分 | 筛选出 1-3 个优先级最高的细分场景 |
