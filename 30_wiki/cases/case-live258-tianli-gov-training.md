# 田力组织部干部培训方案：被退回重写，复盘发现 7 个 Feature 全缺、几乎裸 prompt 提交

> 一句话：为某市委组织部设计「年轻干部能力提升」教研方案，ChatGPT 直出第一版被退回——「太学术化、不够实战、缺少针对性」。用 Feature 思维复盘：当时只用了「基本任务描述」一个 Feature，最终意图/上下文环境/数据来源/参考案例/角色设定/Few-shot/本地化要求 7 个 Feature 全缺——「难怪方案被退回，我几乎什么 Feature 都没加！」（L1333）。政府培训的专业性不是天赋，是一个个 Feature 的精准叠加（L1695-L1697）。

---

## 过程（起点→尝试→失败→转折→结果）

### 起点：一个「要立项要钱」的方案任务

任务：为某市委组织部设计「年轻干部能力提升」教研方案（L1063），培训周期 5 天，内容包括理论学习、案例分析、实战演练（L1075）。

### 尝试：四步裸操作

原始操作流程（L1073-L1079）：打开 ChatGPT → 输入「帮我设计一个年轻干部能力提升的培训方案，培训周期为 5 天，内容包括理论学习、案例分析、实战演练」→ 生成内容整理成文档 → 提交项目负责人。一句话需求，零上下文，零迭代。

### 失败：被退回，四条判词

项目负责人的反馈（L1083-L1093）：「太学术化了，不够接地气」「缺少针对性，不符合我们当地干部的实际需求」「案例分析太空泛，没有本地特色」「实操环节设计不合理，没办法落地」——「重写」。

当时的困惑与错误归因（L1095-L1101）：「我都说清楚了要设计什么样的培训，为什么 AI 生成的这么差？」→「是不是这个 AI 不懂政府培训？」「我是不是该用专门做教育的 AI 工具？」——**典型的工具思维：出了问题就怪工具**。

### 转折：Feature 拆解——7 个缺失 Feature 逐个定位

复盘结论先行：用的 Feature 只有「基本任务描述（勉强算一个）」，缺的是一长串（L1305-L1333）。七个核心缺失，每个都带「如果加上」的具体写法：

| # | 缺失 Feature | 原始问题 | 「如果加上」的关键内容 | 行号 |
|:-:|:--|:--|:--|:--|
| 1 | 最终意图 | 只说「设计培训方案」，没说要达到什么目的 | 说服组织部领导认可专业性、争取立项、**预算 50 万**、突出差异化优势——这不是教学设计，是「要立项要钱」的方案 | L1111-L1135 |
| 2 | 上下文环境 | 完全没有提供任何背景 | 科级干部/平均 35 岁/街道办基层/实战强理论弱；组织部最关注「能解决实际问题」；当地推进产业升级；3 家高校竞争、省委党校是主要对手 | L1137-L1163 |
| 3 | 具体数据来源 | 说「案例分析」但没给案例，AI 只能编造或泛泛而谈 | 干部能力短板调研：65% 系统思考不足、58% 数字化工具不熟练、42% 跨部门协调弱；当地关注：营商环境/基层治理数字化/产业招商 | L1165-L1195 |
| 4 | 参考案例 | AI 不知道什么是「好的」政府培训方案 | 上一个成功方案的 5 天结构（破冰+党性教育→理论+案例研讨→现场教学+实战演练→分组项目+导师辅导→成果汇报）+风格要求 | L1197-L1229 |
| 5 | 专业角色设定 | AI 不知道以什么身份设计 | 「你现在是政府培训领域的顶级专家，有15年政府培训项目经验」，服务过 20+ 个组织部项目，擅长设计实战型、落地型的干部培训方案 | L1231-L1245 |
| 6 | Few-Shot 示例教学 | AI 不知道「案例分析」「实战演练」具体写什么 | 「数字化治理案例分析」模块示例（某街道一网统管）+「营商环境优化」演练流程示例 | L1247-L1277 |
| 7 | 本地化要求 | 政府培训最忌讳「万能方案」 | 案例优先本市真实案例、演练基于当地真实场景、讲师优先本地实战领导、对接当地今年重点工作 | L1279-L1301 |

另缺：N 版选 1（多版本对比）、渐进式披露（逐步给信息）（L1327-L1329）。

### 结果：三轮叠加实验与重做方案（推演）

Feature 叠加实验模拟（L1335-L1451）：
- V1=最终意图+角色设定 → 预期更有说服力、突出差异化
- V2=+上下文环境+数据来源 → 预期围绕真实短板设计、对接当地重点
- V3=+参考案例+本地化+Few-Shot → 预期具体可操作、符合政府培训标准格式、体现本地特色

如果重来的三轮迭代方案（L1453-L1491/L1571-L1611）：第一轮上 4 个核心 Feature（意图/角色/上下文/数据）→ 收集反馈「案例太泛化」→ 第二轮加 3 个本地化 Feature（参考案例/本地化/Few-Shot）→「方案更有针对性了，但还缺少差异化亮点」（L1483）→ 第三轮加 N 版选 1（实战型 vs 理论型 vs 综合型）+渐进式披露 → 选综合型突出「实战落地」优势。**⚠️ 全部为复盘推演，未实际重新执行。**

深度反思三条（L1493-L1539）：①最大问题=把 AI 当「万能生成器」而非「专业协作伙伴」——简单描述需求→等完整方案→直接提交，从未想过「我在用什么 Feature」；②Feature 思维给教育培训业三个能力：需求拆解/专业化/本地化；③制定政府培训 Feature 修炼计划四步（专属 Feature 清单→刻意练习本地化→跨项目迁移→组合创新）。

核心收获（L1613-L1699）：专业性来自 Feature 的精准叠加（对干部特点的理解/对组织部要求的把握/对本地实际的洞察/对培训方法的设计，每个 Feature 都是专业性的一个维度）；**Feature 就是「可复用的专业经验」**——过去每个项目「从零开始」，提炼 Feature 后「每做一个项目，我的能力资产都在增加」（L1663）；「Feature 越多，方案越专业。Feature 越准，方案越有效」（L1697）。

## Critique

**内部局限（自指）**：被退回是实测，但**整个补救方案零实测**——三轮叠加实验是「模拟一下」（L1337），重做方案是「如果当时」（L1453），最终效果如何无任何数据。7 个 Feature 的归因来自学员自己复盘，没有项目负责人对补 Feature 后方案的二次评价。65%/58%/42% 的调研数据在原始 prompt 里并不存在（当时是裸 prompt），它们是复盘时补写的——这本身说明「数据可得性」不是当时失败的约束，「没想到要给」才是。

**外部攻击者 1（Kahneman 式——后见之明偏差）**：复盘叙事把「被退回」整齐归因为 7 个 Feature 缺失，但被退回可能还有方案外的因素——竞标关系、价格、负责人偏好、甚至是高校与政府合作的信任基础。「换我是负责人，V3 方案也可能因为别的理由退回」——Feature 叠加改善的是文本质量，不保证中标。

**外部攻击者 2（Taleb 式——过度拟合单一判词）**：7 个 Feature 是从**一次**退回的四句判词反推的——为这四句判词定制的 Feature 清单，可能过度拟合这一个客户的口味。另一个组织部可能最看重政治性表述规范而非本地化案例。「政府培训 FeatureLibrary」要建立，需要多项目多样本，而非一次失败的全量外推。

## Synthesis

本卡是 Live258 族中**缺失侧信息密度最高**的案例——与 [[case-live258-fact-spread-18-bridges]]（王鹏飞）共同印证族内规律：翻车案例的信息密度高于成功案例。田力的特殊价值在于把「专业性」这个模糊概念拆解了：政府培训的专业性=对干部特点的理解（上下文）+对组织部要求的把握（最终意图）+对本地实际的洞察（本地化）+对培训方法的设计（参考案例+Few-shot），**每个 Feature 是专业性的一个维度**（L1631）——这正是 [[dk-demand-feature-stacking]] 维度覆盖而非数量堆叠在 To G 专业服务业的表述。与黄华春案构成镜像：黄华春无意识蒙对 4 个 Feature 成功，田力一个没蒙对被退回——同一枚硬币两面。其 Feature=可复用的专业经验论断（L1633）与 [[dk-feature-pieces-not-recognized-as-cards]] 同构：经验不提炼为 Feature，每个项目都是「从零开始」。本卡推演部分的价值在展示 Feature 叠加的标准叙事结构（核心 4→本地化 3→差异化 2 的三轮节奏），可作为方案类任务的复盘模板。

## Action Triggers

1. 方案类任务提交前过 7 Feature 检查单：最终意图/上下文环境/数据来源/参考案例/角色设定/Few-shot/本地化要求——缺三个以上不要提交
2. 被客户退回时先做 Feature 归因再动手改：把客户每条判词映射到具体缺失 Feature，逐条补
3. 竞标/立项类方案把「最终意图」写成一句话：这份方案要说服谁、争取什么、预算多少、差异化在哪
4. 建行业 FeatureLibrary：每项目结束记录「用了什么/缺了什么/哪个起关键作用」，按对象/内容/方法/评估分类

## 失败模式

| 失败模式 | 症状 | 修复 |
|:--|:--|:--|
| 一句话裸 prompt 交方案 | 「帮我设计一个年轻干部能力提升的培训方案，培训周期为5天，内容包括理论学习、案例分析、实战演练」→生成→直接提交（L1075-L1079） | 提交前 7 Feature 检查单，缺三个以上打回 |
| 出问题怪工具 | 「这个 AI 不懂政府培训」「该换专门工具」（L1099） | 先审输入：我喂了上下文/数据/案例吗？ |
| 案例空泛无本地特色 | 「案例分析太空泛」被判词点名（L1089） | 本地化 Feature 三件套：本市案例+当地场景+本地讲师 |
| 每个项目从零开始 | 经验不沉淀，下个项目重新试错（L1635-L1653） | 项目结束提炼 Feature 入库，下次直接复用 |
| 推演当验证汇报 | 「模拟叠加会有效」写成「已验证有效」 | 推演标注未执行；补做时按三轮节奏逐个叠加观测 |
