# 360 内训课隔夜重构案

> **定位声明**：本卡是 [[framework-ai-five-layer-architecture]] 第二层（Agent 层）与 [[framework-ai-native-working-paradigm]]「头尾站位」的**解压案例**——记录一堂给 360 做内训课时「课后复盘发现问题→当晚推翻重设计→6 小时交付」的完整决策链与操作序列。它不是教程（照抄流程没用），价值在**决策点序列**：什么时候决定推翻、推翻后第一件事做什么、人站哪。

## 真问题链（决策点序列，本卡核心）

1. **问题浮出的时机不是事前，是事后**（L108，逐字回验）：第一天课后复盘发现「练得不够，大家还没有到我们想象中的那个练习 AI 动手的那个击穿的拐点」，且「本来计划的第二天的原版课程不是最佳解决方案」。
   - 可复用的判断信号：效果「还不错」但没到拐点=不是执行问题，是设计问题——执行问题靠优化，设计问题靠推翻。
2. **推翻决策的成本结构变了**（L112，逐字回验）：过去推翻不现实，因为有了 AI、大量 Agent、多线程，「生产力暴涨之后」推翻的边际成本降到可承受——**AI 化改变的不只是速度，还有「什么决定敢做」**。
3. **推翻后第一件事不是开干，是拆任务**（L124，逐字回验）：「我需要拆分成10几个子任务啊，然后每一个任务依赖的任务又是什么」——先拆依赖，再拆里程碑。
4. **第二件事是画双三角画布**（L124，逐字回验）：「其实 AI 这种任务最怕的就是跑偏啊，做了一半发现歪了，做了一半发现错了，一旦推翻整个项目万劫不复」——用双三角画布先定业务逻辑，防跑偏。
5. **第三件事是 3000+ 字顶层文档口喷**（L126-128，台账 A22）：喷完 AI 整理，「所有 AI 读完这个文档几乎就可以干活」——顶层文档=多 Agent 分工的枢纽。
6. **第四件事是宪法先行**（L130-136，台账 A23/A24）：设计总监 Agent 先研究历史设计规范产出**设计宪法**，然后「连开五个设计师 Agent」并行出图——**并行化的前提是规范先行，没有宪法并行=五种风格打架**。
7. **人的位置**（L144-148，台账 A25）：PPT 从 1.0 迭到 4.0，人只做头部产品定义+尾部细节把关，中间全 AI。
8. **结果验证**（L156-162，逐字回验）：「终于那个练习感击穿了」——用学员猜制作周期的反差做效果证明。

## 机制拆解（为什么隔夜推翻能成）

1. **顶层文档替代了「交代背景」**：多 Agent 并行的最大瓶颈是每个 Agent 都要重新理解任务；3000 字顶层文档把背景一次性显性化，所有 Agent 读同一份。
2. **宪法把品味从人转移到文件**：设计品味原本是最难并行的（每人一个审美）；宪法文件让五个设计师 Agent 共享同一套判断标准，并行才可能。
3. **双三角把「跑偏」从事故变成检查项**：画布定了「业务逻辑是什么」，中途每一步都可以对画布自查，而不是等做完发现歪了。
4. **人站头尾是产能结构不是姿态**：头部（定义）和尾部（把关）是判断密集区，中间是执行密集区——AI 化的收益恰好集中在执行密集区。

## L4 失败模式（轻量深挖）

| 失败模式 | 触发信号 | 修复动作 |
|:--|:--|:--|
| 把「推翻」当勇气而不是计算 | 复盘会上下决心很快，但没有先算重做成本 | 推翻前先跑一遍任务拆解+依赖图，拆得出来才推翻（案例顺序：先拆后决，不是先决后拆） |
| 并行无宪法 | 五个 Agent 产出五种风格，返工比串行还慢 | 并行前强制产出一份书面规范文件，宁晚 30 分钟 |
| 顶层文档写成作文 | 文档很长但没有「Agent 读完能干活」的指令性 | 用「所有 AI 读完这个文档几乎就可以干活」做验收：找一个新的 Agent 只读文档能否复述任务清单 |
| 头尾站位退化成全程遥控 | 中间环节频繁人工介入，AI 在等指令 | 数一数自己今天发了多少条中间指令；>5 条=站位漂移，回头部改定义而不是在中间救火 |

## Critique

### 外部攻击

1. **归因攻击（课程vs案例混淆）**：6 小时交付的是「课」，质量证据是「练习感击穿」这种体感词，没有学习效果的独立度量——推翻的收益被讲者的叙事偏好放大。
   - 回应：成立。本卡只主张决策链与操作序列可复用，不主张「6 小时=同等质量」；证据表已标自述口径。
2. **可迁移性攻击**：讲者自己有一堂的方法论库+设计规范积累，宪法与顶层文档的「原料」是十年积累；换个人没有原料，隔夜推翻照样翻车。
   - 回应：成立，采纳。迁移前提=有可封装的方法论存量（对照 [[framework-encapsulation-methodology]]）；没有存量的团队，本案的复制顺序应反转为「先攒宪法，再谈并行」。

### 不要用的场景

| 场景 | 为什么失效 | 替代方案 |
|:--|:--|:--|
| 高合规要求的交付（对外承诺版） | 隔夜推翻没有质量沉淀周期 | 保留推翻设计，但加独立评审节点 |
| 团队第一次用多 Agent | 没有文档与宪法习惯，并行即 chaos | 先单 Agent 跑通全流程，再拆并行 |

## Synthesis

三步编译收束：本案的独立价值是把「AI 加速交付」这个俗套结论拆成了四个前置件——推翻的成本重算（L112）、任务依赖拆解（L124）、双三角防跑偏画布（L124）、宪法先行再并行（L134-136）。缺任何一件，隔夜推翻都是事故而不是案例。与库内互链：双三角画布与 KDO 人机协作双三角独立同源互证（[[bridge-yitang-kdo-dual-triangle-verification]]）；「宪法先行再并行」与 KDO 的 charter 纪律同构（[[bridge-yitang-kdo-gate-philosophy]]）；头尾站位是 AI Native 人的位置的操作化（[[framework-ai-native-working-paradigm]]）。

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:--|:--|:--|
| 复盘发现「效果还行但没到预期」 | 区分执行问题 vs 设计问题 | 30 分钟内给出「优化或推翻」结论+成本估算 |
| 决定推翻重做 | 先拆子任务+依赖，再画防跑偏画布 | 拆解图+画布先于任何 Agent 开工 |
| 要并行多个 Agent | 先产出规范/宪法文件 | 并行 Agent 共享同一份书面标准 |
| 课程/交付结束 | 用外部视角验证效果 | 有一个「让局外人猜成本」式的反差证据 |
