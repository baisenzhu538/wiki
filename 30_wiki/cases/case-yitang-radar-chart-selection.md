## 可迁移场景 / 适用边界

| 场景 | 说明 |
|:-----|:------|
| ✅ **组织内部评选规模大到负责人无法逐个了解** | 如 50+ 讲师、100+ 选题、大量供应商/候选人，个人拍板不可行 |
| ✅ **需要跨部门/多评委共同决策** | 雷达图把隐性标准显性化，减少政治和印象之争 |
| ✅ **同类评选反复发生** | 选题、人才、项目、供应商等高频重复决策，值得沉淀为组织公式 |
| ✅ **决策后果可观察、可复盘** | 只有能事后验证，才能通过"打补丁"持续优化维度 |
| ❌ **只有 1-2 个维度真正重要** | 雷达图是多维工具，维度太少不如直接列表比较 |
| ❌ **关键标准无法观察或量化** | 若只能凭感觉打分，雷达图会制造虚假精确感 |
| ❌ **团队对基本价值观没有共识** | 维度本身会被质疑，先开价值观/目标对齐会 |

## 诊断信号

| 信号 | 镜头 | 跟进问题 |
|:-----|:-----|:---------|
| CEO/负责人被频繁要求"你定一下谁入选"，但他根本不认识大部分候选人 | 决策超载 + 隐性标准 | 召集有判断力的人开模型共建会，先定义 4-6 个评选维度和打分规则，再看任何候选人 |
| 评选会陷入个人印象、关系远近或部门政治争论 | 标准未对象化 | 强制把所有讨论转换为"该候选人在 X 维度得 Y 分"格式，禁止不带维度引用的感性发言 |
| 同类错误重复出现（如选中的选题上线后失败、投放视频跑不动） | 雷达图维度不完备 | 每次失败后 48h 内复盘：如果当时多一个什么维度就能拦住？把该维度加入雷达图并更新版本 |
| 高管说"我直觉这个人不错"并试图直接拍板 | 隐性权威覆盖 | 要求高管把直觉翻译成一个维度/分数，或只能行使否决权，不能直接通过 |
| 不同评委给同一候选人的打分差异极大，或几个维度总是同高同低 | 维度重叠/缺乏校准 | 用 2-3 个样本做校准会，重写维度定义和锚定分数，检查 MECE |

## 失败模式

| 失败模式 | 真实症状 | 可执行修复 |
|:---------|:---------|:-----------|
| **CEO 仍要最终拍板** | 团队把"推荐名单"递给领导求批准，雷达图只是装饰；领导一句"我再想想"推翻所有分数 | 在评选章程里明确区分"否决权"与"通过权"，写成文档并公开；CEO 只能否决，不能指定入选 |
| **维度为特定候选人量身定制** | 不同批次的评选维度不一样；某人的强项恰好对应临时加出来的维度 | 在看见候选人之前锁定维度、权重和锚定分数；增加一轮盲打分 |
| **犯错后不复盘、不更新雷达图** | 同样的问题反复出现，雷达图版本停留在 V1.0 | 建立"失败 → 48h 复盘 → 维度补丁"机制，每次更新标注版本号和补丁原因 |
| **维度重叠或双重计数** | 几个维度同高同低，一个优势被多次计入总分 | 用 MECE 检查每对维度；合并相关维度或拆分独立维度；必要时引入独立维度权重 |
| **只看总分忽视关键否决项** | 平均分高但某一关键维度（如价值观）极低仍被放行 | 设置硬阈值：任一维度低于 6 分直接淘汰；否决维度单独列出 |
| **雷达图沦为形式化 checkbox** | 表格填了，但真正的决定在线下做出 | 要求决策备忘录必须引用雷达图分数；定期抽样审计"最终决策 vs 雷达图结果"的一致性 |
