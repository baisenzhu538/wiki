> 当一个用户同时是消费者和分销者时，最大的风险不是产品不好，而是你把两种角色当成同一种用户在验证。—— 张磊 AMA Q5（`src_20260616_b1e25c49`）

## 案例背景

| 维度 | 内容 |
| --- | --- |
| 项目 | 生活鲜花社区团购 |
| 目标用户 | 社区"主理人妈妈"——在社区有影响力、愿意组织团购或分享生活的妈妈群体 |
| 核心难点 | 用户兼具 C 端消费者与小 B 分销者双重角色，行为逻辑比普通 C 端更复杂 |
| 所处阶段 | 筹备期，偏早期需求验证 |
| 关键命题 | 1) 双重角色如何拆分？ 2) 怎么判断失败是用户问题还是产品/激励问题？ 3) 测到什么程度可以推进？ 4) 低频、非标、审美驱动品类如何分节奏落地？ |

> 来源：张磊 AMA 口述/笔记，外部可验证性有限。

## Constraints & Boundaries

| 边界 | 说明 |
| --- | --- |
| 双重角色必须拆分 | 主理人妈妈的"买花自用"与"组织团购分销"是两种行为，需要分别拆解用户、场景、问题；二者甚至不一定是同一拨人。 |
| 阶段不可跳跃 | 必须先验证"愿不愿意分销"，再验证"能不能持续分销"，最后验证"成本结构是否跑通"；前置假设未通过时，不要进入重资产规模化。 |
| 低频非标品慎用纯定量 | 生活鲜花低频、非刚需、审美驱动，早期样本量有限，需以定性判断为主，逐步升级到定量验证。 |

## Core Insights

### 1. 先判断阶段：这是需求侧验证

张磊指出，项目正在筹备，最头疼的是用户相关的问题，因此属于**需求侧验证**——验证"用户是否真正在这个场景下有问题，且愿意用这种解决方案"，而不是直接进入产品内核或增长渠道的讨论。

### 2. 核心动作：把"双重角色"拆细

项目被描述为"To C 又 To 小 B"，团长本身就是小 B 角色。必须分别拆解：

- **C 端角色**：买花的妈妈——她的用户、场景、问题是什么？为什么需要在这买花？
- **小 B 角色**：做团长的妈妈——她的分销动机、能力、持续意愿是什么？

> "有可能我不爱花，但我想作为一个团长就去做这件事；也可能很多宝妈正是因为要做这件事才喜欢这件事。"（`src_20260616_7dc80216`）

### 3. 分阶段验证：意愿 → 留存 → 成本

| 阶段 | 验证目标 | 关键动作 | 关键指标 |
| --- | --- | --- | --- |
| 第一轮：意愿验证 | 妈妈是否愿意做分销 | 3-5 个种子用户，人工交付 | 分销报名率、初步合作意向 |
| 第二轮：留存验证 | 妈妈是否能持续分销 | 10-20 个主理人妈妈，轻量化运营 | 周/月分销频次、复购率、持续开团率 |
| 第三轮：成本验证 | 商业模式成本结构是否成立 | 规模化测试前 | 获客成本、履约成本、损耗率、利润率 |

> "首先验证用户是不是真的愿意做分销，别最后发现别人根本不愿意帮你分销。愿意也不代表商业模式成立，这时候可以测核心数据：他们是否可以持续留在这里。"（`src_20260616_b1e25c49`）

### 4. 如何区分"用户不行"还是"产品/激励不行"

张磊给出两条判断线索：

- **如果赛道已有竞品且服务很好**：自己的产品没有优势，大概率需求没问题，是产品或方案设计有问题。
- **如果赛道没有竞品**：说明需求可能非常早期，验证难度高，应放到产品内核和单元模型中进一步验证。

> "早期很容易迷糊，到底是用户选择有问题，还是产品本身有问题？直接验证很难，但可以通过竞品存在与否做初步判断。"（`src_20260616_6c8b240b`）

### 5. 低频、非标、审美驱动品类的节奏

生活鲜花不是刚需高频品，测试节奏要更慢、更依赖定性：

- 先验证"审美与品类是否被接受"，再验证"愿不愿意反复买/开团"；
- 不要一上来就追求大样本和统计显著，早期通过小样本深度访谈和行为观察拿到方向感；
- 每一轮只做"当前最可能失败"的那个假设的验证，把大目标拆成可证伪的小里程碑。

## Common Failure Modes

| 模式 | 症状 | 修复 |
| --- | --- | --- |
| 角色混淆 | 把团长热情当成 C 端需求，总订单好看但复购极低 | 强制拆分 C 端自购与小 B 分销两条链路，分别设指标 |
| 过早规模化 | 还没验证意愿就租仓库、做小程序、铺渠道 | 回到第一轮：用 3-5 个种子妈妈人工跑通分销闭环 |
| 把留存问题归因错误 | 团长两周后不开团，只想到加佣金 | 用定性访谈排查素材、社群氛围、损耗、售后等真实阻力 |
| 假精益 | 做了多轮测试但都在验证同一个低风险假设 | 每轮测试前写明：本轮验证的是哪个前置假设？失败是否导致全盘推翻？ |
| 忽视审美风险 | 花品不稳定，团长不敢推荐 | 在留存验证阶段把"花品一致性"作为独立假设测试 |
