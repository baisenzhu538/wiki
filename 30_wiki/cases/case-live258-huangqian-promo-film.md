# 黄谦导演宣传片 AI 创作：L1/L2 基本功扎实但 L3+ 放大器缺失，效率与创意卡在手动迭代

> 一句话：为达瑞电子做宣传片（方案+脚本阶段），把墨氏片场导演身份、三个一工程方法论、客户 PPT 重点页全注入上下文，方案→脚本两阶段拆解+状态机控节奏，产出符合预期但未完全达到“大幅提效+创意突破”的超预期效果（L2915）——复盘定位：L1/L2 对话式 Feature 是基本功且扎实，L3+ 是放大器且缺失，「放大器缺失」限制了效率与创意突破（L3013，源文为“放大器缺失”）。

---

## 过程（起点→尝试→失败→转折→结果）

### 起点：商务洽谈阶段的宣传片方案+脚本

任务：达瑞电子宣传片创作，处在方案与脚本阶段，最终意图明确——“打动客户（商务洽谈阶段）”（L2925）。输出要求细化到脚本格式、表格结构、哲思七句/痛点价值点/三点提炼（三个一工程）等维度，参考文案基调为“平实稳重+灵气”的上市公司风格（L2925，源文为平实稳重+灵气的上市公司基调）。

### 尝试：L1/L2 层 Feature 的深度应用（做对了什么）

复盘自认的亮点集中在对话层（L2919-L2935）：

- **切换模型+上下文最大化**：弃用效果差的“知识问答”AI，改用飞书智能伙伴，注入“三个一工程方法论”“合伙人讨论记录”“客户PPT重点页”等上下文（L2921）
- **抽卡测试+任务拆分**：多次抽卡组合不同版本优点；创作拆为“方案→脚本”两阶段，脚本阶段再拆为“案例故事模块→真实案例收集→文字衔接”，用“状态机”（AI 需确认后再推进）保障节奏（L2923）
- **设定身份+输出规范**：明确“墨氏片场导演”身份与最终意图（L2925）

L3 层有初步落地（L2929-L2935）：

- 把达瑞电子方案创作逻辑封装为 Skill 复用至后续宣传片策划
- 用飞书妙记、智能纪要沉淀会议/沟通非结构化数据为创作素材库
- 每版产出人工评审，通过口喷修正（对比 v1.0 逐处调整）与板块/细节级修改完成人机协作闭环
- 用“Get笔记+飞书归档”沉淀成交链路方法论、故事化结构（五行工具法）等子体系，形成可复用知识地图，“避免素材污染”

### 失败：上层 Feature 缺失，三个瓶颈显性化

问题共识三条（L2939-L2953）：

1. **上层 Feature 应用缺失**：L3 及以上工具（Workflow 精细化、外部工具联动、自主执行）几乎未用；“角色配置/用户画像”仅浅尝，“工作边界指定”偶尔失效（脚本阶段仍有思路阐述冗余）；L4/L5（长期记忆深度、自净化、组织协同）停留在“探索”阶段——上下文压缩未系统化，权限分层/交叉验证未实践
2. **效率与创意的瓶颈**：抽卡测试虽优化内容但耗时久；多人对话加状态机复杂度高，小团队场景下易冗余；创意突破依赖反复迭代，未借上层 Feature（如自主执行、工具协作）实现 AI 主动提案
3. **工具认知滞后**：对“运行环境”“工具协作”等 Feature 概念模糊，未主动学习适配工具，导致有想法但无高效工具落地（L2953）

### 转折：用 Feature 分层框架自评——底层扎实、上层待拓

黄谦没有停留在感觉不够好，而是把整段创作流程映射到 Feature 分层上逐层自检，得出结构化结论：L1/L2 对话式 Feature 是 AI 创作的基本功，L3+ 是放大器——当前基本功扎实支撑了流畅创作，但放大器缺失限制了效率与创意突破（L3013）。

由此导出坚持/放弃清单（L2955-L2977）：

- **坚持**：L1/L2 核心 Feature 深耕（上下文注入+任务拆分+身份/输出规范的对话式创作逻辑）；知识资产体系化（Get 笔记+飞书沉淀三个一工程、五行工具法）；人机协作闭环（人工评审+口喷反馈）
- **放弃**：低效的纯抽卡测试（若出现自动化 A/B 类特征组合工具则逐步替代）；模糊的经验驱动工作流（新业务如创始人 IP 的十大步骤分解，尝试用 Workflow 工具固化而非纯经验梳理）

### 结果：阶段性成果+两条待验证假设

结果状态：基本符合预期、取得阶段性成果，主观感受“越来越爽”——因数据、场景、体系（人类三角）积累较充分，对话式创作体验流畅（L2915）。同时提出两条新假设（L2989-L2991）：

- 上层 Feature（自主执行+工具协作）能减少 30% 人工迭代时间——计划在标准化业务（如成熟宣传片）中验证
- 长期记忆+上下文压缩可提升 AI 输出精准度 40%——通过知识地图+压缩算法实验验证

**⚠️ 两条假设均未验证**（复盘原文为“需在……中验证”的将来时态）。

沉淀的过程资产（L2995-L3009）：

- **三个一工程**：关键冲突+最小故事线+超级符号（用于影片框架提炼）
- **五行工具法**：金（主题）→木（结构）→水（情感）→火（冲突）→土（收尾），适配故事化结构
- **对话式创作 L1-L2 流程**：明确目标→拆解任务→注入上下文→设定身份/输出规范→抽卡迭代→人工评审
- **三段 SOP**：方案阶段（客户 PPT 解析→方法论注入→抽卡组合→方案定稿，V5.0 迭代逻辑）/ 脚本阶段（案例模块拆分→真实案例收集→文字衔接→语气风格校准→定稿）/ 知识管理（飞书妙记记录→非结构化归档→Get 笔记子体系沉淀→知识地图调用）

## Critique

**内部局限（自指）**：三个缺口。

1. 全流程成果只有主观评价（基本符合预期、越来越爽），无客户方反馈、无中标/成交结果——商务洽谈阶段的宣传片方案，最终判官是客户，复盘全文没有客户反应的一手记录
2. 两条量化假设（30%/40%）无基线数据支撑：人工迭代时间原来多久？精准度原来多少？没有基线的百分比假设无法证伪
3. 状态机冗余的自省与状态机保障节奏的自夸同时存在，何种条件下从资产变负担，复盘只给了“小团队场景”一个模糊边界

**外部攻击者 1（同质化陷阱视角——2025 宣传片行业趋势）**：2025 年企业宣传片行业观察指出，当所有企业都用 AI 生成相似风格的宣传片时，独特的品牌故事和视觉语言才是突围关键。黄谦流程里 AI 参与的恰是框架提炼与脚本生成，三个一工程模板经 Skill 封装复用后，会不会反而加速自家作品的模板化？Skill 复用提效与创意稀释是同一条曲线的两端，复盘只看到了提效端。

**外部攻击者 2（Brynjolfsson 式——生产率 J 曲线）**：底层扎实但上层缺失的自评暗含一个未经验证的假设——上层 Feature 是线性叠加的放大器。生产率 J 曲线研究表明，引入更强的自动化/工作流层往往先经历产出下降期（流程重构、学习成本、人机分工重排）。若试点创始人 IP 项目时不带基线测量，很可能把 J 曲线下沉段误读为上层 Feature 无效而退回舒适区——30%/40% 的收益假设可能方向对、时序错。

## Synthesis

本卡是 Live258 族中分层自评最清醒的案例，核心价值有三点：

1. **分层诊断而非清单核对**：多数学员的复盘是缺了什么 Feature，黄谦的复盘是哪一层缺、哪一层扎实——把 Feature 思维用成了分层诊断工具
2. **基本功定下限、放大器定上限**：L1/L2 对话式 Feature 决定下限，L3+（Workflow/工具联动/自主执行）决定上限（L3013）——这是 Feature 分层体系来自创作域的实证注脚
3. **族内坐标**：[[case-live258-tianli-gov-training]]（田力案）是 L2 层全缺（裸 prompt），黄谦案是 L1/L2 满配而 L3+ 缺位——两案合起来画出 Feature 缺失的两个极端位置

与 [[dk-demand-feature-stacking]] 的互链关系：该卡 L167 已引本案为 Feature 叠加有边界的实例（复杂状态机在小团队易冗余），本卡补充完整证据链——状态机在中长周期、多交付节点的创作流程里是资产（保障节奏），在短平快任务里变负担（管理开销超收益），**过程类 Feature 的启用应有规模阈值**。

另注：三个一工程、五行工具法本身是人类创作体系的方法论，与 Feature 无关，但其被注入上下文后成为 AI 输出的质量杠杆——印证了人类三角（审美、创造力、体系）+AI 三角（场景、基本功、数据）协同进化的总结（L3013）。

## Action Triggers

1. AI 创作流程自检时按层盘点：L1/L2（上下文/拆分/身份/规范）→ L3（Skill 封装/评审闭环）→ L4/L5（长期记忆/自净化/协同），哪一层空着瓶颈就在哪一层
2. 给状态机/多人对话类过程 Feature 设启用阈值：任务周期短、交付节点少的小任务退回轻量流程，不把管理开销当严谨
3. 提量化改进假设前先记基线：当前迭代时长/精准度是多少，否则 30%/40% 永远无法验证
4. 方法论资产（自己的行业 know-how）优先注入上下文，比调 prompt 技巧的杠杆大——客户 PPT、讨论记录、方法论框架是最高价值上下文
5. Skill 封装复用时留反模板化检查项：每次复用后对比产出与上次的差异化程度

## 失败模式

| 失败模式 | 症状 | 修复 |
|:--|:--|:--|
| 只修基本功不装放大器 | 流程流畅但效率/创意无数量级变化，感觉越来越爽却未大幅提效（L2915） | 按 Feature 分层盘点，找出第一个值得 Workflow 化的重复环节试点 |
| 小团队照搬重型流程 | 状态机/多人对话跑起来更累，管理开销超收益（L2947） | 设启用阈值（周期/节点数），低于阈值用轻量流程 |
| 无基线的量化假设 | 声称减少 30% 迭代时间但没说从多少减（L2989） | 假设旁边强制记基线值与测量方式，否则标猜测不可引用 |
| 工具认知滞后于想法 | 有想法但无高效工具落地（L2953） | 每月固定盘点一次工具栈新能力，把 Feature 工具库当资产维护 |
| Skill 复用滑向模板化 | 封装复用后作品风格趋同，丢品牌独特性 | 复用后做差异化对比检查；模板只封装结构不封装创意内核 |
