# 案例：数族如何扫描 100+ 渠道并跑通支付合作

## 一句话

数族（素材中口述部分亦称「徐建发票 SaaS」项目）面向中小商户提供支付/发票相关服务，早期通过「100+ 方向扫描 → 9 个候选预判 → 3 个渠道测试通过」的科学四步法，把渠道探索从「靠手感碰运气」变成可复现的决策流程。

> **命名说明**：本卡 source_refs 中图片文件以「数族」命名，口述文本以「徐建发票 SaaS」指代同一组渠道扫描/测试素材；两者是否为同一商业主体或同一案例的不同命名，尚未在素材内获得直接交叉验证 `[conf=0.60, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt + 案例-数族-渠道扫描/测试.png, 待独立核实]`。

## 1. 背景

### 1.1 业务是什么

数族（/徐建发票 SaaS）主营业务是为生活服务类中小商户——尤其是餐厅、外卖商家——提供支付与开票相关的 SaaS 服务 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §826-831]`。

这个业务的典型特征是：

- **客单价低、商户分散**：面向海量小 B，单客户价值有限，必须靠渠道规模化触达；
- **产品价值清晰但认知门槛低**：发票/支付是刚需，但商户和渠道伙伴对「电子发票」的认知普遍不足；
- **强依赖渠道信任**：小 B 决策短但信任成本高，通过已有信任关系触达（如支付公司、收银软件）比自建销售团队更高效。

### 1.2 早期困局

项目最早通过熟人介绍完成冷启动，拿到第一批客户 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §841-843]`。但熟人资源很快用尽，团队面临两个选择：

1. 招人做直销——成本高、规模化慢；
2. 找渠道合作——但「渠道」是什么、有哪些、选谁，完全没有清晰答案。

这正是渠道探索方法论要解决的典型问题：产品价值已经初步验证，但可持续获客渠道尚未建立。

## 3. 关键决策

### 3.1 决策一：不做直销，做渠道

团队首先判断，面对分散的小 B 商户，自建销售团队不是最优解。更有效的方式是找到已经拥有商户信任、已经处于商户工作流中的第三方，把数族的产品嵌入进去 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §855-860]`。

这个决策的隐含假设是：**渠道的价值不仅是触达，更是信任转移**。支付公司、收银软件公司本身就在商户的日常经营中，它们推荐数族服务时，商户的接受成本远低于陌生销售。

### 3.2 决策二：用「懂发票」作为筛选条件 → 推翻

团队最初有一个直觉假设：最好的渠道伙伴应该是「懂发票」的机构，因为懂行才能更好地理解和推销产品 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §866-873]`。

但验证后发现：

- 市场上绝大部分潜在渠道其实不懂发票；
- 发票 SaaS 本身学习成本低，短平快的培训即可上手；
- 「懂发票」不是必要条件，**渠道是否愿意做、能否放量**才是。

这个认知转折是案例的核心：做减法时，要先验证假设，而不是固守直觉。

### 3.3 决策三：把四个筛选条件定为「乘法关系」而非「加法关系」

团队最终提炼出四条渠道筛选原则 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §920-924]`：

1. **有基础 IT 能力**：能接受信息化产品；
2. **对原有工作显著有帮助**：渠道做这件事能强化自己的主业；
3. **对用户有影响力/信任**：商户愿意听渠道的话；
4. **可以放量**：渠道能大规模、标准化复制。

关键判断是：这四个条件不是「符合一条即可」，而是**缺一不可的乘法关系** `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §932-936]`。任何一条缺失，渠道要么跑不通，要么跑不快。

### 3.4 决策四：否决 6 个看似合理的渠道

在 9 个候选渠道中，团队否决了 6 个，包括：酒水供应商、米面供应商、跑腿的骑手、做消防的、代账公司、美团 BD 城市经理 `[conf=0.95, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-案例-数族-渠道测试.png]`。

否决不是因为这些渠道「完全没价值」，而是因为它们在关键条件上存在明显短板：

- **酒水/米面供应商**：对商家没有把控力，只是供应链关系，无法影响商户决策；
- **跑腿的骑手**：利润太低，骑手宁愿休息也不愿多推销；
- **做消防的**：虽然有管控力，但不会演示产品，销售形态不匹配；
- **代账公司**：同意合作的量比较小，无法放量；
- **美团 BD 城市经理**：有量但稳定性差、非标、流动性大，没法成为长期驱动力。

### 3.5 决策五：押注 3 个通过渠道，分优先级推进

最终通过的 3 个渠道 `[conf=0.95, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-案例-数族-渠道测试.png]`：

| 渠道 | 测试结果 | 战略含义 |
|:---|:---|:---|
| 百望金赋 | 可以继续，但速度会放缓 | 有合规/发票基因，但放量节奏受限，适合稳扎稳打 |
| 支付公司 | 很合拍，可以作为支付的推手 | 与主业强相关，信任链最短，是核心突破口 |
| 收银软件公司 | 一旦接通，量很大 | 处于商户经营核心入口，是规模化主渠道 |

## 4. 结果

### 4.1 直接结果

- 渠道探索从「100+ 方向」收敛到「9 候选」再收敛到「3 通过」，形成清晰的渠道投资组合；
- 支付公司与收银软件公司成为可规模化的核心渠道，业务开始起盘 `[conf=0.80, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-口述.txt §949-950]`；
- 团队建立了一套可复现的渠道筛选语言（四条原则），后续新增渠道时不必从零摸索。

### 4.2 长期影响

这个案例成为一堂「渠道探索四步法」中「扫描 → 预判 → 测试」的典型 To B 样本。它证明：

- To B 早期获客不必自建庞大销售团队；
- 渠道筛选的核心是「乘法条件」而非「单点优势」；
- 懂得在什么时候否决一个渠道，和懂得选择渠道同样重要。

## 5. 业务公式 / 要素映射

### 5.1 渠道漏斗公式

```
可持续获客渠道数 = 扫描方向数 × 预判通过率 × 测试通过率 × 工业化复制系数
```

代入本案例的近似数字：

```
3 个有效渠道 ≈ 100+ 扫描方向 × ~9% 预判收敛率 × ~33% 测试通过率 × 1.0 初期复制系数
```

> 这些比例仅供理解漏斗结构，100+ 为口述估算，9 候选和 3 通过来自图片素材 `[conf=0.78, source=口述估算 + 图片素材]`。

### 5.2 单渠道单元经济映射

每个通过渠道都应独立核算单元经济（参见 `[[framework-yitang-channel-unit-economics]]`）：

```
单渠道单元利润 = 渠道流量 × 转化率 × 客单价 × 复购率 − 渠道获客成本
```

对数族而言：

- **渠道流量**：支付公司 / 收银软件公司覆盖的商户数；
- **转化率**：渠道推荐后商户开通服务的比例；
- **客单价**：支付/发票服务的年费或交易抽成；
- **复购率**：商户持续使用、持续产生交易的比例；
- **渠道获客成本**：渠道分润、培训、对接、运营支持成本。

### 5.3 渠道筛选四原则与五维特性映射

| 四原则 | 对应渠道特性维度 | 解释 |
|:---|:---|:---|
| 有基础 IT 能力 | 成本 / 技能要求 | 降低渠道接入与培训成本 |
| 对原工作显著有帮助 | 产品匹配度 | 渠道推广动机强，不是顺带做 |
| 对用户有影响力/信任 | 集中度 / 持续性 | 商户信任度高，转化阻力小 |
| 可以放量 | 大小 / 快慢 | 覆盖商户规模大、起量快 |

这说明：数族的四原则本质上是对「渠道特性五维度」的 To B 小 B 场景化翻译。

## 6. 成功原因

### 6.1 扫描足够宽

团队没有停留在「直销 or 代理」的二选一，而是把视野打开到 100+ 方向 `[数字来自 Truman 口述，待独立核实]`。这避免了「手里没牌」的困境，也让后续的减法有真正的选择空间。

### 6.2 预判有模型

团队没有靠老板手感排序，而是明确提出四条筛选原则，并验证这些原则是「乘法关系」。这让决策从「我觉得这个行」变成「这个渠道是否符合全部条件」。

### 6.3 测试成本可控

团队用「聊、试、跑小单」的方式快速验证，而不是一上来就签大合作、搭大团队。例如发现米面供应商、骑手、消防等渠道不行，是通过小范围测试和访谈快速排除 `[conf=0.95, source=00_inbox/一堂五步法之增长/truman-渠道探索方法论-案例-数族-渠道测试.png]`。

### 6.4 敢于推翻初始假设

「懂发票才是好渠道」这个直觉被验证推翻，是案例中最有价值的认知跃迁。团队没有因为初始假设而错过更优渠道。

### 6.5 选择信任的杠杆点

最终通过的支付公司和收银软件公司，共同特征是：它们已经在商户的日常经营中占据信任位置。数族没有从零建立信任，而是**借用了渠道已有的信任资产**。

## 可迁移场景

本案例对类似 To B 小 B / fintech / SaaS 项目的迁移价值：

1. **先列 100 个方向，再愁怎么选**：扫描阶段不怕多，怕的是少；
2. **每个候选渠道用「四条原则」过一遍**：IT 能力、对原工作帮助、用户影响力、可放量；
3. **把筛选条件当乘法，不当加法**：有一条硬伤就否决；
4. **测试阶段先看「能不能跑通小闭环」**：不要直接签全国总代；
5. **优先选已在商户工作流中的渠道**：支付、收银、ERP、代账等天然入口；
6. **建立渠道漏斗仪表盘**：扫描数、候选数、测试数、通过数、放量数。

## 失败模式

若跳过本案例中的关键动作，容易陷入以下失败模式（参见 `[[dk-yitang-channel-exploration-traps]]`）：

| 失败模式 | 在本案例中的表现 | 数族如何规避 |
|:---|:---|:---|
| 依赖手感碰运气 | 老板凭经验选一个渠道all in | 用四条原则系统筛选 |
| 跳过扫描预判直接测试 | 只想到直销/代理两个选项 | 列出 100+ 方向 |
| 混淆「事不行」和「人不行」 | 因为某个渠道没跑通就否定整个方向 | 区分是渠道条件不满足还是执行问题 |
| 忽视渠道生命周期 | 把通过渠道当成终身饭票 | 同时布局 3 个不同类型渠道 |
| 单渠道依赖 | 只押注支付公司 | 百望金赋 + 支付公司 + 收银软件公司组合 |

## 教训

- **本案例适用于产品价值已初步验证的阶段**：如果产品本身没人要，再好的渠道也救不了；
- **100+ 方向为口述估算**：实际执行中不必机械追求数量，但要保证视野足够宽；
- **四条原则需按业务场景调整**：不同行业的「乘法条件」会不同，不能直接照搬；
- **本案例未涉及渠道工业化生产**：通过测试后，仍需进入「建模 → 工业化」阶段（参见 `[[framework-yitang-channel-industrialization]]`）。
