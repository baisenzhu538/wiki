## 关键证据

### 背景

KDO Agent 体系运行数月后，王语嫣在周报中识别到一个系统性问题：Agent 是优秀的执行者，但没有一套方法论让 Agent **自己变强**。改进全链路依赖人类推动（王语嫣诊断→黄药师建工具→欧阳锋审查→老顽童执行）。这直接违反了 Truman 闪电模型的核心洞察——「高手不是不踩坑，而是把坑压缩成最小可复用组件，然后用组件拼装新工作流。」

### 触发事件

2026-07-26，王语嫣在诊断「解放思想探索营」素材（#201）时，同步发现了 Agent 体系的进化需求。她将 Truman 的闪电模型（大胆设想→底层自洽→假设试错→建模重构）映射到 Agent 体系，产出了两个并行任务：
- #200（本任务）：Agent 体系自身的能力升级——让 Agent 从执行者变成进化者
- #201：解放思想方法论的知识卡片化

### 现有知识如何连接

本案例是 KDO 方法论的 **Agent 层自指应用**：

- `framework-kdo-modeling-methodology` 的四步法在 #200 中的应用：
  - Step 1「圈定范围」→ 王语嫣诊断报告 §边界：不覆盖具体 context 重写、不覆盖 CLI/基础设施改动
  - Step 2「探索关系」→ 识别 Agent 进化四阶与闪电模型四阶的同构
  - Step 3「压缩模型」→ 5 条 Agent 设计原则（从 41 条 pitfalls 压缩）
  - Step 4「解压展开」→ 7 张卡 = 5 条原则的解压资产

- `bridge-lightning-agent-evolution` 的四阶映射在本案例中的验证：
  - 一阶·大胆设想 → ✅ 王语嫣提出「Agent 应该能自己进化」（人类侧的大胆设想），但 Agent 侧的一阶尚未启动
  - 二阶·底层自洽 → ✅ 5 条设计原则从双三角/TCPR/实事求是推导
  - 三阶·假设试错 → ✅ #200 本身是一次试点——如果 7 张卡被欧阳锋采纳并实际改善 Agent 行为，则验证通过
  - 四阶·建模重构 → ⏳ 待定——等 Agent 实际运行复盘四问后，首次自主沉淀的组件入库

## 可迁移场景

1. **未来任何 Agent 体系的自我升级**：按照「诊断→编排→生产→审查→部署」的五段流程，适用于任何 Agent 工厂的自我进化需求
2. **方法论在 Agent 层的自指应用**：KDO 方法论不仅可以用来生产知识卡片，也可以用来升级方法论的生产者本身——这是「自指」的验证
3. **从 pits 到 principles 的压缩模式**：任何有大量操作经验的 Agent 体系都可以用这套流程——收集 pitfalls → 提取元模式 → 压缩为原则 → 解压为工具
4. **新域方法论与 Agent 化的同步推进**：#200（Agent 进化）和 #201（解放思想卡片化）并行——展示了「方法论的消费 + 方法论的升级」可以同时发生

## 教训

### ✅ 做得好的

1. **王语嫣在诊断中同步识别了方法论和 Agent 两个层面的需求**——不把「Agent 进化」当作独立项目，而是作为方法论消费的自然延伸。
2. **先框架后细节的执行顺序完美**：三层架构（体系构建→复盘进化→任务执行）→ 卡片优先级（P0→P1）→ 卡片内部结构（先 Claims 后 Critique）——全程遵循原则④。
3. **国际标准对标及时**：生产前 WebSearch 确认 KDO 四层觉察不与 Microsoft/Dextralabs 成熟度模型冲突——避免了「命名冲突」的历史陷阱（P-28）。

### ⚠️ 可改进的

1. **Agent 侧的一阶尚未启动**：王语嫣（人类）完成了「大胆设想」——但老顽童（Agent）在执行 #200 时，仍然是在照 spec 生产，没有自主质疑或 reject spec 中的任何一点。Agent 的「当知当觉」（L2）尚未真正到来。
2. **本案例的回填是事后行为**：case-agent-self-evolution-pilot 是在 #200 生产完成后才写的——复盘四问可以在生产过程中实时执行，而非等 7 张卡全部写完后。
3. **验证闭环未闭合**：#200 的卡片质量、Agent 的实际行为改善、欧阳锋审查结果——全部是待定状态。本案例的「结论」部分需在欧阳锋审查后补充。

## Critique

### 内部局限

1. **本案例是「自我指涉」的——既展示了 Agent 自我进化的方法，本身又是 Agent 的产出**。这可能导致循环偏差：案例说「Agent 可以进化了」，但这个声明本身就来自 Agent，未经独立验证。
2. **案例的「结论」全部待定**——等欧阳锋审查 #200 后，才能真正判断「Agent 进化试点」成功了还是失败了。

### 外部攻击者

**Thomas Kuhn（科学革命）**：Kuhn 的范式理论指出，真正的进步不是在既有范式内修修补补，而是范式革命。Agent 自我进化的四层模型暗示「从 L1 到 L3 的线性进步」，但真正的瓶颈可能不是层级跃迁，而是 Agent 是否需要一套全新的范式（如「Agent 不应该只执行任务——Agent 应该有自己的目标」）。#200 可能只修了范式内的边角，而不是范式本身。

## L5 隐性成本

任何 Agent 进化体系都有隐性成本——这些成本不在任务单中，但在实际运行中会逐条浮现：

### 成本一：context 膨胀

| 项目 | 估算 |
|:--|:--|
| 新增 context 规则 | 每条复盘产 1-3 条规则 → Agent 启动 token 月增 ~15% |
| 推导链标注 | 每条规则多 1 行标注 → 不显著 |
| 全 Agent 同步 | 5 条原则 + 7 张工具卡 → 每个 Agent 启动多读 ~2000 行 |

> **如果每月 token 增长 >20% 且推导链覆盖率 <50%** → 说明进化变成了补丁堆叠而非压缩。必须用 `tool-agent-context-derivation-audit` 季度修剪。

### 成本二：复盘时间

| 任务复杂度 | 复盘耗时 | 占总任务时间比例 |
|:--|:--|:--|
| 简单（≤3 工具调用） | 0（跳过） | 0% |
| 中等（3-5 工具调用） | 5-10 分钟 | ~15% |
| 复杂（5+ 工具调用 + 错误恢复） | 15-30 分钟 | ~20% |
| 审查类（欧阳锋审查） | 30-60 分钟 | ~30% |

> **Net ROI 临界点**：当复盘产出的规则在 30 天内至少阻止 1 次同类型错误 → 复盘时间为正收益。如果连续 5 次复盘 0 新增规则 → 复盘 trigger 太激进，需要调高复杂度门槛。

### 成本三：原则修订的连锁更新

原则修订（如新增第 6 条原则或修改现有原则的推导链）→ 所有 Agent 的 context 必须重新审计 → 所有历史复盘的推导链标注可能过期。

> **预防**：原则修订后，`tool-agent-context-derivation-audit` 自动触发全 Agent 审计。原则修订频率建议 ≤ 1 次/季度。

### 成本四：Agent 自主性的安全边界

Agent 从「被动执行」升级为「主动 reject」→ 可能 new failure mode：Agent 过度 reject（把合理的 spec 也当作不自洽拒绝）→ 生产任务被阻塞。

> **预防**：Agent reject 必须有「分析报告 + 建议的替代方案」——不能只 say no，必须 say no + why + what instead。reject 率警戒线 >20%（每 5 个任务有 1 个被拒绝→说明 spec 质量或 Agent 判断有问题）。

### 成本五：方法论资产的维护

#200 产出 7 张新卡 → 这 7 张卡本身产生了新的维护负担：
- 每次 KDO 基础设施变更 → 需检查是否影响这 7 张卡的 Claims
- 每次 Agent 体系有新经验 → 需更新相关卡片的 Critique/Failure Modes
- 季度审计 → 需追加这 7 张卡的 currency 检查

> **维护成本估算**：域 ≥ 7 张卡时，每季度的维护时间 ≈ 卡片数 × 0.5 小时。system 域当前 7 张 ≈ 3.5 小时/季度。

## 事故预演（Pre-Mortem）

> 假设 6 个月后，#200 试点被判定为「失败」——最可能的原因是什么？

| 失败场景 | 发生概率 | 早期信号 | 预防措施 |
|:--|:--|:--|:--|
| **复盘四问变成形式主义** | 高（60%） | 复盘记录中「下次注意」占比 >30% | 第一问硬约束：必须「当 X→做 Y」格式 |
| **5 条原则被忽略** | 中（40%） | context 行数增长但推导链覆盖率 <30% | 季度强制审计 + 覆盖率写入 Agent 启动报告 |
| **欧阳锋不接受 Agent 自查** | 中（35%） | 审查退回理由仍是「格式问题」（lint 可捕获的） | Agent 自查→pre-submit 报告→人审只审实质问题 |
| **Agent 仍然被动执行** | 中（35%） | 30 天内 Agent 提议 = 0 | 在 pre-submit 规则中加入「自动检查 spec 自洽性」 |
| **方法论卡本身过时** | 低（20%） | 6 个月后 7 张卡无任何 Agent 引用 | 季度 currency 检查 |

## 下一步
