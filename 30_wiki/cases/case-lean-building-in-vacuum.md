# 闭门造车案例集

## 核心洞察

**闭门造车的本质，是在与真实用户建立持续反馈回路之前，就把不可回收成本投入了完整产品、系统或品牌；它几乎总是同时触发需求找错、方案做错和过早细化三类浪费。** 破解方法不是"调研更充分"，而是先用 FALSE 模型左侧的 F/A/L 手段让用户为假设投票。

## 一句话摘要

一堂课程用 O2O SaaS、培训课程、IP 玩具、老年相亲平台、智能送水系统、加热八宝粥等六个案例，展示团队因长期脱离市场、埋头开发而导致的典型失败。

## 可迁移场景

以下情况最容易重蹈"闭门造车"覆辙，应优先使用 FALSE 模型左侧工具验证：

1. **技术/产品背景强的团队**：擅长做产品，但缺乏一线销售或用户运营经验，容易"先做再说"。
2. **创始人对目标用户不是用户本人**：老年产品、B2B 工具、垂直行业 SaaS 等场景，创始人假设与用户真实行为差距大。
3. **害怕被抄袭而拒绝早期测试**：食品、消费品、玩具等赛道常见，但保密期过长会导致错过窗口。
4. **涉及重研发或供应链投入**：智能硬件、定制系统、自有品牌等，一旦方向错误，沉没成本极高。
5. **内部决策靠"共识"而非"证据"**：团队会议多、用户访谈少，产品路线图由内部判断驱动。

## 教训与预警信号

1. **预警信号：团队内部会议远多于用户访谈。**
   如果你发现过去两周讨论产品细节的会议超过 3 次，而与真实潜在用户的对话为 0，项目已处于闭门造车状态。

2. **预警信号：第一版就要"完整、精美、可规模化"。**
   无论是 12 人做 SaaS、两年做品牌，还是 150 万做系统，本质都是把"解决方案的完备性"置于"需求存在性"之前。

3. **核心教训：先让用户为最高风险假设投票，再投入不可回收成本。**
   对应 FALSE 模型，应在 F/A 阶段用假页面、假产品、人工服务、预售等方式验证"需求是否存在"，跑通后再进入 L/S/E。

4. **核心教训："怕抄袭"不是不验证的理由。**
   加热八宝粥案例显示，过度保密导致方向错误时损失更大；idea 本身不构成壁垒，执行与验证速度才是。
