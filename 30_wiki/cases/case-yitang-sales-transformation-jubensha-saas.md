# 案例：剧本杀 SaaS 销售体系从零搭建——兼职团队跑通科学销售五步法

> 核心结论：一家为剧本杀门店提供全息影像 SaaS 系统的早期创业公司，在只有 1 名专职销售 + 多名兼职销售、年目标约 200 万元的资源约束下，通过「用户分层 → 卖点提炼 → 过程拆解 → 目标到人 → 激励 + 工具」五步改造，把原本「扫街无重点、卖点各说各话、凭感觉推进」的粗放销售，变成可跟踪、可复盘、可沉淀的基础打法。本案例说明：To B 初创 SaaS 即便没有专职销售铁军，也可以用兼职团队把科学销售方法论打磨出来，为后续规模化复制奠定基础。

---

## Background

- **业务**：为线下剧本杀门店提供全息影像 SaaS 系统，包括投影仪、电子剧本、灯光程序、DM 流程控制、玩家互动大屏、商家后台等一体化方案。
- **阶段**：创业公司早期，产品刚起步，现金流紧张，老板为研发出身。
- **团队**：全公司只有 1 名专职销售，其余销售由其他部门同事兼职担任；没有销售总监，没有专职销售运营。
- **目标**：公司当年营收目标约 200 万元，但目标没有拆到个人，也没有配套的过程管理和销售工具。
- **获客方式**：早期靠「扫街」——全员拿着地图清单，挨家挨户拜访剧本杀门店，缺乏重点和统一话术。

> 注：案例中的品牌名、城市、具体门店数量已脱敏，关键数字来自课程口述，应作为项目经验值参考，不宜直接当作普适 KPI 或业绩承诺。[conf=0.82, source=李蕊口述]

---

## Problem

| 问题 | 表现 | 后果 |
|:---|:---|:---|
| **无用户分层** | 全员扫街，不分新店/老店、大店/小店，拿到清单就出门 | 销售精力分散，大量时间花在非目标客户上 |
| **无统一卖点** | 有人讲「沉浸式剧本」，有人讲「定制解决方案」，甚至有人说「帮忙装修房间」 | 客户听不懂核心价值，每个销售讲法都不一样 |
| **无过程拆解** | 推进全凭感觉，客户热情就判断「一定能成」，卡在装修计划上两个月没推进 | 过程黑盒，丢单原因定位不了 |
| **无目标拆解** | 年目标约 200 万没有拆到人、拆到月、拆到动作 | 员工不知道自己和目标的关系，干到哪儿算哪儿 |
| **无激励机制** | 兼职销售做多做少差别不大，没有提成、PK 或荣誉激励 | 积极性迅速消退，拿不到结果就沮丧 |
| **无销售工具** | 没有统一话术、案例、产品介绍视频，销售靠口头随机发挥 | 新人成长慢，成功经验无法沉淀 |

改造前，团队虽然「动起来」了，但大家很快失去信心：兼职销售不是专业销售，约不到关键联系人、搞不定客户，公司目标无从谈起。

---

## Decision

在引入 [[framework-yitang-scientific-sales-five-step|科学销售五步法]] 后，团队决定不在早期追求「招牛人」，而是把现有兼职团队当作方法论的打磨场，从五个方面同步改造：

1. **用户分层**：把有限精力集中到最容易成交的两类客户；
2. **卖点提炼**：把技术功能语言转成客户能听懂的价值语言；
3. **过程拆解**：把销售路径拆成 8 个环节，识别关键决策点；
4. **业绩管理**：把年目标拆到月、客单价、日动作；
5. **激励 + 工具**：用分组 PK、红包、提成激发动力，用话术和产品视频沉淀能力。

---

## Process

### 1. 用户分层：从「全员扫街」到「两类重点客户」

团队利用美团、大众点评、地图等公开数据，先筛选目标客户，再按成交概率和投入成本分为两类：

| 客户类型 | 特征 | 分层逻辑 |
|:---|:---|:---|
| **即将开业的剧本杀店** | 正在装修、筹备开业，有明确采购窗口 | 决策链短、需求刚性强、对软硬件一体化方案接受度高 |
| **计划翻新的老店** | 已有店面，计划升级房间或替换设备 | 需等待装修计划落地，周期长但客单价不低 |

> 对应方法：[[tool-yitang-customer-segmentation-4step|用户分层四步法]]

分层后，团队把约 80% 的精力投入这两类客户，不再平均分配时间。

### 2. 卖点提炼：从「沉浸式剧本」到「省成本、降依赖、提服务」

老板原为研发出身，最初卖点是一堆功能：电子剧本、灯光程序、DM 控制等。改造后把功能语言转译成客户价值语言，统一为三大核心卖点：

- **省成本**：减少对高价 DM 的依赖，降低人力成本；
- **降依赖**：降低对资深 DM 的门槛要求，新手也能快速上手；
- **提服务**：通过情景化投影、视频辅助读本等提升玩家体验。

针对不同客户类型，又细化话术：新店侧重「开业即差异化、降低运营门槛」；老店侧重「翻新升级、提升翻台和口碑」。

> 对应方法：[[tool-yitang-value-proposition-4step|卖点提炼四步法]]

### 3. 过程拆解：从「凭感觉推进」到「8 阶段 + 关键里程碑」

团队把销售路径拆成 8 个阶段，并为关键阶段设置里程碑，让过程可见：

| 阶段 | 关键动作 | 里程碑 |
|:---|:---|:---|
| 1. 添加微信 | 获取客户联系方式 | — |
| 2. 联系决策人 | 必须约见关键决策人 | 已约见决策人 |
| 3. 提供解决方案 | 按新店/老店场景讲解价值 | — |
| 4. 探店体验 | 带客户到样板店实地体验 | 已探店 |
| 5. 门店勘测 | 确认安装环境和施工条件 | — |
| 6. 合同签署 | 推动定金收取 | 已交定金 |
| 7. 付全款 | 完成尾款支付 | 已付全款 |
| 8. 安装上线 | 硬件安装 + 首次业务开局 | 已安装、已开局 |

其中，「约见决策人」和「客户探店」被识别为两个高成本决策点：产品必须演示、客户必须亲眼看到效果，否则很难推进到付款阶段。

> 对应方法：[[tool-yitang-sales-process-decomposition|销售过程拆解三步法]]

### 4. 业绩管理：从「公司目标 200 万」到「每天加 16 个微信」

团队把年度目标按逻辑拆细，让每个人知道自己的动作标准：

| 拆解维度 | 目标示例 |
|:---|:---|
| 月度成单 | 每月不少于约 5 单 |
| 客单价 | 每单不低于约 4 万元 |
| 月度微信新增 | 不少于约 360 家 |
| 月度联系客户 | 不少于约 1000 家 |
| 日动作 | 每天添加微信约 16 家，联系客户约 45 家 |

每天日会、每周周会过每个客户的具体进度，重点看「目标与完成的 Gap」，有困难大家一起想办法。

> 对应方法：[[tool-yitang-sales-performance-management|业绩管理三步法]]

### 5. 激励 + 工具：分组 PK、红包、提成、话术、产品视频

- **激励机制**：把团队分成 3 个组做 PK，月度线索最多的组给红包；签单后按相应比例提成；日会周会中及时口头认可和分享成功案例。
- **销售工具**：
  - 统一新店/老店话术清单，日会中复盘并更新；
  - 制作约 3 分钟产品演示视频，让客户快速直观感受全息场景；
  - 建立客户阶段登记表，把原来散落在微信和口头上的信息沉淀到表格。

> 对应方法：[[framework-yitang-sales-incentive-6d|六维激励模型]]、[[tool-yitang-sales-toolkit-radar|销售武器库六维雷达图]]

## Result

| 维度 | 改造前 | 改造后 |
|:---|:---|:---|
| 客户聚焦 | 全员扫街，无重点 | 约 80% 精力聚焦「即将开业 + 翻新老店」两类客户 |
| 卖点表达 | 五花八门，功能罗列 | 统一为「省成本、降依赖、提服务」三大价值主张 |
| 销售过程 | 凭感觉推进，信息碎片化 | 8 阶段 + 里程碑，客户卡在哪个节点一目了然 |
| 目标拆解 | 年目标 200 万与每个人无关 | 拆到月、单、客单价、日动作 |
| 数据沉淀 | 口头和微信碎片信息 | 客户阶段登记表、周会记录逐步沉淀 |
| 团队状态 | 做一阵就沮丧 | 形成基本打法，为后续全职销售团队奠定基础 |

> 注：本案例未公开对照组、样本量和完整财务数据，结果描述来自课程口述的项目观察，应理解为「体系化初见成效」而非精确业绩承诺。[conf=0.82, source=李蕊口述]

## 可迁移场景

1. **To B 早期 SaaS / 软件公司**：产品需要演示或交付，销售团队小、资源紧。
2. **一人公司 / OPC**：创始人兼任销售，需要把跟单节奏和话术模板化。
3. **兼职销售团队**：用非全职人员验证销售流程，再过渡到专职团队。
4. **新渠道/新产品从 0 到 1**：需要快速建立最小可复用销售打法。
5. **技术服务型初创公司**：成交依赖客户体验和信任建立，过程必须可视化。

---

## 教训

1. **60 分起点即可启动**。早期团队不需要完善的 CRM 和专职销售铁军，先用表格 + 日会 + 统一话术把基本打法跑起来。
2. **兼职团队也能打磨方法论**。把兼职销售当作验证流程的练兵场，迫使自己把动作标准化、把经验显性化。
3. **用户分层是源头**。To B 初创 SaaS 资源有限，必须先回答「哪些客户最值得打」，再谈卖点和过程。
4. **关键节点必须「见面/体验」**。对于需要演示和信任建立的产品，「约见决策人」和「客户探店」是不能跳过的里程碑。
5. **目标要拆到具体动作**。年目标拆到月、拆到客单价、拆到每天加多少微信，才能让非专业销售知道自己该做什么。
6. **工具要和场景一起迭代**。话术不是一次性写好，而是在日会周会中根据实战反馈持续更新。

## 失败模式

| 失败模式 | 表现 | 避免方式 |
|:---|:---|:---|
| **扫街无重点** | 拿到清单就出门，拜访大量非目标客户 | 先用公开数据做初步筛选，再按「即将开业 / 翻新老店」分层 |
| **卖点各说各话** | 每个人对产品的描述都不一样，客户接收不到统一价值 | 强制使用「省成本、降依赖、提服务」三大卖点，日会复盘纠偏 |
| **凭感觉推进** | 客户热情就判断「快成交」，卡在装修计划上两个月不动 | 用 8 阶段里程碑判断真实进度，识别关键动作是否完成 |
| **不好意思分目标** | 老板把年目标挂在墙上，不敢拆到个人 | 把目标按逻辑拆到月、日、动作，明确每个人扛什么 |
| **只给目标不给激励** | 兼职销售做多做少没差别，动力快速衰减 | 分组 PK、线索红包、签单提成、口头认可组合使用 |
| **工具一成不变** | 话术写一次就束之高阁，新人拿不到最新经验 | 把话术更新纳入日会周会机制，让工具随实战迭代 |
| **忽视交付闭环** | 只盯签合同，不盯安装上线和客户使用 | 把「已安装、已开局」作为最终里程碑，履约决策同样重要 |

## When NOT to Use

1. **产品价值尚未验证**：如果客户试用后反馈差、复购率低，应先回到产品内核验证，而不是建销售体系。
2. **完全没有客户接触渠道**：如果连 1 个可触达的剧本杀门店线索都没有，应优先解决获客渠道问题，而非拆分销售过程。
3. **创始人不愿介入销售**：早期 To B 销售需要创始人亲自理解客户决策链，若完全交给兼职团队放羊，方法论很难落地。
4. **合规边界模糊时**：提成、红包、兼职销售劳动关系等涉及劳动合同、税务、提成合规问题，需在专业机构指导下设计。

## Critique

### 外部反对者

1. **SaaS 增长专家视角**：「早期 SaaS 公司最该验证的是产品价值和市场匹配度，而不是先把销售过程拆成 8 个阶段。如果产品本身不是客户真正需要的，再细的过程拆解也只是加速死亡。」
2. **销售组织顾问视角**：「兼职销售不是专业销售，用他们打磨方法论存在幸存者偏差。真正能跑通的打法，可能只在特定客户类型和创始人强介入下有效，复制到全职团队时不一定成立。」
3. **投资人视角**：「年目标约 200 万、每月约 5 单、客单价约 4 万的拆解看起来逻辑自洽，但早期市场变量大，这种刚性动作指标可能让团队为了完成数量而牺牲客户质量。」

### 内部局限

1. **数据口径未公开**：案例来自课程口述，未披露具体样本量、成交周期、实际完成率等数据，无法做严格因果归因。
2. **缺乏对照组**：改造后的效果可能同时受创始人重视程度、市场环境、产品迭代等因素影响，不能单独归功于科学销售五步法。
3. **激励与合规风险**：分组 PK、红包、提成等设计若涉及兼职人员报酬、劳动关系和税务处理，需由法律、财税及人力资源专业机构复核。

> ⚠️ 法律/合规提示：本案例中的提成、红包、分组 PK 等机制仅作管理思路参考，具体实施涉及劳动合同、薪酬结构、税务申报、客户隐私等法律问题，最终方案需由相关专业机构复核。

## Action Triggers

- 如果你只有 1 个专职销售 + 一群兼职销售，却想建立可复制的销售打法 → 先不要招人，先用现有团队跑通「分层 → 卖点 → 过程 → 目标 → 激励」五步闭环。
- 如果你发现销售各说各话、客户听不懂产品价值 → 强制统一为不超过 3 条价值主张，并在每次日会中抽查话术使用情况。
- 如果你客户推进总是卡在「客户说很忙」「等装修」 → 把销售路径拆成 8 个阶段，明确每个阶段的里程碑和下一步动作。
- 如果你年目标拆不下去 → 从「需要多少单、多少客单价」反推「每月需要多少微信、每天需要联系多少客户」。
- 如果你激励只有提成 → 在资源有限时先用分组 PK、红包、口头认可等低成本激励建立动能，再逐步完善提成制度。

## Synthesis

- 与 [[framework-yitang-scientific-sales-five-step|科学销售五步法]] 的关系：本案例是五步法在 To B 早期 SaaS 场景的典型落地，完整覆盖了提炼卖点、拆解过程、推进业绩、激励团队、打造工具五个模块。
- 与 [[tool-yitang-customer-segmentation-4step|用户分层四步法]] 的关系：把客户从「所有剧本杀门店」聚焦到「即将开业 + 翻新老店」，体现了「确定目标 → 提出假设 → 验证假设 → 全面执行」的分层逻辑。
- 与 [[tool-yitang-value-proposition-4step|卖点提炼四步法]] 的关系：把研发语言「电子剧本、灯光程序」转译成客户语言「省成本、降依赖、提服务」，是功能语言价值化的实例。
- 与 [[tool-yitang-sales-process-decomposition|销售过程拆解三步法]] 的关系：8 个销售阶段和「已约见决策人」「已探店」「已交定金」等里程碑，是过程拆解在销售实战中的具体化。
- 与 [[tool-yitang-sales-performance-management|业绩管理三步法]] 的关系：从年目标约 200 万拆到月、单、客单价、日动作，体现了「拆目标 → 定策略 → 追过程」的落地。
- 与 [[framework-yitang-sales-incentive-6d|六维激励模型]] 的关系：早期资源有限时，先用目标渴望、同事竞争、打仗感情等非物质激励起步，再辅以红包和提成。
- 与 [[tool-yitang-sales-toolkit-radar|销售武器库六维雷达图]] 的关系：话术清单和产品演示视频是 60 分基础工具建设的起点。
- 与 [[framework-lean-pivot-decision|精益转型决策]] 的关系：在资源约束下，用兼职团队低成本验证销售模式，是精益原则在销售体系建设中的应用。
- 与 [[opc-ai-sales-agent-architecture|OPC 智能体架构]] 的关系：剧本杀案例中沉淀的客户分层、阶段判断、话术生成逻辑，可映射为 OPC 销售智能体的 system prompt 输入。
