# 直播复盘提示词五轮迭代：Feature链从4个到25+个

> 一句话：jeffgirl 用两个月把直播复盘提示词从 V1.0 迭代到 V5.0——每次迭代都是"发现一个缺失 Feature→补上→效果提升→发现下一个"的连续过程；V4 起 Feature 组合从"并列堆叠"升级为"链式管道"（上一步输出=下一步输入），V5 终于能识别"看播 87% 非粉丝 vs 成交 60% 粉丝"的系统性错配（实测 L1839/L2025-L2029/L2069）。

---

## 过程（起点→尝试→转折→结果）

### 起点：手工复盘经验写成提示词框架

jeffgirl 做抖音本地生活直播复盘，过去两个月（6-7 月）把手工复盘经验写成提示词框架，完成 1.0→5.0 五轮迭代（L1837-L1841）。"每一次迭代都不是'随便改改'，而是发现了一个缺失的Feature→补上它→效果提升→发现下一个缺失的连续过程"（L1839）。

### 尝试：五轮迭代，每轮补一个 Feature 缺口

**V1.0（6/18，~4 Feature）**：角色（"你是抖音本地生活直播复盘专家"）+任务要求+背景信息+输出格式（L1845-L1853）。能生成报告但只是"单次分析"，无法跨场对比（L1919）。缺：多轮对话/分层标注/负面限制/思维链——为什么没意识到？"以为复盘是一次性分析""没想过要告诉AI'不要做什么'"（L1889-L1917）。

**V2.0（6/21，~6 Feature）**：补"多轮对话+上下文延续"和"分层标注（本场 vs 上期数据）"——第一次实现跨场对比："上期建议你调整封面，你执行了，GMV提升了12%"（L1949）。但新问题：AI 能分析"做没做"，不能判断"做得对不对"。

**V3.0（6/27，~9 Feature）**：补"战略分层（拉新vs复购二选一）""前置目标锚定""负面限制"。**触发事件 6/27 直播失败**（实测）：同时做三件事——低价福利封面引流（拉新）+ 保留高客单货盘（复购）+ 增加预热视频，"结果曝光增加但GPM下降"，而 AI 复盘完全没发现"两个目标相反"的问题——因为它没有"目标一致性校验"这个 Feature（L1987）。这次失败催生了目标对齐能力。

**V4.0（6/29，~15 Feature）**：补"策略对齐度检查""跨维度一致性诊断""六层漏斗（曝光→进入→商品曝光→点击→提单→成交）""货盘分层（引流/锚点/利润/主推）"（L1991-L2023）。**组合方式质变**：不再是并列堆叠，而是 Feature 链——"目标锚定（第2步）→策略对齐检查（第3步）→六层漏斗（第4步）→货盘分层（第5步）→跨维度一致性（第6步）"——"上一个Feature的输出成为下一个Feature的输入。AI不是'一次性分析所有数据'，而是'一步步走完整个诊断流程'"（L2025-L2029）。V4 仍有三大盲区：粉丝与非粉丝混在一起、货盘停留在价格带、流量只看搜索渠道（L2031）。

**V5.0（7/12，25+ Feature）**：三大系统性补全——粉丝/非粉丝分层、全渠道流量、单品级货盘穿透（L2033-L2113）。**触发事件 7/10 数据暴露错配**（实测）："看播用户中非粉丝占87%，但成交用户中粉丝占60%。粉丝转化效率远高于非粉丝。但V4.0把所有数据混在一起分析，完全识别不出这个错配"（L2069）。V5 的落地价值：能说出"179套餐访问→提单率仅11.8%，商详页说服力存在严重断点"——可执行的诊断（L2113）。

### 转折：复盘发现"用了但没意识到"的 4 个 Feature

即使没有 Feature 思维，她已经在做对的事（L2177-L2203）：①多轮迭代（持续调优 Feature 的应用）；②多平台交叉验证——DeepSeek+豆包+得到大脑跑同一组数据（"同时抽卡"）；③最佳实践对标——让 AI 以"交个朋友""与辉同行"为基准打分（"设定审美基准"）；④人工审阅+迭代驱动（Human-in-the-Loop）。同时暴露盲区（L2209-L2251）：温度/参数调优、模型路由、RAG、渐进式披露、反向提示、状态机。

### 结果：Feature 数量与组合方式的演进全景（实测）

| 版本 | 核心 Feature | Feature 数量 | 组合方式 | 效果 | 行号 |
|:---|:---|:---|:---|:---|:---|
| V1.0 | 角色/任务/背景/输出格式 | ~4 | 线性串行 | 能生成报告，无对比 | L2127-L2135 |
| V2.0 | +多轮对话/分层标注 | ~6 | 多轮串行 | 能跨场对比，无目标判断 | L2137-L2145 |
| V3.0 | +战略分层/目标锚定/负面限制 | ~9 | 前置锚定+校验 | 能判断目标一致性 | L2147-L2155 |
| V4.0 | +策略对齐/漏斗/货盘分层/一致性诊断 | ~15 | **Feature链（步骤1→2→3→4→5→6）** | 系统化诊断流程 | L2157-L2165 |
| V5.0 | +粉丝分层/全渠道/单品穿透/时段追踪 | ~25+ | 多维度并行+交叉验证 | 可识别系统性错配 | L2167-L2175 |

改进方向（L2285-L2323，推演）：短期可补模型参数调优、RAG 知识库；中期可试分支测试、主副模型；长期可攻 Agent 封装、工作流自动化。

## Critique

**内部局限（自指）**：单案例单业务（一个人、一个直播账号、两个月），且 Feature 数量（~4/~6/~9/~15/25+）是事后用 Feature 思维回映射的约数——V1 当时并没有"4 个 Feature"的概念，计数带追溯性。更关键：五轮迭代的"效果"叙事只有 Feature 数量的增长，缺少系统性业务指标呈现（GPM/成交额的变化只在 6/27、7/10 两个事件点出现），无法确证"Feature 补全→业务提升"的因果链。

**外部攻击者 1（Kahneman 式——进步叙事偏差）**：复盘文章天然有"每轮都发现缺口并补上"的进步叙事结构——这可能美化迭代过程（真实的迭代常伴随倒退、误判、白费功夫）。"迭代从不清晰变成了可拆解、可重复、可迁移"（L2371）是事后视角的整齐化。验证需要原始版本存档和每轮的失败记录，而非复盘后的重构。

**外部攻击者 2（Taleb 式——平台变量污染）**：五轮迭代横跨 6-7 月，抖音算法调整、季节消费变化、竞争环境都在变。V3 的失败被归因于"双目标相反"（Feature 层面），但曝光增加 GPM 下降也可能是平台流量结构变化。把业务结果归因到 Feature 层，需要排除平台/季节等外生变量——单案例无法做到。

## Synthesis

三个 Live258 案例（`[[case-live258-zhihu-content-acquisition]]`、`[[case-live258-livestream-prompt-v1-v5]]`、`[[case-live258-fact-spread-18-bridges]]`）共同揭示叠加效应的两种形态：黄华春是**并列维度覆盖**（身份/风格/结构三正交维度同时满足），jeffgirl V4 是**链式管道**（上输出=下输入，诊断流程逐步深化），王鹏飞是**关键维度补全**（身份+上下文=40→65 分）。三种形态对应 `[[dk-demand-feature-stacking]]` 的机制层：并列叠加解决"维度缺失"，链式叠加解决"流程深度"，而 V5 的粉丝分层揭示第三层——**分层是发现系统性错配的前提**（数据不分层，再强的 Feature 也看不见错配）。这与 `[[framework-truman-feature-thinking-core]]"Feature 越小越可测试"的断言一致：分层粒度决定可诊断粒度。

## Action Triggers

1. 给自己的复盘/分析类提示词做一次"链式改造"：把并列的多个要求重排成"上输出=下输入"的步骤链（先锚定目标→再逐层诊断→最后交叉验证）
2. 检查数据是否分层：粉丝/非粉丝、渠道、单品三个维度至少分一个——不分层就可能有 87% vs 60% 型的系统性错配看不见
3. 每次迭代前写"触发事件"：上一版暴露了什么具体失败？把失败事件作为下一版 Feature 补全的输入（6/27→V3、7/10→V5 的模式）
4. 对照周期表列出自己的盲区清单（温度/RAG/反向教我/状态机/分支测试）——按短期/中期/长期排优先级

## 失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| 多目标混在一个 prompt | 曝光涨但 GPM 跌，复盘也发现不了（6/27） | 目标锚定 Feature：先二选一（拉新 or 复购），加"目标一致性校验"步骤 |
| 数据不分层 | 人群错配看不见（87% vs 60%） | 粉丝/非粉丝、渠道、单品三维分层，再进漏斗 |
| 迭代只加数量不成链 | Feature 加到 15 个仍是并列堆叠 | 检查是否有"上输出=下输入"的依赖关系——没有就重排成步骤链 |
| 无版本管理 | 好版本找不回/无法对比版本效果 | 每版记录"改了什么 Feature、为什么、结果如何"（对应假设） |
