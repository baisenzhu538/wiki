# Simon Peng 医疗数据集方案：25 个 Feature 全启用的完美清单，零验证结果的边界教材

> 一句话：为 XZ（徐医附院双院区语境）生成《智能外科全流程多模态高质量数据集》交付方案，课后用 Feature 思维复盘——拆解出 25 个 Feature 并判定全部启用（L415-L421）、5 类缺失、5 组叠加效果，外加一份完整改进方案。但全案没有任何验证结果：方案是否被医院接受、改进是否有效，一律未知。学员自己的收尾是“试一试看，貌似应该会有提升的。如果没有，再来”（L507-L509）。

---

## 过程（起点→尝试→失败→转折→结果）

### 起点：一次真实的加班交付

背景（L363-L369）：为 XZ 产出《智能外科全流程多模态高质量数据集》正式交付方案。原始素材两份：

- 《围手术期全生命周期 AI 智慧运营与安全管理平台》——覆盖术前、APS 排程、术中、PACU、术后康复 5 大临床业务全链路
- 《ZG 市医疗高质量数据集建设方案》——市级医疗数据集标准化架构、资产化、运营、分期实施的通用工程框架

客户给了多轮结构化修订指令：删指定章节、合并固定章节、调整章节顺序、清除内部修订备注、输出可直接交付医院的正式 Word 文稿，全程无可视化、交互类需求。

### 尝试：五阶段执行，交付动作本身完成

执行过程（L371-L389）：

1. **需求接收与拆解**：区分两份文档边界（ZG=通用平台底座，AI=医院专属业务素材），提取硬性结构修改规则
2. **素材对齐映射**：以 ZG 四层技术架构为骨架，把 AI 文档第 5-9 章围手术期 5 条业务链逐条映射为 5 个场景化数据集专项模块，解决通用框架与专科业务的拼接
3. **结构重构**：删除原第三章；原第十、十一章合并为《面向高质量数据集应用的数据资产化过程》；原 5-9 章合并为单一场景大章节；剔除分期、启动清单、边界等冗余章节；清除全部过程性备注，统一为医院正式公文风格
4. **内容保留与润色**：原始业务细则、数据来源、建模规则、预处理流程、标注体系、验收指标 100% 完整保留（L387，学员自述），术语替换为徐医附院双院区语境
5. **终稿输出**：无过程痕迹的正式文稿+Word 本地保存操作指引

**注意：方案交付了，但失败环节在本案是缺席的**——复盘全文没有客户反馈，没有验收结果，没有任何方案被挑战的记录。这是本案例与族内其他案例的结构性差异。

### 转折：课后用 Feature 思维复盘——25 个 Feature 拆解

学员按课上 Feature 四层定义拆解出 25 个 Feature 清单（L397-L411）：

- **底层原理 F1-F5**：四层数据平台架构/医疗数据全生命周期治理/围手术期业务时序/隐私合规底层规则/数据集分层验收量化指标
- **核心组件 F6-F14**：多源数据接入连接器/治理标准化映射（ICD/ASA/切口术语统一）/多模态预处理/AI 智能标注流水线/场景化数据集封装/可信计算沙箱/授权运营工单/分级权限管控/分场景 KPI 量化验收
- **工具应用 F15-F20**：多文档素材融合/结构化指令解析/文档层级重构/冗余文字过滤/行业术语替换/正式公文文风标准化
- **场景教程 F21-F25**：术前准备评估/APS 手术室排程/术中风险预警/PACU 复苏监测/术后 0-90 天康复随访五大数据集场景

然后给出三段判断（L413-L433）：

- **实际启用**：F1-F25 全部启用——四层全部完整复用
- **缺失 5 类**：假设实验类（无数据基线摸底、无仿真验证）、持续调优类（无迭代闭环、无样本均衡调优）、跨角色对齐类（无外科/麻醉/手术室/信息/伦理多方对齐模块）、可视化配套类、落地演练类
- **叠加效果 5 组**：如底层架构原理+多文档融合+5 大场景的组合，解决“通用框架和专科业务两张皮”问题（L437）；隐私合规原理+沙箱组件+分级权限覆盖三甲医院高敏感数据合规要求（L443）等

### 结果：改进方案完整，验证完全缺席

改进补全方案（L449-L505）要点：

- **补假设实验**：方案开篇增加数据基线摸底专项实验模块（24 个月手术数据存量统计、接口可用性核验、算力容量测算）；APS 与术中模块增加历史脱敏数据回放仿真单元
- **补持续调优**：月度样本增量采集→模型效果反向修正标注规则的闭环；五大场景各加分层样本均衡处理单元
- **补跨角色对齐**：外科、麻醉、手术室、医务、信息、伦理六方需求对齐工作表，落地前多方签字确认
- **补可视化与演练**：业务架构画布/双三角竞争力画布/Feature 周期落地地图；术前数据集试点演练操作手册
- **体系升级**：Feature 按五层架构重新梳理并逐章标注；通用 Feature 与场景专属 Feature 两层组合复用；每场景增加效果验证单元与风险管控子 Feature；配套交付附件（标注规范手册、基线采集模板、验收核查表）
- **七步重构流程**：基线实验→原理骨架→通用组件→场景叠加→配套嵌入→验收风控→工具包输出（L493-L505）

结果状态：**改进方案零执行**。学员自述把案例分析存入知识库，「应该很快又有新的方案要做，试一试看」（L507）——全案唯一一句关于效果的话，是假设不是结果。

## Critique

**内部局限（自指）**：三个结构性缺陷。

1. **25 个 Feature 全部启用本身就是红旗**——Feature 思维的价值在取舍（哪个起关键作用、哪个可删），全启用=没取舍=清单完整性代替了效果判断；且这些 Feature 是复盘时事后命名的，生成方案时并无 Feature 设计意图，把方案里有什么内容重命名为启用了什么 Feature，是贴标签不是复盘
2. **验证完全缺席**——无客户反馈、无验收结果、改进方案零执行，连方案是否被医院接受都未知；复盘的起点（交付质量如何）本身就是悬空的
3. 学员自己也察觉了方法论摩擦（L425 原话：“很多场景下是无法一步到位的，留白？可能会破坏逻辑完整性。占位是否可以？”）——这个关于框架套不上现实时怎么办的真问题被他自己略过了，恰恰是本案最值得展开的点

**外部攻击者 1（对照国家标准——高质量数据集建设指南）**：2025 年 4 月全国数标委发布《高质量数据集建设指南（征求意见稿）》及配套质量评测规范，信通院《人工智能高质量数据集建设指南》明确标注环节以准确率、一致性、覆盖率为核心量化指标；医疗数据标注行业标准亦定义准确性/一致性等质量特性。用外部标准照本案：方案虽自称验收指标 100% 保留，但复盘从未对照任何外部质量标准核查方案是否达标。Feature 拆解是自指框架，对照国标才是外部锚点——本案恰好缺了这一步。

**外部攻击者 2（Kahneman 式——流畅性幻觉）**：五阶段过程+25 Feature+5 组叠加效果+7 步重构的完整叙事制造了已掌握的流畅感，但全案唯一的实证事实是一份文档按结构要求改完了。流畅的复盘叙事与验证缺席之间的落差正是流畅性幻觉——学员结尾「貌似应该会有提升」暴露了连他自己都不确定，但复盘体量（约 150 行结构化拆解）在观感上远远超过了证据强度。

## Synthesis

本卡按任务单定位如实入库为反例/边界教材，教学价值在于做对了形式、缺了实质：

- **形式齐全**：Feature 四层分类、清单拆解、缺失分析、改进方案一应俱全
- **实质三缺**：取舍（哪个 Feature 关键）、外部锚定（对照国家/行业标准核查）、验证（交付结果跟踪）

族内坐标对照：[[case-live258-huangqian-promo-film]]（黄谦案）同样无外部验收，但有清醒的层级自评与可证伪假设（带验证计划）；本案连假设都是模糊的（“貌似会有提升”）。[[case-live258-tianli-gov-training]]（田力案）证明 Feature 缺失导致失败，本案从反面提醒 Feature 清单齐全不证明任何东西——**Feature 思维的检验标准是能不能指出哪个 Feature 起关键作用，不是能列出多少个 Feature**。卡内双三角映射沿用 [[concept-yihang-dual-triangle-core]] 的六要素口径。

引用纪律：本卡不应被引用为「医疗数据集方案怎么做」的正面参考，应被引用为「复盘形式完整但验证缺席」的识别样本。另注族内规律：可用度最低的素材仍贡献了独有的边界知识——事后贴标签式复盘这一失败模式，在其余五案中均未出现。

## Action Triggers

1. 复盘时强制回答哪个 Feature 起了关键作用、哪个可以删掉——答不出来说明在做清单穷举，不是 Feature 思维
2. 方案类交付后在日历上钉一个结果回收提醒：客户反馈/验收结果回来前，复盘只能标推演
3. 用 AI 生成行业方案后，先对照该行业的外部标准（如数据集国标/行标）核查达标性，再做内部框架复盘
4. 遇到框架套不上现实的摩擦点（如无法一步到位时留白还是占位）时停下展开——摩擦点是暗知识富矿，略过即丢
5. 引用本卡时只作反例/边界教材，不作医疗数据集方案的正面方法论来源

## 失败模式

| 失败模式 | 症状 | 修复 |
|:--|:--|:--|
| 事后贴标签冒充 Feature 设计 | 复盘时把方案内容重命名为 Feature 清单，全部启用无取舍（L415-L421） | 强制回答哪个关键、哪个可删；清单全启用=警报 |
| 验证缺席的完整复盘 | 改进方案/重构流程齐全，但交付结果零跟踪（L507-L509） | 复盘前加一问交付物后来怎么样了；无结果标推演 |
| 自指框架替代外部标准 | 只用课上框架自查，不对照行业国标/行标核查达标性 | 行业方案先过外部标准核查单，再做内部框架复盘 |
| 摩擦点略过 | 发现留白会破坏逻辑完整性的真问题后自行跳过（L425） | 摩擦点单独记一条待解问题，上浮讨论 |
| 叙事流畅感当掌握 | 约 150 行结构化拆解制造已掌握观感，证据强度远低于文本体量 | 复盘文末强制列「本复盘没有证据支持的结论」清单 |
