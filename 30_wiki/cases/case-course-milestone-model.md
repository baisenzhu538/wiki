# 案例：一堂课程里程碑模型——方法论级建模的六步生产流程

> **Burn line**: 如果八年前 Truman 能穿越到现在，他会把这套课程建模的六句话带走。

## 用一句话讲清楚

一堂通过“**敲定边界 → 饱和收集事实 → 整合萃取 → 产出 1.0 模型 → 辩证讨论/撞击实验 → 封装与包装**”六步流程，把方法论课程从“先讲后改”变成“先撞后讲”的科学建模过程。

---

## Background

- **场景**：一堂需要持续产出高质量方法论课程
- **问题**：早期先讲后改，理论出错后团队很难受
- **目标**：建立科学的课程/方法论建模流程
- **来源**：`src_20260614_8269ccdb#2170-2265`

---

## What Happened

### 六步流程

1. **敲定边界**
   - 先定问题边界，超过边界不研究
   - 防止无边无际的信息和观点涌入

2. **饱和收集事实**
   - 收集正面案例、反面案例、最佳实践、搞砸案例
   - 收集自己的经验、体感、全国调研、复盘
   - **事实 > 观点 > 理论**

3. **整合萃取**
   - 对事实分类建模
   - 找 before/after 的共性、卡点、爬坑路径、最佳实践、原则、本质

4. **产出 1.0 模型**
   - 画一个框子：冰山图、双三角、雷达图等
   - 先有模型，再迭代

5. **辩证讨论 / 撞击实验**
   - 内部交叉评审 + 专家评审
   - **以推翻模型为目标**
   - 检查：硬伤？反例？边界模糊？定义不清？
   - 撞到无可撞、专家无坚决反对时，才勉强成熟

6. **封装与包装打磨**
   - 先封装成可交付形式
   - 再做十层解读对外宣传

### 关键原则

- **两种十层解读**：一种是为了推翻，一种是为了宣传；先推翻，再宣传。
- **不许提前讲**：理论没推翻前，谁都不许对外讲，否则团队会舍不得改。

### 结果

这套流程成为一堂做课的底层方法，支撑了个人地图、创业地图、管理地图等核心产品。

---

## 核心要点

- **边界是建模的第一件事**：没有边界，信息和观点会无限涌入，研究无法收敛。
- **事实优先于观点和理论**：只相信中国市场上真实发生的事实，理论只是验证参照。
- **萃取是为了找共性**：从 before/after 的差异中提炼卡点、爬坑路径、原则和本质。
- **1.0 模型先画框子**：不怕粗糙，关键是给讨论和推翻一个可撞击的实体。
- **以推翻为目标的撞击实验**：内部交叉评审 + 专家评审，找硬伤、反例、边界模糊、定义不清。
- **先推翻，再宣传**：成熟前禁止对外宣讲，避免认知沉没成本导致不愿改。
- **封装与包装分离**：模型成熟后再做可交付封装和宣传十层解读。

## 可迁移场景

| 场景 | 如何套用 |
|---|---|
| 做课程/培训 | 边界 → 事实 → 萃取 → 1.0 → 撞击 → 封装 |
| 做方法论产品 | 同样六步，只是把“课程”换成“方法论” |
| 写书/白皮书 | 先饱和事实，再建模，再推翻验证 |
| 团队知识萃取 | 用撞击实验保证质量 |

---

## 教训

- **边界是第一件事**：没有边界，研究会失控。
- **事实优先于理论**：不要先信市场上的理论，先收集事实。
- **推翻比宣传重要**：成熟的标志是撞无可撞。
- **不要提前讲**：讲了就不愿意改了。

---

## 边界

### 适用边界

| 场景 | 说明 |
|---|---|
| ✅ 方法论/课程研发 | 需要从真实案例中提炼可复用模型 |
| ✅ 知识产品生产 | 白皮书、SOP、训练营、教练体系 |
| ✅ 团队知识萃取 | 把个人经验沉淀为组织资产 |
| ✅ 研究型内容 | 问题边界可先被清晰定义，存在可收集的事实 |
| ✅ 有迭代条件的项目 | 允许 1.0 → 撞击 → 修改的循环 |

### 不适用边界

| 场景 | 说明 |
|---|---|
| ❌ 纯艺术创作 | 依赖直觉与表达，难以用“事实>观点”收敛 |
| ❌ 毫无共识的领域 | 找不到 5% 专家共识，无法做撞击实验 |
| ❌ 一次性交付且无迭代资源 | 没有条件完成六步闭环 |
| ❌ 已对外承诺不可改的内容 | “不许提前讲”与外部承诺冲突 |

---

## 失败模式

| 失败模式 | 表现 | 避免方法 |
|---|---|---|
| **边界不定** | 研究范围无限扩大 | 先写一句话边界 |
| **理论先行** | 只看书不看事实 | 先收集真实案例 |
| **1.0 就宣传** | 讲完发现理论有错 | 先完成撞击实验 |
| **没有推翻机制** | 团队自嗨 | 找外部专家评审 |
| **提前对外讲** | 团队产生沉没成本，拒绝重大修改 | 明确成熟前禁止宣讲 |
| **混淆推翻与宣传** | 用宣传型十层解读替代撞击实验 | 分阶段：先推翻十层，再宣传十层 |

## 行动 Checklist

在启动一次方法论级建模前自检：

- [ ] 能否用一句话写清本次建模的问题边界？
- [ ] 边界外的典型现象是否已明确列出？
- [ ] 是否已建立事实收集清单（正面/反面/最佳/搞砸案例）？
- [ ] 收集到的事实是否覆盖了不同来源（自身经验、全国调研、复盘）？
- [ ] 是否已完成事实分类并提炼 before/after 共性、卡点、爬坑路径？
- [ ] 是否已产出 1.0 模型（框子/图/清单）？
- [ ] 是否安排了以推翻模型为目标的内部交叉评审？
- [ ] 是否邀请了具备实践经验的专家评审？
- [ ] 撞击实验的“硬伤/反例/边界/定义”检查清单是否已记录？
- [ ] 在模型通过撞击实验前，是否已禁止对外宣讲？
- [ ] 封装版本与宣传十层解读是否已分离？
- [ ] 最终模型是否已关联到已有框架或武器库（冰山图、双三角、雷达图等）？

## 诊断信号

本案例适用于以下方法论建模卡点的触发信号（完整 Signal → Lens → Follow-up 三元组见 frontmatter `diagnostic_signals`）：

1. **研究范围持续膨胀**：每次建模讨论都发散到原定问题之外。  
   → 追问：能否用一句话写清本次建模的问题边界，并明确哪些现象不在研究范围内？

2. **理论先于事实**：团队先用框架/观点开会，而不是先收集真实案例。  
   → 追问：目前已经收集到的正面案例、反面案例、最佳实践、搞砸案例各有多少个？

3. **1.0 后直接包装**：模型产出后没有专门找反例和专家评审来推翻它。  
   → 追问：我们是否设置了以“推翻模型”为目标的内部交叉评审和专家评审环节？

4. **讲完后不愿改**：理论一旦对外宣讲，团队就很难再接受重大修改。  
   → 追问：在模型通过撞击实验之前，是否已明确禁止对外宣讲？
