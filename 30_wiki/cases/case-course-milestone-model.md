# 案例：一堂课程里程碑模型——方法论级建模的六步生产流程

> **Burn line**: 如果八年前 Truman 能穿越到现在，他会把这套课程建模的六句话带走。

## 用一句话讲清楚

一堂通过“**敲定边界 → 饱和收集事实 → 整合萃取 → 产出 1.0 模型 → 辩证讨论/撞击实验 → 封装与包装**”六步流程，把方法论课程从“先讲后改”变成“先撞后讲”的科学建模过程。

## 边界

### 适用边界

| 场景 | 说明 |
|---|---|
| ✅ 方法论/课程研发 | 需要从真实案例中提炼可复用模型 |
| ✅ 知识产品生产 | 白皮书、SOP、训练营、教练体系 |
| ✅ 团队知识萃取 | 把个人经验沉淀为组织资产 |
| ✅ 研究型内容 | 问题边界可先被清晰定义，存在可收集的事实 |
| ✅ 有迭代条件的项目 | 允许 1.0 → 撞击 → 修改的循环 |

### 不适用边界

| 场景 | 说明 |
|---|---|
| ❌ 纯艺术创作 | 依赖直觉与表达，难以用“事实>观点”收敛 |
| ❌ 毫无共识的领域 | 找不到 5% 专家共识，无法做撞击实验 |
| ❌ 一次性交付且无迭代资源 | 没有条件完成六步闭环 |
| ❌ 已对外承诺不可改的内容 | “不许提前讲”与外部承诺冲突 |

---

## 失败模式

| 失败模式 | 表现 | 避免方法 |
|---|---|---|
| **边界不定** | 研究范围无限扩大 | 先写一句话边界 |
| **理论先行** | 只看书不看事实 | 先收集真实案例 |
| **1.0 就宣传** | 讲完发现理论有错 | 先完成撞击实验 |
| **没有推翻机制** | 团队自嗨 | 找外部专家评审 |
| **提前对外讲** | 团队产生沉没成本，拒绝重大修改 | 明确成熟前禁止宣讲 |
| **混淆推翻与宣传** | 用宣传型十层解读替代撞击实验 | 分阶段：先推翻十层，再宣传十层 |

## 诊断信号

本案例适用于以下方法论建模卡点的触发信号（完整 Signal → Lens → Follow-up 三元组见 frontmatter `diagnostic_signals`）：

1. **研究范围持续膨胀**：每次建模讨论都发散到原定问题之外。  
   → 追问：能否用一句话写清本次建模的问题边界，并明确哪些现象不在研究范围内？

2. **理论先于事实**：团队先用框架/观点开会，而不是先收集真实案例。  
   → 追问：目前已经收集到的正面案例、反面案例、最佳实践、搞砸案例各有多少个？

3. **1.0 后直接包装**：模型产出后没有专门找反例和专家评审来推翻它。  
   → 追问：我们是否设置了以“推翻模型”为目标的内部交叉评审和专家评审环节？

4. **讲完后不愿改**：理论一旦对外宣讲，团队就很难再接受重大修改。  
   → 追问：在模型通过撞击实验之前，是否已明确禁止对外宣讲？
