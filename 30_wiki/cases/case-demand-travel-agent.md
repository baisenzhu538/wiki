# 案例：旅行攻略Agent

**初始判断**：用户需要"AI生成旅行攻略"，功能需求明确。

**踩坑过程**：做出来用户觉得"挺有用但不付费"。复盘发现——用户真正需要的不是攻略本身，是"有人帮我做决策"。攻略是信息，决策是服务。隐性需求（情感+社交任务）被完全忽略。

**核心教训**：L5（隐藏洞察）不是可选项。功能任务只是冰山一角，情感和社交任务才是付费决策的驱动力。

## 关键证据

| 证据点 | 来源 | 可检验性 |
|:---|:---|:---|
| 用户留存高但转化率低：平均阅读 3.2 篇攻略，收藏率 18%，付费转化率仅 0.7% | 产品后台埋点 + 七日内问卷 | 可复测 A/B：向同类用户推送"决策服务" vs "攻略合集" |
| 用户原话高频词："选择困难""怕踩雷""想有人带"，而非"攻略不够详细" | 客服会话抽样（n=120） | 可让两名研究员独立编码，计算 Kappa |
| 竞品案例：某旅行社 Agent 将"三日游方案"改为"帮你吵架式比价+一键预订"后，ARPU 提升 4 倍 | 行业访谈 + 公开案例 | 可索要脱敏数据或做小规模仿照实验 |

## 可迁移场景

- **知识付费选题**：用户买的不是"课程大纲"，而是"帮我判断现在该学什么"。
- **B2B 工具销售**：客户要的不是功能清单，而是"这套工具在我公司里怎么落地、谁会被得罪"。
- **招聘/求职 Agent**：求职者要的不是岗位信息，而是"我值多少钱、下一步投哪类公司"。
- **家庭消费决策**：如装修、购车、保险——信息过剩，关键缺口是"敢拍板的信心"。

## 教训

- 当你发现"用户说有用但不付费"时，首先怀疑功能任务是否被过度满足，而决策/情感/社交任务未被满足。
- 在需求五层模型中，L5（隐藏洞察）应作为最小可行验证的一环：用 5–10 个深度访谈先画"任务地图"，再决定功能范围。
- 把"生成攻略"重新定义为"降低决策负担"后，产品界面、定价模型、推荐话术都会跟着变。

## 失败模式

- **把信息当服务**：以为输出越多攻略越有价值，结果用户淹没在选项里，反而更焦虑。
- **把"愿意聊"当"愿意买"**：用户愿意试玩 Agent，不代表他们愿为"查询工具"付费。
- **忽略社交任务**：旅行往往涉及伴侣、家人、朋友之间的协商，Agent 只服务"一个人查资料"，没解决"如何说服同行者"。
- **过早做通用 Agent**：没有先把一个具体决策场景（如"带老人出国第一站"）做透，导致没有口碑锚点。

## 案例启示

这个案例最值钱的地方在于：它把"AI 旅行攻略"从一个内容生成问题，重新定位成一个**决策支持服务**问题。

具体可执行的改进包括：

1. **把输出从"攻略"改成"可执行的决策包"**：不只给景点列表，而是给出"Day 1 上午去 A 还是 B"的二选一建议，并说明判断标准（排队时间、老人友好度、交通成本）。
2. **引入"同行者协商"功能**：让 Agent 生成两套方案对比卡，方便用户转发给家人/朋友投票，解决社交任务。
3. **付费点放在"决策兜底"**：免费层给信息整理，付费层给"专家复核"或"行程变动时的实时重排"，把价值锚定在"替你担责"。
4. **验证指标从"阅读量"改为"决策完成率"**：统计用户是否真正完成了预订、是否减少了修改次数，而不是只看生成字数。

简言之：用户不为"你知道得多"付费，而为"你让我敢做决定"付费。
