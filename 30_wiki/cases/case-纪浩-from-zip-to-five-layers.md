# 纪浩：从微信传 zip 到五层协作体系

> 纪浩是一堂的后端工程师。从2026年1月到4月，他每天高强度使用AI协作，经历了从"新手盲目"到"有体系地驾驭AI"的完整过程。这个案例记录了他在这四个月中遇到的核心问题、解决方案的演化，以及最终形成的五层协作体系。

## 背景

纪浩是一名后端工程师，对前端和UI设计没有审美，觉得"只要能跑就行"。他在四个月里同时推进四个战场：软件重构、电子、机械、推广。随着让AI接手的任务变多，他开始发现一个普遍问题：**AI开始出现各种各样的混乱行为**——输出不稳定、上下文丢失、同样的任务每次都要重新交代。

更深层的问题是：团队里越来越多的人开始用AI，但好的配置无法复用。想分享一个Skill，要先找到文件夹、打包成zip、通过微信传给别人；更新后版本号不统一，别人出问题只能"模糊口述"反馈，纪浩根本无法定位。

## What Happened

### 第一阶段：微信传 zip 的时代

在集中式管理之前，团队分享和复用AI Skill的方式非常原始：

| 痛点 | 具体表现 |
|:---|:---|
| 存储分散 | 想分享一个Skill，先找到文件夹在哪，打包成zip，通过微信传给别人 |
| 版本混乱 | 更新之后要么文件名变了，要么版本号不统一，张三用的还是旧版本 |
| 反馈无上下文 | 别人用Skill遇到问题，只能"模糊的口述"来反馈，纪浩无法定位问题 |
| 安装靠人 | 更新后要么微信通知张三、李四、王五，装没装不知道 |

核心问题：**人在做机械的分发和管理工作**，而这些工作本来应该由系统自动完成。

### 第二阶段：四要素验证锁定真需求

纪浩没有直接跳进去做一个"技能市场"的产品，而是先用**四要素**检验这是不是一个值得解决的真需求：

| 要素 | 在Skills市场案例中的具体表现 |
|:---|:---|
| **Before-After** | 之前微信传zip、版本混乱、反馈无上下文 → 之后集中管理、统一分发、带上下文的反馈 |
| **真实锚点** | 一堂内部真实使用场景，不是"如果有一个平台就好了"的想象 |
| **受益人** | 维护者（纪浩自己）维护变得方便；用户（同事）能稳定获取最新版本 |
| **可解性** | 存储分散→集中管理有因果链；版本混乱→版本号有能力支撑；反馈无上下文→AI自动上报上下文 |

四要素通过后，他才开始动手。这避免了一个常见陷阱：**把假需求当成真需求**。

### 第三阶段：从一步到八步的PDCA

在做UI设计Skill的过程中，纪浩的PDCA循环是逆向长出来的：

1. **第一步：硬干（Do）**——不管方案，让AI先动手做
2. **第二步：加Check**——在做的过程中发现问题，加一些检查点
3. **第三步：加Plan**——发现光靠Check不够，需要根据实际问题制定计划，把一步计划变成八步
4. **第四步：规范化（Act）**——用规范约束死每一步，然后去细化PDCA
5. **第五步：规模化（Scale）**——把这个流程放到Skills市场上给其他人用

**核心洞察：PDCA不是从Plan开始的，一定是从Do开始的**。先解决具体问题，循环才能搭起来。

### 第四阶段：五层协作体系成型

经过四个月的反复跌打，纪浩形成了一套从"判断"到"规模复用"的五层体系：

```
L1 四要素验证（判断是不是真需求）
   ↓
L2 Agent Workspace（搭建AI的工作环境）
   ↓
L3 Do-first PDCA（从行动开始的迭代循环）
   ↓
L4 双三角模型（人让AI变强 ≠ AI让人变强）
   ↓
L5 Skills Market（规模复用的基础设施）
```

其中Skills市场的设计理念值得注意：**它不是给人用的，是给Agent用的**。Agent按分类+capability匹配 → 自己下载安装 → 自己上报反馈。平台的分类不是为了"人好找"，是为了"按任务类型精确命中"。

## 可迁移场景

1. **团队内部工具/模板的分发**：任何需要在团队内部分发和版本管理的工具，都可以用"四要素+集中平台"思路解决
2. **AI Skill 的管理**：不仅是代码，任何被封装成可复用能力的知识，都需要一个集中管理和分发的平台
3. **从个人工具到团队基础设施**：当个人用的工具被证明有效后，如何扩展为团队级别的基础设施
4. **AI 协作的规模化**：当团队里AI使用率上升、好的配置需要复用时，五层体系提供了一个从判断到规模复用的完整路径

## 诊断信号

当你或团队出现以下信号时，本案例的方法论可能直接适用：

| 信号 | 对应层级 | 立即跟进 |
|:---|:---|:---|
| 团队内部分发 AI Skill/模板靠微信传文件，版本号五花八门，每次更新都要逐个通知 | L5 Skills Market 缺失 | 列出过去一周因此产生过几次返工或版本不一致 |
| 同一个 AI 任务，每次启动都要重新交代上下文，输出质量时好时坏 | L2 Agent Workspace 结构不完整 | 检查 Workspace 五大模块是否齐备 |
| 想做 AI 产品/工具，但说不清解决前后的具体状态变化和受益人 | L1 四要素验证未通过 | 用"从__变成__"一句话描述 Before-After，并指认真实受益人 |
| 团队把 PDCA 当成"先写完整计划再执行"，计划写了但执行不下去 | L3 Do-first PDCA 顺序错误 | 30 分钟内先产出最小可验证输出，再补 Check 和 Plan |

## 常见失败模式

| 失败模式 | 真实症状 | 可执行修复 |
|:---|:---|:---|
| **把"缺少平台"直接当成"需求存在"** | 四要素表填完，但 Before-After 来自想象，找不到具体受益人，也没有可验证数据 | 强制每个要素附一个真实锚点（具体人名/场景/数据）；任意一项缺失先补调研，不进场动手 |
| **Skills Market 写成给人看的说明书** | Agent 无法按 capability 匹配、自安装；用户仍在群里问"这个怎么用"；安装率低于 30% | 用"输入-能力-输出-反馈"四元组重写 Skill 描述；让 AI 根据描述自动生成安装说明和调用示例 |
| **PDCA 循环空转：只调提示词不改结构** | 从一步拆成八步，但每次 Check 只改 prompt，Workspace 结构不变，同样问题反复出现 | 每次 Check 必须输出一条"要改的文档/规则/模板"；Act 阶段只改结构，提示词由结构自动生成 |
| **Workspace 变成资料坟场** | 导诊台、工作手册越写越长，AI 开始"找不到信息"或输出幻觉，同一条规则反复问 | 按"一次对话一个任务"做渐进式披露；每两周用日志驱动排查删除失效模块 |
| **跳过四要素直接做"通用平台"** | 产品功能越做越宽，却找不到一个愿意持续使用的真实用户；上线后活跃度快速归零 | 先锁定一个内部真实场景跑通，再扩展分类和 capability；每个新增功能必须对应一个真实受益人 |

## 适用边界

| 边界 | 说明 |
|:---|:---|
| ✅ 团队已有重复执行的 AI 任务场景 | Skills Market 对一次性创意任务 ROI 低，只有反复出现的任务才值得建基础设施 |
| ✅ 至少有一个真实内部用户（自己或同事） | 四要素验证要求有真实锚点，没有真实用户就没有 Before-After |
| ✅ 任务错误成本可接受 | Do-first PDCA 允许在行动中修正，但如果第一次 Do 的方向完全错误，后续迭代会加深错误 |
| ✅ 有持续维护 Workspace/Skill 的意愿和能力 | Workspace 五模块和 Skills Market 会随使用膨胀，没有维护预算会退化为信息坟场 |
| ❌ 创意发散/探索阶段 | 五层体系是收敛工具，过早会把创意钉死在框架上 |
| ❌ 一次性任务，无复用需求 | 直接做一次性的 AI 对话即可，不需要建 Workspace 和 Market |

## 落地工具：从 zip 到 Skills Market 升级检查清单

| 层级 | 检查项 | 通过标准 |
|:---:|:---|:---|
| L1 | 四要素是否都有真实锚点？ | 能说出至少一个具体用户/场景/数据，而非"应该会更好" |
| L1 | Before-After 能否一句话说清？ | 用"从 __ 变成 __"格式描述，且受益人可命名 |
| L2 | Agent Workspace 五模块是否已命名？ | 系统自述、领域知识、Agent 服务文档、任务管理、日志均有对应文档/目录 |
| L2 | 导诊台是否按场景而非分类组织？ | 一个入口对应一类高频任务，而非按"文档/代码/数据"分类 |
| L3 | 第一次 Do 是否有可验证的最小输出？ | 能在 30 分钟内得到一次 AI 产出，并据此做 Check |
| L3 | Check 是否指向结构改进而非提示词微调？ | 每次 Check 产出至少一条"要改的文档/规则/模板" |
| L4 | 是否明确人让 AI 变强的 manager 动作？ | 列出本任务中必须由人判断/验收的 3 个关键点 |
| L4 | 是否预留 AI 让人变强的挑战动作？ | 至少保留一个"不用 AI、手动完成"的子步骤以保持手感 |
| L5 | Skill 描述是否按 Agent 可自安装格式写？ | 包含输入、能力、输出、反馈四元组，AI 能据此生成安装说明 |
| L5 | 是否有复用路径（分类+capability+匹配规则）？ | 其他 Agent 能根据任务特征找到并调用该 Skill |
