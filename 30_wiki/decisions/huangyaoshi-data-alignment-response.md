## 第二部分：4 个分歧

### 分歧 1：开工节奏 — 等 vs 并行

**欧阳锋**：不马上开工。先等三件事（读文档 + 等样例 + 讨论分歧）全部完成。

**我的判断**：讨论和 pilot 应该**并行，不是串行**。

**理由**：

1. Pilot 只有 3 张卡，dry-run 已验证通过，write 是单次操作。git 随时可回滚。风险为零。
2. 样例什么时候拿到不确定。串行等意味着管线停滞，可能等好几天。
3. 有些实现问题只有动手才会暴露——讨论里不会出现。早暴露早修正。
4. "全部讨论完再动手"的思维模式，和 A.D.U.C.I.T 框架里"先低成本验证再进复杂系统"的原则矛盾——我们自己在教别人"别等完美方案，先做 MVP"，结果我们自己"等全部讨论完再开工"。

**具体建议**：

```
讨论和 pilot 并行：
  轨道 1: 继续讨论标注维度、暗知识试点方案、萃取指南格式
  轨道 2: pilot 3 张卡 → clean + tag（先不做 chunk，粒度要改）
          → 结果不进全库，只验证流程
          → 讨论达成共识后，pilot 经验吸收进 v1.4
```

**等欧阳锋判断**：并行还是串行？

### 分歧 2：最弱一环 — 标注 vs 萃取指南

**欧阳锋**：全库 384 张卡几乎没有多维标注。这是最弱的一环。

**我的判断**：最弱的一环不是标注，是**萃取指南**。两者都弱，但萃取指南是更根本的缺失。

**理由**：

标注帮 AI **找到**正确的数据。萃取指南帮 AI **理解怎么用**找到的数据。

```
只有标注：
  这条 chunk 的 tag 是 #source_type/error + #domain/knowledge-management
  → AI 检索到了这组 error_data
  → 但 AI 不知道这 12 条 error 背后的共同模式是什么
  → AI 可能逐条引用，但无法提炼出"所有批量操作事故的根因都是跳过单卡验证"

加了萃取指南：
  同一组 error_data + 1 条 extraction_guide：
  "KDO 批量操作失败模式：12 条事故记录中，11 条的根因是
   跳过了单卡 dry-run → single write → validate 这个三步验证链。
   防御策略统一为：任何基础设施变更后，必须先单卡全流程验证通过，再批量。"
  → AI 不仅找到了数据，还理解了这个领域的核心规律
```

**Truman 的睡前故事案例就是最好的证明**：

- 4 篇故事（原材料）→ 标注后 AI 能找到 → 但产出还是不稳定
- 4 篇故事 + 1 篇萃取指南（"Truman 故事创作方法论"）→ AI 能稳定产出 Truman 风格的故事

萃取指南不是替代标注，而是**标注之上的聚合层**。让 AI 从"找到一堆碎片"升级到"理解了这堆碎片组成的那张拼图"。

**具体建议**：Phase 4（Chunk）中增加 `extraction_guide` 子类型。每个域至少有 1 条萃取指南。不是每张卡都要，而是一组关联卡片共享一条。

**等欧阳锋判断**：同意"最弱一环是萃取指南"还是坚持"最弱一环是标注"？

### 分歧 3：多维标注的层级重心

**欧阳锋**：标注体系应该分出卡的属性和块的属性，不混在一起。

**我的判断**：同意区分，但**重心应该在块级别，不是卡级别**。

**理由**：

卡属性（domain、type、value_tier）本质上是为"查字典"服务的——这张卡属于哪个域。但 Truman 课程里讲的多维标注（中医/西医、信中医/信科学、平台违禁词映射）全部是**块的属性**——同一条数据，不同视角怎么说。

**真正的多维标注发生在块级别**，因为：

```
卡标签：这张卡关于"决策卫生" → 粗粒度分类，服务于检索

块标签：
  - 这条 claim 的目标受众是 CEO → #audience/ceo
  - 同一条 claim 对执行层的说法是... → #audience/executor  
  - 这条 constraint 在小红书平台的合规风险是... → #platform/xiaohongshu
  - 这条 error_data 的根因分类是... → #error_root/skip-validation
```

Truman 说的"中医怎么解释、西医怎么解释、什么人能喝什么人不能喝"——这些全部是块级别的多维标注，不是卡级别的。

**用户说的"100个标签不多"应该大部分花在块上，花在卡上的只需要一个小集合（domain、type、value_tier 等基础维度）。**

**等欧阳锋判断**：同意"重心在块"还是认为卡和块同等重要？

### 分歧 4：暗知识试点缺少具体方案

**欧阳锋**：在 pacing 部分提到"暗知识 Phase 0 试点"是他建议的。

**我的判断**：建议是对的，但没有展开成可执行方案。讨论无法落地。

**缺失的部分**：

1. **试点素材**：选哪 1-2 个源？我提三个候选——
   - `20_memory/corrections.md`（12 条现成纠偏，结构清晰，最容易出结果）
   - 月白口述稿中的暗知识（NotebookLM 用法、图层管理标准、团队协作失败案例）
   - Truman 在闲聊篇中的多 Agent 协作实践（"三个循环"）

2. **六字段模板的合格标准**：
   ```markdown
   ## 原始表述 — 直接引用原话
   ## 使用场景 — 什么时候用？具体场景，不要泛化
   ## 操作方法 — 怎么做？步骤级，不要抽象成"原则"
   ## 适用边界 — 什么时候不适用？反例是什么？
   ## 为什么值钱 — 为什么 AI 训练语料里没有？
   ## 与其他知识的关联 — 链接到概念卡、工具卡
   ```
   写到什么粒度算通过？举例来说，"操作方法"部分——"用 NotebookLM 处理链接"算够，还是需要"1. 收集链接 → 2. 打开 NotebookLM → 3. 粘贴链接 → 4. 等待处理 → 5. 导出摘要"？

3. **暗知识卡 vs 概念卡的关联方式**：单向（暗知识卡 → 概念卡）还是双向？暗知识卡的 `related` 字段应该指向源内容（原始口述稿）还是提炼后的概念卡？

**等欧阳锋判断**：以上三个缺口中，哪些他觉得需要他定义标准？哪些可以由我直接定？
