# 提案：AI 快速精通领域知识管线

> **触发**：2026-06-02 飞轮迭代后，用户问"这个方法是否可以迁移到训练 AI 快速掌握一门学科？加上自动搜索是否可以加速？"
>
> **核心问题**：KDO 飞轮（建造→使用→反思→实验）在"个人深挖"场景已验证有效。能否将同一模式升级为"AI 自动学习一个陌生领域"的管线？

---

## 一、愿景

```
用户输入："帮我精通 Rust 所有权系统"
        ↓
[自动搜索] 搜索→fetch→ingest→三步编译→概念卡（5-10 张）
        ↓
[缺口分析] 图遍历发现知识盲区 → 针对性补充搜索
        ↓
[深度合成] 对核心争议用四步编译法产出深度文章
        ↓
[循环] 直到覆盖率收敛
        ↓
产出：50-80 张概念卡 + 3-5 篇深度文章 + 跨域链接图
效果：Agent 回答该领域问题时，上下文质量 ≈ 读完了领域最佳教材
```

---

## 二、管线设计

### Phase 1：建骨架（自动）

| 步骤 | 操作 | 工具 | 产出 |
|:----:|:-----|:-----|:-----|
| 1.1 | 搜索领域核心关键词 | WebSearch + fetch-url | 5-10 篇综述/入门文章 |
| 1.2 | 自动 ingest | `kdo ingest --batch` | 10_raw/ 源文件 |
| 1.3 | 批量三步编译（LLM） | 三步编译 prompt + LLM 批处理 | 30_wiki/concepts/ 骨架卡 |
| 1.4 | 分析缺口 | `kdo graph query` 遍历知识图谱 | 缺少的子领域列表 |

### Phase 2：补缺口（自动+人工抽检）

对 Phase 1 识别的缺口逐轮搜索→编译，直到覆盖率达到阈值：

```
缺口列表 → 逐条搜索 → ingest → 三步编译 → 加入图谱 → 重新分析缺口
```

收敛条件：连续两轮新增卡片的 source_refs 中，≥80% 指向已有卡片已覆盖的源。

### Phase 3：注深度（人工）

对核心争议/框架/边界问题，用四步编译法产出深度文章：

- 哪些框架之间有根本性冲突？
- 这个领域的共识是什么？争议是什么？
- 适用于什么场景？不适用于什么场景？

### Phase 4：验证（可跳过）

用 Gold Standard 方式做准确率评估：
- 欧阳锋（或领域专家）手工标注 10-20 条核心判断
- 自动卡片 vs 手工标准 → 计算准确率
- 准确率 < 80% → 排查哪步有问题

## 三、关键风险

### 风险 1：搜索引擎污染

| 风险 | 场景 | 后果 |
|:-----|:-----|:------|
| SEO 垃圾内容 | 搜索返回营销文章而非真实知识 | 概念卡建立在虚假事实上 |
| 过时信息 | 搜索到 3 年前的文章，领域已变化 | 卡片内容过期但不自知 |
| 单一来源偏见 | 所有搜索结果来自同一学派 | 知识图谱没有对立视角 |
| 圈层回声 | 中文互联网特定领域的讨论被特定群体主导 | "共识"可能是圈层共识不是领域共识 |

**已有防御**：

| 防御机制 | 在管线的哪一步生效 |
|:---------|:-------------------|
| `source_refs` + `trust_level` | ingest 时标记来源可信度 |
| 三步编译的 Question 环节 | 强制问"前提假设是什么？反例是什么？" |
| Critique / 外部攻击 | 要求找该方法的反对者 |
| Judge 边界判断 | 要求写出"我不同意哪个观点" |
| D1-D4 门禁 | 拦截无立场的笔记式卡片 |

**需新增的防御**：

| 新增防御 | 说明 |
|:---------|:------|
| **来源多样性门禁** | 每个子领域至少引用 2 个独立来源，否则标记为"单源暂定" |
| **时效标记** | 自动检测源文件的发布时间；超过 2 年的标记 `freshness: stale` |
| **冲突标记** | 当两张卡的 claim 矛盾时，自动创建 contradiction 记录 |
| **人审核签** | 自动产出的卡默认 `status: draft`，经人抽检后才升为 `enriched` |

### 风险 2：LLM 编译幻觉

LLM 在归纳总结时可能：
- 添加原文没有的结论
- 忽略原文中的限定条件
- 把相关性说成因果性

**防御**：
- 三步编译的 Condense 阶段必须保留原文引用（不可凭空总结）
- 编译输出与原文的相似度检查（BLEU 或 embedding cosine）
- `source_refs` 必须精确到段落级别，而非文件级别

### 风险 3：知识库污染

"吸收偏颇知识"最危险的路径不是单张卡错了——是**错的知识和正确的知识以同等的结构被入库，让 Agent 无法区分**。

**防御**：
- `trust_level` 字段显式标注来源可信度（high/medium/low）
- 对争议性话题，强制用对比卡格式（pro/con 并列展示）
- 禁止自动删除已有卡片——新卡片永远以补充而非替换的方式入库

## 四、边界讨论

### 自然科学领域（高适用性）

| 特征 | 示例 | 适用于自动管线？ |
|:-----|:-----|:---------------:|
| 可验证的事实 | 沸点、溶解度、晶体结构 | ✅ 搜索引擎能返回正确答案 |
| 可复现的实验结果 | 胡克定律、欧姆定律 | ✅ 跨文化共识 |
| 稳定的知识体系 | 经典力学、无机化学 | ✅ 过时风险低 |
| 学术共识明确 | 进化论、相对论 | ✅ 争议可标记为"历史上的争议" |

### 工程应用领域（中高适用性）

| 特征 | 示例 | 适用于自动管线？ |
|:-----|:-----|:---------------:|
| 事实+经验混合 | PCB 布局规则、API 设计模式 | ✅ 事实部分可自动学，经验部分需要人标注 |
| 快速变化 | 前端框架、芯片型号 | ⚠️ 需要时效标记 + 定期刷新 |
| 工具依赖 | SDK 用法、CLI 命令 | ⚠️ 版本变化快，需要来源时间戳 |

### 社会科学/商业/人文领域（中低适用性）

| 特征 | 示例 | 适用于自动管线？ |
|:-----|:-----|:---------------:|
| 多种解释框架 | 经济学理论、管理方法论 | ⚠️ 可以学，但必须并置多个框架 |
| 价值观依赖 | 伦理判断、政策立场 | ❌ 不适合自动管线——"正确"取决于立场 |
| 圈层知识 | 创业方法论、投资策略 | ⚠️ 需要标注来源者背景 + trust_level |
| 时效敏感 | 市场分析、行业报告 | ⚠️ 产出即过时的风险高 |

### 哲学/规范性领域（低适用性）

"人应该怎么活""什么是公平"——这些不存在搜索引擎能返回的正确答案。自动管线对此无能为力。

### 边界原则

```
自动管线适用：事实可验证、跨文化共识、有稳定知识体系
自动管线辅助 + 人审核：经验知识、工具用法、多框架并存
不适合自动管线：价值观判断、规范性主张、圈层内部知识
```

## 五、实施建议

### 第一阶段（验证可行性）

选择一个**知识体系稳定的自然科学或工程领域**做 Pilot：

| 候选领域 | 理由 | 素材可获得性 |
|:---------|:-----|:-------------|
| **Python 类型系统** | 事实可验证、官方文档完整、有争议（Optional vs None） | ✅ 高 |
| **信号完整性基础** | 工程事实为主、有仿真可验证、知识体系稳定 | ⚠️ 中等 |
| **RAG 系统架构** | KDO 自身领域、可自验证 | ✅ 最高，但领域变化快 |

建议选 **RAG 系统架构**——和 KDO 自身相关，验证成本最低。

### 第二阶段（评估质量）

- 跑完后用 Gold Standard 方式评估准确率
- 对比同样问题在"学习了 50 张卡后"vs"直接上网搜"的回答质量
- 评估标准：事实正确率、遗漏率、偏见程度

### 第三阶段（决定是否推进）

根据第二阶段评估决定：
- 准确率 ≥ 85% → 可扩展到其他自然科学领域
- 准确率 70-85% → 仅用于工程应用领域，需要人审核
- 准确率 < 70% → 管线设计有问题，停止推进并复盘根因

---

## 六、不做什么

- **不做**社会科学价值观判断的自动学习
- **不做**完全取代人审核的自动管线（draft 自动产出 + 人抽检升 enriched）
- **不做**大规模并行领域学习（一次只跑一个领域，收敛后再跑下一个）
- **不做**训练模型——这是知识库管线，不是 fine-tune 管线
