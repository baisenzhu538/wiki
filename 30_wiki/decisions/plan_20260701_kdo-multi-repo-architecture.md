# KDO 多库架构设计方案

> 老朱的核心目标：用AI重塑工作模式 → OPC公司。主库是武器库，副库是战场。
> 主库告诉你"怎么打仗"，副库记录"正在打什么仗"。

---

## 一、架构原则

1. **主库做方法论，副库做应用**。主库不放具体项目数据和私人日程。
2. **副库可独立运行，但方法论来自主库**。副库Agent启动时从主库加载框架。
3. **跨库查询由路由Agent（王语嫣）处理**。用户不需要知道数据在哪个库。
4. **分库触发条件**：单域超过500张卡、或包含敏感业务数据（客户/财务）。

## 四、跨库路由

王语嫣作为路由Agent，用户问任何问题，她判断该查哪个库：

```
用户："明天有什么重要的事？"
  → 王语嫣查个人OS库（time-os.md + goals）+ 项目管理库（deadlines）
  → 返回：明天的优先级排序 + 时间分配建议

用户："鑫港湾销售下一步怎么推？"
  → 王语嫣查主库（销售方法论）+ 销售域库（客户档案）+ 项目管理库（鑫港湾状态）
  → 返回：基于方法论的销售策略建议

用户："KDO lint报错了"
  → 王语嫣查主库（基础设施状态）→ 路由给黄药师
```
