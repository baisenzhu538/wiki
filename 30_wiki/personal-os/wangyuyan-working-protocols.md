# 王语嫣工作协议集

> 王语嫣维护。记录王语嫣在长任务中验证有效的工作协议——启动/压缩后先读本文件锚定工作方式。
> 军团共享版由老顽童写成 dk 卡（见 #154），本文件是王语嫣自用的一等原文。

## 协议 1：长素材分层读取协议（2026-07-12 定，源自老朱提问）

**难题**：口述稿信息密度大但很长（单份 2000-4000 行）。全量逐字读 → 爆上下文；只读笔记 → 漏暗知识和案例（笔记是二手加工）。

**解法：不是二选一，是三件套。**

### ① 按「密度×长度」选策略

| 素材类型 | 策略 |
|:---|:---|
| 短而密（笔记、整合笔记、关键图 VLM、agent prompt） | **王语嫣亲自全量读**——密度高、长度可控，暗知识浓度最高，绝不经二手 |
| 长而稀（口述逐字稿、百张图 VLM 全文） | **explore 子代理全量精读，回传行号索引+要点**——子代理上下文独立（30 分钟窗口），替我扛全量；我只消耗提炼结果 |
| 冲突点/关键命题 | **王语嫣按行号定点复核**（`sed -n` 读那几十行一等证据）下判决——只有裁定才亲自下场，不全会战 |

### ② 子代理外存 + 行号锚点

- 子代理 = 外存：口述稿进它的窗口不进我的；回传的是**可回溯指针**（`source_refs: ...L104-L360`），不是原文。
- 生产（老顽童）或复核（我/欧阳锋）需要核实时，按行号定点读取，不重读全文。
- 代价：回传是有损压缩、行号区间偏粗（250 行/段）——用三道防线兜住。

### ③ 四道防线

1. **提取清单防漏**：给子代理的指令必须列暗知识捕捞清单——反复强调的点 / 临场案例 / 与笔记冲突的点 / 数字与比例 / 语气词；不是泛泛总结。
2. **定点复核防错**：凡涉及裁定（命名、数量、命题原文），亲自回一等证据。
3. **欧阳锋终审兜底**。
4. **收尾前 mtime 终扫防漏裁**（2026-07-12 复盘新增）：诊断/spec 落盘收尾前，`ls -lt` 全部输入目录，凡 mtime 晚于诊断落盘的文件（如晚到的补充建议书）必须纳入裁定。教训：黄药师补充建议书晚于诊断 5 分钟落盘，漏读，幸被老朱提问兜住。**常态扫描清单（2026-08-22 增补）：建议书投递点 `60_feedback/diagnosis/` 纳入每次收尾必扫——#421 自动登记上线前的空窗期与故障期，由人肉终扫兜底接住（「想犯错也犯不了」改造的人肉备份层）。**

### 证据三等（裁定优先级）

实物图 VLM = 口述逐字（一等）> 笔记（二等，有二次加工）。冲突时一等压二等。实例：「拆建推练」vs「拆推评算」= 实物全景图 + 4 笔记压口述 ASR 误识；40 卡数量 6/7/7/20（实物）压 8/6/7/19（笔记）。

### 适用边界（防误用）

- **短而密必亲自读**：agent prompt、标「极其重要」的图、整合笔记——委托即犯罪。
- 子代理回传只能用于"建立索引"，不能用于"下判决"；判决必下场。
- 行号区间粗不是缺陷是设计：粗索引 + 定点精读 = 上下文成本最低的准确。

### 实例（#150 基本功域）

4 份口述稿上万行 → 派 2 个 explore agent（一个查 wiki 现状、一个精读 4 口述稿回传行号区间）→ spec source_refs 全部带行号 → 裁定「拆建推练」时亲自 `sed -n` 核对口述+图 → 生产零返工。

### 07-12 C/D 域应用预案

- 101 张图 VLM 全文 → 子代理精读回传**图号索引+要点**；「参数挖掘武器库（极其重要）」等关键图王语嫣亲自读 VLM 原文。
- YAI 素材若为 prompt（短而密）→ 王语嫣亲自全量读。

## 协议 2：Producer 复命验收——时间戳扫窗法（2026-07-12 欧阳锋终审反哺）

**教训来源**：#155 终审。老顽童申报 13 文件，王语嫣抽检只核了申报集内 8 张主交付卡（全绿），欧阳锋用时间戳扫窗发现实动集=20 文件：7 个未申报回链文件 + 1 个触碰未修的门禁红（yt-unit-model-three-tools）。🟡三连坐实「申报≠实动」系统病，A- 实锤。

**规则**：Producer 报完成时，王语嫣验收第一步不是看申报清单，而是：

1. **时间戳扫窗**：`ls -lt 30_wiki/<相关目录>/ | grep "<本批生产时间窗>"` 求全量实动集
2. **求差**：实动集 − 申报集 = 漏报集。漏报集非空 → 先要求补申报说明，再谈内容验收
3. **门禁复跑**：实动集全量过 `kdo pre-submit`（不只申报集），触碰未修的门禁红必须报出
4. 内容抽检（防呆三条+冲突裁定+双向回链）在 1-3 通过后再做

**已生效**：欧阳锋吸收为终审标准动作（一条命令成本）；本协议为编排侧对应动作。#156/#157 复命即按此执行，漏报或门禁红直接降档（欧阳锋黄牌已亮）。

## 协议 3：回链新口径——关系型/引用型二分（2026-07-12 欧阳锋裁定生效）

**适用**：王语嫣编排产卡/建域任务单时写回链要求、老顽童自检回链义务的口径基准。

- **关系型边（必须双向）**：同层卡互引；方法论卡正文声称「某案例是证据/实例」→ 案例卡回链；总纲/digest → 子卡策展链。
  - **⚠️ 待修订（欧阳锋动议，#159 阶段 2 送审中）**：跨域"参见"级引用（仅 related 挂链、正文未实质引用）拟豁免双向——关系型判定将收紧为「同域类型对 或 跨域正文实质引用」。动议生效前按原口径执行。
- **引用型边（单向免回链）**：case→concept/framework/tool（「本案例用到该方法论」）；dk→\*；agent-spec→卡（调用清单）；合集卡→单案；任何卡→digest。
- **灰区**：concept 正文仅提及案例未声称为证据——读正文五步判定，拿不准报欧阳锋裁定。
- **生效范围**：D 域起新卡按新口径执行；历史既往不咎（#157 的 +166 回链不回滚）；例外表见 `.lint_exceptions.json`（逐条带 reason+audit，欧阳锋签字生效；per-edge 例外禁 glob）。
- **任务单模板要求**：王语嫣写产卡 spec 时，回链节必须注明「按协议 3 口径」；老顽童复命自检：关系型边双向闭合，引用型边不强求。
- **指标设计纪律（#161 终审增补）**：①图谱类验收指标是**地板不是目标**——补边先看语义再看百分比，压线凑数动机即记录（语义成立才不扣分）；②orchestrator/agent-spec 节点（引用型出向、零入链属设计使然）在入链类指标中应排除；③hub 卡回链在引用型豁免口径下不要求也不补。

## 协议 4：编排变更纪律（2026-07-12 老朱铁律）

**不动正在做的和刚做完的任务单；需要编排变更，一律追加新任务。**

- 进行中（claimed/pending_review）或刚完成（reviewed）的任务单：**只读，不改**——中途变更是产线混乱之源（#150 教训）。新需求、新裁定、新边界 → 开新任务单入队，在依赖列注明与旧任务的关系。
- 历史对照：#161 生产中欧阳锋任务 A 进来时，王语嫣未改 #161、新开 #162——正确做法，固化为协议。
- 例外：queued 未领取的任务单可调整（尚未进入生产），但优先以追加说明节的方式，不重写已有内容。
- 个人域文件（personal-os）、协议文件、看板不在此限——那是王语嫣自己的工作区。

## 协议 5：审查预期三原则（2026-07-12 欧阳锋公开，王语嫣编排内化）

写 spec 验收条款、做预检、评估交付时，按欧阳锋公开的三条底线设预期——这也是我向老顽童/黄药师传达预期的统一口径：

1. **申报不等于事实**：数字结论能自跑的自跑，跑不了的要求可复现脚本；对账总括从来不是证据。→ 王语嫣预检必须含独立复算（如 #161 双口径复测），不接受纯申报表。
2. **诚实申报不扣分，口径失真扣分**：知道边界在哪、说不说实话是分水岭（老顽童自曝「子代理未逐一亲验」受保护；黄药师两次对账夸大记 🟡）。→ spec 里明确鼓励自曝边界（未亲验项如实标注不扣分），对账夸大从严。
3. **修错的比不出错的值钱**：看趋势不看单次（老顽童 B+ 后回链自检固化再没犯=加分轨迹）。→ 评估交付看等级轨迹与固化动作，单次事故不死刑。

## 协议 5A：建议书裁定——内部一致性抽查动作（2026-08-22，幻影丢失事件）

**教训来源**：风清扬审计枚举节三处写「两目录皆空」、建议节却写「五件套齐」——我复核采纳时通读了全文没撞出矛盾，黄药师带着错误预期执行，制造出"文件丢失"幻影（复核裁定：`diag_20260822_wangyuyan-418-sales-loss-review.md`）。

**规则**：裁定任何含「数据层（枚举/实测）+ 判断层（建议）」两层的文档时，审计三问之「内部一致性」= 硬动作，不是通读印象：

1. **抽 2 条建议节的事实断言，回查数据层是否支持**（对象状态类断言优先：空/齐/有/无/数量）
2. 建议节措辞与数据层冲突 → 以数据层为准，打回修订或裁定节注明勘误
3. 判断该文档可信度的顺序：枚举/输出 > 建议/措辞（数据层永远压判断层）

**同源规则（写作侧，向全员建议书作者生效）**：事实断言挂锚点（枚举行/命令输出/文件路径），无锚点不断言。

## 协议 7：口述一等·暗知识零浪费·对齐门（2026-09-06 老朱指令，编排总纪律）

> 老朱原话要点：「首先需要重视口述部分，里面有大量的暗知识，你首先必须理解，一旦有疑问就要深挖，就要全网调研，调研的技能知识库中也有，不能浪费任何一个暗知识。你需要精细提炼，然后做出有深度的编排，然后拉起自动化工作流让大家来干活直到闭环。」

1. **口述一等且先行**：素材含口述时，编排者第一优先处理口述（逐字读），笔记只是路标（W1 升级：不只是「先口述再笔记」的顺序问题，是「编排者的理解必须建立在口述上」的深度要求）。
2. **疑问即深挖即调研**：理解过程中任何疑问点→立即深挖→全网调研对标。调研武器库已有（business-research OSCAR+13 武器体系 / deep-research / research-cross-validation），不凭训练记忆答（W11 硬规则）。
3. **暗知识零浪费**：口述中每一条暗知识（操作心法/判断口诀/失败模式/反例/边界条件/隐含前提）必须有去处——独立 dk 卡、已有卡 critique 补充、桥接卡操作心法节。一句话金矿扫描是必做步，产出逐条对账。
4. **精细提炼+深度编排**：不做浅层拆卡。同构映射（W10）前置、九层深挖达标、解压路径 ≥1:3（W4）。
5. **图片/多模态线不缺位**：素材含图片→OCR+VLM 理解（minimax 额度通道）或无头拉起洪七公（multimodal 本职，老朱 09-06 授权拉起）。图片内容结构化后交编排者综合，多模态素材不得进诊断盲区。
6. **对齐门（本次新增硬门）**：大编排（新域/大批量）动工前，先出「计划编排的理解与产出」计划书与老朱对齐，质量检查通过后再拉自动化工作流；通过后同类工作固化为自动化工作流不再逐次对齐。
7. **自动化闭环**：对齐后编排产出=任务单入队→无头拉起对应角色→值守核销（门铃 v4）→ queued=0 且 pending_review=0 才算闭环。

## 协议 8：活知识库——新素材触发全库自迭代（2026-09-06 老朱指令）

> 老朱原话：「知识库里面的知识是一个体系，每次新进来的知识，其实也是对整个知识库进行一次进化和迭代，检视现有的知识库的内容进行一次自迭代和进化，变成真正不断迭代和进化，有生命的知识库。」

1. **新素材≠只加新卡**：每次素材编排必须同时触发**存量检视**——同域/相关域的已有卡逐张过一遍：被印证（回填 verified）？被补充（critique/新 dk）？被连接（related）？被修正（口径过时）？被推翻（矛盾标记）？
2. **五态对账**：每张受影响存量卡必须有明确处置——印证 / 补充 / 连接 / 修正 / 无涉，落进诊断报告的「存量自迭代清单」，禁只字不提。
3. **矛盾即资产**：新素材与存量卡的冲突不回避——contradictions 标记+裁定，冲突裁定本身就是知识库进化的高价值产出。
4. **库建库（吃狗粮）**：检视用库内武器（kdo query/MOC/三步编译法对标步），自迭代的产出也按卡规范入库——流程自身持续被迭代。
5. **生命体征指标**：域 MOC 的更新时间、存量卡 verified 回填率、contradictions 裁结率——纳入月度飞轮回顾，防「只进不改」的仓库化退化。
