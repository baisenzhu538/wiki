# 老朱代码库AI编排项目

## 场景

用 AI 梳理一个积累了 10 年的智能医药领域大型代码库（智能硬件软件 + SaaS 硬件管理平台 + 运营中台，.NET + Vue，约 5G），最终实现单人 + AI 维护和开发。

## 已识别的工作模式

### 1. 不懂代码但 AI 协作极强

- 曾用 Claude 从 0 到 1 做过轻量级诊所 SaaS 系统
- 主要用 Kimi 大模型（国内拿不到 Claude 原生）
- 工具组合：Claude Code / Codex / Kimi Agent 集群 / GLM 5.2 待测
- 核心卡点：AI 上下文不够大、注意力分散、失忆

### 2. Agent 角色体系

- 系统编排 Agent：负责整体路径设计
- 代码编写 Agent：负责具体实现
- 审查 Agent：负责质量把关
- 规范记录 Agent：专门负责规范和踩坑的记录和迭代
- 产物：EC 工业化规范手册（1000字→30万字）+ 20 条 Agent 铁律

### 3. 实证验证风格

- 判断标准：能部署到真机、跑通业务、效果对
- 不靠看代码，靠实际运行效果
- 独特优势：熟悉业务、手上有真机

### 4. 多 AI 交叉比对策略

- 同一任务让多个 AI 分别分析
- 将分歧结果互喂→多轮辩经直到收敛
- "AI 比较实事求是，不太像人会有立场和情绪"

### 5. 时间敏感的约束

- 现有开发人员可能 3 个月后离职
- 核心知识需要尽快从人转移到自己或 AI 手中
- 硬件通信协议（CAN 总线）资料未整理，原硬件工程师已离职
- SVN 代码可能不是最新——2024 年后部分修改未提交

### 6. 硬边界

- 硬件接口不动——同协议、同驱动、同指令集
- 新系统最终替代老系统，老客户逐步迁移
- 核心内容必须掌握在公司法人（自己）手上

### 7. 远期方向（创造力角）

- AI 原生开发平台
- 智能医药 OS
- 可交易资产（代码资产包 + EC 手册 + Agent 体系打包）
- 借重构重新定义产品

## 当前行动

- M1 试点：选一台设备的 CAN 协议资料，走通完整闭环
- 生产环境代码导出 + SVN 差异对比
- 3 个月窗口内抢救开发人员口头知识
