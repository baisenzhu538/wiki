# Y模型双姿原则：实事求是 + 解放思想

> **一句话定义**：在 Y模型 引擎循环中，**实事求是**负责把认知锚回事实端，**解放思想**负责把认知推离既有范式；二者不是二选一，而是在步骤 6/7 连续切换的「双姿」——先校准，再突破，缺一则循环失速。

---

## 核心主张

Y模型 的底层结构是「一根（客观因果规律）、双路径（理论端 + 事实端）、三姿势」。在三大姿势中，**实事求是**与**解放思想**构成一对互补的校准 - 突破双姿：

| 双姿 | 在 Y模型 中的功能 | 核心问题 | 输出 |
|:---|:---|:---|:---|
| **实事求是** | **事实端校准器** | 「我现在的认知里，哪些是事实、哪些是假设、哪些是信念？」 | 事实 / 假设 / 信念三列表 |
| **解放思想** | **理论端突破器** | 「我现在的认知里，哪些隐含假设从未被挑战过？」 | 隐含假设清单 + 替代路径 |

**关键主张**：
1. **实事求是不是保守，而是精确**。它不让团队停留在「我觉得」「应该是」，而是要求把「我希望是真的」和「事实是什么」分开。
2. **解放思想不是天马行空，而是有纪律的突破**。它必须在尊重事实的前提下进行——没有实事求是作为前序，解放思想容易沦为妄想。
3. **二者在引擎循环中连续触发**：步骤 6 输出「信念列」，步骤 7 以「信念列」为攻击目标；步骤 7 输出的新假设，又必须回到步骤 4/5 用实事求是的方法验证。

> 参见：[[yt-decision-y-model]]（四层结构）、[[method-yitang-y-model-engine-cycle]]（10 步操作法）

---

## 双姿在 Y模型引擎循环中的位置（步骤 6/7）

Y模型 引擎循环的完整操作法见 [[method-yitang-y-model-engine-cycle]]。双姿原则聚焦其中的步骤 6 与步骤 7：

```
步骤 5：运行实验，收集事实
           ↓
步骤 6：实事求是 —— 区分事实 / 假设 / 信念
           ↓  信念列进入下一步
步骤 7：解放思想 —— 挑战隐含假设
           ↓
步骤 8：更新框架认知 V2
           ↓
步骤 9：知行合一 —— 用新认知解决真实问题
```

### 步骤 6：实事求是 —— 事实端校准器

对照实验日志，把当前认知拆成三列：
- **事实**：有数据或可直接观察的支撑
- **假设**：尚未充分验证，但可证伪
- **信念**：没有直接证据，但团队深信不疑

**校准后分支**：
- 如果事实足够支撑决策 → 跳过步骤 7，进入步骤 9（知行合一）
- 如果发现大量信念 → 必须进入步骤 7（解放思想）

### 步骤 7：解放思想 —— 理论端突破器

以步骤 6 的「信念列」为攻击目标，逐一审视隐含假设：
1. 这个假设在什么情况下不成立？
2. 如果完全没有这个限制，我会怎么做？
3. 有没有人打破过这个假设？

**突破后分支**：
- 形成新的关键假设 → 回到步骤 4（实践侧·假设驱动），设计验证方案
- 发现更底层规律 → 更新框架认知 V2 → 进入步骤 8

> 完整触发与衔接逻辑参见：[[framework-yitang-shishi-qiushi]]、[[framework-yitang-jiefang-sixiang]]

## 触发信号表（何时实事求是 / 何时解放思想）

### 何时启动实事求是

| 信号 | 典型话术 | 即时动作 |
|:---|:---|:---|
| 主观臆测泛滥 | 「我觉得」「应该是」「肯定是」频繁出现 | 把「我认为」转写为「我假设」，并追问证伪条件 |
| 数字口径混乱 | 同一个数字被不同人引述时差 2 倍以上 | 回到原始定义：指标是什么？统计口径是什么？来源是什么？ |
| 高度一致但无反证 | 团队对结论高度一致，但说不出反面证据 | 强制红队 / 魔鬼代言人角色，列出 3 条反面证据 |
| 假设长期「优化中」 | 一个假设被验证超过 3 轮仍在调整，没有实质更新 | 重新区分事实 / 假设 / 信念，确认是否有信念伪装成假设 |
| 准备对外承诺 | 路演、发布、签约前 | 对外承诺 ≤ 内部能力的 70%，每个数字附带假设与置信度 |

### 何时启动解放思想

| 信号 | 典型话术 | 即时动作 |
|:---|:---|:---|
| 多轮优化无突破 | 团队在细节上反复打磨，但问题本质未变 | 暂停优化，列出所有「这件事只能这样做」的默认前提 |
| 行业常识成挡箭牌 | 「行业都这样做」「不可能改」「一直是这样的」 | 追问：这个常识的前提条件是什么？当前场景是否满足？ |
| 实事求是后发现信念 | 步骤 6 区分出大量「信念」 | 把信念列作为步骤 7 的攻击目标 |
| 竞品用了不同解法且有效 | 「他们居然这么做，还能成？」 | 跨界类比：source 解法是什么？target 场景的关键差异是什么？ |
| 问题边界被锁死 | 「我们必须用 XX 工具 / 走 XX 流程」 | 极端场景假设：如果完全没有这个限制，我会怎么做？ |

### 双姿切换规则

```
遇到问题
   ↓
是否需要先确认事实？ ——是→ 实事求是（步骤 6）
   ↓ 否
是否已有可行动方案？ ——是→ 知行合一
   ↓ 否
是否被隐含假设锁死？ ——是→ 解放思想（步骤 7）
   ↓
回到步骤 4/5 验证新假设
```

## 边界条件与误用风险

### 适用边界

| 边界 | 说明 |
|:---|:---|
| **需要可验证的事实输入** | 实事求是无法在没有数据、观察或实验条件的情况下运行；此时应先做最低成本情报搜集，再启动校准。 |
| **解放思想需要 L1/L2 积累** | 没有事实与常识积累直接跳到 L4/L5，容易变成空谈。参见 [[framework-yitang-jiefang-sixiang]] 的 L0-L4 修炼路径。 |
| **二者是诊断工具，不是每次必走完的 SOP** | 简单问题或已有成熟工作流的场景，不必强制启动完整双姿流程。 |
| **组织文化是基础设施** | 如果团队不鼓励暴露错误、不保护说反话的人，红队、魔鬼代言人都会流于形式。 |

### 常见误用

| 误用 | 症状 | 修复 |
|:---|:---|:---|
| **用解放思想逃避实事求是** | 「我们先颠覆一下」→ 回避收集反证 | 解放思想必须以步骤 6 的「信念列」为输入，不能凭空启动 |
| **用实事求是扼杀创新** | 过早强调「事实」，让团队不敢提出大胆假设 | 区分「验证阶段」与「构想阶段」——构想阶段允许定性草案，验证阶段再严格定量 |
| **双姿循环但不行动** | 反复做步骤 6-7，从不进入步骤 9 | 每轮循环必须产出一个 48 小时内可验证的最小动作 |
| **把信念当事实捍卫** | 步骤 6 区分出的信念，在步骤 7 中被团队拒绝挑战 | 引入外部视角或未参与项目的人独立审阅 |
| **跨域照搬** | 把 A 域的「解放思想成果」直接平移到 B 域 | 类比只作说明，决策前列出 source/target 关键差异 |

## 跨域示例

### 1. 需求分析：冰山 L4/L5 前的方案中立

- **情境**：产品团队想做一个 CRM 功能，已经画出 PRD。
- **实事求是**：用需求冰山 [[framework-demand-iceberg]] 下钻到 L4/L5，区分「用户说想要 faster horse」（事实：用户描述）与「用户真正需要更快到达某地」（假设：深层需求）。在 L4/L5 验证前，禁止锁定产品形态。
- **解放思想**：如果「CRM」这个品类本身是被 Salesforce 定义的隐含假设，挑战它——用户的问题是否一定需要一个 CRM 来解决？能否是一个工作流自动化 + 消息提醒的轻量组合？
- **双姿切换**：先实事求是（拆推评算 → 事实端），再解放思想（挑战「必须做 CRM」的品类假设），最后回到实事求是（用新形态做最小验证）。

### 2. 产品内核：关键假设 + 做减法

- **情境**：创业团队想在一个产品里同时满足企业客户、个人用户、开发者三类需求。
- **实事求是**：产品内核三问验证——「聊问查测盘赌」收集事实，判断哪类需求有真实付费意愿和可触达渠道。
- **解放思想**：挑战「产品必须大而全才能成功」的隐含假设，思考「砍掉 80% 功能反而更能击穿单点」的可能性。
- **双姿切换**：实事求是发现「三类需求的真实数据差距大」→ 解放思想提出「单点击穿」替代路径 → 实事求是验证新内核的付费转化。

### 3. 科学销售：前三秒话术 vs 需求探索

- **情境**：销售团队把成熟话术直接用于早期潜在客户探索。
- **实事求是**：区分「已验证的成交场景」（事实：成熟客户、已知痛点）与「早期需求探索场景」（假设：客户是谁、痛点是什么）。
- **解放思想**：挑战「销售必须快速成交」的行业常识——在早期需求探索阶段，销售的 KPI 是否可以是「认知收获」而非「成交额」？
- **双姿切换**：先用实事求是识别阶段（需求分析 L4/L5 前禁止产品形态，销售早期同样禁止成交话术），再用解放思想重新定义销售动作，最后用新指标验证。

### 4. 时间管理：时间审计 + 双峰工作法

- **情境**：个人感觉自己每天很忙，但关键项目没有推进。
- **实事求是**：先跑一周时间审计，记录时间切片与产出效率，区分「真实工作时间」与「被会议/消息切碎的时间」。
- **解放思想**：挑战「必须 9-18 点均匀工作」的默认节奏，尝试「大对大、小对小、双峰」的非标准排程。
- **双姿切换**：实事求是给出基线数据 → 解放思想提出新工作节奏 → 实事求是做双周假设实验，对比产出效率。

> 跨域总框架与更多域映射参见：[[framework-yitang-y-model-cross-domain-fusion]]

## When to Use / When NOT to Use

### When to Use

- 面对复杂、模糊、跨域的新问题，需要同时防止「拍脑袋」和「分析瘫痪」。
- 团队对某个结论高度一致，但缺乏反面证据或关键数字口径不清。
- 项目在多轮优化后没有实质突破，怀疑被隐含假设锁死。
- 需要把一个域的洞察迁移到另一域，既要尊重事实差异，又要打破范式束缚。
- 作为 Agent 调用规则：跨域 Coach Agent 在路由前先用实事求是做事实充足度审查，再用解放思想做范式突破建议。参见 [[agent-spec-yitang-Y-model-cross-domain-coach]]。

### When NOT to Use

| 场景 | 原因 | 替代方案 |
|:---|:---|:---|
| 一次性、低风险的微型决策 | 分析成本超过决策收益 | 直接用经验法则或快速试错 |
| 答案已知或已有成熟 SOP | 不需要升级认知 | 执行现有流程 |
| 信息完全封闭、验证周期远超决策窗口 | 强行事实端会陷入分析瘫痪 | 先做情报搜集，或用概率加权做决策 |
| 品味 / 意义型决策 | 不可通约的价值无法被事实端充分捕捉 | 用审美判断框架或集体决策机制 |
| 高压情境下的专家直觉决策 | 结构化分析可能成为负担 | 信任经过训练的模式识别，事后复盘 |
| 团队缺乏心理安全感 | 红队、挑战隐含假设会流于形式或引发冲突 | 先建立安全沟通规则，再引入双姿 |

## Critique

### 外部反对者

1. **Daniel Kahneman（判断心理学 /《噪声》）**：
   实事求是能减少系统偏差，但无法消除判断噪声——同一关键参数不同专家估计可能差数倍。把「事实 / 假设 / 信念」三列表当成决策基础，可能会把不一致的估计包装成精确数字，反而掩盖分歧。

2. **Paul Feyerabend（科学哲学，《反对方法》）**：
   重大科学突破并非都遵循「假设 - 验证 - 迭代」的规范路径。把「实事求是 + 解放思想」包装成普适双姿，可能混淆科学的公共关系宣传与科学真实发生的混乱过程。

3. **Seymour Papert（建构主义）**：
   最深刻的学习发生在「用手建造可分享物件」的过程中，而非先做完整的事实 / 信念区分。对初学者来说，双姿流程可能制造认知门槛，让他们迟迟不敢写出 V1。

4. **组织行为学视角**：
   解放思想要求挑战隐含假设，但在权力不对等或高压文化中，这容易被理解为「质疑领导」。如果缺乏心理安全感，双姿会形式化，甚至成为政治斗争工具。

### 内部局限

1. **步骤 6 的质量取决于输入事实的质量**：如果时间审计、实验日志、访谈记录本身有偏差，实事求是校准只会把偏差结构化，而不会消除偏差。

2. **解放思想需要足够的领域积累**：没有 L1/L2 的事实与常识，直接跳到 L4/L5 容易变成空谈或类比滥用。

3. **双姿循环有跳过「知行合一」的风险**：分析比执行轻松，团队可能在步骤 6-7 反复循环，却迟迟不进入步骤 9。

4. **对 Agent 的依赖增加了新风险**：跨域 Coach Agent 若错误识别阶段，可能把需要实事求是的问题路由到解放思想，或反之。参见 [[agent-spec-yitang-Y-model-cross-domain-coach]] 的边界声明。

## Synthesis

**Y模型双姿原则**把「实事求是」与「解放思想」从抽象口号，转化为 Y模型 引擎循环中可操作的步骤 6/7：**实事求是是事实端校准器，确保认知不脱离现实；解放思想是理论端突破器，确保认知不被既有范式锁死。** 二者不是对立选项，而是同一循环中的连续动作——先校准，再突破，再验证。

在跨域场景中，双姿原则提供了一套通用的诊断语法：
- 需求分析：先实事求是下钻冰山，再解放思想挑战品类假设。
- 产品内核：先实事求是验证关键假设，再解放思想做减法。
- 科学销售：先实事求是识别阶段，再解放思想重新定义 KPI。
- 时间管理：先实事求是审计时间，再解放思想尝试非标准节奏。

本原则是 [[framework-yitang-y-model-cross-domain-fusion]] 的元规则之一，也是 [[agent-spec-yitang-Y-model-cross-domain-coach]] 进行跨域路由与审查时的核心判断依据。使用时应警惕其成本、数据门槛和仪式化风险——它不是每次决策都必须走完的 SOP，而是卡住时用来定位下一步的诊断工具。
