# 组织资产：从直线运动到圆周运动

> **Burn line**：组织最大的浪费不是人不够努力，而是每一次行动都从零开始。

---

## 原始表述

兰毅在分享中反复区分两种组织运行方式：

> 「直线运动就是发起，我做，做完结束了，没有了。你下次再来，还得又发起、催促、验收。这样人会累，组织也不会变强。」`[conf=0.95, source=00_inbox/泛产品设计/兰毅-用泛产品思维做组织-逐字稿.md]`

> 「更好的方式，是把直线运动变成圆周运动。每一次行动，都要留下东西：流程、文档、模板、训练出来的人、被验证过的经验、下一轮可以复用的资产。」`[conf=0.95, source=00_inbox/泛产品设计/兰毅-用泛产品思维做组织-逐字稿.md]`

> 「我带实习生的时候，先设计入口、设计新手任务、设计能力阶梯、设计反馈机制、设计晋级方式。后面就开始想，能不能让实习生招募实习生、培养实习生。这就从直线运动变成了圆周运动。」`[conf=0.90, source=00_inbox/泛产品设计/兰毅-用泛产品思维做组织-逐字稿.md]`

---

## 一句话定义

**组织资产：从直线运动到圆周运动**是指：把组织协作从「发起—推动—结束—再重来」的一次性消耗模式，改造成「行动—沉淀—复用—增强」的循环模式，让团队每跑一轮都留下可复用的流程、知识、人才和关系资产。

---

## Claims

### 断言 1：组织协作层面的主要浪费来自「直线运动」
在「如何把一群人组织起来持续创造价值」这个维度上，传统管理把协作当成「事件」：项目来了就动员，项目结束就散伙，下次重新建立信任、重新分工、重新磨合。组织协作层面的最大成本不是成员不努力，而是每一次行动都从零开始，无法把经验、流程、关系转化为下一轮的能力。这并不意味着战略错误、产品失败等其他浪费不存在，而是在协作设计维度上，直线运动是最隐蔽也最普遍的浪费来源。

### 断言 2：把协作改造成「圆周运动」能让组织自我增强（条件性因果）
泛产品组织设计把协作当成「资产生产」：每次共同行动不仅完成当前目标，还要沉淀能让下一轮更轻松的组织资本。当流程、知识、人才、关系四类资产持续积累，并且成员需求被真正满足时，组织更可能进入规模越大效率越高的增强回路。这不是自动发生的：它依赖领导者愿意从控制转向服务、愿意持续迭代、愿意把资产绑定到真实工作流中。

### 断言 3：圆周运动的关键是「成员即用户」与「领导者即飞轮设计师」
成员不是工具，而是有需求、有动力、有阻力的用户。领导者不是发动机，而是服务系统的设计师：设计入口、能力阶梯、反馈机制和分权结构，让成员互相服务、互相成就。

### 断言 4：圆周运动不是大组织专利，小团队更需要
小团队、实习生项目、临时战队最容易停留在「靠创始人个人记忆续命」的状态。越早建立最小资产闭环，组织越能摆脱对个人依赖，进入可持续成长。

---

## 为什么值钱

### 它把组织从「损耗模式」变成「增益模式」

兰毅指出：「管理思维走偏，很容易把人当工具。产品思维会把参与者当用户，考虑他的需求、动力、阻力、成长、反馈。」`[conf=0.92, source=00_inbox/泛产品设计/兰毅-用泛产品思维做组织-逐字稿.md]` 当成员需求被满足，动力来自内部，组织运行从「催、赶、救火」的损耗模式，变成「互相服务、自我增强」的增益模式。

### 它让规模成为优势而非负担

按常理，组织规模越大，数据越容易下滑。兰毅世董会与 NPC 的案例却出现反常：月活动量达到 **160+ 场/月**，累计 **2000+ 场**；成员留存率从 60% 提升至 **71%**，NPC 留存率达到 **90%**；迭代增长率从 30% 提升至 **300%**。`[conf=0.80, source=00_inbox/泛产品设计/兰毅-用泛产品思维做组织-口述.txt]`（数字来自兰毅口述，待独立核实）这些数字暗示：产品化组织可以通过资产沉淀和飞轮结构，让规模扩大反而效率提升。

### 它降低对创始人个人能力的依赖

直线运动的组织里，创始人是唯一的发动机。圆周运动的组织里，创始人是飞轮设计师：设计服务系统、让成员相互服务、让资产自我迭代。这样创始人才能从「管人」中抽身，回到核心业务能力上。

## 使用场景

- **临时团队跑成一次性消耗**：大航海战队、副业实验组、项目突击队，成员动力靠创始人不断催，散伙后什么都没留下。
- **带实习生像「带新人—离职—再招人」的死循环**：每次都要重新培训、重新磨合，组织没有因为人而变强。
- **规模扩大反而效率下降**：人一多，信息乱、内耗多、创始人越来越累，靠增加会议和通知来续命。
- **社群/私域越做越重**：拉新、促活、维护全靠人工，没有产品化闭环，运营成本线性增长。
- **跨职能协作反复踩同样的坑**：上一次项目复盘的问题，下一次原样复现，没有形成组织记忆。

## 操作方法

### 第一步：识别最近一次「直线运动」

找一个做完就结束、下次从零开始的项目或协作。问自己：
- 这次行动留下了什么可复用的东西？
- 如果核心成员离开，下一轮还能不能跑？
- 同样的错误我们会不会再犯？

### 第二步：为关键角色写「用户需求卡」

| 维度 | 问题 |
|:---|:---|
| 表层需求 | 他/她想完成什么任务、获得什么履历/作品？ |
| 深层需求 | 成长、认可、确定性、关系、荣耀感，哪一项最突出？ |
| 当前阻力 | 时间、能力、情绪、关系尴尬，卡在哪里？ |
| 可设计触点 | 入口任务、能力阶梯、反馈节奏、晋级方式 |

兰毅带大航海战队时，先不分配任务，而是分析成员在不确定环境中需要「目标感、连接感、被鼓励、作品感」。`[conf=0.90, source=00_inbox/泛产品设计/兰毅-用泛产品思维做组织-逐字稿.md]`

### 第三步：设计最小闭环

从以下四类资产中至少选一类，设计一个最小可沉淀单元：

| 资产类型 | 最小沉淀单元 |
|:---|:---|
| 流程资产 | 一个会议模板、一个决策 checklist |
| 知识资产 | 一页复盘纪要、一份失败清单 |
| 人才资产 | 一个可被复制的角色能力描述 |
| 关系资产 | 一个新人对接人和反馈机制 |

### 第四步：跑一周后科学复盘

兰毅建议：「每周复盘一个卡点。哪里卡了？为什么卡？下周只改一个动作。组织产品和普通产品一样，都是一版一版打磨出来的。」`[conf=0.90, source=00_inbox/泛产品设计/兰毅-用泛产品思维做组织-逐字稿.md]`

### 操作口诀

```
先拆需求，再定内核；
先列最佳实践，再做加减法；
跑完一轮，沉淀四类资产；
下一轮从资产出发，而非从零开始。
```

## When NOT to Use

1. **成员没有基本共识和信任**：如果团队完全陌生、目标冲突或毫无信任，先做一次共同经历建立最小共识，而不是直接上复杂机制。
2. **创始人只想榨取成员价值**：圆周运动需要真诚地把成员当用户。如果真实意图是「让更多人免费干活」，产品化设计会变成更精致的剥削工具。
3. **业务价值尚未验证**：组织设计解决的是「人如何更好地协作」，不是「业务值不值得做」。方向错误时，精巧的组织只会加速失败。
4. **高度重复、无决策空间的任务**：如果工作本身像流水线一样单调，成员没有成长感和参与感，再精巧的设计也难以持续激发动力。
5. **强监管/强合规场景**：在金融、医疗、数据安全等领域，组织设计必须在合规框架内进行，不能简单套用「去中心化」「自主协作」的产品化逻辑。

---

## 适用边界

| 适用 | 不适用 |
|:---|:---|
| 成员之间有基本共识和信任 | 成员完全陌生、目标冲突、毫无信任基础 |
| 组织者愿意从控制转向服务设计 | 创始人只想快速榨取成员价值 |
| 业务价值已经初步验证 | 业务本身没有用户价值，组织设计只是加速失败 |
| 任务有一定成长空间和决策空间 | 任务高度重复、无学习曲线、无反馈 |
| 愿意接受小步迭代、每周只改一个卡点 | 追求一次性大刀阔斧变革 |

### 小团队 vs 大团队的不同做法

| 维度 | 小团队（<10人） | 大团队/社群（50+人） |
|:---|:---|:---|
| 核心挑战 | 个人依赖、记忆流失 | 熵增、内耗、质量衰减 |
| 资产重点 | 个人知识→团队模板 | 流程标准→角色复制机制 |
| 迭代节奏 | 每周一次小复盘 | 每月一次系统复盘+每周卡点修复 |
| 领导力重点 | 身先士卒、共创资产 | 设计服务系统、让成员相互服务 |
| 关键指标 | 新人能否独立上手 | 规模扩大后留存/质量是否提升 |

## 预警信号

- 每次项目启动都要重新解释「我们是谁、要做什么」。
- 核心成员一旦请假，项目进度就明显受阻。
- 同样的问题在三个月内出现第二次。
- 创始人参加的会议数量逐周增加。
- 新成员加入两周后仍不知道自己的价值点在哪里。
- 文档越写越多，但没人看、没人更新。

## Failure Modes：常见失败模式

### 失败模式 1：只做直线运动，不沉淀资产
- **症状**：每次项目从零开始、同样错误反复犯、核心能力依赖个别人。
- **修复**：每次行动后强制沉淀流程、模板、复盘、训练记录。

### 失败模式 2：把人当工具，只谈效率不谈需求
- **症状**：成员流失率高、积极性低、开会没人说话、交付质量差。
- **修复**：回到需求分析，为每个关键角色写用户需求卡。

### 失败模式 3：过度设计，一次性改十件事
- **症状**：组织变革轰轰烈烈，成员无所适从，很快回到老样子。
- **修复**：每周只改一个卡点，用小胜仗建立信心。

### 失败模式 4：创始人成为唯一瓶颈
- **症状**：所有决策必须过创始人、成员不敢自主、创始人越来越累。
- **修复**：设计分权机制、角色边界和反馈闭环。

### 失败模式 5：把资产当静态仓库
- **症状**：沉淀了很多文档但没人用，成为「僵尸 SOP」。
- **修复**：资产必须绑定真实工作流，每次使用前更新，每次使用后迭代。

## Critique：三派攻击与回应

### 6.1 精益创业视角（Eric Ries / Build-Measure-Learn）

**攻击**：「直线运动」未必是浪费。早期创业需要快速试错，过早沉淀资产会变成「过早优化」（premature optimization）。在方向未验证前，把每个实验都写成 SOP，反而会拖慢学习速度。

**回应**：
圆周运动不是「事事留文档」，而是「验证过的假设要留下、被否定的路径要留下、可复用的能力要留下」。精益创业强调「经证实的认知」（validated learning），而资产化正是把「经证实的认知」封装成下一轮实验的起点。两者不矛盾：快速跑循环，但循环的结果要变成资产。

### 6.2 组织行为学视角（Henry Mintzberg / 组织结构理论）

**攻击**：Mintzberg 指出组织有五种基本结构（简单结构、机械官僚、专业官僚、事业部制、adhocracy）。把组织当成产品来设计，可能过度简化权力、政治、文化的复杂性，忽视组织中的非正式网络和隐性冲突。

**回应**：
泛产品组织设计并不否认非正式网络的存在，而是为这种复杂性提供健康的表达通道和反馈机制。它替代的是「控制型管理」，而非「管理本身」。当组织规模扩大、成员异质性增强时，产品化设计反而能对冲政治损耗，让协作规则显性化。

### 6.3 复杂系统视角（Donella Meadows / 系统之美）

**攻击**：Meadows 提醒，系统中的「存量」会延迟反馈，过度强调资产沉淀可能让组织变得僵化，降低对变化的适应能力。组织资产一旦形成，可能成为路径依赖的枷锁。

**回应**：
资产必须是「活的」——绑定工作流、定期复盘、允许废弃。兰毅的案例中，迭代增长率从 30% 提升到 300%，正说明资产化与快速迭代可以共存。关键不是沉淀多少，而是沉淀后能否持续重构。

---

## Synthesis：从直线到圆周的迁移路径

如果你只有一个小时启动组织资产化，按这个顺序：

1. **识别一次最近的「直线运动」**：找一个做完就结束、下次从零开始的项目或协作。
2. **列出它留下的四类资产空白**：流程、知识、人才、关系，哪些完全空白？
3. **为关键角色写一张用户需求卡**：至少覆盖表层需求、深层需求、当前阻力。
4. **设计一个最小闭环**：一个会议模板、一个复盘清单、一个新人 onboarding 步骤。
5. **跑一周后复盘**：只改一个卡点，让资产在下一轮被使用。

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:---|:---|:---|
| 每次项目从零开始 | 建立组织资产清单 | 至少沉淀 1 个流程/模板 |
| 带实习生越来越累 | 设计「实习生成长产品」 | 实习生能独立完成一个最小任务 |

| 创始人成为唯一决策点 | 画组织决策流，找到创始人瓶颈 | 识别 3 个可授权的决策 |
| 老成员流失、新成员融不进来 | 建立「相互服务」的配对机制 | 每个新成员都有明确的对接人和反馈渠道 |
| 会议低效、互相甩锅 | 设计会议角色和产出模板 | 每次会议有明确的记录人和 follow-up |
