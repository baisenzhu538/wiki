# 找单元模型实操难点

## 原始表述

找单元模型不是从十大模型里挑一个名字，而是根据业务特征、发展阶段和决策目标，确定「以什么为最小可复制单元」来计算。一堂学员实操中高频出现的 8 类困难包括：十大模型不熟悉、核心单元模型锁定困难、业务和模型需动态调整、多模型计算混乱、模型改变缺时机、最虚指标识别困难、对十大模型的整体理解困难、模型颗粒度把握困难 [conf=0.85, source=原图]。

## 操作方法

1. **增加「非标业务 → 标准模型」映射指南**：列出 30+ 种非典型业务场景（跨境电商、社交电商、知识付费、加盟连锁等），分别对应哪几个标准模型 [conf=0.80, source=原图]。
2. **给出「加法 → 减法」标准 SOP**：第一步用十大模型清单逐条判断是否适用（15 分钟）；第二步在适用模型中做「三问锁核心」排序（10 分钟）；第三步确定 1-2 个核心模型集中力量算，其余标注为「后续跟进」[conf=0.80, source=原图]。
3. **制作「业务阶段 → 模型组合」对应表**：MVP 阶段盯「单订单 + 单用户」；区域复制阶段盯「单门店 + 单商圈」；规模化阶段盯「单城市 + 单 SKU」[conf=0.80, source=原图]。
4. **在触发条件清单中增加阶段切换触发信号**：如「门店数超过 5 家 → 开始计算单商圈模型」「城市数超过 3 个 → 开始计算单城市模型」[conf=0.80, source=原图]。
5. **建立「模型依赖关系图」**：画出十大模型之间的因果链——如单 SKU → 单订单 → 单用户 → 单门店 → 单商圈 → 单城市，前一个跑不通则后面的没有计算意义 [conf=0.80, source=原图]。
6. **统一数据口径词典**：在单元模型 Excel 模板中明确定义每个模型的数据口径，避免不同模型间数字口径不一致 [conf=0.80, source=原图]。
7. **将触发条件清单按「高/中/低」紧急程度分级**：高紧急 = 影响核心盈亏的变化；中紧急 = 影响次要指标的变化；低紧急 = 预判性计算 [conf=0.80, source=原图]。
8. **将「虚」量化为「波动率 × 影响权重」双维度矩阵**：对每个关键假设给两个分数——波动率和影响权重，乘积最大的就是最该盯的 [conf=0.80, source=原图]。
9. **给出「够用就好」的颗粒度标准**：预判期拆到能判断「做不做」就停；测试期拆到能判断「哪里需要调」就停；经营期拆到能判断「怎么优化」就停 [conf=0.80, source=原图]。

## 为什么值钱

选错单元模型，后续所有计算都是精确的废话。找单元模型难点的价值在于：它把「选尺子」的问题从直觉变成可检查、可讨论、可迭代的决策流程 [conf=0.75, source=一堂原创]。
