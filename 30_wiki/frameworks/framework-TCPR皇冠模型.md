# TCP-R皇冠模型

## 一句话定义

**TCP-R皇冠模型**是TCPR体系的高阶版本——以皇冠造型展示T(教学)、C(咨询)、P(实践)、R(研究)四大模块及其内部训练层级，是「能够统揽上万人的共识模型」 [conf=0.82, source=原图/VLM描述]。

## 皇冠结构

```
       T(教学)  C(咨询)  P(实践)
          \      |      /
           \     |     /
            R(研究) — 底座
```

| 层级 | 含义 |
|:---|:---|
| **重点训练** | 用十年心态磨牌，选你最核心的1-2个模块深度打磨 |
| **自己练** | 有敏感觉性，疯狂做——在自己业务中实战 |
| **在一堂练** | 从易到难挑战，用课程/训练营提供的阶梯 |

## 与底层TCPR协议的区别

底层TCPR（framework-TCPR底层网络协议）描述「是什么」，皇冠模型描述「怎么练」——从认知框架升级到训练体系。

## 每个模块 6 项核心训练

### T 教学 Teach：把复杂讲简单，让不同背景的人听得懂

| 层级 | 训练项 | 关键问题 |
|:---|:---|:---|
| 1 | **概念澄清** | 能否用一句话定义核心概念，并让外行听懂？ |
| 2 | **类比构建** | 能否找到 3 个不同领域的类比，帮助学员建立直觉？ |
| 3 | **结构拆解** | 能否把复杂流程拆成 ≤5 个可记忆的步骤？ |
| 4 | **案例映射** | 能否为每个抽象概念匹配 1 个真实案例？ |
| 5 | **互动设计** | 能否设计提问、练习、反馈，让学员主动思考？ |
| 6 | **认知迁移** | 能否让学员把所学迁移到从未见过的新场景？ |

### C 咨询 Consult：提问、诊断、助人决策

| 层级 | 训练项 | 关键问题 |
|:---|:---|:---|
| 1 | **信息收集** | 能否在 10 分钟内问清背景、目标、约束？ |
| 2 | **假设识别** | 能否把用户的隐含假设显性化？ |
| 3 | **根因定位** | 能否区分症状与根因，避免就表面问题给方案？ |
| 4 | **选项生成** | 能否给出 2–3 个可行路径，而不是唯一答案？ |
| 5 | **风险揭示** | 能否指出每个选项的关键假设与失败模式？ |
| 6 | **决策陪伴** | 能否帮助用户在不替 TA 决策的情况下做出选择？ |

### P 实践 Practice：躬身入局，拿结果

| 层级 | 训练项 | 关键问题 |
|:---|:---|:---|
| 1 | **目标拆解** | 能否把模糊目标拆成本周可执行的最小动作？ |
| 2 | **假设验证** | 能否为每个动作设计验证标准和放弃条件？ |
| 3 | **资源协调** | 能否识别并调动完成动作所需的人、财、信息？ |
| 4 | **执行纪律** | 能否在干扰中保持对关键动作的投入？ |
| 5 | **复盘迭代** | 能否从结果中提炼可复用的经验与失败信号？ |
| 6 | **规模化复制** | 能否把个人有效动作变成团队可重复的流程？ |

### R 研究 Research：建模、统筹、提炼可迁移规律

| 层级 | 训练项 | 关键问题 |
|:---|:---|:---|
| 1 | **现象观察** | 能否持续记录真实业务中的重复模式？ |
| 2 | **变量识别** | 能否区分关键变量与噪声？ |
| 3 | **模型构建** | 能否用简单模型解释复杂现象？ |
| 4 | **假设检验** | 能否设计对比/反例来测试模型边界？ |
| 5 | **跨场景迁移** | 能否把模型应用到不同行业/阶段？ |
| 6 | **行业标准输出** | 能否把模型沉淀为可被他人引用/验证的知识产品？ |

## 从训练体系到 Agent 角色切换

TCP-R 皇冠模型不仅用于训练人类，也用于指导 Agent 的**运行时身份切换**。

### Agent 训练层级映射

| 模块 | 人类训练 | Agent 能力要求 |
|:---|:---|:---|
| T | 概念澄清 → 认知迁移 | 能用用户语言解释方法论、给出示例、设计练习 |
| C | 信息收集 → 决策陪伴 | 能诊断问题、给出选项、揭示风险、不替决策 |
| P | 目标拆解 → 规模化复制 | 能拆动作、推动执行、复盘迭代、输出可执行清单 |
| R | 现象观察 → 行业标准输出 | 能跨案例比较、概率加权、提炼规律、输出分析报告 |

### Agent 角色切换与训练层级的对应

- **同一身份内深度切换**：例如 C 身份下，从 L1 信息收集切换到 L4 选项生成，对应咨询过程中从诊断到方案建议。
- **跨身份切换**：例如从 C（咨询）切到 P（实践），对应从「帮你选对路径」到「帮你把路径拆成动作」。
- **切换时调用训练项**：Agent 切换身份后，应默认激活新身份的 L1 能力（如 P 的「目标拆解」），再根据用户输入逐步升级到更高层级。

### 常见切换路径

| 起点 | 终点 | 触发场景 | Agent 行为 |
|:---|:---|:---|:---|
| C 咨询 | T 教学 | 用户说「教我一下为什么这么分」 | 切换到教学身份，解释方法论，给出练习 |
| C 咨询 | P 实践 | 用户说「直接给我本周跟进动作」 | 切换到实践身份，拆动作清单，标注验证标准 |
| P 实践 | R 研究 | 用户说「为什么总是卡在这个阶段」 | 切换到研究身份，跨案例比较，提炼卡点规律 |
| R 研究 | C 咨询 | 用户说「那我现在该先做什么」 | 切换到咨询身份，基于研究结果给出决策建议 |
| T 教学 | P 实践 | 用户说「我明白了，直接给我模板」 | 切换到实践身份，输出可执行模板 |

## When NOT to Use

- **任务单一且明确**：例如「把这段文本翻译成英文」不需要身份切换，直接执行即可。
- **用户明确拒绝身份协商**：尊重用户偏好，按指定风格执行。
- **危机响应或超短窗口**：先按 SOP 执行，事后复盘时再补身份分析。

## 失败模式

1. **把身份当人格**：认为「我是 C 型 Agent」就永远只能咨询，忽视同一会话内的切换需求。
2. **身份漂移**：不声明就切换，让用户困惑 Agent 为什么突然从诊断变成教学。
3. **切换后丢失上下文**：新身份不复述已确认事实，迫使用户重复输入。
4. **过度教学**：用户要动作时，Agent 仍停留在 T 身份讲方法论。
5. **过度执行**：用户要诊断时，Agent 直接跳到 P 身份给方案，跳过关键输入检查。

## Critique

1. **Howard Gardner（多元智能）**：T/C/P/R 四模块无法覆盖人际、内省、空间等智能；本模型更适合知识工作场景，不适用于所有能力盘点。
2. **Daniel Kahneman（噪声）**：身份切换可能引入判断噪声；同一会话内多次切换应明确继承事实与置信度，避免前后矛盾。
3. **用户视角**：身份协商增加了对话启动成本；可以通过 `tcp_session_opening` 压缩为一句话，并在高频任务中预置默认身份。

## Synthesis

- 本卡是 `framework-TCPR底层网络协议` 的高阶训练版本，回答「怎么练」而不是「是什么」。
- 本卡为 `agents/agent-os.md` 的身份切换协议提供训练层级依据：切换后应激活新身份的 L1 能力。
- 所有 `agent-spec` 卡的 `tcp_role` 字段可对照本卡的 6 项训练层级设计 System Prompt 行为。
- 与 `system-yitang-Y-model-os.md` 叠加使用：TCPR 决定「以什么身份协作」，Y模型决定「怎么结构化思考」。
