# 调研雷达图：四象限能力诊断与六种缺失识别

> **一句话**：调研失效往往不是"不会做"，而是"不知道自己哪里不会做"。四象限雷达图帮你定位能力缺口，六种缺失类型帮你识别具体症状。

---

## 核心框架：四象限雷达图

```
                    高度（系统式）
                         ↑
                         |
    深度（挖掘式） ←——— 原点 ———→ 宽度（爆炸式）
                         |
                         ↓
                    动态（自动式）
```

| 象限 | 调研类型 | 核心能力 | 追求 | 典型问题 |
|:---:|:---|:---|:---|:---|
| 左上 | 挖掘式调研 | 情报获取、社会工程 | 足够深 | 太浅就放弃、不敢用非主流方法 |
| 右上 | 系统式调研 | 结构化思维、清单管理 | 足够高 | 信息多但无决策价值、模板堆砌 |
| 右下 | 爆炸式调研 | 快速学习、信息压缩 | 足够宽 | 贪多嚼不烂、只有宽度没有深度 |
| 左下 | 自动式调研 | 机制设计、系统搭建 | 足够动态 | 依赖人工、没有监控机制 |

---

## 六种能力缺失类型（A-F）

### Type A：随机调研型

**症状**：
- 碰到了就研究一下，碰不到就按老方法做
- 没有计划，没有清单，想到哪做到哪
- 调研结果不可复现，下次同样问题重新来

**修复方法**：
1. 建立调研清单模板（OSCAR框架）
2. 每次调研前写3句话目标
3. 调研后写1页复盘

**对应雷达图**：四象限均弱，无系统能力

---

### Type B：大而全型

**症状**：
- 什么都想看，什么都没看透
- 报告很长，但无法回答"我该怎么做"
- 用SWOT/PEST/波特五力模板堆砌

**修复方法**：
1. 强制缩小范围（专注/专业/剥离三原则）
2. 明确决策问题，倒推需要哪些信息
3. 用"如果不知道这个，决策会错吗"筛选信息

**对应雷达图**：爆炸式过强，系统式不足

---

### Type C：案例太少型

**症状**：
- 只有理论框架，没有真实案例支撑
- 无法判断信息可信度
- 遇到反例就崩溃

**修复方法**：
1. 每个判断至少配1个真实案例
2. 建立案例库（成功+失败）
3. 用"这个案例在什么条件下成立"追问

**对应雷达图**：系统式过强，挖掘式不足

---

### Type D：忽略同行型

**症状**：
- 只看自己，不看竞品
- 不知道行业标杆怎么做
- 重复发明轮子

**修复方法**：
1. 建立竞品监控清单（Top 5）
2. 定期竞品拆解（季度）
3. 参加行业会议/社群

**对应雷达图**：自动式不足，信息源单一

---

### Type E：深度不足型

**症状**：
- 调研很浅，想挖但挖不着
- 停留在公开信息，拿不到水下情报
- 关键数字缺失或不可靠

**修复方法**：
1. 学习社会工程技巧（合法合规）
2. 建立专家网络
3. 练习"不择手段"的挖掘心态

**对应雷达图**：挖掘式不足，其他象限正常

---

### Type F：机制缺失型

**症状**：
- 每次调研从零开始
- 没有信息积累，没有知识库
- 团队调研能力无法复制

**修复方法**：
1. 建立调研知识库（按类型/行业/项目分类）
2. 设计调研SOP和模板
3. 培养团队调研能力，不是只有一个人会

**对应雷达图**：自动式严重不足，其他象限可能正常

## 自检问题清单

### 基础自检（5分钟）

1. 我能否在5分钟内说出当前项目的5个关键信息缺口？
2. 我上次调研的结果，现在还能找到并复用吗？
3. 我知道行业Top 3竞品的最新动态吗？
4. 我的调研有明确的决策问题吗？还是"了解一下"？
5. 我能说出至少3个调研失败的真实案例吗？

### 深度自检（30分钟）

| 维度 | 问题 | 评分（1-5） |
|:---|:---|:---:|
| 挖掘式 | 我能拿到竞品不公开的关键数据吗？ | |
| 系统式 | 我的调研报告能直接支撑决策吗？ | |
| 爆炸式 | 进入新领域时，我能快速建立认知吗？ | |
| 自动式 | 我有持续监控竞品/政策的机制吗？ | |
| 案例库 | 我的判断有真实案例支撑吗？ | |
| 知识管理 | 调研成果能复用和传承吗？ | |

**评分标准**：
- 总分30分：25-30优秀，18-24良好，12-17需改进，<12严重缺失

## Constraints & Boundaries

### 适用边界

1. **个人自检**：适合产品经理、分析师、咨询师、创业者自检
2. **团队诊断**：适合团队调研能力评估，找出团队短板
3. **培训前测**：适合调研培训前的能力基线测试
4. **项目启动**：适合新项目启动前，评估团队是否具备调研能力
5. **定期复盘**：建议每季度做一次自检，跟踪能力提升

### 不适用场景

1. **已明确的问题**：如果问题已经很清楚，不需要诊断，直接解决
2. **纯执行型团队**：如果团队只做执行，不做决策，不需要调研能力
3. **高度专业化领域**：如医学研究、法律调查，需要专业方法论
4. **一次性项目**：如果项目只做一次，不值得建立系统能力
5. **资源极有限**：如果团队<3人，优先解决生存问题，再建能力

## Common Failure Modes

| 失败模式 | 症状 | 修复方法 | 预警信号 |
|:---|:---|:---|:---|
| 自检走过场 | 打分随意，不反思 | 强制写改进计划，下次对比 | 5分钟完成自检，无改进计划 |
| 类型标签化 | 给自己贴标签，不行动 | 标签只是起点，必须配行动计划 | "我是Type A"但无改变 |
| 忽视动态变化 | 一次诊断，长期不更新 | 每季度复测，跟踪能力变化 | 去年诊断，今年还在用 |
| 团队与个人混淆 | 个人能力强，团队能力弱 | 分别诊断个人和团队 | 只有个人自检，无团队评估 |
| 诊断后不行动 | 知道问题，但不改进 | 诊断必须配改进计划和资源 | 诊断报告吃灰 |
| 过度诊断 | 频繁诊断，不产出 | 诊断是手段，不是目的 | 每月诊断，但从未完成调研 |
| 忽视优势 | 只关注缺失，不发挥优势 | 诊断后同时强化优势和补缺口 | 改进计划全是补短板 |
| 雷达图僵化 | 四象限权重固定，不调整 | 根据项目类型调整象限权重 | 所有项目用同一雷达权重 |

---

## 行动触发器

1. **新项目启动**：用雷达图评估团队能力是否匹配项目复杂度
2. **调研失败复盘**：用六种类型定位失败根因
3. **季度规划**：用自检清单评估调研能力提升进度
4. **团队招聘**：用雷达图评估候选人调研能力结构
5. **培训设计**：用诊断结果设计针对性培训内容
