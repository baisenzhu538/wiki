# 关键假设 ABCD 模型

## 一句话定义

ABCD 模型是一套把创业中的关键假设按「宏观/微观 × 成败/效率」拆成四类问题的操作系统，让团队针对不同类型的不确定风险，匹配不同的验证工具和决策策略 [conf=0.88, source=00_inbox/精益创业/truman-精益创业-关键假设ABCD模型_ocr_text.md §6-25, 00_inbox/精益创业/truman-精益创业-关键假设ABCD模型_vlm_desc.md §7-28]。

## 核心模型/图示

### 二维矩阵

| | **宏观（全局/方向）** | **微观（局部/动作）** |
|---|---|---|
| **成败问题（能不能成）** | **A 商业成败**<br>策略：一堂五步法 | **B 关键决策**<br>策略：投产比 ROI |
| **效率问题（能不能更好）** | **C 业务提升**<br>策略：业务公式 | **D 关键转化**<br>策略：动力阻力触点 |

*来源：原图「一堂·关键假设ABCD模型 V2.0」[conf=0.95, source=00_inbox/精益创业/truman-精益创业-关键假设ABCD模型_vlm_desc.md §16-27]*

### 四象限释义

- **A 商业成败**：解决「这件事本身能不能成立」的宏观问题，对应一堂五步法（需求→解决方案→商业模式→增长→壁垒）。这是最致命的成败假设，一旦错误，后续投入全部浪费 [conf=0.90, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §951-962]。
- **B 关键决策**：在微观层面判断「某个具体选项值不值得做」，用 ROI（投产比）做快速决策，避免被局部细节绑架 [conf=0.85, source=00_inbox/精益创业/truman-精益创业-关键假设ABCD模型_ocr_text.md §13-18]。
- **C 业务提升**：宏观层面的效率优化，通过业务公式拆解关键变量，找到杠杆点 [conf=0.85, source=00_inbox/精益创业/truman-精益创业-关键假设ABCD模型_ocr_text.md §19-23]。
- **D 关键转化**：微观层面的转化优化，用「动力-阻力-触点」模型分析用户决策节点 [conf=0.85, source=00_inbox/精益创业/truman-精益创业-关键假设ABCD模型_ocr_text.md §24-27]。

### 优先级与验证策略

经验优先级：**A >> B > C、D** [conf=0.80, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §984-989]。

- 越接近成败、越宏观的问题，越值得用精益实验去系统避坑；
- 越微观、越偏效率的问题，越适合用数据、ROI 和局部 A/B 测试解决。

### 与 259 / 五步法的关系

- **五步法**是 A 象限的核心落地工具：需求存在 → 产品内核成立 → 商业模式成立 → 增长渠道可扩展 → 壁垒可建立 [conf=0.90, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §951-962]。
- 五步法的**横向是乘法关系**：对长期生意目标而言，每一步都必须跑通，不能有明显硬伤。
- 五步法的**纵向是加法关系**：不同人群、卖点、SKU、渠道可以组合测试，适合 C/D 象限的多方案并行。
- ABCD 模型提供了「什么时候用五步法、什么时候用 ROI/业务公式/触点模型」的选择框架。

> "259" 通常指一堂对五步法操作节奏的形象化概括：2 个维度（成败 vs 效率）、5 个步骤、9 类关键检查点。本卡不做原创性声明，仅作为一堂对通用精益框架的本土化归纳 [conf=0.70, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §962-970]。

## 适用边界

### 适合场景

- 从 0 到 1 的新业务，需要判断方向是否成立；
- 已有业务进入新人群、新渠道、新 SKU 的扩展决策；
- 团队内部对「该先做产品还是先跑增长」存在分歧时；
- 需要向投资人/合伙人快速解释风险优先级时。

### 不适合场景

- **强监管行业**（医疗、金融、教育、博彩）："假产品""假营销"等验证手段可能触碰合规红线 [conf=0.90, source=任务指令 L3 政策/合规边界]。
- **长周期硬件/重研发**：某些里程碑无法低成本拆分，必须依赖阶段性技术突破。
- **品牌敏感型产品**：粗糙 MVP 可能一次性损伤高端用户信任。
- **B2B 长决策链**：微观触点模型（D）价值有限，关键假设更多在 A/B 象限。

## 失败模式

### 失败模式 1：把效率问题当成成败问题

团队在产品内核尚未验证（A 未成立）时，沉迷于 C/D 象限的转化优化、页面美化，用战术勤奋掩盖战略懒惰。典型表现：花数月打磨 landing page，却未验证用户是否真有痛点 [conf=0.75, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §145-175]。

### 失败模式 2：把成败问题用 ROI 简单算死

A 象限的「商业成败」是高度不确定的假设，不能直接用历史 ROI 推导。例如共享彩票机项目全量投入 400 万做软硬件开发，半年无客户使用 [conf=0.70, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §570]，本质是用 B 象限的投产比思维去解决 A 象限的商业模式验证。

### 失败模式 3：跳步验证，从 A 直接跳到 C/D

跳过「需求→产品内核→商业模式」的 A 象限验证，直接进入增长和效率优化。例如电动滑板项目 A 类 CEO 直接组建团队、独立研发 APP 和硬件，周期 6-12 个月、投入 200-300 万 [conf=0.70, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §88-95]，就是没有把 A 象限假设拆成更小、更便宜的实验。

## 案例映射

### 正例：陈贤敏中式汉堡——五轮验证后才开店

陈贤敏在 2020 年发现中式汉堡新品类后，没有直接开店，而是把高风险假设逐一剥离：

1. 工艺：借烤炉、借朋友店面场地，测试汉堡胚工艺；
2. 口味：邀请员工、朋友、顾客免费品尝，询问购买意愿；
3. 购买：在朋友店小范围试卖 + 上外卖，测试定价和复购；
4. 经过约 5 轮测试，确认工艺、口味、定价、复购均优于经典西式汉堡后，才开第一家店 [conf=0.85, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §701-753]。

**映射到 ABCD**：这本质上是把 A 象限的「商业成败」拆解成多个 B 象限的「关键决策」，再用低成本实验逐个证伪/证实，是典型的 A→B 分层验证。

### 反例：共享彩票机——400 万 all-in 后半年零客户

某同学做共享彩票机，未把「用户是否真有需求、监管是否允许、点位是否成立」等 A 象限假设剥离验证，直接全量做软硬件开发，投入约 400 万，结果半年没有客户使用 [conf=0.70, source=00_inbox/精益创业/transcript_低成本验证实操1_剥离假设篇.md §570]。

**映射到 ABCD**：A 象限的商业模式/需求假设未经验证，直接跳到了产品实现和规模化，属于最严重的跳步失败。

## 执行 checklist

- [ ] 列出当前业务所有关键假设；
- [ ] 把假设放进 A/B/C/D 四象限；
- [ ] 优先处理 A 象限：用五步法从需求→壁垒逐级验证；
- [ ] A 未验证前，不要大规模投入 C/D 象限的优化；
- [ ] B 象限决策必须明确「不通过标准」，避免 ROI 计算被乐观假设带偏；
- [ ] 每个实验定义清晰的通过/不通过标准，失败时果断转向。
