## 核心主张

KDO 工厂的 Agent 们卡在 Truman 定义的「后知后觉」层次——每次踩坑后打补丁（41 条 pitfalls 为证），但没有把补丁萃取为可复用的**建模组件**。本卡将 Truman 的建模四步法映射到 KDO 管线，把「流程是业务的疤痕」从一个比喻变成一套操作方法。

## Truman 建模四步法 → KDO 映射

| Truman 四步 | 定义 | KDO 映射 | 执行角色 |
|:--|:--|:--|:--|
| **1. 圈定范围** | 明确问题边界、用户、场景、约束 | 域诊断报告 + 边界声明 + 素材全量审计 | 王语嫣 |
| **2. 探索关系** | 识别要素间的依赖关系（因果/时序/并列/映射），优先捕捉客观规律 | 素材消化 + 六层交叉验证 + 跨域同构分析 | 王语嫣→老顽童 |
| **3. 压缩模型** | 将关系抽象为简洁模型（流程图/框架图/N步法），保留核心逻辑 | 卡片生产：framework/concept ← 口述稿规律 | 老顽童 |
| **4. 解压展开** | 配套辅助工具（清单/案例/训练步骤/Skill/Agent-spec），确保可落地 | tool→skill→workflow→agent-spec 编译链 | 老顽童+黄药师 |

## 四步操作法

### 第一步：圈定范围

**什么时候做**：新素材到达 `00_inbox/`，尚未开始域诊断。
**执行者**：王语嫣

1. 列出素材全量清单（文件数、类型分布、OCR 状态）
2. 确认素材中的边界声明（Truman 说了"不教什么"）
3. 写出域边界声明：这个域覆盖什么场景、服务什么人、不覆盖什么
4. 对标已有域卡片，声明与相邻域的边界（防止和已有卡片重叠）

**跳步后果**：域边界不清→建卡时不知道往哪放→归属混乱→跨域链接断裂。已有教训：C 域 `ai-saas` 命名三变体（P-29/#168A）。

### 第二步：探索关系

**什么时候做**：边界确定后，建卡前。
**执行者**：王语嫣（跨域同构分析）→老顽童（素材内关系提取）

1. 通读口述稿全文（不只看笔记——笔记已丢一轮信息，P-31）
2. 标注信号词段落（"我给你演示一下""举个例子""这是我真实的"）
3. 提取 Before-After 对照：旧做法→新做法→为什么更好
4. 提取关键依赖关系：先做什么再做什么、跳步会发生什么
5. 跨域同构分析：本域方法论和其他域是否同构？（如 D域三曲线 ≈ C域业务公式参数冰山）
6. WebSearch 外部对标：国际通行框架是什么？名称是否冲突？

**跳步后果**：跳步是 KDO 最高频失败模式。不读口述稿→丢暗知识（P-31）；不 WebSearch→名称冲突（P-28）；不同构分析→孤岛卡片（P-22）。

### 第三步：压缩模型

**什么时候做**：关系探索完成后，开始写卡。
**执行者**：老顽童

1. **出牌**：从 KDO 组件库（`concept-kdo-component-library`）抽 5-8 张牌，排列为依赖关系链
2. 先建总纲卡（framework/domain-digest），再建子卡（concept/tool/case）
3. 每张卡必须呈现**依赖关系**，不只是罗列要素
4. 压缩时追问：这张卡承载了几个关系？有没有丢失关键规律？
5. 对照 Truman 的四个检查：拆解了没？完备了没？有依赖关系没？形状和逻辑匹配没？

**跳步后果**：「格式完整但思维空洞」卡（C-8）——frontmatter 齐全但 Claims 无具体反例、Constraints 模板化。P-17 教训：测了错的指标声称 85%。

### 第四步：解压展开

**什么时候做**：核心框架卡产出后，交审前。
**执行者**：老顽童（解压卡生产）+黄药师（工具链）

1. 对每张 framework 卡，评估解压需求：需要几个 tool/skill/case/agent-spec 才能落地？
2. 解压比底线：1 张 framework → ≥3 张解压资产（tool/skill/case/workflow/agent-spec）
3. 解压卡必须包含**操作步骤 + 判断标准 + 失败模式 + 可执行修复动作**
4. tool→skill 编译：操作步骤清晰、输入输出明确→封装为 Skill
5. skill→agent-spec 编译：有角色定位、对话模式→封装为 Agent 规格

**跳步后果**：压缩过度→模型太抽象→用不起来→卡片变成"知道但不会用"的库存。已有教训：C 域 100+ 张卡只有 1 个 agent-spec；决策域成熟度 A- 却缺 agent-spec（#153）。

## 组件思维（贯穿四步）

Truman 的核心发现：**高手不是不踩坑，而是把坑压缩成最小可复用组件，然后用组件拼装新工作流。**

KDO 的组件库见 `concept-kdo-component-library`。每个组件是一个「先 X 再 Y」的依赖关系对，来自真实踩坑经验。

使用方法：面对任何新域/新任务，先出牌——从组件库中抽 5-8 张牌，按依赖关系排列，形成任务执行方案。不要每次从头设计流程。

## 四层觉察——KDO 当前水平

| 层次 | 定义 | KDO 状态 |
|:--|:--|:--|
| **不知不觉** | 混乱，没觉察，重复踩坑 | — |
| **后知后觉** | 踩坑→复盘→打补丁 | ✅ 当前水平（41 条 pitfalls） |
| **当知当觉** | 边做边建模，实时捕获规律 | 偶尔（debug 时顺手写 pitfalls） |
| **先知先觉** | 没做就能预判 80% 流程 | 目标状态 |

本卡的目标：推动 KDO 从「后知后觉」→「先知先觉」。

## When NOT to Use

| 场景 | 原因 | 替代方案 |
|:--|:--|:--|
| 简单重复任务（已跑通 >10 次无故障） | 建模 ROI 为负——流程已固化，不需要重新出牌 | 直接用已有 SOP |
| 一次性任务（确认不会再有第二次） | 建模成本 > 执行成本 | 做就行，事后不复盘 |
| 紧急救火（必须在 1h 内解决） | 出牌需要思考时间，救火没时间 | 事后复盘时再补建模 |

## Critique

### 内部局限

1. **四步法来自 Truman 的经验萃取，不是学术框架**。它在一堂的教研场景下验证有效，但在其他类型的知识工作（如纯工程开发、纯设计）中可能需要适配。
2. **组件库的质量取决于 pitfalls 的完整度**。如果某类错误还没犯过（因此还没记入 pitfalls），对应的组件就不会存在。
3. **解压比 1:3 的底线是经验值**，可能不适合所有域（如纯理论域可能需要更多解压，纯工具域可能需要更少）。

### 外部攻击者

**Daniel Kahneman（认知偏见）**：建模的"先知先觉"状态本身可能是一种过度自信——你以为预判了 80%，实际可能只有 40%。需要建立独立测量机制（如同行盲评、真实场景验证）而非依赖自我评估。

**Andy Grove（高产出管理）**：四步法增加了流程节点，可能变成 Truman 警告的"给自己找事"。需要区分"防止推翻的节点"和"纯粹摩擦力的节点"。Grove 的标准：这个节点的输出是否被下一步真正消费了？如果没有，砍掉。

## Action Triggers

| 触发条件 | 动作 | 成功指标 |
|:--|:--|:--|
| 新素材到达 `00_inbox/` | 王语嫣启动四步法第一步：圈定范围 | 域边界声明写进诊断报告 |
| 域诊断完成、建任务单前 | 王语嫣跑四步自检（边界/关系/解压路径/组件复用） | 四项全部非空 |
| 老顽童领取新域任务 | 从组件库出 5-8 张牌，写进任务文件「建模方案」节 | 任务文件含建模方案节 |
| 每批 framework 卡产出后 | 老顽童检查解压比：framework → ≥3 解压资产 | 审计脚本通过 |
| 欧阳锋审查 framework 卡 | 检查建模质量维度：关系呈现/双向链接/解压配套/跨域同构 | 审查报告含 P1.5 建模质量节 |

## Step 2 展开：关系探索

> 来源：口述 L1916-L1970, L2103-L2188

详见 `framework-modeling-relation-exploration`。核心要点：

- **关系 vs 规律**：关系是"这两个要素之间有前后/并行/嵌套关系"，规律是"这类关系在不同场景下可重复"。Step 2 先找关系，再筛选规律
- **五类关系**：前后、并行、嵌套、循环、条件
- **几何形态匹配**：先确定逻辑形态（如何运转），再画出几何形态（流程图）。反过来 = 形式主义
- **典型跳步错误**：跳过 Step 2 直奔方案 = 要素之间的关系没搞清就动手

### 失败模式：压缩过度

| 症状 | 不压缩的团队做了什么 |
|:---|:---|
| Step 2-4 压成 1 步 | Step 2 探索关系（半天）→ Step 3 筛选规律（半天）→ Step 4 验证（半天） |
| "我们已经想清楚了" | 用关系分类框架逐条过一遍，总能发现漏掉的依赖 |
