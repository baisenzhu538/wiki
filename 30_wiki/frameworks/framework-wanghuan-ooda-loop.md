# 王欢OODA闭环：人机协作的决策迭代框架

> **Burn line**: 你不需要确定，你只需要比上一圈快。
>
> **来源**：王欢 AI 实战分享（2026-06-18）；OODA 原自美国空军上校 John Boyd 的军事决策理论。

---

## 一、用一句话讲清楚

OODA 是一个四步决策闭环：**观察（Observe）→ 定向（Orient）→ 决策（Decide）→ 行动（Act）**。在人机协作中，它帮助人用更快速度完成“看清事实 → 定位位置 → 做出可验证决定 → 采集新信息”的循环。

---

## 二、四个环节

```
        观察 Observe
       /            \
  看见事实          定位坐标
      |              |
      |              |
  行动 Act ←———→ 定向 Orient
  采集新信息      可验证的决定
       \            /
        决策 Decide
```

### 2.1 观察（Observe）

| 问题 | 内容 |
|:---|:---|
| 看见什么？ | 事实、数据、信号 |
| 关键动作 | 采集信息，不急于判断 |
| 常见错误 | 把假设当事实，只看 confirming evidence |

### 2.2 定向（Orient）

| 问题 | 内容 |
|:---|:---|
| 我在哪？ | 定位当前位置、资源、约束 |
| 关键动作 | 把观察到的事实放入上下文，形成判断 |
| 常见错误 | 脱离上下文做决策 |

### 2.3 决策（Decide）

| 问题 | 内容 |
|:---|:---|
| 做什么？ | 基于定向做出可验证的选择 |
| 关键动作 | 明确下一步行动和验证标准 |
| 常见错误 | 追求最优解而不敢行动 |

### 2.4 行动（Act）

| 问题 | 内容 |
|:---|:---|
| 怎么验证？ | 执行并采集新信息 |
| 关键动作 | 小步快跑，把行动变成下一轮观察的输入 |
| 常见错误 | 行动后不回头复盘 |

---

## 三、为什么在人机协作中特别有效

AI 擅长：
- **观察**：快速处理大量数据，发现模式。
- **行动**：按指令批量执行。

人擅长：
- **定向**：理解上下文，判断信号意义。
- **决策**：在不确定性中做出选择。

> 人机协作的 OODA：AI 加速观察和行动，人负责定向和决策。

---

## 四、与导演模型的关系

| OODA 环节 | 导演工作 |
|:---|:---|
| 观察 | 验收 AI 收集的信息 |
| 定向 | 判断当前位置和形势 |
| 决策 | 定义下一步目标 |
| 行动 | 让 AI 执行并采集反馈 |

---

## 五、应用场景

### 5.1 药柜运营迭代（鑫港湾迁移）

| OODA | 动作 |
|:---|:---|
| 观察 | 看每日订单、患者反馈、库存周转 |
| 定向 | 判断当前是流量问题、转化问题还是复购问题 |
| 决策 | 决定下周优先优化哪个环节 |
| 行动 | 调整品种、推荐话术、运营活动，再观察数据 |

### 5.2 产品迭代

| OODA | 动作 |
|:---|:---|
| 观察 | 收集用户行为数据和反馈 |
| 定向 | 判断产品在五层跃迁中的位置 |
| 决策 | 选择下一个迭代方向 |
| 行动 | 发布新版本，继续观察 |

### 5.3 卡片质量提升

| OODA | 动作 |
|:---|:---|
| 观察 | 门禁检查发现 source 缺失、逻辑漏洞 |
| 定向 | 判断是普遍问题还是个案 |
| 决策 | 决定补 source、重写还是删除 |
| 行动 | 修改卡片，下一轮门禁验证 |

---

## 六、核心原则

> **你不需要确定，你只需要比上一圈快。**

OODA 不是追求一次性正确，而是通过**更快的循环速度**获得优势。每一圈都比上一圈多知道一点，就能更快逼近正确答案。

---

## 七、常见走偏模式

| 走偏模式 | 表现 | 纠偏动作 |
|:---|:---|:---|
| **观察瘫痪** | 收集太多信息不行动 | 设定最小观察集，先转一圈 |
| **定向过慢** | 反复讨论上下文，错过窗口 | 用假设替代完美判断，行动中验证 |
| **决策恐惧** | 害怕错误，不敢决策 | 把决策拆成可验证的小实验 |
| **行动不闭环** | 做了不回头复盘 | 每次行动必须产生新的观察输入 |

---

## 八、Action Triggers

| 触发场景 | 第一个动作 |
|:---|:---|
| 项目进入僵局 | 画一个 OODA 圈，看卡在哪个环节 |
| AI 输出不稳定 | 缩短 OODA 循环，每次只改一个变量 |
| 竞争/市场变化快 | 用 OODA 速度建立优势 |
| 需要验证假设 | 设计一个最小闭环实验 |
