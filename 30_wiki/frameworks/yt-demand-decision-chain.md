# ToB决策链需求分析：多角色、多需求、多顾虑

> 一堂五步法：ToB需求分析不是分析"用户"，而是分析"决策链上的每个角色"。

## 核心框架

ToB决策链：

```
┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐    ┌─────────┐
│ 使用者   │ → │ 影响者   │ → │ 决策者   │ → │ 采购者   │ → │ 把关者   │
│ (使用)   │    │ (评估)   │    │ (批准)   │    │ (执行)   │    │ (合规)   │
└─────────┘    └─────────┘    └─────────┘    └─────────┘    └─────────┘
    │              │              │              │              │
    ▼              ▼              ▼              ▼              ▼
  需求：         需求：         需求：         需求：         需求：
  好用、效率     团队接受度     ROI、战略匹配   价格、合同      合规、安全
  提升           培训成本       预算           交付           风险
```

## 关键洞察

### 1. 每个角色的需求分析

| 角色 | 核心需求 | 顾虑 | 说服证据 |
|:---|:---|:---|:---|
| **使用者** | 好用、效率提升 | 学习成本、改变习惯 | 试用体验、培训支持 |
| **影响者** | 团队接受度、项目成功 | 培训成本、实施风险 | 试点案例、实施计划 |
| **决策者** | ROI、战略匹配、预算控制 | 投资回报不确定、战略偏差 | ROI计算、战略对标案例 |
| **采购者** | 价格合理、合同安全 | 价格超预算、合同风险 | 报价方案、合同条款 |
| **把关者** | 合规、安全、风险可控 | 安全漏洞、合规风险 | 安全审计、合规证明 |

### 2. 决策链的阻力点

每个节点都可能成为阻力点：

| 阻力点 | 表现 | 解决方法 |
|:---|:---|:---|
| **使用者抵制** | 不愿改变现有工作方式 | 降低学习成本，提供培训 |
| **影响者犹豫** | 担心项目失败影响自己 | 提供试点方案，降低实施风险 |
| **决策者不批** | ROI不清晰或预算不足 | 提供详细ROI计算，分期付款方案 |
| **采购者砍价** | 价格超出预算 | 灵活定价、分期、增值服务 |
| **把关者否决** | 安全或合规不达标 | 提前准备安全审计、合规证明 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **只关注使用者** | 产品好用，但决策者不批 | 分析决策者需求，设计ROI证明 |
| **忽视把关者** | 产品很好，但安全审计不过 | 提前准备安全合规证明 |
| **决策链未映射** | 不知道卡在哪个节点 | 画出完整决策链，标注每个节点状态 |
| **证据不足** | 某个角色需要证据，但无法提供 | 提前准备各角色需要的证据 |
| **流程太长** | 决策周期超过客户耐心 | 优化流程，减少不必要的节点 |
| **角色需求冲突** | 使用者要A，决策者要B | 找到平衡点，或优先满足决策者 |
