# 关键假设排序：前置优先、风险高的优先

> "前置假设优先，风险高的假设优先。越在需求侧、越在产品侧的假设，风险越高；越往后，风险越低。早期要尽早判断前面的假设，前面的验证完了之后再去验证后面的，是一个前后关系。"  
> —— 张磊，精益测试 AMA Q3（`src_20260616_b1e25c49`）

在面对一组待验证假设时，创业者常犯的错误是**把资源平均分配**或**从最容易测的环节入手**。本框架给出一条更省命的排序规则：先把假设放到一堂五步法的坐标里，再按"前置优先、风险高的优先"确定验证顺序。它的核心目的是用少量试错成本，大幅降低当前最致命的系统性风险。

---

## Constraints & Boundaries

| 边界 | 说明 |
|------|------|
| **适用阶段** | 主要适用于业务测试阶段，尤其是从 0 到 1 或进入新方向前的假设拆解；预判阶段和规模化增长阶段的排序逻辑需叠加行业预判/单元模型等工具 |
| **前提条件** | 必须先完成假设拆解，能把模糊的业务问题拆成可验证的细分假设；如果连假设都拆不出来，本框架无法直接套用 |
| **不替代专业判断** | 同一业务在不同阶段、不同资源条件下，"风险高"的判断会变化，需要结合具体业务公式和单元模型做二次校准 |
| **不保证正确** | 本框架提供的是排序规则，不是验证结论；前置假设通过只意味着可以继续往后验，不代表商业模式一定成立 |

---

## Core Framework

### 1. 前置假设优先

一堂五步法天然给出了假设的前后依赖关系：

```
需求 → 解决方案（产品内核） → 商业模式 → 增长 → 壁垒
```

- **前面的假设是后面假设的前提**：需求不成立，产品内核再强也白搭；产品内核没跑通，规模化增长就是烧钱。
- **前置假设失败会导致全盘推翻**：如果某一轮验证失败的结果是"一步回退"，说明验证设计合理；如果是"全盘推翻"，说明你跳过了前置假设。

### 2. 风险高的优先

在已经拆好的假设清单里，优先验证"一旦错了就会让项目死亡"的假设。判断维度包括：

- **致死率**：不成立是否会导致整个方向崩塌？
- **验证成本**：能否用低成本快速拿到认知？
- **信息价值**：验证后是否能排除最大不确定性？

> "不要把精力和资源耗在低风险环节上，要直击高风险假设。"（`src_20260616_e66bd149`）

### 3. 用五法给假设"定位"

张磊在 AMA 中反复强调：拿到一个业务，不要先想最高风险的假设，而是**先判断它处于哪个阶段**，再在这个阶段里找关键假设。

| 五步法阶段 | 常见高风险假设 | 典型验证问题 |
|-----------|--------------|------------|
| 需求 | 用户是否真有这个问题？是否足够痛？ | 用户访谈、竞品验证、假页面测试 |
| 解决方案 | 产品内核是否成立？用户是否愿意选择？ | MVP、人工服务、假按钮/假海报 |
| 商业模式 | 单元模型是否跑正？成本结构是否成立？ | 小范围付费、单用户/单 SKU 模型测算 |
| 增长 | 渠道 ROI、天花板、能力匹配 | 渠道评估表、小规模投放 |
| 壁垒 | 护城河是否可建立 | 通常在商业模式跑通后再验证 |

### 4. 需求/产品侧假设先于增长

很多创业者过早进入"怎么获客"的讨论。框架要求：

- 如果前三步（需求、产品、商业模式）没有初步通过，不要 all in 增长验证。
- 增长渠道验证有专门的评估维度：试错成本、ROI、天花板、能力匹配。
- 进入增长阶段的标志是：**单元模型成立，且跑通了一条增长渠道**。

## 案例 1：海外动漫周边独立站

**背景**：学员做动漫周边海外独立站，业务涉及产品、定价、内容、渠道多项假设，不知如何排序。

**张磊的排序方法**：

1. **先代入五法，给假设定位**：
   - 产品是解决方案；
   - 内容获客、渠道获客属于增长；
   - 价格带偏解决方案，具体定价偏商业模式，优惠促销策略偏增长，人群价格敏感性属于需求。
2. **前置优先**：先验证需求侧（用户是否真需要、价格敏感性）和产品侧（产品/解决方案是否成立）。
3. **风险高的优先**：越在需求侧、产品侧的假设风险越高，越应前置验证。
4. **增长后置**：如果需求和产品未成立，不要急着验证内容和渠道获客。

**关键判断**：

> "他这个业务典型的是业务非常早期、缺乏数据、无法分析。就是你来看一看你的这些可验证假设分别是哪些，哪一些可以放在解决方案里，内容获客、渠道获客可以放到增长环节。"（`src_20260616_7dc80216`）

**进入增长阶段的标准**：商业模式成立（单元模型核心指标达标）+ 找到一条有效增长渠道。

## 案例 2：美业门店 200→3980 转化漏斗

**背景**：美业项目有三层漏斗：200 元体验品 → 3980 元套餐 → 2 万元加盟。学员问该测哪一层。

**张磊的判断**：

- 关键不是测某一个单品，而是找到漏斗里风险最高的假设。
- 200 元用户能否转化到 3980 元，是整个商业模型的"关键转化路径"。
- 如果 200→3980 不成立，引流再多也是赔本，2 万元加盟更是空中楼阁。

**验证顺序（里程碑测试）**：

| 里程碑 | 验证内容 | 样本/成本 | 通过信号 |
|-------|---------|----------|---------|
| 第一里程碑 | 200→3980 转化率 | 30-50 个样本，偏定性 | 转化率有提升空间，能定位卡点 |
| 第二里程碑 | 新媒体获客的 200 元引流成本 | 转化率过关后 | 获客成本可承受 |
| 第三里程碑 | 3980→20000 加盟意愿 | 前两步成立后 | 有真实加盟意向 |

> "过早测试加盟政策是典型的'过早固化'错误——加盟链条长、变量多、试错成本高，而前两步只用几十个样本就能拿到关键认知。"（`src_20260616_b1e25c49`）

## Common Failure Modes

| 模式 | 症状 | 修复 |
|------|------|------|
| **平均用力验证** | 同时启动多个假设的验证，资源被稀释，每个都拿不到清晰结论 | 列出假设清单，按五步法阶段和致死率排序，一次只聚焦 1-2 个最高风险假设 |
| **跳过前置直接测增长** | 需求还没验证就大规模投放、铺渠道，发现获客成本极高或转化率极差 | 回到五步法起点，先验证需求和产品内核，增长验证放在单元模型成立之后 |
| **把低风险假设当重点** | 花大量时间优化文案、页面细节，却对核心转化路径视而不见 | 问自己：这个假设不成立，项目会死吗？不会死的就往后排 |
| **过早固化** | 在产品内核没跑通前就开店、开发完整功能、搭建复杂系统 | 用 FALSE 模型从左到右选择最低成本验证方式，先证伪再证实 |
| **阶段并存当借口** | 以"阶段可以并行"为由跳过关键依赖，同时 all in 多个前后耦合的环节 | 明确"探索性测试"和"正式投入"的边界，前置假设未通过前不放大后续投入 |
