# 系统测试曲线与三大测试范式

> 用"X 型幻想曲线 vs Y 型螺旋上升曲线"建立真实业务进展的心智模型，再按灰度/组合/里程碑三种范式组织多轮 MVP，避免一次性重投入、错误选项固化和全盘推翻式浪费。

## 一句话定义

系统测试曲线是一堂基于精益创业迭代思想提炼的高阶验证框架：它先用 X/Y 两条曲线纠正创业者对"一帆风顺"的幻想，再提供灰度测试、组合测试、里程碑测试三种由易到难的范式，帮助团队把单个 MVP 组织成有节奏、可回退、螺旋上升的多轮实验系统。

## 核心模型

### 1. 双曲线：幻想 vs 现实

```
进展 │
     │         X 型：头脑幻想中的一帆风顺曲线
     │        ╱
     │       ╱
     │      ╱
     │     ╱
     │    ╱
     │   ╱
     │  ╱
     │ ╱
     │╱______________________________
     │  ╲    ╱ ╲    ╱ ╲    ╱
     │   ╲  ╱   ╲  ╱   ╲  ╱        Y 型：真实世界的螺旋上升曲线
     │    ╲╱     ╲╱     ╲╱
     │     ↑       ↑       ↑
     │   第一阶段  第二阶段  第三阶段/第四阶段
     └─────────────────────────────────→ 时间
```

| 维度 | X 型幻想曲线 | Y 型螺旋上升曲线 |
|:---|:---|:---|
| 形状 | 平滑、持续向上 | 锯齿状、阶段性上升 |
| 心理假设 | 一开始就想清楚，一做就成 | 早期拿不准，边做边学 |
| 阶段特征 | 没有明显阶段 | 第一/二/三/四阶段，每阶段先试错再突破 |
| 早期状态 | 信心高、认知强 | 信心低、认知低，应保持低投入、大试错空间 |
| 末期状态 | 自然放大 | 信心强、认知强，才可高投入、适当固化 |

> 真实业务进展是"试错—调整—再试错—突破"的循环，不是线性一帆风顺 [conf=0.85, source=一堂-低成本测试-系统测试-口述.txt]。

### 2. 三种系统测试范式

| 范式 | 核心动作 | 难度星级 | 拆解对象 | 避免浪费 |
|:---|:---|:---:|:---|:---|
| **灰度测试** | 先糙发布 → 迭代 → 迭代 → 再迭代发布 | ★★★☆☆ | 拆节点 | 避免"一次性重投入"浪费 |
| **组合测试** | 先列选项 → 测试排除/排序 → 测试排除/排序 → 测试排除/排序 | ★★★★☆ | 拆选项 | 避免"细化错误选项"浪费 |
| **里程碑测试** | 先验证基础假设 → 基于 P1 继续验证 → 基于 P2 继续验证 → 基于 P3 继续验证 | ★★★★★ | 拆假设 | 避免"全盘推翻式"浪费 |

> 难度星级来自讲义图标，灰度 3 星、组合 4 星、里程碑 5 星 [conf=0.90, source=低成本验证-系统测试曲线_ocr_text.md §25-52]。

### 3. 三范式的组合关系

```
公司层（CEO/业务组合）        业务层（项目一号位）            执行层（技术/产品负责人）
     │                              │                                │
     ▼                              ▼                                ▼
 组合测试                       里程碑测试                        灰度测试
 （多项目赛马、多选项）          （假设链逐步验证）                 （节点迭代发布）
 避免选项错                     避免全盘推翻                       避免一次性重投入
```

> 同一公司在不同层级可同时使用三种范式：CEO 用组合测试选方向，项目负责人用里程碑测试控风险，执行团队用灰度测试迭代技术/产品 [conf=0.80, source=一堂-低成本测试-系统测试-口述.txt §医疗硬件案例推演]。

## 与经典理论的关系

| 本框架要素 | 经典来源 | 一堂本土化/归纳部分 |
|:---|:---|:---|
| X/Y 曲线与螺旋上升 | 与精益创业"Build-Measure-Learn"循环、复杂系统非线性演化一致 | 用 X 型"幻想曲线"作对照，强化东方创业者"憋大招"心态的纠偏 |
| 灰度测试 | 软件工程灰度发布、精益创业小批量发布 | 扩展到消费品、硬件、门店等非软件场景 |
| 组合测试 | 实验设计（DOE）、A/B 测试、假设驱动开发 | 强调"先列选项→排除排序→避免过早细化错误选项"的心法 |
| 里程碑测试 | 阶段门（Stage-Gate）、约束理论瓶颈管理 | 与一堂五步法、ABCD 关键假设模型深度衔接 |

> "精益创业"概念源自 Eric Ries，"客户开发"源自 Steve Blank；灰度/组合/里程碑三种范式的命名与组合是一堂基于本土案例的归纳 [conf=0.85, source=任务指令 1.2 与 1.3]。

## 案例映射

### 正例：鞋类产品 MVP 的四级演进

| 版本 | 做法 | 周期 | 成本 | 范式映射 |
|:---|:---|:---:|:---:|:---|
| V1 All in | 自己设计、批量生产 10000 双、直播销售 | 3-6 个月 | 200 多万 | 反面：一次性重投入，无节点拆分 |
| V2 小批量 | 自己设计、小批生产 2000 双 | 2 个月 | 约 60 万 | 灰度测试雏形 |
| V3 测高风险假设 | 产品卖点、材质、颜色测试，内部+工人试穿 | 1 个月 | 约 5 万 | 组合测试雏形 |
| V4 聪明 MVP | 假页面测颜色、3D 打印打样、摆摊/快闪店测试 | 1 周 | 几百 ~ 1 万 | 灰度+组合测试 |

## 如何判断"红点"：从模糊到定量的六类信号

| 阶段 | 判断方法 | 典型信号 | 可信度 |
|:---:|:---|:---|:---:|
| 早期 | 主观信心 | 一号位在业务现场感受到信心增强/变弱 | 🟡 中 |
| 早期 | 定性反馈 | 用户给出"醍醐灌顶""明显更好"等强评价 | 🟡 中 |
| 早期 | 定性排名 | 多个选项中某一项显著优于其他 | 🟡 中 |
| 中期 | 少量订单 | 获得首批真实付费订单 | 🟡 中-高 |
| 中后期 | 区间定量 | "复购率 30% 左右""NPS 80-90" | 🟢 较高 |
| 后期 | 精准定量 + benchmark | 大规模数据、明确盈利模型 | 🟢 高 |

> 早期业务应"接受模糊"，不能因为无法严格定量就停止实验；后期逐步用精准数据验证 [conf=0.85, source=一堂-低成本测试-系统测试-口述.txt §判断红点]。

## 使用清单

1. **画曲线**：先让团队画出自己心中的 X 型曲线，再对比 Y 型螺旋上升曲线，校正预期。
2. **拆假设链**：用一堂五步法或 ABCD 模型把业务拆成前后依赖的关键假设。
3. **选范式**：
   - src_unknown
   - src_unknown
   - src_unknown
4. **定标准**：每轮实验定义"通过/不通过"信号，允许早期使用定性/主观信号。
5. **控固化**：在关键假设未验证前，避免重投入在选址、装修、全量研发、品牌系统上。
6. **螺旋上升**：每完成一轮测试，更新认知地图，再决定下一轮是继续、转向还是终止。
