# JTBD需求分析实战应用：从"用户想要"到"用户雇佣"

> JTBD（Jobs-to-be-Done）：用户不是买产品，而是"雇佣"产品完成某个任务。

## 核心框架

JTBD的核心问题：用户"雇佣"你的产品是为了完成什么**任务**？

| 要素 | 问题 | 示例 |
|:---|:---|:---|
| **任务** | 用户要完成什么？ | "我需要每周向团队汇报项目进度" |
| **情境** | 在什么情况下？ | "周一早上9点，团队例会前" |
| **目标** | 达成什么结果？ | "让所有人清楚项目状态，不需要追问" |
| **障碍** | 现在遇到什么阻碍？ | "Excel表格混乱，整理耗时2小时" |
| **替代方案** | 现在怎么解决的？ | "手动整理Excel，发邮件" |

## 关键洞察

### 1. JTBD vs 传统需求分析

| 传统需求分析 | JTBD |
|:---|:---|
| "用户想要什么功能？" | "用户雇佣产品完成什么任务？" |
| 关注功能列表 | 关注任务完成 |
| 竞品是同类产品 | 竞品是所有完成同一任务的方案 |
| 用户是人口统计属性 | 用户是"有相同任务的人" |

### 2. JTBD的竞争力定义

### 3. JTBD的访谈框架

不是问"你想要什么功能"，而是问：

1. **最近一次**：你最近一次遇到这个任务是什么时候？
2. **情境描述**：当时的情境是什么？时间、地点、情绪？
3. **替代方案**：你当时怎么解决的？用了什么工具/方法？
4. **切换点**：如果用了新产品，是什么让你决定切换？
5. **结果评估**：完成后，结果和你预期的一致吗？

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **功能导向** | "用户说要XX功能，我们就做" | 追问"这个功能帮助用户完成什么任务？" |
| **JTBD太宽** | "用户雇佣我们是为了更好地工作" | 聚焦到具体、可描述的任务 |
| **忽视替代方案** | 只和同类产品竞争 | 列出所有完成同一任务的方案 |
| **JTBD未验证** | 假设用户有某任务，未访谈 | 用JTBD访谈框架验证 |
| **任务描述模糊** | "用户想要高效" | 具体化"高效完成什么任务？在什么情境下？" |
| **忽视情感维度** | 只关注功能任务，忽视情感任务 | JTBD包含功能任务+情感任务+社会任务 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新产品需求定义 | 成熟产品增量优化 |
| 用户访谈设计 | 技术架构设计 |
| 产品功能优先级 | 运营策略制定 |
| 竞品分析 | 定价策略 |
