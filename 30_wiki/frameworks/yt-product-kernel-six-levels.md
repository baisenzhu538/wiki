# 产品内核六个段位：从缺价值意识到全面迁移

> 一堂五步法：产品内核有段位，从"不重视价值"到"能跨领域迁移"。

## 核心框架

| 段位 | 名称 | 核心能力 | 标志 | 典型错误 |
|:---|:---|:---|:---|:---|
| **L1** | 缺价值意识 | 不重视产品价值，只谈愿景 | "创业就是赚钱随便赚" | 没有产品意识，功能混在一起 |
| **L2** | 有价值意识无最小意识 | 看到价值但无法聚焦 | "什么都要，大而全" | 无法剥离核心，资源分散 |
| **L3** | 有最小意识 | 能区分内核与边缘 | "找到决定成败的20%" | 尚未验证，只是假设 |
| **L4** | 评估测试 | 能设计实验验证内核 | "通过测试验证产品力" | 内核一成不变 |
| **L5** | 动态调整 | 随市场变化迭代内核 | "内核随业务演化" | 无法跨领域迁移 |
| **L6** | 全面迁移 | 能跨领域重组创新 | "把A领域内核应用到B领域" | — |

## 关键洞察

### 1. 段位进阶的关键跃迁

| 跃迁 | 从 | 到 | 关键动作 |
|:---|:---|:---|:---|
| L1→L2 | 不重视价值 → 重视价值 | 开始思考"用户为什么选择我们" |
| L2→L3 | 大而全 → 聚焦核心 | 剥离边缘功能，找到20%关键 |
| L3→L4 | 假设内核 → 验证内核 | 设计实验，测试关键转化率 |
| L4→L5 | 静态内核 → 动态内核 | 建立市场监测机制，定期迭代 |
| L5→L6 | 单领域创新 → 跨领域迁移 | 抽象内核逻辑，应用到新领域 |

### 2. L3是入门线

L3（有最小意识）是产品内核的入门线：

- 能区分内核和边缘功能
- 能找到决定成败的20%
- 但尚未验证，只是假设

从L3到L4是最关键的跃迁：从"我觉得"到"我验证"。

### 3. 段位自评测试

**L1测试**：
- 你能用一句话描述产品价值吗？
- 如果描述的是功能（"我们是一个XX平台"），不是价值（"用户的问题是...我们解决..."），则是L1。

**L2测试**：
- 如果只能保留20%的功能，你会保留哪些？
- 如果无法选择，或选择后仍觉得"不够"，则是L2。

**L3测试**：
- 你能列出内核功能和边缘功能吗？
- 如果能区分，但未验证，则是L3。

**L4测试**：
- 你的关键转化率是多少？有验证数据吗？
- 如果有数据，但内核从未调整，则是L4。

**L5测试**：
- 你的内核从定义到现在变化过吗？
- 如果变化过，且有数据支撑，则是L5。

**L6测试**：
- 你能把当前内核逻辑应用到其他领域吗？
- 如果能，且有成功案例，则是L6。

### 4. 团队段位对齐

团队产品内核认知不一致时：

- **对齐方法**：一起填产品内核画布，对比差异
- **常见问题**：
  - 创始人L5，团队L3 → 团队执行不到位
  - 创始人L2，团队L4 → 创始人决策偏差
  - 全员L3 → 缺乏验证，需要推动L4

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **段位自我高估** | "我懂产品"，但实际L1-L2 | 用测试题自评，寻找反例 |
| **段位停滞不前** | 长期L3，未验证到L4 | 强制要求每个内核必须有验证数据 |
| **团队段位断层** | 创始人L5，团队L2 | 建立统一的产品内核流程和模板 |
| **忽视段位进阶** | 满足于"能定义内核"，不追求"能验证" | 建立关键转化率监测机制 |
| **段位与角色不匹配** | 产品经理L6，但CEO只有L2 | CEO必须参与内核定义，提升段位 |
| **L3陷阱** | 以为"找到20%"就够了，不验证 | 强制验证，用数据说话 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 个人能力评估 | 技术能力评估 |
| 团队能力对齐 | 运营能力评估 |
| 招聘产品经理 | 销售能力评估 |
| 培训产品能力 | 设计能力评估 |

## 行动触发器

- 当你说"我懂产品"时 → 用测试题自评，寻找反例
- 当团队争论产品方向时 → 一起填内核画布，对齐段位
- 当做完内核定义后 → 检查是否验证了，还是停留在假设
- 当发现新机会时 → 抽象内核逻辑，考虑跨领域迁移
