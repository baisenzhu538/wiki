# 科学建模七步里程碑：从边界到封装的方法论生产流程

> **Burn line**: 方法论级别的建模不是灵感爆发，而是一套有里程碑、可迭代、可验证的生产流程。

---

## 用一句话讲清楚

把复杂课题从无边无际的信息，逐步收敛成可交付、可验证、可复用的模型资产：先敲定边界，再饱和收集事实，经整合萃取产出 1.0 模型，通过以推翻为目标的撞击实验验证，最后封装并包装打磨。

---

## 核心要点

1. **敲定边界**：先定义研究范围与不研究范围，输出一句话边界定义；超过边界的信息暂不进入。
2. **饱和收集事实**：优先收集中国市场真实发生的事实（正面/反面案例、最佳实践、搞砸案例、自身复盘、用户访谈）；原则为 **事实 > 观点 > 理论**。
3. **整合萃取**：对事实分类建模，找 before/after 共性、卡点、爬坑路径、原则与本质，输出初步分类框架。
4. **产出 1.0 模型**：用框图（冰山图、双三角、雷达图、公式等）给出完整但不完美的原型及初步解释。
5. **辩证讨论 / 撞击实验**：内部交叉评审 + 专家评审，**目标是以推翻模型的方式找反例、找硬伤、检查定义与边界**，直到撞无可撞。
6. **封装**：把模型固化成可交付形式，配案例、工具与使用说明。
7. **包装打磨**：做十层解读、课程、文档、卡牌，完成最终交付物。

> **关键主张**
> - C1 [conf=0.9]：方法论建模必须先从“敲定边界”开始，否则会被无边无际的信息淹没。
> - C2 [conf=0.85]：收集事实的优先级远高于理论和观点。
> - C3 [conf=0.85]：第五步“撞击实验”是最难的，核心是以推翻模型为目标找反例。
> - C4 [conf=0.8]：在撞击实验中，所有人都要奔着找反例去，而不是宣传模型。
> - C5 [conf=0.75]：这套流程能对抗定义不清、丢三落四、边界不清、太随机等常见问题。

---

## 边界

| 边界 | 说明 |
|------|------|
| **事实饱和度** | 案例要足够多，能覆盖主要场景；否则模型易沦为理论包装。 |
| **撞击实验时间** | 不能压缩，通常是最耗时的阶段。 |
| **专家质量** | 专家必须实事求是，有 before/after 经验，且愿意找反例。 |
| **模型边界** | 必须明确适用范围，不能试图解释一切。 |
| **团队文化** | 需要成熟的验证文化与安全氛围，以推翻为目标的讨论才有效。 |

---

## 失败模式

| 失败信号 | 为什么失效 | 替代方案 / 修复动作 |
|---|---|---|
| **流程用于简单任务** | 七步流程太重，overhead 大 | 直接用清单或 SOP |
| **时间极紧仍强行跑满七步** | 撞击实验需要充分时间 | 先做轻量版，后续补验证 |
| **缺少事实就进入建模** | 没有案例支撑会变成空想 | 先积累案例，再启动建模 |
| **团队没有验证文化** | 以推翻为目标的讨论会被视为攻击 | 先建立心理安全与验证氛围 |
| **跳过撞击实验** | 容易产出“看起来对但经不起挑战”的脆弱模型 | 强制引入专家评审与反例驱动验证 |
| **事实收集永无止境** | 调研成本失控，无法收敛 | 用边界定义明确“够用的饱和”标准 |

## 行动 Checklist

- [ ] 拿到一个方法论级课题时，先用一句话写下边界定义，并让团队达成共识。
- [ ] 列出必须收集的事实清单：正面案例、反面案例、最佳实践、搞砸案例、用户访谈、自身复盘。
- [ ] 在整合萃取阶段，画出至少一个初步分类框架（可手绘、表格或白板）。
- [ ] 产出 1.0 模型：选择一个可视化框图（冰山图/双三角/雷达图/公式），不求完美，要求完整。
- [ ] 组织撞击实验：邀请内部 + 外部专家，明确讨论目标是“推翻模型”。
- [ ] 撞击实验后修复硬伤，更新模型版本与边界说明。
- [ ] 封装阶段补充案例、工具、使用说明，确保他人可复用。
- [ ] 包装打磨阶段制作课程/文档/卡牌，完成最终交付物。
