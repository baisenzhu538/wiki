# 业务公式假设管理落地策略集：2+3 策略 × 入门/进阶/高阶三级 = 15 格行动矩阵

> **一句话**：学了假设思维却落不了地，问题不在认知而在组织配套——一堂把「业务公式怎么在团队里跑起来」拆成团队侧 2 策略（凝聚共识/配套角色）+ 业务侧 3 策略（加法激发/管理假设/减法评估），再按项目难度分入门/进阶/高阶三级，萃成 5×3=15 格行动矩阵：两三人的小团队用第一排，协作深的中型项目用第二排，时间紧、风险大、困难高的战略级项目才用第三排。以落地策略集原图为一等准，全部数字为课程案例口径。

---

## 一、定义：什么是落地策略集

一堂业务公式课程的最后一环（管理篇）解决的不是「怎么拆公式」，而是「公式拆出来之后，怎么让整个团队围绕着它长期运转」。楚门把这个问题的答案做成了一张 5×3 的矩阵图——《一堂业务公式·落地策略集》（母版 `_vlm_output/业务公式-落地策略集_vlm.md`，为 15 格内容的一等准）：

- **横轴 = 5 个环节（2+3 策略）**：前 2 个管团队（凝聚共识 / 配套角色），后 3 个管业务（加法激发 / 管理假设 / 减法评估）（管理篇-口述 L666-L706）。
- **纵轴 = 3 级难度**：入门起码（经验少/探索多/解法多）→ 进阶专业（协作多/投入高/周期长）→ 高阶挑战（时间紧/风险大/困难高）。
- **执行逻辑**：「共识是基础，角色是保障，加法多了之后管起来，逻辑清楚之后就得做减法」（口述 L706）——五个环节有先后顺序，不能倒着做。

楚门的定位很直白：这张图不是知识点，是**小抄**——「几个月一两年的路上，不断地从里面找策略来落地」（口述 L764）。使用方式是横竖双向读：先判断自己的业务/团队在第几级，把那一排做扎实；不够用了再往下走一排，「第三排挺难的，但你们有足够多的机会空间能做」（口述 L3132-L3138）。

---

## 二、5 环节释义（维度说明，原图口径）

| 环节 | 归属 | 原图释义 |
|:--|:--|:--|
| 凝聚共识 | 团队侧 | 统一团队做事姿势，培养假设驱动追求 |
| 配套角色 | 团队侧 | 有配套的负责人和专家，确保假设有机会落地 |
| 加法激发 | 业务侧 | 充分提假设和寻找机会，不设限，积极探索 |
| 管理假设 | 业务侧 | 有效管理各种假设，有配套机制管理业务公式 |
| 减法评估 | 业务侧 | 评估假设优先级和机会，善于提前预判和排序 |

（落地策略集母版；框架图 005240 佐证。）

## 三、15 格全量矩阵

### 第 1 排 · 入门起码（经验少 / 探索多 / 解法多）

> 课程原话：「但凡想落地业务公式和假设思维，最起码这一排你得有，如果都没有的话，就很难再做了。」（口述 L1018-L1020；口述此处 ASR 误识作「价值思维」，按勘误还原）

| 格 | 原图条目 | 关键动作（口述展开） |
|:--|:--|:--|
| 1.1 | **我们需要假设驱动**：让团队相信，得用高质量假设+验证实现高难目标：✓ 避免纯拍脑袋/结论先行 ✓ 允许验证失败/接受试错 | 共识的底层心态是「假设默认为假，老板说的话也都是假的，在默认错的情况下证明可能对」（口述 L1048）；开放问题下 10 个假设里只有 1 个显著有效是常态——30% 验证有效率就算好，常只有 10%（口述 L1158-L1160，课程经验值）；「我要的是你们的认知速度，我根本不要成功」——从第一天就讲「咱们一定失败」，团队才不沉闷、才敢涌现想法（口述 L1176-L1218） |
| 1.2 | **至少有一个假设负责人**：业务要有且仅有一个主负责人，负责管理假设：✓ 负责记录和备忘 ✓ 负责驱动完成目标 | 「有且只有一个」负责人，可以是业务负责人本人或其副手；负责记录、备忘、驱动，是假设得以落地的最低保障（口述 L1060-L1066） |
| 1.3 | **一号位积极提假设**：一号位要以身作则，积极驱动业务提假设和进步：✓ 自我灵感闪现 ✓ 带领深度复盘 | 一号位自己都不提假设，团队绝不敢提；一号位要自己灵感闪现、带着大家复盘、拿着案例源源不断提假设（口述 L1070） |
| 1.4 | **至少记下来备忘**：最最起码，能记录下来备忘：✓ 个人备忘：想法笔记 ✓ 团队备忘：假设群/文档 | 个人用笔记本/Cubox/手机备忘录，团队用假设群或公共文档；哪怕不整理也要记下来，「随时想追溯的时候都能找得着」（口述 L1072-L1080、L1220-L1254）；楚门自曝早晨半小时能逼自己记 20 条新假设，其中七八成不会验证、验证的 30% 有一两个有效就很厉害（口述 L1242-L1250，课程案例口径） |
| 1.5 | **能讲清楚价值 or 目标**：最最起码，能讲清楚一个假设的价值：✓ 到底为了哪个目标服务 ✓ 到底有什么具体价值 | 还不到谈 ROI 的份上——最起码说清楚「这个假设服务哪个参数、哪个指标、到底有什么价值」；连这点都做不到，业务公式就很难落地（口述 L1084-L1092；口述此处 ASR 误识作「减法无罪」，按勘误还原为「减法评估」） |

入门案例锚点：Vicky 的短视频培训（建测试群+飞书假设池，口述 L776-L880）、温校长的校园代理驾校（六杯奶茶假设，口述 L886-L988）。

### 第 2 排 · 进阶专业（协作多 / 投入高 / 周期长）

> 定位：从「一个人记、一个人备忘」进入「团队协作」——初阶管的是个人，进阶管的是协作（口述 L1916）。

| 格 | 原图条目 | 关键动作（口述展开） |
|:--|:--|:--|
| 2.1 | **我们有明确目标和公式**：对目标和具体的业务公式有共识：✓ 探索型：为什么而奋斗 ✓ 挑战型：努力要完成 ✓ 必胜型：一定要完成 ✓ 理解基本业务公式：参数+逻辑关系 | 三类目标策略：必胜型（KPI，足够确定的工作，严格完成）/挑战型（OKR，「大概率完不成」但驱动团队一直朝它奋斗，如推荐率=100%）/探索型（连数都没有的模糊方向，如出书、内训）（口述 L1538-L1556）；没有高目标就没有理解业务、探索规律的欲望（口述 L1520-L1526）；楚门个人习惯：确定性运营环节设跳一跳够得着的 30%-50% 目标，增长开放性环节定完不成的目标持续追（口述 L1562-L1566） |
| 2.2 | **能充分管理和讨论**：假设想高质量落地，至少包含两个角色：✓ 谁有能力提假设（Discusser 角色）✓ 谁有义务管假设（Admin 角色） | Discusser = 业务一线、有足够经验、能和管理者平等对话、贡献信息的人；Admin = 通常是业务管理者或其副手。两角色是新共识：管理业务的人 ≠ 最有信息提假设的人（口述 L1470-L1480、L2380） |
| 2.3 | **内部积极讨论和调研**：营造团队积极寻找机会，大胆说话、不设限的氛围：✓ 访谈专家经验 ✓ 同行深度调研 ✓ 用户访谈和调研 ✓ 团队/AI 辅助头脑风暴 ✓ 团队深度复盘 | 加法不再是一号位一个人的事：分头调研、分头访谈、分头聊用户、头脑风暴、AI 辅助、一起复盘（口述 L1484-L1488） |
| 2.4 | **团队正式假设池**：构建一个团队共用的完整的假设池：✓ 提出：提出人+内容 ✓ 优先级：价值+成本高低 ✓ 负责：验证人 ✓ 结果：验证结果和认知 | 基本字段=谁提的+提了啥+成本/收益高中低+谁认领验证+有效/无效/未知/一般（口述 L1492-L1500、L1610）；关键辨析：假设池 ≠ 需求池/线索池/项目池——假设颗粒度更小，需求池五十个就满，假设可以几十个上百个；一个需求天然包含若干假设，早期颗粒度拆细一点更好测试（口述 L1580-L1608）；工具建议用云端多维表格（权限+协作），别用本地文档（口述 L1612-L1634） |
| 2.5 | **能完整评估 ROI 优先级**：完整评估一个假设的优先级，包含以下几个维度：1）ROI：价值和成本 ✓ 至少定性：高中低 ✓ 最好定量：预期数值 2）确定性 3）风险和负收益 | 绝大多数假设池不需要严格定量，定性打高中低即可排序；能定量给预期数值范围更好（口述 L1506-L1512）；优先做「价值高、成本还行、确定性高（过去有经验/同行验证过）、风险和负收益可控」的假设（口述 L1514-L1518）；优先级三要素=优化空间大（距同行最佳/未验证过/距 100% 还远）+在乘法关键路径上+确定性高（口述 L1826-L1836）；反常识点：主乘法路径上的「小」转化率极其重要——加微信率涨 20%，营收直接涨 20%、利润可能翻倍（课程案例口径；一堂自己把加微信率从约 50% 优化到 85%-90% 的行业头部水平）（口述 L1864-L1906） |

进阶案例锚点：王同学 MCN 签素人（漏斗公式+团队假设表，口述 L1314-L1370）、潘鸿海线下娱乐综合店（带头写七八个假设、涨价拆三子假设，半年业绩+50%，美团抖音品类榜第一，口述 L1380-L1452，课程案例口径）。

### 第 3 排 · 高阶挑战（时间紧 / 风险大 / 困难高）

> 定位：战略级长周期项目的满配打法。全部以一堂五年十期马拉松（年度大课）的真实管理过程为案例底座（口述 L1919-L2730，课程案例口径）。

| 格 | 原图条目 | 关键动作（口述展开） |
|:--|:--|:--|
| 3.1 | **我们得有足够假设和配套**：不止对目标有强共识，对过程和具体假设也有足够理性的预期：✓ 预期假设数量：大概需要多少规模的假设验证，才有机会达到目标？✓ 预期配套资源：需要配套什么预算、会议、人才能够执行落地？ | 高阶共识最难的一层：让团队相信「这场仗特别难，必须额外提出 N 个关键假设才有机会达成目标」——料敌从宽（口述 L2274-L2300、L2326）；马拉松的核心共识叫「每次迭代 30%」（虽常完不成，心态最重要，口述 L2278-L2284）；教练团队共识「保持 20 个关键假设」（口述 L2310）；配套层：双目标法兜底士气——合格线（达到就不丢人）+优秀线（极难但可冲刺），如某期 850 万±100 万，下限从未跌破（一次事故「跪着守下限」）（口述 L2110-L2144）；顶层策略会：10-15 人围绕四大参数（会员规模/近期活跃/感情培养/未来信心）盘点有利不利条件、现场提假设对抗，十年只开过 3-4 次（口述 L2210-L2256）；目标解构：6-7 维切片（时长/版本/SKU/直播 vs 回放等）逐维监控（口述 L2160-L2192） |
| 3.2 | **配置完整 PEAHD 角色**：在重要的复杂项目里，需要配置一个完整团队，包含以下五个角色（可兼）：1. 倡导者 Promoter 2. 执行者 Executor 3. 管理者 Admin 4. 轰炸者 Hero 5. 讨论者 Discusser | 五角色≠五个人，是五类职能，强者可一人身兼数角（口述 L2410-L2416）；Promoter=布道、推动、营造假设氛围（老板/老师/激励者）；Executor=利益相关方、干活的人，不一定要张嘴但必须在场听；Admin=业务管理者或其副手；Discusser=一线、能与管理者平等对话贡献信息的人；Hero=脑子里装满方法论，「用户觉得贵咋办，啪一下给你五个假设，不行再给五个」的假设轰炸机（口述 L2388-L2408）；用法=找短板：会开得不好时先问缺哪个角色、能不能外请专家补位（一堂讨论 AI 难题时曾外请 5 个能平等对话的专家）（口述 L2418-L2446）。**命名裁定**：原图与勘误均作 **PEAHD**（口述 L2384 误识作「PAHD、PA 合成一个 A」，L2542 误识作「SPDA」，一律还原为 PEAHD） |
| 3.3 | **善于开项目攻坚会**：在关键节点的重要项目卡点上，善于用攻坚会解题：✓ 邀请所有关键讨论/决策人 ✓ 强主持人引导控场 ✓ 现场一轮轮提假设、相互激发 ✓ 现场民主集中制，激发大量业务假设 | 攻坚会=一堂 ROI 极高但极难复制的会：5-15 个最有判断力的人（内部员工+外部专家）拉进封闭屋子，少则 4-5 小时、多则开过 18 小时（四顿外卖、第 14 小时才加入嘉宾），「不解决不出门」，一轮轮讨论-推翻-再讨论，最后民主集中制拍板（口述 L2498-L2510、L2504-L2508；落地策略集原图此处 OCR 作「民众集中制」，按口述 L2562「民主集中制」还原）；产出实例：马拉松选题/故事线/销售策略（做过两轮）/价格规则/新 SKU/营销策略都出自攻坚会（口述 L2504-L2534）；成功率从早期 40-50% 进化到 80-90%+（口述 L2546-L2552，课程经验值）；配套「小抄」是攻坚会的下限保障——想不出假设就翻小抄（口述 L2364-L2372）；复制难点：目前一堂的攻坚会仍需楚门亲自当 Promoter+Hero，无法抽身（口述 L2526-L2530） |
| 3.4 | **围绕公式统一管理**：业务公式不是孤立存在，而是有一套统一自洽的机制：三角模型——顶点=假设池，左下=关键会议，右下=仪表盘，三边=迭代事/协作人/进展数，中心=业务公式 | 人-事-数三角（详见第五节）；每个项目必须说清楚「服务于哪个公式的哪个部分」，说不清楚就先讨论要不要做（口述 L2586-L2590）；过程指标低于预期→咬牙再开攻坚会拉回去（口述 L2604-L2612） |
| 3.5 | **能善于判断验证策略**：难题1：是否需要单独验证，还是直接正式投入做？难题2：是否需要独立测试还是合并一起测试？难题3：数据量不够，要不要坚持一定做实验验证？本质策略：综合考虑确定性和边际 ROI，对于确定性低、边际成本很高的假设要谨慎对待 | 三难题没有标准答案，考验高级操盘手感（口述 L2960-L3002、L2986-L2990）；理想是控制变量大样本随机实验，现实是「马拉松一年就两次实验机会、数据量几十几百根本没法做实验」（口述 L3004-L3010）；**边际 ROI 本质策略**：确定性低+边际成本高的假设最危险，谨慎对待甚至默认不做（如人工打电话：成功率不高但要耗负责人两周）；边际成本极低的假设（丢一条文案、送几块钱小礼品）打包揉进去直接做，不看数据也无所谓（口述 L3022-L3056）；「完美主义的科学也是一种偏执，得治一治」——每个假设都追求剥离清楚严格统计，业务根本没法做（口述 L3076） |

高阶案例锚点（减法评估三案，全部课程案例口径）：
- **双直播间否决**（口述 L2756-L2900）：30% 听课流量是公域非会员；乐观估销冠转化+50%、新用户占直播收入 5-7%、直播占总收入 70%、盘子 1000 万，极限收益仅二三十万；但只要干扰老用户主路径 3-5% 就亏。结论：不做，拉到一个直播间机器做兼容。
- **MBA 提到第二趴**（口述 L2904-L2940）：数据显示第三趴 MBA 销售额已超第二趴整体（流量更少但转化更高、客单更高），第七八次马拉松敢赌这一把，MBA 销量直接+30%。
- **城市巡回否决**（口述 L2942-L2958）：八城两个月覆盖 800 人，占会员不足 10% 且大多是近期活跃人群，不如把时间花在多讲几次课上。

## 四、为什么假设管理独属 C 域（四象限推演）

这是管理篇最通透的一段论证（口述 L1638-L1812）：既然关键假设管理这么重要，为什么不放在关键假设系列课最开头讲，而放在业务公式（C 象限）的最后一节？答案是**四象限里只有 C 域对假设池是刚需**：

| 维度 | 成败问题（A 五步法 / B ROI 决策） | 效率问题（**C 业务公式** / D 动力阻力触点） |
|:--|:--|:--|
| 纵向：假设数量 | 证伪逻辑——一两个关键假设证伪即可做决定，常年维护一张画布就够 | 叠加逻辑——需要大量假设**轰炸**、饱和式攻击；三年提 100 个假设的人，管理水平高于只提 10 个的（口述 L1754-L1758） |
| 横向：周期长短 | 宏观问题天然长周期 | 微观问题天然短周期（ROI 决策几小时到几周） |

组合之后：A=长周期×假设少，B/D=短周期，**唯独 C=长周期×假设多**——业务公式从高目标定下的那一刻起，少则两三个月，多则三年五年十年一直在用（口述 L1786）；这么长的周期里假设不管理就越来越乱，业务会被卡死在一定水平（口述 L1796-L1798、L3102-L3106）。这就是为什么「假设管理」这个管理工具只能长在这张策略集里，而不能长在五步法或 ROI 决策课里。

由此也回答了修炼顺序：C 域的假设管理是 ABCD 里组织复杂度最高的一课（配套详见 `[[framework-一堂-关键假设-ABCD模型]]` 与总纲）。

## 五、氛围三件套：让团队敢提假设、愿提假设

假设驱动不是「多开会」就能落地的，需要一套**氛围机制**让团队把提假设当成日常工作（`进阶篇-口述:2578-2652`）。课程总结了三件套，从低配到高配逐步升级：

| 件套 | 动作 | 核心话术/机制 | 适用阶段 |
|:---|:---|:---|:---|
| **1. 老板常问「这个想法最早是谁提的」** | 管理者在公开场合反复回溯想法来源 | 「这个想法最早是谁提出来的？真厉害」——每周都说（`:2584-2592`） | 最低配置，任何团队今天就能做 |
| **2. 提议者占一半功劳** | 项目复盘时明确贡献分配 | 提出想法的人占 50%，其余执行者分剩下 50%；打破唯结果论（`:2612-2624`） | 团队已有基本信任，可形成隐性共识 |
| **3. 关联绩效/奖金** | 把「提出假设」写进绩效评估 | 设一个板块让每个人写「这段时间我提了什么设想、有多少想法」（`:2626-2632`） | 高配版，需要 KPI/KR 体系支撑 |

**关键心态**：假设是「可能的惊喜」，不是任务清单。在证实之前，假设就是随机的机会——「守住底线，期待惊喜」（`进阶篇-口述:2552-2554`）。团队应该害怕的是**假设池空了**，而不是假设太多验证不完（`:2566-2570`）。

**验证有效率基准**：在比较开放的问题上，10 个假设里只有 1 个显著有效是常态；30% 验证有效率已经很好（`管理篇-口述:1158-L1160`，课程经验值）。这个基准本身也是氛围的一部分——让团队接受试错、接受大量证伪。

## 六、关键机制深讲：以业务公式为中心的统一管理（人-事-数三角）

高阶格 3.4 的底座是一堂《以业务公式为中心的统一管理》图（母版 `_vlm_output/以业务公式为中心的统一管理_vlm.md`），它是整套策略集的组织学内核（口述 L2624-L2710）：

```
                【假设池】——迭代·事
               /            \
              /   业务公式    \
   协作·人 ——（团队对业务因果关系的共同理解）—— 进展·数
            /                  \
      【关键会议】——————————【仪表盘】
```

- **业务公式是中心**：「业务公式就是你们整个团队现阶段对于整个业务因果关系的理解」（口述 L2638）。
- **假设池=事**：假设是用来迭代业务公式的——每个假设服务哪个参数、哪个公式节点，都要说得清。
- **关键会议=人**：有了公式共识，人的协作自然丝滑；开会先拿出公式，看哪个数低于预期、哪个高于预期（口述 L2662-L2666）。
- **仪表盘=数**：仪表盘的数最好与业务公式直接对应，公式就是仪表盘的数据端（口述 L2668-L2672）。
- **业务公式是团队的最大公约数**（口述 L2656）：马拉松十几个子项目、几十个负责人能不乱，靠的就是这张三角图。

反向教训（When NOT to Use 的第一条来源）：很多团队是**以仪表盘为中心**——先定仪表盘再让业务跟着跑，而仪表盘一旦定错、定歪很难迭代，业务就很吃亏；应该以业务公式为中心驱动一切（口述 L3124-L3128）。

## 七、Critique（外部攻击与本域回应）

**1.「这是咨询公司 MECE+假设树的旧瓶新酒」**：麦肯锡 hypothesis-driven approach（见 `[[concept-mckinsey-hypothesis-driven]]`）同样讲假设驱动与假设树。本域回应：咨询式假设树服务于一次性交付（几周出一个答案），业务公式假设管理服务于长周期自经营（两三个月到十年持续迭代），多出了三样咨询框架里没有的东西：组织配套（PEAHD 五角色）、假设资产化（正式假设池跨项目沉淀）、以及对抗熵增的长期维护（口述 L3110-L3112「所有管理动作都是为了对抗熵增」）。

**2.「精益创业的 Build-Measure-Learn 已经够用」**：BML 循环讲验证节奏，但没有回答「一个 50 人公司每年要同时管几百上千个假设时怎么不乱」。本域回应：策略集的第 3 排（预期假设数量共识、攻坚会、人-事-数三角）正是对 BML 在多项目并发场景下失灵的补丁；第 2 排的假设池字段设计则补上了 BML 没有的资产管理层。

**3.「民主集中制攻坚会是权威文化的包装」**：表面看攻坚会最后还是一号位拍板。本域回应：攻坚会的价值不在拍板权，而在「把最强的脑力在最长的封闭时间里对同一个问题做一轮轮推翻」——成功率从 40-50% 到 80-90%+ 的进化（课程经验值）来自流程成熟度（角色凑齐、小抄兜底、强主持人控场），而非权威强度；楚门本人反而是自己复制这套机制的最大瓶颈（口述 L2526-L2530），恰恰说明它是流程依赖而非个人权威。

## 八、When NOT to Use

| 场景 | 为什么失效 | 替代方案 |
|:--|:--|:--|
| 还在生死线上、商业模式未验证的 0→1 阶段 | 此时问题是 A 象限的成败问题（证伪逻辑），一两个假设定生死，不需要假设池轰炸 | 先用五步法画布+关键假设决策（`[[framework-一堂-关键假设]]`），证伪通过后再来 |
| 单次、短周期的具体决策（几小时到几周） | 这是 B 象限 ROI 决策的领地，上假设池=杀鸡用牛刀 | 直接走 ROI 决策四阶（定性→局部定量→全部定量→财务定量，口述 L1912） |
| 单点转化率/动力阻力的局部优化 | D 象限问题，周期短、假设少，一张触点清单就够 | 动力阻力触点工具，不上策略集 |
| 团队连「假设默认为假」的共识都没有 | 跳过第 1 格直接建假设池=建了一座没人用的仓库 | 回 1.1 格：一号位先公开承诺容错，自己先往假设群里扔三个月 |
| 以仪表盘为管理中心的惯性组织 | 仪表盘定错难迭代，公式中心建不起来，策略集会退化成报表会 | 先按第五节把公式拆出来、讲清楚，再谈假设池（口述 L3124-L3128） |

## 九、Failure Modes（症状 → 根因 → 修复）

| # | 症状（可观察信号） | 根因 | 修复动作 |
|:--|:--|:--|:--|
| 1 | 团队围着老板转，老板说什么下面找论据证明什么 | 1.1 格共识缺失：结论先行、默认老板是对的（口述 L1038-L1042） | 一号位公开宣布「假设默认为假、咱们大概率失败」，把容错写进启动会 |
| 2 | 假设聊完就散，三个月后谁也找不着当时的想法 | 1.4 格没做：没有备忘载体（口述 L1078-L1080） | 今天建假设群+云端文档，只扔假设不讨论不点赞，先养成记录习惯 |
| 3 | 需求池里躺着十几条，都说重要，半年没动 | 把假设当需求管：颗粒度太粗，测不动（口述 L1588-L1608） | 把每条需求拆成 3-5 个小假设，按 ROI/确定性/风险三维粗排序 |
| 4 | 会越开越多，但指标池、会议、仪表盘三张皮互不相关 | 缺中心：没有业务公式作最大公约数（口述 L2626-L2634） | 先把公式拆出来并给协作方讲清楚，再把会议议题和仪表盘指标挂到公式节点上 |
| 5 | 一号位一张嘴就是「咱们分两个场做」，团队忙两周没收益 | 减法评估跳过定量推演，直觉拍板（口述 L2798-L2808） | 照双直播间案的颗粒度推演：乐观收益×各环节占比=极限收益，对比主路径受损风险 |
| 6 | 攻坚会开成加班会，一群人磨到半夜没结论 | 角色没凑齐：缺 Hero（没人能持续供假设）或缺强主持人（口述 L2418-L2434） | 会前按 PEAHD 盘点角色，缺的从外部请；桌上摆小抄兜底；定死出口「不解决不出门」 |
| 7 | 一个没拿准的高成本假设被揉进版本，长期吃成本 | 违背边际 ROI 本质策略：确定性低+边际成本高的假设没做单独谨慎处理（口述 L3022-L3040） | 对「固化后持续吃成本」的假设强制单独验证；边际成本极低的才允许打包上 |
| 8 | 每个假设都要求严格 AB 实验，业务推不动 | 完美主义的科学偏执：数据量根本不够（口述 L3076-L3080） | 接受打包验证和方向性判断，只对高风险假设坚持实验 |

## 十、Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:--|:--|:--|
| 刚学完假设思维，回公司不知道怎么让团队接住 | 判断自己的业务在第几级，把该级一整排 5 格列成一页小抄贴出来 | 2 周内：团队里出现第一个非一号位提出的、被记录下来的假设 |
| 假设越来越多，开始乱、开始丢 | 建团队正式假设池（云端多维表格），字段只要五列：提出人+内容/优先级/验证人/验证结果/认知 | 1 个月内池子里 ≥20 条假设，每条都能说清服务哪个公式参数 |
| 一堆假设不知道先验证哪个 | 用优先级三要素（空间大/乘法主路径/确定性高）打分，再叠加风险负收益一票否决 | 排出 Top 5 验证清单，且每条都有预期数值或定性高中低 |
| 战略级大项目（年度大促/新品类/续费季）启动 | 照马拉松打法：双目标→公式切片→顶层策略会（盘有利不利条件）→「每次迭代 30%」共识 | 启动会结束前，团队对「还需要 N 个关键假设+配套什么会议预算」有明确预期 |
| 重要项目卡在某一道题上两周没进展 | 开攻坚会：按 PEAHD 凑 5-15 人，封闭 4-8 小时，强主持人，一轮轮推翻 | 散会时产出一个有共识的方案，且记录了被推翻的备选 |
