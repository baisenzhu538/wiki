## Reusable Knowledge

### 核心定义

1. **单元模型是商业模式中最基础的最小运作单元**。它体现了成本收益结构的最小循环——一个化妆品、一个外卖单、一小时美甲服务、一个扭蛋机、一个商圈、一个投放用户都可以是一个单元模型。

2. **单元模型的核心心法：复制哪个算哢个，哪个最需盯紧哪个**。不是所有模型都要精算，而是找出那个最可能让项目出现重大风险甚至崩盘的模型，作为一号位的盯紧对象。

### 十大单元模型（三方向框架）

| 方向 | 单元模型 | 核心公式/关注点 | 关键问题 |
|:-----|:---------|:----------------|:---------|
| **按销售过程** | 单订单模型 | 单笔收入 − 单笔直接成本 = 单笔毛利 | 一笔订单到底赚不赚钱？ |
| | 单SKU模型 | 单品周转 × 单品毛利 = SKU 贡献 | 哪些SKU是爆款，哪些是滞销？ |
| **按人头** | 单用户模型（C端） | CAC × 转化率 × 复购率 = LTV | 多少钱买一个用户，他未来能下几单、每单赚多少？ |
| | 单客户模型（B端） | 获客成本 + 首单 + 30/180天留存 + 复购潜力 | 哪些客户是真利润来源，哪些是“难缠单”？ |
| | 单销售模型 | 销售日均获客量 × 提成比例 ≥ 当地养活成本 | 给销售的提成，连他当地工资都远远不够，模型成立吗？ |
| | 单履约模型 | 服务者人均产出 − 服务者人均成本 | 年薪30万的讲师，开的班能养活他吗？ |
| **按空间** | 单柜子模型 | 单点位日均流水 − 单点位成本 | 一个柜子放这，每天能产生多少流水？ |
| | 单门店模型 | 单店收入 − 单店成本 = 单店利润 | 一个门店赚不赚钱，能不能复制？ |
| | 单商圈模型 | 片区总客流 × 转化率 × 客单价 − 片区运营成本 | 这个片区的客流、竞争、配送成本是否支撑得起？ |
| | 单城市模型 | 城市总收入 − 城市总成本（含总部摊销） | 这个城市的总收入能否覆盖总成本，规模经济是否成立？ |

> **心法**：复制哪个算哪个，哪个最需盯紧哪个。不是所有模型都要精算，而是找出最可能让项目崩盘的那个模型，作为一号位的盯紧对象。

### 单元模型的三大角色

6. **业务主理人（一号位）**：决定“复制哪个算哪个，哪个最需盯紧哪个”。负责找出最可能让项目崩盘的那个模型，并作为第一优先级来精算。

7. **数据分析师**：负责每个单元模型的数据收集、测算、追踪。确保每个模型有可靠的数据支撑，而不是凭直觉估算。

8. **战略顾问**：负责跨模型的综合分析与风险预判。看到模型之间的联动效应，比如单用户模型的贬化可能会引发单城市模型的崩盘。

### 与已有方法论的关系

9. **单元模型 → 五步法**：单元模型是五步法最核心的课题。五步法的每一步都可以用单元模型来验证——从调研、测试、产品内核、商业模式到公司文化，每个重大决策都应该先算清楚单元模型。

10. **单元模型 → Y模型**：Y模型的成本、收益、时间、空间四个维度，很多时候需要落到单元模型上才能精确衡量。Y模型是方法论，单元模型是工具——方法论需要工具来贯穿。

11. **单元模型 → 关键假设**：每个单元模型的核心假设（如"单销售模型在当地成立"）都是需要验证的关键假设。单元模型是ABCD模型的“核心实验单元”。

## Critique

#### Mintzberg — “涌现战略不是算出来的”

Mintzberg 在《The Rise and Fall of Strategic Planning》(1994) 中论证，战略是“涌现”出来的，而不是“规划”出来的。一个执着于“算清楚每个模型”的管理者，可能会因为过度依赖数据而错过市场中出现的风险机会。单元模型在复制阶段是有用的，但在创新阶段，“第一个模型是否成立”这个问题本身就是错误的——创新者应该问的是"这个模型能不能被推翻"。

#### Christensen — “规模经济在颠覆面前崩解”

Christensen 在《The Innovator's Dilemma》(1997) 中证明，当颠覆性技术出现时，既有企业的单元模型会突然失效。例如，当共享汽车出现时，传统租车公司的"单门店模型"和"单城市模型"在新的单网点/单用户模型面前直接崩解。“复制哪个算哪个”的策略在稳态市场有效，但在颠覆性变革中，策略应该是"查看哪个模型正在被淘汰"。

### 不要用的场景

- **创新业务起盘期**：单元模型需要稳定的业务流程才能精算。在产品-Market Fit 未达成前，过早精算会因为数据波动大而导致错误结论
- **平台级业务的初期**：平台业务的单元模型通常是双边或多边市场，单一的"单用户模型"可能忽视了网络效应与跨边价值
- **依赖关系型业务**：如咨询服务、B2B大客户管理，每个单元的差异化极大，难以用统一模型覆盖

## Constraints & Boundaries

### 适用边界

| 边界 | 说明 |
|:-----|:------|
| 业务流程已稳定 | 单元模型需要可重复的收入/成本结构。PMF 前数据波动大，过早精算易得出错误结论。 |
| 产品/服务相对标准化 | 项目制或高度定制化业务难以用统一单元覆盖，每个项目的成本结构差异过大。 |
| 有基础数据支撑 | 至少能拿到 3-6 个月的真实交易、履约或获客数据，否则参数可信度不足。 |
| 组织愿意"算小账" | 一号位和管理层能接受把总账拆到单元层面，否则模型只能停留在分析报告里。 |
| 非双边/多边平台早期 | 平台业务需考虑网络效应与跨边价值，单一单元模型会遗漏关键经济逻辑。 |

### 常见失败模式

| 模式 | 症状 | 修复 |
|:-----|:------|:-----|
| **模型选择错误** | 单订单/单SKU算出来盈利，公司总账却在亏钱；团队对"哪个单元最重要"争论不休。 | 用"复制哪个算哪个，哪个最需盯紧哪个"重新筛选，补算单销售、单客户LTV、单城市/单门店，找到真正拖累总账的单元。 |
| **隐形成本漏项** | 模型毛利率>20%，实际现金流持续为负；扩张后发现总部摊销、账期资金成本、售后履约从未进账。 | 建立"双口径单元模型"：财务确认口径看利润，现金流口径看健康度；逐项列出隐性成本并归属到单元。 |
| **参数用理想值** | 同一模型不同人算出的结论相差数倍；用最佳案例或假设值代替实际分布。 | 对关键参数做三点估算（乐观/基准/悲观），标注数据来源和置信度；用历史实际值而非规划值。 |
| **静态模型不更新** | 扩张新城市/新店面后发现模型在当地不成立；早期数据过期仍被用于扩张决策。 | 建立"模型动态校准"机制：每进入新区域、每季度复盘核心参数；业务结构变化时重做单元选择。 |
| **过早精算创新业务** | PMF 未达成前就算一单亏一单，团队丧失探索动力；把辅助工具当成否决工具。 | 创新期先用"假设验证"而非"盈亏核算"，单元模型用于识别关键假设，而非在数据不足时直接下结论。 |

## Calculation Template：To B 单销售模型时间闭环速算

以下模板来自 To B 业务最常见的盲区：销售团队扩张后，人均产出下降，但公司只盯着总营收增长。用单销售模型算清"招一个销售是否划算"。

### 基础假设（以某 SaaS 公司为例）

| 参数 | 数值 | 说明 |
|:-----|:----:|:-----|
| 销售月薪 + 社保公积金 | 18,000 元/月 | 一线城市 B2B 销售 |
| 招聘 + 培训周期 | 2 个月 | 入职到能独立跑客户 |
| 成单周期 | 3 个月 | 平均从首次接触到签约 |
| 回款周期 | 6 个月 | 合同分期付款 |
| 客单价（ARR） | 60,000 元/年 | 单客户年合同金额 |
| 毛利率 | 70% | 扣除交付/服务成本后 |
| 提成比例 | 8% | 按回款发放 |
| 销售人均年成单数 | 6 单 | 成熟后 |

### 计算过程

1. **销售全周期成本**（按评估周期 12 个月）
   - 前 2 个月：培训期成本 = 18,000 × 2 = 36,000 元
   - 后 10 个月：正式期成本 = 18,000 × 10 = 180,000 元
   - 12 个月基础人力成本 = 216,000 元

2. **销售创造毛利**（按 12 个月内回款情况）
   - 入职第 5 个月开始成单（2 个月培训 + 3 个月成单周期）
   - 第 5-12 个月可完成约 4 单（假设成单节奏前低后高）
   - 回款集中在第 11-17 个月，**12 个月评估周期内实际回款可能只有 1-2 单**
   - 12 个月内实际回款毛利 ≈ 1.5 单 × 60,000 × 70% = 63,000 元

3. **现金流视角**
   - 12 个月内投入：216,000 元（工资）+ 提成 1.5 单 × 60,000 × 8% = 7,200 元
   - 12 个月内回款毛利：63,000 元
   - **12 个月现金流缺口：约 160,000 元**

4. **18 个月视角**
   - 第 13-18 个月再回款 3-4 单
   - 累计回款毛利 ≈ 6 单 × 60,000 × 70% = 252,000 元
   - 累计成本 ≈ 18,000 × 18 + 6 × 60,000 × 8% = 324,000 + 28,800 = 352,800 元
   - **18 个月仍亏损约 100,000 元**

### 诊断结论

- 只看"单订单模型"：每单毛利 42,000 元，很赚钱。
- 补上"单销售模型"：招一个销售，18 个月内可能都回不了本。
- 修复方向：提高客单价、缩短成单周期、降低销售成本，或重新评估"规模扩张"节奏。

> 参考：徐剑课堂笔记指出"单销售模型是很多公司的盲区，忽略销售培养的隐形成本"；To B 五步法图片 OCR 亦强调"To B 业务一定要算的是单销售模型，这也是最容易忽视、犯错的单元模型"。

## Synthesis

### 与本库其他概念的关联

- [[yt-entrepreneur-five-step-method]] — 单元模型是五步法的核心验证工具——每一步重大决策都应该先算清楚单元模型

- [[master-decision-hygiene]] — 决策卫生要求“先算小账再算大账”，单元模型是这一原则的工具化实现
- [[master-first-principles]] — 第一性原理要求拆到不可再拆，单元模型正是商业分析的第一性原理层

### 可迁移场景

- SaaS产品的单客户ARR模型与单销售AE模型
- 线下零售的单门店模型与单商圈模型
- 内容创业的单用户生命周期价值与单篇内容生产成本

## Open Questions

- 当一个业务同时存在多个可能的单元模型时（如共享单车既有单车模型也有单用户模型），如何判断哪个是“主模型”？
- 单元模型在跨国拓展时，文化、法规、消费习惯的差异会如何影响同一个模型的可复制性？
- AI时代，当数据收集和分析变得极其容易时，单元模型的三角色分工是否会被AI重构？

## Output Opportunities

- 开发一个“单元模型计算器”的互动工具，输入业务参数自动生成十大模型的初步估算
- 为不同行业（电商、SaaS、线下零售、服务业）构建行业化的单元模型检查清单
- 将单元模型与财务报表对接，建立“从单元到总账”的自动聚合机制

## Action Triggers

- [ ] 当你要分析一个新业务时，先问自己：这个业务的“最小可独立运作单元”是什么？
- [ ] 当你发现公司总账不赚钱时，用“十大模型检查清单”逐个排查，而不是看总账
- [ ] 当你决定扩张新城市/新店面时，先算清楚“复制哪个”的单元模型，而不是直接复制整个城市模型
- [ ] 当你发现团队成员只会看总账时，强制要求他们提交至少一个单元模型的精算表
