# 增长阶段标志：单元模型成立 + 找到增长渠道

> 商业模式跑通的标志是：核心单元成立，且找到了一条增长渠道。指标必须放回具体的单元模型里判断，而不是直接看指标。——张磊，AMA Q3（src_20260616_b1e25c49）

## Summary

本框架回答一个关键决策问题：**业务测到什么程度可以进入放大/增长阶段？**

张磊在一堂精益测试 AMA 中给出的核心判断是：进入增长阶段的标志有两个缺一不可的条件——

1. **核心单元模型成立**：业务的最小可复制单元（如单用户、单SKU、单订单）在真实数据下能跑通。
2. **找到一条有效增长渠道**：已经验证至少一条可持续获客或放量的路径。

同时强调：看指标时不能只看表面数字，必须把指标放回单元模型里判断；在进入增长验证之前，必须先确认需求、产品、商业模式等前置假设已经通过。

## Core Claims

### 1. 进入增长阶段的两个硬标志

| 标志 | 含义 | 典型判断问题 |
|:-----|:------|:-------------|
| **单元模型成立** | 业务的最小运作单元在真实环境下能自洽 | 单用户模型：获客成本×转化率×客单价×复购率是否打平？单SKU模型：回本周期能否接受？ |
| **找到增长渠道** | 已验证一条可复制、可放量的获客/增长路径 | 渠道的试错成本、ROI、天花板、能力匹配度是否满足要求？ |

两者必须同时成立。仅有单元模型成立但没有增长渠道，业务无法规模化；仅有渠道流量但单元模型不成立，放大就是烧钱。

### 2. 指标必须放回单元模型判断

张磊反复强调："不能直接看指标，要把指标放到单元模型里去判断。"

### 3. 增长渠道评估的四个维度

在验证增长渠道前，张磊提到可以使用一堂的"渠道判断"评估表格，从四个维度打分：

1. **试错成本**：验证这个渠道需要花多少钱、多少时间。
2. **ROI**：投入产出比是否健康，首单 ROI 能否打平。
3. **天花板**：这个渠道能支撑多大的业务规模。
4. **能力匹配度**：团队是否具备运营这个渠道的核心能力。

### 4. 前置假设优先，风险高的优先

在讨论测试顺序时，张磊指出：

> 前置假设优先，风险高的假设优先。越在需求侧、越在产品侧的假设，风险越高；越往后，风险越低。

## Constraints & Boundaries

### 适用边界

| 场景 | 说明 |
|:-----|:------|
| **前置假设已通过** | 需求、产品、商业模式三类假设已有初步验证，否则进入增长测试属于阶段错位。 |
| **有明确的单元模型** | 团队能清楚说出"我们复制哪个算哪个"——单用户、单SKU、单订单、单门店或其他核心单元。 |
| **有真实数据支撑** | 不是基于推测或少数样本的情感判断，而是有可量化的单元指标。 |
| **处于"验证→增长"的临界决策点** | 需要判断是继续小规模验证，还是进入规模化复制/加大投入。 |
| **多渠道或多场景需要排序** | 同时面对多个潜在增长路径，需要评估试错成本、ROI、天花板、能力匹配。 |

### 不适用边界

| 场景 | 说明 |
|:-----|:------|
| **只看总指标就放大** | GMV、总用户数等总指标无法替代单元模型判断，容易掩盖补贴或结构性亏损。 |
| **老业务下滑但未拆业务公式** | 应先拆业务公式找到真正出血点，而不是直接换赛道或调产品。 |

## Common Failure Modes

| 模式 | 症状 | 修复 |
|:-----|:------|:-----|
| **"总指标幻觉"** | GMV、用户数增长，但单元模型算不过来；汇报时只讲总增长，讲不清单用户/单SKU经济账 | 把总指标拆成单元模型指标，先算清单用户/单SKU经济账；剔除补贴、异常大单、关系单后再看 |
| **"渠道未验证就放大"** | 找到一个流量渠道就大规模投放；投放后获客成本飙升、转化率暴跌 | 用渠道评估表（试错成本、ROI、天花板、能力匹配）先小样本验证；达到稳定ROI后再逐步加预算 |
| **"跳门：跳过前置假设"** | 需求还没验证就测增长渠道；产品内核未打磨就追求放量；前置假设仍是红灯却进入增长测试 | 回到五步法前置步骤，先验证需求和产品内核；使用"阶段门检查清单"逐项确认后再推进 |
| **"指标脱离单元"** | 看到首单 ROI 高就认为模型成立，忽略履约成本、复购或回款周期 | 把指标放回完整单元模型，看全周期现金流；ToB业务还要算清回款周期与自由现金流 |
| **"增长假设优先级错误"** | 同时验证产品、内容、渠道，资源分散；每个都测但都不深 | 按"前置假设优先、风险高优先"排序，一次只验证最关键的假设；其他选项先调研或对标杆 |
| **"把增长问题误判为需求/产品问题"** | 老业务下滑时直接换赛道或调产品，未拆业务公式 | 先用业务公式拆解，区分是需求、产品、商业模式还是增长问题；找到真正出血点 |

## Case Examples

### 案例 1：动漫周边海外独立站（AMA Q3 原题）

**业务背景**：个人做动漫周边海外独立站，面临产品、定价、内容、渠道多项假设。

**张磊的判断过程**：
1. **先拆假设，代入五步法**：产品是解决方案，内容获客/渠道获客属于增长，价格带属于解决方案，具体定价/促销策略属于增长，人群价格敏感性属于需求。
2. **判断优先级**：前置假设优先，风险高的优先。需求侧、产品侧的假设风险更高，应优先验证。
3. **增长阶段标志**：只有当单用户模型或单SKU模型成立，并且找到一条有效的增长渠道（如某社媒内容获客或付费投放渠道），才进入放大阶段。
4. **个人项目成本控制**：人力、时间、资金都有限时，优先对标竞品，充分调研，尽量少用测试，多用调研。

**关键启示**：复杂业务不要同时测所有假设，先确定是否已进入增长阶段，再把指标放回单元模型判断。

## 阶段门检查清单（Jump-Gate Checklist）

在进入增长阶段前，必须逐项确认以下五个阶段门。任一门的红灯未解除，都不应规模化放大。

| 阶段门 | 关键问题 | 通过信号（绿灯） | 跳门风险（红灯） |
|:------|:--------|:----------------|:----------------|
| **需求门** | 目标用户是否真实存在且愿意为解决方案付费？ | 有真实订单/定金或明确付费意向；用户主动复购或推荐 | 只有"感兴趣"但无付费行为；样本来自熟人/关系单 |
| **产品门** | 最小解决方案是否能稳定交付价值？ | 交付后用户满意度高、投诉率低、有自然口碑 | 交付依赖创始人亲力亲为；每次交付质量波动大 |
| **商业模式门** | 单元模型是否跑正？ | 单用户/单SKU/单订单毛利覆盖全部直接成本+分摊成本 | 只看收入不看成本；现金流为负；回款周期过长 |
| **增长渠道门** | 是否找到至少一条可放量渠道？ | 渠道ROI、转化率、天花板已小样本验证；不是一次性流量 | 渠道依赖个人关系；流量成本不可控；没有复购承接 |
| **规模化门** | 团队和组织能否支撑复制？ | 关键流程有SOP；交付/服务能力有冗余 | 每个订单都依赖创始人；团队无法承接新增量 |

### 进入增长阶段的 5 个必答问题

1. **核心单元是什么？** 单用户 / 单SKU / 单订单 / 单门店 / 单销售 / 其他？
2. **该单元的关键指标是多少？** 获客成本、转化率、客单价、复购率、回本周期分别是多少？
3. **这些指标基于多少真实样本？** 是否已排除补贴单、异常大单、关系单？
4. **增长渠道的四个维度是否已评估？** 试错成本、ROI、天花板、能力匹配度。
5. **需求、产品、商业模式三类前置假设中，是否还有红灯？**

### ToB 业务的额外检查项

基于一堂 ToB 五步法，ToB 业务进入增长阶段前还需确认：

| 检查项 | 关键问题 |
|:------|:--------|
| 单销售模型 | 获客销售成本是否被完整计入单元模型？ |
| 回款周期 | 账期是否会导致自由现金流为负？ |
| 角色分离 | 决策者、使用者、付费者是否都已验证？ |
| 交付周期 | 规模化后交付能力和人效能否支撑？ |
