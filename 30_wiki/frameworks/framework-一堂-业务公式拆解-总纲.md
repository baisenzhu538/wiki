# 一堂业务公式拆解总纲：关键假设 ABCD 体系的核心骨架与灵魂

> **一句话**：业务公式拆解不是「把营收拆成流量×转化×客单」这一组固定变量，而是**关键假设 ABCD 体系的核心骨架与灵魂**——它把定性关键假设，经 **ABC 模型 × Ω 模型 × 参数冰山 L1-L6 × 六层逻辑 × 十大范式**，拆到能提出可验证假设的定量参数。本卡是 C 域（业务公式域）总纲，贯通总纲与子卡、工具、案例的导航。来源：一堂（孔源）业务公式系列课（导入/实操/进阶/参数探索/逻辑关系/管理六讲口述逐字稿 + 课件 VLM 原图）。[^1]

---

## 一、本质：参数 + 逻辑关系 = 目标（"1+1=2"）

业务公式的最简形式被课程反复归约为一道算术题：**参数 + 逻辑关系 = 目标**，即 **1 + 1 = 2**（图 001737 ABC 模型图底部「极简业务公式」；`实操篇-口述:94`「特别像是一加一等于2这是参数叠加，逻辑关系」；`参数探索篇-口述:58`「回归到最简单的1加1等于2最简单的公式上」）。

三要素各管一段（`实操篇-口述:92-122`）：

| 要素 | 回答 | 内涵 |
|---|---|---|
| **目标** | 要什么 | 梳理业务、定长期有挑战的目标、拆子目标 |
| **参数** | 靠什么 | 哪些指标/关键动作/要素/节点通向目标，能不能挖出来 |
| **逻辑关系** | 怎么连 | 参数间是乘法还是加法、强关系还是弱关系、相关还是因果 |

**两大核心追求**（`实操篇-口述:1050-1074`）：业务公式最最核心的追求就两个词——**理解业务规律**（持续理解「什么会通向我的目标、参数的子参数又是什么」，规律可能是因果、相关、加法、乘法）与**表达业务规律**（不能只装在脑子里，必须用公式写下来；写得越深入越清晰，就越能聚焦核心指标、集中资源攻破核心环节，而不是撒胡椒面或随机直觉）。

> 「越高难度的目标、越激烈竞争的市场，就越应该找到更好的业务模式、更多的参数、更清楚的逻辑关系，才能进步。依靠粗糙的、经验化的、直觉化的东西，有些事就没法办。」（`实操篇-口述:1072-1076`）

## 二、ABCD 四象限定位：C = 宏观效率（最难但最值钱的一块）

关键假设 ABCD 体系把业务问题按两个轴切成四个象限，每象限配一套操作系统（图 001240 ABCD 模型 V2.0；`实操篇-口述:2-24`；`逻辑关系篇-口述:2-10`）：

| 象限 | 轴定位 | 问题类型 | 配套工具 |
|---|---|---|---|
| **A** | 宏观 × 成败 | 商业成败 | 一堂五步法 |
| **B** | 微观 × 成败 | 单点关键决策 | 投产比 ROI |
| **C** | **宏观 × 效率** | **业务提升** | **业务公式（本卡所在域）** |
| **D** | 微观 × 效率 | 单点关键转化 | 动力阻力触点 |

四条裁定要点：

1. **C = 宏观效率**。业务公式管的是全局性的效率提升，不是单点转化率（单点归 D），也不是商业成败（归 A）或单点决策（归 B）。
2. **最难但最值钱**。「关键假设版图的最后一块，其实就是 C，也是最难啃的骨头」（`参数探索篇-口述:24`）；「业务公式真正对大家的价值更重要、更值钱，但同时它也太难太非标了，不同行业、不同模式用的模型公式都不一样」（`参数探索篇-口述:26-30`）。管理篇亦自述「最难啃的骨头就是 C 这个业务公式」（`管理篇-口述:20`）。
3. **四套操作系统合起来能解决约 90% 的业务问题**（课程案例口径）：「大家以后遇到的可能 90% 的问题，都可以用这四套操作系统去解决」（`参数探索篇-口述:16-22`）。
4. **ABCD 是一套假设驱动系统**，四个象限本质一致：「本质上都是一种通过提假设、验证假设来推动业务进步」（`参数探索篇-口述:3424-3436`）。

> 老底稿印证：「这一次我们也是把**关键假设 ABCD 的体系的最后一块拼图**拼上了。」「业务公式也是一套关键假设 ABCD 体系串起来的核心骨架，才是真正贯穿整套体系的灵魂。」（`孔源-口述:2474-2500`）线下训练营体系中，五步法训练营和科学决策 ROI 训练营之后，业务公式训练营是第三块拼图（`:2482`）。

这意味着业务公式不是关键假设之外的另一门课，而是**关键假设从「定性」走向「定量」的那座桥**：

- 关键假设回答「成不成、哪条最脆弱」（[[framework-一堂-关键假设]]）；
- ABCD 回答「这条假设属于哪类场景」（[[framework-一堂-关键假设-ABCD模型]]）；
- **业务公式回答「这条假设差多少、先动哪、怎么证伪」**——把「我觉得用户会买单」拆成「流量×转化×客单，分别对应 L1-L6 哪几层、哪个低于基准、用哪个实验证伪」。

## 三、ABC 模型与螺旋上升

ABC 模型是业务公式的构造语法（图 001737；详见 [[yt-business-formula-abc-model]]）：

- **A 目标 Ambition**：梳理业务、挑战目标、拆子目标；
- **B 参数 Basis**：关键财务指标 / 关键行为动作 / 关键运营节点 / 关键业务要素；
- **C 逻辑关系 Connection**：相关/因果、分支/关键路径、弱关系-强公式、数学关系 +-×÷。

**螺旋上升**是 ABC 模型的动力学（`实操篇-口述:96-102`）：「你的业务目标越高，就需要找到更多更准的参数和更好的逻辑关系……它是一个螺旋上升的过程，更好的目标，更好的参数，更好的逻辑关系。」搭出一个公式不难，**难的是随着目标不断拔高，必须有更好的参数和逻辑关系去支撑**——这才是业务公式课题真正难、真正重要的部分（`:104-106`）。进阶路径：从简单到复杂、从粗犷到精细、从直觉到科学、从借鉴到创新（`:126-128`）。

公式两个来源取向（图 001737）：**借鉴公式=实事求是**（先掌握十大业务公式，接 [[yt-business-formula-ten-paradigms]]）vs **创新公式=解放思想**（自己创建、探索业务公式）。新业务偏创新但要防拍脑袋，成熟业务偏借鉴但要防照搬。

## 四、Ω 模型与三板斧（≠ 一堂五步法）

Ω 模型是贯穿业务公式实操的闭环工作流（图 001212；`实操篇-口述:130-136`）：

```
明确目标 → 拆解假设（加法）→ 找关键假设（减法）→ 验证 → 坚持/调整/放弃 → 贝叶斯迭代（回到起点）
```

「三板斧」即其中的三记发力点：**加法拆假设、减法找关键假设、验证迭代**。进阶篇的「降龙十八掌」18 招就是 Ω 模型五环节（准备/加法/减法/验证/迭代）的展开（`实操篇-口述:134-136`；图 001759）。

> ⚠️ 已裁定：**Ω 模型 ≠ 一堂五步法**。五步法是 A 象限（宏观成败）的商业建模工具；Ω 模型是跨象限的假设驱动通用闭环。两者混用是本域高频错误。

## 五、段位爬山地图 L1-L6

公式能力有明确的六级阶梯（图 002307 爬山地图，本域总纲图；`进阶篇-口述:3400-3444`）：

| 等级 | 阶段 | 能力段位 | 常见问题 | 提升路径 |
|---|---|---|---|---|
| **L1** | 入门前 | 只低头执行，靠努力埋头执行 | 缺假设驱动：缺欲望/没假设/重复执行 | 有公式意识 |
| **L2** | 入门前 | 有假设意识，散点随机假设 | 缺业务公式：思考碎片/缺结构/假设随机 | 有公式意识 |
| **L3** | 入门 | 有粗糙公式，有基本业务公式 | 缺完备公式：维度单一/不够完备/层级太浅 | 有稳定拆解 |
| **L4** | 进阶 | 有全面公式，多层细致完备 | 缺假设涌现：没灵感/缺氛围/激励不足 | 有持续拆解 |
| **L5** | 高阶 | 有大量假设，沿公式大量涌现 | 缺持续创新：不够本质/不敢创新/缺迭代 | 激发大量高质量假设+无限进步 |
| **L6** | 高阶 | 创新领先，无限进步+行业领先 | 成为最佳实践 | 激发大量高质量假设+无限进步 |

口述版补充（`进阶篇-口述:3412-3438`）：「真正的入门标志是先有一个可操作的公式」；多数人卡在 L2-L3；L5 与 L6 的区别是创新——L5 涌现大量想法，L6 不断创新、无限进步，最终成为行业最佳实践。讲师自评「大概在 5.2、5.3，五之上六之下」（`:3444`）。**用法**：先自评当前段位，再按该段位「提升路径」列修炼，别越级。

## 六、六大价值与三句话

### 六大价值（批注 003139：现在/未来/协作三面向）

用业务公式理解和表达规律，有六个明显好处：

| 面向 | 价值 | 转变 |
|---|---|---|
| 现在 | 维度 | 从局部到全局：维度很多，基于维度找到被忽略的参数 |
| 现在 | 效率 | 从直觉到高效：沿着公式提假设才不是散点，能判断是不是主要路径 |
| 未来 | 迭代 | 从卡住到突破：可以源源不断地优化、迭代和创新 |
| 未来 | 想法 | 从临时到持续：系统性的分析方法可以大量涌现 |
| 协作 | 协作 | 从独立到协作：可以说服团队、形成共识、协作 |
| 协作 | 心态 | 从焦虑到笃定：能解释业务、能说服自己，有了信心和笃定 |

### 三句话（贯穿全系列课的收尾升华）

`实操篇-口述:148-172`、`进阶篇-口述:3490-3578`：

1. **从碎片到体系**：相对墨守成规的固定执行，灵感驱动更好；相对灵感驱动，对标驱动更有确定性；相对对标驱动，假设驱动最可靠——把结果拆成前置条件、再把前置条件拆成前置条件，所有灵感和对标只是一种可能性。
2. **从黑盒到白盒**：把一个决策、一个业务拆成参数和逻辑关系，别人才能参与理解、讨论，自己才能积累认知；白盒化之后，成败瞬间从运气玄学变成体系和科学——可证伪、可讨论、可复制、可迁移。
3. **从愿望到科学**：核心是相信客观存在的因果关系，在假设上思考和做功，这才是确定性；不能每天早上靠磕头求运气。

## 八、修炼顺序 D→B→C→A（反字母顺序，反常识）

> 「在每一个人的职业路上，大致的修炼顺序 D、B、C、A……通常是先学动力阻力触点（D），然后局部的转化率，然后再学 B（局部）的决策，然后再学 C，最后是最难的 A，最后来形成一个非常高水平的业务操盘能力。」（`进阶篇-口述:3586-3590`）

反常识点：不是按 A→B→C→D 的字母顺序学，而是**从最小单点（D）练起，逐步放大到全局（C），最后才碰宏观成败（A）**。C 排在倒数第二——它是操盘能力的集大成，没有 D 的单点手感和 B 的决策训练，直接学 C 容易架空。

## 九、与其他域的边界：C 全局 vs D 单点，C/D 可互转

**C 与 D 的分工**（`参数探索篇-口述:894-902`）：「业务公式比转化率更值钱，因为业务公式里面全是转化率」——公式里这儿乘一个 30%、那儿乘一个 30%，三个 30% 乘在一起就是 2.7 倍；「C 是个全局性的工作，D 是个单点性的工作」。

**C 与 D 可互转**（`参数探索篇-口述:3438-3452`）：C 和 D 呈现极高一致性、可以彼此转化——一个粗的转化率（D）用「拆建推练」一展开就变成一堆转化率，即一个业务公式（C）；一个业务公式一展开又变成一堆转化率（D）。「你的能力一展开就是参数，一个参数再展开可能就是个公式」。很多人 D 做不好是因为 C 不够好；两者螺旋上升：早期粗、是个大参数，越拆越细，动力阻力围绕每一个环节做。C 和 D 是「一套足够本质的、可以击穿岗位的」能力，学会后换岗位、换行业、换项目都能复用，享受十年维度的复利（`:3454-3466`）。

与 A/B 的边界：A（五步法）管「这门生意成不成」，B（ROI）管「这笔钱投不投」，C 管「已成之事如何系统性提效」——成败问题靠证伪，效率问题靠假设轰炸（管理篇四象限论述，详见 [[yt-business-formula-hypothesis-management-playbook]]）。

## 十一、三要素与三大认知突破

### 三要素：看得清 / 讲得明 / 做得准

> 「业务公式如果真的是要在我们业务进行过程中要用，那必须满足这三点。」（`孔源-口述:178-194`；`孔源-笔记:24-27`）

| 要素 | 含义 | 自检 |
|---|---|---|
| **看得清** | 明确业务的根本矛盾在哪个问题、这个问题该怎么判断 | 能用一句话说出当前主要矛盾吗？ |
| **讲得明** | 这个矛盾下有哪些要素、构成什么、解决优先级是什么 | 要素是否列全、是否分了先后（不眉毛胡子一把抓）？ |
| **做得准** | 面对要素能提出哪些假设、有无清晰判断依据 | 每个假设有没有行为指标与基准？ |

### 三大认知突破（`孔源-笔记:31-71`）

| 突破 | 从 | 到 |
|---|---|---|
| **多维度分层拆解** | 看大盘总指标 | 切用户/渠道/行为/场景/SKU（L3） |
| **参数量化** | 定性「我觉得」 | 给每个定性参数配 3-5 个行为指标（L4-L5） |
| **逻辑关系验证** | 把相关当因果、+× 乱写 | 区分相关/因果，先切分（+）再拆转化（×）（接 [[dk-yitang-business-formula-plus-times-trap]]） |

## 十三、贯通链：定性假设 → L1-L6 定量参数（落地）

把一条关键假设拆到可验证，固定走这五步：

```
1. 写目标（A）：用一句话写出要提升的业务结果，≤5 个变量，可量化/可决策/可分层
2. 列参数（B）：按 财务/行为/节点/要素 四类列出影响目标的变量
3. 定关系（C）：判断参数间是 + 、× 、因果（→）还是相关（~）——资源只投 →，~ 只监控
4. 下钻层（冰山）：从 L1 大盘往下，直到「能提出可验证假设」的那层（通常 L3-L5）就停
5. 找基准+设买点：给关键参数找行业/历史基准判断高低，针对最弱环节设计证伪实验
```

**停钻标准**（接 [[yt-business-formula-parameter-iceberg]]）：一个参数是否需要继续拆到 L6，只有一个标准——**这个参数能不能提出可验证的假设？能，就停；不能，继续拆。**

> 口径约束：所有数字、比例、转化率、行业对照均为**课程经验值 / 课程案例口径**（如「四套操作系统解决约 90% 业务问题」「三个 30% 相乘得 2.7 倍」等），降级使用，不作外部事实断言。

## When NOT to Use

- **业务尚无关键假设**：先回 [[framework-一堂-关键假设]] 做假设识别，没假设就拆公式是「为拆而拆」。
- **从 0 到 1 无范式的新品类**：十大范式帮不上，先用 [[yt-business-formula-abc-model]] 自建创新公式，并接受其「拍脑袋」风险。
- **把它当财务建模替代品**：业务公式是「找抓手、做证伪」的诊断工具，不是预算/估值模型；最终财务结论交专业财务。
- **一次性堆叠多个范式**：先定位「下一步最渴望提升什么」选一个主范式，其他范式只解决主范式里的某个子参数（接 [[yt-business-formula-ten-paradigms]] 使用边界）。
- **把 Ω 模型当五步法用**：Ω 是假设驱动通用闭环（目标→加法→减法→验证→迭代），五步法是 A 象限商业成败建模工具；商业生死问题先走五步法，别拿 Ω 硬套。

## Failure Modes

| 失败模式 | 症状 | 修复 |
|---|---|---|
| **停在 L1-L2** | 只看大盘和财务，无法指导动作 | 下钻到 L3-L4：切人群/渠道，拆漏斗断点 |
| **把相关当因果** | 看到「投放↑转化↑」就加大投放 | 推到 L3 因果层，控制变量验证（接 [[dk-yitang-business-formula-plus-times-trap]]） |
| **+× 写错** | 把漏斗当加法平均用力，或把叠加当乘法求全 | 先切分（+）再拆转化（×）；乘法投最弱环节，加法投边际最高 |
| **照搬范式变量** | 直接套「流量×转化×客单」，不管自身业务 | 范式给结构，变量按自身业务重定义 |
| **公式完美参数不准** | L4 形式对、结论错（虚假确定性） | 给参数找基准，用历史/行业数据校准到 L5 |
| **拆到 L6 失可操作** | 公式过复杂，团队无法执行 | 回退到 L4 可操作层；拆得深不如拆得准 |
| **C/D 边界错位** | 拿单点触点优化当全局公式，或拿全局公式抠单点 | 先判象限：全局效率走 C，单点转化走 D；两者可互转但管理动作不同 |
| **越级修炼** | 没练过 D/B 直接上 C，公式架空落不了地 | 按 D→B→C→A 顺序补课；公式必须从业务里长出来 |
