# 跨步一：从0到1的验证

> 一堂五步法：从0到1不是做产品，而是验证假设。验证通过，才能进入1到10。

## 核心框架

从0到1的3个验证：

```
需求验证（Demand）→ 内核验证（Product）→ 单元模型验证（Business Model）
```

| 验证 | 说明 | 通过标准 |
|:---|:---|:---|
| **需求验证** | 用户是否有真实需求 | 用户愿意用、愿意付费 |
| **内核验证** | 产品内核是否解决需求 | 用户使用后愿意推荐 |
| **单元模型验证** | 单元模型是否成立 | LTV > CAC |

## 关键洞察

### 1. 需求验证

| 验证方法 | 说明 | 通过标准 |
|:---|:---|:---|
| **用户访谈** | 深入了解用户需求 | 用户明确表达需求 |
| ** landing page** | 测试用户兴趣 | 注册率 > 5% |
| **预售** | 测试付费意愿 | 付费率 > 10% |
| **MVP测试** | 最小化产品测试 | 用户使用并反馈 |

### 2. 内核验证

| 验证方法 | 说明 | 通过标准 |
|:---|:---|:---|
| **用户测试** | 用户真实使用 | 用户愿意继续使用 |
| **NPS调查** | 用户推荐意愿 | NPS > 40 |
| **留存测试** | 用户留存情况 | 次日留存 > 30% |
| **付费测试** | 用户付费意愿 | 付费率 > 5% |

### 3. 单元模型验证

| 验证方法 | 说明 | 通过标准 |
|:---|:---|:---|
| **CAC计算** | 计算获客成本 | CAC < LTV/3 |
| **LTV估算** | 估算用户生命周期价值 | LTV > 3×CAC |
| **回本周期** | 计算回本周期 | < 12个月 |
| **规模化测试** | 小规模测试规模化 | 单元模型成立 |

### 4. 从0到1的误区

| 误区 | 说明 | 避免 |
|:---|:---|:---|
| **过度打磨** | 过度打磨产品 | 快速验证 |
| **忽视验证** | 不做验证直接做 | 验证优先 |
| **验证不充分** | 验证不充分就规模化 | 充分验证 |
| **忽视单元模型** | 只验证需求不验证商业模式 | 全面验证 |
| **验证后不敢动** | 验证通过后不敢规模化 | 敢于行动 |

### 5. 从0到1的时间管理

| 阶段 | 时间 | 关键 |
|:---|:---|:---|
| **需求验证** | 1-2周 | 快速 |
| **内核验证** | 2-4周 | MVP |
| **单元模型验证** | 1-2个月 | 小规模 |
| **总计** | 2-3个月 | 快速 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **需求虚假** | 需求不真实 | 重新验证 |
| **内核不匹配** | 内核不解决需求 | 调整内核 |
| **单元模型不成立** | LTV < CAC | 优化模型 |
| **过度打磨** | 验证周期太长 | 快速验证 |
| **验证不充分** | 验证不充分 | 充分验证 |
| **验证后不敢动** | 不敢规模化 | 敢于行动 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 创业初期 | 成熟企业 |
| 新产品 | 现有产品优化 |
| 新市场 | 现有市场 |
| 验证阶段 | 规模化阶段 |
