# 一堂关键假设：用假设驱动业务的方法论入口总框架

> **一句话**：关键假设课是一堂整个课程体系的「第一节必修课」与方法论入口，内核只有一句话——**用假设驱动业务**；方法论骨架是**三板斧（加法→减法→验证→迭代）**，场景定位靠**关键假设 ABCD 模型**，本质是**风险管理**，而定性假设要落到可验证，必须贯通**业务公式 L1-L6 定量化**。本卡统摄这四根柱子，是 [[framework-一堂五步法]] 商业分析版的「第 0 步/前置入口」。

---

## 一、定位：第一节必修课 / 方法论入口

Truman 自述这节课「是**第一课**，是所有课里面听的人数最多、也受好评最多的课」（`truman-口述:22`），是「我送给大家的一节**商业必修课**……**第一节必修课**」（`:38-40`），并历经「**六轮大的升级**」（`:42`，本次为第七次）。直播间累计触达人数为**课程经验值**量级（`:36`，口径降级，不作外部事实）。

> 之所以是「入口」：它不是某一门具体技能，而是一堂所有方法论（五步法、需求冰山、产品内核、单元模型、业务公式）共同默认的**思维前提**——**先看前提条件，再谈执行计划**。没有这一层，后面的框架都会被用成「愿望驱动的精致计划」。

本卡是入口的总纲，四根柱子各有子卡：

|---|---|---|
| 道·核心命题 | 本卡第二节 + [[concept-一堂-key-assumptions]] | 为什么要用假设驱动？什么是关键假设？ |
| 法·三板斧 | [[framework-一堂-关键假设-三板斧]]（骨架）+ [[tool-一堂-hypothesis-validation-three-axe]]（操作） | 怎么从一堆假设收敛到最值得验证的几条？ |

| 术·业务公式 | [[framework-一堂-业务公式拆解-总纲]] + 7 张 `yt-business-formula-*` | 怎么把定性假设拆到 L1-L6 可验证参数？ |

## 二、核心命题：用假设驱动业务

> 原话：「我后面总结了一个词叫做**用假设来驱动业务**……你现在负责这个业务、这个渠道、这个产品的关键假设是什么？我们把这种思考习惯的创业者就叫做 **Y 型创业者**。」（`truman-口述:364-366`）

**假设**：「你这个事如果想成它所依赖的那些前提条件——什么东西成了它才能成。前提条件就是你的假设，这些假设成立了，你的模式基本就可以跑通了。」（`:376-378`）

**关键假设**：「里面最关键的……你要关注 28 法则，把主要精力放在最重要那一条、两条、三条，最多五条上……一号位盯紧的那些最重要的、风险最高、优先级最高的假设。」（`:388-400`）

三条推论：

1. **Idea 不值钱，关键假设才价值千金**（`:584`）。想到一个 idea 不难，难的是判断它依赖的关键假设在什么时间点成立。创意免费，对前提条件的判断才是稀缺能力。
2. **创业本质是验证假设，不是执行计划**。不要把创业理解成铁板一块，要「识别风险最高的关键假设」（`:818`）；直面失败、拆假设远好过没有假设意识（`:962-982`）。
3. **X 型（愿望驱动） vs Y 型（假设驱动）**。X 型默认「一定能成」、all-in；Y 型默认「大概率会失败」、先找最脆弱前提、用小成本逐一验证。差异不在聪明，而在敢不敢面对「我可能错了」。

> Truman 招人标准也落在这里：看一个人能不能把生意用 L3-L5 的关键假设「定性定量地描述出来」（`:1982-1998`）——这正是第二节「定性→定量」贯通的来源。

## 三、道法术场景：四根柱子一张图

```
关键假设（入口总纲）
├── 道：用假设驱动业务（Y 型创业者，Idea 不值钱）
├── 法：三板斧 = 加法（解构要素）→ 减法（找风险最高假设）→ 验证（最便宜策略）→ 迭代（贝叶斯）
├── 场景：关键假设 ABCD = A 商业 / B 决策（宏观—微观）/ C 增长 / D 转化；成败问题 + 效率问题
├── 本质：风险管理（关键假设是一组乘法关系，任一不成立=系统性不成立）
└── 贯通：定性假设 → 业务公式 ABC × 参数冰山 L1-L6 × 六层逻辑 → 最便宜验证买点
```

| 层 | 角色 | 一句话 |
|---|---|---|
| 道 | 思维前提 | 先看前提，再谈计划 |
| 法 | 收敛方法 | 加减验证迭代，把 100 个假设收成 2-3 条 |
| 场景 | 定位器 | 知道自己在解决哪类问题，匹配哪类工具 |
| 术 | 定量化 | 把「我觉得」拆成「我看到」的可验证参数 |

四者缺一不可：只有道没有法，停在口号；只有法没有场景，用错工具；只有场景没有术，假设永远定性、无法证伪。

## 四、关键假设的本质：风险管理

> 原话：「你的关键假设它是**一组全部成立的模式**在成立。我无法形成个乘法关系啊，注意**它不是加法关系**……每一个格子都是乘法，其中一个不成立，就是**系统性的不成立**……你再多的 1 乘以个 0，它都是零。所以**关键假设的本质就是风险管理**，就是你们敢不敢直面风险，敢不敢把你的风险转成假设，提前去验证，保证我们不会一错到底。」（`truman-口述:2460-2476`）

两句话落地：

- **乘法而非加法**：需求×产品内核×商业模式×增长×壁垒，任一环节为零则整体为零。所以不能「需求好了、商业模式差一点没关系」——差一点可能就是零。
- **风险管理而非风险消除**：目的不是把不确定性降到零（不可能），而是「把风险转成假设、提前验证、不一错到底」。某关键假设失败 = 业务巨大硬伤（`:1810`），发现越早，止损越便宜。

找关键假设的三个方向（`:2478-2482`）：**内部判断**（静下心来拆假设、鼓励团队提失败点）、**专家咨询**、**进行调研**。

## 五、定性 → 定量：与业务公式贯通

> 孔源原话：「这一次我们也是把**关键假设 ABCD 的体系的最后一块拼图**拼上了。」（`孔源-口述:2474`）「咱们**业务公式也是一套关键假设 ABCD 体系串起来的核心骨架，才是真正贯穿整套体系的灵魂**。」（`:2500`）

贯通的逻辑链：

```
关键假设（定性：「用户愿意为 X 付费」）
   ↓ 用 ABCD 定位：这是「商业场景·成败问题」
   ↓ 用业务公式 ABC 拆：A 目标（付费率）/ B 参数（流量×转化×客单）/ C 逻辑关系（×漏斗）
   ↓ 用参数冰山 L1-L6 下钻：L1 大盘 → L3 切人群 → L4 拆漏斗断点 → L5/L6 本质参数
   ↓ 用六层逻辑校准：从 R~r（相关）推到 R=f(A,B,C)（因果）再到 R=(A+B)×C×D（公式）
   ↓ 输出：最便宜验证买点（针对最弱环节设计证伪实验）
```

**为什么必须贯通**：定性假设只能回答「成不成」，无法回答「差多少、先动哪」。把假设拆到 L1-L6，才能给每个参数找到行业/历史基准，判断「低还是高」，并把验证成本压到失败损失的 1/10 以内。详见 [[framework-一堂-业务公式拆解-总纲]]。

> 口径约束：本节所有数字、比例、转化率均为**课程经验值 / 课程案例口径**，不作为外部事实断言。

## 六、与五步法的关系：第一节必修课 / 第 0 步

五步法（机会预判→需求分析→产品内核→单元模型→规模化）天然包含假设驱动：Truman 自述早期即用五步法「在自己身上测关键假设」（`:1560,1644`）。因此本域不是五步法之外的另一套，而是 [[framework-一堂五步法]] 商业分析版的**思维前提与第 0 步**：

- 进入五步法 Step 1（机会预判）之前，先问「这个机会依赖哪些关键假设」——用本卡；
- 五步法每一步的换档条件，本质都是「该步关键假设是否被验证」——用 [[framework-一堂-关键假设-三板斧]]；
- [[agent-一堂五步法教练]] 启动时，应先做一次关键假设识别（由 [[agent-一堂-关键假设教练]] 完成），再做阶段路由。

## When to Use

- 准备投入实质性资源的创业/新项目，动手前先拆前提
- 团队对方向有分歧，需要把「争结论」转成「争假设、先验证」
- 业务遇瓶颈，怀疑某个关键假设不成立但说不清是哪条
- 招人/评估操盘手，看对方能否定性定量描述生意的关键假设

## When NOT to Use

- **轻量级、试错成本极低的软件快速迭代**：直接上线本身就是最便宜验证，重画假设树反而拖慢（详见 [[dk-mckinsey-hypothesis-driven-pitfalls]]「低成本试错天然行业」攻击）
- **从 0 到 1 创造新市场**：假设列表可能是白纸，「先验证再投入」会错过窗口；这类场景更适合设计思维/JTBD
- **已有明确市场验证、合同锁定的成熟业务**：关键假设已被客户验证，再走一遍是浪费
- **用它替代行动**：Y 型也可能陷入「永远在验证、永远不行动」——假设驱动是降低不确定性到可接受，不是消除不确定性

## Failure Modes

| 失败模式 | 症状 | 修复 |
|---|---|---|
| **把目标当假设** | 写出「今年做到 1000 万营收」 | 那是结果；改问「要做到 1000 万，依赖哪些前提」 |
| **加法上瘾** | 拆出上百个假设，无法着手 | 强制减法：前置性×风险性排序，聚焦 2-3 条、最多 5 条 |
| **只做加法不做减法** | 列完清单就结束 | 每条假设旁必须标「验证方法+截止日期」，没标=不存在 |
| **把相关当因果** | 看到「投放↑转化↑」就加大投放 | 推到 L3 因果层：控制变量，去掉投放看转化是否还涨 |
| **+× 写错** | 把漏斗当加法平均用力 | 接 [[dk-yitang-business-formula-plus-times-trap]]，先切分（+）再拆转化（×） |
| **定性停在 PPT** | 假设永远「我觉得」，无法证伪 | 强制下钻到 L4-L5，每个定性参数配 3-5 个行为指标 |
| **否定信号被忽视** | 前置假设被证伪还继续投入 | 前置假设不成立 = 业务需终止或重大调整，不是「再试一次」 |
| **未知未知盲点** | 加法列表越长，对未知的盲点越大 | 每轮验证后问「还有什么是我没想到的」，保留外部视角 |

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|---|---|---|
| 有一个 idea 想验证 | 用「用假设驱动业务」问：这个业务/渠道/产品的关键假设是什么 | 一页纸写出 5-15 条前提条件 |
| 假设太多不知道先验哪个 | 按前置性×风险性排序，聚焦 2-3 条 | 明确最脆弱的那条前提 |
| 团队争论不休 | 让各方写出观点背后的关键假设，先验最前置那条 | 争论从「结论」降到「可验证假设」 |
| 要把定性假设变可验证 | 走 ABCD 定位 → 业务公式 ABC → L1-L6 下钻 | 每个关键参数有基准、有证伪实验 |
| 验证结果与假设不符 | 判断是前置假设（终止/大调）还是边缘假设（调整） | 在损失放大前止损或纠偏 |
