# 九层深挖法：商业分析的自我纠错式迭代框架

> **实战验证**：药柜案例分析中，通过九层迭代从单点财务模型逐步补全到政策边界、失败模式、隐性成本、招商骗局、诊所协同风险，最终形成可用决策框架。
>
> **核心洞见**：高质量商业分析不是一次性输出，而是不断发现逻辑缺口、调用知识库补缺口、发现新矛盾、再补缺的自我纠错过程。**这和一个情报分析员的工作方式完全一致——你永远不可能第一次就输出正确结论，你只能通过逐层逼近，让错误越来越少。**

---

## 起源与外部验证

### 我们的实战起源

九层深挖法不是从教科书里来的。它是我们在智能药柜项目的实际分析中长出来的——最初只有一个财务模型（L1），算完发现数字看起来很好但总觉得哪里不对。于是回头看假设（L2），发现日均销售额的假设跨度太大。再查政策（L3），发现不同城市的药柜准入标准完全不同。再挖失败案例（L4），发现一堆人踩过的坑我们差点也要踩。如此逐层追加，最终形成了九层的完整分析框架。

### 与CIA竞争性假设分析（ACH）的深层同构

全网交叉验证发现，我们的九层深挖法与CIA情报分析界的**Analysis of Competing Hypotheses (ACH)**存在深层同构：

| ACH八步法 | 九层深挖法对应层 | 共同原则 |
|:---|:---|:---|
| 识别所有可能假设 | L1-L2（业务公式+假设审计） | 不先入为主，列出所有可能性 |
| 收集证据 | L3-L5（政策+失败+隐性成本） | 证据要原子化，逐条评估 |
| 建立矩阵 | L6-L7（执行+情绪） | 多维度交叉 |
| 排除而非确认 | L4+L8（失败模式+边界案例） | **核心原则一致：找反例比找正例更有价值** |
| 得出临时结论 | L9（决策框架） | 结论是可证伪的，不是最终的 |

ACH之父Richards Heuer的原则是"被最少证据反驳的假设是最稳健的"——这和我们的L4（失败模式库）+L8（边界案例）的设计哲学完全一致：**不是去找支持你做这件事的证据，而是系统性地去找"这件事为什么可能不行"。**

### 与一堂九层宝塔的定位区分

| 维度 | 一堂九层宝塔 | 我们的九层深挖法 |
|:---|:---|:---|
| **性质** | 战略诊断框架 | 商业分析执行框架 |
| **核心问题** | "问题出在战略的哪一层？" | "这个商业决策的完整风险画像是什么？" |
| **九层含义** | 方向/目标/定位/路径/共识/组织/能力/资源/机制 | 业务公式/假设审计/政策边界/失败模式/隐性成本/执行能力/市场情绪/边界案例/决策框架 |
| **驱动逻辑** | 从症状反推根因 | 从表面模型逐层深挖到可决策 |

**两者互补**：先用九层宝塔判断"战略问题出在哪"，再用九层深挖法把那个方向的分析做透。

## 九层详解

### L1：表面业务公式 / 单元模型

建立最基础的收入-成本-毛利-回本框架。这层不问"对不对"，只问"是什么"。

| 问题 | 示例（药柜案例） |
|:---|:---|
| 核心业务公式？ | 收入 = 点位数 × 单点日均销售额 × 365 |
| 固定成本？变动成本？ | 设备采购、点位租金 vs 药品采购、补货物流 |
| 毛利空间？回本周期？ | 单点日均50-400元区间，回本6-24个月 |

### L2：假设审计

检查L1中每个数字的假设依据。**这是大多数人跳过的层——也是最多人栽在这一步。**

| 每个数字是事实、估算还是愿望？ | 50-400元区间是没有实地验证的粗略估算 |
| 保守/中性/乐观边界？ | 保守：日均30元（三四线社区），乐观：日均200元（一线商圈） |
| 哪个数字最敏感？ | 日均销售额——10%的变化=回本周期半年以上的偏移 |

### L3：政策/合规/监管边界

找出影响整个收入模型的"不可抗力"。

在药柜案例中：一类/二类药品的经营许可范围、不同城市对智能售药机的监管态度、处方药销售是否需要执业药师在岗——这些问题如果不查清楚，L1算得再漂亮也是空中楼阁。

### L4：失败模式库

从真实失败案例中提取共因和预警信号。**这是九层中最有价值的一层。**

### L5：隐性成本与替代方案

补全显性成本之外的经济现实：机会成本、管理成本、合规成本、试错成本。同时分析用户的替代方案如何压缩定价空间——用户不是在你和你的竞品之间选，是在你和"其他所有解决方案"之间选。

### L6：人与组织的执行能力

商业模式需要的团队能力 vs 现实中你能调动的人力资源。药柜案例：50台设备需要的运维团队远超最初估算；选址能力不是"雇一个人"能解决的。

### L7：市场情绪/资本/招商骗局

识别非理性的市场放大器和常见陷阱。"加盟骗局""躺赚""半年回本""知名品牌背书"——这些关键词的出现本身就是预警信号。

### L8：边界案例与反例

找到"看似能做但其实不能"和"看似不能但其实可以"的边界。

药柜案例中的关键边界问题：药柜放在医院内部（诊所协同模式）vs 放在社区（纯零售模式）——是两个完全不同的商业逻辑。混为一谈就会得出错误结论。

### L9：整合为决策框架

把前8层整合为一个可执行的判断流程：go/no-go/需验证 + 最大风险点 + 最小验证路径 + 重新评估触发信号。

## 停止条件

| # | 条件 | 说明 |
|:---:|:---|:---|
| 1 | 逻辑自洽 | 各层之间没有明显矛盾，关键假设都有边界 |
| 2 | 新信息增量<10% | 再挖一层产出的新信息少于上一层的10% |
| 3 | 用户喊停 | 用户明确说"够了"或"先到这" |
| 4 | 知识库明确缺口 | 再往下挖需要新的外部信息，且该信息当前不可得 |
| 5 | 已产出可执行决策框架 | 第9层已完成 |

## Constraints & Boundaries

### 适用边界

1. **具体商业/行业/投资分析**：新业务进入、商业模式判断、投资决策支持
2. **复杂问题，表面信息明显不足以决策**
3. **用户明确要求"深挖"或需要深度分析时**
4. **有可调用的知识库支撑**（否则到L4-L5会遇到知识库缺口）

### 不适用场景

1. **简单事实查询**（不需要深挖）
2. **已有标准答案的常规问题**
3. **执行型任务**（按SOP做即可，不需要分析）
4. **信息极度匮乏**（连L1都建立不了）

### 禁止事项

| # | 禁止行为 | 原因 |
|:---:|:---|:---|
| 1 | 未收到"深挖"指令就自动启动九层流程 | 浪费算力，输出过长 |
| 2 | 为了凑够9层而重复已知内容 | 每层必须有新信息增量 |
| 3 | 只用通用商业套话，不调用具体知识库卡 | 失去知识库优势 |
| 4 | 忽略低置信度信息的标注 | 会误导决策者 |
| 5 | 把中间层输出当作最终结论 | 必须收敛到第9层决策框架 |

## Common Failure Modes

| 失败模式 | 症状 | 修复方法 | 预警信号 |
|:---|:---|:---|:---|
| 停在L1就做决策 | 算完业务公式觉得"数字不错"就开干 | 强制走完至少L2-L4 | "这账算下来挺赚钱的" |
| L2假设审计走过场 | 每个假设都标"中等置信度"不做敏感性分析 | 强制做"最坏情况"压力测试 | 假设清单很长但全是中等置信度 |
| 跳过L4失败模式 | 觉得"我的情况不一样" | 找到至少5个真实失败案例，找到与你最像的那个 | "那些失败的都跟我情况不同" |
| L7被市场情绪带偏 | 读到"行业前景广阔"就跳过L7 | 主动搜索"XX骗局""XX加盟后悔" | 所有公开信息都是正向的 |
| 九层走完但L9决策框架模糊 | "结论：可以做，但有风险"——这不是决策框架 | 必须给出可证伪的go/no-go条件和最小验证路径 | 结论没有"如果…则停止"的触发条件 |

## 行动触发器

1. **收到用户"深挖"指令**：自动启动九层流程
2. **L1完成后**：强制做L2假设审计——不通过不进入下一层
3. **任一层发现知识库缺口**：标注缺口，向用户汇报，请求补充信息
4. **L9完成后**：输出决策框架，标注置信度分层
5. **分析完成后**：用迭代递归深挖法反照本次分析有没有系统盲区

### 与王欢OODA闭环的深度比对

王欢引入的OODA（Observe→Orient→Decide→Act，源自John Boyd军事决策理论）与九层深挖法，表面上一个追求速度、一个追求深度，但底层存在深层同构：

| 维度 | OODA（王欢/Boyd） | 九层深挖法（老顽童实战） |
|:---|:---|:---|
| **核心目标** | 通过快速循环逼近正确决策 | 通过逐层剥开避免致命风险 |
| **底层信念** | "你不是因为确定了才行动，是因为行动了才更快确定" | "你不是一次性输出正确答案，是通过发现缺口不断纠错" |
| **驱动引擎** | **TEMPO**：比对手快一圈就赢 | **DEPTH**：比表面分析多一层就少一个盲区 |
| **动作节奏** | 小步快跑——每一圈都在加速 | 深挖慢出——每一层都在加固 |
| **信息获取方式** | 行动本身就是信息采集手段 | 逐层调用知识库+外部验证 |
| **人的角色** | 定向+决策（AI辅助观察+执行） | 判断+归因（知识库提供证据） |
| **适用场景** | 战术决策——需要快速迭代验证 | 战略决策——需要全面风险画像 |
| **外部同构** | ACH（竞争性假设分析） | ACH（同一方法论的不同应用侧重） |

**互补关系**：OODA回答"怎么在不确定中快速行动"，九层深挖回答"怎么在行动前系统排查风险"。在实际运用中——
