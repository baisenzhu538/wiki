# 实事求是：把「我希望是真的」和「事实是什么」分开

> **一句话**：实事求是 = 理解真实的事实 + 基于事实找规律；在具体决策中，就是先把「我希望是真的」和「事实是什么」分开。

## 在 Y模型中的位置

实事求是是从「相信因果规律」生长出的第一层能力。

| Y模型层级 | 对应能力 | 说明 |
|:---|:---|:---|
| 根 | 客观因果规律 | 相信世界可被认知、有规律可循 |
| 第一层能力 | **实事求是** | 区分事实与愿望，区分规律与臆测 |
| 第二层能力 | 解放思想 | 在尊重事实的基础上突破隐含假设 |
| 工具 | 定性定量 / 科学类比 / 假设驱动 / 提炼建模 | 把实事求是落到操作层面 |

> 素材来源：周子敬「实事求是」课程整合笔记；「实事」与「求是」被拆解为两套可训练的能力段位。

### 在 Y模型 引擎循环中的触发与衔接

实事求是是 Y模型 引擎循环中**步骤 6**（区分事实/假设/信念）的具体操作方法。

**触发信号**——以下任一出现时，立即启动实事求是校准：
- 讨论中频繁出现"我觉得""应该是""肯定是"
- 同一个数字被不同人引述时差 2 倍以上
- 团队对某个结论高度一致，但说不出反面证据
- 一个假设被验证超过 3 轮仍在"优化中"而没有实质性更新

**校准后下一步**：
- 如果发现大量"信念"（无证据但深信不疑）→ 进入**解放思想**（`framework-yitang-jiefang-sixiang`），挑战这些信念的隐含假设
- 如果事实已经足够支撑决策 → 进入**知行合一**（`method-yitang-y-model-engine-cycle` 步骤 9），落地执行

> 完整循环参见：[[method-yitang-y-model-engine-cycle]]

## 核心动作

| 动作 | 做什么 | 典型问句 |
|:---|:---|:---|
| **定量描述** | 把关键判断翻译成可观察、可验证的数字或事实 | 「这个指标是如何定义的？统计口径是什么？」 |
| **规律边界识别** | 引用任何规律时，同步列出适用前提与失效场景 | 「这个规律在什么条件下成立？什么条件下不成立？」 |
| **红队蓝队** | 把团队分成支持与反对两方，强制为反面辩护 | 「如果我们是竞争对手，会怎么攻击这个方案？」 |
| **魔鬼代言人** | 指定一人专门寻找反面证据和失败条件 | 「这个项目最可能在哪个环节死掉？」 |
| **反面证据搜索** | 主动寻找与当前结论相矛盾的事实 | 「过去 12 个月里，有没有反例？」 |

## 常见自欺信号

| 信号 | 表现 | 即时反打 |
|:---|:---|:---|
| **确认偏误** | 只收集支持自己观点的证据 | 强制列出 3 条反面证据才允许进入下一轮讨论 |
| **愿望思维** | 用「希望」替代「事实」，数字只挑好看的 | 把「我希望」改成「我假设」，并给出证伪条件 |
| **叙事美化** | 失败归因于「意外」，成功归因于「能力」 | 复盘时先写「如果同样的情况再来一次，我会怎么做不同」 |
| **动机性推理** | 为了证明自己正确而选择性解释数据 | 让未参与该项目的人独立审阅数据与结论 |
| **事后合理化** | 结果出来后，用一套漂亮逻辑包装 | 决策前写下预判，事后对照，区分预测与解释 |

## 验证成本阶梯

面对一个关键假设，按成本从低到高选择验证方式：

```
常识 → 情报 → 实验 → 全量投入
```

| 阶梯 | 方式 | 适用场景 | 风险 |
|:---|:---|:---|:---|
| **常识** | 行业基准、公开数据、专家共识 | 方向性判断、快速排除明显错误 | 可能忽略项目特殊性 |
| **情报** | 竞品调研、用户访谈、专家访谈 | 需要了解竞争格局或用户真实动机 | 样本偏差、信息过滤 |
| **实验** | MVP、A/B 测试、小范围试点 | 需要验证因果假设 | 实验设计缺陷、外部效度有限 |
| **全量投入** | 大规模资源投放 | 假设已被多轮验证 | 一旦假设错误，沉没成本最高 |

> 来源：课程整合笔记中的「创业者定量研究小抄」与「培养务实团队·关键沟通话术清单」。

## 创业者定量研究小抄

每次输出关键数字时，强制回答五问：

1. 这个指标是如何定义的？（统计口径）
2. 你具体怎么测算的？（计算与统计方法）
3. 竞争对手是多少？（竞争情报调研）
4. 有没有行业基准值？（Benchmark 常识）
5. 你的测算结果说服力如何？（重点是面对投资人或团队能说清楚）

常用六维指标体系：市场现状、用户需求、模型收入、模型成本、模型指标、日常运营。具体指标包括 TAM/SAM/SOM、ARPU、LTV、CAC、ROI、留存率、复购率等。

## OPC 智能体适配

可将实事求是映射为两类智能体：

| Agent 角色 | 职责 | 人机分工 |
|:---|:---|:---|
| **输出审计助手** | 检查 AI/人输出的结论是否有事实依据、数据口径是否清晰 | Agent 标记可疑断言，人类补充证据 |
| **反面证据搜索助手** | 针对用户输入的假设，自动搜索反例、失效条件和竞争情报 | Agent 生成反证清单，人类判断权重 |

设计要点：Agent 不替用户做判断，而是强制把「我认为」转写为「我假设」，并追问证伪条件与事实来源。

## Checklist

1. [ ] 当前讨论中是否有人把「希望」当成了「事实」？
2. [ ] 关键数字是否有明确的统计口径和来源？
3. [ ] 是否至少列出了 3 条反面证据或反例？
4. [ ] 引用的规律是否标注了适用边界和失效条件？
5. [ ] 验证方式是按「常识 → 情报 → 实验 → 全量」选择的最低成本方案吗？
6. [ ] 是否指定了魔鬼代言人或红队角色？
7. [ ] 复盘时是否区分了「预测」与「事后解释」？
8. [ ] 对外承诺是否 ≤ 内部能力的 70%？
9. [ ] 每个抽象判断是否配了 1 个具体案例或数据？
10. [ ] 团队是否建立了「事实-猜想」分离卡机制？

## Anti-patterns

| 反模式 | 症状 | 修复 |
|:---|:---|:---|
| **主观臆测** | 用「我觉得」「我认为」做决策 | 改成「我假设……因为……」，并给证伪条件 |
| **忽略事实** | 面对客观数据视而不见，靠情绪决策 | 决策前强制回答：我是否主动搜集了反面证据？ |
| **以偏概全** | 只看成功案例，忽视失败样本 | 多种方法交叉验证，确保样本代表性 |
| **不会定量** | 知道要量化但缺工具 | 先用「创业者定量研究小抄」建立最小指标体系 |
| **过度预测** | 早期项目做 5-10 年精确财务预测 | 对外承诺 = 内部能力 70%，每个预测附带假设与置信度 |
| **金句迷信** | 把「产品为王」「唯快不破」当万能公式 | 听到金句立刻追问：适用场景和前提条件是什么？ |
| **知行分裂** | 分析得头头是道，会后没人动 | 每次会议结束必须写一个 48 小时内可验证的最小动作 |

## Critique

### 外部反对者

1. **Daniel Kahneman（判断心理学 /《噪声》）**：反自欺清单能减少系统偏差，但无法消除「判断噪声」——同一问题不同专家可能给出截然不同的评估。结构化框架会把不一致的估计包装成精确数字，反而掩盖分歧。
2. **Paul Feyerabend（科学哲学，《反对方法》）**：历史上重大科学突破并非都遵循「假设-验证-迭代」的统一方法。把实事求是包装成普适规范，可能混淆科学的公共关系宣传与科学真实发生的混乱过程。
3. **David Dunning（Dunning-Kruger 效应）**：在某些领域，判断自己是否自欺所需的能力，正是自己可能缺乏的能力。红队蓝队辩论若发生在团队集体盲区，两边都会用错误标准判断对错。
4. **Nassim Taleb（反脆弱 / 极端斯坦）**：在极端不确定性领域，过度强调定量可能让人误以为自己掌握了规律，反而对黑天鹅事件准备不足。

### 内部局限

1. **定量需要成本与数据可得性**：早期项目或信息封闭场景中，强行定量会陷入「分析瘫痪」或产生虚假精确。
2. **组织文化决定成败**：如果团队不鼓励暴露错误、不保护说反话的人，红队、魔鬼代言人都会流于形式。
3. **过度聚焦事实可能抑制愿景**：在需要突破性创新或定义新市场的阶段，过早强调「事实」可能让团队不敢提出大胆假设。
