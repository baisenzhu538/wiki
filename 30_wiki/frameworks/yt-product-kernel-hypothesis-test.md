# 内核假设测试：低成本验证方法

> 一堂五步法：产品内核基于假设，假设必须通过低成本方法测试，不是"我觉得"。

## 核心框架

假设测试的步骤：

```
提出假设
    ↓
设计测试（低成本、快速）
    ↓
执行测试
    ↓
分析结果
    ↓
决策（继续/调整/放弃）
```

## 关键洞察

### 1. 假设的表达方式

好的假设必须可测试：

| 差的假设 | 好的假设 |
|:---|:---|
| "用户会喜欢" | "目标用户中，>30%愿意试用" |
| "市场很大" | "目标用户中，>10%愿意付费" |
| "产品很好" | "试用用户中，>50%愿意推荐" |

### 2. 低成本测试方法

| 方法 | 成本 | 时间 | 验证什么 |
|:---|:---|:---|:---|
| **用户访谈** | 低 | 1-2天 | 需求强度、痛点 |
| **原型测试** | 中 | 3-5天 | 使用体验、完成率 |
| **Concierge MVP** | 低 | 1-2周 | 用户愿意使用 |
| **预售/众筹** | 中 | 2-4周 | 用户愿意付费 |
| **A/B测试** | 中 | 1-2周 | 不同方案的转化率 |
| ** Smoke Test** | 低 | 1-3天 | 用户兴趣（landing page） |

### 3. 测试的维度

| 维度 | 测试问题 | 测试方法 |
|:---|:---|:---|
| **用户愿意用** | 用户是否愿意使用？ | 原型测试、Concierge MVP |
| **用户愿意付** | 用户是否愿意付费？ | 预售、众筹、付费试用 |
| **用户愿意推荐** | 用户是否愿意推荐？ | NPS调查、推荐行为追踪 |
| **用户持续用** | 用户是否持续使用？ | 留存测试、试用跟踪 |

### 4. 测试后的决策

| 结果 | 决策 |
|:---|:---|
| 假设验证成功 | 继续投入，扩大规模 |
| 假设部分成功 | 调整假设，重新测试 |
| 假设验证失败 | 放弃或重新定义内核 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **假设不可测试** | "用户会喜欢"——无法测试 | 把假设转化为可量化的指标 |
| **测试方法太弱** | 只有问卷，没有行为验证 | 用行为验证替代口头验证 |
| **测试样本不足** | 只测试了3-5个用户 | 至少测试10-15个目标用户 |
| **测试后不行动** | 测试结果不支持，但继续投入 | 建立"测试-决策"闭环 |
| **测试成本太高** | 测试花了3个月 | 选择低成本方法，快速测试 |
| **忽视负面结果** | 只关注支持假设的数据 | 主动寻找反例 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 产品内核验证 | 技术可行性验证 |
| 创业方向验证 | 市场进入策略 |
| 功能优先级验证 | 品牌传播效果 |
| 商业模式验证 | 运营活动评估 |
