# 需求洞察冰山模型

> "在彻底理解问题空间之前跳进解决方案空间，是创业的大忌。" 冰山模型六层递进：拆（L1用户标签+L2场景问题）→ 推（L3核心任务+L4任务地图+L5隐藏洞察+L6需求假设）→ 评。与其说它是分析框架，不如说它是"防止你自嗨"的纪律工具。

## 六层结构

```
水面之上（拆——粗粒度认知）
  L1 粗拆用户标签：谁在经历这个问题？
  L2 粗拆场景问题：在什么情况下、什么问题？

水面之下（推——逐层深挖）
  L3 圈定核心任务：用户真正要完成什么？
  L4 分解任务地图：全流程动作+摩擦点在哪？
  L5 深挖隐藏洞察：四种力量+三种任务+微观体感
  L6 提出需求假设：机会点+产品形态+最危险假设

岸上（评——做选择）
  评估三角形：普遍性×频次×刚性 → Go/No-Go
```

## 核心原则

1. **方案中立**：L4/L5之前严禁讨论具体产品功能——只讨论"问题空间"
2. **逐层不跳**：每一层是下一层的基础，跳过L3直接到L5=空中楼阁
3. **拆·推·评三步**：拆=建立基本认知，推=深度洞察，评=判断值不值得做

## Agent执行指令

```python
# 冰山模型逐层推演
layers = [
    ("L1", "识别目标用户群：年龄/职业/收入/使用习惯/技术水平"),
    ("L2", "定义场景和问题：在什么时候、遇到什么困难、现在怎么解决"),
    ("L3", "一句话核心任务：动词+对象+语境，方案中立"),
    ("L4", "8步任务地图：定义→定位→准备→执行→监控→调整→结束→总结"),
    ("L5", "四种力量+三种任务：推力/拉力/焦虑/习惯 × 功能/情感/社交"),
    ("L6", "机会卡片：机会名称+产品形态+最危险假设(RAT)×3"),
]
```

## 失败模式

| 失败 | 症状 | 修复 |
|:---|:---|:---|
| 跳过L1L2直接进方案 | 讨论的全是功能细节 | 强制走完L1-L3再讨论方案 |
| L3不够方案中立 | 核心任务描述里包含了特定技术 | 去掉所有产品/技术名词重新描述 |
| L5只分析功能需求 | 忽略了情感和社交维度 | 强制问"用户想感觉什么""用户想让别人看到什么" |
