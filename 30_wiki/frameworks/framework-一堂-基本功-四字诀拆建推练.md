# 基本功四字诀「拆建推练」：把一个动作练成组织能力

> **一句话**：拆出关键动作 → 建成固定套路 → 推成团队共识 → 练出大量重复。四步有顺序、缺一不可：没拆出来的练是瞎练，没建模的练靠手感，没共识的推是压服，没重复的练等于没练。
> **命名口径**：本域四字诀为「拆建推练」（实物武器库全景图为证；口述稿同段 ASR 误识「拆推评算」，以入门-口述 L322「拆、建、推、练」及实物图为准）。与需求域四字诀「拆推评算」（`tool-demand-chai-tui-ping-suan-guide`）内容完全不同，勿混。

---

## 一、四字诀是什么

四字诀是基本功落地的**纵向修炼路径**（入门-口述 L310-328）：所有基本功都得经历这四步——先拆出来，再建一个模型，再逐步推，最后让大家重复练，甚至产生业绩、变成公司长期竞争力。

为什么需要它？因为市场上有四类典型卡点（入门-口述 L304-308），正好对应四步：

| 卡点 | 症状 | 对应解药 |
|:--|:--|:--|
| 缺意识 | 没意识到公司背后有大量重复工作，别不出来 | **拆** |
| 缺建模 | 没办法把基本功可视化做成模型 | **建** |
| 缺落地 | 有了模型，团队不喜欢苦、不喜欢重复，推不动 | **推** |
| 缺重复 | 重复次数太少，应付领导应付下属 | **练** |

各字目标（武器库-口述 L2698-2730）：**拆=找到关键的独立动作**（越小越好，越小越可练）｜**建=固定**（不固定就没法备案）｜**推=形成共识**（推不动多半是没共识）｜**练=大量重复 + 大量反馈**。

> 顺序铁律：早期先做加法再做减法最后稳定；从一两个人以身作则到全员；氛围手段从轻到重（武器库-口述 L2752-2774）。

## 二、拆：找到关键独立动作

**目标**：从工作的几十上百个动作里，识别出那 1-5 个真正值得练的基本功。

### 操作步骤（加法 → 减法 → 稳定）

1. **做加法——四场景找候选**（武器库全景图【拆】组）：
   - 靠框架拆：自上而下按工作流 / 岗位角色 / 用户体验拆（提醒：容易大而全，必须配减法）
   - 靠专家拆：拆业务专家、销冠、老师傅背后高频重复的动作
   - 靠外部拆：参考成熟同行、跨领域最佳实践、标杆案例
   - 靠复盘拆：沿五层冰山（主观感受→客观事实→背后原因→底层模型→能力建设）挖意外事件背后的基本功
2. **做减法——三环六维筛**：用「务实/可练/价值」六要点给候选打分（详见 `tool-一堂-基本功-三环六维自检`），砍到 Top1-5。
3. **稳定——起个名字**：按命名五原则（宽而不泛、简单上口、动名词、差异化、有行动号召）命名，统一团队话语体系。

### 判断标准

- 拆对了：每个候选都能说出「场景+一连串动作+检验方式」
- 拆错了：清单上出现「沟通能力」「赚钱基本功」这种词（太大/太许愿，拆解篇-口述 L502-546）

---

## 三、建：建立固定套路

**目标**：给基本功一个固定的、可重复的套路——从抽象到具体，稳定到肌肉记忆。

### 操作步骤（建模七法，抽象 → 具体 → 稳定执行）

| 层级 | 工具卡 | 产出 |
|:--|:--|:--|
| 底层 | 本质要素-01 | 找最底层 1-5 个本质要素（第一性原理） |
| 抽象 | 拆N步法-02 | 拆成 N 个步骤，找关键要素与因果关系 |
| 具体 | 画雷达图-03 | 多维度对齐审美、定量评估（什么算 60/80/99 分） |
| 具体 | 自查清单-04 | Checklist 固定检查点，保证确定性重复 |
| 具体 | 工具箱小抄-05 | 执行细节沉淀为一页 Cheatsheet |
| 具体 | 文档模板-06 | 标准模板保持输出风格一致 |
| 稳定执行 | 写SOP-07 | 成熟业务写 SOP：完整工作流 + 分工 + 考核 + 监督加锁 |

### 判断标准

- 建对了：新人照小抄+清单做，能达到 60 分（及格线）
- 建错了：模型只有 PPT 和思维导图，没有可照做的最小文档

> 详解见 `tool-一堂-基本功-建模七法`。

## 四、推：形成团队共识

**目标**：让团队真正用起来——推不动多半不是方法问题，是共识问题。

### 操作步骤（推动七式，三条灰度轴）

| 轴 | 工具卡 | 要点 |
|:--|:--|:--|
| 按颗粒度 | 选标杆基本功-01 | 从 1 个基本功开始；先能力、再模块、再任务；各级自行向下拆 |
| 按范围 | 以身作则-02 | 三类一号位亲自相信、带头练——「我练不会，我不要求你们」（武器库-口述 L2766-2768） |
| 按范围 | 选先锋角色-03 | 按进步最大 / 结果最好选先锋示范 |
| 按范围 | 灰度发布-04 | 合伙人 → 身边人 → 小团队 → 全量 |
| 按难度 | 划基本功段位-05 | 单个基本功划 L1-L6 段位，让成长有梯子 |
| 按难度 | 划成长阶段-06 | 岗位按 SABC 划新人/爬坡/专家阶段 |
| 全员执行 | 启动会-07 | 限时启动：讲理念、点燃自驱、立规则 |

### 判断标准

- 推对了：先锋角色开始自发谈论基本功名字；灰度每一环有明确进入下一环的信号
- 推错了：一号位只提要求不练；一上来全员铺开；启动会开完没有后续动作

> 详解见 `tool-一堂-基本功-推动七式`。

## 五、练：大量重复与反馈

**目标**：把刻意练习四要素（`[[deliberate-practice-four-elements]]`：套路/非舒适区/大量重复/及时反馈）组织化——个人苦练靠自律，团队苦练靠五层加码。

### 操作步骤（练习二十法，4×4 五层加码）

| 层 | 工具卡 | 一句话 |
|:--|:--|:--|
| 氛围提醒（轻） | 挂在嘴边-01 / 文字化-02 / 文化墙-03 / 手边武器库-04 | 反复提名字、写进手册、贴上墙、放到办公桌/会议室/屏保 |
| 原则引导 | 最佳实践分享-05 / 美好作品想象-06 / 表扬先进-07 / 20%迭代-08 | 学最好的、想象最好的、表扬练习状态而非结果、每次好 20% |
| 工具训练 | 善于培训-09 / 善于练习-10 / 善于复盘-11 / 善于会议-12 | 新人集训+导师带教；背诵/教学/复刻/模拟/桌下五练习；自我/交叉/BA 对比反馈；融入例会 |
| 流程管控 | 制定计划-13 / 记录过程-14 / 建知识库-15 / 考核评估-16 | 每季度筛 3-5 个定计划；记录时间/次数/版本；沉淀定义/案例/方法；认知/技能/综合三类考试 |
| 制度保障（重） | 监督考察-17 / 绩效考评-18 / 职级划分-19 / 岗位晋升-20 | 检查督导+二次检查；与奖金津贴挂钩；段位入职级；考核入晋升门槛 |

### 判断标准

- 练对了：有练习次数记录、有反馈闭环、有段位变化——行为数据说话
- 练错了：只有口号和墙上的海报，一考核就应付反弹

> 详解见 `tool-一堂-基本功-练习二十法`。

## 七、When NOT to Use

| 场景 | 为什么失效 | 替代 |
|:--|:--|:--|
| 团队 <5 人且在生死线（现金流 <6 个月） | 四字诀是季度级工程，生存期没有训练预算 | 先跑业务单元模型活下来（`yt-entrepreneur-unit-model`） |
| 想办一次培训就把四字诀"走完" | 推+练需要 1-2 个季度，一次培训最多完成拆+建 | 把课程当起点不当终点，回去先以身作则 30 天 |
| 没有共识就靠行政命令强推 | 「推」的灵魂是共识，压服的练全是应付 | 退回以身作则+灰度，先在小范围做出结果 |
| 直接照搬别家公司的基本功清单 | 基本功是长出来的，别人的清单没有你的场景 | 用四场景自己拆，最多参考外部拆的思路 |
| 想练低频战略动作（融资/并购） | 不重复就没复利，四字诀不适用 | 走决策域方法论（`yt-decision-y-model`） |

## 八、Failure Modes（症状 → 根因 → 修复）

| # | 症状 | 根因 | 修复 |
|:--|:--|:--|:--|
| 1 | 拆解会变成许愿会，越拆越多 | 只做加法没做减法（拆解篇-口述 L416-456） | 强制三环六维打分，砍到 Top1-5；多一个都不许立项 |
| 2 | 拆出来全是「沟通/分析/赚钱基本功」 | 太大/太难/太许愿（四类错误，拆解篇-口述 L502-546） | 对照四类错误清单逐个砍，砍不动就降级到动作层重写 |
| 3 | 模型文档 50 页，没人翻开第二次 | 「建」停在抽象层 | 压缩为一页小抄+自查清单，手边武器库部署 |
| 4 | 一号位台上喊苦练，自己一个不练 | 推的顺序错了 | 一号位先练满 30 天并公开记录，再启动会 |
| 5 | 一上来全员铺开，两周后集体反弹 | 跳过了灰度 | 退回灰度发布：合伙人→身边人→小团队，每环出结果再扩 |
| 6 | 练习只有口号、海报、团建 | 练停在氛围层 | 按 4×4 加码：先考核评估，再绩效/职级/晋升挂钩 |
| 7 | 练了很久没反馈，不知道练没练对 | 缺及时反馈环 | 上善于复盘-11（自我/交叉/BA 对比）+ 考核评估-16 |
| 8 | 练三个月没业绩，一号位失去耐心叫停 | 用线性预期看复利 | 按 20%迭代设季度里程碑，连续三次达标再评估去留 |

## 九、Critique（外部攻击与回应）

**1. Jeffrey Pfeffer（Stanford，《Leadership BS》）**：领导力培训项目设计精良、满意度高，但几乎不产生行为改变——直接攻击"四字诀能改变团队行为"。回应：四字诀把「练」设为独立环节并配 20 张执行卡，最终三卡是绩效/职级/晋升挂钩——行为改变靠的是制度层加码，不是培训体验。Pfeffer 批评的正是"只有拆建、没有推练"的伪项目。

**2. Polanyi / Nonaka（隐性知识理论）**：专家知识是隐性的、不可完全编码，拆解动作会丢失默会维度。回应：基本功只编码高频重复的可观察动作层；隐性判断靠「练」中的反馈与师徒传承（善于培训-09 导师带教、善于复盘-11 交叉反馈）传递。四字诀是编码+浸润的组合，不是纯编码。

**3. Kotter 变革八步法（对照参照）**：「推」的灰度发布+启动会+先锋角色与 Kotter 的"建立紧迫感→组建联盟→短期胜利"同构，说明本域「推」不是发明新轮子，而是变革管理在"练基本功"场景的专用裁剪——可信度加分，但也提醒：跳过紧迫感营造（启动会-07 的"点燃自驱"）是变革失败主因。
