# 十倍速公式：避免系统性失败

> 用"常识→情报→实验→全量投入"的递进阶梯，把认知学习的成本压到最低，把重投入的确定性提到最高，从而避免一次性押上全部资源的系统性失败。

## 一句话定义

十倍速公式是一堂基于精益创业思想总结的认知投入框架：在动手交付之前，先用常识和情报把不确定性降到可控水平，再用小规模实验验证关键假设，只有在置信度足够高时才进入全量投入 [conf=0.85, source=一堂课程讲义]。

## 核心模型：四阶认知投入光谱

### 2.1 递进公式

```
常识  <  情报  <<  实验  <<<  全量投入
```

| 层级 | 阶段定位 | 关键策略 | 核心训练 | 大致消耗 | 主要风险 |
|:---:|:---|:---|:---|:---:|:---|
| **常识** | 前期认知学习 | 圈里的共识、专家的经验 | 专家访谈 | ¥百量级 | 过度依赖个人经验，信息陈旧 |
| **情报** | 前期认知学习 | 同行的案例、现成的答案 | 情报调研 | ¥千量级 | 二手信息失真，竞品样本偏差 |
| **实验** | 开始动手交付 | 简版的交付、聪明的测试 | 精益创业 | ¥万量级 | 实验设计偏差，样本不足 |
| **全量投入** | 开始动手交付 | 笃定的信心、拉满地投入 | All in | ¥无限投入 | 方向错误被规模化放大 |

> 注："¥百/千/万量级"和"¥无限投入"为讲义中的经验量级示意，用于表达成本数量级差异，并非精确财务预算 [conf=0.60, source=一堂课程讲义示意数字]。

### 2.2 投入-风险气泡图

```
风险/不确定性
   │
高 │                    ● 全量投入（重投入-危险）
   │
中 │           ● 实验（中投入-可控）
   │
低 │  ● 常识    ● 情报   （轻投入-安全）
   │
   └────────────────────────────
         低        中        高
                 投入金额/资源
```

- **轻投入-安全**：常识、情报阶段，主要消耗时间和访谈/调研成本，失败损失可控。
- **中投入-可控**：实验阶段，需要做出可测试的最小交付物，失败可复盘、可转向。
- **重投入-危险**：全量投入阶段，资金、团队、品牌全部押上，方向一旦错误即为系统性失败。

### 2.3 两大应用场景

**场景一：做事时——螺旋上升**

```
认知弱 / 信心弱  →  认知强 / 信心强
     ↑                        ↓
     └────── 持续低成本验证 ────┘
```

每次只做当前信心足以支撑的投入，用验证结果迭代认知，而不是一次性押注。

**场景二：复盘时——成本反思**

```
重投入学习  →  低成本学习
```

核心心法："学到同样的认知/教训，10% 甚至 1% 的成本能拿到吗？" [conf=0.80, source=一堂课程讲义]

## 与经典理论的关系

| 模块 | 来源 | 说明 |
|:---|:---|:---|
| 假设驱动、实验验证、Build-Measure-Learn | 🟢 Eric Ries《精益创业》 | 十倍速公式把"实验"作为认知跃迁的关键环节，与精益创业思想一致 |
| 客户开发、走出办公室 | 🟢 Steve Blank 客户开发方法论 | "常识"和"情报"阶段对应客户开发中的早期访谈和行业调研 |
| 十倍速差距、四阶光谱、投入-风险气泡图 | 🟡 一堂归纳/本土化 | 操作化表达，非学术原创；"十倍"为修辞性表达，不宜作为精确倍数引用 |
| "常识 < 情报 << 实验 <<< 全量投入"的不等号强度 | 🟡 一堂课程框架 | 表示优先级和成本差距，不是数学不等式 |

## 适用边界

**适合**：
- 早期创业项目、新产品孵化、业务方向探索
- 需求不确定性高、可以通过小实验快速获取反馈的领域
- 团队愿意接受"默认失败"、把验证当作学习过程的文化

**不适合**：
- 强监管行业（医疗、金融、教育、博彩）中涉及合规底线的"实验"，可能触碰法律红线
- 长周期硬件、基础设施项目，无法通过低成本实验快速迭代
- 品牌敏感型产品，粗糙的早期测试可能永久损伤用户信任
- 机会窗口极短、必须一次性押注全部资源的战略战役（但仍应保留止损线）

## 失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| **跳过常识/情报，直接上实验** | 还没搞清楚问题是否存在就开发 MVP，实验设计偏差大 | 先花小成本做专家访谈和情报调研，明确关键假设 |
| **把实验当全量投入的前奏，不设止损标准** | 实验结果模糊，继续追加资源，最终演变成"小 All in" | 每次实验前定义清晰的通过/不通过标准 |
| **永远在低成本学习，不敢进入实验** | 用"调研不够"无限拖延动手，错过窗口 | 设定"最小可行证据"阈值，达到即进入下一阶段 |
| **复盘时把失败浪漫化为"学费"** | 只强调"学到教训"，不追问成本是否可以更低 | 复盘时强制回答："同样的认知，1/10 成本能否拿到？" |

## 案例映射

### 正例：Dropbox 视频 MVP [conf=0.90, source=公开经典案例]

- **背景**：Drew Houston 在开发同步工具前，先用 3 分钟视频 Demo 展示产品概念。
- **所处阶段**：F/实验阶段——没有真实产品，只有简版交付物验证需求。
- **结果**：视频发布当晚获得 7.5 万人等待，几十万人访问 [conf=0.80, source=行业流传数据]。
- **映射十倍速公式**：在常识和情报已经说明"文件同步是痛点"之后，用极低成本的实验验证需求强度，避免直接进入全量开发。

### 反例：长周期硬件项目 1800 万教训 [conf=0.70, source=一堂课程案例]

- **背景**：某导盲机器狗项目在没有充分验证用户需求和商业化路径前，直接投入大量研发资源。
- **失败原因**：
  - 跳过常识/情报阶段对用户真实付费意愿的验证；
  - 把"研发能力"当成"市场需求"，过早进入重投入；
  - 没有在中投入阶段设计可止损的实验节点。
- **映射十倍速公式**：该案例说明十倍速公式在长周期硬件中尤其重要——不能用"All in 研发"替代早期低成本验证。
