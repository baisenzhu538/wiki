# 王欢GAN三角色架构：生成器/判别器/合成器

> **Burn line**: 灵感来自 GAN——生成器和判别器对抗进化，但这里的判别器来自不同公司、不同模型，盲区不重合。
>
> **来源**：王欢 AI 实战分享（2026-06-18）

---

## 一、用一句话讲清楚

王欢借鉴 GAN（生成对抗网络）的思想，设计了一个三角色架构：**生成器负责产出，判别器负责找问题，合成器负责把多源评审意见综合成可执行的改进方案**。

---

## 二、三角色定义

```
        用户
         ↓
    Team Lead（导演）
         ↓
    ┌─────────────┐
    │   Planner   │────→┌─────────────────┐
    │  （规划者）  │     │ Tech Stack Selector │
    └─────────────┘     │   （技术栈选择）    │
         ↓              └─────────────────┘
    ┌─────────────┐
    │  Generator  │  ← 生成器：产出内容/代码/方案
    │  （生成器）  │
    └─────────────┘
         ↓
    ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────┐
    │ Functional  │ │ Adversarial │ │ Codex       │ │ Gemini      │
    │ Tester      │ │ Tester      │ │ Evaluator   │ │ Evaluator   │
    │（功能测试员） │ │（对抗测试员） │ │（代码审查员） │ │（架构评审员） │
    └─────────────┘ └─────────────┘ └─────────────┘ └─────────────┘
         ↑←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←←↑
    ┌─────────────────────────────────────────────────────┐
    │         Master Integration Tester                   │
    │            （主集成测试员/合成器）                    │
    │     综合所有判别器意见，生成最终验收报告              │
    └─────────────────────────────────────────────────────┘
```

### 2.1 生成器（Generator）

| 项目 | 内容 |
|:---|:---|
| **职责** | 产出初稿：内容、代码、方案 |
| **关键能力** | 按任务要求快速生成 |
| **常见模型** | Claude Sonnet、GPT-4、Cursor |
| **注意** | 生成器只负责“做出来”，不负责“做得对” |

### 2.2 判别器（Discriminator）

| 项目 | 内容 |
|:---|:---|
| **职责** | 找问题、挑漏洞、提改进意见 |
| **关键能力** | 从不同视角审查 |
| **常见形态** | 多个不同模型/工具/专家 |
| **核心原则** | 判别器要来自不同“分布”，盲区不重合 |

王欢示例中的四个判别器：
- **Functional Tester**：功能 happy path 验证
- **Adversarial Tester**：主动攻击，目标找 bug
- **Codex Evaluator**：代码审查，专注安全/边界
- **Gemini Evaluator**：架构设计、原创性评分

> **为什么用四个判别器？** Codex（OpenAI）和 Gemini（Google）来自完全不同的模型族，训练分布不同，盲区不重合。主动攻击比被动审查能找到更多 bug。

### 2.3 合成器（Synthesizer / Master Integration Tester）

| 项目 | 内容 |
|:---|:---|
| **职责** | 综合所有判别器的意见，生成最终改进方案 |
| **关键能力** | 去重、排序、冲突消解、可执行化 |
| **常见形态** | 一个更强的模型或人工 |
| **注意** | 不是简单汇总，而是形成 actionable 的反馈 |

---

## 三、与 GAN 的异同

| 维度 | 传统 GAN | 王欢三角色架构 |
|:---|:---|:---|
| 生成器 | 生成 fake 样本 | 产出内容/代码/方案 |
| 判别器 | 一个，判断真假 | 多个，从不同维度找问题 |
| 训练目标 | 生成器骗过判别器 | 生成器产出质量更高的可交付成果 |
| 反馈机制 | 反向传播 | 多轮迭代 + 人工/合成器最终验收 |
| 新增角色 | 无 | 合成器：把多源反馈综合成改进方案 |

## 四、应用场景

### 4.1 软件开发

- 生成器：Claude Sonnet 生成代码
- 判别器：功能测试、对抗测试、Codex 代码审查、Gemini 架构评审
- 合成器：综合所有意见，生成修改清单

### 4.2 内容创作

- 生成器：AI 写初稿
- 判别器：事实核查、逻辑审查、风格审查、受众匹配审查
- 合成器：综合意见，形成修改方案

### 4.3 知识工厂卡片生产

| 角色 | KDO 映射 |
|:---|:---|
| 生成器 | 老顽童/AI 生成卡片 |
| 判别器 | 王语嫣质量检查、欧阳锋审查、相关领域专家 |
| 合成器 | 王语嫣汇总审查意见，形成修改清单 |

## 五、与对抗式生成的关系

`[[concept-wanghuan-adversarial-generation]]` 是这一架构的底层概念。三角色架构是对抗式生成在复杂工程场景中的工程化实现：

- **对抗式生成** = 核心理念：生成和评审分离。
- **GAN 三角色架构** = 工程实现：多判别器 + 合成器。

---

## 六、常见走偏模式

| 走偏模式 | 表现 | 纠偏动作 |
|:---|:---|:---|
| **判别器同质化** | 多个判别器都是同一种模型 | 引入不同模型/不同视角的评审者 |
| **合成器汇总不力** | 意见很多但无法执行 | 把意见结构化，强制按优先级排序 |
| **生成器迭代不足** | 只经过一轮评审就结束 | 设定多轮迭代终止条件 |
| **忽视成本** | 每个任务都用四个判别器 | 按任务复杂度选择判别器数量 |

---

## 七、Action Triggers

| 触发场景 | 第一个动作 |
|:---|:---|
| 单一模型输出质量不稳定 | 引入第二个模型做判别 |
| 复杂任务需要多维度审查 | 设计 2-4 个不同角色的判别器 |
| 多个评审意见冲突 | 引入合成器做最终裁决 |
| 团队审查效率低 | 把判别器角色固化成可自动运行的 checklist |
