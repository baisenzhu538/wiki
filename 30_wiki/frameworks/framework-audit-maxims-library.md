# 审计判词库（13 条）

> **定位声明**：本卡属审查/治理方法论域，是审计判词的**认知层单一真相源**。与 #433 族门禁词表（`90_control/scripts/queue_transition.py` 的 `NEGATIVE_CLAIM_STRONG`/`NEGATIVE_CLAIM_SOFT` 常量——检索常量名定位，行号随版本漂移）的关系：**词表=实现层；存量词条（08-23 随 #433 落地）先于本卡存在，判词 A3 是从其实践回溯提取的——自本卡起（as of 2026-08-27），词表变更须引用判词编号**，不与本卡合并维护。与 charter（`kdo-charter-v0.1-draft.md`，正文版本 v1.2）的关系：A1 已入 §3.16、C2 已入 §3.17 红线 1（均 08-25 老朱拍板）、A6=§3.18 第 3 条原文——本卡是入宪判词的完整版+适用边界说明；A5 未入宪，仅与 §3.18 第 1 条机制配套关联。
> **来源**：风清扬 2026-08-26 建议书（`diag_20260826_fengqingyang-audit-maxims-library`），触发于老朱 08-26 点破「日常审计没有得到可用来训练 agent 的资产」——流程闭环在跑，认知闭环断了。13 条判词全部有出处（实证出处或规范出处，见各条标注），本卡=结构化沉淀，未新增判词。

## 三组判词的分工逻辑

13 条判词按「谁在用、什么时候用」分三组，不是平铺清单：

- **A 组（审计判词 6 条）**：审计/终审/复盘时的判词口径——断言合格线（A1-A3）、教训入库精度（A4）、交付与拍板权责（A5/A6）
- **B 组（跨角色方法论 5 条）**：从全厂复盘并置中提取的验证与协作方法——验证技术（B1-B3）、异步协作协议（B4）、门禁设计原则（B5），不只审计用，生产/基建修改同样适用
- **C 组（自动化治理判词 2 条）**：全自动演进的红线——撤人之前必须满足的前置条件

## 操作步骤（怎么用这 13 条）

1. **审计时**：写任何判词前，先过 A 组——含「无/没有」字样 → 走 A3；含「完成了」 → 走 A2；含「老朱已拍板」 → 走 A6
2. **终审时**：对照 A1/A2 验证交付声明——壳在、数据流、自动化三问逐条要证据锚点
3. **改机制时**：走 B1——列全部读侧消费点，逐一验证写读对账，不改一半就交付
4. **验收批量报告时**：走 B2——不信报告数字，跑差集脚本比对声称清单与实际清单
5. **自动化演进决策时**：走 C1/C2——三件套（可观测/可熔断/可回放）不齐不谈撤人；抽检配额为零的方案直接判 FAIL
6. **复盘时**：新提取的教训入库前先过 A4——写上「不适用边界」再落盘

## Synthesis

13 条判词共享同一信任立场：**默认零信任——声称须验证（A1-A3/B2/B3）、转述须直证（A6）、交付须落公共真相源（A5/B4）、教训须带边界（A4）、机制须连自己都拦（B5）、自动化须可观测（C1/C2）**。A 组定口径（判词本身的合格线与权责链），B 组定方法（验证怎么做才可信），C 组定红线（自动化到什么程度是安全的）。三组合用 = 审计的认知闭环：判词从实证中来（每条有出处）、到机制中去（#433 词表/charter 引用）、随审计实践迭代（新增走审计件「可固化资产候选」常态通道）。与 [[framework-ouyangfeng-review-methodology]] 的关系：审查方法论管「怎么审」，本卡管「下判词时对照什么口径」；与 [[concept-kdo-component-library]] 的关系：组件库萃取自生产端踩坑，本卡萃取自审计端实践，两者在「凡声称必验证」上同构。

## 不要用的场景（When NOT to Use）

| 场景 | 为什么不用 | 替代做法 |
|:--|:--|:--|
| 判词替代具体核查 | 判词是口径不是证据——A1 本身要求独立复现，拿判词当结论 = 自我违反 | 判词只告诉你「要核查什么」，核查动作不可省 |
| A3 套用到有机器验证的场景 | 已有门禁/脚本硬验证的断言（如 lint ERROR 数），人工备择清单是重复劳动 | 直接贴脚本输出作证据锚点 |
| 用判词编号当「权威压人」 | 判词效力来自实证出处，不来自编号；脱离出处的引用 = 誊抄漂移 | 引用判词时必须能回链到出处任务单 |
| 判词与 charter 条文/最新拍板冲突 | 效力层级未定义会引出「判词 vs 条文谁大」的扯皮 | 以 charter 条文与最新拍板为准，判词库走修订流程对齐 |
| 把 C2 当挡箭牌拒绝一切自动化降档 | C2 拦的是「零抽检」，不是「降抽检比例」；合理降档走 dry-run 小批验证（charter §3.17 红线 2） | 降档提案附小批实证数据 |
| 外部方法论对标场景 | 本卡是内部制度提炼，不是行业审计框架（如 COBIT/ISO 27001 审计条款） | 对外表述时注明「KDO 内部治理资产」 |

## 失败模式

| 失败模式 | 真实信号 | 修复动作 |
|:--|:--|:--|
| **誊抄漂移**：转述判词时改写措辞，几轮后与原意偏离 | 卡内判词与建议书原文措辞不一致 | 对照底本逐条回链，判词列保持原文表述，解释放别的列 |
| **出处悬空**：引用判词编号但出处任务单已改名/归档 | source_refs 里出现失效路径 | 引用前 `ls` 验证路径存在；归档时同步更新引用 |
| **判词膨胀**：每次审计都新增判词，13 条变 130 条，无人记得住 | 判词数量月增 >3 条且无淘汰 | 新增走「可固化资产候选」通道，由王语嫣裁定；同义判词合并不并列 |
| **只背不查**：审计时引用 A3 判词但不做存在性核查 | 判词出现但证据锚点缺失 | 终审把「判词+锚点」绑定检查，缺一退回 |
| **边界遗忘**：A4 自身被违反——本卡判词入库时不带适用边界 | 新增判词三字段（判词/出处/边界）缺一边界 | 补边界再入库；缺边界的判词视为草稿不引用 |
| **charter 漂移**：§3.16/§3.17/§3.18 修订后卡内条文未同步（charter 处于高频修订期，四天四改） | 卡内「已入宪」表述与 charter 现行条文不一致 | charter 第三章修订 → 回链核对 A1/A6/C2 文案——按 B1 判词，本卡是 charter 的读侧消费点 |

## Critique（内部局限）

1. **样本期极短**：13 条判词提取自 08-23~08-26 四日的审计与门禁落地实践（含 08-23 前置任务单出处 #432/#433/#444），覆盖的失败模式分布可能严重偏向近期事故类型（队列流转/静默失效类偏重，内容质量类判词缺失）。随审计覆盖面扩大需要补组。
2. **实证出处多为单点**：多数判词只有 1-2 个实证出处支撑，证据强度低于 KDO 惯例（P 编号坑通常多次复现才立规）。A1/C2 的出处为规范出处（入宪拍板）而非实证；C 组仅 2 条，自动化治理场景远未覆盖全；B3/B4 出处为会话实录，文件级回链待补。
3. **外部对标刻意缺失**：本卡为内部制度提炼，未对照外部审计/治理框架（三方法适配声明：判词=内部制度提炼非外部事实断言，外部调研不适用；验证走出处回链）。这是任务单裁定的形态，不是疏忽——但意味着本卡不能作为「行业最佳实践」对外引用。
4. **判词自身的绝对化表述**：C1「唯一真风险」是无条件全称断言——按本卡 A3 口径本应过备择解释清单。保留原文（判词照誊不改），引用时注意此张力，不作为判词库自我豁免的先例。
