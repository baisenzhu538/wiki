# R 型研究 Partner 五状态机：从课题到知识资产

> 本卡属于「AI Partner 体系」+「调研系列课」：一堂正式第一个 R（Research 研究）型 Partner——在已有 P 讲师型、C 顾问型、P 干活型之外的第四种角色。目标：从用户的一个课题，产出一份可复盘、可打印、可复印的知识资产（案例大爆炸资产报告）。

## 1. 定位

- **首个 R 型**（口述下 L3164-3166）：已给 P 讲师型、C 顾问型、P 干活型，这是第一个研究型
- 目标（L3168-3174）：给你建模——带着你一步步明确目标、挖掘建模，最终给你一份关于该课题的**案例大爆炸资产报告**
- 资产报告的价值（L3172-3174）：很值钱——七年前总结的标题方法论，这些年断断续续还在用；它会以资产长到你身上（全量完备的东西）= ROI 型 partner
- 设计原理（L3178-3180）：五里程碑状态机——从一个课题到一份可复盘、可打印、可复印的知识资产

## 2. 五状态机

| 状态 | 名称 | 动作 | 门控 |
|:--|:--|:--|:--|
| 1 | **定边界** | 把任务说清楚、边界定清楚 | 用户确认边界后前进 |
| 2 | **规划信息源** | 规划案例大爆炸调研要从哪些信息源搜 | 用户确认信息源清单后前进 |
| 3 | **饱和送**（饱和搜索） | 一直转圈收集，用工具推动饱和 | 规律基本稳定后前进 |
| 4 | **分类** | 给 3-5 套分类方案，用户挑选拍板 | 用户拍板方案后前进 |
| 5 | **资产报告** | 输出尽量好用的报告（给人用/给 AI 用） | 交付 |

门控原则（任务单要求）：**每阶段"确认后前进"**——AI 推进但人拍板，避免跑偏。

## 3. 输入与输出

- 用户输入（L3200-3202）：课题、材料、关键词、案例、设想——能输入的都输入
- 输出（L3202）：研究结果清单、分类小抄、资产包（DataPack）

## 4. 与五步法的映射

| 五状态机 | 五步法 |
|:--|:--|
| 定边界 | 目标 + 范围 |
| 规划信息源 | 范围（预判渠道） |
| 饱和送 | 搜索⇄建模循环 |
| 分类 | 终止判断（模型形态之一：分类） |
| 资产报告 | 交付做厚 |

R 型 Partner 是五步法的 Agent 化实现——"全程由 AI 负责判断、把关，AI 来干活，你差不多能做出来 7788"（L3162-3164）。

## 5. When NOT to Use

1. **单一情报深挖**——单点挖掘用挖掘式 Partner（更活跃），R 型是宽度建模。
2. **重要决策的推理式调研**——复杂决策用 OSCAR 系统式（里程碑推理），R 型的饱和建模不替代推理链。
3. **需要线下体感的调研**——AI 搜不着的信息（线下/使用体验/体感），R 型只能做搜索类部分。
4. **目标完全模糊时**——用户连"要研究什么决策"都说不清，先人工明确目标再上 R 型（否则状态 1 会反复确认）。

## 6. 失败模式

| 失败模式 | 真实信号 | 修复动作 |
|:--|:--|:--|
| 边界没定清 | 状态 1 反复弹确认，用户失去耐心 | 先人工想清楚课题与边界再启动 |
| 跳步推进 | AI 不等确认直接进入下一状态 | 用九字诀 05 控制不准跳步：每步需经我确认 |
| 饱和不足 | 分类方案少、规律未稳就交报告 | 回到状态 3 继续饱和送（换 5-10 关键词） |
| 分类方案单一 | 只给 1 套方案没得选 | 要求 3-5 套方案（MECE 手术台） |
| 报告不可用 | 输出抽象模型过几周看不懂 | 资产报告必须分层/讲香/DataPack 做厚 |
| 过度依赖 | 用户只点继续，不给意图/审美/反馈 | 九字诀：至少 10-20 轮对话，人主导 |

## 7. Action Triggers

- 需要一个课题的完整建模（案例大爆炸）→ 用 R 型 Partner，五状态机走一遍
- 状态卡住（分类犹豫/饱和不足）→ 回到上一状态，人拍板后前进
- 部署 Agent 时 → 按 #263 流水线：spec（五状态机+四 demo+九字诀为数据源）→ 部署三件套 → cap_hub → 飞书
- 设计其他 R 型 Partner → 复用五状态机骨架（定边界/规划/饱和/分类/资产报告）
