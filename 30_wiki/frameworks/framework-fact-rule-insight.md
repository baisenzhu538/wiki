# 事实-规律-洞察三层框架：专题学习的通用分析结构（认识他/理解他/用他）

> **定位**：属于专题学习（research 域）的通用分析框架——任何"研究一个人/一个现象/一个领域"都可以套的三层结构

## 核心结构

```
认识他（事实层）→ 理解他（规律层）→ 用他（洞察层）
  客观拿到什么       共性总结是什么       底层是什么/我们能学会什么
```

## 框架说明

> 「你帮我去知识库扫一下所有关于他的文章……你给我把它分成三层，就是认识他、理解他和用他的。因为大家帮忙打一下三个词我们内部用的最多的一个 AI 的分析框架，叫做事实逻辑和洞察，这是非常重要的三个词。」（口述 L2878-2881）
> 「让那些工作你先让他去把事实先整理，他能拿到什么外界的事实上的东西。然后第二个叫基于拿到的东西去总结一层规律，叫规律。第三个叫洞察，就是真正底层是什么？你的观点是什么？跟一堂有什么关系？我们能学会什么？……从客观然后到客观背后的共性和共性背后都能学会的东西。」（L2882-2898）

## 操作方法

1. **第一层·事实**：让 AI 扫全库+全网，整理客观事实（履历/时间线/作品/公开信息）——"他能拿到什么外界的事实上的东西"（L2882）
2. **第二层·规律**：基于事实总结共性——模式/方法论/思考结构（L2884-2886）
3. **第三层·洞察**：底层是什么？观点是什么？跟"我"有什么关系？能学会什么？（L2886-2892）——这层偏主观，是增值所在
4. **产出总文档**：AI 生成顶层文档统揽子文档（L2914-2916）——认识/理解/用三层各一组子文档
5. **实操案例**：硅谷大网红专题（L2874-2916）、短剧博主专题（L2920-2924）、实事求是专题（李开复一句话缘起，L2928-2944）

## When NOT to Use

- **信息核实场景**：只需确认"是不是真的"（事实核查）时，用不到三层——第一层即可
- **快速决策**：时间紧迫只需一个答案时，三层分析过重
- **无"用"诉求**：纯好奇了解，不需要"用他"层时，两层足够

## 失败模式

- **跳过事实层**：直接谈"我认为他是谁"——没有客观基础，洞察变臆测
- **停在规律层**：总结了一堆模式但不说"我们能学会什么"——分析没有出口
- **洞察层失真**：硬套"跟我的关系"——洞察要基于事实+规律，不是立场先行

## Action Triggers

- 接到"研究一下 XX"任务 → 套三层：先事实、再规律、后洞察
- 产出内容"浅/AI 味" → 检查是否跳过规律/洞察层（只做了事实层）
- 团队专题学习 → 三层框架统一产出结构（总文档+子文档）

## Critique

- **反驳**：三层太线性，事实/规律/洞察会互相交织——实操中可迭代（先粗事实→规律→洞察→回头补事实），不是严格瀑布。
- **反驳**："洞察"主观性强，容易自嗨——需要与事实/规律绑定（洞察要有事实依据），且"用他"层要具体（能学会什么动作）。
- **条件**：此 dk 前提=有足够素材（全库+全网）；素材为零时先采集（serendipity 五通道）。
- **注意**：三层是"分析结构"不是"产出结构"——产出可以是总文档统揽子文档，不一定要三份独立文档。
