# 项目管过程：六大管理手段保障项目落地

> **一句话**：计划只能解决20%的问题，80%的结果靠过程管理拿到。一堂总结出"管事三件套"（进度、质量、变更）加"管人三进阶"（向上、体验、冲突），六维管理手段精准匹配项目敏感度，让你从被动救火变主动掌控。

---

## 一、核心框架总览

```
管过程 = 管事 + 管人

管事（基础能力，做好→60-70分）：
  ├── 进度管理 ── 确保事项如期推进，不延期
  ├── 质量管理 ── 守住关键节点，不做事后返工
  └── 变更管理 ── 识别变化、评估风险、严肃处理

管人（进阶能力，做好→80-90分）：
  ├── 向上管理 ── 让老板省心放心有信心
  ├── 体验管理 ── 让团队有参与感、有责任感
  └── 冲突管理 ── 平息争论，把冲突变成推进力

被低估的放大器：启动会 ── 2小时前置解决80%执行问题
```

---

## 二、进度管理三要素

进度管理的核心不是"催"，而是**把风险提前暴露出来，消灭在无形之中**。

### 2.1 三要素

| 要素 | 含义 | 核心动作 |
|:---|:---|:---|
| **培养意识** | 让团队知道项目不是PM一个人的事，每个人都有责任 | 跟团队达成三条共识：①按计划执行 ②有问题尽早同步 ③变化第一时间周知 |
| **丰富手段** | 沟通方式从线上异步到线下同步，按需升级 | 线上：顶层文档→电子看板→群消息→电话；线下：墙上看板→攻坚小组→坐旁边陪做→封闭研发 |
| **高频沟通** | 频次比手段更重要——按里程碑→按周→按天→全程陪伴 | 每次沟通对齐三个问题：进展差距？有什么卡点？需要什么支持？ |

### 2.2 沟通四象限（手段选择矩阵）

```
                异步（不同时）              同步（同时在线）
线上  ┌──────────────────────┬──────────────────────┐
      │ 顶层文档/电子看板     │ 电话/视频会议          │
      │ 邮件/群公告          │ 即时消息群聊           │
      ├──────────────────────┼──────────────────────┤
线下  │ 墙上看板/便利贴       │ 攻坚小组/封闭研发      │
      │                      │ 搬小板凳坐旁边         │
      └──────────────────────┴──────────────────────┘
                       成本增加 →
```

**手段选择三原则**：
- 事情三句话能说清？→ 异步文字即可
- 事情紧急且重要？→ 升级为同步
- 涉及多人且反复沟通？→ 直接见面/攻坚会

### 2.3 四个"不要默认"

> 不要默认所有人都知道计划的细节。
> 不要默认所有人都清楚自己此刻该做什么。
> 不要默认所有人有问题会主动说。
> 不要默认所有人有问题会自己去解决。

### 2.4 操作步骤

1. **建顶层文档**：把所有方案、分工、排期集中到一个文档/文件夹，有且只有一份
2. **画看板**：可视化项目进度（墙上或线上），让每个人一抬眼就知道项目在哪
3. **定沟通节奏**：关键路径任务 → 每日确认；一般任务 → 每周站会/周报
4. **培养团队意识**：启动会上明确宣导"有问题尽早说，不要等到周会"
5. **关键难题用重手段**：延期超过2天 → 坐旁边陪做；方向性难题 → 组织攻坚小组

## 三、质量管理节点

质量管理不是QA测试，而是**守住那些决定项目最终目标能否达成的关键节点**。

### 3.1 三类关键质量节点

| 类别 | 含义 | 判断标准 | 守不住会怎样 |
|:---|:---|:---|:---|
| **关键子目标** | 不完成这个就无法达成最终目标的节点 | 有没有一个可定量的指标？ | 项目直接失败 |
| **质量标准检查** | 交付物是否达到约定标准的检查点 | 有没有明确可检查的标准？ | 事后大规模返工 |
| **关键交付物评审** | 重要产出物必须通过关键人审批才能进入下一步 | 有没有明确的评审人和通过条件？ | 被推翻重做 |

### 3.2 炒菜类比（质量节点对照表）

| 项目 | 关键子目标 | 质量标准检查 | 关键交付物评审 |
|:---|:---|:---|:---|
| 手册项目 | 收集85%会员地址 | 错别字为零 | 目录经Truman和花匠评审 |
| 马拉松项目 | 内场招生4000人 | 营销材料无错别字 | 销售PPT经评审 |
| 炒西红柿鸡蛋 | 西红柿1kg以上 | 食材齐全 | 炒完让爸爸尝熟再出锅 |

### 3.3 缓解"被卡"心态的checklist

质量评审最容易被理解为"你在挑我的刺"。五种话术化解：

1. **提前约定**：尽早说清标准和评审流程——"我们一开始就说了，这个必须老板过"
2. **借用规范**：不是我在卡你，是公司有这个要求/同行都这么做
3. **借用反馈**：用户反馈说这是我们的核心，这次一定要守住
4. **上升价值**：为了最终大目标，这个事情真的了不起，我们一起来搞定
5. **缓解情绪**：夸对方能力强+平时关系好+"你这么厉害怎么可能做不好"

> 态度要硬，沟通要软。

### 3.4 操作步骤

1. **梳理关键质量节点**：用画布模板填——项目名→关键子目标→质量标准→交付物评审项
2. **明确量化指标**：每个子目标必须有数字——"收集85%"而不是"收集大部分"
3. **指定评审人**：每个关键交付物明确A（批准者）是谁
4. **建立签字机制**：特别重要的检查项，让检查人签字确认
5. **评审不通过→原地修改**：直到验收合格才能进入下一步或付款

## 四、变更四步处理（识别→评估→决策→执行）

变更是项目管理最难的事——太灵活团队不堪重负，太僵硬失去创业公司优势。核心在于**判断哪些变更需要走严肃流程**。

### 4.1 常见变化识别清单

| 分类 | 具体情况 |
|:---|:---|
| 方案 | 老板新想法、政策变了、甲方变了、前期没细化、有了更棒的选项、情况不符合预期 |
| 进度 | 计划要提前、大量任务超时 |
| 人力 | 有人请假了、成员被调走、被卡在其他项目上、能力远不如预期 |
| 质量 | 大家能力不够降低标准、改标准才能达到目标 |
| 预算 | 预算少了、预算花多了 |

### 4.2 四步处理流程

```
识别变化 → 分析风险 → 决策判断 → 执行变更
   ↓           ↓           ↓           ↓
什么变了？  影响什么？   走不走流程？  怎么落地？
```

#### 第一步：识别变化
- 对变化保持敏感性——是方案变了？排期变了？人变了？预算变了？
- 对照"常见变化识别清单"快速定位变化类型

#### 第二步：分析风险
用六维敏感度模型评估变更影响：
- 影响最终项目目标？（会不会让目标完不成）
- 影响资源投入？（预算、人力、时间）
- 影响团队协作？（让谁不爽、让谁多干活）

> **判断核心**：越是影响范围大、影响深度深，越需要走严肃流程。

#### 第三步：决策判断

| 变更类型 | 处理方式 | 举例 |
|:---|:---|:---|
| **小变更**：不影响目标/资源/协作 | 灵活处理，直接改 | PPT某个配图换一张 |
| **重要变更**：影响目标/资源/协作 | 走严肃变更流程 | 手册从黑白变彩色 |

#### 第四步：执行变更（严肃流程）

1. **重新评审方案**：拉关键负责人评估ROI、可行性、风险
2. **更新计划**：迭代排期表，改时间、改分工、加版本号
3. **周知确认**：邮件/群发/开会，确保所有受影响的人都知道变更
4. **双保险**：后续2次例会中再次强调变更；感谢团队支持

### 4.3 案例：手册黑白→彩色

| 步骤 | 错误做法（Leo-v1） | 正确做法（Leo-v2） |
|:---|:---|:---|
| 识别 | "挺好的，黑白变彩色嘛"——没意识到影响 | 识别出方案/预算/排期/人力/协作五个维度都有影响 |
| 分析 | 无——直接让设计师改 | 评估：印刷成本↑、设计工作量↑、可能延期、设计师会不爽 |
| 决策 | 直接改 | 判断为重要变更→走严肃流程 |
| 执行 | 设计师加班返工、运营不知道、排期混乱 | 拉评审会→更新方案和排期→全员周知→后续2次周会强调→感谢设计师 |

### 4.4 操作步骤

1. **建立变化敏感度**：对照识别清单，每周扫一遍项目各维度有无变化
2. **听到变化先不答应也不拒绝**：先问"这个变化影响目标/资源/协作吗？"
3. **判断为重要变更→启动四步流程**：评审→更新→周知→感谢
4. **反复检查材料**：确保变更后的文档是最新版，避免有人用旧材料

## 五、向上管理三心二意

向上管理的本质：**你管过程，老板扛结果——你要助他成功，他才会放心把项目交给你。**

### 5.1 三心二意法则

| 维度 | 含义 | 核心动作 |
|:---|:---|:---|
| **省心** | 让老板不用追着你要信息 | 关键文档主动共享、关键进展主动同步 |
| **放心** | 让老板知道项目在轨道上 | 关键风险尽早说、已有解决方案更要让他知道 |
| **有信心** | 让老板觉得项目越来越好 | 展示关键里程碑达成、阶段性成果 |
| **有意识要资源** | 搞不定的事主动请求支持 | 要老板的时间（评审/推进）、要资源（加人/预算）、要士气（团建/打气） |
| **有意识做汇报** | 关键进展和成绩主动汇报 | 成绩不说等于没做——老板关注的太多，不做汇报你在他的世界里就不存在 |

### 5.2 三个灵魂拷问

> **Q1：关键风险要不要让老板知道？**
> → 要。比起坏消息，老板更怕你没消息。

> **Q2：比起没消息，什么更让老板害怕？**
> → 从别人口中得知你的坏消息。不要让老板陷入"傻子竟是我自己"的尴尬。

> **Q3：已经有解决方案了，还要让老板知道吗？**
> → 要。老板知道得越多，越知道怎么帮你助攻。而且他知道了"风险已被处理"会更安心。

### 5.3 向老板要资源清单

| 资源类型 | 具体可要什么 |
|:---|:---|
| 时间 | 帮评审关键交付物、帮推进跨部门事项 |
| 人力 | 补人、借人、协调专家 |
| 预算 | 增加预算（如换蓝幕替代绿幕）、TB团建经费 |
| 关系 | 老板刷脸催进度、介绍关键人脉 |
| 士气 | 给团队写封信、会上表扬、公开认可 |

### 5.4 操作步骤

1. **约定沟通方式**：跟老板对齐——关键节点评审？有问题随时说？还是进度正常发个消息就好？
2. **建同步机制**：关键文档放共享文件夹；关键进展群内/邮件同步
3. **风险第一时间上报**：带着解决方案去说——"有个问题，我已经想了三个方案"
4. **关键成绩主动汇报**：里程碑达成→拉个汇报会，感谢团队+感谢老板
5. **定期整理资源需求**：项目推进不下去的时候，别自己硬扛——列出来哪些资源老板能给

## 六、体验管理十五字

体验管理不是"拍马屁"，而是让团队在这个项目中**同时实现自己的收获**——好的项目管理关系是彼此成就的关系。

### 6.1 十五字法则（由浅到深，手段越来越重）

| 法则 | 含义 | 保姆级话术示例 |
|:---|:---|:---|
| **讲地位** | 让他知道他在项目中的位置有多重要 | "这次设计的部分是影响品牌传播的关键环节，幸亏是你来负责""这个事交给你，让我放心的人真的不多" |
| **有成长** | 让他看到做完这个项目他能提升什么能力 | "我知道你一直在练平面设计，这次刚好一起做一次极致训练，做完你的能力会上一个大台阶" |
| **在一起** | 让他感觉我们是一个团队并肩作战 | "这个事情很难，但我会一直冲在前头陪着大家干""你加班到几点我到几点，想吃什么我去买" |
| **给信任** | 让他感觉被充分信任和托付 | "虽然合作过很多团队，但咱们是唯一一个让我放心把后背交给对方的团队""有你在我就很安心" |
| **讲公平** | 让他感觉被喜欢、被欣赏（通常私下说） | "你这个事情真的干得非常棒""你一定是未来能拿到大结果的人" |

### 6.2 派活的三个版本对比

| 版本 | 话术 | 效果 |
|:---|:---|:---|
| V1 纯派活 | "封面设计你负责，下周三出稿" | 被动接受，无参与感 |
| V2 加必要性 | "品牌传播这个部分全靠你了，相信你能做得特别好" | 有一定价值感 |
| V3 加情感 | "大家都说你营销感特别好，终于有机会合作了！我特别期待这次的作品能成为最经典的一版手册" | 积极投入，有使命感 |

### 6.3 操作步骤

1. **派活前想三秒**：这个任务对他有什么价值？我说什么能让他觉得自己在做一件有意义的事？
2. **从"讲地位"开始**：先说他做的多重要，再说任务是什么
3. **过程中及时反馈**：做得好就夸，不要等做完了才说
4. **陪伴行动胜于语言**：加班你也在、困难你冲在前
5. **关键时刻表达喜欢**：项目收尾时真诚感谢每个人的贡献

## 七、冲突管理24字

冲突是在所难免的。冲突的本质不是"这个人难搞"，而是背后有未对齐的信息、未协调的资源、未统一的立场。

### 7.1 冲突四类根源

| 根源 | 表现 | 解法 |
|:---|:---|:---|
| **理解问题** | 双方信息不对等，或思考模型不同——"你说的跟我理解的不一样" | 对齐信息、做翻译 |
| **质量问题** | 一方严格把控质量，另一方觉得"你老卡我" | 提前约定标准、借用规范 |
| **资源问题** | 一方反复改动导致另一方加班超负荷 | 协调资源、找人分担 |
| **立场问题** | 不同部门/公司的目标天然不同 | 各退一步、向上升级 |

### 7.2 24字解法（由轻到重，逐级升级）

```
好好说话 → 对齐信息 → 协调资源 → 各退一步 → 向上升级
```

| 级别 | 解法 | 核心动作 | 话术示例 |
|:---|:---|:---|:---|
| 1 | **好好说话** | 先平复情绪，避免进入吵架状态 | "没想到两个脾气最好的人都着急了——看得出大家都对这个项目特别有责任心" |
| 2 | **对齐信息** | 做翻译——帮双方澄清各自真正想表达的意思 | "你是想说配色一致性对吧？你是担心绿幕抠图对吧？其实你俩不矛盾……" |
| 3 | **协调资源** | 冲突根源是资源不够→帮他去要资源 | "这个确实有难度，我在××方面有经验，我来支持你""我跟老板申请补个人" |
| 4 | **各退一步** | 进入谈判——找折中方案 | "大家都为了项目好，他已经做了这么大退让了，你能不能也退一步？" |
| 5 | **向上升级** | 实在解决不了→拉更大老板来判断优先级 | "这个问题我们拉××进来一起判断吧" |

### 7.3 案例：手册封面的黄色之争

| 冲突 | 设计师 | 教研 |
|:---|:---|:---|
| 立场 | "一堂品牌色是黄色，封面必须用黄色" | "直播间绿幕抠图，黄色会透底，太丑了" |
| 升级 | "你懂不懂设计一致性？" | "你懂不懂可用性第一位？" |

**Leo用24字解法化解**：

1. **好好说话**："真没想到两个最nice的人都急了，最近压力都大，我们一起看看方案"
2. **对齐信息**："矛盾点其实就是配色一致性 vs 绿幕问题，对吗？公司关键物料确实要求黄色，绿幕问题也很真实"
3. **协调资源**："如果所有问题都卡在绿幕，我去申请几百块预算把绿幕换成蓝幕，问题不都解决了吗？"
4. **结果**：皆大欢喜，封面用黄色，幕布换成蓝色

### 7.4 操作步骤

1. **冲突发生时先叫停情绪**：用"好好说话"的话术按住场面
2. **判断冲突根源**：是信息不对齐？资源不够？还是立场不同？
3. **从轻到重逐级使用解法**：能用"好好说话"就不用"向上升级"
4. **做翻译而不是做法官**：帮双方说清楚各自真正的意思，而不是评判谁对谁错
5. **升级前确保前面的解法都试过了**：向上升级是最后手段

## 八、敏感度-管理动作匹配表

管理有成本，手段够用就好。六维敏感度决定你要重点投入哪些管理动作：

| 敏感维度 | 重点管理工作 | 管理目标 | 不敏感的默认策略 |
|:---|:---|:---|:---|
| **预算敏感** | 质量管理、变更管理 | 控制成本不超支——质量追求不能无底线，变更不能随意增加预算 | 成本可控即可，无需精细化 |
| **时间敏感** | 进度管理、变更管理 | 确保按时交付——关键路径日确认，延期风险立刻暴露 | 按周跟进即可，晚几天没关系 |
| **人力敏感** | 进度管理、变更管理、体验管理 | 不能随便加人→优化现有资源效率，体验好才能留住人 | 人手充足，可以灵活调度 |
| **协作敏感** | 全部六项管理工作 | 建立信任和协作机制——每一项都不能忽视，让人感觉"靠谱" | 团队熟悉，默契在，轻量管理 |
| **风险敏感** | 质量管理、变更管理、向上管理 | 降低失败概率——守住质量节点 + 严格控制变更 + 老板知情兜底 | 风险低，常规管理即可 |
| **老板敏感** | 质量管理、向上管理 | 满足关键决策人期望——质量必须达标 + 信息必须透明 | 常规汇报即可 |

> **使用方式**：拿到项目后，对六个维度打分（1-5分），3分以上的维度就是必须重点管理的。如果判断不了敏感度→**多做动作**，现实中99%的问题是动作太少而不是太多。

## 九、操作步骤（总流程）

当你接手一个项目的执行管理时，按以下步骤操作：

### 第一步：评估敏感度，确定管理重点
- 用六维敏感度模型打分（预算/时间/人力/协作/风险/老板）
- 参照匹配表确定哪些管理动作需要重点投入

### 第二步：开启动会，前置解决问题
- 明确分工（现场确认计划排期和截止时间）
- 培养团队意识（有问题尽早说、按计划执行）
- 确定质量节点（关键子目标/质量标准/交付物评审）
- 明确变更流程（什么情况走严肃流程、怎么走）
- 营造团队氛围（讲价值、讲成长、讲信任）
- 提前打预防针（我会高频跟进、质量线会很严、有摩擦很正常）

### 第三步：建立日常管理节奏
- **每日**：确认关键路径任务进展（有没有如期启动、有没有卡点）
- **每周**：站会/周报对齐进展差距
- **里程碑**：评审会+复盘

### 第四步：管事情
- **进度**：培养意识→丰富手段→高频沟通
- **质量**：守住子目标完成→质量标准检查→关键交付物评审
- **变更**：识别变化→分析风险→判断是否走严肃流程→执行变更

### 第五步：管人
- **向上**：让老板省心（主动同步）→放心（风险早说）→有信心（展示进展）
- **体验**：讲地位→有成长→在一起→给信任→讲公平
- **冲突**：好好说话→对齐信息→协调资源→各退一步→向上升级

### 第六步：收尾
- 交付前最后检查一遍关键质量节点
- 向老板做最终汇报（成果+感谢团队）
- 准备复盘（见 `[[framework-yitang-project-retrospective]]`）

## 十、Constraints & Boundaries

### 适用边界

| 场景 | 适用？ | 说明 |
|:---|:---:|:---|
| 有明确计划的项目进入执行阶段（B级以上） | ✅ | 本卡核心场景 |
| 创业公司/跨部门协作/新人多的团队 | ✅ | 手段和话术专为此设计 |
| A级口头项目 | ⚠️ | 口头管理即可——不需要全套质量管理/变更流程 |
| 日常重复运营工作 | ❌ | 不是项目，不需要项目管理 |
| 项目还在定方案/拆计划阶段 | ❌ | 回到上一环，先做好计划和拆解 |

### When NOT to Use

| 场景 | 替代方案 |
|:---|:---|
| 团队高度默契、项目极其简单 | A级口头管理——站会+口头确认即可 |
| 手段过度导致团队反感 | 降级——减少检查频次，回到周会节奏 |
| 变更流程被滥用——小事也走严肃流程 | 坚守判断标准——只影响目标/资源/协作的才走流程 |

## 十一、失败模式

| 模式 | 症状 | 修复 |
|:---|:---|:---|
| **只计划不管** | 计划发完邮件就不管了——以为项目会自动完成 | 建立管理节奏：关键路径日确认，非关键周确认 |
| **沟通频次太低** | 只在周会上问进度，发现延期时已经晚了5天 | 关键路径任务改为每日确认，不要担心"问多了烦" |
| **不守质量节点** | 没有提前明确质量标准和评审人，做完了才发现问题 | 启动会上拉一张质量节点对照表，所有A角色确认 |
| **所有变更都直接改** | 团队频繁返工，协作信任崩塌 | 用六维敏感度评估每个变更——影响目标/资源/协作的必须走严肃流程 |
| **闷头干活不汇报** | 老板不知道项目进展，从别人口中得知坏消息 | 执行三心二意——最低限度：关键风险一定要尽早让老板知道 |
| **纯派活不给价值感** | 团队推一步动一步，毫无主人翁意识 | 用十五字法则重新派活——先讲地位再派任务 |
| **冲突靠吼解决** | 吵架升级到摔椅子、拍桌子走人 | 用24字法则逐级化解——先平复情绪再翻译信息 |
| **管理手段超过敏感度** | 简单项目用重手段，团队觉得PM很烦 | 降级——参照敏感度匹配表减少管理动作 |
| **管理手段低于敏感度** | 高风险项目管理太轻，看不见的风险最终爆发 | 升级——不确定敏感度时多做动作，不要少做 |

## 十二、Critique

### Goldratt行为陷阱
Goldratt指出的三个行为陷阱（学生综合征、帕金森定律、多任务并行）在管过程阶段特别容易爆发：
- WBS做完了，但第一周检查——所有人都说"进展顺利"，实际完成0个
- 因为人们等到最后一刻才开始（学生综合征），工作膨胀到填满所有时间（帕金森）

> **拷问**：你的进度管理依赖"百分比进度报告"吗？如果每个人都报80%，你怎么知道是真的80%还是"前80%做了但最后20%最难"？

**一堂回应**：本卡的质量管理节点正是解决这个问题的答案——**不依赖百分比报告，而是检查关键质量节点的交付物是否真的完成**。"有交付成果+可检查验证"是判断进度的唯一可靠方式。同时，高频沟通不是为了"催"，而是为了发现"还没开始"——这是对抗学生综合征的最有效手段。

### 管理成本 vs 管理效果的平衡
本卡强调"多做动作"，但存在过度管理的风险——特别是在团队经验丰富、项目类型熟悉的情况下。

> **拷问**：你的团队都是5年以上的老手，你还要每天站会每天确认——你真的不是在浪费时间吗？

**一堂回应**：敏感度-管理动作匹配表正是解决这个问题——根据项目特点动态调整管理强度。老手+熟悉项目→轻量管理；新手+高风险项目→重手段。宁可先多做，发现不需要再减（减法比加法容易）。

## 十三、Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:---|:---|:---|
| 项目计划完成，准备进入执行 | 开启动会——2小时前置解决分工/质量/变更/氛围 | 启动会开完，团队知道做什么、怎么协作、质量标准是什么 |
| 关键路径任务连续2天"还在做"没有交付物 | 升级为每日盯对——坐旁边/拉攻坚小组 | 交付物在约定时间完成 |
| 有人提出方案/排期/人力变更 | 先做影响评估——影响目标/资源/协作？ | 30分钟内判断走不走严肃流程 |
| 老板连续2次主动来问进度 | 启动向上管理——主动同步关键进展+风险 | 老板下次不主动问了 |
| 团队成员被催着才动 | 用十五字法则做一次"加价值+加感情"派活 | 成员主动同步进展而不是被追问 |
| 项目中出现争吵/拍桌子 | 用24字法则从第一级开始——好好说话 | 情绪平复后30分钟内回到解决问题 |
| 项目进度报告连续3周"完成80%" | Goldratt缓冲诊断——问"从今天专注做，多久能交？" | 发现≥1个虚报进度的任务 |
| 不确定项目敏感度 | 六维度逐个打分1-5分，3分以上重点管理 | 明确2-3个重点管理方向 |
