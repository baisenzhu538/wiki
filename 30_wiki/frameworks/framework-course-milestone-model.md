# 课程里程碑模型：一堂做课的七步生产流程

> **用一句话讲清楚**：一堂做一门课不是灵感驱动，而是有明确里程碑的生产流程。

这是 Truman 分享的"一堂目前做课的流程"，也是科学建模七步里程碑在课程研发中的具体落地。它把一门课从模糊想法到最终交付，拆成 7 个里程碑。

---

## 核心要点

```
预案 → 敲定边界 → 饱和收集事实 → 整合萃取 → 1.0 模型 → 辩证讨论/撞击实验 → 封装 → 包装打磨
```

## 实操要点

| 里程碑 | 关键动作 | 停止条件 |
|--------|---------|---------|
| 边界 | 写一句话范围 | 团队无异议 |
| 事实 | 案例饱和收集 | 新增案例不再改变判断 |
| 萃取 | 分类、找共性 | 有清晰的 before/after 模式 |
| 1.0 | 画第一个模型 | 模型能解释主要案例 |
| 撞击 | 找反例、专家评审 | 无明显硬伤 |
| 封装 | 做工具、配案例 | 可直接交付 |
| 包装 | 做解读、做课程 | 用户能听懂 |

---

## 边界

| 边界 | 说明 |
|------|------|
| **适用对象** | 面向方法论/课程/框架型内容的生产，不适合单一知识点的轻量输出 |
| **事实饱和度** | 必须有充足案例支撑，否则 M3 无法完成 |
| **撞击实验时间** | 不能压缩，通常是最耗时阶段 |
| **专家质量** | 参与撞击实验的专家需有 before/after 实战经验 |
| **模型范围** | 必须明确适用范围，不能试图解释一切课程类型 |
| **团队文化** | 需要能接受"以推翻为目标"的评审氛围 |

---

## 失败模式

| 失败模式 | 症状 | 修复 |
|----------|------|------|
| **边界漂移** | 课程范围越写越大，内容收不住 | 回到 M2，重写一句话边界定义 |
| **事实不足就建模** | 模型听起来对，但缺乏真实案例支撑 | 暂停建模，回到 M3 继续饱和收集事实 |
| **撞击实验走过场** | 评审变成自我宣传，没人真正找反例 | 明确评审目标为"推翻模型"，引入外部专家 |
| **跳过封装直接包装** | 课程 PPT 很漂亮，但学员无法落地 | 先完成 M6 封装，再进入 M7 包装 |
| **追求 1.0 完美** | 长期停留在画图阶段，不敢产出 | 1.0 不要求完美，要求完整和可验证 |
| **灵感替代流程** | 研发节奏依赖个人状态，进度不可预期 | 用 M1-M7 作为固定检查点推进 |

---

## 行动 Checklist

| 步骤 | 检查项 | 通过标准 |
|------|--------|----------|
| 1 | 预案价值明确 | 能写出"为什么要做这门课"和"不做会损失什么" |
| 2 | 边界一句话定义 | 团队对"解决什么/不解决什么"无异议 |
| 3 | 事实收集饱和 | 新增案例不再改变当前判断 |
| 4 | 萃取有清晰模式 | 能描述 before/after 的共性 ≥3 条 |
| 5 | 1.0 模型可解释 | 能用模型解释 ≥80% 主要案例 |
| 6 | 撞击实验完成 | 无明显硬伤，专家无坚决否定意见 |
| 7 | 封装可交付 | 有工具/模板/案例，学员可直接使用 |
| 8 | 包装用户听得懂 | 找 3 个目标用户测试，能复述核心逻辑 |
