# 阿蕊AI落地六块基本功——销售三基本×AI三基本双层体系

> 单行道结论：AI不会取代你的业务判断，它只会放大你的业务判断——包括模糊的那部分。

## 一、体系总览（双层结构）

阿蕊（公众号「阿蕊科学销售AI体系」作者）的「销售AI落地方法论」是双层结构：先销售基本功把业务看懂，再AI基本功让AI站对位置，最后才封装 Agent。

```
第一层 销售三大基本功（先看懂业务）
  用户分层 → 卖点提炼 → 过程拆解
第二层 AI三大基本功（再让AI站对位置）
  场景拆解 → 提示词逻辑设计 → 分析校正
      ↓
  系统提示词 → 封装Agent → 接工具（Skill跑起来）
```

推进逻辑（art_2 尾部原文）：
- 场景拆清了，你才知道AI该站在哪；
- 提示词设计好了，AI才能稳定给你想要的东西；
- 会分析校正了，AI才能从「偶尔好用」变成「一直好用」。

**「定位问题，比解决问题难10倍，也值10倍。」**——多数人AI用不好，不是卡在工具上，而是卡在「不知道该让AI干什么」；答案不在AI身上，在自己身上。

## 二、销售三大基本功（第一层）

| 基本功 | 回答的问题 |
|:--|:--|
| 用户分层 | 用户是谁 |
| 卖点提炼 | 卖什么 |
| 过程拆解 | 转化流程怎么走 |

## 三、AI三大基本功（第二层）

| 基本功 | 回答的问题 | 对应产出 |
|:--|:--|:--|
| 场景拆解 | AI该站在哪 | AI角色定位+Agent清单 |
| 提示词逻辑设计 | 怎么稳定拿到想要的 | 系统提示词 |
| 分析校正 | 从偶尔好用变一直好用 | 校正回路 |

## 四、与一堂科学销售五步法的桥接

阿蕊体系与库内 `framework-yitang-scientific-sales-five-step`（李蕊）高度同构：一堂五步法=用户分层→卖点提炼→过程拆解→业绩管理→回款履约，其**前三步正是阿蕊的「销售三大基本功」**。差异在第二层：

- 一堂：后两步是业绩管理、回款履约（管理闭环）；
- 阿蕊：叠加「AI三大基本功」（场景拆解→提示词设计→分析校正），把销售方法论落到 Agent 封装。

两条路线可视为：同一套「科学销售」底层认知（李蕊/一堂 与 阿蕊体系同源表述「所有销售动作对应客户决策成本」），分岔出「管理闭环」与「AI封装」两种延伸。消费时可按「要管队伍」走一堂后两步，「要上AI」走阿蕊第二层。

## 五、角色分层的暗知识（AI该扮演什么，取决于业务阶段）

- **验证期**（用户画像没定、流程没跑通）：AI = 专家参谋——帮做假设、建认知、降试错成本（详见 [[case-arui-headhunter-ai-role-switching]]）。
- **复制增长期**（画像清晰、流程稳定）：AI = 提效工具——从内部流程找转化率最低的环节逐个优化。
- **阶段错配即失效**：产品还没验证清楚就设计全自动 Agent，等于地基没打就盖楼。

## 六、Critique（外部攻击者视角）

- 攻击1（证据）：体系出自公众号连载，仅 AI三大基本功之一（场景拆解）有完整展开和案例，提示词逻辑设计、分析校正两块目前只有概念无细节——按半成品框架入库，confidence 0.85 随连载补全再升。
- 攻击2（普适性）：案例均为个人/小团队业务（猎头、剪辑外包），大组织多角色协作场景是否适用未验证。
- 攻击3（营销滤镜）：源文含训练营招募内容（已滤除），体系本身是其训练营课程大纲，存在「把简单事体系化以利售卖」的动机偏差；但「先拆业务再上AI」的核心主张与库内 AI 销售协同、一堂过程拆解交叉印证，非孤证。

## 七、Boundary（适用边界）

- 适用：个人/小团队要「让AI进自己业务」但不知道从哪下手；设计 Agent 前的业务盘点。
- 不适用：业务流程已标准化、只缺算力执行的场景（直接上工具即可，无需六块基本功）；复杂组织级销售体系（需配一堂业绩管理/回款履约）。

## 八、Action Triggers

- 打开AI对话框前不知道该问什么 → 先走三步拆解（[[method-arui-business-scenario-3step-decomposition]]）。
- 要给销售团队配 AI 工具/Agent → 先对照本卡判断每条业务线处于验证期还是增长期。
- 评估外部「销售AI」产品（如 [[entity-销售AIπ平台]]）→ 用六块基本功反查：它覆盖哪几块，缺哪几块。
