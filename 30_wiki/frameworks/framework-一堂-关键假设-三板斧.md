# 一堂关键假设三板斧（骨架）

> **一句话**：三板斧是把「一堆假设」收敛成「用最小成本验证最脆弱那几条」的方法论骨架——**先做加法（解构要素）、再做减法（找风险最高假设）、最后快速验证（最便宜策略）、并用贝叶斯迭代**；操作清单见 [[tool-一堂-hypothesis-validation-three-axe]]，本卡只讲骨架与「为什么」。来源：`truman-口述:1064-1074` + `一堂-关键假设-关键假设三板斧_paddle_ocr.txt`（YitangΩModel）。

---

## 一、四步骨架

> 口述原话：「先做加法再做减法，最后快速验证……第一步先做加法，尝试把一个业务有能力把它解构，找到里面商业环节的这些要素……第二步做减法……谁是你最关键的假设……第三个快速验证……用最快的速度，最便宜的策略去回答关键假设。」（`truman-口述:1064-1074`）

```
加法（解构要素） → 减法（找风险最高假设） → 验证（最便宜策略） → 迭代（贝叶斯更新）
   ↑                                                                              │
   └──────────────────────── 迭代后带着新后验回到加法/减法 ─────────────────────────┘
```

| 步 | 一句话 | 产出 | 道的层面（为什么） |
|---|---|---|---|
| **加法** | 把业务解构为要素，列出所有前提 | 一页纸假设清单 | 不解构就只能看到表面数、表面形态；结构化才能看见前提 |
| **减法** | 按前置性×风险性收敛到 2-3 条 | 关键假设短名单 | 精力有限，二八法则——一号位只能盯紧风险最高的那几条 |
| **验证** | 用最快、最便宜策略回答关键假设 | 证实/证伪结论 | 风险越高步子越小；验证成本≤失败损失的 1/10 |
| **迭代** | 用新证据更新后验，回到加减法 | 更新后的关键假设 | 验证不是终点，是贝叶斯更新；业务阶段变了，关键假设也变 |

### 口述顺序 vs OCR 视觉（不矛盾）

- **口述逻辑顺序**（`truman:1066-1074`）：加法 → 减法 → 验证。强调的是**认知顺序**——先有能力把业务解构出全要素（加法），才知道有哪些假设可减。
- **OCR 视觉排列**（YitangΩModel）：找关键假设（减法）→ 拆解假设（加法）→ 验证阶段（明确目标/坚持/调整/放弃）→ 迭代假设（贝叶斯）。强调的是**操作入口**——先锁定一个关键假设（减法），再把这个假设本身拆解到可验证（加法）。
- **统一读法**：外层循环是「加法（解构业务）→ 减法（收敛关键假设）→ 验证 → 迭代」；对每个被收敛出的关键假设，内层再做一次「加法（把这个假设拆成可验证的子前提）→ 验证」。两种读法是同一方法论的两层，不冲突。

## 二、每一步的「为什么」（道）

### 加法：不结构化，就看不见前提

> 「第一步就是要尝试去拆解业务……追求把一个业务的那些成败的要素尝试结构化，然后拆成最好前后相关的几个部分，最终来指导我做一些重要的决策。」（`truman:1076-1078`）

加法的价值不在「列得多」，而在**把隐性的前提显性化**。大多数失败不是假设验错了，而是**那条关键假设根本没被列出来**。加法可借 [[framework-一堂五步法]]（需求/产品/模式/增长/壁垒）或商业画布做系统性拆解，避免只拆自己熟悉的层。

### 减法：精力有限，只能盯最前置、风险最高的

减法的判据是两个乘子：**前置性**（它在逻辑链越靠前，后面越多环节依赖它）× **风险性**（它不成立时损失越大）。前置性高且风险高的，就是必须先验证的关键假设。这也解释了为什么不能「平均验证」——前置假设不成立，后面所有假设都不用看。

### 验证：最便宜策略，证伪优先

验证的目标不是「证明它成立」，而是**用最低成本让它有机会被证伪**。这与 [[dk-mckinsey-hypothesis-driven-pitfalls]] 的「主动证伪而非证实」一致：能证明假设**不成立**的实验，比证明成立的实验更有价值。验证分明确目标 / 坚持 / 调整 / 放弃四种处置（OCR），前置假设被证伪 = 业务需终止或重大调整，不是「再试一次」。

### 迭代：贝叶斯更新，而非一锤定音

OCR 把迭代标注为「贝叶斯定理」。含义：每条关键假设都有一个**先验概率**（你多确信它成立），每次验证产生新证据后，要用证据更新为**后验概率**，再决定加码 / 调整 / 放弃。三层含义：

1. **验证不给出 0/1**，给出概率变化——「成立可能性从 50% 升到 80%」也是有效结论。
2. **新业务阶段要重估**：早期看需求假设，成长期看增长假设，关键假设随阶段迁移（接 [[framework-一堂-业务公式拆解-总纲]] L6 动态层）。
3. **反对一次性线性流程**：验证是循环，不是「验完就开工永不回头」。

## 三、与风险管理 / 乘法的关系

三板斧之所以有效，根子在 [[framework-一堂-关键假设]] 第四节：**关键假设是一组乘法关系，任一为零整体为零**（`truman:2460-2474`）。因此：

- **加法**是在找出所有乘项；
- **减法**是在找出最可能为零的那个乘项；
- **验证**是在它真的为零之前，先小额测试它会不会为零；
- **迭代**是业务阶段变了之后，重新找当前最可能为零的乘项。

这也解释了「关键假设的本质就是风险管理」（`:2474`）——三板斧是风险管理的**操作节奏**：不是消除风险，而是把风险转成假设、用最小成本提前验证、不一错到底。

## 四、案例演示：外层 / 内层循环 + 贝叶斯迭代

> 口径：以下数字为**假设演示 / 课程经验值**，仅用于演示方法论，不作事实断言。案例沿用 [[concept-一堂-key-assumptions]] 的陈贤敏中式汉堡，保持全库一致。

### 案例 1：外层循环（解构业务 → 收敛 → 验证 → 迭代）

目标：判断「中式汉堡」能不能做。

**外层加法**（解构业务全要素，一页纸假设清单）：

| 要素层 | 关键假设（我们以为…） |
|---|---|
| 需求 | 上班族需要「中国味 + 汉堡形态」的快餐 |
| 产品内核 | 卤味/肉夹馍 + 汉堡胚的组合用户愿意复购 |
| 定价 | 客单价 25-35 元能被接受 |
| 渠道 | 写字楼 / 商圈点位能稳定获客 |
| 单元模型 | 单店月毛利能覆盖房租人工 |

**外层减法**（前置性 × 风险性排序，收敛到 2-3 条）：

1. **「中式汉堡有足够大的市场」**——最前置、风险最高；它不成立，后面全白做
2. 「单店模型能跑通」——次前置
3. 「客单价 25-35 被接受」——边缘，可在验证中调

**外层验证**（最便宜策略）：不开 3 家，先开 **1 家实验店**——成本约为 3 店同开的 1/3，且能证伪核心假设。

**外层迭代**：实验店数据出来后回到加法 / 减法——若「市场」被证实，下一轮减法聚焦「单店模型能否复制到不同点位」。

### 案例 2：内层循环（把一条关键假设拆到可验证）

锁定最关键假设「中式汉堡有足够大市场」后，内层再做一次加法，把它拆成可验证的子前提：

| 子前提 | 证伪实验（实验店内） | 验证信号（经验值） |
|---|---|---|
| 目标人群确实存在且会来 | 记录午 / 晚高峰客流结构、复购客占比 | 目标客群占比 ≥ X% |
| 价格带被接受 | 测 25 / 30 / 35 三档定价的转化 | 主推价位转化 ≥ Y% |
| 口味驱动复购 | 跟 30 天复购率、套餐连带率 | 复购 ≥ Z% |

> 内层 = 第一节「统一读法」里说的：对每个被收敛出的关键假设，再做一次「加法（拆子前提）→ 验证」。**外层回答「验哪条」，内层回答「这条怎么验到能证伪」。** 内层拆不下去时，接 [[framework-一堂-业务公式拆解-总纲]] 把子前提落到 L1-L6 可证伪参数。

### 案例 3：贝叶斯迭代数值走查

同一条关键假设「中式汉堡有市场」，演示概率如何随证据更新（数字为假设演示）：

| 时点 | 证据 | 先验 → 后验 | 处置（按阈值） |
|---|---|---|---|
| T0 开店前 | 行业类比、问卷 | **50%**（没证据不赌） | 不开 3 店，先做最便宜验证 |
| T1 实验店 4 周 | 午晚高峰排队、复购达标、单店毛利为正 | 50% → **80%** | ≥70%：加码，准备第 2 店但仍小步 |
| T2 第 8 周 | 某周复购明显下滑、周边竞品跟进 | 80% → **65%** | 40-70%：调整（菜单 / 点位），暂停扩店 |
| T3 调整后 4 周 | 复购回升、连带率提升 | 65% → **78%** | ≥70%：恢复小步扩店 |

三条规则落地：

- **验证不输出 0/1**：T1 不是「成了」，是 50%→80%；T2 不是「败了」，是 80%→65%。
- **阈值驱动动作**（与 OCR「坚持 / 调整 / 放弃」一致）：≥70% 加码、40-70% 调整、<40% 放弃 / 转型。前置假设跌破 40% = 业务需终止或大调，不是「再试一次」。
- **阶段变了要重估**：「市场」成立后，下一轮关键假设迁移到「可复制性 / 单店模型」，回到外层循环（接 [[framework-一堂-业务公式拆解-总纲]] L6 动态层）。

> 这正是「迭代求不固执」：不是一次验证定终身，也不是遇到反证据就崩——用后验概率把「坚持 / 调整 / 放弃」变成可计算的决策。

## When NOT to Use

- **试错成本极低的软件迭代**：直接上线就是 cheapest test，完整三板斧反而拖慢——做 20% 核心步骤即可（见 tool 卡「不要用的场景」）。
- **数据严重不足**：三板斧输出质量依赖输入代表性，宁可先补数据。
- **秒级紧急决策**：完整流程耗时，紧急场景用更轻量判断。
- **从 0 到 1 创造新市场**：加法列表是白纸，先探索而非收敛。

## Failure Modes

| 失败模式 | 症状 | 修复 |
|---|---|---|
| **只做加法不做减法** | 列完清单就结束，或清单上百条 | 强制减法到 2-3 条，每条标验证方法+截止日期 |
| **减法按喜好不按风险** | 先验证「我关心/好验证」的而非最关键的 | 用前置性×风险性排序，问「它不成立整个业务会倒吗」 |
| **验证成本过高** | 一上来做完整产品验证 | 成本≤失败损失 1/10，先用问卷/访谈/假产品 |
| **把验证当终点** | 验过一次就永久当成立 | 贝叶斯迭代：新证据更新后验，阶段变了重估 |
| **忽视证伪信号** | 前置假设被证伪还继续投入 | 前置不成立=终止或大调，不是「再试一次」 |
| **价值/增长顺序颠倒** | 产品没跑通就验「能不能扩大」 | 先价值假设（成败），后增长假设（效率），顺序不可颠倒 |

## Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|---|---|---|
| 有一个 idea，不知从何验证 | 加法：用五步法/画布解构业务全要素 | 一页纸完整假设清单 |
| 假设太多无法着手 | 减法：前置性×风险性排序，聚焦 2-3 条 | 关键假设短名单 + 验证顺序 |
| 要设计验证 | 验证：每条配最便宜证伪实验 | 成本≤失败损失 1/10，能证伪而非只证实 |
| 验证结果出来了 | 迭代：贝叶斯更新后验，决定加码/调整/放弃 | 后验概率变化有记录，下一步明确 |
