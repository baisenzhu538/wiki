# 产品内核验证：三维度验证法

> 一堂五步法：产品内核不是"定义了就完了"，而是必须通过三维度验证：用户愿意用、愿意付、愿意推荐。

## 核心框架

三维度验证：

| 维度 | 验证问题 | 验证方法 | 关键指标 |
|:---|:---|:---|:---|
| **用户愿意用** | 用户是否愿意使用产品？ | 原型测试、试用、Concierge MVP | 激活率、使用频率 |
| **用户愿意付** | 用户是否愿意付费？ | 预售、众筹、付费试用 | 付费转化率、客单价 |
| **用户愿意推荐** | 用户是否愿意推荐？ | NPS调查、推荐行为追踪 | NPS、推荐率 |

## 关键洞察

### 1. 三维度缺一不可

| 维度缺失 | 结果 | 案例 |
|:---|:---|:---|
| 愿意用但不愿付 | 免费用户多，无法商业化 | 很多工具产品 |
| 愿意付但不愿用 | 付费后流失，续费率低 | 某些SaaS产品 |
| 愿意用也愿意付但不愿推荐 | 增长慢，获客成本高 | 某些B2B产品 |
| 三维度都满足 | 产品内核成立 | 优秀产品 |

### 2. 验证的段位

| 段位 | 验证方法 | 可信度 |
|:---|:---|:---:|
| L1 | "我觉得用户会喜欢" | 极低 |
| L2 | 问了朋友，朋友说好 | 低 |
| L3 | 用户访谈，说"愿意用/付/推荐" | 中 |
| L4 | 原型测试，用户完成核心任务 | 中高 |
| L5 | 预售/众筹，用户实际付费 | 高 |
| L6 | 产品上线，数据验证三维度 | 极高 |

### 3. 验证方法的选择

| 阶段 | 验证方法 | 成本 | 可信度 |
|:---|:---|:---|:---:|
| 概念阶段 | 用户访谈 | 低 | 中 |
| 原型阶段 | 原型测试 | 中 | 中高 |
| 预售阶段 | 预售/众筹 | 中 | 高 |
| 上线阶段 | 数据监测 | 低 | 极高 |

### 4. 验证后的决策

| 验证结果 | 决策 |
|:---|:---|
| 三维度都满足 | 内核成立，继续迭代优化 |
| 愿意用但不愿付 | 检查价值感知和定价策略 |
| 愿意付但不愿用 | 检查产品体验和激活流程 |
| 愿意用也愿意付但不愿推荐 | 检查超预期体验和分享机制 |
| 三维度都不满足 | 内核假设错误，重新定义 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **无验证** | 定义了内核，从未验证 | 强制验证，至少一个维度 |
| **单维度验证** | 只验证"愿意用"，不验证"愿意付" | 三维度都必须验证 |
| **口头验证** | 用户说"愿意"，但行为不一致 | 用行为验证替代口头验证 |
| **样本不足** | 只验证3-5个用户 | 至少验证10-15个目标用户 |
| **忽视负面结果** | 验证不支持假设，但继续投入 | 尊重数据，调整方向 |
| **验证方法错误** | 用问卷验证"愿意付" | 用预售或付费试用验证 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 产品内核验证 | 技术可行性验证 |
| 创业方向验证 | 市场进入策略 |
| 功能优先级验证 | 品牌传播效果 |
| 商业模式验证 | 运营活动评估 |

## 行动触发器

- 当定义内核时 → 同时设计验证方案
- 当验证"愿意用"时 → 问"愿意付吗？愿意推荐吗？"
- 当用户说"愿意"时 → 用行为验证替代口头验证
- 当验证结果不支持时 → 尊重数据，调整方向
