# 销售目标权衡框架

## 一句话

销售目标不是数字，而是阶段优先级；同一个客户在不同目标（GMV / 收入 / 毛利 / 利润 / 用户数 / 立标杆 / 高客单）下会被重新分级，管理者必须先定目标再分层，否则销售动作必然混乱。

## 目的

解决「公司到底要什么」与「销售该打谁」之间的错位问题。通过把抽象目标翻译成可执行的优先级规则，避免「既要流水又要利润又要用户数」导致团队无所适从，同时让 SABC 客户分级随阶段目标动态漂移而非一成不变。

## When to Use

- 销售团队同时被下达多个目标，资源分配打架，不知道先保哪一头。
- 同一批客户在不同季度被反复调整跟进优先级，一线销售抱怨「标准天天变」。
- 公司进入新市场或新阶段，需要重新定义「重点客户」长什么样。
- 激励方案设计时，需要决定考核 GMV、收入、毛利还是利润（或组合）。
- 产品从探索期进入复制期/增长期，原先的客户分层明显不再适用。
- 需要向销售团队解释「为什么昨天放弃的客户今天又变成 S 级」。

## When NOT to Use

- **产品价值尚未验证**：目标权衡只能帮你选择客户，不能替代产品-市场契合验证；如果产品没人要，聚焦只会加速失败。
- **没有基本的过程数据**：分不清 GMV、收入、毛利、利润之间差异时，强行定目标只是拍脑袋。
- **一次性短期 campaign**：短期活动可以用单一目标直接驱动，不需要完整的目标漂移分析。
- **销售团队少于 3 人且无协作摩擦**：人少时目标冲突不明显，OPC 场景建议直接由创始人定 1 个核心指标即可。
- **高层目标本身就朝令夕改**：如果公司战略每周变化，任何目标权衡框架都会失效，应先解决战略稳定性问题。

## 操作步骤

### Step 1：列出当前阶段候选目标

从课程经验总结的常见目标清单出发，选出公司当前真正在追求的 1–3 个指标 `[conf=0.85, source=00_inbox/销售专题/李蕊-销售体系之一-客户分层和卖点提炼-口述.txt L508-L520]`：

| 目标类型 | 关注问题 | 典型场景 |
|:---|:---|:---|
| **GMV / 流水** | 交易规模、市场声势 | 新业务造势、抢占市场份额、给投资人看规模 |
| **收入** | 实际到账或确认收入 | 支付公司按费率折算、SaaS 订阅ARR |
| **毛利** | 收入减去直接成本 | 产品成熟后优化交付结构 |
| **利润** | 毛利减去费用后的净收益 | 公司要造血、控制烧钱 |
| **用户数** | 客户数量 / 市场份额 | 薄利多销、平台型业务早期放量 |
| **立标杆** | 行业影响力、品牌背书 | To B 早期需要头部客户案例 |
| **高客单** | 单笔订单金额 | 资源有限时抓大客户 |

> **经验值说明**：课程案例中出现的目标冲突（流水 vs 收入 vs 利润）来自特定企业的阶段选择，不作为普适优先级排序。

### Step 2：识别目标之间的冲突

多个目标同时存在时，常见冲突包括 `[conf=0.85, source=00_inbox/销售专题/李蕊-销售体系之一-客户分层和卖点提炼-口述.txt L470-L500]`：

| 冲突对 | 典型表现 | 风险 |
|:---|:---|:---|
| GMV vs 利润 | 做大流水但补贴过高，账面好看但不赚钱 | 现金流被占用，利润被牺牲 |
| 用户数 vs 高客单 | 低价引流客户多，但支付能力弱 | 转化率低，服务成本高 |
| 立标杆 vs 利润 | 头部客户议价能力强，要求低价或定制 | 赢了案例但亏了本 |
| 收入 vs 毛利 | 收入确认快但直接成本高 | 规模越大亏损越多 |
| 高客单 vs 速度 | 大客户决策链长，短期难以贡献业绩 | 影响季度目标达成 |

### Step 3：确定阶段唯一主目标

管理者必须回答「如果只能保一个，先保谁」。课程反复强调：「既要又要还要」在资源有限时会让销售动作彻底变形 `[conf=0.86, source=00_inbox/销售专题/李蕊-销售体系之一-客户分层和卖点提炼-口述.txt L468-L472]`。

主目标选择建议：

| 业务阶段 | 常见主目标 | 辅助目标（可妥协） |
|:---|:---|:---|
| 探索期 | 立标杆 / 验证客户 | 用户数（小样本验证） |
| 复制期 | GMV / 用户数 | 收入（优先规模） |
| 增长期 | 收入 / 毛利 | 用户数（保持增速） |
| 成熟期 | 利润 / 高客单 | 立标杆（选择性维护） |

> **经验值说明**：阶段与目标的映射来自课程观察，具体业务需结合自身现金流、竞争格局和团队能力调整。

### Step 4：根据主目标重新划分 SABC

同一批客户在不同主目标下会重新分级。操作规则 `[conf=0.85, source=00_inbox/销售专题/李蕊-销售体系之一-客户分层和卖点提炼-口述.txt L392-L394]`：

1. 把主目标翻译成可识别的客户属性（如「流水大」→ 交易频次高、单笔流水规模大）。
2. 用 `[[tool-yitang-customer-segmentation-4step]]` 重新提出分层假设。
3. 验证假设：历史数据 + 小规模试点，或定性访谈。
4. 输出新的 SABC 清单，并明确「哪些原 A 级客户在新目标下可降为 B/C」。

### Step 5：把目标翻译为激励与资源分配

激励奖金池的考核指标必须与阶段主目标挂钩 `[conf=0.85, source=00_inbox/销售专题/李蕊-销售体系之四-激励体系搭建-口述.txt L1586-L1590]`：

- 追 GMV → 考核流水/交易额，注意防止刷单和虚假交易。
- 追收入 → 考核实际到账或确认收入，关注回款周期。
- 追利润 → 考核贡献利润，销售可能倾向放弃低毛利客户。
- 追用户数 → 考核新客数，需配套防羊毛党机制。
- 追立标杆 → 考核头部客户签约，需配套案例产出标准。

### Step 6：设定目标切换的信号与复盘周期

目标漂移不应是随意的。建议：

- 每季度复盘一次主目标是否仍成立。
- 设定切换信号：如「连续两个月现金流为正」可从 GMV 切向利润；「标杆客户已覆盖 Top 3 行业」可从立标杆切向规模。
- 切换时同步更新 SABC 分级、激励公式和销售话术。

## 示例

### 示例 1：快钱支付商旅客户的目标漂移

**背景**：支付公司进入商旅板块，销售团队同时跑航空公司、酒店、旅行社，业绩完成率约 40%–50%，方向混乱。

**阶段 1：追 GMV / 流水**
- 主目标：把交易流水做起来，造声势。
- 客户重分级：航空公司、连锁酒店、组团社因流水大成为 S/A 级；小旅行社、单体酒店降为 B/C 级或被放弃。
- 关键调整：原本被认为「不可行」的航空公司被重新评估为重点客户 `[conf=0.85, source=00_inbox/销售专题/李蕊-销售体系之一-客户分层和卖点提炼-口述.txt L280-L282,L320-L324]`。

**阶段 2：追收入**
- 主目标：费率收入。
- 客户重分级：经济型连锁酒店因 POS 机产品费率高（约千分之五）变为 S 级；纯交易平台因费率低（约千分之一）优先级下降。

**阶段 3：追利润**
- 主目标：贡献利润。
- 客户重分级：航空公司因能买单的高毛利产品成为 S 级；低费率平台进一步边缘化。

> **经验提示**：这个案例说明「客户分层不是对客户做永久定性，而是对当前阶段目标下资源分配的动态判断」。

### 示例 2：亲子教育公司的利润保卫战

**背景**：某亲子教育公司玩具产品主要通过亲子渠道销售。某大渠道流量很大，但要求约 50% 返佣。

- 若阶段目标是 GMV：这个大渠道可能是 A 级甚至 S 级。
- 若阶段目标是利润：销售必须放弃该渠道，转而攻克返佣要求较低的中型渠道，否则卖越多亏越多 `[conf=0.85, source=00_inbox/销售专题/李蕊-销售体系之一-客户分层和卖点提炼-口述.txt L488-L499]`。

### 示例 3：美容院的目标错配

**背景**：高端美容院老板学习互联网打法，用低价/免费体验扩大线索范围，希望后续转高客单。

- 问题：阶段目标是「高利润客户」，但获客动作吸引的是支付能力不足的羊毛党。
- 结果：线索量大但转化极低，门店承载能力被浪费。
- 修正：先明确主目标是「高利润」还是「用户数」，再设计获客门槛和分层标准 `[conf=0.85, source=00_inbox/销售专题/李蕊-销售体系之一-客户分层和卖点提炼-口述.txt L476-L486]`。

## Critique

### 外部反对者

#### 反对者 1：精益创业派认为「早期不应过度讨论目标权衡，而应快速验证假设」

**反对点**：创业早期一切都是不确定的，花时间做 GMV/收入/利润的权衡是过度分析，不如先跑通一个付费客户。

**回应**：本框架并不主张在早期做复杂权衡，而是强调「哪怕只有 1 个目标，也要先把它说出来」。探索期主目标通常是「立标杆」或「验证客户」，这正是为了避免把「规模」误当成早期目标。

#### 反对者 2：增长黑客派认为「流水和利润可以通过增长同时解决」

**反对点**：只要增长够快，规模效应会自然摊薄成本，早期不必纠结利润。

**回应**：课程案例显示，很多团队把「规模」当作逃避利润思考的借口，结果融资一收紧就断裂。本框架要求显式回答「当前可以牺牲什么、不能牺牲什么」，而不是假设增长会自动解决一切。

#### 反对者 3：销售管理者认为「目标变化会打击团队士气，应该保持稳定性」

**反对点**：频繁切换主目标会让销售觉得管理层没想清楚，降低执行力。

**回应**：目标切换的打击往往来自「不透明」而非「变化」本身。本框架要求每次切换都同步更新 SABC 分级、激励公式和话术，让销售理解「为什么变」，并参与目标切换信号的讨论。

#### 反对者 4：财务/战略专家质疑「阶段与目标映射过于简化」

**反对点**：真实企业中 GMV、收入、毛利、利润往往同时考核，本框架的「唯一主目标」会误导管理者放弃多维平衡。

**回应**：本框架承认多目标并存是常态，但强调资源冲突时必须排序。辅助目标可以保留，但不能与主目标在同一优先级竞争。具体权重应由企业根据自身情况设定，本框架提供的是决策结构而非固定配方。

### 内部局限

1. **课程案例多为互联网企业，对制造业、项目制企业覆盖有限**：支付公司、美容院、亲子教育等案例的冲突模式可能无法直接套用到长周期、重交付的 B2B 项目制企业。

2. **未给出量化权衡模型**：框架提供了冲突清单和阶段建议，但没有提供如 ROI、LTV/CAC、贡献利润等量化计算模板，落地时仍需配合财务模型。

3. **对「老板目标本身不合理」缺乏纠偏机制**：如果创始人坚持「全都要」，本框架只能暴露冲突，无法强制改变决策。

4. **目标切换信号依赖内部数据质量**：如果 GMV、收入、毛利、利润的核算口径不一致，切换信号会变成新的争议点。

## Synthesis

- 本框架是 `[[framework-yitang-scientific-sales-five-step]]` 中「提炼卖点」步骤的前置判断：分层之前必须先定目标，否则分层失去依据。
- 与 `[[tool-yitang-customer-segmentation-4step]]` 形成「目标 → 分层 → 验证 → 执行」的完整链路：本框架负责「目标」，四步法负责「分层」。
- 与 `[[framework-yitang-sales-incentive-6d]]` 配合：激励的考核指标必须与本框架确定的主目标一致，否则激励会反向驱动错误行为。
- 与 `[[tool-yitang-sales-performance-management]]` 配合：业绩管理中的 Gap 分析、Pipeline 预测需要以主目标为口径，避免用 GMV 口径预测利润目标。
- 与 `[[case-yitang-yitu-lead-industrialization]]` 呼应：益涂的五级漏斗也是先明确目标（利润 + 标杆），再决定线索筛选标准；目标变化时，漏斗责任主体和红线也应重新校准。
- 与 `[[yt-management-goal-management]]` 同构：都是把模糊目标转化为可执行、可复盘的优先级系统。
- 与 `[[yt-unit-model-overview]]` 连接：GMV、收入、毛利、利润最终都要落到单元模型，才能判断目标切换是否经济可行。
- 对 `[[opc-ai-sales-agent-architecture]]` 的启示：销售智能体在给出客户分级建议时，必须先询问当前阶段主目标，否则分级建议可能失效。
