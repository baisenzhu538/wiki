# 五类工作 × 4化：基本功的进攻方向诊断图

> **一句话**：你手上的活分五类——创造、专业、领先、标准、SOP；练基本功不是平均用力，是看清每类工作的「下一站」往哪推：创造类→专业化、专业类→领先化、领先类→标准化、标准类→SOP化。
> **口径说明**：认知篇口述讲「四类工作」（方法论入门-口述 L340-360），武器库全景图扩为**五类**（新增 E·SOP 类）；本域统一称「五类工作 4化」，不称 ABCD（规避管项目域 ABCD 复杂度分级撞名）。

---

## 一、模型总览

一堂开了一场 18 小时连续攻坚会，把见过的所有基本功扔到桌面上分堆，分出工作类型（入门-口述 L334-350），并写下四大追求（入门-口述 L352）：

```
工作类型（五类）          4 化追求（进攻方向）
A 创造类（开放、成功率不高）  ──→  专业化：用模型对抗失败
B 专业类（市场有最佳实践）    ──→  领先化：拆最佳实践成行业前列
C 领先类（已是核心竞争力）    ──→  标准化：建体系不依赖个人
D 标准类（具体稳定）          ──→  SOP化：大表格锁死 100% 执行
E SOP类（已流程化）           ──→  维持+加锁：监督执行、两层加锁
```

> 注意：4 化只有四箭——E 类是 D 类 SOP 化到位后的稳态，不再"化"，只做维持和加锁。类别之间没有严格边界、允许重合、随阶段迁移（入门-口述 L340-342）。

## 二、五类工作逐类解析

### A 创造类 → 专业化

| 项 | 内容 |
|:--|:--|
| 特征 | 开放选项、成功率不高、最容易选错 |
| 例子 | 做内容（写文案/写脚本）、做创意（名字/定位/营销）、做选择（选址/选品/选人） |
| 打法 | **#建池子 #头脑风暴 #攻坚战**：用专业模型对抗失败，不依赖灵感——「关键假设的公司不能依赖灵感，纯依赖灵机一动，你就先在沙滩上坐着吧」（武器库-口述 L2578-2584） |
| 到位标志 | 不依赖领导拍脑袋，有稳定的专业方法做开放题 |

### B 专业类 → 领先化

| 项 | 内容 |
|:--|:--|
| 特征 | 本身难、市场上有大量最佳实践可学 |
| 例子 | 管理类（面试/开会/复盘）、业务类（销售/投放/私域）、通岗类（写作/逐字稿/表达） |
| 打法 | **#找最佳实践 #建审美 #做分解**：拆最佳实践让自己快速成为行业前列，练出水准、练成本事（武器库-口述 L2606-2616） |
| 到位标志 | 关键动作质量对齐行业最佳实践，外人能一眼看出专业段位 |

### C 领先类 → 标准化

| 项 | 内容 |
|:--|:--|
| 特征 | 已是行业稀缺能力、公司核心竞争力，但依赖某一个人/某些情况 |
| 例子 | 获客能力、IP 能力、电商能力、投放能力、规模复制 |
| 打法 | **#建模型 #持续复盘升级**：建成体系让它有机会复制，别那么依赖某一个人（武器库-口述 L2624-2630） |
| 到位标志 | 明星员工休假，业务不抖；能力可被第二梯队接手 |

### D 标准类 → SOP化

| 项 | 内容 |
|:--|:--|
| 特征 | 特别具体、特别稳定、确定性极强、需大规模复制 |
| 例子 | 运营类（门店/私域/品牌自播）、管理类（巡店/招聘店员）、执行类（品控/邮寄/做奶茶） |
| 打法 | **#魔鬼细节建模 #持续复制**：在更精细化环节不断建模，写 SOP——一个又一个表格打勾，让所有东西 100% 严丝合缝执行（武器库-口述 L2632-2640） |
| 到位标志 | 任何人照 SOP 执行结果一致，不依赖过程中大家的自觉性 |

### E SOP类 → 维持+加锁

| 项 | 内容 |
|:--|:--|
| 特征 | 已流程化文档化（《社群运营SOP》《直播检查SOP》《转班/生产/门店SOP》） |
| 打法 | **#100%执行 #监督执行 #两层加锁**：追求百分之百执行，还要监督执行；甚至专门派人监督那个监督的人，两层锁死、指哪打哪（武器库-口述 L2642-2646） |
| 到位标志 | 执行偏差可被监督机制实时发现，两层锁难以被突破 |

## 三、核心动作：把 ABCDE 往右推

楚门做客时说的那句话是本模型的灵魂（武器库-口述 L2656-2666）：

> 「我们真正做管理，就是在业务不断发展的过程中，要努力地把工作往右推的过程……脑子里要有一根弦儿。推一步就进步一步，当你能推得比同行明显领先 1-2 步的时候，你的结果大概也领先 1-2 步。」

一堂自己的现身说法（武器库-口述 L2668-2680）：做课最初是创造类工作（依赖创意）→ 通过复盘和审美提升变成专业类（做课水平领先）→ 现在正在往标准化推 → 理想终局是 SOP 化，「如果做课 SOP 化了，这家公司大概率就能复制出无数人」。

> 推不到头没关系——「最终可能很多工作推不到 1，因为 1 太绝对了，但你们能推几步推几步」（武器库-口述 L2660）。

## 四、怎么用：三步诊断

1. **盘点分类**：列出团队全部高频工作，按「成功率是否开放」「是否依赖特定个人」两问定位到五类
2. **确定下一站**：每类只看向右一格（创造→专业化，不要幻想一步到 SOP）
3. **匹配四字诀**：往右推的具体动作，全部落在「拆建推练」工具卡上（`[[framework-一堂-基本功-四字诀拆建推练]]`）

## 五、When NOT to Use

| 场景 | 为什么失效 | 替代 |
|:--|:--|:--|
| 拿 4化当线性 KPI，逼创造类工作交 SOP | 创造类过度流程化=扼杀探索，探索期没有"正确动作"可固化 | 创造类只专业化；探索用精益验证（`yt-entrepreneur-lean-validation`） |
| 3-5 人小团队、工作类型单一 | 五类是分工较完整组织的诊断图，小团队全员多类叠加 | 只取「往右推一格」的心法，不画全图 |
| 把「往右推」当进度考核指标 | 推过头=过度管理（美团"过度运用"原则：忘了目标光练基本功） | 推的节奏跟业务目标对齐，定期问"这步推得值不值" |
| 用类别给人贴标签（"你就是标准类的人"） | 类别描述工作不描述人，贴标签会锁死人的发展 | 只对工作分类，对人用段位体系（`concept-一堂-基本功-段位体系`） |
| 低频高 stakes 的战略动作 | 五类针对高频重复工作，战略判断不在此列 | 决策域 Y 模型（`yt-decision-y-model`） |

## 六、Failure Modes（症状 → 根因 → 修复）

| # | 症状 | 根因 | 修复 |
|:--|:--|:--|:--|
| 1 | 创意岗被要求周交 SOP，没人敢试错 | 创造类按标准类管 | 创造类只追到专业化：建池子+多轮减法，撤掉 SOP 要求 |
| 2 | 专业类工作"会做就行"，多年不进步 | 没追领先化 | 每季度拆 1 个行业最佳实践，对标差距列清单 |
| 3 | 核心竞争力绑在明星员工身上 | 领先类没标准化 | 启动建模型+复盘升级，90 天内套路文档化 |
| 4 | 标准类工作靠大家自觉，出错率看心情 | 没 SOP 化 | 写 SOP：大表格打勾 + 分工 + 考核机制 |
| 5 | SOP 写了没人查，形同虚设 | 缺监督加锁 | 上监督执行，关键 SOP 两层加锁（监督的监督） |
| 6 | 为"到底算哪类"吵两星期 | 把坐标当标签 | 两问快判（开放？依赖个人？），允许重合，定完就走 |

## 七、Critique（外部攻击与回应）

**1. James March（1991，探索-利用悖论）**：组织需要在探索（exploration）与利用（exploitation）间平衡，过度利用会让组织丧失适应力——攻击"一切往右推到 SOP"的单向逻辑。回应：本模型恰恰内置了平衡——创造类永远停在专业化、不推向 SOP；「往右推」是对每类工作"推一格"而非"推到底"，左端（创造）和右端（SOP）必须同时存在。

**2. 丰田生产方式（标准作业）的边界争议**：精益的"标准作业"被批评压抑改善空间。回应：本模型 SOP 化只覆盖 D/E 类确定性工作，且 E 类的"两层加锁"针对的是执行偏差不是改善——改善动作本身属于 C 类的"持续复盘升级"，两条线不冲突。

**3. Christensen（创新者窘境）**：流程和价值观会让组织无法做破坏性创新——攻击"专业化/标准化让组织僵化"。回应：本模型是工作分类诊断不是组织宪法；当环境剧变时，曾经的"标准类"会被重新判定为"需要重新创造"——类别随阶段迁移是模型的显式设定（入门-口述 L340-342）。

## 九、Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:--|:--|:--|
| 新官上任要盘团队家底 | 画一张五类工作分布图：列出全部高频工作并归类 | 1 周内产出分布图，每类至少 2 项，全团队对分类无重大异议 |
| 某项核心竞争力怕流失 | 按 C 类打法启动「建模型+持续复盘升级」 | 90 天内该能力产出 1 份方法论+1 张自查清单，第二梯队可接手 |
| 新业务从 0 到 1 启动 | 先按创造类对待：建池子+头脑风暴+攻坚战，只专业化不 SOP | 3 个月内跑通专业方法，再评估是否往领先化推 |
| 标准类工作出错率居高不下 | 写 SOP 并加监督：大表格打勾 + 关键 SOP 两层加锁 | 一个季度内执行偏差可被监督实时发现，出错率显著下降 |
