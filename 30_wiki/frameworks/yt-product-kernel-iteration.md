# 产品内核迭代：五种迭代方向

> 一堂五步法：产品内核不是静态的，需要随市场变化而迭代。迭代有五种方向，不是随机尝试。

## 核心框架

五种迭代方向：

| 方向 | 触发条件 | 迭代内容 | 示例 |
|:---|:---|:---|:---|
| **用户层迭代** | 当前用户层饱和或流失 | 扩展到新用户层 | 从一线城市扩展到二三线城市 |
| **场景层迭代** | 当前场景覆盖不足 | 扩展到新场景 | 从办公场景扩展到家庭场景 |
| **价值层迭代** | 用户价值感知变化 | 调整核心价值主张 | 从"高效"到"智能" |
| **功能层迭代** | 技术或竞品变化 | 优化或替换核心功能 | 从人工推荐到AI推荐 |
| **模式层迭代** | 商业模式需要调整 | 调整定价或交付模式 | 从一次性购买到订阅制 |

## 关键洞察

### 1. 迭代 vs 优化

| 维度 | 优化 | 迭代 |
|:---|:---|:---|
| 范围 | 功能层面 | 内核层面 |
| 目标 | 提升现有指标 | 适应市场变化 |
| 风险 | 低 | 高 |
| 频率 | 高频 | 低频 |

常见错误：把功能优化当成内核迭代。

### 2. 迭触发信号

| 信号 | 说明 | 对应方向 |
|:---|:---|:---|
| 关键转化率持续下降 | 内核竞争力下降 | 价值层或功能层迭代 |
| 用户增长停滞 | 当前用户层饱和 | 用户层迭代 |
| 用户使用场景单一 | 场景覆盖不足 | 场景层迭代 |
| 竞品推出颠覆性功能 | 技术或竞品变化 | 功能层迭代 |
| 收入模式遇到瓶颈 | 商业模式需要调整 | 模式层迭代 |

### 4. 迭代的节奏

| 阶段 | 迭代频率 | 迭代范围 |
|:---|:---|:---|
| 验证期 | 每2-4周 | 小范围功能调整 |
| 增长期 | 每1-2月 | 中等范围内核调整 |
| 成熟期 | 每3-6月 | 大范围方向调整 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **迭代无方向** | 随机尝试，资源浪费 | 基于五种方向选择，有数据支撑 |
| **迭代太频繁** | 内核不稳定，用户困惑 | 降低迭代频率，给内核稳定时间 |
| **迭代不及时** | 市场变化后仍坚持旧内核 | 建立市场监测机制，及时识别变化 |
| **只优化不迭代** | 功能越来越多，内核不变 | 定期评估内核是否需要迭代 |
| **迭代不验证** | 迭代后不看数据 | 每次迭代后验证关键指标 |
| **团队对迭代无共识** | 每个人想往不同方向迭代 | 基于数据对齐迭代方向 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 产品内核调整 | 功能优化 |
| 市场变化应对 | 技术架构升级 |
| 商业模式调整 | 运营策略调整 |
| 产品方向重新定位 | 品牌传播调整 |
