# AI产品开发·审美与体系的分工

> 一句话："审美负责定义结果（这个东西应该长什么样），体系负责让结果重复发生（每次都能做成这样）。" ——付则宇口述 L1786-1794

> 本卡双面呈现：§A 复盘后的认知框架 + §B 真实过程的教训。

---

## §A 认知框架：四步法（拆→建→推→练）

与一堂四字诀同构：

| 步骤 | 动作 | 付则宇做了什么 |
|:---|:---|:---|
| **拆** | 拆解标的，建立审美标准 | 拆解 300+ 条口播视频，提炼画面节奏/字幕/动画/音效四要素 |
| **建** | 将审美组件化 | 把"网感"拆成可量化组件——9类视频分类、每个类型固定模板 |
| **推** | AI串联自动化 | 用商用API串联：文案→语音→字幕→素材匹配→渲染，全流程零人工 |
| **练** | 批量产出迭代 | 从 16 小时/条降到零门槛，稳定产出 80 分网感视频 |

**三层账本**：

| 账本 | Before | After |
|:---|:---|:---|
| 认知账 | 选题/脚本/拍摄/剪辑全需专业知识 | 只需输入文案，工具自动完成 |
| 时间账 | 7-20 小时/条 | 几分钟/条 |
| 经济账 | 人工剪辑市场价数千元/条 | API 成本几元/条 |

## §B 真实过程的教训

> 口述 L1754-1760

付则宇亲述：实际开发顺序和复盘框架是反的——

```
真实过程：先追 Hyper Friends 做了一个月 → 发现不对 → 回头拆视频 → 建立审美 → 组件化 → 自动化
复盘框架：拆（建立审美）→ 建（组件化）→ 推（自动化）→ 练（批量产出）
```

**教训**：复盘后的四步法是事后认知重构——它掩盖了"先踩坑再回头"的真实路径。这不意味着四步法是错的，而是**不要把复盘结构当执行路线图**。

---

## 哲学基础

> L1786-1794

"美是负责把那个东西定义下来它应该长成什么样子。体系是负责把美的定义变成一个可以重复发生的东西。"

- 审美 = 判断"什么样的视频算好"
- 体系 = 把这个判断固化为可复用的组件和流程
- AI = 加速器，不是替代审美

## 失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| 技术先于审美 | 追 Hyper Friends 做了一个月才发现方向错了 | 先拆 300 条视频建立审美，再选技术路线 |
| 把复盘结构当执行路线 | 上来就按拆→建→推→练顺序做 | 预期第一圈是乱的——先做、再复盘、再结构化 |
