# 业务公式×Y模型桥接：关键假设层的全面操作化

> **一句话**：Y模型定义了"理论+事实→关键假设→验证→迭代"的认知循环，但**"关键假设怎么来"、"假设间什么关系"、"假设怎么管"**这三个问题，Y模型没有回答——业务公式（C域）就是这三个问题的完整答案。Y模型是骨架，业务公式是肌肉。

---

## 一、核心命题：Y模型缺什么，C域补什么

```
Y模型（认知循环）                C域（操作层）

理论 ──→ 关键假设 ──→ 验证      参数挖掘六层（L1-L6）
  ↑                    │         "假设从哪里来？"
事实                    │              ↓
  ↑                    │        逻辑关系六层（L1-L6）
  └── 迭代 ←── 结果 ←──┘        "假设间什么关系？"
                                        ↓
                                假设管理五大策略
                                "假设怎么管？"
                                        ↓
                                统一管理三角
                                "假设怎么变组织OS？"
```

| Y模型的"黑盒" | C域的"白盒化" | 操作化程度 |
|:--------------|:-------------|:----------|
| "提出关键假设"——怎么提？ | 参数挖掘武器库：每个参数就是一个假设（"A参数提升会带动B目标提升"），参数越多假设空间越大 | 可逐格操作 |
| "假设间的关系"——哪些假设是关键路径？ | 逻辑关系六层：加法/乘法/因果/相关，乘法的必经节点=关键路径 | 可结构化判定 |
| "假设太多砍哪个"——优先级怎么定？ | 减法评估：ROI+确定性+风险三维排序 | 可量化打分 |
| "假设验证结果怎么沉淀"——组织怎么记住？ | 假设池+管理三角：事(假设迭代)×人(关键会议)×数(仪表盘) | 可机制化 |

---

## 二、关键映射：Y模型四层 → C域对应

### 2.1 理论端 + 事实端 → 参数冰山

Y模型左臂（理论）+右臂（事实）= **参数的初始认知**：

- 理论 → 框架性认知 → 对应 **L1 基础参数 + L2 财务参数**（初阶靠经验）
- 事实 → 数据与观察 → 对应 **L3 分层参数 + L4 转化参数**（进阶靠分析）
- 理论与事实交叉 → 涌现 → 对应 **L5 创新参数 + L6 魔法参数**（高阶靠创新）

Y模型的"列出对这件事的基础框架认知" = C域的"先用经验和直觉，找出几个大的数字"（L1）。

### 2.2 关键假设层 → 参数×逻辑关系

这是桥接的**核心齿轮**：

| Y模型关键假设 | C域等价表达 | 进阶路径 |
|:-------------|:-----------|:---------|
| "A会影响B" | L2 相关关系（体温计） | → L3 因果（方向盘）：验证A是不是真的导致B |
| "B = A1×A2 + A3" | L4 公式完备（X光片） | → L5 定量（刻度尺）：A1从40%→85%能带来多少？ |
| "这个参数是杠杆点" | L6 魔法参数（导航仪） | 动态建模：最佳参数组合是什么？ |

> **等价定理**：一个"好假设"= 一个可落到参数冰山 L3 以下 + 逻辑关系 L3 以上的命题。停在 L1-L2 的假设是"假假设"——只描述现象不指向动作。

### 2.3 验证层 → 假设驱动18招 + 减法评估

Y模型验证 = C域18招中的：
- 收集数据（埋点/录像/统计）
- 专家访谈（十步法）
- MVP实验（A/B测试三追求：控制变量/随机样本/样本量足够）
- 减法评估筛选"先验哪个"

### 2.4 迭代层 → 假设飞轮 + 认知积累

Y模型的"迭代"在C域变成了**有记忆的迭代**：

```
Y模型原始版：    假设 → 验证 → 结果 → 新假设（旧假设被丢弃）
C域增强版：      假设 → 验证 → 结果 → 参数认知升级 → 更好的新假设
                                    ↑
                              假设池沉淀（组织记忆）
```

关键差异：Y模型每轮从头开始，C域的假设池让每轮验证都**积累到参数认知里**。同一参数被验证3次后，不再需要重新假设——它从"假设"升级为"已知参数"。

## 三、Y模型作为Agent OS时的C域对接

`[[system-yitang-Y-model-os]]` 是所有域 Agent 的共享底座。C域对接意味着：

| Agent OS 层 | C域注入的能力 | Agent 行为变化 |
|:-----------|:-------------|:-------------|
| 关键假设层 | 参数挖掘武器库 schema | Agent 不再问"你有什么假设"，而是"这个业务的L1-L4参数是什么？从参数里找假设" |
| 验证层 | 减法评估三维度 | Agent 能排序假设优先级，建议"先验这个乘法参数" |
| 迭代层 | 假设池 + 管理三角 | Agent 能记住上一轮的参数认知，不重复提问 |
| 跨域融合 | 十大范式 | Agent 能识别"这是个流量变现型业务→标准拆法是流量×转化×客单价×复购" |

## 四、与关键假设ABCD总框架的定位

在 `[[framework-一堂-关键假设-ABCD模型]]` 中：

| A（五步法） | B（决策/Y模型） | C（业务公式） | D（转化率黑客） |
|:-----------|:---------------|:-------------|:---------------|
| 宏观成败 | 微观成败 | **宏观效率** | 微观效率 |
| 方向对不对 | 决策对不对 | **系统效率高不高** | 单点转化好不好 |

C域（业务公式）是ABCD中**直接对接Y模型"关键假设"层的域**——A给方向、B给判断框架、D给单点武器，**C给的是"把假设系统化"的完整方法**。Y模型说"要提关键假设"，C域说"假设=参数×逻辑关系，我教你从L1挖到L6"。

## 五、When NOT to Use

| 场景 | 为什么失效 | 替代 |
|:--|:--|:--|
| 业务方向还没定（还在探索做什么） | C域预设了"已有明确业务目标"——没目标拆不出公式 | 先用A域五步法定方向 |
| 只有一次性决策（非重复业务） | C域的重武器（假设池/管理三角/参数冰山）是为长周期重复业务设计的 | 用B域Y模型轻量版（画一个Y字就够了） |
| 团队连"什么是参数"都说不清楚 | C域的门槛是L1——至少能说出业务的"大数字" | 先读 `[[yt-business-formula-abc-model]]` |

## 七、Action Triggers

| 触发场景 | 第一个动作 | 成功指标 |
|:--|:--|:--|
| 用Y模型跑了几轮但假设质量没提升 | 把当前假设逐条过参数冰山：能落到L几？L1-L2的假设打回重写 | 假设池中≥50%的假设落到L3以上 |
| Agent问"你有什么假设"用户答不出来 | 切换问法："这个业务最关键的数字是什么？它由哪几个数字乘出来？" | 用户能说出≥3个L1级参数 |
| Y模型验证结果没有积累 | 建一个轻量假设池（表格：假设内容/参数层级/验证结果/认知升级） | 3轮后有≥2个参数从"假设"升级为"已知" |
