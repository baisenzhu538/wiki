# 压缩路径：从万字规范到40条铁规

## 原始表述

> 从一开始的那个提示词大概是在1000字，就是我给他立了个规范，一个规范从开始1000字最后迭代到30万字。后来我想这30万字的目的是干嘛呢？其实就是想办法去除他的幻觉。但是规范多了之后，你一下子塞进去它又麻烦了。后来我就把它提炼，比如说40条铁规，这个很容易记得住。（L958-971）

## 使用场景

- 用AI做复杂产品/系统时，需要给AI一套行为规范但规范多了AI记不住
- 知识库膨胀到检索效率下降，需要"减肥"
- 团队需要一套**人也能记住、AI也能执行**的共享规范
- KDO组件库从"穷举pitfalls"过渡到"提炼核心原则"时

## 操作方法

### 三步压缩法

```
穷举 → 合并 → 提炼

1000字初始规范
    ↓ 穷举
30万字（覆盖所有边界、异常、暗知识）
    ↓ 合并（去重、聚类、找共性）
~500条规则组
    ↓ 提炼（找最少不可约原则）
40条铁规（人记得住、AI执行得了）
```

### Step 1：穷举

**目标**：把规范写到"没有任何模糊地带"。

- 每一个操作步骤 → 一条规则
- 每一个失败模式 → 一条规则
- 每一个边界条件 → 一条规则
- **不停迭代，直到AI不再犯错**

半肥猫案例：1000字 → 30万字。\"就是想办法去除他的幻觉\"（L962）。

> **关键心法**：不要害怕规范膨胀。穷举阶段的目标不是简洁，是**消灭所有已知的AI出错路径**。膨胀是必经之路。

### Step 2：合并

**目标**：从30万字中找到真正的模式。

- 去重：相同的规则只留一条
- 聚类：同类型的规则归为一组
- 找共性：哪几条规则本质上在说同一件事？

这一步产出的不是最终规范，而是**规则骨架**——约500条规则组。

### Step 3：提炼

**目标**：找到**最少不可约原则**。

- 从500条规则组中，寻找"如果删掉这条，系统会崩"的那些——这就是铁规
- 铁规的数量上限：**人能轻松记住的数量**（约40条）
- 铁规的判断标准：不是"这条对AI有用"，而是"没有这条一定会出事"

> \"规范多了之后，你一下子塞进去它又麻烦了\"（L968）——这个洞察是关键。30万字规范本质上是**训练数据**，不是**操作手册**。AI通过穷举学到了模式，但运行时只需要铁规。

### 三步法与KDO建模方法论的同构对照

| 压缩路径 | KDO建模方法论 | 对应关系 |
|:--|:--|:--|
| 穷举（1000字→30万字） | pitfalls收集 + 全量素材消费 | 收集所有"什么会出错" |
| 合并（去重+聚类+找共性） | 组件识别 + 模式提取 | 从散落坑中找到共同根因 |
| 提炼（40条铁规） | 组件库标准化 + 核心原则 | 最少不可约原则 |

> 半肥猫的压缩路径 = KDO建模方法论在**AI行为约束**场景的独立验证。同一个方法论，KDO用在知识管理，老朱/半肥猫用在AI系统构建。

## 适用边界

| 适用 | 不适用 |
|:--|:--|
| 给AI的系统级规范（非单次提示词） | 一次性问答 |
| 需要**人和AI共享**的行为标准 | 纯人用的操作手册 |
| 规范数量膨胀到影响执行效率 | 规范本身就很简单（<10条） |
| 知识库/组件库需要"瘦身" | 还在探索阶段，规范本身不稳定 |

## 为什么值钱

1. **这是被真实项目验证过的方法**：15天完成原本5-6人半年的工作量（L954-956），不是理论推演。
2. **解决了"AI规范悖论"**——规范太少AI犯错，规范太多AI也犯错。压缩路径是走出悖论的唯一已知路径。
3. **与KDO方法论完全同构**——这意味着KDO的底层逻辑在不同场景下被独立验证，不是自说自话。
4. **人和AI都可以用**——\"40条铁规，这个很容易记得住\"（L970）。人记住铁规，AI执行铁规，这是人机协作的共享语言。

## Critique

### 内部局限

1. **"40条"是经验数字，非上限**：不同领域的"最少不可约原则"数量不同。40条适合软件系统规范，设计系统可能需要80条，法律合规可能需要200条。
2. **穷举阶段的时间成本被低估**：从1000字到30万字，背后是大量的人工编写和迭代测试。\"15天\"中AI加速的是执行，不是决策。
3. **铁规的维护成本未讨论**：40条铁规需要随系统演进持续更新——谁来维护？什么触发更新？

### 外部挑战

1. **Rich Sutton（《苦涩的教训》作者）**：\"利用计算能力的方法最终会击败试图手工编码知识的方法。\"铁规本质上是手工编码的知识——如果未来AI的长上下文能直接消费30万字规范而不降效，压缩路径的"提炼"步骤就失去了存在意义。
2. **Rodney Brooks（机器人学先驱）**：\"AI系统中最难的不是让它在80%情况下做对，而是找到那20%会出错的边界。\"铁规的本质是覆盖那20%——但铁规的质量取决于穷举阶段覆盖了多少边界。
