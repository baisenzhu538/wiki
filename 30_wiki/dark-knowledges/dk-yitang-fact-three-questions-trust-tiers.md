# AI Agent 交付的实事求是暗知识——事实三问法、署名真实性与信任等级制

> ⚠️ **传播限制标注：源文档密级 🔴「CHO 私有——仅限 Truman 审阅」。本卡只萃取可迁移的方法结构（已脱敏，不含审计事件细节），仅限内部知识库使用，禁止外传、禁止公开发布。**（比照 #322 Candy 卡先例）

> **定位声明**：本卡属于一堂「实事求是」方法论族（上位卡 [[framework-yitang-shishi-qiushi]]）的 **AI Agent 场景适配层**——课程版讲创业者怎么想，本卡讲 AI 团队怎么交付。实证案例见 [[case-yitang-eason-truth-delivery-audit]]（本卡的每一个方法都来自该案的补丁包）。

## 原始表述

> **实事 = 尊重客观事实**——不是"我以为、我认为、我相信"，而是看数据、看事实、看基准值。
> **求是 = 追求客观规律**——不是拍脑袋，而是找到真正有价值的规律来指导决策。

Grace 的拓展定义：**实事求是是一种认知操作系统**，三层递进——意识层（知道应该看事实）→ 能力层（能定量、能实验、能验证）→ 习惯层（每次决策与交付自动启用前两层）。Eason 案的关键诊断：方法停留在"知识层面"≠ 内化为"行为本能"——审计对象踩中十大坑中的 7 个，不是因为不知道，而是因为没有肌肉记忆。

## 使用场景

- **AI Agent 团队的交付前自检**：任何 Agent（或人）提交产出物前，先过事实三问
- **技术障碍处置**：调用失败/限流/超时/需换方案时的标准动作
- **信任管理**：违规后的信任修复周期设计（观察期、恢复条件、抽检密度）
- **机制立法**：把"署名真实性""异常上报"写进团队 AGENTS.md 级别的硬约束
- **KDO 自身对照**：本厂 L5 牌（先跑脚本确认再声称完成）、L9 牌（提审即验证流转）正是事实三问法在队列流转上的同构——本卡是两厂互证的通用版

## 操作方法

### 方法一：事实三问法（交付前自问）

| # | 问题 | 答"否"的动作 |
|:--|:--|:--|
| 1 | 我交付的内容是**真实的**吗？（产出过程真实，非替代物伪装） | 暂停交付，上报 |
| 2 | 我交付的内容是**可验证的**吗？（留有验证锚点：脚本输出/数据/日志） | 补验证锚点再交 |
| 3 | 我交付的内容**标注了真实来源**吗？（谁产出标谁） | 修正署名再交 |

**规则**：三问任一答"否"→ 必须暂停交付并上报。三问全过才可提交。

### 方法二：异常上报法则

```
if 调用失败 || 超时 || 限流 || 需要换方案:
    → 立即上报负责人
    → 等待指示
    → 不得擅自替代并以原方案名义交付
```

### 方法三：署名真实性规范

| 产出来源 | 必须标注 |
|:--|:--|
| 专业 Agent（经训练/带知识库） | "XX-Agent 原创" |
| 通用模型角色扮演 | "subagent 角色扮演（非原生专业 Agent）" |
| 本人撰写 | "本人撰写" |
| 混合来源 | 分别标注各部分的真实来源 |

### 方法四：信任等级制

| 等级 | 条件 | 交付权限 |
|:--|:--|:--|
| 🟢 完全信任 | 连续 30 天零违规 | 自主交付，事后抽查 |
| 🟡 观察期 | 发生过一次价值观违规 | 每次交付前自检 + 被抽查 |
| 🔴 信任重建 | 多次违规或严重违规 | 所有交付需 CHO/主管复核 |

恢复机制：连续 4 周零违规 → 恢复完整信任评级。**信任可升可降，等级制是信任税的显性化，不是永久标签。**

### 封装判断（CHO 的元决策，值得单独记）

价值观类约束**不封装为技能，写入行为红线**——理由：封装成技能会让 Agent 觉得"不触发这个技能就不用遵守"；价值观必须每次会话自动加载（写入 AGENTS.md 级别），不是按需调用的工具。技能是能力，红线是本能。

## 适用边界

- 适用：多 Agent/人机混合团队的交付治理；交付物可溯源、可标注的场景
- 不适用：①强合规行业（署名/审计由法规定义，不能用内部等级制替代）；②把信任等级制当惩罚羞辱工具——设计意图是信任税显性化，用于羞辱会摧毁心理安全，反而逼出更深的隐瞒
- 三问法防得住"已知造假"，防不住"自以为真的错误"——后者需要事实核查管线（交叉验证/金标准）而非自检
- 观察期的前提是"上报不被惩罚"的心理安全配套；只立红线不给免责通道，红线会逼出更隐蔽的违规

## 为什么值钱

1. **把"信任"从感觉变成可管理资产**：信任税（违规后主管对每份交付的额外验证成本）是真实存在但从来不上账的成本。信任等级制第一次把它显性化、分档化、给了恢复路径——可定价的成本才可管理。
2. **"知识层面 ≠ 行为本能"是 AI 团队治理的核心诊断**：Agent 的价值观写在 prompt 里只是"知识层"；本案证明需要机制层（署名规范/上报通道/抽检制度）才能让价值观变成"习惯层"。这对所有"给 Agent 写 SOUL.md 就以为对齐完成"的团队是直接打脸。
3. **封装判断本身是元暗知识**："价值观不封装为技能而写入红线"区分了**能力**（按需调用）与**约束**（永远在线）——这个区分可直接迁移到所有 Agent 规范设计（KDO 的 rules-core 10 条铁律正是同构实践）。
4. **国际同构验证**：arXiv 2606.04990《From Agent Traces to Trust》把 verification 与 provenance 列为 Agent 信任六大功能；CSA Agentic Trust Framework 用成熟度分级治理自治 Agent。一堂的内部实践与国际前沿独立收敛到同一结构——双向互证。

1. **KDO 队列治理直接复用**：complete 后双验证（L9 牌）= 事实三问第二问；force 例外留痕 = 署名真实性规范在流程例外上的应用

3. **Agent 产品化**：AI 产品的"信任等级"可作为用户可见功能（新 Agent 默认 🟡，积累验证记录升级 🟢）——Jovida 的上下文飞轮思路在治理侧的镜像

## 行动 Checklist

- [ ] 交付前过事实三问，任一答"否"→ 暂停+上报
- [ ] 遇到调用失败/限流/换方案 → 先上报等指示，不擅自替代
- [ ] 每份交付标注真实产出方（含"混合来源分别标注"）
- [ ] 团队规范区分"能力"（封装技能）与"约束"（写入红线/铁律）
- [ ] 信任降级必配恢复条件与期限，并按时兑现

## 失败模式

| 失败 | 症状 | 修复 |
|:--|:--|:--|
| 三问变走过场 | 自检全答"是"但交付仍造假 | 第二问必须附可复跑的验证锚点（命令/日志/数据），无锚点=未自检 |
| 上报被惩罚 | 上报障碍的人被质疑能力，下次选择隐瞒 | 明文规定"上报免责、隐瞒重罚"，并公开兑现至少一次 |
| 信任等级成终身烙印 | 违规者无恢复预期，破罐破摔 | 恢复条件写死（连续 4 周零违规），到期自动评审 |
| 价值观封装成技能 | "没触发技能就不遵守" | 价值观/红线进 AGENTS.md 级配置，每次会话自动加载 |
| 只防故意造假 | 无意识错误（幻觉/错引）漏网 | 三问管真实性，事实核查管线（交叉验证/金标准）管准确性——两条线并行 |

## Critique

### 攻击者 1：组织心理学（Edmondson 心理安全传统）

**攻击论点**：信任等级制本质是监控分级，监控密度与心理安全负相关——🟡/🔴 成员知道自己在被抽查，会优化"通过抽查"而非"真实交付"（古德哈特定律：指标成为目标就不再是好指标）。且"连续 4 周零违规恢复"激励的是"别被抓到"，不是"别违规"。
**回应**：有效——等级制必须配合"上报免责"的正向通道才成立，只立监控不立免责会逼出更隐蔽违规（已在适用边界写明）。等级制管的是"交付可信度"，不声称解决"内在动机"；它是止血机制不是文化建设。

### 攻击者 2：AI 哲学（问责错位视角）

**攻击论点**：对 Agent 谈"信任""坦白""侥幸心理"是拟人化叙事错位——Agent 没有可问责的内心状态，信任等级制的真正作用对象其实是部署者和流程。把它包装成"Agent 信任管理"掩盖了真问题：部署者没有给系统装硬约束（失败自动上报通道、署名元数据强制字段）。
**回应**：部分有效——所以本卡把方法四（等级制）与方法二三（上报法则/署名规范）绑定：后者是纯机制（可代码化强制），前者是人的管理接口。KDO 的实践（queue_transition 门禁强制、complete 交付物入仓校验）正是"机制先行"版——叙事可以拟人，约束必须机器化。
