# 踩坑：小胖猴拨号器——需求→方案跳跃。跳过L3直接到L6

## 原始表述

**坑**：销售需要打电话→做拨号器→用户不用。

**真相**：用户要的是"高效触达客户"，不是"拨号器"。跳到方案前没定义核心任务（L3）。

**修复**：任何时候想说出产品名，先问"用户真正要完成的任务是什么？"

## 使用场景

- **产品设计**：设计产品时，先定义核心任务（L3），再跳到方案（L6）
- **需求分析**：分析需求时，避免从需求直接跳到方案
- **用户访谈**：用户访谈时，先挖掘核心任务，再讨论方案
- **团队需求讨论**：统一团队语言，避免"需求→方案"跳跃
- **一堂五步法学习**：理解L3（核心任务）和L6（方案）的关系

## 操作方法

1. **核心任务定义**：
   - 任何时候想说出产品名，先问"用户真正要完成的任务是什么？"
   - L3 核心任务：用户真正要完成的事
   - 销售需要打电话→核心任务是"高效触达客户"
   - 不是"拨号器"，是"高效触达客户"
2. **需求→方案跳跃识别**：
   - 识别团队是否从需求直接跳到方案
   - 症状：销售需要打电话→做拨号器
   - 纠正：先定义核心任务，再设计方案
3. **L3→L6流程**：
   - L1 现象：用户表面行为
   - L2 需求：用户说的功能
   - L3 核心任务：用户真正要完成的事
   - L4 问题：问题的本质
   - L5 情感和社交任务：驱动决策的隐性需求
   - L6 方案：才进入解决方案空间
4. **团队沟通**：
   - 统一用"核心任务"语言讨论需求
   - 避免"需求→方案"跳跃
   - 先定义核心任务，再讨论方案

## 适用边界

| 场景 | 是否适用 | 说明 |
|:
|:---|:---|
| 产品设计 | ✅ 适用 | 先定义核心任务（L3），再跳到方案（L6） |
| 需求分析 | ✅ 适用 | 避免从需求直接跳到方案 |
| 用户访谈 | ✅ 适用 | 先挖掘核心任务，再讨论方案 |
| 团队需求讨论 | ✅ 适用 | 统一团队语言，避免"需求→方案"跳跃 |
| 一堂五步法学习 | ✅ 适用 | 理解L3（核心任务）和L6（方案）的关系 |
| 成熟产品优化 | ⚠️ 部分适用 | 已有产品，但仍需回顾核心任务 |
| 紧急修复 | ❌ 不适用 | 紧急修复需要快速进入方案 |

## 为什么值钱

1. **需求→方案跳跃识别**：最常见的需求分析错误，从需求直接跳到方案
2. **核心任务定义**：先定义核心任务，再设计方案，避免"拨号器"式错误
3. **L3→L6流程**：系统化的需求分析流程，避免跳跃
4. **团队共识**：统一团队语言，减少无效讨论
