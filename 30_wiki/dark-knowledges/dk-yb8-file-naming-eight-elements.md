## 原始表述

> AI降本增效的起点不是打开AI，而是整理文件体系，文件体系命名的八个要素：项目、渠道、用途、尺寸、版本、输出端、对接端和时间。

## 使用场景

企业一号位/管理者在推行AI工具前，或设计/营销团队需要与AI协作产出大量素材时。

## 操作方法

1. 停止直接使用AI生成内容
2. 先建立团队统一的文件命名规范
3. 命名必须包含八要素：项目（所属业务线）、渠道（投放平台）、用途（海报/详情页/封面等）、尺寸（1080x1920等）、版本（v1/v2/final）、输出端（手机/PC/小程序）、对接端（内部设计部/外部供应商/直接投放）、时间（20240115）
4. 将历史文件按此规范批量重命名归档
5. 再接入AI工具进行生成、调用、迭代

## 适用边界

| 边界 | 说明 |
|:
--|:-----|
| **不适用于个人临时一次性文件** | 个人临时文件不需要八要素框架。 |
| **不适用于已具备完善DAM系统的大企业** | 已有数字资产管理系统的团队按现有规范即可。 |
| **易混淆为"文件要命名规范"的常识** | 重点是八要素的完整框架（特别是输出端和对接端），而非简单的"要规范命名"。 |
| **适用于需要AI批量处理素材的团队** | 批处理/AI检索/AI调用的前提是可解析的文件命名。 |

| 失败模式 | 典型症状 | 修复方法 |
|---|---|---|
| AI先行，命名后补 | 先用AI生成了几百张图，回头看文件名叫"未标题-1""final-final-v3" | 先停工1周，统一重命名归档，再恢复AI使用 |
| 只命名不执行 | 制定了规范但没人遵守，新旧文件混在一起 | 把命名规范集成到工具链：保存模板/导出脚本自动生成符合规范的文件名 |
| 要素缺失 | 文件名只有项目+日期，缺少输出端和对接端信息 | 补齐八要素模板，特别是"输出端"和"对接端" |
| 规范过度 | 要求每个临时文件都八要素命名，团队抵触 | 区分正式产出（八要素）和临时草稿（简化命名） |

## 为什么值钱

公开AI教程几乎都在讲提示词工程和模型选择，但企业落地AI失败的核心原因往往是输入侧的数据/文件混乱——这个"先整理文件体系再开AI"的逆向逻辑，以及"八要素"的具体拆解（特别是"输出端"和"对接端"这两个跨部门协作维度），在现有AI训练语料中极为稀缺，属于一线管理者反复试错后的隐性经验。
