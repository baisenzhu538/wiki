> 本卡属于 [[framework-truman-feature-thinking-core]] 的暗知识——"无意识→有意识"转变的机制层（T 型→F 型思维分界的实证）。与 KDO 基建铁律"不登记 = 不存在"（工具登记四步法）同构：个人侧的"不命名 = 不复用"。

# 一堆散牌却不知道那是牌——无意识经验与Feature库的鸿沟

> 一句话：你早就攒了一堆 Feature（散经验），只是把它们当"某个工具的偶然经验"记着——所以每换一个工具就默认重踩一遍。Feature 思维的最大产出不是新 Feature，是让已有实践显性化、可归因、可复用（实测 L2891-L2901/L23）。

---

## 原始表述

王鹏飞（L2891-L2901）：

> "我其实早就在攒Feature，只是我把它们当成'踩过的坑'记着。比如做园所物料时，我的备忘录里躺着这么几条：生成PPT时字体必须写中文名「思源黑体CN」，写英文名一定失效；形状里的文字要顶对齐，否则中文会莫名居中错位；要留白就改space_before，不要敲空行；视频封面用思源黑体Heavy、白+金黄两行、居中47%，用圆体就不对。"

> "以前我认为这是'某个工具的偶然经验'，所以每换一个工具就默认要重踩一遍。听完这节课我才反应过来：这些就是L2/L3层实打实的Feature，是可以迁移到任何一次物料生成里的牌。我不是没有FeatureSet，我是有一堆散牌却没意识到那是牌，所以从来没有整理、没有编号、没有复用。"（L2901）

黄华春（L23/L313-L319）同构：

> "当时我做的时候，觉得'AI帮我写文章'这件事很简单……但今天用Feature思维重新拆解，我发现当时其实'无意识'地使用了好几个Feature，只是我自己不知道。"（L23）

> "这种'知道自己不知道什么'的感觉，其实是我最大的进步——因为只有知道了'缺什么'，你才能'补什么'。"（L313-L319）

## 使用场景

| 场景 | 典型症状 | 案例 |
|:---|:---|:---|
| 备忘录/收藏夹存技巧 | 每条都是"某工具的偶然经验"，从不迁移 | 王鹏飞四条散经验（实测 L2891-L2901） |
| 换工具/换平台 | 默认重踩一遍老坑 | 王鹏飞"每换一个工具就默认要重踩一遍"（实测 L2901） |
| 复盘时无词汇 | "感觉不太对"但说不清缺什么 | jeffgirl 迭代靠模糊感觉（L2327-L2339） |
| 做对但不知道为什么 | 成功经验无法复制 | 黄华春三篇文章无意识用 4 Feature（实测 L23） |

## 操作方法

1. **散经验重命名**：把每条备忘录/收藏夹条目改写成 Feature 句式——"做 X 时要 Y，否则 Z"（王鹏飞四条 → "字体 Feature""对齐 Feature""留白 Feature"）
2. **编号归层**：按 L0-L5 分层（字体/参数=L0-L1，提示词写法=L2，流程/物料生成=L3），建立个人 Feature 库索引
3. **标注使用记录**：每条 Feature 记"用过几次/效果如何"（王鹏飞 L2905 的验收标准：至少 3 个 Feature 真实用上+记下分数变化）
4. **复盘制度化**：每次实践后列"实际用了什么"（含无意识的）→ 对照周期表命名 → 补进 Feature 库（黄华春的组合模板+效果追踪表机制，L295-L309）
5. **迁移测试**：换工具时先查 Feature 库——哪些牌可以原样搬（"Feature跨工具稳定"，framework-truman-feature-thinking-core T-F 分界）

## 适用边界

| 场景 | 适用？ | 说明 |
|:---|:---|:---|
| 高频重复的 AI 实操 | ✅ 核心场景 | 散经验积累最快 |
| 低频一次性任务 | ⚠️ 边际价值低 | 不值得建库 |
| 纯创意探索（无输出标准） | ⚠️ 部分适用 | Feature 命名可能过度结构化 |
| 已有成熟工具链的组织 | ⚠️ 需要库治理 | 散牌库建了不维护=新收藏夹 |

> ⚠️ 边界警示（反例）：王鹏飞自己点破——"不要收藏Feature，要消化Feature"（L2905）。散牌识别+建库的终点不是"库很漂亮"，是"3个Feature真实用上并记下分数变化"。库变收藏夹 = 从散牌退化成"装饰性牌库"（与 `[[dk-feature-not-learned-but-used]]"把武器库当技巧合集"同构）。

## 为什么值钱

1. **无意识是常态，不是例外**：黄华春（3 篇文章 4 个 Feature 全无意识）、王鹏飞（早就在攒 Feature 但当成坑）、jeffgirl（用对但没意识到）——三个独立案例都证明"用对了但不知道"是普遍起点
2. **识别即复利**：散经验从"换工具就归零"变成"跨工具稳定资产"——Feature 库是个人 AI 能力复利的记账本
3. **命名是控制的前提**："知道自己不知道什么"（L313-L319）才能补缺；"知道自己有什么"才能组合——两者都是显性化的产物
4. **组织级价值**：王鹏飞"平等对话"洞察（L2903）——Feature 坐标让"太生硬/不像我们"的形容词讨论变成可教学的语言，一个人会做 → 一群人会做

## Critique

**内部局限**：两条主证据（王鹏飞/黄华春）均来自"优秀作业"的自我反思——能写出"散牌"反思的人已经完成了显性化，样本偏向"反思成功者"；大量"无意识使用但从未反思"的人不在样本里，本 dk 的普适性证据不足。

**外部攻击者 1（Kahneman 式——事后命名偏差）**："这些就是 L2/L3 层 Feature"是课后用 Feature 思维回映射的命名——同样的散经验在命名前和命名后并没有本质变化，变化的只是描述方式。把"命名"当作"能力提升"本身可能是一种叙事幻觉：真正提升来自"记下分数变化"的验证（王鹏飞 L2905），而非命名本身。

**外部攻击者 2（Taleb 式——过度系统化风险）**：散牌 Feature 库可能诱发"整理癖"——把大量时间花在分类、编号、美化库结构上，而实际使用频率没有变化（王鹏飞自嘲的"收藏癖"）。Feature 库的 ROI 取决于"被调用的次数"，一个精美但从不打开的库比散牌更糟（多了一层维护成本）。

## 常见失败模式

| 失败模式 | 症状 | 修复 |
|:---|:---|:---|
| 库变收藏夹 | Feature 库建得很漂亮，从不调用 | 每条 Feature 必须标"用过几次/分数变化"；每季度清理 0 使用条目 |
| 只命名不验证 | 散牌改了名但还是老用法 | 命名后强制 1 次真实使用+记录效果 |
| 换工具不查库 | 老坑重踩（字体/对齐/留白） | 换工具前先过一遍 Feature 库的迁移检查 |
| 无意识使用不复盘 | 做对不知道为什么 | 每次实践后列"实际用了什么"再对照周期表 |
