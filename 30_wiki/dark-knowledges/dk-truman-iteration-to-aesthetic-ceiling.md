# 迭代到审美上限：一张图的隐形成本远超显示器——Truman的泛产品设计第一性原则

## 原始表述

> Truman在泛产品设计课上分享了一个真实的产品迭代案例：为了让一张导航图更好看，他透过一张一张的比对，花了整整半个多小时。最终产品经理一句话点破：**"显示器很便宜，你不用救它。"** 这是一个关于**产品第一性原则**的关键暗知识——迭代的终点不是"足够好"，而是"审美上限"。

## 使用场景

- **核心交付物打磨**：用户每天高频使用的产品元素（如导航图、仪表盘、关键界面）
- **品牌触点优化**：每一个用户接触点都是品牌印象的累积，不能"差不多"
- **竞品差异化**：功能趋同时，审美体验成为关键差异化因素
- **长期产品迭代**：核心产品的持续打磨，而非一次性项目
- **高价值内容生产**：课程、报告、演示等需要反复打磨的内容产品

## 操作方法

1. **识别核心交付物**：列出产品中用户每天接触的元素，标出"高频+高价值"的组合
2. **设定审美标准**：为每个核心交付物定义"审美上限"的标准——不是"能用"，而是"看了舒服"
3. **迭代到无以复加**：一张图比对几十张、一个动画调几十版，直到"没有更好的版本"
4. **区分"救"和"迭代"**：产品经理说"不用救它"=功能已完备；Truman的迭代=审美未到上限
5. **记录审美决策**：把每次审美选择的原因记录下来，形成团队的审美共识

## 适用边界

| 边界 | 说明 |
|:
--|:-----|
| ✅ 适合 | 用户高频接触的核心产品元素 |
| ✅ 适合 | 品牌差异化关键触点 |
| ✅ 适合 | 长期产品的持续打磨 |
| ❌ 不适合 | MVP验证阶段——速度优先，功能完备即可 |
| ❌ 不适合 | 内部工具、后台系统——用户不直接接触 |
| ⚠️ 注意 | "审美上限"不等于"完美主义"，需区分核心与非核心元素 |

## 为什么值钱

1. **隐形成本复利**：核心交付物的审美质量在每次使用中复利，用户注意力很贵
2. **品牌认知累积**：每一个"差不多"的触点都在消耗品牌信任，每一个"极致"的触点都在积累
3. **竞品壁垒**：功能容易被复制，审美体验是长期积累的差异化壁垒
4. **团队标准**："迭代到审美上限"的团队标准会渗透到所有产出中
