# 市场规模估算的5个陷阱：从"拍脑袋"到"结构化验证"

> 一堂五步法：市场规模估算不是"拍数字"，而是有方法、有逻辑、有交叉验证的结构化过程。

## 核心框架

| 陷阱 | 表现 | 危险等级 | 修复方法 |
|:---|:---|:---:|:---|
| **1%陷阱** | "市场100亿，拿1%就够了" | 🔴 高 | 论证为什么能拿到1%，而不是0.01% |
| **报告迷信** | 直接引用第三方报告，未验证 | 🔴 高 | 检查报告日期、样本、方法论 |
| **TAM幻觉** | 把总市场当可触达市场 | 🔴 高 | 强制拆TAM/SAM/SOM三层 |
| **单一方法** | 只用一种估算方法 | 🟡 中 | 至少两种方法交叉验证 |
| **静态假设** | 假设市场不变，忽视增长和竞争 | 🟡 中 | 考虑增长率、新进入者、技术替代 |

## 关键洞察

### 1. 1%陷阱的本质

"市场100亿，我们拿1%就是1亿"——这是最危险的逻辑。

为什么不是0.01%？为什么不是10%？1%的假设依据是什么？

| 问题 | 验证方法 |
|:---|:---|
| 你能触达多少用户？ | 获客渠道、转化率、CAC |
| 你能转化多少？ | 产品匹配度、定价、竞争 |
| 你能留住多少？ | 留存率、LTV、竞品替代 |
| 你能 defend 多少？ | 壁垒、网络效应、切换成本 |

### 3. TAM/SAM/SOM的正确用法

不是只给一个数字，而是三层拆解：

| 层级 | 定义 | 用途 | 常见错误 |
|:---|:---|:---|:---|
| TAM | 总潜在市场 | 看长期天花板 | 把TAM当目标 |
| SAM | 可服务市场 | 考虑渠道、能力限制 | 忽视渠道限制 |
| SOM | 可获得市场 | 短期内实际能拿到 | 过于乐观 |

### 4. 交叉验证的实践

至少两种方法：

| 方法组合 | 验证逻辑 | 差异处理 |
|:---|:---|:---|
| 自上而下+自下而上 | 宏观 vs 微观 | 差异<3倍取保守值 |
| 自下而上+竞品对标 | 用户估算 vs 市场验证 | 差异3-10倍检查假设 |
| 替代方案+自上而下 | 成本推导 vs 市场报告 | 差异>10倍重新评估 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **拍脑袋估算** | "大概100亿吧" | 展示计算过程，每个数字有依据 |
| **报告复制粘贴** | 直接引用，未验证 | 检查报告日期、样本、方法论 |
| **忽视敏感性** | 只给一个数字，不做区间 | 做最好/最差/最可能三种情景 |
| **假设过于乐观** | 所有假设都取上限 | 用历史数据验证假设合理性 |
| **忽视时间维度** | 假设市场静态 | 考虑增长率、竞争、技术替代 |
| **TAM当融资依据** | 用TAM说服投资人 | 用SOM证明短期可行性，TAM证明长期空间 |
