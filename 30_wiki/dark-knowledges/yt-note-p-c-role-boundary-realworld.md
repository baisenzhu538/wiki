# P/C 角色真实场景边界与切换条件（基于聊天记录案例）

## 原始表述

这张暗知识卡基于同一位用户（创业者、管理者、执行者三位一体）在同一天内与**两个不同角色的 AI Agent**的真实聊天记录，提炼出 P 角色与 C 角色在实际使用中的**边界划分规则**和**切换信号**。

**C 角色对话**：54 条消息，走完"明确长期追求 → 四要素诊断 → 输出行动报告"的完整流程。用户从"我是 L2，想到 L6"出发，经历了被追问、被挑战、被要求自我评分的过程，最终获得了 6000+ 字的《清单体笔记 · 10 倍速练习行动报告》。C 角色的价值在于**发现用户自己都没意识到的盲区**（如"知道好标准但滑回惯性"的隐蔽失败模式）。

**P 角色对话**：2 条消息，用户发送 400+ 字的非结构化复盘感想，AI 直接返回 6 大模块的清单体笔记。P 角色的价值在于**降低表达摩擦**，让用户脑中已经清晰的内容立即落地为可传播格式。

**核心切换信号：输入的"完成度"**。当用户的输入是**"成品"**（已完成思考、已有结论、只需结构化）时，用 P 角色；当用户的输入是**"素材"**（有感受但无结论、有问题但无方案、有意愿但无路径）时，用 C 角色。这个判断标准可以用一个简单的问题检验：**"如果现在把这份输入直接结构化，用户会满意吗？"** 如果答案是"会"，用 P；如果答案是"不会，他还需要被问几个问题"，用 C。

## 使用场景

- **个人效率提升**：已有清晰思考，需要快速结构化输出（P 角色）
- **深度诊断与复盘**：有感受但无结论，需要被追问和挑战（C 角色）
- **团队协作**：多人使用 AI 时，角色选择影响权力动态和信任结构
- **产品设计中 AI 角色默认设置**：避免把 C 角色当成默认设置导致的时间窃盗
- **组织决策**：高管用 P 角色整理思考后转发团队，需警惕"切清楔"风险

## 操作方法

1. **判断输入完成度**：
   - 成品信号：结论明确、案例具体、逻辑自洽
   - 素材信号：感受词多、行动词少、问题多于方案
2. **选择角色**：
   - 成品 → P 角色：直接结构化，降低表达摩擦
   - 素材 → C 角色：深度诊断，发现盲区
3. **误用代价自查**：
   - 该用 C 时用 P → 用户获得结构完整但思考不成熟的产物
   - 该用 P 时用 C → 已完成思考的用户被无意义追问，时间窃盗
4. **组织使用规范**：
   - 明确标注 AI 产出是"结构化思考"还是"诊断建议"
   - 避免把 P 角色产出当作最终决策转发

## 适用边界

| 边界 | 说明 |
|:-----|:-----|
| ✅ 适合 | 个人使用 AI 进行内容生产或深度诊断 |
| ✅ 适合 | 已有明确输入完成度判断能力的用户 |
| ✅ 适合 | 需要区分"思考过程"和"思考结果"的场景 |
| ❌ 不适合 | 用户无法判断自己输入完成度的场景——需自动检测 |
| ❌ 不适合 | 高 stakes 组织决策——需人工复核 AI 产出 |
| ⚠️ 注意 | P/C 角色选择是权力延伸，在团队中需谨慎使用 |

## 为什么值钱

1. **避免时间窃盗**：大多数 AI 产品把 C 角色当默认设置，对已完成思考的用户是浪费
2. **发现盲区**：C 角色的"不舒适"设计能强迫用户面对不愿面对的真相
3. **降低表达摩擦**：P 角色让已清晰的内容立即落地为可传播格式
4. **组织风险预警**："切清楔"和"想清楔"的区别在组织层面可能导致重大决策失误
