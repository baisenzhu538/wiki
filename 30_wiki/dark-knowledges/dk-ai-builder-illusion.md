# Builder 幻觉：用 AI 做出东西 ≠ 完成从 0 到 1

> **一句话**：AI 让「把产品做出来」变得极其便宜，但「做出来」从来不是商业成功的瓶颈。Builder 幻觉就是把「能跑通的原型」误当成「完成了从 0 到 1」，忽略了市场验证、用户洞察和品味判断。

---

## 原始表述

> 「每个人都是 builder 是个很糟糕的主意。你能够把一个产品做出来，不代表你能做出一个很好的产品出来。」[确认] —— Andrew Ambrosino，OpenAI Codex 产品负责人

> 「你以为你完成了产品的从 0 到 1 吗？产品做出来能够上线，根本不是从 0 到 1。你能不能找到前面 1000 个用户，愿意为他付钱，愿意为他付出成本，这个才叫产品的从 0 到 1。」[确认] —— 口述稿 L407-L414

> 「AI 写的代码就是 fast fashion software。如果你真的要建一家公司，软件不能是一次性的。」[确认] —— Tony Fadell

---

## 使用场景

- 用 AI 快速做出原型后，团队开始庆祝「上线」。
- 个人创业者觉得自己「一个人就是一个团队」。
- 产品方向还没想清楚，就开始 vibe coding。
- 投资人或老板被原型误导，以为产品已经验证。

---

## 操作方法

### Step 1：在动手前强制回答 5 个问题

| # | 问题 | 为什么重要 |
|---:|---|---|
| 1 | 用户是谁？ | 没有用户，产品只是玩具 |
| 2 | 解决什么痛点？ | 没有痛点，没有购买理由 |
| 3 | 凭什么买你而不是竞品？ | 没有差异化，就是 fast fashion software |
| 4 | 怎么找到前 1000 个付费用户？ | 这是从 0 到 1 的真正标志 |
| 5 | 这次尝试能沉淀什么资产？ | 没有复利，做出来就是消耗品 |

### Step 2：把「上线」重新定义为「验证」

- 原定义：代码能跑 / 页面上线 / workflow 通
- 新定义：找到愿意按原价付费的种子用户 / 拿到真实市场反馈 / 验证购买理由

### Step 3：用 AI 做原型，但用人做判断

- AI 负责：快速生成多个方案、写代码、做设计、跑测试
- 人负责：选方向、定标准、判断哪个方案更值得继续

### Step 4：设定「停止做原型」的触发器

当以下任一情况出现时，停止做原型，开始验证市场：
- 已经做了 3 个以上原型但没有任何真实用户反馈
- 团队开始讨论「这个功能很酷」而不是「用户需要这个」
- 连续一周没有和真实用户聊过

### Step 5：把每次尝试资产化

即使失败，也要沉淀：
- 用户访谈记录
- 被否定的方案及原因
- 可复用的代码/设计组件
- 更新的 AGENTS.md 或技能文档

---

## 现象

Builder 幻觉有以下典型表现：

1. **把原型当产品**：AI 生成的代码/页面/workflow 能跑起来，就认为产品完成了。
2. **把功能当价值**：「我能做 A、B、C、D」等同于「用户需要 A、B、C、D」。
3. **把成就感当验证**：自己用 AI 做出东西时成就感爆棚，误以为市场也会买单。
4. **跳过问题定义**：没有想清楚「用户是谁、解决什么问题、凭什么买我」，直接动手。
5. **忽视复利**：做出来的东西没有沉淀为可复用的知识、流程或品牌资产。

---

## 根因

| 根因 | 说明 |
|:---|:---|
| **实现成本骤降** | AI 让写代码、做设计、生成内容变得极便宜，降低了「做出来」的门槛。 |
| **成就感反馈即时** | 原型几分钟就能跑起来，给人强烈的即时满足感。 |
| **混淆必要与充分** | 「做出来」是产品上市的必要条件，但不是充分条件。 |
| **跳过品味判断** | 没有回答「该不该做、做成什么样、用户为什么选我」。 |
| **Fast Fashion Software 心态** | 像快时尚一样快速生产、快速丢弃，没有壁垒和复利。 |

---

## 反向信号：你还没有完成从 0 到 1

至少包含以下 3 个真实失败信号：

| 信号 | 具体表现 | 诊断 |
|---:|---|---|
| **1. 没有付费用户** | 产品上线后，没有一个人愿意按原价付费 | 从 0 到 1 的标志是找到第一批愿意付钱的种子用户，不是上线 |
| **2. 回答不清「凭什么买你」** |  Asked「用户为什么选你而不是竞品」，只能说「我功能更多/更便宜」 | 没有独特的购买理由，只是另一个 fast fashion software |
| **3. 没有可复利的资产** | 每次新任务都从零开始，没有沉淀知识、流程、品牌或用户关系 | 做出来的东西是消耗品，不是资产 |

> 口述稿强调：「销售和营销本身就是内置在产品的设计里面的，你的产品做出来就已经注定了谁会买它、能卖多少钱。」[确认]

## Action Triggers

| 触发场景 | 第一个动作 |
|:---|:---|
| AI 生成第一个可运行原型时 | 停下来问：这是正确的方向吗？用户会为此付费吗？ |
| 团队开始讨论「上线」时 | 把定义从「上线」改成「找到 1000 个付费用户」 |
| 有人说「我一个人就是一个团队」时 | 反问：你一个人能完成市场验证吗？ |
| 准备开始 vibe coding 时 | 先写一页纸的问题定义：用户、痛点、购买理由、竞品差异 |
| 原型迭代很多轮但没有外部反馈时 | 停止迭代，找 5-10 个真实用户聊 |

## Fast Fashion Software：速生速朽的软件

Tony Fadell 提出「AI 写的代码就是 fast fashion software」[确认]。这不是说 AI 代码质量差，而是说：

- 它能被快速生产出来
- 也能被竞争对手快速复制
- 如果没有壁垒（品牌、网络效应、atoms、独特的用户洞察），就会快速消失

> 口述稿：「ChatGPT 第一年冒出来的一夜爆红的工具，今天还剩下多少？大部分都已经消失了。商业模式还没跑通。」[确认]

### 如何避免 Fast Fashion Software

1. **建壁垒**：atoms（实体）、品牌、网络效应、独特的用户关系。
2. **沉淀资产**：把每次尝试转化为 token capital、知识库、可复用流程。
3. **持续迭代**：第一代做产品，第二代修产品，第三代修商业模式。
4. **人在环**：不要让 AI 替你思考，让 AI 替你执行。

---

## 适用边界

- **适用于**：用 AI 做产品/内容/工具的个人和团队，特别是已经做出原型但还没有验证市场的阶段。
- **不适用于**：纯学习性、探索性的原型制作（此时「做出来」本身就是目标）。

---

## 为什么值钱

Builder 幻觉是 AI 时代最常见、最隐蔽的认知陷阱。它值钱在：
- 它直接针对 AI 降低实现门槛后的新风险。
- 它把「从 0 到 1」重新定义为「市场验证」而非「产品上线」。
- 它连接了品味系统、token capital、AI 原生组织等多个关键概念。
