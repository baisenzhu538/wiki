---# "做而不信"陷阱：执行了流程，但不相信结果

> 一堂五步法：最大的危险不是不做验证，而是做了验证但不相信结果。

## 核心框架

"做而不信"：表面上执行了验证流程，但内心不相信验证结果，继续按原有假设行动。

| 表现 | 说明 | 危险等级 |
|:---|:---|:---:|
| **访谈了但不相信** | 用户访谈显示需求不够，但认为"访谈对象不对" | 🔴 高 |
| **验证了但不调整** | 验证不支持假设，但继续投入 | 🔴 高 |
| **有数据但不决策** | 数据清晰，但决策凭直觉 | 🔴 高 |
| **流程走了但无改变** | 按流程做了，但结果不好不反思 | 🟡 中 |
| **学习了但不应用** | 学了方法论，但实际操作照旧 | 🟡 中 |

## 关键洞察

### 1. "做而不信"的根源

| 根源 | 表现 | 修复 |
|:---|:---|:---|
| **认知失调** | 验证结果和预设冲突，心理不适 | 承认预设可能错误，接受新信息 |
| **沉没成本** | 已投入太多，不愿承认错误 | 沉没成本不是决策依据，未来收益才是 |
| **自我认同** | 产品方向和自我认同绑定 | 区分"我"和"我的假设" |
| **团队压力** | 承认错误影响团队士气 | 建立"快速失败、快速调整"的文化 |
| **外部期望** | 投资人、客户期望方向不变 | 透明沟通，调整期望 |

### 3. 从"做而不信"到"做且信"

| 步骤 | 行动 |
|:---|:---|
| **承认不确定性** | 预设可能错误，验证是为了发现真相 |
| **设定验证标准** | 验证前设定"如果X，则调整Y" |
| **尊重数据** | 数据不支持时，按预设标准调整 |
| **快速调整** | 发现错误后，快速调整方向 |
| **记录教训** | 记录验证失败的原因，避免重复 |

### 4. 团队层面的"做而不信"

| 层级 | 表现 | 修复 |
|:---|:---|:---|
| **创始人** | 创始人不相信数据，团队被迫执行 | 创始人必须带头尊重数据 |
| **团队** | 团队不相信方法，执行敷衍 | 培训+小胜利建立信任 |
| **文化** | 组织文化不鼓励失败 | 建立"快速失败、快速学习"的文化 |

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **访谈对象不对** | 访谈结果不支持，说"访谈对象不对" | 承认需求可能不够，扩大访谈范围 |
| **验证方法不对** | 验证不支持，说"验证方法有问题" | 尝试多种方法交叉验证 |
| **时机不对** | 验证不支持，说"时机不对" | 区分"时机不对"和"需求不够" |
| **数据量不够** | 验证不支持，说"样本太小" | 扩大样本，如果仍不支持，调整方向 |
| **特殊情况** | 验证不支持，说"这是特殊情况" | 区分"特殊情况"和"普遍情况" |
| **未来会变好** | 验证不支持，说"未来会变好" | 用数据证明"未来会变好"的依据 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 个人决策偏差 | 技术问题 |

| 验证结果应用 | 创意发散 |
| 数据驱动文化 | 品牌传播 |
