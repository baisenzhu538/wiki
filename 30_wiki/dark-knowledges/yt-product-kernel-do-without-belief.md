# "做而不信"陷阱：执行了流程，但不相信结果

## 原始表述

一堂五步法：最大的危险不是不做验证，而是做了验证但不相信结果。

"做而不信"：表面上执行了验证流程，但内心不相信验证结果，继续按原有假设行动。

| 表现 | 说明 | 危险等级 |
|:
|:---|:---:|
| **访谈了但不相信** | 用户访谈显示需求不够，但认为"访谈对象不对" | 🔴 高 |
| **验证了但不调整** | 验证不支持假设，但继续投入 | 🔴 高 |
| **有数据但不决策** | 数据清晰，但决策凭直觉 | 🔴 高 |
| **流程走了但无改变** | 按流程做了，但结果不好不反思 | 🟡 中 |
| **学习了但不应用** | 学了方法论，但实际操作照旧 | 🟡 中 |

## 使用场景

- **个人决策偏差**：个人决策时，识别"做而不信"偏差
- **团队认知对齐**：团队讨论时，统一对验证结果的认知
- **验证结果应用**：验证后，应用验证结果调整方向
- **数据驱动文化**：建立数据驱动文化，避免"做而不信"
- **一堂五步法学习**：理解"做而不信"是五步法最大的危险

## 操作方法

1. **"做而不信"识别**：
   - 问自己：如果数据不支持直觉，你选哪个？
   - 如果答案偏向"直觉"，可能在"做而不信"
   - 识别症状：访谈了但不相信、验证了但不调整、有数据但不决策
2. **"做而不信"根源分析**：
   - 认知失调：验证结果和预设冲突，心理不适
   - 沉没成本：已投入太多，不愿承认错误
   - 自我认同：产品方向和自我认同绑定
   - 团队压力：承认错误影响团队士气
   - 外部期望：投资人、客户期望方向不变
3. **从"做而不信"到"做且信"**：
   - 承认不确定性：预设可能错误，验证是为了发现真相
   - 设定验证标准：验证前设定"如果X，则调整Y"
   - 尊重数据：数据不支持时，按预设标准调整
   - 快速调整：发现错误后，快速调整方向
   - 记录教训：记录验证失败的原因，避免重复
4. **团队层面修复**：
   - 创始人：创始人必须带头尊重数据
   - 团队：培训+小胜利建立信任
   - 文化：建立"快速失败、快速学习"的文化

## 经典案例：Truman 与小鹅通——"做，但默认不信"

### 背景

一堂早期做直播课时，面临一个选择：在微信群里一句句说，还是用「小鹅通」独立直播间？

### Truman 的执行姿势

> **Truman 原话**："小鹅通独立直播间在最早的时候是一堂的内核吗？……我拿不准，我真拿不准。所以最早的时候测试时间有限，为了减少试错，我没办法一周一周地浪费时间，然后我就用小鹅通了。但是在我心里，小鹅通我默认它不是产品内核，我默认它就是个关键假设，它默认是不错的——就我做，但我不认为它重要，未来如果需要的话，我就把它撤回来。"（来源：`一堂-产品内核实操课-Truman-口述.txt` L2782-L2796）

### 解构"做而不信"的正确姿势

Truman 的小鹅通决策，体现了"做而不信"的三个核心默认：

| 默认 | 含义 | 对应的行为 |
|:---|:---|:---|
| **默认不是内核** | 不做价值判断，不把"用了"等同于"它重要" | 使用但不依赖，随时可以放弃 |
| **默认是关键假设** | 承认不确定性，它只是待验证的猜测 | 没有因为投入了就情感绑定 |
| **默认是可以撤的** | 保持"撤回选项"的开放性 | 心里始终有撤回预案，不对撤不下来的路径形成依赖 |

### 为什么这个姿势重要？

- **防止过早堵死**：越是早期、越是开放选项、越是创新内核时，越应该保持"做而不信"的怀疑态度——不要过早把某个选项固化为内核
- **减少沉没成本绑定**："做都做了"的心理会让人不愿意撤，但 Truman 的姿势是"做了也可以随时撤"
- **保留迭代空间**：小鹅通在 Truman 心里从来不是内核，所以当压力大时，"要不然就撤回去就行"——这个选项从未被关闭

### 与常见走偏的对比

| 常见走偏 | Truman 的做法 |
|:---|:---|
| "用了小鹅通 → 它就是内核了" | "用了小鹅通 → 我默认它不是" |
| "投入了时间 → 不能放弃" | "测试时间有限 → 为了减少试错才用，随时可撤" |
| "做了就证明它是重要的" | "做，但我不认为它重要" |
| 越投入越坚信 | 始终保留撤回选项 |

1. **最大危险识别**：最大的危险不是不做验证，而是做了验证但不相信结果
2. **认知偏差识别**：系统化的"做而不信"识别框架
3. **团队修复**：从创始人到团队到文化的系统化修复方法
4. **数据驱动文化**：建立"快速失败、快速学习"的数据驱动文化

## 失败模式 / 常见走偏

| 失败模式 | 症状 | 纠正 |
|:---|:---|:---|
| 访谈对象不对 | 访谈结果不支持，说"访谈对象不对" | 承认需求可能不够，扩大访谈范围 |
| 验证方法不对 | 验证不支持，说"验证方法有问题" | 尝试多种方法交叉验证 |
| 时机不对 | 验证不支持，说"时机不对" | 区分"时机不对"和"需求不够" |
| 数据量不够 | 验证不支持，说"样本太小" | 扩大样本，如果仍不支持，调整方向 |
| 特殊情况 | 验证不支持，说"这是特殊情况" | 区分"特殊情况"和"普遍情况" |
| 未来会变好 | 验证不支持，说"未来会变好" | 用数据证明"未来会变好"的依据 |
