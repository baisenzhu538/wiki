# 暗知："愿望思维"是创业最大的陷阱

## 原始表述

"愿望思维"是创业者的默认设置：把"希望"当成"事实"，把"我能做到"当成"用户需要"，把"未来可能"当成"现在就要全力以赴"。它让创业者不是死于能力不够，而是死于方向错了还特别自信。

> 先用创业者有一个非常典型的心态，就是美好愿望驱动……第一个美好愿望，我对于我能做成有一个非常美好的设想。第二个，他默认我一定能做成……因为我能成，所以才会把资源都砸进去。
>
> ——Truman，一堂《关键假设课》口述

一堂用 X 型创业者、Y 型创业者和无人餐厅等案例反复证明：**创业者的最大陷阱不是能力不足，而是把"愿景"直接等同于"已验证的假设"**。具体表现为三种混淆：把情感上的必然当成逻辑上的必然、把功能上的可行当成商业上的必然、把执行力当成验证。

## 使用场景

- **商业模式从 0 到 1 探索**：需要区分愿景与关键假设，避免把愿景当作战术
- **产品内核验证**：判断"去掉这个要素用户是否还选"，验证核心价值主张
- **团队复盘**：发现方向性偏差而非执行性偏差，识别愿望思维信号
- **投资/创业决策前**：用低成本实验替代大规模押注，设定验证成本上限
- **创业教育/培训**：用一堂案例教学，帮助创业者识别自己的愿望思维

## 操作方法

1. **三种混淆识别**：
   - 把情感上的必然当成逻辑上的必然："我需要，所以市场一定需要"
   - 把功能上的可行当成商业上的必然："我们能做出来，所以用户会买单"
   - 把执行力当成验证："只要投入够大、执行够快，就能跑出来"
2. **纠偏四问法**：
   - 这是我们自己的愿望，还是已被 5 个以上真实用户验证过的付费原因？
   - 如果去掉这个技术亮点，用户还会选择我们吗？他们愿意多付多少钱？
   - 在为这个假设全力以赴之前，我们愿意承受的最大验证成本是多少？
   - 有没有更小的实验可以证伪它？
3. **愿景拆解为假设**：
   - 把愿景拆解为可证伪的关键假设
   - 每个假设匹配一个最小验证实验
   - 设定"愿意为验证这个假设付出的最大成本"
4. **产品内核验证**：
   - 每次讨论"能做什么"时，同时问"用户为什么需要、愿意多付多少钱"
   - 把技术方案与商业价值分开讨论

## 适用边界

| 适用场景 | 不适用/慎用场景 |
|:---|:---|
| 商业模式从 0 到 1 探索，需要区分愿景与关键假设 | 艺术创作、品牌创意等依赖直觉与灵感的领域，过度验证会扼杀创造力 |
| 产品内核验证：判断"去掉这个要素用户是否还选" | 已通过市场验证的战略执行阶段，不宜再反复质疑基本盘 |
| 团队复盘：发现方向性偏差而非执行性偏差 | 团队只有一人"默认失败"，其他人全部"愿景驱动"时，这个人容易被边缘化 |
| 投资/创业决策前，用低成本实验替代大规模押注 | 高压窗口期需要快速决断，但仍应保留最小验证动作 |

## 为什么值钱

1. **防止方向性错误**：创业者不是死于能力不够，而是死于方向错了还特别自信
2. **低成本验证**：用最小实验替代大规模押注，降低创业试错成本
3. **产品内核识别**：区分"功能亮点"和"用户真正愿意付费的原因"
4. **团队决策质量**：避免团队被愿景驱动，忽视真实用户验证

## 失败模式 / 常见走偏

| 失败模式 | 典型错觉 | 纠偏动作 |
|:---|:---|:---|
| 把"情感上的必然"当成"逻辑上的必然" | "这个需求很明显，因为我也需要" | 不要问"有没有人需要"，要问"目标用户愿意为之付费的原因是什么，这个原因是否足够强" |
| 把"功能上的可行"当成"商业上的必然" | "我们能做出来，用户就会买单" | 每次讨论"能做什么"时，同时问"用户为什么需要、愿意多付少钱"，把技术方案与商业价值分开讨论 |
| 把"执行力"当成"验证" | "只要贷款够多、执行够快，就能跑出来" | 大规模投入前设定"愿意为验证这个假设付出的最大成本"，需要全力以赴才能验证的事还不值得做 |
| 把愿景直接当作战术 | "我的愿景一定会实现" | 把愿景拆解为可证伪的关键假设，每个假设匹配一个最小验证实验 |
