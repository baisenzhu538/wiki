# 30-50%创业失败源于需求误判

## 原始表述

> 一堂方法论核心数据：30-50%创业失败的根本原因是需求判断错误——做了一个"没人要"或"不值得付费"的产品。

**最常见的误判模式**：把"用户说需要"当成"用户会付费"；把"我觉得这是个问题"当成"这是个普遍问题"；把"高频场景"和"高频使用"混为一谈。

**防御**：评估三角形（普遍性×频次×刚性）是最小有效防线。

## 使用场景

- **创业机会评估**：评估创业机会时，先验证需求判断是否正确
- **产品需求验证**：验证产品需求是否值得付费，避免"没人要"的产品
- **投资尽调**：评估创业项目时，重点审查需求判断的可靠性
- **团队需求讨论**：统一需求评估标准，避免主观臆断
- **一堂五步法学习**：理解需求分析在创业中的核心地位

## 操作方法

1. **需求误判识别**：
   - 把"用户说需要"当成"用户会付费" → 验证付费意愿
   - 把"我觉得这是个问题"当成"这是个普遍问题" → 验证普遍性
   - 把"高频场景"和"高频使用"混为一谈 → 区分场景和使用频率
2. **评估三角形应用**：
   - 普遍性：这个问题有多少人遇到？
   - 频次：这个问题多久遇到一次？
   - 刚性：这个问题不解决会怎样？
   - 三个维度都高才是真需求
3. **付费意愿验证**：
   - 用户说"需要"≠用户会"付费"
   - 最小验证：预售、定金、意向金
   - 用金钱投票比用嘴巴投票更可靠
4. **数据驱动决策**：
   - 用数据替代主观判断
   - 30-50%的失败率是统计事实，不是恐吓
   - 系统性地用评估三角形过滤需求

## 适用边界

| 场景 | 是否适用 | 说明 |
|:---|:---|:---|
| 创业机会评估 | ✅ 适用 | 30-50%失败率说明需求判断是创业第一关 |
| 产品需求验证 | ✅ 适用 | 避免"没人要"或"不值得付费"的产品 |
| 投资尽调 | ✅ 适用 | 重点审查创业项目的需求判断可靠性 |
| 团队需求讨论 | ✅ 适用 | 统一评估标准，避免主观臆断 |

| 成熟产品优化 | ⚠️ 部分适用 | 已有用户基础，需求判断风险较低 |
| 企业内部创新 | ⚠️ 部分适用 | 内部创新有资源支持，但仍需验证需求 |

## 为什么值钱

1. **数据警示**：30-50%的失败率是统计事实，不是恐吓，说明需求判断是创业第一关
2. **评估框架**：评估三角形（普遍性×频次×刚性）提供最小有效防线
3. **付费验证**：用户说"需要"≠用户会"付费"，用金钱投票更可靠
4. **系统防御**：系统性地用评估三角形过滤需求，避免主观臆断

## 失败模式 / 常见走偏

| 失败模式 | 症状 | 纠正 |
|:---|:---|:---|
| 把"需要"当"付费" | 用户说"需要"就直接开发 | 验证付费意愿，用金钱投票 |
| 主观臆断 | "我觉得这是个问题" | 验证普遍性，用数据说话 |
| 混淆场景和使用 | "高频场景"="高频使用" | 区分场景频率和使用频率 |
| 忽略评估三角形 | 只关注一个维度 | 普遍性×频次×刚性，三个维度都高才是真需求 |
| 数据盲区 | 不知道30-50%失败率 | 把需求判断作为创业第一关，系统验证 |
