# 暗知：假设驱动方法论的三个反直觉陷阱

## 原始表述

假设驱动方法论（Hypothesis-Driven Approach）被赋予了它本身不具备的能力：**让你在信息不完全时做出正确决策**。实际上，假设驱动的价值不在于"给出正确答案"，而在于"给出有方向的错误"——让你快速排除明显错误的选项，从而缩小搜索空间。这张暗知卡揭示三个反直觉的认知陷阱：**假设质量不是问题、保护假设的本能、证伪困难**。

## 使用场景

- **创业假设验证**：一堂课程强调假设驱动优势，但陷阱未被充分讨论
- **商业决策分析**：用假设驱动缩小搜索空间，但避免把假设当结论
- **团队 brainstorm**：快速生成假设后，需要设计最小成本验证实验
- **产品功能验证**：区分"证实"和"证伪"，避免确认偏误
- **风险管理**：识别假设树无法覆盖的未知未知（unknown unknowns）

## 操作方法

1. **生成假设后先验证**：不要直接把假设当结论执行，设计最小成本验证实验
2. **区分假设完备性与正确性**：假设树漂亮不代表根基正确，验证前提假设
3. **主动证伪而非证实**：
   - 问"什么证据能证明这个假设是错的？"
   - 设定明确的证伪标准（如"留存率提升20%"而非"留存率提升"）
4. **警惕结构美感陷阱**：MECE 的假设树可能掩盖根基错误
5. **接受大多数初始假设是错的**：假设驱动的价值在于快速排除错误，而非找到正确答案

## 适用边界

| 边界 | 说明 |
|:
--|:-----|
| ✅ 适合 | 信息不完全时需要快速缩小搜索空间的决策场景 |
| ✅ 适合 | 团队愿意接受假设可能被证伪的文化 |
| ✅ 适合 | 有资源设计最小成本验证实验的场景 |
| ❌ 不适合 | 目标本身模糊，连"要验证什么"都说不明白 |
| ❌ 不适合 | 高 stakes 单次决策，无法承受假设错误代价 |
| ⚠️ 注意 | 假设树越完美，对未知未知的盲点可能越大 |

## 为什么值钱

1. **避免假设当结论**：假设驱动的价值在于快速排除错误，而非找到正确答案
2. **证伪思维**：主动寻找否定证据，比收集支持证据更有价值
3. **识别认知陷阱**：假设完备性≠正确性，结构美感可能掩盖根基错误
4. **风险管理**：识别假设树无法覆盖的未知未知，避免黑天鹅盲区
