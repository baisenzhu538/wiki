# 需求替代陷阱：竞品不是敌人，替代方案才是

## 原始表述

> 一堂五步法：最大的竞争不是同类产品，而是用户现在的替代方案——包括"不解决"。

核心暗知识：做需求分析时，"竞品"不应狭义理解为同类产品，而应扩展为"所有完成同一任务的方案"——直接竞品、间接竞品、人工方案、现有工具（Excel/微信），以及最强的"不解决"。需求够不够痛，取决于"不解决"的后果有多严重。

## 使用场景

| 适用场景 | 说明 |
|:---|:---|
| 新产品定位 | 识别真正的竞争边界，避免只对标同类 |
| 竞品分析 | 把替代方案纳入竞争图谱 |
| 需求验证 | 用"不解决的后果"检验需求强度 |
| 差异化策略 | 在替代方案的痛点上建立差异 |

## 操作方法

### 1. 替代方案四问

1. **用户现在怎么解决的？**（识别所有替代方案）
2. **替代方案的成本是多少？**（时间、金钱、精力）
3. **替代方案的痛点是什么？**（为什么现在的方式不够好）
4. **用户切换的意愿和成本？**（愿意换吗？切换成本高吗？）

### 2. 替代方案全景表

竞争不是"同类产品"，而是"所有完成同一任务的方案"：

| 替代方案类型 | 示例 | 威胁程度 |
|:---|:---|:---:|
| **直接竞品** | 同类产品的其他品牌 | 中 |
| **间接竞品** | 不同品类但解决同一问题 | 高 |
| **人工方案** | 雇人、自己手动做 | 高 |
| **现有工具** | Excel、微信、邮件 | 极高 |
| **不解决** | 忍受问题，不采取行动 | **最高** |

关键洞察：**"不解决"是最强的竞争对手**。如果用户不解决问题的后果不严重，需求就不够痛。

| 你的产品 | 直接竞品 | 间接竞品 | 人工方案 | 不解决 |
|:---|:---|:---|:---|:---|
| 项目管理工具 | Asana、Trello | Excel、邮件 | 项目经理手动跟进 | 不跟进 |
| 在线客服系统 | Zendesk、Intercom | 微信、电话 | 客服手动回复 | 不回复 |
| 数据分析工具 | Tableau、PowerBI | Excel、PPT | 数据分析师手动整理 | 不分析 |

### 3. 验证"不解决"

如果用户现在不解决这个问题，后果是什么？后果不严重 → 需求不够痛 → 产品很难成立。这是最易被忽略、也最致命的竞争判断。

### 4. 切换成本分析

用户从替代方案切换到你的产品，需要什么：

| 切换成本类型 | 示例 | 降低方法 |
|:---|:---|:---|
| **学习成本** | 新系统操作复杂 | 简化界面、迁移工具、培训 |
| **数据迁移成本** | 历史数据无法导入 | 提供迁移工具、兼容旧格式 |
| **习惯成本** | 用户已习惯旧方案 | 渐进切换、并行使用、即时反馈 |
| **信任成本** | 不确定新方案是否更好 | 免费试用、案例、退款保障 |
| **社交成本** | 需要团队一起切换 | 团队版优惠、协作功能 |

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新产品定位 | 成熟产品优化 |
| 竞品分析 | 技术架构设计 |
| 需求验证 | 运营策略 |
| 差异化策略 | 品牌传播 |

## 为什么值钱

这条暗知识值钱在两点：

1. **重新定义竞争边界**。多数团队把竞品分析局限在同类产品，结果被跨品类的间接竞品、甚至"不解决"颠覆。把竞争扩展为"所有完成同一任务的方案"，才能看到真正的威胁——这解释了为什么"功能比竞品强"的产品依然失败。
2. **用"不解决"检验需求强度**。"不解决"是最强竞争对手，意味着需求的痛度 = "不解决的后果严重程度"。这是一个可操作的需求真伪判断器：问"用户不解决会怎样"，比问"用户想要吗"更接近真相。

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **只关注直接竞品** | 产品差异化只在同类产品中 | 列出所有替代方案，找到差异化 |
| **忽视"不解决"** | 假设用户必须解决这个问题 | 验证"不解决"的后果是否严重 |
| **低估现有工具** | 认为Excel/邮件不是竞争 | 分析用户用Excel/邮件的成本和痛点 |
| **切换成本过高** | 用户试用后不回来 | 分析具体切换成本，逐一降低 |
| **只比价格** | "我们比竞品便宜" | 分析用户决策的所有维度 |
| **忽视间接竞品** | 被跨行业产品颠覆 | 定期扫描所有完成同一任务的方案 |
