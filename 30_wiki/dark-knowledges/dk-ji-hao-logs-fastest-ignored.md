# 暗知识：日志增长最快但最容易被忽视

## 原始表述

在人和AI协作的五层体系中，日志是唯一由AI自动生成、增长最快的层，也正因为"不需要人创建"，它最容易被忽视，最终变成无法追溯的噪音堆。

在纪浩的五层体系中，日志是唯一一个不需要人"创建"而是被AI"自然生成"的层。也正因如此，它增长得最快、混乱得最快、被忽视得也最快。很多人搭建工作空间时会精心设计系统自述、工作手册、工具集，但日志部分往往是最后一个被想起来的——而到那个时候，日志已经溢出了。

**纪浩的原话**："日志是最容易被忽视的。因为它不是你主动去建的，是AI自动生成的。你会觉得，哦，日志自己会记录的，不用管。结果三个月后你发现日志里面全是垃圾，找不到任何有用的东西。"

日志是人理解AI行为的**唯一客观通道**。当AI产出意想不到的结果时，人大脑的第一反应是猜原因——这个时候的猜测几乎总是错的。日志让你回到具体的执行过程，用事实替代假设。没有日志，你就是在盲目地调教AI。

## 使用场景

- **持续迭代的多轮人机协作**：日志是追溯"AI为什么这样输出"的唯一事实基座
- **多人/多AI共享工作空间**：没有统一日志，各自对执行过程的理解会迅速分叉
- **AI输出质量调试**：当AI产出意想不到的结果时，用日志替代猜测
- **工作空间维护**：把日志纳入定期审查节奏，避免日志溢出
- **团队知识沉淀**：日志是AI协作过程的客观记录，可供复盘和学习

## 操作方法

1. **主动设计日志结构**：
   - 记录什么：时间、模型/版本、提示词、关键上下文、输出摘要
   - 存在哪：统一日志目录和命名规范
   - 怎么命名：日期+任务+版本，便于检索
   - 多久回顾：每周/每迭代定期审查
2. **最小必要字段**：
   - 时间戳
   - 模型/版本信息
   - 提示词（或提示词摘要）
   - 关键上下文
   - 输出摘要
   - 决策点记录
3. **日志审查节奏**：
   - 每周/每迭代定期审查日志结构
   - 清理噪声，归档过期日志
   - 检查命名规范一致性
4. **复盘习惯**：
   - 养成先看日志再下结论的习惯
   - 用事实替代假设
   - 不同会话/不同人统一日志模板

## 适用边界

| 场景 | 是否适用 | 说明 |
|:---|:---|:---|
| 任务输出完全可观察和验证（如排序算法是否正确） | ⚠️ 部分适用 | 可以直接看结果验证，但仍建议记录关键参数以便复现 |
| 使用成熟可观测性平台覆盖全部执行过程 | ✅ 适用 | 平台已经替代了部分日志功能，但仍需与协作空间打通 |
| 任务是一次性、不会重复的尝试 | ⚠️ 部分适用 | 单次尝试可以简化日志，但关键决策点仍需记录 |
| 需要持续迭代、多轮人机协作的复杂任务 | ✅ 高度适用 | 日志是追溯"AI为什么这样输出"的唯一事实基座 |
| 多人/多AI共享同一工作空间 | ✅ 高度适用 | 没有统一日志，各自对执行过程的理解会迅速分叉 |

## 为什么值钱

1. **唯一客观通道**：日志是人理解AI行为的唯一客观通道，用事实替代猜测
2. **调试效率**：当AI产出意外结果时，日志让你回到具体执行过程，避免盲目调教
3. **团队协同**：统一日志让多人/多AI共享工作空间时理解一致
4. **知识沉淀**：日志是AI协作过程的客观记录，可供复盘和学习

## 失败模式 / 常见走偏

| 失败模式 | 常见错觉 | 纠正方式 |
|:---|:---|:---|
| 把日志当作"AI会自动处理好"的层 | "日志自己会记录，不用管" | 主动设计日志结构：记录什么、存在哪、怎么命名、多久回顾 |
| 只在出错后才想起查日志 | "平时不用看，出问题时再说" | 建立定期审查节奏（如每周/每迭代），把日志纳入工作空间维护 |
| 日志堆量但无结构，关键信息淹没 | "记录越多越好" | 约定最小必要字段：时间、模型/版本、提示词、关键上下文、输出摘要 |
| 用记忆和猜测替代日志复盘 | "我当时大概是这样问的" | 养成先看日志再下结论的习惯，用事实替代假设 |
| 不同会话/不同人记录的日志格式不一致 | "只要记下来就行" | 统一日志模板和命名规范，让日志可被检索和拼接 |
