# 需求蔓延：从MVP到全功能的陷阱

## 原始表述

> 一堂五步法：最大的危险不是没功能，而是在伪需求上无限膨胀，淹没核心功能。

核心暗知识：需求蔓延（Scope Creep）= 在真需求上无限叠加衍生需求，导致产品臃肿、核心模糊、用户流失。判断蔓延的试金石是"减法测试"——砍掉这个功能，核心需求还能不能验证？能，就是蔓延。

## 使用场景

| 适用场景 | 说明 |
|:---|:---|
| 新产品 MVP 设计 | 锁定最小功能集，防止开局就臃肿 |
| 需求优先级排序 | 用减法测试筛掉衍生需求 |
| 资源有限时的取舍 | 砍掉非核心，集中验证 |
| 创业早期产品决策 | 抵抗"再加一个功能"的冲动 |

## 操作方法

### 1. 识别蔓延信号

| 信号 | 说明 | 危险等级 |
|:---|:---|:---:|
| **用户假设付费** | "如果加上XX功能，我就付费" | 🔴 高 |
| **团队假设必需** | "必须做XX，否则用户不用" | 🔴 高 |
| **功能比竞品多** | 功能列表比竞品长 | 🟡 中 |
| **只加不减** | 从未砍掉功能 | 🟡 中 |
| **MVP超时** | MVP做了6个月还没上线 | 🔴 高 |
| **核心功能未验证** | 在核心需求未验证前加功能 | 🔴 高 |

### 2. 减法测试

每个新增功能前，做减法测试（三个问题任一答"能"，即为蔓延）：

1. **砍掉这个功能，核心需求还能验证吗？** 能 → 这个功能是蔓延，不是必需。
2. **去掉最近新增的3个功能，产品核心价值受损吗？** 不受损 → 这3个都是蔓延。
3. **用户愿意为"现有功能"付费吗？**（不是"加上XX后"付费） 不愿意 → 新增功能也救不了，先解决核心价值。

### 3. MVP 的 M 是什么

MVP（Minimum Viable Product）的 M 是 Minimum：

| 维度 | 正确理解 | 错误理解 |
|:---|:---|:---|
| **Minimum** | 最小功能集验证核心需求 | 最小功能集=简陋产品 |
| **Viable** | 用户能完成核心任务 | 产品能用就行 |
| **Product** | 可交付的体验 | 可以是Concierge MVP（人工服务） |

### 4. 蔓延的根源与修复

| 根源 | 表现 | 修复 |
|:---|:---|:---|
| **创始人完美主义** | "产品必须完整才能上线" | 先验证核心，再完善 |
| **团队共识偏差** | "大家都觉得需要" | 用数据验证，不是投票 |
| **用户压力** | "用户要求加功能" | 区分"要求"和"愿意付费" |
| **竞争焦虑** | "竞品做了，我们也得做" | 验证竞品功能是否成功 |
| **技术驱动** | "我们能做，所以做了" | 回到"用户需要吗？" |

蔓延的典型路径：

```
真需求：用户需要高效管理客户信息
    ↓
衍生1：加个标签功能
    ↓
衍生2：再加个自动化流程
    ↓
衍生3：再加个数据分析看板
    ↓
衍生4：再加个AI预测...
    ↓
结果：产品臃肿，核心功能被淹没，用户流失
```

## 适用边界

| 适用场景 | 不适用场景 |
|:---|:---|
| 新产品MVP设计 | 成熟产品功能迭代 |
| 需求优先级排序 | 技术架构设计 |
| 资源有限时的取舍 | 运营策略制定 |
| 创业早期产品决策 | 品牌传播策略 |

## 为什么值钱

这条暗知识值钱在两点：

1. **给出"蔓延"的可操作判据**。"功能太多"是模糊感受，"砍掉它核心还能不能验证"是可执行的判断。减法测试把"该不该加功能"从争论变成测试——这是创业早期最容易失控、也最容易用纪律锁住的决策点。
2. **揭露"假设付费/假设必需"的伪需求机制**。蔓延很少来自真用户付费，几乎都来自"用户说加了就付费"和"团队觉得必须做"两类假设。识别这两类假设，就堵住了 80% 的蔓延入口。

## 失败模式

| 失败模式 | 症状 | 修复方法 |
|:---|:---|:---|
| **MVP不够M** | 功能太多，验证不了核心 | 砍掉非核心功能，只保留验证核心需求的最小功能集 |
| **用户假设付费** | "加了功能就付费" | 先验证现有功能是否愿意付费 |
| **团队假设必需** | "必须做XX" | 问"多少用户因为缺少这个功能而流失？" |
| **功能竞赛** | 功能比竞品多 | 聚焦核心功能，做到10倍好 |
| **只加不减** | 从未砍掉功能 | 定期做需求减法测试 |
| **核心未验证就扩展** | 核心需求还没验证，就加新功能 | 先验证核心，再扩展 |
