## 原始表述

> 你们要习惯性建模，你们带着模型过来跟我聊，我只聊模型不聊结果……我有一票否，但我没有一票通过权……我负责的是模型足够健康，且执行是 OK 的。

## 核心洞察

当组织规模变大、CEO 不可能熟悉每个候选人/项目时，“让 CEO 拍结果”会放大偏见和错误。Truman 的解法是**把评选结果从 CEO 手中拿掉，只保留对评选模型的审查权和否决权**。团队先和 CEO 一起画出 4-6 个关键维度的雷达图，作为共同工作公式；CEO 只负责两件事：模型是否科学、执行是否到位。这是一种把“建模”嵌入组织治理的反直觉设计。

更深一层，这条规则解决的是三个组织常见病：

1. **CEO 偏好被放大**：人越多，CEO 个人印象对结果的权重越不成比例。
2. **团队互相甩锅**：没有共同公式时，“谁上谁下”变成政治博弈。
3. **模型与执行混为一谈**：模型对了但执行走样，或执行到位但模型偏了，都分不清楚责任。

把 CEO 的权责拆成“模型审查 + 一票否决 + 执行监督”，本质上是把评选决策从“人治”推进到“模型治 + 流程治”。

## 操作方法

1. **把决策拆成“模型”和“结果”**
   模型 = 评选维度 + 权重 + 评分规则；结果 = 按模型跑出来的排序。两者必须分开文档化。

2. **让 CEO 只参与模型设计**
   拉着有判断力的人一起定义 4-6 个关键角，CEO 只确认“这个模型是否科学”。一旦确认，CEO 不再干预具体评分。

3. **CEO 保留一票否决，不保留一票通过**
   可以拦住高风险选项（如诚信红线、战略方向冲突），但不能直接指定谁通过。

4. **执行责任单独落到 owner**
   模型只负责筛选，执行质量由执行 owner 负责。CEO 监督执行是否到位，而不是替执行团队背结果。

5. **持续打补丁**
   每次评选后复盘：哪些维度失真？哪些权重需要调？模型本身要迭代。迭代决策仍按模型规则走。

6. **明文写进决策流程**
   谁可以否决、否决必须记录原因、模型多久复盘一次，全部写进 SOP，避免口头放权。

## 诊断信号

| 诊断信号 (Signal) | 透镜 (Lens) | 跟进问题 (Follow-up) |
|:
|:---|:---|
| CEO 经常推翻模型跑出的结果，重新指定人选 | CEO 仍把结果拍板权握在手中 | 上次 CEO 推翻结果时，是模型有问题还是执行有问题？ |
| 评选会上大家争论“谁更好”，而不是“模型是否科学” | 共同工作公式缺失或被绕过 | 如果按现有模型打分，结果会是什么？差距在哪里？ |
| 同一类评选每次都要重新吵架 | 模型没有被固化成 SOP | 我们上一次评选后复盘过模型吗？哪些维度需要调？ |
| 员工觉得结果不公平，但说不出哪里不公平 | 模型不透明或权重不合理 | 评选维度和权重是否向参与者公开？ |
| 模型评分很高的人，实际执行总是掉链子 | 模型维度缺少执行可行性校验 | 模型是否包含“可执行性”或“资源匹配度”维度？ |
| CEO 说“我只看模型”，但会上却在聊印象分 | 角色边界模糊 | 我们能否把 CEO 的发言限制在模型审查和否决两件事上？ |

## 适用边界

| 边界 | 说明 |
|:---|:---|
| 适用于可结构化、多维度、高频的评选决策 | 招聘、晋升、项目立项、供应商选择等。战略级、非结构化决策仍需要 CEO 直接判断。 |
| 需要团队具备基础建模能力 | 如果连 L3/L4 的雷达图都画不出，模型会流于形式。 |
| CEO 必须愿意放权 | 如果 CEO 舍不得放弃拍板权，机制会失效。 |
| 模型质量必须过硬 | 模型有漏洞时，甩锅给模型比人治更危险。 |
| 不适用于零样本决策 | 第一次做、没有历史数据校准的决策，不宜直接交给模型。 |
| 需要配套的执行监督机制 | 只审模型不盯执行，会导致“模型对了，结果还是崩”。 |

| 失败模式 | 典型症状 | 修复方法 |
|---|---|---|
| CEO 口头放权实则拍板 | 模型跑完，CEO 还是凭印象推翻 | 明文写进决策流程，谁否决谁记录原因 |
| 维度定义不清晰 | 评分时各打各的，无法横向比较 | 每个角给出 3-5 级具体定义和案例 |
| 模型一成不变 | 早期有效，后期被团队钻空子 | 每季度/半年复盘一次模型 |
| 把模型当挡箭牌 | 结果不好就怪模型，没人负责执行 | 明确执行 owner，模型只负责筛选 |
| 只有模型没有执行监督 | 选出来的人/项目执行失败率高 | 把执行可行性、资源匹配度纳入模型维度 |
| 模型权重由 CEO 一人定 | 权重反映 CEO 偏好而非业务本质 | 权重由跨职能小组共同校准，CEO 只审科学性 |
| 模型过复杂无法落地 | 10 个维度、20 个指标，评分成本过高 | 先跑 4-6 个关键角，够用即可 |
