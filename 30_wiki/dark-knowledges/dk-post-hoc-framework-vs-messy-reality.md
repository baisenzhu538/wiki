# 真实过程≠复盘结构

> 一句话：付则宇亲述——实际开发顺序和复盘出的四步法是反的。复盘框架有价值，但它掩盖了"先踩坑再回头"的真实路径。

---

## 原始表述

> 口述 L1754-1760

付则宇的真实开发过程：

```
实际：追Hyper Friends一个月 → 发现不对 → 回头拆视频 → 建审美 → 组件化 → 自动化
复盘：拆（建审美）→ 建（组件化）→ 推（自动化）→ 练（批量产出）
```

复盘后的结构把"试错→发现不对→回头"这个最关键的学习过程隐去了。

---

## 使用场景

- 读任何"方法论框架"时——问自己：这个框架是执行路线图还是事后归纳？
- 复盘自己的项目时——如实记录混乱的第一圈，不要只写"干净版本"
- 教别人时——先讲真实过程，再讲提炼后的框架

## 操作方法

```
1. 复盘时先写"实际发生了什么的流水账"（保留混乱）
2. 再从流水账中提炼框架
3. 两个版本都保留——框架给别人看，流水账给自己看
```

## 适用边界

- ✅ 任何方法论提炼场景
- ❌ 第一次做某事的执行手册——此时还没法提炼框架，先做再说

## 为什么值钱

大多数人只看到付则宇的四步法——不知道他先追了一个月的错误方向。这个暗知识比框架本身更有价值：**第一圈是乱的，这很正常；复盘让它看起来有条理，但它本来就是乱的。**
