# 桥接卡：教练式领导力 × Feature 分层 L5

> 定位：连接 `framework-truman-feature-layered-system`（Feature 分层体系）与 `framework-coaching-leadership-core`（教练式领导力卡组）的跨域桥接卡。核心命题：**五阶梯 = 组织层（L5）Feature 的组合**；**教练对话 = 倾听/提问/反馈 Feature 的点菜**。

## 一句话定义

教练式领导力五阶梯与 Feature 分层 L5 组织层是**同一件事的两种语言**：五阶梯回答"组织如何让成员心甘情愿解决难题"，L5 组织层回答"团队如何 AI 化协作"——两者的底层都是"设计人与人的协作结构"。教练对话则是 L2-L3 层的 Feature 点菜（每个倾听/提问/反馈动作 = 一个可复用 Feature）。

## 双向桥接：A 给 B 带来什么

### Feature 分层 → 教练式领导力（技术语言给管理语言）

| Feature 分层 | 给领导力的启示 |
|:--|:--|
| 分层自洽原则（下层优先） | 领导力五阶梯同构：能用 L0 认同解决的不上 L1 结果——"如无必要，勿增实体" |
| L5 组织层 13 Feature | 五阶梯 = 组织层 Feature 的组合方式（见下方同构映射表） |
| Feature 原子性（49 原子） | 加减币清单 = 领导力"原子行为"库，与 Feature 原子同构 |
| 渐进披露 | 领导力培养也要"先宽后窄"——先掌握少数高频加币行为，再扩展 |

### 教练式领导力 → Feature 分层（管理语言给技术语言）

| 领导力概念 | 给 Feature 分层的启示 |
|:--|:--|
| 五阶梯 L0-L5 | L5 组织层设计需要领导力思维——"组织 AI 化"本质是"带团队解决问题" |
| 教练对话三组武器库 | 倾听/提问/反馈 = 人与 AI 协作的交互 Feature 库 |
| 猴子理论 | 组织层设计中责任归属（谁的猴子谁背）是 Agent 编排的边界原则 |
| 2×5 耐心标准 | Agent 能力培养同样需要"安全空间有期限"——迭代次数预算 |

## 同构映射表（五阶梯 ↔ Feature L5 组织层）

| 五阶梯层 | 领导力核心 | Feature 分层对应 | 组织层 Feature 组合 |
|:--|:--|:--|:--|
| **L0 认同** | 以身作则/安全氛围 | L5 组织文化 | 角色分工（领导示范）+ 共享资源（安全空间） |
| **L1 结果** | 扛事/稀缺优势/实事求是 | L5 目标管理 | 目标设定 Feature + 责任归属（猴子理论） |
| **L2 共识** | 讲道理/提问/出口式咨询 | L5 决策沟通 | 决策流程 Feature + 讲道理机制（白盒决策） |
| **L3 成长** | 基本功/1v1 反馈 | L5 人才发展 | 反馈循环 Feature + 刻意练习容器 |
| **L4 希望** | 愿景/文化/社会价值 | L5 愿景组织 | 愿景对齐 Feature + 组织叙事 |
| **L5 希望（终）** | 组织级领导力 | L5 组织编排 | Agent 编排 + 角色分工 + 共享资源（完整组织层） |

## 教练对话 = Feature 点菜

| 对话目标 | 点菜组合（武器库 Feature） |
|:--|:--|
| 建立信任 | 倾听：专注 + 3F + 大智若愚（先听再说） |
| 理清问题 | 提问：引发思考 + 切换视角 + 重定义 |
| 推动共识 | 提问：明确出口 + ABCD；倾听：识别分歧 |
| 促进成长 | 反馈：BASIC + BE FASTER + 刻意练习容器 |
| 处理冲突 | 倾听：识别卡点 + 静默；反馈：负面反馈结构 |

> **点菜原则（同构分层自洽）**：能用倾听解决的不用提问，能用提问解决的不用反馈——下层优先，避免过度设计对话。

## 元技能认识（ICF/GROW 对照）

**"模型不会倾听，教练才会"**——模型选择是元技能：

- GROW 模型（行动完成率 +67%，ICF 2026）的 G（出口）R（倾听）O（提问）W（反馈）四环节，莫非武器库实际覆盖
- Truman 明言"不讲 GROW 讲给莫非"——因为 GROW 是结构，倾听/提问/反馈才是让结构生效的能力
- ICF 八项核心能力（积极倾听=能力6/强有力提问=能力7/直接沟通=能力8）与武器库三组同构
- **启示**：无论用哪个模型（GROW/五阶梯/Feature 分层），最终效果取决于"是否真会倾听、真会提问、真会反馈"——这是模型之上的元技能

## 使用导航（什么时候用哪边）

| 场景 | 用哪边 |
|:--|:--|
| 设计团队 AI 化方案 | Feature 分层 L5（技术语言） |
| 带团队解决开放难题 | 五阶梯 + 武器库（管理语言） |
| 设计 Agent 协作流程 | Feature L5 + 猴子理论（责任归属） |
| 培训管理者 | 五阶梯 + 武器库（先建管理直觉） |

## 边界与反例（When NOT to Use）

| 场景 | 为什么不用 | 正确做法 |
|:--|:--|:--|
| 一次性任务 | 不需要分层体系 | 直接做 |
| 团队无 L2 基础 | 下层没练熟上层站不稳 | 先建基础 |
| 把桥接当"等同" | 五阶梯≠Feature 分层（语言不同） | 用桥接转换视角，不混用术语 |
| 过度设计对话 | 每个对话都点满 8 个 Feature | 下层优先，最少可用组合 |

## 常见失败模式

| 失败模式 | 症状 | 修复动作 |
|:--|:--|:--|
| 术语混用 | 跟管理者说"L5 组织层"他听不懂 | 先翻译成五阶梯语言 |
| 桥接变等同 | "五阶梯就是 Feature L5" | 记住：同构≠等同，视角不同 |
| 点菜过载 | 一次对话用 6 张卡 | 最少可用组合（信任→理清→推动） |
| 忽略元技能 | 有 GROW 模型但不会倾听 | 先练武器库基本功 |

## Critique

### 攻击者 1：方法论纯粹主义者——"跨域同构映射是过度类比"

**攻击论点**：五阶梯（领导力层级）与 Feature 分层（技术栈层级）的"同构"是事后构造的类比——任何两个层级系统都能找到表面映射，但映射不产生新知识，反而可能混淆两个独立框架的边界。

**回应**：桥接的价值不在"证明同构"，而在**双向翻译**——让管理者理解技术团队的语言（L5 组织层），让工程师理解管理语言（五阶梯）。这正是用户确认的跨课桥接需求。承认：映射表是启发式工具，不是数学等价，使用时保持"视角转换"而非"概念合并"。

### 攻击者 2：AI 工程视角——"组织层 Feature 与领导力是不同抽象层级，强行映射误导设计"

**攻击论点**：Feature L5 组织层的 Feature（角色分工/共享资源/Agent 编排）是**技术实现**维度，五阶梯是**人际影响力**维度。把"角色分工"映射到"以身作则"会误导 Agent 编排设计——技术方案不能靠管理直觉决定。

**回应**：桥接卡明确区分"同构≠等同"（When NOT to Use 第 3 条），映射表用于**启发设计**（组织层缺哪块），技术实现仍按 Feature 分层自洽原则。承认：卡内应强调"映射只回答'缺什么'，不回答'怎么做'"。

### 攻击者 3：ICF 教练伦理——"把教练对话拆成 Feature 点菜可能机械化教练过程"

**攻击论点**：教练对话是高度情境化的共情过程，拆成"点菜组合"可能让学习者机械套用，丧失对当下情境的敏感——这恰恰违背教练精神（人不是 Feature 的组合）。

**回应**：元技能认识节已声明"模型不会倾听，教练才会"——点菜表是**新手脚手架**，帮助建立结构感；熟练后应超越结构，回到倾听本身。承认：卡内应补"点菜表是入门地图，不是操作手册——熟练后放下地图"。
