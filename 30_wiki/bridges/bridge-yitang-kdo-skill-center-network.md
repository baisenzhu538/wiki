# 桥接：一堂技能中心/能力网络 × KDO 30_wiki 知识库

> **定位声明**：本桥做两件事：①把一堂「技能中心→能力网络」的设想与 KDO 已在跑的 30_wiki 对表——确认同构、标出差距；②收录配套的**阳谋论**——能力网络成立的前提是全部打开，这正是本库全库公开 git 化的理由。dk「阳谋论」挂靠本卡。

## 一堂端：技能中心设想（宣讲会 L1054-1088，台账 B93/B94）

1. **技能中心**：各同学的经验/流程/方法沉淀成**团队级**组织形态——「去技能中心看一下」，Agent 扫到某个成员贡献的技能装上就会用（台账 B93 场景描述）。
2. **与技能市场的两个区别**（台账 B93）：①天然基于课程体系——技能彼此关联成理论框架，不是货架清单；②有行动计划与场景化支持。
3. **能力网络论**（L1076-1080，逐字回验）：「流通的不只是人，不只是人学的内容啊，未来可以有各种能力包方法包，甚至 Data Pack」；「你的 AI Agent 因为接入了这套东西，有可能会变得更聪明一点」；「这个能力会变成一点点的网络」。台账 B94 压缩金句：**这个网络不是给你用的，是给你 AI 用的**（原文为 L1076-1104 连续表述的浓缩，引用时以原文锚为准）。
4. **真正有价值的动作**（L1080，逐字回验）：「真正有价值的地方不是大家学到了多少技巧，而是有没有把这些经验一定程度上再扔到这个[网络]」。

## KDO 端：已实现的部分

| 一堂设想 | KDO 现状 | 差距 |
|:--|:--|:--|
| 技能沉淀成团队级形态 | 30_wiki/（概念/框架/case/dk 卡）+ 40_outputs/capabilities/skills/shared/（工具=变量、shared 桥接点不变） | 卡多、行为化少——卡片→skill 行为化产线刚立（skills-assistant 第 7 角色） |
| Agent 扫到技能装上就会用 | kdo query 语义检索 + Graph RAG；cap_hub 可发现工具 | 「装上就会用」的自动挂载未闭环（#588 扫描机制在办） |
| 基于体系非货架 | 卡片间双向链接 + 域 digest + index | 检索按域组织已达标；跨域桥接密度待提升（本批 4 桥即补此债） |
| 网络给你 AI 用 | CLAUDE.md 定位即「AI for Business」；卡片 frontmatter 的 discoverable_by/tags 全部为 Agent 检索设计 | 部分老卡 discoverable_by 缺失/粗糙 |
| 经验扔回网络 | 会话结束三问强制落盘（新资产必入 30_wiki/00_inbox/10_raw） | 依赖个人纪律，无机械门禁 |

**对表结论**：KDO 不是「对标」技能中心——是它的**提前实现**（诊断 D3 口径：KDO 已实现一部分）。真正的差距不在存量资产，在**行为化率与挂载闭环**：资产躺在库里不等于 Agent 用得上。

## 阳谋论：网络为什么必须打开

### dk：阳谋论
- **维度标签**：开放战略
- 一句话：最好的战略是阳谋——「我不靠桌下动作获胜，就我所有东西都是打开的」（宣讲会:L888，逐字回验；「最好的战略是阳谋」为台账 B84 压缩语）；因为能力网络的复利来自流通，藏着掖着等于主动退出网络。
- 锚：宣讲会:L886-888（行号锚为准；台账号 B84 系未编号尾部块、B85 为神秘计划/FDE 与阳谋无关）；本库同构：全库公开 git 化
- 使用边界：适用于知识/方法/技能类资产（流通即增值）；不适用于涉密与个人信息（密级件走 #322 传播限制先例，如 Eason 审计卡）。
- 配套条件（台账 B83）：开放要有结构——每方向设标杆、范围自定、默认不派活，否则「口子太大团队散了」。

**两端同构点**：一堂开源战略的动机是「好的学习材料不在教程不在分享，在真实的业务现场和细节里」（台账 B80，商业机密天然封闭是十几年夙愿的敌人）；KDO 全库公开 git 的动机是资产可被 Agent 检索与互链——两侧共同点：**封闭保护的是存量，开放才能产生增量**。

## 口径互证（本桥的元证据）

实战路径:L532（逐字回验）：讲者自我介绍「我做了一家叫一堂的公司，是一个在 AI for Business 想探索最佳实践的一个研究型的公司」——与本库 CLAUDE.md 知识库定位「AI for Business — 用 AI 增强商业判断力与商业审美」**原文同口径**（台账 A80 已标注）。两个组织在互不知情的情况下选择了同一句话定义自己——这是本批素材里最直接的一处「同源感」证据，也是 KDO 消化一堂体系素材时低摩擦的原因。

## 失败模式

| 失败 | 症状 | 修复 |
|:--|:--|:--|
| 资产≠能力 | 库很大，Agent 检索命中率低 | 补 discoverable_by/tags；新卡过 pre-submit 的可发现性检查 |
| 只进不出 | 只吸收一堂素材，不回吐 KDO 资产 | 按 B94 判据：每批产出标注哪些可反哺外部网络 |
| 开放无结构 | 全部打开但无人能找到、无人敢用 | 每方向设标杆+范围声明（B83 条款） |
| 密级一刀切 | 全封闭或全公开 | #322 传播限制先例：密级标注+脱敏，内部库可用不外传 |

## Synthesis

本桥的结论有三层：①**同构确认**——KDO 30_wiki 是一堂技能中心设想的在跑实例，且「给你 AI 用的」这一定位（Agent 可检索性优先于人类可读性）两端一致；②**差距清单**——行为化率与挂载闭环是 KDO 的下一步，不是资产量；③**阳谋论**回答了「为什么敢全开」：能力网络的复利机制使开放成为战略而非姿态。对本批的操作含义：本批 12+ 卡全部按「给你 AI 用的」标准写入 discoverable_by 与行号锚——这正是「把经验扔回网络」的 KDO 形式。
