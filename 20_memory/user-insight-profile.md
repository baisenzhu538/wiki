## 2. 认知风格层 (Cognitive Style)

### 2.1 学习与决策方式

| 维度 | 当前观察 | 置信度 | 备注 |
|------|---------|--------|------|
| 学习偏好 | 先调研再动手；接受小错率、批量换速度；大量看视频学习 | high | 来源 user-preferences + C 角色诊断 |
| 决策风格 | 定方向/规则/优先级/最终拍板；偏好 ≤3 选项的选择题；喜欢二选一 | high | 五绝架构中欧阳锋角色 + YAI 对话模式 |
| 信息处理方式 | 偏好结构化、标签化、原子化知识；喜欢用文档/SOP沉淀 | high | 从 KDO 实践 + EC 手册案例推断 |
| 风险偏好 | 接受小错率，先跑起来再迭代；愿意进入非舒适区 | high | 从多次任务 + C 角色诊断推断 |
| 沟通偏好 | 简单直接、中文、不喜欢频繁提问、希望 AI 主动推进 | high | 来源 user-preferences |
| 对 AI 的期待 | 不是替代思考，而是放大判断、加速产出；希望 AI 做虚拟教练/反馈 | high | 从对话模式 + C 角色诊断推断 |
| 反馈需求 | 知道自己缺反馈，愿意展示学习过程给 AI/他人看 | high | 来源 C 角色诊断 |
| 迭代能力 | 有极强耐心，能把 1000 字手册迭代到 30 万字再浓缩成 20 条铁律 | high | 来源 C 角色诊断 |

### 2.2 表达与反馈习惯

- **喜欢的反馈方式**: 直接指出错误、主动推进、给结果而不是过程
- **不喜欢的反馈方式**: 频繁确认、技术细节冗长、绕弯子
- **表达情绪的方式**: 通常直接说"可以了""不对""很好"，情绪信号较隐性
- **口头禅/高频词**: "可以了""非常好""你的理解很正确""仔细分析下""仔细消化一下"
- **决策触发词**: "你来定""先跑""给我放桌面""按这个来""继续""1、2、3 我都需要"

### 2.3 注意力与能量模式

- **高效时段**: 晚上、周六周日相对整块时间
- **低能量信号**: （待观察）
- **容易分心的场景**: 周中被杂事打断，导致长期练习/学习无法深入
- **恢复能量的方式**: 进入非舒适区并取得突破后会有强烈爽感

### 3.4 价值观与判断原则

> 用户做判断时隐含的优先级。

- **深度 > 广度**: 愿意花时间在关键认知上
- **实用 > 理论**: 但不排斥为理解付费

## 4. 咨询触发器 (Consulting Triggers)

> 当用户出现以下信号时，AI 应调用对应的咨询框架或追问策略。

| 用户信号 | 含义 | AI 应调用 |
|----------|------|----------|
| "我想练 X" | 启动刻意练习/技能建设 | YAI T 角色：先诊断段位和卡点 |
| "你帮我设计方案" | 需要 C 角色方案输出 | 先确认是否已诊断，否则回退到 T 角色 |
| "太泛了""难执行" | 方案颗粒度不对 | 压成明天最小动作 |
| "可以了" | 认可当前方向 | 记录为偏好，继续推进 |
| "不对""再想想" | 方向或判断有分歧 | 停下来，明确分歧点，给 ≤3 选项 |
| "我积分用完了""后面交给 Hermes" | 资源约束变化 | 调整执行路径，切换 Agent/工具 |
| "给我放桌面" | 需要可交付文件 | 同时输出到桌面 + 归档到 vault |
| 深夜发起对话 | 高效时段 | 可以推进需要深度思考的任务 |

## 5. 待验证假设 (Hypotheses)

> 这些是从对话中推断出来的，需要更多证据验证。

1. 用户在不同项目之间切换时，容易把长期能力练习放在次要位置。
2. 用户对 AI 的期待是"副驾驶"而非"代驾"——需要保留判断权。
3. 用户在知识库建设上投入大量精力，是因为他认为这是其他所有业务能力的底层操作系统。
4. 用户喜欢把复杂问题拆成工单/队列/任务单来管理。
5. 用户对"深刻"有较高标准，表面回答容易被要求再深挖。
