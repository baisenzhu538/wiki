# 广冷红外板 V2.2 调试复盘

> 执行者：Codex
> 问题：V2.2 新增 SN74LVC2G07 电平转换后，16 通道红外全部不工作
> 根因：SN74LVC2G07 开漏输出 → RCLK 上升沿变缓 → 595 锁存不可靠
> 修复：RCLK 后加 Ir_Delay(200) + 分段判断逻辑

---

## 一、三个阶段

### 第一阶段：盲目试延时（无效）

- Ir_Delay 从 15→30→100→200→300→500，反复烧录
- 零进展。原因：没有诊断手段，纯粹撞运气

### 第二阶段：诊断切入（突破）

- **做诊断版固件**：强制拉高 QD1/QD3（绕过 595 直接驱动 MOSFET），灯灭了
- 关键结论：发射管和接收管硬件没问题 → 问题在 595 控制时序
- 确诊：SN74LVC2G07 开漏输出 → RCLK 上升沿变缓 → 595 锁存不可靠
- 修复：RCLK 拉高后加 Ir_Delay(200)

### 第三阶段：判断逻辑修正

- IN1 && IN2 && IN3 && IN4 全不通 → 绿灯永不灭
- 发现 IN2/IN3/IN4 收不到光，但只是没用对判断方式
- 分段隔离法：先让 IN1 单独通 → IN2 → 再合起来
- 最终：`no<8 → IN1&&IN3, no>=8 → IN2&&IN4`

---

## 二、核心教训

### 1. 先诊断，后修复

延时调参是撞运气。诊断版（强制拉高 QD 绕过 595）直接定位到 595 时序问题，省掉大量无用功。

> **诊断的本质不是"找到问题"，而是"排除不可能"。** 诊断版排除了发射/接收管硬件故障，把搜索空间从"整个系统"缩小到"595 控制信号"。

### 2. 分段隔离验证

不要一次搞定四个变量。先让 IN1 单独通 → IN2 → IN3 → IN4 → 再合起来。每加一个变量验证一次，比一次全加然后用排除法快得多。

### 3. 理解硬件原理

SN74LVC2G07 的上拉电阻、开漏特性、上升沿时间——这些不搞清楚，就无法解释"为什么 RCLK 加延时有效"。只能试，不能理解。

### 4. 代码要和硬件/场景对齐

最终版 `no<8 → IN1&&IN3` 不是纯技术决策，来自售货机业务理解：一次掉一个货、靠近哪侧就哪侧检测。判断条件是业务逻辑，不是纯技术问题。

---

## 三、可复用的调试方法

### 嵌入式红外/对射调试 checklist

1. **硬件验证** — 强制驱动发射管（绕过逻辑 IC），确认发射/接收电路完好
2. **时序诊断** — 确认控制信号的上升沿/下降沿是否在器件手册范围内
3. **分段隔离** — 单通道验证 → 多通道联调，逐变量叠加
4. **判断逻辑** — 最后修，先确保每一路硬件信号正确

### 电平转换引入时序问题的排查路径

```
新增电平转换芯片 → 查输出类型（开漏 vs 推挽）
  → 开漏？查上拉电阻值 → 算 RC 时间常数
  → 信号频率是否超过 1/(RC) 可用带宽
  → 固件时序是否匹配
```
