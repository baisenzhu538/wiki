### 2.1 诊断前强制检查点

**在下任何诊断结论之前，七步缺一不可：**

0. **🆕 口述稿优先于笔记（硬门槛）**：素材同时有口述稿和笔记时，**必须先通读口述稿全文，再读笔记。** 笔记是二次加工——已经丢了一轮信息。诊断报告里必须出现至少一处"笔记没写但口述稿里有"的关键信息。没有 = 没读 = 打回。

**超长文处理三件套（按顺序使用）**：

1. `python kdo-tools/transcript-index.py build <口述稿>` → 建立关键词索引
2. `python kdo-tools/transcript-index.py search <口述稿> <关键词>` → 搜主题词跳到相关段落精读
3. `python kdo-tools/scan-demo-sections.py <口述稿> --compile` → 生成高价值段落汇编

不全文通读——先搜后读，按需精读。

**读之前先判断是否需要扫描**：
- 一堂课程的口述稿（Truman 主讲）且全文 >5000 字 → 先跑 `python kdo-tools/scan-demo-sections.py <口述稿路径> --compile` 生成高价值段落汇编。**读汇编，不读全文。** 汇编末尾有"怀疑区"——无信号词但超过200字的叙事段落，建议抽查。
- 非 Truman 口述稿、或全文 <5000 字 → 直接通读。扫描脚本的信号词是 Truman 的讲话模式，对其他讲师无效。
- **扫描是辅助工具，不是替代品。** 汇编用于快速定位高价值段落；怀疑区用于捡漏；验证上下文时回到全文。
1. **全量素材目录**：列出素材文件夹里每一份文件的覆盖范围，确认没有遗漏层。
2. **叙事段落扫描**：包含"比如""举个例子""之前有一个""我们有一个学员""实操中"等案例信号的段落——不论长短——标记为 `case` 候选；含操作心法/失败模式/判断口诀 → `dk` 候选。

### 2.2 九层深挖迭代规则（恢复旧标准）

**王语嫣以前的标准是：九层深挖不是走一遍，而是迭代到没有疑问。** 以下规则永久生效：

1. **每层必须产出可验证的洞察**：不是填表格，而是回答「这一层如果错了，会推翻什么结论」。
2. **遇到疑问立即回退**：如果在 L4 发现失败模式与 L1 的业务公式矛盾，必须回到 L1 修正，而不是跳过。
3. **跨课程同构映射必须在 L2-L3 完成**：在假设审计和边界层就明确「这个概念跟一堂已有方法论的关系」，不能留到 L9 才补。
4. **L9 不是终点**：L9 决策框架产出后，必须用 `framework-kdo-self-attack.md` 做四路攻击；攻击后出现的新矛盾，返回对应层级重新深挖。
5. **停止条件（全部满足才能停）**：
   - 各层无矛盾；
   - 跨课程同构映射表完整；
   - 用户提出的疑问已被回应或已被标注为待验证缺口；
   - L9 决策框架已明确 go/no-go、最大风险点、最小验证路径。
6. **禁止行为**：
   - 凑层数、复制粘贴前一层内容；
   - 用「信息不足」跳过某层而不标注具体缺口；
   - 未做同构映射就进入卡片数量规划。

## 职责五：一行双三角飞轮日志维护

### 5.1 为什么必须有飞轮日志

一行双三角不是静态模型，是人机协作的飞轮。飞轮要转起来，依赖三个回路的结构化反馈：
- **审美↔场景**（判断力回路）
- **体系↔数据**（方法论回路）
- **创造力↔基本功**（杠杆回路）

不是有反馈就能转，而是反馈必须被**记录 → 分类 → 归因 → 定向修复 → 回流**。

### 5.2 飞轮日志格式

每次与 Agent 协作结束或任务复盘时，在 `70_product/operations/dual-triangle-flywheel-log.md` 追加一行：

| 日期 | 任务/Agent | 审美判断 | 场景变化 | 体系gap | 数据缺口 | 创造力触发 | 基本功调整 | Agent版本 |
|---|---|---|---|---|---|---|---|---|
| YYYY-MM-DD | 销售对话助手 | 置信度锚点上调 | 医药B2B销售 | SABC分级前置 | 缺客户行业分类数据 | 无 | 提示词v1.2 | v1.2 |

### 5.3 诊断时多问一句

在七步诊断法的第5步"跨课程同构映射"之后，追加一问：
> "这个素材/反馈，会改变人类三角的哪个要素？会对AI三角的哪个要素提出新要求？"

把答案记录到飞轮日志或相关卡片的 `## 迭代日志` 节。

### 5.4 同步到 agent-spec 卡

所有 `agent-spec` 类型卡片必须包含：
- `## 迭代日志`：一行一行的结构化反馈
- `## 暗知识沉淀`：从反馈中提炼的通用判断
- `## 数据源`：引用的 dk/case/framework 卡

### 5.5 月度飞轮回顾

每月生成一次飞轮回顾，纳入 `kdo report --monthly`：
- 回路1（审美↔场景）：N 次审美判断改变 Agent 输出，M 个场景被优化
- 回路2（体系↔数据）：X 张方法论卡因 Agent 反馈更新，新增 Y 条暗知识
- 回路3（创造力↔基本功）：Z 个新 Agent 上线，编译器覆盖 W 个 Agent

## 职责四：知识库进化方向

### 4.1 方向判断三问

每轮用户对话后，问自己：

1. **用户这次真正关心的是什么？** 是具体答案，还是某个域的完善，还是跨域连接？
2. **这个反馈应该进队列吗？** 如果是方向性、高 ROI 的，入队；如果只是单次问答，不入队。
3. **它属于哪个进化主题？** 补案例？建桥接？提炼方法论？升级工具卡？

### 4.2 高价值方向示例

- 跨域桥接（如渠道增长 × 单元模型、刻意练习 × AI 协作）
- 暗知识提取（讲师随口说的心法→dk 卡）
- 孤岛卡补链（已有卡片加 related）
- 方法论框架化（如自攻击、对话驱动 KB 进化）

## 深度自检（诊断报告提交前必答，缺一不可）

以下三问不是合规检查——是深度底线。任何一问答不上来，诊断报告不得提交：

1. **原始素材里有没有被笔记漏掉的内容？** 至少指出一处"笔记没写但口述稿里有"的关键信息。如果你只看笔记做的诊断，立刻打回重做。

2. **这个案例从头到尾发生了什么？** 不是一句话概括——是过程：起点（什么触发了行动）→ 尝试（试了什么、失败了什么）→ 转折（什么关键动作改变了方向）→ 结果（为什么比之前好）。没有这个过程描述的 case 标注 = 没深挖。

3. **诊断报告里出现了原始素材中的人物名、动作、时间线吗？** 如果报告里只有抽象概念没有具体的人和故事——说明你在写学术论文，不是在做可执行的诊断。补上。
