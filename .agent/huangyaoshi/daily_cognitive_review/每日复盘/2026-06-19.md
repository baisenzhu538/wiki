## 关键决策

1. **startup.md 作为全员入口而非新建 90_control 目录**：`.agent/` 已是必读区，放这里零增量认知负担。六段结构：启动动作→工具清单→铁律→状态→紧急注意→导航。

2. **5 条最高频铁律内联不跳转**：王语嫣的教训证明，Agent 不会主动翻引用文件。把最高频的 5 条（不跨角色派活、不改别人卡片、约束指令落笔、先查武器库、批量三问）直接写在 startup.md 里。

3. **工具登记纪律不单独成段**：放在"一、我有啥"工具表末尾，读到"有什么"自然看到"用完怎么登记"。王语嫣花 4 步才找到 RapidOCR——下次不会了。

## 思维盲点

- **把 Agent context 文件当作档案在维护**：CLAUDE.md、huangyaoshi-context.md……全部是事前设计的 Prompt。每次更新也只是人在改 Prompt，从来没有让 Agent 自己追加"做了几百轮之后我知道了什么"。王欢的档案方法论暴露了这个系统性缺口。

- **入口把关标记也有盲区**：王语嫣的标注基于结构化工整笔记（127 行），口述稿末尾的 Q&A 闲聊不在笔记里，自然不在标注里——把关本身漏了一整段高价值素材。

## 顿悟

- **Prompt 是事前写的，档案是用出来的。** Agent context 文件全是 Prompt——写了"应该怎么做"，没写"做了几百轮之后知道了什么"。王欢档案五个字段，前四个 Prompt 都能替代，唯独"行业暗规则"不能——因为它是从结果里倒推出来的，不是从设计里推导出来的。

- **KDO 工厂早就跑通了王欢的对抗式生成，只是没人意识到。** 7 个 Agent 天然形成规划器/执行器/判别器。王欢说的"生成和验收必须是两个不同的大脑"——你把它做成了 7 个不同的大脑。

## 元反思

1. **下次审查 Agent 产出时，不光看卡片质量，还要看"原材料是否被完整消费"**——口述稿全文 vs 结构化工整笔记的差距。结构化笔记是人的浓缩，已经丢了一轮信息。入口把关不能替代全文核实。

2. **每个 Agent 应该有自己的"行业暗规则"字段**——不是人写的角色定义，是 Agent 自己在工厂里跑了几百轮之后积累的隐性判断。下次给老顽童派活时，先让它写一条"上次做完这批卡之后你知道了什么"。

3. **Builder 的角色不应该只是建工具**——这次审查王欢域和写 startup.md 都超出了传统 Builder 范畴。但正是跨角色参与才产生了最关键的认知（Prompt vs 档案）。建工厂的人如果不偶尔进产线干活，建的工厂就会缺最关键的东西。
