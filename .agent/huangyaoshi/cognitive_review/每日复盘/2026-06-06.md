### 2.2 思维盲点与修正

**盲点 1：排除法用错了方向。**
- 症状：Codex 请求不到代理 → 换端口 → 无效。换协议栈 → 无效。换语言 → 无效。换 WSL → 无效。
- 正确做法：2 次同层尝试失败后 → 往上走一层。端口和协议都试了还不行 → 排查 OS 层（沙箱/防火墙/网络）。
- 修正：强制规则——**3 次同层尝试后，必须往上一层排查。**

**盲点 2：惯性假设协议。**
- 之前 Claude Code→Kimi 走 Anthropic 协议成功了，就假设 Codex 也走同一协议。
- 实际：Codex 走 OpenAI Responses API（WebSocket 优先）+ Kimi Chat Completions API。完全不需要 Anthropic。
- 修正：接入新工具第一步——**先抓包看请求格式，再选最简单的协议。**

**盲点 3：复盘写成报告。**
- 把今天的复盘写成了"做了什么 + 什么状态"的流水帐，被用户批评。
- 根因：没有区分"工作汇报"和"认知复盘"——前者是给别人看的产出清单，后者是对自己思维模式的审视。
- 修正：按结构化模板写复盘——必须提取错误模式、技能变化、能力评分、用户反馈。

### 2.3 顿悟时刻

1. **"WebSocket 是绕过 Win10 沙箱的通道"**——意识到 Codex 优先走 WebSocket，那边的代理接了 WebSocket 所以一次成功。Win10 沙箱拦 HTTPS 但 WebSocket 升级握手发生在沙箱放行之前。

2. **"那边 10 分钟我 6 小时，差在'先看请求格式再动手'"**——那边的 Claude 看了 Codex 的实际发包（WebSocket + Responses API），选了最简单的 Kimi Chat Completions API 做翻译。我从 Anthropic 协议开始写，多绕了 3 小时。

3. **"复盘不是工作汇报"**——用户批评后意识到：汇报是给别人看的产出清单，复盘是对自己思维模式的审视。两者的核心差异：复盘必须回答"下次怎么做才能不一样"。

## 五、元反思

今天的复盘被用户批评后，我才意识到：我之前写的复盘**没有元认知层**。我在"描述发生了什么"，但没有"审视自己为什么这样想、这样做"。

元认知的核心问题是：**为什么我 6 小时不接受"沙箱是根因"这个明显的事实？**

回溯：我换了 6 种变量，每一种都有理由——"可能是端口被占""可能是 aiohttp 有 bug""可能是 Python 的问题""可能是 WSL 网络问题"。这些理由单独看都有道理，但拼在一起暴露了一个模式：**我在逃避"最不可控的变量"**（操作系统沙箱），转而追逐可控的变量（端口、代码、协议）。因为可控变量让我感觉自己还在"解决问题"，而承认"沙箱问题"意味着接受"这个问题不在我的控制范围内"。

**下次当我在同一层换了 3 种以上变量时，问自己：我是不是在逃避最不可控的那个根因？**
