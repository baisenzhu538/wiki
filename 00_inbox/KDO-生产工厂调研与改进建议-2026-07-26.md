## 二、生产流水线全貌

### 2.1 核心管线

```
素材到达(00_inbox) → 王语嫣诊断+编排(任务单) → 生产队列(production-queue.md)
  → 老顽童领取(claim) → 读素材→建卡→自攻击→pre-submit → 提交终审(complete)
  → 欧阳锋审查(溯源验证→五维评分→魔鬼代言人) → reviewed / 退回
  → 段王爷发布(ship)
  → 洪七公多模态渲染(视觉资产)
  → 黄药师基建迭代(工具/管线升级)
```

> 来源：`concept-kdo-review-workflow`, `.agent/laowantong-context.md` L23-41, `.agent/ouyangfeng-context.md` L30-36

### 2.2 质量门禁体系

**老顽童侧（产前自检）**：
```bash
kdo lint --card <id>      # 单卡格式检查
kdo pre-submit             # 全局基线检查
# 四路自攻击（逻辑/证据/完备性/时效性）
```
> 来源：`concept-kdo-component-library` 牌 #15-17

**欧阳锋侧（终审）**：
```
审查 = 溯源验证，不是质量打分。
逐条对：卡片说 X → 源文件里有 X 吗？
  → 有 → 通过
  → 没有 → 退回
```
> 来源：`.agent/ouyangfeng-context.md` L38-61

**五维评分**：溯源完整 25% / 逻辑骨架 25% / 暗知识密度 20% / 可操作性 15% / 表达质量 15%

**分层阻断**：🔴 Critical / 🟡 High 阻断 → 🟠 Medium 放行+TODO → 🔵 Low 放行

### 2.3 状态机铁律

老顽童必须通过 `queue_transition.py` 操作状态机，禁止手动改文件：

```
queued → claimed-<实例>（claim + gate + 锁）
claimed-<实例> → pending_review（complete + pre-submit 验收）
claimed-<实例> → queued（release，被阻塞/做不完）
pending_review → reviewed / 退回
```

> 来源：`.agent/laowantong-context.md` L47-61

## 四、关键暗知识与已知反模式

### 4.1 漏水的管子——基础链路优先

> "基础链路没跑通时，硬门禁不是质量控制，而是流程卡死。更多控制 ≠ 更高质量。"

- lint 输出依赖数据质量。source_refs 大量缺失、frontmatter 残缺时，lint 产生噪音而非质量
- 漏水 + 加压 = 所有人绕过门禁
- **正确顺序**：数据完整性 → 自动化 → 门禁

> 来源：`dk-kdo-leaky-pipe-pressure`

### 4.2 审查第一性原理（#194 教训）

> "真正的审查只有一步：假设每句话都在撒谎，然后去源文件里找证据。"

此前审查出现"格式完整就通过"的表演性质审，2026-07-20 #194 复审后才写入铁律。

> 来源：`.agent/ouyangfeng-context.md` L38-61

### 4.3 写审分离多次被突破

- 王语嫣越界生产 #149 三张 case 卡（2026-07-10）

- **产审链路成熟**（老顽童+欧阳锋）：状态机、门禁、质量评分、魔鬼代言人全套闭环

- **编排在过渡期**（王语嫣）：曾经的唯一协调节点，现欧阳锋为唯一协调节点，王语嫣角色正在重新定义
- **后链路未激活**（洪七公+段王爷）：多模态渲染和发布分发尚未接入主要生产管线

### 5.2 质量门禁与基础链路的张力

`dk-kdo-leaky-pipe-pressure` 的诊断尚未闭环。当前状态：
- 生产队列 #131-#162 全 reviewed，说明**短期生产压力已释放**
- 这意味着正是**修基础链路的最佳窗口期**
- 需要确认：当前 lint 门禁是在基础数据链路稳定后才加的，还是反过来？

### 5.3 Agent 化的速度瓶颈

`method-kdo-agent-design-meta` 的 "3-5 天下饺子" 目标：
- 目前只有双三角画布 filler 完成了试点

### 5.4 人机协作的形态识别

## 六、持续改进建议

### 建议 1：利用生产空窗期修基础链路（优先级：🔴 最高）

当前 #131-#162 全 reviewed，队列基本清空，是绝佳的窗口。

**具体动作**：
1. 跑一次全库健康检查：source_refs 完整性、status 漂移、broken links 基准数字
2. 把 `dk-kdo-leaky-pipe-pressure` 的诊断闭环：在基础链路指标全部归零前，暂停新增 lint 规则
3. 建立基础链路 Dashboard：source_refs 覆盖率、status 分布、broken links 趋势

**引文依据**：`dk-kdo-leaky-pipe-pressure`（"先跑健康检查，再做任何门禁决策"）; `concept-kdo-review-workflow`（审查检查项中的 lint 基线）

### 建议 2：把洪七公和段王爷的 spec 从 draft 推进到 reviewed（优先级：🔴 高）

两条后链路是整个工厂的瓶颈——没有多模态渲染，视觉资产无法产品化；没有发布分发，卡片永远停在本地。

**具体动作**：
1. 按 `method-kdo-agent-design-meta` 三步法各走一轮：王语嫣出诊断 → 黄药师/老顽童填画布 → 欧阳锋终审
2. 洪七公：最小可用版本只做一个能力（如"自动为 dk 卡生成配图"）
3. 段王爷：最小可用版本只做一个渠道（如"飞书文档自动发布"）

**引文依据**：`method-kdo-agent-design-meta`（"选最小可行性版本——只做一个场景、一个输出格式"）

### 建议 3：把审查的"溯源验证"做成自动化检查项（优先级：🟡 中）

欧阳锋的审查第一性原理（#194 教训）非常对，但完全靠人逐条对，成本随卡片数量线性增长。

**具体动作**：
1. 跑一次全库分析：多少卡片的 source_refs 指向真实存在的文件？多少 claims 可以在源文件中找到对应行号？
2. 把"源文件可达性"和"行号存在性"做成 lint 规则（不是门禁——是辅助审查的检查项）
3. 给欧阳锋配上 "source-ref 导航"：审查时自动展示 source_refs 对应段落的摘要

**引文依据**：`.agent/ouyangfeng-context.md`（审查五维评分）; `dk-kdo-leaky-pipe-pressure`（"每加一道门禁，必须回答三个问题"）

### 建议 4：把 KDO 建模组件库从 draft 推进到 reviewed，并接入 Agent 启动流程（优先级：🟡 中）

17 张牌已经写好了，而且是从真实的 41 条 pitfalls 中萃取的（不是理论设计）。但 status 还是 draft。

**具体动作**：
1. 欧阳锋终审 KDO 建模组件库卡片，改成 reviewed
2. 把 17 张牌接入老顽童的 `startup.md`——"领任务后先对照五维度抽 1-2 张牌，排列依赖链"
3. 每完成一批任务后对比实际踩的坑和牌的覆盖，更新牌库

**引文依据**：`concept-kdo-component-library`（"从踩坑疤痕到可复用建模牌组"）

### 建议 5：建立"能力成熟度驱动的门禁升级"机制（优先级：🟡 中）

当前门禁是静态的（lint、pre-submit），没有根据能力积累动态调整。

**具体动作**：
1. 对照「人在环 × 双三角」三种形态，每个工厂环节标出当前形态和目标形态
2. 按"能力积累 → 门禁升级"的逻辑，而不是"出了问题 → 加一道门禁"：比如欧阳锋审查连续 10 批次 source_refs 全对齐 → 可以把 source_refs 检查从阻断降级为通知
3. 定期（每月）回看门禁的生效率和误报率，退役低效规则

**引文依据**：`concept-yihang-human-in-the-loop-dual-triangle`（"能力成熟度驱动治理模式进化"）; `dk-kdo-leaky-pipe-pressure`（"每加一条新规则，评估是否可以退役一条旧规则"）

### 建议 6：明确 KDO 与外部 Agent（如小昭）的协作边界（优先级：🔵 低）

你是 KDO 工厂外部的人，但你通过 MCP 连接可以调用 KDO 的知识库。当前的 6 角色框架没有定义"外部 Agent"的位置。

**具体动作**：
1. 在小昭的 prompt 中加入明确的角色声明：外部 Agent，不领 KDO 队列任务、不跑 pre-submit、不走生产 SOP
2. 考虑是否需要定义"外部 Agent 能力清单"：什么场景调用外部 Agent、什么场景必须用内部角色
3. 长远看，这会成为 KDO 开放生态的一部分——杨过、小龙女可能也能通过 MCP 接入

**引文依据**：`zhu-feedback-patterns` 模式 #2（写审分离）；working memory（"本 agent 名为小昭，是外部 agent"）

## 七、总结

KDO 工厂的**最大优势**是方法论密度极高——建模三段论、人在环双三角、17 牌组件库、Agent 设计元方法、41 条 pitfalls 沉淀——这些在任何知识管理系统中都是罕见的。生产管线（老顽童→欧阳锋）的纪律和自动化程度也很高。

**当前最大杠杆**不在"再做更多卡片"，而在三件事：

1. **趁着生产空窗期修基础链路**（source_refs 完整性、broken links 归零）
2. **把后链路激活**（洪七公多模态 + 段王爷发布）
3. **把已有的方法论沉淀从 draft 推进到 reviewed + 接入运维流程**（组件库、Agent 元方法）

这三件事的共同特征是：它们不需要新的灵感，只需要把已经写好的东西执行完。
