## 程诚：通信行业USP模型需求拆AI提示词教程

核心目标

通过“基础入门→进阶深化→行业适配→实战演练”四阶段提示词，引导AI以单轮/多轮对话模式，帮助使用者将业务需求拆至“可落地、无遗漏、颗粒度适配”的层级，还原需求客观真相。

### 第一阶段：基础入门——3分钟快速拆解（单轮提示词）

适用场景

需求初步梳理、快速输出核心框架，适合新手或时间紧张的场景。

通用版提示词

```markdown
我需要基于“用户-场景-问题”USP模型拆解业务需求，请按以下要求输出结构化结果：
1. 核心任务：帮我拆解【你的业务名称，例：ToB灵活用工结算服务】的需求；
2. 拆解维度（每维度至少3条关键信息）：
   - 拆用户：明确需求载体（如企业/个人、规模/属性、核心诉求优先级）；
   - 拆场景：明确需求触发器（如时间、空间、事件、约束条件）；
   - 拆问题：明确需求原动力（如用户的痛点、未被满足的诉求、潜在风险）；
3. 输出格式：
   - 业务核心定位（1句话概括）；
   - 三维拆解清单（分点列出，每条简洁具体）；
   - 初步结论（需求的核心组合：用户×场景×问题）。 
```

使用说明

1.
替换【你的业务名称】为具体业务（如“社区生鲜配送服务”“通信基站兼职结算系统”）；

2.
无需额外补充信息，AI会基于通用逻辑输出基础框架；

3.
若输出信息模糊，可进入第二阶段深化。

输出示例（通信行业灵活用工结算）

```markdown
- 业务核心定位：面向通信运营商/代维外包商，解决临时装维/网优兼职人员结算合规与效率问题的ToB服务；
- 三维拆解清单：
  1. 拆用户：
     - 主体：三大运营商运维部门、中小代维外包企业（50-200人）；
     - 属性：运营商（国企，合规优先）、代维商（民企，成本+效率优先）；
     - 诉求优先级：合规票据＞结算效率＞成本控制；
  2. 拆场景：
     - 时间：基站紧急抢修后24小时内、5G工程集中攻坚期、季度报税前夕；
     - 空间：偏远基站、城市商圈室分站点、跨区域项目现场；
     - 事件：台风后故障抢修、开学季宽带装机、运营商集采项目验收；
  3. 拆问题：
     - 合规痛点：兼职无发票，企业无票支出面临税务风险；
     - 效率痛点：分散人员对账慢，批量发薪需2-3天；
     - 应急痛点：紧急场景下结算滞后，影响兼职人员积极性；
- 初步结论：核心需求=通信行业运营商/代维商（用户）× 紧急抢修/集中工程/季度合规（场景）× 结算合规缺失/效率低/应急响应慢（问题）。 
```

### 第二阶段：进阶深化——多轮对话拆至颗粒度（引导式提示词）

适用场景

需求精细化拆解、补充隐性信息，解决“拆不细、有遗漏”的问题，核心是AI通过追问引导使用者完善信息。

通用版提示词（首轮触发）

```markdown
我需要基于“用户-场景-问题”USP模型深度拆解【你的业务名称】需求，麻烦你以“提问引导+结构化输出”的方式帮我推进，具体要求：
1. 首轮输出：先列出3个核心追问（分别对应“用户、场景、问题”维度），帮我补充关键信息（示例：用户是否有分层？场景是否有约束条件？问题是否有优先级？）；
2. 后续流程：我回复你的追问后，你再输出“三维拆解细化清单”，并继续提出1-2个深化追问（如用户分层的具体差异？场景中的时间节点是否明确？）；
3. 最终输出：当信息足够时，生成“颗粒度达标”的拆解报告，包含：
   - 用户分层（按属性/诉求/决策链拆分）；
   - 场景细分（按时间/空间/约束/事件拆分，标注核心场景）；
   - 问题深挖（按痛点类型/优先级/影响范围拆分）；
   - 需求本质总结（用户×场景×问题的核心组合）。 
```

使用说明

1.
替换【你的业务名称】后发送，AI会先发起追问；

2.
按实际业务情况回复追问，无需担心信息不全（AI会逐步引导）；

3.
当AI判断信息足够时，自动输出精细化拆解报告，若仍需补充可主动说明。

```markdown
### 三维拆解细化清单
1. 拆用户（分层+决策链+诉求）：
   - 运营商（大型国企）：
     - 决策链：代维管理中心发起需求→财务部门审核合规性→集采部门定服务商；
     - 核心诉求：合规（需税务备案、四流合一）＞应急（24小时发薪）＞效率（批量对账）；
     - 禁忌点：拒绝无代征资质的平台，不接受复杂的操作流程；
   - 代维商（中小民企50-200人）：
     - 决策链：项目负责人（痛点发起）→财务（成本核算）→老板（最终拍板）；
     - 核心诉求：合规（无票支出解决方案）＞效率（一键导入对账）＞成本（按结算金额比例付费，0预存）；
     - 禁忌点：高费率、需专职人员操作的平台；
2. 拆场景（细分+约束+核心标注）：
   - 紧急抢修场景（核心）：
     - 时间：故障后12小时内招人、完成后24小时内发薪；
     - 空间：偏远基站、灾害现场（无固定办公环境）；
     - 约束：人员分散、身份信息收集急、需快速对账；
   - 集中工程场景（高频）：
     - 时间：季度5G基站新建期、开学季/交房季（1-3个月）；
     - 空间：多站点（跨区域）、工程现场；
     - 约束：按工程节点（通电/验收）结算、批量人员（100+）、跨区域税务差异；
   - 季度合规场景（刚需）：
     - 时间：季度末报税前夕（10天内）；
     - 空间：企业办公室（电脑操作）；
     - 约束：需补充所有兼职结算票据、对接财务系统；
3. 拆问题（类型+优先级+影响）：
   - 合规类问题（P0优先级）：
     - 运营商：无票支出导致税务稽查风险，需四流合一凭证；
     - 代维商：兼职无发票，企业所得税多缴25%，无合规入账凭证；
   - 效率类问题（P1优先级）：
     - 运营商：跨区域人员对账需人工2-3天，易出错；
     - 代维商：手动导入兼职信息+工时，耗时且易遗漏；
   - 应急类问题（P1优先级，运营商专属）：
     - 紧急抢修时结算流程长（1-2天），兼职人员响应积极性低；
   - 成本类问题（P2优先级，代维商专属）：
     - 传统结算平台费率高（1.5%以上），长期使用成本高；

后续追问：运营商的财务系统是否有特定对接要求（如用友/金蝶）？代维商的兼职人员数据是否有固定格式（如Excel模板）？ 
```
