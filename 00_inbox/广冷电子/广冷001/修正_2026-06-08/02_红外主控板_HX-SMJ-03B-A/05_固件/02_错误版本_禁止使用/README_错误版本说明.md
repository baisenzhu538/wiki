# 红外板固件版本说明

## 警告：存在错误版本固件

经独立源码分析，红外板固件存在**多个版本族**，其中仅**一个版本正确**，其余版本存在**致命功能缺陷**。

---

## 正确版本（唯一基线）

**文件**: `ir.c`（现场调试成功版）
**路径**: `广冷-代码固件/广冷-现场调试-红外代码/广冷红外板--现场调试成功版/.../DRIVE/ir/ir.c`

### 关键特征

| 参数 | 正确值 | 说明 |
|:-----|:-------|:-----|
| 扫描路数 | `IrTask.no%=16` | 16路全扫描 |
| 发射掩码 | `mask=0x0001<<no` | 单路依次点亮，无串扰 |
| QD通道 | QD1~QD4 **全部启用** | 4组发射管全部驱动 |
| 接收判断 | `IN1&&IN2&&IN3&&IN4` | 四路冗余检测 |
| 状态存储 | `sta=0xFFFF` (u16) | 16位状态 |
| 延时 | `Ir_Delay(15)` | RCLK后15个空循环 |

### 功能表现
- 16路红外光栅全部正常工作
- 单路依次点亮，无串扰
- 四路接收冗余，可靠性高
- 支持16货道完整检测

## 错误版本（禁止使用）

### 错误版本A：03_firmware版

**文件**: `03_firmware/红外板/ir.c`

| 参数 | 错误值 | 后果 |
|:-----|:-------|:-----|
| 扫描路数 | `IrTask.no%=8` | **只扫描8路，另一半货道失效** |
| 发射掩码 | `mask=0x0101<<no` | **同时点亮两路，产生串扰** |
| QD通道 | QD3 **被注释掉** | 第3组发射管永远不亮 |
| 接收判断 | `IN3&&IN4` | **忽略IN1/IN2，冗余减半** |
| 状态存储 | `sta=0xFF` (u8) | 只能存8路状态 |

### 错误版本B：黄工版

**文件**: `广冷-代码固件/黄工资料电脑-源码/.../ir.c`

- 与错误版本A特征相同
- 来源标注为"黄工资料电脑-源码"

### 错误版本C：修改测试版

**文件**: `广冷-代码固件/广冷-现场调试-红外代码/修改测试/.../ir.c`

- 与错误版本A特征相同

## 风险对比

```
正确版：  16路扫描 → 单路点亮 → 四路接收冗余 → 100%货道检测
错误版：   8路扫描 → 双路串扰 →  两路接收判断 →  50%货道失效+误判
```

**生产风险**：如果生产线误烧录错误版本，设备出厂后：
1. **一半货道无法检测货物**（no%=8只扫描8路）
2. **存在串扰导致的误判**（mask=0x0101同时点亮两路）
3. **第3组发射管永远不亮**（QD3被注释）

这是会导致客户退货的致命缺陷。

---

## 生产烧录校验清单

烧录红外板固件前，必须核对以下源码特征：

- [ ] `mask=0x0001<<no`（不是0x0101）
- [ ] `IrTask.no%=16`（不是8）
- [ ] QD1~QD4全部启用（QD3未被注释）
- [ ] 接收判断为`IN1&&IN2&&IN3&&IN4`（不是仅IN3&&IN4）
- [ ] `sta=0xFFFF`（不是0xFF）

**建议**：制作"全通道自检固件"作为生产测试标准工序，逐路点亮发射管+检测接收。

## 故障根因重新判断

欧阳锋故障报告（2026-06-04）将根因归结为"SN74LVC2G07开漏输出导致RCLK上升沿变缓"，修复方案为：
1. RCLK拉高后加`Ir_Delay(200)`
2. 接收判断改为分段检测

**但"现场调试成功版"源码中实际为**：
- `Ir_Delay(15)`（不是200）
- `IN1&&IN2&&IN3&&IN4`（不是分段检测）

**重新判断**：故障的真正根因可能**不是RCLK上升沿**，而是**错误版本固件本身**（QD3被注释、只扫8路、双路串扰）。实习生从黄工版出发修改，引入了新错误；而"现场调试成功版"是黄工在V2.0上亲自调通的原始正确版本。
