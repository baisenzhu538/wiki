## 一、项目全貌与系统架构

### 1.1 项目背景

广冷电子 HX-SMJ 项目是一款自动售货机控制系统，包含以下核心模块：

| 模块 | 板卡型号 | 功能定位 | 复杂度 |
|:-----|:---------|:---------|:-------|
| **主控板** | HX-SMJ-01B | 整机控制核心：MCU、电源、通信、电机驱动、温度控制 | 高 |
| **红外主控板(A)** | HX-SMJ-03B-A | 红外光栅发射/接收主控，管理货道检测 | 中 |
| **红外从控板(B)** | HX-SMJ-03B-B | 红外光栅从控，配合A板完成货物检测 | 中 |
| **继电器板** | HX-SMJ-01-1 | 6路继电器扩展，控制货道电磁锁/电机 | 低 |
| **安卓板** | 外购 | 上位机显示与交互（另行项目分析） | - |

### 1.2 系统连接关系

```
                    +-------------+
                    |   安卓板    |  (外购上位机)
                    |  (上位机)   |
                    +------+------+

        +-----------+   主控板    +-----------+
        |           | HX-SMJ-01B  |           |
        |           |  STM32ZET7  |           |
        |           +------+------+           |
        |                  |                   |
   CAN总线            6路GPIO            13路电机驱动
        |                  |                   |
   +----+----+      +------v------+      +-----+-----+

   |03B-A    |      | HX-SMJ-01-1 |      |  (13通道)  |
   +----+----+      +-------------+      +-----------+
        | 红外对射
   +----v----+
   |红外B板  |

   +---------+
```

| BOM -> Gerber | 层文件齐全 |

### 3.4 原理图验证发现的问题

| 问题 | 位号 | 原理图 | BOM/PCB | 影响 |
|:-----|:-----|:-------|:--------|:-----|
| 1. 缓冲器型号错误 | U11-U13 | SN74LVC**1**G07DBVR (单路) | SN74LVC**2**G07DBVR (双路) | 中：功能可实现，但封装不匹配 |
| 2. 电容缺失 | C35 | 未标注 | 10uF/25V钽电容 | 低：AMS1117输出滤波，影响电源稳定性 |

**问题1说明**: 1G07是SOT-23-5单路缓冲器，2G07是SOT-23-6双路缓冲器。PCB焊盘为6脚，若贴1G07会空一脚，功能上单路缓冲器也能工作，但非最佳设计。

**问题2说明**: C35为AMS1117-3.3输出端滤波电容，缺失会导致LDO输出纹波增大，影响红外MCU电源质量。

### 3.5 固件源码关键发现（🔴 致命风险）

**独立验证确认**：红外板固件存在**多个版本**，经逐行源码比对，仅**一个版本完全正确**，其余版本存在**致命功能缺陷**。

#### 版本族完整比对（独立验证结果）

| 版本 | 路径 | mask | QD3 | 接收判断 | sta | no% | 验证状态 | 结论 |
|:-----|:-----|:-----|:-----|:---------|:-----|:-----|:---------|:-----|
| **现场调试成功版** | `广冷红外板--现场调试成功版/.../ir.c` | `0x0001<<no` | 启用 | `IN1&&IN2&&IN3&&IN4` | `0xFFFF` | 16 | ✅ 已验证 | **唯一正确基线** |
| 新修改-测试版 | `修改测试/新修改-测试/.../ir.c` | `0x0001<<no` | 启用 | `IN1&&IN2&&IN3&&IN4` | `0xFFFF` | 16 | ✅ 已验证 | ⚠️ 接近正确（switch仍no%8） |
| 修改-测试版 | `修改测试/修改-测试/.../ir.c` | `0x0001<<no` | 启用 | `IN1&&IN2&&IN3&&IN4` | `0xFFFF` | 16 | ✅ 已验证 | ⚠️ 接近正确（switch仍no%8） |
| 修改测试版 | `修改测试/.../ir.c` | `0x0001<<no` | 注释 | `IN3&&IN4` | `0xFF` | 8 | ✅ 已验证 | ❌ 部分修正（mask对了，其余仍错） |
| 03_firmware版 | `03_firmware/红外板/ir.c` | `0x0101<<no` | 注释 | `IN3&&IN4` | `0xFF` | 8 | ✅ 已验证 | ❌ 错误版本 |
| 黄工版 | `黄工资料电脑-源码/.../ir.c` | `0x0101<<no` | 注释 | `IN3&&IN4` | `0xFF` | 8 | ✅ 已验证 | ❌ 错误版本（与03版完全相同） |

**验证方法**：逐行读取6个版本的ir.c源码，提取mask、QD3、接收判断、sta、no%五个关键参数进行比对。

#### 正确版本关键特征（现场调试成功版）

| 关键参数 | 正确值 | 说明 |
|:---------|:-------|:-----|
| 扫描路数 | `IrTask.no%=16` | 16路全扫描 |
| 发射掩码 | `mask=0x0001<<no` | 单路依次点亮，无串扰 |
| QD通道 | QD1~QD4 **全部启用** | 4组发射管全部驱动 |
| 接收判断 | `IN1&&IN2&&IN3&&IN4` | 四路冗余检测，可靠性高 |
| 状态存储 | `sta=0xFFFF` (u16) | 16位状态，支持16路 |
| 延时参数 | `Ir_Delay(15)` | RCLK拉高后15个空循环 |

#### 错误版本关键特征（03_firmware版/黄工版）

| 关键参数 | 错误值 | 后果 |
|:---------|:-------|:-----|
| 扫描路数 | `IrTask.no%=8` | **只扫描8路，另一半货道失效** |
| 发射掩码 | `mask=0x0101<<no` | **同时点亮两路，产生串扰** |
| QD通道 | QD3 **被注释掉** | 第3组发射管永远不亮 |
| 接收判断 | `IN3&&IN4` | **忽略IN1/IN2，冗余减半** |
| 状态存储 | `sta=0xFF` (u8) | 只能存8路状态 |
| 延时参数 | `Ir_Delay(15)` | 与正确版相同 |

#### 风险对比

```
正确版：  16路扫描 → 单路点亮 → 四路接收冗余 → 100%货道检测
错误版：   8路扫描 → 双路串扰 →  两路接收判断 →  50%货道失效+误判
```

**生产风险**：如果生产线误烧录错误版本，设备出厂后**一半货道无法检测货物**，且存在**串扰导致的误判**（明明有货却报无货，或反之）。这是会导致客户退货的致命缺陷。

#### 故障根因重新判断（⚠️ 逻辑推断，待硬件验证）

欧阳锋故障报告（2026-06-04）将根因归结为"SN74LVC2G07开漏输出导致RCLK上升沿变缓"，修复方案为：
1. RCLK拉高后加`Ir_Delay(200)`
2. 接收判断改为分段检测

**独立源码验证发现问题**：

| 修复项 | 故障报告声称 | 现场调试成功版实际源码 | 结论 |
|:-------|:-------------|:----------------------|:-----|
| Ir_Delay(200) | "RCLK拉高后加200" | 实际为`Ir_Delay(15)` | ❌ 修复未在成功版中体现 |
| 分段检测 | "no<8→IN1&&IN3" | 实际为`IN1&&IN2&&IN3&&IN4` | ❌ 成功版未采用分段检测 |

**重新判断（逻辑推断，待示波器验证）**：故障的真正根因可能**不是RCLK上升沿**，而是**错误版本固件本身**（QD3被注释、只扫8路、双路串扰）。实习生从黄工版出发修改，引入了新错误；而"现场调试成功版"是黄工在V2.0上亲自调通的原始正确版本。

**建议**：在V2.2硬件上用示波器实测RCLK上升沿时间，确认`Ir_Delay(15)`是否足够，而不是盲目加200。
