# 广冷电子主控板三版本固件深度比对报告

> 分析对象：GL_V5.1.2.hex（最新兼容版）vs GLHX_ZKB_V4.4.8（旧标准版）vs YXG_V3.9.6（旧安卓版）  
> 分析方法：二进制逆向分析、字符串提取、地址空间比对、协议特征识别  
> 分析目的：判断 GL_V5.1.2 的底层逻辑、代码血缘、功能差异及兼容性实现方式

---

## 二、核心发现：代码血缘关系

### 🔴 关键结论：GL_V5.1.2 的 Bootloader 与 YXG（安卓版）几乎完全相同

| 比对项 | GL_V5.1.2 vs YXG | GL_V5.1.2 vs GLHX_ZKB | GLHX_ZKB vs YXG |
|--------|-----------------|------------------------|----------------|
| **Bootloader差异** | **仅 72 字节** | **4,683 字节** | **4,678 字节** |
| **Application共同地址** | 117,348 个 | 117,348 个 | 117,348 个 |
| **Application差异字节** | 113,976 个 (97%) | 114,602 个 | 113,976 个 |

**底层逻辑判断：**

1. **GL_V5.1.2 是基于 YXG（安卓版）的 Bootloader 升级的**，而不是基于 GLHX_ZKB（标准版）
2. Bootloader 仅 72 字节差异，说明使用的是**同一套 IAP 升级架构**（相同的 Bootloader 源码，可能仅修改了版本号或跳转地址）
3. GLHX_ZKB 使用了**完全不同的 Bootloader**（6KB vs 5KB，差异巨大），说明它的 IAP 架构是独立开发的

## 三、Application 深度差异分析

### 3.1 内存布局对比

| 区域 | GL_V5.1.2 | GLHX_ZKB | YXG |
|------|-----------|----------|-----|
| Bootloader (0-6KB) | 5.0 KB | 6.0 KB | 5.0 KB |
| App Low (6-64KB) | 58.0 KB | 58.0 KB | 58.0 KB |
| App High (64-128KB) | 56.6 KB | 64.0 KB | 58.3 KB |
| App Extended (128KB+) | ❌ 无 | 15.6 KB | ❌ 无 |
| **总段数** | 2段 | 1段(连续) | 2段 |

**关键发现：**
- GLHX_ZKB 是唯一使用 **128KB 以上扩展区域** 的固件，说明它的功能最复杂、代码量最大
- GL_V5.1.2 和 YXG 都限制在 128KB 以内，说明它们针对的是较小的 Flash 容量或更精简的功能集

### 3.2 函数调用复杂度

| 固件 | Application 函数调用数 | 复杂度评估 |
|------|----------------------|-----------|
| GLHX_ZKB | ~8,183 | ⭐⭐⭐⭐⭐ 最复杂 |
| YXG | ~7,191 | ⭐⭐⭐⭐ |
| GL_V5.1.2 | ~7,076 | ⭐⭐⭐⭐ 最精简 |

**结论：GL_V5.1.2 是精简优化版**，比 YXG 减少了 ~115 个函数调用，比 GLHX_ZKB 减少了 ~1,100 个。

### 4.3 服务器配置差异

| 固件 | 服务器地址 | 端口 | 协议 |
|------|-----------|------|------|
| GL_V5.1.2 | `zd.jumiai.cn` | 1883 | TCP/MQTT |
| GLHX_ZKB | `39.96.10.250` | 11883 | TCP |
| YXG | `zd.jumiai.cn` | 1883 | TCP/MQTT |

**关键发现：**
- GL_V5.1.2 和 YXG 使用**相同的服务器**（zd.jumiai.cn:1883）
- GLHX_ZKB 使用**不同的服务器**（39.96.10.250:11883）
- 这说明 GL_V5.1.2 在**云端协议层继承了 YXG 的配置**，而不是 GLHX_ZKB

### 4.4 协议栈结论

| 维度 | 结论 |
|------|------|
| **4G模块** | GL_V5.1.2 采用 EC20（与 GLHX_ZKB 相同），YXG 采用 Air720/有人模块 |
| **WiFi模块** | 三者都支持 ESP32，但 AT 指令集不同 |
| **服务器** | GL_V5.1.2 继承 YXG 的服务器配置 |
| **协议复杂度** | GL_V5.1.2 精简了多模块支持，只保留 EC20+ESP32 |

## 六、兼容性实现方式分析

### 6.1 "兼容安卓版和标准版"的技术实现

根据二进制分析，GL_V5.1.2 的兼容性可能通过以下方式实现：

| 层面 | 实现方式 | 证据 |
|------|---------|------|
| **Bootloader** | 复用 YXG 的 Bootloader（IAP架构） | 仅72字节差异 |
| **网络协议** | 融合 GLHX_ZKB 的 EC20 协议 + YXG 的服务器配置 | 使用 QIOPEN 但连接 zd.jumiai.cn |
| **云端协议** | 可能同时支持两种协议格式 | 需运行时抓包确认 |
| **硬件驱动** | 统一使用相同的 GPIO 映射 | 与 BOM 完全匹配 |
| **显示接口** | 可能通过运行时检测选择 DGUS 或 Android | 无字符串证据，需硬件确认 |

### 6.2 与源码文件的关联

从之前分析的源码文件看，固件中存在以下兼容机制：

```c
// 来自 wireless_module_init.h
#define WEIRELESS_MODULE_TYPEDEF_EC20    0x01
#define WEIRELESS_MODULE_TYPEDEF_ESP32    0x02

// 来自 usart.h - UART 使能配置
#define UART1_ENABLE  1  // DGUS屏
#define UART2_ENABLE  0  // 预留
#define UART3_ENABLE  0  // 预留
```

**推断：** GL_V5.1.2 可能在编译时通过宏定义切换功能模块：
- 标准版：`UART1_ENABLE=1, UART2_ENABLE=0, UART3_ENABLE=0`（仅 DGUS）
- 安卓版：`UART1_ENABLE=1, UART2_ENABLE=1`（DGUS + Android）

## 七、风险评估与建议

### 7.1 潜在风险

| 风险编号 | 风险描述 | 等级 |
|---------|---------|------|
| 1 | **内部版本号不一致**：文件名 V5.1.2，内部显示 V5.0.0 | 🟡 中 |
| 2 | **服务器地址变更**：从 39.96.10.250 改为 zd.jumiai.cn | 🟡 中 |
| 3 | **Bootloader 与 YXG 相同**：如果 YXG 有已知漏洞，GL_V5.1.2 也可能受影响 | 🟡 中 |
| 4 | **功能精简**：比 GLHX_ZKB 小 24KB，可能删除了某些功能 | 🟡 中 |
| 5 | **OTA 标识变更**：从 YXG_V 改为 XYJ_V，可能影响云端识别 | 🟡 中 |

### 7.2 建议验证事项

1. **硬件兼容性测试**：将 GL_V5.1.2 烧录到标准版主板，验证所有 GPIO 功能是否正常
2. **网络通信抓包**：验证它实际连接的服务器地址和协议格式
3. **DGUS/Android 切换**：验证运行时是否能自动识别显示模块类型
4. **OTA 升级测试**：验证 OTA 下载和烧录功能是否正常
5. **温度控制验证**：验证 3 区制冷/制热功能是否正常
6. **电机驱动验证**：验证 13 路货道电机 + 步进电机是否正常

## 八、最终结论

### 8.1 代码血缘结论

```
YXG_V3.9.6 (安卓版, 2020)
    ↓ Bootloader 复用 (99% 相同)
    ↓ Application 重写 (97% 不同)
    ↓ 网络协议精简 (删除有人模块/Air720，保留 EC20+ESP32)
    ↓ 服务器配置继承 (zd.jumiai.cn)
GL_V5.1.2 (最新兼容版, 2025)

GLHX_ZKB_V4.4.8 (标准版, 2021)
    ↓ 独立的 Bootloader (完全不同)
    ↓ 更大的代码体积 (143.6 KB)
    ↓ 不同的服务器 (39.96.10.250)
    ↓ 更完整的协议栈
```

### 8.2 兼容性实现方式

GL_V5.1.2 的"兼容安卓版和标准版"是通过以下技术路径实现的：

1. **基于安卓版（YXG）的 Bootloader**：保证 IAP 升级架构兼容
2. **重写 Application**：融合标准版的 EC20 4G 协议栈 + 安卓版的服务器配置
3. **精简多模块支持**：删除 YXG 中的有人模块/Air720 支持，只保留 EC20+ESP32
4. **统一的硬件抽象层**：使用相同的 GPIO 映射，兼容同一套 PCB 硬件
5. **可能的运行时检测**：通过硬件跳线或自动检测切换 DGUS/Android 模式

### 8.3 对项目的影响

| 维度 | 影响 |
|------|------|
| **BOM 正确性** | ✅ 不受影响，GL_V5.1.2 与 BOM 的器件完全匹配 |
| **原理图更新** | ⚠️ 仍需更新，但固件验证表明 GPIO 定义正确 |
| **生产烧录** | ⚠️ 需确认烧录的是哪个版本（标准/安卓/兼容） |
| **云端对接** | ⚠️ 需确认服务器地址和协议格式 |
| **售后维护** | 🔴 风险：无源码，只有 hex 文件，后续维护困难 |
