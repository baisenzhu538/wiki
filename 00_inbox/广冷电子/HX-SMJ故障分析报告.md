# 广冷电子 — HX-SMJ 红外光栅故障分析报告

> 分析日期：2026-06-04
> 分析人：欧阳锋（Architect）
> 背景：离职工程师留下的红外对射板资料混乱，2025-11 批次存在"斜着对射"故障

---

## 一、项目全景

### 系统架构

这是一个**自动售货机红外光栅检测系统**，共 6 种电路板：

| 板号 | 名称 | 说明 |
|:----|:-----|:------|
| HX-SMJ-01B | **主控板** | STM32F103ZE MCU，CAN 总线主节点 |
| HX-SMJ-03B-A | **红外板-A（主控红外板）** | V2.2 自带 STM32F103RCT7 |
| HX-SMJ-03B-B | **红外板-B（外设红外板）** | 无 MCU，通过 20pin 排线连 A 板 |
| HX-SMJ-01 | 继电器板 | — |
| HX-SMJ-04B | 货道电机板 | — |
| HX-SMJ-02 | 4G/WiFi 通信板 | — |

### 红外板核心芯片方案（V2.2）

```
发送通道（16路）：
  STM32 → QD1/QD2 → SN74LV595 (×2) → AP2302B MOSFET (×16) → IR333C-A 红外发射管

接收通道（16路）：
  PT334-6B 接收管 → LMV358IDR 运放 → CD4051BPWR 多路器 (×2) → STM32
```

## 三、故障现象

- 正常情况：A 板第 N 路发射 → 直线 → B 板第 N 路接收
- 实际：**B 板上排对 A 板下排才能工作**（通道错位）

---

## 四、根本原因（双重错位）

### 错位一：硬件架构变化（V2.0 → V2.2）

V2.2 不是简单修改，是**完整的 PCB 重新设计**：

| 改动项 | V2.0 | V2.2 | 影响 |
|:------|:----|:----|:-----|
| 红外板 MCU | 无（被动板） | **自带 STM32F103RCT7** | 架构完全不同 |
| 电源域 | 统一供电 | **3.3V + 5V 隔离（U7 稳压器）** | 信号需电平转换 |
| 595 数据线 | QD1 + QD3（2条） | **QD1/QD2/QD3/QD4（4条）** | 🔴 |
| LED 连接方式 | 可能直焊 | **独立端子 X01-X016** | — |
| 元件数（A板） | ~111 个 | ~260 个 | 翻倍 |
| 元件数（B板） | ~80 个 | ~196 个 | 翻倍 |

### 错位二：固件没跟上硬件

**固件是写给 V2.0 架构的，但实物是 V2.2。**

| 固件中的 GPIO | V2.0 用法 | V2.2 实际需要 |
|:------------|:---------|:------------|
| QD1 (PC6) | A板 595 #1 数据 | ✅ 正确 |
| QD2 | **不存在** | ⚠️ A板 595 #2 数据 — **固件没驱动** |
| QD3 (PC15) | B板 595 #1 数据 | ✅ 正确 |
| QD4 | **不存在** | ⚠️ B板 595 #2 数据 — **固件没驱动** |

### 两个错位叠加的后果

```
固件以为：  QD1 → 级联2个595 → 16路（A板）
           QD3 → 级联2个595 → 16路（B板）

实际 V2.2： QD1 → 595 #1（8路，A板）
           QD2 → 595 #2（另8路，A板）← 没人驱动
           QD3 → 595 #1（8路，B板）
           QD4 → 595 #2（另8路，B板）← 没人驱动
```

第二片 595 没收到数据，16 路中只有 8 路在工作→**通道错位→斜着对射**

## 六、V2.2 PCB 与 V2.0 的详细差异

### 6.1 增加的 IC（V2.2 有，V2.0 无）

- **U7**：SOT-223 稳压器（3.3V 电源域）
- **U9**：额外 SN74LVC2G07（电平转换）
- **V2.2 A 板有自己的 STM32F103RCT7**（LQFP-64）

### 6.2 电阻网络变化（关键区域）

位置 ~X=185-200mm（靠近 J2 连接器）：

```
V2.0: R17(100k)-R18(1k)-R19(100k)-R20(100k)-R21(1k)-R22(100k)-R23(8.2k)-R24(1k)
V2.2: R17(9.1k)-R18(1k)-空-空-R20(9.1k)-R21(1k)-R96(6.8k)-R95(24k)
```

- R19/R22 **已被 PCB 设计删除，没有焊盘**，焊不上去，也不需要焊
- R17/R20 从 100kΩ 改为 9.1kΩ（MOSFET 栅极开关加速）

### 6.3 LED 限流

| 版本 | 限流电阻 | LED 峰值电流 |
|:----|:-------:|:-----------:|
| V2.0 | 91Ω | ≈37mA |
| V2.2 | **51Ω** | ≈67mA（↑1.8 倍，信噪比更高）|

### 6.4 V2.2 的设计意图

V2.2 是一次有目的的信号完整性改版，不是腐败：

| 改动 | 目的 |
|:----|:-----|
| 3.3V/5V 电源隔离 | 数字噪声不串扰模拟信号 |
| SN74LVC2G07 电平转换 | 3.3V→5V 施密特整形，抗干扰 |
| R1~R16 8.2k→2k | MOSFET 栅极加速，匹配 500μs 扫描窗口 |
| R25 91Ω→51Ω | LED 电流增大，提高信噪比 |
| 独立 LED 端子 | 方便生产和维护 |

## 六、卡住的问题（待硬件工程师介入）

经过全部资料分析后，以下问题需要 **示波器实测** 才能确认：

1. **STM32 GPIO 与原理图是否一致**——原理图标题栏是 2021 年的，需实测确认 QD1/SRCLK/RCLK 接到 STM32 的哪几个脚
2. **电平转换器是否引入时延**——CD4051 的地址线（A/B/C）经过 SN74LVC2G07 从 3.3V 转到 5V，可能比固件切地址到读数的间隔还慢，导致读到上一个通道的值
3. **运放阈值是否偏移**——R17/R20 从 100kΩ 改为 9.1kΩ，LMV358 的参考电压变了，可能影响某些通道的信号判定

这三个问题都只需要 **示波器看一眼波形** 就能确认。

## 七、修复方案

### 修复方式：只改固件，不改硬件

在 `Ir_Select_Send()` 中增加 QD2 和 QD4 的驱动：

```c
// 需要加的代码：
IR_595_QD2 = ...;  // A板 595 #2 的数据线
IR_595_QD4 = ...;  // B板 595 #2 的数据线
```

### 关键待确认信息

**QD2 和 QD4 在 V2.2 红外板-A 的 STM32 上对应哪个 GPIO？**

最可能：
- **QD2 = PC7**（PC6 的相邻引脚，STM32F103RCT7 的 pin 17）
- 需要实测确认

确认方法：用万用表量红外板-A 上第二片 SN74LV595（U5）的 14 脚（SER）→ 通到 STM32 哪个脚。
