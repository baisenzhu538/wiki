# PCB 生产闭环 · Feature 组合方案 + 提示词草稿

> 对应课程：AI 基本功第一课《Feature 思维》
> 对应意图：用户老朱定义的**意图 1——生产闭环**（用 AI 识别 PCB 版图，最终产出"可外发制造的资料包 + 固件烧录 SOP"）
> 用法：本文件是"意图一定，Feature 组合自己跳出来"的实战示范。下面先讲组合，再给可复制的提示词。

---

## 一、为什么"丢张图让 Kimi 硬看"达不到

你现在的做法只动了 **1 个 Feature：多模态**（让模型看懂图）。
但你要的产物是**两个业务级可交付物**，不是"这张板有啥器件"的描述：

- A. 可外发制造的资料包（Gerber + 坐标文件 + BOM 表）——板厂拿去就能做板
- B. 固件烧录 SOP——告诉你怎么把正确固件烧进去、保证不出问题

只靠多模态，模型给你的是**描述**（散文），不是**结构化制造资料**。差的正是后面那串 Feature。
所以方案的本质 = **多模态只是起点，后面那串才是把意图兑现的关键**。

---

## 二、Feature 组合方案（意图 1 生产闭环）

| Feature（课程层级） | 在"生产闭环"里具体干啥 | 是否 Kimi 纯识图能做 |
|---|---|---|
| **多模态**（L2） | 看 PCB 图，识别器件、丝印、封装 | ✅ 已在用 |
| **任务拆解**（L3） | 把"看图→出制造包"切成：识别→坐标→校验→出 BOM→写烧录 SOP，逐步做 | ✅ 靠提示词 |
| **CoT 思维链**（L3） | 让模型推导"从图到可制造文件"的步骤、烧录流程怎么写 | ✅ 靠提示词 |
| **结构化输出**（L4） | 吐 BOM 表 / 坐标 JSON，不是散文——板厂和程序接得住 | ✅ 靠提示词 |
| **Few-shot**（L4） | 给 1–2 个 BOM/坐标格式范例，模型照葫芦画瓢 | ✅ 靠提示词 |
| **角色**（L4） | "你是 20 年经验的 PCB 设计工程师"，定语气和判断标准 | ✅ 靠提示词 |
| **代码执行**（L5） | 用 Python 算坐标、校验引脚对应、生成网表辅助 | ❌ 需带 code interpreter 的环境 |
| **RAG**（L2） | 调你的历史设计库 / 元件数据库 / 过往成功 Gerber，做一致性校验（防老型号搞错） | ❌ 需接知识库 |
| **工具调用 / Function Calling**（L5） | 直接调 EDA（立创/Altium）导出制造包，而不是让模型"想象"坐标 | ❌ 需接 EDA API |

**关键判断**：前 6 个（多模态→角色）是"提示词层 Feature"，你现在的环境（Kimi/通用大模型）**马上能用**；后 3 个（代码执行/RAG/工具调用）是"环境能力 Feature"，需要**飞书 Agent（配代码执行+知识库）或带 code interpreter 的模型**才能兑现。

所以下面给**两份提示词**：
- **草稿 A**：Kimi/通用大模型现在就能跑（覆盖前 6 个 Feature，先把"BOM+坐标+烧录 SOP 文本"跑出来）
- **草稿 B**：飞书 Agent 完整版（在 A 基础上加代码执行 / RAG / 工具调用指令，逼近"可外发制造包"）

## 三、分阶段任务拆解（串起所有 Feature）

把大任务切成 6 步，每步只喂当前需要的信息（**渐进披露**：一次一张图、一次一个区域，别一次全灌——正好治你"上下文过长走神"的痛）：

1. **阶段 0 · 意图确认（L0）**：上传图，AI 先复述"我要产出什么"，你确认范围（防止跑偏）
2. **阶段 1 · 器件识别**：多模态 + 结构化输出 → 产出 BOM 草稿（器件/料号/封装/数量）
3. **阶段 2 · 坐标提取**：多模态 + 结构化输出 → 产出坐标文件（器件→x,y,角度）
4. **阶段 3 · 校验（代码执行）**：Python 校验引脚对应、封装匹配；RAG 对照历史库防错
5. **阶段 4 · 烧录 SOP（CoT）**：推导"怎么把正确固件烧进去、不出问题"的步骤清单
6. **阶段 5 · 打包输出**：结构化汇总成可外发资料包（BOM+坐标+烧录 SOP）

---

## 四、提示词草稿 A（Kimi / 通用大模型 · 现在就能跑）

> 适用：你今天就能复制到 Kimi 或任意支持识图的大模型。**一次只传一张图**。
> 覆盖 Feature：角色 / 任务拆解 / CoT / 结构化输出 / Few-shot / 多模态。

```
你是一位有 20 年经验的 PCB 设计工程师，专做可量产电路板的 DFM（可制造性设计）审核。

我的目标（最终意图）：
我给你一张 PCB 版图（照片或截图）。请你帮我把它转成"可外发制造"的资料，最终我要两样东西：
1）一份结构化的 BOM 表 + 器件坐标清单（板厂拿去就能贴片）；
2）一份固件烧录 SOP（告诉我怎么把正确固件烧进去、保证不出问题）。

请严格按下面 5 步来，每步做完再进下一步（不要一次性全写完）：

第 1 步｜意图确认
先复述你理解的任务范围，等我回"继续"再往下。

第 2 步｜器件识别（BOM 草稿）
识别图中所有器件，按下面格式输出（这是范例，照这个结构来）：
| 序号 | 器件名称 | 推测料号/型号 | 封装 | 数量 | 位号(如 U1,R3) |
（如果看不清型号，标"待确认"并说明原因，不要瞎编）

第 3 步｜坐标提取
对每个位号给出贴片坐标（x, y, 旋转角度），输出 JSON：
{"components":[{"ref":"U1","x":12.3,"y":45.6,"rot":90}, ...]}

第 4 步｜烧录 SOP（思维链）
一步步推导：① 这款板用什么烧录接口（SWD/JTAG/USB）② 烧录前要做哪些检查 ③ 具体烧录命令/步骤 ④ 怎么验证烧录成功、不出问题。每步写清"为什么"。

第 5 步｜打包
把上面结果汇总成一份可外发资料包文本（BOM + 坐标 + 烧录 SOP）。

注意：
- 看不清的地方明确标"待确认"，绝不开脑洞补全。
- 一次只处理我传的这张图，不要假设还有别的图。
```

## 五、提示词草稿 B（飞书 Agent 完整版 · 加代码执行/RAG/工具调用）

> 适用：你在飞书上建一个"PCB 生产助理"Agent，开启**代码执行**能力、接入**历史设计库（RAG）**、并配置**调 EDA/文件导出的工具**。
> 在 A 的基础上多出 3 个 Feature：代码执行、RAG、工具调用。

```
你是"PCB 生产助理"，身份：资深 PCB 设计工程师 + 制造工艺专家。

【最终意图】用户上传 PCB 版图，你要产出可外发制造资料包（BOM + 坐标 + Gerber 辅助）+ 固件烧录 SOP，并保证一致性、可制造性。

【可用能力，按阶段调用】
1. 多模态：识别版图器件、丝印、封装。
2. 代码执行（Python）：用 numpy 做坐标换算、引脚对应校验、封装匹配检查；生成网表辅助。
3. RAG：检索"历史设计库"和"元件数据库"，对识别结果做一致性校验——重点防"老型号被认错/封装不匹配"。
4. 工具调用：识别完成后，调用 export_gerber() 导出制造包、调用 export_bom() 生成标准 BOM 文件。

【执行流程（任务拆解 + ReAct：边做边校验，不要回退重来）】
阶段0 意图确认：复述任务，等用户确认。
阶段1 识别：多模态产出 BOM 草稿（结构化表格，看不清标"待确认"）。
阶段2 坐标：提取每个位号 x,y,rot，输出 JSON。
阶段3 校验（代码执行 + RAG）：
   - 跑 Python 校验引脚数/封装/位号冲突；
   - 调 RAG 比对你历史同类型板，标出"疑似不一致"项，给出证据。
阶段4 烧录 SOP（CoT）：推导接口→检查→步骤→验证。
阶段5 导出（工具调用）：调 export_bom() 和 export_gerber() 生成可外发文件，回链给用户。

【输出标准】所有器件数据必须结构化（表格/JSON），烧录 SOP 必须可逐步操作。任何不确定项显式标注，禁止臆造。
```

## 六、落地建议（在哪跑、怎么搭）

1. **马上能试**：把草稿 A 复制到 Kimi（或豆包/千问），**一次传一张 PCB 图**，先跑出 BOM+坐标+烧录 SOP 文本。这已经比"硬看描述"强一大截。
2. **要逼近"可外发制造包"**：在飞书建"PCB 生产助理"Agent，开启代码执行+接历史设计库（RAG）+ 配 EDA 导出工具，用草稿 B。你飞书上已有十来个 Agent，搭这个不陌生。
3. **渐进披露纪律**：几百张图别一次灌。建个队列，一次一张、按区域切，结果落外部文件（常识记忆），需要哪张取哪张——这正是你"上下文过长走神"的正解。

---

## 七、已知边界（诚实提醒）

- Kimi 纯识图 **做不到**：坐标精算、引脚校验、调 EDA 导出 Gerber、接你的历史库。这些必须升级到"带代码执行+工具调用"的环境（草稿 B）。
- 模型识别 **会看错丝印/封装**，尤其老板子。所以"待确认"标注和 RAG 历史比对是必须的，不能全信 AI 一口吐出的 BOM。
- 这版只覆盖**意图 1 生产闭环**。意图 2 售后闭环（故障定位 + 维修 SOP）是另一套 Feature 组合（多模态+ReAct+RAG），需要时单独拆。
