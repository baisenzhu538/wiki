## L2 上下文工程

### RAG（检索增强生成）
- **大白话**：不靠模型死记，而是"用的时候去外面查资料，把查到的资料喂给模型一起回答"。
- **比喻**：不是让一个人凭记忆答题，而是给他一个能随时翻的文件夹，边翻边答。
- **为何需要**：模型训练完就"冻住"，不知道你的私有数据（PCB 图、十年协议、药店业务）。RAG 接外部知识库，用时检索相关片段塞进上下文。
- **老朱场景**：整理十年协议、识 PCB——这些模型没见过。正确做法 = 建索引 → 问时只取相关片段，而非全塞（全塞会撑爆走神，即"上下文过长注意力分散"）。

### 渐进式披露
- **老朱原理解**（基本对）："先建索引，需要哪部分再去取哪部分"——这就是核心。
- **完整三步**：① 资料预处理成可检索碎片（切块 / 向量化 / 建索引）→ ② 模型需要时只取"当前最相关那一小块"喂给它 → ③ 需要下一块再取，信息随任务推进逐步给。
- **实现手段**：RAG（语义检索）是常见实现；也可"先给摘要、细节按需展开""长对话定期摘要压缩"。
- **老朱场景**：几百张 PCB、几十页协议——别一次全丢，先建索引，问"第 3 张板电源部分"只取那部分。

### 常识记忆 / 长时记忆
- **老朱理解（准确）**：用外部文件帮模型记东西，因为上下文窗口有限。
- 模型"短期记忆" = 上下文窗口（几万到几十万字就满），超了就忘 / 走神。
- **解法**：长期知识外置成文件 / 数据库 / 向量库，需要时取。
- **老朱场景**：十年协议、历史对话、学员档案都该外置，不是每次塞上下文。正解 = 常识记忆 + 渐进披露。

## L3 推理增强

### CoT（思维链 Chain-of-Thought）
- 让模型"一步步想出来再答"，不脱口而出。像考试写过程。
- **怎么加**：提示词写"请一步步思考 / Let's think step by step"。
- **老朱场景**：选品判断、销售定价分析——让模型列步骤，比直接要结论稳。

### 任务拆解（Task Decomposition）
- 把大任务切小，逐个解决。别一次干完"识图 + 出 BOM + 校坐标"，拆成 ① 识别器件 ② 提取坐标 ③ 生成 BOM ④ 校验。
- **老朱 3D 组装失败 = 没拆**：让模型"一次性把零件凑成总装"，把推理当执行，模型没操作 CAD 能力只能想象坐标，失败。正确拆解：读图 → 调 CAD API 放零件 → 校验坐标，每步用对工具。

### ReAct（推理 + 行动 Reasoning + Acting）
- 模型边想边干、边看结果边调整："想一步 → 做动作（查资料 / 调工具）→ 看结果 → 再想下一步"。
- **与 CoT 区别**：CoT 想完再答（纯脑内）；ReAct 想 + 做 + 看 + 再想（手脑并用）。
- **直接解释老朱发现的"Agent 对话别反复回退"**：ReAct 链式推进，回退打断推理链让它乱。

**三者关系**：任务拆解是结构，CoT 是每步怎么想，ReAct 是边想边调工具，常组合。

## L4 输入增强 + 输出控制

### Few-shot（少样本）
- 给模型几个例子照学。直接给"例 1 输入→输出，例 2 输入→输出"，模型照葫芦画瓢。**例子质量决定输出质量**。
- **老朱场景**：销售话术教练——给几条"好话术 → 为什么好"，模型按标准评新话术。

### 角色（Role / System Prompt）
- 给模型身份。"你是有 20 年经验的药店数字化顾问"——定身份后语气 / 知识侧重 / 判断标准全变。飞书上的领导力助理、开会助理本质 = 角色 + 职责封装。

### 结构化输出（Structured Output / JSON Mode）
- 让模型按固定格式吐（JSON / 表格），方便程序接。识 PCB 要拿去用就必须结构化，否则人工摘。
- **老朱场景**：PCB 识图吐"器件清单 + 坐标"必须结构化才能进 EDA。

### Function Calling（函数调用）
- 让模型能"叫外部函数"：模型说"我要调 getPCB('板3')"，由程序执行、结果喂回。是连接模型与外部系统的桥，也是一种工具调用机制。

## L5 外部能力

### 工具调用（Tool Use）
- 模型不止"说"还能"动手"调外部工具。Function Calling 是一种；广义 = 模型决定调哪个工具、传参、拿结果继续。

### 代码执行（Code Execution）
- 给模型能跑代码的环境（Python），它写代码算 / 处理数据。**老朱场景**：PCB 坐标计算、协议解析——写脚本算比嘴算准；3D 坐标变换也能代码算。

### API
- 应用程序接口，系统间通信的"插座"。模型 / 程序通过 API 调别的服务（查库存、发消息）。

### EDA / CAD
- **EDA**（电子设计自动化）：画电路板软件（立创 EDA、Altium）。PCB 图即 EDA 文件。
- **CAD**（计算机辅助设计）：画结构 / 机械软件（SolidWorks、AutoCAD）。3D 组装要进 CAD。
- **关键**：EDA / CAD 有 API / 脚本接口。正确做法 = 让模型 / 程序调这些软件 API 去放零件、出图，不是让模型用语言"想象"坐标。

## 老朱两道硬仗的正解（串联）

### PCB 识图
多模态(看图) + RAG(历史设计库) + 结构化输出(器件 + 坐标 JSON) + 代码执行(算坐标) + 可选调 EDA API(直接生成网表)。**不是"丢张图硬看"**。

### 3D 组装
任务拆解(读图 → 取零件 → 放坐标 → 校验) + 工具调用(调 CAD API) + 代码执行(坐标变换) + ReAct(边放边校验)。**不是"让模型推理想象总装"**。
