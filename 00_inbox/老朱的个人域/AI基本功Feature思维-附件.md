# 从"追工具"到"攒特性"——AI 基本功第一课 Feature 思维学习心得

说实话，我一开始接触 AI，走的就是典型的"追工具"路线。什么火就换什么，今天这个明天那个，一直被工具的名字带着跑。这么干了一阵子，自己在业务里也慢慢摸索出一些门道，甚至攒过一些迭代的概念和打法，但都散、都不够系统。直到上了这一课，我才突然意识到：原来我摸出来的那些东西，早就叫"Feature"了——只是我从来不知道这个概念，更没把它串成一张清单。课程里像"最终意图""渐进披露"这些词，我现在还没完全吃透，但框架本身已经让我换了个角度看问题。

这一课对我最大的价值，不是教我一个新招，而是把我脑子里那些说不清的经验，"对上了号"。

## 一、Feature 是什么：我摸过的那些招，原来都有名字

课程里说，Feature 是"提升 AI 解题水平的最小实践单位"——一句话，就是把 AI 能力拆到最小、能上手、能迁移的那个颗粒度。它卡在底层大模型和上层工具中间，跨工具稳定。课里还画了一条 T 型和 F 型的分界：T 型是"工具思维"，以工具为单位学，工具一变能力归零；F 型是"Feature 思维"，攒的是特性，换工具也还在。五大学派里，Feature 派正好取中间——既像原理派一样稳定，又像工具派一样实用。

听到这儿我有点恍然。因为我早就在实践里撞到过这几个东西，只是没命名：

- **Temperature（温度）**：这个我有印象，之前真试过。有时候 AI 输出太发散、乱飘，我把 Temperature 调低一点，立刻就稳了。当时只觉得"哎这样好点"，没意识到这本身就是一次 Feature 级的调优。
- **上下文一长，AI 就走神**：我们实际用下来发现，喂给 AI 的内容太长，它的注意力就分散，回答反而差。这其实就是课程里说的"长上下文"问题——对应的 Feature 是渐进披露、RAG、长时记忆，而不是一股脑全灌进去。
- **跟 Agent 对话不能反复回退**：我们在飞书上建了十来个 Agent，实践中摸出的规律是——跟它对话得先想清楚，一步步往前推，别老往回退。因为它是推理逻辑，你一直退，它自己也乱。这背后考的就是结构化思考，对应课程里的任务拆解、多轮确认、ReAct 这类特性。

所以我这课不是从零开始学，是把已有的经验"升级"成了系统语言。这点让我挺受触动的：原来我不是不会，是我一直没把招式命名、没攒成库。我们之前自己摸索的那点东西，不算白费，只是差了这张"清单"把它们串起来。

## 二、为什么要用 Feature 思维：我踩过的两个坑

第一个坑就是"追工具"。以前什么工具火就换，换完发现又得从头学，永远在追新。现在懂了，这是 T 型思维的代价——工具一变，我的能力跟着归零。反过来说，我飞书上那十来个 Agent，如果我只懂"飞书这个壳"，哪天平台变了就全废；但我真正攒下的长时记忆、结构化输出、多 Agent 分工这些 Feature，是跟着我走的。

第二个坑是把 AI 当黑盒、不系统。课程里那个例子很扎我：有人调了一个 temperature 参数，成本直接降到四十分之一，效果还跟最好的模型持平。我虽然也试过 temperature，但从来没往"这是一个能撬动成本十倍的 Feature"这个角度想。基本功不是会换工具，是懂工具背后那些最小的技术特性——这话我现在是真信了。

所以 Feature 思维对我而言，核心就一句：借工具之假，修能力之真。工具火不火不重要，重要的是它比我现在用的多了哪几个 Feature；攒下的 Feature 才是复利，是越用越值钱的东西。

## 三、怎么把"拆 / 加 / 组合"用到我接下来的工作

我现在手头能落地的场景一大把，正好可以拿课程里的"叠加"思路一条条过。课程里招商日报从 30 分叠到 90 分，靠的是叠了信息源、判断规则、模型切换、周榜、二次筛选五个 Feature，没换工具——这种"不换工具先问还能叠什么"的打法，我要直接搬。

- **药店业务：AI 辅助选址、选品、动态运营**。这三个我打算先拆 Feature：选址和选品靠"数据增强"（联网搜索、RAG 接外部数据）+"判断规则化"（把我的选品标准翻译成加分扣分逻辑）+"模型组合"；动态运营靠"长时记忆"+"结构化输出"。不是换个 AI 工具就完事，是把这几样特性一层层叠上去。
- **销售话术教练（已经在用）**。下一步叠 Feature：加案例（few-shot 给 AI 看优秀话术）、加角色设定、加迭代反馈、再加打分环节——每一轮叠一个，看分数变不变，跟课程里"30→50→70→90"一个路数。
- **教练式领导力助理 + 开会助理**。这是组合 Feature：长时记忆（记住团队每个人的情况）+ 结构化输出（会议纪要、行动项）+ 多 Agent 分工（一个听、一个总结、一个跟任务）。原子特性按场景封装成 Skill，复用。
- **技术文档与图纸：PCB 识别 + 3D 组装（我正卡着的两道硬仗）**。这块是我现在最实在的困难，也最能说明"Feature 用错了"的代价：
  - 一是**用 Kimi 识别以前留下来的大批 PCB 板电子图纸**。EDA 虽然开始接 AI 了，但到底能做到多深、能不能直接读出线路和器件，我还在摸清。我现在的做法还是"丢张图让大模型硬看"，这显然不是正路——识图属于多模态 + 外部能力（代码执行、调 EDA/CAD 的 API），不是靠语言模型凭眼睛猜。
  - 二是**把零散结构件 3D 模型推理组装成总装图**。我试过，靠推理逻辑让 AI 拼 3D，花了一大笔 token，结果完全做不到。现在回过头看，是我把"推理"当成了"执行"——3D 组装得靠任务拆解 + 工具调用（调 CAD/EDA 接口）+ 多 Agent 分工，不是让语言模型靠逻辑去想象坐标。
  - 课程给我的启示就在这：这两道坎，不是 AI 不行，是我没用对 Feature 组合。下一步我打算照作图工作流那个工业化路径——渐进披露管长上下文、任务拆解把图纸按模块拆开、工具调用接 EDA、多 Agent 分工并行——一个 Feature 不够就叠，不对就换组合。课里"最终意图""渐进披露"这些词我现在还没完全吃透，但已经隐约明白：我让 AI 组装 3D 时，既没把"最终要什么"说清，又没做渐进披露，所以它在长上下文里走神、在推理里乱退。

## 收尾

写到这里，这课给我最实在的启发就一句：别再追工具的名字了，去攒特性的库。我以前那些零散的摸索不是没用，是把它们命名、串起来，我就从"T 型"跨到了"F 型"。接下来每碰到一个新 AI 工具，我先问一句"它比我现在多了哪几个 Feature"；每遇到一个干不好的活——不管是门店选址还是 PCB 识图——先问"还能叠什么 Feature、是不是 Feature 组合用错了"。这大概就是我把这门课真正带走的东西。
