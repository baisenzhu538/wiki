# 巨米技术库迁移准备清单（本周内执行）

> 背景：另一台电脑有 4 个 agent 专门处理「巨米」过去十年的知识资产——后端、前端、通讯协议、各机型电子资料（含固件）、机械域原设计图。
> 计划：本周买内存 + 加硬盘到这台 WorkBuddy 机器（当前 `C:\Users\Administrator`），把巨米库**全部拷过来**，统一本地，让我（WorkBuddy）能直接读、MCP 能直接检索。
> 本文件是迁移前的准备与迁移后的接入步骤。

---

## 一、买硬件前：先估容量（关键，别买小了）

巨米十年资产里**设计图、固件、图片最占空间**，务必先量另一台的真实大小再下单。

- 另一台 PowerShell 估总大小：
  ```
  (Get-ChildItem D:\巨米知识库 -Recurse -File | Measure-Object -Property Length -Sum).Sum / 1GB
  ```
- 或另一台 Git Bash：
  ```
  du -sh /d/巨米知识库
  ```
- **买盘留 2–3 倍余量**（后续 agent 还会持续产出新文件）。

---

## 二、目录规划（建议）

- 新硬盘挂 **D:**，统一放 `D:\巨米知识库\`，与 KDO 库 `C:\Users\Administrator\Desktop\wiki` 并列，便于管理。
- 子目录按 4 个 agent 的域切分，方便后续检索与权限：
  ```
  D:\巨米知识库\
  ├─ backend\          # 后端
  ├─ front-end\        # 前端
  ├─ protocol\         # 通讯协议（十年积累，重点）
  ├─ electronics\      # 各机型电子资料 + 固件
  └─ mechanical\       # 机械域原设计图
  ```

## 三、拷之中：传输方式（二选一）

**方式 A — 移动硬盘中转（最稳，强烈推荐）**
避开手机热点的 AP 隔离、避开我沙箱出网限制。
1. 另一台 → 移动硬盘：`robocopy D:\巨米知识库 E:\巨米知识库 /E /COPYALL /R:3 /W:5 /LOG:copy1.log /TEE`
2. 移动硬盘 → 这台新盘：`robocopy E:\巨米知识库 D:\巨米知识库 /E /COPYALL /R:3 /W:5 /LOG:copy2.log /TEE`

**方式 B — 网络直传（需另一台开共享 + 这台能访问）**
```
robocopy \\另一台内网IP\巨米知识库 D:\巨米知识库 /E /COPYALL /R:3 /W:5 /LOG:copy.log /TEE
```
前提：另一台共享文件夹、且两台能互访（手机热点可能 AP 隔离，路由器一般可通）。

参数说明：`/E` 含空目录；`/COPYALL` 保留权限时间戳；`/R:3 /W:5` 失败重试；`/LOG` 留记录便于查漏。

## 四、要拷哪些（别漏）

- ✅ **原始资料**（十年积累的全部）
- ✅ **4 个 agent 的「产物文件」**（整理后的索引 / 结构化文档 / 向量库导出）——不止原始资料，这些才是 agent 的精华
- ⚠️ **4 个 agent 的「运行环境」**（程序/配置）是否也要迁，另行决定；当前只要"让我看到资料"，拷文件即可

1. **验证可读 + 清点规模**：类比之前对 KDO wiki 的清点（各子类文件数、总大小）。
2. **扩展 kdo MCP 检索范围**：把 `D:\巨米知识库` 纳入 kdo server 的索引，让 `kdo_search` 能直接查巨米技术库（需改 MCP 配置 / 重建索引）。
3. **纳入管理**：如需要，把巨米库接到「老朱的个人域」或单独 vault，和 KDO 库并列检索。

## 六、前提与坑（备忘）

- 网络传依赖另一台共享 + 这台可访问；AP 隔离 / 沙箱限制仍在 → **移动硬盘中转最稳**。
- 加内存后这台更能跑本地重任务（本地模型 / 向量库），可选升级。
- 当前 WorkBuddy 机器为 Windows（路径 `C:\Users\Administrator`），robocopy 用 Windows 原生路径。
