## 二、核心洞察（欧阳锋版，与 Codex 版互补）

### 洞察 1：KDO 的卡片就是 Feature，课程给了 KDO 缺的「消费端协议」

课程定义：**Feature = 提升 AI 解题水平的最小实践单位**（AI 范围 / 解题水平 / 实践单位 / 最小颗粒度）。

KDO 卡片（tool/framework/case/dk）在结构上就是 Feature——但 KDO 只有**生产端协议**（如何产卡、审卡、入库），没有**消费端协议**。课程恰好补上了：

```
生产端（KDO 已有）：素材 → 卡片 → 审查 → 入库
消费端（课程提供）：点菜（从周期表挑 5-10 个 Feature 提假设）
                    → 组合（多个 Feature 叠加调优）
                    → 复盘（成也好败也好，武器库变强）
```

**编排含义**：KDO 卡片库的价值主张可以从"知识存储"升级为"解题武器库"——用户面对任务时像点菜一样查卡、组合、验证。这是比"再建 N 张卡"更高层的收益。

### 洞察 2：wiki 已有 3 张同主题卡——本素材第一价值是升级而非新建

| 已有卡 | 状态 | 与本素材的关系 |
|:--|:--|:--|
| `tool-Truman-Feature特性层训练法` | draft，source_refs=src_unknown | 同主题**不同来源**（Truman AMA）——本次课程素材可补齐其 source_refs 并升级 |
| `tool-ai-feature-inventory` | 已入库 | AI Feature 盘点——需对比确认与课程 100 Feature 的关系 |
| `concept-kdo-feature-registry`（黄药师 2026-08-08 今日新建）| draft | 来源是双三角口述 + cap_hub——**与本次素材同源异构，需 bridge 而非再建** |

⚠️ **最大重复风险**：老顽童拿到素材后可能直接"新建 Feature 思维框架卡"——必须先在任务单里写明"查 `kdo query Feature`，对比以上 3 张卡后再动手"。

### 洞察 3：两个"Feature 注册表"不是一回事，不可混编

- **cap_hub/features.json**（12 项）= KDO 基础设施的**质量门禁 Feature**（F1_UPDATED_AT、F4_MOC_DEADLINK、SEC_TYPO 等 lint 规则）
- **课程周期表 V0.8** = AI **使用能力 Feature**（100 个原子动作：设定角色/最终意图/温度/版本管理…）

黄药师今天的 concept-kdo-feature-registry 锚定的是前者。编排时必须显式区分，否则消费端会拿 lint 规则当解题武器用。

### 洞察 4：课程核心主张是对 KDO 自己的警示

> "feature 不是学会的，是用会的"——如果只把课程卡片化入库，不绑定使用场景，就是课程明说的"技巧派"。

**编排含义**：这批卡片必须绑定消费场景（王语嫣编排套餐 / 飞书 bot 查询 / Agent 出牌），否则入库即贬值。这也正是王语嫣的核心职责——**编排不是发任务单，是保证卡片被用起来**。

### 洞察 5：素材里的 3 个 case 是隐藏金矿（含可溯源数字）

| case | 数字（可溯源）| 建议卡型 |
|:--|:--|:--|
| 作图工作流进化 | 提示词 60 分 → +换模型/版本管理 → +抽卡/Skill/多 Agent → 成功率 50-70%，日产 30-40 张 | case |
| 伟强招商日报 | 30 分 → +信息源/规则(50) → +换模型成本降 10 倍(70) → +周榜/二次筛选(90) | case |
| 作业评查报告温度参数 | 2 万/次 → 调温度参数后 1-2 千（成本降 90%+，准确率 95%）| case 或 dk |

三个 case 恰好都是"叠 Feature 螺旋上升"的完整证据链——**比概念卡更值钱**。

## 三、对两份已有建议书的裁定（O7：记录不代改）

### Codex 版「给王语嫣的任务编排建议书.md」

**可取**：① "KDO Skills = Feature 工程化实现"的判断成立；② 四个"元 Feature"（GAN/OODA/synthetic/self-attack）提炼有洞察；③ "王语嫣 = 周期表活字典，点菜不炒菜"与课程"向所有人兼容/翻译"完全同构；④ 编排质量门禁 5 问（覆盖率/并行度/对抗充分性/反馈闭环/成本）可直接用。

**不可取**：
1. **未溯源**——四个"元 Feature"对应的是 KDO 现有 skill，不是课程内容。建议书本质是"用 Feature 语言重包装 KDO"，而非"把课程 KDO 化"。两个任务混在一份文档里，王语嫣执行时会分裂。
2. **未覆盖素材资产清单**——100 Feature 周期表、四要素定义、分层体系、3 个 case 全部缺失。
3. **王语嫣定义过窄**——"不执行只编排"与 context.md 实际职责（内容咨询/方向把关/队列维护/任务标注）不符，照做会丢职责。

**裁定**：吸收其"元 Feature + 质量门禁 + 点菜式定位"三部分，本建议书补齐其缺的部分。

### 洪七公版「AI基本功_任务编排建议书」

**可取**：素材盘点细、卡片结构建议（7 张）基本合理、VLM 方法论记录有价值（600px=100% 黄金切分标准）。

**问题**：① "周伯通"创建卡片 = 老顽童，职责正确；② 但其卡片清单与 wiki 已有 3 张同主题卡冲突，未做去重；③ 与 Codex 版无整合。

**裁定**：卡片结构并入本建议书的 P1 计划，去重后执行。

### 不做什么（显式排除）

- ❌ 新建"Feature 思维框架卡"（已有 3 张同主题卡，先升级后补链）
- ❌ 营销/闲聊内容入卡（口令、实体周期表、投票器、探月、同行吐槽）
- ❌ 直接引用口述原句（转写噪声大，以笔记为准）
- ❌ "课程全集"式大卡（拆成 P1 的 8 张即可，避免大而全）

## 五、一句话总结

> **这个素材的编排不是"再建 8 张卡"，而是三件事：把 V0.8 周期表变成结构化资产（P0-2）、把已有 3 张 Feature 卡升级补链（P0-3/P1-7）、把消费端协议用起来（P2-1）。**
> 卡片是生产端的事，**让卡片被点菜式使用**才是编排端的事——这才是"feature 不是学会的，是用会的"在 KDO 里的版本。
