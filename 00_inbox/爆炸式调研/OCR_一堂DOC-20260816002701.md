## 段4 ✅

不能只靠颜色传达信息（红=失败/绿=成功对色盲无效，要配图标文字）。

**120. 可操作性** WCAG 第二原则：所有功能必须能"操作"——可键盘操作、操作时间可调（限时任务要能延长）、避免强闪烁（癫痫风险）。

**121. 可理解性** WCAG 第三原则：内容和操作必须"可懂"——文字清晰可读、行为可预测（别点 A 弹 B）、错误输入有辅助纠正。

**122. 健壮性** WCAG 第四原则：界面必须"健壮"——用标准语义化标签（按钮就是 button，标题就是 h1/h2），兼容屏幕阅读器等辅助技术。

## 段5 ✅

```markdown
123. 对比达标 WCAG 硬性标准：正文文字与背景对比度 ≥ 4.5:1，大号文字 ≥ 3:1——这是"看着舒服"的客观底线，Figma 有对比度检查插件。

124. 键盘可达 所有鼠标能完成的操作，键盘都必须能完成（Tab 顺序合理、焦点可见、能 Enter 触发）——这是做页面产品绕不开的验收项。

## ★ 微软 UX 原则（Windows 官方）★

125. 减少概念 微软 UX 核心原则：引入新概念前先问"有必要吗？能删掉吗？"——减少概念 = 增加用户信心，概念越少越敢操作。
```

## 段6 ✅

```markdown
126. **小事重要** 微软 UX： 小事也分好坏——"常见小问题"和"频繁小细节"值得专门花时间打磨；做得更少，但把留下的做到位。

127. **解决干扰** 微软 UX： 可发现性差的问题，靠加图标、加入口解决是错的——那是增加干扰；正确做法是减少干扰、让核心功能自己突出。

# ★ 表单与微文案（实战专项）★

128. **表单最简** 表单字段只留绝对必要的： 能不问就不问（"以后可能需要"的信息先不收集），研究显示字段越少完成率越高。
```

129. 微文案 按钮、错误提示、空状态、加载中的文字也是设计——"请稍候"和"正在为您打包商品"传递的安心感完全不同，小字决定体验温度。
