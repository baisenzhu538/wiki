# Agent 自我进化协议 · 任务编排建议书

## 一、背景与问题

### 1.1 新素材到达

`00_inbox/解放思想探索营/` 到达一批新素材：Truman 主讲的「解放思想」创新方法论课程 + 温小宝/嗷大叶/吴迪三位实践者案例分享。核心产出为 **闪电模型**（大胆设想→底层自洽→假设试错→建模重构），洪七公已完成 OCR + 结构化笔记 + 首版任务编排建议。

### 1.2 已有资产

知识库中已入库 Truman 的 **高阶建模方法论**（`framework-kdo-modeling-methodology`），核心内容包括建模四步法（圈定范围→探索关系→压缩模型→解压展开）和一组 **先 X 后 Y 组件规则**（先目标后路径、先框架后细节、先定性再定量、先加法后减法、先输入后输出、先共识后执行）。

### 1.3 核心判断

**闪电模型 + 高阶建模方法论 不只是要入库的知识卡片。它们是 KDO Agent 体系自我进化的操作系统。**

当前 Agent 体系的状态：
- ✅ 能执行：按 spec 生产、按标准审查
- ✅ 能踩坑：41 条 pitfalls 记录了踩过的坑
- ❌ 不能进化：踩坑后打补丁，但没有把补丁萃取为可复用的建模组件
- ❌ 不能自洽：每个 Agent 的 context 是经验堆叠（"贴上去的规则"），不是从底层原则推导出来的产物

闪电模型给了进化路线图（四阶），高阶建模方法论给了每一步的操作组件（先 X 后 Y）。两者结合，可以让 Agent 从「能执行」升级到「能进化」。

## 二、核心框架：Agent 自我进化协议

### 2.1 三层架构

```
┌────────────────────────────────────────────────┐
│              第三层：体系构建层                    │
│  从双三角 → Agent 设计原则 → context 逐层推导      │
│  依赖：高阶建模方法论（先框架后细节）               │
├────────────────────────────────────────────────┤
│              第二层：复盘进化层                    │
│  每次复盘按闪电模型四阶追问，沉淀为模型组件         │
│  依赖：闪电模型 + 先定性再定量 + 先共识后执行       │
├────────────────────────────────────────────────┤
│              第一层：任务执行层                    │
│  每次接任务自动调用先 X 后 Y 组件规划工作           │
│  依赖：高阶建模方法论（先目标后路径）               │
└────────────────────────────────────────────────┘
```

### 2.2 两层方法论的关系

| | 高阶建模方法论 | 闪电模型 |
|:--|:--|:--|
| **角色** | 发动机——怎么建 | 路线图——建什么 |
| **回答** | 每一步用什么方法 | 进化要经过哪些阶段 |
| **Agent 应用** | 执行任务时的思维组件 | 复盘进化时的追问框架 |
| **来源** | 已入库（`framework-kdo-modeling-methodology`） | 新素材（待入库） |

## 三、任务编排

### P0：Agent 设计原则卡（体系构建层）

**目标**：从双三角推导出一组 Agent 设计原则，让所有 Agent 的 context 可追溯到同一套底层逻辑。

| 项 | 内容 |
|:--|:--|
| **负责** | 王语嫣（裁决）+ 老顽童（执笔） |
| **输入** | 双三角模型、TCPR 皇冠模型、41 条 pitfalls、现有所有 agent-spec |
| **产出** | 1 张 framework 卡 `framework-agent-design-principles` |
| **方法** | 高阶建模方法论第三步「压缩模型」：从现有素材中萃取规律，压缩为一组设计原则 |
| **验收** | 每个原则可举出至少 1 条 pitfall 作为反面证据 + 1 个现有 agent 行为作为正面证据 |
| **时效** | 3 天内 |

**设计原则草案（待王语嫣裁决）**：

1. **人定审美，AI 执行**：人类定义"好"的标准（审美/体系/方向），Agent 在标准内自由执行
2. **独立审查，不审查自己**：生产者和审查者必须分离，同一个 Agent 不能审自己的产出
3. **先目标后路径**：接到任务先对齐目标和验收标准，再规划执行路径
4. **先框架后细节**：先建总纲卡（domain-digest/framework），再建子卡（concept/tool/case）
5. **踩坑必建模**：每条 pitfall 必须追问"能不能变成一条规则或一张卡"，不只打补丁
6. **提交前自检是不可跳过的组成部分**：不是可选项，不绿不交

### P1：老顽童护栏内化（任务执行层）

**目标**：将欧阳锋的双护栏审查逻辑内化到老顽童的生产流程中——提交前自跑逻辑护栏和事实护栏，不等欧阳锋退回。

| 项 | 内容 |
|:--|:--|
| **负责** | 老顽童（执行）+ 欧阳锋（定义护栏清单） |
| **输入** | 闪电模型第二阶「底层自洽」+ 欧阳锋现有审查标准 + 高阶建模方法论「先输入后输出」 |
| **产出** | 老顽童 context 中新增「提交前自检护栏」章节 |
| **方法** | 类比闪电模型的「逻辑护栏 + 事实护栏」双护栏系统 |
| **验收** | 老顽童连续 5 个任务提交后，欧阳锋一审通过率 ≥ 80%（当前约 50%） |
| **时效** | 1 周内 |

**护栏清单（欧阳锋定义，老顽童自跑）**：

| 护栏 | 检查项 | 类型 |
|:--|:--|:--|
| related ≥ 5？ | 每张卡至少 5 条正向链接 | 逻辑护栏 |
| source_refs 带行号？ | 每个引用可 grep 定位 | 事实护栏 |
| pre-submit PASS？ | 门禁全绿 | 逻辑护栏 |
| frontmatter YAML 可解析？ | `yaml.safe_load` 通过 | 逻辑护栏 |
| Claims 有反例？ | 每条主张至少 1 个具体反例 | 事实护栏 |
| 素材消费率 ≥ 80%？ | VLM/OCR 关键信息已入卡 | 事实护栏 |

### P2：Agent 自我进化协议（复盘进化层）

**目标**：每个 Agent 复盘时按闪电模型四阶追问，把踩坑经验从"打补丁"升级为"建模型"。

| 项 | 内容 |
|:--|:--|
| **负责** | 全部 Agent（执行）+ 王语嫣（监督） |
| **输入** | 闪电模型四阶 + 高阶建模方法论「先共识后执行」 |
| **产出** | 每个 Agent 的 context 中新增「自我进化协议」章节 + 首次复盘执行记录 |
| **方法** | 闪电模型第四阶「建模重构」：试完了要沉淀 |
| **验收** | 连续 2 周复盘记录中，每条踩坑都有对应的规则/卡片产出 |
| **时效** | 持续 |

**复盘四问（每次复盘必答）**：

```
1. 大胆设想：这次我主动改进了什么？有没有 push back 不合理的要求？
2. 底层自洽：我的做法能从 Agent 设计原则推导出来吗？还是拍脑袋？
3. 假设试错：新方法有没有用小任务低成本验证？结果如何？
4. 建模重构：这次踩的坑/发现的规律能不能变成一条规则写进 context 或方法论卡？
```

### P3：闪电模型入库（知识生产层）

**目标**：将解放思想探索营素材按标准流程入库，产出 framework/case/concept 卡片。

| 项 | 内容 |
|:--|:--|
| **负责** | 洪七公（信息图）+ 老顽童（卡片生产）+ 黄药师（框架萃取） |
| **输入** | 逐字稿 2 份 + 结构化笔记 2 份 + 幻灯片 8 张 + 批注 27 张 |
| **产出** | 见洪七公首版建议（A 档 7 张信息图 + B 档 4 个案例拆解 + C 档训练营练习） |
| **方法** | 高阶建模方法论四步法（圈定范围→探索关系→压缩模型→解压展开） |
| **验收** | 按现有 KDO 质量标准 |
| **时效** | 2 周内 |

**P0-P2 优先于 P3**。理由是：Agent 先用闪电模型 + 高阶建模方法论升级自己的能力，再用升级后的能力去生产闪电模型的知识卡片——这就是"先框架后细节"在自己身上的应用。
