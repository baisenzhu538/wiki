## 二、黄药师补充一：域结构设计

### 2.1 建议：独立域目录

C域和基本功域一样，应该建独立域目录，而不是散落在 concepts/frameworks/tools/cases 四个通用目录里。

```
30_wiki/business-formula/          ← 新建
├── concepts/                      ← 概念卡（业务公式定义、ABC模型、PEAHD角色等）
├── frameworks/                    ← 框架卡（十大范式、参数冰山、逻辑关系六层等）
├── tools/                         ← 工具卡（参数挖掘武器库、减法评估checklist等）
├── cases/                         ← 案例卡（复盘营、我请客、会销、扭蛋机等）
├── matrices/                      ← 矩阵表（参数×范式、逻辑×策略等）
└── _index.md                      ← 域索引入口（一个本体，多个索引）
```

**理由**：
1. 基本功域的经验教训——卡散在通用目录里，后面补双向链接补到吐血（欧阳锋终审 F2 就是双向链接不全）
2. "一个本体，多个索引"——本体在 `business-formula/` 下，双三角/cap_hub/Y模型从各自入口用 wikilink 引用，不复制内容
3. 域内卡片之间的引用走相对路径（`[[parameter-iceberg]]` 而非 `[[business-formula/parameter-iceberg]]`），域外引用走 `[[framework-business-formula-dual-triangle-bridge]]` 桥接卡

### 2.2 不建议：C/D 域共用一个父目录

C域（业务公式，宏观效率）和 D域（转化率黑客，微观效率）虽然相邻，但**方法论独立**——C域的核心模型（参数冰山、逻辑关系六层、十大范式）和D域的核心模型（动力阻力触点、四阶段转化）是不同的操作系统。建议平行独立：

```
30_wiki/business-formula/          ← C域：宏观效率
30_wiki/conversion-hacker/         ← D域：微观效率（等洪七公处理完素材后建）
```

两域的桥接通过一张 `framework-business-formula-conversion-bridge.md` 桥接卡完成。

## 三、黄药师补充二：卡片分批与类型区分

### 3.1 卡片类型 → 不同质量模板

洪七公的 20 张卡清单是平铺的，但不同类型的卡片质量标准和欧阳锋终审扣分点不同：

| 类型 | 数量 | 模板参考 | 终审重点 |
|:-----|:-----|:---------|:---------|
| **concept**（定义/角色） | ~4张 | `concept-一堂-基本功定义.md` | 定义精确、消歧清楚、diagnostic_signals≥2 |
| **framework**（框架/范式） | ~8张 | `framework-一堂-苦练基本功-总纲.md` | 层级清晰、When NOT to Use、Critique≥2位攻击者 |
| **tool**（工具/checklist） | ~5张 | `tool-一堂-基本功-三环六维自检.md` | 操作步骤可执行、Failure Modes≥3条、有打分/判定标准 |
| **case**（案例） | ~3张 | 现有案例卡模板 | 公式→拆解→验证→结果四段、可迁移的教训 |

### 3.2 建议分三批生产

| 批次 | 卡片 | 张数 | 依赖 | 老顽童估时 |
|:-----|:-----|:----:|:-----|:----------|
| **P0 第一批** | 业务公式定义卡、ABC模型卡、十大范式卡、参数冰山卡、逻辑关系六层卡、假设管理五大策略卡、统一管理三角卡、减法评估卡 | ~8 | 无（纯C域本体） | 6-8h |
| **P1 第二批** | PEAHD五角色卡、落地策略矩阵卡、降龙十八掌卡、Ω模型卡、参数挖掘武器库卡、演化路径卡、案例卡×3（视频号/扭蛋机/复盘营） | ~8 | P0卡产出后（wikilink可引用） | 4-6h |
| **P2 第三批** | 两张矩阵表（参数×范式、逻辑×策略）、五篇课程结构索引、DataPack库、案例卡×2（会销/我请客） | ~4 + 矩阵 | P0+P1卡 | 3-4h |

**总计**：~20 张卡 + 矩阵/索引/DataPack。与洪七公的估算（10-13h）相比，我加上了模板学习、欧阳锋退回返工、双向链接补全的缓冲。

### 3.3 防呆清单（从基本功域 #150 的返工教训中提取）

老顽童生产前，把以下三条贴在任务单里：

1. **每张卡 frontmatter 必填 `updated_at`**（欧阳锋 F1 扣分项）
2. **每张卡引用了另一张卡 → 另一张卡的 related 必须回链**（欧阳锋 F2 扣分项——"对接/回链/闭环"类声明，终审一律双向 grep）
3. **所有 source_refs 用行号锚点**（`口述.txt L240-L300`），王语嫣长素材协议的硬要求

### 5.2 建议后续的 Agent-Spec（Step 3 时写）

- **假设管理 Agent**：管理假设池、追踪验证状态、触发减法评估
- **业务公式诊断 Agent**：给定业务公式+当前数据 → 识别最大瓶颈参数 → 建议 Top 3 假设
- **跨域融合 Agent**：C域参数 ↔ 双三角六顶点 ↔ cap_hub 能力调用的路由层

### 5.3 与今天 YAI Agent 的对接

东家今天要观察一堂的两个 YAI agent（业务公式 + 黑客转化率）。建议王语嫣在任务编排中预留一个 **"YAI 观测笔记"** 槽位：
- 路径建议：`00_inbox/Handle the business/Business formula/_vlm_output/YAI-agent-observation-20260712.md`
- 观测维度：推理链是否基于 ABC 模型？参数挖掘到 L 几？逻辑关系判断到 L 几？有没有我们素材里没覆盖的能力？
- 这份笔记直接决定我们第三步"自建 agent"时的差异化方向——**做 YAI 做不到的，不做 YAI 已经做了的**
