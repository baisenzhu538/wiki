# 供应商管理全流程方案

> 版本：v1.0  
> 日期：2026-08-07  
> 适用场景：中小型医疗器械/设备企业，与代工厂（OEM/ODM）合作开发与生产  
> 编制依据：千惠合作复盘教训 + 全网行业最佳实践  
> 定位：组织资产，持续迭代

---

## 写在前面

这份方案不是理论框架，而是用真金白银（千惠项目的时间和资金损失）换来的实战手册。

核心原则只有一条：**信任不能替代尽调，关系不能替代制度。**

我们是一家中小型设备企业，资源有限、人手有限、议价能力有限。正因如此，供应商管理不能靠"人盯人"，必须靠"制度管人"。这套制度的设计目标不是把供应商当贼防，而是**用清晰的规则筛选出真正靠谱的合作伙伴，同时保护自己不犯重复的错误**。

## 第一章 选型前：尽职调查与内部共识

### 1.1 供应商画像"共识会"机制

**这是千惠复盘后确立的第一项制度。**

在正式接触任何新供应商之前，由项目负责人召集内部"共识会"，参与人至少包括：

- 项目负责人（老朱）
- 技术负责人（骆工/技术部）
- 采购/商务对接人

**共识会要回答三个问题：**

1. 我们要找什么样的供应商？（能力需求清单）
2. 我们能接受什么底线？（红线清单）
3. 谁来负责哪个维度的评估？（分工表）

**共识会产出物**：《供应商需求说明书》——包含技术能力要求、产能要求、交付周期要求、成本目标、合规要求、地理位置偏好等。这份文件是后续筛选的标尺。

> 千惠教训：当时没有共识会，老朱独自决策，技术部意见被忽视，导致选型标准模糊，后期内部沟通障碍巨大。

### 1.2 尽职调查清单（"五查"体系）

在接触潜在供应商后、签约前，必须完成以下五项调查：

#### 查一：资质合规

| 检查项    | 方法                   | 红线             |
| ------ | -------------------- | -------------- |
| 营业执照   | 国家企业信用信息公示系统核实       | 经营异常/吊销 → 一票否决 |
| 生产资质   | 核实生产范围是否覆盖目标产品       | 超范围 → 一票否决     |
| 质量体系认证 | ISO9001 / ISO13485 等 | 无任何体系认证 → 高风险  |
| 知识产权   | 自有还是贴牌？有无侵权记录        | 有侵权纠纷 → 谨慎评估   |

#### 查二：征信与涉诉

| 检查项    | 方法                | 红线                         |
| ------ | ----------------- | -------------------------- |
| 司法案件   | 天眼查/企查查/中国裁判文书网   | 涉诉超过5条 → 深入核查每一条           |
| 被执行人   | 中国执行信息公开网         | 被列入失信被执行人 → 一票否决           |
| 行政处罚   | 信用中国/国家企业信用信息公示系统 | 环保/税务/安全处罚 → 评估严重性         |
| 实缴社保人数 | 社保局官网或企查查         | 实缴人数 < 5人 → 与"大场地"矛盾 → 高风险 |

> 千惠教训：廖总有十几条司法案件，我们直到项目接近失控才查。如果一开始就查，可能根本不会选他。

#### 查三：真实生产能力

| 检查项        | 方法                | 红线                   |
| ---------- | ----------------- | -------------------- |
| 自有场地 vs 租赁 | 产权证/租赁合同 + 现场核实   | 场地不属于自己的 → 核实实际控制力   |
| 核心工序是否自制   | 现场看车间、看设备、看工人操作   | 关键工序全部外包 → 实质是"皮包公司" |
| 人员配置       | 要求提供社保缴纳名单 + 现场核对 | 看到的人 ≠ 名单上的人 → 追问    |
| 设备清单       | 现场拍照 + 核对设备铭牌     | 设备闲置/积灰 → 产能存疑       |

> 千惠教训：第一次去千惠看到场地大、各种整机在造，以为有实力。实际上那些可能都不是他的——他连钣金都外包到12公里外的石楼镇。

#### 查四：技术能力验证

| 检查项    | 方法                  | 红线                     |
| ------ | ------------------- | ---------------------- |
| 结构工程师  | 直接与对方工程师做技术对话       | 老板代替工程师回答 → 可能没有自有工程师  |
| 电子工程师  | 同上                  | 只有结构、没有电子 → 电子必然外包     |
| 过往案例   | 要求提供至少3个成功案例 + 现场考察 | 拿不出案例 → 无实战经验          |
| 技术方案评审 | 让对方出具技术方案，我方技术部评审   | 方案笼统/回避细节 → "大包大揽"型供应商 |

> 千惠教训：廖总第一次见面就"没问题""大包大揽"，但深入技术问题就回避。骆工后来证实：他根本没有电子开发能力。

#### 查五：财务健康度

| 检查项     | 方法             | 红线                  |
| ------- | -------------- | ------------------- |
| 注册资本与实缴 | 企查查/天眼查        | 实缴远低于注册资本 → 资金实力存疑  |
| 近2年经营状态 | 要求提供财报或银行流水    | 亏损/现金流为负 → 可能挪用预付款  |
| 是否在找融资  | 侧面观察/行业打听      | 到处找融资 → 资金链紧张 → 高风险 |
| 供应商评价   | 联系其上游供应商了解付款信誉 | 拖欠上游货款 → 资金链问题      |

> 千惠教训：廖总天天打电话找融资，我们没有重视这个信号。

### 1.3 对比机制

**铁律：不对比，不签约。**

至少接触3家以上潜在供应商，制作《供应商对比评估表》，从以下维度打分：

| 维度    | 权重  | 说明                   |
| ----- | --- | -------------------- |
| 技术能力  | 30% | 工程师水平 + 过往案例 + 方案评审  |
| 交付能力  | 25% | 产能 + 交付周期 + 弹性       |
| 成本合理性 | 20% | 报价透明度 + 综合成本（含运输/售后） |
| 质量管控  | 15% | 质量体系 + 检验能力          |
| 合规与征信 | 10% | 资质 + 涉诉 + 财务健康       |

> 千惠教训：当时只接触了千惠一家，云印明确不做、印象有纠纷不能合作，就再没找过其他家。理由是"没有资源""时间急"——但这不能成为跳过对比的理由。

### 1.4 现场考察（必做）

**不管对方介绍得多好，必须去现场。** 考察要点：

1. **看车间**：设备是否在运转？工人是否在干活？还是只是"展厅"？
2. **看仓库**：原材料是否齐备？成品是否有序？还是空空荡荡？
3. **看人员**：声称的工程师是否真的在场？能否直接对话？
4. **看管理**：有没有SOP？有没有检验记录？车间整洁度如何？
5. **看周边**：周边工厂是否与其有关联？（发现转包线索）
6. **突击回访**：第一次考察后，不提前通知再去看一次

> 千惠教训：王健第一次去就发现"大包大揽"问题，但被驳回。如果当时有制度化的考察流程和打分表，结论就不会取决于个人感觉。

## 第二章 签约：合同要点与红线条款

### 2.1 合同类型选择

**铁律：绝不用"订单合同"替代正式合作协议。**

| 合作类型     | 合同类型            | 说明            |
| -------- | --------------- | ------------- |
| 新产品联合开发  | 《委托开发协议》+《采购合同》 | 研发与生产分开签，风险隔离 |
| 成熟产品代工   | 《委托生产合同》        | 标准代工合同        |
| 钣金/零部件加工 | 《加工承揽合同》        | 简单加工类         |

> 千惠教训：廖总提出用订单合同替代协议，我们同意了。导致没有明确的技术需求、交付节点和违约责任，出了问题"拿着订单合同你告诉他都没得告"。

### 2.2 合同必须包含的条款

#### A. 技术需求明细（附件）

- 详细列明所有技术参数、功能要求、性能指标
- 作为最终验收的唯一依据
- 任何技术变更必须双方书面确认

> 这是千惠合同最大的漏洞——没有技术需求明细，导致验收无标准、变更无控制。

#### B. 交付节点与里程碑

| 里程碑      | 交付物    | 验收标准    | 截止日期  |
| -------- | ------ | ------- | ----- |
| M1：方案确认  | 技术方案文档 | 技术部评审通过 | 签约后X天 |
| M2：首件/样机 | 可运行样机  | 功能测试通过  | M1后X天 |
| M3：小批量   | 小批量产品  | 质量检验合格  | M2后X天 |
| M4：量产交付  | 正式产品   | 全检合格    | M3后X天 |

每个里程碑必须有**明确的交付物**和**验收标准**，不能只写一个"5月30日交付"。

#### C. 付款节点（与里程碑挂钩）

| 节点  | 比例   | 触发条件          |
| --- | ---- | ------------- |
| 预付款 | ≤30% | 合同签订后         |
| 进度款 | 30%  | M2样机验收通过      |
| 验收款 | 30%  | M4量产交付验收通过    |
| 质保金 | ≥10% | 质保期满后支付（至少1年） |

> 千惠教训：4月17日打款，但合同没有明确的付款节点与交付里程碑挂钩，钱付出去了就失去了谈判筹码。

#### D. 违约责任

- **节点违约金**：每延迟一个里程碑，按订单总额的5‰/天计算
- **总交货违约金**：超过约定交货日期X天，甲方有权取消订单并要求赔偿
- **质量违约**：验收不合格的返修/重做费用由乙方承担
- **转包违约**：未经甲方书面同意转包主体工序的，扣减订单总额20%作为违约金，甲方有权终止合同

#### E. 禁止转包条款

合同中必须明确写明：

1. 主体工序（电子开发、结构设计、总装）严禁转包
2. 确需外协的工序（如钣金加工），须提前书面报备并获得甲方同意
3. 甲方有权直接接触乙方的分包方进行质量监督
4. 乙方不得以任何理由阻止甲方接触分包方

> 千惠教训：廖总层层转包（电子给上合智能、钣金给石楼镇厂），还阻止我们去现场看。如果合同有禁止转包条款，我们就有法律依据。

#### F. 知识产权与保密

- 所有技术资料、设计图纸、工艺文件的知识产权归甲方所有
- 乙方不得为第三方生产同类产品
- 乙方须对甲方的技术信息严格保密
- 合同终止后X日内归还所有技术文件并删除电子副本

#### G. 售后条款

- 质保期：自验收之日起不少于1年
- 质保期内因加工原因导致的问题，乙方负责免费返修
- 质保金：预留10%作为售后保证金，质保期满后支付
- 若乙方无法提供售后能力，甲方自行承担，但应在合同中明确

#### H. 争议管辖

- 约定由甲方所在地人民法院管辖
- 避免到供应商所在地打官司

### 2.3 合同签订前的内部审批

合同签订前须经以下人员会签：

1. 技术负责人（确认技术需求明细）
2. 采购/商务（确认价格、付款条款）
3. 项目负责人（确认交付节点）
4. 公司负责人（最终审批）

## 第三章 过程管控：嵌入式管理

### 3.1 项目启动会

签约后、正式开工前，召开项目启动会，双方参加：

- 确认技术需求明细（逐条过）
- 确认交付里程碑和截止日期
- 确认双方对接人（甲方对接人、乙方对接人、技术对接人）
- 确认沟通机制（周报频率、例会时间、问题升级路径）
- 确认现场监督权限（甲方有权不定期到现场查看进度）

### 3.2 工作日志制度

**铁律：没有落到纸面上的跟进，等于没有跟进。**

甲方对接人每日填写《项目工作日志》，记录：

- 当日跟进事项
- 乙方反馈的进度
- 发现的问题
- 下一步计划

工作日志至少每周同步给项目负责人和技术负责人。

> 千惠教训：老朱说"其实我们都有跟进，但没有落到纸面上"。导致复盘时时间线混乱，很多事情"读起来有点费劲"。

### 3.3 里程碑验收

每个里程碑到达时，必须进行正式验收：

1. 乙方提交《阶段交付物清单》
2. 甲方技术部按合同技术需求明细逐项检验
3. 验收通过 → 签署《阶段验收单》→ 触发下一笔付款
4. 验收不通过 → 出具《整改通知单》→ 限期整改 → 复验

**里程碑验收不通过的，暂停下一笔付款。**

> 千惠教训：没有里程碑验收机制，钱付了、时间过了，才发现什么都没做出来。

### 3.4 现场监督权

合同中约定甲方享有现场监督权：

- 甲方有权不定期到乙方生产现场查看进度
- 乙方不得以任何理由拒绝或拖延
- 甲方有权直接接触乙方的分包方
- 乙方须在24小时内回应甲方的现场查看请求

> 千惠教训：廖总"至少十几次以上"拒绝让老朱去钣金厂看。如果有合同条款保障现场监督权，就不会这么被动。

### 3.5 通讯协议/技术文档管理

对于涉及软硬件接口的技术合作：

- 通讯协议文档须由乙方技术工程师（非老板）出具
- 甲方技术部须对协议文档进行评审
- 任何协议变更必须双方技术工程师确认，并书面记录变更原因
- 协议版本号管理：V1.0 → V2.0 → V3.0，每次变更注明日期和原因

> 千惠教训：通讯协议从V1.0到V3.0再到7月20日整体推翻，每次变更都没有正式的变更管理流程。

### 3.6 风险预警机制

以下信号出现时，立即启动风险评估：

| 风险信号         | 级别 | 应对措施            |
| ------------ | -- | --------------- |
| 乙方老板回避关键技术问题 | 黄色 | 要求与乙方技术工程师直接对话  |
| 承诺的交付物多次延期   | 橙色 | 书面发出《交期预警函》     |
| 发现未经报备的转包行为  | 红色 | 启动合同违约条款，准备替代方案 |
| 乙方更换关键技术人员   | 橙色 | 要求书面说明原因，评估影响   |
| 乙方老板到处找融资    | 黄色 | 加强财务监控，加速替代方案准备 |
| 乙方拒绝甲方到现场查看  | 红色 | 立即启动替代方案        |

> 千惠教训：以上6个信号全部出现了，但我们没有系统的风险预警机制，每个信号都被单独处理或忽略。

### 3.7 "技术疑虑举证机制"

内部建立机制：任何技术疑虑必须附带具体证据或具体问题。

- "我觉得他不行" → 不算数
- "他回答X问题时回避了Y技术点" → 算数
- "他给的方案在Z环节存在W缺陷" → 算数

目的：既不压制直觉，又逼出技术深度。提出疑虑的人必须能说出具体哪里不对，否则只记录为"待验证的直觉"，不作为决策依据。

## 第四章 验收与交付

### 4.1 验收标准

验收依据为合同附件中的《技术需求明细》，逐项检验：

1. 功能测试：所有功能是否正常
2. 性能测试：性能指标是否达标
3. 外观检验：外观是否合格
4. 可靠性测试：连续运行测试
5. 文档移交：操作手册、维护手册、BOM表

### 4.2 验收流程

1. 乙方提交《交付物清单》和《自检报告》
2. 甲方技术部按技术需求明细逐项检验
3. 检验通过 → 签署《验收单》
4. 检验不通过 → 出具《不合格报告》→ 乙方整改 → 复验
5. 复验仍不通过 → 按合同违约条款处理

### 4.3 交付物清单

交付时乙方须移交：

- 合格产品（约定数量）
- 技术文件（图纸、BOM、工艺文件）
- 检验报告
- 操作手册和维护手册
- 备品备件清单
- 供应商清单（用于售后追溯）

## 第五章 售后与收尾

### 5.1 质保期管理

- 质保期内出现质量问题，48小时内响应
- 乙方负责免费返修/更换
- 质保期满前30天，甲方进行质保期评估
- 评估通过 → 释放质保金
- 评估不通过 → 扣除相应质保金

### 5.2 合作终止/降级

当决定终止或降级合作时：

1. 书面通知对方，说明原因
2. 盘点在对方处的所有物料、设备、技术文件
3. 安排搬离（如有）
4. 结算剩余款项（扣除违约金/质保金后）
5. 签署《合作终止协议》

### 5.3 合作后评价

合作结束后（无论终止还是继续），填写《供应商合作评价表》：

- 交期表现（准时率）
- 质量表现（合格率、返修率）
- 配合度（沟通响应、问题解决）
- 转包情况
- 综合评分

## 第七章 十句铁律

> 以下十条是用千惠项目的真金白银换来的。无论时间多紧、关系多好、对方说得多么好听，这十条**无论如何**不可违背。

**铁律一：不查征信，不签约。**  
企查查/天眼查5分钟的事。涉诉超过5条、被执行人、实缴社保与声称规模不符——任何一个出现，停下来想清楚再走。千惠廖总十几条司法案件，我们直到项目快崩了才查。

**铁律二：不对比三家，不签约。**  
"没有资源""时间急"不是理由。只接触一家就签约，等于把命运交给一个你根本不了解的人。即使最终选了第一家，对比的过程也会让你知道自己的议价空间和风险底线。

**铁律三：订单合同不能替代正式协议。**  
订单合同只有数量和价格，没有技术需求、没有交付节点、没有违约责任。出了问题"拿着订单合同你告诉他都没得告"。研发归研发，生产归生产，分开签。

**铁律四：技术需求必须写成合同附件。**  
口头说的"没问题"不算数。每一个功能、每一个参数、每一个性能指标都要白纸黑字写进合同附件，作为最终验收的唯一依据。变更必须双方书面确认。

**铁律五：付款必须跟里程碑挂钩。**  
预付款不超过30%，每笔后续付款都要跟具体的里程碑验收挂钩。钱付完了就失去了谈判筹码。千惠4月17日打款后，就再也没什么能约束廖总了。

**铁律六：禁止转包写进合同，违者重罚。**  
主体工序严禁转包，外协须提前书面报备。甲方有权直接接触分包方。发现未经报备的转包，扣减20%订单金额。千惠的层层转包（电子给上合智能、钣金给石楼镇厂），如果有合同条款就有法律武器。

**铁律七：现场监督权不可让步。**  
甲方有权不定期到乙方现场查看进度，乙方不得以任何理由拒绝。千惠廖总"至少十几次"拒绝让老朱去钣金厂看——如果合同保障了现场监督权，他就没有这个底气。

**铁律八：风险信号出现，立即启动替代方案。**  
老板回避技术问题、交付多次延期、发现转包、更换关键人员、到处找融资、拒绝现场查看——任何一个信号出现，不要抱幻想，立即启动替代方案评估。千惠6个信号全亮了，我们还在"抱有幻想"。

**铁律九：包容有边界，止损要果断。**  
包容对方的短板可以，但包容的代价不能是项目失控。当对方连续两次承诺交付都落空时，就该从"包容"切换到"止损"。包容性太强不是优点，是风险。

**铁律十：没有落到纸面上的跟进，等于没有跟进。**  
工作日志、阶段验收单、会议纪要、问题清单——全部落纸面。口头沟通不算数，"我跟进了"但没记录等于没跟进。复盘时没有记录，时间线就"读起来有点费劲"，教训就白白流失。
