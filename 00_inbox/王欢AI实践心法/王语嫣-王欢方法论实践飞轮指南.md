## 一、wiki 卡片和 prompt 模板分别起什么作用

### 1.1 wiki 卡片 = 可复用的知识资产

wiki 卡片不是普通文档，而是**被 AI 能检索、能调用、能关联的知识单元**。

| 维度 | 普通文档 | wiki 卡片 |
|:---|:---|:---|
| 阅读对象 | 人 | 人 + AI |
| 结构 | 线性段落 | 按类型结构化（framework/concept/tool/case/dk） |
| 调用方式 | 人手动查找 | AI 按问题自动匹配 |
| 价值周期 | 看一次忘一次 | 长期可复用、可迭代 |

### 1.2 prompt 模板 = 把 raw 资料加工成卡片的生产线

prompt 模板是**预先写好的指令**，让 AI 稳定地、重复地把某种 raw 资料（口述稿、图片、案例）转换成某种 wiki 卡片。

| 对比 | 随手提问 | prompt 模板 |
|:---|:---|:---|
| 背景说明 | 每次都要重新说 | 一次写好，多次复用 |
| 输出结构 | 不稳定 | 稳定、可预期 |
| 人的角色 | 演员（每次亲自写） | 导演（定义模板，验收结果） |
| 质量 | 看当时发挥 | 随着模板迭代持续提升 |

### 1.3 两者关系

```
raw 资料（口述稿/图片/案例）
        ↓
  prompt 模板（生产线）
        ↓
  AI 生成初稿
        ↓
  人验收
        ↓
  wiki 卡片（知识资产）
        ↓
  下次遇到同类问题，AI 调用这张卡片
```

**一句话：prompt 模板是工具，wiki 卡片是产品。**

## 二、prompt 在什么情况下加载

### 2.1 prompt 给谁用

prompt 主要有两种用法：

1. **人直接复制到 AI 对话框使用**：你收到一份口述稿，打开对应的 prompt 模板，复制到豆包/Claude，粘贴资料，让 AI 生成。
2. **agent 作为 system prompt 或任务指令加载**：老顽童/王语嫣等 agent 在处理某类任务时，自动读取对应的 prompt 文件作为执行标准。

### 2.2 按场景加载 prompt 的规则

| 你收到的输入 | 加载哪个 prompt | 产出什么卡片 |
|:---|:---|:---|
| 一段课程/访谈口述稿 | `prompt-transcript-to-dk-card` | dark-knowledge 卡 |
| 一个具体商业案例 | `prompt-case-to-case-card` | case 卡 |
| 一个可操作的方法/流程 | `prompt-method-to-framework-card` | framework 卡 |
| 一个概念定义 | `prompt-concept-to-concept-card` | concept 卡 |
| 一个可直接用的模板/清单 | `prompt-template-to-tool-card` | tool 卡 |
| 多张相关卡片 | `prompt-cross-domain-dk-extraction` | 跨域 dk 卡 |
| 一组图片/示意图 | `prompt-images-to-framework-card` | framework/concept 卡 |

### 2.3 agent 加载 prompt 的触发条件

对于 KDO 知识工厂里的 agent：

- **老顽童**：收到"把 XX 资料加工成 XX 类型卡片"的任务时，从 `40_outputs/code/prompts/` 或任务文件中读取对应 prompt。
- **王语嫣**：在质量验收时，用 prompt 模板生成验收 checklist，检查卡片是否符合标准。
- **欧阳锋**：审查时，用 prompt 模板检查卡片是否达到 enriched 标准。

## 三、你的第一个飞轮：口述稿 → dk 卡

### 3.1 飞轮结构

```
收到口述稿
    ↓
加载 prompt-transcript-to-dk-card
    ↓
AI 生成 dk 卡初稿
    ↓
用 checklist 验收
    ↓
{ 不达标 } → 精确反馈 → AI 迭代 → 再验收
    ↓
{ 达标 } → 保存为 wiki 卡片
    ↓
把本次修改点反哺到 prompt 模板
    ↓
下次收到口述稿，直接调用更新后的模板
```

### 3.2 为什么要从 dk 卡开始

- dk 卡价值最高：暗知识、反直觉、避坑。
- 口述稿里 dk 含量最高：讲课时的案例、教训、判断最容易被忽略。
- 成功一次，后面 100 次都能复用。

## 四、可直接使用的 prompt 模板

### prompt-transcript-to-dk-card

```markdown
## Background
你是 KDO 知识工厂的内容生产者。我要把一段课程/访谈口述稿加工成一张 dark-knowledge 卡片。

目标读者：团队内部成员，需要快速调用关键洞察和避坑经验。

我的角色定位：
- 行业：[填写你的行业]
- 核心职责：[填写你的职责]
- 输出风格：简洁、结构化、少修辞、多用表格和 checklist

## Instruction
请从口述稿中提取暗知识，并按以下结构组织：

1. **核心洞察**（1 句话，用 Burn line 风格）
2. **为什么值钱**（2-3 点，说明这个洞察为什么重要）
3. **典型场景**（2 个，说明在什么情况下会遇到这个问题）
4. **操作方法**（3-5 步，可执行）
5. **适用边界**（2 行表格：适用 / 不适用）
6. **常见失败模式**（3 条表格：失败模式 / 症状 / 修复）
7. **与其他知识的关系**（2-3 个相关概念或框架）
8. **Action Triggers**（3 个：什么情况下用这个洞察）

## Task
基于以下口述稿，生成一张 dark-knowledge 卡片。

## Constraint
- 不要直接复制原文，要提炼和结构化
- 每个观点都要有原文依据，不能凭空发挥
- 不要写空泛的建议，每条都要有具体动作
- 失败模式必须包含"症状"和"修复"两列
- 输出必须是 markdown 格式
- 不要生成 YAML frontmatter

## Output
- 标题：用一句有力的话概括核心洞察
- 正文约 1500-2500 字
- 使用表格、列表、代码块增强可读性

## Example
参考以下结构和风格：
- `dk-wanghuan-spec-trap`
- `dk-wanghuan-magic-defeats-magic`

[在此粘贴口述稿]
```

## 五、验收 checklist

收到 AI 生成的 dk 卡初稿后，逐条检查：

### 5.1 结构完整性
- [ ] 有明确的"核心洞察"或"Burn line"
- [ ] 说明了"为什么值钱"
- [ ] 有 2 个以上典型场景
- [ ] 有可执行的操作方法
- [ ] 有适用边界表格
- [ ] 有 3 条以上失败模式（含症状+修复）
- [ ] 有与其他知识的关系
- [ ] 有 3 个以上 Action Triggers

### 5.2 内容质量
- [ ] 没有直接复制原文的大段内容
- [ ] 每个观点都有原文依据或合理推导
- [ ] 没有空话、套话
- [ ] 建议都是可执行的
- [ ] 适用边界区分了"适用"和"不适用"

### 5.3 与 KDO 规范一致
- [ ] 卡片类型正确（dark-knowledge）
- [ ] 有明确的 source 引用
- [ ] 术语和命名与现有卡片一致
- [ ] 没有内部 dangling 链接

### 5.4 升级标准（达到 enriched）
- [ ] 加 YAML frontmatter（id, type, status, domain, source_refs, related, tags）
- [ ] status 改为 enriched
- [ ] reviewed_by 指定欧阳锋
- [ ] 运行 `python 90_control/scripts/kcard-quality-gate.py` 无新增 P0/P1

## 六、飞轮加速的 4 个杠杆

### 杠杆 1：AI 业务档案

每次对话前，先把你的 AI 业务档案粘贴进去。这样 AI 知道你是谁、你的风格、你的行业暗规则、你的输出标准。

参考：`[[tool-wanghuan-ai-business-profile]]`

### 杠杆 2：BITCOE 框架

每次写 prompt 时，检查六槽位是否填全：
- B Background（背景）
- I Instruction（指令/方法）
- T Task（任务）
- C Constraint（约束/红线）
- O Output（输出格式）
- E Example（示例）

参考：`[[framework-wanghuan-bitcoe-prompt-framework]]`

### 杠杆 3：对抗式生成

不要只让 AI 生成一版。让 AI 生成后，再让另一个 AI/模型按最高标准挑毛病，迭代 2-3 轮。

参考：`[[dk-wanghuan-magic-defeats-magic]]`、`[[concept-wanghuan-adversarial-generation]]`

### 杠杆 4：标准 × 迭代

输出质量 = 标准 × 迭代。不要追求一次写对，要追求每一轮都比上一轮更清晰。

参考：`[[dk-wanghuan-output-equals-standard-times-iteration]]`

## 八、常见问题

### Q1：prompt 模板是不是每次都要完全一样？

不是。模板是起点，每次根据具体资料微调。但 80% 的内容应该固定，只改 20% 的变量部分。

### Q2：为什么一定要先写 AI 业务档案？

因为 AI 不知道你的上下文。你不说，它按通用水平输出；你说了，它按你的标准输出。业务档案就是一次性把上下文说清楚。

### Q3：验收时怎么给出有效反馈？

不要用"感觉不对"这种模糊反馈。要用：
- "第三段没有原文依据，请补充"
- "失败模式只有 2 条，请补到 3 条"
- "适用边界表格缺失，请补充"

越具体，AI 改得越准。

### Q4：什么时候把 prompt 升级成系统？

当你发现：
- 同一个 prompt 模板已经稳定产出 10 张以上合格卡片；
- 处理流程中有多个步骤可以自动化；
- 有多个 prompt 模板之间需要串联。

这时就可以考虑把它们编排成一个知识生产系统。
