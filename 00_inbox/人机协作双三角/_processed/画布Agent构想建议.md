# 画布 Agent 构想建议

> 背景：基于「双三角画布填充 Prompt」终稿和巨米推广测试，提出"画布 Agent"的产品形态、核心能力、实现路径和与 OPC 智能体军团的集成方案。

---

## 一、什么是画布 Agent

**定义**：画布 Agent 是一个专门负责"把模糊任务结构化"的智能体。它在任何具体工作开始前介入，通过九层深挖把用户需求转换成一张标准双三角画布，并把过程中沉淀的数据自动整理为 DataPack。

**一句话定位**：

> 任何新任务进入系统，先过一遍画布 Agent，再决定交给哪个执行 Agent。

---

## 二、为什么要做画布 Agent，而不是只用 Prompt

| 对比维度 | 单次 Prompt | 画布 Agent |
|----------|------------|-----------|
| 状态记忆 | 没有，每次从零开始 | 有，记住用户历史画布和偏好 |
| DataPack 管理 | 人工整理 | 自动识别、命名、归档 |
| 跨任务复用 | 需要手动复制 | 自动推荐相关历史画布和 DataPack |
| 质量稳定 | 依赖用户每次输入质量 | 主动追问、校准、补全 |
| 规模扩展 | 一对一对话 | 可以同时服务多个任务、多个项目 |
| 与执行 Agent 衔接 | 人工传递画布 | 自动把画布分发到下游 Agent |

**结论**：Prompt 是画布 Agent 的"对话引擎"，但画布 Agent 是 Prompt + 记忆 + 数据管理 + 任务分发的完整系统。

---

## 三、画布 Agent 的核心能力

### 3.1 九层对话引擎

- 内置终稿 Prompt 作为 System Prompt
- 支持固定走完九层，不跳过、不合并
- 每层结束时自动总结并要求用户确认
- 对模糊回答提供 2-3 个选项推进

### 3.2 DataPack 自动识别与归档

在对话过程中，Agent 自动识别以下内容并提示用户是否沉淀为 DataPack：

- 正面案例
- 负面案例
- 客户故事
- 品牌话术
- 选题模板
- 工具配置
- 评估标准
- 复盘数据

每个 DataPack 自动命名、打标签、标注来源画布、标注使用次数。

### 3.3 历史画布与 DataPack 智能推荐

当用户开始新任务时，Agent 主动推荐：

- 相似任务的历史画布
- 可复用的 DataPack
- 历史成功/失败模式

例如：

> 你之前做过「巨米推广」的画布，其中"客户改造案例库"和"高转化选题清单"可能适用于这个新任务，是否复用？

### 3.4 画布质量评分

第 9 层输出时，Agent 对画布完整度进行自评：

| 评估项 | 标准 | 分值 |
|--------|------|------|
| 任务定位清晰度 | 核心问题是否一句话说清 | 0-10 |
| 场景聚焦度 | 是否有明确边界和优先级 | 0-10 |
| 审美可验证性 | 是否有 60 分/99 分标准和 Not-to-do | 0-10 |
| 体系可执行性 | 流程、里程碑、分工是否明确 | 0-10 |
| 创造力差异化 | 是否有独特假设和跨领域灵感 | 0-10 |
| 数据可用性 | 是否有正面/负面案例和 Domain Knowledge | 0-10 |
| 基本功匹配度 | 工具选型是否具体可落地 | 0-10 |
| 飞轮闭合度 | 是否有评估、反馈、迭代机制 | 0-10 |

总分 80 分以上才建议进入执行阶段；低于 60 分要补完对应层。

### 3.5 与下游执行 Agent 的自动衔接

画布完成后，Agent 根据画布内容自动判断应该调用哪个执行 Agent：

| 任务类型 | 下游 Agent |
|----------|-----------|
| 内容型 | 内容生产 Agent |
| 销售型 | 销售话术 Agent / 客户跟进 Agent |
| 产品型 | 产品需求 Agent / 原型设计 Agent |
| 数据分析型 | 数据分析 Agent |
| 复合型 | 多 Agent 编排执行 |

画布本身作为下游 Agent 的 System Context 输入。

## 四、画布 Agent 的三种产品形态

### 形态一：对话式画布 Agent（最小可行版）

**实现方式**：在 Claude Project / GPTs / Kimi 智能体中配置 System Prompt + 上传历史画布和 DataPack 作为知识库。

**优点**：
- 零开发成本
- 立即可用
- 适合个人用户

**缺点**：
- DataPack 管理依赖手动
- 跨任务复用能力弱
- 无法自动分发下游 Agent

**适合阶段**：现在就可以做。

### 形态二：工作流画布 Agent（中等版）

**实现方式**：在 Coze / Dify / 飞书多维表格中搭建工作流：

```
用户输入任务 → 触发九层对话节点 → 每层输出结构化字段 → 自动存入多维表格 → 生成画布 Markdown → 推荐历史 DataPack → 分发到下游 Agent
```

**优点**：
- 结构化存储
- 可以自动化归档 DataPack
- 便于团队协作

**缺点**：
- 需要学习无代码平台
- 复杂逻辑（如智能推荐）受限

**适合阶段**：1-2 周内可以搭建原型。

### 形态三：本地/私有化画布 Agent（完整版）

**实现方式**：用 Python + 本地数据库 + API 调用构建：

```
前端对话界面
    ↓
对话管理模块（维护九层状态）
    ↓
LLM 调用层（Claude / Kimi / MiniMax）
    ↓
画布存储模块（SQLite / JSON）
    ↓
DataPack 管理模块（向量检索 + 标签体系）
    ↓
下游 Agent 路由模块
```

**优点**：
- 完全可控
- 可训练自己的画布模型
- 可接入任意下游 Agent
- 数据完全私有

**缺点**：
- 开发成本高
- 需要维护

**适合阶段**：作为 OPC 智能体军团的长期基础设施。

## 五、画布 Agent 在 OPC 智能体军团中的位置

### 5.1 系统架构图

```
                    ┌─────────────────┐
                    │   用户输入新任务   │
                    └────────┬────────┘
                             ↓
                    ┌─────────────────┐
                    │   画布 Agent     │
                    │  （九层深挖 +    │
                    │  DataPack 管理）  │
                    └────────┬────────┘
                             ↓
              ┌──────────────┼──────────────┐
              ↓              ↓              ↓
      ┌───────────┐  ┌───────────┐  ┌───────────┐
      │ 内容生产   │  │ 销售转化   │  │ 数据分析   │
      │  Agent    │  │  Agent    │  │  Agent    │
      └─────┬─────┘  └─────┬─────┘  └─────┬─────┘
            └──────────────┼──────────────┘
                           ↓
                    ┌─────────────────┐
                    │  数据飞轮/复盘    │
                    │  回流到画布 Agent │
                    └─────────────────┘
```

### 5.2 画布 Agent 是 OPC 的"任务入口网关"

所有任务必须先经过画布 Agent，确保：

- 每个任务都有清晰的六要素输入
- 每个任务都沉淀了 DataPack
- 每个任务都能被正确路由到执行 Agent
- 每个任务都能被复盘和迭代

### 5.3 画布 Agent 与 DataPack 飞轮

```
画布 Agent 生成画布
        ↓
执行 Agent 使用 DataPack 产出结果
        ↓
结果被评估、复盘
        ↓
新数据沉淀为新 DataPack
        ↓
画布 Agent 在下个任务中推荐复用
        ↓
循环……
```

## 六、画布 Agent 的实现路线图

### 第一阶段：MVP（1-2 周）

**目标**：能跑通九层对话并输出画布。

**动作**：
1. 在 Claude Project 或 Kimi 中创建"画布 Agent"，配置终稿 Prompt
2. 上传已有的双三角课程笔记、历史画布、DataPack 作为知识库
3. 测试 3-5 个真实任务
4. 收集反馈，优化 Prompt

**交付物**：可用的对话式画布 Agent

### 第二阶段：结构化（2-4 周）

**目标**：画布和 DataPack 能被结构化存储和检索。

**动作**：
1. 用飞书多维表格或 Notion 建立画布数据库
2. 设计 DataPack 标准字段（名称、类型、用途、来源、标签、使用次数）
3. 把每次画布输出自动或半自动同步到数据库
4. 实现简单的关键词/标签检索

**交付物**：画布 + DataPack 知识库

### 第三阶段：智能化（1-3 个月）

**目标**：画布 Agent 能主动推荐、自动分发、持续学习。

**动作**：
1. 用向量数据库存储画布和 DataPack，实现语义检索
2. 开发画布质量评分模块
3. 开发下游 Agent 路由模块
4. 建立反馈闭环：执行结果回流到画布 Agent

**交付物**：完整的画布 Agent 系统

## 七、画布 Agent 的关键设计决策

### 7.1 九层是否可以动态裁剪？

**建议**：作为 Agent 的默认模式，九层固定走完；但可以增加一个"快速模式"，只对复杂任务使用九层，对简单任务使用三层精简版（任务定位 + 场景 + 输出）。

### 7.2 DataPack 由谁命名？

**建议**：AI 主动建议名称和标签，用户确认或修改。避免完全由 AI 决定导致混乱。

### 7.3 画布是否必须达到 80 分才执行？

**建议**：作为默认规则，80 分以上进入执行；60-80 分提示用户补完关键要素；60 分以下不建议执行，返回补画布。

### 7.4 用户是否可以看到底层 Prompt？

**建议**：可以。让用户理解九层逻辑有助于他们提升双三角思维，这是长期目标。

## 八、画布 Agent 与双三角课程的呼应

画布 Agent 实际上是在帮你把双三角课程中学到的六顶点、四级修炼、DataPack、飞轮设计等概念，固化成一个可以天天用的生产工具。

| 课程概念 | 在画布 Agent 中的体现 |
|----------|---------------------|
| 六顶点 | 画布的六个必填模块 |
| 四级修炼 | DataPack 从粗糙到精细的迭代 |
| DataPack | 自动识别、命名、归档、复用 |
| 飞轮设计 | 执行结果回流，更新画布和 DataPack |
| 人机分工 | 每层明确标注人和 AI 的职责 |

## 九、推荐的第一阶段落地方案

综合考虑成本、速度和可扩展性，我建议第一阶段这样落地：

### 9.1 工具选择

- **对话引擎**：Claude Project（长上下文、适合复杂对话）或 Kimi（中文好、便宜）
- **画布存储**：飞书多维表格（免费、协作方便）
- **DataPack 管理**：飞书云文档 + 多维表格标签
- **下游衔接**：先用人工判断调用哪个 Agent，后续再自动化

### 9.2 最小流程

```
用户在 Claude Project 中打开"画布 Agent"
        ↓
按九层填完画布
        ↓
AI 输出 Markdown 画布
        ↓
用户一键复制到飞书多维表格
        ↓
AI 同时输出 DataPack 清单
        ↓
用户按清单整理 DataPack 到飞书云文档
        ↓
用户基于画布调用具体执行 Agent
        ↓
执行后把结果和反馈更新到飞书
```

### 9.3 第一步行动

1. 我在 Claude Project 或 Kimi 中帮你配置好画布 Agent。
2. 你把巨米推广的真实素材（客户故事、历史文章、品牌介绍）上传到知识库。
3. 我们用真实场景跑一次，生成第一版正式画布。
4. 根据这次体验，决定要不要升级到工作流版或本地版。

## 十、风险与边界

1. **不要期待画布 Agent 一次性解决所有问题**。它只是把任务结构化，执行仍然需要下游 Agent 和人的努力。
2. **DataPack 质量决定画布 Agent 价值**。Garbage in, garbage out。
3. **过度结构化可能扼杀创造力**。在创造力层要给足空间，不要让 Agent 太急着收敛。
4. **用户审美不够时，画布质量有限**。Agent 可以引导，但不能替代用户提升审美。

---

## 总结

**画布 Agent 不是又一个聊天机器人，而是 OPC 智能体军团的"任务入口网关"。**

它解决的终极问题是：

> 当有一个新想法时，如何快速把它变成 AI 能高质量执行、人能持续复盘迭代、数据能不断沉淀复用的结构化任务。

短期可以用 Claude Project/Kimi 跑起来，中期用飞书/Coze 做结构化，长期可以发展为私有化智能中枢。
