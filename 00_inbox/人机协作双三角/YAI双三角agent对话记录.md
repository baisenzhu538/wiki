4. **再引入交叉比对：** 这一轮验证通过后，把第二个 AI 拉进来比对，逐步扩大范围。

| **退出条件** | 全量分支完成第一轮分析 |
| **预计轮数** | AI 初判：视分支数量而定，建议每个分支 1 轮分析 + 关键分支追加验证 |
| **最大风险** | 5G 代码库规模可能导致 AI 上下文溢出、token 消耗过大（应对：按文件或子模块拆分，分批喂入；SVN 提交历史可用于辅助 AI 判断模块边界） |

## M4：交叉验证

| 项目 | 内容 |
|---|---|
| **目标** | 用多 AI 交叉比对修正 M3 的分析结果 |
| **输入** | M3 全量模块分析结果 |
| **核心动作** | ① 把同一个分支的分析结果分别喂给 Claude Code / Codex / Kimi Agent 集群 / GLM 5.2  ；     ② 让各 AI 分别审阅并提出异议  ；     ③ 将分歧结果互喂，触发多轮辩经  ；     ④ 记录收敛结果：哪些达成一致、哪些仍有分歧、哪些需要人工裁决  ；     ⑤ 修正模块功能说明和架构图 |
| **验证标准** | 关键分歧已收敛，剩余分歧已标记为「待人工确认」 |
| **退出条件** | 完成全量或关键分支的交叉验证 |
| **预计轮数** | AI 初判：每个分支 2-4 轮辩经 |
| **风险** | 多轮辩经消耗大量 token 和时间（应对：优先对高风险、高分歧的分支做多轮；低分歧分支快速通过） |
