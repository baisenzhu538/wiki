# 执行与工具层 (Execution Case)

## 工作流协议（三阶段循环）

### Phase 1: 广域扫描与初始线索库建立

1. **需求解析**：将用户需求分解为 3-5 个核心调研子目标。
2. **关键词育种**：为每个子目标生成 三组嵌套关键词：
   - **宽泛组** (探索边界，如"新能源汽车 竞争格局")
   - **精确组** (聚焦核心，如"蔚来 2024 毛利率")
   - **长尾组** (挖掘细节，如"蔚来换电站 用户体验 吐槽")
3. **执行扫描**：使用搜索引擎执行这三级关键词搜索。
4. **线索提取**：从搜索结果中提取 《初始线索库》，必须包含：
   - **实体**：公司、产品、人名、机构。
   - **术语**：技术名词、行业黑话、事件名称。
   - **关联**：初步发现的竞争、合作、上下游关系。
   - **冲突点**：任何早期发现的观点矛盾或数据不一致。
5. **退出条件**：生成 《线索启动报告》，包含：子目标、初始关键词、初始线索库。**必须获得用户"确认启动"指令后，方可进入 Phase 2。**

### Phase 2: 线索驱动的知和侦察循环

这是一个 **循环过程**，最小循环单元为 **处理一个线索库**。

**单次循环步骤**：

1. **选择线索**：从《线索库》中选取一个优先级最高且未被充分挖掘的线索 (如"公司X")。
2. **策略匹配**：查询 `./references/03_search_tactics.md`，为该线索匹配 具合适的OSCAR战术 和 **最高效的** 资源。
3. **生成侦察指令**：设计具体的搜索指令或调查动作。
4. **执行与采集**：执行指令，收集信息片段。记录《递归信息的原始来源 (平台+URL/查询式)》。
5. **交叉验证**：对于关键信息点 (如"A与B公司合作")，立即到其他相关渠道进行验证。
6. **结束判断**：分析新信息的价值，提取新的实体、术语、关联关系，并将其添加回 《线索库》——标记已处理线索的状态。
7. **冲突标注**：如果发现信息矛盾，在工作区创建 "**冲突信息点**"，罗列矛盾双方的信念及来源。

**循环控制与退出条件**：

- **继续循环**：如果《线索库》中仍有高优先级未处理线索，或在上次循环中发现了高价值新线索。
- **退出循环**：当满足以下任一条件：
  a. 已完成 3轮完整循环（遍历线索库3次）。
  b. 连续 2次循环 未向线索库添加高价值新条目。
  c. 用户发出 "**终止侦察**" 指令。
- **循环产出**：《立体化信息网络图谱》及支撑它的原始信息片段（即来源标注）。

### Phase 3: 精细融合与报告生成

1. **信息加权**：依据 `./references/04_source_triage.md` 对信息进行可信度加权。
2. **报告撰写**：严格遵循 `./references/05_board_memo_manifest.md` 的格式与风格。
3. **快捷指令**：
   - 报告每个关键论断后**必须**附上 标 【1】【2】 注明来源。
   - 必须包含独立章节 "**关键信息冲突与不确定性分析**"，直接引用 Phase 2中标注的"**冲突信息点**"内容。
   - 必须在报告末尾附上 "**本次调研采用的 主要方法与渠道清单**"，说明侦察路径。
4. **最终产出**：《基于公开数字情报的分析报告》。
5. **路径确认**：向用户提交报告，并询问 "报告已生成，请重点关注"**冲突与不确定性分析**"章节，是否需要基于现有发现，启动新一轮针对特定疑点的侦察循环？"

## 架构范式声明

本Skill采用 "**侦察-行动" (Scout) 与 "完工转化" (Architect)** 融合范式。

- **侦察-行动**：体现在Phase 2的**线索流转 → 策略匹配 → 执行 → 更新"循环中。
- **完工转化**：整个工作流是一个可自我迭代的侦察框架，Phase 3的结束语为新一轮侦察预留了接 口。
