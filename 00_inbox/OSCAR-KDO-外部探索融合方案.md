## 一、问题诊断

KDO 当前的外部探索 SOP（定义在 `entry-quality-gate` skill）是一套实战长出来的工作流。一堂 OSCAR 五步法是经过方法论验证的调研框架，在 wiki 中已有完整卡片（`framework-yitang-oscar-research`，置信度 0.9）。**两者在做同一件事，但互不引用，术语未对齐，且 KDO SOP 缺失了 OSCAR 最核心的前三步。**

---

## 二、当前状态：逐项对照

| OSCAR 步骤 | 核心问题 | KDO SOP 对应 | 覆盖度 | 差距 |
|:---|:---|:---|:---:|:---|
| **O·锁定目标** | "要做出什么决策？" | **无显式步骤** | 🔴 | KDO 直接"选方向"，跳过了目标锁定。四种目标类型（选择题/解答题/设计题/竞争题）未被应用。 |
| **S·缩小范围** | "聚焦什么层面？" | 选方向（隐约对应） | 🟡 | "确定3-4个搜索方向"≈缩小范围，但没有四层面意识（宏观/中观/微观/单点），也没有"剥离清单"。 |
| **C·罗列清单** | "按什么步骤执行？" | **无** | 🔴 | 无调研计划/执行清单。广撒网直接搜，跳过"先设计搜什么、按什么顺序"。探索过程透明靠事后补。 |
| **A·获取情报** | "怎么拿到高质量情报？" | 广撒网+深追搜 | 🟡 | 只用 web_search（=公开信息层）。OSCAR A 有五层：公开/半公开/专家访谈/逆向工程/社会工程——全未用。 |
| **R·正确归因** | "怎么判断情报是否可信？" | 交叉比对+六层比对 | 🟢 | KDO 超越 OSCAR。六层比对（L1-L6）是 R 的增强版，加上四路 Attacker 交叉验证和准入清单。 |

### 整体判断

```
KDO SOP = R-heavy（后重前轻）
OSCAR   = O/S/C-heavy（前重后轻）

融合方向 = 用 OSCAR 的前端设计补 KDO 的前三步 + KDO 的后端验证保留为增强版 R
```

| KDO 独有能力 | 说明 | 价值 |

## 四、OSCAR 有、KDO 缺失的部分（需注入）

### 4.1 注入 O：锁定目标

**当前问题**：KDO SOP 第一步是"选方向（确定3-4个搜索方向）"——这已经是 S 了。O 完全跳过。

**注入内容**：

| 注入点 | 具体内容 | 来源 |
|:---|:---|:---|
| O 步骤 | 在"选方向"之前增加"锁定目标"——明确本次外部探索要回答什么决策问题 | OSCAR O |
| 四种目标类型 | 判断是选择题/解答题/设计题/竞争题中的哪一种，影响后续策略 | OSCAR O |
| 反模式检查 | "这是为了解还是做决策？""一句话能否说清目标？" | OSCAR O 失败模式 |

**注入后 SOP 第一步变为**：

```
Step 0：锁定目标（O）
  - 这次外部探索要支持什么决策？
  - 是选择题/解答题/设计题/竞争题？
  - 如果答案为"了解一下"→拒绝启动，先回到决策问题
```

### 4.2 注入 S：缩小范围 + 四层面

**当前问题**："选3-4个搜索方向"没有层级意识。

**注入内容**：

| 注入点 | 具体内容 | 来源 |
|:---|:---|:---|
| 四层面标注 | 每个搜索方向标注层面（宏观/中观/微观/单点） | OSCAR S |
| 剥离清单 | 明确"本次不搜索什么"——防止范围失控 | OSCAR S 剥离原则 |
| 反模式检查 | "搜索方向是否超过5个？""是否每个方向都有明确层面？" | OSCAR S 失败模式 |

**注入后 SOP 第二步变为**：

```
Step 1：缩小范围（S）
  - 确定搜索方向，每个标注层面（宏观/中观/微观/单点）
  - 写剥离清单：本次不搜索什么？
  - 如果方向>5个或跨两个以上层面→缩小范围
```

### 4.3 注入 C：罗列清单

**当前问题**：KDO SOP 没有调研计划/执行清单步骤。

**注入内容**：

| 注入点 | 具体内容 | 来源 |
|:---|:---|:---|
| 搜索清单 | 每个搜索方向列出：关键词、搜索来源类型、预期产出 | OSCAR C |
| 阶段门控 | 搜到什么程度可以停止？搜到什么程度需要深追搜？ | OSCAR C + Agent Pipeline 门控 |
| 反模式检查 | "清单是否针对本次目标定制？""是否在套模板？" | OSCAR C 失败模式 |

**注入后 SOP 第三步变为**：

```
Step 2：罗列清单（C）
  - 每方向列出：搜索关键词 + 目标来源类型 + 预期产出
  - 设定门控：信息源≥3个才进入下一阶段？覆盖率≥70%？
  - 如果清单和上次完全一样→重新设计（防止清单僵化）
```

### 与旧 SOP 的差异

| 维度 | 旧 SOP | 新 SOP |
|:---|:---|:---|
| 步数 | 5步 | 6步（O/S/C/A/R/出诊断） |
| O 目标锁定 | 无 | ✅ 四类型目标判断 |
| S 层面意识 | 无 | ✅ 四层面标注 + 剥离清单 |
| C 执行清单 | 无 | ✅ 关键词清单 + 门控条件 |
| A 获取手段 | web_search 单一 | ✅ 公开+半公开，有条件扩展 |
| R 归因 | 已有 | 保留，加 OSCAR 归因四步法引用 |

## 六、失败模式融合

将 OSCAR 的 10 种失败模式注入 KDO SOP 的已知失败模式库：

| OSCAR 失败模式 | KDO 对应风险 | 注入位置 |
|:---|:---|:---|
| 目标模糊（"了解一下"） | 外部探索无决策指向 | Step 0 门控 |
| 范围失控（什么都想看） | 搜索方向过多、跨层面 | Step 1 剥离清单 |
| 清单僵化（套模板） | 每次探索用同一套关键词 | Step 2 反模式检查 |
| 跳过O直接S | KDO 旧 SOP 的默认行为 | Step 0 强制前置 |
| 跳过S直接C | 搜索方向无层面标注 | Step 1 强制标注 |
| 获取不足 | 只搜3-5条就停 | Step 3 门控（≥3独立源） |
| 归因草率 | 交叉比对不充分 | Step 4 六层比对 |
| 权威迷信 | 单一来源下结论 | Step 4 多源验证 |
| 验证不足 | 未做 search_files 扫 wiki | Step 4 交叉比对 |
