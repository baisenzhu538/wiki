# 设计：KDO 技能提取基础设施

> 问题：KDO 三步编译法只产概念卡。月白的"图片文字变形处理"、半肥猫的"豆包输入法+口喷"——这些技能在 enrich 阶段被丢弃。需要一条系统化的技能提取管线。

---

## 零、KDO 知识处理的三个维度

用户明确了 KDO 知识处理服务于三个方向：

| 维度 | 干什么 | 产出 | KDO 管线 | 受众 |
|:------|:------|:-----|:-----|:-----|
| **对内** | 对齐认知，帮 Agent 更准 | 概念卡 + 技能卡 | enrich → validate → kdo query | AI Agent + 我（检索） |
| **对外** | 传播给人看 | 文章/网页 | produce → validate → ship | 外部读者 |
| **对己** | 提升自己能力 | 技能卡 | 提取 → 检索 → 复用 | 我 |

技能卡横跨对内和对己两个维度：对内让 Agent 理解操作流程，对己让我能搜到"怎么做"。CLI 接口也属于对内——为 Agent 提供知识检索能力。

本次设计的技能提取管线，同时服务于**对内**（Agent 不被概念卡限制）和**对己**（自己不丢失技能）。

---

## 一、问题的本质

KDO 的 capture→ingest→enrich→validate 管线是为**陈述性知识**（概念/理论/框架）设计的。技能是**程序性知识**（操作/方法/技巧），三步编译法的压缩→质疑→对标对它无效：

| | 概念卡 | 技能卡 |
|:--|:------|:------|
| 核心问题 | "这是什么" | "怎么做" |
| 三步编译法 | ✅ 浓缩观点→质疑边界→对标冲突 | ❌ 技能没有"观点"，只有步骤 |
| 丢失位置 | — | enrich 阶段被当成边角料丢弃 |
| 例子 | [[y-model]] | "AI 生图文字变形怎么修" |

**技能不是"没被记录"——是管道里根本没有接技能的口。**

正文结构：

```markdown
# 技能：用口喷输入法生成高质量 AI 提示词

## 原始表述
> 半肥猫在 AI 俱乐部分享中提到：...

## 操作步骤
1. 打开豆包输入法
2. 口述你想让 AI 做的事（自然语言，不用组织）
3. 豆包自动转文字
4. 把文字贴进 AI 工具作为提示词

## 适用场景
- ✅ 快速出初稿
- ✅ 思路不清晰时先说出来
- ❌ 需要精确参数控制时不适合
- ❌ 涉及隐私内容时不适合

## 为什么有效
口述绕过了"组织语言"的认知负荷，直接用自然语言表达意图。
相比打字，口述的速度是 3-5 倍，且更接近"人脑思考"的自然节奏。

## 工具/环境
- 豆包输入法 App（必需）
- 安静环境（建议）

## 常见失败模式
- 口述太长导致转写偏差 → 分段口述
- 环境噪音干扰 → 用耳机麦克风

## 关联技能
- [[skill-ai-prompt-iteration]] — 拿到初稿后的迭代技巧
- [[skill-ai-image-text-fix]] — 图片文字问题处理

## 来源
- 半肥猫，AI俱乐部-AI学习落地分享，2026-06
```

### 2.3 管道位置：enrich 的并行步骤

```
capture → ingest → enrich ─┬→ 概念卡（三步编译法，已有）
                           └→ 技能卡（技能提取，新增）
                                   │
                                   ▼
                              validate（扩展支持 skill 类型）
                                   │
                                   ▼
                              kdo query 可检索技能
```

**关键**：技能提取和概念卡生产是**同一次 enrich 的两个并行输出**，不需要多跑一趟。

## 三、技能检测机制

### 3.1 语言模式

口述稿中，技能通常伴随以下语言模式：

| 模式 | 例子 |
|:------|:-----|
| 操作链 | "先打开...然后...接着..." |
| 技巧声明 | "技巧就是..." / "我的方法是..." / "一个小窍门" |
| 工具+动作 | "用豆包输入法..." / "在 AI 里输入..." |
| 对比经验 | "以前我...后来发现..." |
| 避坑指南 | "不要...应该..." |
| 效果断言 | "...之后效果好了很多" |

### 3.2 LLM Prompt（enrich --extract-skills 使用）

```
你是技能提取器。从以下口述稿中提取所有可操作的技能。

对每条技能，提取：
1. 原始引用：技能相关的原文段落
2. 技能名称：简短的动作描述（动词开头）
3. 操作步骤：1-2-3 怎么做
4. 适用场景：什么时候用、什么时候不用
5. 为什么有效：背后的原理
6. 工具/环境：需要什么工具
7. 关联域：链接到哪些已有概念卡

输出格式：每技能一个 YAML + Markdown 块。

不要提取：
- 纯观点/理论（那是概念卡的活）
- 太具体的个性化偏好（除非有通用价值）
- 重复的技能（如果已有类似 skill 卡，标注而不是新增）
```

### 3.3 CLI

```bash
# enrich 时顺便提取技能
kdo enrich --wiki-path <path> --extract-skills

# 从指定口述稿单独提取技能
kdo enrich --extract-skills --source <transcript_path>

# 批量回溯：扫全部已有 enrich 过的口述稿，补提技能
kdo enrich --extract-skills --all-transcripts
```

## 五、和 DK 暗知识卡的关系

| | dk-* (暗知识) | skill-* (技能) |
|:--|:-------------|:--------------|
| 方向 | 负向："不要做什么" | 正向："要怎么做" |
| 模板 | 六字段（原始表述→场景→操作→边界→价值→关联） | 七字段（原始表述→步骤→场景→原理→工具→失败模式→关联） |
| 触发 | 失败/错误/踩坑 | 经验/技巧/方法 |
| 共存 | 同一条经验可同时产 dk 卡和 skill 卡 | |
| 例子 | dk-ef-001：开漏输出导致时序问题 | skill-diagnostic-firmware：怎么做诊断版固件 |

## 七、不做的事

- **不新建独立的 skill extractor 命令**——集成到 `kdo enrich` 里，保持管线入口一致
- **不做全自动技能卡**——LLM 产骨架，人审核+补充步骤+关联卡片
- **不追求完美覆盖**——先跑通月白+半肥猫两条线，验证模板和 prompt 有效，再扩展
