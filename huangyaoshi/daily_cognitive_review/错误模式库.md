# 错误模式库

> 诚实优先。无新错误就写"无"，不编造。

## 错误记录

### E5: 批量正则范围失控——匹配全部 YAML 列表行（2026-06-28，次数：1）

**症状**：`_fix_source_refs_final.py` 中 `re.sub(r'^(\s*-\s+)(.+)$', ...)` 将所有 frontmatter 的 `- value` 行替换为 `src_unknown`，波及 domain（1,011 张）+ related（1,287 张）。

**根因**：正则未限定作用域——匹配了 YAML frontmatter 中所有以 `- ` 开头的行，不限于 `source_refs:` 段落。

**对策**：批量替换前用段落上下文限定正则，先 3 张卡 dry-run 检查 diff 范围。Git 恢复用精确基线 commit 不用相对深度 `HEAD~N`。

### E3: 批量操作未声明变更范围（2026-06-17，次数：1）
**症状**：470 skill 重分类导致 486 文件变更，欧阳锋无法快速审查。**根因**：执行前未在任务文件写明预期变更范围。**对策**：P-30——任何批量操作前声明影响文件数+修改字段+修改前后值。

### E1: Provider 迁移时协议不匹配（2026-06-14，次数：1）

**症状**：Hermes 切到 DeepSeek 后功能降级，模型显示为 `deepseek-chat` 而非 `deepseek-v4-pro`。

**根因**：`models_dev_cache` 标注 deepseek provider 走 `@ai-sdk/openai-compatible`，但 config 配了 `/anthropic` URL。

**对策**：改 provider 前先查 `models_dev_cache.json` 确认 `npm` 字段。

### E2: 模型发布日不查公告（2026-06-14，次数：1）

**症状**：Kimi API 全线 400 + tool call 截断 48 字符，3 小时改 model/temperature/base_url 无效。

**根因**：K2.7 当天发布，Anthropic 协议 tool call 未适配。WebSearch 在第 30 步才触发。

**对策**：API 大规模异常→第 3 步内 `WebSearch "<provider> update"`。

### E6: 夹具参数越界误测旁路（2026-08-21，次数：1）

**症状**：#395 归一化实测第一轮，夹具正文 121 字 < promote 的 200 字空壳阈值，卡走了 `_needs_rerun` 退回路径——测的不是目标"待编排路径"，若不看输出细节就拿"归一化打印出现"交差，结论就是错的。

**根因**：造夹具时只构造了"缺 updated_at"这一个目标变量，没对照被测代码的其他校验规则（MIN_BODY_CHARS），夹具落在了旁路的参数空间。

**对策**：夹具设计 = 目标变量 + 校验规则表逐条核对；测试输出必须看到目标路径的标志性结果（本例= pending-cards 副本的 frontmatter），不能只看中间日志。

### E7: 管道末端退出码冒充被测程序结果（2026-08-21，次数：1）

**症状**：`queue_transition.py complete ... | head -3` 后 `echo exit=$?` 输出 0——那是 head 的退出码，被门禁拦截的 complete 实际 exit 1，差点误读成"拦截场景返回成功"。

**根因**：bash 管道的 `$?` 取最后一个命令；断言被测程序退出码时隔了管道。

**对策**：断言退出码时 `${PIPESTATUS[0]}`，或先重定向落盘再查 `$?`。
