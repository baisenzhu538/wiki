- **反复把 model 名当诊断目标**：5 次改 model（kimi-coding→kimi-for-coding→k2p6→kimi-for-coding→kimi-k2-thinking→deepseek-v4-pro）。真正的诊断应该是查 API 返回的具体错误 + 查公告 + 查日志。

- **Parse 函数签名没查就调用**：`parse_frontmatter()` 返回 `tuple[dict, str]`，当 dict 用。调用前应该 `grep "def func"` 确认签名。

## 元反思

**下次怎么做才能不一样？**

1. **API 报错 → 三步诊断法**：查公告（WebSearch）→ 查日志（grep ERROR）→ 查 API console。三步跑完再改配置。绝不先改参数。
2. **每个域完成 → 自动触发交叉审计**。王语嫣的审计模板已经验证有效。以后老顽童完成一个域，王语嫣自动跑一次。
3. **调用项目内部函数前先确认签名**。`grep "def func"` 一秒钟的事，省 10 分钟 debug。
4. **每张框架卡必须带至少一张案例卡。** 深入浅出的原则：一个深度洞察配一个具体场景。不怕案例多，怕没有。
