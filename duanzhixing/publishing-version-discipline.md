# 发布版本纪律 (Publishing Version Discipline)

> 发布不仅仅是"把内容推出去"——包含版本号、变更日志、回滚机制、渠道分离。

## 核心四维

### 1. 版本号与变更日志

| 规则 | 说明 |
|------|------|
| 每次发布有唯一版本号 | 格式 `YYYY-MM-DD-vN`，如 `2026-06-21-v1` |
| 变更日志 | 记录本次发布的变更内容、新增/删除/修改 |
| 发布人 | 记录是谁执行的发布（段王爷 / 老顽童代班） |

**变更日志模板**：
```markdown
## v2026-06-21-v1
- 发布人：段王爷
- 渠道：飞书文档(yitanger域) + 本地Markdown
- 变更：
  - 新增：段王爷能力差距分析报告
  - 新增：duanwangye-self-evolution 技能
  - 新增：duanwangye-knowledge-collision 技能
- 已知问题：公众号发布需 WECHAT_APP_ID/SECRET 凭证
```

### 2. 回滚机制

| 场景 | 回滚方式 |
|------|---------|
| 飞书文档发错 | 文档版本历史 → 恢复到前一版本 |
| 飞书文档内容错误 | PATCH 更新内容块（非删除重发） |
| 本地文件发错 | git revert / 从备份恢复 |
| 公众号发错 | 草稿可删除；已发布可修改（限20字内）或删除重发 |

**铁律**：
- 飞书文档**不删除重建**——使用版本历史恢复。删除会导致外部链接404。
- 每次发布前创建飞书文档的版本快照（修改前先读当前版本号）。
- 本地产出物在 `40_outputs/` 下保留历史版本，命名带日期。

### 3. 渠道分离

| 渠道 | 用途 | 发布节奏 |
|------|------|---------|
| **本地 Markdown** | 源文件归档 + Obsidian 知识沉淀 | 每次发布 |
| **飞书文档（内部）** | 内部审阅、协作讨论 | 写完即发 |
| **飞书文档（公开）** | 外部传播、分享链接 | 审阅通过后发 |
| **公众号草稿** | 预览、人工确认 | 手动触发 |
| **公众号发布** | 正式对外发布 | 人工最终确认 |
| **知乎** | 公域传播 | Phase 2 接入 |

**分离原则**：
- 内测版（内部飞书）和正式版（公众号/知乎）严格分离
- 正式版发布必须经过：碰撞检查 → 审阅确认 → 格式适配 → 渠道发布 → 效果追踪
- 一条内容可以在多平台发，但必须是**同一版本**（版本号一致），防止观众在不同平台看到不同内容

### 4. 发布追踪

| 追踪项 | 工具/方式 |
|--------|----------|
| 发布记录 | 飞书多维表格（Bitable）— 文档ID、版本号、发布时间、渠道 |
| 阅读/互动数据 | 公众号后台 / 知乎后台 |
| 反馈收集 | Langfuse trace（Phase 2） |
| 回滚记录 | 与发布记录同表，字段 `status: rolled_back` |

## 发布纪律检查清单

发布前必须逐项确认：

- [ ] 版本号已生成（格式 `YYYY-MM-DD-vN`）
- [ ] 变更日志已填写
- [ ] 飞书文档已创建版本快照
- [ ] 本地 Markdown 已保存到 `40_outputs/`
- [ ] 内测版与正式版渠道已确认分离
- [ ] 发布人已记录
- [ ] 如需回滚，回滚路径已确认
