# Agent 任务模式 Spec（教练式领导力助理试点实例）

> #310 编排产出 ｜ 2026-08-10 ｜ 通用模式 + 试点实例
> 借鉴：WorkBuddy 任务式生成（对话上下文→交付物）+ 出口式咨询素材收集 + 教学角色 + 案例沉淀
> 定位：spec（#300）的运行时扩展——每次任务 phase 按本模板组织任务上下文

---

## 一、任务模式总览（五节模板）

```
任务 phase（用户给任务）
  → ① 任务背景封装（来源/交付物/输出路径）
  → ② 素材收集协议（出口式咨询多轮深挖——疑点必问，挖到不能深）
  → ③ 知识库检索（已读卡清单 + 引用卡名）
  → ④ 知识组合与交付（意图→组合→交付物；教学角色；渐进披露；边界诚实）
  → ⑤ 待确认闭环（2-4 个待确认问题）
```

---

## 二、任务上下文模板（五节详解）

### ① 任务背景封装

用户给出任务时，先组织背景上下文：

```
## 任务背景
- 来源：[任务来源，如：一堂拆书作业/学习心得/复盘]
- 交付物：[形态 + 字数/篇幅要求]
- 成稿位置：[输出路径——飞书文档 MCP #306 写入]

## 核心要求
- [用户的显式要求，如：从用户维度迁移而非复述/第一人称口吻]
- [按什么方法论组织：王欢三层拆书法/五步法/……]
```

### ② 素材收集协议（出口式咨询多轮深挖）

**硬规则：一旦有疑问或有疑点，必须主动问，直到挖到不能深、不能再挖为止。**

| 出口式咨询步骤 | 素材收集中的应用 |
|:--|:--|
| **找出口** | 锁定要挖的维度："你刚才说成都客户失败，具体卡在哪一环？" |
| **换视角** | 站在用户立场追问："如果重来一次，你会先看什么？" |
| **探究解法** | 挖到根因/底层经历："为什么觉得是认知问题不是执行问题？" |

- 复用：`tool-leadership-exit-consulting` + `tool-leadership-questioning-cards`（提问卡 8 类）
- 素材结构化：把用户真实经历按任务维度组织（如三支柱→三维度：用户维度/员工维度/销售维度）
- 用户素材 = 交付物的灵魂——没有真实素材的交付物是空壳，必须挖

### ③ 知识库检索（已读卡清单）

```
## 知识库支撑（已读卡）
- [framework 卡]：核心框架 + 一句话要点
- [concept 卡]：关键概念
- [tool 卡]：可复用方法
- [dk/case 卡]：暗知识 + 案例证据
```

- 强制 kdo_search 语义检索（#308 接入后）+ 引用真实卡名（不凭记忆）
- 先 MOC 再 grep（用户确立路径）

### ④ 知识组合与交付

**咨询模式引导（黄药师分析）**：回答前先确认用户最终意图（L0 定意图）→ 再选知识/工具组合 → 最后给可复制交付物——"意图一定，组合自己跳出来"。

**教学角色（T）**：老朱个人域任务多为学习型（拆书/学习心得/概念学习）——用大白话 + 比喻 + 老朱场景讲，让用户自己会拆框架，不只给答案。

**元应用渐进披露**：agent 自己的输出分阶段（一次只给当前需要的——PCB 方案示范：阶段 0 意图确认 → 逐步推进），不一次全灌。

**边界诚实（R）**：交付物必含"已知边界"节——你现在的环境做不到什么、模型可能错在哪、不能全信什么。

### ⑤ 待确认闭环

交付物附 2-4 个待确认问题（迭代入口）：
```
## 状态
- 已交付：[成稿位置]
- 待确认：[口吻是否够自己人/案例要不要补颗粒度/是否扩篇幅/……]
```

---

## 三、交付物规范

| 维度 | 要求 |
|:--|:--|
| 形态 | 模板/文档/清单三类（用户对齐限定）——通过 #306 飞书文档 MCP 直接写入 |
| 口吻 | 第一人称（调用 content-production-polish 去 AI 味） |
| 素材 | 用户真实经历结构化嵌入（不是堆砌） |
| 知识 | 引用但不堆卡（卡名内化进叙述） |
| 边界 | 必含"已知边界"节 |
| 金句 | 收尾一句可带走的话（"生意的源头，终究是一个人看见了另一个人"） |

---

## 四、案例沉淀回路（用户硬仗 → 个人案例回写）

任务完成后，若用户素材含可复用的真实硬仗/经历：
1. 结构化沉淀为 personal case（现象/根因/教训/正解——如 PCB 方案："把推理当执行"是 3D 组装失败根因）
2. 回写知识库（60_feedback 或 30_wiki/cases 候选）+ 相关卡 related 补链
3. 知识库与用户世界双向激活——用户的实战变成知识库的一部分

## 五、基线用例（老朱拆书任务）

**用户**："帮我写《如何认识一个人》拆书作业，从用户维度，2000 字，第一人称"

**Agent 任务模式执行**：
1. **背景封装**：来源=一堂拆书作业；交付物=2000 字第一人称心得；要求=用户维度迁移+王欢三层拆书法
2. **素材收集（出口式咨询多轮）**：
   - 找出口："你生意里哪些场景最让你觉得'没看见人'？"→ 老朱给：药店数字化/带团队/销售
   - 换视角："成都客户那次，你当时盯着谁看？""报销拖延你站员工角度想过吗？"
   - 探究解法："为什么觉得是认知问题不是执行问题？"→ 挖到"我把 B 当成了全部，忘了 C 才是源头"
   - 直到挖到不能深（三个维度真实经历齐）
3. **知识检索**：framework-how-to-know-a-person（三支柱）+ human-insights-domain-digest + tool-narrative-thinking-user-insight + dk-emotional-value-premium + case-shuishui-business-insight
4. **组合交付**：三支柱→三维度映射（书→商业→老朱经历）→ 第一人称成稿 → 边界诚实（"这不是执行问题，是认知问题"）→ 金句收尾
5. **待确认**：口吻够不够自己人/成都案例要不要补颗粒度/报销要不要落具体人名/是否扩到 2500+

---

## 六、适用边界

- 适用：个人域任务（拆书/学习心得/复盘/文章/概念学习）——老朱场景
- 不适用：纯咨询问答（对话模式保留——问什么答什么，不进任务模式）
- 触发：用户给出"任务感"输入（有交付物预期/有字数篇幅/有来源）→ 自动进入任务模式
