## 背景裁定（王语嫣，7-13 修订）
YAI 实证：**三种 agent 用三种控制机制，互不通用**——关键决策=里程碑制（按深度递进，适配价值观/不确定性决策）；业务公式=S0-S8 阶段制+轮次标注 R1-RN+交付物版本迭代（按信息积累推进，适配可量化问题）；转化率=动力/阻力/触点三模块制（用户选顺序）。外部 agent 视此为架构缺陷，王语嫣裁定：**这是正确设计——问题类型决定控制机制**。因此引擎协议卡=「共享件层 + 控制机制选择器」，四域 spec 按问题类型选机制、共享件全继承。

## 产出 1：`method-一堂-教练对话引擎协议`（30_wiki/methods/）

### 第一部分·共享件（所有机制继承，逐条带 YAI 行号证据）
- **确认理解开场**：复述+追问澄清（"你看我理解得准不准？有偏差直接改我这句话"）
- **精度分级五档**：精确数据/粗略估算/区间/体感好坏/无法判断——任何量化提问都附此菜单，降低回答门槛（转化率实录 R2）
- **「你来说，我帮你记」纪律**：宽度展开阶段不追求完整，"不确定"可标注，跳过允许
- **盲区补漏**：用户列完后，agent 对照域盲区库补候选（用户说 3 条阻力→agent 补 3 条），用户判成立/不成立，agent 不替判
- **逐句术语映射**：用户原话实时映射到域术语编号（"担心实力→不靠谱""多比对→怕冲动"），建立共同语言
- **硬约束显式宣告**：不可行选项早宣告（"⛔ 当下不该推：理由+等待信号"）
- **目标价值量化**：把目标换算成业务价值账（转化率 10%→30%=每月多 6 次上门/约 20 万收入），制造动力
- **交付物确认仪式**：阶段收口用明确断点（"请回复『确认目标』"），版本化迭代（公式树 FT-v0.1→v0.2）
- **待验证假设声明**：所有结论标注"待验证假设，不是最终方案"，全程不替用户拍板
- **置信度三级标注**：每个参数标 高/中/低+证据来源（高=用户直接给数/中=体感估算/低=纯推断）；置信度决定追问策略——高值直接用、中值标注待验证、低值作为核心追问目标反复提及（业务公式实录；映射库内一等/二等素材惯例）
- **续接=交付物落盘**：每次阶段收口产出存盘（公式树版本/备忘录/假设池状态），用户隔周隔月带数据回来，从落盘卡恢复对话状态而非凭记忆重述——wiki 版实现=备忘录卡/案例卡落盘即续接凭证，教练开场先读最近相关卡
- **边界声明话术**：超出当前模块的请求接住但挂起（"话术是下游执行动作，本模块不生成，报告后单独拆"）

### 第二部分·控制机制三选一（域 spec 按问题类型选）
**机制一·里程碑制 M0-M8（B 域决策类：价值观/不确定性问题，按深度递进）**
- M0 确认理解（选项合并 pattern：用户说"A和B一样"→合并不硬拆）
- M1 宽度展开：逐选项吐成本收益；**底牌资产盘点**（跨选项共用资产独立列出：经验/能力/团队/知识产权）
- M2 盲区补充（共享件已含，此处接域盲区库）
- M3 高度扫描：四维追问=时间窗口/机会成本/长期视角/整体资源配置；假设抛出式（"假设①②③，哪些成立？"）
- M4 深度分级：L1-L4 菜单让用户选，默认从轻，不设天花板
- M5 硬约束过滤（共享件已含）
- M8 备忘录收束：成本/收益/高度层摘要/关键不确定项（⭐优先级）/下一步行动表+「不替你做决定」声明

**机制二·阶段制 S0-S8（C 域业务公式类：可量化问题，按信息积累推进）**
- S0 开场识别→S1 目标边界校准→S2 业务流还原→S3 初版公式校准→S4 分层与数据缺口→S5 主要矛盾预热→S6 主要矛盾与关键假设→S8 一页纸沉淀
- 每轮三标注铁律：**当前轮次 R? / 当前阶段 S? / 本轮只解决 X**（防漂移，用户始终知道进度）
- 追问 3-2-1 递减：初期每轮 3 问（信息缺口大）→中期 2 问→后期 1 问或不问（收口输出）
- 阶段判断纪律："不下结论"明示（信息不足时标注倾向但悬置结论）
- 交付物版本迭代：公式树 FT-v0.1→v0.2…，每版记录校准逻辑
- 一页纸交付物 9 模块模板：目标边界/业务流/L1-L4 公式树/主要矛盾/关键参数表（含置信度）/关键假设（成功线+失败转向线）/首个实验设计/待补数据清单/下一轮复盘口径
- 假设管理：H1-HN 编号，五要素=内容/影响参数/验证方式/成功线/失败转向线；状态=待验证/已验证/废弃

### 附录：YAI 平台 Partner 全景（截图证据，大纲第四章）
官方 Partner 已见 5 个：业务公式拆解教练/关键转化率拆解/科学决策搭档/**一堂双三角挖掘师**/**刻意练习十倍速**——后两个我们无课程素材，登记为素材线索（待老朱）；Partner 分类=教学型/咨询型/实践型/研究型（对照：A/B 域≈咨询型、C 域≈教学型、D 域≈实践型）；平台支持私有 Partner 创建（用户自定义）

**机制三·模块制（D 域转化率类：要素拆解问题，用户选顺序）**
- 三模块=动力/阻力/触点，起点由信号判断给建议（"最明显信号来自阻力→建议先拆阻力"），用户可改选（"按建议来/先动力/先触点"）
- 每模块内部：用户直觉列举→盲区补漏→逐条配「消除方向+策略名+动作示例」→确认保留→减法排序（按与转化动作的关联紧密度）
- 模块间承接：前一模块产出是后一模块的输入（"消除方向有了，但什么时候递到客户手里=触点"）
