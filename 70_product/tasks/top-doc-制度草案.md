# 顶层文档制度（草案 · #339 试点产出）

> 来源：楚门《AI×知识管理》"顶层文档制度"（口述 L648-706）+ KDO 试点实证（top-doc-爆炸式调研.md）
> 状态：草案，建议进编排协议/agent-os 后生效

---

## 一、为什么需要（试点实证）

KDO 现状：任务单 = **生产态**（每任务单有背景/验收/边界），但缺**项目总览态**——一个项目（如爆炸式调研）跨多个任务单（#332-335）、多份诊断、多类产出，新加入者/回看者需要"从哪开始看"的单一入口。顶层文档 = 项目的最上层总览，**有且只有一个**，解决"文档在哪儿"的来回询问。

## 二、适用场景

| 需要 | 不需要 |
|:--|:--|
| 跨 ≥3 个任务单的项目（如爆炸式调研：诊断+3 波卡组+Agent） | 单任务小活（顶层文档反而重） |
| 有独立素材目录（00_inbox/）的项目 | 纯补链/修补任务 |
| 预期长期演进（如 Agent 系列） | 一次性产出 |
| 多角色参与（素材处理/生产/终审/编排） | 单角色快任务 |

## 三、结构模板（必知必会前置，链接后置）

```
# 顶层文档：<项目名>项目总览

> 类型：项目顶层文档 | 维护：<编排者> | 创建：<日期>

## 必知必会（30 秒读完）
- 这是什么 / 核心产出 / 核心方法论 / 当前状态 / 关键约束（5 条内）

## 项目背景
（为什么做这个项目）

## 参与方
（各角色做了什么——表格）

## 关键文档索引（链接后置）
### 素材 / 诊断与编排 / 任务与队列 / 产出卡 / Agent
（按类别列关键文件路径，只列"入口级"文档，不穷举）

## 下一步（编排视角）
（当前待办与依赖）
```

## 四、维护节奏

| 时机 | 动作 | 责任人 |
|:--|:--|:--|
| 项目立项（首个任务单入队时） | 建顶层文档（必知必会+背景+参与方骨架） | 编排者 |
| 每批任务终审闭环 | 更新"当前状态"+"下一步"（+产出卡索引） | 编排者 |
| 项目收官 | 更新为终态（产出清单完整）——**不删除**，作为历史入口 | 编排者 |
| 新角色加入项目 | 读顶层文档入门（替代逐文件翻找） | 新角色 |

## 五、与现有体系衔接

- **任务单 = 生产态**（怎么做的细节）→ 顶层文档 = **总览态**（项目是什么、现在到哪了）
- **队列/看板 = 状态流** → 顶层文档 = **项目语义层**（把散任务串成项目故事）
- **域 digest = 域级顶层**（#321 销售域 digest 是雏形）→ 顶层文档 = **项目级**（同一思想的项目层落地）
- 命名规范：`70_product/tasks/top-doc-<项目名>.md`（统一前缀，检索即得）
