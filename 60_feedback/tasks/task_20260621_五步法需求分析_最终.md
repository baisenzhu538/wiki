## 0. 前置：新卡片类型注册

老顽童在 `90_control/` 注册新类型 `prompt-methodology`，与现有 `tool/concept/framework/case/dk` 并列。

**新类型定义**：
- **做什么**：封装完整的提示词文本 + 设计原理 + 定制指南。不是"给你用"——是"教你怎么写出同级别提示词"。
- **区别于 tool**：tool 卡关注工具操作方法，prompt-methodology 关注提示词工程方法论
- **区别于 Skill**：Skill 是黑盒自动化执行，prompt-methodology 暴露内部设计逻辑供 Agent 学习
- **卡片结构**：触发场景 + 完整提示词（含占位符） + 设计原理 + 定制指南 + 已知局限

## 第三批：新类型首张卡——prompt-methodology（1 张）

### PM-1：prompt-demand-ai-coach

- **路径**：`30_wiki/prompt-methodology/prompt-demand-ai-coach.md`
- **类型**：`prompt-methodology`（新类型）
- **核心内容**：
  - **触发场景**：需要 AI 作为需求分析教练，引导用户完成 L1-L6 全流程推演
  - **完整提示词**：引自 `AI场景推演教练提示词.txt`（含占位符）
  - **设计原理**：五层内核——Role（导师角色设定）→ Knowledge Base（L1-L6定义）→ Interaction Rules（主导+引导+中立）→ Workflow（Step 0-5）→ Initialization（启动语）
  - **定制指南**：替换 L1-L6 定义可适配不同分析框架；替换 Interaction Rules 可适配不同教练风格
  - **已知局限**：依赖 LLM 对 JTBD 和四种力量的理解深度；开放式问题过多时用户容易迷失
- **关联链接**：→ `framework-demand-iceberg` / → D-2~D-7 六张工具卡 / → `framework-demand-usp-model`（欧阳锋约束：prompt-methodology 卡必须链对应框架卡）
- **素材来源**：`AI场景推演教练提示词.txt`
- **欧阳锋约束**：此类型卡必须引用对应 tool/framework 卡——说明"这个提示词帮你在哪个工具上落地"
