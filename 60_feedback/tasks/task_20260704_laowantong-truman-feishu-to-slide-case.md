# 任务 #64：Truman「飞书 To slide」PPT 迭代案例卡

## 任务目标

产出一张 S+ 级核心案例卡 `case-yihang-dual-triangle-truman-feishu-to-slide-ppt-evolution`。

**核心要求**：这张卡不能只是「展示 Y模型 循环」，必须展示 **PPT 案例是双三角框架从「人在环」走向「AI 原生工作流」的关键一轮迭代**。要回答：这个案例为双三角框架贡献了什么新认知？

## 必须包含的人物、动作、时间线

| 要素 | 内容 |
|:---|:---|
| **人物** | Truman（主讲人/实践者） |
| **起点** | 过去一年做 PPT，相信自媒体推荐的工具 |
| **旧模式** | 试 3-5 天，不行就扔掉，失败清零 |
| **心态转折** | 「失败不再是工具的失败，而是我们在路上迭代的过程」；「结果不好，只是积累未到」 |
| **建系统** | 去年年底开始建 PPT 知识站场（Home），堆审美、模型、数据包、工作流 |
| **持续试错** | 一次测试、两次测试、三次测试，项目失败但资产增长 |
| **大胆假设** | 今年春天：主流 PPT 工具超过 30 页就难以调试，定义「飞书 To slide」 |
| **新工作流** | 飞书写文档 → 分割线区分页面 → 一键渲染成可演讲 PPT |
| **结果** | 支持 1000 页级商业培训 PPT，多人和 Agent 协作打磨，效率提升约 5 倍 |

## 卡片深度要求

### 1. 必须展示 Y模型 引擎层循环

| Y模型阶段 | 案例对应内容 |
|:---|:---|
| 目标 | 做出高质量、可协作、大页数的商业培训 PPT |
| 基础框架认知 | PPT 不是工具问题，而是审美+体系+数据+基本功的系统问题 |
| 理论侧·科学类比 | 借鉴文档协作、版本管理、程序渲染等范式 |
| 理论侧·提炼建模 | 提炼「飞书文档 → 分割线 → 一键渲染」工作模型 |
| 实践侧·假设驱动 | 假设主流 PPT 工具超过 30 页难以调试，文档渲染可突破 |
| 实践侧·定性定量 | 1000 页验证可控性；效率提升约 5 倍 |
| 实事求是 | 承认主流工具有天花板；承认自己的工具「糙」但够用 |
| 解放思想 | 跳出「必须用 PPT 软件做 PPT」的隐含假设 |
| 真正认知 | 「结果不好只是积累未到」；「AI 原生工作流 = 人简单创作 + AI 全面接管」 |
| 知行合一 | 用到高阶营、To B 交付、内部协作中 |

### 3. 必须说明「这轮迭代对双三角框架的贡献」

卡片中必须有明确的「迭代贡献」章节，回答：

- 在这轮迭代之前，Truman 对「人机协作做 PPT」的朴素认知是什么？（答：相信工具、试完就扔、人在环式把关）
- 这轮迭代更新了什么认知？（答：AI 原生工作流 = 人简单创作 + AI 全面接管；失败是积累不是清零）
- 这个认知如何进入双三角框架？（答：强化了「基本功」中自定义工作流的地位；强化了「创造力」中重新定义问题边界的地位；为「飞轮」提供了真实案例）

### 4. 必须指向可复用资产

在卡片中明确列出：
- **Workflow**：「飞书文档 → 结构化分隔 → 一键渲染」的演示文档工作流
- **Skill**：如何用 3-6 个月建设一个 AI 原生工作流
- **Agent**：PPT 内容审核 Agent（检查结构、审美、一致性）
- **DataPack**：商业培训 PPT 的审美标准、结构模板、配图指南

### 5. 必须提炼为跨域通用方法原型

这张案例卡的最高价值，是把 Truman 做 PPT 的方法抽象成可迁移到任意 AI 协作领域的元方法。卡片中必须有独立小节「通用方法原型」，包含：

| 步骤 | PPT 动作 | 通用问法 |
|:---|:---|:---|
| 0 | 现有工具和 Agent 都试遍，承认它们不够 | 我是否把问题错误定义成了「找更好的工具/Agent」？ |
| 1 | 定义真正目标 | 我要解决的真正问题是什么？好结果的标准是什么？ |
| 2 | 建立朴素框架认知 | 这件事的基础框架认知是什么？（允许不完整、会错） |
| 3 | 建设审美 | 什么是这个领域的「好」？能否拆成可判断维度？ |
| 4 | 建设体系 | 解决这类问题的稳定流程是什么？ |
| 5 | 积累数据资产 | 我过去做过什么可沉淀为数据/模型/模板？ |
| 6 | 磨练基本功 | 需要哪些最小工具组合？能否自己搭粗糙但够用的工具？ |
| 7 | 做大胆假设 | 这个领域有哪些隐含假设可以挑战？ |
| 8 | 失败即积累 | 能否把失败重新定义为资产积累，而不是清零？ |
| 9 | 重新定义问题边界 | 能否换一个容器/介质/形态来解决？ |
| 10 | 沉淀 AI 原生工作流 | 人在哪个环节做最小创作，AI 在哪个环节全面接管？ |

并明确回答：
- **为什么国内外很多 PPT Agent 都做不好，Truman 却做出来了？**（答：他不是继续优化现有 Agent 范式，而是在它们都失败后重定义问题边界；他用双三角六要素作为迭代参数，一边做一边调校自己）
- **Truman 原来完全不懂，如何从零开始做？**（答：这正是 Y模型 的核心——面对全新事物时，用「目标→朴素框架认知→实事求是/解放思想→更新认知→知行合一→下一轮」的循环推进，而不是先等自己变专家）
- **审美是怎么被建立的？**（答：通过大量案例、A/B 对比、标杆研究，把过去 Keynote 转成模型；审美需要长期训练，未来甚至可能成为独立课程）
- **「粗糙」为什么能赢？**（答：粗糙不是目的，让飞轮转起来才是目的；在干中学、在学中干，逐步逼近最好水平；第一步可以尽可能详细，但不必完美）
