### 校准点 1：差集 `_tmp` 划痕文件口径

**实证**：交付物节声明 `_tmp/debug_copy.py`、`_tmp/out.json` → 当前 `_extract_deliverable_paths` 均提取 → 差集三态检查对划痕文件判 missing/untracked → 🔴 假阳性（划痕=中间产物，git 常 ignore，报「未入仓」无意义）。

**口径**：交付物声明路径含 `_tmp/`（前缀或路径段）→ **豁免三态检查**（missing/untracked/dirty 不判）；pre_review 对豁免路径出 **WARNING**：「交付物节含划痕路径 `_tmp/…`（中间产物非交付物，按约定豁免；如属误写请清理交付物节）」。

**实现落点**：`_extract_deliverable_paths` 提取层过滤（连带 E040 `_check_deliverables_committed` 与 pre_review 两侧一致生效——单一真相源，不另写豁免分支；与跨仓路径 `Knowledge Delivery OS` continue 豁免同构）。

### 校准点 2：负向判词宽词阈值

**实证**：正常执行报告「无阻塞/无遗留/未发现异常/无代码交付物」→ 命中 soft warn「无/未发现」→ 噪音（warn 失去提示价值，狼来了效应）。

**口径**：`NEGATIVE_CLAIM_SOFT` 词表 `["无","缺","没有","未发现","截断","损坏","乱码","半写"]` → 收窄为 `["未发现","截断","损坏","乱码","半写"]`。

**依据**：单字/两字通用否定词「无/缺/没有」由 STRONG 词（不存在/缺失/丢失…）+ PATTERN 1（无/缺/没有/未 + 0-6 字 + 敏感名词）兜底——组合断言（「无远程备份」）已硬拦，单字出现无断言价值，只制造 warn 噪音。「未发现」保留（意见书语境「我没看到」嫌疑，提示价值在）。

**保持不动**：PATTERN 1 `.{0,6}` 窗口、PATTERN 2 主语词表（#430/#435 用例验证过）；判据二 lint（#515 FAIL 三宗已修 + #569 节边界已补）。
