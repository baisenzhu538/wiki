### Wave 5a：CI 框架（3张）

#### W5-1：framework-ci-operating-model
- **路径**：`30_wiki/frameworks/framework-ci-operating-model.md`
- **类型**：framework
- **核心内容**：
  - Define→Gather→Analyze→Implement 四阶段循环
  - 每阶段的决策问题、输入、输出物
  - 与一堂三层八模块的映射表：Gather=✓（模块1-8），Define=✗，Implement=✗
  - 关键引用："If the output does not change a decision, you did not do CI. You gathered trivia."
- **Agent 执行指令**：CI 程序的设计模板（不是工具调用，是流程设计指导）
- **素材来源**：`diag_20260621_外部知识探索_三个新盲区.md` §盲区A + web: BestBootcamps CI Framework Guide 2026 + Competitive Intelligence Alliance
- **关联链接**：→ `framework-yitang-research-weapon-system`

#### W5-2：tool-ci-define-phase
- **路径**：`30_wiki/tools/tool-ci-define-phase.md`
- **类型**：tool
- **核心内容**：
  - KITs（Key Intelligence Topics）和 KIQs（Key Intelligence Questions）定义方法
  - 区分"想知道"vs"需要知道"的四象限
  - 示例：从"调研竞对"→"竞对的新定价是否会在Q3影响我们的win rate？"
  - 决策驱动的问题定义模板
- **Agent 执行指令**：KIQ 生成模板（Agent 根据决策场景自动生成 KIQs）
- **失败模式**：问题太宽无法回答 / 问题太多无法聚焦 / 问题与决策无关
- **关联链接**：→ `framework-ci-operating-model`

#### W5-3：tool-ci-implement-phase
- **路径**：`30_wiki/tools/tool-ci-implement-phase.md`
- **类型**：tool
- **核心内容**：
  - 洞见嵌入运营节奏的 5 种模式（forecast call / QBR / deal review / enablement / Slack digest）
  - Battlecard 制作标准（何时更新、谁用、怎么度量）
  - CI 资产度量：win rate impact / battlecard adoption rate / time saved
  - 从"产出报告"到"改变决策"的最后一公里
- **Agent 执行指令**：CI 分发自动化模板
- **失败模式**：报告没人看 / battlecard 过时 / 度量指标选错
- **关联链接**：→ `framework-ci-operating-model` / → `tool-yitang-research-continuous-tracking`

### Wave 5b：SATs 工具包（5张）

#### W5-4：framework-structured-analytic-techniques
- **路径**：`30_wiki/frameworks/framework-structured-analytic-techniques.md`
- **类型**：framework
- **核心内容**：
  - SATs 8 类技术分类表：诊断/Contrarian/想象力/指标/假设检验/因果/冲突管理/决策
  - 每类选 1-2 个代表技术
  - 与一堂方法论的映射：九层深挖=ACH / 交叉验证=多源验证 / Red Team=缺失 / Devil's Advocacy=缺失
  - CIA 来源标注（Heuer & Pherson）
- **Agent 执行指令**：Agent 如何自动选择 SATs 技术（场景→技术映射）
- **素材来源**：`diag_20260621_外部知识探索_三个新盲区.md` §盲区B + Heuer & Pherson SATs 文献
- **关联链接**：→ `framework-yitang-nine-layer-deep-dig` / → `framework-yitang-18-strategy-cards`

#### W5-5：tool-key-assumptions-check
- **路径**：`30_wiki/tools/tool-key-assumptions-check.md`
- **类型**：tool
- **核心内容**：
  - 四步法：列出所有假设 → 评估每个假设的证据强度 → 标记"无证据支撑"的假设 → 为弱假设设计验证
  - 案例：一堂进入 Skill 市场的隐藏假设清单（企业客户愿意为内部工具付费？企业有预算？决策者是HR还是技术负责人？）
  - 与第 1 掌（调研先行验证假设）的升级关系
- **Agent 执行指令**：根据商业计划自动生成假设清单的 Prompt 模板
- **失败模式**：遗漏"太明显"的假设 / 把信念当事实
- **关联链接**：→ `framework-structured-analytic-techniques`

#### W5-6：tool-devils-advocacy
- **路径**：`30_wiki/tools/tool-devils-advocacy.md`
- **类型**：tool
- **核心内容**：
  - 操作步骤：选定结论→指定挑战者→提出最强反驳→评估反驳→修正结论或记录风险
  - 模板："我们最大的风险是______，因为______。如果______发生，我们的假设将不再成立。"
  - 与"交叉验证"的区别：交叉验证=多源核实事实，魔鬼代言人=主动攻击自己的逻辑
  - Agent 天然适配：LLM 换个角色 Prompt 就能扮演挑战者
- **Agent 执行指令**：魔鬼代言人 Prompt 模板（"你现在是______的激烈反对者，请提出最强反驳..."）
- **失败模式**：挑战者不够狠 / 把反驳当攻击人身 / 挑战后不修正
- **关联链接**：→ `framework-structured-analytic-techniques` / → `skill-半肥猫-ai-research-validation`

#### W5-7：tool-red-team-analysis
- **路径**：`30_wiki/tools/tool-red-team-analysis.md`
- **类型**：tool
- **核心内容**：
  - 四步法：定义对手→理解对手的动机和能力→模拟对手的最优策略→制定应对方案
  - "如果我是竞对CEO"清单：我的弱点是什么？竞对会先打哪个市场？竞对有什么我没想到的资源？
  - 与第 3 掌（竞对跟踪）的互补：跟踪=观察行为，Red Team=模拟决策
- **Agent 执行指令**：Red Team Prompt 模板（"你现在是竞对CEO______，你的目标是______..."）
- **失败模式**：过度乐观估计自己 / 低估竞对 / 镜像思维（假设竞对像自己一样思考）
- **关联链接**：→ `framework-structured-analytic-techniques` / → `tool-yitang-research-competitor-tracking`

#### W5-8：tool-indicators-signposts
- **路径**：`30_wiki/tools/tool-indicators-signposts.md`
- **类型**：tool
- **核心内容**：
  - 定义方法：对每个关键假设，列出"什么信号出现时假设需要重新评估"
  - 可观测指标 vs 滞后指标：leading indicators（招聘变化、域名注册、新品商标）vs lagging indicators（季度财报）
  - 案例：一堂假设"企业客户会为 Skill 付费"→ signpost：3 个月内 <5 家企业主动询价=假设可能不成立
- **Agent 执行指令**：Agent 自动监控 signals 的方案（cron + API polling + 阈值告警）
- **失败模式**：信号太多无法区分噪音 / 信号出现但不触发行动 / 只设 leading 不设 lagging
- **关联链接**：→ `framework-structured-analytic-techniques` / → `tool-yitang-ai-monitoring-alert`

### Wave 5c：多智能体架构（4张）

#### W5-9：framework-multi-agent-research-architecture
- **路径**：`30_wiki/frameworks/framework-multi-agent-research-architecture.md`
- **类型**：framework
- **核心内容**：
  - 四种模式对比矩阵：Supervisor / Swarm / Pipeline / Hybrid
  - 选择决策树：依赖关系？可靠性要求？探索 vs 确定性？
  - LangChain benchmark 数据：Swarm 比 Supervisor 少 40% token，但 Supervisor 可靠性更强
  - 生产 failure modes：Supervisor 单点故障 / Swarm 无限循环 / Pipeline 错误传播
- **Agent 执行指令**：架构选择模板（根据任务特征自动推荐模式）
- **素材来源**：`diag_20260621_外部知识探索_三个新盲区.md` §盲区C + web: LangChain benchmark + Paiteq guide + Lushbinary patterns
- **关联链接**：→ `tool-agent-native-overview` / → `concepts/kimi-深度调研集群方法论-deep-research-swarm`

#### W5-10：tool-agent-research-supervisor
- **路径**：`30_wiki/tools/tool-agent-research-supervisor.md`
- **类型**：tool
- **核心内容**：
  - 操作步骤：Supervisor 分解任务→分配 Worker→收集结果→合成输出
  - 可靠性保障：重试机制 / 超时处理 / 结果验证
  - 适用场景：合规分析、报告生成、需要审计追踪的任务
  - 不适用场景：高并发探索、低延迟要求
- **Agent 执行指令**：LangGraph Supervisor 模式代码示例（Python）
- **失败模式**：Supervisor 瓶颈 / Worker 结果不一致 / 合成质量差
- **关联链接**：→ `framework-multi-agent-research-architecture`

#### W5-11：tool-agent-research-swarm
- **路径**：`30_wiki/tools/tool-agent-research-swarm.md`
- **类型**：tool
- **核心内容**：
  - 操作步骤：Swarm 自发分工→并行探索→peer-to-peer 交接→自动交叉验证
  - ⚠️ **欧阳锋条件：标注"2026年中快速演化领域，最佳实践可能半年后过时"**
  - Token 优势：比 Supervisor 少 40%
  - 与 Kimi Deep Research Swarm 的对比
  - 适用场景：多源并行搜索、探索性调研、需要速度的场景
- **Agent 执行指令**：Swarm 模式代码示例 + Kimi Swarm 参考
- **失败模式**：无限循环 / 重复劳动 / 缺乏最终合成
- **关联链接**：→ `framework-multi-agent-research-architecture` / → `concepts/kimi-深度调研集群方法论-deep-research-swarm`

#### W5-12：tool-agent-research-pipeline
- **路径**：`30_wiki/tools/tool-agent-research-pipeline.md`
- **类型**：tool
- **核心内容**：
  - Pipeline 模式对应 OSCAR 五步法：O(搜索)→S(筛选)→C(提取)→A(分析)→R(报告) 每步的 Agent 实现
  - 与"人手动 OSCAR"的差异：Agent 不需要等待、可 24h 运行、需要更明确的验收标准
  - 适用场景：依赖明确的串行任务
- **Agent 执行指令**：Pipeline 模式代码示例（LangChain SequentialChain）
- **失败模式**：单步失败全链崩溃 / 中间结果格式不兼容 / 累积误差
- **关联链接**：→ `framework-multi-agent-research-architecture` / → `framework-yitang-oscar-research`
