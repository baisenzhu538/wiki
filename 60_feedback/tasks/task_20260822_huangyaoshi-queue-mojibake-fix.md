# #410 production-queue.md 中文 mojibake 逆向修复

## 来源

- context.md blocker 长期遗留："production-queue.md 全文件中文 mojibake 损坏（UTF-8-SIG 混合编码）——历史遗留，新行正常 UTF-8；提请黄药师做编码修复"
- 用户 08-22 授权"清理遗留库级债务"；欧阳锋终审多次受其干扰（历史行中文不可读，如"鑰侀〗绔?=老顽童"）

## 背景诊断（2026-08-22 欧阳锋实测）

- 队列文件字节合法 UTF-8，但**字符内容被双重转码损坏**：原始 GBK 中文 → 被按 UTF-8 解码 → 再按 GBK 编码存回 → 现在显示为"鑰侀〗绔?≈"类乱码
- 行结构（表格/段标题/划线标记）完好——乱码只影响中文文本内容
- 逆向路径：乱码文本按 UTF-8 编码回字节 → 再按 GBK 解码 → 得原始中文

## 任务目标

修复队列全文件中文乱码，使历史行中文恢复可读，**队列行结构零损伤**。

## 执行范围

1. **先备份**：`git` 已有版本 + 额外 `.bak` 快照（参考既有 `production-queue.md.bak-before-esc-fix` 先例）
2. **样本校准先行**：取 1 行乱码验证逆向转码方法（先确认 1 个样本成功，再批量——#397 正则教训）
3. **逆向转码**：全文件乱码文本 → UTF-8 编码回字节 → GBK 解码 → 写回
4. **逐段复核**：行结构完整性（表格列数/段标题/划线标记/编号）+ 中文可读性抽查
5. **git diff 审查**：只应显示乱码字符 → 正常中文的变化，行结构零变化

## 边界

- **队列是唯一真相源**——强制备份 + 分块验证 + diff 复核三步缺一不可；转码失败即回滚，不硬推
- 修复对象仅 production-queue.md；其他 mojibake 文件（如 30_wiki 历史乱码）另立项
- 修复后 commit 入档（E040）
- 若样本验证发现乱码模式不止一种（多代转码），如实列出口径，不强行一刀切

## 验收标准

1. 历史行中文全部可读（抽样 ≥20 行 + 全文乱码关键词扫描）
2. 行结构零变化（git diff 不涉及行数/列数/标点结构变化）
3. 逆向方法有样本验证记录（先 1 行后全量）
4. 欧阳锋终审抽"转码真实性"（乱码→中文逐行对，无内容误改）

## 交付
