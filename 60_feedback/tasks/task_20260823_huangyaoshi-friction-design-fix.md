## 设计修正（三处）

### 修正 1：双层上报→通道唯一（治分叉）

**删除独立 friction-log 层**。上浮通道只有一个=建议书（`60_feedback/diagnosis/`），但格式分级弹性：
- **最小形态（三行）**：现象一句话 / 在哪发现的 / 建议方向（可选——不写不算缺陷）
- **完整形态**：现状老顽童式（实证+源码定位+方案+落点）
- agent 无需判断「写哪个」——写了就对了；想写多详细是自由度不是门槛
- 六角色 context 硬话术改为：「执行中发现任何摩擦/问题，最迟会话结束前落一份最小建议书（三行即可）——建议方向可留空，王语嫣会定向追问」

### 修正 2：新增机器自报层（真自动探测，零依赖自觉）

很多摩擦本身是**系统事件**，机器可探测，不需要 agent 报：
- **门禁拦截事件**：queue_transition 的 F-034/处置门禁/负向判词每次拦截 → 自动 append 一条到 `90_control/gate-blocked.log`（时间/任务/门禁/拦截原因）——#454 式误判从此机器自报
- **探针第五探针**：conveyor_probe 扫 gate-blocked.log 增量 → 自动登记 PROPOSAL-PENDING（类型=`[gate-blocked]`）+ 通知王语嫣
- 后续可扩：命令失败/异常退出日志（观察期后）

### 修正 3：消费端明确（王语嫣处理成本）

- `[gate-blocked]` 机器行：直接可决策（拦截原因自带，多数是误判→修门禁；少数是真拦截→无动作）
- 最小建议书：信息不足时按登记行的 agent 名定向追问一句（不翻上下文）
- 完整建议书：十分钟决策（今天 #457 实证）
