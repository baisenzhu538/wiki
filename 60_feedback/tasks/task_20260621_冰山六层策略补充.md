**OCR 原文策略**：
```
∞场景 ∞问题 ∞需求 ∞痛点
```

**补充内容**——在"核心三问"前增加**四维穷举展开**：

| 维度 | 展开方法 |
|:---|:---|
| **场景** | 时间（早晚/周末/节假日）+ 空间（家/办公室/路上/公共场所）+ 社会情境（独自/带娃/聚会/出差） |

## L3：tool-demand-iceberg-l3-core-job

**OCR 原文策略**——三个子策略**全部缺失**：
```
1) 固定核心执行者（核心执行/相关方）
2) 固定核心任务（愿景/大/中/小）
3) 固定替代产品（直接/间接竞区间）
💬 交付：一句话核心任务描述（足够客观）
```

**补充内容**——在现有 JTBD 公式后追加三节：

### 策略 1：固定核心执行者

不是"用户"——是具体到"谁在执行这个任务"和"谁在影响这个任务"。

| 角色 | 问题 |
|:---|:---|
| **核心执行者** | 谁在亲手完成这个任务？ |
| **相关方** | 谁在影响/审批/否决这个任务？ |

### 策略 2：固定核心任务（愿景分级）

同一需求，不同愿景级别意味着完全不同的产品形态。

| 愿景 | 范围 | 示例（"帮用户管理财务"） |
|:---|:---|:---|
| **大** | 成为用户的财务操作系统 | 覆盖收入/支出/投资/保险/税务 |
| **中** | 解决一个完整的财务子任务 | "帮用户每月自动对账+分类" |
| **小** | 解决一个具体的单一痛点 | "提醒用户信用卡还款日" |

### 策略 3：固定替代产品

用户现在用什么东西（或什么行为）在完成这个任务？

| 类型 | 问题 | 示例 |
|:---|:---|:---|
| **直接竞品** | 有没有公司在做一样的事？ | "用YNAB做预算" |
| **间接竞品** | 有没有不同的方案在解决同一个任务？ | "用Excel手动记账" |
| **非消费** | 用户选择不做——为什么？ | "算了不管了，月底看余额" |

**OCR 原文策略**：

```

**当前问题**：8 步表全空——只有表头没有内容。

**补充内容**：

### 三个分析深度（新增）

| 深度 | 做什么 | 产出 |
|:---|:---|:---|
| **基础** | 推理场景过程——极简一条线串起 8 步 | 一句话描述每步 |
| **更宽** | 完整任务地图——前中后全景 | 8 步完整表格 |
| **更深** | 每步三句话：动作 + 痛点 + 机会点 | 每步标注 1 个可切入机会 |

### 8 步表填充指南

每步必须回答四列，不能留空：

| # | 步骤 | 用户做什么 | 现有替代方案/土办法 | 摩擦点/情绪 | 机会信号 |
|:---:|:---|:---|:---|:---|:---|
| 1 | 定义 | 明确目标是什么 | 脑子里想/问同事/翻聊天记录 | 模糊→焦虑 | 是否常被跳过？ |
| 2 | 定位 | 找信息/工具/人 | 搜索引擎/微信群问/翻文件夹 | 找不到→挫败 | 信息在哪最难找？ |
| 3 | 准备 | 收集资源 | 手动整理/下载/复制 | 耗时→烦躁 | 什么准备工作最重复？ |
| 4 | 执行 | 实际动手 | （因任务而异） | 关键崩溃点 | 用户最常卡在哪里？ |
| 5 | 监控 | 检查是否在轨道上 | 手动检查/凭感觉/忘了 | 不知道进度→不安 | 用户怎么知道"做对了"？ |
| 6 | 调整 | 偏离时修正 | 推倒重来/凑合/放弃 | 返工→崩溃 | 什么错误最难恢复？ |
| 7 | 结束 | 确认完成 | 自己判断/问别人 | 不确定→焦虑 | 用户怎么知道"做完了"？ |
| 8 | 总结 | 反思/记录 | 不总结——最大的机会 | 经验流失 | 什么教训用户下次还会踩？ |

⚠️ 每步的"用户做什么/土办法/摩擦点"不能写"因任务而异"——必须给 2 个具体示例（1个消费品示例 + 1个企业服务示例）。

## L5：tool-demand-iceberg-l5-forces

**OCR 原文策略**：
```
1) 隐藏四种力量：（推力+拉力）>（焦虑+习惯）
2) 隐藏三种任务：①功能②情感③社交任务
3) 隐藏微观体感：推演关键场景极细体感
💬 交付：关键环节的期望成果
```

**当前问题**：标题写了"微观体感"但正文里一个字都没有。

**补充内容**——在"四种力量"后追加：

### 策略 3：微观体感推演

> 不是"用户觉得不方便"——是"用户拿出手机→解锁→打开App→等了3秒白屏→皱着眉点了一下→没反应→又点了一下→弹窗→关不掉→退出"。

**推演方法**：选 L4 中最痛的 1 个环节，按时间轴逐秒展开。

| 时间点 | 用户动作 | 视觉/听觉/触觉 | 情绪变化 |
|:---|:---|:---|:---|
| 0s | | | |
| 3s | | | |
| 5s | | | |
| ... | | | |

**关键原则**：
- 像素级描述——"加载中"和"白屏3秒"是完全不同的体验
- 关注沉默时刻——用户不说话时的表情、动作比说出来更重要
- 一个产品的"高级感"和"信任感"由无数微观体感构成

## L6：tool-demand-iceberg-l6-hypothesis

**OCR 原文策略**：

💬 交付：《需求关键假设清单》

```

**当前问题**：有机会卡片模板但没有 A-E 五个机会原型。

**补充内容**——在"机会卡片模板"后追加：

### 五个机会原型（A-E）

每个机会来自 L4/L5 不同洞察路径：

| 原型 | 来源 | 核心问题 | 示例 |
|:---|:---|:---|:---|
| **A** | L4 的摩擦点 | 哪个步骤用户最痛苦，改掉就能显著提升体验？ | "对账环节平均耗时2小时→自动对账省1.5小时" |
| **B** | L4 的替代方案 | 用户的土办法里，哪一步最原始、最容易被自动化？ | "手动翻聊天记录定位→一键搜索定位" |
| **C** | L5 的四种力量 | 推力最大的环节在哪？拉力最容易构建的点在哪？ | "推力=每月扣错钱→拉力=自动纠错+赔付" |
| **D** ⭐ | L5 的情感/社交任务 | 隐性需求的最大机会——用户不好意思说的需求 | "不是'想要绩效管理工具'——是'想让老板看到我在努力'" |
| **E** | L5 的微观体感 | 哪个微观体验一旦做好，能建立信任护城河？ | "卡扣的'咔嚓'声让用户觉得安全" |

**机会点 D 高亮**——冰山图中 D 被标注为重点。因为隐性需求（情感/社交任务）是竞争对手最不容易发现的，也是最容易建立壁垒的。
