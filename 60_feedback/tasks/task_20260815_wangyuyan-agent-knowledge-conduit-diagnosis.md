# 知识库→Agent 传导机制盘点诊断（#323，P0）

## 背景

用户指出（2026-08-15）：知识库更新应**惠及所有 agent**，这是系统性工程。现状：agent 知识接入三种割裂形态——A 编译快照型（销售对话助理 7-04 编译、AI 基本功教练）、B SOUL 内嵌+检索型（#303/#304）、C 无检索接入型（Hermes 老顽童/欧阳锋等）。共同缺陷：①知识变更无事件 ②digest/MOC 导航覆盖不全（E015）③检索接入不均（#308 只覆盖新助理）。新知识入库（#320/321/322）不会自动传导到任何 agent。

## 任务（调研先行 + 盘点诊断）

1. **全网调研（先行，≥2 独立来源）**：RAG→Agent 知识传导最佳实践——知识库变更通知、MCP 统一检索、agent 知识版本化、编译快照 vs 检索模式（调研先行原则：先调研后动笔）
2. **全 agent 盘点**：现状矩阵——每个 agent（销售对话助理/教练助理/会议助理/AI基本功教练/老顽童/欧阳锋/黄药师/洪七公/段王爷/王语嫣等）的接入形态、知识来源、检索能力、知识变更传导路径
3. **机制缺陷定位**：结合 E028（索引滞后）/E015（MOC 缺失）/#260/#261（知识接入缺口先例）/#265（四回路）实证
4. **诊断报告**：三层传导管线目标架构（①检索层：kdo_search MCP 全推广 ②导航层：digest 制度化+流水线门禁 ③刷新层：快照型迁移）+ P1-P3 分阶段落地建议（含每个 agent 的迁移路径）

## 三方法证据要求

- 全网调研 ≥2 独立来源（调研先行，先于动笔）
- 6 层交叉验证 + 9 层深挖
- 盘点基于实测（逐个 agent 查部署文件，不凭记忆）

## 验收标准

- 诊断报告落盘（现状矩阵 + 调研证据 + 三层架构 + P1-P3 建议 + 全 agent 迁移路径）
- 现状矩阵实测可复验（每个 agent 有部署文件证据）
- 欧阳锋审查
