# 任务 #97：AI 自我 X 光拆解与迭代 method 卡

## 来源

口述稿 L2118-2136。Truman 描述了一个**已跑通后被加防守封掉的** AI 操作：

> "你打开知识库，跟他说你去学一下知识库的双三角模型，然后自己剖析一下自己的设计过程。第二次请用双三角模型给我画一下，你这怎么设计出来的。之前的拉群是可以给你画的很顺畅的，现在不行了，就在内部加个防守。"

这不是"人用 X 光拆案例"（#88），也不是"人让 AI 复盘协作"（#85）——是 **AI 主动学双三角、主动拆自己、主动暴露自己的六要素缺口**。

## 任务目标

产出 1 张 method 卡 `method-yihang-ai-self-xray-iteration`——AI 用双三角自我拆解与迭代的操作法。

## 核心内容

### 1. 与 #85 的本质区别

| 维度 | #85 AI 辅助复盘 | 本卡 AI 自我拆解 |
|:---|:---|:---|
| 触发者 | 人 | AI 自己 |
| 时机 | 协作结束后 | 开始工作前 + 工作过程中 |
| 目标 | 复盘已经发生的 | 在行动前暴露盲区 |
| 输出 | 复盘报告 | 自我迭代计划 |

### 2. 操作流程

```
1. AI 接到任务
2. AI 去知识库学双三角模型
3. AI 用双三角拆自己的设计过程：
   - 审美：我判断"好"的标准是什么？够不够？
   - 体系：我的工作流稳定吗？缺什么里程碑？
   - 创造力：我有没有跳出来看这个问题？
   - 场景：问题边界清晰吗？
   - 数据：我有什么数据可以调用？缺什么？
   - 基本功：我要用什么工具组合？会不会用？
4. AI 输出自己的六要素缺口清单
5. AI 向人请求补缺口（数据/审美/体系）
6. 补完后执行任务
7. 任务结束后用 #85 复盘，形成闭环
```

### 3. Truman 的"防守"说明了什么

这个功能后来被加了防守（L2130："现在不行了，就在内部加个防守，你需要可能更聪明也许才能击穿这一层"）。说明：
- 它确实能跑通，不是理论假设
- 它太强了——AI 能拆自己的设计过程意味着它能暴露内部实现
- 防守的原因是安全和 IP，不是技术做不到

### 4. 对 KDO Agent 设计的直接启示

- KDO Agent 在启动前应先跑一遍自我 X 光——"我接到这个任务，我的六要素够不够？"
- agent-spec 中应内置"自我拆解"触发规则：任务复杂度超过阈值→自动走一遍自我 X 光
- 这是 Agent 从"被动执行"升级到"主动补盲"的关键一步
