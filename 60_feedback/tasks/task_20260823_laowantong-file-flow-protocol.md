## 动作（规范四件套+两类纪律细则）

1. **唯一编号**：建议书/诊断/审查意见书 frontmatter 必填 `doc_id: D-YYYYMMDD-NNN`（D=diagnosis 类，当日三位序号，跨 agent 全局唯一，lint 查重）；任务单沿用队列号 #xxx；spec 卡沿用卡片 id。三套编号不混用（E045）。
2. **版本号**：frontmatter `version: v1.0` 起版；订正/增补=新文件 v1.1/v1.2（`amends: <旧 doc_id>` 必填引用）；重大重写=+1.0。已交冻结文件的版本号永不变。
3. **日期时间节点**：`created_at` / `updated_at` 必填（ISO 8601）；冻结文件以 `updated_at` 为终态时间戳；`frozen_at` 可选标注进入看板流程时刻。
4. **命名方式**：固化现有惯例为条文——`diag_YYYYMMDD_<author>-<slug>.md`、`task_YYYYMMDD_<assignee>-<slug>.md`（slug 禁路径词/空格，F-040 口径）；订正件 slug 加后缀 `-v1.1` 或 `-amend`。
5. **两类纪律细则**：
   - 一次性交付物：全冻结（进入看板流程后一字不改；探针登记/裁定划行不构成对文件的修改——看板行在队列文件，不在建议书内）
   - 流转文件（任务单）：append-only——只追加节禁改既有节；frontmatter 状态字段归 queue_transition 独占；追加节必须带日期+署名
   - 每角色文件清单表：该角色产出的文件类型×纪律类型×命名模板×编号空间（一张表六角色）
6. **冻结判定口径**：什么算「已交」——建议书落 diagnosis/ 并被探针登记（或人工放入 PROPOSAL-PENDING）即冻结；任务单提审（pending_review）后到复审退回前冻结，退回补件=追加节不改既有节。
