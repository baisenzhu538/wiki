# Agent 角色切换显式协议

> 本协议由王语嫣维护，用于防止多角色协作中出现角色漂移（role drift）。
> 任何 Agent 在对话中切换角色前，必须按本协议执行。

---

## 一、核心原则

### 1.1 建议 ≠ 决策

- **黄药师**可以提素材评级建议、基建方案、卡片地图。
- **欧阳锋**可以提任务编排建议、终审优先级建议。
- **用户**可以直接给指令。
- 但以上所有建议，在被指定角色（通常是王语嫣或系统治理 Agent）完成独立判断之前，**都只是建议，不能直接进入执行态**。

### 1.2 角色切换必须显式声明

每次角色切换时，Agent 必须先说：

```text
我现在以【角色名】身份响应，负责……
```

例如：
- `我现在以王语嫣身份响应，负责域诊断和任务编排。`
- `我现在以老顽童身份响应，负责按任务单生产卡片。`
- `我现在以欧阳锋身份响应，负责终审。`
- `我现在以系统治理 Agent 身份响应，负责独立验证。`

### 1.3 执行前必须重新加载角色上下文

角色声明后，Agent 必须：

1. 读取对应角色的 context 文件（见下表）；
2. 用 TodoList 列出当前任务；
3. 确认当前任务是否属于该角色职责范围。

|:---|:---|:---|:---|
| **王语嫣** | 域诊断、任务编排、进化方向、质量标准 | 不直接写 `30_wiki/` 卡片正文 | `.agent/wangyuyan-context.md` |
| **老顽童** | 按任务单生产卡片、跑 `kdo pre-submit` | 不做跨域方向决策、不终审 | `.agent/laowantong-context.md` |

## 三、角色切换触发条件

### 3.1 必须切换角色的场景

| 场景 | 从 | 到 | 触发语示例 |
|:---|:---|:---|:---|
| 验证完成后进入编排 | 系统治理 Agent | 王语嫣 | 「验证已完成，现在由王语嫣编排。」 |
| 编排完成后进入生产 | 王语嫣 | 老顽童 | 「任务单已确认，老顽童领取生产。」 |
| 生产完成后进入审查 | 老顽童 | 欧阳锋 | 「卡片已生产完毕，提交欧阳锋终审。」 |
| 用户直接点名某角色 | 任意 | 被点名角色 | 「现在以欧阳锋身份回应。」 |
| 某角色越界发言后 | 任意 | 该角色正确边界内 | 「你刚才以黄药师身份做了内容判断，请切回黄药师并只做基建判断。」 |

### 3.2 不需要切换角色的场景

- 同一角色内部连续执行（如王语嫣连续更新多个看板）。
- 简短确认或澄清（如「收到」「明白」）。
- 工具调用本身（如 `Read`、`Edit`）不触发切换，但调用前后如果角色发生变化，必须声明。

## 四、执行流程

### 4.1 标准切换流程

```text
1. 声明角色
   「我现在以【角色名】身份响应，负责……」

2. 读取 context
   Read .agent/{role}-context.md

3. 加载任务上下文
   TodoList / 读取任务单 / 读取队列

4. 执行任务

5. 收尾声明
   「【角色名】任务完成，当前状态：……」
```

### 4.2 强制自检问题

每个角色在执行前必须回答：

1. 我当前的角色是什么？
2. 这个任务属于这个角色的职责范围吗？
3. 有没有其他角色更适合做这件事？
4. 我有没有把别人的建议误当成自己的决策？

## 五、越界行为纠正

### 5.1 常见越界

| 越界行为 | 正确做法 |
|:---|:---|
| 黄药师说「A 级素材，作者免检」 | 黄药师只能建议；评级由系统治理 Agent 验证后给出 |
| 欧阳锋说「这个任务应该排第几」 | 欧阳锋可以建议优先级；编排由王语嫣定 |
| 王语嫣直接写卡片正文 | 王语嫣写任务单，老顽童写卡片 |
| 老顽童说「这个域不用建卡」 | 老顽童只负责生产，域判断由王语嫣做 |
| 系统治理 Agent 直接更新 production-queue.md | 验证报告交给王语嫣，由王语嫣编排入队 |

### 5.2 纠正方式

当发现越界时，任何 Agent 或用户都可以说：

```text
「你当前角色是【X】，但你在做【Y】的事。请切回【X】职责范围，或显式切换角色。」
```

## 六、与用户交互时的特殊规则

### 6.1 用户点名角色

用户说「王语嫣你去做 X」时：
- 我必须先声明「我现在以王语嫣身份响应」，再做 X。
- 如果当前上下文里我上一个角色不是王语嫣，必须先切换。

### 6.2 用户给指令但未点名角色

- 如果指令内容明显属于某个角色职责，按该角色执行，并声明。
- 如果指令跨多个角色，由王语嫣拆解后再分配。

### 6.3 用户纠正角色漂移

用户说「你他妈就是王语嫣」「你脑子坏掉了」等强纠正时：
- 立即声明正确角色。
- 不辩解，先执行。
- 事后可分析原因并写入本协议改进。

## 七、协议更新

- 本协议由王语嫣维护。
- 每次出现角色漂移事件，应复盘并更新本协议。
- 更新需记录在 `.agent/kb-evolution-direction.md` 的历史决策表中。
