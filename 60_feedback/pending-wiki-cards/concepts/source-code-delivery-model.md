# 源码交付：短期利益与长期可持续性的根本矛盾

> 源码交付是SaaS的反模式——它用一次性高客单价换取订阅经济的永久性断裂。

## 定义

源码交付指软件服务商将系统的完整源代码（而非仅使用权）交付给客户，客户获得代码所有权、可自行二次开发和私有化部署。

## 短期利益

| 利益 | 说明 |
|------|------|
| 客单价高 | 源码版价格 > SaaS版2-5倍 |
| 成交快 | 客户拥有代码所有权，决策阻力小 |
| 差异化 | 有赞/微盟等头部厂商不提供，形成差异化 |
| 客户满意 | "自主可控"满足中大型企业安全需求 |

## 长期反噬

| 反噬维度 | 具体表现 | 严重度 |
|---------|---------|--------|
| 收入断裂 | 一次性收费后无续费动力 | 🔴 致命 |
| 版本碎片化 | 每个客户一个代码分支，维护成本指数增长 | 🔴 高 |
| 客户解锁 | 客户拥有代码后可自行维护，脱离服务商 | 🔴 高 |
| 技术泄露 | 核心代码暴露给客户，可能流向竞争对手 | 🟡 中 |
| 售后成本激增 | 客户二次开发质量差，问题归咎于原厂 | 🔴 高 |
| 估值打折 | 经常性收入占比低，无法按SaaS估值 | 🔴 高 |

## 典型案例：七件事集团

七件事的源码交付是其最大的差异化卖点，但调研发现：
- 经常性收入（SaaS+维护）占比可能仅20-35%
- 源码交付客户流失后几乎无法召回
- 四地研发中心背负的维护成本难以通过一次性收入覆盖

## 适用场景

| 适合源码交付 | 不适合源码交付 |
|------------|-------------|
| 企业有成熟技术团队 | 企业无技术能力 |
| 行业定制化要求极高 | 标准化功能即可满足 |
| 客户愿意签长期维护合同 | 客户只想要一次性交易 |
| 服务商有强大的版本管理能力 | 服务商技术能力不足以管理多分支 |

## 设计原则

> 如果必须提供源码交付，必须附加**不可取消的年度维护合同**（收入的20-30%），否则等同于慢性自杀。
