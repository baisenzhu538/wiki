# KDO知识库咨询入口可用性问题复盘与修复建议

> 提交者：Kimi Code CLI（咨询使用者）
> 触发场景：在回答用户关于「双三角」的问题时，没有先通过 KDO 检索知识库，而是直接用 Glob/Grep/Read 翻文件。
> 请 @黄药师、@欧阳锋 评估：这是工具建设问题、使用习惯问题，还是两者都需要修？

---

## 一、问题描述

在最近的咨询任务中，用户要求我「全面理解知识库里面关于双三角的认知」。但我没有先通过 KDO 的检索接口查询知识库，而是默认使用了 `Glob/Grep/Read` 直接翻文件。这导致：

1. **检索效率低**：需要人工遍历目录、猜测文件名、多次 grep。
2. **容易遗漏关联卡片**：同一概念有多个版本（如 OCR 版、enriched 版、framework 版），不容易一次性找全。
3. **缺乏统一视角**：没有利用 KDO 的 brief/graph 能力把相关 source、wiki、关联概念聚合成一个上下文视图。

---

## 二、原因分析

### 2.1 kdo 工具本身存在可用性问题（客观门槛）

我实际测试了 kdo 的核心查询命令，发现以下问题：

| 命令 | 状态 | 具体问题 |
|------|------|---------|
| `kdo query "双三角"` | ❌ 不可用 | `relpath()` 期望 `Path` 对象但收到 `str`，抛出 `AttributeError` |
| `kdo graph query "双三角是什么"` | ⚠️ 可用但 stdout 乱码 | Windows 终端 GBK 编码错误，中文输出乱码；但输出到文件再读是正常的 |
| `kdo brief --topic "双三角" --output file.md` | ✅ 可用 | 能正确聚合 source + wiki 上下文 |
| `kdo cards --query "双三角"` | ❌ 参数不存在 | `cards` 子命令没有 `--query`，实际参数是 `--type/--domain/--has/--missing` |

**结论**：kdo 的检索能力不是不存在，但入口有 bug、Windows 输出编码有问题、CLI 参数设计不直观，客观上增加了使用门槛。

### 2.2 咨询者（我）的使用习惯问题（主观问题）

即使 kdo 有这些 bug，我也不是完全用不了：

- `kdo brief --topic ... --output ...` 是可用的；
- 我可以直接读 `.kdo/search_index.json` 和 `graph_state.json`；
- 我可以把 `graph query` 输出重定向到文件避免乱码。

但我没有。这说明：

1. **默认工作流是 Grep/Read 直接翻文件**，没有把 kdo 当作默认入口。
2. **对 kdo 能力边界不熟悉**，不知道 brief/graph query 能带来什么增量。
3. **没有把「检索综合」任务和「目录遍历」任务区分开**。

---

## 三、建议修复方案

### 3.1 高优先级：修复 kdo 核心查询入口

1. **修复 `kdo query` 的 `relpath` 类型 bug**
   - 位置：`kdo/commands/delivery.py` 的 `cmd_query`
   - 修复：将 path 转换为 `Path` 对象后再传给 `relpath(root, path)`。

2. **修复 Windows stdout UTF-8 编码问题**
   - 位置：`kdo/cli.py` 的 `main()` 入口
   - 修复：在程序启动时强制 `sys.stdout.reconfigure(encoding='utf-8')`，避免 `gbk` 报错和乱码。

### 3.2 中优先级：提升 CLI 一致性和文档

3. **统一 `kdo cards` 参数命名**
   - 建议：增加 `--query` 作为 `--has` 或关键词搜索的别名，或改进 help 文档说明。

4. **补充「AI 助手/咨询者如何使用 kdo 做知识库咨询」的操作指南**
   - 放在 `90_control/` 或 `docs/` 中；
   - 明确说明什么场景用 `brief`、什么场景用 `graph query`、什么场景用 `cards`；
   - 给出 Windows 下的最佳实践（如优先 `--output` 到文件）。

### 3.3 对咨询者的工作流约定

5. **以后遇到「理解知识库中某概念」的任务**：
   - 第一步：`kdo brief --topic <概念> --output 50_delivery/briefs/...`
   - 第二步：基于 brief 中的相关卡片，用 `Read` 精读关键文件
   - 第三步：如需找关联概念，用 `kdo graph query <问题> --json > file.json`
   - 第四步：`Grep/Read` 只作为验证细节或读取特定段落的补充

## 五、附：已验证的可行路径

下面这条路径在当前版本是可用的，可以作为临时工作流：

```bash
cd Desktop/wiki
python -m kdo brief --topic "双三角" --output "50_delivery/briefs/brief_20260614_双三角.md" --limit 8
```

然后读取 `50_delivery/briefs/brief_20260614_双三角.md` 获取相关上下文。
