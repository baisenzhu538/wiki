## 洞察 1：战略失败往往不是方向错误，而是阶段与杠杆错配

### 模式描述

同一批战略动作在“跑马圈地期”可能是正确选择，到了“吃饱期”或“转型期”就会致命。大量案例显示，团队把生命周期阶段搞错后，会在错误的时间追求错误的杠杆：高速增长期追求盈利、单点未盈利时规模化、转型窗口期仍做增量优化。

战略框架通常回答“做什么”，却很少回答“现在该做什么”——而时机错配会让正确的战略方向变成错误的结果。

### 支撑案例（≥3）

| 案例 ID | 核心事实 | 错配表现 |
|:---|:---|:---|
| `case-strategy-failure-02-supermarket` | 精品超市 O 高速增长期追求盈利 | 在跑马圈地期设了“盈利”目标，反噬增长 |
| `case-lean-premature-expansion` | 多个项目单点未盈利就规模化 | 把局部验证当全局验证，用杠杆放大错误 |
| `case-strategy-practice-12-zero-loss` | 央企新店零亏损 | 吃饱期关键是复制模型而非创新模型 |
| `case-strategy-shell-oil` | 壳牌在原油还赚钱时转型服务 | 转型窗口期提前布局，而非等到主业衰退 |
| `case-strategy-wuxi-suntech` | 无锡尚德从全球第一到熬不过绝望之谷 | 现金流撑不过产业周期低谷 |
| `case-strategy-revival-13-bestore` | 良品铺子涨价暴跌后多维转型 | 吃撑期转型需要多维度同时发力 |
| `case-strategy-revival-14-gucci` | Gucci 起死回生 | 高端化需要砍掉低端才能腾出空间 |

### 框架未覆盖的理由

- `framework-strategy-six-stages` 区分了阶段，但缺少“阶段转换信号 + 阶段适配动作”的操作清单；
- `framework-strategy-brm` 回答赛道/定位/模式选择，但不绑定生命周期阶段；
- 经典框架（五力、价值链、BCG）多为静态分析，缺乏“何时该切换杠杆”的决策触发器。

### 建议沉淀为 dk 卡

`dk-strategy-stage-leverage-mismatch`：战略阶段与杠杆错配的识别清单。

## 洞察 2：团队常把“相关指标”当成“因果抓手”，在错误杠杆上平均用力

### 模式描述

创业者容易把容易观测的指标（满意度、到店频率、触达次数、社群人数、复购率）当成增长抓手，却未找到真正的因果链条。结果是：越用力优化表面指标，浪费越大。

这个模式的危险性在于它看起来“数据驱动”——团队确实在追踪指标、做 A/B 测试、优化流程——但只要抓的是相关性而非因果性，就会陷入“平均用力做促销”“全员提升满意度”的低效循环。

### 支撑案例（≥3）

| 案例 ID | 表面抓手 | 真实因果杠杆 |
|:---|:---|:---|
| `case-gym-membership-formula` | 满意度、到店频率 | 把“到店频率”变成“到店习惯” |
| `case-saas-renewal-formula` | 销售触达频次 | 让客户真正“用起来” |
| `case-dental-clinic-formula` | 拉流量 + 打折 | 建立“危机感知”才能提升成交率 |
| `case-private-domain-ecommerce-formula` | 拉人、发广告、做活动 | 信任 × 用户升级路径 |
| `case-offline-catering-formula` | 投抖音本地推、发优惠券 | 会员复购与场景绑定 |

### 框架未覆盖的理由

- `yt-business-formula-abc-model` 和 `yt-business-formula-parameter-iceberg` 开始涉及因果，但缺少“从相关到因果”的显性诊断流程；
- `framework-lean-false-model` 提供验证工具，但不直接教团队如何从业务公式中识别因果杠杆；
- 经典战略框架（五力、价值链）几乎不涉及经营指标背后的因果推断。

### 建议沉淀为 dk 卡

`dk-strategy-correlation-vs-causation-leverage`：如何在业务公式中识别真正的因果抓手。

## 洞察 3：战略方向可以正确，但组织能力/机制/资源不匹配会让执行变形

### 模式描述

大量失败案例（尤其是大企业失败案例）显示：战略方向本身并非致命问题，共识不足、组织僵化、核心能力缺失、激励机制背离、关键资源短缺才会让战略在执行中变形。隆中对“最完美的战略规划也可能被执行摧毁”也是同一命题。

这个模式与“战略错误”不同——它不是方向问题，而是“方向与组织承载力不匹配”的问题。

### 支撑案例（≥3）

| 案例 ID | 战略方向 | 执行变形原因 |
|:---|:---|:---|
| `case-strategy-failure-05-it` | IT 公司多元化 | 高层反复横跳，共识不足 |
| `case-strategy-failure-06-phone-n` | 手机公司追赶对手 | 组织僵化，迭代缓慢 |
| `case-strategy-failure-07-phone-l` | 收购软件团队补生态 | 缺乏软件生态能力，收购无法融入 |
| `case-strategy-failure-08-video` | 视频平台转型内容平台 | 版权库资源短缺 |
| `case-strategy-failure-09-boeing` | 737 MAX 项目 | 激励机制优先财务指标而非安全 |
| `case-strategy-failure-04-appliance` | 家电公司渠道推新品 | 路径依赖，研发能力不可迁移 |
| `case-strategy-longzhong-plan` | 隆中对 | 完美规划被执行环节摧毁 |

### 框架未覆盖的理由

- `framework-strategy-brm` 有“执行”环节，但缺少与战略选择同步诊断组织/机制的具体清单；
- `tool-strategy-nine-problems` 列出九类问题，但未提供“如何识别组织/机制/资源缺口”的系统性方法；
- `framework-strategy-mckinsey-7s` 覆盖组织要素，但与战略决策流程的接口不够显性。

### 建议沉淀为 dk 卡

`dk-strategy-organization-strategy-mismatch`：战略方向与组织承载力的同步诊断清单。
