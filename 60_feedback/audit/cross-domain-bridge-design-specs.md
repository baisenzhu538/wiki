## 1. 通用设计原则

每张桥接卡必须遵守：
1. **不重复原卡内容**：只讲“两个域如何接口”，具体方法论引用原卡。
2. **有明确触发问题**：卡一开头就要回答“用户什么情况下会需要这张卡”。
3. **有端到端流程图**：用 Mermaid 或表格展示 A 域输出 → 桥接点 → B 域输入。
4. **有具体调用清单**：列出本卡会引用哪些具体卡，并在 related 中体现。
5. **有失败模式**：桥接最容易出现的 2-3 个错误。
6. **可信度标注**：任何引用原卡外的断言必须标注 `[conf=X, source=...]`。

## 2. 桥接卡 1：framework-strategy-lean-validation

### 2.1 一句话定义

> 把战略选择翻译成一个可验证的假设清单，并用精益工具按优先级和成本排序验证。

### 2.2 触发问题
- “我们定了一个战略方向，但不知道哪里最可能错。”
- “战略会上讨论很嗨，但没人能说清楚先验证什么。”
- “老板想all-in，我想先小步验证，怎么设计实验？”

### 2.3 端到端流程

```
战略输出（来自 strategy-domain）
  ├── 赛道选择      → 验证：市场容量、竞争格局、时机窗口
  ├── 定位选择      → 验证：目标用户是否认可差异化价值
  ├── 商业模式      → 验证：用户是否愿意按预期付费
  ├── 增长路径      → 验证：渠道成本/转化率是否成立
  └── 壁垒假设      → 验证：优势能否持续、能否被快速模仿
           ↓
    用 ABCD/假设金字塔排序关键假设
           ↓
    用 FALSE 模型选择最低成本验证工具
           ↓
    按十倍速公式设计实验 → 执行 → 学习 → 战略迭代
```

### 2.4 核心表格

| 战略假设类型 | 典型问题 | 推荐精益工具 | 通过标准示例 | 不通过标准示例 |
|:---|:---|:---|:---|:---|
| 赛道存在 | 这个市场真实存在且足够大吗？ | 假营销/新闻稿测试、竞品分析 | 100+ 有效线索 | 投放后 CTR <0.5% |
| 需求真实 | 用户会为这个概念付费吗？ | 假产品页面、预售 | 预售转化率 >X% | 1000 UV 0 订单 |
| 方案有效 | 产品/服务能交付承诺价值吗？ | 人工 VIP、MVP | NPS >40 | 复购率 <5% |
| 商业模式 | 单元模型能跑正吗？ | 最小版本、小规模试运营 | LTV/CAC >3 | 单客亏损且无法收窄 |
| 增长可扩展 | 这个渠道能放大吗？ | 灰度测试、组合测试 | CAC 随规模不上升 | CAC 翻倍而转化率不变 |
| 壁垒可持续 | 竞争优势能维持多久？ | 竞品对标、时间窗口验证 | 6 个月内无直接竞品 | 巨头 3 个月内进入 |

### 2.5 失败模式

1. **验证顺序错误**：先验证商业模式，后发现需求不存在。
2. **把战略口号当假设**："我们要做行业第一"不是可证伪假设。
3. **实验设计过度粗糙**：用一个 landing page 验证需要深度访谈才能回答的问题。
4. **通过标准太软**："用户很感兴趣"不能替代"用户付费"。

### 2.6 必须链接的卡

- 战略域：`framework-strategy-brm`、`framework-strategy-six-stages`、`framework-strategy-business-design`
- 精益域：`framework-lean-false-model`、`framework-lean-abcd-model`、`framework-lean-systematic-test-curve`、`framework-lean-tenx-formula`
- 已有概念：`yt-entrepreneur-lean-validation`、`yt-entrepreneur-key-hypotheses`
- 决策域：`yt-decision-y-model`

### 2.7 9 层深挖

| 层级 | 深挖 |
|------|------|
| L1 | 输入是战略选择（方向/定位/模式），输出是验证计划与战略迭代信号 |
| L2 | 关键假设：战略方向可以被拆解为可证伪命题；验证结果能影响战略决策 |
| L3 | 某些战略假设（如政策方向、巨头动向）无法通过精益实验验证，只能用调研/经验 |
| L4 | 失败模式：验证顺序错误、口号当假设、实验粗糙、通过标准太软 |
| L5 | 替代方案：直接咨询行业专家、购买行业报告、竞品全面对标 |
| L6 | 需要一号位能接受"战略可能错"，团队能把战略语言翻译成假设语言 |
| L7 | 常见叙事："战略定了就要All-in" vs "先验证再投入"的文化冲突 |
| L8 | 边界：高度不确定性赛道（如全新品类）、强政策依赖赛道不适合纯精益验证 |
| L9 | 决策框架：战略假设 → 优先级排序 → 选择验证手段 → 实验 → 学习 → 战略迭代 |

## 3. 桥接卡 2：framework-five-step-lean-interface

### 3.1 一句话定义

> 把一堂五步法（需求→产品内核→商业模式→增长→壁垒）的每一步，映射到对应的精益验证工具和通过标准。

### 3.2 触发问题
- “我知道要做五步法，但每一步怎么验证？”
- “产品内核画布填完了，怎么知道填得对不对？”
- “商业模式设计了很多版本，先测哪一个？”

### 3.3 核心表格

| 五步法阶段 | 核心问题 | 待验证假设 | 精益工具 | 通过标准 |
|:---|:---|:---|:---|:---|
| 需求 | 用户要解决什么任务？ | 这个需求真实且重要 | 客户访谈、假营销、搜索词验证 | 访谈中用户主动描述痛苦 |
| 产品内核 | 最小可交付价值是什么？ | 产品能交付承诺价值 | 假产品、人工 VIP、MVP | 早期用户愿意复购/推荐 |
| 商业模式 | 怎么赚钱？ | 单元模型成立 | 预售、最小版本试运营 | LTV/CAC 可算且为正 |
| 增长 | 怎么放大？ | 渠道可扩展 | 灰度测试、组合测试 | CAC 可控，边际成本不激增 |
| 壁垒 | 怎么守住？ | 优势可持续 | 竞品动态监测、时间窗口验证 | 6-12 个月护城河可见 |

### 3.4 失败模式

1. **跳步验证**：需求没验证就做 MVP。
2. **工具错配**：用 landing page 测产品内核（应该用人工 VIP）。
3. **通过标准不一致**：不同步骤用不同口径判断"成功"。
4. **把验证当终点**：验证通过后直接全量投入，缺少"螺旋上升"。

### 3.5 必须链接的卡

- 五步法：`yt-five-step-method`、`yt-entrepreneur-five-step-method`、`yt-five-step-canvas`
- 精益：`framework-lean-false-model`、`framework-lean-abcd-model`、`framework-lean-systematic-test-curve`
- 产品内核：`concept-一堂-kernel-validation`、`yt-panproduct-execution-low-cost-mvp`

### 3.6 9 层深挖

| 层级 | 深挖 |
|------|------|
| L1 | 把五步法的抽象流程翻译成可执行的验证动作 |
| L2 | 关键假设：五步法的每一步都有对应的可证伪命题和最低成本验证工具 |
| L3 | 强监管行业（医疗、金融）中某些步骤的验证受合规限制 |
| L4 | 失败模式：跳步、工具错配、标准不一致、把验证当终点 |
| L5 | 替代方案：直接按行业最佳实践设计，跳过部分验证 |
| L6 | 需要团队理解五步法不是线性流程，而是迭代循环 |
| L7 | 常见叙事："五步法做完了就能成功" vs "五步法每步都要验证" |
| L8 | 边界：成熟行业的微创新可能不需要完整五步法验证 |
| L9 | 决策框架：定位当前步骤 → 选择待验证假设 → 匹配精益工具 → 设定通过标准 → 螺旋上升 |

## 4. 桥接卡 3：framework-lean-pivot-decision

### 4.1 一句话定义

> 当精益实验结果不理想时，用决策框架判断是 pivot（转型）、persevere（坚持）还是 kill（终止）。

### 4.2 触发问题
- “实验数据不好，是我们没做对，还是方向错了？”
- “用户反馈很热烈但不付费，该 pivot 吗？”
- “连续 3 次实验失败，是坚持还是止损？”

### 4.3 决策矩阵

| 实验结果 | 对战略假设的影响 | 建议动作 | 决策检查清单 |
|:---|:---|:---|:---|
| 需求不存在 | 战略基础崩塌 | Pivot 或 Kill | 是否有其他用户群体？是否有相邻需求？ |
| 需求存在但方案弱 | 产品内核不成立 | Pivot 方案 | 能否用更 sharp 的解决方案？ |
| 需求/方案都成立但模式不成立 | 商业模式不成立 | Pivot 商业模式 | 定价、渠道、成本结构哪个错？ |
| 模式成立但增长不可扩展 | 增长假设失败 | Pivot 增长路径 | 是否有其他渠道？ |
| 都成立但壁垒弱 | 长期价值受威胁 | Persevere + 建壁垒 | 能否在窗口期内建立护城河？ |
| 都成立 | 方向正确 | Persevere + 放大 | 进入十倍速增长阶段 |

### 4.4 必须链接的卡

- 精益：`framework-lean-false-model`、`framework-lean-abcd-model`、`framework-lean-systematic-test-curve`
- 决策：`yt-decision-y-model`、`yt-tool-y-model-ruler`
- 战略：`framework-strategy-brm`、`framework-strategy-six-stages`

### 4.5 9 层深挖

| 层级 | 深挖 |
|------|------|
| L1 | 输入是实验结果，输出是 pivot/persevere/kill 决策 |
| L2 | 关键假设：实验结果能区分"执行失败"和"方向错误" |
| L3 | 沉没成本、团队情绪、创始人ego会干扰决策 |
| L4 | 失败模式：把执行失败当方向错误 pivot；把方向错误当执行失败坚持 |
| L5 | 替代方案：设置硬性 kill 条件、引入外部顾问、做情景规划 |
| L6 | 需要一号位有"止损勇气"和数据解读能力 |
| L7 | 常见叙事："坚持就是胜利" vs "快速 pivot" |
| L8 | 边界：长周期项目（硬件、医疗）中，单次实验结果可能不足以决策 |
| L9 | 决策框架：明确假设 → 设计实验 → 收集信号 → 分类诊断 → 选择动作 |

## 5. 桥接卡 4：framework-ai-accelerated-strategy-cycle

### 5.1 一句话定义

> 用 AI 同时加速战略分析（市场/竞争/用户）和精益验证（假设生成/实验执行/数据分析），形成更快的战略-验证闭环。

### 5.2 触发问题
- “AI 这么强，能不能让战略分析和验证都变快？”
- “我们用 AI 做内容，但战略验证还是很慢，怎么打通？”
- “AI 生成假页面/假文案后，怎么判断验证结果是否可信？”

### 5.3 AI 在闭环中的位置

```
战略分析阶段
  ├── 市场扫描        → AI Agent 聚合行业信号、财报、评论
  ├── 竞争对标        → AI 自动拆解竞品功能/定价/用户评价
  ├── 用户假设生成    → AI 从数据中提取潜在需求假设
  └── 情景推演        → AI 多模型并行模拟不同战略选择
           ↓
精益验证阶段
  ├── 假设排序        → AI 评估假设风险/成本/可验证性
  ├── 实验素材生成    → AI 生成 landing page / 访谈提纲 / 问卷
  ├── 数据收集        → AI 爬虫 / 多 Agent 调研
  ├── 结果分析        → AI 统计 + 模式识别
  └── 报告生成        → AI 生成验证报告，人做最终判断
           ↓
战略迭代阶段
  └── 人基于 AI 输出做 pivot/persevere/放大决策
```

### 5.4 人机分工边界

| 任务 | AI 做 | 人做 |
|:---|:---|:---|
| 信息收集 | 扫描、聚合、摘要 | 判断信息来源可信度 |
| 假设生成 | 提出候选假设 | 选择最关键假设 |
| 实验设计 | 生成方案草稿 | 设定通过/不通过标准 |
| 素材生成 | 文案、页面、问卷 | 最终审核与品牌调性把控 |
| 数据分析 | 统计、聚类、可视化 | 业务意义解读 |
| 决策 | 提供情景模拟 | 最终拍板 |

### 5.5 必须链接的卡

- AI 协作：`framework-multi-agent-research-architecture`、`framework-wanghuan-harness-seven-stages`、`concept-yitang-ai-research-human-loop`
- 战略：`framework-strategy-brm`、`framework-strategy-business-design`
- 精益：`framework-lean-false-model`、`framework-lean-systematic-test-curve`
- 决策：`yt-decision-y-model`

### 5.6 9 层深挖

| 层级 | 深挖 |
|------|------|
| L1 | 用 AI 压缩战略分析和精益验证的周期，但不改变决策责任归属 |
| L2 | 关键假设：AI 能降低信息收集和实验执行成本，但不能替代假设判断 |
| L3 | AI 幻觉、数据隐私、版权、广告法对生成内容的约束 |
| L4 | 失败模式：AI 输出当决策、过度信任 AI 统计、忽略 AI 无法验证的战略假设 |
| L5 | 替代方案：传统咨询公司、行业专家网络、手动调研 |
| L6 | 需要人有 AI 工具使用能力和批判性判断能力 |
| L7 | 常见叙事："AI 让验证成本归零"的过度乐观 |
| L8 | 边界：高度依赖人际信任、政策敏感、数据稀缺的领域 |
| L9 | 决策框架：人定方向 → AI 加速执行与验证 → 人做最终决策 |

## 6. 桥接卡 5：framework-demand-lean-bridge

### 6.1 一句话定义

> 把需求分析冰山（L1-L6）中识别出的需求假设，用 FALSE 模型和 ABCD 模型进行低成本验证。

### 6.2 触发问题
- “需求分析做了很多，但怎么知道不是纸上谈兵？”
- “冰山 L6 的机会卡片，怎么快速验证？”
- "RAT 评估完了，哪些假设最值得先做实验？"

### 6.3 冰山层级 → 验证工具映射

| 冰山层级 | 典型假设 | 验证工具 | 通过标准 |
|:---|:---|:---|:---|
| L1 用户标签 | 这类用户存在且可触达 | 假营销、社群测试 | 获取成本可控 |
| L2 场景问题 | 这个场景真实发生且痛苦 | 用户访谈、Reddit/评论分析 | 用户主动描述痛苦 |
| L3 核心任务 | 用户用这句话描述任务 | 访谈、问卷调查 | 70%+ 用户用一致语言描述 |
| L4 任务地图 | 任务链中的崩溃点准确 | 用户共创、原型测试 | 用户在关键步骤有强烈共鸣 |
| L5 四种力量 | 推/拉/焦虑/惯性的强度判断 | 量表问卷、A/B 测试 | 推力 > 惯性，拉力足够强 |
| L6 机会假设 | 这个组合值得做产品 | 假产品、预售、MVP | 付费转化或深度承诺 |

### 6.4 必须链接的卡

- 需求分析：`framework-demand-iceberg`、`tool-demand-iceberg-l1-user` ~ `tool-demand-iceberg-l6-hypothesis`
- 精益：`framework-lean-false-model`、`framework-lean-abcd-model`
- 已有概念：`yt-entrepreneur-key-hypotheses`

### 6.5 9 层深挖

| 层级 | 深挖 |
|------|------|
| L1 | 把需求分析的定性洞察转化为可验证的实验计划 |
| L2 | 关键假设：冰山的每一层洞察都对应可证伪命题 |
| L3 | 用户隐私、数据代表性、访谈引导性会扭曲验证结果 |
| L4 | 失败模式：把访谈态度当付费意愿、把单点数据当普遍需求 |
| L5 | 替代方案：大数据分析、竞品成功路径对标、专家判断 |
| L6 | 需要研究员既懂用户研究又懂实验设计 |
| L7 | 常见叙事："用户说他需要"等于"市场真实需求" |
| L8 | 边界：全新品类中用户无法表达未见过的东西 |
| L9 | 决策框架：冰山洞察 → 提取假设 → RAT 排序 → FALSE 验证 → 迭代洞察 |
