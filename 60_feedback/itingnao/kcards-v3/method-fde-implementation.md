# 方法卡：FDE 模式落地实施

## 一句话定义

FDE 模式落地是指通过组建前沿部署工程师团队，嵌入客户现场共同解决问题，并建立"现场探索 → 抽象沉淀 → 平台复用"的机制，把单次客户合作转化为长期产品能力。

## 适用场景

- AI Agent/企业级 AI 产品落地。
- 客户需求高度定制化，标准化产品无法满足。
- 新市场/新产品形态，需要通过深度合作发现 PMF。
- 客单价高、合作周期长，能承受前期重投入。

## 实施七步法

### 第一步：明确 FDE 目标

FDE 团队的核心目标通常是三类之一：

| 目标 | 说明 |
|------|------|
| 获客成功（Adoption） | 帮助新客户成功上线 |
| 扩展销售（Expansion） | 在现有客户中发现 upsell 机会 |
| 产品创新（Innovation） | 与客户共创新产品/功能 |

### 第二步：选择第一批客户

理想的首批客户特征：

1. **问题足够痛**：最好是 CEO 前五大优先级问题。
2. **愿意深度合作**：允许工程师驻扎现场。
3. **有代表性**：其需求能抽象为平台能力。
4. **合同价值大**：能支撑前期投入。
5. **决策速度快**：避免陷入漫长采购流程。

### 第三步：组建 FDE 团队

| 角色 | 要求 |
|------|------|
| FDE 负责人 | 有技术背景 + 客户经验 + 产品思维 |
| 现场工程师（Delta） | 全栈能力强，能快速实现原型 |
| 行业专家（Echo） | 懂客户业务，能发现真实痛点 |
| 后方产品经理 | 能从现场方案中抽象共性 |
| 后方平台工程师 | 把共性方案沉淀为平台能力 |

### 第四步：嵌入客户现场

- 驻扎周期：通常 3-12 个月。
- 工作方式：与客户团队坐在一起，参与日常会议。
- 关键行为：
  - 观察实际工作流程。
  - 快速搭建原型验证假设。
  - 每天与客户反馈迭代。

### 第五步：交付第一个成果

- 选择最容易量化价值的切入点。
- 目标：在 4-8 周内交付第一个可用结果。
- 要点：
  - 不要追求完美，先跑通价值。
  - 让客户看到具体改善（如效率提升、成本降低）。
  - 建立信任，为扩大合作铺路。

### 第六步：抽象沉淀到平台

- 定期召开"前线 → 总部"同步会。
- 对每个客户方案问三个问题：
  1. 这个需求是个性化的还是共性的？
  2. 能否抽象为通用功能？
  3. 下一个客户复用时能减少多少定制工作？
- 把可复用能力写入平台路线图。

### 第七步：规模化复制

- 当平台能力足够时，新客户只需要轻量定制。
- 逐步降低单客户 FDE 投入。
- 把 FDE 资源释放到更复杂、更高价值的客户问题上。

## 关键指标

| 维度 | 指标 |
|------|------|
| 客户成功 | 上线时间、客户满意度、NPS |
| 商业价值 | 合同金额、续约率、扩展率 |
| 产品沉淀 | 共性功能数、新客户需求复用率 |
| 效率提升 | 单客户 FDE 投入时间、部署周期 |
| 利润率 | 单客户毛利率变化趋势 |

## 健康 FDE 公司的财务特征

```
单客户利润曲线

利润
  ↑
  │      ╱‾‾‾‾‾‾‾‾
  │    ╱
  │  ╱
  │╱
  └────────────────→ 时间
    亏损期    盈利期
```

- 早期：投入大，可能亏损。
- 中期：产品更适配，部署变轻，合同扩大。
- 后期：边际成本下降，利润率显著提升。

## 常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| 滑向咨询 | 只做项目，不做平台 | 强制要求每个项目沉淀通用能力 |
| 产品臃肿 | 把每个客户需求都做成功能 | 产品经理抽象后再决定是否入平台 |
| 人才错配 | 招只会写代码的工程师 | 招 T 型人才，懂业务会沟通 |
| 客户选择错误 | 选错首批客户，投入打水漂 | 严格筛选，宁缺毋滥 |
| 忽视后方平台 | 前线忙，总部产品跟不上 | 建立固定同步机制和优先级 |

## 与相关方法的关系

- **客户发现（Customer Discovery）**：FDE 是深度客户发现的一种形式。
- **精益创业**：通过现场实验快速验证假设。
- **平台战略**：把定制经验沉淀为可复用平台。
- **解决方案销售**：但 FDE 更强调产品化和长期价值。
