# 方法卡：AI 落地效果评估

## 一句话定义

AI 落地效果评估是通过一套结构化指标，衡量 AI 应用在效率、质量、成本、收入和组织能力上的实际贡献，避免被技术炫目或虚假繁荣误导。

## 适用场景

- AI 试点项目结束后验收。
- 决定是否扩大 AI 应用范围。
- 向管理层或投资人汇报 AI 投入产出。
- 对比不同 AI 方案的实际效果。

## 评估四维模型

```
        效率
         |
    成本 ———— 收入
         |
       质量
```

### 1. 效率维度

| 指标 | 说明 |
|------|------|
| 任务处理时间 | AI 处理同样任务所需时间 |
| 人均产出 | 单位人力完成的业务量 |
| 响应速度 | 用户请求到获得结果的时间 |
| 并发能力 | 同时处理多少任务 |

### 2. 质量维度

| 指标 | 说明 |
|------|------|
| 准确率 | AI 输出正确的比例 |
| 错误率 | 需要人工修正的比例 |
| 一致性 | 相同输入下输出是否稳定 |
| 用户满意度 | 终端用户对 AI 结果的评分 |

### 3. 成本维度

| 指标 | 说明 |
|------|------|
| 单任务成本 | 总成本 ÷ 处理任务数 |
| 人力成本节省 | 减少的人工投入 |
| AI 调用成本 | API、算力、模型费用 |
| 维护成本 | 数据标注、模型迭代、系统维护 |

### 4. 收入维度

| 指标 | 说明 |
|------|------|
| 转化率提升 | AI 介入后业务转化率变化 |
| 客单价变化 | 推荐系统或客服带来的客单价变化 |
| 新收入 | AI 直接创造的新产品/服务收入 |
| 客户留存 | AI 服务对客户留存的影响 |

## 评估步骤

### 第一步：定义基线

- 在引入 AI 前，记录当前指标。
- 例：人工审核 1000 条标签需要 8 小时，错误率 5%。

### 第二步：设定目标

- 明确 AI 引入后期望达到什么水平。
- 例：AI 辅助后，审核 1000 条标签需要 2 小时，错误率降至 2%。

### 第三步：A/B 测试或平行运行

- 实验组：使用 AI。
- 对照组：继续使用原流程。
- 控制其他变量，确保结果可信。

### 第四步：收集数据并分析

- 计算各项指标的绝对变化和相对变化。
- 关注长期趋势，而非短期波动。

### 第五步：综合评估 ROI

```
AI 净收益 = 效率收益 + 质量收益 + 收入提升 - AI 成本 - 维护成本 - 组织变革成本
```

### 第六步：复盘与迭代

- 哪些目标达成？哪些未达成？
- 未达成的原因是什么？
- 下一步优化方向是什么？

## 虚荣指标 vs 可行动指标

| 虚荣指标 | 可行动指标 |
|---------|-----------|
| AI 调用次数 | 单任务成本 |
| 用户使用量 | 用户留存率 |
| 模型准确率 | 业务错误率 |
| "AI 赋能"项目数 | AI 带来的实际收益 |

## 常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| 没有基线 | 无法证明 AI 带来了什么 | 上线前记录关键指标 |
| 只看技术指标 | 准确率高但业务效果差 | 以业务指标为主 |
| 忽视隐性成本 | 只算 API 费用，不算人工标注 | 全成本核算 |
| 短期乐观 | 试点效果好，规模化后崩塌 | 持续追踪 3-6 个月 |
| 选择性报喜 | 只展示好看的数据 | 建立独立评估机制 |

## 与相关方法的关系

- **A/B 测试**：科学对比 AI 与人工效果。
- **ROI 分析**：量化投入产出。
- **PDCA**：持续迭代改进。
- **OKR**：把 AI 效果目标纳入组织目标体系。

```markdown
1. 项目背景与目标
2. 基线数据
3. 实验设计
4. 关键指标变化
5. ROI 计算
6. 风险与局限
7. 下一步建议
```
