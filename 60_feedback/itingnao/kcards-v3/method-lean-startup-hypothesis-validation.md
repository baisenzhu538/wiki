# 方法卡：精益创业假设验证

## 一句话定义

精益创业假设验证是把创业想法拆解为可证伪的假设，通过最小化实验快速获取真实用户反馈，避免在错误方向上过度投入。

## 核心循环

```
构建假设
    ↓
设计实验（MVP）
    ↓
收集数据
    ↓
验证/证伪假设
    ↓
学习并迭代
    ↓
构建新假设
```

## 两类关键假设

### 1. 价值假设（Value Hypothesis）

- 用户是否认为产品有价值？
- 是否愿意为此付费或使用？
- 例："用户愿意为 AI 生成的简历优化付费 29 元。"

### 2. 增长假设（Growth Hypothesis）

- 产品如何获取用户？
- 用户是否会推荐或复购？
- 例："通过小红书投放，单用户获客成本低于 10 元。"

## 假设的 SMART 化

| 差假设 | 好假设 |
|--------|--------|
| 用户会喜欢我们的产品 | 在目标用户中，MVP 的 7 日留存率 ≥ 30% |
| 我们能卖出去 | 在 2 周内，通过朋友圈销售 50 份 |
| 这个产品能火 | 在抖音投放 5000 元，获得 1000 个有效线索 |

## MVP 设计原则

1. **最小化**：只验证核心假设，不做多余功能。
2. **可测量**：有明确的判断标准。
3. **快速**：能在数天或数周内完成。
4. **低成本**：失败成本可控。

## 常见 MVP 形式

| 形式 | 适用场景 |
|------|---------|
| 登陆页 + 预约 | 验证需求强度 |
| 假门测试（Fake Door） | 验证用户点击意愿 |
| 众筹/预售 | 验证付费意愿 |
| 手工后台 | 验证服务流程 |
| 单功能原型 | 验证核心体验 |
| A/B 测试 | 验证不同方案效果 |

## 数据解读原则

1. **关注可行动指标**，而非虚荣指标。
2. **设定 kill criteria**：达到什么标准继续，什么标准放弃。
3. **区分信号和噪音**：样本量要足够。
4. **记录失败假设**：失败也是学习。

## 常见陷阱

| 陷阱 | 表现 | 对策 |
|------|------|------|
| 逃避证伪 | 只收集支持自己的数据 | 主动寻找反证 |
| MVP 过度设计 | 把 MVP 做成完整产品 | 聚焦核心假设 |
| 样本偏差 | 只问朋友或身边人 | 找真实目标用户 |
| 指标虚荣 | 只看下载量、注册数 | 看留存、转化、付费 |
| 迭代太慢 | 沉迷计划，不敢实验 | 小步快跑，快速试错 |

## 与相关方法的关系

- **科学方法**：假设→实验→验证。
- **设计思维**：以用户为中心发现问题。
- **敏捷开发**：快速迭代交付。
- **增长黑客**：数据驱动增长实验。
