# 智能药柜项目线下调研任务清单

## 使用说明

本清单用于指导药柜主题关键命题的线下验证。每条任务包含：验证目标、验证方式、责任主体建议、输出物、优先级、预计周期。

> **原则**：未经书面材料、第三方数据或官方口径验证的数字和断言，不得作为商业决策依据。

---

## P0（最高优先级：决定项目生死）

### P0-1 单设备真实运营数据验证

| 项目 | 内容 |
|------|------|
| **验证目标** | 获取已运营药柜的真实日均销售额、订单量、客单价、夜间订单占比、退货率 |
| **验证方式** | 选取 3–5 个不同场景（社区/医院/高校/企业园区）的设备，获取连续 30 天系统流水；现场蹲点 7 天核对 |
| **责任主体** | 项目负责人/运营负责人 |
| **输出物** | 《单设备运营数据汇总表》、与原财务模型的差异分析 |
| **预计周期** | 2–4 周 |
| **关联卡片** | `method-single-point-financial-model.md`、`method-medical-cabinet-business-model-decomposition.md` |

### P0-2 设备真实成本与供应链验证

| 项目 | 内容 |
|------|------|
| **验证目标** | 确认小机器 BOM 成本能否降到 3.5 万元以下；确认 200 台订单真实性 |
| **验证方式** | 获取供应商报价单/BOM；核查 200 台订单的 PO、合同、付款条件、客户资质 |
| **责任主体** | 供应链/采购负责人 |
| **输出物** | 《设备成本拆解表》《200 台订单验证报告》 |
| **预计周期** | 1–2 周 |
| **关联卡片** | `concept-medical-cabinet-hardware-technology.md`、`method-medical-cabinet-business-model-decomposition.md` |

### P0-3 广东/广州医保个账与统筹支付口径

| 项目 | 内容 |
|------|------|
| **验证目标** | 确认广州是否允许药柜刷医保个账；原研药超出医保支付标准部分能否刷个账；统筹是否开放 |
| **验证方式** | 电话咨询广州医保局、广州市监局；实地走访已接入医保的药柜/药店 |
| **责任主体** | 合规/政府关系负责人 |
| **输出物** | 《广州医保药柜支付口径确认函》或电话记录 |
| **预计周期** | 1–2 周 |
| **关联卡片** | `fact-national-policy-redlines.md`、`concept-regional-policy-map.md`、`concept-medical-cabinet-compliance-redlines.md` |

### P0-4 处方来源与远程审方合规性

| 项目 | 内容 |
|------|------|
| **验证目标** | 确认"大院处方、小院续方"模式在当地是否被允许；远程审方具体要求 |
| **验证方式** | 咨询当地卫健委、药监局；审查诊所处方开具流程、药师审方记录 |
| **责任主体** | 合规负责人 + 医疗顾问 |
| **输出物** | 《处方合规审查报告》 |
| **预计周期** | 2–3 周 |
| **关联卡片** | `concept-medical-cabinet-compliance-redlines.md`、`concept-pitch-vs-regulation-misalignment.md` |

### P0-5 深圳龙岗 6 月 1 日试点真实状态

| 项目 | 内容 |
|------|------|
| **验证目标** | 确认 6 月 1 日上线是内测还是对外运营；10 台设备实际运行情况 |
| **验证方式** | 实地考察深圳龙岗试点；访谈设备投放点周边用户/药店 |
| **责任主体** | 项目负责人 |
| **输出物** | 《深圳龙岗试点实地考察报告》 |
| **预计周期** | 1 周 |
| **关联卡片** | `medical-cabinet-roadmap.md` |

## P1（重要补充）

### P1-1 诊所+药柜真实落地规模与分成数据

|------|------|
| **验证目标** | 获取已合作诊所数量、分成比例、诊所真实收益 |
| **验证方式** | 访谈 5–10 家已合作诊所老板；查阅分账流水 |

| **预计周期** | 2–3 周 |
| **关联卡片** | `concept-clinic-cabinet-legal-relationships.md`、`method-medical-cabinet-business-model-decomposition.md` |

|------|------|

## 输出物模板建议

每次调研完成后，应产出包含以下要素的报告：

1. **调研目标**：验证什么命题
2. **调研方法**：电话/实地/问卷/后台数据
3. **样本信息**：时间、地点、对象、样本量
4. **原始发现**：第一手数据/记录
5. **与录音说法的差异**：是否证实/证伪/修正原有假设
6. **对知识卡的影响**：是否需要更新某张卡片
7. **剩余疑问**：哪些仍待验证
8. **附件**：录音记录、照片、合同/文件扫描件、数据截图

## 与现有知识卡的联动机制

1. 每完成一项调研，更新对应知识卡的"待核验问题"部分，标注验证日期和来源。
2. 若调研结果证伪原有假设，立即在卡片中标记并降级置信度。
3. 若调研结果将卡片置信度提升至 ≥ 0.78，可考虑迁移至 `30_wiki/`。
4. 每季度复核一次本清单，根据项目进展调整优先级。
