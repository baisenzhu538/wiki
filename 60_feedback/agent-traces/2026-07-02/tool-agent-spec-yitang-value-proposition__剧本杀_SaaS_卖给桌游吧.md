## 4. 需要避免的表达
- ❌ “AI 智能拼组，行业首创” —— 夸大且不可验证，客户更关心实际成功率而非技术标签。  
- ❌ “保证翻台率提升 30%” —— 属于过度承诺，不同门店环境变量过多，容易引发法律与信任风险。  
- ❌ “你们之前用微信群太落后了” —— 否定客户既有做法，易造成对立，应替换为“从熟悉的微信群拼组，升级为系统自动衔接”。

## 5. 关键卡点与 contingency / 验证问题
- 关键卡点：店长是否愿意改变工作流、历史会员数据迁移难度。  
- Contingency：若全员推广受阻，可先提供「排房 + 拼组」最小闭环给旗舰店，1 个月后拿对比数据说服其他店；若数据迁移复杂，可提供人工导入模板，1-2 周内完成。  
- 验证问题：  
  1. 试用期间有哪家店的流失率数据明显变化？  
  2. 最终购买决策是否还需要 IT 部门或老板额外审批？  
  3. 如果旗舰店试跑一个月收支可量化，是否方便下季度预算会推动全国采购？

## 6. 风险提示
- 卖点匹配置信度：**中高**（基于试用 7 天可观察行为变化，但全国推广的量化收益尚无法完全证实）。  
- 拼组成功率、空置率等数据引用，须以客户试用期实际统计为准，避免口头估算后被质疑；建议输出前与客户对齐具体数字或使用试算范围。  
- 剧本版权、会员隐私数据涉及合规，需客户确认数据用途符合当地法规，必要时请法律顾问复核。
