# 数字员工体系独立收敛样本的 KDO 进化建议书

> **定位**：Live86 分享者用三个月、零代码、下班后 1-1.5h/天，在本地部署 agent 平台上自建了一支数字员工团队（架构师/运维专家/协作平台/建模专家/workflow 平台/AIGC 专家）。这是一个**独立收敛样本**——他没看过 KDO，却走到了和我们高度同构的架构。独立收敛的价值：他踩过的坑=我们的预言验证，他解决的形态=我们的对照实验。
> **编号约定**：本建议书内编号（L1-L6）为建议性占位，正式编号以王语嫣入队时为准（decisions.md 2026-08-09 D2）。
> **视角声明**：建设者视角——每条建议都落到"改哪个机制/加哪个门禁/动哪个文件"，不停留在理念层。

---

## L1 残余文案规则门禁化盘点（P2，0.5d）

**他的实证**：建模专家总不按自定规则提炼，每次靠人提醒。原话——"如果每次都要靠提醒 AI 遵守规则，规则就没有真正变成系统能力"。解法：封装成 workflow/skill。

**KDO 对照**：我们已从"文案铁律"收了一批到门禁（E018 机制化、#363 提审 git 门禁、#375 claim 门禁、#390 流转自动收口）——方向被独立验证。但**还剩多少"靠 context 文案提醒"的规则没门禁化，全库没有一张清单**。

**建议动作**：
1. 扫 PROTOCOL/AGENTS.md/SOUL 模板/各 agent context 中的祈使句规则（"必须/禁止/记得"族），产出两列清单：已门禁化 / 仍靠自觉
2. 仍靠自觉的按摩擦频率（friction-log 命中数）排序，Top 3 提门禁化立项
3. 输出物：清单 + 排序依据，不入队具体改造（由王语嫣裁）

**验收**：清单可复扫（脚本化，不是一次性人工读）；每条规则标注"门禁化成本"（脚本可判定 vs 需语义判断）——语义判断类规则门禁化是伪命题，要诚实标注。

## L2 "项目经理 agent"反模式立项前检查（P3，0.25d）

**他的实证**：信了架构师建议造消息分发 AI 当项目经理，用一段时间发现——agent 间本可直接通信，中间层既不能 100% 懂他想法、转述还失真，最终砍掉。**中间传话层是反模式。**

**KDO 对照**：我们走 git+看板异步协作（文件即真相源），王语嫣的编排产物是任务单文件而非实时消息——天然避坑。但这个坑的诱惑会反复出现（"要不要加个调度 agent 自动分配任务？"）。

**建议动作**：在 agent 出生模板/立项三问里加一条检查项：**"新 agent 是否实质承担传话/转发职责？是→拒，改直连或改文件协作"**。改动位置：`#263` 出生模板 + claim 门禁关键词族可顺带覆盖。

**验收**：模板文件 diff + 一个假想"调度 agent"提案走一遍检查能被拦下。

## L3 长程任务"项目空间"持久上下文（P2，1d 调研+试点）

**他的实证**：长期任务放独立"项目空间"，与日常短任务上下文隔离防污染；一个 agent 挂不同项目空间调不同知识库，而非新建 agent。

**KDO 对照**：任务单+session 归档是同构雏形，但长程任务（#392 调研包、#393 标签体系）目前**单会话驱动**——每次续作靠失忆恢复锚点+任务单重建上下文，跨会话的中间态（调研半成品、已排除方向）不在任何地方。

**建议动作**：
1. 长程任务（预计跨 ≥3 会话）配 `60_feedback/tasks/<task_id>-workspace/` 持久目录：中间产物、已排除方向清单、下一步指针
2. 出生模板/claim 门禁联动：claim 长程任务时检查 workspace 存在性，不存在则创建并写入"上次停在哪"
3. 先在 #393（标签体系，天然长程）试点一轮再推广

**验收**：#393 中途换会话续作，新会话只读 workspace 不写失忆恢复就能接续——实测一次。

## L4 trust_level 反向用：检索/调研注入端源优先（P2，1d）

**他的实证**：AI 默认搜索抓公众号/百家号低质源；解法=限定行业最佳资讯站+本地搜索引擎+克隆仓库说明做知识库，**在注入端控源**。

**KDO 对照**：#382 刚修好 trust 过滤，但只在**输出端**（delivery 检索结果剔除 low-trust）。污染发生在注入端（agent 调研时读进上下文的素材），输出端过滤是末端补救。

**建议动作**：
1. `kdo_search`（MCP/CLI）加 `min_trust` 参数或排序权重：trust≥high 提权，low 默认折叠
2. 调研类 agent（洪七公/段王爷/R 型 Partner）SOUL 加"受信任源清单"段——从 source_refs 注册表自动生成，不手维护
3. 与 #382 语义对齐：无 frontmatter/缺 trust_level 按 medium 放行不误杀

**验收**：同一查询在 min_trust=high 下结果集变化可 diff；低质源（已知 520 张 low-trust）不再进调研上下文。

## L5 防忽悠三层法结晶为 skill（P3，0.5d）

**他的实证**：甄别 AI 输出的阶梯——①看不懂→让 AI 解释；②仍困惑→让它找同类事件看别人怎么解；③再不行→让它出最低成本验证方案自证。

**KDO 对照**：欧阳锋 O3 实证+三问是终审侧的同构重武器；这个三层法是**消费侧轻量版**，适合每个 agent 日常用。

**建议动作**：写成 skill（触发词："AI 给的方案靠不靠谱/看不懂的回答"），挂 agent-basic-skills-coach 体系，kdo 注册。内容含三层阶梯+每层话术模板+终止条件（第三层仍未过→标记存疑而非采信）。

**验收**：skill 通过 `kdo skill eval`（能力+回归）；一个真实场景（如"架构师推荐 Matrix"类错误建议）回放能被第二层拦下。

## L6 AI 人效原则写入出生决策（P3，0.25d）

**他的实证**：管理半径 5-10 人对 AI 同样成立；原则=尽可能少的 agent 产出尽可能多成果——新需求优先"现有 agent+workflow 组合"，而非新建 agent。

**KDO 对照**：fleet 已 10+ 角色，出生模板已固化挂 kdo MCP（#263），但"要不要生新 agent"没有前置闸。

**建议动作**：立项三问加第 0 问："现有角色+workflow/skill 组合能否覆盖？能→不新造"。与 L2 同一次改动落进出生模板。

**验收**：模板 diff + 裁决案例登记 1 条（哪怕首例就是"否决某个新 agent 提案"的假设推演）。
