## 二、五层问题模型

```
外部Agent体验 = 五个层级叠加，任何一层断裂→体验断裂

L1 卡片元数据层    title/aliases/tags是否完整？         ← 08-02问题所在
L2 索引管道层      新卡入库后索引是否实时刷新？          ← 07-26问题所在
L3 搜索能力层      BM25是否够？语义/同义词/RRF是否工作？ ← 07-27部分修复
L4 接口设计层      MCP tool desc是否有场景引导？         ← 黄药师建议书
L5 新人引导层      外部Agent是否有入口文档/help？         ← 完全缺失
```

### L1：卡片元数据 — 生产侧（老顽童+欧阳锋）

| 当前状态 | 缺口 |
|:---|:---|
| 正常卡有 title/aliases/tags | ❌ 无强制性门禁——空title的卡能通过终审 |
| 标签体系已建立（tag-registry.yaml）| ❌ 老顽童不一定填、欧阳锋不一定查 |

**07-27黄药师修的索引三层**已被L1缺口重新击穿——索引管道能感知aliases，但卡片根本没写aliases。

### L2：索引管道 — 基建侧（黄药师）✅ 已修

07-27黄药师已升级索引三层。08-02的问题不是索引层的错——是L1没给索引层输入。

### L3：搜索能力 — 基建侧（黄药师）🟡 部分修复

| 已修 | 未修 |
|:---|:---|
| RRF排序（BM25+Graph RAG权重融合）| 无语义搜索——"创新者的窘境"和"disruptive innovation"互不可达 |
| MCP返回aliases+tags+position | 同义词词典未建 |
| | 搜索失败无诊断输出（只返回空列表）|

### L4：接口设计 — 基建侧（黄药师）🔴 完全缺失

黄药师建议书中点出的核心问题——**KDO MCP接口讲香V1**：

- `kdo_search` tool description是一行技术描述，外部Agent不知道"什么时候用、搜不到怎么办"
- 搜索结果只有score没有场景化判断——snippet太短，Agent必须逐张`kdo_read`才能判断相关性
- 工具间无路由——Agent不知道`kdo_search`搜不到时可以换`kdo_graph`

### L5：新人引导 — 全角色 🔴 完全缺失

对内部四角色：管线规则、角色分工、SOP文档齐全。
**对外部Agent：零入门文档。**

外部Agent首次接入KDO时面对的是：
- 不知道有哪些工具
- 不知道工具间关系
- 不知道KDO知识库的域结构
- 不知道检索策略（先用kdo_search还是kdo_graph？）
- 失败时无建议路径

## 三、与KDO第一性原则的关联

**KDO第一性原则**（2026-07-26用户纠正）："Agent进来读的是加工好的30_wiki知识卡，不是00_inbox原材料。如果卡片产出后Agent搜不到、匹配不上，前面所有诊断和生产都白做。"

这句话当初是对**内部Agent**说的。现在加上外部Agent：

> **KDO第二原则（推论）**：外部Agent是知识工厂的"最终用户"——它们能不能搜到、能不能理解、能不能用，是检验KDO价值的终极标准。内部四角色管线只是"生产系统"，MCP接口才是"交付系统"。生产得再好，交付不出去=零。
