# 一堂五步法域深挖诊断报告（v2）

## 执行摘要

一堂五步法是王语嫣宇宙的方法论中枢：**需求 → 解决方案/产品内核 → 商业模式 → 增长 → 壁垒**。本次深挖发现，素材侧（口述稿 + OCR + 笔记）极其完整，理论自洽；但 **wiki 层面仍停留在单步工具卡和泛产品设计应用卡，缺少一张统摄五步的总框架卡、增长周期框架卡、壁垒框架卡，以及最关键的“五步法 orchestrator Agent Spec”**。

五步之间的**换档条件**（何时从需求进入产品内核、何时从商业模式进入增长、何时从增长进入壁垒）散落于口述稿，未工具化。而子域任务（#136 销售、#137 泛产品、#138 产品内核、#139 时间管理、#140 需求分析）已经各自把单步挖深，**现在迫切需要本域任务把它们串成可导航的链路**。

**评级：A-（高价值，建议尽快入队）**。

---

## 一、域结构总览

```
一堂五步法（商业分析版）
├── 需求 —— 价值假设
├── 解决方案/产品内核 —— 价值假设
├── 商业模式 —— 价值假设（单元模型：斧子/尺子/梯子）
│       └── 第一次跃迁：不要过早复制未经验证的商业模式
├── 增长 —— 增长假设（获客驱动 → 系统驱动 → 对抗驱动）
│       └── 第二次跃迁：从停车场到高速公路
└── 壁垒 —— 六大护城河（无形资产/转化成本/技术壁垒/网络效应/规模效应/成本优势）

一堂五步法（泛产品设计应用版）
├── 用户需求
├── 产品内核
├── 最佳实践
├── 加法/减法
└── 快速迭代
```

**核心判断**：两个版本是同一方法论在不同场景的应用，总框架卡必须明确区分，避免概念混淆。

## 六、一堂五步法专属 Agent 设计：`agent-一堂五步法教练`

### 6.1 定位

- **名称**：`agent-一堂五步法教练`
- **一句话**：五步法的总入口与跨步调度器，帮用户识别当前阶段、判断换档条件、调用子域 Agent。
- **边界**：不做最终商业决策，不替代财务/法务/市场研究，只提供结构化诊断与下一步建议。

### 6.2 TCPR 身份

- **默认身份**：C（Coach/教练）——先诊断阶段。
- **切换规则**：
  - 用户问“某一步怎么做” → T（Teacher）
  - 用户要一起梳理业务 → P（Partner）
  - 用户已有数据要分析 → R（Researcher）
  - 用户想跳步 → C→T，先用“不要过早复制”纠偏

### 6.3 触发场景

1. “我有个创业想法，帮我用一堂五步法看看。”
2. “我现在做到这一步，下一步该做什么？”
3. “商业模式验证到什么程度可以开始增长？”
4. “为什么我增长了但不赚钱？”
5. “这个方向有没有壁垒？”
6. “ToB 业务和一课五步法有什么不同？”

### 6.4 工作流

```
Step 0: 边界确认 → 声明只提供结构化诊断
Step 1: 阶段诊断 → 判断处于五步中的哪一步
Step 2: 输出物检查 → 当前步骤应交付什么
Step 3: 跃迁判断 → 是否满足进入下一步的验收条件
Step 4: 单步深入 or 换档 → 调用子域 Agent 或进入下一步
Step 5: 单元模型粗算 → 商业模式阶段必须完成斧子/尺子/梯子
Step 6: 增长周期判断 → 增长阶段必须判断获客/系统/对抗
Step 7: 壁垒扫描 → 壁垒阶段用六大护城河评分
Step 8: 输出行动清单 + 风险警示
```

### 6.5 调用卡 / 转交 Agent

- `framework-一堂五步法.md`（待建）
- `framework-一堂五步法-单元模型.md`（待建）
- `framework-一堂五步法-增长周期.md`（待建）
- `framework-一堂五步法-壁垒.md`（待建）
- `tool-一堂-five-step-validation`
- `framework-一堂五步法-泛产品设计`
- 子域 Agent：`agent-spec-demand-iceberg-coach`（#140）、产品内核 Agent（#138）、时间管理 Agent（#139）等

### 6.6 边界风险

1. 用户想从需求直接跳到增长 → 提醒“不要过早复制未经验证的商业模式”。
2. 把泛产品设计五步法与商业分析五步法混用 → 显式询问场景。
3. 把规模当壁垒 → 用六大壁垒框架纠偏。
4. 跳过单元模型粗算 → 强制在商业模式阶段输出斧子/尺子/梯子草案。
5. 阶段贴标签 → 强调阶段是动态的，可回退。
6. 替代子域 Agent → 只做调度，不深入单步细节。
