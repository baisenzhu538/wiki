## 0. 一句话结论

记忆胶囊四层从下往上定稿为 **L1 全量上下文 → L2 反馈/审计/建议 → L3 沉淀可复用资产 → L4 方法论/规范**。底层原始资料另处保存 + 备份，保证「哪怕项目崩盘、没人了，只要有全量上下文就能马上复刻整个项目」。

## 1. 四层定义（定稿）

| 层 | 定义 | 责任人 | 产出形态 |
|:--|:--|:--|:--|
| **L1 全量上下文** | 每个角色工作过程的完整记录 = 原始日志，另处保存 + 备份 | 每个角色各自保证自己的全量记录 | 原始日志（SQLite 等，另处备份） |
| **L2 反馈 / 审计 / 建议** | 基于 L1 定期做反馈、审计、建议 | 风清扬（**最重要的本职**，不是唯一本职） | 审计报告 / 建议书 |
| **L3 沉淀可复用资产** | 把 L2 结论沉淀为可复用资产（卡 / spec / 模板），也可能修订宪法、修订工作流、甚至做基础设施迭代——都以「将来能持续复用」为准 | 王语嫣等 | 卡 / spec / 模板 / 修订案 / 基建迭代 |

## 2. 三条铁边界

1. 风清扬位置停在 L2：做审计/建议，不把手伸进 L3 沉淀、不替谁写规范正文。
2. 每个人复盘是他们自己的事（各自迭代过程，必需）；风清扬不负责、不催他人复盘。
3. 文档是角色间唯一沟通；老朱 CLI 的个人纠偏先内化进各角色自己的记忆，只有需角色间协作的才落正式文档。
