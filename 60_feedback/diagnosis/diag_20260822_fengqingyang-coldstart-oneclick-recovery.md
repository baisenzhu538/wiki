# KDO 冷启动一键恢复建议书

> 老朱指令：把"右键启动 + 一句话恢复记忆"写成建议书交王语嫣立项，降低每次启动的 token 损耗。
> 定位：观察者建议书（B2-2 ① 只交王语嫣）。本文件只提方案与口径，不派活。

## 0. 一句话结论

老朱每次启动 agent 都要手动开 Terminal + 说一长串"去什么文件夹、读什么文件"，浪费大量 token 且体验差。**恢复口令 KDO 其实早已写好，只是没接到位**。方案 = 三件事一起做：①人侧一键启动 ②冷启动自恢复固化进 context 铁律区 ③恢复收敛为"锚点一份"。做完后体验 = 右键 → 选角色 → 「王语嫣，继续」→ 自动读锚点、报状态、直接干活。

## 1. 现状与根因（审计证据）

| 证据 | 位置 | 说明 |
|:--|:--|:--|
| 各角色 context 已有失忆恢复口令 | 如 `.agent/wangyuyan-context.md` L114 | 但口令是「读 startup、方向、队列和看板」——**这一串本身就是老朱每次要说一长串的原因** |
| 更简口令早已写好 | `20_memory/wangyuyan-amnesia-recovery.md` §4 | 「重启恢复口令：老朱说『继续』→ 读本节 + 停车场 + queue status」——写好但未生效 |
| 王语嫣 context 陈旧 | `updated: 2026-07-20` | 恢复口令藏在 L114，不在前 30 行 L0 铁律区；agent 启动读不到 → 表现为「王语嫣一直问我有什么事」 |
| 两套真话不一致 | context L114 vs 锚点 §4 | 一处说"读一堆文件"，一处说"读本节"——正是漂移实锤 |

**根因不是"没有恢复机制"，是三层脱节**：口令藏得深、口令指向一堆文件、两处口径不一。文档写了 ≠ agent 会话开始时知道。

## 2. 方案（三件事，缺一不可）

### A · 人侧一键启动（黄药师）

- 产出：`启动agent.ps1`（或右键菜单集成），右键 wiki 文件夹 → Windows Terminal → 菜单选角色 → 自动 cd 到 wiki 目录 → 拉起对应 CLI 工具。
- 范围：CLI 类角色（王语嫣/欧阳锋/黄药师/老顽童/段王爷/洪七公）；飞书类不用（gateway 常驻，飞书里直接聊）。
- 验收：老朱三步内从桌面到 agent 会话，无需手动敲路径与工具命令。

### B · 冷启动自恢复固化进 context 铁律区（各角色 context 维护者）

- 每个角色 context 的 **L0 铁律区（前 30 行）** 新增一条硬规则：
  > 收到「你是{角色}，继续」→ **无条件**先读 `20_memory/<role>-amnesia-recovery.md` 的「当前状态」节 → `queue_transition.py status` → 核对 `git rev-parse --short HEAD` → 一句话报「记忆已恢复，当前……」，再等指令。
- 关键：写成**无条件动作**，不许等用户补充指令；读锚点一节 + 核两个数，5 秒内完成。

### C · 恢复收敛为「锚点一份搞定」（王语嫣 + 黄药师）

- 统一口令为一句：**「你是{角色}，继续」**。
- 消灭 context 里旧口令「读 startup、方向、队列、看板」那串——全部由锚点链出（锚点已有队列/方向/停车场链接）。
- 锚点「当前状态」节成为唯一恢复真相源；context 只存"读锚点"这一条，不再复制状态。

## 3. Token 收益账

- 现状：每次恢复 = 数百 token 的口令 + agent 来回追问（"我有什么事"）+ 反复确认路径。
- 目标：每次恢复 = 两个字「继续」+ agent 自动读一个几 KB 锚点 + 一句状态回报。
- 按每天 5-8 个角色各启动 1 次计，单日可省数千 token；且消除"不知道要干什么"的确认损耗。

## 4. 建议立项切分

| 单 | 内容 | 归属 | 依赖 |
|:--|:--|:--|:--|
| #A | 一键启动脚本 + 右键菜单 | 黄药师 | 无 |
| #B | 各角色 context 恢复协议固化进 L0 区 | 王语嫣（口径）+ 各角色 context 维护者 | 无 |
| #C | 恢复口令收敛 + 锚点成为唯一恢复文件 | 王语嫣（锚点主）+ 黄药师（脚本核验） | B 完成后统一 |

> 建议优先级：B/C（纯文档收敛，先止血 token 损耗）→ A（脚本体验，后补）。
