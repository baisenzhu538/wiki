# 王语嫣调研能力建设报告

> 背景：用户指令「调研也是你的重要技能」。本报告整合 `30_wiki/` 中调研相关资产与全网调研方法论，明确王语嫣的调研能力边界、工作流和下一步行动。只读知识库 + 写反馈，不改 `30_wiki/`。

---

## 一、为什么王语嫣必须强化调研能力

王语嫣的核心职责是**诊断式咨询**：把用户模糊的商业问题匹配到知识库中的框架。但诊断质量受两个瓶颈制约：

1. **知识库覆盖不足**：用户问题可能落在知识库空白区，需要先通过调研补全信息，再判断缺哪张卡。
2. **外部素材置信度**：用户提供的转录稿、访谈、行业报告需要被评估是否可信，否则诊断建立在流沙上。

因此，调研不是替代诊断，而是诊断的**前置能力**和**置信度底座**。

## 三、全网调研方法论精华

### 3.1 深度研究智能体（Deep Research Agents）

来自 arXiv 系统综述（2025）与 Firecrawl 博客（2026）的核心观点：

| 维度 | 关键洞察 |
|:-----|:---------|
| **工作流** | Static（预定义流水线）vs Dynamic（自适应重规划）。王语嫣适合 Dynamic——根据用户回答动态调整调研方向 |
| **规划策略** | Planning-Only / Intent-to-Planning / Unified Intent-Planning。王语嫣天然是 Intent-to-Planning——先追问澄清意图 |
| **记忆机制** | 长上下文窗口 vs 中间步骤压缩 vs 外部结构化存储。王语嫣应使用外部结构化存储（KDO wiki + 诊断记录） |
| **事实核查** | Grok 式多层深度验证 + Zhipu Rumination 式自我反思。关键结论需多源交叉验证 |
| **非参数持续学习** | 基于案例的推理（CBR）——把历史调研案例存入案例库，遇到相似问题时复用 |

### 3.2 信源可信度评估

来自斯坦福大学 Wineburg & McGrew、SIFT、CRAAP、国际事实核查网络：

| 方法 | 核心动作 |
|:-----|:---------|
| **横向阅读（Lateral Reading）** | 不在当前页面深挖，而是打开新标签查第三方对该来源的评价 |
| **SIFT** | Stop → Investigate the source → Find better coverage → Trace claims |
| **Source Triangulation** | 每个重要声明至少 3 个独立来源，且来源方法论/视角不同 |
| **CRAAP** | Currency / Relevance / Authority / Accuracy / Purpose |
| **信源五级**（OSCAR 借鉴） | L1 原始数据 → L2 学术研究 → L3 权威媒体 → L4 社区内容 → L5 社媒碎片 |

### 3.3 用户/市场研究经典方法

来自 Shopify、UX 百科、产品经理实务：

| 方法 | 适用场景 | 王语嫣用法 |
|:-----|:---------|:-----------|
| 深度访谈 | 挖掘动机、行为、痛点 | 用户说"业务不好"时追问具体场景 |
| 焦点小组 | 获取群体反馈 | 暂不直接使用 |
| 观察/田野调查 | 看用户真实行为 | 建议用户做 MVP 测试时观察 |
| 问卷调查 | 量化验证 | 诊断后期验证假设 |
| 二手资料 | 行业趋势、竞争格局 | 快速建立行业基线 |

## 四、王语嫣调研能力模型

### 4.1 定位

王语嫣的调研能力不是「替代 deep-research」或「替代老顽童产卡」，而是：

> **在用户描述模糊问题时，通过追问 + 轻量调研 + 置信度评估，快速判断：该问题该用哪个框架、知识库缺什么、用户提供的素材可不可靠。**

### 4.2 三层能力

```
L1 诊断性调研：5-15 分钟，回答"这个问题该用什么框架看"
L2 置信度评估：15-30 分钟，回答"这条信息可不可靠"
L3 深度研究委托：30 分钟+，回答"这个主题全貌是什么"（委托 deep-research / 老顽童）
```

### 4.3 王语嫣调研工作流（WYY-Research）

#### Step 0：意图澄清（追问）
- 用户原始问题是什么？
- 这是决策问题还是认知问题？
- 时间窗口有多紧？
- 已有信息源是什么？

#### Step 1：知识库扫描
- `kdo query "<用户问题>"` 召回已有概念卡
- 检查是否有 `diagnostic_signals` 命中
- 识别缺口：框架缺失 / 案例缺失 / 信源缺失

#### Step 2：轻量外部调研（L1 诊断性调研）
- 用 WebSearch 做 2-3 轮横向阅读
- 目标不是写报告，而是确认：
  - 用户问题的行业基准是什么
  - 常见失败模式是什么
  - 哪个框架最匹配

#### Step 3：置信度评估（如用户提供素材）
- 对每条关键声明执行 SIFT
- 用 OSCAR 信源五级 + 动态调整（时效/直接经验/利益冲突）打分
- 输出 🔵/🟡/🔴 分级

#### Step 4：诊断匹配
- 将调研发现映射到知识库 framework/tool/case
- 标注命中框架、盲区、Gap

#### Step 5：产出诊断记录
- 写入 `60_feedback/diagnosis/`
- 如需补卡，写 `60_feedback/corrections/`
- 如需深度研究，建议用户委托 deep-research 或老顽童

## 八、关键判断

1. **王语嫣不应成为 deep-research 的替代者**，而应成为 deep-research 的「入口过滤器」和「结果解释者」。
2. **调研能力的核心是「问题定义」和「置信度判断」**，而非搜索次数。
3. **wiki 中调研资产丰富但分散**，最需要的是一张能把它们串成诊断工作流的「总纲卡」。
4. **横向阅读和 SIFT 是王语嫣最应内化的两项技能**——它们直接服务于外部素材置信度评估。
5. **所有调研产出最终应回到 KDO 飞轮**：调研发现 → 诊断记录 → 补卡/修卡 → 知识库增强 → 下一次诊断更精准。
