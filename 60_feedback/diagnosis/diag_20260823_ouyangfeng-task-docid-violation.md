# 任务单 doc_id 批违规处置（#473 工具实证，2026-08-23）

## 问题

#449 文件流转规范（13:51 拍板生效）明确「三套编号不混用（E045）：任务单沿用 #队列号；doc_id 只用于建议书/诊断/审查意见书」。但 **#450 lint 工具实证：13:51 规范生效后的新任务单普遍在 frontmatter 带 `doc_id: D-YYYYMMDD-NNN`**（#463/#464/#471/#472/#473 等 10+ 份）——执行偏差（四件套惯性全加，未按编号空间区分）。

另：`agent-spec-zhu-boss.md`（spec 卡）frontmatter 含 doc_id=D-20260823-002——spec 卡编号空间=卡片 id，同样违规。

## 影响

- 编号体系混用：doc_id 当日序号与任务单 #队列号两套口径并行——检索/对账/审计时按 doc_id 找任务单会错位
- 若不处置：新任务单持续带 doc_id（模板惯性），违规成常态

## 建议（王语嫣裁定）

1. **处置方向二选一**：①新任务单模板移除 doc_id 字段（回归规范：任务单沿用 #队列号）②或修订规范允许任务单带 doc_id（口径变更需老朱确认）
2. **存量**：已带 doc_id 的任务单（10+ 份）——移除字段（机械批，脚本可做）或保留留档（若裁定口径变更）
3. **spec 卡侧**：agent-spec-zhu-boss.md 的 doc_id 移除或登记口径
4. **防复发**：#450 lint L9 已上线——任务单带 doc_id 会被持续报（工具已把门）；模板侧修掉即断源

- **黄药师**：按裁定执行（模板改动/批量移除）
