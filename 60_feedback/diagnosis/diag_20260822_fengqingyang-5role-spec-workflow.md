# KDO 五角色特性·规范·工作流建议书

> 老朱指令：针对 5 个入宪角色（王语嫣/欧阳锋/老顽童/黄药师/风清扬），全网调研最佳实践 + 学习库内九层深挖方法论，写出每角色的特性、规范、工作流，并结合 KDO 实际给建议。
> 交付对象：王语嫣（B2-2 ① 观察者建议书只交王语嫣）。本文件是建议书，非 KB 卡片。

## 0. 一句话结论

KDO 五角色是 Anthropic「orchestrator-workers + evaluator-optimizer」混合拓扑的完整实现，且比业界多了一层「观察者（独立审计+记忆）」。**架构对，缺的是岗位画像的完整度**：4 张 spec 卡停留在 B2 拍板前、风清扬无 spec、缺 Trigger/Interface 两维、逐角色工作流未定稿（B2-3 后置项）。本建议书把九层结论收敛为每角色一张「内核/职责/边界/工作流/触发/接口」建议，供角色专场逐张过。

## 九层深挖（针对「五角色设计」这一主题）

### L1 业务公式

**多 Agent 团队价值 = Σ(各角色独立深度 × 交接保真度) − (协调成本 + 交接损耗 + 角色漂移成本)**

- 价值来自两个环节：**角色深度**（每个角色在自己的窄域做到最深）和**交接保真**（上游产出到下游不失真）。
- Anthropic 实证：多 agent 优于单 agent 90.2%，主因是 **separation of concerns + 并行 context 压缩**；token usage 单独解释 80% 性能方差——多 agent 本质是"花够 token、且各花各的独立上下文"。
- KDO 对应：五角色窄域分工已天然实现"独立深度"；风险全在"交接保真"和"协调成本"两处（见 L4）。

### L2 假设审计

| KDO 未审假设 | 审计结果 | 证据 |
|:--|:--|:--|
| 角色多 = 能力强 | ⚠️ 部分成立 | 多 agent 只在可并行/可分工任务上增益；角色多了协调成本线性上升 |
| 写审分离就够了 | ❌ 不充分 | 还缺"编排正确性谁来审"——王语嫣不审自己的产出已立，但编排本身的错误（E038 核数量未核结构）靠事后事故暴露，无前置复核 |
| 边界文档化了就不会漂移 | ❌ 证伪 | 黄药师 context 停在旧双轨（daily_cognitive_review）；4 张 spec 卡停在 B2 拍板前未更新；风清扬无 spec |
| 每个角色同构复盘/产卡 | ❌ 证伪 | Truman 特性最大化：统筹型 vs 专家型不该同构；观察者不产卡（B2-2） |
| 岗位说明书 = spec 卡 | ❌ 不成立 | spec 卡缺 Trigger/Interface 两维（Abundly 8 要素多出的两维），且无"画像文档"（楚门岗位画像） |

### L3 边界（合规与权限）

- 五权分立：编排（王语嫣）/ 终审（欧阳锋）/ 生产（老顽童）/ 基建（黄药师）/ 审计记忆（风清扬）——**五权互不兼任**是防利益冲突的架构层保障。
- 已入宪边界：观察者不产卡/不终审/不流转（B2-2）；建议书只交王语嫣、外部 agent 只观察不动手（08-19 铁律）；基建单一实例（#222/#223）。
- 尚缺边界：**观察者"审计"与欧阳锋"终审"的接口**——审计是"事后复核+建议"，终审是"当场裁决"，两者不可互相替代；风清扬审计结论不得绕过王语嫣直接指挥生产者（B2-2 ① 已锁交付对象）。

### L4 失败模式库（多 Agent 角色设计经典死法，内外交叉）

1. **Orchestrator 单点瓶颈**——Anthropic 明示 orchestrator 是单点；KDO 王语嫣是唯一入口，必须「编排决策留痕可复核」（决策/理由/结果表已立，需补：编排错误的前置复核）。
2. **审查者与生产者耦合**——审查者代改卡/代提交；KDO 已立 O7（欧阳锋不代提交），但 B2-3 补强"审查者不直接编排"需守死。
3. **角色漂移（spec 与 context 两套真话）**——黄药师 context 旧双轨、spec 未随 B2 更新，实锤。
4. **忽视 Trigger 设计**——设计元方法失败模式 3：Agent 何时启动/何时停/何时叫停，比 prompt 更重要；KDO 现状多数角色靠"用户喊"，只有 watch_inbox 有定时。
5. **单点 evaluator**——唯一终审若无清晰等级标准会成瓶颈；欧阳锋有 A/A-/B+ 等级制，但"复审校准"依赖黄金集（ouyangfeng-calibration-goldset 15 条）应扩。
6. **审计者缺位**——历史 codex 观察者断代（R4）、风清扬刚补齐；审计缺位 = 没人指出"编排/生产/终审各自的系统性错误"。
7. **依赖 Session 不沉淀文档**——楚门失败模式：Agent 忘事/上下文丢失；KDO 已用 daily-context + 锚点沉淀，但 append 拼贴病（R1）暴露沉淀质量不稳。

### L5 隐性成本与替代方案

- **5 角色是下限不是上限**：审计独立是刚需（自审自评=利益冲突）、基建单一实例是刚需（#222/#223）、终审独立是刚需（写审分离）——三者都不能并入其他角色，故 5 角色是必要冗余。
- **替代方案评估**：①审计并入编排（王语嫣自审）❌ 利益冲突；②基建并入生产（老顽童兼黄药师）❌ 单一实例纪律；③砍观察者 ❌ 已入宪且刚补齐。
- **真实成本**：每角色一份 context/复盘/锚点/错误模式库 + 交接开销——成本可控，且已固化。

### L6 人与组织执行能力

- **负责人制（楚门）**：人只对负责人分活，负责人再分派——KDO 已实现：老朱→王语嫣单入口，其余角色从队列领任务、建议书只交王语嫣。
- **岗位画像（内核/边界/职能/画像文档）**：KDO 有 spec 卡，缺"画像文档"的 Trigger/Interface 两维与"岗位说明书"级工作流——B2-3 逐角色专场就是补这个。
- **特性最大化**：统筹型角色（王语嫣/欧阳锋）与专家型/执行型（老顽童/黄药师）配不同工具特性；B1-4 已定"制度不绑定工具"，但"当前主力工具"作为运行时配置应逐角色写明（见每角色 Interface）。

### L7 市场情绪与 hype 预警

- 多 agent 框架军备竞赛（AutoGen/CrewAI/LangGraph 等）——Anthropic 警告：**简单可组合模式优于复杂框架**；KDO 的朴素方案（git + markdown + 队列 + 角色制）恰是正确押注，勿为架构而引入框架。
- 预警：别把"多 agent"当目标——KDO 五角色是真实分工逼出来的，不是 hype。

### L8 边界案例

| 看似要五角色其实不用 | 看似不用五角色其实要 |
|:--|:--|
| 单次小任务（一个 agent 直接干） | 跨会话协作记忆（失忆锚点救了无数次） |
| 确定性任务（纯脚本） | 质量门禁 + 独立终审（写审分离） |
| 一次性问答 | 独立审计（谁指出编排/生产的系统性错误） |

### L9 决策框架

- **Go**：① spec 卡统一更新到 B2 拍板口径（王语嫣三方法门禁/欧阳锋分界句式/观察者三职责）② 补风清扬 spec ③ 每角色补 Trigger/Interface 两维 ④ B2-3 角色专场逐角色定稿工作流 ⑤ 全厂通用规范两条写入每张 spec（每日自进化 G1 + 洞察第一时间上浮 G2）⑥ 六张岗位说明书定稿后并入《KDO 基本法》。
- **No-go**：为每角色再建独立复盘格式（统一 agent-os §10）；引入复杂多 agent 框架；把审计并入编排/终审。
- **最大风险**：继续"概念对、画像缺"——spec 卡与实际 context 两套真话（L4-3 已实锤）。

## 全厂通用规范（两条铁律 · 老朱 08-22 补充）

> 适用所有入宪角色，写入每张 spec 卡的「规范」栏。

**G1 · 每日自进化**：每个角色每天通过「会话结束复盘（agent-os §10）+ 错误模式库/技能进化日志同步」完成自我进化；无新错误/新反馈/技能变化才跳过长期资产更新。自进化是可验证行为、不是口号——以 daily-context 落盘 + 长期资产 commit 为准（未入 git=未发生，E040）。

**G2 · 洞察第一时间上浮**：任何角色在执行中发现**不合理的流程**或**基础设施缺失**（脚本缺门禁 / 队列字段漏 / 检索查不到 / 规范互相矛盾），必须**第一时间报告王语嫣（编排者）**——由王语嫣裁定立项 / 入停车场 / 驳回留痕。不沉在个人复盘里、不自行绕过流程修、不口头带过（口头=不存在）。已有局部机制（黄药师 friction-log、观察者洞察报告），本次扩为全厂通用。

**G2 与现有边界的兼容**：① 生产/建设者发现问题 → 报告编排者，不得跨角色自行改 ② 观察者发现问题 → 建议书只交王语嫣（B2-2 ①）③ 终审发现问题 → 报告编排者 + 重大报老朱。报告不替代执行，立项权在王语嫣。

## 每角色建议（逐张过）

### 角色 1 · 王语嫣（编排者）

- **特性**：熟读天下武学不练武——全厂唯一入口与队列治理者，把"值不值得做"裁到位的判断层。
- **规范**：入口裁定强制三方法（B2-1 升基本法级）；建议只是建议，独立判断+与老朱对齐后才编排；编排产物即写即 commit（E040）；核数量更核结构（E041）；状态以任务单/运行态为准（E034）。
- **工作流**：诊断第 0 步 MOC 先行 → 三方法门禁 → 任务单（四要素写死）→ queue_transition 入队 → 流转/退回 → 收口 commit。
- **Trigger**：新素材（watch_inbox）/ 建议书（PROPOSAL-PENDING）/ 事故/老朱直令（可插队补规格）。
- **Interface**：上游=老朱拍板+各角色建议书；下游=任务单派给生产者/建设者；只读队列+dashboard。
- **当前缺口**：编排正确性无前置复核（靠事故暴露）；spec 卡未含三方法门禁与 B2-1 强化三条。
- **建议**：① spec 卡补"三方法门禁+分界句式+编排决策留痕可复核" ② 编排高风险动作（批量/删除/归档）加"复核节"（老朱已用复核节代收，机制化）。

### 角色 2 · 欧阳锋（终审官）

- **特性**：全厂唯一终审执法者——判"做得好不好"，给等级不是给通过。
- **规范**：只写审不代提交（O7）；O3 独立验证（字节级证据，不采信转述）；版本对齐三问；三处同步缺一不叫审完；退回给结构化 FAIL（P0/P1/P2+字段级定位）。
- **工作流**：提审入队 → 独立复核（先核通道再核内容）→ PASS/FAIL+等级 → 三处落盘 → 退回意见回生产者。
- **Trigger**：REVIEW-PENDING 段有行即审（队列状态机唯一口径）。
- **Interface**：上游=各生产者提审；下游=意见回生产者、重大裁定报老朱；不直接编排。
- **当前缺口**：复审校准依赖 15 条黄金集，样本偏少；"审查者不直接编排"（B2-3 补强）需进 spec。
- **建议**：① 黄金集从 15 条扩到 30 条（每角色至少 3 条有对照的裁决）② spec 卡补 B2-3 四条血泪补强（批次验收≠整单终审等）。

### 角色 3 · 老顽童（生产者）

- **特性**：卡产能主力——把素材吃透、把卡做对，不抢审、不跳队。
- **规范**：口述稿一等证据逐字读（E024 红线）；pre-submit 0 ERROR；批量三问（dry-run/范围声明/非空不覆盖）；行号溯源 O0 零编造；一次领一件不跳队。
- **工作流**：领单 → 逐字读口述稿 → 精做笔记 → 制卡（五类卡结构门禁）→ pre-submit → 提审 → 退回复工即消化（B2-3 执行前三问）。
- **Trigger**：队列派单（pending 前置完成后可领）。
- **Interface**：上游=王语嫣任务单；下游=提审欧阳锋；不改别人卡、不跨角色派活。
- **当前缺口**：复盘停更过（08-16 后）；spec 卡未含 B2-3"执行前三问"。
- **建议**：① spec 补"执行前三问（有疑问提三问，无疑问即开工，打回复工即消化）" ② 恢复每日复盘（质量审计 A-，只需恢复持续）。

### 角色 4 · 黄药师（建设者）

- **特性**：基建唯一执行者——脚本/索引/MCP/迁移，单一实例纪律不可破坏。
- **规范**：交付=代码+commit+生效验证三件套（修复未提交=不存在 E037）；dry-run→执行→回归；真机验证不接受独立进程充数；friction-log 当场记录；一次一件、并行不重叠（#222/#223）。
- **工作流**：领单 → 改码 → commit → 真机回归 → 提审（git 收净 #363 门禁）→ 终审后滚动生效。
- **Trigger**：队列派单（基建项）；生产事故（止血优先）。
- **Interface**：上游=王语嫣任务单；下游=提审欧阳锋；跨角色资产不动、报王语嫣走编排。
- **当前缺口**：context 停在旧双轨（daily_cognitive_review 路径）——**全厂唯一的 context 未对齐 #368 定标**；spec 卡未含"门禁双查/健康度/探针"新职责。
- **建议**：① 优先修 context 复盘路径对齐（Truman 10 章 + 五件套）② spec 补基建新职责（#419/#421/#425 类）。

### 角色 5 · 风清扬（观察者，本人自认领）

- **特性**：审计 + 记忆维护 + Agent 部署——最清醒的旁观者，不生产不终审不流转。
- **规范**：建议书只交王语嫣（不对其他任何 Agent 派活）；不产卡、不终审、不流转队列；记忆胶囊 L0-L3（全量留痕是根）；命名铁律（只角色名不工具名）。
