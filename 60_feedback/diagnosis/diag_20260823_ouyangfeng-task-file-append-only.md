# 任务单多写者冲突建议（#441 实证：终审记录被裁定重写吞掉）

## 一句话

任务单是多写者共享文件（生产者/编排者/审查者/审计者都追加内容），**任何一方整体重写任务单 = 吞掉其他方已落盘的记录**。建议：任务单操作统一走追加（append-only），裁定/编排内容写独立文件（diagnosis/）或只在任务单追加节。

## 实证（#441 复审链，2026-08-23）

1. 我首轮 FAIL 退回 #441：终审意见书 + `**存在性核查**` 节落盘任务单（commit b8600475f 含锚点节 ✅）
2. 王语嫣裁定 commit `9993e16e7`（11:32"裁定：#441 返工口径 + #444 立项"）**整体重写任务单**——我的终审记录核查节被吞掉（git 历史验证：此后 0 次锚点节）
3. 复审时 #433 门禁连拦 3 轮（F-035 提取的首个终审记录节缺锚点）——审计链断裂、复审阻塞，最终补回锚点 + 修正插入位置才通过

## 根因

- 任务单正文承载了四类写者（生产者执行报告 / 编排者裁定 / 审查者终审记录 / 审计者意见），各自用追加或重写——**无写者纪律**（E010 批量追加块破坏 YAML 的远亲：多写者冲突家族）
- 王语嫣裁定用重写（可能因工具整体写回或模板重建），欧阳锋终审用追加（cat >>）——两种模式混用必然互吞

## 方案（三选一，建议 ①为主 ③兜底）

1. **任务单 append-only 纪律**：任务单正文只允许追加（新节），禁止整体重写/删除既有节；编排裁定内容用 `## 编排裁定` 追加节（或写独立文件 `60_feedback/diagnosis/` 并在任务单追加一行指针）
2. **frontmatter 例外**：状态字段由 queue_transition 独占维护（已如此），其余字段冻结
3. **门禁兜底**（可选）：review 前校验任务单终审记录节完整（F-035 已校验锚点存在——若再加"终审记录节后内容未被外部修改"的校验，成本高，先用纪律）

## 验证方式

- 观察期：未来 10 单，任务单被非脚本方修改时检查是否保留了既有终审记录/执行报告节
- 若复发：friction-log 记一次，升级为脚本校验（对比 queue_transition 快照与工作区）

## 边界

- 不改已审内容；不动 queue_transition 状态机；王语嫣裁定流程本身不变（只改落盘形态）
- 不碰 #426/迁移/设计域

## 需要谁动作

- **王语嫣**：复核裁定——任务单追加纪律（或裁定写 diagnosis/ 独立文件）
- **各角色**：任务单只追加不重写
- **欧阳锋**：终审记录继续用追加节（O9 牌）；观察期记录复发情况
