# 泛产品设计域二次深挖诊断报告（v2）

## 执行摘要

泛产品设计域当前状态是**“骨架完整、血肉严重不足”**。顶层的 composite-concept、6 张中层 framework、33 张 `yt-panproduct-*`/`tool-泛产品落地-*` 叶子卡，以及产品内核域的 5 张 concept 卡、若干框架/工具/dk/case 卡已经搭出体系，但大量口述稿中的**操作细节、真实案例、出牌顺序、能力迁移路径、量化数字**尚未进入卡片。四张中层框架卡仍用 `src_unknown` 占位，19 张落地工具卡被 VLM 通用改写占据，产品内核三份主口述稿中 40%–50% 的案例细节未被吸收。

**两个最大风险**：
1. **Agent 调用会返回“正确但空洞”的建议**：现有叶子卡缺少具体招式和案例，Agent 无法给出可执行动作。
2. **同一概念出现多个版本**：如验证框架有“决定性/优化性/完备性”与“愿意用/愿意付/愿意推荐”两套三维度；迭代五方向有“进化/量化/细化/强化/简化”与“用户层/场景层/价值层/功能层/模式层”两套命名；泛产品卡牌数量有“30 张”与“36 张”之争。

**建议**：优先 P0 补完泛产品设计 4 张中层框架卡 + 产品内核 3 张核心 concept 卡 + 1 张六策略验证工具卡；P1 升级需求/审美/落地的核心叶子卡并补建 5–8 个口述案例卡；P2 替换落地工具卡的 VLM 通用内容，并新建出牌导航、需求可行性四字诀、能力迁移诊断、失败模式匹配等 Agent 规格。

## 三、泛产品设计域：可直接 Agent 化的环节

| # | Agent | 解决的问题 | 输入 | 输出 | 调用卡 | 边界风险 |

| 1 | 用户视角训练 Agent | 设计者用“我觉得好”替代“用户觉得好” | 用户画像 + 产品主题 | 设计视角 vs 用户视角两套清单 + ≥3 个反向假设 | `yt-panproduct-demand-user-perspective` | 无法替代真实访谈 |
