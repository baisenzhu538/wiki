# Skill 健康度勘察与检测方法论建议书

> **结论先行**：76 个已登记 skill 中，**🟢 健康仅 3 个（4%），🟡 亚健康 11 个（14%），🔴 不健康 62 个（82%）**。
> 核心病灶不是内容深度，而是**登记面系统性欠账**：72/76 无 manifest、无 trigger.natural_language、无来源卡适配（三写一致的「真相源」侧几乎全空）。
> 已挂载的 45 个 skill 平均健康分仅 3.0/8——**大量「挂了但路由不可用」的 skill 正在被 agent 引用**。

---

## 一、调研方法（按知识库调研方法论执行）

遵循 `research-core` 统一调研入口（OSCAR 意图路由 → 核心纪律 → 武器库按需载入）：

| 步骤 | 执行 |
|:--|:--|
| **O 目标** | 建立 skills 健康度检测方法论 + 对全厂已挂载 skills 摸底打分 |
| **S 范围** | `40_outputs/capabilities/skills/` 全部 76 个登记 skill（shared/ 76 = INDEX 登记面）+ 45 个挂载单元对照 |
| **C 清单** | 健康度维度（结构/路由/内容/挂载）、机械扫描 + 抽样精读双轨 |
| **A 获取** | kdo 语义检索 ×4 组 + 目录/矩阵/76 个 SKILL.md 机械扫描 + 关键卡全文精读 |
| **R 归因** | 打分依据 = darwin-skill 9 维 rubric（SkillLens 实证）+ skill-architecture-design 五维量化评价 + 项目健康度雷达 3 色信号，全部来自知识库内卡 |

**检测方法论来源（知识库内三源交叉）**：

1. **darwin-skill 9 维 rubric**（Microsoft SkillLens arXiv 2605.23899 实证）：LLM-as-judge 评估 skill 准确率仅 46.4%，加入 meta-skill 维度升至 73.8% → **健康度检测必须含「失败模式编码 + 反例黑名单 + 可执行具体性」维度**，且**绝对总分只用于 triage、keep/revert 必须 paired 比较**（±8 judge 噪音）。
2. **skill-architecture-design 五维量化评价**（#593 已行为化）：触发准确率 >90%、ZSAR 无修改采纳率 85%、工具调用效率、Token 节省率、自治治理等级——**路由面（description 触发）是健康度第一关**。
3. **项目健康度雷达 3 色信号**（yt-tool-project-health-radar）：6 维扫描 + 3 色信号判定 + 约束点追问，**「全黄灯 = 最危险模式」**——本库 62 个🔴正对应「所有维度都不行但没人发现」。

## 二、勘察发现（按严重度排序）

### 🔴 P0 登记面系统性欠账（路由不可用 = 挂了等于没挂）

## 三、健康度检测方法论建议（KDO 落地版，供后续例行审计使用）

### Skill Health Radar 八维检测（机械可测，5 分钟/个）

| 维度 | 检查项 | 数据来源 |
|:--|:--|:--|
| A 触发词可路由 | manifest.trigger.natural_language 非空 | manifest.yaml |
| B 描述信息量 | description ≥ 80 字符且含触发场景 | frontmatter |
| C 失败模式编码 | 正文含失败模式表/分支 | SKILL.md |
| D 边界与反例 | 有「不适用/不要做/反例」章节 | SKILL.md |
| E 来源可追溯 | adapted_from 有来源卡 | frontmatter |
| F 三写一致 | manifest.yaml 存在且挂载单元同步 | manifest + MOUNT-MATRIX |
| G 主文件克制 | ≤ 300 行（500 行护栏预警线） | 行数 |
| H 操作可执行 | 有编号步骤/操作流程 | SKILL.md |

**档位**：≥6/8 🟢 健康；4-5/8 🟡 亚健康（补短板即可）；≤3/8 🔴 不健康（路由/内容至少一项阻塞）。

**注意（darwin-skill 实证教训）**：
1. 本 8 维是**结构层 triage**，不能替代实测——效果层（dim8 实测表现 23/100）需 test-prompts 跑真实输出，按 darwin-skill 规则 dry_run > 30% 判失效
2. 绝对分数只用于「先改谁」排序，**keep/revert 一律 paired 同 judge 比较**（±8 噪音）
3. 建议补 test-prompts.json 后纳入例行扫描脚本（黄药师基建域）

### 例行频率建议
- **机械层**：随 #588 扫描脚本扩展（黄药师），每次刷新目录自动跑 8 维
- **精读层**：季度审计一次，抽 20% 已挂载 skill 精读 + 实测
- **变更触发**：任何挂载变更（P4）后必跑 A/F 两维
