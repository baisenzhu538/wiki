## 五、生产建议

### 5.1 老顽童补卡任务

1. **补充已有卡**：7-9 张已有卡（见第三节对照表），每张补充 1-3 条暗知识。
2. **新建 dk 卡**：4 张（见第四节）。
3. **合计**：约 11-13 个文件变更。

### 5.2 优先级

- **P0**：`dk-content-muscle-memory-vs-knowledge` + `framework-community-knowledge-production-failure-modes` 补充（社群运营是 Vikki 群的核心）。
- **P1**：`dk-founding-ip-trust-over-traffic` + `framework-brand-three-degree` 补充。
- **P2**：`dk-content-implicit-value-without-price` + `dk-community-lecturer-vs-crowd-model` + 其他已有卡补充。

### 5.3 验收标准

- 每条暗知识都有明确原文引用和说话人。
- 补充到已有卡时，必须说明它解决了该卡的哪个盲区。
- 新建 dk 卡必须包含：原始表述 → 使用场景 → 操作方法 → 适用边界 → 为什么值钱 → 与其他知识的关联。

## 六、SOP 雏形（试点成功后推广）

基于本次扫描，可形成「群聊暗知识补挖 SOP」：

1. **读原文**：必须读 `.md` 原始提炼稿，不能只看结构化笔记。
2. **一句话扫描**：逐段标注「让我停了一下的句子」。
3. **映射已有卡**：把每句话分到已有卡、待建新卡、噪声三类。
4. **识别缺口**：已有卡接不住的，才新建 dk 卡。
5. **反向补链**：补充后更新目标卡的 related，建立双向链接。
6. **自攻击检查**：用 `framework-kdo-self-attack` 检查每条暗知识是否被过度泛化。

## 七、试点方法边界与风险

### 7.1 方法边界

| 边界维度 | 本次试点的限定 | 超出限定需另开任务 |
|:---|:---|:---|
| 素材类型 | 仅限已结构化的群聊精华提炼（.md） | 未转录的语音、视频、直播口述需先做素材处理 |
| 挖掘方式 | 「一句话金矿扫描」+ 已有卡映射 | 若需新建 5 张以上 dk 卡，说明已有框架接不住，应回退到领域诊断 |
| 目标卡处理 | 4 张新 dk + 7-9 张已有卡补充 | 不覆盖原卡核心主张；不修改已 reviewed 卡片的正文 |
| 验证深度 | 依赖原文引用与说话人标注 | 涉及因果断言（如「A 导致 B」）需额外数据验证 |

### 7.2 4 张新 dk 卡的 When NOT to Use / 自攻击

| 新 dk 卡 ID | When NOT to Use | 自攻击要点 |
|:---|:---|:---|
| `dk-content-muscle-memory-vs-knowledge` | ① 需要把能力显式拆解成可执行 SOP 的培训场景；② 初学者尚未建立基础概念时直接套用心法；③ 用于判断「AI 能否替代某任务」但缺少足够案例样本时 | 风险：把「肌肉记忆」泛化为所有隐性能力，忽略可编码部分；把「难抽象」等同于「AI 做不了」，可能低估少样本提示/微调的效果；未区分身体技能与认知自动化 |
| `dk-founding-ip-trust-over-traffic` | ① 品牌冷启动阶段需要优先解决认知度而非信任；② 低客单价、冲动消费品类；③ 创始人人设与产品价值脱节、无法承担信任背书时 | 风险：把「信任>流量」当成绝对排序，忽视不同阶段权重；创始人 IP 若缺乏交付能力，追求信任会加速口碑崩塌；未区分「创始人 IP」与「网红」可能只是变现路径差异 |
| `dk-content-implicit-value-without-price` | ① 价格敏感型大众市场；② 法规/平台要求必须明示价格；③ 冷流量、低信任场景下缺少社会证明时 | 风险：暗示价值可能滑向信息不透明；若学员/方法/结果证据不实，会变成虚假宣传；高客单成交仍需后续价格沟通，不能无限期回避 |
| `dk-community-lecturer-vs-crowd-model` | ① 社区早期需要强互动和共同创造；② 讲师不可持续或无法保证输出质量；③ 期望通过群众中心模型获得稳定交付时 | 风险：二元对立可能掩盖「结构化框架 + 自由碰撞」的混合形态；群众中心模型对运营机制要求极高，误用会导致噪声淹没价值；讲师中心模型的扩展性依赖于讲师产能 |
