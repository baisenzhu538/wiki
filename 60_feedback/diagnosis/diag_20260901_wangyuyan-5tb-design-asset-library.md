# 5TB 设计素材库方案诊断

## 一、问题重述（目标层，人排）

- **素材**：设计师办公电脑（⚠️ 09-01 老朱确认：**另一台机器，非本机**），多分区多盘，~5TB，图片（jpg/png/psd/ai）+ 视频 + PPT + PDF
- **诉求**：全面索引 + 分类打标 + 检索调用；全交 agent 自动化跑，老朱无时间逐张看；消费侧反馈回路修正
- **部署架构**：方案 B（对方机器装最小节点），搬迁按 kdo-seed 三层切分——机制原样搬/机器绑定重建/内容不搬；交付文档=桌面《设计素材库建设方案-v1.0.md》
- **战略判断（半肥猫背书）**：素材是长期资产，以后都能用得上
- **真正的目标**（建议老朱确认）：不是"整理干净"，是"**设计师/AI 在 1 分钟内找到可复用素材**"——检索调用是目的，整理是手段

## 二、三个反直觉判断（本方案的地基）

1. **物理冻结原则**：5TB 存量不改名、不移动。改名=索引断链+PPT 引用死亡+不可逆。身份=SHA-256 哈希，位置=卷 UUID+相对路径，语义=元数据+XMP sidecar。VLM 识图✅，物理重命名❌（识别结果写元数据）
2. **命名法则是入口门禁不是存量方案**：月白七要素命名法（tool-asset-file-naming-convention）自证 >1 万文件文件名编码失效。存量走索引，增量（新素材入库）走七要素命名规范
3. **VLM 分层跑**：tagger（JoyTag 4GB 显存 9 张/秒）全量 + VLM（MiniMax/Qwen2.5-VL）只跑精选子集。人机边界（库内现成结论）：AI 标类型/场景/技术参数；**项目归属/来源/版权状态必须人工**

## 四、爆炸式调研五步法执行方案

### 第 1 步：目标（人排，半天）
- 锁定唯一目标：检索调用（不是整理癖）
- ROI 预判：5TB 全量机器时间约 1-2 周后台，人工集中在词表建模 2-3 天——成立
- 决策点：交付物形态 = catalog 工具 + 词表 + 检索接口（给 AI 用的 DataPack 层）

### 第 2 步：范围（人排，收缩边界）
- **不全量开工**。试点 = 一个分区 or 一个高价值素材类目（建议：图片素材先行，PPT/PDF 第二批，视频最后）
- 边界声明：PSD/AI 源文件只索引不解析内容层（第一层）；视频只抽关键帧

### 第 3 步：搜索⇄建模（循环，AI 70% + 人 30%）——核心
1. **全量盘点**（机器，1-2 天）：PowerShell/Python 扫全盘 → SQLite catalog（路径/卷 UUID/SHA-256/类型/尺寸/时间）→ 类型分布报告
2. **抽样建模循环**（这是爆炸式的精髓——不是凭空设计分类法）：
   - 随机抽 500 张图 → cap_hub.vlm（MiniMax）批量描述 → 归纳 facet 轴候选
   - 再抽 500 → 检查新样本是否推翻词表 → 推翻就修词表再来
   - **终止标准（12 字）：规律基本稳定体系**——新抽样不再产生新轴/新值
   - 产出：facet 词表 v1.0（预计 4-6 轴：主题/项目/资产类型/风格/色彩/用途）+ 受控词表每轴枚举值
3. **人排 30%**：词表终审（老朱+设计师）、项目/版权维度人工规则、top 渠道素材（花瓣/小红书收藏夹）优先入库

### 第 4 步：放量（机器为主，1-2 周后台）
- JoyTag/WD14 全量打标（有 8GB 显卡 10 万张约 3-5 小时；无显卡 STAG CPU 慢跑）
- 标签写 XMP/IPTC（ExifTool 批处理；PSD/AI/视频用 sidecar 不碰原文件）
- VLM 精选子集：每系列代表图+高价值目录走 MiniMax 深度描述
- PPT/PDF：Docling 抽文本层 + 每页渲染图走 VLM（PPT 信息大半在图片层，单通道必丢）
- 装载 Billfish 索引模式（免费，官方就是为多盘不动原文件设计）或 digiKam（UUID 架构，注意 Windows 超大库分批导入坑）
- **排除 Eagle**（导入即复制，5TB→10TB）

### 第 5 步：交付做厚（分层/讲香/DataPack）
- **分层**：catalog 工具层（人用 UI）/ 元数据层（XMP 随文件走，工具可换）/ 检索接口层（AI 用）
- **讲香**：素材库使用手册（设计师版一页纸 + AI 调用版）
- **DataPack**：素材索引 SQLite + 词表 yaml + 检索脚本——以后任何 Agent 可直接查询素材库
- **增量门禁**：新素材入库检查单（七要素命名 + 打标 + 入库登记）——不进门禁不进库

## 五、风险与边界（诚实声明）

1. 库内方法论验证上限 ~1 万文件级，5TB（估 10 万+ 文件）是新域——digiKam Windows 超大库有漏扫坑，分批导入+哈希对账兜底
2. VLM 打标准确率需试点期实测（抽样人核 100 张定合格率红线，建议 ≥85% 才放量）
3. MinerU 是 AGPL 协议，商用场景注意；Docling（Apache 2.0）是安全默认
4. 版权维度 AI 判不了——设计师素材的授权状态必须人工规则（如按来源目录继承）
5. Eagle 价格未官网核实（第三方 ¥199 买断），如考虑付费工具下单前核官网

## 八、消费侧反馈回路（2026-09-01 老朱追加：使用中修正，不逐张看）

**核心立场：老朱不需要逐张看图——机器先把全部素材标到 60-80 分，错误在使用中暴露，每次"这张不合适"都是一次定向修复+词表进化。**（半肥猫 60 分原则 + KDO 飞轮机制移植）

```
使用中老朱/设计师一句话："这张不合适" / "搜出来的不对"
        │
        ▼
  反馈记录（素材路径+查询词+问题类型，一行）
        │
        ▼
  归因三分类：① 这张标错了（修单条） ② 这类都标错了（修词表该轴） ③ 检索逻辑问题（修查询层）
        │
        ▼
  定向修复 → 回流词表/检索 → 下次更准
```

- **反馈入口做到零成本**：检索结果页/命令行里一个标记动作（如 `asset_query.py feedback <id> "不合适原因"`，或 Billfish 里打"待修"标签），使用场景里随手完成，不专门抽时间
- **周报制消化**：王语嫣值守拍定期汇总反馈 → 单条错立即修，同轴错误 ≥3 条触发词表修订（near-miss 升级机制同款）
- **质量爬坡曲线**：上线初期 60-80 分可用 → 每次消费反馈都在推高准确率 → 这比"上线前逐张审 10 万张"既现实又更快达到高质量
- **对应 KDO 原型**：一行双三角飞轮日志 + method-dialogue-driven-kb-evolution（热进化：使用反馈驱动系统进化）
