# 半肥猫标签模板优点提炼（源：开放麦《知识库搭建与落地》口述 L495-680，10_raw/sources/banfeimao-openmic/）

> JSON 模板文件全库未获（库内+桌面/下载/文档/D 盘四路已搜）——但口述里有模板完整方法论，提炼不受阻。若你手头有 JSON 原件，发我后做结构对照补全。

## 一、模板七层优点（逐条提炼）

| # | 优点 | 半肥猫原话要点 | KDO 对照 |
|:--|:--|:--|:--|
| 1 | **文档两段式**：标签段给 AI / 正文段给人 | 「人类一般不读标签段；AI 看前十几行就知道相不相关，不相关跳过——效率特别高」 | 我们 frontmatter 已是这个结构，但标签段内容质量参差（今天抽查实锤） |
| 2 | **标签九维内容** | 来源/主题/事实/经验/判断/案例/规则/适用场合/**禁用场合** | 我们缺「适用场合/禁用场合」两维——这是检索后能否直接用的关键 |
| 3 | **原子化拆分** | 「一个原子块只讲一件事，语义不能再分」（黄芪水例子：原理/适用人群/经济边界分开存） | 我们的卡常一卡多事——拆分颗粒度无标准 |
| 4 | **颗粒度=业务定** | 「没有固定标准，看对项目的理解」——颗粒度难不在打标签（机械），在知道标什么 | 与 data-labeling 报告原则 4（最小本体承诺）互证 |
| 5 | **多层标注**（核心优点） | 基础层（食材/克重/步骤，够用）→**专业层**（中医原理+西医营养+宜忌人群+热量算法）→**风控层**（平台映射词）→**受众话术层**（专家版/普通人版同文多表达）→**图片层**（连图片用途都标） | **我们只有基础层**——M16/M58 等新卡应示范多层 |
| 6 | **分库隔离+映射表桥接** | 大库混喂 AI「分不清楚」→拆专业库（流量库/专业库/人设库分开）→**映射表把库桥接**——「既专业又合规，还像真人说话，不被平台违规」 | KDO 域隔离（30_wiki 分域）已在做；**域间映射表没有**——bridge 卡是散的，没有系统性映射表 |
| 7 | **资产沉淀闭环** | 标注过的知识卡片/迭代文档/经验全部沉淀知识库（Cubox 管 20 万条） | KDO 同构（30_wiki+台账），已具备 |

## 二、金标准方案（合并版——报告五原则 × 半肥猫七优点 × 标杆卡样本）

**标签规范 v1.0（新卡执行）**：
1. 两段式（现状保持）+ 标签段九维自查（新增：适用场合/禁用场合两维）
2. 检索者视角选词（标杆卡纪律）+ MECE 不重叠（报告原则 2）
3. 每标签配一行语义描述（报告原则 5——embedding 靠描述不靠名字）
4. 高价值卡升级多层标注（半肥猫第 5 优点：专业层/风控层/话术层按需）
5. 原子化自查：一张卡只讲一件事（半肥猫第 3 优点）

**存量体检维度扩展**（原三查 → 五查）：空串残渣/万能词堆砌/来源名当标签 + **装饰性标签**（原则 1：不影响检索行为的删）+ **重叠标签对**（原则 2：MECE 冲突）

**分库映射表**（半肥猫第 6 优点落地）：30_wiki 域间系统性映射表立项（bridge 卡聚合为映射矩阵）——低优排队

## 二·五、YAML 模板原件挖获（老朱指认：10_raw/sources/banfeimao-openmic/标签示例.yaml）

**模板结构解剖**（「常见食物的份量换算」样例卡）：

**标签段（给 AI）**：title/type=knowledge_card/card_subtype=method/topic/source+source_type/author/created+updated/**quality_score: 9**/**permission_scope: public_material**/**status: ready_to_archive**/tags（4 个精准词：膳食指南/食物份量/量化/膳食设计）/**reuse_direction: 科普写作，膳食指导，食谱设计，Agent知识库**/review_required

**正文段（给人）**：一句话结论 → **适用场景**（含「Agent 回答 XX 时调用」！）→ 内容 → **可复用方式**（又一次「Agent 调用」）→ **注意事项**（生重熟重差异=边界 dk）→ 来源（**页码级锚** 335-341）→ 质量评分

### 超越我们现有规范的四个字段（提炼精华）

| 半肥猫字段 | 含义 | KDO 缺口 |
|:--|:--|:--|
| **reuse_direction** | 复用方向直写（含 Agent 调用场景） | 我们没有——卡说「这是什么」，不说「能拿去干什么」 |
| **适用场景+可复用方式双节** | 场景与复用分开写，两次点名「Agent 回答时调用」 | 我们的卡无此结构 |
| **quality_score 自评** | 9/10 量化自评 | 我们有 confidence 但无质量自评惯例 |
| **permission_scope + status 生命周期** | public_material / ready_to_archive | 我们有 status 但无 permission 维度 |

**结论**：半肥猫模板的内核=**「为 Agent 复用而写卡」**——从 reuse_direction 到「Agent 回答时调用」，整张卡的每个节都在回答「AI 怎么用我」。这与 data-labeling 报告原则 1（从下游决策倒推标签）完全同源，且给了可抄的字段级实现。

## 二·六、金标准方案 v1.1（最终版）

标签规范在 v1.0 基础上增补：**新卡 frontmatter 增加 reuse_direction 必填**；**正文增「适用场景/可复用方式/注意事项」三节骨架**（清单体）；quality_score 自评试行。执行同前（规范入 tags-vocab+存量体检批五查+新卡即日 v1.1）。
