## 二、核心词层：Agent 方法论（可复用到任何画布 Agent）

### 2.1 对话节奏

```
场景确认 → 自由输入 → 六要素归类 → 确认 → 排序减法 → 主挖角深挖 → 副挖角 → 贯穿约束标记 → 信心打分 → 保底策略 → 备忘录输出 → 里程碑计划
```

### 2.2 六要素状态标记体系

| 状态 | 含义 | 什么时候用 |
|:---|:---|:---|
| 已确认 | 信息充分，不需要本轮深挖 | 用户说得清楚的 |
| 有方向/待补 | 有线索但不够 | 用户提了但没展开 |
| 偏薄 | 信息明显不足 | 关键角但用户没提 |
| 已确认（偏薄弱） | 确认了现实约束——但这个角本身就是弱点 | 体系/数据是约束不是缺口 |
| 暂放 | 本轮不碰 | 创造力通常放后面 |

### 2.3 排序优先级框架

| 标签 | 含义 | 处理 |
|:---|:---|:---|
| 主挖角 | 最影响下一步动手的角 | 深挖，追问 3-5 轮 |
| 副挖角 | 影响结果质量但不阻塞动手 | 追问 1-2 轮 |
| 贯穿约束 | 现实已知条件，不影响本轮 | 标记，不深挖 |
| 暂放 | 后续迭代再议 | 记录，跳过 |

### 2.4 关键追问模式

| 场景 | 追问模板 |
|:---|:---|
| 用户提了方向但没细节 | "你心里有没有一个大概的X？哪怕只是很模糊的——第一步做什么、第二步做什么、怎么判断做完了" |
| 用户给出了方案但没验证标准 | "你怎么判断它做得对不对？如果AI说错了，你打算怎么发现？" |
| 用户提了多个AI交叉比对 | "当三个AI出现分歧时——A说X，B说Y，C说Z——你打算怎么裁决？" |
| 用户自认短板 | "假设这件事做完了，你拿到了一份产出——你怎么判断它算不算够用了？" |
| 用户给出了标准 | 追加升级："你刚才的标准是'我能验证'，要不要再往上拉一层——'其他AI能接手'？" |
| 深挖结束 | "这个角你觉得补得够不够？还是想再深挖一轮？" |
| 准备收束 | "0分完全没底，10分可以直接开跑——你现在大概是几分？" |
| 用户信心不足（≤5分） | 给保底策略：压到最小实践版本，只验证一个分支/一个AI/一个标准 |

### 2.5 画布版本管理

```
v0.1 → v0.1（更新）→ v0.1（更新·基本功角）→ v0.3 → v0.4
```

每次更新只改变化的部分，用表格标注"状态变化"（如 有方向/待补 → 已深度补充）。

### 2.6 备忘录输出结构

1. 场景一句话
2. 价值目标
3. 六角总览（状态+一句话摘要+下一步）
4. 六角详情
5. 本轮重点补充
6. 空白项与待补项
7. 当前实践信心
8. 保底通用策略
9. 下次继续挖的问题

## 三、Data Pack 层：本案例的具体数据（挂载到这个对话的上下文）

- 场景：10年代码库梳理，5G，.NET+Vue，智能医药
- 用户画像：不懂代码，有Agent体系+EC手册+20条铁律
- 审美标准：两层——真机验证 + 10项AI可接手资产包
- 工具组合：Claude Code/Codex/Kimi Agent集群/GLM 5.2
- 梳理路径：逐分支分析→出架构图→多AI交叉比对→多轮辩经收敛

## 四、对 KDO Agent 设计的直接启示

1. **画布Agent (#69) 的追问逻辑**：采纳"主挖角/副挖角/贯穿约束"三级优先级框架
2. **画布Agent 的状态标记**：采纳"已确认/有方向/偏薄/暂放"四态体系
3. **信心打分机制**：每轮深挖结束后用 0-10 分锚定用户真实状态
4. **保底策略**：信心不足时不硬推，压到最小实践版本
5. **里程碑计划生成**：从画布→可执行计划的自动转换（YAI Partner 的 M1-M6 模板）
6. **备忘录格式**：输出结构可复用到 canvas-agent.py 的最终输出
