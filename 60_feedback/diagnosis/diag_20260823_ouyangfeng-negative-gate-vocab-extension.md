# 负向判词门禁词表扩展建议（#433 后续演进）

## 一句话

把 #433 负向判词门禁的强词表从「存在性类」扩展到「数据异常类」（为空/空值/损坏/截断/乱码/半写）——让「字段为空/数据损坏」这类断言也必须带 `**存在性核查**` 锚点，堵住截断假象类误判。

## 背景实证

- **#434 终审截断假象**（2026-08-23）：我查 SQLite 用 `substr(payload_summary,1,90)` 截断视图，截断点落在 `grade=` 字段边界，误读为"grade 空值"、差点报成假缺陷——完整读取后确认四字段全有值。
- **根因分析**：审查者的采集错误不会自证——"找茬定势"把异常信号优先解释为内容缺陷，而非自己的工具制造了假象。已立「双假设原则」（O0 对偶：假设卡片撒谎，也假设读取撒谎）入启动口念，但纪律形态需要门禁兜底（#433 拦我 3 次后行为彻底改变=门禁有效实证）。
- **缺口**：#433 强词表 8 词（不存在/未备份/未同步/确认缺失/缺失/卡住/丢失/死锁）全是存在性类——"grade 为空"这类**数据异常断言不在词表**，今天不会被拦。

## 方案（两步，复用 #433 机制，非新体系）

1. **词表扩展**（黄药师，queue_transition.py 一行）：`NEGATIVE_CLAIM_STRONG += ["为空", "空值", "损坏", "截断", "乱码", "半写"]`
   - 效果：意见书断言"字段为空/数据损坏/被截断"→ 必须带 `**存在性核查**` 锚点 → 被迫附完整读取证据
   - #433 执行报告已声明"词表先小后大，误报进 friction 后扩表"——**扩表是 #433 设计的预期演进路径**，非新体系
2. **核查锚点规范升级**（王语嫣入审查 SOP，#433 三段式话术同批）：三段式加"**数据视图声明**"——完整读取 / 截断视图+截断点，二选一声明

## 验证方式

- 正测：构造含"grade 为空"断言的测试意见书 → 被拦（无核查锚点）
- 反测：同断言 + 核查锚点（含"SQLite 全列完整读取，无截断"）→ 通过
- 回归：pytest test_queue_transition.py 全过

## 边界

- 不改 #433 已审内容（词表扩展为演进维护，或另立 #433 后续单）
- 不判核查质量（F-034 同款原则不变）；"为空"若为真实断言（字段确实空），带核查锚点照常通过——门禁只强制举证，不预设结论
- 不碰 #426/迁移/设计域
