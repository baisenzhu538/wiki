# Builder 验证分层纪律建议书

## 一、触发

老朱 2026-08-23 问：「你的每次任务都跑狗粮测试吗？」——诚实自审后暴露：**验证有层次，"跑了"与"真了"是两件事**。本洞察建议固化进黄药师岗位说明书（spec）+ 执行报告模板，让验证纪律可审计而非靠自觉。

## 二、验证分层模型（核心洞察）

| 层 | 定义 | 覆盖 | 举例（今日） |
|:--|:--|:--|:--|
| **L1 单元/回归测试** | pytest 用例，逻辑层 | 100% 代码类任务 | 每单 4-5 新用例 |
| **L2 狗粮（真实场景全链路）** | 真实文件/命令走完整流程 | 代码类任务大部分 | #432 写入→镜像→模拟丢失→恢复→verify |
| **L3 活体（生产环境真实投递）** | 生产环境真实发生 | **少数** | #443 huangyaoshi 通道待下一张单；飞书通知（今天才真通） |

**三条铁律**：
1. **"跑了"≠"真了"**：#421 假成功事故——HTTP 200 被当发送成功，实际签名错误（code 19021）全部假发；外部 API 必须验业务码，用户确认才算数（P-15 同族再犯实证）
2. **模拟≠真实**：恢复演练用临时目录+模拟丢失，不等于真删 A 库；L3 未发生的必须显式标「待活体」，不假装全验过
3. **文档/治理类任务无狗粮概念**：用验证清单（grep 归零/枚举清零/exists 逐项）代替，两者不能混称

## 三、建议固化（写 spec 时可用）

1. **黄药师 spec 加「验证纪律」条款**：代码类任务三验（L1 单测 + L2 正反向狗粮 + L3 活体标注）；执行报告必须声明验证分层（L1/L2/L3 或「待活体」）
2. **执行报告模板加「验证分层」字段（值域四态：L1 / L2 / L3 / 待活体）**：
   - `L1` 单元/回归测试（pytest 逻辑层）
   - `L2` 狗粮全链路（真实场景走完整流程）
   - `L3` 活体（生产环境真实投递/发生）
   - `待活体` 显式声明（L3 尚未发生，禁止写成"已验证"）
   - 缺声明 = 审查时可追问（不硬拦，F-034 同款"只拦机械项"原则）
3. **"待活体"是合法状态**：不是缺陷，是诚实边界（#443 通道待投递、镜像计划任务待老朱确认）；禁止把"待活体"写成"已验证"
4. **外部依赖验证双保险**：API 类（飞书/webhook）成功必须验响应业务码 + 用户/消费者确认，两者缺一不算"真了"

> 补充（2026-08-23 老朱口径精确化）：第 2 条字段值域明确为 **L1/L2/L3/待活体 四态**——F-028 角色专场写黄药师岗位说明书时，验证分层字段即按此四态写入执行报告模板与 spec 条款。

## 四、依据实证

- #421 假成功事故（2026-08-23 修复：签名算法 + 业务码校验 + 用户确认）
