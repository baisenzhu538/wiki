# 老朱口述一等证据落盘纪律缺失（#448 实证）

## 问题（#448 终审发现，2026-08-23）

- **#448 老朱角色卡**：执行报告声称"六条口述 №1-№6 全织入"，卡 source_refs 引"#448 任务单老朱口述 №1-№6"——但**任务单仅含 №1-№4 原文**，№5/№6 只在 CLI 对话中给出、未转录入任何文件
- **一等证据断链**：口述稿=一等唯一主锚（charter §3.13 红线）——№5/№6 未落盘 = 未发生（E040），后续口径演进/复审/飞书端印证时无法溯源
- **风险**：老朱 CLI 纠偏是日常高频通道（双通道铁律：CLI=老朱↔agent 纠偏、文件=agent 间协作）——口述逐条落盘目前**靠执行者自觉转录**（本次只转了 4/6 条）——同类断链必然复发

## 根因

口述输入通道**无落盘纪律**：老朱口述到达（CLI 对话）→ 谁负责转录？转录入哪？以什么格式？——全无明文规则，靠会话内顺手。这正是 #460"治沉没"的对象（发现问题/重要输入不落盘=沉没），口述输入是同类问题的又一实例。

## 建议（两段）

### 1. #448 补录（立即可做）

- №5/№6 原文补录：建议王语嫣向老朱/王语嫣会话记录取回 №5/№6 原话（含时间戳），补入 `60_feedback/tasks/` 独立记录文件（#448 已 reviewed 冻结，按 #449 规范补录=新增件，`amends: D-20260823-002` 引用）或任务单追加节（若裁定上板冻结允许补证据节）
- 补录后卡 source_refs 指向更新（含 №5/№6 行号）

### 2. 口述落盘纪律（通道级，防复发）

- **规则**：老朱 CLI 口述（一等证据）到达即转录——接收 agent 会话内立即落盘（原话+时间戳+上下文），不隔夜
- **落点**：任务单「老朱口述输入」节（现行实践，规范化为必写）或 `20_memory/laozhu-dictations/` 独立目录（按日/按主题，与 zhu-time-os 衔接）
- **最小形态**：原话一行 + 时间戳即可（同 #460 最小建议书三行精神——详略是自由度不是门槛）
- **门禁可选**：口述类 source_refs 引用的编号（№N）必须能在落盘文件找到对应原文——#450 lint 可加检查项（与 doc_id/amends 同族）

## 需要谁动作

- **老顽童**：#448 后续若需重提（补录后）配合
