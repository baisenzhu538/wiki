## 2. 问题表征（Problem Representation）

### 2.1 用户原话摘要

> 知识库中已有"一堂"创业课程体系的 100+ 张卡，但缺少经典管理咨询方法论卡片。一堂体系本质是"创业版的麦肯锡方法"，两套体系之间存在天然桥接点但知识库尚未打通。

### 2.2 关键特征提取

| 维度 | 内容 |
|:-----|:-----|
| 主体 | KDO 知识库 30_wiki/ |
| 场景 | 用户（创业者/咨询者）查询问题时，可能匹配不到经典框架 |
| 目标 | 补齐经典框架卡，同时避免与一堂体系重复 |
| 障碍 | 两套体系表述不同但底层方法同源，容易重复建设 |
| 时间 | 中期 |
| 性质 | 知识库内容策略 + 跨体系桥接设计 |

### 2.3 问题表征句

> KDO 知识库在创业方法论（一堂体系）和经典管理咨询方法论之间存在**语义桥接缺口**：用户描述的问题可能同时被两套语言描述，但知识库只覆盖了其中一套，导致框架匹配失败。

## 5. 框架匹配与盲区暴露

### 5.1 命中框架

| 框架/卡ID | 匹配理由 | 提供的视角 |
|:----------|:---------|:----------|
| `concept-mckinsey-mece` | 一堂预判模型分类需要 MECE 原则 | 维度选择时的盲区检查 |
| `concept-mckinsey-issue-tree` | 一堂五步法的"充分做加法"对应 Issue Tree | 问题拆解工具 |
| `concept-mckinsey-hypothesis-driven` | 一堂关键假设验证与之同源 | 假设驱动工作流 |
| `concept-minto-pyramid-principle` | 产品内核三问精神一致 | 结构化沟通 |
| `concept-maister-trusted-advisor` | 王语嫣角色定位的理论支撑 | 可信顾问而非搜索引擎 |
| `yt-entrepreneur-five-step-method` | 已有一堂主框架 | 桥接靶点 |

### 5.2 用户盲区 / Gap

1. **混淆了"知识缺失"和"可达性缺失"**：很多问题不是一堂没讲，而是没用到用户搜索的关键词。
2. **缺少桥接式卡片的标准格式**：如何写"这是麦肯锡概念，这是对应的一堂概念"没有模板。
3. **攻击者设计不足**：经典框架卡如果只讲优点，会变成一堂体系的对立物而非补充。
4. **没有区分用户场景**：创业者、咨询者、王语嫣对同一张卡的需求不同。
5. **低估了维护成本**：桥接关系需要随一堂课程更新而更新。

## 6. 关键洞察

1. **真正的问题不是"缺 8 张卡"，而是"缺一种桥接式知识设计"**。KDO 不应该变成麦肯锡教材的中文版，而应该成为"创业者用得上、咨询者查得到"的双语词典。
2. **桥接式卡片的核心字段是"对应关系"和"使用信号"**：不是告诉用户 MECE 是什么，而是告诉用户"当你在一堂课程中看到'维度选择'时，你其实在用 MECE"。
3. **应优先补对王语嫣诊断能力有直接支撑的卡**：MECE、Issue Tree、Hypothesis-Driven、5 Whys 是最小可行集。
4. **攻击者设计是桥接式卡片的护城河**：没有攻击者的经典框架卡只是维基百科条目，有了攻击者才与一堂体系形成对话。
