# DataPack 调研对齐稿

## 一、DataPack 到底是什么（三源收敛）

| 源 | 定义 |
|:--|:--|
| 课程口径（宣讲会 L378-384，金矿 B43） | 「可调用的**数据包**，结构化、AI 读起来友好，**它不是 Skill——里面没有太多规则**。AI 需要做一个事时把这个包加载上，上下文补充完了，表现全面上升」；「Markdown、结构化、易调用、相对完整」 |
| 官方任务 #5（L964-968） | 「你不愿意删的 DataPack——可能是设计宪章、关键文档、方法论模型、一堂课抽出来的东西，你会**经常调它**」 |
| 库内一手实证（case-live258 冷邮件复盘，L2621-2647） | 「真正有价值的 DataPack 应包括：**客户原话/问过的问题/拒绝原因/哪些邮件能发出去/哪些标题被拦截/哪类客户更容易回复/报价后卡在哪里**——AI 没有这些数据，就只能靠通用经验」 |

**我的综合理解**：DataPack = **给 AI 的领域弹药库**——把「这个领域里真实发生过的数据、金标准样本、踩坑案例、判断对照」结构化打包。Skill 教 AI「怎么做的步骤」，DataPack 给 AI「依据什么判断」。加载 DataPack 的瞬间，AI 从「通用经验」升级为「有真实弹药的领域专家」——这就是你说的「瞬间理解并使用」的机制。

## 二、和 Skill 的分工（关键：不是二选一，是分层配合）

| | Skill | DataPack |
|:--|:--|:--|
| 装什么 | **程序性知识**：步骤/规则/边界/检查清单 | **陈述性知识**：金标准样本/真实案例/对照数据/踩坑实录/反例 |
| 回答 | 「怎么做」 | 「依据什么做、做到什么程度算好」 |
| 形态 | SKILL.md（指令性） | 结构化 Markdown/JSON（资料性） |
| 类比 | 菜谱 | 食材+成品对照图+失败品照片 |

**YAI 的系统提示词/Skill/DataPack 三层**：系统提示词=身份与行为规则（固定），Skill=按需调用的步骤，DataPack=按问题类型挂载的弹药（可更换）——同一个 agent 解决不同问题挂不同 DataPack。

## 三、你的两个提案：方向对，形态要拆成两层

### 提案 1：洪七公识图（✅ 采纳，拆两层）
- **Skill**：《识图工作流》——步骤（图像预处理→OCR→VLM 描述→置信标注→交付格式）+ 边界（何时人工复核）+ 踩坑应对规则（从「操作手册」升格为「规则」的部分）
- **DataPack**：《识图金标准库》——金标准样本（正确 OCR/VLM 输出对照）、踩坑案例实录（模糊图/表格图/手写体的失败样本与原因）、置信度判定对照表
- **配合方式**：Skill 里写「输出后对照金标准库自检」——其他 agent 挂上 DataPack 就知道「好的识别长什么样」

### 提案 2：段王爷网络登录内容（✅ 采纳，同构拆两层）
- **Skill**：《登录内容处理工作流》（抓取→解析→清洗→结构化）
- **DataPack**：《登录内容样本库》（典型页面解析对照/反爬失败案例/字段抽取金标准）
