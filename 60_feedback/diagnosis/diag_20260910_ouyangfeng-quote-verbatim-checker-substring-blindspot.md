## 现象（三级标注）

【实证】#684 R2 复审：六卡 `kdo pre-submit` QUOTE_VERBATIM 全部 0 issues 的同时，审查侧独立全量锚点扫描（`_tmp/of684_anchor_scan.py`）捕获 2 处伪逐字引文（tianli 卡 L177）：

| 卡内引文（标 L1099） | 源 L1099 实文 | 缺陷 |
|:--|:--|:--|
| 「这个 AI 不懂政府培训」 | 是不是这个AI不懂政府培训？ | 删「是不是」——且恰因子串关系（引文=源句去头子串）被放行 |
| 「该换专门工具」 | 我是不是该用专门做教育的AI工具？ | 换词（用→换）+删限定+压缩，五字组合全文件 0 命中，仍被放行 |

【实证】同卡 L72「难怪方案被退回，我…」（源为「——」，卡改「，」）标点替换同样放行。

【推断】放行机制：子串匹配（引文是源句子串即通过）+ 相似度阈值（短引文换词后仍过线）——检查器源码在 kdo 安装侧未逐行核实，机制定性待黄药师确认。

## 影响

1. 「检查器 0 issues」≠「伪逐字 0」——上轮 #684 FAIL C 的 32 处是重改写（子串不成立）被抓住，本轮轻摘录/换词（子串或近邻成立）溜过。同一缺陷类两种命运，全取决于改写幅度。
2. 工厂口径（evidence_task654-presubmit：`声称逐字的引文在 source_refs 源文件中未逐字命中`）要求的是**逐字命中**，与检查器实际容差不一致——口径与工具脱节。
3. 依赖检查器做唯一防线的工作流（pre-submit 附提审、L1 机械门禁）对该缺陷类失防。

## 建议方向（供黄药师评估，审而不改）

1. **短引文最小长度**：低于 N 字（建议 8-10 字）的引文不做子串放行，要求整行级命中或直接转人工/转审。
2. **子串放行加最短超出量**：引文命中源句但删去源句 ≥K 字（如「是不是」3 字）时降级 WARNING 提示「摘录式引文，人工核对」，不静默 PASS。
3. **换词检测**：子串不命中时启用字符级对齐（difflib SequenceMatcher），相似度 0.6-0.9 区间（既非逐字也非重写）报 WARNING「疑似换词摘录」。
4. **标点归一显式化**：若设计上容许标点归一（——/，），在检查器文档与输出中声明；否则纳入比对。
5. **短期兜底（不动检查器）**：审查侧对「伪逐字」类退回任务复审时，一律附独立锚点扫描（方法：提取「引文+（Lnnn）」对→归一化→逐条回源比对，样例 `_tmp/of684_anchor_scan.py`），不采信检查器 0 issues 单证。
