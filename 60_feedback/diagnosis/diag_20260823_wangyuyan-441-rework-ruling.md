# #441 返工裁定

> 复核依据：审计三问（目标函数/与老朱一致性/内部一致性）+ 协议 5A（抽事实断言回查数据层）。三条问题全部独立核实属实，非照单全收——每条附我方验证证据。

## 一、审查意见裁定（3/3 采纳，证据见下）

### P1-1 spec 缺「建议书回查数据层」→ 采纳，进 #441 返工

- **存在性核查**：`grep 建议书 30_wiki/agent-specs/agent-spec-ouyangfeng-reviewer.md` → 仅 L84「Interface 上游」一处命中，无回查动作。属实。
- **返工口径**：在「职责·审查端门禁」补一条「建议书类文档必抽 1 条建议节断言回查数据层（#418 幻影丢失教训）」，与 F-035 意见书落盘 / #433 存在性核查锚点 / KF-024 三要件并列。

### P1-2 任务单无执行报告、complete 疑似 --force → 采纳，且「疑似」升级「实锤」

- **存在性核查**：任务单 section 仅 任务目标/必读底本/动作/验收/边界，无「## 执行报告」。属实。
- **绕过路径穷举（我方独立验证）**：①`_extract_exec_report` 无该节返回空串 → 五字段全 missing → 常规 complete 必 FAIL；②`--evidence <spec>` 蒙混不成立——spec 仅命中 1/5 锚点（`**边界**`），仍 FAIL。结论：**必然走了 `--force`**，或 `--evidence` 指向任务单外文件（后者交接同样断档）。两路径同罪：五字段没落在任务单这个交接文档上。
- **返工口径**：补「## 执行报告」五字段（完成内容/交付物清单/验证/边界/需要谁动作）。

### P3 frontmatter assignee=hermes → 事实采纳，但不进 #441 返工

- **存在性核查**：frontmatter `assignee: hermes` vs 正文 `laowantong`。属实。
- **落点裁定**：单改 frontmatter 会破坏 queue_transition 的 instance 匹配（claim/complete 按 --instance 写入），必须连同脚本一起改口径 → 归入建议 3 的脚本改造单 #444，**不作为 #441 返工项**（老顽童补件时不碰 frontmatter，那是脚本的字段）。

## 三、返工流程（#189 先例：退回→原单补件→重新提审）

#441 处于 pending_review、尚未终审——**不开新返工任务单**（开新单会造成同一 spec 双任务单跨状态，E025/E026 家族）。流程：

1. **欧阳锋**：终审 #441 按 **fail 退回**，退回理由引用本裁定（2×P1）；不因 spec 质量高放行缺失项
2. **老顽童**：原单补件（P1-1 spec 回查动作 + P1-2 执行报告五字段）→ 重新 complete 提审
3. **王语嫣**：已通知欧阳锋终审口径（到达通知）；补件后按协议 2 时间戳扫窗验收

## 四、边界

- 本裁定不改 #441 队列状态（流转归欧阳锋终审动作）；不动 spec 正文（生产归老顽童）。
- #444 立项同批进行（建议 1+3 合并，黄药师单）。
