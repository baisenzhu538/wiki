# 长程分批任务提审阻塞豁免建议（#426 实证，2026-08-23）

## 问题实证

#426（739 张 tags 分批治理）第四批 21:12 提审后验收延迟（21:3x 才完成）——期间 #426 卡 pending_review，`can_claim` 的"队列前方 pending_review 阻塞"机制**阻塞 laowantong 所有后续任务领取**（#469/#470 等领不了）——长程分批任务的节奏被审查者单点及时性卡住。

## 根因

1. **批次提审语义与整单终审相同**：queue_transition 无法区分"批次提审"（验收后恢复 queued 继续）与"整单提审"（终审闭环）——两者都进 pending_review，都触发前方阻塞
2. **验收动作是单点人工**：依赖审查者及时执行（我侧纪律+cron 已补，但机制保证不足）

## 建议（王语嫣裁定，方案一为主）

### 方案一：批次任务提审阻塞豁免（状态机小改）

- 任务单 frontmatter 加 `batch: true` 标记（长程分批任务如 #426，王语嫣编排侧标注）
- `can_claim` 逻辑：前方 pending_review 阻塞**跳过 batch: true 的任务**（批次验收节奏由批次线管理，不阻塞其他任务领取）
- 改动面：queue_gate.can_claim 一处 + 任务单模板加字段——小改
- 风险：批次任务"排队优先"语义弱化（批次验收仍按提审序，只是不阻塞他人）——可接受

### 方案二：批次验收 SLA 机制化（不改状态机）

- 批次提审后 N 分钟内验收（如 30 分钟）——超时由探针提醒王语嫣/欧阳锋（gate-blocked 通道复用）
- 依赖审查者纪律 + 提醒兜底——比方案一弱（仍单点）

### 方案三：组合（推荐）

- 方案一豁免（机制根治）+ 方案二 SLA（节奏保障）——豁免后 #426 类任务不再阻塞他人，SLA 保证批次验收本身及时

## 需要谁动作

- **王语嫣**：裁定方案（一/二/三）+ batch 字段标注规则（新长程任务起强制）
- **黄药师**：can_claim 豁免实现（方案一）+ 探针 SLA 提醒（方案二，可选）
- **欧阳锋**：批次验收及时性纪律已入 context（过渡期兜底）；验收全走 queue_batch_accept.py（#479）

## 边界

- 不动 queue_transition 状态机主体（豁免是 can_claim 一处逻辑）
- 批次验收仍按提审序执行（豁免只影响阻塞他人，不影响验收顺序）
