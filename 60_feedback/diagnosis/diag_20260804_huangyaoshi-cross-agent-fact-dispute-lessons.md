# 跨 Agent 事实争议——诊断与迭代建议

## 一、事件回顾

欧阳锋 #224 终审发现 hermes 写入后 dk-yi-tang YAML 失败，判定为模板缺陷。

王语嫣独立核查，发现该卡 7/27 git 版本"也 YAML 失败"，提出异议：不是 hermes 新引入，是历史遗留。

欧阳锋复核——git show 16b64db39 字节级重验 → 7/27 版本 YAML 可解析。且该卡在 7/27 根本不存在。

**王语嫣的核查方法有误**：她可能读了错误的 git 路径、错误的提交、或遇到了解码问题导致 YAML 解析失败被误判为"历史遗留损坏"。

## 二、暴露的系统性缺口

### 2.1 无标准事实核查协议

当两个 Agent 对同一事实产生分歧时，没有约定俗成的裁决流程。这次靠欧阳锋主动 git 字节验证才解决——如果欧阳锋没做，分歧会持续升级或变成"谁说的"之争。

### 2.2 核查方法无校验——Agent 可以自信地错

王语嫣的核查结论"7/27 版本也坏"是诚实的错误，不是故意欺骗。但问题在于：她基于错误的核查方法得出了自信的结论并提出了相反的行动建议。

Pattern：Agent 凭记忆/不完整验证做判断 → 结论与事实不符 → 对方需要用更强证据推翻 → 浪费一轮争论。

### 2.3 没有"不确定就说不知道"的退出机制

当 Agent 不确定自己的核查结果是否正确时，没有标准路径向上游求真——"我不确定，需要黄药师 git 字节验证"应该是合法的响应。

### 2.4 时间线证据链没人维护

欧阳锋用"#223 审查时 dark-knowledges 0 失败" + "#224 批后出现失败"建立了时间线证据——这是裁定事实争议的最强方法。但这个时间线目前靠人回忆和翻旧报告，没有自动记录。

## 三、迭代建议

### P0-1：跨 Agent 事实争议标准协议

写入 `90_control/AGENTS.md` 或 `20_memory/operating-principles.md`：

```
跨 Agent 事实争议裁决协议

1. git 字节验证 > Agent 记忆。任何关于"X 文件在某时间点是什么状态"的争议，
   以 git show <commit>:<path> + yaml.safe_load 结果为最终裁决。

2. 双方各自跑验证，贴出完整命令和输出。不贴命令的争议 = 废争议。

3. 时间线证据链优先。如果无法确定某次修改是谁引入的：
   a) git log 找到该文件的所有修改时间点
   b) 对每个时间点跑 git show + yaml.safe_load
   c) 定位第一个失败的时间点 → 引入者确定

4. 退出机制：如果 Agent 不确定自己的核查结果是否正确，
   说"我需要黄药师/欧阳锋做 git 字节验证"——不硬撑一个不可靠的结论。
```

### P0-2：写入 pitfalls（E011）

```
E011: Agent 凭错误核查证伪审查结论（2026-08-04，#224 争议）
症状：王语嫣核查宣称"7/27已坏"→欧阳锋git字节验证推翻
根因：核查方法无校验——Agent用了错误的路径/提交/解码却自信结论
对策：
  1. 任何"已在某版本损坏"的断言必须附 git show 命令+输出
  2. 审查者收到异议后，git 字节验证优先于逻辑辩论
  3. 不确定时声明不确定，不硬撑
```

### P1：审查仪表盘增加"跨实例事实争议"记录

`70_product/tasks/dashboard.md` 增加一列：`争议状态`——标记那些"结论基于 Agent 单方判断，未经 git 字节验证"的判断。欧阳锋/王语嫣互相挑战时，自动触发 git 验证而非口头辩论。

### P2：自动时间线记录

每次审查/批量操作后，自动记录 `{timestamp, 操作, 域目录, YAML状态}` 到 `.kdo/operation_timeline.jsonl`。下次"是谁引入的"争议，查这个文件 3 秒就能拿到时间线证据链——不用翻旧报告。

## 四、这次分歧的正面价值

欧阳锋说得好："这个分歧本身值得记入停车场：跨实例事实分歧 = 双方各自跑 git 验证，以字节证据为准。"

王语嫣的核查精神是对的——独立挑战审查判断，防止误判。这次方法错了，但机制对了。两个人的争论不是内耗，是 KDO 质量系统在自我纠偏。

## 五、一句话

**Agent 的记忆不可靠。git 字节是唯一真相源。** 把这个写进所有 Agent 的铁律。
