## 四、9层深挖

### L1 业务公式
无限画布演示 = f(素材理解+空间规划, 媒体准备, HTML构建+QA) → 单文件HTML，空间即逻辑

### L2 核心假设
- 假设1：空间关系可以承载逻辑关系（聚簇=内容块，嵌套=层级，路径=时序）
- 假设2：确定性脚本闸门守住机械规则，独立Agent守住语义/观感，两层防线互补
- 假设3：人类可编辑的纯文本大纲（Roam）→确定性重建HTML，比直接改HTML更可维护

### L3 边界
- 适用：内容有空间结构（总分/层级/时间线/对比/循环）的演示
- 不适用：纯线性逐页幻灯（用reveal.js/PPT即可）、无空间逻辑的内容
- 关键判据：用户要"一张画布上镜头运动"还是"一页页翻"？

### L4 失败模式

| 卡点 | 表现 | 根因 |
|:--|:--|:--|
| 等距平铺无聚簇 | 所有场景排一排，空间没承载逻辑 | 没执行聚簇优先四原则 |
| 伪嵌套 | 场景摆高低但镜头从未钻入图形内部 | 父子scale比<3或子坐标未落在父包围盒 |
| 横图看不清 | 左文右图，横图只占取景框一小块 | 缺imgfocus步 |
| 构建者自审放行 | 自己写的HTML自己审 | 违反信任红线 |

### L5 跨课程同构映射

**核心发现：本skill的工程化方法论与KDO自身的质量控制体系完全同构。**

| 无限画布Prezi | KDO已有体系 | 同构深度 |
|:--|:--|:--|
| 空间即逻辑 | 案例打磨·故事线选择（空间结构=叙事逻辑） | 不同域的同构：空间/叙事都是"结构承载意义" |
| 三步流水线(Plan→Media→Build) | 四字诀「拆建推练」 | Plan=拆+建, Media=建, Build=推+练 |
| 四道机械闸门 | kdo pre-submit / kdo lint | 同构：确定性脚本守住机械规则 |
| 七维独立终审 | 欧阳锋审查方法论v2.0 | **完全同构**：独立审查+多维检查+禁止自审 |
| 信任红线(构建者禁自审) | 欧阳锋"审而不改" | **完全同构**：审查与构建必须分离 |
| Roam大纲双向产线 | Skill双格式桥接(CC↔Hermes) | 同构：人类可编辑源↔机器产出，双向同步 |
| 降级铁律(2-3次失败→降级) | 调研先行"30分钟无果→标存疑" | 同构：时间盒约束，完整交付>单点完美 |

### L6 信息可信度
- 正文为一等证据：完整教程含代码/命令/实战产物截图
- VLM报告为二等证据：洪七公逐图识别，交叉验证了正文
- 外部验证：Prezi原生方法论从设计哲学角度佐证了"空间叙事"的有效性

### L7 反例
- "等距平铺=看不出谁和谁一伙"→空间没承载逻辑
- "纯y平铺+远景hub≠嵌套"→伪装成层级

### L8 行动框架
1. 判断适用性（空间逻辑 vs 线性翻页）
2. 按三步流水线执行，每步落盘JSON
3. 每步过闸门脚本，rc≠0修复
4. 独立子Agent跑七维终审
5. 交付：单文件HTML + roam.md + update.sh

### L9 决策框架
- **Go**：内容有空间结构、需单文件HTML、要非线性叙事
- **No-Go**：纯线性翻页PPT、无空间逻辑的内容
- **最大风险**：构建者跳过独立终审自审放行
- **最小验证**：全景图能否读出聚簇结构和逻辑关系

## 五、暗知识捕捞

| 暗知识 | 类型 | 原文锚点 |
|:--|:--|:--|
| 空间即逻辑——画布的位置关系=内容的逻辑关系，不能只看空间读出一条线 | 核心哲学 | §3 |
| 构建者禁止手写或修改review.json——只能由独立子Agent产出 | 信任红线 | §6 |
| 按时交付完整演示 > 单个素材的完美——2-3次失败立即降级 | 降级铁律 | §2 |
| 真嵌套≠平铺+远景hub——必须scale比≥3、子坐标在父包围盒内、有钻入+退回 | 边界条件 | §3 |
| 横图必须加imgfocus步——否则占取景框一小块必然看不清 | 操作心法 | §4 |
| 禁止用"结构说明图/目录页"剧透——结构靠镜头运动自然涌现 | 设计原则 | §3 |
| Roam大纲的价值：HTML难手改→让纯文本成为人类可编辑的源 | 架构决策 | §5 |
