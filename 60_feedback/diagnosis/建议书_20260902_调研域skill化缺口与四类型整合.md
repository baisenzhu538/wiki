# 调研域 Skill 化缺口与四类型整合建议书

> **结论先行**：知识库调研域 90+ 张卡已形成完整方法论体系（四类型认知框架→OSCAR/五步法等执行方法→90+ 工具技巧），**但 skill 化严重不均**：系统式已通过 research-core 全员覆盖，**爆炸式调研完全无 skill、挖掘式只有工具无流程、四类型判定逻辑未行为化**——这三块缺口正是「全 Agent 按调研目的选方法」能力落地的真空。建议王语嫣立项让生产者深度挖掘补位，Skills 助理验收后挂载。

---

## 一、勘察结论：四种调研类型知识库已有完整出处

知识库内四种调研分类的权威来源 = `framework-yitang-four-research-types`（四类调研模型，低置信度标注待审但为域内总卡）+ `framework-yitang-research-radar`（四象限：深/高/宽/动态）：

| 调研类型 | 维度 | 核心追求 | 适用场景 | 对应方法体系（知识库卡） |
|:--|:--|:--|:--|:--|
| **挖掘式调研** | 深·挖 | 关键情报水下、单点信息极重要 | 尽调、竞对核心数据、单点验证 | 穷尽手段 5 层（公开→半公开→专家→逆向→社会工程）+ 单点狙击三步法 |
| **系统式调研** | 高·准 | 复杂决策、多维度整合 | 行业/公司/市场系统分析 | OSCAR 五步法（O 目标→S 范围→C 清单→A 获取→R 归因） |
| **爆炸式调研** | 宽·全 | 新领域进入、快速建认知 | 新赛道、学新领域、案例建模 | 五步法（目标→范围→搜索⇄建模→终止→交付）+ 饱和覆盖 |
| **自动式调研** | 动态·稳 | 长期跟踪、竞争监控 | 竞对盯梢、政策跟踪、趋势判断 | CI 四阶段循环 + 监控预警 + 持续跟踪 |

> 老朱记忆中的「动态调研」= 自动式调研（雷达图"动态"维度）。四种调研 = 深/高/宽/动态 四维定位，可组合分阶段（爆炸→系统→自动，挖掘按需插入）。

## 二、缺陷与短板（按严重度排序，建议立项方向）

### 🔴 短板 1：爆炸式调研完全无 skill——最成熟的方法论却是真空

- 知识库已有：`framework-baozhashidiaochan-five-step`（五步法，欧阳锋已审，含失败模式表/When NOT/Action Triggers）、`framework-r-type-research-partner-five-state`（五状态机）、饱和覆盖/开一篇文档/借假修真等概念卡、多个实证案例（设计原则 90 条/OPC 128 方向/Leo 润滑油等）
- **甚至有已部署的 Agent**：`research-explosion-partner`（#335 SPEC 终审 PASS A-、#348 部署）——TCPR 身份+五状态机+饱和自证话术
- **但没有沉淀为 skill**（shared/ 无任何爆炸式/饱和式 skill）
- **缺口性质**：五步法是"给人类的方法论课程"，Agent SPEC 是"给特定 agent 的岗位说明"——中间缺一个"任何 agent 遇到新领域/案例建模任务→自动按五步法执行"的通用 skill
- **判定**：符合 SPEC §三触发（欧阳锋终审出口已建议行为化的体系 + 复用频次高），Go

### 🔴 短板 2：挖掘式只有工具无流程——穷尽手段五层卡未行为化

- 已有：`tool-yitang-research-exhaust-means`（穷尽手段 5 层+手段选择矩阵）、`tool-yitang-research-single-point-sniper`（单点狙击）、social-engineering 系列卡、OSINT 工具链卡（osint/dorking/media-verification/web-scraping）
- skill 层只有**工具类**（research-osint/google-dorking/media-verification/web-scraping 均为"某渠道怎么用"），**无"该不该上挖掘式 + 手段从哪层开始 + 何时升级"的方法流程 skill**
- **缺口性质**：agent 面对"竞品核心成本是多少"这类单点关键情报，不知道要穷尽手段、不知道手段分层升级逻辑、不知道合规边界
- **判定**：Go（工具已有 4 个，缺的是流程编排层）

### 🟡 短板 3：四类型判定/路由逻辑未行为化——全 Agent 按目的选方法的"大脑"缺失

- `framework-yitang-four-research-types` 卡是**认知参考**（介绍四类型是什么、何时用哪种），不是**执行入口**（给我任务→判定该用哪类→走哪条流程）
- 诊断信号表（"这个信息太重要了必须拿到"→挖掘式；"决策太复杂"→系统式；"完全不了解"→爆炸式；"需要长期跟踪"→自动式）是判定逻辑的现成素材，但散在卡内未变成可执行路由
- **#594 research-core 第一层现状**：OSCAR 意图路由按**任务形态**分类（查证/行业/竞品/深挖/情报），不是按**四类型维度**（深/高/宽/动态）分类——两者互补，但四类型判定缺失导致 agent 拿到"新领域快速认知"任务时不知道该走爆炸式五步法（现有路由直接指向行业报告武器，跳过饱和建模）

### 🟡 短板 4：自动式（CI/监控）行为化边界需谨慎

- 已有 `research-ci-framework` skill（CI 情报四阶段 Define→Gather→Analyze→Implement）+ `research-sats`（Signposts 指标）
- 但自动式本质是**长期运行机制**（cron/机器人推送/持续订阅），非单次可执行流程——纯 SKILL.md 难自包含
- **建议**：CI 框架保持现有 skill 不动；只把"何时该启用自动式 + 监控怎么搭（对象/源/阈值/推送/复核闭环）"行为化进四类型判定层，不另造 CI 执行 skill

## 三、整合建议（供编排层/生产者参考）

### 核心判断：不建议另起炉灶造第 18 个独立 skill

- `research-core` 已是全 Agent 统一调研入口（#594 终审 A，21 挂载单元全员覆盖），再加平级入口会**路由分裂**（#594 刚做完 17→1 整合，反向操作是开倒车）
- 推荐结构（对齐 #594 三层）：
  - **第一层升级**：research-core 的 OSCAR 意图路由前加"四类型判定"——按四类型模型把任务分型（深/高/宽/动态），路由到对应方法线（挖掘→穷尽手段流程；系统→OSCAR 武器库；爆炸→爆炸式五步法 skill；自动→CI 框架）
  - **补 2 个缺位 skill**：`research-explosion-five-step`（爆炸式，行为化自五步法+R 型状态机，可参照已部署 agent 的 SPEC）+ `research-digging-approach`（挖掘式穷尽手段流程）
  - **判定层自包含**：四类型诊断信号表 + When NOT 写进 research-core 第一层（最小自包含，不必先读子卡）

### 生产边界建议（防撞车）

- 与 #594/#595/#597 错峰：等 research-core 相关收口后再动第一层
- 不重写 30_wiki 卡（老顽童产卡域）；skill 生产走欧阳锋终审出口
- 爆炸式 skill 参照先例：`skill-architecture-design`（#593 U2 行为化样板——有 manifest/触发词/失败模式/边界）
