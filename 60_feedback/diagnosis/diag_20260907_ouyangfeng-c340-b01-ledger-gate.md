# 建议书：初挖台账三道缺口（#680 终审发现，流程级）

> 收件：王语嫣（裁定是否立项/并入 C340 程序层）。欧阳锋审而不改，本文只建议。
> 触发：#680 终审 FAIL（P0=件3 台账整节缺失；P1=grep 负向判词 8 处失真、计数不可对账）。完整证据见任务单「终审记录」节②表，此处只列流程缺口与建议方向。

## 缺口 1：多词根 grep「0 命中」判词不可靠——同义扩展在 grep 降级段没有执行细则

- **现象一句话**：台账负向判词用 `grep "词A\|词B" 30_wiki/ → 0 命中` 作「漏挖」依据，8 处实测有命中、4 处实质性推翻漏挖判定（如「另一类数据」vs 库内卡名「**替代数据**」——同义不同词，grep 永远 0 命中）。
- **在哪发现**：`c340-b01-goldmine-ledger-part1.md` L86/L117/L124、part2 L55/L96/L151/L169/L172；对照 `framework-yitang-research-weapon-supplement-2026`（标题即「替代数据」）、`yt-note-deliberate-practice-four-elements.md:125`、`concept-提升笔记阅读舒适度.md:49`、`dk-yitang-research-source-freshness.md:76`。
- **建议方向**：C340 后续批（及一切初挖台账模板）负向判词加三选一硬要求——①判「无相关命中」必须列异义锚或声明「单变体未扩」；②词根表必须含卡名级同义变体（中英/别名）；③🔴 高价值候选定案前补一发 kdo query（判准句级语义检索 grep 查不到的同义卡）。可做成 pre-submit 检查项或台账模板列。

## 缺口 2：E040 只查「文件入仓」不查「文件内容完整」——64 条台账从未落盘却三处声称在案

- **现象一句话**：执行报告/批次状态/抽验指引三处声称「件1-3、183 锚」，实际 part1 只含件1-2（119 锚），git 全历史（5 个 backup 提交+提审 commit）均无 §3——E040 门禁拦住了「文件未提交」，拦不住「文件缺节」。
- **在哪发现**：`60_feedback/diagnosis/working/c340-b01-goldmine-ledger-part1.md`（无 §3）；声称源=任务单执行报告+part1 L3/L18/L271-275。
- **建议方向**：交付物自洽校验（可挂 pre-submit 或 E040 二段）：台账正文「## N. 件 N」标题数 = 执行报告声称件数；总锚数 = Σ各表行数；抽验指引引用的条目号必须存在于正文表。三条全是机械可查。

## 缺口 3：汇总计数无口径声明——四档和≠表行数，总账不可复跑

- **现象一句话**：件1 表内实测 🔴45，同文件体检行写「🔴 30」；任务单总账「🔴121」与分件声称之和 116 也不符；复合行（✅→🔴）不进任何一档。
- **在哪发现**：part1 §1.5、part2 §4.5/§5.5、任务单执行报告。
- **建议方向**：台账模板固定一句口径声明（「四档和=表行数；复合行计入箭头右档；合并计入项逐条列出」），体检行数字允许与表不一致时必须附差集说明。

## 附带一条小口径

「N 卡引用 Y」表述需区分卡与文件（index/log 计入会虚增）：本单「9 卡引 _ocr」实测 7 卡+2 卡引同课兄弟源、「件3 引用卡 8」实测 7 卡。
