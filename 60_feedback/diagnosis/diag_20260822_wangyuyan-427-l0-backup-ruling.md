## 四、裁定点（给老朱拍板的精确口径）

1. **A 本机 git 外主库**：批准。路径建议 `C:\Users\Administrator\.kdo-memory\L0\`，只放 L0 SQLite/WAL，不进 git。
2. **B 第二盘镜像**：批准。路径建议 `D:\KDO-memory\L0-backup\`，用 `robocopy /MIR` 做 30min 后置镜像；恢复路径按建议书场景 1/场景 3 月检执行。
3. **C 云端冷备**：缓议。原因：默认云同步本地路径未验证存在；飞书云盘不是可直接 `robocopy/zip` 的本地路径。待云盘客户端/同步目录/凭据路径确定后再补 C。
4. **责任边界**：风清扬建 L0/备份脚本与恢复 verify；黄药师只负责计划任务/常驻持久化注册且需老朱授权；两者不抢活。
5. **登记要求**：拍板后备份路径写入 `memory-registry.md` 表 1（与 Hermes 记忆/失忆恢复锚点同级），不藏在脚本注释里。

## 五、为什么不直接 A+B+C

C 的今天不可执行性高于收益：云端冷备的价值是抗本机双损，但没有已验证同步目录与凭据路径前，写进方案只是"看起来更安全"。先把 B 做实，比把 C 写空更诚实。
