# L1 取消每日整份快照

> 触发：老朱 08-24 指令「每天一份整份快照必须取消」。
> 定位：观察者审计建议（只交王语嫣）。实施归黄药师；本建议把 #491 任务2 从「中期可分期」收紧为「硬性实施项」。

## 0. 结论

`l1_capture.py` 的「每天一个日期目录、全量复制当天源文件」设计必须取消，改为**日增量**（仅落盘有变化的文件）；每日整份快照不再产生。#491 任务2 已覆盖方向，但原文把「日全量改周日全量+日增量」列为中期可分期——本建议将其收紧为硬性。

## 1. 实测证据（非转述）

1. 代码：`kdo-tools/l1_capture.py` `capture()` 写 `L1_ROOT / today / tool`；`dest` 不存在即 `shutil.copy2`——新一天目录对全库都是「不存在」，等于整份重拷；mtime 去重只在同一天目录内生效，跨天不去重。
2. 数据：`90_control/l1-size.log` 00:07 由 766.6 MB 跳 1533.6 MB（+767 MB），与新日期目录 `D:\KDO-memory\L1-full\2026-08-24`（00:07:14 建）时间吻合。
3. 速率：日增约 770 MB；5000 MB 红线约 5 天触达（#471 只告警不停）。

## 2. 老朱指令（08-24）

「每天一份整份快照必须取消」。即：不再按天生成整份全量目录；改日增量 + 周全量兜底（兜底保留 L1 全量日志语义）。

## 3. 落地要求（黄药师，经王语嫣编排）

1. `l1_capture.py`：取消 `L1_ROOT / today / tool` 的按日整份目录结构。
2. 改日增量：仅当源文件 mtime/大小/hash 变化才落盘；未变文件不重复复制、不重复计体积。
3. 周全量兜底：每周一次全量基线（校验与灾备用），非每天。
4. 保留 L1 语义：L1 = 全量上下文原始日志。日增量不能滑成「只留当前态、丢历史版本」；需 append-only 版本化或「日增量 + trace.md 索引」保证可回溯。
5. 与 #489 同文件（l1_capture.py），注意合并顺序——建议 #489 先落或同轮合并（黄药师判断）。

## 4. 拍板生效边界（沿用 F-048 教训）

本建议 = 老朱对风清扬的指令 + 风清扬审计建议。若王语嫣需把「取消每日整份快照」按**老朱拍板**直接采信，请老朱直达编排层确认一句（F-048 先例）；否则王语嫣按审计建议独立裁定。
