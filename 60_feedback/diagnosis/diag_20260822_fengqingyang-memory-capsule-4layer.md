# KDO 记忆胶囊四层架构建议

> 学习输入：老朱 08-22 提供的《建设者工作成果_记忆胶囊与方法论与基建_2026-08-21.md》（巨米归档库四角色治理链）。
> **关键认知（老朱 08-22 纠正）**：巨米体系**没有审计者角色**，记忆胶囊功能由**建设者**承担。KDO 中该功能已入宪归**观察者（风清扬）**——B2-2 ②「记忆维护：时间胶囊+记忆胶囊及摘要/洞察」。故：记忆胶囊建设是**观察者本职建设**，不是黄药师基建脚本。
> 定位：观察者的记忆胶囊建设方案（可写记忆工具脚本，不产 KB 卡、不终审、不派活）。

## 0. 一句话结论

KDO 记忆现状是 **L3 最强、L0 最缺、L1 有瑕、L2 刚起步**。王语嫣 08-22 重启失忆、过程层找不回，是 **L0 全量留痕缺失**的实锤。修复由**观察者承担建设**（对标巨米建设者）：把 L0 补上、L1 定上界、L2 机制化、L3 保持，消费端做成每次会话自动注入的「胶囊精华段」。

## 1. 学习输入：巨米建设者如何承担记忆胶囊

**角色事实**：巨米四角色（编排者/审查者/生产者/建设者）无审计者，记忆胶囊 L0-L3 全链由**建设者**建、跑、消费。

| 层 | 定义 | 巨米建设者实现 |
|:--|:--|:--|
| L0 原始事件流 | 全量留痕，不删，审计用 | `activity_log.db`（建设者建） |
| L1 胶囊摘要 | 事件加权：高价值全保留、低价值仅计数，输出设**确定上界** | `memory_capsule.py`（#185 建设者落地） |
| L2 洞察提炼 | 自动提炼周期模式/教训/delta，带溯源锚点 | 建设者待建（缓议） |
| L3 方法论沉淀 | 洞察转正 → 案例（审查链 + 用户拍板） | 建设者起草 + 用户拍板 |

**建设者视角的三个工程细节（学习重点）**：
- L1 加权细则：narrative/decision/review_rejected 全保留；review_passed/task_completed 截断 Top 20；backlog/suspended 仅计数。179 事件 → 30 行 + 计数段。
- 消费端上界：`session_boot ⑥ 胶囊精华段` **≤1KB**，每次会话自动注入。
- 自动化链：L0 30min cron → L1 2h cron → 消费端 session_boot 注入；**长窗口优先**修互踩（短窗口胶囊 inactive 入库不踩长窗口激活位）。

## 5. 记忆维护职责升级（风清扬自我认领，建设者式）

- 从「维护锚点 + 诊断报告」升级为「**KDO 记忆胶囊建设者**」：
  - L0：建并跑全量留痕（断流检查每周）；
  - L1：建并跑胶囊摘要（≤1KB 上界、加权、治拼贴）；
  - L2：生产洞察报告（周度，消费全量上下文）；
  - L3：把可转正教训提交转正链，不自行转正。
- 可写记忆工具脚本（属记忆维护本职，非 KB 产卡）；不碰门禁/队列/看板基建（黄药师域）。
