# 王语嫣诊断记录模板 v3

> 每次诊断结束后，将关键过程沉淀为一条诊断记录。
> 本模板基于 WYY-Diagnosis 工作流：准备 → 问题表征 → 假设清单 → 诊断性追问 → 框架匹配 → 记录反馈。
> 经过 3 次实战诊断（KDO 反馈入口 / 外部知识库对标优先级 / 一堂-麦肯锡桥接）迭代而来。
>
> **使用说明**：
> - **完整版**：用于重要诊断、跨域问题、需要多人协作审查的场景，保留全部 10 节。
> - **轻量版**：用于 15 分钟内的快速诊断，可只保留 0-6 节，省略 7-9 节。

## 1. 准备：诊断前的元问题

在开始追问前，先确认以下问题是否已回答：

- [ ] 用户要做什么决策？（诊断必须服务于决策）
- [ ] 用户已经知道什么？（避免重复提问）
- [ ] 用户愿意被挑战到什么程度？（决定追问锋利度）
- [ ] 时间窗口有多紧？（决定诊断深度）
- [ ] 这个问题是否需要先调研？（判断 WYY-Research 调用层级）

## 附录：v2 → v3 迭代说明

基于 2026-06-13 三次实战诊断（`diag_20260613_kdo_feedback_entry`、`diag_20260613_kdo_wiki_benchmark_priorities`、`diag_20260613_yitang_mckinsey_bridge`）发现的问题：

| v2 问题 | v3 改进 |
|:--------|:--------|
| "诊断性追问"表格对基于素材的诊断不友好 | 拆分为 4.1（对话式 Q&A）和 4.2（基于素材的应追问问题） |
| 关键特征提取表格过宽，填写负担重 | 精简为核心 4 维 |
| 假设清单缺少"证伪条件" | 新增"证伪条件"列，避免确认偏误 |
| 缺少与 WYY-Research 的衔接 | 新增第 7 节"调研衔接" |
| 失败模式 6 项过多，容易流于形式 | 精简为 4 个核心项，并增加"如何修正" |
| 缺少置信度标注 | 在 0. 基础信息中增加"置信度"字段 |
| 缺少沉淀判断 | 在元反思中增加"是否值得沉淀为 skill/case" |
