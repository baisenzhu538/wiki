# 诊断记录：咨询者能力体系与经典商业框架缺口

## 用户问题

用户要求全网调研以下内容：
1. 如何做咨询（管理咨询的方法论与实战框架）
2. 作为咨询者的自我修养和段位
3. 咨询者需要哪些技能和 Skill
4. 咨询者的自我进化路径

## 诊断追问

本次任务性质为"知识库缺口调研"而非"商业问题诊断"，用户已给出明确调研指令。未执行标准诊断追问，改为直接检索知识库 + 全网调研。

检索发现：知识库中已有"一堂"创业课程体系的 100+ 张卡（含预判模型、关键假设验证、充分做加法/减法等），但**缺少经典管理咨询方法论卡片**。一堂体系本质是"创业版的麦肯锡方法"，两套体系之间存在天然桥接点但知识库尚未打通。

## 命中框架

| 框架 | 匹配理由 | 提供的视角 |
|:-----|:---------|:----------|
| `yt-foresight-model-taxonomy` | 预判模型分类的维度选择逻辑，与 MECE 互文 | 终局预判时的结构化拆解 |

## 关键判断

1. **两套体系可以桥接**：一堂的创业方法论与麦肯锡经典咨询框架并非互斥，而是"同一棵技能树的不同分支"。知识库的增量价值不在于"再讲一遍 MECE"，而在于**标注桥接点**——让创业者知道什么时候该用一堂卡、什么时候该用麦肯锡框架。

2. **王语嫣自身的诊断能力也需要这些框架支撑**：当前知识库中 `diagnostic_signals` 仅在 1 张卡（终局光谱图）上试点。如果要提升诊断匹配精度，需要更多带 `diagnostic_signals` 的框架卡。MECE / Issue Tree / 5 Whys 等天然适合承载诊断信号。

3. **Trusted Advisor 模型直接关联 KDO 知识工厂的信任机制**：王语嫣作为诊断咨询者，其角色定位（"可信顾问"而非"搜索引擎"）与 Maister 的 Trusted Advisor 理论高度一致，可作为角色 SOP 的底层支撑框架。

## 盲区 / Gap

### 概念缺口（8 张卡）

本次调研识别出知识库中**该有但还没有**的经典商业框架，建议老顽童补卡：

| 建议卡名 | 类型 | 来源 | 关联已有卡片 | Gap 说明 |
|:---------|:-----|:-----|:-------------|:---------|
| `concept-mckinsey-mece` | framework | McKinsey | `yt-foresight-model-taxonomy`（维度选择） | 预判模型分类的维度拆分需要 MECE，但知识库无此卡 |
| `concept-mckinsey-issue-tree` | tool | McKinsey | `yt-entrepreneur-five-step-method`（充分做加法） | 选项池拆解的底层工具是 Issue Tree，知识库有做法无工具 |
| `concept-mckinsey-hypothesis-driven` | method | McKinsey | `yt-entrepreneur-key-hypotheses`（关键假设验证） | 一堂有"关键假设"概念，但缺少假设驱动工作流的系统卡片 |
| `concept-minto-pyramid-principle` | framework | Barbara Minto | `yt-product-kernel-three-questions`（结论先行） | 产品内核三问的精神与 Pyramid Principle 一致，但无结构化沟通框架卡 |
| `concept-mckinsey-7s-framework` | framework | McKinsey | 一堂"创业修炼地图"组织维度 | 7-S 提供组织诊断的完整维度，可用于诊断创业团队能力缺口 |
| `concept-toyota-5-whys` | tool | 丰田生产系统 | `yt-product-kernel-three-questions`（根因追问） | 产品内核验证需要根因分析工具，5 Whys 是最轻量级的 |
| `concept-maister-trusted-advisor` | framework | Maister 等 | 王语嫣角色 SOP | 王语嫣"可信顾问"定位缺少理论支撑卡，可直接引用 |
| `concept-pareto-8020` | principle | Pareto | 一堂各卡的优先级判断 | 80/20 频繁被各卡隐性使用，但无独立概念卡，溯源链断 |

### 诊断基础设施缺口

- `diagnostic_signals` 仅 1 张卡试点，系统性不足。以上 8 张卡中至少有 5 张（MECE、Issue Tree、Hypothesis-Driven、5 Whys、7-S）天然适合承载 `diagnostic_signals`，可作为第二批试点。

## 反馈建议

### 给老顽童的卡片加工建议

1. **优先顺序**：建议按 `MECE → Issue Tree → Hypothesis-Driven → Pyramid Principle → 5 Whys → 7-S → Trusted Advisor → 80/20` 排序。前 4 张是麦肯锡最核心的思维基础设施，后 4 张是应用场景更具体的工具/框架。

2. **每张卡的 Bridge 节必须写**：区别于"重新讲一遍麦肯锡教材"，每张卡需要明确标注"与一堂体系的桥接点"。例如 MECE 卡要写出："一堂的 `yt-foresight-model-taxonomy` 在选择预判维度时，隐含使用了 MECE 原则——但一堂课程未显式命名它。当你在做终局预判时，检查你的维度列表是否 MECE，是避免盲区的重要步骤。"

3. **来源处理**：这 8 个概念来自经典英文商业文献（*The McKinsey Way* / *The McKinsey Mind* / *The Pyramid Principle* 等），不是口述稿素材。`source_refs` 应引用书籍/作者，而非 inbox 文件。

4. **攻击者设计**：每张 tool/framework 卡需要 ≥2 位外部攻击者、不同范式、有紧迫感。建议攻击者池：
   - **Kahneman**（认知偏差/系统1-2）
   - **Taleb**（黑天鹅/非线性/脆弱性）
   - **Christensen**（颠覆式创新/过度分析陷阱）
   - **Mintzberg**（战略即实践/反对过度结构化）
   - **Eric Ries**（精益创业/快速实验 vs 完美分析）

### 给欧阳锋的审查建议

- 以上 8 张卡与一堂体系的桥接关系是否正确，需要你对两套体系都有理解后确认。
- 建议先批准 1-2 张（如 MECE + Issue Tree）作为试点，验证"桥接式卡片"的格式是否成立，再批量生产剩余 6 张。
