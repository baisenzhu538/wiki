# 审查结果推送链缺口诊断（#498 误报事件触发）

## 事件实证（2026-08-25 01:27 前后）

欧阳锋 01:0x 完成 #487/#498/#505/#506 终审 → 探针 01:27 检出并落王语嫣 inbox（`90_control/todos/wangyuyan.md` 末行实证："⚖️ KDO 已终审 4 单：#487, #498, #505, #506"）→ **王语嫣未读 inbox 即对老朱答"#498 没审"**——误报。机制正常工作（inbox 落盘即时，不受夜间静默压制），消费侧未读。

## 链路盘点（实测 conveyor_probe.py 主流程）

| 事件 | 现通知对象 | 缺口 |
|:--|:--|:--|
| new_failback（FAIL 退回） | 按 assignee 路由生产者 ✅ | 无 |
| new_review（新提审） | 欧阳锋 ✅ | 夜间静默压制 |
| **new_reviewed（PASS）** | **仅王语嫣** | **🔴 生产者（老顽童/黄药师）收不到"我过了"** |
| 通知通道 | 飞书 webhook + CLI inbox 双通道（#501） | 飞书夜间 22-08 静默；inbox 即时但 CLI 角色靠自觉读 |

## 根因

1. **PASS 路由缺失**：`new_reviewed` 只组 messages["wangyuyan"]（#462 当时治的是编排者盲区）——生产者 PASS 感知无通道，只能等王语嫣转达或自己查队列
2. **夜间静默一刀切**：终审完成信号被压到 08:00——老朱夜间工作时段（近三日实证高频）结果不可见
3. **CLI 消费侧靠自觉**：inbox 即时落盘但无强制读取点——王语嫣误报事件证明"落盘 ≠ 被读"

## 建议方向（R1-R3，王语嫣裁定）

- **R1 PASS 路由生产者**（核心，小改）：`new_reviewed` 按队列行 assignee 路由通知生产者（复用 #443 failback 同款 ASSIGNEE_ROLE 路由），王语嫣抄送保留——"你的单过了/等级 X"直达老顽童/黄药师
- **R2 夜间静默分级**：终审完成（PASS/FAIL）信号豁免飞书静默（或设白名单），其余信号（可领取/建议书）维持静默——**✅ 老朱 08-25 已拍板：终审完成类信号豁免静默**（原话"豁免"）；施工时终审完成两路（生产者 PASS 路由 + 王语嫣抄送 + 欧阳锋提审叫醒）均豁免，其余信号维持 22-08 静默
- **R3 CLI 角色 inbox 必读纪律**：王语嫣/欧阳锋 CLI 启动 SOP 加"读自己 inbox 未读段"动作（机制 #501 已在，缺执行纪律）——进 agent-os 修订窗口

## 边界

- R1 复用既有路由与幂等机制，不引新通道；R2 豁免范围老朱已拍板（终审完成类豁免，其余维持）；R3 纪律条文进修订窗口不在本建议书施工
