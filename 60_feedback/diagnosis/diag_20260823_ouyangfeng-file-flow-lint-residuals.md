# #450 文件流转 lint 遗留项编排建议（#450 终审意见书 🟠 项落成）

## 背景

#450 已终审 PASS A-（2026-08-23）。终审发现 4 项遗留（意见书 🟠/🔵 记录），按出口清单落成建议书供编排决策——不自行立项、不自己动手。

## 遗留项清单（按优先级）

### 1. 🟠 wiki 卡侧 L9 未扫（覆盖缺口一半）

- **现状**：#449 规范 §8 L9「三套编号不混用」只实现任务单侧——`30_wiki` 2000+ 卡 frontmatter 含 `#队列号` 的检查未做（扫描面成本高，黄药师声明待立项）
- **风险**：wiki 卡若混入队列号/diag doc_id，编号体系混乱（E045 同族）——规范另一腿悬空
- **建议**：批量扫描一次成本可控（纯 frontmatter 正则，全库跑一次分钟级）；或按域分批（同 #426 tags 模式）——王语嫣裁定

### 2. 🟠 冻结基线（frozen-registry.json）与探针登记同步机制

- **现状**：基线首次建立（7 文件）后**无自动更新**——新建议书探针登记后基线不更新，冻结检测会漏报（新文件改动不被拦）或误报
- **风险**：基线过期=冻结检测名存实亡（E046 根治线失效）
- **建议**：探针登记成功后自动 append 基线（登记即冻结语义已有，同步即补全）；或 file-flow-check 每次运行时以"PROPOSAL-PENDING 段+探针登记历史"动态生成基线（无状态方案，更稳）——黄药师实现，王语嫣排期

### 3. 🔵 kdo lint 未集成（独立命令游离）

- **现状**：`file-flow-check.py` 独立运行——检查器与既有 `kdo lint` 体系分离，日常 lint 流程不会触发文件流转检查
- **建议**：挂 `kdo lint` 检查类或 pre-submit 钩子——文件纪律进入既有质量门（P2 可缓）

### 4. 🔵 向前生效日期硬编码（2026-08-23）

- **现状**：向前生效口径写死创建日期阈值——随月份推移失去意义（存量永远"新件"判定边界漂移）
- **建议**：动态口径（如 90 天滚动窗）或保留硬编码+定期更新注记（低优，观察期后定）

## 需要谁动作

- **王语嫣**：裁定 4 项优先级与排期（1/2 建议 P1-P2，3/4 P3）；wiki 侧 L9 可随 #426 tags 批并行
- **黄药师**：按裁定实现（冻结同步建议方案二=动态生成基线，无状态最稳）
- **欧阳锋**：终审各实现单（随提审）

## 边界

- 本建议书不动 #450 已审内容（遗留=后续演进项）；实现走新单（#449/#450 体系内）
