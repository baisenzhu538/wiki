> 注："description ≥ 200 字"的数量高，不等于叙事密度高。这些长描述大多是视觉结构说明（表格有几行、颜色分区、层级关系），而非故事/案例/操作心法的叙事。

### 2.2 核心发现：VLM 只做了「视觉识别」，没做「知识挖掘」

当前 `describe-images-minimax.py` 的 SYSTEM_PROMPT 要求 VLM：
1. 判断图片类型
2. 提取标题
3. 描述核心内容和视觉结构
4. 列出关键元素、文字、图表
5. 分析视觉风格
6. 给标签
7. 说明适用场景
8. 给出置信度

**问题**： prompts 里没有要求提取：
- 这个框架的**一句话定义**
- **适用条件 / 不适用条件**
- **操作步骤 / 使用流程**
- **常见错误 / 失败模式**
- **典型案例 / 数字**
- **与其他框架的关系**
- **可迁移场景**

因此，VLM 输出的是「这张图长什么样」，而不是「这张图里有什么值得入库的知识」。

### 2.3 单元模型域深度不足的典型证据

以 `一堂-单元模型-单sku模型_vlm_desc.md` 为例：

> 这是一张教学类幻灯片，以表格形式系统介绍'单SKU模型'的核心概念。表格共分四行，分别从一句话解释、常见变种、典型类型、建议要用（含触发条件）四个维度展开说明。该模型强调按每个SKU进行计算以测算毛利结构……

VLM 正确识别了「四行表格」「一句话解释 / 常见变种 / 典型类型 / 触发条件」，但**没有追问**：
- 单 SKU 模型在真实业务中常漏掉哪些成本项？
- 什么情况下「单 SKU 盈利」会掩盖「总账亏损」？
- 有哪些反例（比如爆款 SKU 养活长尾 SKU）？
- 和「单订单模型」「单用户模型」冲突时怎么选？

这些正是暗知识与案例所在，但当前 prompt 没有触发 VLM 提取。

## 4. 自攻击诊断逻辑

### 4.1 攻击 1：有没有漏掉素材层？

**攻击**：VLM 描述已经覆盖了所有找到原图的图片，但只提取了视觉层；图片中的文字内容、数字、案例细节很多被简化或忽略。

**例子**：`一堂-单元模型-扭蛋机案例_vlm_desc.md` 提取了「单店测算 → 3台试跑 → 50台扩张」和「斧子/尺子/梯子」框架，但**没有提取具体数字**（月流水 3000、租金 25%、玩具成本 30%、最乐观月赚 1350、18 个月回本红线）。这些数字对 case 卡至关重要。

### 4.2 攻击 2：框架匹配有没有歧义？

**攻击**：VLM 把多张图识别为「框架图」「信息图」，但没有判断它属于 framework / tool / case / dk 哪一类。这会导致后续生产方老顽童需要重新分类，效率低。

**例子**：`一堂-单元模型-对抗小抄01` 被识别为「管理策略表格」，实际上它既是 tool（可执行清单）也是 dk（对抗规模不经济的心法）。

### 4.3 攻击 3：交叉验证够不够充分？

**攻击**：VLM 输出没有与已有 wiki 卡片做交叉对照，导致无法判断「这是新卡还是 enrich 旧卡」。如果直接批量生产，会产生大量重复卡片。

**例子**：十大单元模型在 overview 中已有表格；若按 VLM 描述直接生产，会与 `yt-unit-model-overview` 大量重复。

### 4.4 攻击 4：如果素材作者（一堂讲师）在场，会反驳哪条诊断？

**反驳**：讲师可能会说「这些图本身就是辅助理解的，真正的心法在我口述稿和案例里」。

**回应**：这正是诊断结论——**图片不能独立成卡，必须与口述稿 / OCR 文本 / 案例上下文结合**。洪七公的 VLM 输出是「视觉索引」，不是「成品原料」。下一步需要把 VLM 描述与 OCR 文本、口述稿（如有）做跨源融合，才能提取 case/dk。

## 6. 盲区 / Gap

1. **VLM prompt 未要求提取暗知识与案例**：这是系统性 gap，不是单张图质量问题。
2. **缺少跨源融合**：VLM 描述没有与 OCR 文本、口述稿、已有 wiki 卡片对齐，导致无法判断重复与缺口。
3. **课程清单 / 地图类图片价值低**：其他域中大量课程清单、大地图只是目录，本身不具备独立成卡价值，需要先提取关键节点再做判断。
4. **12 张找不到原图的 OCR 卡无法处理**：需要用户或洪七公补充原图或确认是否跳过。
5. **单元模型域已有 10+ 张卡，新增卡片必须与现有卡片做 related 补全**：否则会造成知识孤岛。

## 7. 反馈建议（下一步任务）

### 7.1 立即执行：洪七公二轮 VLM 提取（P0）

对 **单元模型域 35 张 + 科学决策域 35 张** 做第二轮 VLM 提取，使用新的 case-mining prompt。

Prompt 核心要求：
1. 一句话定义该图表达的核心概念
2. 适用条件与不适用条件
3. 操作步骤 / 使用流程（如有）
4. 常见错误 / 失败模式（至少 3 条）
5. 图中出现的具体数字、案例、时间线
6. 与其他框架 / 概念的关系
7. 可迁移场景
8. 判断它是 framework / tool / case / dk 哪一类
9. 如果是案例，给出「一句话」「关键数字」「教训」
10. 如果是暗知识，给出「反直觉点」和「行动建议」

输出格式仍用 JSON，但字段从「视觉描述」改为「知识挖掘」。

### 7.2 并行执行：交叉对照表

黄药师或王语嫣制作一张「VLM 文件名 → 现有 wiki 卡片 id → 处理动作（新建 / enrich / 跳过）」的对照表，避免重复生产。

### 7.3 后续生产（老顽童）

- **新建卡**：单商圈 / 单城市 / 外部对抗地图 / 象限分析法 / 学练用 / TCPR 底层网络协议 / 找*实操难点 dk 系列 / 科学决策 ROI 案例等。
- **enrich 卡**：`yt-unit-model-overview`、`yt-unit-model-ladder`、`yt-unit-model-three-tools`、`yt-scale-economy-weapon-library`、`case-unit-model-gashapon` 等。
- **跳过**：纯课程清单、无法找到原图的 12 张、已有更高质量口述稿对应的图片。

### 7.4 质量标准

- 每张从 VLM 原料生产的卡片必须附带 `source_refs`：原图 + VLM 描述文件 +（如有）OCR 文本。
- 每个关键声明必须标注 `[conf=X, source=...]`。
- 涉及已有卡片的必须补充双向 `related`。

## 8. 王语嫣结论

洪七公的 VLM 结构化整理完成了**高质量视觉索引**，为后续知识提取提供了基础，但**尚未达到可直接进入 30_wiki 生产的原料标准**。

主要问题：
- VLM prompt 只要求「描述图片」，没要求「挖掘知识」。
- 单元模型域尤其吃亏：大量框架图被压缩成标题 + 表格行说明，丢失操作细节、失败模式、案例数字。
- 与已有 wiki 资产缺少对照，存在重复生产风险。

建议：**先做一次以知识挖掘为目标的二轮 VLM 提取，再产出卡片生产任务**。
