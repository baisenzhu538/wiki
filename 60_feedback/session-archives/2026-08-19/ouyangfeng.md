## 思维盲点

1. **wmic/tasklist 文本解析在 Git Bash 被转义截断**——两次尝试拿到截断输出，差点误判"18 进程无 profile=多开"；PowerShell CIM 直查后真相大白（9 服务 × 2 父子进程）。**为什么漏**：习惯沿用 Linux 文本解析法，没先想 Windows 管道转义差异——验证方法惯性（O-11 家族），Windows 取证弃 wmic 用 CIM。
2. **complete --force 直接跳被 O-3 锁 bug 卡住时，第一反应是"手动改"**——停住走脚本正常路径 claim --force → complete 即通。**为什么没先走**：O-3 bug 已知但没在脑内形成"替代路径"缓存，遇错才现想——脚本拒绝先读错误信息再找合法路径（O5 牌被实证），替代路径应预研。
3. **note-coach 差点直接按"无需求信号"归档不问身份**——用户反问暴露盲区：拍板材料缺"它是什么"这一节。**根因**：把"无活跃"当成了唯一决策输入，漏了"知情权"维度——给用户的拍板材料 = 身份 + 活跃度 + 成本，缺一不可。

## 顿悟

1. **冒烟"行为签名"三级证据链**：metadata（tool_turns=0）→ 正文（967 chars）→ 内容正确性（8 条纪律逐条对真实）——前两级只证明"答了"，第三级才证明"答对了"。审查冒烟不取最高级证据等于没审。
2. **迁移验收的责任方交接链理论落地**：T0（system→user）→ T1/T2（user→NSSM）→ T4（多余 profile 归档）——四单形成完整迁移叙事，每单验收都是"上一级退役 + 下一级承接"双证。这一套方法论可复用于任何基础设施迁移。
3. **用户拍板的最小授权边界**：拍板本身是用户决策（不可代），拍板后的机械执行（mv/归档）在授权范围内可代，但执行链必须落盘（谁/何时/可回滚）——授权是"做了"，记录是"被看见"。
