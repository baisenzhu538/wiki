## 思维盲点

1. **PARA 库误判（最大盲点）**：凭"英文库从未消化"的旧报告+文件名统计就归类"垃圾候选"，给"归档/删除"选项。为什么错？把"未消化"当成"低价值"（实际是核心资产待消化）；抽查少量样本就下结论（B5 牌违背——没通读）；处置建议默认姿态是"清理"而非"保守保留"。**教训：处置类判断必须先问内容价值，默认保守**。
2. **快照过期再犯**：记忆里"#352-356 queued 待做"——实际 08-18 晚第 3 次会话已全部完成。恢复时虽读了"目录内最新"，但对 context.md 快照的待办仍照单全收。**教训：待办类记忆也要以队列实际状态核实**（B1 门禁就是干这个的——应该一恢复就跑）。
3. **yaml 大脚本不先小样本验证**：_no_dup 的 node.value 是 (key,value) 元组、heredoc 转义破坏字符串——两个 bug 各浪费一轮全量扫描。**教训：长脚本先跑 5 个文件小样本再全量**。
4. **批量归档不验证切割**：cut -c9-12 取到 "_202" 而非月份，135 单归档目录错位，修了两次。**教训：mv 前先 echo 验证目标路径**。

## 顿悟

1. **门禁体系的本质是"完成感打断器"**：B1（入队）、#363（git 收净）、#375（内容价值判断）、#362（版本对齐）——每道门都打断一个"大脑自动标记完成"的瞬间。PARA 事件证明：完成感最危险的时刻是"清理"类任务——大脑觉得"扫除垃圾"有成就感，恰恰最容易把核心当垃圾。

# Truman 11章复盘 · 黄药师 · 2026-08-19（第二场：偶遇采集修复 + 蒸馏技能矩阵建设）

## 概要（一句话）

记忆恢复开场 → 偶遇采集管线体检（发现并修复重复采集）→ inbox 自动化断链根因（WSL cron 静默死亡）→ 狗粮逼出微信限流断流三层修复 → WSL cron 清仓迁移 → 视频蒸馏技能矩阵（仓颉/一盏神灯/darwin/自蒸）双端安装注册 + KDO 全链路挂载。

## 差异栏（vs 今日第一场）

第一场是治理批次终审收口（别人驱动）；本场是**能力建设**（用户直接派活，不走队列）：从"修机制"切到"建能力+修自动化"。三个新认知：① WSL  cron 类自动化在"全量 Windows"后应默认视为已死 ② 狗粮实测比代码审查更能抓真 bug（IncompleteRead 三连）③ 技能生态要装正版优先于复刻（仓颉/darwin 都是开源的，复刻只用于未公开的一盏神灯）。

## 关键决策

| 决策 | 理由 | 结果 |
|:---|:---|:---|
| watch_inbox 迁 Windows 计划任务（非修 WSL cron） | 用户拍板"全量 Windows"，WSL 不常驻 = cron 必然静默失效 | kdo-inbox-watch 每 10 分钟，实测调度器触发成功 |
| 文章去重用规范化键（__biz+mid+idx / gid）而非完整 URL | 微信分享追踪参数每次不同，完整 URL 去重必然失效（《重构协同》采了 3 份实证） | 6 变体收敛 1 键；文件名幂等 |
| 抓取失败不记 seen（对齐视频"成功才记录"语义） | 旧逻辑"瞬时断网 = 文章永久丢失" | 失败下轮自动重试 |
| 重复产物归档不删除 | PARA 教训：处置类默认保守 | duplicates-archive/ 零丢失 |
| 技能安装用 junction 不写副本 | E034 stale-copy 教训：副本必漂移 | 单一真相源，四处挂载一处改 |
| 仓颉/darwin 装正版，一盏神灯才复刻 | 调研最佳实践（startup.md 零之零）：有开源原版不重新发明轮子 | 省自研成本，质量上限更高 |

## 思维盲点

1. **#366 误判（本场最大）**：凭 context.md 里"FAIL 结构化意见（capsule_sync 停用/兼容）"旧记录就把 capsule-sync 定时器 disable 了——实际 01:33 commit 131815020 已完成 v2 兼容改造并复审 PASS A。用户一句"不是早就做完了吗"点醒。**教训：凭旧的 FAIL/问题记录定性前，先查后续 commit 和终审结论**——与"恢复以目录最新为准"同构：记忆中的"问题状态"也是快照。
2. **以为 kdo query 一个命令覆盖全部检索**：实测一盏神灯查不到才发现 graph 索引与 search_index.json 是分离的两套，新卡必须跑 `kdo index` 才进 BM25 检索。#327 修的是 `--rebuild` 语义，操作侧的"入库后跑 index"习惯本场才建立。
3. **PowerShell/cmd 编码坑**：.ps1 无 BOM 被 PS 5.1 按 GBK 解析吞字符（变量静默变空）；.cmd 中文注释同理炸。教训：.ps1 带 BOM、.cmd 纯 ASCII。

## 顿悟

1. **静默失效是最危险的失效**：WSL cron 死了 2 天无人察觉（洪七公交付汇总躺 inbox）；文章抓取失败记 seen 是另一种静默丢失。共同解药：巡检要覆盖"应该跑而没跑"的负状态，不只是"跑了报错"。
2. **狗粮测试的回报远超预期**：幂等重放一次抓出"限流断流→重试→部分响应降级→贪婪提取"四层修复链。写完代码就跑真实数据，是本场 ROI 最高的动作。
3. **用户是最终的事实校准器**：一盏神灯的名字、#366 的状态，两次都是用户一句话纠正我的转写/记忆偏差。转写层（tiny 模型）不可靠时，人名/专名要等用户校验。
