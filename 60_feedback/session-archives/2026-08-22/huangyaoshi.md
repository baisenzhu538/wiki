## 思维盲点

1. **VENV_PY 路径上溯层数错**：scripts→code→40_outputs→wiki 是 3 层，我写了 2 层——相对路径层级必须数清再写。
2. **--json 塞全文**：117KB 输出爆炸——JSON 只放元数据，全文走 --stdout，这是设计问题不是功能问题。
3. **路由判定漏混合页**：text_based 但 pages_needing_ocr 非空时误报"本地直提完成"——分类与页级标注是两回事。
4. **手动 scan() 消费 watch_inbox state**：调试脚本时手动调 scan() 把文件写入 seen，正式运行不再登记——调试自动化前先读 state 写入逻辑。

## 顿悟

1. **"声称验证"是外部 agent 协作的第一道门**：小昭的卡写得漂亮（格式全对、benchmark 数字都有）但软件没装、审查没做——**格式完整 ≠ 事实为真**，与 P-15 同构，只是换了个角色。
2. **收编比拦截更有价值**：外部 agent 越权产出，拦截=浪费，收编（inbox→登记→编排）让它在正规流程里复活——#407 就是实证。
3. **KDO 已是 2026 最前沿架构**：九层调研最大发现——Karpathy LLM Wiki 编译器模式与 KDO 逐项同构。这意味着我们讨论的重点应从"架构"转向"调用回路"——知识库的价值实现端。
4. **分角色自动化=传送带自动化**：用户澄清后对齐——探针不替任何人判断，只做推送。这不是技术问题，是"通知层"缺失。
