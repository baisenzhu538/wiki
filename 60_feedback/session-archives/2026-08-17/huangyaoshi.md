# Truman 11章复盘 · 黄药师 · 2026-08-17（第 2 次会话：视频号全自动偶遇链路打通）

## 概要（一句话）

把"手机转发→全自动入库"的楚门方式一做到终态：微信 4.x 数据库解密（复用段王爷 passphrase）→ 文件传输助手消息 ZSTD 解压 → 链接自动提取 → **ltaoo parse_sph（元宝 Cookie）链接直链解析** → 自动下载 → GPU 转写 → LLM 三层次知识化 → 00_inbox，实测 WorkBuddy 视频 146s 全链自动完成，计划任务固化（每 10 分钟）。

## 差异栏（vs 本日第 1 次会话）

与第 1 次（记忆恢复+断链修复）最大不同：**从"修好半成品"到"找到终态架构"**——第 1 次以为 res-downloader 播放嗅探是下载正解，第 2 次被用户两次纠偏（"在外面只有手机""应该不是元宝，看楚门口述爬虫"）后回到源头调研，锁定**元宝登录态 parse_sph（链接→直链，无人值守）**才是唯一全自动解。另一个视角变化：**从"让用户操作"转向"让用户零操作"**——UI 自动化死磕浏览器播放 1 小时失败（预览页无登录态播不了），改为"用户扫码一次拿登录态（CDP 自动提取）+ 全自动链路"。

## 关键决策

| 决策 | 理由 | 结果 |
|:---|:---|:---|
| 下载正解 = 元宝登录态 parse_sph（ltaoo/wx_channels_download） | 唯一"链接→直链"无需播放的方案；2026 调研确认（公共 Worker 失效后的主流回退）；v260817 今天刚发版 | 实测解析 WorkBuddy 链接成功（code:0，作者/评论数与预览页一致） |
| 微信 4.x 数据库解密复用段王爷 passphrase | 用户提示"段王爷就是这么做的"→ build_keys.py 硬编码 passphrase；PyWxDump/内存扫描都不支持 4.x | 19/19 验证通过，无需再提取 |
| CDP 远程操作替代用户手动复制 Cookie | 用户 F12 按出计算器（DevTools 门槛）；用户只扫码，Cookie 由脚本自动提取 | 13 个腾讯域 Cookie 全量提取（含 hy_token 主 token） |
| 全量 Cookie 而非单个 | 只填 2 个 Cookie 返回"无法播放"，13 个全量（含 hy_token 684B）才成功 | parse_sph 一次通过 |
| 计划任务固化（登录自启服务 + 每 10 分钟监控） | 无人值守要求 | wx-channels-download + wechat-link-monitor 已注册 |
| 知识化脚本 NO_PROXY 绕过系统代理 | MITM 工具（wx_video_download/res-downloader）设置系统代理后拦 DeepSeek API（SSL 证书） | LLM 调用稳定 |

## 思维盲点

1. **浏览器死磕视频播放 1 小时是弯路**——预览页（finder-preview）无微信登录态，怎么点击都不播放；res-downloader 只抓图片。为什么死磕？以为"浏览器自动化能模拟用户播放"。**教训：需要登录态的页面，让用户扫码一次（拿登录态）远胜 UI 自动化模拟**——用户扫码是 1 分钟，自动化是 1 小时+脆弱。
2. **Cookie 提取不全导致"无法播放"**——第一次只提取 2 个 Cookie（主 token 561553b），parse_sph 返回"此内容暂时无法播放"；全量 13 个（含 .tencent.com 域 hy_token）才成功。为什么漏？凭"主 token 够用"的直觉。**教训：接口需要什么就提供什么，先看接口实现/文档再猜**。
3. **改了 config.yaml 不重启服务不生效**——第一次填 Cookie 后直接调 API 返回旧配置错误。为什么？忽略进程持有配置。**教训：配置变更后必须重启服务再验证**（P-29/P-30 家族）。

## 顿悟

1. **"用户零操作"是偶遇采集的设计标准**——楚门"AI 超级入口"的本质：用户动作 = 转发一次，其余全自动。KDO 版终态对齐：转发→（电脑无人值守）提取→解析→下载→转写→知识化→inbox。**每个需要用户手动做的环节都是设计缺陷**。
2. **微信 4.x 数据是"金矿"但钥匙在旧工具里**——段王爷 6 月装的 wx_key/wechat-decrypt 看似过期，实际 passphrase 永久有效（数据库密钥不变），19/19 全解密。**"旧资产+新需求"组合常被忽略，先盘点已有工具再重新发明**（B3 牌）。
3. **CDP（浏览器调试协议）是"让用户零操作"的万能钥匙**——登录态、Cookie、DOM 操作都能脚本化，用户只需扫码。这次 Cookie 提取、未来任何"需要登录态"的自动化都用它。
