## 思维盲点

1. **常驻进程没问"谁续命"**：kimi web 挂会话后台被超时收尸。为什么漏掉？启动时只想"先跑起来验证"，没问"这个进程的寿命归谁管"——寿命问题必须在启动瞬间回答，事后补就是事故。
2. **对陌生机器的 API 健壮性默认乐观**：远程创建会话的 POST 直接把家用机 API 噎死（502→全端点超时）。为什么漏掉？没有小步试探纪律——先用轻量 GET 压测、再 POST 写操作，我给反着来了。探针四连 502 才承认它死了。
3. **时间戳手写漂移**：02:12 vs 实际 02:08。为什么漏掉？顺手写"当前时间"没跑 date——凭感觉代替取数的微缩版。

## 顿悟

1. **组网的正确心智模型：Tailscale 通的是"马路"，服务是"门"**——网络通≠内容可见；默认互相看不见才是安全基线，每扇门逐个授权开。老朱问"你能看见我家电脑吗"，正确答案不是"能/不能"，是"马路通了，门还没开，开门是一条命令的事"。
2. **kdo-seed 三层切分是通用迁移模式**：跨库（tech-wiki）→ 跨机（素材库工具包）第二次应用成立——机制原样搬/机器绑定重建/内容不搬。值得沉淀为正式方法卡。
3. **降级预案要常备**：最稳的远程执行通道不是 API 而是"用户的手"。设计远程方案时，用户手工降级路径必须是第一备胎，不是事后补丁。
