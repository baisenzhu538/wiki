## 思维盲点

1. **#498 状态误报**：老朱问 #498 为什么状态没更新，我先答「在审」——实际已 reviewed。我凭「没收到终审通知」推断「未审」，把通知缺席当成了事件缺席。**为什么漏掉**：脑子里通知系统是默认可靠的，「没收到」被我直接映射成「没发生」；而探针空转恰恰让一切「没收到」都不可解释。更深层：我报状态时没有触发「回源核验」反射——队列行和任务单 frontmatter 就在那，grep 一下 5 秒钟的事，我用了 0 秒凭印象答。教训已内化：状态断言必回源（queue_transition status 实测），通知只作线索不作证据。
2. **git mv 丢编辑（A5 自查首例）**：编辑文件后 git mv，工作区修改不随 mv 走，编辑丢失。**为什么漏掉**：把 git mv 想成「带状态的 mv」，没意识到它只操作索引和路径，工作区脏内容被留在原路径。行动前复核最新态（§3.16）当时还没写进 charter，正是这个坑催生了它。
3. **git add 静默失败**：收尾 commit 时 dashboard.html 路径写错（少了 70_product/tasks/ 前缀），且命令带了 `2>/dev/null` 吞掉错误，git add 部分路径不匹配=整体原子失败，commit 报 pathspec 错误才发现。**为什么漏掉**：想省输出噪音加了静默重定向，结果把唯一的失败信号也静掉了；且误以为 add 是逐路径独立的。教训：git 写操作链永不吞 stderr。

## 顿悟

**「缺席的证据 ≠ 证据的缺席」在通知系统上是字面真理。** 探针空转 44 分钟期间，「没收到通知」这个信号的语义从「没事发生」坍缩成「无法解释」——我却在 #498 上按旧语义做了判断。这推翻的不止是一个操作习惯，是一个认识论默认：凡依赖信号通道做推断，先问通道本身是否健康。通道健康性检查必须先于信号语义解读。这也解释了为什么 R2（拒删接 gate-blocked 通道）值得立项——拒删事件只在本地日志里，等于把一个「无法解释的沉默」埋进半夜。
