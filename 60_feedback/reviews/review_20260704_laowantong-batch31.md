## 每张卡补的内容

### 1. `yt-skill-storyline-problem-solving`（问题解决线）

- **目的**：明确工具解决"把混乱诊断过程变成可追踪思维链"的问题，适用场景包括需要分析复杂问题、需要展示诊断逻辑、需要传承诊断过程。
- **操作步骤**：6步（精确描述问题 → 列出所有可能原因 → 设计验证方法 → 执行验证 → 推导方案 → 显式化牺牲）。
- **不要用的场景**：4条（危机恢复需立即行动、问题只有一个明显原因、组织文化用诊断文档追责、高度复杂系统因果）。

### 2. `yt-skill-storyline-target-tradeoff`（目标取舍线）

- **目的**：明确工具解决"把模糊纠结变成显性决策框架"的问题，适用场景包括面临多选项多因素决策、需要向他人解释选择、决策后容易后悔、团队决策需要透明化。
- **操作步骤**：7步（穷尽列出比较因素 → 定义评判标准 → 分配权重 → 为每个选项评分 → 计算加权总分 → 显式列出牺牲 → 标注不确定性和遗漏因素）。
- **不要用的场景**：4条（根本价值冲突、时间<1小时、信息大量未知、分析麻痹）。

### 3. `yt-skill-storyline-timeline`（严格时间线）

- **目的**：明确工具解决"用时间轴重构事件因果链"的问题，适用场景包括需要回答"这件事是怎么发生的"、复盘失败/成功案例、向他人展示推理过程、事件涉及≥3个时间节点。
- **操作步骤**：6步（列出所有已知时间节点 → 按时间顺序排列 → 标注状态变化 → 检查因果链完整性 → 标注推断 → 退出标准）。
- **不要用的场景**：4条（高度复杂系统分析、情感密集型叙事、节点过多不拆分、混入解释评价）。

### 4. `challenge-point-design`（挑战点设计）

- **目的**：明确工具解决"把模糊勇气变成具体动作"的问题，适用场景包括用户愿意练习但进步不明显、进入非舒适区后缺少方向、每次新练习周期开始时。
- **操作步骤**：4步（设定1个具体挑战点 → 写在文档里 → 练习过程中有意识地挑战 → 练习后复盘）。
- **不要用的场景**：4条（用户还在零基础摸索、用户状态很低、一次设定多个挑战点、挑战点不记录）。
- **质疑**：包含内部局限（挑战点设计假设"只要设定就能突破"，但实际上容易退回舒适区）+ 外部攻击者 **阳志平**（挑战点设计忽视了认知资源的波动性，真正有效的突破往往来自"内部涌现"而非"外部设定"）。

### 5. `completion-criteria-design`（完成标准设定）

- **目的**：明确工具解决"把'学会'变成可验证描述"的问题，适用场景包括任何需要明确学习终点的场景、用户说"不知道学到什么程度"、作为AI差距分析的评估依据。
- **操作步骤**：3步（学之前先写3条完成标准 → 学习过程中对照标准 → 学完后打勾或修正）。
- **不要用的场景**：4条（探索性无明确目标的学习、标准太虚、标准不现实、一次写太多标准）。
- **质疑**：包含内部局限（完成标准设定是"闭门造车"，可能和真实业务场景需要的"学会"不一样）+ 外部攻击者 **徐玲**（《得到》总编辑——完成标准设定忽视了学习的非线性特征，过度强调"完成标准"可能会让人急于求成）。

### 6. `four-questions-feedback`（四问法自我反馈）

- **目的**：明确工具解决"把'学完了'变成'看清了'"的问题，适用场景包括任何单次练习后的复盘、没有外部反馈来源时的替代方案、作为AI虚拟教练差距分析的输入。
- **操作步骤**：4步（练习后立即做 → 每个问题举出至少1个具体例子 → 重点回答第4问 → 贴在练习模板里必填）。
- **不要用的场景**：4条（完全没有练习过程时、用户极度抗拒反思、回答太笼统时不深入、四问写完就结束）。
- **质疑**：包含内部局限（四问法假设"只要问自己四个问题就能看清学习过程"，但实际上大多数人的元认知是不准确的）+ 外部攻击者 **陈虎平**（逻辑图谱创始人——四问法是"向后看"的，真正有效的学习反馈往往是"向前看"的）。

### 7. `productization-judgment`（产品化判断四维度）

- **目的**：明确工具解决"把'会用工具'升级为'会用工具做产品决策'"的问题，适用场景包括评估AI工具在产品中的可用性、需要向团队/客户解释工具价值、作为AI工具学习曲线的最终产出。
- **操作步骤**：4步（列出适用场景3个具体例子 → 列出不适用场景2个具体例子 → 判断集成位置 → 思考组合可能性）。
- **不要用的场景**：4条（纯个人兴趣学习无产品场景、对工具完全不了解时、判断太泛、脱离业务）。
- **质疑**：包含内部局限（产品化判断四维度是"理性分析"框架，但真正优秀的产品决策往往来自"用户体验直觉"）+ 外部攻击者 **张小龙**（微信创始人——产品化判断四维度是"工具导向"的，但真正优秀的产品往往是"用户导向"的）。

### 8. `yitang-strategy-canvas`（战略画布）

- **目的**：明确工具解决"把复杂竞争格局压缩成一张可视化图表"的问题，适用场景包括团队争论"我们和竞品有什么不同"、发现获客成本持续上升、考虑进入新市场或新品类、战略规划会产出过多目标。
- **操作步骤**：5步（列出目标买家真正在意的竞争要素6-8个 → 画出3条曲线 → 找出差异化空白 → 用"四动作"重构曲线 → 验证）。
- **不要用的场景**：4条（完全空白市场、买方需求高度碎片化、替代方案评估需要精确财务模型、团队无法诚实面对自身曲线）。

### 9. `yt-unit-model-build`（单元模型搭建五步法）

- **目的**：明确工具解决"把抽象的'单元模型'概念落地为可复制的分析流程"的问题，适用场景包括评估新业务机会、业务扩张前、团队对投资/不投资争论、融资路演需要展示商业模式。
- **操作步骤**：5步（找到最小可复制单元 → 列出所有收入项 → 清理所有成本项 → 验证数据准确性 → 做动态预判）。
