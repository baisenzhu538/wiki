# 跨域审计：KDO 框架是否被静态化

> 审计触发：双三角域教训——Y模型和双三角一度被写成静态分析框架，忽略了引擎层迭代。本审计主动排查其他域是否存在同类问题。
> 审计日期：2026-07-04
> 审计范围：7 张核心框架卡 + 3 张跨域抽检

---

## 一、审计维度与评分标准

| 维度 | 满分 | 检查问题 |
|:---|:---:|:---|
| 迭代发动机 | 2 | 卡片是否展示了该框架通过多轮循环演化？是否有「V1→V2→Vn」的进化叙事？ |
| 起点认知 | 2 | 是否说明了最初的朴素框架认知是什么？是否承认第一版可能是错的？ |
| 关键案例 | 2 | 是否有具体案例推动框架更新？案例是作为「应用示例」还是「迭代驱动者」？ |
| 人类判断 | 2 | 是否说明人在哪些环节做判断？是否有「人在环」或判断节点映射？ |
| 飞轮机制 | 2 | 是否说明下一轮如何启动？是否有资产沉淀和反馈闭环？ |
| 反静态化 | 2 | 是否明确警告不要把这个框架当固定模板？是否有「不要硬套」的声明？ |

**风险评级**：
- **低**（≥10 分）：引擎思维内建，不太可能被误用为静态模板
- **中**（6-9 分）：有引擎思维的种子但不够突出，存在被静态化使用的风险
- **高**（≤5 分）：完全以静态工具形态呈现，高度可能被误用

## 二、核心审计结果

### 2.1 `yt-decision-y-model` — Y模型核心卡

| 维度 | 得分 | 判定 |
|:---|:---:|:---|
| 迭代发动机 | 1/2 | "无限进步（持续迭代）"出现在图中，"知行迭代"是五步法第5步。但引擎层叙事（"从朴素认知开始，一轮一轮迭代"）缺失。卡片读起来更像"这是一个四层结构模型"而不是"这是一台迭代发动机" |
| 起点认知 | 0/2 | 无"朴素框架认知""第一版允许错误"等表述。卡片假设读者已经理解了问题 |
| 关键案例 | 1/2 | 跨域迁移示例（子女教育/SaaS/内容创作）和七人作业合集，但它们被呈现为"应用示例"而非"推动框架进化的迭代事件" |
| 人类判断 | 1/2 | OPC 智能体适配节提到"Agent 不替用户做判断"，但未显式映射人在哪些节点做判断 |
| 飞轮机制 | 0/2 | 无飞轮记录机制。五步法第5步"知行迭代"只有一句话 |
| 反静态化 | 1/2 | Synthesis 中说"不是一张填空就能成功的模板"，Critique 提到仪式化风险。但正文主体未强调 |

**总分：4/12 | 风险评级：高**

**具体问题**：
1. 引擎层语言完全缺失——卡片把 Y模型 呈现为四层静态结构，而 Truman 在课程中反复强调"列出来你的基础框架认知，不完整也没关系，会不断迭代的"
2. 五步法被写成线性流程（1→2→3→4→5），缺少循环箭头
3. 案例是"Y模型可以用于 XX 场景"，不是"XX 案例推动了 Y模型 框架本身的进化"

**建议修改**：
- 在"核心框架"节之前增加一节"引擎层 vs 工具层"，明确 Y模型 首先是迭代发动机
- 将五步法改为循环图（第5步 → 第1步）
- 为每个跨域迁移示例加一句"这一轮循环后框架认知被升级为什么"

### 2.3 `framework-yitang-shishi-qiushi` — 实事求是框架卡

| 维度 | 得分 | 判定 |
|:---|:---:|:---|
| 迭代发动机 | 0/2 | 卡片描述的是 Y模型 中的一个**子能力**（校准器），不是独立引擎。但作为子能力，它未说明自己在引擎循环中的位置和触发条件 |
| 起点认知 | 0/2 | 无 |
| 关键案例 | 0/2 | related 中链接了 case 卡，但正文未展示案例如何推动了对"实事求是"理解本身的迭代 |
| 人类判断 | 2/2 | 实事求是的本质就是区分"我希望是真的"和"事实是什么"——这天然是人类判断活动 |
| 飞轮机制 | 0/2 | 无 |
| 反静态化 | 0/2 | 无显式警告 |

**总分：2/12 | 风险评级：高**

**具体问题**：
1. 卡片把实事求是呈现为独立方法论，而非 Y模型 引擎循环中的一个具体步骤（步骤 6）
2. 缺少与 Y模型 引擎层的操作性连接——读者不知道"什么时候该调用实事求是、调用完之后下一步做什么"
3. 验证成本阶梯（常识→情报→实验→全量）在 extraction 中有但卡片中未充分展开

**建议修改**：
- 在开头增加一节"在 Y模型 引擎循环中的位置"（已有雏形但过于简略）
- 增加"触发条件"：什么信号告诉你需要跑一次实事求是校准？
- 增加验证成本阶梯的操作说明
- 增加"校准后下一步"：实事求是之后 → 解放思想（如果发现很多信念）或知行合一（如果事实已经足够）

### 3.2 `framework-demand-iceberg` — 需求洞察冰山模型

| 维度 | 得分 | 判定 |
|:---|:---:|:---|
| 迭代发动机 | 0/2 | 完全静态的六层分析框架，无循环、无迭代。到达 L6 之后做什么？卡片未回答 |
| 起点认知 | 0/2 | 无"朴素认知"概念。框架假设用户按 L1→L6 线性推演 |
| 关键案例 | 0/2 | related 中有 pending_unknown 占位，无实际案例链接 |
| 人类判断 | 1/2 | 有"方案中立""逐层不跳"等原则，隐含了人在判断，但未显式映射 |
| 飞轮机制 | 0/2 | 无。L6 之后是终点 |
| 反静态化 | 0/2 | 无。卡片本身就是一个六步填表模板 |

**总分：1/12 | 风险评级：高**

**具体问题**：
1. 最典型的静态化案例——冰山模型被呈现为一次性分析工具："拆→推→评"，评完结束
2. 没有回答"如果 L6 的需求假设被验证错了，下一步做什么？"
3. 没有说明"冰山模型本身在多次使用后如何升级"——同一个品类的需求洞察，第二次用冰山模型应该比第一次更快，这种"学习效应"未被框架捕捉
4. Agent 执行指令是 Python 代码——这是好的操作性设计，但它进一步固化了"按步骤执行"的静态印象

**建议修改**：
- 增加"冰山模型的迭代使用"节：第一次冰山 → 验证假设 → 更新 L4 任务地图 → 第二次冰山更快
- 增加"冰山模型的边界"：什么时候不需要走完六层？
- L6 之后增加一步："如果假设被推翻，回到 L3 重新圈定核心任务"

| 维度 | 得分 | 判定 |
|:---|:---:|:---|
| 迭代发动机 | 0/2 | 纯静态战略规划框架：差距分析→战略规划→战略执行。有"执行"但没有"执行后回到差距分析"的闭环 |

| 飞轮机制 | 0/2 | 无。战略执行之后是终点 |
| 反静态化 | 0/2 | 无 |

**总分：1/12 | 风险评级：高**

**说明**：BRM 源于 IBM BLM，本身就是战略规划工具而非迭代发动机。但 KDO 卡片未声明这个边界——读者可能以为 BRM 是一套完整的做事系统（像 Y模型 那样），而实际上它只覆盖"规划"这一个环节。

**建议修改**：

- 增加"BRM 与 Y模型 的关系"：BRM 的五看三定可以作为 Y模型 循环中"理论侧·科学类比"的输入

**模式发现**：

2. **非一堂域框架卡普遍静态化**：冰山模型、BRM 等卡片以"步骤清单"形态存在，没有迭代闭环。
3. **天然迭代的框架（OODA）静态化风险最低**，但也缺少案例锚定。

## 五、修复优先级

### P0：根节点修复（影响最大）

**`yt-decision-y-model`（高风险）** — Y模型是全库根节点，它的静态化会连锁影响所有依赖它的卡片。必须优先修复。

修复任务单：`task_20260704_laowantong-fix-staticization-yt-decision-y-model`

### P1：Y模型子组件修复（连锁影响）

**`framework-yitang-shishi-qiushi`（高风险）** — 需要在开头增加"在 Y模型 引擎循环中的位置"

## 六、审计结论

**KDO 框架卡存在显著的两极分化**：最近一批卡片（2026-07-03/04 产出的 synergy、engine-cycle 等）引擎化程度很高，但老一代卡片（Y模型核心、实事求是、解放思想）和非一堂域卡片（冰山模型、BRM 等）仍以静态工具形态存在。

根因是清楚的：引擎层思维是双三角域在王语嫣九层深挖诊断中才被系统化提炼出来的（DK-52 到 DK-60），此前的卡片生产者（包括老顽童自己）没有这个意识。

**修复策略**：不是把所有框架卡都重写成引擎卡——有些框架（如 BRM、冰山模型）本身就是静态规划工具。修复的核心是**声明边界**：这个框架是引擎的一部分，还是一次性工具？如果是静态工具，它和 Y模型 引擎的接口在哪里？
