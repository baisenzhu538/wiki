# 概念卡入口标注：AI 基本功的 Feature 思维

> 本标注纠正王语嫣此前对「基本功」的浅层理解：基本功不是「会用工具」，而是掌握 AI 工具的**最小可操作技术特性（Feature）**，并能用 Feature 组合来解决问题。该概念来自 Truman 在双三角课程中关于基本功的展开（行 1210、1386-1468）。

---

## 一、核心命题

1. **基本功 ≠ 会用某个工具**：今天学 ChatGPT、明天学 Coze、后天学 Cursor，这种「工具迷信」是基本功学习的最大陷阱。
2. **基本功 = 掌握 AI 工具的 Feature（最小可操作技术特性）**：把每个工具拆成一个个最小技术单位，围绕 Feature 做决策，而不是围绕工具名字做决策。
3. **Feature 是原子化的、可测试的、可组合的**：一个模型参数（temperature）、浏览器使用、长时记忆、加案例、加约束、思维链，都是 Feature。
4. **Skill 是 Feature 的封装逻辑**：Feature 是底层原子，Skill 是把原子打包后的可复用逻辑。
5. **Feature 思维让人不被工具带走**：新工具火不火不重要，重要的是它多了哪几个 Feature；不需要的就继续用现有工具。

## 二、原文依据

### 2.1 基本功的定义

> 「第三个我们说的基本功，说的是 AI 基本功啊，就是 AI 上的那些工具，那些特性。」（行 1210）

> 「比如说公司做一个分层的记忆系统，你会就是会不会就不会啊，所以说它是一些偏工具类的技术类的东西，我们叫基本功。」（行 1218）

### 2.2 工具迷信的反面例子

> 「我们用国外的模型做跑一轮，几万封一封信花了我们几万块钱……后来只要突然间想到了一个参数，他说好像有一个参数过去没用，我试一下。然后调了一个 temperature……跟国外模型一模一样。就一个参数。」（行 1380-1388）

> 「所以我们用了大概 40 分之 1 的成本，达到了跟全球最好的模型的水准，就靠调一个小的参数。」（行 1392）

### 2.3 Feature 思维的正式提出

> 「我没有在必修课里说，就是很多时候大家在学基本功上很容易陷入到一种叫做工具迷信和工具驱动？就是一直被工具带着走。」（行 1398-1400）

> 「所以最近我一直在鼓励大家用一种叫做特性思维，我叫 Feature 思维。Feature 已经变成现在一个高频词汇了。」（行 1402-1404）

> 「就是不要老盯着工具，你去盯着每一个工具那些特有的那些最小的技术特性。」（行 1408）

> 「比如说一个模型，一个参数，比如浏览器使用就是一个特性，长时记忆就是个特性，对吧？然后比如说给他加一个案例，给他加一个限制，给他加一个什么思维链，这些都是特性。」（行 1410-1412）

> 「我们要围绕着最小的特性去讨论和做决策，不要被限制在某一些工具的名字上。」（行 1414）

### 2.4 Feature 的组合与工具比较

> 「当有了特性思维，你会发现所有的工具其实你把它拆完之后，一共也就几十个特性，就在这些特性上不断工作就好了。」（行 1416）

> 「每一个特性都有可能让你实现 AB 测试的结果提升，但是就不要纠结于工具本身。」（行 1418）

> 「龙虾之所以火，是因为它有三四个核心特性，爱马仕又有那么一两个特性，口袋词又那么三四个特性。就是通过不断的特性组合形成一个好的结构，其他都不重要。」（行 1420-1424）

### 2.5 Feature 与 Skill 的关系

> 「特性是原子化的最小技术单位，叫可操作的原子化的最小技术单位。它跟 skill 是两套东西，skill 就是一个封装逻辑。」（行 1426-1428）

> 「AI 基本功第一课，很有可能我们主讲的就是这个特性思维。就是我们把所有的这些工具全打开了，打成特性清单。你们就沿着这些特性工作，不要老被那些工具带着走就好了。」（行 1440-1444）

### 2.6 系统思维的落脚点

> 「系统思维用 AI……你如果实在想说，你就去聊他的场景，他的数据，然后以及他的技术特性啊……他是多个特性组合出来的，很难说某一个东西就能做。」（行 1456-1466）

## 三、概念澄清

| 概念 | 定义 | 例子 |
|:---|:---|:---|
| **Feature（特性）** | AI 工具的最小可操作技术单位 | temperature 参数、浏览器使用、长时记忆、思维链、加案例、加约束 |
| **工具** | 把多个 Feature 打包后的产品 | ChatGPT、Coze、Cursor、Claude、Kimi |
| **Skill** | 把 Feature 按特定场景封装后的可复用逻辑 | 口喷提示词、PPT 渲染工作流、论文初审 Agent |
| **基本功** | 掌握 Feature 清单，并能根据场景组合 Feature | 知道什么时候调 temperature、什么时候加浏览器、什么时候用长时记忆 |
| **工具迷信** | 被工具名字带着走，忽略底层 Feature | 因为某个工具火了就切换，结果没用到新 Feature |

---

## 四、Feature 思维的实操价值

### 4.1 对个人：不被工具带走

- 新工具出现时，只问：「它比我现在用的工具多了哪几个 Feature？」
- 如果新 Feature 不是当前任务需要的，继续用旧工具。
- 如果新 Feature 能提升结果，快速迁移。

### 4.2 对团队：统一语言

- 团队讨论不再说「用大模型还是小模型」，而是说「这个任务需要温度调节 + 长上下文 + 浏览器使用」。
- Feature 清单成为团队选型、评估、AB 测试的共同语言。

### 4.3 对 Agent 设计：原子化能力

- Agent 的能力不应该按工具划分，而应该按 Feature 划分。
- 例如：一个 Agent 可以组合「思维链 + 长时记忆 + 工具调用」三个 Feature，而不是绑定到某个具体模型。
- 这样 Agent 可以随着工具升级无缝迁移。

### 4.4 对 KDO 建设

- 应该把热门工具拆解为 Feature 清单，沉淀为 concept/method/tool 卡。
- 避免 KDO 出现「追热点工具卡」而缺少「底层 Feature 卡」。
- 双三角画布中的「基本功」格子，未来可以填入 Feature 清单而不是工具列表。

## 五、常见 Feature 分类（示例）

| 类别 | Feature 示例 |
|:---|:---|
| **模型参数** | temperature、top_p、max_tokens、frequency_penalty |
| **上下文工程** | 长上下文窗口、RAG、长时记忆、摘要压缩 |
| **推理增强** | 思维链（CoT）、自我一致性、多路径推理 |
| **外部能力** | 浏览器使用、代码执行、文件读写、API 调用 |
| **输入增强** | 加案例（few-shot）、加约束、加角色、加输出格式 |
| **输出控制** | JSON 模式、结构化输出、Function calling |
| **多模态** | 图像理解、语音输入、视频分析 |
| **协作机制** | 多 Agent 并行、红蓝军对抗、迭代反馈 |

## 六、建议卡片结构：`concept-yihang-ai-feature-thinking`

1. **一句话定义**：Feature 思维 = 把 AI 工具拆成最小可操作技术特性，用特性组合而非工具名字来思考和决策。
2. **为什么重要**：避免工具迷信、降低切换成本、统一团队语言、让 Agent 能力原子化。
3. **Feature 与工具/Skill 的关系**：用三层澄清表。
4. **原文故事**：temperature 参数让成本降到 1/40 的案例。
5. **实操步骤**：
   - 列出当前任务需要的 Feature
   - 评估现有工具是否覆盖这些 Feature
   - 新工具出现时只比较 Feature 差异
   - 把常用 Feature 组合沉淀为 Skill
6. **常见陷阱**：工具迷信、Feature 堆砌、把 Skill 当 Feature、忽视 Feature 的适用边界。
7. **Critique**：
   - Feature 思维是否会让普通人更难入门？——不会，反而降低了认知负担，因为只需关注少量原子单位。
   - 是否所有工具都能拆成 Feature？——大多数可以，但某些整体化体验（如 Vibe Coding）可能难以完全拆解。

## 九、自攻击

- **反例**：某些工具的整体 UX 就是其价值，拆成 Feature 后可能丢失体验优势。
- **边界**：Feature 思维主要适用于技术类基本功；审美、创造力等人类三角能力不能完全 Feature 化。
- **成本**：维护 Feature 清单需要持续跟进工具更新，否则清单会过时。
