## 1. Anthropic Agent Skills 设计原则（2025-10 发布）

### 1.1 官方定位与时间线

- **2025-10-16** 发布工程博客《Equipping agents for the real world with Agent Skills》，正式定义 Agent Skills：`organized folders of instructions, scripts, and resources that agents can discover and load dynamically`。
  - URL: https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills
- **2025-12-18** 转为开放标准，成立 **agentskills.io**（Apache 2.0 + CC-BY-4.0），跨产品可移植。
  - URL: https://agentskills.io/ | https://github.com/agentskills/agentskills
- 官方示例仓库：https://github.com/anthropics/skills（docx/pdf/pptx/xlsx 生产级技能源码参考，document-skills 为 source-available 非开源）

### 1.2 SKILL.md frontmatter 规范（agentskills.io Specification，2025-12 版）

规格全文：https://agentskills.io/specification

| 字段 | 必填 | 约束 |
|---|---|---|
| `name` | ✅ | ≤64 字符；仅小写字母/数字/连字符；不得以连字符开头结尾、不得连续连字符；**必须与父目录同名** |
| `description` | ✅ | ≤1024 字符；描述做什么 + **何时用**；含触发关键词 |
| `license` | ❌ | 许可证名或捆绑 LICENSE 文件引用 |
| `compatibility` | ❌ | ≤500 字符；环境要求（产品/系统包/网络） |
| `metadata` | ❌ | 任意 k-v（如 author、version） |
| `allowed-tools` | ❌ | 空格分隔的白名单工具（实验性，如 `Bash(git:*) Bash(jq:*) Read`） |

目录结构约定：`SKILL.md`（必）+ `scripts/`（可执行代码）+ `references/`（按需读取文档）+ `assets/`（模板/图片/数据）。

### 1.3 核心设计原则：渐进式披露（Progressive Disclosure）

三层加载机制（原文明确）：
1. **第 1 层（~100 tokens）**：启动时仅加载所有已装技能的 `name + description` 进入 system prompt——这是"第一级渐进披露"，是触发决策的全部依据；
2. **第 2 层（<5000 tokens 推荐）**：任务匹配 description 时，agent 读取完整 `SKILL.md` 正文；
3. **第 3 层+**：SKILL.md 内按需引用 `references/`、`scripts/` 等附属文件。

规格硬性建议：**SKILL.md 保持 <500 行、body <5000 tokens**；引用文件保持一层深，避免深层嵌套引用链。附带官方校验工具 `skills-ref validate ./my-skill`（https://github.com/agentskills/agentskills/tree/main/skills-ref）。

### 1.4 何时建 skill vs 普通文档（最佳实践指南原文要点）

来源：https://agentskills.io/skill-creation/best-practices + https://agentskills.io/skill-creation/optimizing-descriptions

- **skill 的价值 = 弥补"agent 本来会做错"的知识差**："Focus on what the agent *wouldn't* know without your skill… Ask yourself: Would the agent get this wrong without this instruction? If the answer is no, cut it."
- **建 skill 的触发信号**：
  - 任务需要专业流程/组织专属上下文（公司规范、API 模式、边角案例）；
  - 多步骤可重复工作流（要变成一致、可审计的流程）；
  - 需要跨产品复用。
- **不该建**：通用知识（"agent already knows what PDFs are"——原文反例）；agent 凭基础工具就能完成的单步任务（"read this PDF" 不会触发 PDF skill——官方明确说明简单任务不触发）。
- **创作方法论（"从真实执行提炼"）**：
  1. 与 agent 协作完成真实任务，记录：**成功的步骤 / 你纠正它的地方 / 输入输出格式 / 你提供的上下文**；
  2. 或从项目真实产物合成（runbook、事故报告、review 评论、git 历史补丁）——"project-specific material, not generic references"；
  3. **每次纠正 agent 的错误，就把纠正写进 Gotchas 章节**（原文："When an agent makes a mistake you have to correct, add the correction to the gotchas section"）——这是最直接的迭代路径。
- **写作技巧**：Gotchas 章节、输出格式模板（放 assets/ 按需加载）、多步流程 checklist、验证循环（自校验通过才继续）、Plan-Validate-Execute 模式（批/破坏性操作先出计划 JSON → 校验脚本核对 → 再执行）；**给默认方案而非菜单**（"Provide defaults, not menus"）；**教方法而非具体答案**（"Favor procedures over declarations"）。
- **描述优化**（独立专文）：imperative 句式（"Use this skill when…"）；聚焦用户意图而非实现；宁可"pushy"（"even if they don't explicitly mention 'CSV'"）；用 ~20 条查询（8-10 应触发 + 8-10 不应触发，其中负面用例要选 **near-misses 近似干扰项**）测触发率，3 次/条，阈值 0.5；**train/validation 6:4 划分防过拟合**；约 5 轮迭代足够。URL: https://agentskills.io/skill-creation/optimizing-descriptions
- **Eval 驱动迭代**（专文）：`evals/evals.json` 存测试用例（prompt + expected_output + files）；**每次跑 with_skill / without_skill 基线对照**；断言要对具体可验证事项（"chart has labeled axes"），不要"output is good"；记录 `timing.json`（token/duration）评估成本收益；LLM 分级 + 人工复核 + 执行轨迹（transcripts）三方信号喂给 LLM 提改进。官方提供 `skill-creator` skill 自动化此流程（https://github.com/anthropics/skills/tree/main/skills/skill-creator）。URL: https://agentskills.io/skill-creation/evaluating-skills
- **安全**：只装可信来源 skill；装前审计捆绑代码/依赖/外部网络指令（工程博客原文）。

### 1.5 未来方向（官网原文）

"we hope to enable agents to **create, edit, and evaluate Skills on their own**, letting them codify their own patterns of behavior into reusable capabilities"——Agent 自我生成技能是官方规划方向。

## 2. OpenAI 对 Agent 工具/技能管理的建议

### 2.1 官方码产品实践（可实证）

## 3. 编码 Agent 的 Skills/Rules 最佳实践（AGENTS.md / CLAUDE.md / Cursor .mdc）

### 3.1 AGENTS.md 生态（60k+ 项目）

https://agents.md/ 实证要点：
- **定位**：README 是给人类的；AGENTS.md 是给 agent 的"README"，集中放构建步骤、测试命令、代码约定，"keep READMEs concise"。
- **结构建议**：Setup commands（装依赖/起 dev/跑测试）+ Code style（TypeScript strict、单引号、函数式）。
- **多文件支持**：AGENTS.md + AGENTS-extra.md 层级、子目录局部 AGENTS.md 覆盖。
- 关键设计哲学：**一个 AGENTS.md 跨 30+ 工具工作**（Codex、Gemini CLI、Copilot、Cursor、Windsurf、Zed、Aider、goose、opencode 等），是"反厂商锁定"的标准路线。

### 3.2 CLAUDE.md / 记忆（Claude Code）

来源：Anthropic 上下文工程文（https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents）原文：
- "CLAUDE.md files are **naively dropped into context up front**, while primitives like glob and grep allow it to navigate its environment and retrieve files just-in-time"——即 **混合策略**：核心记忆文件预载 + 文件系统按需探索（just-in-time retrieval）。官网记忆文档：https://code.claude.com/docs/en/memory（域名被墙，未直接抓取，内容以工程博客实证为准）。
- 记忆多级机制：`CLAUDE.md`（项目常驻记忆）→ `~/.claude/CLAUDE.md`（用户全局记忆）→ `claude --continue` 会话恢复。社区域名：http://claude.md。
- 用户级 skills 存储 `~/.claude/skills/`，与我的 `~/.hermes/skills/` 结构同构。

### 3.3 Cursor Rules（专文全文实证）

来源：https://cursor.com/docs/context/rules（全文已抓取）：
- **四种规则**：Project Rules（`.cursor/rules/*.mdc`，git 版本化，path-scoped）、User Rules（全局）、Team Rules（团队仪表盘，Team/Enterprise 版）、**AGENTS.md**（"Simple alternative to .cursor/rules"）。
- **.mdc frontmatter 三字段触发矩阵**（原文表）：
  - `alwaysApply: true` → 每次会话都注入；
  - `globs: src/**/*.tsx` → 文件匹配时自动附加；
  - `description`（无 globs）→ agent 读描述自行判断相关性拉取；
  - 都缺 → 仅 @-mention 手动触发。
  - **纯 .md 在 .cursor/rules 里被无视**（无 frontmatter 无法声明 description/globs/alwaysApply）。
- **Best practices（原文）**：规则 <500 行；**大规则拆成多个可组合小规则**；给具体例子或引用文件；**引用文件而非复制内容**（防止随代码演进过时）；重复出现的 prompt 才固化成规则。
- **What to avoid**：不要复制完整 style guide（用 linter）；不要枚举 agent 已知命令（npm/git/pytest）；不要为罕见 edge case 加指令。
- **Claude Skills 集成**：Cursor 已原生支持 Agent Skills 格式（clients.md 列示，https://agentskills.io/clients）。

## 4. Agent 自我进化 / 自我反思机制

### 4.1 记忆分层（Anthropic 上下文工程文，实证）

长期任务三大技术，按任务类型选型：
1. **Compaction（压缩）**：上下文将满时让模型总结关键信息（保留架构决策、未解 bug、实现细节；丢弃工具输出冗余），重开新窗口续跑。调优法：先用高召回 prompt 测复杂轨迹，再提精度。
2. **Structured note-taking（结构化笔记 = agentic memory）**：agent 定期把 notes 写到上下文之外（NOTES.md 模式），后期拉回。**例证**：Claude 玩 Pokémon 直播——无任何记忆 prompt，agent 自发记地图/成就/战斗策略，跨上下文重置延续数小时的策略（https://www.twitch.tv/claudeplayspokemon）。Claude Developer Platform 已发布 memory tool（文件系统式，https://www.anthropic.com/news/context-management）。
3. **Sub-agent 架构**：主 agent 持高层计划，子 agent 各自独立探索（可耗数万 token）后只回传 1000-2000 token 的压缩摘要。

### 4.2 复盘循环与技能迭代频率（最可操作的官方流程）

- **官方标准循环**（agentskills.io evaluating-skills）：**执行→分级→人工复核→LLM 提改进→下一轮迭代**，四信号驱动：failed assertions + human feedback + execution transcripts（+"always pass in both"的无效断言要删）。停止条件："feedback is consistently empty, or no meaningful improvement between iterations"。**频率建议**：2-3 个测试用例起步（"Don't over-invest before you've seen your first round of results"），复杂领域多轮；描述优化约 5 轮。
- **Anthropic 官方四步技能迭代法**（工程博客原文）：① Start with evaluation（先找能力缺口）；② Structure for scale（SKILL.md 臃肿就拆分引用）；③ Think from Claude's perspective（观察真实使用轨迹，警惕过度依赖某段上下文）；④ **Iterate with Claude**——"ask it to self-reflect on what went wrong. This process will help you discover what context Claude actually needs, instead of trying to anticipate it upfront."
- **让 agent 自我改进有官方成功数据**：多 Agent 研究系统文中（https://www.anthropic.com/engineering/multi-agent-research-system）——Claude 4 模型是"excellent prompt engineers"，给定 prompt+失败模式能自我诊断；其 tool-testing agent 反复测试 MCP 工具并**重写工具描述，使后续 agent 任务完成时间降 40%**。原文金句："Let agents improve themselves."
- **OpenAI 系对应物**：Codex 的 AGENTS.md 硬性上下文纪律（bounded size、10K cap）+ Agents SDK tracing 构成"可观测→定位瓶颈→改工具描述/指令"的回路。

### 4.3 记忆分层落地的可操作建议（综合）

- **工作记忆**（单任务，token 预算内）：plan 文件、checklist、NOTES.md；
- **项目记忆**：CLAUDE.md / AGENTS.md / 项目级 rules——预载但保持"最小高信号"（Anthropic 上下文工程核心原则："find the smallest set of high-signal tokens…"）；
- **长期技能库**：~/.claude/skills 或 ~/.hermes/skills 等按需加载（渐进披露）；
- **硬上限纪律**：注入片段 ≤10K tokens（Codex 规则）、SKILL.md <500 行（Agent Skills 规格）、description ≤1024 字符。

## 5. 多 Agent 架构下的技能共享与版本管理

### 5.1 官方可操作机制

- **插件市场 = 技能分发**：`anthropics/skills` 仓库可作为 Claude Code **Plugin Marketplace** 安装（`/plugin marketplace add anthropics/skills` → `/plugin install document-skills@anthropic-agent-skills`）——这就是"技能中心"的官方形态：**git 仓库 + 语义化插件包 + 市场索引**。团队可自建私有 marketplace。URL: https://github.com/anthropics/skills
- **开放标准保证跨产品复用**：Agent Skills 已开源 + 多客户端支持（agentskills.io/clients 列示，含 VS Code、Cursor 等），"build once, use across any skills-compatible agent"。
- **skills.sh 徽章**：anthropics/skills README 头部 `[![skills.sh](https://skills.sh/b/anthropics/skills)](https://skills.sh/anthropics/skills)`——第三方技能分享/发现平台（skills.sh）已存在，可作为公共"能力中台"候选。

### 5.2 多 Agent 协作实证架构（Anthropic 多 Agent 研究系统）

- **orchestrator-worker 模式**：lead agent 规划→并行 spawn 子 agent→子 agent 独立上下文探索→返回压缩摘要→lead 综合；CitationAgent 独立做引用定位。
- **分工提示词要求**（原文）：每个子 agent 需要 **objective + output format + 工具/来源指引 + 明确任务边界**，否则子 agent 重复劳动或互相干扰。
- **"电话游戏"对策**（附录原文）：**子 agent 输出直接写文件系统**，传轻量引用给协调者，避免大输出经对话历史层层转录丢信息——多 Agent 共享产出物的关键模式，"Subagent output to a filesystem to minimize the 'game of telephone'"。
- **成本实证**：多 Agent 系统 token 消耗约为 chat 的 15×，仅适合高价值+可并行任务；编码类任务并行度低，不太适合。
- **规模化经验**：多 Agent eval 用 end-state 评估而非逐步骤核对；rainbow deployments 灰度发布避免打断运行中 agent；好 prompt 不是死指令而是"collaboration frameworks"（分工/方法/算力预算）。

### 5.3 面向五绝架构的落地建议

- 公共技能库用 git 仓库 + 每个 skill 独立目录（SKILL.md 规范兼容）；
- 技能版本靠 `metadata.version` + git 历史 + `skills-ref validate` 门禁；核心卡片生产技能放共享 repo，各 bot 按需启用（metadata 字段做"适用 agent"标记）；
- 跨 bot 产出物走文件系统引用而非对话内传输（参考电话游戏对策）；
- 描述字段用统一触发词体系（KDO/卡片/生产等），保 near-miss 互斥，防多 bot 误触发。

## 关键结论（浓缩）

1. **技能本质 = 程序性知识打包**，触发靠 description 前瞻、内容靠渐进披露，`SKILL.md <500 行` 是硬纪律；
2. **建技能的门槛 = agent 没有它就会做错**；素材来自真实任务纠错而非凭空想象；
3. **迭代闭环 = eval（with/without 对照）→ 断言分级 → 人工复核 → LLM 提改**，描述优化另配 20 条触发测试 + train/val 防过拟合；
4. **记忆分层 = CLAUDE.md/AGENTS.md 预载 + 笔记外置 + 按需技能加载 + ≤10K token 注入上限**；
5. **多 Agent 共享 = 开放标准技能格式 + plugin marketplace 分发 + 文件系统传递产出**；
6. **让 agent 自我进化有官方实证**：自我反思 → 把纠错写进 Gotchas → 重写工具描述（-40% 时间）→ skill-creator 自动化。
