# 口语化润色 + 配图（Step 7-8）

Candy 九步法第 7-8 步。结构稳定后才润色——润色不是重写，是让文字"读出声来也不别扭"。

## Constraints

<hard_limits>
- 框架没定型之前不碰文字
- 不改有力量的原句——润色的敌人是过度润色
- 保留人设和态度，不要磨平成公众号味
</hard_limits>

## Step 7: 配图是结构

**每张图回答一个问题——不是"这一段需要配图"，是"这个认知需要导航"**

| 图类型 | 承担的功能 |
|:--|:--|
| 路线图 | 告诉读者今天怎么走 |
| 结构图 | 解释层级关系 |
| 对比图 | 展示差异 |
| 流程图 | 展示步骤 |
| 数据图 | 让数字可感知 |

**配图工作流**：
1. 写稿时留图片占位
2. 图片下方保留中文提示词
3. 生成后上传 CDN
4. 最终用外链，不用本地路径

## Step 8: 口语化润色

### 七条原则

| # | 原则 | 对比 |
|:--|:--|:--|
| 1 | **短句有呼吸感** | ❌ "在实际工作场景中我们常遇到各种问题" → ✅ "工作里，你会碰到各种问题" |
| 2 | **口语连接词** | ❌ "首先...其次...最后" → ✅ "先说...然后...最后就是" |
| 3 | **场景先于道理** | ❌ "注意力是稀缺资源" → ✅ "你有没有这种感觉——刷了一下午手机，啥也没记住？" |
| 4 | **术语后人话** | ❌ "通过结构化提问实现认知降熵" → ✅ "说白了就是——你会提问，就不会瞎想" |
| 5 | **保留人设** | ❌ 把所有"我觉得"改成"笔者认为" → ✅ 保留口语习惯 |
| 6 | **不改有力量的原句** | 如果原句已简洁有力，不要"为了润色而改" |
| 7 | **结构稳定后才润色** | 框架没定型不碰——否则改完框架白润色 |

### Agent 润色指令
```
对以下文本执行口语化润色。严格遵循：
1. 句长 ≤25 字为主
2. 每段 ≤3 句
3. 术语后紧跟"说白了就是..."
4. 先场景后道理
5. 保留原文有力量的原句不动
6. 不改结构——只改表达
```

## 常见失败

| 症状 | 根因 | 修复 |
|:--|:--|:--|
| 润色后不像自己写的 | 过度润色 | 回滚，只改最生硬的 20% |
| 配图像装饰 | 没回答"这张图承担什么功能" | 删掉重做——每张图必须有一个认知功能 |
