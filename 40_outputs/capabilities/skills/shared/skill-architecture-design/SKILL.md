# Skill 架构设计模式（Anthropic 范式执行版）

最高级的 skill 设计不是写文字，是**设计一个稳定的控制系统**——从"写 Prompt"到"写固件"。按本 skill 执行：自由度评估→范式选型→四层架构→宪法自检→量化评价。

**与 `tool-ai-skill-engineering-guide` 的分工（不撞车）**：那卡是流程向（怎么用 AI 辅助把素材封装成 skill 的工作流：素材→打包→注册）；本 skill 是设计向（封装前怎么定架构：自由度/范式/结构/评价）。生产一个新 skill：先用本 skill 定架构，再走工程指南卡跑流程。

## 触发条件

- 设计新 skill 的架构（还没动笔写 SKILL.md 时的选型阶段）
- 评审存量 SKILL.md 的结构（主文件膨胀/范式错配诊断）
- 写 skill 的 description（触发 SEO）与质量评估

**不触发**：一次性提示词（维护成本>重复成本，直接写）；charter 全自动红线覆盖的永久人审场景（自治设计与红线冲突，人审节点保留）；未验证触发场景的新技能（先积累 3+ 真实使用样本再固化）。

## 操作步骤

### 第一步：自由度评估（先于一切选型）

问：这个任务是"悬崖窄桥"还是"开阔平原"？
- 高自由度任务（文案/头脑风暴）→ 文字引导
- 中自由度（报告/表格）→ 模板+占位符+定点填充
- 极低自由度（格式转换/精确计算）→ 外挂脚本，不让 AI 猜

### 第二步：范式选型（选型口诀）

越模糊越往 3/4 走（人机协同），越精确越往 2/5 走（脚本与侦察），规模化生产往 6/7 走：

| # | 范式 | AI 角色 | 适用 |
|:--|:--|:--|:--|
| 1 | 分拣路由 Navigator | 分拣员 | 多格式报告、多品牌规范、政策查询 |
| 2 | 黑盒工具链 Operator | 操作员 | 格式转换、像素级图形、自动打包 |
| 3 | 协同共创 Partner | 合伙人 | 深度文案、战略规划、商业提案 |
| 4 | 双步创构 Philosopher | 哲学家 | 顶奢前端设计、生成艺术 |
| 5 | 侦察与行动 Scout | 侦察兵 | 网页测试、动态 UI、环境调试 |
| 6 | 元工程化 Architect | 总建筑师 | 构建 Skill 本身、MCP 服务 |
| 7 | API 联动 Orchestrator | 调度中枢 | 生产级 Agent 集群、CI/CD |

> 范式表是**描述性地图**（定位存量 skill）而非规定性清单（新 skill 不必七选一）；范式间可组合（如 Scout+Operator）。主判据永远是第一步的自由度匹配。

### 第三步：四层模块架构生产

1. **身份与加载层**：YAML description 三句话写清"我是什么/解决什么/独家工具"（决定被路由点将的概率）；初始对话协议强制确认"我准备分 X 步走预期 Y，是否现在开始？"
2. **逻辑与智能层**：核心执行原则设护栏；分阶段工作流用 Exit Criteria 守关口；强制"交作业前先扮演挑刺者（列 3 个技术缺陷并修 1 个）"
3. **执行与工具层**：黑盒脚本封装（禁读脚本源码，只读 --help）；外科手术式编辑（str_replace 定点修改，拒绝全量重印）；先侦察再行动（严禁盲猜环境状态）
4. **资源与支撑层**：references/ 离线知识库；examples/ 满分作业锚点；自动化评估（QA Pairs 验证鲁棒性）

**500 行护栏**：主文件正文控制在数百行内，长内容切 references/ 按需借调；全篇祈使句。

### 第四步：执行宪法自检（高杠杆 8 条）

To-Do：description SEO（工具名+3 触发场景短语+产出物属性）／外科手术式编辑指令／初始对话协议／递归"读者"验证（无记忆新实例试读）
Not-To-Do：严禁猜测环境状态／严禁模糊形容词（改具体参数或对比标杆）／严禁单次全量重印／严禁无反馈的一股脑生成（关键决策点设人类中断器）

### 第五步：量化评价

| 维度 | 水准线 |
|:--|:--|
| 触发准确率 | >90%（改述请求仍精准触发——description SEO 成败线） |
| ZSAR 无修改采纳率 | 85%（15% 错误用 Prompt Patch 靶向修，不整体重刷） |
| 工具调用效率 | 高阶 skill 应降 30%+ 往返次数 |
| Token 节省率 | 远低于对话重复粘贴 prompt |
| 自治治理等级 | C（每步确认）→B（AI 写人审）→A（自动执行抽检）→S（自回归闭环） |

## 失败模式表

| 失败 | 症状 | 修复 |
|:--|:--|:--|
| 主文件膨胀 | SKILL.md 塞全部规则，触发后吃光上下文 | 500 行护栏+references 按需借调 |
| 范式错配 | 创意任务给铁脚本/精确任务给自由引导 | 回第一步重评自由度 |
| 触发 SEO 失败 | 用户要显式点名才能唤醒 | description 重写+改述请求自测 |
| 全量重印 | 每次修改重输出整个文档 | 显式写入"只用 str_replace 定点编辑" |
| 作者诅咒 | 假设 AI 知道团队内幕 | 补信息倾倒阶段+无记忆新实例递归验证 |

## 适用边界

- 适用：skill/SOP/Agent 提示词工程的**架构设计阶段**；skill 生产的前置对标
- 不适用：一次性提示词；永久人审合规场景（只做预处理）；未验证触发场景的新技能
