# 多研究员交叉研究（multi-researcher-cross）

> **定位**：本 skill 是 `[[workflow-multi-researcher-cross]]` 的可执行件。工作流卡讲"为什么与何时"，本文件给"照着跑的三件套"——研究员画像池、任务书模板、合并裁决规则。
> **来源**：AI大航海 2026-09-05 金矿 A60-A62（`00_inbox/AI大航海20260905/AI实战路径-五个层级全解析-口述.txt:368-408`）——Truman 单角色研究发现"研究总是有自己的偏好和狭窄性，而且 AI 本来就是概率很随机"，于是假设：把课程地图拆成 10 个背景/信息/目标/思维方式/立场都不同的研究员，挑 3-5 个分头研究再合并交叉，总报告显著更好。

## Constraints

<hard_limits>
- 研究员画像必须**按课题域相关性策展**，不是凑数量——业界实证（arXiv:2311.17371 MAD benchmark）显示域无关的任意画像与无条件唱反调会**降低**准确率
- 反方/审计型研究员必须**门控触发**：仅当 ≥2 名研究员已独立得出一致结论时才准提反例（见裁决规则 R4）
- 冲突**不许平均**：两个研究员结论相反时，不允许写"取中间值/综合来看各有利弊"——必须回到锚点裁决，锚点裁决不了就升级给人
- 每条任务书必须过 A62 信息完整性门（见 §3），省 Token = 研究员自由发挥 = 交叉失效
- 本 skill 产出的是**研究报告**，不产出知识卡；要攻击已有知识卡用 `kdo-self-attack`（互补，见 §6）
</hard_limits>

## 1. 何时用 / 何时不用

**用**：
- 课题是判断题或开放题，不是检索题（"X 值不值得做"而非"X 的定义是什么"）
- 单角色答过一次，但你怀疑答案有偏好或太窄
- 结论要拿去做资源投入决策，错一次成本高

**不用**：
- 事实检索（一个 `kdo query` 能答的）——多研究员是浪费
- 对已有知识卡找漏洞——用 `kdo-self-attack`（对抗攻击，非并行研究）
- 两个 Agent 在同一事实上的口径争议——用 `[[workflow-cross-agent-fact-dispute]]`（事后裁决协议）

## 2. 研究员画像池（10 张，按 AI for Business 能力地图策展）

> 用法：拿到课题后从池中挑 3-5 张。挑选标准=**这张画像的背景/信息源/目标/思维方式/立场，对这道题会产生真实分歧**——如果两个画像大概率给出相同答案，只留一个。
> 画像只写在提示词里（同通道多实例即可，不需要多供应商）。每张画像三要素：**看什么 / 不信什么 / 产出什么**。

| # | 画像 | 看什么（信息源偏好） | 不信什么（立场） | 产出什么 |
|:--:|:--|:--|:--|:--|
| P1 | 商业模式建筑师 | 价值链、收费点、成本结构 | 不信"用户体验好就能赚钱" | 变现路径与成本图 |
| P2 | 需求分析师 | 表面诉求之下的真问题（冰山） | 不信用户口述的需求 | 真需求判定 + 反证 |
| P3 | 决策心理师 | 决策者动机、认知偏差、Y模型 | 不信"理性人假设" | 动机-诉求-本质三问结果 |
| P4 | 增长操盘手 | 获客渠道、转化率、分发断点 | 不信"产品好自然增长" | 增长杠杆与断点清单 |
| P5 | 壁垒审计师 | 护城河、可复制性、竞争位 | 不信"先发优势" | 可防御性评估 |
| P6 | 财务裁判 | 单位经济、ROI、现金流 | 不信"规模故事" | 数字账 + 待核实标注 |
| P7 | 交付运营工程师 | 流程、执行成本、失败模式 | 不信"方案对就行" | 落地步骤与卡点 |
| P8 | 反方案例审计师 | 反例、失败案例、边界条件 | 不信"任何无反例的结论" | 反例清单（须门控，见 R4） |
| P9 | 一线用户声音 | 真实使用者反馈、场景细节 | 不信"官方口径" | 场景级证词 |
| P10 | 组织与人事 | 谁来干、能力是否匹配、激励 | 不信"工具能替代人" | 承接能力判定 |

> **出处锚**：P8 门控、画像按域策展两条来自外部实证（arXiv:2311.17371 "devil's advocate design often hurt performance"；persona curation 须域相关）。其余 9 张为本厂 AI for Business 能力地图（战略/需求/决策/洞察/模型/增长/壁垒/产品）落到研究角色的实例化。【推断】画像与能力域的映射是本厂设计选择，非业界标准，可在使用中迭代。

## 3. 任务书模板（A62 信息完整性门内置）

> 给编排者（你或你的主 Agent）用。Truman 原话："它写了一个完整的任务说明书，把我的问题翻译成了一个给各个研究员的任务书。我又补了一个信息：**不要省 Token，保证完整，不要丢三落四，一定要把信息传清楚**。"（口述稿 L380）

```markdown
# 研究任务书：<课题名>

## 0. 你的画像（逐字抄入，不得缩写）
你是【P<N> <画像名>】。你看<…>，你不信<…>，你要产出<…>。
在你的整个回答中保持这个立场，不要滑向中立综述。

## 1. 课题与子问题（全量列出，一个不省）
主问题：<一句话>
子问题 1：<…>
子问题 2：<…>
（Truman 实操：列 3-4 个他真正关心的子问题）

## 2. 边界条件（明确"不研究什么"）
- 时间尺度：<…>
- 排除项：<…>
- 已知前提（不得重新论证）：<…>

## 3. 信息源与检索指令
- 必查：<知识库路径 / 数据源清单>
- 检索方式：<kdo query 关键词 / grep 锚点 / WebSearch>
- 查不到就写"未找到+已试过的检索词"，**禁止**凭印象补全

## 4. 交付格式（逐项对齐，缺一项=退回）
- 结论 ≤5 条，每条标注【实证/推断/猜测】（三级标注，实证须附文件:行号或 URL 锚）
- 证据表：结论 ↔ 锚点 ↔ 可信度
- 你这个画像特有的反例或边界：≥1 条
- 与主流认知不一致的地方：明确标出（没有就写"无"）

## 5. A62 信息完整性门（提交前自检，逐条打勾）
- [ ] 子问题全量回答，没有跳过任何一个
- [ ] 没有为了简洁而省略推理过程
- [ ] 所有数字都带出处
- [ ] 所有"没有/不存在"类负向判词都附了检索锚点
- [ ] 信息传清楚了：一个没参与讨论的人只读你的报告能复述你的结论
```

> **A62 门是硬门**：编排者在合并前回读每份研究员报告，第 5 节任一项未满足 → 退回该研究员补跑，不进合并池。Truman 的原话是发给 Agent 的信息完整性嘱咐，此处固化为可校验清单。

## 4. 合并裁决规则

> 合并 ≠ 摘要拼接。Truman 案例里编排者"合并这些多个角度合并同类项"，形成的是**事实分析 → 规律洞察 → 应用设想**的分层报告，不是六份报告的堆叠。

**R1 同类项对齐**：把各研究员的结论按主题（不是按人）重排。同一主题下并列所有研究员的说法，标注各自的置信级别和锚点。

**R2 三级标注贯穿**：合并报告里的每一条关键判断，继续带【实证/推断/猜测】。研究员标【推断】的，合并者不得擅自升格为【实证】。

**R3 三种关系，三种处理**：
| 关系 | 判定 | 处理 |
|:--|:--|:--|
| 共识 | ≥2 名研究员独立命中同一结论 | 可进正文主张。**但先查同源偏置**：如果他们都只引了同一份材料，这不算独立验证，降级为单源 |
| 互补 | 各说各的、拼起来才完整 | 拼图，标注每块由谁覆盖；这是多视角研究**最常见也最有价值的产出** |
| 冲突 | 结论直接相反 | **禁止平均**。回到锚点裁决（原始材料/数据）；锚点裁决不了 → 明确写"两说并存，裁决需 <具体决策者>"，把问题交还给人 |

**R4 反方门控**：P8（反方案例审计师）只在 **≥2 名研究员已独立得出一致结论**之后才允许提出反例，且反例必须附存在性核查锚点（ Constitution 第二条）。原因：业界实证显示无条件唱反调会拉低整体准确率——反方的价值是检验已形成的共识，不是制造分歧。

**R5 单源隔离**：只有一名研究员提出、无人印证的结论 → 单独放"待验证"区，不进正文主张，不进执行建议。

**R6 报告分层**（对齐 Truman 案例产出结构）：
```
1. 原始任务书（保留，可追溯）
2. 各研究员任务书 + 各自报告（全文，不删减）
3. 事实分析（R1 对齐 + R3 处理结果）
4. 规律与洞察（事实之上的一层抽象）
5. 应用设想 / 决策建议（标注每条建议由哪个视角支撑）
```

## 5. 操作步骤（编排者视角）

1. **判型**：这是判断题吗？（§1）不是 → 停，改用单角色检索。
2. **挑画像**：从池中挑 3-5 张，写下"为什么是这几张、他们会在哪道子问题上分歧"。写不出分歧点 = 挑错了，重挑。
3. **写任务书**：套 §3 模板，每名研究员一份，画像节逐字抄入。
4. **过 A62 门**：对每份任务书跑 §3 第 5 节自检。
5. **并行下发**：3-5 个实例同时跑（Truman 实测：单个研究员 10-20 分钟）。**先并行后串行**——不要串行等待。
6. **回读校验**：每份报告过 §3 第 5 节 A62 门，不合格退回。
7. **合并裁决**：按 §4 R1→R6 执行。
8. **交人**：报告 + 遗留冲突清单一起交，冲突不藏着。

## 6. 适用边界（与相邻能力的关系）

| 能力 | 解决什么 | 区别 |
|:--|:--|:--|
| `research-multi-agent` | 多 Agent **架构选型**（Supervisor/Swarm/Pipeline/Hybrid） | 它回答"用什么拓扑组织 Agent"；本 skill 回答"怎么用立场多样性产生更好的研究"。本 skill 的编排拓扑默认 Supervisor 型，详见该 skill |
| `kdo-self-attack` | **攻击已有知识卡**找逻辑/证据漏洞 | 交叉=多视角并行研究（产出前）；攻击=对抗性验证（产出后）。同一张卡可以两者都过：先交叉研究产出，再自攻击检验 |
| `research-cross-validation` | 对**单一结论**做多源交叉验证 | 交叉验证是"一条信息真不真"；本 skill 是"一个课题怎么看全" |
| `[[workflow-cross-agent-fact-dispute]]` | 两个 Agent 在**同一事实上口径不一**的事后裁决 | 它是争议裁决协议；本 skill 的 R3 冲突处理在锚点裁决不了时可升级到该协议 |

## 7. 失败模式（具体症状 + 修复）

| 症状 | 根因 | 修复 |
|:--|:--|:--|
| 五份报告读完像一份，交叉没产生增量 | 画像挑重了（背景/思维方式实际相同） | 回到步骤 2：写下每张画像的**预期分歧点**，写不出的换掉 |
| 研究员各自编数据、结论漂亮但查无出处 | 任务书没写检索指令，或 A62 门没跑 | §3 第 3 节"查不到就写未找到"是硬约束；合并前回读第 5 节 |
| 合并报告变成"综合来看各有利弊" | 触犯了 R3 禁止平均 | 强制走锚点裁决；裁决不了的写明升级给谁 |
| 反方研究员把共识全盘推翻，报告没法收口 | 触犯了 R4 门控 | 反方只在 ≥2 人共识形成后介入，且反例须附锚点 |
| 报告交了，人不知道下一步该干嘛 | 漏了 R6 第 5 层（应用设想） | 第 5 层每条建议标注支撑视角，无视角支撑的建议删掉 |
| 研究员把任务书里的"已知前提"重新论证了一遍，浪费时间 | 边界条件没写清 | §3 第 2 节明确"不得重新论证"清单 |

## 8. Critique

- **成本真实存在**：Truman 实测单研究员 10-20 分钟，5 人并行也是 10-20 分钟墙钟时间，但 token 成本是单角色的 3-5 倍。对检索题用这套是纯浪费——判型（步骤 1）是整个流程最便宜也最关键的一步。
- **业界对 MAD 的批评同样适用于本 skill**：arXiv:2311.17371 发现多智能体辩论未必优于 Self-Consistency（并行采样+多数投票）。本 skill 的辩护是：它针对的是**视角覆盖不足**而非**推理不稳定**——Self-Consistency 解决"同一视角采样方差"，本 skill 解决"单一视角结构性盲区"。但若你的问题只是后者不成立，先用 Self-Consistency 更便宜。
- **"10 选 3-5"的 10 是 Truman 课程地图的产物，不是普适常数**。本厂的 10 张画像池对应 AI for Business 能力地图，换一个厂这个数字会变。关键不是 10，是"池中画像两两之间存在真实分歧点"。
- **画像提示词可能造成表演性立场**：Agent 可能"扮演"一个投资人但没有投资人的真实判断力。缓解：画像只改变**看什么和不信什么**（信息源与怀疑点），不要求画像具备其不具备的专业能力（如不要求 P9 具备财务建模能力）。
