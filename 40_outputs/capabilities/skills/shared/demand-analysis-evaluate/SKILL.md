# 需求评估：真伪 × 大小 × 紧迫

评估三角形 + 四种力量建模。不只是"有没有需求"，是"值不值得做"。

## 评估三角形

| 维度 | 判断标准 | 红灯信号 |
|:--|:--|:--|
| **普遍性** | 目标用户中有多少人遇到这个问题？ | <5%的目标用户 |
| **频次** | 用户多久遇到一次？ | <每月1次 |
| **刚性** | 用户愿意付多少钱解决？ | "挺好的但不太想付费" |

### 评分

每维 1-5 分。总分 ≥12 且无单维=1 → 值得做。

### 常见误判

| 误判 | 表现 | 案例 |
|:--|:--|:--|
| 频次高估 | 觉得"天天都要"但其实1月1次 | 麦家小馆人才选拔——以为天天招人，实际季度 |
| 刚性误判 | 用户说"很重要"但不付费 | 少儿财商教育——家长说重要但不愿付 |
| 普遍性误判 | 把"我身边"当成"全市场" | 四线家政——身边的阿姨≠全城需求 |
| 天花板误判 | 市场很小但以为很大 | 偏远县域5G——人口基数太小 |

## 四种力量建模

用户切换产品时，四种力量在博弈：

| 力量 | 方向 | 关键问题 |
|:--|:--|:--|
| **推力** | → 离开旧方案 | 旧方案最让用户痛苦的2个点？ |
| **拉力** | → 选择新方案 | 新方案超出的2个核心收益？ |
| **焦虑** | ← 阻止切换 | 用户对新方案最担心的2个点？ |
| **习惯** | ← 阻止切换 | 用户对旧方案的惯性依赖？ |

### 切换公式

```
切换概率 = (推力 × 拉力) / (焦虑 × 习惯)

如果 焦虑 + 习惯 >> 推力 + 拉力 → 用户不会切换
```

### 四种力量分析模板

```
用户：[画像]
当前方案：[用户现在怎么解决]

推力：1... 2...
拉力：1... 2...
焦虑：1... 2...
习惯：1... 2...

结论：推力+拉力=[X] vs 焦虑+习惯=[Y] → [判断]
```

## 执行流程

```
需求假设
  ↓
评估三角形（普遍性/频次/刚性）
  ↓
四种力量建模（推/拉/焦虑/习惯）
  ↓
综合判断：值得做 / 需要更多验证 / 放弃
```
