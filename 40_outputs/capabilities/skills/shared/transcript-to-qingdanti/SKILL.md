# 口述稿 → 清单体笔记（transcript-to-qingdanti）

> 把课程逐字稿、会议记录、访谈稿、直播回放稿重组为可一分钟扫读的清单体笔记。
> 本质：**结构重组，不是再创作**。删字不删信息，挪序不改原意。
> 标准源：`00_inbox/一堂-AI时代清单体笔记-Truman-口述-01.txt`（122KB 全稿）+ 训练段位图/系统故事线结构化件 + yt-note 卡族。

## 触发词

清单体、清单体笔记、把这段逐字稿整理成清单、口述稿转笔记、 transcript-to-qingdanti 、一堂笔记法

## 两步法定位（v1.1，老朱 09-04 定稿）

清单体笔记生产分两步，本 skill 只管第二步：

| 步 | 内容 | 归属 |
|:--|:--|:--|
| 第一步 | **接收→门禁验收**：W6 三方法 + 暗知识全挖，用清单体枚举防漏（管信息增量） | 另轨（深挖管线），不在本 skill 范围 |
| 第二步 | **清单体整理**：结构层重组——分层/编号/重点前置/闭环（管可达性） | **本 skill** |

> 王语嫣实测背书：清单体改可达性、不改增量。本 skill 不承诺挖出更多内容，只承诺把已有内容整理成可扫读的 L4 级清单笔记。第一步没做完的稿子进入本 skill，产出的是"结构漂亮的信息残缺品"——D1/D2 会在 rubric 里把它打回去。

## 红线（先读，违反=交付无效）

1. **不改变原意、不创造内容**：笔记里的每个判断、数字、结论都必须能在原文找到出处。作者的口误保留原意可顺句，但不得升级成原文没有的论断。
2. **长稿分段处理防截断**：超过单次处理能力的稿子先按话题切段，逐段重组，最后合并+对账，禁止一把梭。
3. **删字不删信息**：语气词、插入语、重复表达、寒暄可删；结论、对象、动作、规则、数字、时间、金额、角色必须保留（Truman："砍到 30%，但一个信息都没少"）。

## 产出标准（六条写死，逐条可机械检查）

| # | 标准 | 机械检查法 |
|:--|:--|:--|
| 1 | **分层 ≤3 层**：2-3 层最佳；每层 3-5 个点、不超 7 个；超 7 个拆成两组 | 数缩进深度；数每层条目数 |
| 2 | **编号序列**：有顺序逻辑用系统有序列表（1. 2. 3.），无顺序用无序列表；一行一个逻辑点、不折行；禁止手工敲"一、""1)"等字符编号 | grep 手工编号字符；查折行 |
| 3 | **重点前置**：每节第一句是该节结论（总分结构），加粗 | 逐节读首句，问"这是不是本节结论" |
| 4 | **提出-展开-回收闭环**：每节=提出论点→展开要点→一句回收；全文=总问题→分节展开→总回收 | 逐节查首尾；查全文末是否有总回收 |
| 5 | **一分钟扫完**：只读加粗句+编号首行即可重建全文主干 | 遮掉非加粗内容实测扫读 |
| 6 | **全>简但不漏**：口述一等信息全覆盖——全优先于简，但表达求简；宁多一条不漏一条 | 回原文逐段对账，关键信息零丢失 |

## 生产流程（五步）

### Step 0 输入检查与分段

- 确认输入是逐字稿/口述稿全文（不是别人的笔记——笔记只覆盖 ~40%，以原稿为准）。
- 超长稿按话题/说话人切段，记录分段边界，逐段走 Step 1-4，最后合并。

### Step 1 通读 + 信号词标注

- 通读全文一遍，标出信号词段落：「划重点」「举个例子」「注意」「结论」「说白了」「本质是」。
- 这些段落是重点前置和回收句的取材地。

### Step 2 定故事线骨架

- 从 10 种笔记故事线中选主线（系统故事线结构化件）：严格时间线 / 执行流程线 / 案例复盘线（STAR) / 问题解决线 / 对比分析线 / 关键要素线 / 目标取舍线 / 事实洞察线 / 经典方法论线 / 原创方法论线。
- 多人多场稿件（如开放麦）按「人/主题」分节，每人内部再选故事线。
- 顶层先写一句话总览结论（提出）。

### Step 3 逐节重组

- 每节第一句写结论（重点前置，加粗）。
- 正文按编号序列展开：保留主体词、动词、数字；删语气词、寒暄、重复。
- 每节末一句回收本节要点。
- 同级内容行长尽量相近，避免"长长短短没有分担"。

### Step 4 对账 + 扫读自检

- **信息对账**：逐段回原文核对——数字/时间/金额/角色/结论/动作/规则零丢失；发现遗漏补回（全>简）。
- **创作对账**：逐条问"这句原文有没有"——没有就删或改写回原文表述。
- **一分钟扫读**：遮住非加粗内容，能否 1 分钟重建主干；不能→重点前置没做到位。
- 六条产出标准逐条打勾（见上表机械检查法）。

### Step 5 rubric 评分自检门禁（v1.1 新增，不过线不交付）

- 按同目录 `rubric.md`（清单体评分 rubric v1.0，段位图六维 × 0-2 分）给产出打分，每维引一处锚点证据。
- **过线标准**：总分 ≥9 且 D4（重新整理）/D5（故事线）/D6（强逻辑）各 ≥1；D4=0 或 D2=0 触发单项否决。
- 分数写入交付物头部 blockquote：`自评分数（rubric v1.0）：X/12 档位 [D1..D6] — 扣分点：…`。
- 低于线 → 修最低分维度 → 复评，循环到达标再交付。

## 信息删留对照表

| 删（噪音，删了不影响语意） | 留（关键信息，删了内容就不对） |
|:--|:--|
| 语气词（呢/啊/吧/这个/那个） | 结论、判断、立场 |
| 插入语、寒暄、互动组织语言 | 对象、角色、主体 |
| 重复表达（同义复读） | 动作、规则、步骤 |
| 口头禅、自我修正的废句 | 数字、时间、金额、比例 |
| 跑题的玩笑（无信息量） | 因果、条件、边界声明 |

## 判断标准（老顽童铁律：操作步骤≠原文复述，必须给判断标准）

1. **分层判断**：一层=下品（没有层次感），≥4 层=串糖葫芦（加载不了）；2-3 层、每层 3-5 点是人类扫读的甜区。
2. **编号判断**：有先后/依赖/因果用有序列表，并列项用无序列表；拿不准时问自己"调换顺序意思变不变"——变=有序。
3. **重点前置判断**：本节首句能不能单独发出去当结论？不能→还没提炼完。
4. **回收判断**：回收句=本节要点的再确认，不是新信息；回收里出现新信息=展开不全。
5. **删留判断**：删掉这句后，未来的使用者会做错决策/漏掉事实吗？会→必须留；不会→删。
6. **全简平衡判断**：先求全（对账零丢失），再求简（表达压缩）；两者冲突时全优先——这是与"备忘最小信息量"场景的差异点。

## 常见失败模式（症状→修复）

| 失败模式 | 症状 | 修复 |
|:--|:--|:--|
| 逐字誊抄（大而全） | 笔记像乱码 transcript，语气词全在 | 直击备忘：每句只留最小信息量，删留对照表过一遍 |
| 串糖葫芦 | 一层套一层超 3 层，显示器看不全 | 拆平：深层的子点上提或并列成组 |
| 手工编号 | "一、""1)"手工字符，中间插入一条全崩 | 改用系统自动编号 |
| 长短不一 | 行长悬殊，扫读节奏断裂 | 长行拆点、短行合并，行长尽量相近 |
| 白花花低密 | 大片空白/一层一个点，手机翻三屏 | 提高信息密度，同层归并 |
| 重点埋没 | 结论藏在段落中间，首句是铺垫 | 结论提到节首加粗 |
| 只提不收 | 节末没有回收，读者不知本节完了 | 每节补一句回收 |
| 创作越界 | 出现原文没有的判断/升华/建议 | 删除或改写回原文表述；红线零宽容 |
| 长稿截断 | 后半稿内容丢失或明显变糙 | 分段处理+合并后对账 |

## When to Use

- 课程/直播逐字稿 → 可扫读复习笔记
- 会议/访谈记录 → 团队共享备忘
- 口述稿 → 入库前的结构化素材（供后续产卡引用）

## When NOT to Use

- 法律/合同/协议类需要 100% 原文逐字的场景 → 原文存档优先
- 创意发散/头脑风暴 → 清单体线性结构限制发散，用自由记录
- 高度叙事性内容（故事、案例的情感脉络） → 强行条目化会丢叙事逻辑
- 需要作者原创判断的产出（评论/分析文章） → 那是再创作，不是本 skill 的边界
