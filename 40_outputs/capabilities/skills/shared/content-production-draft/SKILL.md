# 内容草稿生产（Step 3-6）

Candy 九步法第 3-6 步。骨架 > 文采，案例逼出观点。

## Step 3: 框架先成立

**动作**：在写正文之前，先确认结构能不能站住。

**骨架自检三问**：
1. 听众知道现在讲到哪了吗？
2. 每一部分是不是在回答一个不同的问题？
3. 最后是不是能收回到开头的承诺？

**如果这三点不成立，后面润色再多也没用。**

### 三段式结构
```
开场承诺 → 主体递进 → 最后收束
   ↓           ↓           ↓
 告诉听众     逐层论证     回到开场
 今天能得到   每个模块     兑现承诺
 什么         一个观点
```

## Step 4: 案例激活

**动作**：为每个论点找一个能"逼出观点"的真实案例。

**好案例的标准**：
- 有场景（具体的时间地点）
- 有人物（具体的人）
- 有冲突/转折
- 有痛感（读者能感同身受）

**不是**"举例说明"——是用案例把论点逼出来。

## Step 5: 案例归位

**动作**：每个案例落到唯一的结构位置。

| 检查 | 不合格信号 |
|:--|:--|
| 案例在论证什么？ | 说不清——这个案例应该删掉 |
| 换一个案例结论还一样吗？ | 不一样——案例选对了 |
| 有没有"为了放案例而放案例"？ | 有——删掉 |

## Step 6: 标题主语校准

**从"我做了什么"→"对读者有什么用"**

| ❌ 作者视角 | ✅ 读者视角 |
|:--|:--|
| "我用ESR写了一份逐字稿" | "怎么写一份能讲出来的课" |
| "我的Problem OS方法论" | "你会提问，就不会瞎想" |
| "Candy的9步法" | "从素材到可交付内容的完整流程" |

## 常见失败

| 症状 | 根因 | 修复 |
|:--|:--|:--|
| 大纲很好看但写不出来 | 框架没经过自检三问 | 回 Step 3 |
| 案例很多但内容不生动 | 案例不是"真实"的 | 找有痛感的真实经历 |
| 标题很学术但没人想看 | 主语是作者 | 切换为读者视角 |
