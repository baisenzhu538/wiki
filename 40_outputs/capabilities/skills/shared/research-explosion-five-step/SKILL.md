# 爆炸式调研五步法（案例大爆炸行为化）

> 解决的核心问题：进入新领域时收集的信息随机、碎片、像盲人摸象，同一关键词给 AI 的答案五花八门。解法不是"看更多"，而是**饱和覆盖式收集案例，直到规律基本稳定**——案例是假的（借），模型是真的（修真）。
>
> 定位：`research-core` 第一层四类型判定的「宽」路由线。本 skill 是方法论执行层；`research-explosion-partner` agent 是已部署的会话载体（五状态机+门控），两者同源不同层。

## 触发条件（何时进入本流程）

| 信号 | 示例请求 |
|:--|:--|
| 新领域快速建认知 | 「调研一下XX领域」「我要进入这个赛道，先建认知」 |
| 案例建模/找规律 | 「帮我调研'交互设计原则'，做成 90 条策略集」 |
| 信息五花八门 | 「网上信息很多但无法判断」「像盲人摸象」 |
| 方向盘点 | 「XX 一人公司都有哪些方向」 |
| 私有库建总锚 | 「把这类课程/文章爆炸式调研一遍」 |

## 操作步骤（五步）

### 第一步：目标——明确 + ROI 预判（人把关）

1. 一句话说清最终意图：这次调研为了做**什么决策/产出什么**（不是"了解一下"）
2. 复杂课题先跑「调研的调研」：花几小时饱和建模，收益是否足够大？不划算 → 降级为简单查询
3. 目标不清 → 先追问用户（九字诀 01-04：深层目标/约束条件/已有事实/判断思路喂给 AI），不模糊开工

### 第二步：范围——收缩边界（人把关）

1. 回答「我到底拿什么写」：时间/地域/对象类型/质量下限
2. 预判未来调研的重要渠道：官方/自媒体/社区/教程/研报/竞品，列出信息源清单（状态 2 门控）
3. 边界写进建模文档头部——给 AI 模糊任务 = AI 给你错误结果

### 第三步：搜索⇄建模循环（AI 主力，最难的一环）

1. **先开一篇建模文档**（`研究：<课题>建模`）——收集与建模之间的桥，刷一个存一个；不会分类也先开
2. **搜索**：多渠道收集案例（搜索引擎/AI 对话/教程/社区/灵感闪现）
3. **建模**：把信息合并进文档，合并整理、分堆排序、寻找规律
4. **循环**：搜索→建模→建不成再搜索→搜索完再建模，一直转
5. **饱和自证话术**（每轮必用，防 AI 编造+防敷衍）：
   - 让 AI 记数：每轮新增多少条、总数多少（有数字在就不太会骗人）
   - 换 5-10 个关键词/渠道再搜一轮：「你再给我换五个关键词，再搜一轮」
   - 问新增量：「相对于上一轮新增加了多少？对体系有修正吗？」
6. 量级参考：两三个案例不够 → 二三十个更好 → 常见饱和区间 500-4000 案例（实证：4000 标题→3000 收敛→十大策略）。**量级不是硬指标，饱和才是目标**

### 第四步：终止判断——规律基本稳定体系（12 字标准，人把关）

1. 判断标准：**新信息无法推翻框架**——再加案例发现框架都差不多 → 可以往后走
2. 检查"50-100 个还有没有明显优化你的体系"：有明显优化 → 继续饱和；只剩细枝末节 → 停
3. 量化信号：换 5 组关键词后新增仅细枝末节 = 饱和达成（定性研究对标：新信息阈值 ≤5% 即停）
4. 成形模型的四种合法形态（任一即可）：**SABC 排序 / 一二三级分类 / 二维象限 / N 步法**
5. 换了 5 组关键词仍有大量新增 → 不是"没饱和"，是第二步边界定错了 → 回第二步收缩

### 第五步：交付——做厚（AI 起草，人验收）

裸模型很硬很抽象，过几周自己都看不懂 → 必须做厚三件套：

1. **分层**：从抽象到具体（框架层/抽象层/方法层/案例层）
2. **讲香**：给人看 = 好看的输出文档；给 AI 用 = 清单/文档/**DataPack 数据包**
3. **可复用**：让没参与调研的同事/agent 也能直接用；标注来源与验证状态（实测/引用/推演）

## 反例黑名单（When NOT to Use）

| 场景 | 判词 | 改走 |
|:--|:--|:--|
| 单一信息点深挖（"竞品核心成本是多少"） | 爆炸式过重 | `research-digging-approach`（挖掘式） |
| 重要决策的推理式调研（里程碑推进） | 饱和建模不替代推理链 | OSCAR（`research-core` 第一层·系统式线） |
| 时间极短的紧急调研（一晚上要结论） | 饱和覆盖投入产出比不成立 | 快速扫描 + 标注信息风险 |
| 线下为主的调研（体验/体感信息） | AI 搜不着，70-30 分工中 AI 只占 70% | 人工侧补现场信息，AI 只做搜索类部分 |
| 长期持续盯梢（竞对动态/政策跟踪） | 单次建模不解决"动态·稳" | `research-ci-framework`（自动式） |

## 失败模式表

| 失败模式 | 真实信号 | 修复动作 |
|:--|:--|:--|
| 目标模糊 | AI 结果五花八门、跑分与目标无关 | 回第一步：写清最终意图与要做的决策，九字诀 01-04 喂给 AI |
| 边界无边 | 资料越收越多收不住 | 回第二步：明确"我到底拿什么写"，写进文档头部 |
| 只搜不建模 | 收集一堆案例没有文档/文档里只有链接堆 | 立刻开建模文档：合并、分堆、排序、找规律，刷一个存一个 |
| 过早终止 | 50 个案例就下结论、规律未稳 | 检查 50-100 个还有没有明显优化，有就继续饱和 |
| 永不停歇 | 4000 个案例还觉得不够、无限收集 | 用 12 字终止标准：新信息已无法推翻框架即停 |
| 交付裸奔 | 模型抽象到过几周自己看不懂 | 做厚三件套：分层/讲香/DataPack |
| 案例当真 | 纠结具体案例细节不放 | 借假修真：框架/模型/规律才是真的，案例是借的 |
| AI 记数虚报 | 饱和证据只有语文描述没有数字 | 记数+严苛标准+人工抽查三件套；数字对不上一轮作废重记 |
| 分类方案单一 | 建模只给 1 套分类没得选 | 强制 3-5 套分类方案对比后拍板（MECE 手术台） |
| 跳步推进 | 不等确认直接从搜索跳到交付 | 五步各自有门控：人确认后才前进（九字诀 05-06） |
