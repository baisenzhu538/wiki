# 蒸馏自己的技能（含成长功能）

> 方法论来源：视频《蒸馏就是AI时代的合法抢劫》第二部分（偶遇采集 2026-08-19 入库）。
> 核心：人先和 AI 共同把活干好一遍，再把"怎么干好的"固化成 Skill，并让 Skill 自己会成长。

## 工作流程

1. **共同完成任务（前置条件）**
   - 用户已在对话中和 AI 协作完成了一项真实任务（如：反复迭代写出合格的朋友圈文案）
   - 过程中用户提的每一轮要求 = 隐性标准的显化（如：大白话、加卖点、控制长度防折叠）
2. **总结工作环节**
   - 回顾整段对话，列出完成任务经历的所有工作环节
   - 把用户提过的所有要求/共识逐条收集，一条不丢
3. **提炼成 Skill**
   - 取工作环节中最有价值的部分，整理为 Skill：触发场景 → 固定流程 → 验收标准（用户的全部要求转化为检查清单）
   - 命名 `<任务>-workflow`，写入 `~/.workbuddy/skills/<name>/SKILL.md`
4. **加入成长功能（最关键一步，不可省略）**
   - 在 Skill 文件里写入成长条款：
     - 每次使用本 Skill 完成工作后，**主动询问用户反馈**（满意/不满意/要改什么）
     - 把反馈转化为对 SKILL.md 的具体修改（标准加严、流程调整、反例入库）
     - 修改后向用户确认再落盘
   - 效果：Skill 每次被用都会自我调优，越用越好用
5. **交付说明**
   - 告诉用户：以后同类任务直接说"用 <name> 帮我……"即可
   - 每次用完它都会问你要反馈——别嫌烦，那是它在成长

## 重要规则

- 成长功能是这类 Skill 和普通 Skill 的本质区别——没有反馈回路的蒸馏不算完成
- 工作共识必须来自真实对话记录，禁止编造用户没提过的要求
- Skill 里的验收标准用可检查的形式写（字数、格式、必含要素），不写"写好一点"这种虚词
- 需要集中式大优化时，转 `darwin-skill`（9 维评分 + git 棘轮 + 人在回路）——成长功能是日常小步进化，darwin 是定期大改
