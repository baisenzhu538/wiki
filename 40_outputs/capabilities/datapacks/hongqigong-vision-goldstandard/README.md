## 要素③ · 置信判定对照表

### 三档判定

**🟢 直接交付（单源可交）**
- 数字型 PDF 有嵌入文本层，且第二源核验零差异（G1：2087/2087）
- 截图批量段级成功率 ≥95%，且 prompt 未注入任何词表/先验（G2：173/173；G4：96%）
- 前提：产出落盘素材目录 + 带覆盖率台账（E021/G6）

**🟡 人工抽核后交付**
- VLM 单源做逐字任务（实测漏字 ≈0.14%，G1 第三源）
- prompt 注入过词表/术语表/先验知识 → 自动降一档（P6）
- 框架图：标题 / 箭头标注 / 颜色归属三处必抽（P6）
- 内容含品牌名/专名 → 形近字全表扫描（P7：漏一个"棠"字 = 3 文件 19 处错）
- 置信 0.3 / `_parse_error` → 先查原始 JSON 再归因（P8）
- 首次使用新引擎/新请求格式 → 先用极简图验证（P3）

**🔴 停 · 换路径或多源，不硬扛**
- 150DPI 渲染密集小字已出错字 → 300DPI 重跑（P5：10 标题错 7）
- HTTP 200 + "没看到图片" → 软失败，先查请求格式（P3：10+ 次空转的教训）
- 中文 .md 只有纯 ASCII/0 字节 → 先查上游落盘，不是原文缺失（P1）
- 文本层含 U+200B 等不可见码点 → 清理 + 声明后再交（P2）
- 手写体 / 扫描倾斜件 → **本库无病例**，人工 + 多源（见 pitfall-cases.md 无病例声明）
- `abab6.5s-chat` → 禁用（7% 随机失败，M3 铁律）【复盘记录：`20_memory/hongqigong-amnesia-recovery-20260613.md`】
- 视觉通道单 key 死亡 → 切降级序列：文本层 > 实例视觉 > VLM（P9）

## 要素④ · 使用说明

**适用问题**
- OCR/VLM 产出后的自检：对着 G1-G6 看"做到什么程度算好"
- 批量识别任务前置排雷：先读 pitfall-cases.md 的规则行，别重踩 P1-P9
- 交付置信声明：按三档表定档，写进交付物 frontmatter（模板见 G1）
- 逐字保真任务：先看 G1 的引擎优先级（文本层 > 实例视觉 > VLM）

**何时挂载**：识图/OCR/VLM 任务**领取后动手前**读一遍踩坑规则；**交付前**对一遍置信三档表。与 `long-image-ocr` skill 配合：skill 管步骤，本包管判定。

**边界**
- 不装工作流步骤——那是 Skill 的职责（#658 已覆盖 transcribe/采集面）
- 样本原件不复制进本包，全在 `00_inbox/`（输入只读纪律），本包只存对照、判定与锚点
- 手写体/扫描倾斜**无病例**，命中时如实说"本库无病例"（pitfall-cases.md 底部声明）
