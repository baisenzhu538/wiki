# 踩坑实录（反例）

> 全部为库内实证案例，非推演。每条 = 症状 → 根因 → 处置 → 锚点。
> 排查新故障时**先查症状表**，再读对应处置；勿凭直觉改代码（P-21 教训：先造诊断再修）。

## P-01 「no yuanbao cookie」
- **症状**：parse_sph 返回 no yuanbao cookie，全部视频号解析挂。
- **根因**：config.yaml 的 sphCookie 未配置或被清空。
- **处置**：重跑 CDP 提取，**全量**写回（见 P-02 的数量要求）。
- **锚点**【实证】：`40_outputs/code/scripts/wechat-serendipity-collect-guide.md` §6.2。

## P-02 只填主 token →「此内容暂时无法播放」
- **症状**：cookie 看起来配了、没过期，但内容全部拒播。
- **根因**：cookie 必须**全量**（含 `.tencent.com` 域的 `hy_token`，共 **13 个**）。只填主 token 不够。
- **处置**：提取脚本不做域裁剪，13 个全量写入 config.yaml，**改配置必须重启解析服务**。
- **锚点**【实证】：guide §4.3「要点」原文 + §6.2。

## P-03 cookie 月级过期
- **症状**：链路整月正常后突然全挂，无代码变更。
- **根因**：元宝 cookie 生命周期约 1 个月。
- **处置**：重新扫码 + CDP 提取（guide §4.3）；这是**计划内的周期性运维**，不是故障，排查时先查 cookie 时间再查代码。
- **锚点**【实证】：guide §五边界表"元宝 Cookie 过期 ⚠️ 每月重建"。

## P-04 数据库解密失败
- **症状**：`_build_and_decrypt.py` 解密失败。
- **根因**：①微信进程未运行；②重装微信后密钥变更。
- **处置**：先登录微信再跑解密；重装场景从旧 `build_keys.py` 带密钥。
- **锚点**【实证】：guide §6.2 + §6.3。
- **教训**：解密依赖**登录态+密钥+进程**三要素，缺一个都表现为"解密失败"，先分清缺哪个。

## P-05 WAL 未合并 → 读不到新消息
- **症状**：监控拍跑完，无新链接，但手机上明明发了。
- **根因**：微信运行中 WAL 未 checkpoint，数据没落主库。
- **处置**：重启微信（退出→打开）立即合并；或等空闲自动落盘。
- **锚点**【实证】：guide §6.2。
- **教训**："读不到"≠"没发生"——先查存储层合并状态，再怀疑提取逻辑。

## P-06 公众号抓取 IncompleteRead 断流
- **症状**：抓全文（3.5MB）中途断流，`http.client.IncompleteRead`。
- **根因**：微信对重复抓取**限流断流是常态**，不是异常。
- **处置**（`fetch_mp_article`）：重试 3 次 + **降级判定**——部分响应里已含 `id="js_content"` 正文标记就直接用（全文大头是内联资源，正文在前段）；失败不记 seen，下一轮自动重试。
- **锚点**【实证】：`kdo-tools/wechat_link_monitor.py:409-437`（docstring + except 分支）+ guide §6.2。

## P-07 「失败不记 seen」× 无正文页 = 29 小时空转死循环
- **症状**：同一 image_detail 图片分享链接每 10 分钟重试一次，永不收敛（2026-08-31 起 ~29h 实证）。
- **根因**：设计原则"失败才重试"（成功才记 seen）遇上**结构上永无正文的页面**（图片分享页），变成无限重试。
- **处置**：识别页面类型即 `mark_seen` 跳过，不进解析重试（#608）。
- **锚点**【实证】：`kdo-tools/wechat_link_monitor.py:515-519`（注释原文"永远抓不到正文……循环 ~29h 实证"）。
- **教训**：重试策略必须有**可终止性**判断——"失败重试"只适用于瞬态失败，不适用于结构性不可能。

## P-08 固定 900s 转写超时 → 重下重转写循环
- **症状**：65 分钟长视频转写被杀，无产出未标 seen → 下一拍重新下载重新转写。
- **根因**：固定 timeout 未随时长缩放。
- **处置**：`transcribe_timeout(video)` 按媒体时长动态计算。
- **锚点**【实证】：`kdo-tools/wechat_link_monitor.py:109-112`（docstring 原文"固定 900s 对 65min 视频必然超时杀进程"）。

## P-09 系统 MITM 代理拦下载/抓取
- **症状**：下载慢/中断、抓取被拦、LLM 知识化失败。
- **根因**：系统代理（MITM）拦 https。
- **处置**：抓取/下载统一 `urllib.request.build_opener(urllib.request.ProxyHandler({}))` 无代理直连；知识化脚本 NO_PROXY。
- **锚点**【实证】：`wechat_link_monitor.py:269,292,324,371,386,417`（6 处 ProxyHandler({})）+ guide §6.2。

## P-10 加密视频喂转写 → Invalid data
- **症状**：下载成功但 whisper 报 Invalid data。
- **根因**：该链接走的是"卡片直链"通道，拿到的是**加密视频**（解密密钥仅播放时暴露）；sph 短链通道的直链是非加密版。
- **处置**：卡片直链改走播放拦截兜底（需人在电脑前，非自动化）；不在转写侧修。
- **锚点**【实证】：guide §五边界表 + §6.2"转写失败 Invalid data"行。
- **教训**：失败可能来自**上游通道选择**，先查输入合法性再修处理端。

## P-11 完整 URL 去重被追踪参数绕过
- **症状**：同一篇文章采了多份（2026-08-19 前）。
- **根因**：同一内容每次分享的追踪参数（chksm/scene/share_token/utm_*）都不同，完整 URL 去重必然穿透。
- **处置**：`canonical_key` 规范化——公众号取 `__biz+mid+idx` 三元组，头条取 gid，其余原样；双写原 URL + 规范化键；存量重复归档 `60_feedback/wechat-collect/duplicates-archive/`（inbox 只增不删铁律）。
- **锚点**【实证】：`wechat_link_monitor.py:57-85` + guide §6.2"同一内容采了多份"行 + `duplicates-archive/` 目录在库。

## P-12 凭据走 env 变量不生效（工具层"登录失效"）
- **症状**：`HERMES_PROFILE=<role>` 拉起非五绝 profile，三个全部自报为**发起者**身份。
- **根因**：无头单发链路不读该 env；正确通道是命令行 `-p <profile>` flag。
- **处置**：凭据/身份改显式参数传递；并追历史上经此通道的拉起是否发生过跨 profile 误写。
- **锚点**【实证】：`60_feedback/diagnosis/diag_20260906_duanwangye-hermes-headless-profile-flag.md` 证据 2/3（三组对照实测）。
- **同构提示**：与 P-02 同构——**凭据传递不完整/不走正确通道，表现都是"看起来配了但拒你"**。

## P-13 报错但 exit 0 = 假成功
- **症状**：`hermes -z ... -Q` 报 `unrecognized arguments: -Q`，进程却退出 0。
- **根因**：`-Q` 只属于 `chat` 子命令；主命令直调不识别但退出码不反映。
- **处置**：不能只看退出码，要校验**产出物特征**（如日志中角色自报身份、文件落盘）。
- **锚点**【实证】：diag 同上建议书证据 4。
- **同构提示**：与 P-08 同构——"流程走完了"≠"产物有效"，判成功要看产物。

## P-14 转写稿繁体 + 术语错词（tiny 模型边界）
- **症状**：`src_wechat_2404c1658025473c.md` 输出繁体（`喬治阿克爾`/`銀蒙市場`），`src_wechat_dy_7654610643165120177.md` 关键概念失真（`刚中之导`→缸中之脑【推断】）。
- **根因**：tiny 级模型能力边界 + 音近词歧义，非流程故障。
- **处置**：转写稿定级 🟡（仅检索索引），引用专有名词前对照原音视频；需要高质量逐字稿换更大模型，不在流程层打补丁。
- **锚点**【实证】：两个产物文件原文；错词的"应为什么"标注为【推断】（上下文解读）。
