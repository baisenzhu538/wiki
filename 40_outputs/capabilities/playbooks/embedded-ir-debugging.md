# Playbook：嵌入式红外/对射调试三步法

> **触发条件**：红外对射/光电传感器阵列异常（全部不工作 / 部分通道失效 / 信号不稳定）。
> **核心原则**：先诊断后修复——没有诊断手段就调参数 = 撞运气。
> **参考案例**：广冷红外板 V2.2（SN74LVC2G07 电平转换引入 RCLK 时序问题）。

---

## Step 0：准备诊断工具（10min）

**在修 bug 之前，先造一个能告诉你"哪里坏了"的工具。**

| 场景 | 诊断工具 |
|------|---------|
| 怀疑发射管故障 | 诊断版固件：强制拉高 IO 口（绕过逻辑 IC），直接驱动 MOSFET / LED |
| 怀疑接收管故障 | 诊断版固件：只读接收管 ADC 值，不依赖业务逻辑判断 |
| 怀疑时序问题 | 诊断版固件：在关键信号点翻转一个空闲 IO，用示波器/逻辑分析仪抓波形 |
| 怀疑判断逻辑 | 诊断版固件：串口打印每路原始值，不做阈值判断 |

**原则**：诊断工具的目的是**排除不可能**，不是**修复问题**。它让你把搜索空间从"整个系统"缩小到具体模块。

---

## Step 1：硬件验证 — 排除物理层（15min）

```
发射管正常？→ 强制驱动发射管（绕过 IC），用手机摄像头看是否发光
接收管正常？→ 强制驱动发射管，示波器看接收管输出是否跳变
供电正常？→ 测 VCC/GND 电压，确认在工作范围内
```

**关键判断**：如果强制驱动后硬件正常，问题在控制逻辑层。如果强制驱动仍然不工作，问题在硬件层（焊接/器件损坏/PCB）。

---

## Step 2：时序诊断 — 确认控制信号质量（20min）

**这一步在确定硬件完好后执行。**

### 电平转换场景（如新增 SN74LVC2G07）

```
新增电平转换芯片 → 查输出类型（开漏 vs 推挽）
  → 开漏？查上拉电阻值 → 算 RC 时间常数 τ = R × C
  → 信号频率 > 1/(2πτ)？→ 上升沿变缓，无法可靠触发
  → 对策：
    1. 减小上拉电阻（加快上升沿）
    2. 或固件端加延时等待信号稳定
    3. 或换推挽输出型电平转换芯片
```

### 通用时序检查

| 信号 | 检查项 | 工具 |
|------|--------|------|
| 时钟线（如 595 RCLK/SRCLK） | 上升沿时间 < 数据建立时间 | 示波器 |
| 数据线（如 595 SER） | 数据在时钟沿前后保持稳定 | 逻辑分析仪 |
| 锁存信号（如 595 RCLK） | 上升沿后延时足够（≥200ns）再读 | 示波器 |

**经验值**：开漏输出 + 10kΩ 上拉 + 50pF 负载 → τ ≈ 0.5μs → 上升沿 ~1.5μs。如果后续 IC 的 setup time < 1.5μs，不可靠。

---

## Step 3：分段隔离 — 单变量验证（15min）

**不要一次搞定四个变量。** 单通道验证通过后再叠加。

```
IN1 单独通 → 验证 → 通过 ✅
IN2 单独通 → 验证 → 通过 ✅
IN3 单独通 → 验证 → 失败 ❌ → 定位到 IN3 通道
IN1 + IN2 合起来 → 验证 → 通过 ✅
IN1 + IN3 合起来 → 验证 → 确认 IN3 问题
```

**为什么这样做**：
- 一次调四个变量 → 2^4 = 16 种组合，找不到问题时无法排除任何变量
- 分段隔离 → 每个变量独立验证，失败时立即定位
- 速度差：分段隔离 ~15min vs 盲调 ~数小时

---

## Step 4：判断逻辑 — 最后修（10min）

**前提**：Step 1-3 确认每一路硬件信号正确。

判断逻辑是业务层的，不是技术层的：
- 光电开关是"被遮挡"还是"未被遮挡"作为有效信号？
- 多路组合判断（AND / OR / 计数阈值）？
- 去抖时长是否匹配实际物体通过速度？

**案例**：广冷售货机 `no<8 → IN1&&IN3, no>=8 → IN2&&IN4`——这个逻辑来自业务理解（一次掉一个货、靠近哪侧就哪侧检测），不是纯技术决策。

---

## 电平转换引入时序问题的排查路径（速查卡）

```
新增电平转换芯片
  ├── 查输出类型：开漏（Open-Drain）or 推挽（Push-Pull）？
  ├── 开漏？→ 查上拉电阻值 → 算 RC 时间常数
  ├── 信号频率是否超过可用带宽？
  └── 固件时序是否匹配？
```

---

## 反模式（不要做的事）

| 反模式 | 为什么无效 | 正确做法 |
|--------|-----------|---------|
| 反复调延时值（15→30→100→200→500） | 如果问题不在延时本身，调参数是撞运气 | 先用诊断版定位问题模块 |
| 同时改多个变量 | 无法确定哪个变量有效 | 分段隔离，单变量验证 |
| 不看数据手册就上手 | 不了解开漏特性就无法解释"为什么加延时有效" | 先读 IC 数据手册输出特性章节 |
| 修判断逻辑而不验证硬件 | 逻辑修正建立在错误信号上 = 越修越错 | Step 1-3 必须先过 |
