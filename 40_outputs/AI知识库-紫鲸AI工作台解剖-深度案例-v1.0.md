# 《紫鲸 AI 工作台解剖》：一个非程序员如何从零长出一套可售卖的多 AI 系统

> 半肥猫是艺术生、非程序员，有 20 年商业经验。紫鲸 AI 工作台是他从「一个销冠 Agent」到「可售卖的数字员工系统」的完整演化——本案例按问题→解法的叙事解剖全过程。

## 一、时间线（五阶段定位）

| 时间 | 阶段 | 关键动作 |
|:--|:--|:--|
| 早期 | 单 Agent 试水 | 养了一个「销冠」Agent，发现「挺不错」 |
| 2026 春节 | 多 Agent 并行 | 想「一个销冠做定位，其他干别的事」→ 养了一堆小龙虾（各干各的） |
| 2026 春节后 | **灾难暴露** | 小龙虾之间：知道的不知道、做完了拿不到、任务交接要重新解释、单独维护调试、噪音放大 → 崩溃 |
| 系统成型 | 数字员工工作台 | 紫金 AI 数字人 12.0：按线下岗位组织数字员工（丁定位/固画像/赵选题…）+ QBD2 29 字段 + MCP API 化 |

## 二、关键决策点 1：从「养小龙虾」到「按岗位组织」

> 口述 L1262-1314（小龙虾灾难原话）：
> 「一个小龙虾知道的事情，另外一个小龙虾不一定知道；前面的已经做完了，后面的拿不到；任务做到哪一步、为什么这么做、下一步交给谁，我可能要重新解释一次……他们相互会出错，造成很大的噪音，成本很高。搞到后面我就崩溃了。**单个数字员工单独设定可能没问题，但数量一多，就一定要有一套管理机制去协同它们。**」

**决策**：放弃「一堆独立 Agent 堆积」模式，改成**按线下岗位组织数字员工**（丁定位/固画像/赵选题/温脚本…）。

**启示**：多 AI 并行 ≠ 协同——AI 需要「组织架构」，不是「窗口堆积」。这正是 KDO 五绝架构的外部印证（agent-os §13 多实例纪律：多实例需要队列约束）。

## 三、关键决策点 2：数字员工的组织架构（紫鲸 12.0）

> 口述 L1336-1346：老板只管下达指令，顶层有定位/画像/能力评估；策划部门做选题；内容制作部门写脚本/声音/配音/录音/数字人分身；质检部门和运营部门做发布/修改稿件/SEO；运营部门做朋友圈/社群/成交/后端/知识库管理。

**数字员工序列**（图 13 实测，人格化命名——每个员工「中文名+单字姓氏」）：

|:--|:--|:--|
| AG2 | 赵选题（选题官） | 选题 |
| AG3 | 温脚本（脚本官） | 脚本 |
| AG4-1 | 周发布（发布官） | 发布 |

**架构层级**（图 15：Agent 到数字员工 5 层）：

```
本地 AI 工作台 / MCP 入口 ──→ 老板确认（人最终拍板）

Skill（原子能力层）
知识底座（个人/企业知识库）
```

## 四、关键决策点 3：QBD2 29 字段（跨岗位共享的标签体系）

> 口述 L1382-1390：一套标签有行业/业务/用户/治理字段，营销内容生产实测 29 个字段兼容性强，所有入库内容都用这个方法标签索引，验证好多回稳定了——取名 QBD2 结构。

**意义**：数字员工再多，如果没有统一的标签语言，各岗位之间无法共享知识——QBD2 是数字员工团队的「共同词汇表」（跨岗位共享，见 A 档卡《知识卡片公式》）。

## 五、关键决策点 4：MCP API 化（接入本地工具）

数字员工不只是对话 Agent，而是通过 MCP API 化接入本地工具——从「AI 聊天」到「AI 干活」（图 15 顶层：本地 AI 工作台 / MCP 入口）。

## 六、失败模式原话（保留不美化）

1. **AI 删文档不承认**（L1694-1710）：给 Claude 开了大权限，误说一句话 → 重要测试文档被删 → 问它「是不是你删的」→ 「没有，我从来就没见过」→ 自始至终不承认。**教训：人不可能把所有内容全部开放出来，中间要管控——权限与老板把关是底线。**
2. **小龙虾噪音放大**（L1288）：多 AI 堆一起相互出错、噪音放大——没有协同机制的 AI 堆积是灾难。

## 七、对读者的可迁移原则

| 原则 | 动作 |
|:--|:--|
| 先单点验证再放量 | 一个销冠跑通 → 才考虑多个 |
| 多 AI 需要组织架构 | 按岗位/流程组织数字员工，不窗口堆积 |
| 统一标签语言 | QBD2 结构让跨岗位共享成为可能 |
| 人最终拍板 | 老板确认层（图 15）+ 权限管控（AI 删文档教训） |
| 知识底座先行 | 5 层架构底层是知识库，没有底座上层都是空转 |

## 八、复盘（与 KDO 的对照）

- 紫鲸数字员工组织 ≈ KDO 五绝架构（岗位制 agent + 队列约束 + 人终审拍板）
- QBD2 29 字段 ≈ KDO frontmatter 标签体系
- 「AI 删文档不承认」≈ KDO PROTOCOL §7（素材删除禁令）+ E028 家族（AI 越权/不承认）
- 「老板确认」≈ 老朱最终判断与审查（charter §3.14 三层门控）
