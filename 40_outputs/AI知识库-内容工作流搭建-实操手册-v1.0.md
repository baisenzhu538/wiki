# 《AI知识库-内容工作流搭建》实操手册

> 目标：把内容生产从「每天手动写」变成「工作流自动跑」。拿到就能用。

## 一、内容 Workflow 八步总览

```
定位 → 用户研究 → 选题 → 脚本 → 素材 → 发布 → 私域承接 → 复盘
 ↑                                                          ↓
 └────────────── 知识库 ←────────────────────────────────────┘
```

| # | 节点 | 业务含义 | 质量护盾 |
|:--|:--|:--|:--|
| 1 | **定位** | 内容方向/受众/价值主张 | — |
| 2 | **用户研究** | 需求洞察/痛点挖掘 | 🛡️ 真实输入 |
| 3 | **选题** | 选题决策/标题拟定 | — |
| 4 | **脚本** | 内容结构/文案撰写 | 🛡️ 核心处理 |
| 5 | **素材** | 多模态采集制作 | — |
| 6 | **发布** | 多平台分发 | 🛡️ 可用输出 |
| 7 | **私域承接** | 流量沉淀/用户转化 | — |
| 8 | **复盘** | 数据回收/效果分析 | 🛡️ 质量检查 |

## 二、双闭环（工作流的灵魂）

```
外闭环：8 节点主流程（业务飞轮）——定位到复盘一遍遍跑
内闭环：知识库 ↔ 首尾节点（数据-经验循环）
  - 复盘 → 知识库：复盘结果沉淀入库（第 8 步产出进库）
  - 知识库 → 定位：历史经验/数据支持下次定位（第 1 步输入来自库）
```

**核心认知**：工作流不是一次性流水线，是**飞轮**——每跑一圈，知识库变厚，下一圈更快更好。

## 三、Workflow 六要素（搭之前先检查）

> 口述 L828-856：「一个好的 workflow 是要有知识库的……我发现很多人做的工作流，他们都不太喜欢去做知识库。」

| 要素 | 定义 | 检查 |
|:--|:--|:--|
| 知识库 | 业务事实/案例/边界 | 工作流有燃料吗？ |
| Prompt 规则 | 提示词约定/角色/边界 | 每个节点有独立 Prompt 吗？ |
| 检索方式 | AI 如何查知识库 | RAG/关键词配了吗？ |
| 明确任务 | 一次只做一个任务 | 节点拆细了吗？ |
| 输入输出标准 | 格式约定 | 前后节点接口对齐吗？ |
| 验收方法 | 怎么判断做对了 | 质量护盾/人工验收有吗？ |

## 四、搭建步骤

### 第 1 步：画主流程（八步或简化版）

按你的业务画 5-8 个节点，每个节点一个任务：
- 内容业务：定位→用户研究→选题→脚本→素材→发布→私域承接→复盘
- 简化版：定位→选题→创作→发布→复盘

### 第 2 步：挂质量护盾（4 个质检站）

| 护盾 | 位置 | 检查什么 |
|:--|:--|:--|
| 真实输入 | 用户研究→选题 | 输入数据真实吗？ |
| 核心处理 | 脚本→素材 | 创作质量达标吗？ |
| 可用输出 | 素材→发布 | 输出能直接用吗？ |
| 质量检查 | 私域承接→复盘 | 最终把关 |

**判断标准**：每个护盾 = 一个可执行的检查项（不是口号）。

### 第 3 步：接知识库双闭环

- 复盘节点 → 输出沉淀入知识库（数据回收后入库）
- 知识库 → 定位节点（历史经验反哺）

### 第 4 步：拆节点 + 换模型

- 大提示词 → 拆细（每节点一个任务）
- 拆细后测试：便宜小模型能稳定输出 = 拆分到位（口述 L1084-1100 节点拆细）

### 第 5 步：试跑 + 验收

- 用真实数据跑通一轮
- 每个护盾节点验收
- 跑完复盘 → 入库 → 下一轮更快

## 五、常见坑

| 坑 | 症状 | 解法 |
|:--|:--|:--|
| 不做知识库直接搭 Workflow | 工作流空转，AI 乱答 | 先建知识库（阶段 1-2） |
| 大提示词一锅端 | 挑模型/不稳定/贵 | 节点拆细 |
| 没有质量护盾 | 垃圾产出自动发布 | 4 个质检站挂上 |
| 只跑不沉淀 | 每轮从零开始，无复利 | 复盘→知识库闭环 |
