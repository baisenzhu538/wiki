## 三、整理原则

### 3.1 文件三分类法（引用欧阳锋建议书）

| 类别 | 色标 | 定义 | 处理方式 |
|:-----|:----:|:-----|:---------|
| **基准线** | 🔴 | 描述"产品是什么"的不可替代文件 | 保留，命名规范化，建立版本锁 |
| **佐证** | 🟡 | 有存档价值但不是产品本身 | 保留，单独归档，可压缩打包 |
| **过程** | ⚪ | 用完即弃的中间产物 | **删除** |

### 3.2 版本锁原则

原理图 + PCB + BOM + 坐标 + 固件 五文件必须互锁：
- 动了其中一个，其他必须重新确认
- 版本锁表记录在项目 README 中
- 新版本 = 新文件，**不覆盖旧文件**

## 四、详细整理步骤

### 阶段一：备份与清点（1~2小时）

**步骤 1.1：完整备份**
```bash
# 将整个广冷电子文件夹压缩备份
# 备份名：广冷电子_整理前备份_20260605.zip
```

**步骤 1.2：建立清点清单**
- 列出所有文件类型分布（.c/.h/.pdf/.zip/.rar/.xlsx/.csv/.docx/.jpg/.hex/.bin）
- 识别所有重复文件（按文件名+大小匹配）
- 标记临时文件模式：
  - `~$*.xlsx` — Excel临时文件
  - `*.o` / `*.crf` / `*.dep` / `*.d` / `*.axf` — 编译中间产物
  - `*.TMP` / `*~RF*.TMP` — 系统临时文件
  - `微信图片_*` — 微信传图副本
  - `*.rar` 与同名解压文件夹并存 — 保留其一

**步骤 1.3：确定"正确版本"**
根据已有分析文档，确定各资料的正确版本：

| 资料类型 | 正确版本 | 依据 |
|:---------|:---------|:-----|
| 红外板 BOM | V2.1-修改_2025-12-03 | 最新贴片确认单 |
| 红外板 Gerber | V2.1-修改_PCB V2.2_2025-12-03 | 与BOM同期 |
| 红外板固件 | 现场调试成功版(9915B) | 已验证通过 |
| 主控板固件 | V5.0.0（铁科院协议） | 当前运行版本 |
| 设计分析PDF | HX_SMJ-03_红外光栅板设计分析.pdf | 唯一设计文档 |

### 阶段二：清理过程文件（30分钟）

**删除清单（⚪ 过程文件）：**

```
□ 所有编译中间产物
  - *.o, *.crf, *.dep, *.d, *.axf, *.hex（旧版本）, *.bin（旧版本）

□ 微信传图副本

□ 重复压缩包
  - 与已解压文件夹同名的 .rar / .zip
  - 例：广冷-PCB-嘉立创.rar（与同名文件夹重复）

□ KEIL 工程临时文件
  - DebugConfig/

□ 旧版本固件（保留最新+现场调试成功版）
  - 黄工原始版（已确认功能不全）
  - 修改测试版（已确认改坏）
```

### 阶段三：合并双文件夹（2~3小时）

**核心决策：以广冷001为主干，广冷002为补充**

理由：
- 广冷001 已有 `_archive` 和 `PROJECT_CATALOG.md` 整理基础
- 广冷002 包含一些 001 没有的资料（如合同、更完整的PCB历史资料）

**合并策略：**

```
对于每个文件/文件夹：
  1. 如果 001 和 002 内容完全相同（按大小+修改时间）
     → 保留 001 的，删除 002 的
  
  2. 如果 002 有而 001 没有
     → 移动到 001 的适当位置
  
  3. 如果两者都有但版本不同
     → 按"正确版本"表判断，保留正确的，错误的移入 _archive/deprecated/
  
  4. 如果无法判断哪个正确
     → 保留较新的，旧的移入 _archive/deprecated/ 并标注
```

**广冷002 独有资料清单（需合并到001）：**

| 资料 | 路径（在002中） | 建议合并位置 |

### 阶段五：命名规范化（1小时）

**命名规则：**

```
文件夹命名：
  [板号]-[板名]/
  例：HX-SMJ-03B-A-红外板-A/

文件命名：
  [类型]_[板号]_V[版本]_[日期].[扩展名]
  例：BOM_HX-SMJ-03B-A_V2.1-修改_2025-12-03.csv

固件命名：
  [项目]_[板型]_V[版本]_[日期]_[说明].[hex/bin]
  例：广冷_红外板_V5.0.0_2025-12-23_铁科院协议.hex
```

**禁止：**
- 文件夹名超过 50 字符
- 文件名包含 `、` `（` `）` 等全角符号
- 同一目录下存在仅日期不同的同名文件（应分版本存放）

## 五、风险与注意事项

### 5.1 不可删除的资料（即使看起来重复）

| 资料 | 原因 |
|:-----|:-----|
| 现场调试成功版固件 | 唯一已验证正确的版本 |
| 2022年巨米智能生产资料 | 历史合作记录，可能有法律价值 |
| 合同.pdf | 法律文件 |
| 8张实物板照片 | 实物证据，已用于OCR确认丝印 |

### 5.2 需要人工判断的资料

| 资料 | 问题 | 建议 |
|:-----|:-----|:-----|
| 4505018_V1.0 | 可能非本项目 | 移入 _archive/06_deprecated/ 并标注"待确认" |
| 云柜控制板CAN2.0_v5.0.0 | 可能是其他项目共用库 | 保留在固件目录，标注"可能为通用库" |
| 多个"第一次匹配BOM" | 中间过程文件 | 移入 _archive/04_bom_old/ |

### 5.3 整理后仍需跟进的事项

1. **解决设计PDF与BOM的矛盾**：联系原工程师或供应商确认 DC-DC 到底是 TPS54360 还是 JW5026
2. **固件源码编译验证**：确认清理后的 KEIL 工程能正常编译出与 "现场调试成功版" 一致的 hex
3. **建立新项目模板**：将本次整理经验沉淀为 `electronics-project-template/`
