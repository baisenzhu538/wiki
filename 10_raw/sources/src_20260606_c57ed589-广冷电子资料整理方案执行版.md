## 三、整理原则

### 3.1 文件三分类法

| 类别 | 色标 | 定义 | 处理方式 |
|:-----|:----:|:-----|:---------|
| **基准线** | 🔴 | 描述"产品是什么"的不可替代文件 | 保留，命名规范化，建立版本锁 |
| **佐证** | 🟡 | 有存档价值但不是产品本身 | 保留，单独归档，可压缩打包 |
| **过程** | ⚪ | 用完即弃的中间产物 | **删除** |
| **待验证** | ❓ | 无法确定正确性，需要实物验证 | **单独存放**，不放入基准线 |

### 3.2 验证状态标注体系

每项资料必须标注以下验证状态之一：

| 状态 | 图标 | 含义 | 处理方式 |
|:-----|:----:|:-----|:---------|
| 已验证 | ✅ | 已有报告确认，或实物已验证 | 放入基准线 |
| 基于报告 | ⚠️ | 基于已有分析文档，未独立验证 | 放入基准线，但标注来源 |
| 待验证 | ❓ | 存在矛盾或不确定性 | 放入 `99_pending_verify/`，不放入基准线 |
| 已废弃 | ❌ | 已确认错误/过时/损坏 | 放入 `_archive/deprecated/` |
| 未知 | ❔ | 用途不明 | 放入 `_archive/unknown/` |

### 3.3 版本锁原则

原理图 + PCB + BOM + 坐标 + 固件 五文件必须互锁：
- 动了其中一个，其他必须重新确认
- 版本锁表记录在项目 README 中
- 新版本 = 新文件，**不覆盖旧文件**

### 阶段五：命名规范化（1小时）

**命名规则：**

```
文件夹命名：
  [板号]-[板名]/
  例：HX-SMJ-03B-A-红外板-A/

文件命名：
  [类型]_[板号]_V[版本]_[日期].[扩展名]
  例：BOM_HX-SMJ-03B-A_V2.1-修改_2025-12-03.csv

固件命名：
  [项目]_[板型]_V[版本]_[日期]_[说明].[hex/bin]
  例：广冷_红外板_V5.0.0_2025-12-23_铁科院协议.hex
```

**禁止：**
- 文件夹名超过 50 字符
- 文件名包含 `、` `（` `）` 等全角符号
- 同一目录下存在仅日期不同的同名文件（应分版本存放）
