## 3. 时序逻辑分析

### 3.1 Ir_Delay延时参数

```c
void Ir_Delay(u32 cnt)
{
    u32 i;
    for(i=0;i<cnt;i++)
    {
        while(0);
    }
}
```

**所有版本**中`Ir_Delay`的参数均为 **15**，出现在以下位置：
- RCLK拉低后：`Ir_Delay(15)`
- SRCLK拉低后：`Ir_Delay(15)`
- 数据建立后：`Ir_Delay(15)`
- SRCLK拉高后：`Ir_Delay(15)`
- RCLK拉高后：`Ir_Delay(15)`

**⚠️ 重要发现**：故障报告中提到的 **"RCLK拉高后加Ir_Delay(200)"** 在**所有找到的源码版本中均未体现**。实际代码中RCLK拉高后的延时固定为 **15**（循环计数），而非200。

> 注：Ir_Delay(15)的实际物理延时取决于CPU主频和编译器优化，通常在微秒级别，用于满足595/4051的时序建立/保持时间要求。

### 3.2 595移位时序（成功版）

```c
IR_595_RCLK=0;      // 1. 锁存时钟拉低
Ir_Delay(15);
for(i=0;i<16;i++)   // 2. 循环16次（2片×8位）
{
    IR_595_SRCLK=0; //    移位时钟拉低
    Ir_Delay(15);
    // 设置QD1~QD4数据
    if(mask&((u16)0x8000>>i))
    {
        IR_595_QD1=1; IR_595_QD2=1;
        IR_595_QD3=1; IR_595_QD4=1;
    }
    else
    {
        IR_595_QD1=0; IR_595_QD2=0;
        IR_595_QD3=0; IR_595_QD4=0;
    }
    Ir_Delay(15);
    IR_595_SRCLK=1; //    移位时钟拉高（数据移入）
    Ir_Delay(15);
}
IR_595_RCLK=1;      // 3. 锁存时钟拉高（输出到引脚）
Ir_Delay(15);
```

### 3.3 接收判断逻辑

#### 成功版/修改-测试版/新修改-测试版：
```c
if(IR_4051_IN1&&IR_4051_IN2&&IR_4051_IN3&&IR_4051_IN4)
    return 1;  // 无遮挡（四路全部检测到信号）
else
    return 0;  // 有遮挡
```

#### 黄工版/03_firmware/修改测试版：
```c
if(IR_4051_IN3&&IR_4051_IN4)
    return 1;  // 无遮挡（仅判断IN3和IN4）
else
    return 0;  // 有遮挡
```

**差异分析**：
- 成功版要求**四路接收信号全部有效**才判定为无遮挡，冗余度最高，抗干扰能力最强。
- 黄工版仅判断**IN3&&IN4**，忽略了IN1和IN2，这与故障报告中提到的 `"no<8 → IN1&&IN3，no>=8 → IN2&&IN4"` 逻辑**不符**。
- 故障报告描述的分段判断逻辑（前8路用IN1&&IN3，后8路用IN2&&IN4）在**任何版本源码中均未找到**。

## 4. 多版本差异对比

### 4.1 核心差异汇总表

| 对比项 | 现场调试成功版（正确版） | 黄工版/03_firmware（错误版） | 影响 |
|--------|------------------------|------------------------------|------|
| **扫描路数** | 16路 (`no%=16`) | 8路 (`no%=8`) | ❌ 错误版只能扫描一半货道 |
| **QD3状态** | 启用 (`IR_595_QD3=1/0`) | **被注释掉** (`//IR_595_QD3=1;`) | ❌ 错误版后8路发射无法独立控制 |
| **mask值** | `0x0001<<no` | `0x0101<<no` | ⚠️ 错误版mask模式异常，可能同时点亮多路 |
| **接收判断** | `IN1&&IN2&&IN3&&IN4` | `IN3&&IN4` | ⚠️ 错误版忽略IN1/IN2，可靠性降低 |
| **sta位宽** | `u16 sta` (16位) | `u8 sta` (8位) | ❌ 错误版状态变量只能存8路 |
| **QD2/QD4** | 定义并初始化 | **未定义/未初始化** | ⚠️ 与PCB V2.2兼容性待验证 |
| **Ir_Delay** | 15 | 15 | ✅ 一致 |
| **RCLK延时** | 15 | 15 | ✅ 一致 |

### 4.2 关键错误：QD3被注释

黄工版/03_firmware中的`Ir_Select_Send`函数：
```c
if(mask&((u16)0x8000>>i))
{
    IR_595_QD1=1;
//  IR_595_QD3=1;    // ←←← 被注释！
}
else
{
    IR_595_QD1=0;
    IR_595_QD3=0;
}
```

**后果**：
- QD3始终为低电平（else分支仍执行`IR_595_QD3=0`）
- 如果PCB上QD3连接到第二片595的SER，则**第二片595始终输入0**
- 导致**后8路红外发射管无法被独立控制**，只能全关或受QD1串扰影响

### 4.3 关键错误：mask=0x0101

黄工版使用 `mask = ((u16)0x0101 << no)`，而非成功版的 `0x0001 << no`。

- `0x0101` 的二进制为 `0000 0001 0000 0001`
- 左移后会在**两个位置**同时出现1（bit0和bit8同时移位）
- 这会导致**同时点亮两路发射管**，违反单路扫描原则，可能造成串扰

## 7. 附录：关键源码片段

### 7.1 成功版 Ir_Select_Send（16路正确实现）

```c
void Ir_Select_Send(u8 no,u8 enable)
{
    u8 i;
    u16 mask;
    if(enable)
        mask=((u16)0x0001<<no);  // 单bit掩码
    else
        mask=0;

    IR_595_RCLK=0;
    Ir_Delay(15);
    for(i=0;i<16;i++)  // 16位 = 2片×8位
    {
        IR_595_SRCLK=0;
        Ir_Delay(15);
        if(mask&((u16)0x8000>>i))
        {
            IR_595_QD1=1; IR_595_QD2=1;
            IR_595_QD3=1; IR_595_QD4=1;
        }
        else
        {
            IR_595_QD1=0; IR_595_QD2=0;
            IR_595_QD3=0; IR_595_QD4=0;
        }
        Ir_Delay(15);
        IR_595_SRCLK=1;
        Ir_Delay(15);
    }
    IR_595_RCLK=1;
    Ir_Delay(15);
}
```
